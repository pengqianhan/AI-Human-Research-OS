# Summary

This paper studies whether LLMs can act as selective surrogates for GPU kernel evaluation, forecasting the runtime/performance of a candidate kernel instead of compiling and executing it on hardware. The motivation is that as LLM-driven kernel search scales to large search budgets, repeated on-device measurement becomes the bottleneck, not kernel generation.

# Key Ideas

* Use an LLM to forecast relative performance of a candidate GPU kernel directly from source code, avoiding a compile-and-execute cycle on real hardware.
* Make the surrogate selective: it should know when its forecast is unreliable and defer to a real GPU measurement rather than guess.
* Evaluate surrogates along three axes: forecast accuracy, calibration of confidence, and practical usefulness for recovering fast kernels under a fixed GPU-measurement budget.
* Use reinforcement learning to improve both forecast accuracy and confidence calibration beyond a base pretrained LLM.

# Method

The surrogate is an LLM that reads kernel source code and predicts relative runtime/performance, paired with a confidence signal used to decide whether to trust the forecast or fall back to an actual GPU measurement. The surrogate is plugged into a kernel search loop (e.g., evolutionary search or coding-agent search) in place of, or alongside, on-device evaluation.

# Experiments

* Compares forecast accuracy and calibration of the LLM surrogate against ground-truth GPU measurements.
* Integrates the surrogate into a kernel search process and reports that it lets the search examine several times as many candidates under the same GPU-evaluation budget.
* Reports that surrogate-assisted search finds faster kernels than an equal-budget baseline that relies solely on real GPU measurement.

# Limitations

* The paper notes (per the authors' framing) open questions about whether LLM forecasts generalize across unfamiliar hardware configurations and kernel families not seen during calibration.

# Notes

Read at a summary level (abstract + PDF skim); not yet read in full. Reading questions:

* What confidence/selectivity mechanism is used to decide "trust forecast vs. measure on GPU," and how is it calibrated?
* How much of the speedup comes from the surrogate itself vs. simply running more search iterations cheaply?
* Could the same selective-surrogate idea apply to other expensive-to-evaluate search domains (e.g., compiler flags, model architecture search)?
