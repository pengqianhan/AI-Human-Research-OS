# 并行运行 / 自我进化 / 经验共享 — GitHub 调研与对 AI-Human Research OS 的启发

> 针对一个目标的调研笔记:让本 OS 成为**适合 agent 长期运行、自我进化、并行执行、跨 agent 共享经验**的科研环境。

## 一、先做诊断:现有设计 vs 这次提出的目标(有结构性落差)

读 [`INSTRUCTION.md`](../INSTRUCTION.md) 可知,当前 OS 是一个**被动的知识整理 OS**——无数据库 / 服务器 / CLI,只有 Markdown + 文件夹约定 + 记忆层 + skills,信条是"小而可逆、不加重型结构"(Agent Rule #8)。

而这次提出的四个目标,是一个**主动的多 agent 运行时**的要求。两者之间有一道需要正视的落差:

| 这次的目标 | 现在已有的 | 缺的(=改进空间) |
|---|---|---|
| **长时间运行** | `HANDOFF.md` + `session-handoff` skill | 自主循环的**边界**:成功标准 / 最大轮数 / 停止条件 |
| **自我进化** | skill 晋升路径(lesson→项目级 skill→hub) | 驱动进化的**验证 / 评测闭环**(现在全靠人手晋升) |
| **并行执行** | 按项目隔离、uv 环境按文件夹 | **同时运行的调停**:文件竞争、任务抢占、加锁——这块几乎空白 |
| **经验共享** | `memory/MEMORY.md`(单一文件) | 并行写入时**不冲突**的共享记忆结构 |

**最大的盲点是"并行"。** N 个 agent 同时写同一个 `MEMORY.md` 必然冲突。`agentos`(每个 agent 独立 VM、无共享状态)和 `sepo`(经 GitHub 异步协作)这两份已有笔记,都没有直接解决"在一个本地文件 OS 上,N 体同时跑、还要即时共享经验"这个问题。**这才是本次的主战场。**

---

## 二、改进建议(按目标拆,且守住"克制"原则)

### 1. 并行执行 —— 纯文件方案也能解决(最高优先级)
- **每个 agent 一个 git worktree**(本 harness 自身就有 `isolation: worktree` 这套机制):各自隔离、零文件冲突地并行,跑完再合并。
- **"一文件 = 一个 agent/run"原则**:不要让所有 agent 都往共享 `MEMORY.md` 写;每个 agent 只往 `runs/<run-id>.md` **追加(append-only)**,再由某一体定期把**耐用知见**蒸馏进 `PROJECT_MEMORY.md`。这正是把 sepo 的"机器确定性写的原始记录 ↔ 人 curate 的 Markdown"物理分离,搬到研究场景。
- **轻量任务台帐**:`memory/tasks.md` 里用"追加一行 claim 即认领"的最小租约方式(无需数据库、无需锁服务器)。

### 2. 经验共享 —— 用"追加专用的研究流水"做底座
- 落地 sepo 笔记里已提到的 **`daily/YYYY-MM-DD.md` / `runs/` append-only 日志**。它既是"并行不冲突的共享经验"的物理底座,又补上了 Task 层→Project 层蒸馏链路缺的那块"原始底座"。

### 3. 自我进化 —— 给 skill 进化加验证闸
- 现在的晋升是人手。在这里加一个 **eval / 验证闸**,它就变成"自我进化":**只有通过验证的 skill 才晋升进 hub**。手本见下表的 EvoAgentX / GenericAgent / SkillFoundry。

### 4. 长时间运行 —— 先抄"边界",再谈自治
- 照 sepo 笔记的结论:**抄自治之前先抄边界**。给每个研究目标先固定 `成功标准 + 最大轮数 + 停止条件`。

## 四、推荐路线:现在做的一小步 vs 远期

守住 `INSTRUCTION.md` 的克制原则的话,**当前只该做"并行的地基",自主循环留到远期**:

1. **现在(无需数据库 / 服务器)**:`runs/` append-only 日志 + "一文件=一 run"记忆 + git worktree 并行。这样"并行执行 + 经验共享"就能无冲突成立。
2. **下一步**:给 skill 晋升加一个验证闸(="自我进化"最小版),手本为 GenericAgent / EvoAgentX。
3. **远期(需明确确认)**:自主编排层(sepo 的边界模型 + Arbor 的 hypothesis-tree)。

## 一句话总结

这四个目标里,"长时间运行 / 自我进化 / 经验共享"都能在你已有的记忆层、skill 晋升、handoff 上**结构化加深一点**就成立;真正的新硬骨头是**并行**——而它在本地文件 OS 上的正解,就是"**每 agent 一个 worktree + 一文件一 run 的 append-only 记忆 + 定期蒸馏**",本质仍是把 sepo 的"机器原始记录 ↔ 人 curate 记忆"分离原则贯彻到底。先把这块地基铺好,再谈自治。
