# Q1 Problem Definition

* **Input (X):** raw market data at the target frequency (hourly OHLCV for a seven-stock equity universe; minute-level OHLCV, funding rates, and open interest for BTC/USDT), plus published prior literature that alpha agents may draw on for factor design; LLM agents are never given evaluation-window prices, returns, or labels.
* **Output (Y):** a sequence of trading actions (position weights or buy/sell/hold decisions) produced by a nine-role agent pipeline (planner, orchestrator, alpha, risk, portfolio, backtest, execution, audit, and memory agents), realized as backtested equity curves and standard performance metrics (cumulative/annualized return, volatility, Sharpe ratio, maximum drawdown).
* **Core problem:** building an effective algorithmic trading (AT) system traditionally requires a professional team developing and testing over years. The paper proposes replacing that team's division of labor with an agent for each AT-pipeline stage, coordinated by standardized inter-agent protocols instead of bespoke integration code, with the explicit goal of "democratizing financial intelligence to the general public."
* **Scope:** two homegrown, in-house backtested demonstrations — a static seven-stock hourly equity portfolio and a BTC/USDT minute-frequency strategy — presented as a proof-of-concept for the orchestration architecture, not a general benchmark, live-trading deployment, or comparison against other LLM-agent trading systems.

# Q2 Problem Novelty

Multi-agent LLM trading systems already exist and the paper's own Appendix C benchmarks itself against six of them by GitHub activity — TradingAgents (already in this wiki), AI Hedge Fund, ContestTrade, QuantAgent, Alpha Arena, and StockAgent — rather than claiming to be first. Its distinctive claims are architectural rather than algorithmic: (1) an exhaustive, one-to-one mapping of every classic AT-pipeline stage (data, alpha, risk, portfolio, backtest, execution, audit, plus a planner/orchestrator/memory control layer) onto a named agent role, broader than the role sets used by the compared frameworks (TradingAgents uses four analyst types plus researcher/trader/risk roles; AI Hedge Fund uses 18 undifferentiated agents; QuantAgent uses 4); (2) standardized, protocol-level communication — the Model Context Protocol (MCP) for orchestrator-to-agent-pool control messages, and the Agent-to-Agent protocol (A2A) for both agent-to-memory persistence and peer-to-peer coordination — treated as an infrastructure choice rather than ad hoc message passing over shared context; (3) a leakage-prevention design threaded through every layer as a first-class architectural concern: LLM agents draft factor *structures* from published literature only, all numerical computation runs in tool modules the LLM never inspects the raw evaluation-window output of, and a UUID-indexed memory layer stores only aggregated, non-invertible summaries. None of the six comparison systems in the paper's own table is documented as treating leakage prevention as an explicit protocol-level design axis in this way.

# Q3 Scientific Hypothesis

If each stage of a traditional algorithmic-trading pipeline is mapped onto a specialized agent role, coordinated through standardized protocols (MCP for orchestrator control, A2A for agent-to-agent and agent-to-memory communication) with a memory agent that persists only leakage-safe structural summaries, then the resulting agentic system should reproduce professional-grade, auditable algorithmic trading behavior from off-the-shelf LLMs and published literature alone — achieving competitive risk-adjusted performance (Sharpe ratio, volatility, maximum drawdown) relative to passive benchmarks, without a dedicated engineering team and without evaluation-window market outcomes ever reaching an LLM-facing prompt.

* **General multi-agent LLM foundations.** ReAct (reasoning-and-acting), Toolformer (self-taught tool use), Generative Agents, Reflexion (reflection and memory), CAMEL (role-based multi-agent coordination), and AutoGen supply the general agent-design vocabulary the framework composes rather than a finance-specific contribution.
* **Prior financial LLM-agent systems it maps itself against (Appendix C, by GitHub stars/forks at the time of writing):** TradingAgents (24,800★/4,600 forks per this paper's own snapshot — a smaller count than this wiki's TradingAgents note reports from a later HF listing, consistent with rapid star growth over 2025-2026), AI Hedge Fund (42,300★/7,500 forks, 18 agents), ContestTrade (465★/124 forks, event-driven factor portfolio), QuantAgent (306★/71 forks, technical/pattern analysis), plus Alpha Arena and StockAgent as smaller comparators. Five of the six expose some form of persistent memory and the three most-starred projects all expose explicit multi-agent orchestration — the paper reads this as the field converging toward its own architectural choices.

# Q5 Key Solution Idea

1. **Nine-role AT-to-agent mapping.** A planner and orchestrator sit above five stage-specific agent pools — data, alpha, risk, portfolio, and execution — plus backtest, audit, and memory agents, mirroring Figure 1's explicit component-by-component translation of a traditional algorithmic-trading system into agent roles.
2. **Two-protocol communication design.** MCP exposes each agent pool as a tool-like endpoint with a unified request-response schema; the orchestrator sends compact control messages (node type, task id, declared inputs with schemas, policy flags, timeout, retry budget), tracks health via heartbeats, and monitors completion. A2A handles two distinct jobs: agent-to-memory exchange (reading prior context, uploading logs and key results so state and rationale persist across runs) and intra-pool peer coordination via typed messages (ask, tell, propose, confirm) with role tags and context ids; if a collaborator fails, a peer can take over or the orchestrator reassigns the task, and all peer exchanges are timestamped and stored for replay and audit.
3. **LLM/numerical-computation separation as the leakage barrier.** Alpha agents propose factor *structures* from prior published literature only and never access evaluation-window data; all numerical signal construction, forecasting, and diagnostics (e.g., rank-IC) run in deterministic tool modules whose raw output is never exposed to the LLM. Only the Backtest Agent is permitted to load data belonging to the evaluation window at all.
4. **Structured, leakage-excluding context protocol (Appendix E).** Every inter-agent message is a JSON object `C = {task_id, agent_role, run_mode, time_window, universe, inputs, tool_outputs, diagnostics, uuid}` with `run_mode ∈ {train, test, live}`; each message categorically excludes raw test-period price/return series, future-timestamp labels, and any optimization objective tied directly to the evaluation window (e.g., test-set Sharpe ratio). Numerical arrays are referenced by dataset ID rather than inlined.
5. **UUID-indexed, leakage-safe memory (Appendix F).** Each memory entry's UUID is `SHA256(role ∥ task ∥ params ∥ time)`, giving immutability (entries referenced only by hash), identity matching (compatible past states are retrievable across orchestration cycles), safe retrieval (downstream agents receive only summarized metadata, never raw test-set values), and isolation (separate UUID namespaces for training and evaluation memory). Stored entries take the form `{uuid, agent_role, plan_step, features_hash, metrics_summary, timestamp}` and never contain raw prices, returns, or full P&L paths.
6. **One plan graph reused across markets.** The equity and BTC pipelines share the same DAG topology and message schema; only data sources, decision-clock granularity, and risk-gate thresholds differ. The BTC pipeline (Appendix B) adds a concrete, fully specified strategy: 100+ engineered features (momentum, mean-reversion, breakout, volatility-regime, and trend features across eight horizons), an XGBoost regressor retrained every 24 hours on a rolling 7-day window with a strict feature-timestamp/label gap to prevent leakage, a regime-conditioned blend of model prediction and price-action rules (the model's weight rises from 0.10 to 0.40 as its own confidence score increases), and layered risk controls (drawdown-triggered position cuts at 1%/2%/3% thresholds, a volatility-scaled stop-loss, and a hard −3% max-drawdown kill switch).

# Q6 Experiment Design

Two backtests share one orchestration pipeline, differing only in data source, horizon, and rebalancing schedule. **Equities:** a static seven-stock universe (AAPL, MSFT, GOOGL, JPM, TSLA, NVDA, META), hourly bars from Polygon and yfinance, walk-forward from 09/2022 to 01/2025 with GPT-4o drafting factor lists from published literature only (no test-period exposure); the reported headline window is 24/04/2024–31/12/2024 with a 3-month scrolling training window; baselines are SPY, QQQ, IWM, VTI, and an equal-weighted (EW) portfolio rebalanced weekly. **Cryptocurrency:** BTC/USDT minute bars over a 17-day window (27/07/2025–13/08/2025, roughly 23,500 one-minute observations) with a 7-day scrolling window, the XGBoost-plus-regime-rules strategy described above, and a Buy&Hold baseline. Metrics: Total/Annual Return, Volatility, Sharpe Ratio (risk-free rate set to zero given the short evaluation horizons), and Maximum Drawdown for both markets; the crypto backtest additionally reports Calmar ratio, win rate, trade count, and average/median holding time.

# Q7 Datasets and Code

No new public benchmark dataset is released; the equity backtest uses commercially available hourly bars from Polygon and yfinance, and the crypto backtest uses Polygon minute-level OHLCV, funding-rate, and open-interest data — both proprietary data feeds rather than a redistributable static dataset. Code is released at [github.com/Open-Finance-Lab/AgenticTrading](https://github.com/Open-Finance-Lab/AgenticTrading) (573 GitHub stars per HF metadata at the time of this note). Appendix C independently profiles six other open-source agentic-trading repositories (stars, forks, license, market coverage, agent count, and memory/orchestration features) as a form of community-activity related work rather than an empirical backtest comparison.

# Q8 Evidence Quality

This note is built from the full arXiv HTML text (Abstract, §1 Introduction, §2 Proposed Framework for FinAgent Orchestration including 2.1–2.2, §3 Homegrown Trading Examples including 3.1–3.2, Table 1, and Figures 2–3, §4 Conclusion, and Appendices A–G) via `hf papers read`, which returned full content for this paper (unlike ASI-Bench and Recuris in this wiki, whose very recent submissions returned only placeholder pages). One evidence-quality point the paper does not self-flag deserves emphasis: Table 1 shows the memory-less, LLM-free equal-weighted (EW) benchmark achieves the *highest* total return in the entire comparison (47.46%, Sharpe 3.37) — more than double the paper's own agentic system (20.42%, Sharpe 2.63) and every ETF baseline. The paper accurately reports this number in its own table but frames its headline comparison against the S&P 500 (15.97%) rather than against EW, and characterizes its own result as "risk-controlled" (lowest volatility at 11.83%, smallest max drawdown at −3.59%) rather than return-maximizing — an honest framing, but one that leaves unaddressed whether the nine-agent architecture's benefit over EW is separable from a much simpler rule-based risk overlay that a non-agentic system could apply directly to the same EW weights. Other gaps: neither backtest reports confidence intervals, multiple random seeds, or repeated-run variance (unlike, e.g., ASI-Bench's mean±std across three runs elsewhere in this wiki); the BTC evaluation window is only 17 days, and unlike TradingAgents' equivalent ~3-month-window caveat, this paper does not flag its own window length as a limitation; and despite Appendix C's detailed community-activity comparison against six other agentic-trading systems, no empirical backtest is run against any of them — only against passive/rule-based baselines and the paper's own EW portfolio.

# Q9 Contributions

1. FinAgent, an orchestration framework mapping all nine stages of a traditional algorithmic-trading pipeline (planner, orchestrator, data/alpha/risk/portfolio/backtest/execution/audit agents, plus a memory agent) onto coordinated LLM agents rather than bespoke pipeline glue code.
2. A two-protocol communication design — MCP for orchestrator-to-agent-pool control, A2A for agent-to-agent and agent-to-memory exchange — presented as reusable infrastructure for agentic finance systems generally, not tied to this paper's specific strategies.
3. A protocol-level leakage-prevention design threaded through context messages (categorical exclusion of test-period data/labels/evaluation-tied objectives), role restrictions (only the Backtest Agent may load evaluation-window data), and a SHA-256-UUID-indexed memory layer that stores only aggregated, non-invertible summaries in separate training/evaluation namespaces.
4. Two working, cross-market demonstrations (seven-stock hourly equities; BTC/USDT minute crypto) sharing one plan graph and message schema, showing the architecture generalizes across asset classes and trading frequencies via data-source and risk-gate changes alone.
5. A fully specified, reproducible BTC/USDT strategy (Appendix B) — 100+ engineered features, rolling-retrained XGBoost forecasting, regime-conditioned signal blending, and multi-layer drawdown/volatility risk controls — offered as implementation detail supporting the framework claim rather than a standalone algorithmic contribution.
6. A quantitative survey of six open-source agentic-trading GitHub projects by community activity, used as indirect evidence that the field is converging toward multi-agent orchestration and persistent memory as standard features.

# Q10 Next Steps

The paper's own stated future work: longer backtesting horizons and additional markets; ablations on gating, memory, and messaging design choices (none are reported in this version); adaptive planner updates under market regime shifts; broader information sources for signal construction beyond published literature; and releasing benchmarks and logs for replication. This note adds one question the paper's own Table 1 raises but does not address: since its agentic system underperforms the simplest possible baseline in the table (EW, no LLM involved) by more than a factor of two on total return, and the paper's own framing concedes the trade-off is toward risk control, the natural missing experiment is a direct ablation — applying the same drawdown/volatility risk-control rules used inside the agent pipeline directly to the EW portfolio, to test how much of the nine-agent architecture's advantage over EW is actually attributable to agentic reasoning versus a risk overlay that requires no LLM at all.
