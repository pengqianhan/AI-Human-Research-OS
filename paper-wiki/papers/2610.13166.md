# Q1 Problem Definition

* **Input (X):** for the synthesis engine, real-world professional work found in documentation, code repositories, issue reports, and professional materials, plus the set of tasks already accepted and the records of earlier research and review. For the trained agent, the public part of a task package, $\mathcal{P}(T) = (I, E)$: an instruction $I$ and an executable terminal environment $E$.
* **Output (Y):** from the engine, task packages $T = (I, E, S, V, M)$ with a reference solution $S$, a private verifier $V$, and an execution configuration $M$ (the Terminal-Bench package format). From the teacher, multi-turn trajectories in those environments. From training, a model that completes long terminal tasks.
* **Constraints:** the verifier may only check requirements the agent can find in the instruction or discover in the environment (equation 3 in the paper); test data may stay private, but scoring must not add undiscoverable requirements. The whole pipeline is automated.
* **Core problem:** (i) a task can describe investigation, implementation, and verification while the supplied materials already do part of that work, so the collected trajectory skips it; (ii) longer or harder tasks do not by themselves make later work depend on earlier results, which is what the authors mean by behavioral patterns "connecting across stages".

# Q2 Problem Novelty

Terminal-task synthesis for fine-tuning is a crowded line: the paper's Table 1 lists twenty prior models from fourteen systems. The claimed gap is horizon and what the horizon contains. The authors argue that existing synthesizers produce short trajectories that show commands and tool calls but not sustained problem solving, and they describe the target with a taxonomy of 27 "agentic behavioral patterns" in five families (information exploration and judgment; diagnosis and correction; construction and work progression; verification and result establishment; strategy and execution coordination). The closest prior work it names is recursive expansion of reference solutions (RST, Li et al., 2026a), which also lengthens tasks; TerminalHorizon's difference is checking by execution that the intended work is still needed.

# Q3 Scientific Hypothesis

1. **Independent execution exposes work the environment has done in advance.** If an agent that took no part in building a task attempts it with only the public package, and its trajectory is compared with the work the task seed intended, then gaps caused by construction (a bundled solver, a prebuilt recovery path, a decision already supplied) can be found and the task rebuilt so the work is required.
2. **Extending a task under the same goal carries patterns across stages.** If new requirements are made to depend on evidence, artifacts, and state from earlier in the task, the resulting trajectories contain longer chains of feedback-linked actions.
3. **Such trajectories are data-efficient.** If a model is fine-tuned on a few thousand of them, it improves on terminal benchmarks more than models trained on far more short trajectories, and the gain transfers to other agentic tasks without hurting general reasoning.

# Q5 Key Solution Idea

**Stage 1, challenge-guided long-horizon synthesis.** An inner loop per task and an outer loop per batch.

* **Planner Agent.** Reads the accepted tasks and accumulated records and writes research briefs for the next batch: a scope of work, requirements not yet covered, and real-world sources to investigate.
* **Deep Research Agent.** Follows a brief through documentation, repositories, issue reports, and professional materials, and produces a task seed: a draft instruction plus evidence about what the agent must discover, implement, or debug.
* **Construction Agent.** Builds instruction, environment, reference solution, verifier, and configuration together, under the rule that the verifier checks only publicly supported requirements.
* **Independent Challenger.** An agent with no access to the research records, blueprint, reference solution, or private tests attempts the candidate. A synthesis review reads the package, trajectory, and score and records runtime defects, information leakage, scoring inconsistencies, and whether the intended work was preserved.
* **Horizon Gap Analysis and reconstruction.** The seed's intended work is compared with what the challenger did, and omitted work is traced to initial materials, object relationships, or tool behavior. The task is revised and challenged again. The review is meant to separate an efficient solution that still does the work from work the environment completed in advance. Accepted tasks and all records feed the next batch's planning.

**Stage 2, progressive horizon expansion.** An Evolution Agent proposes an extension of an accepted task under the same goal and checks whether the parent's solution already satisfies it. Four content directions: broader roles, deeper mechanisms, richer evidence, and method upgrades. Three interaction designs tie the new work to earlier progress: later decisions depend on evidence gathered by probing; observable tool or system effects link earlier operations to later diagnosis; objects or state vary across runs under a fixed public specification. An accepted child becomes the parent for the next expansion.

**Worked examples from the appendix.** In a radio-interferometric calibration task, the first version shipped `solve-bandpass` and `solve-gain` tools, so the challenger passed by calling them; reconstruction removed the fitting routines and kept inspection and residual feedback, and the next challenger had to implement and revise a fit. A RabbitMQ partition-recovery task took five reconstruction rounds and six challenges, because in intermediate versions the recovery branch existed but the running environment never triggered it. The paper's point from that case: adding a branch adds no work unless execution actually reaches it.

# Q6 Experiment Design

* **Data.** 1,535 task environments in 25 professional domains. Two trajectories per task from DeepSeek-V4-Pro-0813 under the [Terminus 2](../concepts/terminus-2.md) harness, filtered by an LLM reviewer (gpt-5.6-luna, high reasoning effort) on three criteria: trajectory validity, environment-grounded progress, and multi-turn training value. The reviewer does not see the final reward, and failed trajectories are kept when the process is sound. 2,852 trajectories remain (TerminalHorizon-3K).
* **Training.** Full-parameter SFT of Qwen3.5-27B with LLaMA-Factory: learning rate $1\times10^{-5}$, cosine schedule, three epochs, maximum sequence length 262,144, no packing, 144 H20 GPUs. The same recipe is applied to Qwen3.5-35B-A3B and Qwen3.5-122B-A10B.
* **Evaluation.** Twelve benchmarks: Terminal-Bench 1.0 (80 tasks), 2.0 and 2.1 (89 tasks each) through Harbor with Terminus 2, three hours per task, mean pass@1 over three runs; AutomationBench v1.0.6 (600 rollouts, three runs); τ²-Bench Airline and Retail (four runs per task); VitaBench English Cross-domain (100 tasks, Avg@4); MATH-500, GSM8K, AIME 2024, AIME 2025, and KOR-Bench Cipher (three runs).
* **Analyses.** Trajectory statistics against other synthesizers (300 sampled tasks each, same teacher protocol), two teacher models on 100 sampled tasks, three model sizes, a data-scaling curve, per-category Terminal-Bench 2.1 results, and four 12-hour RSI-Exam case studies.
* **Decontamination.** All 1,535 training instructions are compared with 3,251 evaluation instances by exact 13- and 14-gram overlap, 5-gram Jaccard, TF-IDF cosine, and math-aware 8-gram retrieval, and 190 candidate pairs are reviewed by gpt-5.6-luna.

# Q8 Evidence Quality

* **Supported.**
  * *The trajectories are longer.* Mean 52.8 interaction turns and a 90th percentile of 98, above every compared synthesizer under the same teacher protocol (the paper's Figure 4); the longest feedback-linked action chain has a median of 25 turns; trajectories contain 8.6 core patterns on average.
  * *Fine-tuning helps on terminal tasks.* Terminal-Bench 1.0 goes from 46.3 to 55.0, 2.0 from 41.6 to 55.8, and 2.1 from 46.82 to 60.67. On 2.1 the fine-tuned model matches or beats the base in all 16 categories and improves in 11, most in debugging (+46.7 points), data science (+25.0), and machine learning (+22.2).
  * *The gain is not specific to one base model.* Terminal-Bench 2.1 improves by 13.85, 13.11, and 14.98 points for the 27B, 35B-A3B, and 122B-A10B models.
  * *Transfer to other agentic benchmarks.* AutomationBench Pass Rate 5.5 to 17.2 and Partial 26.4 to 49.7; VitaBench 20.5 to 31.8; τ²-Bench Airline 79.0 to 84.5 and Retail 84.9 to 87.5.
  * *Text-level decontamination found nothing.* No exact 13- or 14-gram match, a maximum 5-gram Jaccard of 0.006, and none of the 190 reviewed pairs judged contaminated.
* **Weaker or narrower than the headline.**
  * *The two stages are never ablated.* No model is trained on first-round tasks before reconstruction, on stage-1 tasks without expansion, or on a length-matched set of short trajectories from the same pipeline. The evidence that challenge-guided reconstruction and expansion cause the gain is the case studies in Appendices H and I and the length statistics. The experiments show that this dataset works, not which part of the engine makes it work (reader observation).
  * *"Fewer than one-tenth the data" counts trajectories.* TerminalHorizon-27B scores 55.8 on Terminal-Bench 2.0 with about 3k trajectories against 52.8 for Terminal-Universe-27B with 32.0k, same base model and harness. The trajectories here are several times longer by design and training uses sequences up to 262,144 tokens; token volume is not reported for either, so the comparison does not establish efficiency per token (reader observation). The 3.0-point margin is also a comparison with a number reported by another paper.
  * *The Terminal-Bench 2.0 base score is not the authors' own run.* The 41.6 is marked as taken from the official model card, while the fine-tuned model's 55.8 comes from this paper's protocol (three-hour limit, three runs, Terminus 2 with a JSON parser). The 1.0 and 2.1 comparisons are not marked this way.
  * *The result is also distillation.* Trajectories come from DeepSeek-V4-Pro-0813, whose own benchmark scores are not given; on a 100-task sample it passes 50.0% of these tasks. No control trains on the same teacher's trajectories from another synthesizer's tasks (reader observation). The teacher comparison shows the tasks elicit long trajectories from GLM-5.2 as well (46.1 mean turns against 53.5), but no model is trained on GLM-5.2 data.
  * *The reasoning gains are small-sample.* AIME 2024 and 2025 have 30 problems each, so +3.4 and +6.6 points are about one and two problems, averaged over three runs. "Preserved" is supported; "strengthened" rests on little.
  * *The RSI-Exam studies are four single runs.* In three of four cases the base model stopped on its own after 0.20, 1.12, and 1.28 hours while the fine-tuned model used all 12, so those gains (+27.03, +20.74, +7.71 normalized points) measure persistence together with research quality; the paper treats continuing as the capability being shown. In the fourth, both ran about 11.4 to 12 hours and the base model's submitted solution had lost the macro compression of its best intermediate one (466.35 against a best recorded 286.05 public cost), a delivery failure rather than a search failure.
  * *Data scaling is one curve.* The text says performance rises from 1,000 to about 3k trajectories with no sign of saturation; intermediate values appear only in a figure.
  * *Quality control is model-judged.* The synthesis review, the trajectory filter, and the contamination review are all LLM judgments ([LLM-as-a-judge](../concepts/llm-as-a-judge.md)); no human audit of task quality or of filter decisions is reported.

# Q9 Contributions

* A way to test a synthesized task for work the environment has already done: have an uninvolved agent solve it and compare its trajectory with the intended work, then rebuild. The observation that the first challenger often passes anyway is the useful part: task success does not reveal a hollowed-out task.
* Progressive expansion that ties added requirements to earlier evidence, artifacts, and state.
* TerminalHorizon-3K and three fine-tuned model sizes, with gains on Terminal-Bench and on four agentic benchmarks outside the terminal.
* A 27-pattern vocabulary for describing what a long trajectory contains, and a trajectory filter that judges process without seeing the outcome and keeps informative failures.

# Q10 Next Steps

* **Ablate the engine (reader suggestion).** Train on tasks as first constructed, on reconstructed tasks without expansion, and on the full set, at matched token volume. Without this the engine's two ideas are untested as causes.
* **Report token volume (reader suggestion).** Compare with other synthesizers per training token, not per trajectory.
* **Separate persistence from skill (reader suggestion).** In the RSI-Exam setting, force the base model to use the full budget, or give both models a rule against early stopping, and repeat runs.
* **Audit the judges (reader suggestion).** Sample accepted tasks and dropped trajectories for human review, and report how often the challenger still finds prebuilt work after the final round.
* **From the authors.** The scaling curve shows no saturation, which they read as room for more data.
* **Project fit (reader note).** The challenge step is a cheap check for any agent-written task or evaluation in this repository: before trusting a task, have a fresh agent solve it from the public materials only, and read the trajectory for steps the setup made unnecessary. The RabbitMQ case is the warning that a code path existing is not the same as it being exercised.
