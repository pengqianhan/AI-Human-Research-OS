# Q1 Problem Definition

* **Input (X):** black-box interaction with an unknown, deterministic, goal-directed POMDP $\mathcal{M}=\langle\mathcal{S},\mathcal{A},\mathcal{O},T,\rho,G\rangle$; a frozen LLM; and a budget of $B$ real actions. On ARC-AGI-3 an observation is a 64x64 colour grid, actions are keys and clicks whose meaning is unknown, and the agent gets no task description and no environment source, only a completion signal.
* **Output (Y):** a persistent world-model hypothesis $h_t=(\psi_t,\theta_t)$: a natural-language rulebook $\psi_t$ (objects, action semantics, dynamics, goals, unresolved alternatives) and an executable $\theta_t$ (initialiser, transition predictor, observation function, goal set) that a planner searches for an action sequence reaching the goal.
* **Objective and constraints:** first maximise the probability of reaching a goal within $B$ actions, then minimise the actions used. Every action sent to the environment counts, including exploration, failed attempts, and resets; model construction, simulated rollouts, and replay do not.
* **Core problem:** a finite interaction history leaves a version space of programs that all reproduce the observed transitions but disagree on unseen states ("a box stops at a wall" against "a box stops at column 7"). Replay can reject an inconsistent program; it cannot pick the right rule among consistent ones.

# Q2 Problem Novelty

Not a new problem. Code world models learned from interaction (WorldCoder, GIF-MCTS) and ARC-AGI-3 systems that verify an executable model by replay before planning (Rodionov's baseline1, OPINE-World, Twin, Tycho) already exist, and the paper says so: "Language rules, executable artefacts, reflection, and replay are established components". The difference it claims lies in how these parts are organised. The rule-level hypothesis lives in a rulebook that is separate from the code and constrains it, so a change in understanding must be written as a rule before it is compiled, while an implementation bug can be fixed without touching the rulebook. Within the authors' own series, Memento, Memento 2, and Memento-Skills learn the policy side (episodic memory, reflective learning, executable skills); Memento 3 is presented as the model side.

# Q3 Scientific Hypothesis

1. **A rulebook speeds convergence.** If rule hypotheses are kept in language and code must implement them, the agent reaches an effective executable model with fewer real actions and fewer agent turns than with code alone.
2. **Two-part acceptance keeps planning honest.** If a model is used for planning only when the LLM judges the code faithful to the rulebook *and* exact replay reproduces every recorded next observation, acceptance does not rest on language-model confidence alone.
3. **A population reduces self-confirmation.** A wrong model can stay unfalsified if its own plans never visit the states where it errs. If $N$ models share one interaction history and one is sampled per planning episode, different models steer exploration and the run depends less on one early hypothesis.
4. **The loop is a form of recursive self-improvement.** The rulebook and executable are both what gets revised and what guides the next round of evidence gathering, while the LLM's weights stay fixed.

# Q4 Related Work and Key People

* **World models and code world models.** Dyna, neural latent world models, and a multimodal latent model that treats language as a predictive modality (Lin et al., 2024); Parsel and Hypothesis Search for language-guided program induction; WorldCoder, GIF-MCTS, code world models for general game playing; [Code as Worlds](2608.27549.md) for physical reasoning.
* **ARC-AGI-3 systems.** baseline1 (persistent Python model, simplified and verified before planning) and Rodionov's follow-up component study; OPINE-World (natural-language hypotheses plus an object-centric executable, exploration driven by ontology error); Twin; Tycho (when to build, repair, use, or bypass a model); graph-based exploration without a generative model.
* **Language rules and reflective memory.** [Reflexion](../concepts/reflexion.md), AutoManual, WALL-E, and the Memento series.
* **Uncertainty over models.** Version spaces, minimum description length, ensembles and probabilistic dynamics models, posterior sampling for temporally coherent exploration.
* **Workspaces as learning state.** DreamTeam (Workspace Optimization), Continual Harness, NOOA, Belief-Calibrated Optimization.
* **Key people.** University College London, Huawei Noah's Ark Lab (UK), and the University of Liverpool; Jun Wang is the corresponding author and Haitham Bou-Ammar is among the authors. Likely critics: builders of other ARC-AGI-3 systems, who would ask for matched backbones and held-out games, and model-based RL researchers, who would question the Pong learning-cost comparison.

# Q5 Key Solution Idea

* **Code as Model.** The learning state is $Z_t=(H_t,\psi_t,\theta_t)$: the full interaction record, the rulebook, and the executable. On ARC-AGI-3 these are a Markdown file `world_model.md` and a Python module `world_model_engine.py` that predicts the complete next grid and level completion.
* **Five-stage loop after each real action.** *Observation* appends the transition. *Reflection*: the LLM chooses among `retain`, `revise_rulebook`, and `repair_code`. *Rule revision* edits the rulebook if chosen. *Compilation* produces code from the previous code, the proposed rulebook, and the record. *Verification* accepts the pair only if (a) the LLM judges the source faithful to the rulebook and (b) replay from each trajectory's first observation matches all 64x64 cells of every recorded frame. A rejected proposal returns to reflection.
* **Simplicity preference.** Among admissible pairs the LLM is asked to prefer a shorter rulebook and implementation, which the paper reads as a minimum-description-length prior; each simplification is re-checked.
* **Planning and exploration.** The planner finds a shortest path to the predicted goal in the executable and executes it one action at a time, stopping at the first prediction mismatch. With no goal-reaching plan, the LLM picks an intermediate target (test a mechanic, reveal a region, touch an unexplained object) and an auxiliary planner reaches it.
* **Git memory.** Rulebook and modules live in one repository; the controller commits and tags every iteration, and the agent can diff or restore earlier versions.
* **Population extension.** $N$ rulebook-executable pairs share $H_t$. Members whose plans are identical action sequences form one behavioural class; a class is sampled uniformly per planning episode; every real transition is checked against all members and falsified members are repaired. The paper calls this a computational approximation to the remaining version space, not a calibrated posterior.

# Q6 Experiment Design

* **ARC-AGI-3 main result.** All 25 public games (183 levels). The harness starts from the baseline1 codebase and runs in Claude Code with Claude Opus 5 at extra-high reasoning effort, $N=1$. Metric: Relative Human Action Efficiency (RHAE, ceiling 100), which weights later levels more and caps per-level efficiency $(h_\ell/a_\ell)^2$ at 1.15. Baselines are five community-leaderboard entries with papers (baseline1, NOOA, OPINE-World, DreamTeam, Continual Harness); their numbers and the human action counts come from official ARC Prize scorecards.
* **Rulebook ablation.** The rulebook is removed from the update loop, leaving a code-only world model with harness, verifier, executor, backbone, and effort unchanged, on one game per difficulty band (ft09, ka59, cn04, at 35, 104, and 132 human actions per level).
* **Population.** $N=2$ against $N=1$ on wa30, the game with the largest human action baseline.
* **Atari Pong case study.** Arcade Learning Environment, frame-skip 4. The level planner is replaced by a feedback policy that queries the learned model; learning stops once a checkpoint wins 21:0; the fixed controller is then scored on three episodes with different openings and no LLM calls. Baselines: the same LLM choosing each action from the two latest frames with no memory, a random policy, and published model-free (GDI, LASER, IMPALA, Rainbow) and model-based (EfficientZero, EfficientZero V2) results.

# Q7 Datasets and Code

Evaluation uses the public ARC-AGI-3 set and ALE Pong; no new dataset. The paper text and the Hugging Face paper page give no code repository, and the rulebooks and executables are shown only as figure excerpts (sc25, tr87, Pong). Reproduction depends on a hosted model (Claude Opus 5) and on the baseline1 codebase the harness was built from. The paper reports no token, time, or dollar cost, though it gives "substantial time and monetary cost" per run as the reason the ablations cover so few games.

# Q8 Evidence Quality

* **Supported.**
  * *Full clearance at the efficiency ceiling.* 25 of 25 games, 183 of 183 levels, mean RHAE 100.0, 7,518 actions against 17,135 for the human baseline (0.44; per-game ratio 0.20 on m0r0 to 0.67 on lf52, median 0.42), every game below its human count.
  * *Ahead of the listed baselines.* baseline1 99.0 (25 games, 8,347 actions, 0.49 of human), NOOA 85.1 (19 games), OPINE-World 78.4 (20), DreamTeam 38.1 (6), Continual Harness 20.5 (3). The paper also states a 59.3-point lead in mean RHAE over Claude Opus 5 with the ARC Prize Standard harness.
  * *Pong.* The learned controller wins 21:0 in all three scored episodes (3,358, 4,014, and 5,039 actions); the same LLM without a world model scores -19 and random play -20.7.
* **Weaker or narrower than the headline.**
  * *The margin over the closest system is small.* baseline1, whose codebase this harness starts from, also clears every game; the difference is 1.0 RHAE point, from two games (sc25 84.2 and tn36 90.1), and about 10% fewer actions (reader arithmetic from Tables 1 and 2). Baseline numbers are scorecard values under each system's own backbone and budget, not matched reruns.
  * *The public set is close to saturated, by the paper's own account.* Its related-work section notes that Tycho and Rodionov's component study report saturation or near-saturation with stronger frontier models, that public-set completion "cannot isolate the contribution of a world-model architecture", and that comparisons should examine model choice, reasoning budget, repeated-run stability, and held-out evaluation. The paper reports the public set only, with no repeated runs or held-out games.
  * *The rulebook ablation is three games.* With the rulebook: 617 actions and 678 agent turns; without: 677 and 830 (9% and 18% fewer). Per game the action differences are 75 against 79, 341 against 382, and 201 against 216. Both arms reach RHAE 100, no spread is reported, and the authors write that the results "suggest" faster convergence.
  * *The population result is one game at $N=2$.* wa30 drops from 899 to 597 scored actions (0.66x), with eight of nine levels equal or better and level 8 worse (130 to 138). The extra LLM work of maintaining two models is not reported.
  * *The Pong cost comparison counts only environment frames.* 9,504 frames against 2.0x10^8 for the model-free baselines and 4.0x10^5 for EfficientZero (the paper's ratios: about 2.1x10^4 and 42). LLM compute during learning is outside this measure, the published baselines follow their own protocols, learning was stopped on the same 21:0 criterion that is then reported, and the LLM draws on pretrained knowledge of the objects and dynamics, as the paper notes. Exact replay is also relaxed here: "Full-frame replay retains residual rendering and paddle-motion errors."
  * *Rulebook fidelity is an LLM judgement.* The same frozen LLM writes the rulebook, compiles it, and judges whether the code is faithful; the paper gives no rate at which that judgement is wrong, and no count of how often each reflection choice or a rejection occurred.

# Q9 Contributions

* Code as Model: a persistent rulebook plus its executable realisation as the agent's world-model memory, revised by a loop of observation, reflection, rule revision, compilation, and verification with the LLM frozen.
* An acceptance rule that pairs an LLM fidelity check with exact replay against the whole interaction record.
* A shared-history population of world models with sampling over behaviourally distinct plans.
* A definition of model-based recursive self-improvement, with a Bayes-adaptive POMDP formulation in which the single model is a point belief and the population an empirical one.
* ARC-AGI-3 results (all 25 public games at the RHAE ceiling with 44% of human actions) and a Pong case study with a controller that runs without LLM calls.

# Q10 Next Steps

* **From the authors.** The paper has no limitations section. Its closing related-work paragraph names what comparisons on ARC-AGI-3 should cover: model choice and reasoning budget, action efficiency, repeated-run stability, and held-out evaluation.
* **Matched controls (reader suggestion).** Rerun baseline1 with the same backbone and effort; repeat each ablation several times and on more games; report LLM tokens and wall-clock next to actions, since action counts exclude all model-construction work.
* **Measure the fidelity judge (reader suggestion).** Log how often code passes replay but fails the fidelity check and the reverse, and audit a sample by hand; this is the one acceptance step with no execution behind it.
* **Raw history against distilled rules (reader suggestion).** [Learn2Play Bench](2610.08215.md) finds that distilled lessons can lock in a wrong rule while raw histories let agents revise it. Memento 3 keeps both, the full record and a rulebook that must replay against it, which is one design answer to that failure; running it on Learn2Play's hidden-rule games would test the answer away from ARC-AGI-3.
* **Project fit (reader note).** The split between a rulebook stating what is believed and code stating how it is applied, with every revision committed so earlier hypotheses can be diffed or restored, resembles this repository's Git-tracked memory files; the paper's rule that a change of understanding is written down before the implementation changes is a usable convention for agent-maintained instructions.
