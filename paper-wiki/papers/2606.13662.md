# Summary

This paper introduces EurekAgent, an environment-engineered system for metric-driven autonomous scientific discovery. Instead of prescribing a specialized research workflow, the system coordinates off-the-shelf CLI agents through a prepare-propose-implement loop while shaping the surrounding environment: permissions, artifacts, budgets, and human oversight.

The central claim is that, as general-purpose coding agents become stronger, the bottleneck shifts from designing agent behavior to designing the environments that make autonomous research reliable, inspectable, resource-bounded, and hard to game.

# Key Ideas

* Treat environment engineering as the main control surface for autonomous scientific discovery.
* Use permissions engineering to expose useful tools while protecting hidden evaluators, official result files, GPU allocation, and same-round peer isolation.
* Use artifact engineering to make filesystem state, Git history, ranked solutions, logs, and evaluator feedback into shared long-term memory.
* Use budget engineering for wall-clock and API-cost limits, stage deadlines, resumability, and controlled continuation.
* Keep humans in the loop through a terminal UI and web monitor without requiring manual steering at every step.

# Method

EurekAgent receives a problem description, hidden evaluation code, a submission specification, optional initial code, and budget settings. It runs one prepare stage, then repeats proposal and parallel implementation stages for a configured number of rounds.

The proposal stage reads prior artifacts and generates diverse hypotheses. Each implementation session gets its own workspace, iterates against a secure evaluator, and cannot inspect same-round peers. The controller ranks valid submissions and carries prior-round artifacts forward as shared context.

# Experiments

The paper evaluates EurekAgent with Claude Code as the CLI agent and GLM-5.1 as the base model across mathematics, kernel engineering, and machine learning engineering.

* Mathematics: reports new state-of-the-art results on 26-circle packing, Erdos minimum overlap, and the first autocorrelation inequality while remaining training-free.
* Kernel engineering: reports a best TriMul median runtime of 2005.03 microseconds under a local A100 evaluation, outperforming regraded leaderboard solutions and TTT-Discover in the reported setup.
* Machine learning engineering: reports an 85.71 percent any-medal rate on a seven-task MLE-Bench Lite subset, above listed baseline rates on that subset.
* Cost: reports all three mathematics runs below $17 average API cost, with the 26-circle packing result below $11 total API cost.

# Limitations

The evidence is strongest for metric-driven tasks with executable evaluators. Broader scientific settings with less formal objectives may need different evaluation, provenance, and human-review mechanisms.

The MLE-Bench result is on a selected seven-task subset rather than the full benchmark, and the TriMul leaderboard comparison is based on local regrading because the official competition was closed.

# Notes

Reading questions:

* Which environment controls are general enough to transfer into this research OS, especially hidden evaluators, durable artifacts, and budget-aware continuation?
* How should the system distinguish legitimate web/literature reuse from copying a public solution too directly?
* Can OKF paper-library maintenance use the same environment-engineering frame: artifacts as memory, validation as evaluator, and topic pages as supervised shared context?
