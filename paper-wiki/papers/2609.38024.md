# Q1 Problem Definition

* **Input (X):** a frozen language model M, an execution harness h (tools, file access, observation interface, interaction budget, scoring rule), a task description T and a harness description H, disjoint train / validation / test task splits, and an external corpus C of public skill documents (GitSkills) split into heading-delimited sections.
* **Output (Y):** a natural-language skill document s* that, placed in the agent's context, maximizes expected reward on the validation split and is then scored on the held-out test split. The paper folds the construction of the *initial* skill into the optimization problem instead of assuming one is supplied.
* **Core problem:** existing skill optimizers (TextGrad, GEPA, SkillOpt, WikiSkill) refine a skill only from the agent's own rollouts, so procedural knowledge the agent cannot infer from its own failures stays out of reach and every improvement costs rollouts. Millions of shared skills already encode such knowledge, but they were written for other tasks and harnesses: on SpreadsheetBench, 92.9% of retrieved skills come from a different harness (Figure 1), so reusing them verbatim can hurt.
* **Constraint:** M and h stay fixed; the skill text is the only decision variable. Candidate skills are accepted only if they beat the incumbent on the validation split.

# Q2 Problem Novelty

The subproblem is new in framing rather than in parts. Skill optimization from execution experience (SkillOpt, SkillOpt-Lite, WikiSkill, Trace2Skill, SkillGrad, EvoSkill) and skill construction from external knowledge (SkillRouter, SkillFlow, Graph-of-Skills, Anything2Skill, OpenSkill, Agent KB) are both established lines. The paper's claim is that nobody has used an external skill corpus *throughout* optimization: retrieval-based methods either re-retrieve at test time per task instance or use external knowledge only at initialization, and experience-based optimizers never consult a corpus. It matters because a corpus-grounded initial skill removes the need for rollouts before the first useful skill exists, and because a corpus can supply the missing procedure behind a diagnosed failure rather than relying on the optimizer model's parametric guess.

# Q3 Scientific Hypothesis

If (a) relevant procedural knowledge is retrieved at the section level from a large skill corpus, (b) each retrieved section is rewritten into a lesson expressed only in the objects, commands, and units of the target harness (dropping domain nouns, procedures without counterparts, and tool claims not corroborated by the harness description), and (c) this retrieve-and-adapt step is applied both before any rollout and inside each rollout-driven update, then the resulting skill will outperform skills built from the optimizer's parametric knowledge alone and skills retrieved without adaptation, on the same rollout budget, and the two stages will contribute separately.

# Q4 Related Work and Key People

* **Skill optimizers (baselines):** TextGrad (textual gradients), [GEPA](../concepts/gepa.md) (reflective mutation with a Pareto front), [SkillOpt](2605.23904.md) (bounded add/delete/replace edits with a validation gate), WikiSkill (co-evolving skill and wiki of failure modes). The paper reports its own reruns of each.
* **Skill retrieval and construction:** SkillRouter (bi-encoder retrieve, cross-encoder rerank; used as the retrieval-without-adaptation baseline), SkillFlow, SkillLens, Graph-of-Skills, SkillRAE, SE-GoS, GraSP, SkillRet, Anything2Skill, OpenSkill, Agent KB.
* **Corpus:** GitSkills (Destefanis et al., 2026, arXiv:2608.10906), a dataset of agent skills crawled from GitHub.
* **Wiki neighbors:** [SkillOpt-Lite](2607.03451.md) and [Code2Skill](2609.05571.md) also optimize or mine skills; [Raven](2609.33439.md) retrieves at most two skills per task from a crawled catalog (SkillCorpus) at inference time, the "repeated retrieval per task instance" alternative RASO positions itself against.
* **Key people:** Hyunwoo J. Kim (KAIST, corresponding) with students at KAIST and Korea University (first author Jaewon Chu, also behind AgentGrad); Yunyang Xiong (Meta AI).

# Q5 Key Solution Idea

* **Section-level BM25 retrieval.** Skill documents are split at headings; a query-generation agent writes a query and BM25 returns the top K = 5 sections. Retrieving sections rather than whole documents is meant to surface a relevant procedure buried in a skill with a different overall goal.
* **Cross-Harness Adaptation.** An adaptation agent receives a requirement c_i (a task procedure in RASI, a textual gradient in RASU), T, H, and the retrieved sections, and emits one concise lesson under three rules: strip domain-specific nouns and procedures with no counterpart in the target harness; address only c_i; keep specific tool or parameter claims only when H corroborates them. The Figure 5 example rewrites a satellite-imagery skill's "skip empty groups" rule into "treat the output as missing" for a spreadsheet task, which fixes an index shift the retrieval-free run makes.
* **RASI (initialization, zero rollouts).** From T and H, generate M requirement-query pairs, retrieve and adapt a lesson per requirement, then have a skill-initializer agent write s_0 with each lesson attached to its step. The retrieval-free control (RFSI) runs the identical pipeline minus retrieval and adaptation, so the gap isolates the retrieved knowledge.
* **RASU (update, with rollouts).** Roll out a minibatch of 40 training tasks with s_t, have a generator read failed trajectories in chunks of 8 and emit (textual gradient, retrieval query) pairs that one merge call deduplicates, retrieve and adapt a lesson per pair, and have an updater produce s_{t+1} from s_t, the gradients, and the lessons; accept only if validation reward improves. Two epochs over the training split.
* **Leakage control.** Repositories matching a benchmark's name or its source datasets are removed from the corpus wholesale before indexing. T and H are written once per benchmark by a coding agent (codex) reading the harness code, without test instances, and reused across methods, models, and seeds.

# Q6 Experiment Design

* **Benchmarks and splits (train / val / test):** OfficeQA 50 / 24 / 172 (246 numeric questions over about 89,000 pages of U.S. Treasury Bulletins); SpreadsheetBench 80 / 40 / 280 (online-judge style, multiple test workbooks per task); ALFWorld 39 / 18 games, 134 out-of-distribution evaluation games; WebShop 80 / 40 / 500. Splits follow SkillOpt.
* **Models:** GPT-5.6-Luna (reasoning effort low) and Qwen-3.5-9B (vLLM on one RTX A6000; temperature 0.0 for rollouts, 0.7 for the optimizer). The same model plays target and optimizer in every method.
* **Comparisons:** initialization at zero rollouts (No skill, SkillRouter, RFSI, RASI); update methods starting from RFSI as in prior work (TextGrad, GEPA, SkillOpt, WikiSkill) against RASO; the four update methods under a fixed RASI initialization (Table 4 for GPT, Table 6 for Qwen); RASU under a fixed RFSI initialization (Tables 7-8).
* **Ablations (GPT-5.6-Luna, OfficeQA and SpreadsheetBench):** 2x2 over initialization and update (Table 2); adaptation on or off in each stage (Table 3); K in {1, ..., 10}; corpus fraction from 0% to 100%.
* **Reporting:** mean ± standard error over three seeds; API cost and rollout counts per method (Tables 9-10).

# Q8 Evidence Quality

* **Supported:**
  * *Initialization without rollouts helps on every cell.* GPT-5.6-Luna: RASI 45.74 / 49.17 / 72.64 / 45.06 against RFSI 40.11 / 44.40 / 69.40 / 43.89 and No skill 11.44 / 32.98 / 64.43 / 43.56 (OfficeQA / SpreadsheetBench / ALFWorld / WebShop). Qwen-3.5-9B: RASI 40.50 / 30.48 / 47.76 / 23.27 against RFSI 34.89 / 27.74 / 42.04 / 12.54.
  * *Unadapted retrieval can hurt.* SkillRouter sits at or below No skill on most cells (ALFWorld 55.97 vs 64.43 with GPT; WebShop 9.42 vs 16.27 and SpreadsheetBench 23.45 vs 28.81 with Qwen).
  * *Full method beats the baselines as they are normally run.* GPT: RASO 49.03 / 63.33 / 74.13 / 46.61 against the best baseline 45.54 / 57.02 / 72.64 / 45.54. Qwen: 42.25 / 31.55 / 51.00 / 24.73 against 37.40 / 29.76 / 43.53 / 13.43.
  * *The two stages are separable and additive.* From RFSI+RFSU (40.70 / 51.67), swapping in RASU gives 47.56 / 61.07, swapping in RASI gives 45.93 / 58.45, and both give 49.03 / 63.33. Adaptation alone accounts for +3.88 / +7.74 in RASI and +2.33 / +5.47 in RASU.
  * *Update advantage survives a matched initialization.* With every update method started from RASI (GPT), RASU 49.03 / 63.33 against SkillOpt 46.51 / 60.24, WikiSkill 47.09 / 55.00, GEPA 45.74 / 58.69, TextGrad 43.41 / 57.97. With Qwen under RASI, the retrieval-free updaters gain at most +0.59 and three of four fall below the initial skill on OfficeQA, while RASU adds +1.75 / +1.07.
  * *Cost.* At two epochs RASO uses the same rollouts as TextGrad and WikiSkill (196 / 320 / 114 / 360) and fewer than GEPA and SkillOpt, and its GPT-5.6-Luna API cost ($0.84 / $0.49 / $0.79 / $10.28) is lowest on three benchmarks and within $0.06 on the fourth.
  * *Retrieval settings.* K = 5 is best on both ablation benchmarks and K = 10 slightly degrades; 1% of the corpus already beats no corpus.
* **Weaker or bounded:**
  * *The headline Table 1 comparison is not initialization-matched.* Baselines start from RFSI while RASO starts from RASI, so the main-table gaps combine both stages; the matched comparison (Table 4) shrinks RASO's lead to +1.94 over WikiSkill on OfficeQA and +3.09 over SkillOpt on SpreadsheetBench (reader note).
  * *Small margins relative to error.* Several gains are within about two standard errors: WebShop with GPT (46.61 ± 0.11 vs GEPA 45.54 ± 0.35) and the Qwen SpreadsheetBench update gains (31.55 ± 0.31 vs 30.48 ± 0.78 initial). The clear wins are OfficeQA and SpreadsheetBench with GPT and ALFWorld and WebShop with Qwen (reader note).
  * *Small validation splits.* Acceptance decisions ride on 24 OfficeQA and 18 ALFWorld validation items, so one item moves the gate by 4-6 points (reader note).
  * *Corpus leakage control is keyword-based.* Whole repositories are dropped when a skill names the benchmark or its datasets; a skill that encodes benchmark-specific procedure without naming it would pass (the authors acknowledge this and exclude at repository level to reduce the risk).
  * *Ablations cover two of four benchmarks and one model.* The 2x2, adaptation, K, and corpus-size analyses use GPT-5.6-Luna on OfficeQA and SpreadsheetBench only.
  * *The optimizer and the adaptation agent are the same frontier model.* Whether adaptation needs a strong rewriter is untested; the Qwen runs use Qwen as adapter and show smaller absolute gains.

# Q9 Contributions

* Frames skill optimization as starting from scratch and shows that a corpus-grounded initial skill, built with zero rollouts, beats an LLM-written one on all eight model-benchmark cells.
* Cross-Harness Adaptation as a shared operation: a constrained rewrite of retrieved procedure into the target harness's vocabulary, with ablations showing it is what turns retrieval from harmful (SkillRouter) into helpful.
* Failure-driven retrieval inside the update loop (RASU), which beats four retrieval-free updaters under both matched and conventional initializations, and does so at equal rollouts and lower cost.
* Evidence that the gain comes from diverse external knowledge rather than a few source documents: a 1% corpus already helps and performance rises with corpus size.

# Q10 Next Steps

* **Stated by the paper:** none beyond the conclusion; limitations are not discussed in a dedicated section.
* **Initialization-matched main table (reader note):** report every baseline from RASI as the default, since the paper's own Table 4 shows the fairer comparison and the update-stage margin is the contested claim.
* **Adapter strength (reader note):** cross the adapter model with the target model (strong adapter, small target) to see whether Cross-Harness Adaptation is a cheap one-time cost that lets small targets benefit from frontier-written lessons.
* **Leakage audit (reader note):** sample the retrieved sections that actually entered accepted lessons and check them for benchmark-specific procedure, the gap the keyword blocklist leaves open.
* **Relevance to this repository (reader note):** the repository's skills hub is itself a skill corpus. RASI's recipe, generate requirement-query pairs from a task and harness description, retrieve sections, rewrite them for the target harness, is a candidate workflow for drafting a new project skill from existing hub skills before any run is spent, and the adaptation rules (drop uncorroborated tool claims) match the hub's source-policy concerns.

# Related

* [Agent skill libraries](../topics/agent-skill-libraries.md) - the first paper in this topic to use a public skill corpus as the prior for optimizing one skill, and to show that unadapted retrieval from that corpus can be worse than no skill.
* [Agent self-evolution](../topics/agent-self-evolution.md) - a rollout-driven skill update loop with a validation gate, as in SkillOpt, whose repair proposals are grounded in retrieved external procedure rather than only the optimizer's parametric knowledge.
* [SkillOpt](2605.23904.md) - the strongest retrieval-free updater on SpreadsheetBench in every comparison here; RASO reuses its splits, its chunked gradient generation, and its validation-gated acceptance.
* [SkillOpt-Lite](2607.03451.md) - also optimizes an existing skill from trajectories with minimal patches and an independent validation gate; not compared here.
* [Code2Skill](2609.05571.md) - mines a skill bank from code rather than retrieving from shared skill files; both papers argue that externally sourced procedural knowledge beats what trajectories alone can yield.
* [Raven](2609.33439.md) - its Skill Forge retrieves skills per task at inference time from a crawled catalog; RASO instead folds retrieval into a one-time optimization so no retrieval happens at test time.
* [X-Tree](2609.32993.md) - the opposite answer to where reusable procedure should live: RASO keeps it as adapted text in context, X-Tree mines it from trajectories and trains it into the weights.
* [GEPA](../concepts/gepa.md) - baseline; with GPT-5.6-Luna it is the second-best retrieval-free updater on SpreadsheetBench (54.53) but degrades the initial skill on SpreadsheetBench with Qwen-3.5-9B (24.05 vs 27.74).
* [ALFWorld](../concepts/alfworld.md) - 39 / 18 train / validation games and the 134 out-of-distribution evaluation games; RASO 74.13 (GPT-5.6-Luna) and 51.00 (Qwen-3.5-9B), the latter 7.47 points above the best baseline.
* [WebShop](../concepts/webshop.md) - 80 / 40 / 500 split; RASI's largest initialization gain with Qwen-3.5-9B (+10.73 over RFSI) and RASO's largest update gain (24.73 vs 13.43), while GPT margins are about one point.
* [OfficeQA](../concepts/officeqa.md) - 50 / 24 / 172 split over the 246-question set; RASO 49.03 against 45.54 (SkillOpt) with GPT-5.6-Luna, and the benchmark where No skill and SkillRouter both score 11.44.
* [SpreadsheetBench](../concepts/spreadsheetbench.md) - 80 / 40 / 280 split of 400 tasks; the benchmark with the largest absolute gains (RASO 63.33 vs 57.02) and the one where 92.9% of retrieved skills come from a different harness.
