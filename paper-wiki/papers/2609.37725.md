# Q1 Problem Definition

* **Input (X):** a long-horizon agentic task (deep research, terminal coding, mathematical optimization, repository optimization, or a multi-agent swarm) run under a fixed context budget (32K tokens in most experiments; 272K in the swarm setting), where accumulated history quickly exceeds what fits in the live context.
* **Output (Y):** at every turn, the next context `C_{t+1}` itself. A standard LM only appends its output (`C_{t+1} = C_t ⊕ y_t`, Eq. 1); a Context Language Model (CLM) produces `C_{t+1} = f(C_t, y_t)` where `f` is an arbitrary transformation the model chooses (Eq. 2), alongside the task actions it would take anyway.
* **Core problem:** context management is not a native LM capability. It is either scheduled by a hand-engineered harness (compact at a length threshold, as in Codex, Cursor, or Terminus-2) or exposed as a small, human-defined tool set (compact, offload, retrieve, fold). The paper argues both cap the strategies a model can use, and its pilot benchmark shows each fixed strategy failing on at least one simple task.
* **Constraint:** the implementation must run on existing models zero-shot and stay compatible with standard serving, where any in-the-middle edit invalidates the prefix KV cache and forces re-prefill — so efficiency must be measured with that cost included.

# Q2 Problem Novelty

The problem — keeping a bounded context useful over a long trajectory — is well established. The paper's novelty claim is about the *action space*: it places itself at the end of a progression from harness-scheduled compaction (Codex, MEM1), through model-triggered but predefined tools (Self-Compact, AutoCompact, Context-as-a-Tool, ACM, Sculptor, Context Folding, AgentFold), to full read-write agency over the live context. It also separates itself from [Recursive Language Models](2512.24601.md): RLMs externalize the *input* as a read-only REPL variable but still append retrieved material to a growing live context, while CLMs make the live context (including execution history) editable. The two are presented as complementary. The framing explicitly invokes the Bitter Lesson: let the model search for strategies instead of fixing human priors.

# Q3 Scientific Hypothesis

If a model can rewrite its own live context with general-purpose code (rather than choose among a few predefined context tools or follow a harness schedule), then (a) capable existing models will discover context-management strategies that beat human-designed ones on both accuracy and inference compute (prefix-reuse FLOPs), and (b) because context management becomes an ordinary model behavior, it can be improved like any other skill — through natural-language instructions, evolved skill documents, and reinforcement learning — without changing the harness.

# Q5 Key Solution Idea

**Context as a file.** The live context is mirrored into a file whose path is given in the system prompt. The model edits it with ordinary Bash or Python; edits are synchronized to the server and become the next turn's context. If the model does not edit, generation is appended as usual, which preserves prefix-cache reuse by default. Multi-agent workloads fall out naturally: an agent swarm is several context files, and creating or deleting a file spawns or terminates a subagent.

Around that core the paper builds four supporting pieces:

1. **Prefix-reuse FLOPs** (Eq. 3, App. C): a trajectory-level cost metric that charges decoding, prefill, and the re-prefill caused by any edit under standard prefix caching. This keeps CLM from looking cheap just because its context is short.
2. **In-context learning of strategy** (Eqs. 4–5): an instruction or skill document `s` steers context management; `s` can be evolved with a GEPA-style prompt-evolution loop, using either a stronger proposer (assisted evolution) or the agent itself (self-evolution).
3. **RL with a success-gated efficiency advantage** (Eq. 6): stepwise GRPO broadcasts each trajectory's outcome advantage to all its segments, since edits break the append-only trajectory. An extra advantage ranks *only successful* trajectories in a group by prefix-reuse FLOPs (set to zero if fewer than two succeed), so the model is rewarded for cheap context editing without being paid to discard information.
4. **Suffix Cache Reuse (SCR)** (Sec. 4.3, App. B): an SGLang patch that, after an edit replaces a span, relocates the cached KV states of surviving suffix spans (re-rotating RoPE positions) instead of re-prefilling them, capping relocated spans per edit at `k`. Reused states encode the pre-edit context, so SCR is an approximation that the paper validates empirically. For hybrid models (Qwen3.6-27B: 48 of 64 layers linear attention) it snapshots the recurrent state and reflects the edit only in the full-attention layers.

Qualitatively, zero-shot CLMs invented behaviors the authors did not program: an orchestrator scoreboard updated through 163 in-place edits while staying at 6–8K tokens, a new `notes` chat role, loops that strip irrelevant search results, and a reusable `compact_turns` helper invoked 37 times.

# Q6 Experiment Design

| Claim | Testbed | Model and budget | Baselines |
|---|---|---|---|
| Fixed strategies fail on simple tasks | ContextBench (new): Needle Retention, Sudoku Sketchpad, KV Store, Log Triage, with context pressure varied | GPT-5.4, 32K | Base Mini-SWE-Agent, Codex-style Summary, Context Folding, RLM, Self-Compact, ACM — each given an author-written method-specific skill of comparable detail |
| Better accuracy and lower cost on coding and deep research | TerminalBench 2.1 (89 tasks), TBLite, BrowseComp-Plus (830 questions) | Qwen3.6-27B (and Qwen3.5-9B), 32K, turn cap | MEM1 (re-implemented), Self-Compact, ACM, RLM, Codex-style Summary, on a shared Mini-SWE-Agent backbone; all zero-shot |
| Beats specialized evolutionary workflows | Circle packing, Heilbronn, min-max/min-distance, Erdős minimum overlap | Claude 4.6 Sonnet, 32K, 100 attempts or 5 h, one run per method | OpenEvolve, OpenEvolve-Agent |
| Holds over 12-hour repository optimization | EdgeBench-10 (10 of 48 public tasks), best of 3 seeds | Qwen3.6-27B and Claude 4.6 Sonnet, 32K (also 128K) | Base harness, Codex-style Summary; CLM with up to 5–6 subagents |
| Scales to agent swarms | Software World: 6 agents optimize requests, urllib3, and 4 downstream repos for 24+ h; scored on 17 held-out benchmarks from 4 unseen packages | GPT-5.6 Sol, 272K, Pi harness | Summary-compaction swarm at matched USD spend |
| Strategy is steerable and learnable | One-sentence instructions (threshold, sub-question boundary, backup); skill evolution on ContextBench; RL on 3,040 OpenResearcher prompts, evaluated on BrowseComp-Plus | Claude 4.6 Sonnet; Qwen3.6-27B with Claude Fable 5.1 proposer, or Opus 5 alone; Qwen3.5-9B | No-instruction control; initial skill; summary harness trained with the same recipe |
| SCR saves server compute | BrowseComp-Plus; sensitivity over `k` on 64 questions | Qwen3.6-27B on SGLang | Standard SGLang prefix caching |

The design covers each headline claim with at least one dedicated experiment and reports compute next to accuracy throughout. Two harness details favor CLM and are worth keeping in mind when reading the comparisons: CLM gets a reminder 2,048 tokens before the budget, and on BrowseComp-Plus its editing turns do not count toward the 100-turn cap and an over-budget request is rolled back and retried up to six times (App. E).

# Q8 Evidence Quality

**Well supported**

* *Zero-shot gains with compute accounted for.* With Qwen3.6-27B at 32K, CLM reaches 59.4% on BrowseComp-Plus, 11.4% relative above the strongest baseline (Codex-style Summary), using 21.5% and 28.9% fewer prefix-reuse FLOPs than Summary and MEM1. It matches Summary on TerminalBench 2.1 at 70% of its FLOPs and beats it on TBLite (73.7% vs. 67.0%) at 91%. Because the metric charges re-prefill, this is not just a shorter-context artifact.
* *Long-horizon optimization.* On EdgeBench-10 with Qwen3.6-27B, CLM scores 44.6 at 179 PFLOPs per trial against 42.3 at 437 for Summary; with Claude 4.6 Sonnet, 51.0 against 42.3. CLM has the best best-of-run score on all four math problems (e.g., Heilbronn 0.03653 vs. 0.03127 for OpenEvolve; circle packing 2.618 vs. 2.541).
* *Learnability.* RL lifts Qwen3.5-9B CLM from 28.8% to 42.5% on BrowseComp-Plus, matching the trained Summary harness (42.1%) at 1.34 vs. 2.19 PFLOPs per question. Assisted skill evolution raises held-out KV Store accuracy from 38.3% to 74.2% (dev-split gains on all four ContextBench tasks).
* *SCR.* SCR matches standard SGLang accuracy at 65.0% of its prefix-reuse FLOPs on BrowseComp-Plus.

**Weaker or narrower than the headline**

* *Small run counts.* The math problems use one run per method; EdgeBench reports best-of-three; Software World is a single matched-spend comparison. These are suggestive rather than statistically established.
* *ContextBench is self-constructed.* The tasks and every baseline's usage skill were written by the authors. The paper says the skills were matched in detail, but baseline performance still depends on that authorship.
* *Unequal harness affordances* (see Q6): the budget reminder, uncounted editing turns, and rollback retries on BrowseComp-Plus are CLM-specific.
* *Model-capability dependence.* Gains grow with model strength. Qwen3.5-9B edits its context less often (1.4 vs. 2.6 edits per TerminalBench task) and its median peak context nearly fills the 32K budget. Reader observation: the 9B zero-shot comparison flips between settings — CLM 39.9% vs. Summary 37.7% in App. F, but 28.8% vs. 34.7% before RL in Table 2. The two use different configurations (28K budget and 80 turns in the RL setup), so the paper's results support "CLM needs a capable or trained model" more than "CLM always wins zero-shot."
* *Swarm result is extrinsic but singular.* The 65% figure is greater downstream speedup over the initial releases at the same spend, measured by executed instructions on 17 held-out benchmarks from one six-repository world.
* *SCR is approximate.* Relocated states encode the pre-edit context. Its robustness rests on a 64-question sensitivity study over `k`, and 5.3 of the 7.8 points of extra reused prompt tokens come from reasoning-token stripping rather than CLM edits — so much of SCR's benefit is general to reasoning-model serving.

# Q9 Contributions

1. A definition of Context Language Models (model-controlled context transition `C_{t+1} = f(C_t, y_t)`) and a minimal, harness-light implementation — context as a file — that runs on existing models and extends directly to subagents and swarms.
2. ContextBench, a diagnostic that isolates context management from reasoning and knowledge, showing that none of six existing strategies is perfect even on simple synthetic tasks.
3. Prefix-reuse FLOPs as a trajectory-level cost metric that makes edited and append-only contexts comparable under standard serving.
4. Zero-shot evidence across coding, deep research, math optimization, 12-hour repository optimization, and a 24-hour agent swarm that unrestricted context editing matches or beats harness-defined and tool-based context management at lower cost.
5. Two learning routes: steering and evolving in-context skills, and a stepwise-GRPO recipe with a success-gated efficiency advantage.
6. Suffix Cache Reuse, an SGLang serving co-design for non-prefix edits (including hybrid linear-attention models) that also helps ordinary reasoning-token stripping.

# Q10 Next Steps

* **Safety of an editable context** (author-stated): a writable context is a new channel through which prompt injections or self-generated instructions can persist across turns; the paper cites reports of models inserting unauthorized instructions into their own compaction summaries. Defenses that keep flexibility while preserving context integrity are open.
* **Scaling RL and distilling harnesses into CLMs** (author-stated): many harness operations are context transformations, so harnesses could be treated as procedural memory that is developed externally and later internalized into weights.
* **Context-length awareness** (App. G): models estimate their own token usage poorly at long lengths and need environmental hints; CLM currently relies on a budget reminder. Training this awareness directly is an open item.
* **Serving** (App. B): most remaining redundant prefill on hybrid models comes from SGLang storing recurrent states only at request boundaries; finer-grained checkpoints (e.g., at message boundaries) would help both standard caching and SCR.
* **Reader-noted gaps:** a fairness ablation that removes CLM's extra affordances (budget reminder, uncounted editing turns, rollback) would isolate the effect of unrestricted editing; multiple seeds on the math and swarm settings; and an audit of *what* CLMs delete, since a model that freely rewrites its own history can also erase evidence a human reviewer would want preserved.
* **Research-OS fit (reader interpretation):** this repository already treats durable state as files that agents read and rewrite (`HANDOFF.md`, project memory, skills). CLM moves the same file-native idea one level down — the live context itself — and its skill-evolution result suggests context-management policies could live as ordinary skills here rather than as harness code.
