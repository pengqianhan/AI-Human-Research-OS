# Q1 Problem Definition

* **Input (X):** a long-horizon agentic task (terminal coding, deep research with search tools, mathematical optimization, repository optimization, or an agent swarm over several repositories), a base language model with a fixed context limit (mostly 32K tokens, 272K for the swarm run), and a minimal agent harness (Mini-SWE-Agent with a Bash interface) in which the live context is mirrored to a file whose path appears in the system prompt.
* **Output (Y):** a sequence of contexts c₁, c₂, … chosen by the model itself, c_{t+1} = f^CLM_θ(c_t), rather than the standard append-only transition c_{t+1} = c_t ⊕ f^LM_θ(c_t); task performance (accuracy, verifier reward, best-of-run score, downstream speedup) and inference cost measured as *prefix-reuse FLOPs*, which charges prefill for every token from the first prefix mismatch onward plus decode for generated tokens.
* **Core problem:** context management is not a native LM capability. Existing systems either fix the policy in the harness (compaction at a length threshold, every-turn summarization) or expose a small human-designed action set (compact, offload, retrieve, fold). The paper's ContextBench pilot (Figure 2) shows none of these solves four simple synthetic tasks (Needle Retention, Sudoku Sketchpad, KV Store, Log Triage) under up to 24× context pressure at a 32K limit: summaries lose or hallucinate needles, in-place edits are impossible so Sudoku boards get regenerated, and offloaded data cannot be evicted from the live context on demand.
* **Scope:** text-only agents; Qwen3.6-27B, Qwen3.5-9B, GPT-5.6 Sol, GPT-5.4, Claude 4.6 Sonnet, Opus 5, and Claude Fable 5.1 in various roles; all zero-shot comparisons use untrained methods on a shared Mini-SWE-Agent backbone; RL is run only on Qwen3.5-9B for deep research.

# Q2 Problem Novelty

The problem is not new; the degree of autonomy is. The paper lays out a progression (Sec. 2, Appendix A): harness-scheduled compaction (Cursor's Composer self-summarization, Codex CLI, Terminus 2, MEM1 every-turn updates), then model-triggered actions within a fixed menu (AutoCompact and Self-Compact decide *when*, Context-as-a-Tool compacts a predefined portion, ACM adds offload and retrieve, Sculptor selects fragments, AgentFold folds), then [Recursive Language Models](2512.24601.md), which keep a long *input* outside the context as a REPL variable but still append everything generated. CLMs remove the last restriction by making the live context itself a writable file. Concurrent work the paper cites includes Memento ("Teaching LLMs to manage their own context", Kontonis et al., 2026) and CompactionRL; the retrieved text does not compare against Memento empirically. The authors frame the move with Sutton's Bitter Lesson: let the model search for strategies beyond human priors. It matters because context policy currently lives in harness code that must be re-engineered per model and task, and because an append-only context forces a trade-off between retention and cost that an editable context can escape.

# Q3 Scientific Hypothesis

If a language model is given unrestricted read-write access to its own live context, with edits synchronized into the next turn, then (1) even without training it will produce context-management strategies that beat fixed harness policies and constrained tool menus on both task performance and inference compute across long-horizon tasks; (2) because the strategy is now model behavior rather than harness code, it can be improved by natural-language instruction, by skill evolution, and by reinforcement learning; and (3) the re-prefilling cost of in-the-middle edits can be reduced by reusing cached states for surviving suffix tokens without hurting task performance. Figure 5 and Table 1, Figures 9 and 10 with Table 2, and Figure 11 are the respective tests.

# Q4 Related Work and Key People

* **Evolutionary discovery baselines.** [AlphaEvolve](../concepts/alphaevolve.md) and OpenEvolve, the specialized workflows CLM is compared against on four math-optimization problems.

# Q5 Key Solution Idea

* **Context as a file.** The live context is mirrored into storage with model write access; the model edits it with ordinary Bash (regex substitutions, Python loops, helper functions), and each edit is synchronized back and sent to the LM server for the next turn. No edit is appended by default; if the model does not touch the file, generation appends as usual. The paper's point is that f^CLM subsumes every prior tool menu, and that the model, not the harness, now *defines* the context-management functions (Figure 3d shows a reusable `compact_turns` helper invoked 37 times).
* **Multi-agent by construction.** Several context files can coexist and sync to their own servers; subagents are created and destroyed by creating and deleting context files. Figure 3a shows an orchestrator maintaining an in-context scoreboard through 163 in-place edits while holding 6-8K tokens.
* **Emergent behaviors observed zero-shot.** A new chat role for internal notes, loops that strip stale search results, summaries that preserve untried ideas for later exploration.
* **Three ways to improve the strategy.** (i) *Steering*: a single appended sentence changes compaction threshold, semantic-boundary compaction, or back-up-before-compaction behavior (Figure 9). (ii) *Skill evolution*: a GEPA-style loop proposes skill documents from training-split traces, selects on a dev split, and reports once on a held-out split, with either a stronger proposer (Claude Fable 5.1 for Qwen3.6-27B) or the agent itself (Opus 5). (iii) *RL*: stepwise [GRPO](../concepts/grpo.md) with the trajectory-level outcome advantage assigned to every segment, plus a *success-gated efficiency advantage* A^eff that re-ranks only successful trajectories within a group by prefix-reuse FLOPs (zero for failures, zero when fewer than two successes), explicitly to avoid rewarding edit frequency or deleted volume, which the paper notes would invite [reward hacking](../concepts/reward-hacking.md).
* **Suffix Cache Reuse (SCR).** After an edit replaces span B with B′, standard prefix caching re-prefills B′ and everything after it; SCR keeps the cached states of surviving suffix tokens C (which still encode the old prefix, a staleness the paper says can even help) and prefills only B′. It also applies to the common case where serving strips prior reasoning tokens between turns.

# Q6 Experiment Design

* **ContextBench pilot.** Four synthetic diagnostics with GPT-5.4 at 32K, baselines Mini-SWE-Agent, Codex-style Summary, Context Folding, RLM, Self-Compact, ACM.
* **Zero-shot long-horizon tasks (Qwen3.6-27B, 32K, 100-turn cap).** Terminal-Bench 2.1, TBLite, BrowseComp-Plus versus MEM1, Self-Compact, ACM, RLM, Codex-style summarization, all untrained on the same backbone; search tools exposed as in-context skills rather than a fixed tool interface (Figure 5, Pareto frontiers of accuracy versus prefix-reuse FLOPs).
* **Open discovery.** Four math problems (circle packing, Heilbronn, min-max/min-distance, Erdős minimum overlap) with Claude 4.6 Sonnet against OpenEvolve and an OpenEvolve-Agent variant, 100 scored attempts or five hours (Table 1); EdgeBench-10 single-repository optimization for 12 hours, best of three seeds, with and without up to five subagents (Figure 8 left); Software World, six agents optimizing six interdependent Python repositories for over 24 hours with GPT-5.6 Sol at 272K, scored on four unseen downstream packages (Figure 8 right).
* **Learning.** Steering (Figure 9), evolution on ContextBench (Figure 10 and Figure 28, skills never see the held-out set), RL of Qwen3.5-9B on OpenResearcher evaluated on held-out BrowseComp-Plus with checkpoint selection on a validation set, against a summary harness trained with the same recipe (Table 2), each with and without the efficiency reward (Figure 29).
* **Serving.** SCR versus standard SGLang on BrowseComp-Plus with Qwen3.6-27B (Figure 11), plus a decomposition of server-side compute.
* **Context-length awareness (Appendix G).** 50 inputs, models estimate their own prompt length with and without a token-count anchor; existing LMs are poorly calibrated at long lengths, which motivates the "every tool result reports your current size" hint the steering prompts rely on.
* **Not designed in.** No ablation of the file-mirroring design against a tool-menu variant *of the same model and prompt*; Software World and EdgeBench compare against one baseline (Codex-style summarization); the main zero-shot numbers are single configurations without confidence intervals in the text retrieved; no non-SGLang serving comparison for SCR.

# Q7 Datasets and Code

Introduces ContextBench (four synthetic diagnostic tasks) and EdgeBench-10 (a ten-task subset of EdgeBench); reuses Terminal-Bench 2.1, TBLite, BrowseComp-Plus, OpenResearcher (RL training), the AlphaEvolve/OpenEvolve math problems, and Software World. Code is released at `facebookresearch/context-language-models` (475 GitHub stars per `hf papers info`). Reproducing the main runs requires Qwen3.6-27B serving under vLLM or SGLang, API access to GPT-5.6 Sol and Claude 4.6 Sonnet, and multi-hour to day-long compute per trial for the open-discovery experiments.

# Q8 Evidence Quality

* **Well supported.**
  * The zero-shot deep-research result is the strongest: 59.4% on BrowseComp-Plus at 32K beats the best baseline by 11.4% relative with 21.5% fewer prefix-reuse FLOPs, against five baselines on one backbone. The cost metric is conservative for CLMs because it charges full re-prefill after every in-the-middle edit.
  * The RL result is a controlled comparison: the same recipe trained on both CLM and a summary harness; CLM goes 28.8% → 42.5% and ends 0.4 points above the trained summary harness at 1.34 versus 2.19 PFLOPs per question. The paper is candid that the untrained 9B CLM starts six points *below* the summary harness.
  * The evolution protocol keeps train, dev, and held-out splits separate and reports held-out once.
  * The safety discussion (Sec. 6) names the obvious risk: an editable context is a new persistence channel for prompt injection or self-generated instructions, citing OpenAI's report of models inserting instructions into compaction summaries.
* **Weaker than the headline.**
  * The coding claim is parity, not a win: CLM *matches* Codex-style summarization on Terminal-Bench 2.1 (at 70% of its FLOPs) and the TBLite gain (73.7% versus 67.0%) comes at 91% of the FLOPs.
  * Math-optimization margins are mostly small (Erdős 0.38094 versus 0.38123, min-max 0.07758 versus 0.07690); the 16.8% Heilbronn gain is the one large effect, and each is a best-of-run score from a budgeted search without variance.
  * "65% greater improvement" on Software World and the EdgeBench-10 margin with Qwen3.6-27B (44.6 versus 42.3) rest on single long runs (best of three seeds for EdgeBench) against a single baseline; the Claude 4.6 Sonnet EdgeBench margin (51.0 versus 42.3) is larger.
  * Subagents add little on EdgeBench-10 (44.2 versus 44.6), so the multi-agent extension's benefit is shown only on the one swarm task.
  * The "up to 35.9 points" evolution gain is on a ContextBench synthetic task (KV Store), not on a real workload, and the evolved skill is model-specific.
  * SCR's "35% less server-side compute" is one benchmark, one model, one serving engine, and relies on stale cache states whose effect on other tasks is asserted ("empirically preserving") rather than broadly measured in the retrieved text.
* **Reader observation.** The baselines are all run untrained with the same backbone, which is fair, but several (Self-Compact, ACM, ContextPilot-style policies) were designed to be trained; the comparison therefore measures zero-shot interface quality, not the ceiling of constrained action spaces.

# Q9 Contributions

* A simple, general interface, context as a writable file synchronized into the next turn, that subsumes prior context-management tool menus and extends to multi-agent systems by file multiplicity.
* Evidence that frontier and 27B open models already use that interface productively zero-shot, with emergent behaviors (new roles, helper functions, in-context scoreboards) and Pareto improvements in accuracy versus compute on deep research, parity on terminal coding, and wins over specialized evolutionary workflows and summary-based swarms on day-long tasks.
* Three learning routes for the context strategy (instruction, skill evolution, RL), including a success-gated efficiency advantage that rewards cheaper successes without rewarding deletion itself.
* Prefix-reuse FLOPs as a trajectory-wide cost metric that accounts for re-prefilling, and Suffix Cache Reuse as a serving co-design that recovers most of the re-prefill cost.
* ContextBench as a diagnostic that isolates context management from reasoning and knowledge, with results showing existing methods fail even on simple synthetic tasks.

# Q10 Next Steps

* **Security of a writable context.** Measure injection persistence and self-instruction insertion rates for CLMs versus summary harnesses, and test defenses (append-only audit logs, signed system segments, diff review by a second model) that keep editing flexible.
* **Controlled interface ablation.** Hold model, prompt, and tools fixed and vary only the editing interface (full file, constrained menu, append-only) to separate "more autonomy" from "better prompt".
* **Variance and scale.** Repeat the zero-shot and open-discovery runs with seeds and intervals; test whether the 9B RL gain transfers to coding where the untrained CLM only matched baselines.
* **Harness-to-CLM distillation.** The paper proposes translating existing harness operations into context edits and then into weights; a first test is distilling Codex-style compaction into a CLM and checking whether the student exceeds the teacher.
* **Context-length awareness training.** Appendix G shows poor self-estimation of prompt length; training that signal in, or making it a standard environment hint, is a cheap follow-up.
* **Project fit (reader note).** Memory and handoff files in this repository already play the role of an externally edited context; a CLM-style setup would let the agent own that file directly. The paper's warning that compaction can smuggle instructions across turns applies to any agent-written summary we persist.

* [ContextPilot](2608.28476.md) - the trained constrained-action-space approach; CLM's RL differs in training an unconstrained editor and in gating efficiency on success.
