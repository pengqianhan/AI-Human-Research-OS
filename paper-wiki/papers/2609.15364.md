# Q1 Problem Definition

* **Input (X):** a new digital environment ℰ (e.g., a desktop OS, an application such as FreeCAD, a browser) with no gold labels or human supervision, plus a target task instruction q; at test time the agent additionally conditions on a frozen, previously-constructed durable memory M.
* **Output (Y):** during exploration, an evolving durable memory M storing environment-specific knowledge, reusable procedures/scripts, and reusable causal relationships between actions, conditions, and consequences; at test time, a sequence of executable code-as-policy actions a_1,...,a_T produced by an actor agent conditioned on q, the interaction history, and the frozen memory M, until a verifier agent confirms the task is satisfied.
* **Core problem:** pretrained digital agents encounter new environments whose interfaces, tools, conventions, and failure modes are not fully captured by their pretraining, and existing adaptation routes either require costly additional human-assisted training data collection or rely on context management that memorizes successful trajectories without discovering the underlying causal structure (which action, under which condition, produces which consequence) — the paper asks whether an agent can autonomously discover such causal relations in a new environment and consolidate them into a reusable memory, without updating model parameters.
* **Scope:** two digital-agent benchmarks (OSWorld 2.0 0808-offline, 82 tasks; Agents' Last Exam Near-term, 67 tasks) plus a generalization check on 40 sampled GameCraft-Bench game-development tasks; two open-source backbone models (GLM-5.3 as actor, Kimi-K3 as verifier/curriculum agent); a code-as-policy action interface rather than raw pixel/coordinate actions; the paper does not evaluate training-based adaptation or environments outside computer-use and game-development settings.

# Q2 Problem Novelty

The paper does not claim to originate digital agents, code-as-policy action representations, or memory-augmented context management — it builds on OSWorld/OS-Agents-style benchmarks, CodeAct's executable-program action space, and prior test-time adaptation work (Reflexion, agentic context engineering) that treats accumulated experience as retrievable context. Its stated novelty is twofold: (1) reframing environment adaptation as autonomous *causal discovery* rather than trajectory memorization — explicitly distinguishing "remembering what worked" from "inferring which factors determine success, failure, and state transitions," a distinction the paper's ablation and failure-mode analysis (Sec. 4.6) treats as load-bearing; and (2) a broad-then-deep two-stage exploration curriculum (parallel broad coverage, then sequential deep refinement on hard cases) explicitly analogized to the pretraining-then-posttraining paradigm in LLM development, applied here to environment self-exploration rather than model training. It positions itself against training-based adaptation (costly, human-assisted, hard to apply to private/changing environments) and against memory approaches that treat history only as static context (Shinn et al.'s Reflexion; Zhang et al.'s agentic context engineering) rather than as a source of extractable, verifier-grounded causal structure.

# Q3 Scientific Hypothesis

If a multi-agent system separates exploration direction (curriculum agent), execution (actor agent with evolvable memory), and independent outcome verification (verifier agent isolated from the actor's private reasoning and memory) — and if exploration proceeds broad-then-deep (first covering diverse environment structure in parallel, then sequentially targeting hard cases, hidden constraints, and boundary conditions revealed during broad exploration) — then the resulting frozen memory of grounded causal action-condition-outcome knowledge should transfer to downstream test-time tasks well enough that open-source backbone models equipped with it outperform substantially larger or more capable frontier closed-source models evaluated without such memory, because the causal structure captured is specific to the *environment* rather than the task instance, so it generalizes across the many different tasks a downstream user might request within that same environment.

# Q4 Related Work and Key People

* **Digital agents.** Cites OSWorld, OS-Agents survey (Hu et al., 2025b), Cradle, OS-Copilot, Agent S2 as the base paradigm of tool-use/GUI agents in software environments; OpenCUA (human-demonstration learning), UI-TARS-2 (multi-turn RL), EvoCUA (synthetic-experience policy optimization) as prior adaptation routes RSIAgent explicitly avoids by staying training-free; CodeAct (Wang et al., 2024) as the source of its code-as-policy action representation.
* **Recursive self-improvement of agents.** Situates itself among DGM (Darwin Gödel Machine, self-modification evaluated on coding benchmarks), HGM (using descendant performance to select agents with more improvement potential), and Hyperagents (a meta-agent modifying both itself and the task agent) — the paper notes these methods require access to benchmark scores or labeled reference data, whereas RSIAgent operates with no external task rewards, discovering structure purely from environment feedback during self-exploration.
* **Memory, history, and experience reuse.** Distinguishes itself from HyMEM (hybrid symbolic-node/trajectory-embedding memory graph for computer-use agents), Voyager (automatic curriculum for skill acquisition in Minecraft), EchoTrail-GUI and ZhuLong (self-exploration for reusable GUI/EDA-scripting experience), and CoEvoSkills/Recuris (verification-feedback-driven skill/memory refinement) — RSIAgent's differentiator claimed against this group is explicit causal-relationship extraction (action, condition, consequence) as the unit of memory, validated by an isolated verifier agent, rather than trajectory-level or skill-level reuse alone. # Q5 Key Solution Idea

1. **Three-role multi-agent harness.** An actor agent (primary policy, generates executable code-as-policy actions, holds an evolvable memory of environment knowledge, reusable procedures, and lessons learned) is paired with a verifier agent (independent evaluator, isolated from the actor's private reasoning/memory to reduce correlated errors, grounds its PASS/FAIL judgment directly in environment feedback such as execution results and interface state) and a curriculum agent (high-level coordinator that generates practice tasks based on the current target, accumulated memory, and prior outcomes — selecting prerequisite skills, informative variants, failure-driven practice, and stress tests, and deciding when exploration has diminishing returns).
2. **Stage 1 — Broad Recursive Self-exploration (BRS).** A recursive loop where the curriculum agent proposes multiple parallel tasks spanning different exploration directions each iteration, the actor and verifier agents execute and grade them, and the curriculum agent uses the accumulated results to identify remaining knowledge gaps and propose the next, more-informed batch — building broad environment coverage, reusable procedures, and failure patterns.
3. **Stage 2 — Deep Recursive Self-exploration (DRS).** A sequential loop that progressively increases difficulty: the curriculum agent proposes a single challenging task designed to expose hidden constraints or current-memory weaknesses, the actor attempts it using accumulated memory, the verifier grounds the outcome, and each verified result (success, failure, or newly revealed uncertainty) is consolidated into memory before the next, harder task is proposed — a successful practice does not automatically end exploration if the curriculum agent judges further practice worthwhile.
4. **Frozen test-time memory reuse.** After exploration, the curriculum agent and all memory updates are disabled; the actor agent directly reuses the frozen procedures, discovered constraints, and failure lessons to guide actions on downstream target tasks, with the verifier agent still active to confirm task completion — decoupling the (potentially expensive) exploration phase from cheap, repeated test-time use.
5. **Evolvable-memory consolidation policy.** After each verified outcome, the actor agent adds new knowledge and revises or removes outdated entries, so memory content is explicitly gated by independent verification rather than accepted on the actor's own account of success — the paper's own failure-mode analysis (Sec. 4.6) treats gaps in this gating (incomplete verification, unreliable consolidation) as a primary limitation rather than an assumption to take for granted.

# Q6 Experiment Design

**Setup.** Code-as-policy harness shared across conditions. GLM-5.3 serves as the default actor agent; Kimi-K3 serves as both verifier and curriculum agent (in a separate context). BRS uses a nominal budget of 8 exploration projects with up to 4 executed concurrently, checked between completed waves; DRS proceeds sequentially until the curriculum agent judges no further useful practice remains. Benchmarks: OSWorld 2.0 (0808 offline, 82 tasks) and Agents' Last Exam (ALE) Near-term (all 67 tasks), reporting Partial score (mean task score) and Binary accuracy (fraction receiving full credit), both as percentages; baseline scores for comparison models are drawn from official technical reports/blogs, not independently re-run.

**Main results (Table 1, Sec. 4.2).** RSI (comparing RSIAgent to a no-exploration "RSIAgent (w/o RSI)" baseline using the same harness with empty memory) raises OSWorld partial score 71.97→78.98 and binary accuracy 37.80→42.68; on ALE, partial 83.75→84.82 and binary 49.25→50.75. Against frontier closed-source models, RSIAgent (78.98 OSWorld partial, 84.82 ALE partial) exceeds GPT-6 Astra (72.60, 82.26) by 6.38 and 2.56 points respectively, and also exceeds Claude Opus 5 (70.19, 79.54) on both benchmarks — using open-source GLM-5.3/Kimi-K3 as the underlying models with no weight updates.

**RSI-rounds analysis (Sec. 4.3).** On three representative OSWorld tasks (T044 video editing, T049 presentation repair, T065 railway booking) tracked across 8 recursive steps, scores reach 100%, 80%, and 100% by step 8; the paper notes memory accumulation is gradual while task-level score gains can appear as discrete jumps once critical requirements are covered, and flags that single-task curves make such breakthroughs more visible than the underlying gradual accumulation.

**Ablation (Sec. 4.4).** On four OSWorld tasks (T080 WPS spreadsheet repair, T085 REAPER audio editing, T089 browser presentation repair, T106 3D Slicer liver segmentation): full RSI (both BRS+DRS) reaches a mean 74.54% partial score, versus 65.52% for BRS-only (DRS skipped) and 56.50% for DRS-only (BRS skipped, exploring from empty memory). BRS-only improves over baseline on every task; DRS-only falls *below* baseline on two of the four tasks (T085, T089) — evidence the paper reads as supporting the broad-then-deep ordering specifically, not just "more exploration helps."

**Generalization to game development (Sec. 4.5).** 40 sampled GameCraft-Bench tasks, compared against Play2Code (an iterative-playtesting-and-revision baseline) across four different base game generators (Codex+GPT-5.5, Kimi-K2.6, GLM-5.3-Flash, Qwen3.8-27B). RSIAgent improves overall quality scores across all four generators (e.g., 52.77→61.28 for the strongest base generator, 31.28→46.37 for the weakest); Play2Code's benefit shrinks or reverses as the base game quality rises (e.g., 52.77→51.05, a regression, on the strongest generator), while RSIAgent's "(w/o RSI)" variant already beats Play2Code on 3 of 4 generators and full RSI improves further on top of that in every case.

**Failure-mode analysis (Sec. 4.6).** From selected case audits, the paper identifies three interacting failure mechanisms: insufficiently targeted exploration (practice that doesn't challenge the specific decisions responsible for a weakness — e.g., a missing-user-information handling rule that stayed wrong because no practice task tested it), incomplete verification (the verifier returning PASS despite unsupported field values or rubric discrepancies), and unreliable memory consolidation (an inadequately verified decision becoming a persisted, reused rule — e.g., treating a missing-data marker as a valid answer across subsequent attempts).

# Q9 Contributions

1. RSIAgent, a training-free, three-role (curriculum/actor/verifier) multi-agent framework for recursive self-improvement in new digital environments, autonomously acquiring, verifying, and consolidating environment-specific causal knowledge into a reusable memory without updating model parameters.
2. Broad Recursive Self-exploration (BRS) and Deep Recursive Self-exploration (DRS), a two-stage broad-then-deep exploration curriculum explicitly analogized to LLM pretraining-then-posttraining, with an ablation showing the two stages are complementary rather than substitutable (DRS-only can underperform the no-exploration baseline on some tasks).
3. Empirical demonstration that frozen, autonomously-constructed memory lets open-source backbone models (GLM-5.3 actor, Kimi-K3 verifier/curriculum) outperform frontier closed-source models including GPT-6 Astra and Claude Opus 5 on OSWorld 2.0 and Agents' Last Exam, without weight updates.
4. Evidence the approach generalizes beyond computer-use tasks to autonomous game development on GameCraft-Bench, consistently improving games from both weak and strong base generators where a comparable iterative-revision baseline (Play2Code) can degrade already-strong outputs.
5. A named three-mechanism failure-mode taxonomy for recursive self-improvement in this setting (insufficiently targeted exploration, incomplete verification, unreliable memory consolidation), grounded in case audits rather than asserted, identifying verification quality and consolidation reliability — not just exploration coverage — as necessary conditions for RSI gains to hold.

# Q10 Next Steps

The paper's own stated limitations (Sec. 7): additional test-time exploration and practice introduces substantial computation cost; performance depends on finite exploration budgets, stopping policies, and the resulting memory's quality; the model-based verifier agent may produce incorrect judgments that propagate into later exploration and memory updates; different environments may require different tools, verification signals, and exploration strategies, and the paper's own experiments do not fully isolate every component's individual contribution. The paper names extending RSI beyond digital computer-use environments to AI-for-Science settings (where agents must learn specialized tools, workflows, and scientific procedures) and to games (as a domain for studying long-horizon exploration and adaptation) as future work, and separately flags ethical risks from autonomous software exploration (unintended actions, unauthorized access, privacy leakage).

Beyond the paper's own framing, three points are worth flagging for a reader assessing this note's evidence. First, the verifier agent is drawn from the same small pool of frontier open-source models (Kimi-K3) as the rest of the harness rather than being an independently-sourced or formally-verified oracle, so the paper's own Sec. 4.6 finding that "incomplete verification" is a real, observed failure mode in its own runs is a direct, load-bearing limitation on how much the memory-consolidation gating can be trusted — not a hypothetical concern. Second, the frontier closed-source comparison numbers (GPT-6 Astra, Claude Opus 5, etc.) are copied from external reports rather than re-run under RSIAgent's own evaluation harness, so the reported margins (2.56–6.38 points) could partly reflect protocol differences between benchmarks-as-officially-reported and benchmarks-as-run-here rather than a like-for-like capability gap — the paper does not report a controlled re-run of any frontier closed-source model under its own harness to rule this out. Third, the game-development generalization check samples only 40 of GameCraft-Bench's tasks and compares against a single baseline (Play2Code); whether RSIAgent's advantage holds on the benchmark's full task distribution, or against other continual-improvement baselines, is untested here.
