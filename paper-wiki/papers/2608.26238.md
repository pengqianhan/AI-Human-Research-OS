# Q1 Problem Definition

* **Input (X):** a text prompt (optionally paired with a reference image) describing a many-part, hard-surface object, and a frozen, non-3D-trained LLM with vision input and code-execution access to an OpenSCAD-style CSG compiler.
* **Output (Y):** Procedura, an agentic framework that grows the object as a procedural assembly A=(P,C) — an ordered set of named parametric CSG parts P joined by typed, machine-checkable mates C — one part at a time, so that compiling the program yields a mesh with sharp machined edges, a native named-part decomposition, and user-editable parameters, rather than a soft, undecomposed, unedited mesh.
* **Core problem:** native 3D generators (score-distillation, feed-forward, native-diffusion, and autoregressive-mesh methods) recover impressive geometry but output dense meshes that "stay soft where a machined object should be sharp," carry no part decomposition ("nothing in the mesh says which triangles belong to which part"), and expose no editable parameter — segmentation and editability require separate post-hoc models. Program-based alternatives (CSG-tree induction, structured assembly programs, sketch-extrude CAD, and LLM script-writing) can in principle produce editable, part-structured shapes, but the paper's stated gap is that this program-writing line "remains single-shot, producing the code once with no visual feedback, so many-part objects come out with wrong part counts and misplaced parts."
* **Scope:** the LLM policy is frozen and receives no 3D-specific training; all structure comes from the agentic scaffold (planning, mate-driven building, verification gates, decoupled critic, and separate materials/articulation passes) rather than from model weights.

# Q2 Problem Novelty

Native 3D generation (DreamFusion, Magic3D, Point-E, Shap-E, LRM, LGM, Direct3D, TRELLIS, UltraShape, Hunyuan3D, PolyGen, MeshAnything, MeshGPT) and program-based 3D generation (CSGNet, UCSG-Net, ShapeAssembly, JoinABLe, AutoMate, DeepCAD, Fusion 360 Gallery, SkexGen, Text2CAD) are each active lines this paper builds on rather than originates; so are recent agentic 3D-code systems with draft-execute-revise loops (CADDesigner, CadSmith) and domain-tuned coders (CAD-Coder, cadrille), and LLM scene-layout systems (ProcTHOR, LayoutGPT, SceneCraft). Procedura's stated novelty is coupling three properties none of these combine: (1) every relation between parts is a *typed, machine-checkable mate* verified against the compiled mesh, rather than a raw transform the model emits and hopes is correct; (2) placement is *solved* analytically from the mated frames rather than guessed by the model, removing what the paper calls "the largest single source of drift in prior 3D-code systems"; and (3) the reviewer that diagnoses a defect is *decoupled* from the agent that fixes it, on the stated reasoning that "a model that judges its own output carries the very assumptions that produced the error, so an independent reviewer is more likely to catch it" — as opposed to prior agentic 3D-code loops where the same model both critiques and edits.

# Q3 Scientific Hypothesis

If an LLM agent (a) plans a many-part object as an ordered assembly graph with typed mate declarations before writing any code, (b) grows the program one part per call rather than regenerating the whole object each turn, solving each new part's placement analytically from its declared mate rather than letting the model emit a raw transform, (c) admits a part only after it passes a compile gate, a per-mate registration/penetration gate, and a delta-aware connectivity gate, and (d) alternates this building phase with a decoupled single-turn vision critic whose diagnosis one-shot-gates exactly one subsequent edit — then the resulting objects will have sharper edges, more correct part connectivity, and higher judged geometric/aesthetic/semantic quality than both native 3D generators and prior single-shot or self-critiquing 3D-code agents, while remaining fully editable by named part and extensible to per-part materials and simulator-validated articulation without changing the underlying frozen LLM.

# Q4 Related Work and Key People

* **Native 3D generation.** Optimization-based score distillation (DreamFusion, Magic3D), feed-forward regression (Point-E, Shap-E, LRM, LGM), native 3D diffusion (Direct3D, TRELLIS, UltraShape, Hunyuan3D), and autoregressive mesh models (PolyGen, MeshAnything, MeshGPT) all optimize to input views and output dense, soft, undecomposed meshes; recovering parts or edit handles requires bolting on a separate segmentation model (PartField, SAMPart3D) after the fact.
* **Program-based 3D generation.** CSG-tree induction (CSGNet, UCSG-Net), structured assembly programs (ShapeAssembly, JoinABLe, AutoMate), and CAD-native sketch-extrude generation (DeepCAD, Fusion 360 Gallery, SkexGen, Text2CAD) target editable, part-structured output directly, but the paper groups LLM-based parametric script-writing (Three.js/Blender scripting) here too as still fundamentally single-pass.
* **Agentic 3D-code generation — the closest prior line.** Draft-execute-revise loops (CADDesigner, CadSmith) and domain-tuned coders (CAD-Coder, cadrille) already iterate, but without Procedura's typed-mate verification or decoupled critic; the paper's own benchmark results (Q6) show CAD-Coder and cadrille shipping no mesh at all on a nontrivial fraction of MechBench-36 cases. ArtiCraft (built on GPT-5.6-sol) is evaluated as the strongest prior agentic 3D-code baseline. Separately, prior articulation work (vision-language articulation methods, LLM scene-layout systems ProcTHOR/LayoutGPT/SceneCraft) informs Procedura's articulation stage, where the kinematic graph reuses the same mate network rather than a separate representation.

# Q5 Key Solution Idea

1. **Procedural assembly with typed mates.** An object is A=(P,C): an ordered set of named parametric CSG parts P, each compiling to exact planes/cylinders (not sampled geometry), joined by mates C=(i,j,type,Fᵢ,Fⱼ,d,φ) — a typed relation between a mate frame on the new part and one on an already-placed part, sharing a nominal dimension d plus a signed fit offset φ. The paper defines nine static mate types (bolt-pattern, peg-socket, seat-face, flange, tab-slot, press-fit, lip-rabbet, snap-tab, key) and three kinematic types (revolute, prismatic, spherical), each fixing a specific degree-of-freedom signature.
2. **Two-stage assembly-graph planning.** One vision call decomposes the target into an ordered, named part list with declared interfaces (mate partner, type, shared nominal), constrained so every part attaches to something already placed; a second vision call reviews that plan against the reference image but is code-restricted to only add a missing part or sharpen a description/mate — it may never merge, remove, rename, or reorder, a rule enforced in code rather than trusted to the prompt.
3. **Mate-driven, one-part-per-call building.** Rather than regenerating the whole object each turn, the agent adds exactly one part per call, grounded in three sources: the assembly reference (image, prompt, and the current plan slice), the full built-so-far program as text, and up to 12 rendered viewpoints (6 orthographic, 6 isometric) the agent itself selects. For a static mate, placement is *solved* rather than generated — Tⱼ = Fᵢ·Δ(φ)·Fⱼ⁻¹ — which the paper credits as removing prior systems' largest drift source. Each candidate part must clear three gates before being committed: a compile gate (with the compiler error fed back on failure), a per-mate registration-area/penetration-depth gate (a(c) ≥ τₐ·d² and δ(c) ≤ δₘₐₓ(φ)), and a delta-aware connectivity gate that only rejects a part if visible floaters *increase* over the current baseline (allowing legitimate later connections). Parts get up to three quality attempts before being committed anyway with a warning.
4. **Decoupled-critic refinement with a diagnosis-gated edit invariant.** After a building pass, a single-turn vision critic — architecturally separate from the building agent, receiving rendered views, a parts-color legend, the program, and a trail of prior flags — returns a one-line summary and a prioritized, severity-tagged issue list naming the responsible module. A hard invariant then gates editing: a successful diagnosis sets a one-shot latch that exactly one subsequent edit consumes, and the edit tool refuses to fire unless that latch is set (diagnose itself refuses if the rendered views are stale relative to the current program). An ablation of this gate is reported to blow the diagnose-to-edit ratio out from ≈1:1 to 15 edits against 2 diagnoses when ungated. A span-based connectivity metric (component span ratio against a threshold τ=0.01, chosen because volume-based checks miss thin flat panels that are visually detached but have near-zero volume) gates the terminal "finish" action until zero visible floaters remain.
5. **Separate materials and articulation passes reusing the same mate graph.** Materials: a four-stage, non-agentic pipeline extracts a compact PBR material library from the reference image, assigns one material per named part, runs a separate single-turn material critic, then rewrites multi-material parts into sibling color blocks. Articulation: static mates group parts into rigid links, kinematic mates supply joint type/axis/anchor candidates from deterministic geometric evidence (rotational-symmetry axes, contact regions), a vision call assigns axes/limits/drives over the resulting parent-child tree, and the result is exported as OpenUSD/URDF and validated in Isaac Sim through a fixed battery (dynamic settle, per-joint actuation sweep, rest-contact scan, wheeled-mobility test, URDF re-import), with any flagged fault feeding rendered simulation frames back to the planner for one refine pass.

# Q6 Experiment Design

Two benchmarks: MechBench-36, a new hard-surface benchmark of 36 deliberately many-part objects (rovers, mechs, cranes, excavators, engines, landing gear) chosen to stress part count, placement, and connectivity beyond a single sub-assembly; and P3D-Bench, an existing 203-case text-and-image benchmark scored by its own assembly judge. Prompt and reference view are locked identically across all compared methods. Judging is blind: every method's output is re-rendered from one fixed view set under a grey-clay rig, assigned an opaque hash, and scored by a vision-LLM judge (Gemini 3.7 Flash in high-reasoning mode) along semantic fidelity, geometric quality, and aesthetics, supplemented by CLIP image-text alignment, sharp-edge length above a 60° dihedral threshold (Shrp₆₀), and the 95th-percentile dihedral angle (Dih₉₅). Procedura is run with Gemini 3.7 Flash as the primary backbone (frozen, no 3D training) and GPT-5.6-sol as a secondary backbone; the compiler is OpenSCAD, renders are produced in Blender, and physics validation runs in headless Isaac Sim.

On MechBench-36, Procedura (Gemini 3.7 Flash) reaches an overall score of 0.828, ahead of the strongest native generator TRELLIS.2 (0.810), the strongest prior agentic 3D-code baseline ArtiCraft on GPT-5.6-sol (0.702), and GPT-5.6 single-shot generation (0.792); CAD-Coder and cadrille score 0.135 and 0.092 respectively, each failing to ship a mesh on several cases (11 and 5 of 36). Procedura's sharp-edge length (158.08) is 2.6–3.1× the next-best code method and far above native generators (natives cluster at 6.4–35.2 Shrp₆₀); its 95th-percentile dihedral (97.97°) also leads. Paired against its own un-agentic base model, Procedura gains +0.105 aesthetics (20 wins, 7 losses, p=0.019) and +1.80 CLIP (p=0.011). On P3D-Bench (203 cases), Procedura leads every scored column for both backbones (Gemini 3.7 Flash: 0.590±0.009 overall; GPT-5.6-sol: 0.575±0.010), ahead of the corresponding single-shot backbones (0.566, 0.563) and further ahead of GPT-5.5 (0.524), Gemini 3.1 Pro (0.513), and Opus 4.6 (0.448); its geometry-column margin (0.490 vs. 0.392 for single-shot) is the largest single-axis gap, which the note reads as targeting the mate-driven precision claim directly.

An ablation on MechBench-36 (n=36) removes one mechanism at a time from the full pipeline (overall 0.828): removing the refine loop drops to 0.800, removing planning drops furthest to 0.791 (the largest single-mechanism cost, concentrated in aesthetics), and removing 3D feedback (the rendered-viewpoint context) drops to 0.819 with losses spread across every axis. A qualitative refinement case study on an "assault buggy" model shows high-severity issues falling from 4 to 3 to 2 across refinement cycles, with one cycle achieving a sub-millimetre contact correction that changes connectivity without changing silhouette. Separately, materials are demonstrated on the same buggy model (25 extracted library entries, 41 parts assigned, corrected by the material critic, then split into sub-part color blocks), and articulation is evaluated on 18 objects: 14 of 18 clear every physics-validation phase, 9 of those also clear advisory asset rules, 4 fail outright (one has no load response, three have actuators that never traverse their commanded range), and position-driven joints that do pass traverse at least 97% of their commanded range.

# Q9 Contributions

1. Frames 3D-shape-as-code generation as the target paradigm and scales it with a frozen, non-3D-trained LLM agent rather than a specialized 3D model — Procedura produces detailed, many-part shapes from a text prompt using only a general-purpose vision-language model plus a compiler.
2. A procedural-assembly representation with typed, machine-checkable mates: part placement is solved analytically from declared mate frames rather than emitted as a raw transform, and every part commit is gated by compile, mate-registration/penetration, and connectivity checks, keeping the build connected, precise, and editable by name throughout.
3. A decoupled vision critic with a diagnosis-gated edit invariant (one diagnosis unlocks exactly one edit), reported to hold the diagnose-to-edit ratio near 1:1 versus 15 edits per 2 diagnoses when the gate is removed.
4. State-of-the-art results against both native 3D generators and every prior 3D-code agent tested, on P3D-Bench and the new MechBench-36, with the largest reported margins in edge sharpness and geometric quality; extensions to per-part PBR materials and simulator-validated articulation (14/18 objects passing a full physics battery) demonstrate the same mate graph supports downstream tasks beyond static geometry.

# Q10 Next Steps

The paper's own stated limitations: the agent perceives the build only through rendered images, so occluded interiors and fine contact geometry can escape every camera angle — the authors suggest depth maps, cross-sections, or direct mesh queries as a stronger feedback signal; CSG geometry suits mechanical, hard-surface objects but expresses organic, freeform surfaces less naturally than a neural field would; and the mate vocabulary covers only rigid joints, so a relation the plan never declares as a mate cannot be verified by the gate system, leaving an unverified corridor for connectivity errors the plan simply omits. The paper's closing framing generalizes beyond 3D modeling specifically: it states its principles — casting generation as coding, joining parts by verifiable relations, separating the critic from the fixer, and validating every claim in a compiler or simulator rather than trusting the model's own report — as carrying to "program-based generation at large."

This note adds one connection beyond the paper's own framing: Procedura's diagnosis-gated edit invariant (one diagnosis unlocks exactly one edit, verified by a stale-view refusal check) is a within-episode instance of the same diagnose-then-patch discipline this wiki's Agent self-evolution and Agent harness engineering topics track at the cross-episode level (e.g. SkillOpt's held-out validation gate, AutoSaddler's typed patches) — the gate exists here to stop a single build's own critic-fixer loop from thrashing, not to admit a change into a memory that persists across future tasks, but the underlying commitment ("verify before you let a proposed change take effect") is the same discipline applied at a much finer grain.
