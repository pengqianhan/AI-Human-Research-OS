# Q1 Problem Definition

* **Input (X):** real execution traces M = {(f_t, x_t, o_t)} from runs on real MCP services and open agent corpora, plus a target chain length L and number of environments K.
* **Output (Y):** a typed tool-composition graph; environment clusters with databases synthesized on demand; a dataset of (task q, verification set V, tool chain ω, initial state s₀); models trained on it; and harder versions of existing benchmarks.
* **Constraints:** each chain must be a walk on the graph that satisfies dependency reachability, state preconditions, and parameter provenance (every argument traceable to q, s₀, or an earlier observation), and re-executing it from s₀ must pass all assertions. The objective is long-horizon, cross-environment coverage under replay verification, not the fidelity of any one database.

# Q2 Problem Novelty

Partly new. Environment scaling for agents is crowded: simulators such as Simia and GenEnv use an LLM as a textual world model, while EnvScaler, [Agent World Model](../concepts/agent-world-model.md), [Agent-World](../concepts/agent-world.md), and AgentScaler-style synthesis (Fang et al.) build executable databases, tools, and tasks. WorkRover and WEFT evolve whole interaction systems, and [Agent-Reflex](2610.17953.md) adds failures. The authors group these as *data-centric* (theme, then database, then tools, then tasks) and name three resulting limits: tool interfaces that diverge from real ones, compositions not grounded in execution, and tasks confined to one environment. The new element is the ordering: real traces first, then a witnessed tool graph, with databases only where state requires them. This follows a Trace-to-ENV principle shared with [Trace2Env](2610.06100.md) and Terminal-Universe. The third limit is narrower than stated: [CompoWorld](2609.33665.md), not cited here, already composes independently executable services into cross-service tasks along random-walk dependency graphs, but its graphs are sampled at the service level rather than mined from traces (reader comparison).

# Q3 Scientific Hypothesis

If tool composition is taken from relations witnessed in real executions, and tasks are decompiled from walks that actually ran, then SFT on those tasks should teach transferable cross-environment orchestration rather than only the form of function calls. Performance should grow with data and with environment breadth, execution-witnessed edges should beat LLM-judged ones, and the same machinery should produce harder versions of frontier benchmarks.

# Q5 Key Solution Idea

**Trace corpus by execution authenticity.** MCP-ecosystem tasks whose tool definitions exactly match live servers are executed by several agents on those servers. Web-sourced trajectories are ranked: real-server records (Toucan-1.5M, ToolBench with unavailable interfaces removed) are high; real-workspace runs from SWE-agent and [OpenHands](2407.16741.md), keeping only explicit tool calls, are medium; synthetic-environment trajectories are low and are kept only when tool names and schemas match real tools.

**Typed, weighted tool graph.** A node is a tool plus its normalized argument configuration. Between adjacent calls, deterministic rules (no LLM) add a *data* edge when the next input uses a value from the previous output with matching field type, a *state* edge when one call mutates an object that the next reads or mutates, and a *retry* edge when a failed call is followed by a different tool that succeeds. An edge's weight is how often the transition is observed, w = N_ij / N_i. Low-frequency edges are dropped, and data edges must be traceable, which removes false links from constants such as `limit=10`. Data, state, and retry edges make up 69%, 25%, and 6% of the graph.

**Selective grounding.** Clustering by connection density gives 804 environments. *Operation* environments (181, those with a state-changing tool) get a database built from a theme by a research agent, following Agent-World. *State-query* environments initialize state from recorded partial snapshots. *Stateless* environments such as web search reuse cached returns from the corpus for matching calls.

**State-aware walks with rollback.** From a node bound to a database and snapshot, the walk keeps only neighbors whose inputs can be filled from earlier returns or current state, samples among them by edge weight, and executes the step. If a tool fails or the resulting state contradicts the traversed edge, the environment is restored to the previous snapshot and another neighbor is sampled; chains that still cannot proceed are discarded.

**Decompile and replay.** An LLM writes a natural-language task with no tool names or call order, and the verification set combines final-state, key-intermediate-snapshot, and required-output assertions. A sample is kept only if replay from s₀ passes everything. Teacher trajectories are then generated for retained tasks and filtered by the same checks. Difficulty is controlled through L, K, and the share of cross-environment edges.

**Benchmark upgrades.** For an existing benchmark, its real tool calls are collected and linked by the same rules to outside tools that share data or state, expanding one environment into a cluster. Longer walks are then reverse-generated into tasks. Three doctoral-level experts reviewed candidates over two days and tasks needed approval from at least two (Fleiss' κ = 0.82, 93.1% agreement), yielding AutomationBench Pro (300 tasks) and τ³-Bench Banking Pro (98 tasks).

# Q6 Experiment Design

* **Data and training.** Over 200,000 raw trajectories; Kimi K3 as teacher and task writer; 34,376 SFT samples and 653 RL samples, the RL candidates screened with Pass@16 on the 35B model to keep those with one or two correct rollouts. One-epoch SFT on Qwen3-8B, Qwen3.6-35B-A3B (16 GPUs), and GLM-5.2-744B-A40B (256 GPUs). RL runs 48 steps of asynchronous GRPO with a binary execution-based reward, learning rate 2e-6, batch 256, and group size 16.
* **Benchmarks (seven).** [AutomationBench](../concepts/automationbench.md), [SkillsBench](../concepts/skillsbench.md), [JobBench](../concepts/jobbench.md), τ³-Bench Banking (of the [τ²-Bench](../concepts/tau2-bench.md) family), [BFCL](../concepts/bfcl.md) V4, [Harvey LAB](../concepts/harvey-lab.md), and [OfficeQA](../concepts/officeqa.md) Pro.
* **Baselines.** Proprietary (Claude Opus 5, GPT 5.6 Sol), large open models, same-size 8B environment-scaling models, and 27-35B open models. Results come from official leaderboards first, then provider reports, then local reproduction; ToolSpace results and local reproductions are means of three runs.
* **Analyses.** Pro against Standard for seven frontier models; data fractions and environment fractions from 1/16 to full; top-50% against random-50% environments by BGE relevance; task clusters (t-SNE, DBSCAN) on 2K questions from four corpora; synthesized file counts over 500 Agent-World environments; component ablation at 35B on five benchmarks.

# Q7 Datasets and Code

The paper states that data sources and MCP services are covered by open-source licenses and that overlaps with test sets (task, tool-call sequence, or initial state) were excluded.

# Q8 Evidence Quality

* **Supported.**
  * *Gains at every scale.* Average over seven benchmarks: 7.2 to 19.6 (8B, 20.7 with RL), 23.0 to 41.0 (35B, 43.2 with RL), and 44.6 to 56.6 (744B), above GLM 5.3 (53.8), Qwen 3.8 Max (54.5), and GPT 5.6 Sol (48.9), and level with Claude Opus 5 (56.6). The tie is an average of a different profile: the 744B model leads Opus 5 on AutomationBench (54.7 against 45.6) and Harvey LAB, and trails on JobBench (57.5 against 68.0) and τ³-Bench Banking.
  * *Largest gain where composition matters.* AutomationBench rises 8.2 to 45.8 at 35B, while the 8B environment-scaling baselines stay below 1 there.
  * *Harder Pro splits.* All seven frontier models drop: AutomationBench by 11.3 to 38.2 points (Opus 5.5 from 59.2 to 26.3) and τ³-Bench Banking by 14.4 to 25.6, and tool calls rise on both.
  * *Witnessed edges beat LLM-judged ones.* LLM-judged edges lower all five ablation benchmarks by 5.4 to 8.0 points (6.8 on average, reader calculation from Table 3), close to removing state edges (7.1) or data edges (7.4). Uniform walks cost 4.7, no rollback 3.3, and no retry edges 1.4 (reader calculation).
  * *More data and environments help.* The full set is best on all five scaling benchmarks, and the step from half to full data still adds 4.6 on AutomationBench.
* **Weaker or narrower than the headline.**
  * *Synthesis cost is a proxy.* The 55.3% saving (2,724 to 1,218 files) is a file count, and the paper says token, time, and compute costs were not measured. Collecting over 200,000 trajectories, including runs on live services, is not counted against it (reader observation).
  * *The no-overfit argument is partial.* Top-50% and random-50% environments differ by at most 1.7 points on four named benchmarks, but the text gives no such gap for τ³-Bench Banking, which improves late (19.6 to 34.0 only at the full set). Decontamination excludes overlapping tasks, tool sequences, and initial states, not overlapping tools, and the graph's most visible environments (Gmail, Slack, Salesforce, Airtable) are the kind of SaaS applications AutomationBench simulates (reader observation).
  * *"Beyond the teacher" has another explanation.* The paper reads the 744B model's 56.6 against Kimi K3's 49.7 as evidence against simple distillation. Trajectories are filtered to those passing verification, so the student learns from the teacher's successes rather than its average behavior, and GLM-5.2 starts at 44.6 (reader observation).
  * *RL evidence is thin.* RL's +2.2 at 35B comes mostly from τ³-Bench Banking (34.0 to 42.3). AutomationBench and JobBench are unchanged to one decimal (45.8, 40.0), which is unusual for three-run means, and the paper does not comment (reader observation).
  * *Pro difficulty may include measurement differences.* Standard scores are from a public leaderboard and Pro scores from the authors. Trace assertions come from one walk's intermediate snapshots, so a valid different route might fail them, a possibility the expert review of tasks and scripts does not measure directly (reader observation).
  * *Weak spots remain.* Harvey LAB stays at 1.7 to 2.5 at 35B and at 0.0 at 8B, so "exceeds its backbone on all seven" hides a very small gain there. Ablations cover five of the seven benchmarks at 35B, with no spreads shown.
  * *Baseline rows are mixed.* Agent-Reflex-8B is listed at 51.3 on BFCL V4 here and 52.9 in [its own paper](2610.17953.md) (reader comparison), and Opus 5 on AutomationBench is 45.6 here and 50.3 in [MiMo-V2.6](2610.11959.md).

# Q9 Contributions

* A tool-first formulation of environment synthesis: a typed, weighted graph of witnessed tool relations as the single primitive behind tasks and benchmarks, built with deterministic rules.
* Selective grounding, which materializes databases only where tools change state and reuses recorded returns elsewhere.
* State-aware walks with rollback and replay-gated decompilation, producing 34,376 verified samples averaging 18.86 tool calls among those with at least five.
* Ablation evidence that how edges are obtained matters about as much as which edge types exist.
* AutomationBench Pro and τ³-Bench Banking Pro, expert-reviewed harder splits.

# Q10 Next Steps

* **Same-backbone comparison with CompoWorld (reader suggestion).** Both papers fine-tune Qwen3.6-35B-A3B and report AutomationBench, τ³-Bench Banking, and SkillsBench, but with different data sizes and teachers. Training on equal amounts of each pipeline's data would separate mined from sampled composition.
* **Non-adjacent dependencies (reader suggestion).** Edges come from adjacent calls only, so a value read early and used many steps later is not captured unless it passes through neighbors. Mining longer-range provenance could add such links.
* **Off-script replay (reader question).** Stateless tools return cached results for matching calls. What a student's differently worded query receives during RL is not specified in the text, and the choice affects how far agents can explore.
* **Route-independent checks (reader suggestion).** Comparing state-only assertions with the current mix on the Pro splits would show how much of the score drop comes from trace assertions.
* **More data (from the paper).** The step from half to full data shows no plateau, so scale has not reached its limit.
