# Q1 Problem Definition

* **Input (X):** a research idea ("spark"), run in either Proposal Mode (no data) or Data-Aware Mode (measured results already exist).
* **Output (Y):** a complete, submission-ready LaTeX paper project — manuscript sections, verified bibliography, editable vector figures, and a venue template — assembled from a structured blueprint.
* **Core problem:** turning a research idea into a complete paper requires more than text generation: literature retrieval, experiment design and execution, evidence-based claim revision, publication-ready figure production, and consistency maintenance across a long generation process.
* **Scope:** implemented entirely as thirteen composable skills inside an existing coding assistant (Claude Code), with no separate agent platform, orchestration server, graph database, or cluster scheduler.

# Q2 Problem Novelty

The paper positions itself between two established poles. Autonomous end-to-end research agents (AI Scientist, AI Scientist-v2, AutoResearchClaw, Kosmos, Robin) match or exceed Spark-to-Paper's breadth — several run real experiments and draw figures — but each ships as a standalone application with its own orchestration server and sometimes a graph database or cluster scheduler. Lightweight skill-based writing assistants (Idea2Story, ARS) need no standing infrastructure but automate a narrower slice: none of them run real experiments end to end or produce editable vector figures rather than embedded bitmaps. Spark-to-Paper's novelty is combining full-breadth automation (including real experiment execution) with zero standing infrastructure and editable vector output — a combination the authors argue is absent from prior systems, and make the positioning checkable against each compared system's own public documentation (their Table 1 / Fig. 1).

# Q3 Scientific Hypothesis

If (a) deterministic gates handle only checkable constraints (template, blueprint, citation, manuscript-evidence, figure, and compilation gates) while models are reserved for genuine semantic judgment (local self-review plus manuscript-level adversarial review), and (b) experiment planning is separated from reporting — table structure and required evidence fixed before execution, claims later classified as supported / partially-supported / unsupported / contradicted / needs-confirmation — and (c) runaway failure trajectories are bounded to seven experiment–critique–revision cycles before the system restarts from a different idea, then end-to-end research-paper generation can be reliable and evidence-grounded without standing infrastructure. The paper tests this through controlled ablations of the integrity/review stack and adversarial-review precision, not through whether generated papers make novel scientific contributions or would pass peer review.

# Q4 Related Work and Key People

* **Autonomous end-to-end research agents:** AI Scientist, AI Scientist-v2, AutoResearchClaw, Kosmos, Robin — automate more of the research process (including running novel experiments) but each requires a dedicated standalone codebase and orchestration infrastructure.

# Q5 Key Solution Idea

An eight-stage pipeline (stages 0–8) in which skills communicate through shared project-directory artifacts, splitting model judgment from deterministic, directly-checkable operations:

0. **Input routing** — selects Proposal Mode or Data-Aware Mode.
1. **Planning** — converts the input into a blueprint: research question, main contributions, section structure, notation, and experimental design.
2. **Citation** — searches literature and verifies candidate references against DOI/arXiv metadata.
3. **Writing** — generates the full LaTeX manuscript from the blueprint and verified bibliography, all sections written against the same project context.
4. **Refinement** — revises the manuscript as a whole (removes repetition, reconciles terminology/notation) rather than section by section.
5. **Review** — self-review operates locally after each edit; adversarial-review runs multiple isolated manuscript-level passes (theoretical soundness, experimental design, systems validity), where every raised issue must quote the exact passage it challenges and is checked three ways: is the problem actually present, is it already addressed elsewhere, is it out of stated scope.
6. **Figure generation** — two separate paths. Explanatory/method figures: an image-generation model produces a raster visual target, then the coding assistant reconstructs it as editable HTML (text, shapes, connections), iteratively compared against the raster target and rendered to vector PDF (falling back to raster if reconstruction is unreliable). Quantitative result figures: read directly from measured experimental outputs via generated plotting code, never through an image-generation model.
7. **Assembly** — combines manuscript sections, bibliography, figures, and venue template into one LaTeX project.
8. **Experiment execution** — runs the planned experiments and updates manuscript claims from the measured evidence.

Before execution, the planning stage fixes the table structure required to evaluate the manuscript's main claims while leaving numerical cells empty — a lightweight preregistration inside the pipeline. The **Self-Refutation Loop** is the paper's named failure mode: the system plans experiments to test a hypothesis, judges the evidence insufficient, revises the method, and re-runs — sometimes repeating this cycle indefinitely rather than accepting the idea may not work. Spark-to-Paper bounds this to seven experiment–critique–revision cycles; if the objective still cannot be supported, the trajectory terminates, a failure report is recorded (original idea, attempted methods, observed results, why evidence fell short), and a new trajectory starts from a different idea. Only trajectories that produce coherent supporting evidence are consolidated into a final manuscript.

# Q6 Experiment Design

Evaluated across eight controlled research topics using controlled ablation studies and adversarial review, on six dimensions: citation validity, fabrication detection, figure editability, review precision, cross-template robustness, and generation cost (tokens, USD, wall-clock).

* **Fabrication detection (36 seeded failure probes):** single-pass draft 14% → +deterministic gates only 69% → +self-review 81% → +adversarial review (full stack) 92%. Adversarial review also reaches 74% precision (most raised issues correspond to verifiable problems rather than spurious critiques).
* **Citation validity:** 99.5% computed over 384 references from eight Spark-to-Paper campaign papers, versus 97.8% for a human-preprint reference set of 320 references from eight sampled papers.
* **Figure editability:** 96.4%, evaluated over roughly 1,900 ground-truth figure elements (excluding figures intentionally rasterized by design).
* **Comparison table (citation validity / figure editability / cost / tokens / wall-clock):** Spark-to-Paper 99.5% / 96.4% / $8.1 / 11.9M tokens / 3.2h; AI Scientist 93% / 0% / $10–15 / n/r / ~12h per batch; AI Scientist-v2 91% / 3% / ~$20–25 / n/r / ≤15h; human preprints 97.8% / 58% / n/a.
* **Single-pass baseline** (same backbone, no quality-control stack): citation validity drops to 81%, cost $0.66, runtime 16 minutes.

# Q8 Evidence Quality

The ablation and comparison numbers are self-reported by the same team over a small, author-selected evaluation base — eight controlled topics and 36 seeded probes — rather than a standardized public benchmark. Baseline comparisons (AI Scientist, AI Scientist-v2 cost/time/validity figures) are drawn from each compared system's own public documentation rather than a matched re-run under identical conditions, so the cost and quality contrasts in the headline table are not strictly controlled. The paper is explicit that claim-to-evidence semantic matching inside the manuscript gate is still model-judged rather than fully deterministic. The 92% full-stack fabrication-detection rate is measured only against seeded probes, which may not represent the full distribution of naturally occurring fabrications a generation system could produce.

# Q9 Contributions

1. Demonstrates that end-to-end research-paper generation — literature retrieval, experiment design and execution, evidence-revised claims, and editable vector figures — can be implemented purely as skills inside an existing coding assistant, with no standing infrastructure.
2. Names and bounds the Self-Refutation Loop failure mode via a seven-cycle limit, failure-report logging, and idea-restart recovery.
3. Separates deterministic integrity gates (template, blueprint, citation, manuscript-evidence, figure, compilation) from model-based self-critique (self-review, adversarial review) as an explicit reliability architecture.
4. A dual figure-generation path — programmatic plotting for data-grounded figures, image-generation-then-HTML-reconstruction for explanatory diagrams — that produces editable vector output, in contrast to prior systems' 0–3% figure editability.
5. Public, checkable positioning against named prior systems plus an open-sourced skill implementation.

# Q10 Next Steps

* The paper's own limitations: claim-evidence semantic support is model-judged, not deterministic; the gates deliberately verify only checkable properties, not whether a contribution is important, an argument persuasive, an experimental design scientifically appropriate, or a figure communicative; when required code or data are unavailable, results are left unspecified rather than fabricated; unreliable HTML figure reconstruction falls back to raster; supporting a new venue requires new template resources; the implementation runs inside Claude Code on a Claude-family model, though the design is claimed (not demonstrated) to be portable.
* Natural follow-ups: validate the 92% full-stack fabrication-detection rate against real, unseeded fabrications and a larger topic sample; run matched re-implementations of AI Scientist / AI Scientist-v2 under identical compute and cost accounting rather than citing their public documentation; assess downstream scientific validity or reviewer acceptance of generated manuscripts, not only structural integrity metrics.
* **Research-OS fit:** the deterministic-gate-versus-model-judgment split and the bounded Self-Refutation Loop are directly comparable to this repository's own evaluator contract and claim-to-evidence provenance conventions (never invent citations or results; record unknowns honestly) — worth comparing designs if paper drafting from experiment results is ever automated in this repository.
