# Q1 Problem Definition

* **Input (X):** a user-specified task — a software-engineering issue, a web-browsing goal, or a miscellaneous-assistance query — plus a chosen agent implementation and backing LLM.
* **Output (Y):** an event-stream trajectory of actions (bash commands, Python/IPython code, browser interactions) and observations ending in task completion, scored against one of 15 integrated benchmarks spanning software engineering, web browsing, and miscellaneous assistance.
* **Core problem:** building agents that interact with the world the way a human developer does — writing code, running a terminal, browsing the web — requires solving several coupled infrastructure problems together: giving agents create/modify/execute capability inside complex software systems, letting them gather task-relevant information on the fly, and doing this safely (sandboxed, without side effects on the user's system). The paper's own Table 1 comparison shows existing agent frameworks each cover only part of this: some lack sandboxed code execution, some lack a browser, some lack multi-agent delegation, some lack a systematic evaluation framework.
* **Scope:** an open-source platform (agent abstraction + runtime + tool library + evaluation harness), not a single fixed agent; it ships a default generalist agent (CodeActAgent) and specialists (BrowsingAgent, a GPTSwarm integration) built on top of that platform.

# Q2 Problem Novelty

Multiple open-source agent frameworks already existed (AutoGPT, LangChain, MetaGPT, AutoGen, AutoAgents, Agents, XAgent, OpenAgents, GPTSwarm) alongside SWE-specific systems (SWE-Agent, AutoCodeRover). The paper's own nine-dimension framework comparison (graphic UI, standardized tool library, built-in sandbox and code execution, built-in web browser, multi-agent collaboration, human-AI collaboration, an agent hub, an evaluation framework, agent QC/integration tests) shows OpenHands as the only system with every listed capability. The novelty is this combination, plus treating software itself — code, CLI, browser — as the general-purpose interface for agents, mirroring how humans act on the world, rather than proposing one new single-agent algorithm.

# Q3 Scientific Hypothesis

If an agent platform provides a common event-stream interaction protocol, a docker-sandboxed runtime exposing bash/IPython/browser primitives, an extensible agent-computer-interface skill library, and a delegation mechanism for cooperating specialist agents, then a single generalist agent (CodeActAgent) built on that platform — without benchmark-specific prompt engineering — can stay competitive across qualitatively different task families (software engineering, web browsing, miscellaneous assistance) simultaneously, unlike prior systems typically optimized for one task category at a time.

# Q4 Related Work and Key People

* Extends CodeAct (Wang et al., 2024) as the action representation — code execution rather than JSON function-calls — for the default CodeActAgent.
* Positions itself against general-purpose agent frameworks (AutoGPT, LangChain, MetaGPT, AutoGen, AutoAgents, Agents, XAgent, OpenAgents, GPTSwarm) and SWE-specific agent-computer-interface work (SWE-Agent's ACI concept, AutoCodeRover); see the paper's Table 1 and Appendix C.
* Integrates 15 pre-existing benchmarks (SWE-Bench, HumanEvalFix, BIRD, BioCoder, ML-Bench, Gorilla APIBench, ToolQA, WebArena, MiniWoB++, GAIA, GPQA, AgentBench, MINT, Entity Deduction Arena, ProofWriter) rather than introducing a new one.
* Authors: Xingyao Wang (project lead) with 23 co-authors across UIUC, CMU, Yale, UC Berkeley, Contextual AI, KAUST, ANU, HCMUT, Alibaba, and All Hands AI; advised by Graham Neubig, Heng Ji, and Hao Peng.

# Q5 Key Solution Idea

Five platform components:

1. **Event-stream interaction mechanism** connecting UI, agents, and environments through a chronological history of actions and observations, plus auxiliary execution state (accumulated LLM cost, multi-agent delegation metadata).
2. **Docker-sandboxed agent runtime** exposing a bash shell, a Jupyter IPython server, and a Playwright-based Chromium browser (via BrowserGym action primitives — navigation, clicking, typing, scrolling) inside a securely isolated container; arbitrary user-supplied docker images are supported by injecting the OpenHands action-execution API into them.
3. **AgentSkills library:** an extensible toolbox of Python functions auto-imported into the IPython environment. A new skill is added only when (1) it is not readily achievable for the LLM to write directly, or (2) it requires calling an external model (e.g., vision-language image/PDF parsing). Ships file-editing utilities adapted from SWE-Agent and Aider.
4. **Agent delegation** (`AgentDelegateAction`): lets one agent — e.g., the generalist CodeActAgent, which has limited browsing support — hand off a subtask to a specialized agent, e.g., BrowsingAgent for complex web navigation.
5. **Evaluation framework** integrating 15 benchmarks across software engineering, web browsing, and miscellaneous assistance, used to benchmark every shipped agent under matched conditions.

# Q6 Experiment Design

Compares OpenHands agents (mainly CodeActAgent across GPT-4o-mini, GPT-4o, and Claude-3.5-Sonnet backbones, plus BrowsingAgent and a GPTSwarm integration) against open-source, non-benchmark-tuned baselines on 15 benchmarks, reporting success rate and average per-task USD cost.

**Software:** SWE-Bench Lite (300 instances, no hint text) — CodeActAgent v1.8/Claude-3.5-Sonnet reaches 26.0% resolve rate at $1.10/instance, competitive with contemporaneous SWE specialists (Aider's 26.3%) without matching them. HumanEvalFix Python (164 instances, 0-shot) — CodeActAgent v1.5/GPT-4o reaches 79.3% pass@k, below SWE-Agent's 87.7% (which is 1-shot, vs. OpenHands's 0-shot). BIRD text-to-SQL — up to 47.3%; ML-Bench — up to 76.5%; BioCoder — up to 27.5%; Gorilla APIBench — up to 36.4%; ToolQA (easy) — up to 47.2%.

**Web:** WebArena (812 tasks) — BrowsingAgent/Claude-3.5-Sonnet reaches 15.5%, competitive among zero-shot domain-general prompting agents but below trained specialist models. MiniWoB++ (125 environments) — up to 40.8%, well below trained RL specialists (CC-NET's 91.1%).

**Miscellaneous:** GAIA — CodeActAgent/GPT-4o reaches 53.1% (v1.5 figure cited in the results table); GPQA — the strongest reported baseline in that comparison column is few-shot chain-of-thought GPT-4 at 38.8%.

# Q7 Datasets and Code

No new benchmark; integrates 15 pre-existing ones (listed above) into a common evaluation harness. Released under the MIT license; at the time of writing had 32K GitHub stars and 2.1K+ contributions from 188+ contributors as a community project (continuing today as OpenHands/All Hands AI).

# Q8 Evidence Quality

The paper's central claim is breadth and cross-task competitiveness, not state-of-the-art on any single benchmark, and the results table is transparent about this: OpenHands agents trail the best specialist baseline on nearly every individual benchmark (e.g., HumanEvalFix 79.3% vs. SWE-Agent's 87.7% 1-shot; MiniWoB++ 40.8% vs. CC-NET's 91.1% trained-RL specialist), while remaining the only system evaluated — under one unmodified system prompt — across all three task categories at once, since the same CodeActAgent (not a per-benchmark-tuned variant) is used throughout §4. A caveat the paper itself states directly: several baseline comparisons are not strictly matched (e.g., SWE-Agent's HumanEvalFix number is 1-shot against OpenHands's 0-shot), so cross-row comparisons need to be read with that difference in mind rather than as apples-to-apples. As a systems/platform paper rather than a single-hypothesis empirical paper, its strongest evidence is arguably the Table 1 feature comparison plus the community-adoption numbers (32K stars, 188+ contributors) — real usage/adoption evidence, but not a controlled experiment.

# Q9 Contributions

1. An open-source agent platform (OpenHands, f.k.a. OpenDevin) combining an event-stream interaction protocol, a sandboxed multi-modal runtime (bash + IPython + browser), an extensible agent-skills tool library, and cooperative multi-agent delegation — the only system in the paper's own nine-dimension framework comparison with every listed capability.
2. AgentHub: a hub of 10+ community-contributed agent implementations sharing a common agent abstraction, including the CodeAct-based generalist CodeActAgent, a BrowsingAgent, and a GPTSwarm integration.
3. An integrated evaluation framework spanning 15 established benchmarks across software engineering, web browsing, and miscellaneous assistance, showing one generalist agent and system prompt stays competitive across all three categories simultaneously.

# Q10 Next Steps

* The paper's own stated limitations and future work (Appendix A): more principled multi-modality support (viewing images/video, processing spreadsheets via standard IPython/browser integration rather than ad hoc skills); agents still struggle with complex tasks and need improvement via both training and inference-time techniques; long-file editing remains weak; and automatic, graph-based (GPTSwarm/LangGraph-style) workflow generation to reduce the current hand-crafted-agent-design burden.
* Its ethics statement frames the platform itself as a risk-mitigation tool — systematic evaluation to surface risks before deployment, human-AI collaboration rather than unsupervised autonomy, and broad research access to frontier-agent tooling for safety research — rather than treating agent-capability growth as risk-neutral.
* **Research-OS fit:** OpenHands's AgentSkills inclusion rule — add a skill only when an LLM cannot readily write the equivalent code, or when it requires an external model call — is a concrete, reusable design heuristic for this repository's own skill-library discipline ([research-skills-hub](../../research-skills-hub/index.md)). Its delegation mechanism (`AgentDelegateAction`) is an early, directly citable precedent for the multi-agent delegation patterns this wiki already tracks in [LongHorizon-Harness](2608.01964.md).
