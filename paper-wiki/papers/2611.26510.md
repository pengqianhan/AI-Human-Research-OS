# Q1 Problem Definition

* **Input (X):** a fixed teacher model (DeepSeek-V4-Pro-Preview), a fixed pool of 1,000 training tasks per domain with execution environments, an initial student checkpoint (Qwen3.5-4B or 9B), and initial trajectories from the unguided teacher and the initial student.
* **Output (Y):** a training set of 512 trajectories, and the student fine-tuned on it, that scores higher on the domain benchmark than a student trained on 512 randomly sampled successful unguided teacher trajectories.
* **Constraints:** teacher, task pool, training-set size and SFT recipe are held fixed across methods; the student is always trained from the initial checkpoint; the student is evaluated without any generated skills, under each benchmark's official protocol; the agent has a budget of five outer-loop rounds.

# Q2 Problem Novelty

SFT on successful agent trajectories (FireAct onwards), trajectory selection for useful behaviors (Behavior Priming), recovery of demonstrations from teacher failures (PROOF-Gen), skill and prompt optimization without weight updates (GEPA and others), and agents that run post-training (FT-Agent, RSI-Master) all exist. The paper's angle is that a success label does not say which behaviors a demonstration teaches: successful trajectories can still contain unsupported claims, repeated guessing, or superficial checks. It argues the teacher's behavior should be shaped during generation, including on tasks the teacher already solves, and that an agent should run that shaping.

# Q3 Scientific Hypothesis

If an agent writes skill instructions that change how a fixed teacher reasons and verifies, and selects demonstrations by behavior as well as outcome, then a student fine-tuned on the same number of trajectories with the same recipe will score higher than one trained on random successful unguided trajectories. A second hypothesis: keeping the skill text in the student's training input, although it is absent at evaluation, helps the student internalize when each behavior applies.

# Q4 Related Work and Key People

* **Autonomous post-training.** Agents that revise training code from evaluation feedback (autoresearch-style loops), FT-Agent (data and training-strategy refinement), RSI-Master (persistent experiment records and reviewer guidance), and Agent²RL-Bench.
* **Skill-based agent learning.** GEPA and other prompt and skill optimizers; co-evolving skill libraries or procedural scaffolds with training; Skill-to-LoRA (skill-specific adapters from skill-guided demonstrations); Skill-SD (a skill-conditioned teacher scores tokens of the student's own rollouts).
* **Learning from agent trajectories.** FireAct, AlphaMath, step-level preference work, error-recovery trajectories, Behavior Priming, PROOF-Gen.
* **Key people.** Guoxin Chen and Shuang Sun (equal contribution), Fanzhe Meng, Xinyu Tang, Ruihua Song, and Wayne Xin Zhao (Gaoling School of Artificial Intelligence, Renmin University of China; RUC-AIBOX). The same group authored several of the training-task sources and harnesses used here. Likely critics: authors of on-policy distillation and RL-for-agents work, who would ask how this compares with training on the student's own rollouts.

# Q5 Key Solution Idea

1. **Skill-FT.** For a task x, the selected skills s are appended to the base system prompt p, and the teacher rolls out τ ~ Rollout(π_T, x; p ⊕ s). The student is fine-tuned on selected trajectories with standard SFT, keeping the original system prompt, skill text included, in the input; loss covers assistant reasoning, responses and tool calls only.
2. **Inner loop (agent).** The agent inspects tasks, unguided teacher trajectories and, in later rounds, student evaluation trajectories; looks for habits to discourage and useful behaviors the teacher rarely shows; writes skills and chooses which tasks they apply to; tests them in pilot rollouts; scales promising ones to batches; and selects 512 demonstrations by outcome and behavior. It may also select unguided trajectories that already show the wanted behavior.
3. **Outer loop.** Each round trains θ_r = SFT(θ_0, D_r) from the same initial checkpoint, evaluates without skills, and returns scores and trajectories; the experiment history carries over, the weights do not.
4. **Infrastructure.** The agent works from a Docker container through MCP tools that read tasks and trajectories and submit rollout and SFT jobs; an execution controller schedules SGLang evaluation automatically after SFT; records link every evaluation back to its training set and skills. At the end the agent picks a final checkpoint and records why, and that checkpoint is evaluated in three fresh runs.

Appendix B shows four generated skills, for example one that puts the numerical acceptance condition into an executed check and forbids widening a tolerance, and one that ties the next search query to the unsupported assumption when a search stalls.

# Q6 Experiment Design

* **Domains and benchmarks.** Terminal (training tasks from CalibForge; Terminal-Bench 2.1, 89 tasks), Search (FORT-Searcher; BrowseComp-Lite, 185 tasks), SWE (DeNovoSWE; Doc2Repo, 50 repositories, mean test pass rate). 1,000 training tasks per domain, randomly sampled.
* **Models.** AutoMaster runs in Codex with GPT-6 Astra at xhigh effort; teacher DeepSeek-V4-Pro-Preview at high effort; students Qwen3.5-4B and 9B.
* **Baselines.** Base (no fine-tuning) and Vanilla SFT (512 random successful unguided teacher trajectories). Full-parameter SFT for every method: 512 trajectories, 3 epochs, learning rate 1e-5, global batch 32, 131,072-token maximum length.
* **Ablations.** w/o Skill Guidance (agent selects from unguided rollouts), w/o Data Selection (agent designs skills for a fixed random task subset, no agent-directed selection), Task-Matched SFT (unguided rollouts on exactly AutoMaster's final task IDs and per-task counts, successful and failed kept), and Keep vs. Remove skill text in training input.
* **Statistics.** Mean ± SD over three evaluation runs per checkpoint; paired bootstrap 95% intervals over tasks (10,000 resamples) for the main gains.

# Q7 Datasets and Code

Evaluation uses public benchmarks; training tasks come from public datasets released by the same group and collaborators. The paper links a project page, a GitHub repository (RUCAIBox/AutoMaster) and models. The agent prompts and generated skills beyond the four in Appendix B were not checked here.

# Q8 Evidence Quality

* **Main table.** AutoMaster has the highest mean in all six settings: Terminal-Bench 2.1 28.09 vs. 22.47 (4B) and 35.58 vs. 26.59 (9B); BrowseComp 46.13 vs. 43.24 and 51.53 vs. 46.85; Doc2Repo 33.72 vs. 32.30 and 40.79 vs. 36.05. Paired bootstrap intervals exclude zero for all three 9B settings and for 4B Terminal-Bench, but include zero for 4B BrowseComp ([-1.08, 6.85]) and 4B Doc2Repo ([-1.94, 5.33]). The paper says this itself.
* **What the SD covers.** The ± is over three evaluation runs of one checkpoint, so it measures evaluation noise only; each method is trained once, and training-seed variance is not reported. With 89 tasks, one Terminal-Bench task is 1.12 points.
* **Checkpoint selection.** AutoMaster's agent picks its final checkpoint from up to five rounds using evaluation feedback on the same benchmark it is reported on, then re-evaluates it in three new runs. The baselines get one checkpoint each. Fresh evaluation runs remove selection on run noise but not selection among five trained students on test-set feedback; Figure 8's best rounds beat round 1 by 2.16 to 4.87 points. No held-out benchmark separates design from evaluation (reader assessment).
* **Ablations are informative.** Both components matter in all six settings, and Task-Matched SFT shows the gain is not just task choice (AutoMaster ahead by 1.08 to 10.11 points). But on 4B Terminal-Bench both single-component variants (17.60, 20.22) fall below Vanilla SFT (22.47), and Task-Matched SFT keeps failed trajectories, so the comparison mixes behavior shaping with success filtering.
* **Success labels.** In Table A5, 8.79% to 20.70% of AutoMaster's Terminal and Search demonstrations succeed where the matched unguided rollout failed, so some of the gain may come from more successful demonstrations on hard tasks, not only better behavior on tasks both solve.
* **Keep vs. Remove.** Keeping skill text beats removing it by 2.15 to 4.01 points across all six settings, with identical supervised outputs. The explanation (rules and their conditions stay explicit) is offered as a possibility, supported by two examples.
* **Reader check.** Terminal-Bench means sit on the 1/267 grid expected for 89 tasks times three runs (28.09 = 75/267), and BrowseComp means on the 1/555 grid, consistent with the stated protocol.

# Q9 Contributions

1. Skill-FT: shaping a fixed teacher's behavior with natural-language skills during rollouts, including on tasks it already solves, as a source of better SFT demonstrations.
2. AutoMaster: an agent-run post-training loop that designs, pilots, scales and revises those skills and selects demonstrations, with infrastructure that links every evaluation to its training set and skills.
3. Controlled evidence across three domains and two sizes that this beats random successful-trajectory SFT at equal data and recipe, with component and task-matched ablations.
4. The finding that retaining skill instructions in training input beats removing them, although evaluation has no skills.

# Q10 Next Steps

* **Training-seed variance.** Train each method with several seeds to show the gains exceed training noise, especially the 4B BrowseComp and Doc2Repo settings whose intervals include zero (reader suggestion).
* **Held-out selection.** Let the agent select checkpoints on a validation split or a second benchmark, so that the reported benchmark is not also the agent's feedback signal (reader suggestion).
* **On-policy comparison.** Compare Skill-FT with on-policy distillation from the same skill-conditioned teacher (Skill-SD style) at matched compute (reader suggestion).
* **Skill transfer.** Test whether skills designed for one student size or teacher transfer to another, which would show whether the agent is finding general behaviors or tuning to one pair (reader suggestion).
