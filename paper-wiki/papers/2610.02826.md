# Q1 Problem Definition

* **Input (X):** a pool of 2,929 hard terminal tasks (420 tasks filtered and made harder from the authors' earlier RST pipeline, plus 2,509 self-constructed "SWR" tasks across about 50 domains such as software usage, biology, chemistry, physics, hardware, operations, and security), one base model (Qwen-3.8-27B), and three discovery harnesses that differ in execution support: Terminus 2 (plain model-terminal loop), StateM (persistent workflow states and checked transitions), and Recursive Self-Reflect Terminus (RSRT, Terminus 2 plus continuation after a failed completion claim, up to 180 minutes, told only that verification failed).
* **Output (Y):** (a) a set of verified training trajectories expressed entirely in the general Terminus 2 interface, and (b) a fine-tuned Qwen-3.8-27B that runs under Terminus 2 alone, with no source harness and no runbook at inference.
* **Core problem:** different harnesses let the same model solve different hard tasks, so their successes are valuable supervision. But each successful trajectory also records its harness's controller messages, task-specific prompts, workflow logic, and stopping rules. Pooling such trajectories for SFT can teach the model to expect control that will not exist under a general harness at deployment. The paper asks how to keep the useful planning, checking, recovery, and continuation behavior while removing the harness-specific scaffolding.

# Q2 Problem Novelty

Not a new problem. Learning from one's own successful trajectories is old (SWE-Gym trains on verified software-engineering trajectories; Reflexion and ExpeL reuse lessons in context), and transferring harness-supported behavior into weights is an active 2026 thread: Harness-Zero distills harness behavior for a fixed target harness, DCAS studies transfer across scaffolds, and Yu et al. report that imitating stronger experts can misfit a weaker model's execution setting. What is new here is the framing of *several* harnesses as discovery tools whose union widens the set of solved tasks, and a same-model rewrite step that turns each harness-assisted success into fresh executions under one general harness. The paper contrasts itself with recursive self-improvement work that optimizes a harness or co-evolves harness and model (ModularRSI, SoL-Pi, [Dream-RSI](2609.14858.md), [ScienceBuddy](2609.17523.md)): RSR "does not optimize a single harness or assume an autonomous recursive cycle". The problem matters because harness gains on Terminal-Bench are large and model-specific, and a model that only performs well inside one harness is hard to deploy elsewhere.

# Q3 Scientific Hypothesis

1. **Complementarity hypothesis.** If one fixed model is run under harnesses with different control logic, the harnesses will solve partly disjoint task subsets, so their union yields more (and more diverse) successful trajectories than any one harness. Tests: Table 1 (per-harness and union coverage), the equal-rollout subset (1,247 tasks), Figure 5 (per-domain coverage), Table 3 (execution styles), Table 6 (base-model harness swap on benchmarks).
2. **Rewrite hypothesis.** If each harness-assisted success is compacted, turned into a runbook, screened for leakage, and re-executed from scratch under the general harness, then SFT on the passing re-executions will beat both the base model and SFT on the raw source trajectories, because the training data then matches the deployment harness while keeping the behavior that made the source succeed. Tests: Table 5 (Base vs. Direct SFT vs. RSR on six benchmarks).

# Q5 Key Solution Idea

The differentiator is a same-model rewrite pipeline that sits between multi-harness discovery and SFT.

* **Multi-harness discovery.** Run Qwen-3.8-27B under Terminus 2, StateM, and RSRT; keep every rollout that passes the task verifier. 14,598 rollouts yield 2,001 passing trajectories on 759 tasks.
* **Planner.** Compact each source trajectory (task instruction, actions, observations; harness control messages removed) and write a runbook: required end state, key milestones, useful checks, recovery strategies, common pitfalls. Runbooks may describe interfaces and validation but must not contain the finished deliverable. K = 4 runbooks per source.
* **Critic.** Deterministic checks (schema validation, removal of known artifacts, rejection of unsupported tool references), then a model-based critic that sees only the public task instruction and the runbook and rejects verifier leakage and solution leakage. The abstract says rejected candidates are regenerated from critique feedback ("recursive" revision); the method section describes only the screening.
* **Executor.** Each retained runbook guides M = 4 fresh executions in a new sandbox under Terminus 2 at temperature 0.7. The runbook is private guidance and never appears in the recorded trajectory, so the executor must act on the current environment rather than replay the source.
* **Trajectory filter.** The same model flags values that appear in a trajectory but cannot be derived from the task or environment (a sign of hidden answer transfer), and those demonstrations are discarded. Only the public interaction history (instruction, observations, model responses) is kept for SFT.

The paper rewrites sources from StateM and RSRT (Sec. 3.4); the RSR training set is the passing rewrites plus the 766 passing Terminus 2 trajectories used as is. 12,893 rewrite rollouts give 11,094 passing rewrites (86%).

# Q6 Experiment Design

* **Discovery analysis.** Coverage per harness and per union (Table 1), rollout counts and per-rollout success (Table 2: 14.2%, 15.9%, 11.7%, pooled 13.7%), an equal-rollout subset that removes the unequal sampling caused by more sandbox errors under RSRT and StateM, per-domain coverage over 87 fine-grained labels (Figure 5), and execution-style statistics with a rule-based command classifier (Table 3).
* **Rewrite analysis.** Two case studies (Markdown inline parsing from an RSRT source, OpenFOAM PitzDaily from a StateM source) and command-similarity metrics within and across runbooks (Table 4).
* **Training comparison.** Three arms on the same base model: Base; Direct SFT on the 2,001 passing source rollouts with harness-specific insertions removed; RSR on rewrites plus 766 Terminus 2 trajectories. Benchmarks: Terminal-Bench 2 (89 tasks), Terminal-Bench 3 (74), Terminal-Bench 4 (66), Terminal-Bench Hard (100, from RST), Software Terminal 100 (SWR100, self-curated), and Long-Horizon Terminal-Bench (LHTB, 46 tasks, process reward). Metrics: pass@3 and mean per-run pass rate over three runs.
* **Harness ablation without training.** The base model under each of the three harnesses on TB2, TBH, and TB3, one run each (Table 6).
* **Not designed in.** No data-size-matched comparison (Direct SFT trains on 2,001 trajectories, RSR on about 11.9K); no ablation removing the critic, the trajectory filter, or the runbook (for example, re-executing the same tasks without guidance); no count of how many runbooks the critic rejected or how many trajectories the leakage filter removed; no training hyperparameters in the retrieved text; no train-test overlap analysis between the RST/SWR training tasks and TBH/SWR100; no confidence intervals.

# Q8 Evidence Quality

* **Well supported.**
  * Harness complementarity is clear and survives the sampling control: the union solves 759 tasks against 565 for the best single harness, and on the equal-rollout subset 352 against 285 (+23.5%); every harness keeps exclusive solves (30, 56, 21 on that subset). Table 6 shows the same pattern at evaluation time: the union of three harnesses solves 68.5% of TB2 and 70.0% of TBH where the best single harness reaches 58.4% and 66.0%.
  * RSR beats Direct SFT on every benchmark and metric in Table 5. The TB2 gain is large in absolute tasks (66/89 against 48/89 pass@3; mean 70.1% against 43.8%), and on TBH 63/100 against 56/100.
  * Direct SFT *lowers* TB2 below Base (pass@3 57.0% to 53.4%, mean 51.7% to 43.8%), which supports the paper's distribution-mismatch argument; the authors tie it to looping "dead end" behavior seen in three inspected trajectories and to RSRT trajectories longer than 100 steps.
* **Weaker than the headline.**
  * The RSR arm has about six times more training trajectories than Direct SFT and includes 766 un-rewritten Terminus 2 trajectories, so Table 5 does not separate the effect of rewriting from the effect of more data.
  * TB3, TB4, and SWR100 gains are a few tasks (7 vs. 4 of 74, 6 vs. 3 of 66, 6 vs. 3 of 100), from three runs with no intervals. On LHTB all arms complete 0 of 46 tasks; the 0.25 to 0.29 process-reward change is partial progress only.
  * TBH comes from the same RST pipeline that supplies 420 training tasks, and SWR100 from the same team's SWR collection; overlap with the training pool is not discussed.
  * Bookkeeping does not fully reconcile: the abstract says RSR expands "2,001 successful source trajectories", while Sec. 3.4 rewrites StateM and RSRT sources; the rewrite rollouts cover 975 unique tasks although discovery solved only 759.
  * The leakage controls are described but not measured: there is no audit of how often runbooks or rewrites carried answer-specific content past the critic and filter.
* **Reader observation.** On TBH the untrained base model under RSRT already reaches 66.0% in a single run, above the RSR-trained model's 63% pass@3 under Terminus 2. So on that benchmark the internalized policy recovers less than the inference-time harness provides; on TB2 the trained model (70.1% mean) exceeds every single-harness base run (at most 58.4%).

# Q9 Contributions

* Evidence that harnesses act as complementary *discovery* tools for one model: no harness dominates across domains, and their union adds 194 solved tasks (34.3%) to the best single harness.
* A same-model planner-critic-executor rewrite pipeline that converts harness-assisted successes into general-harness trajectories, with private runbooks, leakage screening, fresh-sandbox re-execution, and a provenance filter for values not derivable from the task.
* A measured failure of the naive alternative: direct SFT on mixed-harness trajectories can regress the general-harness model (TB2).
* A released 27B model trained on the rewritten trajectories, with gains on all six reported evaluations over Base and Direct SFT.

# Q10 Next Steps

* **Isolate rewriting from data volume.** Train Direct SFT on a subsample matched to RSR's size, or RSR on 2,001 rewrites, and ablate the critic, the filter, and runbook guidance separately.
* **Measure leakage.** Report critic rejection rates and run an independent leakage audit on a sample of runbooks and rewrites, since the same model writes, screens, and executes them.
* **Close the harness gap.** On TBH the base model under RSRT still beats the trained model under Terminus 2; iterating discovery with the RSR model (a second round) would test whether the gap keeps shrinking, which is the "recursive" reading the title suggests but the paper does not run.
* **Cross-model transfer.** Rewrite the same harness-assisted successes with a different executor model to see whether runbooks transfer across models or only across harnesses.
* **Project fit (reader note).** The private-runbook pattern (guidance used during generation but kept out of the recorded trajectory) is a concrete recipe for turning skill-assisted agent runs in this repository into training or evaluation traces that do not depend on the skill being present.
