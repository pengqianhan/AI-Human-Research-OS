# Q1 Problem Definition

The paper asks for the **minimal viable pipeline for optimizing an agent skill** when the foundation model and task harness are initially fixed. A skill is a mutable natural-language program; task rollouts produce trajectories and scores; an optimizer must edit the skill so that expected reward improves on unseen tasks without overfitting individual failures.

It then widens the optimization target from a skill file to the executable harness. In this second setting, the candidate edits may change prompt context, tools, control flow, state handling, and other runtime code. The desired output is therefore either a better validated skill or a better validated skill–harness pair, while preserving independent evaluation and reversibility.

# Q2 Problem Novelty

Automated reflection, skill evolution, and harness optimization are established problems. SkillOpt already frames textual revision through optimization analogies and uses mini-batch reflection pooling, hierarchical merging, learning-rate-like update damping, and rejected-edit history. Other cited systems use single-trace reflection, contrastive diagnosis, fault-isolated edits, or pooled trajectory lessons.

The novelty is the paper's attempt to identify which components are actually necessary. It argues that semantic execution traces make skill optimization unlike blind numerical search: a coding agent can inspect causal evidence in readable logs and patch the natural-language program directly. SkillOpt-Lite consequently tests whether file-system exploration, cross-trajectory consensus, minimal editing, and held-out validation can outperform a more elaborate optimizer. HarnessOpt applies the same loop to executable scaffolding.

# Q3 Scientific Hypothesis

The central hypothesis is: **if an optimizer can inspect raw trajectories as files, extract failure patterns shared across tasks, make a bounded patch, and accept it only on an independent validation set, then skill evolution should converge faster and generalize at least as well as pipelines that pool reflections and damp textual updates.**

Two supporting hypotheses are explicit. First, consensus across heterogeneous trajectories should reduce sensitivity to single-example peculiarities; the paper connects this to expected on-average stability in PAC learning. Second, selecting candidates on a disjoint validation set should provide a cleaner generalization gate than reusing training failures. The harness extension hypothesizes that jointly editing skills and execution code can remove bottlenecks that prompt-only optimization cannot reach.

# Q4 Related Work and Key People

The related work falls into four groups:

* **Open-loop verbal learning:** Reflexion and Voyager turn individual trajectories into textual lessons but do not provide the paper's independent dynamic validation loop.
* **Structured skill optimization:** SkillOpt, Trace2Skill, SkillForge, SkillCAT, SkillAdaptor, and SoftSkill add aggregation, contrast, isolation, compression, edit constraints, or rejected-update mechanisms.
* **Agent interfaces and harnesses:** SWE-agent, Code as Agent Harness, Meta-Harness, Agentic Harness Engineering, and Self-Harness treat the software around the model as a major capability determinant or optimization target.
* **Theory:** zeroth-order optimization supplies analogies for gradient estimation, coordinate search, trust regions, and control variates; stability and validation bounds supply the paper's generalization argument.

Yifei Shen and Bo Li are affiliated with LMMs-Lab, Bo Li also with NTU MMLab, and Xinjie Zhang with Microsoft. Researchers working on skill learning, prompt optimization, agent interfaces, program synthesis, and evaluation would likely focus on whether the simplified pipeline's gains survive independent replication, larger validation sets, and component-wise ablations.

# Q5 Key Solution Idea

SkillOpt-Lite treats the working directory as the optimizer's memory and interface:

1. **Trajectory staging:** each rollout, including reasoning history, environment states, and task score, is saved as an independent text file rather than pre-merged into a reflection batch.
2. **Trajectory exploration:** a coding agent uses ordinary file and shell tools to locate clusters of failures and inspect high-leverage traces without loading the whole corpus into one context window.
3. **Consensus mining and minimal edit:** the optimizer looks for cross-task invariants, rejects one-off quirks, and writes a compact patch to the active skill.
4. **Validation gating:** the candidate is scored on a disjoint validation set. An improvement becomes active; a new historical best overwrites `best_skill.md`; rejected candidates go to logs rather than an active rejected-edit buffer.

This removes SkillOpt's mini-batch reflection pooling, hierarchical text merging, learning-rate-like damping, epoch-level slow updates, and live rejected-edit buffer. HarnessOpt lifts the editable-path restriction from one skill file to harness source code. Its round-zero diagnostic proposal requires human approval; later rounds restrict writable files, run compile and five-example smoke checks before full validation, use a sample-dependent dead band for small score changes, keep feature toggles, and roll back regressions.

# Q6 Experiment Design

SkillOpt-Lite is compared with initial skills and the full SkillOpt pipeline on six benchmarks: SearchQA, SpreadsheetBench, ALFWorld, LiveMathematicianBench, DocVQA, and OfficeQA Pro. The comparisons use the same optimizer models; GitHub Copilot is the file-operating coding agent. SkillOpt runs for at least four epochs or ten batches, while SkillOpt-Lite runs for ten batches. Because the original LiveMath and OfficeQA validation sets contain only 10–20 instances, the authors change those two train/validation/test splits from 2:1:7 to 2:2:6; OfficeQA uses an offline variant because active search APIs were unavailable.

Reported results include:

| Setting | Paper-reported result |
|---|---|
| Average Spreadsheet score across evaluated model scales | SkillOpt-Lite 69.7 vs SkillOpt 57.1 |
| LiveMath, GPT-5.5 | SkillOpt-Lite improves over SkillOpt by 8.8 points |
| LiveMath, GPT-5.4-nano | SkillOpt-Lite improves over SkillOpt by 25.4 points |
| ALFWorld, GPT-5.4-nano | SkillOpt-Lite reaches 81.3%, 9.5 points above SkillOpt |
| SpreadsheetBench, GPT-5.4-nano | joint HarnessOpt reaches 0.7758 vs 0.7620 for GPT-5.5 with the standard harness and SkillOpt |
| Best joint HarnessOpt scores | 0.8505 for GPT-5.4 and 0.8577 for GPT-5.5 |

The paper reports the largest skill-optimization gains on reasoning and deterministic code-execution tasks. Search, embodied interaction, and enterprise QA generally show smaller differences. Ten-step validation traces are used to argue that the simplified pipeline reaches useful candidates earlier. HarnessOpt is evaluated as a focused SpreadsheetBench case study across four model scales, with qualitative diagnoses of model-specific failures such as limited spreadsheet observation, weak answer checking, and repetitive tool-failure loops.

# Q7 Datasets and Code

The study uses existing datasets rather than introducing a new one: SearchQA, SpreadsheetBench, ALFWorld, LiveMathematicianBench, DocVQA, and OfficeQA Pro. The paper modifies the splits for LiveMath and OfficeQA as described above and uses an offline OfficeQA setup, so comparisons should preserve those exact variants.

The authors link a public SkillOpt-Lite repository and a project page. The paper describes a VS Code Copilot integration that exposes skill and harness optimization through slash commands. The paper text establishes the repository's availability, but this reading did not independently reproduce its experiments or audit whether every benchmark split, trajectory, model endpoint, and result artifact is packaged for one-command replication.

# Q8 Evidence Quality

The evidence is broad enough to support a promising systems result: the skill pipeline is tested across six task families and several model scales, uses the same optimizer models for the main comparison, reports convergence traces, and includes an explicit held-out acceptance gate. The pilot also supplies a useful negative result: an unvalidated one-batch edit can beat the full optimizer on some tasks yet degrade Spreadsheet, motivating validation rather than simplicity alone.

Important limits remain:

* SkillOpt-Lite removes several mechanisms together, so the comparison does not isolate which removed component causes each gain or cost reduction.
* LiveMath and OfficeQA begin with very small validation pools; changing their splits reduces but does not eliminate selection variance, and the reported text does not provide uncertainty intervals or repeated-seed significance tests.
* The zeroth-order and PAC analyses justify design intuitions and gates, but they do not by themselves prove convergence of LLM-generated edits in discrete program space.
* HarnessOpt's empirical evidence is a single SpreadsheetBench case study. Its reported model inversion demonstrates what happened under this harness and protocol, not that smaller models generally surpass larger ones after environment optimization.
* Several explanations for why reflection pooling hurts or why particular harness edits help are plausible post-hoc mechanisms rather than separately randomized causal tests.

The paper therefore supports a strong hypothesis that direct file-based debugging plus independent gating is an effective optimization baseline. It does not yet establish that every complex optimizer component is redundant across models, domains, or long-running evolution.

# Q9 Contributions

1. Reframes skill optimization as a language-mediated program-debugging problem while mapping existing techniques to zeroth-order optimization operators.
2. Connects cross-trajectory consensus to algorithmic stability and argues for strictly independent validation when selecting evolving skills.
3. Introduces SkillOpt-Lite, a four-stage, file-native optimization loop with fewer active mechanisms than SkillOpt.
4. Reports faster convergence and improved results across six benchmarks, with especially large gains on reasoning and spreadsheet tasks.
5. Extends the same file-native loop to editable harness code through HarnessOpt.
6. Adds concrete harness safeguards: human-approved bootstrapping, path restrictions, sandboxed smoke and validation gates, dead-band handling, feature toggles, and rollback.
7. Packages the workflow as an IDE-facing implementation for triggering skill evolution from a concise command.

# Q10 Next Steps

The highest-value follow-up is a preregistered factorial ablation of trajectory files, autonomous exploration, consensus instructions, edit-size constraints, independent validation, rejected-history access, and slow-update mechanisms. It should use repeated seeds, larger held-out sets, paired confidence intervals, fixed token and wall-time budgets, and untouched final test sets.

HarnessOpt needs multi-domain evaluation and stronger software-engineering evidence: regression suites, security and permission tests, patch-size and maintainability metrics, crash and rollback rates, adversarial trajectories, and independent review of accepted mutations. Long-running studies should test whether repeated accepted patches accumulate complexity or validator overfitting even when each local step appears beneficial.

For this Research OS, the directly reusable design is a **file-native evidence loop**: preserve raw attempts as separate artifacts, mine only recurring lessons, propose the smallest patch, and require validation outside the evidence used to generate that patch. Promotion from a project-local lesson into a shared skill or harness should also consider provenance, generality, maintainability, and human authority—not only a scalar benchmark increase.
