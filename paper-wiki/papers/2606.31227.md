# Q1 Problem Definition

* **Input (X):** an AI agent's full deployment surface — the model-serving/agent-platform infrastructure it runs on, the MCP servers and installed agent skills that extend it, its live conversational behavior as exposed to end users, and the underlying LLM's alignment robustness under adversarial prompting.
* **Output (Y):** for each of four layers, a structured finding set (issue type, severity, supporting evidence, remediation suggestion) and an aggregate security score; for the model layer specifically, an attack-success-rate profile across (vulnerability × attack-operator) combinations rather than a binary verdict.
* **Core problem:** AI-native software (model servers, agent platforms, MCP servers) has grown faster than the security tooling that defends it — components are too new for existing fingerprint databases, version themselves irregularly, and carry a different dominant threat model (unauthenticated compute access, credential leakage, prompt injection, tool abuse, jailbreaks) than classical web scanners target. No single detection technique can establish sound evidence across all four layers at once.
* **Scope:** four integrated modules — rule-based infrastructure scanning, LLM-driven MCP-server and agent-skill auditing, black-box multi-turn agent red-teaming, and large-scale jailbreak evaluation — released as an open-source platform (CLI, web server, and an installable agent skill) by Tencent Zhuque Lab.

# Q2 Problem Novelty

Per the paper's stated motivation, three gaps separate the AI attack surface from existing tooling's reach: a *cataloguing gap* (fingerprint databases lack signatures for young AI components), a *versioning gap* (AI projects use irregular schemes — build numbers, `.dev` snapshots, rolling `latest` tags — that break semantic-version comparison), and a *threat-model gap* (the dominant AI-era exposures are unauthenticated access, credential disclosure, prompt injection, and tool abuse, not the injection/XSS classes classical scanners hunt for). The paper's second novelty claim is architectural: security risk is stratified across four layers that differ not just in implementation but in what kind of evidence establishes a finding, so — per its own Related Work comparison (Table 6) against Nuclei, Semgrep, CodeQL, Invariant MCP-Scan, MCPSafetyScanner, garak, PyRIT, promptfoo, and DeepTeam — no prior open-source tool spans all four layers or audits the agent-skill supply chain, which the paper positions as its most direct point of novelty.

# Q3 Scientific Hypothesis

Formalized as the **Layer-Adaptive Assessment Principle**: if each attack-surface layer is evaluated with the *least expensive* assessment paradigm capable of producing the evidence class that layer requires — deterministic signature matching for infrastructure, LLM-driven semantic auditing for MCP servers and agent skills, interactive black-box red-teaming for deployed-agent behavior, and large-scale statistical attack enumeration for model alignment — then the resulting framework achieves security coverage across the AI stack that no single-paradigm tool can achieve, while preserving the speed, reproducibility, and near-zero false-positive rate of the cheaper paradigms wherever they suffice. The paper derives this from two supporting principles it states formally: Security Heterogeneity (different risk classes require fundamentally different evidence) and Evidence Sufficiency (an assessment procedure is valid only if it can produce the evidence class a given property requires).

# Q4 Related Work and Key People

* Ten-author team from **Tencent Zhuque Lab** (Yong Yang, Xing Zheng, Huiyu Wu, Huangsheng Cheng, Xiaorong Shi, Jing Guo, Bo Yang, Yi Zhou, Xiangfan Wu, Zonghao Ying).
* Positions itself against tools that are each strong within a single layer: template-driven network/code scanners (Nuclei, Semgrep, CodeQL) cover infrastructure and source code but have no notion of agents or model alignment; MCP-specific auditors (Invariant MCP-Scan, MCPSafetyScanner) cover the protocol layer alone; LLM red-teaming frameworks (garak, PyRIT, promptfoo, DeepTeam) probe agent/model behavior but neither fingerprint infrastructure nor audit MCP source. None, per the paper, audits the agent-skill supply chain.
* Builds on an active MCP-security literature establishing tool poisoning, tool shadowing, and "rug pulls" — attacks whose vector is a tool's advertised metadata rather than its output or source — as real and effective; the paper frames its M2/M3 modules as operationalizing detection of these classes within a deployable auditor and red-teamer, rather than measuring one attack class in isolation.
* The model-layer module (M4) is built on an open-source red-teaming framework (an extended fork of DeepTeam) and integrates established jailbreak techniques from the literature (GCG-style optimization, PAIR query-based search, tree-of-attacks search, Crescendo multi-turn escalation, best-of-n sampling) and standardized benchmarks (SafeBench, JailbreakBench); its stated contribution there is unification and scale rather than a new attack or benchmark.

# Q5 Key Solution Idea

1. **Layer-paradigm matching.** Four attack-surface layers (infrastructure, protocol/tool, agent behavior, model) are mapped to four evidence classes (signature, semantic, behavioral, statistical) and four corresponding detection paradigms, formalized in Section 4 as the layer-adaptive assessment framework described in Q3.
2. **Infrastructure scanning (M1).** A hand-written interpreter evaluates declarative YAML fingerprint and vulnerability rules — 107 fingerprint rules and 1,443 vulnerability rules across 75 AI components — over four match fields (body/header/icon/hash) with a version-normalization procedure built specifically for irregular AI versioning (build numbers, `.dev` tags, rolling `latest`). Findings are explicitly tiered by confidence (verified / version-based / inferred), and a programmatic-fingerprint escape hatch handles components (e.g., MLflow) that resist declarative description.
3. **MCP server auditing (M2).** An LLM-driven agentic harness with a bounded reason-act loop, context-compaction for large repositories, and heterogeneous model routing (different models for reasoning, code-reading, and cheap filtering). Introduces **"Prompt-as-Rule"**: detection knowledge encoded as natural-language criteria plus explicit exclusion conditions (ten patterns aligned to the OWASP MCP Top 10), run in both static (source-code) and dynamic (black-box protocol-only) modes. Because an LLM auditor that reads untrusted code/tool output is itself an injection target, the harness structurally separates instructions from ingested data and judges tool-abuse findings by the *response* rather than the crafted *request* ("analyze the result, not the input").
4. **Agent-skill scanning** extends the same LLM-driven paradigm to SKILL.md packages: a staged pipeline (preprocessing → static risk-clue retrieval → constrained agentic analysis → risk classification) audits whether a skill's actual behavior matches its declared purpose, classifying artifacts as normal/suspicious/malicious and releasing **SkillTrustBench** (5,520 evaluation cases distilled from 62,652 skills across marketplaces) to benchmark detection effectiveness.
5. **AI agent red teaming (M3).** A black-box, multi-turn conversational red-teaming agent that probes a deployed agent through dialogue alone, organized around capability-awareness (skip attacks the target has no surface for), escalation ladders (benign probe → evasion → overt jailbreak, stopping at the first confirmed hit), and objective anchors (SSRF canary tokens, planted markers) that turn subjective judgments into near-deterministic checks, across four risk families (data leakage, tool abuse, indirect injection, authorization bypass).
6. **LLM jailbreak evaluation (M4).** A three-role (simulator/target/judge), three-ingredient (vulnerability/attack/metric) harness integrating roughly seventy single-turn encoding/obfuscation operators plus multi-turn strategies (crescendo with backtracking, tree-of-attacks, best-of-n) over sixteen datasets (~7,000 harmful prompts spanning bias, toxicity, illicit activity, PII, and more), judged by a generic plus harm-specific LLM-as-judge family, yielding a comparable attack-success-rate profile per model.
7. **Delivery.** One shared backend is exposed three ways — CLI, web server (WebSocket/SSE streaming server-agent architecture), and a distributable, dependency-free agent skill installable in OpenClaw, Cursor, Claude Code, CodeBuddy, and Windsurf — with a strict data-minimization contract when an optional cloud threat-intelligence service is used.

# Q6 Experiment Design

This is primarily a systems/technical-report paper rather than a single controlled experiment. Its clearest quantitative evaluation is the **SkillTrustBench leaderboard** (Table 3): the same AI-Infra-Guard skill scanner is run with different base LLMs and scored by loose F1, precision, recall, and false-positive rate, holding the audit specification fixed and varying only the underlying model — the strongest models exceed 0.98 loose F1 with recall near 1.0. Beyond that benchmark, the report does not present head-to-head detection-accuracy tables against ground truth for the infrastructure scanner, MCP auditor, or agent red-teamer; its evidence for those modules is largely descriptive (design rationale, worked examples such as the system-prompt-extraction escalation trace) plus the qualitative capability-coverage comparison against named external tools in Table 6.

# Q7 Datasets and Code

Releases **SkillTrustBench** (dataset: huggingface.co/datasets/cuhk-zhuque/SkillTrustBench; leaderboard: huggingface.co/spaces/cuhk-zhuque/SkillTrustBench-Leaderboard), reportedly already adopted as a recommended evaluation benchmark by ClawScan, an external OpenClaw-ecosystem scanning project. Code released at github.com/Tencent/AI-Infra-Guard (5,347 GitHub stars per `hf papers info`); product/project page at matrix.tencent.com/clawscan/. The vulnerability rule corpus (1,443 rules) is described as a Chinese-language ("zh") corpus mirrored in a parallel English-language corpus; the sixteen jailbreak datasets and the ten MCP static-audit detection patterns are documented in the paper's appendices but not released as a single standalone leaderboard the way SkillTrustBench is.

# Q8 Evidence Quality

Full text was retrieved successfully via `hf papers read` (arxiv.org/html render), giving direct access to the method sections, the formal Section 4 theory, and the Related Work comparison table rather than only the abstract. As a systems/engineering technical report, most of its claims are architectural and descriptive rather than backed by held-out accuracy numbers: the corpus-scale figures (75+ components, 1,400+ rules, 16 datasets, ~70 encoding operators, ~7,000 harmful prompts) are the authors' own counts, not independently verified; SkillTrustBench is the one module with a genuine benchmark table, and it evaluates AI-Infra-Guard's own scanner design (across base models) rather than comparing against competing skill scanners. The claim of being "the only open-source framework spanning all four layers" rests on the authors' own Table 6 comparison against eight named tools, not a systematic literature survey, so completeness of that comparison is not independently checked here. No adversarial or third-party evaluation of the framework's own false-positive/false-negative rate is reported outside the skill-scanning benchmark.

# Q9 Contributions

1. The **layer-paradigm matching / layer-adaptive assessment** principle: a formal argument (Security Heterogeneity + Evidence Sufficiency) for why AI agent security requires four distinct detection paradigms tied to four distinct evidence classes, rather than one universal scanning methodology.
2. Four integrated detection modules realizing that principle end-to-end — a rule-based infrastructure scanner with AI-specific fingerprint/version-normalization logic, an LLM-driven MCP-server and agent-skill auditor built on the **Prompt-as-Rule** paradigm, a black-box multi-turn agent red-teamer with cost-aware escalation, and a large-scale jailbreak-evaluation harness — released as one open-source, extensible platform deployable as CLI, web service, or portable agent skill.
3. **SkillTrustBench**, a new benchmark jointly measuring agent-skill trustworthiness and scanner detection effectiveness (5,520 cases from 62,652 real-world skills across marketplaces), already referenced by an external project (ClawScan).
4. Three cross-cutting design patterns the authors argue generalize beyond this system: Prompt-as-Rule (declarative natural-language detection criteria with explicit exclusions), objective anchoring of otherwise-subjective LLM judgments (canary tokens, planted markers), and treating the scanner itself as an adversarial target that must defend against the untrusted artifacts it analyzes.

# Q10 Next Steps

The paper's own stated future directions: (a) large-scale measurement applying the infrastructure scanner across the public AI deployment landscape to quantify real-world exposure; (b) making the four layers cooperate — e.g., infrastructure findings seeding agent reconnaissance, or static MCP findings focusing dynamic testing; (c) continuous expansion of the fingerprint/CVE, Prompt-as-Rule, and jailbreak-operator knowledge bases as the ecosystem evolves. Open questions this note flags beyond the paper's own list: whether layer-paradigm matching generalizes to attack surfaces the four-layer model omits (persistent agent memory, inter-agent/multi-agent communication channels); how the framework's own false-positive/false-negative rate compares to human red-teamers outside the one benchmarked module (SkillTrustBench); and how Prompt-as-Rule detection criteria stay current as the MCP and agent-skill ecosystems evolve faster than any static rule corpus can track — a maintenance problem structurally similar to the harness-maintainability question already open in this wiki's Agent harness engineering topic, but applied to security rules rather than capability code.
