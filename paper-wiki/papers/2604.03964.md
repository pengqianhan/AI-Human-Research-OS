# Q1 Problem Definition

* **Input (X):** heterogeneous procedural resources for a target scientific domain — repositories, APIs, scripts, notebooks, documentation, databases, and papers.
* **Output (Y):** a library of validated, executable *skill packages*, each encoding task scope, inputs and outputs, execution steps, environment assumptions, provenance, and tests.
* **Constraint / gap:** much scientific know-how stays fragmented across artifacts that agents cannot directly operationalize. The task is to convert that know-how into reusable skills that coding and scientific agents can actually call.

# Q2 Problem Novelty

Not an entirely new problem: skill libraries (Voyager, Claude agent skills, SkillHub, SkillSMP) and resource-to-agent conversion (Paper2Agent, ToolRosetta, ToolUniverse, Deploy-Master) already exist. It still matters because prior libraries are largely hand-crafted or narrow, and the gap between abundant scientific know-how and usable agent capability is a key bottleneck for building effective scientific agents. SkillFoundry's angle is *automatic, self-evolving* construction across heterogeneous resources, with explicit novelty measurement (71.1% of mined skills differ from SkillHub and SkillSMP).

# Q3 Scientific Hypothesis

If heterogeneous domain resources are automatically mined into validated, executable skill packages and the library is maintained through closed-loop expansion, repair, merging, and pruning, then (a) the resulting library will be substantially novel and internally valid, and (b) equipping agents with these mined skills will improve performance on scientific benchmarks and on concrete domain tasks beyond what hand-crafted skill libraries provide.

# Q4 Related Work and Key People

* **Skill libraries:** Voyager (embodied skill learning); Claude / Anthropic agent skills (skills as modular packages); SkillHub and SkillSMP (used as novelty baselines).
* **Resource → agent conversion:** ToolUniverse (1,000+ ML models/APIs), Deploy-Master (50,000+ runnable tools mined from repos), Paper2Agent (papers/codebases → MCP-based agents), ToolRosetta (repos/APIs → MCP-compatible tools).
* **Domain-specific scientific agents:** ChemCrow, SpatialAgent, CRISPR-GPT, Biomni.
* **Authors / affiliation:** Shuaike Shen, Wenduo Cheng, Mingqian Ma, Alistair Turcan, Martin Jinye Zhang, Jian Ma — Carnegie Mellon University (Ray and Stephanie Lane Computational Biology Department and Machine Learning Department, School of Computer Science).

# Q5 Key Solution Idea

A self-evolving pipeline rather than a static or one-shot converter: (1) organize the target domain as a **domain knowledge tree**; (2) **mine** resources from high-value branches; (3) **extract operational contracts** (scope, I/O, execution steps, environment assumptions, provenance, tests); (4) **compile** them into executable skill packages; (5) run a **closed-loop validation process** that iteratively expands, repairs, merges, or prunes the library. The differentiation versus prior work is the automatic growth and maintenance of a domain-scoped library under executability and novelty checks, instead of hand-curated skills or single-pass repo-to-tool extraction.

# Q6 Experiment Design

* **Library-level validation:** executability and novelty of mined skills, with novelty measured against SkillHub and SkillSMP.
* **Task-level utility — MoSciBench:** six datasets spanning climate science, biomedical engineering, cheminformatics, health psychology, population genomics, and earth science (named: health spa, massspecgym, pop genetics, nurse stress, cyclone, terra). Baseline = vanilla Codex vs Codex+SkillFoundry. Metrics: Repo-Acc, Paper-Acc, and code execution success rate.
* **On-demand skill design — two genomics tasks:** cell type annotation (compared against SpatialAgent) and the scDRS workflow (Biomni with vs without SkillFoundry skills). Metrics: coverage and accuracy for annotation; a qualitative score (0–7) and RMSE against expert outputs for scDRS.

# Q7 Datasets and Code

* **Benchmarks/datasets:** MoSciBench (six datasets above). Genomics: developing human heart MERFISH dataset — 228,635 cells, 238 genes, 3 samples (Farah et al., 2024) — for cell type annotation; TMS FACS scRNA-seq with a height GWAS for the scDRS workflow.
* **Code/data release:** yes — code and an interactive dashboard at <https://github.com/ma-compbio-lab/SkillFoundry> and <https://ma-compbio-lab.github.io/SkillFoundry/> (explore the skill library, domain tree, and mined resources).

# Q8 Evidence Quality

The main claims appear supported by the reported results: 71.1% novelty versus existing libraries; improvement on five of six MoSciBench datasets; and gains on both genomics tasks. The authors flag important caveats that limit how far the hypothesis is verified — most mined skills are validated through internal testing rather than broad downstream evaluation, current coverage is relatively limited, and evaluation is concentrated on a small number of domains. So generalization beyond the tested domains and the correlation between internal tests and real downstream success are not yet established. (Note: this reading is from the abstract plus the full-text HTML; deeper critique is provisional.)

# Q9 Contributions

1. **SkillFoundry**, a self-evolving framework that converts heterogeneous domain resources into structured, executable, validated agent skills.
2. An **evaluation protocol** combining library-level validation (executability and novelty) with task-level utility.
3. Evidence that the mined skills **extend beyond existing libraries** and improve performance on scientific benchmarks.
4. A demonstration that SkillFoundry can **design task-specific skills on demand** for real scientific workflows (genomics: cell type annotation and scDRS).

# Q10 Next Steps

* **Authors' stated future work:** broaden domain coverage; strengthen expert-informed downstream evaluation across more realistic workflows; improve long-term maintenance and novelty assessment as the library grows.
* **Follow-up questions:** How are "high-value" branches of the domain knowledge tree selected? How robust is closed-loop repair/merge against skill drift and silent duplication? How well do internal tests predict real downstream success?
* **Research-OS fit:** SkillFoundry's skill-package contract (scope, I/O, steps, environment assumptions, provenance, tests) closely parallels this repo's `research-skills-hub` `SKILL.md` contract; its mining + closed-loop validation loop could inform automated skill creation and validation for this Research OS.
