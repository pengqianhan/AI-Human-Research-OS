# Q1 Problem Definition

* **Input (X):** a stream of conversational or multimodal inputs for one user, or a stream of task sessions for an agent, written to memory before any future query is known; later, a question or a new task.
* **Output (Y):** a persistent state (typed record stores plus a hypergraph index) from which a bounded evidence set answers each later question, and a procedural store of skills that a task agent follows.
* **Constraints:** three stated requirements. Source fidelity: concrete details stay recoverable after writing and after consolidation. Bounded access: a query inspects a small graph neighborhood and a capped set of rows, not the full history. Temporal identity: repeated mentions of one event may share evidence, but distinct occurrences must not merge because they are worded alike. Also: no fine-tuning, and closed or open models.

# Q2 Problem Novelty

The paper sorts existing memories by what they give up. Consolidating systems (Mem0-style fact extraction) lose details for good; keep-everything retrieval loses efficiency; binary-triple graph memories (Graphiti/[Zep](2501.13956.md), GraphRAG) split n-ary facts; hypergraph memories such as HyperMem route retrieval down from topic summaries; file-system memories, with Claude Code's auto memory as the named example, reach a detail only through a size-capped index of one-line summaries or string search; parametric memories need training. It also adopts the split between user-centric memory (record broadly, connect pieces) and agent-centric memory (distill precisely, retrieve little). The claimed novelty is one store that serves both, with records kept intact and the graph used only as a cited index. Each piece has precedents (typed memory agents in MIRIX, n-ary hypergraphs, offline consolidation); the combination and the no-rewrite contract are the new part.

# Q3 Scientific Hypothesis

If complete records remain the system of record, the graph is a bounded index whose facts cite those records, and consolidation changes only how evidence is connected (merging duplicate entity anchors) rather than what evidence exists, then a memory can be accurate on particulars, cheap at answer time, and usable with any model. The ablation predicts an ordering: flat memory (M0) below graph indexing (M1) below graph plus AutoDream (M2).

# Q5 Key Solution Idea

1. **Typed evidence plane.** A Meta Memory Manager routes each input to some of six writers (Core, Episodic, Semantic, Procedural, Resource, Knowledge Vault), each owning its type's schema. Writers keep names, counts, and dates in the record. The record is committed to the vector database before any graph work, so a failed graph write never rolls back a memory, and a failed graph read falls back to direct retrieval.
2. **Provenance hypergraph.** Only episodic and semantic records are indexed. Anchors (canonical name, type, embedding, ids of rows that mention it) are admitted by a deterministic key and gate; nearest-neighbor candidates plus one conservative LLM call per record decide renames, and a rename must pick a retrieved candidate. Each record yields n-ary frames (predicate, role-typed anchor arguments, literal attributes such as dates and prices, cited row ids); a frame needs at least two distinct anchors. A semantic frame's id hashes predicate and role-anchor keys, so repeated support accumulates on one node; an episodic frame adds an occurrence key (explicit event time, else the immutable row id), so two undated runs on different days stay separate.
3. **Graph-owned retrieval under budgets.** A deterministic planner picks one of five operators (single, temporal, intersection, list-union, count) and sets budgets from 6 base rows and 4 cited rows for a single lookup up to 8 and 12 for a count. Fifteen anchors are recalled and scored; a base lane collects rows tied to those anchors and a relation lane ranks up to 240 incident frames by an additive score with role and planned-versus-done terms. Fusion returns graph facts together with the rows they cite. The answering agent may call retrieval up to five times, and a rule-based check triggers one more search and rewrite when the draft is uncertain, lacks a requested value, or disagrees with the evidence.
4. **AutoDream, semantic side.** On the newly written semantic frontier, each eligible anchor of an identity-stable type (person, organization, location, object, concept) is paired with its nearest name-index neighbors at cosine at least 0.86; an LLM confirms or rejects each pair, rejections are cached, and per-round caps bound cost. A merge unions row ids and rewires frame arms; records, episodic-only anchors, and fact frames are never changed.
5. **AutoDream, procedural side.** Once five task sessions are pending, a distiller judges each outcome from transcript quotes and extracts lessons and mistakes; a curator creates, edits, or deletes skills, and an edit's citation of an experience is recorded only when its quote checks out.

# Q6 Experiment Design

* **User memory.** LoCoMo (1,540 non-adversarial questions) and LongMemEval-S (300 questions), judged by gpt-4o-mini with majority-of-3; SHDocQA and MHDocQA (100 questions each, substring match) and DetectiveQA (71 questions, letter match) from MemoryAgentBench; MemoryCD review summarization and generation for 100 Home_and_Kitchen users (ROUGE, BLEU-4, BERTScore). Answerer and extractor are gpt-4.1-mini at temperature 0; baselines are mem0, A-Mem, MemoryBank, Graphiti, and HyperMem (rerun by the authors with original settings), plus long-context and RAG on MemoryCD.
* **Configurations.** M0 is flat vector memory (like MIRIX-1.0), M1 adds the graph, M2 adds semantic AutoDream (invoked after every five chunks). Document-QA and all timing runs use M1; MemoryCD does not record which configuration was used.
* **Agent memory.** ALFWorld (39 training tasks, 134 held-out episodes, 50-step cap; GPT-6 Luna and GPT-5.6 Luna) and WebShop (40 training, 140 held-out, 15-step cap; GPT-6 Luna), against no memory, ReasoningBank, and AWM with shared prompts and backbone, three runs each. MetaClaw-Bench Part I (346 questions over 30 days) with GPT-5.2 and Qwen3.6-35B-A3B; the GPT-5.2 baselines are MetaClaw's reported values.
* **Cost.** Ingestion wall-clock, answer latency, answer tokens, training and test tokens.

# Q8 Evidence Quality

**Conversational recall (accuracy, percent).**

| Method | LoCoMo overall | LoCoMo multi-hop | LoCoMo temporal | LoCoMo open | LoCoMo single-hop | LongMemEval-S |
|---|---|---|---|---|---|---|
| mem0 | 82.9 | 80.5 | 80.4 | 66.7 | 86.6 | 56.3 |
| HyperMem (rerun) | 91.0 | 91.1 | 84.4 | 76.0 | 95.2 | 58.3 |
| MIRIX-1.0 (M0) | 85.7 | 83.3 | 85.0 | 70.8 | 88.3 | 58.8 |
| MIRIX-2.0 M1 (graph) | 88.4 | 89.0 | 86.0 | 71.9 | 91.1 | 70.0 |
| MIRIX-2.0 M2 (graph + dream) | 91.4 | 91.8 | 89.4 | 74.0 | 94.1 | 72.6 |

**Document QA (M1, percent).** SHDocQA 83.0 against 52.0 for HyperMem; MHDocQA 71.0 against 49.0; DetectiveQA 64.8, below MemoryBank (67.6) and HyperMem (66.2). On MemoryCD, MIRIX-2.0 has the highest value in every column of review generation and every cross-domain summarization metric, with small margins (cross-domain ROUGE-L 0.1510 against 0.1430; BERTScore spans at most 0.006 across systems).

**Agent memory (success, percent, mean ± std over three runs, GPT-6 Luna).**

| Method | ALFWorld | WebShop | ALFWorld test tokens (M) | WebShop test tokens (M) |
|---|---|---|---|---|
| No memory | 69.4 ± 0.7 | 31.9 ± 1.8 | 2.147 | 4.238 |
| ReasoningBank | 66.9 ± 2.8 | 25.7 ± 3.8 | 3.351 | 6.620 |
| AWM | 73.6 ± 1.9 | 36.0 ± 4.3 | 3.674 | 5.448 |
| MIRIX-2.0 | 76.4 ± 6.2 | 37.4 ± 2.1 | 3.813 | 4.975 |

With GPT-5.6 Luna on ALFWorld: 61.7% against 54.2% (no memory) and 58.0% (AWM), MIRIX std 14.0. Gains are uneven by task type: with GPT-6 Luna, Clean goes 60.2% to 74.2% and Heat 47.8% to 73.9%, while Pick, Look, and Pick Two fall below no memory. On MetaClaw-Bench with GPT-5.2, accuracy is 49.2% against 44.0% for MetaClaw Skills (reported) and file-check completion 27.7% against 17.1%; with Qwen3.6-35B-A3B, 52.7% against 51.8% and completion tied at 30.8%.

**Cost.** M1 answers faster than HyperMem on all five timed benchmarks (SHDocQA 5.45 s against 10.55 s); document ingestion is 3.8 to 4.0 times slower than M0, and M1's answer latency is higher than M0's on each document task. On DetectiveQA, M1 uses 1.16M answer tokens against 0.35M for HyperMem. The full M2 system is not timed.

**Limits on the evidence.** The paper is unusually explicit here: user-memory results are single runs partly scored by an LLM judge; ablations add components in groups and do not isolate n-ary frames, cited rows, occurrence identity, answer-time verification, or the distiller, judge, and curator; some baselines are reported values; merge precision and detail retention are not measured. Reader additions:

* The headline LoCoMo lead over HyperMem is 0.4 points against the authors' rerun (91.0); HyperMem's own reported 92.7 is above MIRIX-2.0's 91.4. On a single run of 1,540 questions with an LLM judge, the LoCoMo ordering against HyperMem is not established; the LongMemEval-S lead (14.3 points) is much larger than that noise.
* LongMemEval-S has 300 questions, so accuracies should be whole counts over 300. Six of the eight reported values fit (for example 70.0 = 210/300, 58.3 = 175/300), but M0's 58.8 and M2's 72.6 do not (the nearest counts give 58.7 or 59.0, and 72.3 or 72.7). This may be a different denominator or truncation; the paper does not say.
* The "graph" gain on LongMemEval-S (11.2 points, M0 to M1) also bundles the five-call retrieval agent, the operator planner, and the answer-time rewrite if those are absent in M0; the paper describes M0 only as flat vector memory, so which of these M0 shares is unclear.
* MIRIX-2.0 on ALFWorld (76.4 ± 6.2) overlaps AWM (73.6 ± 1.9) within one standard deviation, as the paper notes, and its test-token use is the highest of the memory methods there; the WebShop and ALFWorld gains over no memory come with task types that get worse.
* The MetaClaw-Bench GPT-5.2 comparison mixes the authors' run with values reported by MetaClaw's authors; MetaClaw's first author shares the name P. Xia with a MIRIX-2.0 author, which would help protocol fidelity but does not make the comparison a rerun.

# Q9 Contributions

1. A memory design that separates storage (typed, complete records committed first) from indexing (a provenance-citing n-ary hypergraph with event-occurrence identities and fail-soft writes).
2. Graph-owned retrieval with deterministic per-operator budgets that bound the evidence a question inspects.
3. AutoDream: consolidation outside the write path that merges entity anchors without rewriting records, and turns task sessions into cited skills, so one store serves user-centric and agent-centric memory.
4. Evaluation across conversational recall, document QA, personalization, and procedural memory, with a candid account of what the tables do not isolate.

# Q10 Next Steps

* **Stated by the paper.** Component-level ablations (n-ary frames, cited rows, occurrence identity, verification, procedural judge and curator); timing and token cost of the full M2 system; merge precision, source-detail retention, and skill provenance coverage; repeated user-memory runs.
* **Latency as the history grows.** The budgets bound evidence per question, but latency against history length is not measured; a growth curve would test the efficiency claim directly (paper notes the gap; measurement is a reader suggestion).
* **Shared rerun with HyperMem.** Run HyperMem and MIRIX-2.0 on LoCoMo with several seeds and two judges to settle a 0.4-point lead (reader suggestion).
* **Retrieved skills that hurt.** Pick, Look, and Pick Two got worse with memory; a gate that skips retrieval for tasks the actor already handles could be tested (reader suggestion).
* **File-memory comparison.** The paper argues against summary-indexed file memories such as Claude Code's auto memory but does not evaluate one; a head-to-head on LoCoMo would test that argument (reader observation).
