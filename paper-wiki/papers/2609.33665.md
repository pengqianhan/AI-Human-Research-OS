# Q1 Problem Definition

* **Input (X):** machine-readable tool specifications crawled from public Model Context Protocol (MCP) implementations. Each specification gives tool names, descriptions, and typed parameters, but no state model or transition logic.
* **Output (Y):** (1) a library of independently executable *services* (email, Slack, calendars, databases, and so on), each with a typed state, a tool set, and transition code; (2) verified tasks that require information to flow across several services; (3) SFT trajectories and RL tasks built from them; and (4) an agent trained on those tasks.
* **Core question:** can the *composition* of services, rather than the number of separate environments, be made an explicit scaling dimension for training general agents on multi-service workflows?
* **Formal setting:** each service is a POMDP without a task reward. A composed environment is their product: the joint state is the tuple of service states, tools are namespaced by service, and a tool call changes only its own service. Information passes between services only through the agent's observations and later actions. Task success is decided by a terminal verifier, not per-step rewards.

# Q2 Problem Novelty

Partly new. Automated environment construction for agent training is an active line: AgentScaler, ScaleEnv, Agent-World, EnvScaler, DreamGym's reasoning-based experience model, dependency-graph expansion, generated websites, and learner-adaptive environment transformations (including EnvHarness, cited by key `huang2026envharness`, which matches [EnvHarness](2608.19880.md) in this wiki). Multi-application benchmarks such as AppWorld and CompWoB already show that success on single tasks does not transfer reliably to their combinations, and Terminal-Universe builds tasks across related codebases. The authors' new element is reusing *independently executable, stateful services* and recombining them through task-specific causal dependency graphs, so which services appear together and how information must flow between them become controllable generation parameters. The second new element is a rubric reward that shifts RL credit toward the criteria a rollout group rarely satisfies.

# Q3 Scientific Hypothesis

If an agent is trained on tasks built by composing familiar services with explicit cross-service information dependencies, it should learn to coordinate those services in new combinations and improve on cross-application workflow benchmarks, more than an agent trained on the same amount of data from single environments. For RL, if rubric criteria that the current rollout group rarely satisfies receive more weight, the policy should move toward *full* task completion rather than collecting easy partial credit.

# Q5 Key Solution Idea

* **Typed services from tool specs.** A coding agent, working in the pi harness inside a sandbox, infers the service's entities and writes a Pydantic state model that rejects unknown fields and invalid updates. It implements each tool as an operation that returns an updated state and a JSON observation, writes a test suite, and repairs the code until normal-use and error-handling tests pass. A separate agent session then writes adversarial tests (including boundary conditions) from the specification alone. Tools that fail are quarantined rather than used as verified transitions.
* **Selective world-model simulation.** Tools that depend on external systems or exceed the coding agent's ability are simulated by an LLM that predicts the next state and observation. The prediction is forced through the same Pydantic models, so later deterministic tools can use the updated state. Only 7.1% of tools are simulated, and about 10% of training samples call at least one simulated tool.
* **Service library.** 448 services exposing 10,130 tools. No domain holds more than a quarter of services; software development and DevOps is largest (22%), followed by productivity and collaboration (12%).
* **Random-walk dependency graphs.** For each task, K services are sampled and a walk over them defines directed edges, where each edge means the next service needs information returned by the previous one. The walk must cover every sampled service, never visit the same service twice in a row, and revisit at least one service (a revisit models a value that went stale). Walk length L is the main difficulty control. The graph records service-level dependencies, not a fixed tool-call sequence.
* **Agentic task generation and verification.** A coding agent explores the services, turns the walk into a concrete scenario with a validated initial state, an instruction, and a rubric, then solves the task itself. Its end state becomes the reference goal, and each rubric criterion becomes an executable final-state check that must accept the reference solution. The probe must also exercise every tool the task uses. The checks test task-relevant conditions only, so other solution paths can pass.
* **Completion-Focused Rubric Reward.** For each rollout group, the pass rate p_j of every criterion is computed, the criterion gets weight λ + (1 − p_j), and a trajectory's reward is its weighted fraction of satisfied criteria (1 only when all pass). Rarely satisfied criteria therefore carry more reward. The authors' gradient analysis shows the weighting multiplies each criterion's gradient term by its completion gap, but it cannot help on a criterion that every rollout fails. The reward then goes into standard GRPO, with the same advantage applied to all agent-generated tokens and tool observations excluded from the loss.

# Q6 Experiment Design

* **Construction:** GLM-5.3 builds services and tasks, and DeepSeek-V4-Flash generates trajectories. Each task composes K = 5 services plus 5 distractor services for tool discovery, with walk length L sampled from 7 to 12. The agent uses four meta-tools: list_services, list_tools, describe_tool, and call_tool.
* **Training:** Qwen3.6-35B-A3B gets SFT on 3K successful trajectories (three epochs, batch 32, learning rate 1e-4), then GRPO on 1K tasks (Adam, learning rate 1e-5, clipping 0.20/0.28, group size 8, λ = 0.01, zero KL and entropy coefficients). The reported model is the post-RL checkpoint.
* **Benchmarks (eight):** τ³-Banking, DeepPlanning, VitaBench, VitaBench 2.0, AutomationBench 1.0.6, WildClawBench (34-task pure-text subset, run in OpenClaw), SkillsBench (OpenHands with skills, Avg@3), and Agents' Last Exam (run in Claude Code). Qwen3.5-397B-A17B serves as the LLM judge "in some" evaluations; thinking is enabled with a high reasoning budget.
* **Baselines:** closed models (GPT-5.4, Claude Opus 4.6, Gemini-3.1 Pro), open models (DeepSeek-V4-Flash, GLM-5.2, Kimi-K2.6, Qwen3.8-27B, Qwen3.5-397B-A17B, and the Qwen3.6-35B-A3B backbone), and six agent-specialized 35B-A3B models. Apodex 1.1 Mini is run under the authors' protocol; the other five (Occamy-1.0, Agents-A1, Nex-N2-mini, BigBang-1.0, Ornith-1.5-35B) use numbers reported in the Occamy report.
* **Analyses:** SFT-only scaling at 100/500/1K/3K examples, each from a distinct composition (four benchmarks, no RL); single-environment vs. composed-environment SFT at 1K trajectories each; RL reward curves; and an evaluation-set comparison with and without the reweighting (Appendix A).

# Q8 Evidence Quality

* **Supported:**
  * *Gains on every benchmark.* Improvements over the backbone are +5.84 (τ³-Banking), +9.17 (DeepPlanning), +10.50 (VitaBench), +1.62 (VitaBench 2.0), +22.00 (AutomationBench), +3.18 (WildClawBench), +15.19 (SkillsBench), and +5.82 (ALE), a mean of 9.17.
  * *Strongest on cross-application workflows.* AutomationBench task success rises from 10.33% to 32.33%, above GPT-5.4 (27.67%), Gemini-3.1 Pro (28.17%), Claude Opus 4.6 (25.50%), and GLM-5.2 (26.33%), and 4.73 points above the best agent-specialized 35B-A3B model (Occamy-1.0, 27.60%). Partial-credit domain scores rise from 41.94 to 72.68 on average, with the largest gain in HR (+49.40).
  * *Composition helps more than single environments.* At an equal 1K SFT trajectories, composed-environment training beats single-environment training on all four compared benchmarks, for example τ³-Banking 9.62→17.53 and AutomationBench 12.83→33.33. Single-environment SFT slightly *lowers* τ³-Banking and DeepPlanning below the untrained backbone.
  * *Small SFT sets already help.* All four scaling benchmarks improve over the backbone with 100 examples. At 3K, τ³-Banking reaches 17.87 and DeepPlanning 35.02.
  * *The reweighting helps the RL curve.* On an internal evaluation set, the reweighted run starts lower (about 0.63 vs. 0.68), overtakes around step 50, and reaches about 0.76 vs. 0.67 at step 140.
* **Weaker or bounded:**
  * *RL contributes little.* RL improves on SFT by 1.2 points on average across the eight benchmarks and slightly lowers τ³-Banking; the authors say the gains are "primarily driven by SFT." The reweighting ablation is an internal evaluation curve, not a benchmark comparison. In the paper's own numbers, the post-RL AutomationBench score (32.33%) is below the SFT-only 1K and 3K scores in the scaling study (33.33% and 32.67%) (reader comparison; these may come from different runs).
  * *More data does not always help.* SkillsBench peaks at 45.13 with 1K SFT examples and falls to 40.91 at 3K; AutomationBench is flat from 1K to 3K.
  * *Stronger or smaller baselines are not discussed.* Table 1's own Qwen3.8-27B row scores 38.50% on AutomationBench, above CompoWorld's 32.33% and DeepSeek-V4-Flash's 36.33%, and also leads CompoWorld on six of the eight benchmarks. The text compares only against the frontier closed models and the 35B-A3B group (reader observation from Table 1). Frontier models also lead on τ³-Banking, DeepPlanning, and VitaBench 2.0, as the authors note.
  * *Teacher confound.* SFT trajectories come from DeepSeek-V4-Flash, which itself scores higher on AutomationBench, so part of the gain may be distillation from a stronger model (reader inference). The single-vs-composed comparison at a fixed data budget is the paper's control for this and does point to composition itself.
  * *Mixed protocols.* Five agent-specialized baselines use numbers reported elsewhere, and an LLM judge is used "in some" evaluations without the text saying which. Table 1 reports no seeds or confidence intervals.
  * *Environment fidelity is checked only indirectly.* Environment quality rests on manual spot checks and downstream gains. The authors acknowledge that finite tests cannot capture real business rules and that simulated observations can mislead later decisions.
  * *No overlap check.* The retrieved text reports no check for overlap between the 448 services (built from public MCP specifications) and the applications in AutomationBench or other test benchmarks (reader note).

# Q9 Contributions

* Compositional environment scaling: a formalization and pipeline that turn a finite library of verified, typed services into a combinatorially large space of cross-service training tasks. The authors count about 1.47×10^11 possible 5-service sets from 448 services, as candidates before task synthesis and verification.
* A hybrid service-construction recipe: coding-agent implementations checked by self-written and independent adversarial tests, with a type-constrained LLM world model covering the 7.1% of tools that cannot be coded reliably.
* Random-walk dependency graphs with revisits as a controllable difficulty knob for multi-service tasks, plus probe-based verification in which the task author must solve its own task.
* The Completion-Focused Rubric Reward, with a gradient-level explanation of how it shifts credit toward unmet criteria.
* Evidence that composed-environment SFT beats single-environment SFT at equal data, and a 35B-A3B model that leads its size class on AutomationBench.

# Q10 Next Steps

* **Isolate composition from the teacher (reader note):** repeat the single-vs-composed comparison with the same teacher on all eight benchmarks, and with a weaker trajectory generator, to see how much of the gain survives.
* **Make RL matter:** the authors observe that uniform rubric scores are already high after SFT while full completion remains rare. Harder walk lengths, curricula that raise L over training, or combining completion-focused weights with structural credit assignment (as in [SLCA-GRPO](2609.29050.md)) are natural follow-ups (reader note).
* **Fidelity audits of simulated tools:** measure how often world-model observations diverge from real services and whether affected trajectories hurt or help transfer.
* **Service-library growth vs. composition growth:** the authors note each new service adds many candidate compositions. A controlled comparison of adding services against generating more compositions from the existing pool would show which scales better.
* **Link to environment adaptation (reader note):** [EnvHarness](2608.19880.md) reshapes one environment around a target policy's weaknesses, while CompoWorld widens the task distribution by composition. Choosing walks according to a policy's diagnosed weaknesses would combine the two.
