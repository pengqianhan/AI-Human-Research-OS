# Q1 Problem Definition

* **Input (X):** a task made of a persona (who the user is and how they speak), a hidden belief (the strategy the user wants), and test conditions: a data cutoff date, the channels through which the agent may reach data, a turn limit, and a time limit per turn. The agent sees only a vague opening request and receives no data.
* **Output (Y):** a deliverable, meaning every message and file the agent hands over across the session: data tables, code, backtest results, and a report. Only the deliverable is graded; the execution log and workspace can make a check fail but never make it pass.
* **Constraints:** every dated row of delivered data must be no later than the cutoff, every fill must come after its signal, and reported metrics must be recomputable from the delivered trade log. In the experiments a session has up to six rounds of 300 seconds each.

# Q2 Problem Novelty

A new combination of known difficulties. The paper argues that each existing benchmark closes the world in one place and so removes a failure instead of measuring it. Stating the task in full removes the strategy the user never asked for; handing over curated data removes the unverified figure; replaying history inside the benchmark's own pipeline removes the backtest that looks ahead. Simulated-user benchmarks in the τ-bench line do hide intent, but over a closed database with a target state. Its comparison table lists FinBen, FinDeepResearch, AlphaForgeBench, CLQT, InvestorBench, AMA, Herculean, and τ-banking, and marks only FinCosmos as having hidden intent, self-sourced data, agent-kept point-in-time correctness, generated tasks, executable deliverables, and reference-free grading together.

# Q3 Scientific Hypothesis

If intent, data, and timeline are all left open and the delivery itself is verified by programs, then sessions that look successful to the user or to an LLM judge will still fail checkable invariants. The paper calls these silent failures: nothing crashes and the report reads as convincingly as a correct one. A second claim is that the tasks are solvable, tested by letting an agent with persistent memory practice on evaluator feedback.

# Q4 Related Work and Key People

* **Financial agents and benchmarks.** Trading agents with memory, tools, and multi-agent roles (FinMem among them; this wiki's [TradingAgents](2412.20138.md) is cited in the same group), research agents, question answering over filings (FinBen, MultiFinBen), research benchmarks with fully specified questions (FinDeepResearch), strategy benchmarks that hand over a specification and curated data (AlphaForgeBench), and trading benchmarks in historical or live markets (InvestorBench, AMA).
* **Open-world agent evaluation.** Simulated users that hide intent over a closed world (τ-bench, [τ²-Bench](../concepts/tau2-bench.md), τ-Voice, τ-Knowledge); Web benchmarks that open the environment but state the task in full (WebArena, Mind2Web, GAIA, BrowseComp); deep-research benchmarks graded by LLM judges (DeepResearch Bench, PaperBench); refreshed or regenerated task sets (LiveBench, GDPevo). The paper cites evidence that simulated-user fidelity is limited, and so uses its simulator as an examiner under fixed disclosure rules.
* **Look-ahead bias.** Memorized financial values before a model's training cutoff, trading agents profiting from leaked outcomes, and audits of backtest conventions. These audit models or fixed pipelines; FinCosmos checks the backtest each agent builds.
* **Key people.** The Fin AI community (Yupeng Cao, Xueqing Peng, Lingfei Qian, Haohang Li, Yangyang Yu, Jimin Huang, Sophia Ananiadou), several of whom wrote InvestorBench, AMA, and FinBen, with Xue Liu and Jian-Yun Nie. Likely critics: authors of the evaluated agents, who would point to the 300-second turn limit, and simulated-user researchers, who would ask how results move with a different simulator model.

# Q5 Key Solution Idea

Hide the specification, give no data, and grade the delivery with programs wherever a number can be recomputed.

1. **Strategy Generator.** A hidden strategy fixes one option for each of six components: stock selection, market timing, portfolio construction, risk control, execution, and transaction cost. Coherence rules exclude combinations that make no sense. The space holds about 3.8 million strategies before parameter values are drawn, each option has a difficulty from 0 to 3, and sampling is seeded. The release freezes the first ten sampled tasks (seeds 0 to 9).
2. **User Simulator.** A language model plays one of three personas (retail investor, generalist analyst, biotech specialist). The belief enters its prompt as plain-language convictions with exact numbers. The disclosure policy is that after a single vague opening idea, the user states only what the agent asks about or proposes, objects when a proposal conflicts with the belief, and names the wrong part of a deliverable without restating the strategy. A program validates every simulator decision before the message is sent, and the simulator may close the session only when every core goal is met with cited evidence.
3. **Evaluator.** 45 dimensions in seven categories; 37 are scored 0 to 4 in five categories (data, strategy, backtest, assessment, user experience), and cost and process transparency are reported only. Programs grade 17 dimensions, an LLM judge 19, and both together 6. Where an LLM grade has a program counterpart, the lower value is used. Fifteen dimensions are vetoes. Pre-veto quality Q is the equal-weighted category mean on a 0 to 100 scale, and a session is accepted only if every veto passes, the user ended satisfied, and grading is complete.
4. **Key checks.** Data provenance (every series traceable to a URL or API call); point-in-time correctness (a single late row fails the veto); independent recomputation (returns rebuilt from the delivered trade log and compared with reported metrics within fixed tolerances; a missing trade log or price series fails); strategy fidelity (each item of the hidden strategy checked against the deliverable, with the score capped at 1 if a stated requirement is missing and at 2 if a never-stated one is).
5. **Leak-free feedback.** The agent receives scores and evidence per dimension, except that data and strategy dimensions return scores without reasons, since their evidence would reveal the hidden strategy.

# Q6 Experiment Design

* **Systems.** Claude Code with Claude Opus 5.5, Codex with GPT-6.1 Sol, Gemini CLI with Gemini 3.8 Flash, Kimi Code with Kimi K3, and Claude Opus 5.5 without tools as a bare-model baseline. Memory features are off.
* **Environment.** A sandbox per session; vendor search and scraping tools; code execution; the Financial Modeling Prep server over the [Model Context Protocol](../concepts/model-context-protocol.md) with 247 financial APIs. All ten tasks concern U.S. stocks.
* **Simulator and judge.** The simulator runs on Claude Opus 4.8 at low reasoning effort; the LLM judge on Claude Opus 5.5.
* **Protocol.** Ten tasks, three independent sessions per task and system, 150 sessions. Primary metric: acceptance rate. Also pass^k (accepted in all k sessions of a task, following τ-bench), pre-veto quality with a bootstrap interval over tasks, category scores, veto failure shares, end reasons, silent failure rate, clarification coverage (share of initially unstated items the agent got the user to state), and assumption rate (share of never-stated items the delivery gets wrong). Differences use paired permutation tests over tasks with Holm correction.
* **Human study.** Two financial experts who did not build the framework label every user message in 60 sessions for simulator errors, grade the four LLM-judged vetoes on a 30-session calibration set, and attribute each failed session to the agent, simulator, or evaluator.
* **Learning from feedback.** Claude Code with a persistent memory practices each task until first acceptance; a review step edits the memory after each graded session.

# Q8 Evidence Quality

**Main table (30 sessions per system).**

| System | Signed off | Accepted | Quality [95% CI] | Vetoes failed | Turns cut at 300 s | USD per session |
|---|---|---|---|---|---|---|
| Claude Code | 30% | 0 | 37.1 [27.8, 45.0] | 7.4 | 65% | 2.24 |
| Codex | 33% | 0 | 37.2 [30.6, 43.3] | 7.2 | 69% | 0.80 |
| Gemini CLI | 33% | 0 | 22.2 [16.9, 27.4] | 9.3 | 75% | 0.80 |
| Kimi Code | 20% | 0 | 22.3 [14.3, 31.6] | 10.1 | 74% | 0.83 |
| Bare model | 0% | 0 | 20.2 [18.8, 21.5] | 9.1 | 0% | 0.24 |

Codex and Claude Code are indistinguishable (p = 0.99). Gemini CLI and Kimi Code do not differ from the bare model, which has no tools and earns its score from describing a plan (strategy 49.8, user experience 44.6, data 0). Quality falls with task difficulty (Spearman ρ = -0.24).

**Silent failures.** The simulated user signed off 35 of 150 sessions (23%) and all 35 fail at least one veto. 29 delivered no trade log or prices, 15 used post-cutoff data or filled before the signal, 15 delivered a strategy other than the user's, and 33 of the 35 fail at least one of these three. Signed-off sessions look better than the rest (pre-veto quality 50.8 against 21.0). Using only the four LLM-judged vetoes, 17 of the 35 would be accepted, an 11% acceptance rate instead of zero. The grader also reorders agents: Gemini CLI ties for first by sign-off with 10 of 30 sessions and keeps none under the LLM-judged vetoes, while Codex keeps 8.

**Where agents break.** Of 120 agent sessions, 25 deliver the user's strategy; taken in sequence, 15 of those keep data within the cutoff, 14 also avoid look-ahead, and none delivers trades that reproduce its reported returns. A task's belief voices 6.7 items on average, the opening request states 2.6 to 3.7, and by the end the user has stated 4.5 to 5.4, so agents elicit 54 to 64% of what they were not told and get 66 to 83% of the never-stated items wrong. The strategy-ambiguity veto fails in 68% of sessions.

**What the zero acceptance rate rests on (reader observations).**

* Two strict completeness vetoes, process completeness and the verifier audit, fail in 120 and 119 of the 120 agent sessions and do not separate the agents. The paper reports that without them 2 of 150 sessions would be accepted. So the headline zero is nearly fixed by two checks whose definitions are not in the paper; the workflow table and the silent-failure breakdown carry the information.
* Time is binding. 70% of agent turns hit the 300-second limit, only 58 of 120 agent sessions reach a fourth turn, and the user walks away unsatisfied in 77. A walk-away ends the session as blocked, which fails the conversation-experience veto. The paper lists the turn limit as a limitation; the results measure these agents under a budget of at most 30 minutes of work per session.
* Two counts do not sum to 35. The paper says 29 signed-off sessions lack a trade log or prices and that the program could rebuild returns in 5; and that reported metrics match the agent's own equity curve in 10, contradict it in 11, and come with no curve in 12 (33 in total). The remaining sessions are not described.
* Ten tasks with three sessions each leave wide intervals, which the paper says.

**Trust in the benchmark.** Experts flag a task-critical simulator error in 3 of 60 sampled sessions and attribute 53 of 60 failed sessions (88%) to the agent, 3 to the simulator, and 4 to the evaluator. The LLM judge agrees with experts at κ = 0.87 on the calibration set, against 0.93 between the two experts. The experts are paid team members. The simulator, the judge, and one evaluated agent come from the same model family, which the limitations section states.

**Learning from feedback.** The memory-equipped agent reaches acceptance on all ten tasks after a median of 34.5 sessions per task (range 12 to 132, 506 in total); the median task fails 6.3 vetoes per session over its first five sessions and 2.6 over its last five before acceptance. On three tasks the last five sessions fail as many vetoes as the first five or more. Strategy ambiguity is the last veto to clear on 6 of 10 tasks. Reader inference: each task's hidden strategy is the same on every attempt and no held-out task is tested, so this shows the tasks can be passed and the feedback is usable, not that the agent acquired a skill that transfers to a new strategy. The paper's own limitation, that feedback scores can leak the hidden strategy across attempts, points the same way.

# Q9 Contributions

1. An evaluation design that hides intent, withholds data, and makes the agent responsible for point-in-time correctness, with tasks generated from a grammar instead of a fixed pool.
2. Reference-free grading in which programs recompute what can be recomputed and bound the LLM judge's scores, with vetoes that a polished report cannot offset.
3. Measurements showing that user sign-off and LLM-judged vetoes would accept 23% and 11% of sessions that program checks reject, and would rank the agents differently.
4. A workflow diagnosis: agents fail most at eliciting the strategy and at delivering reproducible results.
5. A practice loop with leak-free feedback in which a memory-equipped agent eventually passes all ten tasks.

# Q10 Next Steps

* **Limitations stated by the paper.** Ten frozen tasks, three sessions per agent; long-only U.S. equity strategies with a fixed-cost model; simulator, judge, and one agent from the same model family; most turns hit the time limit; program checks cannot prove every figure is real; feedback can leak the hidden strategy across attempts, so leaderboard results should come from frozen agents.
* **Vary the budget.** Rerun with longer turns to separate what agents cannot do from what they could not finish in 300 seconds (reader suggestion).
* **Report acceptance without the two saturated vetoes** beside the full rule, so the metric can separate agents as they improve (reader suggestion).
* **Held-out transfer for learning.** After practice on seeds 0 to 9, test the memory on fresh seeds from the same grammar (reader suggestion).
* **Simulator sensitivity.** Swap the simulator model and report how sign-off and clarification coverage move.
* **Project fit.** The rule that the workspace log can fail a check but never pass one, and that a reported number counts only if it can be rebuilt from delivered files, is directly usable for evaluating research artifacts.
