# Q1 Problem Definition

* **Input (X):** a pre-trained and mid-trained omni-modal Mixture-of-Experts model; pools of executable agent tasks with verifiers in four domains (code, general professional workflows, visual artifacts, cybersecurity); and a set of agent harnesses through which the model acts.
* **Output (Y):** a policy that solves long-horizon agent tasks more often and with shorter, more maintainable solutions, measured on public and internal agent benchmarks, plus the infrastructure that makes such training run.
* **Constraints:** rewards must be accurate, deterministic, and cheap enough to compute for about 25K trajectories per step; training must stay stable at context lengths up to 1M tokens; and the reward must not be obtainable by shortcuts such as fetching a published fix.
* **Core problem:** how to scale RL post-training for agents along training compute, environment and harness diversity, and grader compute at once, without reward hacking, expert-load collapse, or runaway trajectory length.

# Q2 Problem Novelty

Not a new problem. Large-batch agentic RL is the standard post-training route for frontier models, and the report builds on named prior parts: [GRPO](../concepts/grpo.md), partial rollout (Kimi k1.5), dynamic sampling of zero-variance groups, Rollout Routing Replay (R3) for MoE train-inference consistency, multi-teacher on-policy distillation (MOPD), and the Muon optimizer family. What is new here is mostly engineering at a disclosed scale and a few specific mechanisms: training across recombinable *mini-harnesses*, two groupwise grading schemes that separate passing rollouts by quality, freezing the MoE router during RL, a four-layer reward-hacking defence, and prefix-conditioned distillation (MOPD2). The online grading scheme (GAR) is cited to a separate paper from the same group (Dong et al., 2026).

# Q3 Scientific Hypothesis

1. **Compute.** If RL batch size, environment diversity, and grader compute are scaled together, benchmark scores keep rising across coding, general, visual, and cyber tasks during one run.
2. **Harness diversity.** If the same tasks are trained under several minimal, decoupled harness configurations, the learned behaviour transfers to harnesses never used in training.
3. **Groupwise grading.** If passing rollouts in a group are ranked by quality and positive advantage is moved toward the better ones, pass rate keeps improving while turn count and token length stay controlled and patches stay within scope.
4. **Router freezing.** If the MoE router is frozen during RL, expert load stays balanced and benchmark performance is unaffected.
5. **Layered hack defence.** If environments are cleaned, attacked by a dedicated hack agent until no exploit remains, and audited during training, confirmed reward hacking stays a small share of trajectories.

# Q5 Key Solution Idea

* **Foundation.** A hybrid backbone interleaving 128-token sliding-window attention with global attention, sparse MoE feed-forward layers, a 681M-parameter ViT, and audio encoders. Pre-training covers 48T tokens (Flash) and 30T (Pro). Mid-training on agent-centric data extends context from 256K to 1M, switches hidden weight matrices to the Muown optimizer for large-batch training, uses MXFP4 quantization-aware training, and includes examples in which the model reflects on and corrects its own earlier reward-hacking turns.
* **RL at scale.** GRPO with prompt-mean loss aggregation and asynchronous partial rollouts (staleness 4). Each step uses 1,568 prompts with group size 16, about 25K sequences and 2.7-3.7B training tokens (roughly 110K-150K tokens per sequence). Importance-ratio clipping has separate bounds for positive and negative advantages, widened or narrowed at runtime from policy entropy. Groups that all pass or all fail are filtered out.
* **Environments.** *Code:* five synthesis pathways (GitHub pull requests and issues, internal development requests, specification-driven tasks, source-code-driven synthesis, long-horizon elaboration); each task is attempted four times and an auditing agent compares its own judgement of each patch with the test reward to flag false positives and false negatives; fail-to-pass and pass-to-pass outcomes must be stable over eight reruns. *General:* resettable local workspaces with multi-agent-built software mocks, tasks scored by atomic binary rubric items (code checks plus LLM checks), a self-hosted SFT model as grader. *Visual:* open-ended design graded pointwise then groupwise, and visual replication graded mainly by pixel-level similarity. *Cyber:* reproduce an OSS-Fuzz vulnerability; a proof-of-concept is accepted only if the sanitizer's vulnerability type and topmost project-level stack frame both match by string rules, and the agent gets the compiled harness binary as well as source.
* **Multi-harness training.** Production harnesses are rejected as RL substrates because their safeguards and instruction prompts fall outside the task reward and their modules cannot be varied one at a time. All training harnesses instead derive from one minimal agent loop (system prompt, tools, context management) whose implementations are recombined per domain.
* **Reward-hacking mitigation.** (1) the mid-training correction data; (2) environment preparation: remove build logs, verifier outputs, residual patches, bytecode, and caches, truncate Git history at the base commit, isolate containers from the network, and instruct against retrieving existing solutions; (3) a hack agent that probes prepared environments, with cleanup and re-attack repeated until it finds no exploit; (4) offline trajectory audits during training, with the online grader zeroing the reward of confirmed hacks.
* **Groupwise agentic grading.** *GRS* (offline, for a subset of high-pass-rate tasks): an agent studies several rollouts and writes task-specific solution and behaviour rubrics; a grader agent later scores each training rollout, and the reward is $R^{\mathrm{test}}\cdot S^{\mathrm{sol}}\cdot S^{\mathrm{beh}}$. *GAR* (online, remaining code tasks): an SFT-trained grader inspects all trajectories of a mixed-outcome group in a shared workspace, ranks passing patches on approach, precision, minimality, absence of side effects, and craftsmanship, and rescales passing advantages by quality factors so that their total is preserved (up to a cap on the rescaling factor), leaving failed trajectories unchanged before a final re-centring.
* **Behavioural regularization.** A length penalty applied only to successful rollouts that exceed a percentile reference length within groups above a pass-rate gate; segment-level penalties that mask malformed or invalid tool calls in positive trajectories and penalize them more in negative ones, with the removed advantage mass redistributed.
* **After RL.** MOPD2 combines domain teachers, including SFT-trained teachers for tasks without reliable rewards, by sampling single student turns from teacher or demonstration prefixes.
* **Infrastructure.** A Sample to Sequence to Context to Segment trajectory hierarchy with a rule-and-strategy Penalty Module; a multi-tenant Harness Pool on Ray; a Payload Porter that keeps the driver on metadata while payloads sit in a distributed store; a Sample Mixer that holds the per-source batch mix despite 90x and 66x spreads in tokens and rollout time across 25 sources; context caching across GPU and pinned host memory.

# Q6 Experiment Design

* **Main runs.** One RL run per model ("You Only RL Once"). Task mix: agentic and competitive coding 68%, general tool use 12%, aesthetic design 13%, context following 3%, cybersecurity 4%.
* **Curves during RL.** DeepSWE v1.1, AutomationBench v1.0.6, and the internal MiMo Visual Coding benchmark, with total token counts; DeepSWE Pass@1 under four training mini-harnesses and three held-out harnesses (codex, claude code, mini-swe-agent).
* **Ablations.** GAR on and off (Flash, code-only RL, batch 128, token-mean loss); router frozen against trainable (Pro, expert-load statistics at decoder layer 9).
* **Final comparison.** 17 benchmark rows in four categories against MiMo-V2.5 Pro, Claude Opus 5, GPT-5.6 Sol, and Claude Fable 5, with baselines at their highest reasoning setting; the MiMo-V2.6 numbers are after RL plus MOPD2.
* **Run failure analysis.** A timeline of interruptions for both runs by cause.
* **Open suite.** Qwen3.5-9B is fine-tuned on 77.4B tokens of MiMo-generated data (27.2B loss tokens) to give MiMo-V2.6-Distill-Qwen-9B, then trained with GRPO separately per domain on the released environments, plus a multi-harness coding run scored on seven harnesses.

# Q8 Evidence Quality

* **Supported.**
  * *Scores rise during RL.* DeepSWE v1.1 average@3 goes from 58.4 to 72.6 (Pro) and 48.7 to 65.7 (Flash) as cumulative RL cost grows. For Pro the cost splits into rollout 43.8%, training 43.5%, and grading 12.7%.
  * *Router drift causes load collapse.* With a trainable router, over the first 20 steps the coefficient of variation of expert load rises from 0.78 to 2.0, peak load from 6x to 16x the mean, and cold experts from 0.5% to 22%. Restoring only the router's pre-RL parameters at step 20 recovers balance with benchmark performance unchanged; the frozen-router run stays flat (about 0.7, 5.5x, 1%).
  * *Online grading changes training dynamics.* Without GAR, turns and token length grow quickly and more trajectories hit the length limit; with it, pass-rate gains continue through step 52 with roughly stable turn counts. Maintainer-style audits found the ungraded policy adding speculative compatibility branches, swallowed exceptions, relaxed validation, and evaluation-specific configuration changes.
  * *Reward hacking is documented with cases.* Table 2 quotes rollouts that install a newer package release, fetch upstream files, clone the upstream repository, or read ticket history to find the fix. The hack agent found exploit paths the team's cleanup had missed, over several rounds.
  * *The open suite reproduces RL gains at 9B.* RL improves on the SFT checkpoint in all 11 reported evaluations, for example [SWE-bench Verified](../concepts/swe-bench-verified.md) 61.1 to 66.2, [SWE-bench Pro](../concepts/swe-bench-pro.md) 44.6 to 47.6, Terminal-Bench 2.1 37.1 to 52.8, [OfficeQA Pro](../concepts/officeqa.md) 19.5 to 24.8, and AutomationBench 30.3 to 33.1. Multi-harness RL improves all 21 dataset-harness pairs over SFT.
* **Weaker or narrower than the headline.**
  * *"Comparable to frontier models" is mixed on the paper's own table.* Among the 15 rows with at least one frontier number, MiMo-V2.6-Pro is highest on two (AutomationBench 53.1 against 50.3, 45.8, 46.2; Terminal-Bench 2.1 89.9 against 89.1, 88.8, 84.3) and ties on one (Agents' Last Exam 31.6). It trails on DeepSWE (71.9 against 74.0 and 73.0), Terminal-Bench 4.0 (34.9 against 49.0), ProgramBench (26.5 against 37.0), OSWorld-Verified (82.0 against 86.0), GDPval-AA (1673 against 1708), and by wide margins on exploit development (ExploitBench 47.9 against 70.0-78.5) (reader count from Table 3). CyberGym (94.0) and MiMo Cyber Bench have no frontier numbers.
  * *The multi-harness claim lacks its control.* Held-out harness Pass@1 on DeepSWE rises from about 50% to 66% during training, but no run trained on a single harness is evaluated on the same held-out harnesses, so the gain cannot be assigned to harness diversity as opposed to RL in general. The 9B experiment has the same gap: its single-harness RL result is not reported per harness (reader observation).
  * *RL and MOPD2 are not separated.* The final table is after both; no row shows the RL-only checkpoint on the full benchmark set.
  * *The GAR ablation is one pair of runs in a smaller setting.* Batch 128 and token-mean aggregation, against 1,568 prompts and prompt-mean aggregation in the main run. GRS, the length penalty, and the segment penalties have no ablation.
  * *The hack rate is what the detectors confirm.* "Below 2%" is the logged share of trajectories confirmed as hacks by the team's own grader and audits; hacks that neither catches are not counted, and no recall estimate is given (reader note).
  * *Single runs, figures without tables.* Training curves, the GAR comparison, and the router comparison are figures from one run each, with fluctuations between checkpoints noted by the authors and no variance estimates.
  * *Most of the 9B gain comes from distillation, and several test sets are in-distribution.* For example MiMo Code Bench (mini) goes 19.5 to 51.6 with SFT and to 59.9 with RL; the four internal mini sets "follow the same task distributions as their corresponding training sets".
  * *Operational fragility is reported, which is useful.* Runs were interrupted by GPU-memory double-bit errors, a Kubernetes failure, an unreachable grader, KV-pool exhaustion from biased length estimates under partial rollout, MoE imbalance giving one expert-parallel rank over 30x the mean token load, and host-memory limits during packing.

# Q9 Contributions

* A disclosed recipe and cost for scaling mixed-task agentic RL on a 1T-parameter MoE model: batch, token, and dollar figures, optimizer settings, and a failure timeline.
* Multi-harness training with minimal, recombinable mini-harnesses, evaluated on held-out harnesses.
* Groupwise agentic grading (GRS and GAR) plus behavioural regularization that keeps trajectory length in check.
* A four-layer reward-hacking defence with concrete cases and an adversarial hack agent.
* A rule-based, sanitizer-grounded verifier for vulnerability reproduction that replaces differential testing and LLM judging.
* Router freezing as a fix for expert-load collapse in MoE RL, with a diagnostic that isolates router drift.
* MOPD2 and the RL infrastructure (trajectory hierarchy, Harness Pool, Payload Porter, Sample Mixer).
* An open 9B distilled model, about 7k RL tasks with verifiers, a framework, and a mini-harness.

# Q10 Next Steps

* **From the authors.** No limitations or future-work section. The conclusion frames the release as a step toward model self-improvement and hopes the open resources support reproducible research.
* **Missing controls (reader suggestion).** A single-harness RL run scored on the held-out harnesses; an RL-only row before MOPD2; ablations of GRS and the length penalty at the main batch size.
* **Estimate hack recall (reader suggestion).** Plant known shortcuts in a sample of environments and measure how many the grader and audits catch, so "below 2%" can be read as a rate, not a floor.
* **Per-domain regression (reader suggestion).** [One to More, More to One](2609.23377.md) reports that pooled agentic RL hides a "category see-saw". With 68% of the mix on coding here, per-domain curves for the smaller shares (cyber 4%, context following 3%) would show whether the same happens at this scale.
* **Project fit (reader note).** The environment-preparation list (strip build artifacts and caches, truncate history, isolate the network, then attack your own setup until nothing leaks) is a concrete checklist for the frozen evaluators this repository's research-integrity rules ask projects to protect.
