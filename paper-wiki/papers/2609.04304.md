# Q1 Problem Definition

* **Input (X):** a natural-language question requiring live web search — typically a long-tail entity or fact identified only through multiple indirect, mutually constraining clues — plus a base MoE LLM (Qwen3.6-35B-A3B or Qwen3.5-397B-A17B, 256K-token context).
* **Output (Y):** Iris-mini (35B-A3B) and Iris-pro (397B-A17B), two single-agent ReAct search agents (no sub-agents, no test-time verification) that interleave reasoning with `SEARCH`/`SCRAPE` tool calls against live search and terminate with a final answer.
* **Core problem:** building a capable search agent requires more than a strong backbone: naturally occurring web questions are usually too easy for training (answerable from parametric memory, or resolvable by directly searching a surface string), while hand-written hard questions are expensive to scale; separately, inference-time context management (CM) — trajectory summarization, discard-and-restart, retry-with-memory — can be worth more to a benchmark score than the underlying policy differences between competing systems, so reporting only CM-enabled numbers conflates policy capability with harness engineering.
* **Scope:** two model scales (35B-A3B "mini", 397B-A17B "pro"), each evaluated with and without CM, on four benchmarks (BrowseComp, BrowseComp-ZH, DeepSearchQA, the text-only subset of Humanity's Last Exam), holding tool set, context limit, and judge fixed across all comparisons.

# Q2 Problem Novelty

Search-agent RL training (Search-R1, ASearcher, R1-Searcher, Search-o1) and hyperlink/knowledge-graph-based hard-task synthesis (WebSailor, WebShaper, DeepDive, and the same team's own prior OpenSeeker/OpenSeeker-v2, REDSearcher, FORT-Searcher) are each established lines the paper builds directly on. Its stated novelty is combining four elements that prior work mixes only partially: (a) a fully reverse-constructed pipeline that builds multi-hop questions from a real web corpus's hyperlink structure with an explicit anchor-abstraction step that removes every directly-searchable surface string, forcing disambiguation-by-reasoning; (b) dual-criteria verification that admits a question only if a reference model fails it closed-book *and* solves it once the supporting entity graph is supplied, jointly enforcing difficulty and solvability/uniqueness; (c) two-level (trajectory- and turn-level) trajectory filtering before SFT, with the turn-level rubric *induced from the judge's own free-form critiques* rather than hand-written; and (d) an "SFT-RL climbing" loop that alternates RL exploration with supervised distillation of the RL round's hardest-solved, most-efficient rollouts, plus explicit, separately-reported with/without-CM evaluation — a methodological transparency choice most prior search-agent papers do not make.

# Q3 Scientific Hypothesis

If training data is reverse-constructed from a real web-graph's hyperlink/entity structure — with anchor abstraction blocking string-matching shortcuts and dual-criteria verification admitting only questions that are simultaneously hard (closed-book failure) and solvable (open-book, unique answer) — and if the resulting teacher trajectories are filtered at both the trajectory level (correctness, non-degeneracy, minimum search depth) and the turn level (a data-induced rubric masking at most 10% of turns), then alternating supervised fine-tuning with reinforcement learning against live search ("SFT-RL climbing," feeding each round's hardest-solved rollouts back into the next SFT pass) should produce compact ReAct search agents whose *intrinsic* (no-context-management) capability is state-of-the-art among open models of comparable scale, with context management then further and separately improving performance on top of that intrinsic capability rather than substituting for it.

# Q4 Related Work and Key People

# Q5 Key Solution Idea

1. **Web-graph task synthesis.** The corpus is modeled as a directed hyperlink graph; a seed page is drawn via an answer-anchored sampling policy that fixes a target answer entity, then expanded into a local subgraph over its out-links. Because reader services strip inline anchors, the true out-link set is recovered by merging a structured semantic (RDF-triple) mirror of the corpus with rendered page markup to maximize link recall.
2. **Entity-graph distillation, multi-hop question generation, and anchor abstraction.** Raw pages are distilled into a compact, connected entity graph preserving the cross-page relational structure; a question is generated together with a reasoning path of at least N coupled relations (forcing genuine multi-hop dependence); every non-answer entity is then rewritten into a descriptive, non-identifying reference so the question cannot be resolved by searching a surface string, demanding disambiguation-by-reasoning instead.
3. **Dual-criteria verification.** A pair (question, answer) is admitted only if a reference model fails it closed-book (no tools) *and* solves it correctly when the entity graph is supplied as context — jointly enforcing difficulty and solvability/answer-uniqueness before any trajectory is generated.
4. **Two-stage trajectory filtering before SFT.** A strong teacher solves each admitted question under ReAct (interleaved reasoning, `SEARCH`/`SCRAPE` calls, on-the-fly document summarization as observations). Coarse filtering keeps only trajectories that are correct (judge-verified against the reference answer), non-degenerate (a sliding-window compression-ratio loop detector plus auxiliary detectors for repetition and identical-argument tool calls), and sufficiently deep (a minimum tool-call-turn count), then deduplicates. Fine filtering then labels individual turns KEEP/MASK with an LLM judge whose rubric is *induced from the judge's own free-form critiques* of sampled trajectories rather than hand-written, capped at masking 10% of turns per trajectory so masked-but-retained turns still provide context without contributing to the training loss.
5. **RL against live search with in-house reward/summarization.** A group-relative policy gradient is optimized against live web search using request-level partial rollout — long-tail sessions are interrupted and resumed from their committed prefix at the next step (rollouts organized as a forest of cached message states, with truncated importance sampling correcting for prefixes generated under different policy weights) rather than discarded outright. A co-located in-house Qwen3.5-397B-A17B model serves both as a binary generative reward model (scoring only the extracted final answer against the reference, no additive format term) and as the observation summarizer that compresses retrieved pages — the only context-reduction mechanism during rollout — removing dependence on an external API in the training loop.
6. **SFT-RL climbing.** SFT and RL alternate in rounds ("climbs"). Each climb selects, per query with a pass rate 0 < R̄(q) ≤ 1/2 (solvable but not yet reliable), the shortest successful rollout meeting a minimum tool-call-turn count, and distills this self-paced, automatically-hardening curriculum back into the policy via SFT before the next RL round resumes.
7. **Context management (CM) as an explicit, separately-reported evaluation axis.** Every benchmark is reported both with and without CM, holding tool set, context limit, and judge fixed; discard-all (clearing history and restarting when a context threshold is reached) is the reported default, while retry (summarizing a failed attempt into the next attempt, MiroThinker-style) is explored separately as an inference-cost-heavy upper bound rather than adopted as the headline configuration.

# Q6 Experiment Design

Evaluated pass@1 (single rollout) on four benchmarks — BrowseComp, BrowseComp-ZH (accuracy), DeepSearchQA (F1, evidence-comprehensiveness scoring), and HLE text-only (accuracy) — each judged with the benchmark's own official LLM-judge prompt. The main results table (CM enabled, discard-all) places Iris-mini/Iris-pro against 30–35B and ~400B open peers plus a frontier/heavy-compute reference band that includes results the paper explicitly reproduces from official published scores rather than its own reruns where noted. A separate CM analysis table isolates the effect of context management by comparing w/o-CM, retry, discard-all, and discard-all+retry against three prior systems that explicitly report no-CM baselines (OpenSeeker-v2, REDSearcher, FORT-Searcher), and explicitly excludes additional test-time verification/re-answering strategies used by a comparator (XYZ-Aquila) as outside the scope of a CM-only comparison. A benchmark-leakage guard blocks access to the Hugging Face dataset/space pages hosting benchmark questions and answers at three enforcement points: removed from search results, refused on scrape, and caught by a post-hoc URL guard even if the model supplies the URL from memory.

# Q7 Datasets and Code

No new benchmark is introduced; evaluation reuses BrowseComp, BrowseComp-ZH, DeepSearchQA, and HLE. The training corpus is built entirely by the paper's own web-graph reverse-construction pipeline, combined with unspecified "in-house and open-source question sets." Models are initialized from Qwen3.6-35B-A3B and Qwen3.5-397B-A17B (both MoE, 256K-token context); SFT trains two epochs at global batch size 64 and max sequence length 262,144 tokens; RL uses the open-source Relax training engine. The paper states it "plan[s] to release the model weights together with the complete recipe for data construction, training, and evaluation" — not yet released at the time of this note. The linked GitHub repository (AllSpark-Research/Iris) had 37 stars at retrieval time.

# Q8 Evidence Quality

This note is built from the arXiv PDF full text (all 12 pages, including the case-study appendix), extracted with `pypdf` because the arXiv HTML mirror for this very recent (3 Sept 2026 submission, 7 Sept 2026 processed) paper returned only a logo-image placeholder page at retrieval time — `hf papers read` likewise returned no usable body text. Headline numbers are consistent across the abstract, Figure 1, and Table 1 (Iris-mini 82.2/84.8/86.9/52.3 and Iris-pro 88.6/85.1/92.9/56.4 on BrowseComp/BrowseComp-ZH/DeepSearchQA/HLE). The paper is transparent about several evidence boundaries this note preserves rather than smooths over: Appendix A reports a specific case (BrowseComp-ZH Question 85) where the agent's answer ("Bolton") appears directly supported by the cited source material while the official ground truth ("Lannister") does not, explicitly framed as "a potential inconsistency between the benchmark annotation and the underlying source material" rather than an error the authors hide; the paper explicitly declines to adopt "reverify/reanswer" test-time verification strategies used by a comparator (XYZ-Aquila) on BrowseComp-ZH, keeping its own reported numbers to a single ReAct rollout without added verification machinery; and it explicitly does not report discard-all+retry (its single highest-scoring configuration in most settings) as the default, citing the extra inference cost per retry and echoing DeepSeek-V3.2's point that actual compute cost must be accounted for when benchmarking CM strategies. All reported results are single-model, pass@1 point estimates without confidence intervals or repeated-seed variance; several comparator numbers (rows marked "r" for Nex-N2 and DeepSeek-R1) are explicitly flagged as reproduced by a third party (the XYZ-Aquila Team) rather than self-reported by their original authors, and this note treats every such number as carrying that provenance rather than as independently re-verified here.

# Q9 Contributions

1. An automated, verifiable data-construction pipeline that reverse-constructs hard multi-hop search questions from a real web corpus's hyperlink/entity structure, with anchor abstraction blocking string-match shortcuts and dual-criteria (fails-closed-book, solves-with-evidence) admission.
2. A combined SFT (trajectory- and data-induced turn-level filtering) plus live-web RL (in-house co-located reward model and observation summarizer, request-level partial rollout with prefix reuse) training recipe, alternated as "SFT-RL climbing" so each round's hardest-solved, most-efficient RL rollouts are distilled back into the next supervised pass as a self-paced curriculum.
3. Iris-mini (35B-A3B) and Iris-pro (397B-A17B), reported as the strongest open-source search agents in their respective parameter ranges on BrowseComp, BrowseComp-ZH, DeepSearchQA, and HLE, evaluated under an explicit with/without-context-management protocol that separates intrinsic policy capability from inference-time harness gains — with Iris-pro's no-CM numbers alone already competitive with several CM-assisted 1T-scale frontier systems.

# Q10 Next Steps

The paper's own stated next direction is that both its synthesized search data and its search-specialized models — used as on-policy-distillation teachers — transferred positively to domains not explicitly targeted during training, including general tool use (BFCL, τ-bench) and "Cowork" tasks (OfficeQA, APEX); the authors interpret this as evidence that search may be "an atomic capability" reusable wherever an agent must act under incomplete information, rather than a narrow vertical specialization, and state an intent to pursue using search data and search-derived teachers throughout training generally rather than confined to a separate specialization stage. The paper also explicitly leaves closing the reported gap to the most capable frontier/heavy-compute systems (e.g., Apodex-1.0-H, Kimi-K3, Claude Fable 5, GPT-5.6 Sol on BrowseComp) as an "important direction for future work."

This note flags one open question beyond the paper's own: the same reference-model-based dual-criteria verification (Section 2.3) that the paper uses to certify its *training* questions as simultaneously hard and solvable is structurally identical to the closed-book/open-book judgment that surfaced a ground-truth ambiguity in an *evaluation* benchmark (BrowseComp-ZH Q85, Appendix A) the paper does not control — the paper reports auditing for this failure mode only in a downstream benchmark, not in its own reverse-constructed training corpus, leaving open whether comparable answer-uniqueness ambiguities exist undetected in the training data itself.
