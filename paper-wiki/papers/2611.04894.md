# Q1 Problem Definition

* **Input (X):** a natural-language question, an optional set of initial images (present in 187 of 204 tasks), and a required answer format, given to a multimodal model or agent that may use web search, webpage reading, text-to-image search, reverse image search, and image cropping.
* **Output (Y):** a final answer (an entity, a set, an ordered list, or a table-like answer) scored for complete correctness, plus partial credit for the intermediate results and subquestion answers it states.
* **Constraints:** answers must be derivable from public, searchable sources fixed before the question was written; the critical visual evidence is meant not to be replaceable by question text, page titles, captions, OCR, or model knowledge.

# Q2 Problem Novelty

Partly new. Multimodal search benchmarks already exist: MMSearch, BrowseComp-VL, MMSearch-Plus, MM-BrowseComp, VisBrowse-Bench, BrowseComp-V3, InterLV-Search, and VDR-Bench. The paper's argument is that in many of them an image mainly identifies a starting entity, after which text search suffices, and that more image searches do not by themselves make the visual context harder. Its focus is *visual context management*: keeping visual observations about several objects, linking them to identities and external facts, and using them to choose later searches. Its own comparison table (a qualitative classification by the authors) claims it is the only one combining set answers with multi-image, multi-hop, evidence-linked tasks and partial credit.

# Q3 Scientific Hypothesis

If tasks require agents to carry visual evidence across many images, objects, and dependent search steps, then even frontier models with search tools will rarely solve them completely. Partial-credit scoring will reveal large gaps between getting many intermediate results right and getting the whole answer right, especially for tasks that require checking every member of a set. Letting the agent look at retrieved images directly should beat giving it text descriptions of those images.

# Q4 Related Work and Key People

* **Agentic information seeking.** [GAIA](../concepts/gaia.md), [BrowseComp](../concepts/browsecomp.md), [WideSearch](../concepts/widesearch.md) (breadth and item-level completeness), DeepWideSearch, [DeepSearchQA](../concepts/deepsearchqa.md), [GISA](../concepts/gisa.md) (set, list, and table answers with human trajectories), and DeepResearch Bench II; search systems such as [SearchOS-V1](2607.15257.md), which keeps shared records of tasks, evidence, coverage, and failures.
* **Multimodal search and browsing.** MMSearch (requery, rerank, summarize, answer), BrowseComp-VL, MMSearch-Plus (fine-grained visual cues), VDR-Bench (region-level retrieval against text shortcuts), VisBrowse-Bench, InterLV-Search (single-chain and multi-branch search), MM-BrowseComp (reasoning checklists), and BrowseComp-V3 (final-answer and subgoal scoring).
* **Vision-language models.** InternVL3, Kimi-VL, Qwen3-VL, Qwen3.5 to Qwen3.8, GLM-5.3-Flash, DeepSeek-V4.1-Flash, and Kimi K3; the paper notes that long context windows do not ensure good visual state management.
* **Key people.** First author ZhengXian Wu, with co-authors at Tsinghua University, Ant Group (the organization listed on Hugging Face), and Renmin University of China. Its reference list includes SearchOS-V1 and a taxonomy of silent failures in multimodal search with overlapping author names. Interested parties: authors of BrowseComp-V3, MM-BrowseComp, and InterLV-Search, whose benchmarks overlap most in design.

# Q5 Key Solution Idea

**Five task families.** *Set-wise Visual Search* (68 tasks): check a visual property for every member of a defined set, then filter, compare, or count. *Sequential Visual Search* (34): a visual finding in one step decides the next search. *Hybrid Wide-Deep Search* (34): earlier findings define a candidate set, and filtering it picks the next target. *Competitive Visual Disambiguation* (34): tell apart near-identical candidates from local details. *Visual-Structure-Guided Search* (34): the order, positions, or connections of objects in an image decide what to search and in what order. Reference solutions average 17.6 steps (median 17, total 3,593), from 3.9 for disambiguation to 23.9 for set-wise tasks (maximum 61 in a hybrid task).

**Construction.** Annotators first fix public sources with a bounded entity set, reliable entity-image links, and independently checkable facts, then organize entities, images, facts, and candidate sets into an evidence structure, apply one family's structural constraints, and write a question that hides the intermediate nodes and the answer. Program checks cover record structure, scoring-prompt placeholders, image integrity, and export consistency; human review covers sources, visual integration, shortcuts, and answer consistency, and every retained task is reviewed. Tasks that bypass the visual evidence or allow a shorter unintended path are discarded.

**Scoring.** Accuracy is 1 only if the answer contains all and only the required content, with aliases accepted and set order ignored unless required. Process Score is the fraction of a task's labelled critical states that the final answer gets right, averaged over tasks, so different search paths that recover the same states score the same. Both are produced by a semantic judge from per-task scoring prompts in separate calls, using only the `final_answer` field.

# Q6 Experiment Design

* **Systems.** 16 models answering directly (13 open-weight, from Qwen3-VL-4B to Qwen3.5-397B-A17B, Kimi-K3, DeepSeek-V4.1-Flash, GLM-5.3-Flash, and MiniMax-M3; and GPT-5.5, Gemini 3.5 Flash, and Claude Opus 4.8). Seven backbones run as [ReAct](../concepts/react.md) agents and three as DeerFlow agents.
* **Tool budget.** Up to 30 search rounds, 60 evidence-tool calls with at most four per round, five results per search, webpage text cut at 12,000 characters, 20 images per task (longest side 1,536 pixels), and crops enlarged up to four times. Forward search uses Serper and reverse image search SerpApi.
* **Protocol.** One run per task from a fresh context (Pass@1), temperature 0 except for GPT-5.5 and Claude Opus 4.8, where it is left at the default.
* **Visual-access ablation.** For three ReAct backbones: *Text* (web search and reading only), *Caption* (image search and reverse search, with retrieved images described by separate calls to the same model), and *Full* (direct inspection and cropping), with task-level gains and losses (Tables 5 and 6). Tool use and timing are summarized in Figure 5, and 17 trajectories are shown as case studies.

# Q7 Datasets and Code

The benchmark is released (a [project page](https://dingwu1021.github.io/VisSearch-Bench/), the [antins-labs/VisSearch-Bench-v1](https://github.com/antins-labs/VisSearch-Bench-v1) repository with 4 stars per `hf papers info`, and a Hugging Face dataset), none opened for this note. The release format is Parquet with embedded images and nine fields per task, including the reference answer, a gold trajectory with source links, and both scoring prompts; there are English and Chinese versions. The paper gives all agent and judge prompts and the inference hyperparameters. The agent harness code is not described as released in the text.

# Q8 Evidence Quality

* **Supported.**
  * *The tasks are hard for current systems.* Direct answering tops out at 6.37% accuracy (GPT-5.5 and Gemini 3.5 Flash), and the best searching agent solves 54 of 204 tasks (Kimi-K3 with ReAct, 26.47%).
  * *Search helps every backbone tested.* Qwen3.5-397B-A17B goes from 1.96% to 15.69% with ReAct and 10.29% with DeerFlow, and from 12.72 to 32.43 Process Score with ReAct; every paired ReAct or DeerFlow run is above its direct-answer row in Table 3.
  * *Partial results do not add up to complete answers.* On set-wise tasks GPT-5.5 with ReAct reaches 44.10 Process Score but 8.82% accuracy (6 of 68), and no system exceeds 11.76% there. Direct answering scores 0% on competitive disambiguation for every model, while searching agents reach 44.12%.
  * *Looking at images beats captions.* For all three backbones, Full beats Caption and Text on accuracy and Process Score; dropping image tools entirely (Text) costs 1.47 to 10.29 accuracy points.
* **Weaker or narrower than the headline.**
  * *One run, small margins.* The top two agents differ by two tasks (54 against 52), and Full beats Caption by 2, 2, and 7 tasks. Table 6 shows how much moves between settings: 14, 18, and 33 tasks change outcome between Full and Caption for a net change of 2, 2, and 7. With one sample per task and default temperature for two proprietary models, run-to-run variation of that size is plausible and unmeasured (reader inference).
  * *Domain columns rest on few tasks.* The domain shares imply 48 Culture, 36 Life Sciences, 36 Physical Sciences, 24 each for Society, Geography, and Technology, and 12 Business tasks, so one Business task is worth 8.33 points (reader arithmetic).
  * *The scorer is an LLM, described two ways.* Section 3.3 describes rule-based comparison with alias normalization, while Appendix B states that both metrics come from a semantic judge applying per-task prompts. The judge model is not named in the text, and there is no judge-human agreement check (see [LLM-as-a-Judge](../concepts/llm-as-a-judge.md)).
  * *Process Score credits stated, not demonstrated, intermediate results.* It is computed from the final answer text, not the trajectory, so a model can earn it without searching: GPT-5.5 answering directly scores 22.61 overall and 43.47 on structure-guided tasks (reader observation).
  * *Visual indispensability is checked by humans, not measured per task.* The Text setting still solves 12 to 25 tasks per backbone, and direct answers solve up to 13. The paper does not report which tasks can be solved without image tools, so how many tasks truly require visual evidence is not established (reader observation).
  * *Framework comparisons are thin.* DeerFlow runs only three backbones and its configuration is not described beyond its tool protocol; the ablation uses three open models.
  * *A promised comparison is missing.* Appendix A describes four external benchmarks as "used in the cross-benchmark evaluation", but no cross-benchmark results appear in the text or table captions read for this note.
  * *Contamination risk going forward.* Releasing gold trajectories with source links for public web tasks makes later training-data leakage easy; the paper does not describe a held-out or private split (reader observation).

# Q9 Contributions

* A task taxonomy for multimodal search that targets how visual evidence is carried across objects and steps, not only whether an image is used.
* 204 human-built tasks with fixed public sources, reference answers, gold trajectories, and per-task scoring rules, released in English and Chinese.
* A Pass@1 evaluation of 16 models and two agent frameworks with a partial-credit metric that separates intermediate correctness from complete answers.
* A visual-access ablation with task-level gain and loss counts.

# Q10 Next Steps

* **Better aggregation across sets (from the paper's findings).** The weakest family is set-wise search, where agents get many items right but rarely all of them; explicit per-item tracking, as in [SearchOS-V1](2607.15257.md)'s coverage records, is a natural test.
* **Repeated runs (reader suggestion).** Three to five runs per system would show whether the top rankings and the Full-versus-Caption margin survive sampling noise.
* **A no-vision control per task (reader suggestion).** Marking the tasks that Text or Direct already solves, and reporting results on the rest, would turn the visual-indispensability claim into a measurement.
* **Judge validation (reader suggestion).** Naming the judge and reporting agreement with human grading on a sample, especially for set and table answers, would bound scoring error.
* **Trajectory-level process scoring (reader suggestion).** Scoring critical states from the trace (which pages and images were actually inspected) would reward found evidence over guessed intermediate answers.
