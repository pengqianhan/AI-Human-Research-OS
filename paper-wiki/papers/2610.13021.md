# Q1 Problem Definition

* **Input (X):** a household task description and a first-person image of the current state, plus at each step a small set of candidate actions written in natural language; optionally, experience from earlier basic tasks, either as full interaction trajectories or as a Markdown skill summary the agent wrote.
* **Output (Y):** one chosen action per step until the goal state is reached or the step budget runs out; the score is success rate.
* **Constraints:** evaluation is offline and deterministic. Each task is a pre-computed state-transition graph; the step budget is the shortest path plus 3 extra steps at test time (plus 6 while learning).
* **Core problem:** measuring whether a self-evolving agent accumulates experience and reuses it on harder, unseen tasks in an embodied setting. The paper operationalizes "continual learning" as compositional generalization: learn on basic tasks, then solve advanced tasks that recombine the same atomic actions.

# Q2 Problem Novelty

Partly new. Continual-learning and skill-evolution benchmarks for agents exist in digital settings (the paper cites EvoAgentBench, SEA-Eval, AgentCL, SkillLearnBench, SkillFlow, ContinualSkillBench, SkillEvolBench), and embodied benchmarks cover perception, navigation, manipulation, and planning without a learning phase. The claimed first is the combination: a continual-learning benchmark in embodied simulation. Compositional generalization as the measuring device is borrowed from web, video, reasoning, and manipulation benchmarks the paper cites.

# Q3 Scientific Hypothesis

1. **Experience transfers upward.** If an agent has done related basic tasks, it will solve advanced tasks built from the same atomic actions more often than a zero-shot agent.
2. **More experience should help more.** If continual learning works, success on advanced tasks should rise with the number of basic tasks done first. The paper finds this does not hold.
3. **Experience changes decisions, not only outcomes.** If learning is real, agents should pick fewer unexecutable actions and more shortest-path actions.

# Q4 Related Work and Key People

* **Continual-learning benchmarks for agents.** Knowledge-intensive transfer (EvoAgentBench, StreamBench, AgentCL), interactive digital environments (SEA-Eval, LifelongAgentBench), long-term simulated worlds, and skill-centric evolution (SkillLearnBench, SkillFlow, ContinualSkillBench, SkillEvolBench).
* **Embodied benchmarks.** Scene understanding and spatial reasoning (EmbodiedScan, EmbSpatial-Bench, PhysBench), navigation (R2R and successors, GOAT-Bench, OpenEQA), manipulation (Meta-World, RLBench, ManiSkill2, LIBERO, RoboCasa), and long-horizon planning (ALFRED, TEACh, CALVIN, BEHAVIOR-1K).
* **Compositional generalization.** Web and mobile agents, video action recognition, reasoning, and robot manipulation.
* **Key people.** Peking University's School of Intelligence Science and Technology and BIGAI (Yiwu Zhong, Zilong Zheng, Zhenliang Zhang), with the University of Hong Kong. Likely critics: robotics researchers, who would note that choosing among written options is not embodied control, and continual-learning researchers, who would note that the protocol has no long task stream and measures no forgetting.

# Q5 Key Solution Idea

* **Three compositional levels.** An *atomic action* is one object interaction that takes three steps (observe, approach, operate). A *basic task* composes two atomic actions into a household operation (shortest path 6 steps). An *advanced task* composes four atomic actions drawn from two to four basic-task categories (shortest path 12 steps). Basic tasks fall in six categories: object manipulation, spatial placement, accessibility control, appliance operation, activity-driven scene configuration, and household state restoration.
* **Offline graphs instead of a live simulator.** The authors use TongSim's closed-source version for its richer action set, so they pre-compute a state-transition graph per task. Each node is an environment state with a captured image and four candidate actions of three kinds: *optimal* (on the shortest path, found by breadth-first search), *suboptimal* (executable but off the shortest path), and *invalid* (not executable in that state).
* **Leak control in the text.** Task descriptions and options are written by Qwen3.7-Plus in three stages: rewrite the task as a scene-level request that does not list objects or order; rewrite each state's options so all look plausible; and harden options across states to remove regularities, including the repeating observe-approach-operate rhythm. Three annotators check images, descriptions, and options; a sample is kept only if all three approve.
* **Three settings.** *Zero-shot*; *In-Context Learning (ICL)*, where the full trajectories of two related basic tasks stay in context; and *Skill Learning*, where the agent writes a Markdown skill summary after the same two basic tasks and only that summary is provided at test time.

# Q6 Experiment Design

* **Benchmark.** 268 tasks: 168 basic and 100 advanced.
* **Agents.** Four harnesses (OpenClaw, Claude Code, Codex, Hermes), each with Qwen3.8-Flash and GPT5.6-Terra through official APIs.
* **Analyses.** Compositional complexity (advanced tasks with 3 to 6 atomic actions; Hermes with Qwen3.8-Flash); number of learning samples k from 0 to 6 (Hermes and OpenClaw with Qwen3.8-Flash); action-type selection rates relative to zero-shot (all four harnesses with Qwen3.8-Flash, from the main-experiment logs); and step-budget sensitivity (0 to 6 extra steps; Hermes with Qwen3.8-Flash).
* **Metric.** Success rate only.

# Q8 Evidence Quality

* **Supported.**
  * *Advanced tasks are hard zero-shot and experience helps in every configuration.* Zero-shot success is 42.9-58.9% on basic tasks and 3.0-12.0% on advanced tasks. With two basic tasks first, all eight harness-model pairs improve under both methods: ICL 16.0-52.0%, Skill Learning 22.0-38.0% (Table 1).
  * *One sample is enough; more do not help.* From k=0 to k=1 success goes from 8.0-10.0% to 28.0-40.0% across two harnesses and both methods; from k=1 to k=6 none of the four curves rises consistently.
  * *The gain survives harder compositions and tighter budgets.* From 3 to 6 atomic actions, zero-shot falls from 28.0% to 4.0% while ICL and Skill Learning still reach 32.0% and 26.0% at 6. With 0 extra steps, zero-shot is 0.0%, ICL 15.0%, Skill Learning 7.0%.
  * *Experience mainly removes unexecutable choices.* Invalid-action selection drops by 13-20% in all harnesses, suboptimal actions rise by 3-8%, and optimal actions rise; Skill Learning shifts behavior less than ICL in every harness.
* **Weaker or narrower than the headline.**
  * *"Above 30%" is not uniform.* The text says learning raises advanced success "from around 10% to above 30%", but 5 of the 16 learning cells in Table 1 are below 30% (ICL 16.0 and 27.0; Skill Learning 22.0, 26.0, 25.0; reader count). Hermes with GPT5.6-Terra gains only 5 points from ICL (11.0 to 16.0).
  * *The protocol is two-shot transfer, not a learning stream.* Each advanced task is preceded by two basic tasks chosen as related to it, held in one context. There is no long sequence of tasks, no retrieval from a growing memory, and no measurement of retention or interference, which are what "continual learning" usually tests (reader observation).
  * *Interface familiarity is not separated from skill transfer.* The benchmark's own construction notes that every atomic action follows an observe-approach-operate pattern that the option-hardening stage tries to hide. A single basic task is enough to cut invalid actions sharply and deliver nearly the whole gain, and more tasks add nothing; that pattern is what one would expect if the agent mostly learns how this environment's steps work rather than accumulating composable skills. No control uses *unrelated* basic tasks, which would separate the two (reader inference; the paper's reading is that agents "cannot extract sufficiently distinct information" from more samples).
  * *ICL against Skill Learning is undecided, and the samples are small.* Neither method wins consistently (ICL is higher in 5 of 8 pairs, reader count), and with 100 advanced tasks one task is one point. All runs are single, with no variance or significance tests, so harness and model differences of a few points are not resolved either. Neither model is reliably better: GPT5.6-Terra trails Qwen3.8-Flash in 4 of the 8 learning cells that share a harness, including Skill Learning in three of four harnesses (reader count).
  * *Small inconsistencies between tables and analyses.* Section 5.1 gives ICL at 4 atomic actions as 42.0% for Hermes with Qwen3.8-Flash where Table 1 has 44.0%, and Section 5.2's k=0 range is 8.0-10.0% where Table 1's zero-shot for OpenClaw with Qwen3.8-Flash is 5.0%. The paper says Section 5.1 extends the evaluation data but does not give task counts for the analysis subsets.
  * *Failed learning episodes are not analyzed.* Basic tasks are solved about half the time zero-shot under the test budget (the learning phase allows three more steps), so a sizeable share of learning-phase trajectories, and of the skill summaries written from them, may come from failures; the paper does not report learning-phase success or split results by it.
  * *"Embodied" here means image plus four written options.* The agent never issues motor commands or navigates continuously; the graph format is what makes evaluation reproducible, and it is also what makes the task a visual multiple-choice sequence.

# Q9 Contributions

* The first benchmark, by the authors' claim, that tests learning from experience in an embodied household simulation, with a three-level compositional task design.
* An offline graph format that makes a closed-source simulator's tasks reproducible and classifies every agent decision as optimal, suboptimal, or invalid.
* An eight-configuration evaluation across four agent harnesses showing consistent transfer from basic to advanced tasks.
* A negative scaling result: beyond the first learning sample, more experience does not improve success, for either raw trajectories or written skills.

# Q10 Next Steps

* **From the authors.** Design harnesses for continual learning, since harness scores are close and far from saturation; find mechanisms that let agents keep gaining from additional interactions.
* **Unrelated-experience control (reader suggestion).** Give agents basic tasks that share no atomic actions with the advanced task. If the gain persists, it is environment familiarity; the difference between related and unrelated experience is the compositional-transfer signal the benchmark is meant to measure.
* **A real stream (reader suggestion).** Order all 168 basic tasks into one sequence with a persistent memory or skill library, then test on the 100 advanced tasks without telling the agent which experience is relevant; report retention and interference alongside success.
* **Condition on learning outcome (reader suggestion).** Report advanced-task success separately for cases where the two basic tasks were solved, to see whether failed episodes help, hurt, or are ignored.
* **Raw history against distilled lessons.** [Learn2Play Bench](2610.08215.md) found that distilled lessons can freeze a wrong rule while raw histories let agents revise it; here skill summaries shift decisions less than trajectories do but end at similar success, a second data point that the choice of memory format changes behavior more than headline scores show.
