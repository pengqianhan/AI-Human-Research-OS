# Q1 Problem Definition

* **Input (X):** the O*NET occupation database (occupations, task statements, Detailed Work Activities), a filter for digitally executable tasks, a search agent with access to public documents, and a teacher model π_T that can act inside a coding-agent scaffold.
* **Output (Y):** a corpus of (workspace of real files, task statement, deliverable requirements, weighted positive criteria with evidence anchors and verification procedures, negative penalty criteria) plus an admitted teacher trajectory per task, suitable for SFT and for rubric-scored rejection fine-tuning of a "working agent" that reads diverse files, coordinates tools, and produces deliverables.
* **Core problem:** training such agents by imitation needs many tasks built on real files *and* a verifier that can check the deliverable. The two existing pipelines each lack one half: EnvCraft generates the files with a model and checks tasks with a state script that cannot read document contents; NexForge uses real files but has no task-specific rubric or verifier, so result quality is unchecked.
* **Secondary problem:** tasks a model invents freely collapse toward frequent occupations and generic analysis, so diversity has to be controlled before any file is retrieved.

# Q2 Problem Novelty

Task and environment synthesis for agents is established in domains with programmatic verification (tool use, software engineering, terminal tasks; Table 1 lists AgentSynth, TaskCraft, SWE-smith, CLI-Universe). Working-agent synthesis is recent (EnvCraft, NexForge, both 2026). What is new is the object that mediates task and verification: an evidence graph over real files, from which both the task statement and each rubric criterion's anchors are compiled, so verification reads the same files the task depends on. It matters because deliverable quality (a spreadsheet, a memo) cannot be checked by workspace state alone, and because an evidence-anchored judge gives a selection signal for later self-training.

# Q3 Scientific Hypothesis

If tasks are grounded in real files through an evidence graph whose nodes and edges also anchor the rubric criteria, and each task is executed once and revised against the original files before trajectories are collected, then (1) SFT on the admitted trajectories will improve a base model on independent working-agent benchmarks, across scaffolds other than the one used for rollouts, and (2) selecting a model's own rollouts by the evidence-anchored rubric will improve it further than selecting by an unanchored judge or at random.

# Q5 Key Solution Idea

* **Seeds fix direction, files fix content.** A seed is (occupation, Detailed Work Activity, occupation-specific work demand, dominant execution pattern from a vocabulary of 16, expected input file family, retrieved occupational evidence). Only DIGITAL-annotated O*NET tasks survive, leaving 246 occupations, 16 sectors, 891 task types, and 3,419 occupation-task pairs. Work demands are kept only when cited professional passages support them. Seeds are chosen greedily by marginal coverage over occupation, task type, pattern, and input family, with the rule re-applied after files are downloaded.
* **Real-file workspaces with hidden roles.** A search agent finds a coherent public case and downloads its files in native formats. Each file gets a hidden role (core, supporting, confuser, ambient) that steers assembly and is never shown to the working agent.
* **Evidence graph to task specification.** Nodes record a file, the fact it provides, and its role; edges record cross-file dependencies. The graph is compiled into a task statement, deliverable requirements, positive criteria c_k = (deliverable, requirement, expected value, weight, anchors A_k ⊆ nodes, verification procedure φ_k), and negative criteria for concrete prohibited outcomes. The agent sees only the statement and files; the judge sees the anchors and φ_k.
* **Execution-conditioned one-step revision.** The teacher runs each initial specification once; a revision agent reads the files, graph, rubrics, and that execution and returns only the fields to change. The teacher is rerun only if the task statement changed; otherwise the original trajectory is re-judged against the revised rubric. 81.6% of rollouts were reused.
* **Admission.** Deterministic checks (filenames, readable formats, required sheets and formulas), then a judge score Q = (Σ w_k a_k − Σ λ_j v_j) / Σ w_k with per-criterion fraction met a_k and binary violations at admission; admit at Q > 0.90 and drop trajectories with degenerate tool use.
* **Rubric-guided rejection fine-tuning.** Sample 4 rollouts per query from the SFT model on 2,000 new queries, judge the four jointly against the rubric, keep the best when it exceeds 0.95, train one epoch.

# Q6 Experiment Design

* **Corpus:** 3,638 materialized tasks → 2,153 admitted → 2,169 trajectories from 2,150 workspaces; 466 task types, 15 of 16 sectors, 164 of 256 sector-pattern cells; PDF in 96.7% of trajectories; 50.0 assistant steps and 162.0k tokens on average, with 1.3% hitting the 262,144-token ceiling.
* **Pipeline model:** GLM-5.2 for workspace construction, graph and specification generation, revision, teacher rollouts (Codex scaffold), and the judge.
* **Training:** SFT of Qwen3.6-27B and Qwen3.6-35B-A3B, 3 epochs, Muon, peak LR 2e-5, batch 8, packed to 262,144 tokens; RFT from the 35B SFT checkpoint on 462 matched trajectories, 1 epoch, LR 1e-6, three arms differing only in the selection rule (anchored judge, unanchored judge that sees rubric text but not anchors, random-of-4).
* **Evaluation:** GDPVal-AA (220-task gold subset) as Bradley-Terry Elo over an internal pool with GLM-5.3 (OpenHands) fixed at 1667 and a bridge node for cross-scaffold comparison; Workspace-Bench-Lite micro score; SpreadsheetBench II execution accuracy. Pass@1, fixed scaffold configurations, comparisons only within a scaffold; missing deliverables count as losses. RFT arms are scored by direct paired comparison against the SFT model.
* **Audits:** file-hash, 13-gram text, and occupation overlap against GDPVal; SFT-vs-base win rates split by occupation coverage; judge perturbations (delete the cited worksheet; corrupt rows, numbers, or citations).

# Q7 Datasets and Code

Synthesized tasks, rubrics, trajectories, and trained checkpoints are released in the Hugging Face collection groundhogLLM/graphforge (per the abstract and reproducibility statement). Workspace files are public documents distributed as source links rather than contents. Training configurations are in Appendix A. # Q8 Evidence Quality

* **Supported:**
  * *SFT gains on all three benchmarks and both bases.* Qwen3.6-27B: GDPVal 1380.0 → 1445.7 (OpenHands) and 1364.0 → 1427.4 (Codex); Workspace-Bench-Lite 56.0 → 63.7 (Claude Code) and 61.4 → 65.2 (Codex); SpreadsheetBench II 10.3 → 24.0 and 15.6 → 24.6. Qwen3.6-35B-A3B: GDPVal +101.7 / +101.4 Elo; Workspace-Bench-Lite +3.8 / +6.6; SpreadsheetBench II 2.8 → 19.3 and 4.7 → 18.7.
  * *Cross-scaffold transfer.* All rollouts use Codex, and gains hold under OpenHands and Claude Code as well.
  * *Not memorization of GDPVal.* Zero shared file hashes (39,201 vs 260), no substantive shared 13-grams, 13 of 44 GDPVal occupations covered; SFT win rate over base is 0.739 [0.671, 0.803] on the 155 uncovered-occupation tasks and 0.692 [0.585, 0.800] on the 65 covered ones.
  * *Rubric selection carries signal.* On Workspace-Bench-Lite and SpreadsheetBench II, anchored RFT (+4.0 / +4.0, +1.0 / +0.9) beats unanchored (+2.5 / +1.7, −1.8 / 0.0) and random (+1.1 / +2.8, −0.3 / −3.1); random selection is the weakest arm on every benchmark.
  * *The judge reads the cited evidence.* Deleting a criterion's cited worksheet drops that criterion's score by 0.377 while non-target criteria move by 0.016 on average.
* **Weaker or bounded:**
  * *GDPVal Elo is noisy at 220 tasks.* The 27B base and SFT intervals overlap ([1326.6, 1432.1] vs [1376.2, 1513.8]), the unanchored RFT arm has the highest GDPVal point estimate (+34.1 / +25.3) even though the paper's thesis favors anchoring, and every RFT difference interval includes zero; the authors say so.
  * *The judge misses fine-grained corruption.* Row, numeric, and citation corruptions inside cited evidence change scores by under 0.03, which the authors attribute to GLM-5.2's limits as an agentic judge. The same judge admits trajectories and selects RFT candidates, so content errors that pass it enter training (reader note).
  * *One model family, one pipeline model.* Both bases are Qwen3.6; every pipeline component is GLM-5.2, so generator and judge share a model and its blind spots. Teacher trajectories come from GLM-5.2, whose own GDPVal Elo (as GLM-5.3) is 1667 under OpenHands, about 220 points above the best student (reader note).
  * *Scale and attribution.* 2,169 trajectories with no scaling study; no ablation isolates the evidence graph, the hidden roles, or the revision step from the overall pipeline. The RFT ablation isolates selection only, holding task admission fixed.
  * *Absolute level.* The SFT models remain well below the frontier rows (Claude Opus 5 at 1774.1 Elo, 70.1 Workspace-Bench-Lite, 33.6 SpreadsheetBench II) and SpreadsheetBench II gains start from very low bases (2.8 and 10.3), so the +13.7 and +16.5 there are large relative to a weak start (reader note).

# Q9 Contributions

* A synthesis pipeline whose task statement and verification rubric derive from one evidence graph over real files, giving each criterion the files needed to check it without leaking a solution into the task.
* Occupation-grounded, coverage-selected seeds that keep a working-agent corpus broad across 466 task types and 15 sectors.
* Execution-conditioned one-step revision that repairs tasks and rubrics against the original files and reuses 81.6% of rollouts.
* Evidence that 2,169 trajectories move two Qwen3.6 bases on three independent benchmarks across three scaffolds, with contamination audits, and that the anchored rubric is a usable selection signal for rejection fine-tuning on two of the three benchmarks.
* Open data and checkpoints.

# Q10 Next Steps

* **Stated by the authors:** study how gains scale with more trajectories; replace GLM-5.2 with stronger frontier models in the pipeline and judge; test other model families; extend to more task families and file types; study how evidence-anchored verification interacts with longer-horizon scaffolds.
* **Separate generator from judge (reader note):** the judge sensitivity audit shows content-level blindness; an independent judge model, or deterministic checks for numeric criteria, would test whether admitted trajectories carry undetected content errors.
* **Component ablations (reader note):** train on NexForge-style tasks (real files, no rubric) or on the same workspaces with randomly anchored criteria to measure what the evidence graph itself contributes to downstream gains.
* **Relevance to this repository (reader note):** the hidden-role workspace (core, supporting, confuser, ambient) and criterion-level evidence anchors are a reusable pattern for evaluating project agents that must read a research folder: write each acceptance criterion with the files that verify it, and seed the folder with plausible but inapplicable distractors.
