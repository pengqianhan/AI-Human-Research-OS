# Q1 Problem Definition

* **Input (X):** a lightweight target profile, a source scope (colleague, celebrity/public-figure, or relationship), and heterogeneous source materials (chat logs, work documents, email, screenshots, subtitles, interviews, user descriptions).
* **Output (Y):** a versioned skill package `S = (A, M, L)` — generated files `A` (SKILL.md, work.md, persona.md, work_skill.md, persona_skill.md, manifest.json, meta.json), machine-readable metadata `M`, and lifecycle state `L` (version, update time, correction count, rollback history).
* **Core problem:** actionable knowledge about a person or role — review judgment, decision heuristics, communication style — is usually embedded in messy traces rather than clean instructions, and no end-to-end workflow turns those traces into inspectable, correctable, agent-usable skills.
* **Scope:** an artifact-construction problem, not behavioral cloning. The system does not claim to faithfully reproduce a person; it claims to produce a bounded, editable package with visible provenance and limits.

# Q2 Problem Novelty

Skill packaging (Agent Skills standard, Claude Code skills), memory/persona systems, and role-play agents are all established. The paper's novelty is combining them into one artifact contract: it treats "distilling a person's knowledge and style" as a software-engineering problem with explicit portability, inspectability, correctability, composability, and governance requirements, rather than as a prompting or fine-tuning problem. The colleague/celebrity/relationship presets and public gallery turn this into a deployed, externally observable system rather than a lab demo.

# Q3 Scientific Hypothesis

If person-grounded knowledge is split into two coordinated tracks — a capability track (practices, mental models, decision heuristics) and a bounded behavior track (communication style, interaction rules, correction history) — and packaged with explicit metadata, versioning, and correction handling, then the result is a portable artifact that can be inspected, corrected, rolled back, and installed across agent hosts without requiring open-ended person simulation. The paper does not test whether generated skills are behaviorally faithful to the source person or improve downstream task outcomes; it tests only that the artifact pipeline and lifecycle operations work as built.

# Q4 Related Work and Key People

* **Agent skills and reusable capability:** ReAct, Toolformer, Reflexion/Self-Refine, AutoGen, AgentBench, and the Agent Skills standard (SKILL.md + progressive disclosure) establish the modular-capability framing COLLEAGUE.SKILL packages into.
* **Skill libraries and synthesis:** Voyager, SkillX, SkillGen, AutoSkill build or refine skill libraries from execution trajectories; COLLEAGUE.SKILL instead distills human traces (not agent trajectories) and separates capability from bounded behavior with explicit correction/rollback state.
* **Memory, personalization, role-play:** RAG, LaMP, PersonaAgent, Character-LLM, RoleLLM, SOTOPIA study adaptation to user history or role-play fidelity. COLLEAGUE.SKILL is deliberately narrower — an inspectable, reviewable artifact rather than an unrestricted persona simulator.
* **Authors/affiliation:** Tianyi Zhou, Dongrui Liu, Leitao Yuan, Jing Shao, Xia Hu — Shanghai Artificial Intelligence Laboratory.

# Q5 Key Solution Idea

A shared distillation-and-packaging core with three domain presets layered on top:

1. Collectors/parsers normalize heterogeneous sources (Feishu, DingTalk, Slack, WeChat exports, email, PDFs, screenshots, subtitles) into local knowledge directories.
2. Analyzers extract durable capability (work methods, decision heuristics, mental models) and bounded behavior (expression style, interaction rules) as two separate tracks.
3. A writer renders a versioned schema (schema v3) into SKILL.md (combined), work.md/persona.md (editable sources), work_skill.md/persona_skill.md (independently invokable sub-skills), and manifest.json/meta.json.
4. A correction handler turns natural-language feedback ("he would not say that") into Markdown patches (capability track) or normalized `{scene, wrong, correct}` records (behavior track), archiving the prior version before applying each update — giving rollback.
5. Colleague, celebrity/public-figure, and relationship presets reuse this same pipeline with different source boundaries, consent assumptions, and (for celebrity) an added six-dimensional public-evidence research pass with quality checks.

The key design choice is keeping capability and behavior separately invocable, so a user can take "review judgment" without "communication style," and vice versa.

# Q6 Experiment Design

There is no task-performance or human-subject evaluation. The paper instead reports system and deployment evidence: the artifact schema and file contract, the correction/rollback lifecycle, and public deployment counters observed on 2026-05-28 (repository stars, gallery skill/contributor counts, cumulative gallery star counts across skill cards). These are presented explicitly as evidence of distribution surface, not adoption quality or behavioral fidelity — the paper is upfront that this is not designed to validate whether generated skills are useful or faithful.

# Q7 Datasets and Code

* No benchmark dataset is used or released; the "corpus" is whatever traces a user supplies (private work documents, public interviews/subtitles, or private interaction logs).
* Code and gallery are open-source: [github.com/titanwings/colleague-skill](https://github.com/titanwings/colleague-skill), with a public site at [titanwings.github.io/colleague-skill-site](https://titanwings.github.io/colleague-skill-site/).
* At time of writing (2026-05-28): ~18.5k GitHub stars, gallery listing 215 skills / 55 meta-skills from 165 contributors, and reported (lagged, order-of-magnitude) >100k cumulative gallery stars across skill cards.

# Q8 Evidence Quality

The evidence supports the paper's narrow claim (the artifact pipeline exists, runs, and has real public deployment) but not a broader claim of usefulness or fidelity. There is no comparison against a baseline persona/memory system, no measurement of whether extracted capability actually matches the source person's judgment, and no study of correction quality, rollback effectiveness, or misuse/overattachment risk in the relationship preset. The paper explicitly names these as open: source matching, task performance, emotional safety, and trust calibration are left to future human and task-based studies.

# Q9 Contributions

1. Formulates "person-grounded trace-to-skill distillation" as an artifact problem with five properties: portable, inspectable, composable, correctable, governable.
2. The COLLEAGUE.SKILL pipeline: dual capability/behavior tracks, a versioned artifact schema, and a correction-and-rollback lifecycle.
3. A generalization mechanism (application presets) that reuses one pipeline across colleague, celebrity/public-figure, and relationship domains via different source/consent/evidence rules.
4. An open-source deployment with a public gallery, demonstrating the artifact format as a governed distribution surface rather than a private prompt collection.

# Q10 Next Steps

* Run human/task-based studies: do colleague skills catch the same review issues as the source expert; do capability-only variants preserve utility without persona risk; do corrections improve behavior without regressions.
* Evaluate celebrity/public-figure skills for citation grounding versus hallucinated motives, and relationship skills for overattachment or non-consensual-simulation risk.
* Compare full, capability-only, and behavior-only artifact variants under matched source evidence as a risk-utility evaluation protocol.
* **Research-OS fit:** the capability/behavior split and correction-record schema (`{scene, wrong, correct}`) are a concrete pattern worth comparing against this repository's own skill/memory update conventions (e.g. `human-cognition-cache` merge-before-append rules) if agent-skill authoring in this repo ever needs a similar correction lifecycle.
