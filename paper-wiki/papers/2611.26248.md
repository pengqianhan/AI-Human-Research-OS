title: "TwinLab-Bench: Evaluating AI Scientists in Agentic Twins of Real Labs"
description: A benchmark of 52 tasks from real laboratory records (physical sciences, life sciences, engineering) that tests whether an AI scientist can design its own experiments. The tested actor agent gets the lab's notebooks and data up to a cutoff, requests experiments of its own design within a budget, and submits a report scored against what the lab later found. Each task's environment is a TwinLab agent, a coding agent that answers requests from the lab's raw records and deterministic calculators fitted to them; in a replay study it deviates from the record on 2% of requests against 41% for a language model given only the task description. The best of 13 models, Claude Fable 5.2, averages 45.0 of 100.

# Q1 Problem Definition

* **Input (X):** for one task, the handoff that a real laboratory had at a cutoff point (notebooks, raw instrument data, protocols, interim conclusions), a list of procedures and equipment and reagent options, and an experiment budget in units such as laboratory days or wells. The actor agent has a sandbox with a shell and Python, web search with the source blocked, and one channel for new readings: experimental requests to the task's TwinLab agent.
* **Output (Y):** a report with conclusions and a recommended procedure, scored 0 to 100 by a judge agent against the hidden truth (what the record shows after the cutoff), with credit for both the conclusion and the in-run evidence behind it.
* **Constraints:** each request costs budget; scarce materials cannot be recovered once used; the TwinLab agent returns only what an experiment would return, gives no hints, and answers history questions only up to the cutoff; quantities that neither the record nor the literature constrains are marked as simulation limits.

# Q2 Problem Novelty

The paper separates three increasingly open abilities of an AI scientist: running a given computational workflow, choosing the next measurement from a given design space, and designing one's own experiments. Existing benchmarks cover the first two (data-analysis and terminal benchmarks; SciGym, DiscoveryWorld and BoxingGym in designed worlds; replays of published measurements such as ASB, where the agent picks among recorded conditions). The third needs an environment that returns real readings for experiments nobody has listed in advance. The new part is the environment: a per-lab twin that answers freely composed experiments from that lab's own records, rather than from written rules or a language model's general knowledge.

# Q3 Scientific Hypothesis

If a coding agent answers experimental requests by looking up the lab's recorded values and running calculators built only from that lab's data, with extrapolation confined to nearby settings with a written basis, then its readings will match real records far more often than a language model playing the lab, and a benchmark built on it can score experimental design (not recall) because the answer can only be reached through the agent's own experiments.

# Q4 Related Work and Key People

* **Benchmarks without new physical experiments.** Knowledge question sets (GPQA, LAB-Bench and others), data-analysis benchmarks, Terminal-Bench and its science variant, ML-research benchmarks (MLE-bench, RE-Bench, [PaperBench](../concepts/paperbench.md)), end-to-end research systems and benchmarks, Kosmos.
* **Readings from simulation, replay, or a language model.** Text worlds and equation models (ScienceWorld, DiscoveryWorld, SciGym, BoxingGym), EmbodiedLab (instrument operation in a physics simulator), replays of published measurements, language models as world models, and language models playing patients and users in agent evaluations, whose feedback is reported to depart from real environments. AgentBeats packages a benchmark as an agent; TwinLab-Bench splits that role into an environment agent and a judge agent.
* **Rubric scoring.** Items with full and partial credit, following PaperBench and HealthBench; a vision-language model as judge.
* **Key people.** Yang Wan and Linchao Zhu (the Hugging Face paper page lists Zhejiang University; the code is under the ZJUSCL GitHub organization). Likely critics: builders of real self-driving labs, who would ask how far a twin can stand in for physical execution, and the replay-benchmark line, who would ask how much of the score depends on calculator extrapolation.

# Q5 Key Solution Idea

1. **Task construction.** About 375 candidate sources narrowed to 52 tasks (49 adapted from one lab's records, 3 grounded syntheses), 20 physical sciences, 20 life sciences, 12 engineering. Each record is split at a cutoff: before goes to the actor, after becomes the hidden truth. Task forms: claim reviews (most), troubleshooting, research campaigns; some tasks offer no experiments and need only analysis of the handoff.
2. **The TwinLab agent.** A coding agent with read, search and calculator tools only. For each request it finds a basis in the task materials, takes a recorded value on comparable material or runs a calculator, and writes the result in the instrument's own format, attaching a matching real image when one exists. Environment code keeps state across requests (for example a sample already used up), adds noise at the measured repeatability, and asserts that observations leak no identifiers or hidden truth.
3. **Calculators.** Deterministic programs written per task from the lab's data (resampling measurements, fitting a physical model, filling an instrument export template). Of 371 listed parameter values, 100 are extrapolated, each with a written basis; extrapolated values also act as distractors.
4. **Difficulty control.** Budget of one to three times the expert route's use for most tasks (median 1.6), scarce materials, artifacts with benign explanations, confounded measurements, and some tasks whose correct answer is "cannot be decided within the budget"; for real-record tasks these come from the record.
5. **Scoring.** Rubric items for conclusions and for in-run verification; core items whose failure zeroes the run; every full-credit core item re-checked by two independent calls; rubrics frozen before final runs. A run is invalid if a reading leaks the hidden truth, contradicts earlier observations or physics, or refuses a relevant experiment; a script replays every calculator call.

# Q6 Experiment Design

* **Main evaluation.** 13 models as actors, 17 actor configurations counting reasoning efforts; GPT models in Codex, others in Claude Code. TwinLab and judge agents run on DeepSeek-flash for every actor. Most actors run once per task; DeepSeek-flash and MiMo-V2.6-Pro run three times. Cost is reported with score.
* **Twin fidelity.** A pilot replaying expert-route requests on 12 tasks against three environments (language model with task description, language model with raw materials, TwinLab agent); provenance of all readings in 831 runs with 7,808 requests; extrapolation-dependence audit; six extrapolation-swap variants; three held-out-condition tasks; red-team actors (exploit and flaw-finding arms) on four tasks.
* **Score validity.** Judge stability (three judgments of the same run), swapping the TwinLab and judge models to Sonnet 5.5 and Opus 5.5, and whether rubric scores separate reports independently labelled correct or wrong.
* **Memorization control.** Changing the true state of the lab while keeping the handoff word for word (11 states), closed-book memory probes, and a zero-budget baseline on the 33 tasks whose decisive data are not in the handoff.
* **Failure analysis.** For Opus 5.5 at high effort: plan-vs-run comparison of key decisions, failure types of zero-score runs, and budget doubling.

# Q7 Datasets and Code

The authors release the tasks, the environment code (noise, checkpoints, billing, scarce-material stock), the evaluation code, and all prompts (actor, TwinLab, judge, probes), at github.com/ZJUSCL/TwinLab-Bench with a project page at twinlab-bench.github.io. Each task uses its source records under their licenses; where a license did not allow reuse, the authors contacted the providers. The actor's web search blocks the benchmark and task names.

# Q8 Evidence Quality

* **Headline scores.** Claude Fable 5.2 45.0, Claude Opus 5.5 40.2, the other configurations 5.4 to 31.7. Most actors ran once per task, so single configurations carry run noise of the size seen in the repeated runs (DeepSeek-flash 19.7 ± 3.3, MiMo-V2.6-Pro 14.0 ± 3.6). Pairwise conclusions are better supported: the paired task-level comparison separates 66 of the 75 pairs whose means differ by at least 10, and Fable 5.2 is significantly above 14 of the other 16 configurations.
* **The twin is the strongest contribution, and it is checked several ways.** Deviation from the record falls from 41% (task description only) to 14% (raw materials) to 2% (TwinLab), and inconsistency on repeated requests from 31% to 8% to 4%, on 63 recorded requests in 12 tasks. 76% of readings in the evaluation runs come from the record (53%) or record-calibrated calculators (23%). Held-out conditions are predicted with median error 0.74% interpolated and 2.47% extrapolated (15 readings, three tasks); swapping extrapolations changed the pass verdict in 2 of 12 pairs. All 9 exploit attempts were blocked. Each of these studies is small, and the fidelity pilot and the evaluation share the same environment model.
* **Memorization controls are unusually thorough.** With zero budget, Opus 5.5 and DeepSeek-flash pass none of 33 tasks; when the true state changes, 8 of 10 decidable states get conclusions that follow the new state; tasks whose source a model names do not score consistently higher. The control on Fable 5.2 is weaker: it names the source of 16 tasks, and those score 49.0 against 58.7 on tasks it does not name.
* **Judge reliability.** A DeepSeek-flash judge, same model as one actor; the authors test for self-preference by swapping in Opus 5.5 (pass agrees in 19 of 20 runs, κ = 0.83). Repeated judgments give a mean within-run score SD of 2.4 to 2.8. In 19 of 21 tasks with both correct and wrong reports, every correct report outscores every wrong one.
* **Failure analysis is one model.** The knowing-doing gap (decisions the plan states in full score 87% of maximum in the run, unmentioned ones 62%) and the failure taxonomy (12 of 16 zero-score runs fail on an experimental decision, most often accepting a mechanism without a discriminating test) are for Opus 5.5 at high effort only. The text refers to the plan table as Table 6, but the plan percentages are in Table 5. Budget doubling turned 2 of 8 budget-exhausted failures into passes.
* **Reader note.** The paper reports that the tasks were built and the text drafted with Claude Code and Claude Opus 5.5; the best-scoring actor is Claude Fable 5.2. No analysis tests whether task construction favours the model family used to build it (reader observation, not a finding).

# Q9 Contributions

1. A benchmark that scores self-designed experiments on 52 tasks from real lab records, with more than 100 experimental action types (two annotators counted 105 and 107) and rubrics that credit in-run evidence, not only the final answer.
2. The agentic twin: an environment agent that answers freely composed experiments from one lab's records and calculators, with noise, state, budgets, scarce materials and leakage guards enforced by code.
3. A set of validity studies for an LLM-run environment: replay fidelity, held-out prediction, extrapolation swaps, red-teaming, judge swaps, and three memorization controls.
4. Evidence that frontier agents stay below 50 of 100 and that their main weakness is experimental judgment (accepting untested mechanisms, choosing on weak early evidence), not budget.

# Q10 Next Steps

* **Stated by the paper.** Releasing tasks and code with blocked web search; the long-term goal of real laboratories that execute any designed experiment.
* **Repeated runs for the top actors.** Run Fable 5.2 and Opus 5.5 three times per task to give the headline gap (45.0 vs. 40.2) an uncertainty (reader suggestion).
* **Cross-family environments.** Run the TwinLab and judge agents on a model family unrelated to both the actors and the task-building agent to bound any family effect (reader suggestion).
* **Twin as a training environment.** The same twins could provide on-policy training signal for experimental-design skills, with held-out labs for evaluation; the paper does not try this (reader suggestion).
* **Link to self-driving labs.** Calibrating a twin against an automated lab that can actually execute a subset of designed experiments would test fidelity beyond recorded conditions (reader suggestion).
