# Q1 Problem Definition

* **Input (X):** a stream of raw data "episodes" ingested through Zep's API — for the paper's experiments specifically, chat messages with a reference timestamp t_ref and speaker/actor — plus, at query time, a natural-language text-string query α.
* **Output (Y):** for ingestion, a dynamically maintained, bi-temporal knowledge graph 𝒢=(𝒩,ℰ,φ) with three hierarchical subgraphs (episode, semantic entity, community); for retrieval, a formatted text-string context β = f(α) = χ(ρ(φ(α))) containing the facts and entity/community summaries an LLM agent needs to answer α.
* **Core problem:** LLM agents need continuously evolving memory from conversations and business data, not the largely static corpora that conventional RAG assumes; entire conversation histories and business datasets cannot fit inside an LLM context window, so agent memory needs its own architecture rather than being treated as a special case of document retrieval.
* **Scope:** the paper focuses specifically on the message-type episode (conversational memory) even though Zep's episode abstraction also supports text and JSON inputs; text/JSON episode handling and the episodic-edge citation/traceability mechanism are described as future work, not evaluated here. Community-subgraph retrieval methods and the system's business-data-synthesis capability are likewise not directly benchmarked in this paper's two experiments.

# Q2 Problem Novelty

Adding memory to LLM agents was already explored in MemGPT (OS-inspired paging between a bounded context window and external storage) and knowledge-graph-enhanced RAG generally (GraphRAG, AriGraph). The paper's stated novelty is Graphiti's bi-temporal model — tracking both a chronological event timeline T (when a fact was true in the world) and a transactional timeline T′ (when Zep's data ingestion recorded or invalidated that fact) — which the authors describe as "a novel advancement in LLM-based knowledge graph construction" enabling non-lossy, continuously updatable representation of an evolving world rather than a static document index. The three-tier subgraph structure (episode/semantic-entity/community) is explicitly derived from prior work (episodic/semantic distinction from AriGraph, community summarization from GraphRAG) rather than novel in itself; the novelty claim rests on the temporal-extraction-and-edge-invalidation mechanism layered on top.

# Q3 Scientific Hypothesis

If conversational and business data are ingested into a dynamic, bi-temporal knowledge graph that (a) preserves raw episodic data non-lossily, (b) extracts and resolves semantic entities and facts with LLM-driven deduplication, (c) tracks when each fact became valid and when it was invalidated using both a real-world and a transactional timeline, and (d) is queried through a three-stage search→rerank→construct pipeline combining lexical, semantic, and graph-traversal search — then an LLM agent using this graph as its memory will answer questions requiring cross-session synthesis, temporal reasoning, and long-term context maintenance more accurately and at lower latency than agents using full-conversation context, session summarization, or the MemGPT paging approach, especially as conversation length grows beyond what fits comfortably in a context window.

# Q5 Key Solution Idea

1. **Bi-temporal knowledge graph with three hierarchical subgraphs.** The episode subgraph stores raw input non-lossily (messages/text/JSON) with bidirectional indices to derived entities for future citation/traceability; the semantic entity subgraph holds resolved entities and the facts (edges) extracted between them; the community subgraph clusters strongly-connected entities into higher-level summarized nodes via label propagation (chosen over the Leiden algorithm specifically because label propagation supports an incremental single-step dynamic extension — new nodes join the community held by the plurality of their neighbors — reducing how often a full, expensive community refresh is needed).
2. **Entity and fact extraction with reflection and resolution.** Entity extraction uses the current message plus the last n=4 messages for context, automatically extracts the speaker as an entity, and applies a Reflexion-inspired reflection pass to reduce hallucination; candidate duplicate entities are found via 1024-dimensional cosine-similarity embedding search plus full-text search over names/summaries, then an LLM resolution prompt merges duplicates into an updated name/summary. The same entity/fact pipeline supports hyper-edge-style multi-entity facts (the same fact can be extracted between multiple entity pairs).
3. **Temporal extraction and edge invalidation.** Each fact's edge stores four timestamps: t′created and t′expired on the transactional timeline T′ (when Zep's system recorded/invalidated the fact) and t_valid and t_invalid on the real-world timeline T (when the fact was actually true). New edges are compared against semantically related existing edges by an LLM; when a temporally overlapping contradiction is found, the older edge is invalidated (t_invalid set to the new edge's t_valid), with the transactional timeline always prioritizing newly ingested information — letting the graph represent an evolving world without discarding historical relationship states.
4. **Three-stage, multi-method retrieval pipeline.** Search (φ) runs cosine semantic similarity, Okapi BM25 full-text search, and breadth-first graph traversal (which can seed from recent episodes to pull in recently mentioned entities/relationships) in combination, each targeting a different notion of similarity (word, semantic, contextual/graph-distance). Reranking (ρ) supports Reciprocal Rank Fusion, Maximal Marginal Relevance, a graph-based episode-mentions frequency reranker, a node-distance-from-centroid reranker, and a cross-encoder LLM reranker (highest accuracy, highest cost). The constructor (χ) formats the reranked facts, entity summaries, and community summaries into a text context string for the agent.

# Q6 Experiment Design

Two benchmarks. **Deep Memory Retrieval (DMR)**, from the MemGPT paper: 500 multi-session conversations (5 sessions, up to 12 messages each) with one QA pair per conversation, scored by an LLM judge against golden answers. The authors also implemented full-conversation and session-summary baselines themselves (MemGPT's own reported number is reused, not independently re-verified against a rerun of MemGPT). **LongMemEval (LME)**, specifically the LongMemEval_s subset: longer, more realistic conversations averaging ~115,000 tokens, six question types (single-session-user, single-session-assistant, single-session-preference, multi-session, knowledge-update, temporal-reasoning), evaluated with GPT-4o using the benchmark's own question-specific prompts. Models used: BGE-m3 for embedding/reranking; gpt-4o-mini-2024-07-18 for graph construction and (with gpt-4o-2024-11-20) for response generation; gpt-4-turbo-2024-04-09 additionally used on DMR specifically to match MemGPT's original evaluation setup. Experiments were run December 2024-January 2025 from a residential Boston, MA connection to Zep's AWS us-west-2-hosted service, which the authors flag as adding network latency not present in the local baseline runs.

**DMR results:** Zep reaches 94.8% with gpt-4-turbo (vs. MemGPT's reported 93.4%, full-conversation baseline 94.4%, session-summary baseline 78.6%, recursive-summarization baseline 35.3%) and 98.2% with gpt-4o-mini (vs. full-conversation 98.0%, session-summary 88.0%; the authors could not reproduce MemGPT's number under gpt-4o-mini due to insufficient published methodological detail). The paper itself is explicit that this margin is not strong evidence of Zep's value: each DMR conversation is only 60 messages, easily fitting in a modern context window, so the near-identical full-conversation-baseline score is unsurprising, and the authors independently critique DMR's design (single-turn fact-retrieval only, ambiguous question phrasing, poor representation of real enterprise use cases). **LongMemEval results:** Zep improves accuracy over the (unspecified in the retrieved text, but implicitly a comparable baseline) by 15.2% with gpt-4o-mini and 18.5% with gpt-4o, with gains concentrated in single-session-preference, multi-session, and temporal-reasoning categories, plus knowledge-update specifically when paired with gpt-4o; latency drops by approximately 90% versus baseline due to reduced prompt size. One reported regression: single-session-assistant questions decline (-17.7% gpt-4o, -9.06% gpt-4o-mini), which the authors flag as needing further work rather than explaining. A direct MemGPT-vs-Zep comparison on LongMemEval was attempted but abandoned: MemGPT does not support direct ingestion of existing message histories, and the authors' archival-history workaround failed to produce successful responses.

# Q8 Evidence Quality

This note is built from the full arXiv HTML paper text (all sections through the appendix's graph-construction prompts and reference list), retrieved via `hf papers read`, so the fidelity pass could check the method description, both experiments' setups, and the reported numbers directly against the source rather than relying on an abstract alone. The paper is candid about DMR's weak evidentiary value for memory systems specifically and about the unresolved single-session-assistant regression on LongMemEval, which supports treating its own headline numbers as presented in good faith. That said, this is a vendor-authored paper about the vendor's own commercial product (all five authors are Zep AI employees), the DMR comparison partially reuses a self-reported MemGPT number rather than an independently rerun one, and the "baseline" LongMemEval results Zep is compared against are not fully specified in the retrieved text (the 15.2%/18.5% figures are stated as improvements without the note being able to confirm the exact baseline configuration from the passages retrieved). Later papers already in this wiki ([MemOS](2507.03724.md), [EverMemOS](2601.02163.md)) independently reimplement and outperform Zep under a shared backbone, which is useful triangulating evidence but was not available to this paper's own authors at publication time (January 2025, versus MemOS/EverMemOS's later 2026 submissions).

# Q9 Contributions

1. Graphiti, a bi-temporal (event-time and transaction-time) dynamic knowledge-graph engine that non-lossily integrates unstructured conversational data with structured business data and supports fact invalidation without deleting history — the paper's own core novelty claim relative to prior LLM-based knowledge-graph construction.
2. Zep, a production memory-layer service built on Graphiti with a three-tier subgraph structure (episode/semantic-entity/community) and a configurable three-stage search→rerank→construct retrieval pipeline combining lexical, semantic, and graph-traversal search with five reranking strategies.
3. Empirical results reported as state-of-the-art on DMR versus MemGPT (94.8% vs. 93.4% with gpt-4-turbo) and substantial accuracy gains (up to 18.5%) with ~90% lower latency versus an unspecified baseline on the more realistic LongMemEval_s benchmark — accompanied by the authors' own critique that DMR itself is a weak benchmark for differentiating memory systems, which the paper offers as partial motivation for the field needing better memory benchmarks.
