# Q1 Problem Definition

* **Input (X):** a stream of user audio in 1-second units, plus injected observations (schemas of the tools the frontend may call and results of its earlier calls); the user's request may be disfluent and corrected mid-utterance (in the paper's running example the user switches from two laptops to one tablet).
* **Output (Y):** at each unit, a turn state (listen or speak), voiced text, and a possibly empty private action (a tool call that is never voiced). Success requires that executed calls match the gold calls exactly (no missing or extra call, all normalized arguments correct), the spoken answer rests only on returned observations, the frontend acts within a deadline once information is sufficient (or asks only for missing values), and turn-taking stays correct (take the turn at the end, not in pauses; stop on interruptions; continue through backchannels).
* **Constraints:** one causal policy must make conversational and task decisions together; tools can be exposed directly (Direct), only through a backend agent (Backend, as in Realtime-Venus's frontend-backend design), or both (Both).

# Q2 Problem Novelty

Full-duplex speech models (Moshi, MiniCPM-o, Realtime-Venus) and frontend-backend voice agents that delegate tasks to a text agent (Realtime-Venus Harness, DuplexOmni, Gander, JoyAI-VL-Interaction, SALMONN-duo, Hu et al.'s frontend-backend architecture) already exist, as do speech frontends that call tools directly (GPT-Realtime, Qwen-Audio-3.1-Realtime, NemotronLabs VoiceChat). The paper's new framing is diagnostic: under request-based delegation, Pass@1 factors into the share of sessions the frontend hands off times the pass rate of those hand-offs, so the hand-off share is a hard ceiling that no backend can raise. It locates the bottleneck of frontend-backend agents in *initiation*, not execution, and asks how a duplex model can learn task agency without losing conversational agency.

# Q3 Scientific Hypothesis

If a full-duplex model is trained to treat the backend as one more tool in the same action interface as domain tools, and is rewarded (in streaming RL) for acting on time with complete, correct calls and grounded answers, then it will initiate requests the baseline frontend never sends, raising task success with the same backend; and if only the thinker-to-talker projector is then re-fitted, speech intelligibility lost during thinker training can be recovered without undoing task gains.

# Q4 Related Work and Key People

* **Full-duplex interaction systems.** dGSLM, Moshi, SyncLLM, and pretrained-LLM duplex adaptations; the Full-Duplex-Bench series for pauses, backchannels, turn-taking and interruptions, with v3 adding tool use on real disfluent speech.
* **Frontend-backend agents.** Realtime-Venus's asynchronous Harness, JoyAI-VL-Interaction (chooses each second among speaking, silence and delegation), DuplexOmni (pluggable thinking layer), Hu et al. (delegation token plus streaming ASR to a text backend), SALMONN-duo (cost-aware RL for when to delegate), DuplexAgent-RSI (improves the delegation harness from traces). [Gander](2609.08977.md), in this wiki, is another frontend-backend design whose published FDB v3 Pass@1 (40.0 with a GPT-5.6 backend) appears among Duopra's reference points.
* **Direct tool use and hybrid routing.** GPT-Realtime, NemotronLabs VoiceChat, Qwen-Audio-3.1-Realtime (GRPO for tool use), DuplexSLA, SHANKS, Qwen-Audio-Agent.
* **Key people.** Chiyu Chen and colleagues at Shanghai Jiao Tong University with Tencent (Chenglu Sun is marked project lead) and the University of Bristol; Gongshen Liu and Zhuosheng Zhang are marked as corresponding authors in the HTML. Likely critics: the Realtime-Venus team, whose model is both the base and the main baseline, and Full-Duplex-Bench authors.

# Q5 Key Solution Idea

1. **Unified action space.** Duopra keeps Realtime-Venus-Audio's (RV-Audio) streaming loop (a thinker LLM emitting duplex control tokens and text each 1-s unit; a talker voicing the text conditioned on projected thinker hidden states) but replaces its free-text private delegation with structured JSON in the private `<delegate>` span: `select` retrieves tool schemas and `call(f, args)` invokes any exposed tool. The backend agent is just `query(task)`, whose argument is a self-contained natural-language task that must carry the user's latest values, steps and dependencies. Direct calls and delegation share one interface and one success criterion; under Both the model chooses the route with no separate dispatcher.
2. **Stage 1: protocol SFT.** The thinker (transformer layers and final norm; embeddings, output head, audio encoder and speech modules frozen) is trained on 12,800 synthetic-speech sessions (Chinese and English) mixing tool-use demonstrations with capability-retention dialogues, 400 updates of 32 sessions. Output: Duopra-SFT.
3. **Stage 2: full-duplex RL.** LoRA on the thinker, Dr. GRPO, groups of G = 8 streaming rollouts with the same scripted user audio and tool catalog; direct calls hit simulated tools, Stage-2b delegations go to a frozen Qwen3.8-27B backend; a scorer compares logged calls with gold calls and reads timing from the log, and a judge checks spoken claims against observations available at the time. Stage 2a (7,908 tasks: direct calls, corrections, clarification, interruptions, backchannels) rewards timing (+0.1 for acting within k_act = 3 units), penalizes using a corrected value (-0.6 per value), and scores conversational control; output Duopra-RL1. Stage 2b adds five families (dependent and conditional calls, delegation under varying tool visibility, recovery) and an outcome-tier reward: 1.2 / 1.1 / 0.9 for complete grounded execution within 3 units / within 8 / later, 0.1 + 0.15c for an honest partial report, -0.95 for a fabricated result, penalties for duplicate execution; output Duopra-RL.
4. **Stage 3: projector-only talker repair.** With the Duopra-RL thinker frozen, only the 3.7M-parameter thinker-to-talker projector is trained so that its L2-normalized output on RL hidden states matches the base projector's output on the original model's hidden states (cosine loss), with an L2-SP penalty toward the base projector weights. Output: Duopra.

# Q6 Experiment Design

* **Benchmarks.** Full-Duplex-Bench v3 (100 disfluent English recordings, 12 simulated APIs; 66, 18 and 16 recordings need one, two and three calls) for task agency; FDB v1.0 takeover rates (turn-taking, pauses, interruptions, backchannels), FDB v1.5 and VoiceBench for conversation and general spoken ability.
* **Systems.** Baselines in the authors' streaming pipeline with the same Qwen3-8B backend and simulated APIs: RV-Audio + Harness and DuplexOmni; no-tool controls RV-Audio and MiniCPM-o 4.5. Duopra checkpoints (SFT, RL1, RL, final) under Direct, Backend and Both, with Qwen3-8B or DeepSeek-V4.1-Flash as the frozen backend. Published results of commercial and open systems are listed only as reference points from other setups and judges.
* **Protocol.** Three decoding seeds per recording (300 sessions per configuration); Qwen3.8-27B judges arguments and responses; paired 95% intervals by recording-level bootstrap, keeping a recording's three runs together; these do not cover training-run variability.
* **Diagnostics.** Pass@1 = Call x Pass|call decomposition; matched-session analysis of where gains come from; exclusive outcome classes (pass, wrong argument, missing, extra, no call); training-stage comparisons; talker-conditioning cosine and CER/WER for the projector repair.

The design tests the initiation hypothesis directly (same backend, different frontend) and separates stage effects, but each stage is one training run, and Stage 2b changes both tasks and reward at once (the paper says so).

# Q7 Datasets and Code

FDB v3, v1.0, v1.5 and VoiceBench are public. Training data are synthetic speech over 56 domain tools in seven domains (Stage 1 adds 16 device tools, split into 40 training, 16 validation and 16 test tools; Stage 2b expresses 32 tool functions through 84 catalogs, 2,688 schemas). The paper links a project page, GitHub (cyChen2003/duopra) and Hugging Face; release contents were not checked here. Training ran on Kunlun P800 accelerators.

# Q8 Evidence Quality

* **Initiation diagnosis is well supported.** RV-Audio + Harness executes a domain call in 31 of 300 sessions (Call 10.3%, hand-offs in 33 sessions, 11.0%) and passes 14 of them (Pass|call 45.2%, Pass@1 4.7%). Duopra (Backend, same Qwen3-8B) reaches Call 86.7% with Pass|call 51.5% (Pass@1 44.7%; gain +40.0, 95% CI [31.3, 48.7]). On the 31 sessions where the baseline did call, Duopra passes 12 against the baseline's 14; its whole gain comes from the other 269 sessions, 122 of which it passes. Swapping in DeepSeek raises Pass|call (+12.5, CI [4.8, 20.4]) but lowers Call, and the Pass@1 change (+4.7, CI [-2.3, 11.7]) is not significant. Together these support "a stronger backend cannot supply requests that were never sent".
* **Direct vs. delegated.** Direct 47.7%, Backend 44.7% (Qwen3-8B), Both 44.3%; none of the Duopra exposure differences on Pass@1 is significant. Under Both, Duopra delegates in one session with Qwen3-8B and none with DeepSeek, so "Both" measures native calling, not routing competence; the paper says this. Backend costs time (factual-answer latency 14.85 s vs. 10.42 s with Qwen3-8B) and, with Qwen3-8B, more wrong-argument sessions (+10.7 points, CI [4.3, 17.3]).
* **Training stages.** Stage 2a raises call frequency but not Pass@1 (26.0% to 26.7%, +0.7, CI [-5.0, 6.0]); Stage 2b adds +21.0 (CI [15.3, 27.0]), with multi-call requests going from 0.0% (RL1) to 27.5%. Once no-call sessions fall, wrong arguments become the largest failure class (58 of 300 for Duopra Direct), illustrated by an order ID where the letter O became a zero.
* **Conversation retained only in part.** Against RV-Audio, Duopra improves turn-taking TOR (59.1 to 75.6), pause TOR (18.1 to 5.4, lower is better) and interruption TOR (79.5 to 91.3). But interruption TOR falls from 97.0 (SFT) and 96.5 (RL1) to 91.3, turn-taking latency rises from 2.27 s to 2.75 s, and all post-trained checkpoints produce zero backchannels on the 55 FDB v1.0 backchannel items. "Coexist with key conversational agency" is accurate only with these qualifiers, which the paper states.
* **Projector repair.** Mean cosine to the original talker conditioning rises from 0.929 to 0.974; on the 221-utterance set, CER 6.01 to 2.58 and WER 9.74 to 7.66. The same utterances selected the projector among four candidates, so this is selection-set evidence, as the paper notes.
* **Comparability.** Published commercial numbers (GPT-Realtime 60.0, Gemini Live 3.1 54.0, Gemini Live 2.5 49.0) come from other setups and judges; the claim that Duopra is "on par with Gemini Live 2.5" is context only.
* **Reader checks.** Pass@1 values are all whole counts of 300 sessions (47.7 = 143/300, 44.7 = 134/300, 49.3 = 148/300, 4.7 = 14/300), and Call x Pass|call reproduces Pass@1 for every row checked. Variation is over decoding seeds only; one training run per stage. The evaluation judge (Qwen3.8-27B) is the same model as the frozen Stage-2b RL backend, which could favor the trained style on the judged Arg./Resp. columns, but Pass@1 itself rests on call matching (reader observation).

# Q9 Contributions

1. A formalization of full-duplex agency as one causal policy making conversational and task decisions, with information-sufficiency and success criteria shared by direct calls and delegation.
2. The hand-off-ceiling decomposition (Pass@1 = Call x Pass|call) and the evidence that frontend-backend baselines fail mainly at initiation.
3. Duopra: a unified JSON action interface in which the backend agent is a natural-language-argument tool, trained with protocol SFT, outcome-tiered streaming RL, and projector-only talker repair.
4. A tenfold Pass@1 improvement over the base frontend with the same backend on FDB v3, reported together with the conversational and speech costs.

# Q10 Next Steps

* **Recover backchanneling.** Add backchannel tasks or rewards to Stage 2, or extend the projector-only idea to the control-token policy, and test whether task gains survive (the paper names this as open).
* **Argument fidelity.** Wrong arguments are now the largest failure class; spelled-out alphanumeric IDs (B-O-B, P-O-9-9-9) suggest a targeted reward or a confirm-before-call behavior for identifiers (reader suggestion).
* **Interactive users.** FDB v3 uses prerecorded requests and simulated APIs; evaluate with users whose follow-ups depend on the agent's replies and results (the paper's stated future work).
* **Real routing.** Since Duopra almost never delegates under Both, build tasks where some tools are backend-only and measure routing decisions with cost, as SALMONN-duo does (reader suggestion).
* **Training variance and other bases.** Repeat stages with several seeds and on a second duplex base model (reader suggestion; the paper names other base models as untested).
