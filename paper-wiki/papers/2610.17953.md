# Q1 Problem Definition

* **Input (X):** a multi-turn tool-use task served through MCP-format tools, where any tool return may be an error or a misleading payload and a user may step in mid-episode to correct the agent.
* **Output (Y):** a trained 8B policy that notices the failure from what it can see (the tool return, the user's message, the state of the task), changes its plan, and still completes the task.
* **Training resources:** a pool of executable, database-backed environments with verifiers; a log of real tool errors to draw perturbations from; a set of other LLMs to sample contrasting trajectories; a stronger analyzer model to diagnose failures.
* **Constraint:** at deployment the policy gets no skill prompt and no separate reflector. Whatever reflection it does has to be in the weights.

# Q2 Problem Novelty

Not a new problem. Inference-time reflection (Reflexion, Self-Refine, ExpeL), training on repaired trajectories (Agent-R, ReflectRL, LoongReflect), and training under perturbed interaction (NoisyAgent) all target it. The paper's argument is about what earlier methods fail to keep: each repair is fitted to the one episode that produced it, so nothing accumulates into a statement about the environment that a later episode with a different failure could reuse, and a scalar return under noise says an episode was harder without saying which recovery the failure admitted. It also argues that the environment-scaling line it comes from (EnvScaler, Agent-World) assumes clean tool feedback and template users, so more environments add successful trajectories but no record of which well-formed return was wrong.

# Q3 Scientific Hypothesis

If recovery knowledge is mined once per environment, from contrasts between models that succeeded and failed on the same task under the same injected noise, and then used as supervision that is removed before the policy sees it, the policy will learn to recover without a prompt, and will be more robust to noise it was never trained on than policies trained on more clean environments or on per-episode repairs.

# Q4 Related Work and Key People

* **Reflection.** Inference-time: Reflexion, Self-Refine, ExpeL. Training-time: Agent-R (MCTS revision points), ReflectRL, LoongReflect (privileged reflection plus outcome RL, the closest prior in supervision type, with an episode-level hindsight rewrite as the privileged context). Robustness: NoisyAgent (clean/noisy rollout mixing with an adaptive schedule).
* **Environment synthesis.** Simulated feedback (Simia, GenEnv) against executable environments: [EnvScaler](../concepts/envscaler.md), Agent World Model (AWM), ScaleEnv, [Agent-World](../concepts/agent-world.md), EnvACE, and TOUCAN's trajectory synthesis from real MCP services.
* **Agentic RL.** [GRPO](../concepts/grpo.md), DAPO, REINFORCE++, and the group's own Tool-Star, ARPO, and AEPO; SEED (arXiv:2607.14777), which re-scores the same action tokens with and without privileged context, supplies ORPO's distillation estimator unchanged.
* **Key people.** Guanting Dong, Zhicheng Dou, and Ji-Rong Wen's group at Renmin University's Gaoling School, with Tat-Seng Chua (NUS). The group also wrote Agent-World and EnvScaler, the two strongest baselines and the source of the environment recipe and the RL task pool. Chua is also an author of NoisyAgent and of AgentNoiseBench, the benchmark used for the out-of-distribution noise test. Likely critics: authors of NoisyAgent and SEED, who would ask for matched-protocol reruns, and tool-use benchmark maintainers.

# Q5 Key Solution Idea

**Stage 1, Reflection Skill Discovery (RSD).** 557 high-usage MCP servers from the Smithery registry each seed an environment: a research agent builds a topic database, a coding agent writes tools and unit tests, and only tools that compile, pass tests, respect state transitions, and admit a verifier are kept (both agents are GPT-OSS-120B, matching Agent-World's setting); each environment has 60 verifier-backed tasks. Replaying agents on nine public benchmarks (MCP-Atlas, τ³-Bench, AutomationBench, OfficeQA Pro, JobBench, Harvey LAB, GDPval, Workspace-Bench, SkillsBench) yields 177,700 tool returns, 24,510 of them errors, grouped into eight families: server or gateway unavailable 33.6%, authentication 17.9%, timeout 14.7%, resource missing 10.5%, argument validation 10.2%, generic exception 8.3%, rate limit 4.5%, network 0.3% (shares are multi-label). Each tool return is replaced by a compatible failure with probability 0.2, the family drawn uniformly so rare ones still get practice. Nine models from five families (4B to 284B) attempt every task; DeepSeek-V4-Flash and the environment verifier jointly label each rollout (disagreements dropped) and locate the first wrong turn; success and failure trajectories on the same task are paired, at least five tasks per environment; and the analyzer turns each environment's pairs into skill records. 1,170 skills result. A record has a trigger over visible history, a diagnosis naming the failure family, a recovery template (retry, switch endpoint, ask the user, or abort), and flags for reversibility and partial effects.

**Stage 2, Reflective SFT (ReSFT).** Qwen3-8B itself generates every training continuation, with the matched skill in context: *self-reflection* restores the environment snapshot taken before the first wrong turn and continues; *skill recovery* resets to the initial state and restarts the task; *user-centric reflection* has a GPT-4.1 user simulator rewrite the skill as a correction message, deliberately including partial hints, ambiguity, and wrong advice. Only continuations the verifier accepts are kept, and the skill text is removed from the stored input (the user message stays, since a user turn is visible at deployment). With the backbone's own verified successes, the corpus is 54K trajectories.

**Stage 3, On-Policy Reflective Policy Optimization (ORPO).** From the ReSFT checkpoint, RL runs on 2.5K EnvScaler RL tasks, not RSD tasks. Each group has G = 8 rollouts, a quarter of them in perturbed environments, with advantages normalized over the whole mixed group, and a PPO-style clipped loss with KL to a reference policy. The environment's skill card is looked up by environment ID (the 557 RSD environments cover EnvScaler's 100-plus) and prepended to the history; the same policy re-scores the already-sampled action tokens under that context. The detached shift Δ = sg[ℓ_skill − ℓ] sets a weight γ = sigmoid(β·Δ), and the distillation term raises the student's log-probability on tokens the skill-conditioned teacher favours, weighted by γ. The total loss is the RL loss plus λ times this term. The teacher pass is one extra forward pass, never a rollout.

# Q6 Experiment Design

* **Benchmarks.** Long-horizon tool use: [BFCL](../concepts/bfcl.md) V4 (six categories, official averaging), ACEBench (step and turn level), a stratified 200-task ToolSandbox subset, [τ²-Bench](../concepts/tau2-bench.md) (Retail, Airline, Telecom), and [VitaBench](../concepts/vitabench.md) (four domains, Avg@4). Noise: AgentNoiseBench on τ²-Bench and VitaBench, tool noise and user noise, scored by Stability-Gated Success, which credits a task only if the trajectory was never derailed.
* **Baselines.** All trained methods start from Qwen3-8B. Reflection: Reflexion, ExpeL, Agent-R and NoisyAgent (both reproduced). Environment scaling: Simulator, TOUCAN-7B, Agent World Model (AWM), EnvACE (reproduced), EnvScaler, Agent-World (reproduced). Foundation models for reference: GPT-5.2, Claude-4.5-Sonnet, Gemini 3 Pro, Qwen3-235B-A22B.
* **Protocol.** Scores the authors measure are means of three runs. Most baseline numbers are taken from each method's paper; methods without released checkpoints, or benchmarks a paper did not report, were reproduced locally.
* **Analyses.** ORPO against GRPO, DAPO, REINFORCE++, NoisyAgent RL, and SEED for 100 RL steps on the same task pool with matched budgets (Figure 4); a one-component-removed ablation on AgentNoiseBench; per-axis Stability-Gated Success on 13 noise axes, normalized per axis, with 95% paired bootstrap intervals over 165 tasks per axis.

# Q7 Datasets and Code

The authors state they release the ReSFT and ORPO training data, the full skill library, the Agent-Reflex-8B checkpoint, training and evaluation code, the task identifiers of all training data, and the tool-fault injector, at [RUC-NLPIR/Agent-Reflex](https://github.com/RUC-NLPIR/Agent-Reflex) (13 stars at fetch time) and a Hugging Face collection. They release failure counts and families but not per-service identities of the mined error logs. The repository's contents were not checked.

# Q8 Evidence Quality

* **Supported.**
  * *Best 8B overall on the tool-use suite.* 58.6 overall (unweighted mean of five benchmark averages) against Agent-World-8B 53.6, EnvScaler-8B 50.9, NoisyAgent-8B 43.4, and the Qwen3-8B backbone 40.2; Qwen3-235B-A22B scores 57.7 and GPT-5.2 64.4. Per benchmark: τ²-Bench 62.1 against 54.6 for Agent-World, ACEBench 78.0 against 52.0 for NoisyAgent and 72.5 for EnvScaler (the gain is at the turn level, 73.3, with step level tied at 85.0), VitaBench 17.5 against 6.8 for Reflexion.
  * *Inference-time reflection does not transfer to an 8B policy.* Reflexion-8B and ExpeL-8B fall below their own backbone on VitaBench (6.8 and 7.3 against 11.4).
  * *Robustness under noise.* AgentNoiseBench overall 29.1 against 25.9 for NoisyAgent and 18.2 for EnvScaler. Pooled over both sides, Agent-Reflex is derailed on 28.5% of rollouts, EnvScaler-8B on 44.8%, the backbone on 56.1%. The two tool-noise axes where its lead clears the bootstrap interval against both baselines are the ones whose returns are well-formed (misleading lure, incomplete information), which is the case the paper's argument predicts environment scaling cannot teach.
  * *Every component contributes on the noise benchmark.* Removing self-reflection data costs most (45.9 to 41.3 on the τ² setting, 12.3 to 8.9 on Vita), then skill recovery, then user correction; removing the distillation term (43.7, 9.5) or only its confidence weight (44.5, 10.4) also lowers both.
* **Weaker or narrower than the headline.**
  * *Mixed provenance of baseline numbers.* Most baseline rows are copied from the methods' papers and four are local reproductions, while Agent-Reflex is a three-run mean under the EnvScaler protocol. The NoisyAgent row in the noise table is quoted from its paper, whose numbers come from RL on the evaluated τ²-Bench and VitaBench domains; on the VitaBench half that row (14.2) is higher than Agent-Reflex (12.3). No standard deviations are given for the main tables.
  * *Not uniformly better.* Agent-World-8B is higher on τ²-Retail (72.8 against 68.4), BFCL Web (47.0 against 44.5), and VitaBench OTA (20.0 against 8.0), EnvScaler-8B on VitaBench In-store (29.5 against 29.0), and other baselines on several BFCL categories; the overall lead comes from averaging.
  * *Ablations cover the noise benchmark only.* No component is removed on the five tool-use benchmarks, so the 58.6 is not attributed. Nothing isolates the noise injection itself (ReSFT built on clean environments), the diversity of the nine-model pool, or the size of the 54K-trajectory corpus relative to baselines' data.
  * *ORPO against other RL algorithms is shown only in a figure*, after 100 steps from Qwen3-8B (not from the ReSFT checkpoint the full method uses), so the size of its advantage was not read from the text.
  * *"Out of distribution" is argued, not measured.* AgentNoiseBench's noise was not used in training and is injected by a different process, but it is built on τ²-Bench and VitaBench, which are also in the main suite, and its tool-noise categories overlap in kind with the mined families (faulty, incomplete, wrong returns). One senior author is common to the benchmark and the method.
  * *Reflection is inferred from outcomes.* The paper does not count how often the trained policy diagnoses an error, asks the user, or aborts; the derail rate is the closest measure. Whether the recovery templates' "abort" and "ask the user" branches are ever used is not reported.
  * *One backbone, one scale.* Every trained result is Qwen3-8B; the paper lists transfer across capacities as future work.

# Q9 Contributions

* An empirical tool-failure taxonomy from 24,510 real error returns, with recovery implications per family and an injector the authors say they release.
* A way to make reflection supervision reusable: cross-model success/failure pairs under the same injected noise, distilled into structured, environment-indexed skill records with reversibility and partial-effect flags.
* Three verified data recipes (local repair from the failure snapshot, global restart, user correction that may be wrong), all generated by the policy being trained, with the privileged skill stripped from stored inputs.
* A demonstration that the privileged slot in SEED-style on-policy distillation can hold an environment-level artifact mined once offline, rather than a stronger model or a per-episode hindsight rewrite.

# Q10 Next Steps

* **From the authors.** Online skill summarization and incremental updates as tools change; temporal failure signatures (latency, concurrency, partial writes); transfer of the library across model sizes and composition of skills across environments; distilling other environment-level artifacts (verified sub-plans, tool contracts) through the same slot.
* **Matched reruns (reader suggestion).** Re-run NoisyAgent, SEED, and Agent-World under one protocol with variances, and report the noise benchmark against baselines trained on the same 2.5K RL tasks.
* **Ablate the tool-use suite (reader suggestion).** Remove noise injection, the model pool, or the skill library and report the five-benchmark overall, not only the noise benchmark.
* **Measure reflection directly (reader suggestion).** Count recovery actions by failure family in held-out trajectories, including how often the policy asks the user or stops, and test whether the policy obeys deliberately wrong user advice less often after UR training.
* **Project fit (reader note).** The skill record format (trigger, diagnosis, recovery choice among retry, switch, ask, abort, plus reversibility) is a usable checklist for how a repository agent should handle failed tool calls; the paper's evidence is that writing such rules down helps as training signal, not that prompting with them helps.
