# Q1 Problem Definition

* **Input (X):** an LLM agent (a backbone inside a harness, optionally with a self-evolving method) that plays one of 20 newly designed text games through a black-box command interface. Each turn the game describes the state and lists valid actions; the agent picks one and receives textual feedback. The game's rules are hidden and deliberately novel or counterintuitive (in one game, stealing a colleague's lunch gets you promoted and hard work does not). The agent plays repeated episodes (5 for normal games, 10 for five challenge games) and may carry experience between episodes, but its weights never change.
* **Output (Y):** a deterministic, automatically computed terminal score per episode, normalized to 0-100 against a per-game reference score $C_g$ ($z = 100x/C_g$), and four per-game metrics aggregated across games: **Max** (mean of per-trial peaks), **Mean** (average over episodes), **Learning Gain** (last-$k$ minus first-$k$ episode mean, $k=\min(3,\lfloor T/2\rfloor)$), and **Learning Slope** (slope of a linear fit over episodes).
* **Core question:** how effectively LLM agents acquire *new* knowledge from interaction, as opposed to recovering knowledge already in pretraining, and how backbone, self-evolving method, and harness each affect that ability.

# Q2 Problem Novelty

Partly new. Benchmarks for self-evolving or continual agents already measure improvement over task streams or repeated attempts (StreamBench, MemoryBench, Evo-Memory, LifelongAgentBench, SWE-Bench-CL, MemoryArena, J-TTL on Jericho games, AutoEnv). The paper's objection is that most of their tasks follow familiar real-world or public-game rules, so improvement may be recall rather than learning; ARC-AGI-3 uses unfamiliar environments but mixes in visual ability. Learn2Play's claimed novelty is the combination of (a) hand-designed games whose rules are absent from existing games, (b) deterministic replayable feedback with automatic scoring, (c) re-shuffled variants that change the visible instance but keep the rule, to test transfer, and (d) a human study on the same interface.

# Q3 Scientific Hypothesis

The paper is framed as five research questions rather than hypotheses. Stated as the claims it tests:

1. **RQ1.** If a method keeps more of the original evidence (raw histories rather than distilled rules, lessons, or workflows), the agent will learn more across episodes, because it can revise early, wrong conclusions.
2. **RQ2.** If the backbone is fixed and only the harness changes, performance and learning will change, with the model's own vendor harness doing best.
3. **RQ3.** Humans and agents differ in how they explore: humans try more varied strategies and recover from setbacks more often.
4. **RQ4.** If the visible instance changes each episode while the rule stays fixed, learning will slow, more so for weaker backbones.
5. **RQ5.** Higher token prices or more inference do not by themselves buy better performance; a better-suited harness can raise scores at lower cost.

# Q4 Related Work and Key People

* **Self-evolving agents without weight updates.** [Reflexion](../concepts/reflexion.md) (verbal reflections), ExpeL (insights plus retrieved trajectories), Voyager (executable skills), [Agent Workflow Memory](../concepts/agent-workflow-memory.md) (induced workflows), Dynamic Cheatsheet, ACE (structured playbooks), ReasoningBank and ERL (reusable reasoning patterns), GEPA (prompt evolution), Agents of Change (prompt and code revision), EvoTest (evolving the whole agent configuration), Meta-TTL (evolving the adaptation policy), and TT-SI (test-time fine-tuning, outside this paper's scope).
* **Benchmarks for learning from experience.** StreamBench, MemoryBench, Evo-Memory, LifelongAgentBench, SWE-Bench-CL, MemoryArena, AutoEnv, J-TTL, ARC-AGI-3.
* **Harness effects.** The paper cites vendor guidance that models are trained with, and harnesses tuned to, each other (MacCallum and Fioca, 2026; Shihipar, 2026) to explain why Claude Code and Codex beat OpenCode on the same backbone.
* **Key people.** All authors are at the National University of Singapore; Bryan Hooi is the senior author. Likely critics: authors of the self-evolving methods evaluated here (EvoTest, ReasoningBank, AWM), since each runs under a common protocol rather than its own tuned setting, and ARC-AGI-style evaluators who would ask how "novel" a hand-written text rule is to a model.

# Q5 Key Solution Idea

* **Novel rules, controlled variation.** 20 game templates (Table 4-5 of the paper): ten *fixed* games repeat one instance so the agent can refine a map, recipe, or plan (PrimordialSoup, GemForge, Catnip, Dungeon, DreamGarden, Ecosphere, Grapevine, Castaway, RedEye, Patch Reality); ten *re-shuffled* games change menus, guests, bosses, or layouts while the rule stays fixed (Poisoner, SynergyCorp, Haunted Inn, Roommates, Roadside Observatory, Lost and Found, Mola Tea, Plague, Butterfly, Model Auditor). Five challenge games (Catnip, DreamGarden, Mola Tea, RedEye, Roadside Observatory) get ten-episode windows and weight 3, so challenge and normal games each carry half the aggregate weight.
* **Reference-normalized scores.** Each pinned instance has a reference score labelled exact (oracle or proof), partial (best proved value), or estimated (search or score cap); 14 of 20 are exact.
* **Separating learning from performance.** Max and Mean measure achieved performance; Learning Gain and Learning Slope measure change across episodes, so a strong but static agent and a weaker but improving one are distinguishable.
* **Three comparisons on one protocol.** Nine backbones under one common harness (OpenCode, an open-source coding-agent CLI); six experience methods with the backbone fixed (Naive with no cross-episode memory, Memory with raw histories, Reflexion, EvoTest, ReasoningBank, AWM); and same-backbone harness swaps (OpenCode against Claude Code for Claude Opus 5, against Codex for GPT-5.6-SOL). Three independent trials per configuration and game.

# Q6 Experiment Design

* **RQ1 backbones.** Claude Opus 5, Claude Sonnet 5, Gemini 3.5 Flash, Gemini 3.7 Flash, GPT-5.6-SOL, GPT-5 Mini, DeepSeek V4 Pro, Kimi K3, Qwen 3.8 Max, all under OpenCode with fixed loop, prompts, replay protocol, and memory format.
* **RQ1 methods.** The six methods run with Kimi K3, Claude Opus 5, and GPT-5 Mini.
* **RQ2 harnesses.** Trials are isolated (Claude Code with persistent auto-memory disabled, Codex with `--ephemeral`, OpenCode in a fresh session); within a trial, earlier episodes stay in the session subject to each harness's context handling.
* **RQ3 humans.** College students, paid with extra rewards for top scores, play the same interface without AI tools or code; 21-30 participants per game. Top-1, Top-3, and Top-5 records per game are selected by Max. Behavior is compared on fixed games: sequence similarity of consecutive episodes' actions (Python `SequenceMatcher`) and the rate of reaching a new personal best right after a score drop.
* **RQ4 transfer.** For each re-shuffled game, a same-instance control repeats one instance; Learning Slope over ten episodes is compared for seven OpenCode backbones plus Claude Code and Codex.
* **RQ5 cost.** Estimated from recorded token usage with fresh-input, cache-read, cache-write, and output prices from a 30 August 2026 snapshot; not billing records.
* **Rule-discovery audit.** Appendix D gives per-game learning curves, leaderboards, and archived evidence labels on whether a run discovered the target rule, reported per game rather than aggregated.

# Q8 Evidence Quality

* **Supported.**
  * *Backbones differ in performance and in learning, and the two rankings differ.* Under OpenCode, Claude Opus 5 leads Max (74.5) and Mean (53.8) while Qwen 3.8 Max leads Learning Gain (+25.2) and Slope (+6.30); GPT-5 Mini is last (Max 34.0).
  * *Raw histories beat distilled experience with Kimi K3.* Memory leads all four metrics among the six Kimi K3 methods (Max 63.3, LG +16.9) against EvoTest (62.4, +1.8), Reflexion (61.6, +14.8), ReasoningBank (59.9, +8.3), AWM (56.1, +4.8), and Naive (54.7, +0.3).
  * *The harness matters at a fixed backbone.* Claude Code with Opus 5 reaches Max 81.8 / Mean 62.3 / LG +27.1 against OpenCode's 74.5 / 53.8 / +21.3; Codex with GPT-5.6-SOL reaches 74.3 / 54.8 / +22.2 against 57.0 / 41.1 / +14.5. OpenCode itself beats every self-evolving method on the same backbone (Kimi K3: 68.5 against Memory's 63.3; Opus 5: 74.5 against EvoTest's 66.1).
  * *A better harness can also be cheaper.* For Kimi K3, OpenCode uses 0.55M input tokens and 8.1 model calls per episode ($0.313) against Memory's 1.26M and 27.0 calls ($0.586), because it executes several actions per model response and strips repeated game feedback.
  * *Re-shuffling slows learning, unevenly.* Learning Slope drops by 2.67 for Claude Sonnet 5, 2.15 for Gemini 3.7 Flash, and 1.94 for GPT-5.6-SOL, but only 0.59 for Opus 5 and 0.52 for Claude Code, and the drop is negative (the re-shuffled slope is higher) for Qwen 3.8 Max (-0.41) and Codex (-0.19).
  * *Concrete failure mechanisms.* In GemForge an EvoTest-Opus 5 run turns one failed fusion into a prompt rule forbidding all tier-2 and tier-3 fusions and plateaus (46, 81, 83, 83, 83); in Haunted Inn an agent states the taboos but places guests greedily and runs out of safe rooms; in Poisoner a GPT-5 Mini run serves the same menu position every banquet.
* **Weaker or narrower than the headline.**
  * *"Raw histories beat distillation" holds for one backbone, not all three.* With Claude Opus 5, Memory is third on Max (60.9) behind EvoTest (66.1) and Reflexion (64.8), and ReasoningBank has the highest Learning Gain (+12.3). Across the three-backbone averages, Reflexion has the highest Max (60.0) while Memory leads Mean, LG, and LS. The GemForge case is one trial, and the authors say it does not show that compression causes the aggregate difference.
  * *The human comparison is best-of-many against an average of three.* Human Top-1 is the single best of 21-30 players per game, selected by the same Max it is scored on, while each agent's Max averages three trials. Averaged over all eligible participants, humans score Max 43.6, Mean 31.2, LG +10.4, below most agent configurations. Claude Code with Opus 5 (81.8) is close to Human Top-1 (84.3) and above Human Top-3 (79.1). The finding is about the best humans, as the abstract says, not about people in general.
  * *Behavioral statistics are descriptive.* Action-sequence similarity (0.54 humans over 150 pairs, 0.66 agents over 918 pairs) and recovery after a setback (13 of 39 human drops, 33.3%, against 52 of 238 agent drops, 21.8%) pool non-independent episodes and compare Top-3 humans with all six Opus 5 methods; the authors call them descriptive, not causal.
  * *Small trial counts and no intervals in the main tables.* Three trials per configuration; trial standard deviations are only in Appendix C, and many differences between neighbouring methods (for example Kimi K3 Memory 63.3 against EvoTest 62.4 on Max) are small.
  * *Methods run under a common protocol, not their tuned settings.* Self-evolving methods call the model per action and reinsert stored experience, while the harnesses can batch actions and run code; part of the method gap is therefore a loop-design gap, which the paper itself uses to explain OpenCode's advantage.
  * *Harness mechanism is asserted, not tested.* That Claude Code and Codex win because the models are trained on them is attributed to vendor statements; no experiment isolates training co-adaptation from harness features such as context handling.
  * *Six of 20 reference scores are partial or estimated,* so normalized scores above or near 100 are not guaranteed to mean optimal play in those games.
  * *Internal reference errors.* The text cites "Table 2" for the table labelled Table 1 and has unresolved "Table 4.3/4.5" references; the numbers themselves are consistent across the main text and appendix where checked.

# Q9 Contributions

* Learn2Play Bench: 20 text games with novel or counterintuitive hidden rules, deterministic replayable feedback, automatic reference-normalized scoring, and fixed versus re-shuffled variants that separate learning a rule from memorizing an instance.
* A metric set (Max, Mean, Learning Gain, Learning Slope) that reports achieved performance and improvement separately.
* A matched comparison of nine backbones, six experience-reuse methods, and three harnesses, including token-cost estimates, showing that harness and memory format can matter as much as the backbone.
* A human study on the same interface, with behavioral comparisons of exploration and recovery.

# Q10 Next Steps

* **From the authors.** Balance exploration and exploitation so agents keep testing new strategies after one works; store learned rules linked to the interactions that support them so a rule can be revised when new feedback contradicts it; help agents separate rules that hold across situations from instance-specific details.
* **Rule-with-provenance memory (reader suggestion).** The GemForge failure is a rule that outlived its one supporting observation. A memory that keeps each distilled rule next to its supporting episodes, and marks it tentative until a second observation agrees, is a direct test of the authors' second direction; [Trace2Env](2610.06100.md)'s worldbook, which retains provenance and keeps unsupported rules tentative, is one existing design to borrow.
* **Fair human baselines (reader suggestion).** Report human Max as an average over three randomly chosen players per game (matching the agents' three trials), or agents' best-of-N over as many trials as there are humans, so the two sides use the same selection.
* **Contamination horizon (reader note).** The rules are novel only until the games, solutions, and run logs are public; future models trained on them would turn learning back into recall. Held-out templates, or periodically refreshed rule parameters, would keep the benchmark measuring learning.
* **Project fit (reader note).** This repository's scheduled agents carry lessons forward in memory files. Learn2Play's result that raw episodes can outperform distilled rules (at least for one backbone) argues for keeping links from each memory entry back to the conversation or run that supports it.
