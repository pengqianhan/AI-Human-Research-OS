# Q1 Problem Definition

* **Input (X):** a machine-learning paper, its official repository at a pinned commit, and a set of tasks. A task is one own-method measurement from a main table, identified by dataset, metric, reporting statistic, and location. A fresh coding-agent session (the Reproducer) receives the paper, the tasks, and either the raw code or a refined artifact.
* **Output (Y):** new measurements with execution evidence. A task succeeds when its value lies in a compatibility interval built from five human-verified reference runs and a separate Auditor does not invalidate the execution behind it.
* **Constraints:** the paper's stated setup takes precedence over conflicting code; published targets stay visible, but reference observations, the other condition, and other agents' run directories are withheld; a shipped score file never counts as a measurement; each paper gets a 24-hour wall-clock limit and GPU experiments use eight H100-80GB GPUs.

# Q2 Problem Novelty

Partly new. Reproduction benchmarks exist: [PaperBench](../concepts/paperbench.md) and SciReplicate-Bench score reimplementation with rubrics, [CORE-Bench](../concepts/core-bench.md) scores execution of released capsules, and REPRO-Bench and ReplicationBench extend to other sciences. Automated reproduction systems exist too (PaperCoder, AutoReproduce, VERITAS, and the Compiler for Agent-Native Research Artifacts). The new question is about the hand-off: how much of reproduction success depends on the released artifact, and how much on the reproducer's ability to fill gaps, tested by fixing the reproducer and changing only what it is handed.

# Q3 Scientific Hypothesis

If the procedures and decisions recovered during one reproduction are preserved in a standard form (dependency resolution as an installation procedure, experiment discovery as a launcher, each correction as a documented choice with its reason and affected tasks), then later independent reproducers will succeed more often and spend less, and weaker models will gain most, because success will depend less on inferring missing details. In the paper's working model a measurement is Y = μ + D + ε, where D is the shift caused by execution choices that depart from the specified experiment and ε is run-to-run variation; the artifact aims to shrink |D|.

# Q5 Key Solution Idea

**The refined reproducible artifact (RRA) has four parts.**

* *Refined codebase:* execution defects repaired and missing experiment support added.
* *Environment setup:* compatible dependencies and the route to data and checkpoints.
* *Experiment launchers:* entry points that tie each task to its configuration, execution scope, outputs, and score extraction, and separate scored runs from smoke tests.
* *Reproduction guide with a change record:* twelve sections; each ambiguity entry gives its source location, the gap, the adopted resolution and its reason, sensitivity, and affected tasks; changes are labelled as execution fixes, correctness fixes, or convenience changes.

**Construction workflow.** Humans define the workflow, delivery standards, and protocols; agents do all construction. Six roles in three stages: Specify (Intake, Planner) fixes the intended measurement before any result is known; Execute (Builder, construction Reproducer) builds the environment and runs the experiments, linking every measurement to an output file; Preserve (Distiller, Packager) writes the guide and assembles a deliverable tested from a clean shell. A Reviewer in a separate context challenges plans, execution records, and the final artifact. Human reference scores are withheld from construction.

**The benchmark's reference rule.** Five human reproducers on separate servers each run every task from the raw commit, without sharing scripts or results, and must fix seeds and repetition choices before seeing scores. The compatibility interval is the reference mean plus or minus the larger of a 95% Student-t prediction half-width and 1% of the mean. Only tasks whose published score falls in that interval are kept: 1,029 of 1,463 curated tasks (70.3%), from 387 of 502 experiments.

**The integrity audit.** After a session ends, an Auditor traces each reported value to its output file, execution record, and generating script, using timestamps and hashes. A Finder proposes localized violations, a Refuter tries to overturn each one, and contested cases go to a panel. Five violation classes can invalidate a result: copying a value, substituting the measurement instrument, altering an operand, choosing the outcome after seeing values, and computing the wrong statistic.

# Q6 Experiment Design

* **Main comparison (Table 3).** Opus 5 builds the 36 artifacts. Sonnet 4.6, Sonnet 5, Opus 5, and Gemini 3.8 Flash each attempt all 1,029 tasks from raw code and from the RRA, one fresh session per paper, model, and condition, three evaluations each; Codex is the primary Auditor. Papers come from a random sample of 50 ICML 2026 Spotlight papers with code, minus 14 excluded for availability, compute, or closed-model access.
* **External benchmark (Table 4).** 45 CORE-Bench Hard capsules reproduced from raw code, from VERITAS's patched code and fix log, or from an RRA.
* **Robustness (Table 5).** Equal weight per paper, and a stricter 80% interval.
* **Mechanism (Section 4.4).** Paired task outcomes, time to first scored execution, and case studies.
* **Ablations (Table 6).** Sonnet 5 on 287 tasks from 12 papers: raw code, "ordinary outputs" (Opus 5's raw-code run directory with code, scripts, and logs but no result files and no guide), the full RRA, and the RRA minus each component together with its descriptions elsewhere.
* **Audit checks (Table 7, Figure 6).** Codex against Claude as Auditor, and both against two human reviewers on all 409 tasks of eight random papers under both conditions (818 outcomes).
* **Cost (Section 4.7, Appendix E).** Construction cost against per-round savings.

# Q8 Evidence Quality

* **Supported.**
  * *Higher success for every model.* Raw to RRA, mean of three evaluations: Sonnet 4.6 72.3% to 91.6%, Sonnet 5 76.5% to 93.3%, Opus 5 89.2% to 94.7%, Gemini 3.8 Flash 67.6% to 90.8%. The four-model means are 76.4% and 92.6%, and the spread between best and worst model falls from 21.6 to 3.9 points (reader check of the abstract's figures against Table 3).
  * *Lower downstream cost.* Tokens fall 6.3% to 19.8% and API spend 16.8% to 23.7% per model, failed attempts included.
  * *Holds under other scoring.* With equal weight per paper the gains are 6.7 to 20.7 points; with the 80% interval they are 10.3 to 39.1 points. Three to six of 36 papers regress per model.
  * *The standardized hand-off beats leftover run directories.* On the ablation subset: raw 73.9%, ordinary outputs 81.2%, full RRA 93.0%.
  * *The audit is measured against people.* Against shared human labels, Codex reaches 88.6% precision and 79.5% recall and Claude 85.7% and 61.5%; each falsely flags 4 of 779 valid outcomes. The raw-to-RRA gain keeps its direction under either Auditor.
  * *Reuse on another benchmark.* On CORE-Bench Hard: raw 62.2%, VERITAS 68.9%, RRA 73.3%, with spend per successful capsule falling from $8.43 to $4.34.
* **Weaker or narrower than the headline.**
  * *The task set is conditioned on reproducibility.* Only tasks where five human runs agreed with the published score are evaluated; the 434 dropped tasks (numerical mismatch 183, execution blocked 186, resource or access limits 65) are exactly where the hand-off question is hardest. The paper says the results are not a conference-wide reproduction rate.
  * *Nearly a third of the recovered tasks are audit recoveries.* Of 813 raw failures that become successes, 348 were numerical mismatches, 210 were not run, and 255 were numerically matching results the Auditor had invalidated. That last group depends on an Auditor with 79.5% recall; in the human-labelled subset 33 of 39 invalid outcomes were under raw code, which supports the direction of the effect but not its exact size (reader observation).
  * *Ablation differences are small counts from one evaluation.* Removing a component costs 3.1 to 5.2 points on 287 tasks, which is about 9 to 15 tasks (reader calculation), from a single evaluation with one model; the main table's standard deviations across evaluations are 1.1 to 3.4 points. The ordering of the four components is therefore not established.
  * *CORE-Bench differences are two or three capsules.* 62.2%, 68.9%, and 73.3% of 45 capsules are 28, 31, and 33 capsules (reader inference from the percentages), from one run.
  * *The intervention is the whole workflow.* The RRA and the ordinary outputs come from separate upstream runs, so the comparison does not isolate the effect of organizing the same recovered knowledge; the paper states this. The artifacts are also built for exactly the tasks that are then scored, with launchers for them (reader observation).
  * *Break-even needs many reuses.* Building 36 artifacts costs $5,026 in API usage; break-even takes 8, 13, and 9 full rounds for Sonnet 4.6, Sonnet 5, and Opus 5, excluding GPU time, auditing, maintenance, and the human reference runs. Gemini 3.8 Flash is left out: its saving of $66 per round (392 minus 326 in Table 3) would need about 76 rounds (reader calculation).
  * *Refinement can make things worse.* 136 raw successes become failures, 64 of them from two papers (AuxiliaryMCMC 50, LiME 14), and the paper notes that an artifact can preserve or introduce incorrect choices.
  * *Harnesses differ across vendors,* so comparisons between models are descriptive, and one model (Opus 5) built every artifact in the main experiment.
  * *Paper-code contradictions are unvalidated.* A separate agent-assisted static analysis records 238 contradiction findings touching 669 tasks; the paper says these are not human-validated error rates and do not explain the gains.

# Q9 Contributions

* A four-component artifact standard that stores executable steps together with the reasons for them.
* An agent workflow that builds such artifacts from a paper and its repository, with pre-registered measurement specifications and independent review.
* A benchmark with human-verified reference distributions rather than a single published number, and success defined as numerical compatibility plus execution integrity.
* An execution-integrity audit with five violation classes, validated against two-person human review, including outcomes no Auditor flagged.
* Evidence that the hand-off, not only the model, determines reproduction success: with refined artifacts all four models exceed 90%.

# Q10 Next Steps

* **Human reuse.** The authors name studies of human researchers' time and comprehension, and full accounting of construction, verification, and maintenance costs.
* **Use before submission.** The intended primary use is authors running the workflow on their own paper to find missing details and paper-code conflicts before release; this use is proposed, not evaluated.
* **The dropped 30% (reader suggestion).** Running the workflow on Category 3 and 4 tasks would show whether it can turn an unreproducible result into a reproducible one or a documented discrepancy.
* **Same-knowledge control (reader suggestion).** Reorganize one upstream run's outputs into the four components and compare against the unorganized outputs, to separate format from extra work.
* **Cheaper builders (reader suggestion).** Only Opus 5 and, on CORE-Bench, Sonnet 5 build artifacts; whether a cheaper model can build artifacts that a stronger one reuses is untested.
* **Reader connection.** The audit's violation classes (copied values, substituted measurements, post-hoc selection) are the failure types that autonomous-research evaluations in this wiki report for agent-written papers; an RRA-style evidence chain could be required of those agents as well.
