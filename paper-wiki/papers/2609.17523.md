# Q1 Problem Definition

* **Input (X):** a stream of researcher interactions with a deployed scientific agent: requests with uploaded data (documents, tables, sequences, images), follow-up replies, and the agent's execution record (code, tool calls, observations, artifacts). The agent is a task model π_θ running inside an editable harness H (instructions, scoped skills, context settings) over fixed scientific infrastructure.
* **Output (Y):** an updated model-harness pair (θ_{k+1}, H_{k+1}) that performs better on held-out scientific tasks, redeployed to the same researchers.
* **Core question (the authors' own wording):** how can a scientific agent turn collaboration with researchers into *sustained* improvements in its working procedures and underlying capabilities, rather than one-off corrections inside a single conversation?
* **Constraints:** researcher replies and historical answers are not treated as ground-truth labels. Tools, infrastructure, rubrics, and evaluators stay fixed while the harness is edited. The harness and rubrics stay fixed while the model is trained. Development, training, and held-out test tasks are kept separate.

# Q2 Problem Novelty

Partly new. Harness and prompt evolution (Reflexion, GEPA, ACE, [Meta-Harness](../concepts/meta-harness.md)), rubric-based RL (Rubrics as Rewards), learning from user interaction (OpenClaw-RL), and joint harness-plus-weight updates (SIA; HELIX linking harness evolution to training-data construction) all predate it. The paper names these as precedents. Its new element is the *nesting*: an inner harness-editing loop run with the model fixed, whose selected harness then shapes the task distribution and rollouts of an outer RL loop, with the whole pair redeployed to real researchers whose next interactions seed the next cycle. The other new element is packaging collaboration records as executable tasks with task-specific rubrics. This matters because the deployment interface of a science agent becomes its training-data source.

# Q3 Scientific Hypothesis

If researcher collaborations are converted into executable tasks with task-specific rubrics, and a fixed task model's harness is revised only through small, validation-gated edits before the model is RL-trained under the selected harness, then (a) harness edits alone improve held-out accuracy at fixed weights, (b) RL alone broadens the set of solvable problems under a fixed harness, and (c) alternating the two over several cycles compounds, with few regressions on held-out problems.

# Q4 Related Work and Key People

* **Persistent procedural adaptation:** Reflexion, GEPA, ACE (Agentic Context Engineering), [Meta-Harness](../concepts/meta-harness.md), PILOT. The bounded single-edit scope and acceptance-on-improvement rule are attributed to [SkillOpt](2605.23904.md) and SkillGen, and the regression-aware evaluation to SkillGen.
* **Recursive self-improvement:** Darwin Gödel Machine and Hyperagents (editable improvement procedures), SEAL (self-generated update directives). The paper explicitly notes that its reflector stays fixed, so better task performance does *not* mean the improvement mechanism got stronger.
* **Learning from interaction and joint adaptation:** OpenClaw-RL, RLAnything, SIA, HELIX, AgentBuild (scientist-authored rubrics).
* **Training signal:** Rubrics as Rewards for reward aggregation, AdaRubric for task-adaptive rubrics, Robust Rubric Rewards for the fixed judge, [GRPO](../concepts/grpo.md) (DeepSeekMath), and Environment Evolution for Terminal Agents for difficulty-calibrated task augmentation.
* **Science infrastructure:** Biomni (tool catalog and data lake), LAB-Bench, Harbor (task packaging), ReAct.
* **Key people:** PhAI Labs (all first authors), with corresponding authors Zhenfei Yin, Yingcheng Wu, and Ling Yang. Affiliations also include Fudan University/Zhongshan Hospital, Oxford, Stanford, and Princeton. Likely critics: the Meta-Harness and HELIX/SIA authors (whose ideas it composes), and anyone asking for controlled baselines on the benchmark numbers.

# Q5 Key Solution Idea

* **Workspace and pluggable harness.** A chat-plus-trajectory UI over 224 tools in 22 modules (genomics, molecular and cancer biology, pharmacology, bioimaging, literature, databases; tool catalog derived from Biomni), Python/R/Bash execution, a local data lake, and a persistent workspace. The editable harness (instructions, skills, context procedures) sits behind a common execution interface, so procedural changes are explicit and evaluable.
* **Collaboration → task + rubric.** Related turns are consolidated around one objective. A self-contained instruction is written *without* the historical answer. A rubric is built from the full collaboration trajectory (scope, method, evidence, required artifacts). Both are packaged as a Harbor task (instruction, assets, environment, rubric-based tests) usable for rejection-sampling SFT or RL.
* **Inner recursion (harness, model fixed).** A separate fixed auxiliary model (GPT-6 Astra) reads recent trajectories and rubric feedback, cites the unmet criterion, and proposes *one* bounded edit (one skill added/removed/revised, one instruction, or one context setting), checked by a schema and size budget. Parent and candidate run on identical development tasks, seeds, and budgets. The candidate is accepted only if it is valid and strictly improves the mean rubric score (ties keep the parent), and previously solved tasks are included to catch regressions.
* **Outer recursion (model, harness fixed).** Task environments are augmented and difficulty-calibrated against the current model and selected harness. The model is trained with GRPO on fresh on-policy rollouts using a weighted rubric reward (executable checks where possible, a fixed judge otherwise). The inherited harness is re-evaluated under the new weights before the pair is redeployed. Background training runs while the online service keeps serving.

# Q6 Experiment Design

The evidence consists of four case studies, not a controlled benchmark comparison against other systems.

* **RQ1, researcher interaction (qualitative):** two real sessions (a JAK1 small-cell lung cancer study plan; an ARL4C presentation). The paper shows how they would become task objectives and criteria, but labels the resulting task specifications as illustrative derivations, "not archived rubric packages or scored outputs."
* **RQ2, coupled cycles:** Qwen3.5-4B, three cycles (the section heading says "Two-Cycle", the text and figure say three, indexed k = 0, 1, 2). Each cycle has 10 harness-search steps selected by validation accuracy, then 20 RL updates. Held-out single-attempt accuracy and per-family breakdowns are reported.
* **RQ3, harness only:** fixed Qwen3.5-4B, 24 edit batches over 288 adaptation conversations with a *simulated* user (a fixed Qwen3.8-27B helper choosing from bounded replies that never reveal the answer). The selected harness is compared with the initial one on a separate validation set.
* **RQ4, RL only:** fixed initial harness H0, about two hours of RL, pass@4 coverage before and after on a common panel.
* **Task pool:** 895 tasks from LAB-Bench and Biomni-Eval1 over four families (LitQA2 96, DbQA 511, ProtocolQA 108, GWAS 180; 16 subtopics).

No new benchmark. The case studies reuse LAB-Bench and Biomni-Eval1 tasks. The paper releases the product (http://science-buddy.io) and a GitHub repository (Gen-Verse/ScienceBuddy). # Q8 Evidence Quality

* **Reported results:**
  * *Coupled cycles:* harness validation accuracy rises within each cycle (38.9→44.4%, 34.4→46.7%, 61.1→70.0%). Mean training reward rises between the first and second half of each RL phase (33.3→38.8%, 44.1→60.5%, 57.8→69.8%). Held-out accuracy goes from 42.2% to 73.3%; 33.3% of test problems flip from wrong to right and 2.2% from right to wrong. All four families improve.
  * *Harness only:* validation accuracy 31.1% → 51.1% (+20 points) at fixed weights. The best batch accuracy seen during adaptation is 75.0%. The final harness has four instruction entries and nine scoped skills (Python execution, schema inspection, bounded record lookup, answer submission, gene-set checks, cytoband lookup).
  * *RL only:* pass@4 coverage 48.3% → 67.8% (+19.5 points).
* **Limits of that evidence:**
  * *Small, unreported evaluation sets.* Test-set sizes are not stated in the retrieved text. Percentages such as 2.2% and 33.3% are consistent with a test set of only about 45 problems (reader inference), so each problem is worth about 2 points and no confidence intervals are given.
  * *No external baselines.* There is no comparison with Meta-Harness, GEPA, SIA/HELIX, or an RL-only run with matched compute. The coupled result is not decomposed into how much comes from harness versus model per cycle.
  * *Simulated feedback in the quantitative harness study.* The measured harness gains come from a bounded, reference-assisted user simulator, not from real researchers. The real-researcher evidence (RQ1) is qualitative and does not produce scored rubrics.
  * *Mixed metrics.* Harness gains use first-response accuracy, RL gains use pass@4 coverage, and the coupled study uses single-attempt accuracy, so the three results are not on one scale.
  * *No per-edit attribution.* The authors state that effects of individual skills and feedback sources "are not separately isolated."
  * *Fixed reflector.* The authors themselves say this is not evidence that the improvement mechanism improves; only the model and harness improve.

# Q9 Contributions

* A released, working scientific workspace with an inspectable trajectory view and a pluggable harness interface.
* A concrete recipe for turning collaboration records into executable tasks plus task-specific rubrics, with explicit information boundaries between the task policy, user simulator, feedback interpreter, harness reflector, verifier, and learner (Table 2 of the paper).
* The recursive-in-recursive schedule: validation-gated single-edit harness search with the model fixed, nested inside rubric-reward GRPO with the harness fixed, with re-evaluation of the inherited harness after each model update and asynchronous background updates behind a live service.
* Case-study evidence that each loop alone, and the two coupled, improve a 4B model on biomedical task families.

# Q10 Next Steps

* **Controlled comparisons:** run harness-only, RL-only, and coupled schedules at matched compute on a larger held-out set with confidence intervals. Compare against Meta-Harness or GEPA for the inner loop and against SIA/HELIX for the joint loop.
* **Real rather than simulated feedback:** measure harness gains from the real-researcher stream, and test whether collaboration-derived rubrics agree with expert graders.
* **Does the inner loop overfit?** The harness is selected on a small development set with a strict-improvement rule. [RRSI](2609.24972.md)'s argument that unregularized harness evolution fits the evolve set applies directly (reader-constructed link).
* **Order and ratio of loops:** 10 harness steps and 20 RL updates per cycle is one arbitrary schedule. Whether the harness should be re-searched after every model update, or evolved jointly, is untested.
* **Relation to routing-harness RSI (reader note):** [NeoHorse-1](2609.08183.md) also turns deployed-harness signals into post-training data. Comparing what each extracts from deployment (rubric-scored tasks here, routing and capability signals there) would clarify which signal is most useful.
