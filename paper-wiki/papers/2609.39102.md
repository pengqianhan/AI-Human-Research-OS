# Q1 Problem Definition

* **Setting:** proposer-solver self-evolution of a search agent, as in Dr. Zero (Yue et al., 2026, arXiv:2601.07055). A proposer turns source documents into questions with pseudo-labels; admitted pairs train a solver; the solver's agreement with the pseudo-label on new proposals becomes the proposer's reward. No human-annotated QA data is used.
* **Input (X):** a corpus of source documents, a base model (Qwen3.5-4B or Qwen3.5-9B) playing both roles, and a search tool.
* **Output (Y):** a trained search policy (the main solver), evaluated on open-domain single- and multi-hop QA.
* **Core problem:** in this closed loop, agreement is the only proxy for correctness. A wrong pseudo-label can train the solver to repeat the same error on later questions from that source, and the proposer is then rewarded for that agreement. The authors call the outcome **co-cheating**: internal reward improves while external correctness does not. They stress it implies no intentional coordination.
* **Measurement:** a post-hoc auditor (gpt-6-astra/high) builds an evidence-backed reference from each source and judges the saved pseudo-label and the five solver responses used for proposer reward. It reports label truth T_P, solver truth T_S, in-loop agreement A, **false-agreement mass** F (pairs agreeing on the same wrong answer), and lost credit L (correct responses denied credit by a wrong label). The auditor never feeds back into training.

# Q2 Problem Novelty

Partly new. The authors state they do not introduce self-play, answer verification, or cross-fitting. Self-generated curricula (SPIN, R-Zero, Absolute Zero, SPICE), self-evolving search (Dr. Zero, Search Self-Play), proxy-reward overoptimization (Gao et al., 2023), and pseudo-label confirmation bias (Arazo et al., 2020) are all prior work. SearchMaster (arXiv:2608.01822) is named as the closest complementary diagnosis of misleading search self-play signals, and CAFE (arXiv:2608.24794) as concurrent work on co-evolving feedback. The narrower contribution is an external audit showing that this specific failure grows round by round, and isolating one cause: the **training ancestry of the solver that supplies proposer feedback**.

# Q3 Scientific Hypothesis

If the solver that scores a proposal has been trained on pseudo-labels derived from the same source document, a source-derived error can come back to the proposer as reward. Removing that path, so every scoring solver has never trained on the evaluated source, should lower false agreement and give a better curriculum, and therefore a better downstream search policy. Improving label quality alone (verification before training) should help less, because it does not cut the return path.

* **Key people:** Meijia Chen (Rutgers), Hao Li, and Zheng Lu (equal contribution); corresponding authors Tianyu Shi (McGill) and Alaa Khamis (King Fahd University of Petroleum and Minerals). Several co-authors list "Independent Researcher". Likely critics: the Dr. Zero and Search Self-Play authors, who may ask whether the coupled baseline was run as intended, and readers who want human validation of the LLM auditor.

# Q5 Key Solution Idea

* **Multi-sample verification (MSV), an admission-time check.** For each proposal, the same model answers three times with the source document and three times without it. A view's majority exists when at least two samples agree. The task is admitted only if both majorities exist and are compatible, and the majority then replaces the proposer's draft label. Cost: six extra labeler generations per candidate. Its limit, by the authors' account: six samples from one model can share errors, and verification does not stop a later feedback solver from reusing labels derived from the evaluated source.
* **CrossFit, the main method.** Each source document is assigned once to fold 0 or fold 1, and every question derived from it keeps that fold. Two auxiliary solvers train only on admitted questions from their own fold. Questions from fold 0 are then scored by the solver trained on fold 1, and vice versa. The proposer reward keeps Dr. Zero's frontier rule, f(k) = (5−k)/4 for 0 < k < 5 matches out of five solver responses (zero otherwise); only *which* solver produces the responses changes. The main solver is not split: it still trains on all admitted questions from both folds.
* **Why source-level folds:** splitting individual questions would put related questions from one document on both sides and keep the reuse path open, which the ablations confirm.
* **Combining them:** MSV decides admission and the label; CrossFit decides who scores the next proposal.

# Q6 Experiment Design

* **Training:** three rounds per treatment, each with 18 proposer and 25 main-solver updates; 1,600 admitted questions per round; five solver responses per question; a sequence-normalized policy-gradient objective with group-normalized advantages; temperature 0.8, top-p 0.95; at most five assistant actions and 512 new tokens per action. CrossFit adds 25 updates per round for each auxiliary solver (50 in total). All treatments start from the same public checkpoint.
* **Treatments:** Dr. Zero (coupled feedback), MSV, CrossFit, MSV + CrossFit. Prompting, R1-Instruct, and Search-R1 are reproduced on the same backbones as further baselines.
* **Downstream evaluation:** a fixed 1,325-question suite, 200 each from Natural Questions, TriviaQA, PopQA, HotpotQA, 2WikiMultiHopQA, and MuSiQue plus all 125 Bamboogle questions. One greedy trajectory per question, identical tool budget and answer extraction, Cover-EM (a normalized reference answer appearing in the normalized prediction), macro-averaged over the seven benchmarks.
* **Audit:** every scheduled step (129 per run, 43 per round) is audited; round-3 means are reported. Audit coverage J/E is about 0.86 for every treatment; unresolved cases are left unresolved rather than forced.
* **Mechanism controls on a fixed replay bank:** the same 3,000 saved questions and adopted labels, varying only the feedback solver's training data (coupled, same-source auxiliary, full-data auxiliary, random question-level split, source-ID split, half-budget source-ID, and MSV variants), reported as mean ± SD over five seeds. This removes admission and curriculum changes as explanations.
* **Cost:** reserved H200-hours, tokens, and judge requests per run.

# Q8 Evidence Quality

* **Supported:**
  * *Co-cheating grows under coupled feedback.* Mean false-agreement mass is 0.004 (4B) and 0.003 (9B) in round 1 and reaches 0.061 and 0.088 in round 3, while lost credit falls. Agreement rises above solver truth (round 3: A 0.710 vs. T_S 0.669 at 4B; 0.752 vs. 0.689 at 9B).
  * *CrossFit changes the audit in the intended direction.* Round-3 label truth rises from 0.747 to 0.819 (4B) and from 0.737 to 0.851 (9B); false agreement falls to 0.030 and 0.037; agreement drops to or below solver truth. MSV alone reaches only 0.057 and 0.072; MSV + CrossFit reaches 0.020 and 0.017.
  * *Downstream gains.* Average Cover-EM: Base 0.384/0.409, Search-R1 0.401/0.434, Dr. Zero 0.400/0.428, MSV 0.407/0.436, CrossFit 0.488/0.512, MSV + CrossFit 0.491/0.515 (4B/9B). CrossFit improves every benchmark at both scales, with larger gains on the four multi-hop sets (10.0/10.9 points) than the three single-hop sets (7.3/5.2). Its advantage over Dr. Zero grows from 4.2/4.3 points after round 2 to 8.8/8.4 after round 3. Micro and macro averages rank treatments identically.
  * *Source ancestry is the operative variable (fixed bank).* A separate evaluator is not enough: same-source and full-data auxiliary solvers leave F at 0.064/0.087 and 0.058/0.069, and a random question-level split at 0.050/0.062. The source-ID split reaches 0.004/0.001, with fixed-bank solver truth 0.687→0.770 (4B) and 0.717→0.868 (9B) and replay accuracy 88.1%→91.5% and 87.0%→91.7%. A half-budget auxiliary (0.005/0.002, 91.6%/91.8%) rules out extra updates as the cause.
* **Weaker or bounded:**
  * *One adaptive run per treatment.* The downstream table and the audit come from a single self-evolution run per arm and scale. Only the fixed-bank replay reports seeds. There are no confidence intervals or significance tests on the 1,325-question results.
  * *The audit is an LLM judge.* gpt-6-astra/high constructs the reference and judges correctness; about 14% of audited cases stay unresolved. The retrieved text reports no human agreement check, although the related-work section names human validation as the motivation for blinded evidence gathering.
  * *Not compute-matched.* CrossFit as run (25 updates per fold) reserves 72% (4B) and 79% (9B) more H200-hours than Dr. Zero (650 vs. 379 and 854 vs. 476); MSV costs about 90% more and nearly five times the judge requests; MSV + CrossFit costs 2.6-2.7 times. The half-budget CrossFit (+36%/+40%) matches the full version on the replay bank, but its downstream Cover-EM is not reported. Reserved hours include waiting time, so these are budget ratios, not GPU utilization.
  * *Effect size versus mechanism (reader note).* Coupled self-evolution adds only 1.6-1.9 points over the base model, while CrossFit adds 10.4 (4B) and 10.3 (9B) points, from a change in false-agreement mass of 3-5 points. The replay experiments tie the *audit* change to source ancestry, but nothing isolates how much of the downstream gain comes through reduced co-cheating rather than other effects of scoring with differently trained auxiliary solvers (for example, a different difficulty signal for the frontier reward).
  * *Lower false agreement has other explanations.* The authors note that F on accepted questions can fall simply by rejecting hard tasks, and that shared pretraining errors, overlapping web evidence, and semantically related sources can still correlate the two solvers. CrossFit raises lost credit (0.020→0.038 at 4B, 0.025→0.041 at 9B), so it trades false agreement for more wrongly denied credit.
  * *Baselines.* The reproduced Search-R1, R1-Instruct, and Prompting rows follow the Dr. Zero protocol; the retrieved text does not say what training data the Search-R1 reproduction used. The evaluation is a fixed subsample of each benchmark under the lenient Cover-EM metric.

# Q9 Contributions

* A named failure mode (co-cheating) for proposer-solver self-evolution, with an external, evidence-backed audit protocol and metrics (T_P, T_S, A, F, L) that separate in-loop agreement from correctness, and evidence that it worsens over rounds.
* A simple, objective-preserving intervention, CrossFit, which changes only the provenance of the proposer's feedback, leaving the main solver's data and update rule intact.
* Fixed-bank replay controls that isolate source-level exclusion from evaluator duplication, arbitrary partitioning, curriculum selection, and extra optimization.
* A cost table that reports what each intervention costs in reserved GPU time, tokens, and judge requests.

# Q10 Next Steps

* **The authors' list:** extend exclusion from single documents to connected sources (related pages, shared evidence), and measure end-to-end efficiency; neither robustness to connected sources nor lower end-to-end cost is established yet.
* **Seeds and human audit (reader note):** repeat the adaptive runs with several seeds, and have humans adjudicate a sample of the audit to calibrate the LLM judge, before treating the 8-9-point gains as stable.
* **Compute-matched comparison (reader note):** give Dr. Zero the same extra budget (more solver updates or more rounds) and report the half-budget CrossFit's downstream score.
* **Beyond search QA (reader note):** the same return path exists in any loop where a learned evaluator trained on self-generated labels scores the next round's proposals, for example self-play code generation or self-evolving skill libraries that grade their own tests. The [Agent self-evolution](../topics/agent-self-evolution.md) topic's verifier-independence designs (RSIAgent's isolated verifier, HexaAnything's verifier kept independent of the proposing model) address the same concern at the harness level; CrossFit is a weight-level, data-ancestry version of that idea.
* **Contrast with Iris's admission test (reader note):** [Iris](2609.04304.md) admits a training question only if a reference model fails it closed-book and solves it with the supporting entity graph, which enforces difficulty and solvability. MSV instead admits a question when its with-source and without-source majorities agree, which enforces stability. The two filters select different questions, and neither addresses feedback ancestry.
