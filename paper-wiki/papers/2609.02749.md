# Q1 Problem Definition

* **Input (X):** a research task `tau = (q, D, E, g)` (problem statement, data/material, environment with tools and budget, target) and an existing agentic system `A = (M_theta, H)` — a frozen LLM backbone plus a harness supplying orchestration, memory, verification, and iterative refinement.
* **Output (Y):** an "operational knowledge" set `K = {S_1, ..., S_m}` of verified, distilled skills, added as explicit operating context so that `A_res = (M_theta, H, K)` and the agent's policy becomes `a_t ~ pi_theta(a | tau, h_t, H, K)`.
* **Core problem:** neither the backbone (broad but fixed prior) nor the harness (controls procedure, not domain content) supplies the domain-specific know-how that separates *knowing* a method from *making it work* — which methods/tools apply, when, and how to use them correctly, including API quirks and implementation pitfalls. That know-how exists in repositories and papers, but in forms written for human readers and too large to load during a task, so an agent currently rediscovers it through costly trial and error on every task rather than reusing it.
* **Scope:** the model backbone and harness are left unchanged; DisCo only builds and supplies the missing knowledge layer `K` as operating context, distilled from repositories, papers, and task-specific web search.

# Q2 Problem Novelty

This repository's [Agent skill libraries](../topics/agent-skill-libraries.md) topic already covers several skill-package systems: [SkillFoundry](2604.03964.md) mines heterogeneous scientific resources into a growing library via expand/repair/merge/prune; [OpenSkill](2606.06741.md) builds skills and self-built verification anchors from open-world resources without target-task supervision; [ResearchStudio-Idea](2607.04439.md) packages literature-search and idea-generation as interoperable skills; [SkillOpt-Lite](2607.03451.md) and [SkillOpt](2605.23904.md) *optimize an existing* skill document from execution trajectories via a text-space training analogy; [COLLEAGUE.SKILL](2605.31264.md) distills human traces (not agent trajectories) into versioned packages. Repo-To-Skill's novelty within this lineage is threefold: (1) it explicitly formalizes "operational knowledge" `K` as a third component alongside model and harness, rather than treating skills as an implicit prompt-engineering artifact; (2) it anchors distillation on *declarative source material* — versioned software repositories and papers — via a single four-stage pipeline (scope -> ground -> construct -> verify) shared by two forms, task-agnostic (built ahead of time from a source) and task-oriented (built on demand from a task), each ending in a construction record `R` that retains evidence, checks, and unresolved gaps; (3) it operates at a different scale than any other entry in this topic: the AREX-Skill Library holds 5,000+ skills distilled from 1,000 ML repositories under a generated 20-area/178-family taxonomy, evaluated via matched with/without-skills ablations on four independent, pre-existing third-party benchmarks (MLE-bench, PaperBench, FrontierCS, PassNet) rather than a custom in-house benchmark.

# Q3 Scientific Hypothesis

If domain-specific operational knowledge is distilled from declarative sources (repositories, papers, task-specific search) into verified, progressively-disclosed skills and supplied as operating context to an otherwise unchanged model-and-harness agent, then that agent will solve ML research and engineering tasks measurably better than the same agent without that knowledge — with gains that hold under a matched backbone, harness, and execution budget across benchmark types, and that grow with task difficulty, without requiring any change to the agent's control loop itself.

# Q4 Related Work and Key People

# Q5 Key Solution Idea

* **Operational knowledge as skills:** `K` is instantiated as skills `S = (SKILL.md [knowledge interface], references/ [knowledge substrate], scripts/ [execution interface])` following the Agent Skills specification, organized per source into a skill graph `G = (S, L)` where links encode routing/dependency/composition relations; an entry skill routes to component skills, and progressive disclosure means the agent's context at any moment holds only the opened branch.
* **Unified four-stage distillation pipeline:** `z -> scope -> Q -> ground -> X -> construct -> G~ -> verify -> (G, R)`, where `z` is the anchor, `Q` the capabilities the run decides to cover, `X` the gathered evidence, `G~` the candidate graph, and `(G, R)` the verified graph plus its construction record (evidence used, checks performed, unresolved gaps).
* **Two distillation forms sharing that pipeline:** *task-agnostic* (anchor = a source `c`, e.g. a repository or paper; built ahead of time, reusable by any future task) vs. *task-oriented* (anchor = a task `tau`; source material is actively searched to fill a capability gap, produced on demand but reusable for that task class).
* **DisCo's two modes over the same backbone+harness:** *creator mode* runs distillation and deposits accepted graphs into the AREX-Skill Library; *researcher mode* solves a task by loading only the relevant library branch as `K`. Costs are asymmetric: creator mode is paid once per source and amortized across all future tasks; researcher mode pays only for what a task actually opens.
* **AREX-Skill Library construction:** 5,353 skills across 1,000 repository graphs (GPT-5.5 + GPT-5.6-sol, xhigh reasoning, ~$40/repository), classified against an LLM-induced two-level taxonomy (20 areas, 178 capability families, built via an iterative locator-plus-judge convergence protocol over 100 repository batches, using only repository identifiers and summaries as model input — stars/URLs/existing categories excluded), yielding 2,209 exact area-to-family assignments (700 repositories in more than one family) and exposed through a generated router. Classification is kept separate from skill generation: the original repository, not the generated graph, is the primary evidence for taxonomy placement.
* **Verification before admission:** assertion-backed usability cases plus safe repository-native checks (examples, tests, CLI, tiny-fixtures, smoke scripts); a failure triggers localized repair and a rerun; static gates additionally check metadata, link integrity, self-containment, provenance, and local-path leakage.
* **Beyond the public repository collection:** 636 paper-derived skills distilled from 153 source papers (for PaperBench's 20 targets, excluding each target paper and its own code/artifacts), plus task-oriented graphs built specifically for MLE-bench (one per competition, descriptive-only, not executable), FrontierCS (one shared 9-node/42-link recovery-router graph across all 188 tasks), and PassNet (one benchmark-level graph) — in every case skill construction is completed and frozen before the downstream benchmark run, under a separate one-time construction budget.

# Q6 Experiment Design

Fixed GPT-5.5 backbone and Codex harness throughout; the only controlled variable is access to DisCo-distilled skills. Four independent, pre-existing benchmarks:

* **MLE-bench (full, 75 Kaggle competitions across Low/Medium/High tiers):** Any-Medal score rises from 31.11% (no skills) to 72.89% (+41.78 points, 134.3% relative), consistent across tiers (Low +43.94, Medium +37.72, High +48.89 points; High shows the largest relative jump, 13.33% -> 62.22%, 366.8% relative). Codex + AREX-Skill also beats the strongest public MLE-bench leaderboard entry (Famou-Agent 2.0 / FM Agent on Gemini-3-Pro-Preview, 64.44%) by +8.45 points overall, without a custom harness or control-loop change.
* **PaperBench (full, 20 papers, official replication grader):** average replication score rises from 29.45% to 39.59% (+10.14 points, 34.4% relative); improves 18 of 20 papers and degrades 2 (sample-specific-masks: 57.11 -> 52.04; stay-on-topic: 32.31 -> 27.79); largest relative gains concentrate on low-baseline tasks (rice: 7.94 -> 48.51, 6.1x; ftrl: 1.50 -> 17.17, 11.4x).
* **FrontierCS (Agent Track, 188 tasks, 5-hour/2-CPU/4GiB budget each):** Score rises from 70.63 to 77.14 (+6.51, 9.22% relative; 95% paired-bootstrap CI [3.41, 9.83]); improves 74 tasks, leaves 66 unchanged; per-task gain is essentially uncorrelated with extra token/step/tool-call usage (Spearman rho of 0.006/0.014/0.015), and Codex+AREX-Skill Pareto-dominates Claude Code (both an Opus 4.8 and a Qwen3.7 Max configuration) on score, tokens, steps, and tool calls simultaneously, using 3.1-3.3x fewer tokens.
* **PassNet (200 samples, graph-compiler pass generation, NVIDIA A100):** AS Score rises from 1.343 to 1.5313 (+14.0% relative), surpassing TorchInductor's 1.419; failed samples drop from 14 to 5 (-64.3%); Correctness rises from 81.35% to 90.76%.

Skill-construction budgets are always kept separate from and prior to the matched execution budget in every setting (e.g., MLE-bench uses <=24 GPU-hours for exploration/skill-construction and a separate <=24 GPU-hours for the scored run).

* No new benchmark is introduced; all four evaluation benchmarks (MLE-bench, PaperBench, FrontierCS, PassNet) are pre-existing, independently authored third-party benchmarks, and public-leaderboard baseline numbers (MLE-bench, FrontierCS) are copied from those leaderboards rather than re-run by the authors.

# Q8 Evidence Quality

The core ablation is well controlled: backbone, harness, and running budget are held fixed and only skill access varies, across four independent, pre-existing, third-party benchmarks rather than one in-house benchmark — a stronger design than most entries in this repository's [Agent skill libraries](../topics/agent-skill-libraries.md) topic. Per-task breakdowns are reported rather than only aggregates (skills help on 74/188 FrontierCS tasks and 18/20 PaperBench papers, and the paper explicitly reports and hypothesizes a cause for the 2 PaperBench regressions — a possible retrieval-precision trade-off where a retrieved skill pulls the agent away from an idiosyncratic approach it might otherwise have found unaided). The FrontierCS stratified analysis (near-zero Spearman correlation between per-task gain and extra token/step/tool-call usage) is a genuine check that the aggregate gain is not just resource-scaling in disguise. Caveats: PaperBench's source-paper selection ("up to 10 representative papers from related work") and MLE-bench's per-task web-search-based skill construction both involve model judgment calls whose consistency is not independently audited in the retrieved text; the skill-construction cost (~$40/repository at xhigh reasoning effort, times 1,000 repositories, plus per-task construction budgets for the other three benchmarks) is substantial, and the paper does not report how many downstream tasks are needed to amortize it, so the net compute/cost trade-off of building the library versus not building it is not directly established; and the MLE-bench/FrontierCS baseline comparison rows are taken from public leaderboards rather than run by the authors under identical hardware, so those particular cross-system comparisons (not the central with/without-skills ablation itself) carry the usual leaderboard-comparability caveat. **Fidelity note:** unlike two other papers added to this wiki around the same date, the HF CLI's `papers read` command returned this paper's full body text successfully; the figures above are read directly from that retrieval, cross-checked against the tables reproduced in the main text.

# Q9 Contributions

1. Formalizes "operational knowledge" `K` as a third, explicit component of an autonomous research agent (`A_res = (M_theta, H, K)`) distinct from the model backbone and the harness, and argues it is the layer neither currently supplies.
2. Presents DisCo, a dual-mode (creator/researcher) skill-powered research agent built around one unified four-stage distillation pipeline (scope/ground/construct/verify) that spans task-agnostic (source-anchored) and task-oriented (task-anchored) skill production, with every candidate skill graph verified before admission and gaps recorded rather than hidden.
3. Builds the AREX-Skill Library at a scale distinct from prior skill-library work in this repository: 5,000+ verified skills from 1,000 ML repositories organized by an LLM-induced 20-area/178-family taxonomy and generated router, plus 636 paper-derived skills from 153 papers.
4. Demonstrates, via a matched with/without-skills ablation holding backbone, harness, and budget fixed, consistent gains from adding distilled operating context alone across four independent benchmarks (+134.3% MLE-bench, +34.4% PaperBench, +9.2% FrontierCS, +14.0% PassNet), with the largest relative gains concentrated on harder or lower-baseline tasks.

# Q10 Next Steps

* The paper does not evaluate combining distilled skills with a different or stronger harness than Codex, so how the reported gain composes with concurrent harness-engineering advances remains untested.
* The two observed PaperBench regressions are attributed to a hypothesized retrieval-precision trade-off but not directly diagnosed; the paper proposes better routing or an explicit fallback to unguided reasoning as future work without implementing or evaluating either.
* The paper does not report how many downstream tasks are needed to amortize the one-time, non-trivial skill-construction cost (~$40/repository at scale, plus per-benchmark construction budgets), leaving the net cost-effectiveness of building a library like AREX-Skill versus not building one an open empirical question.
* **Research-OS fit:** this is the largest-scale entry in this repository's [Agent skill libraries](../topics/agent-skill-libraries.md) topic, and the first to isolate skill contribution via a controlled with/without ablation on four independent, pre-existing third-party benchmarks rather than a custom in-house one. It is plausibly complementary rather than competing with [SkillOpt](2605.23904.md)'s claim of best-or-tied results on 52 of 52 (model, benchmark, harness) cells: SkillOpt optimizes one compact skill document per domain from execution trajectories via a text-space training loop, while DisCo distills many skills per source ahead of time from declarative artifacts — a natural follow-up experiment is seeding a SkillOpt-style trajectory-optimization loop from an AREX-Skill-constructed starting skill rather than treating the two as alternatives.
