# Q1 Problem Definition

* **Input (X):** a set of recorded interaction traces $\mathcal{D}_{\text{build}}=\{h^{(i)}\}$ from an environment whose code, data, and hidden state are unavailable (a terminal, a coding workspace, an Android app, a website, an enterprise tool API, a text game), plus, at simulation time, a new task agent's action $a_t$ and the simulated history $\hat h_t$. The language model's weights stay fixed.
* **Output (Y):** a simulated next observation $\hat o_{t+1} \sim Q_\theta(\cdot \mid \hat h_t, a_t, \mathcal{D}_{\text{build}})$ that matches what the real environment would return, and, across turns, simulated dynamics that preserve the consequences of earlier actions (deleting `report.txt` should make a later `cat report.txt` fail even though the delete printed nothing).
* **Core question:** can one agent serve as the environment for another, and can existing traces alone give that agent what it needs to know?

# Q2 Problem Novelty

Partly new. Language world models (LWMs) that predict the next observation from a description and history already exist and are benchmarked (AgentWorldBench; Li et al., 2026), and retrieval or memory has been added to them (RAWM retrieves past transitions; WorldEvolver adds episodic memories and induced rules but keeps querying the real environment to update them). Separately, trajectories are distilled into skills or workflows for the *task* agent (Agent Workflow Memory, Trace2Skill, SkillGen, TraceCompiler), and Terminal-Universe rebuilds *executable* terminal workspaces from trajectories. Trace2Env claims to be the first to (a) work trace-only, with the real environment unavailable during simulation, (b) reconstruct a non-executable, provenance-linked behavioral specification of the environment rather than an executable replica or task-agent skills, and (c) operate it with an agent that inspects knowledge selectively and commits state through a validating harness.

# Q3 Scientific Hypothesis

1. **Structure beats raw context.** If trace evidence is reorganized into schemas, grounded evidence, and induced rules, next-observation fidelity will exceed both direct prompting and prompting with retrieved raw transitions.
2. **Agency adds to knowledge.** If a world-model agent inspects that knowledge adaptively, keeps explicit episode state and memory, and commits only validated transitions, it will beat the same knowledge given as a static prompt.
3. **Faithful simulation shows up in transfer, not in simulated success.** A world model that preserves earlier consequences will induce task-agent action sequences that still succeed when replayed in the real environment, even if fewer tasks succeed inside the simulation.

# Q4 Related Work and Key People

* **Language world models.** Li et al. (2026) on predictive fidelity and downstream utility, Zuo et al. (2026) scaling LWMs across agentic environments (AgentWorldBench), simulated transitions for planning and policy learning, and objectives that value decision-relevant fidelity over literal accuracy.
* **Experience-augmented world models.** RAWM (retrieved transitions as evidence) and WorldEvolver (episodic memories plus semantic rules from prediction errors, with continued access to the real environment).
* **Trace-grounded reconstruction.** [Agent Workflow Memory](../concepts/agent-workflow-memory.md), Trace2Skill, Memory-Skill Co-Evolution, SkillGen, and TraceCompiler distill trajectories into artifacts for the acting agent; Terminal-Universe reconstructs executable terminal workspaces from trajectories to produce real tool feedback and training tasks.
* **Environments used.** AgentWorldBench, EnvScaler, [ALFWorld](../concepts/alfworld.md), and [ScienceWorld](../concepts/scienceworld.md).
* **Key people.** Quanyu Long and colleagues at Nanyang Technological University (last author Wenya Wang), with Xiao Chen at The Hong Kong Polytechnic University. Likely critics: the AgentWorldBench and Word2World authors, and environment-synthesis groups (EnvScaler, Terminal-Universe) who argue that executable reconstruction gives verifiable state that a language simulator cannot.

# Q5 Key Solution Idea

* **Worldbook (offline, built once).** A construction model (gpt-5.6-sol) aligns each recorded action with its result, extracts observed facts, candidate state effects, outcomes, and uncertainty, keeps the original observation, and withholds effects with ambiguous attribution. It then induces a shared vocabulary of actions and state fields (*schemas*), keeps recorded transitions and demonstrations (*grounded evidence*), proposes rules and reviews them against supporting and contrasting cases (a success-failure contrast suggests a missing precondition; a counterexample narrows a rule or leaves it tentative), and stores *provenance* links from every artifact to the supporting traces and turns. The package is immutable during simulation.
* **Episode workspace.** $\mathcal{W}_t = (K_\mathcal{E}, \hat s_t, M_t)$: the fixed worldbook says how the environment behaves, the mutable episode state says what is currently true, and the episodic memory says what happened. A missing state entry means "unknown", not "absent", and cross-episode evidence never establishes what exists in the current episode.
* **Agentic step with two gates.** For each action, the world-model agent retrieves worldbook entries and an *applicability gate* labels each one supporting, uncertain, or format-only (useful for response layout but not for facts, since it came from another episode). The agent then proposes a transition $q_t = (\Delta_t, \tilde o_{t+1})$: an ordered list of declarative updates to declared state variables plus an observation. A *validation gate* in the shared harness applies the effects to a copy of the state, checks them against schemas, rule support, and constraints, and only then commits state and returns the observation.

# Q6 Experiment Design

* **Single-step fidelity (seven environments).** AgentWorldBench Terminal (354 records from 76 trajectories), SWE (472/99), Android (200/92), and Web (200/118), plus EnvScaler Food (150/15), Shopping (84/15), and Benefits (45/12). The official gpt-5.2 judge scores Format, Factuality, Consistency, Realism, and Quality on 1-5, rescaled to 0-100 and averaged; paired differences use a trajectory-level bootstrap (10,000 resamples).
* **Construction data.** Terminal: 20 trajectories of a gpt-5.6-sol [Terminus 2](../concepts/terminus-2.md) agent on [Terminal-Bench](../concepts/terminal-bench.md) 2.0 (334 turns), excluding strong overlaps with evaluation trajectories. Web: 50 gpt-5.6-sol trajectories on [WebArena](../concepts/webarena.md). Android and SWE: task-grouped five-fold cross-fitting over the benchmark's own trajectories. EnvScaler: 16, 3, and 15 reserved successful trajectories.
* **Multi-turn consistency.** [ALFWorld](../concepts/alfworld.md) (100 held-out Word2World test tasks; worldbook from 40 successful trajectories, 836 turns, with failed attempts, hidden state, and reward labels excluded) and SciWorld ([ScienceWorld](../concepts/scienceworld.md); 40 tasks; worldbook from 30 Measurement gold-path trajectories). A task agent solves each task in the real environment (Real) and in the world model (WM); its WM action sequence is replayed in the real environment (W2R); the consistency ratio is CR = W2R / Real.
* **Baselines.** Direct Prompting (official AgentWorldBench prompt, one call), Trace RAG Prompting (five lexically retrieved raw turns), Worldbook Prompting (the worldbook as static context with retrieved demonstrations and evidence), and Harness only (Trace2Env's runtime without any worldbook knowledge or persistent state). The multi-turn study compares only Direct Prompting with Trace2Env.
* **Backbones.** gpt-5.6-sol and deepseek-v4.1-flash as world models, both using the same gpt-5.6-sol-built worldbooks, which tests transfer of a worldbook across operating models.
* **Ablations.** Worldbook components and number of construction traces on Terminal; adaptive loop and state tracking; cost and latency per record; gains split by overlap between evaluation and construction tasks.

# Q8 Evidence Quality

* **Supported.**
  * *Consistent single-step gains over direct prompting.* Average judge score 75.94 against 69.51 (gpt-5.6-sol, +6.43) and 75.75 against 68.71 (deepseek-v4.1-flash, +7.04); best in 11 of 14 environment-backbone pairs and never below Direct Prompting. On AgentWorldBench the trajectory-clustered intervals for the gain over Direct Prompting exclude zero in every environment for both backbones, and Factuality and Consistency improve in every pair.
  * *Large multi-turn transfer gap.* On ALFWorld, Direct Prompting "succeeds" in 97% of simulated tasks but only 3% of its action sequences succeed in the real environment (CR 0.032); Trace2Env's are 88% and 85% (CR 0.914), with 93% real success. On SciWorld: 92.5% and 45% (CR 0.529) against 87.5% and 60% (CR 0.706). The case study traces one cause: Direct Prompting accepts an unsupported `put` command as a successful placement and continues coherently from a state the real environment never reached, while Trace2Env predicts "Nothing happens", keeps the item in inventory, and lets the agent recover with the valid `move` command.
  * *Evidence carries the worldbook.* On Terminal, adding grounded evidence to a schema-only worldbook gives +2.45 ± 0.89, adding induced abstractions alone gives -1.12 ± 0.90, and abstractions on top of evidence add +0.69 ± 0.63; evidence on top of abstractions adds +4.26 ± 1.02.
  * *More traces help.* Rebuilding the Terminal worldbook from 20 to 36 traces raises the score from 64.89 to 66.42, still rising at the largest available set; construction cost grows roughly with trace volume.
  * *Cost is controllable.* On Terminal, full Trace2Env costs about $0.187 and 38.1 s per record with 5.0 model calls, against about $0.04 and 26.0 s for Direct Prompting; removing the adaptive loop keeps about 80% of the gain at 29% of the cost (63.09, $0.054).
* **Weaker or narrower than the headline.**
  * *The agentic runtime adds little over a static worldbook in single-step prediction.* Trace2Env beats Worldbook Prompting by 1.59 points (gpt) and 0.89 (deepseek) on average, and loses to it on Terminal with deepseek (64.12 against 65.24), on Android with gpt (65.10 against 65.53, and against Trace RAG's 66.50), and on Shopping with gpt (85.36 against 85.89). Most of the gain over direct prompting comes from the reconstructed knowledge.
  * *The multi-turn result has only one baseline.* ALFWorld and SciWorld compare Trace2Env with Direct Prompting only, so the CR gain cannot be split between worldbook content, retrieved raw traces, and the agentic runtime. The 3% W2R for Direct Prompting may largely reflect one recurring command-format convention (`put` against `move`) that any trace-informed baseline would pick up (a reader inference from the case study, not a measured breakdown).
  * *Unseen-task gains are smaller and not uniform.* On Terminal records whose tasks are not in the construction set (312 of 354), the gain over Harness only is +3.69 [1.71, 5.63] with gpt but +0.61 [-1.78, 2.96] with deepseek, which is not distinguishable from zero; records whose tasks were in construction gain +17.86 and +12.86. On Android apps that appear in no other fold, the gain over Direct Prompting is -0.59 with gpt. The main text's statement that gains "remain significant" on unseen Terminal records holds only for gpt, as the appendix's own wording ("smaller with DeepSeek") concedes.
  * *One judge from the same model family.* Every single-step score comes from the official gpt-5.2 judge, while the worldbooks are built by gpt-5.6-sol and one of the two world models is gpt-5.6-sol; no human or second-family check of the judge is reported in the sections read.
  * *Run-to-run variation is visible but unreported.* The same configuration appears as 65.42 in the main table and 64.89 in the ablation and cost tables for Terminal with gpt (Harness only 60.06 and 60.14), so differences of about half a point are within the spread between reported runs.
  * *Fidelity is bounded by the traces,* as the authors state: behavior never observed in construction traces can only be inferred, and the Terminal worldbook was built from 20 trajectories.

# Q9 Contributions

* Frames environment simulation as an agentic task ("agentic language world modeling"): a world-model agent serves as the environment for a task agent.
* Trace2Env: a learning-free pipeline that turns traces into a provenance-linked worldbook, a workspace that separates reusable knowledge from episode state and memory, and a propose-then-validate transition protocol with applicability and validation gates.
* Evidence on nine environments that structured trace knowledge raises single-step fidelity over direct and retrieval prompting, and that preserving state consequences sharply improves real-environment transfer of simulated interaction.
* Component, scaling, cost, and construction-overlap analyses showing that grounded evidence matters more than induced rules and that a cheaper non-adaptive mode keeps most of the gain.

# Q10 Next Steps

* **From the authors.** Stronger active inspection and inference over the worldbook; reconstruction that goes beyond observed behavior; use of agentic simulated environments for task-agent training and evaluation.
* **Complete the multi-turn comparison (reader suggestion).** Add Trace RAG Prompting, Worldbook Prompting, and Harness only to the ALFWorld and SciWorld runs, and break down where Direct Prompting's simulated successes fail on replay, to show how much of CR comes from the runtime rather than from trace content.
* **Train in the simulator (reader suggestion).** The paper argues W2R is the right criterion; the next test is whether a task agent trained or tuned against a Trace2Env replica improves in the real environment, as [CompoWorld](2609.33665.md) checks for environments partly simulated by an LLM world model.
* **Rules linked to evidence for task agents (reader note).** Trace2Env's ablation that evidence matters more than induced rules, and that rules help only on top of evidence, agrees with [Learn2Play Bench](2610.08215.md)'s finding that raw histories can beat distilled rules; both suggest keeping provenance from any learned rule back to the episodes that support it.
