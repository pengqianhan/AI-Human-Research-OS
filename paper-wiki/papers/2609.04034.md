# Q1 Problem Definition

* **Input (X):** a design brief specifying required content, deliverable type and size, and visual register (e.g., an event poster, infographic, marketing material, or long-text layout).
* **Output (Y):** an editable design artifact delivered as native DOM (HTML/CSS/SVG) with fully decoupled text, asset, and background layers plus real (non-rasterized, directly editable) text, produced by a Coding Agent — a VLM "creative brain" (Codex driven by GPT-5.6 Sol in the reported system) that calls an image generation model (GPT Image 2) on demand as a "visual world simulator" — together with an "Agent Design Replay" trace recording the full creative and technical trajectory.
* **Core problem:** the two existing paradigms for automated visual design are each one-sided. Pure diffusion image generation (e.g., GPT-Image-2, Nano-Banana) produces visually rich results but yields flattened bitmaps with error-prone text and deeply entangled layers, precluding any layer-wise post-editing. Pure code generation via Coding Agents (writing HTML/SVG/CSS directly) gives precise layout control and naturally decoupled, editable layers, but current code LLMs lack two-dimensional spatial sense and aesthetic intuition, and are poor at hand-drawing complex visual assets (cinematic backgrounds, 3D hero visuals, illustrations), typically falling back to plain color blocks, gradients, or emoji as placeholders.
* **Scope:** single-page design artifacts — posters, infographics, marketing materials, and long-text layouts — validated through case studies rather than a held-out quantitative benchmark; multi-page decks and full websites are explicitly out of scope for the reported validation.

# Q2 Problem Novelty

Visual code generation (Design2Code, WebSight, Web2Code, LaTCoder, UICopilot, DesignBench and related layout-fidelity benchmarks/methods) and image-based design generation (COLE, OpenCOLE, Graphist, PosterCraft, TextDiffuser) are each established, separate lines the paper explicitly builds on and distinguishes itself from. Agentic, reasoning-driven design generation is also established (Visual ChatGPT, GenArtist, Idea2Img, RPG, GoT, T2I-R1, Mind-Brush), including the paper's stated direct predecessor, GenClaw, which uses code as a controllable intermediate canvas in a code→image direction. This paper's stated novelty is inverting that direction into image→code: using an image generation model as an up-front visual simulator and a layer-by-layer intermediate-asset generator, while treating structured code — not a raster image — as the final engineering deliverable, under a VLM-as-creative-brain / image-model-as-visual-simulator division of labor explicitly inspired by World Action Models (WAM).

# Q3 Scientific Hypothesis

If a VLM-led Coding Agent (a) first calls an image generation model for an "imagined visual" to establish a global aesthetic and compositional prior before any code is written, (b) generates isolated, layer-by-layer visual assets separately from that imagined visual (never reusing its pixels), (c) writes native, viewport-independent HTML/CSS combining those assets with real text under an explicit per-element layer tagging scheme, and (d) iteratively self-heals the result against both deterministic layout checks and VLM-based rendered-screenshot visual review; then the delivered artifact should achieve both refined, non-templated aesthetics — closing the gap pure code generation leaves — and full production-grade layer/text editability — closing the gap pure diffusion image generation leaves — while an Agent Design Replay trace makes the entire creative-to-technical trajectory inspectable and reproducible rather than an opaque final output.

# Q5 Key Solution Idea

1. **Two-role division of labor (World-Action-Model-inspired).** A VLM acts as the "creative brain," coordinating requirement understanding, design planning, code construction, and result judgment; an image generation model acts as an on-demand "visual world simulator," quickly turning abstract ideas into concrete visual references — never the final deliverable.
2. **"Imagine first, then act."** Before any code is written, the agent calls the image model for an *imagined visual* — not a structural sketch but a picture of what the finished piece could look like — establishing composition, lighting, and color priors. This step is treated as part of the design plan itself (the plan is only settled once there is something to look at) and as the cheapest point for a user to redirect the design, before any code exists.
3. **Visual simulation as a prior-extraction step.** The VLM visually parses the imagined visual for color tone, compositional distribution, and style, without needing to reproduce it pixel-for-pixel; the paper frames this as functionally analogous to rendering feedback — one shows what the code currently is, the other shows what the design could be, and both hand the agent pixels to judge.
4. **Structural coding with on-demand, layer-by-layer asset generation.** The agent determines canvas topology and image/text spatial distribution from the visual prior, then calls the image model separately for clean standalone local assets (a text-free background, an isolated subject) rather than cropping them from the imagined visual, avoiding layer entanglement and pixel contamination. Assets are produced either with a direct alpha channel (where supported) or via a green-screen-plus-matting-script route. The agent then writes native HTML/CSS as a fixed-pixel-size canvas — layout is explicitly not allowed to depend on the viewport, so drag coordinates stay meaningful — tagging every user-movable element as its own layer.
5. **Dual verification and iterative visual self-healing.** A headless-browser pass runs deterministic layout-rule checks (element overflow, failed resource loads, malformed DOM); a VLM reviewer then compares an actual rendered screenshot against the original design intent for visual balance, alignment, and text readability. When a flaw is found, the agent generates a targeted local patch rather than regenerating the whole page, typically converging within one or two reflection-repair rounds.
6. **Editable delivery plus Agent Design Replay.** The final artifact is native DOM with decoupled text/asset/background layers (double-click-to-edit text, drag-and-scale assets, independent per-layer export). In parallel, the system serializes the full decision trajectory — requirement decomposition, visual imagination, asset prompts, code evolution, and reflective repair — into an Agent Design Replay, intended to move the process away from an uninterpretable black box and give users a basis for tracing intent and intervening manually.

# Q6 Experiment Design

Validation is case-study-based rather than a held-out quantitative benchmark, organized along three angles: (1) a controlled comparison against pure diffusion (GPT-image-2) and pure code generation (Codex on GPT-5.6 Sol) under an identical brief, annotating each baseline's specific failure mode (disordered text for diffusion; large blank areas and chaotic layout for pure code) against Editable Visual Design's combination of clean typography and separable layers; (2) a diverse-scenario showcase spanning event posters, infographics, marketing materials, and long-text layouts, checking that type-scale/grid alignment holds in information-dense cases and multi-layer spatial organization holds in visually-driven cases; (3) a real-case walkthrough of the Agent Design Replay trajectory on two artifacts — an information-dense red panda field-guide infographic (120 editable layers across 13 groups, where review caught and repaired real layout defects) and a visually-driven travel poster (6 layers in 1 group, where review passed with no changes) — reported across three phases (understand-and-plan, generate-and-build, review-and-fix) with per-step timestamps.

# Q7 Datasets and Code

No dataset, benchmark, or public code release is described in the retrieved text; validation rests entirely on qualitative case studies rather than a released, reproducible artifact set or numeric scoring protocol. The "creative brain" (Codex on GPT-5.6 Sol) and the "visual world simulator" (GPT Image 2) are both pre-existing third-party models used as components, not released by this paper.

# Q8 Evidence Quality

This note is built from the arXiv HTML full text (Abstract through Related Work; the references list was not needed to support any claim in this note). The paper is unusually explicit about the limits of its own case-study evidence: it states directly that "aesthetic quality is hard to evaluate in the way generation quality usually is," that there is no ground truth for what a poster should look like, and that it therefore "report[s] cases rather than scores," with its visual-quality check being "a VLM judgment that stands in for a designer's eye rather than measuring anything" (Section 5, Limitations). This note treats every aesthetic or quality claim in the paper as qualitative case evidence rather than as a benchmarked result, since the paper itself establishes none. Editability claims are similarly asserted (layer counts, DOM structure) rather than measured against any usability criterion — the paper states outright that "what matters is whether a designer who opens the file can get it to do what they want, and that does not reduce to a number." The paper also names its own binding constraints candidly: delivered quality is bounded by whichever underlying model is weaker (the coding agent's layout code, or — more often, per the paper — the image model's compositional sense, which can return something "technically clean but compositionally ordinary"); the asset-generation route additionally requires a subject cleanly separable from its background; and only single-page artifacts were tested, with the paper stating explicitly that a multi-page deck or full website "has to stay consistent across pages" in ways not evaluated here.

# Q9 Contributions

1. Editable Visual Design, a Coding-Agent-driven paradigm that splits visual design generation into a VLM "creative brain" and an on-demand image-generation "visual world simulator," inverting its direct predecessor GenClaw's code→image direction into image→code.
2. A five-step workflow — understanding and planning, visual simulation, structural coding with on-demand layer-by-layer standalone asset generation, dual (deterministic plus VLM) verification and self-healing, and editable delivery — that produces artifacts with decoupled, independently editable text/asset/background layers and real, non-rasterized text.
3. Agent Design Replay, a serialized trace of the full creative-to-technical trajectory (requirement decomposition, visual imagination, asset prompts, code evolution, reflective repair), demonstrated on case studies across posters, infographics, marketing materials, and long-text layouts, intended to make the generation process auditable and human-interpretable rather than an opaque final output.

# Q10 Next Steps

The paper's Discussion section names several forward directions rather than concrete planned experiments: extending "Generation for Understanding" from tasks with strong symbolic/logical structure (geometric auxiliary lines, spatial mazes) — where the authors argue generative feedback has so far yielded limited gains — toward using generation as a source of visual imagination and aesthetic priors for compositional decision-making, on the analogy that rigorous math is hard to do "inside a dream" but dreams are a source of visual inspiration; generalizing the division of labor traced through GenClaw and Mind-Brush, treating a generation model as a reusable external simulator and local-asset renderer callable by any general-reasoning VLM; pushing further from "bitmap output" toward "structured delivery" as a design-generation direction generally; and exploring more natural human-AI design interaction — for example, an agent operating a mouse through a GUI to lay out and draw directly on a canvas — building on Agent Design Replay's process-visibility goal. The paper's own named limitations for future work are scaling consistency (type scale, palette, visual thread) across multi-page decks or full websites, which remain untested beyond single pages; the ceiling imposed by whichever underlying model (coding agent or image model) is weaker, most often reported as the image model returning a compositionally ordinary reference; and the absence of any quantitative aesthetic or editability metric, both currently assessed only through case studies and a VLM judgment standing in for a designer's eye.

This note flags one open question beyond the paper's own: the verification loop's VLM reviewer judges the rendered page against "the original design intent," but that intent is itself established earlier in the same pipeline by the same VLM's own imagined-visual and planning steps — the paper does not report whether this self-referential review loop (the same model class judging its own earlier design decisions rather than an independent design brief) was checked against an external human-authored specification, which would bear on how much the self-healing step is actually correcting deviations from the brief versus reinforcing the VLM's own initial aesthetic choices.
