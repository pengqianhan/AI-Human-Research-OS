# Q1 Problem Definition

* **Input (X):** a user's multi-session dialogue history and a current request q, with a frozen answer model (the personal agent; Qwen3-8B or GPT-4o-mini).
* **Output (Y):** a response that uses the user's memories correctly: current rather than superseded preferences, memories applied only within their scope, unresolved conflicts surfaced, and objective evidence not overridden by the user's beliefs. The system's intermediate outputs are a memory store (facts plus *Relational States*) and a per-request *Reasoning State*.
* **Constraints:** the answer model stays frozen, original facts are never overwritten, and memory construction runs offline with one shared LLM (DeepSeek-V4-Flash) for every compared system.

# Q2 Problem Novelty

Partly new. Memory systems that extract, link, and update records are established (MemGPT, MemoryBank, [Mem0](2504.19413.md), A-MEM, LightMem, SimpleMem, Supermemory, PGMem, and [Zep](2501.13956.md)'s temporal knowledge graph). Benchmarks for misuse of retrieved memory are recent: MemSyco-Bench (by overlapping authors) and MemTrapBench. The paper's claim is that the gap is *state*: a fact's current validity and its relation to other facts, and, per request, which facts apply and with what priority. The first part is close to typed temporal graphs such as Zep's; the second, a learned per-request usage policy for a frozen agent, is the newer piece, alongside post-retrieval methods such as [MemAdapter](2610.05162.md) from the same group, which this paper does not cite.

# Q3 Scientific Hypothesis

If memory keeps each fact together with explicit update and conflict relations, and retrieval follows those relations, then the agent receives complete evidence more often. If a separate policy, rewarded by how much its guidance improves a frozen agent's answer over no guidance, writes per-request rules about which memories apply and how, then the agent uses complete evidence correctly more often than with fixed self-reflection or its own guidance. Both effects should be largest on tasks about preference updates, scope, and conflicts with evidence.

# Q4 Related Work and Key People

* **Long-term memory systems.** MemGPT (storage tiers), MemoryBank (summaries with an Ebbinghaus-style retention curve), [Mem0](2504.19413.md) (atomic fact extraction with add, update, and delete decisions), A-MEM (linked Zettelkasten notes), LightMem (staged compression with sleep-time updates), SimpleMem, Supermemory (a temporal memory graph), PGMem (persona signals linked to supporting events), and [Zep](2501.13956.md) (cited for temporal structure).
* **Personalization and user modeling.** LaMP, HELLO, Reflective Memory Management, and personalization for web actions and agent training.
* **Reliability of memory use.** [MemSyco-Bench](../concepts/memsyco-bench.md), [MemTrapBench](../concepts/memtrapbench.md), PersistBench-style over-personalization studies, and inference-time fixes compared in Appendix C.1: Self-Recheck (filtering retrieved memories), MemGate (query-conditioned admission), and Dynamic Partition (grouping memories by domain).
* **Key people.** Zhishang Xiang and Yunbo Tang (equal contribution), Jinsong Su and colleagues at Xiamen University, and Qinggang Zhang at Jilin University (corresponding authors), with co-authors at NTU, UBC, and Waterloo. The same group built MemSyco-Bench and MemAdapter. Likely critics: the MemTrapBench authors (ZJUNLP), whose AdaptiveMem is a simpler inference-time mitigation not compared here, and memory-system authors whose baselines retrieve almost nothing in this setup (see Q8).

# Q5 Key Solution Idea

**Facts and Relational States.** An extractor (DeepSeek-V4-Flash) reads each new session with the relevant branch of the existing ontology and returns, in one JSON object, up to 32 atomic memories (type preference, fact, belief, experience, or constraint; scope global, domain, task, or situation; time, source turn, and a verbatim evidence quote), concept edits limited to CREATE, MERGE, and SPLIT, and relations. A newer state of the same kind gets a SUPERSEDES edge to the older one, which is marked superseded but kept; an unresolved contradiction gets CONFLICTS_WITH and both ends are marked disputed. Quoted material is stored as world facts even when it contradicts the user. Each session's update is committed only after validation (grounded facts, one parent per concept, acyclic update relations). A fact's Relational State is its current validity and scope plus its concept attachment and relations.

**Relation-aware retrieval.** Embedding search (bge-m3) picks K = 10 seed facts; traversal then adds every fact connected to a seed through stored relations, in both directions, with no filtering afterwards.

**Reasoning State from a trained policy.** A Qwen3-4B-Instruct-2507 policy reads the request, the retrieved facts, and their Relational States, and writes 2-4 imperative bullets (at most 80 words) that say which memories apply, what role each plays (primary evidence, preference, constraint, condition, historical context, or supporting context), and which controls when they conflict. It is told not to answer the question. The bullets go to the answer model with the evidence.

**Reward.** For each training instance the policy samples G = 8 candidate states. A frozen Qwen3-8B answers with each, and the reward is its score with that state minus its score with the same evidence and no state, with penalties for format violations and for revealing the reference answer. GRPO trains the policy (learning rate 1e-6, KL coefficient 0.001, clipping 0.2 and 0.28, rollout batch 512). Training data is about 60K synthetic instances built from FEVER and SciFact (objective questions paired with conflicting user beliefs, identities, or claimed expertise) and PersonaMem (current, historical, and updated preferences), with distractor memories added.

# Q6 Experiment Design

* **Benchmarks.** [MemSyco-Bench](../concepts/memsyco-bench.md) (When to Use memory: accuracy and sycophancy rate; How to Use memory: accuracy and correct use), [MemTrapBench](../concepts/memtrapbench.md) (Safety, Cognitive Bias, Task Boundary, Trauma; judge scores on a percentage scale), [LoCoMo](../concepts/locomo.md) including adversarial questions, and LoCoMo-Refined (corrected annotations and a stricter judge), with LLM-judge score and token F1.
* **Baselines.** NaiveRAG, MemGPT, MemoryBank, Mem0, A-MEM, LightMem, Supermemory, SimpleMem, and PGMem, all sharing the answer model, the memory-construction LLM, bge-m3, and top-10 retrieval, under Qwen3-8B and GPT-4o-mini at temperature 0. DeepSeek-V4-Flash is also the judge where a benchmark needs one ([LLM-as-a-Judge](../concepts/llm-as-a-judge.md)).
* **Analyses.** Complete retrieval rate and accuracy on questions with complete evidence (Acc@complete; Figure 5 and Table 4); transfer of the policy to six other memory systems (Figure 6); ablations removing Relational States, Reasoning States, or RL training (Table 2); a comparison with Self-Recheck, MemGate, and Dynamic Partition on top of Mem0 (Table 3); the policy against the answer model's own guidance (Self-Guide, Figure 9); context length and hit rate (Figure 11); and complete-evidence questions from MemSyco-Bench's Valid Memory Selection task (Figure 13).

# Q8 Evidence Quality

* **Supported.**
  * *Large gains on memory-use tasks.* MemSyco-Bench average accuracy is 57.6 with Qwen3-8B and 58.9 with GPT-4o-mini, 12.2 and 5.9 points above the best baseline, with the lowest sycophancy rate under both answer models (38.0 and 31.9). How-to-Use accuracy rises most (72.4 against at best 63.7 with Qwen3-8B).
  * *The trained policy is what helps.* In the Qwen3-8B ablation the overall score is 59.9 with everything, 53.0 without Reasoning States, and 53.2 with Reasoning States from the untrained policy, so the policy's guidance only helps after RL. Removing Relational States costs 8.9 points on MemSyco-Bench and 6.4 on MemTrapBench but only 0.3 on LoCoMo.
  * *Use, not just retrieval.* On LoCoMo-Refined, retrieval completeness is only slightly better than the best baselines (complete retrieval 0.680 against 0.669 for MemoryBank), with a shorter context (565 tokens against 816), while Acc@complete is 70.8% on LoCoMo-Refined and 68.5% on MemSyco-Bench, 11.5 and 31.2 points above the best baselines. On Valid Memory Selection with complete evidence, a Reasoning State lifts accuracy from 75.4% with self-reflection to 86.7%.
  * *Learned guidance beats self-guidance on memory-use tasks.* Against the answer model's own guidance, the policy adds 8.2 and 6.1 MemSyco-Bench points and 16.8 and 11.0 MemTrapBench points, but only about 1 point on LoCoMo and minus 1.4 on LoCoMo-Refined with GPT-4o-mini.
* **Weaker or narrower than the headline.**
  * *"Consistent improvements" holds for averages, not cells.* With Qwen3-8B, SimpleMem (79.9) and LightMem (79.7) beat EvoMemState on the MemTrapBench average (79.1), SimpleMem has higher LoCoMo F1 (46.4 against 41.6), and EvoMemState's Cognitive Bias score (62.3) is the lowest of all ten systems; with GPT-4o-mini SimpleMem is ahead on both LoCoMo metrics (reader reading of Table 1).
  * *Training data resembles the main benchmark.* The 60K training instances pair objective evidence with conflicting user beliefs and track preference updates, which is the design of MemSyco-Bench, a benchmark by overlapping authors. The reward model is the same Qwen3-8B used as an answer model in evaluation. The largest gains are on the two memory-use benchmarks and the smallest on LoCoMo, which fits in-distribution learning as well as it fits the paper's account (reader inference).
  * *The policy may need EvoMemState's own annotations.* Figure 6 reports gains of 0.2 to 4.9 points when the policy is added to other memory systems, but on complete-evidence Valid Memory Selection questions replacing self-reflection with a Reasoning State changes the baselines by +0.4 to -1.6 points while EvoMemState gains 11.3. The policy was trained on inputs that carry validity, scope, and relation fields, which other systems' records lack (reader inference).
  * *Some baselines barely retrieve.* On LoCoMo-Refined, Supermemory's hit rate is 0.006, Mem0's 0.110, and LightMem's 0.166, against 0.684 for NaiveRAG, and their LoCoMo-Refined judge scores are 16.6 to 25.7 with Qwen3-8B. Mem0's own paper reports strong LoCoMo results ([Mem0 note](2504.19413.md)), so these numbers look more like pipeline or configuration failures than properties of the methods, and they lower the bar EvoMemState is compared against (reader observation).
  * *A preliminary number does not add up.* Section 2.2 says fixed self-reflection lowers accuracy "for most systems", with the largest drop 1.6 points (Mem0), and lowers average accuracy from 50.5% to 48.9%. A 1.6-point fall in the average with a largest single drop of 1.6 would require every system to fall by exactly 1.6, which contradicts "most" (reader check from the text; Figure 3 itself was not read).
  * *Single runs and one judge.* No spreads or seeds are reported, the Reasoning State is sampled at temperature 0.3, and DeepSeek-V4-Flash both builds every system's memory and judges the answers, with no judge-human agreement check.
  * *LoCoMo numbers are not comparable across papers.* Judge scores here are at most 46.4 on LoCoMo, while other wiki papers report LLM-judge accuracies of 77.7% to 87.1% ([LoCoMo](../concepts/locomo.md)); this paper includes adversarial questions and uses its own short-answer prompt and judge (reader observation).
  * *Text only and small stores.* MemSyco-Bench stores average 22.1 records and 27.3 edges, so the ontology is tested at small scale; the authors name multimodal memory as the main limitation.

# Q9 Contributions

* A memory representation that keeps every extracted fact and records its current validity, scope, supersession, and unresolved conflicts as typed edges, with relation-following retrieval.
* A separate, small policy trained with GRPO to write per-request memory-use rules for a frozen answer model, rewarded by improvement over no rules.
* Evidence, through complete-evidence accuracy and ablations, that on memory-use benchmarks the gain comes from how memories are used more than from how completely they are retrieved.

# Q10 Next Steps

* **Multimodal memory (from the paper).** Extending facts and relations to documents, images, and other user artifacts.
* **Compare with MemAdapter and AdaptiveMem (reader suggestion).** The same group's training-free [MemAdapter](2610.05162.md) reports MemSyco-Bench average accuracy of 80.46 to 86.67 with Qwen3-8B as answer model, under a different protocol (4-bit quantization, other memory backends). A same-protocol comparison would show whether a trained policy is needed, and MemTrapBench's AdaptiveMem is a simpler prompt-level baseline.
* **Out-of-distribution memory use (reader suggestion).** Testing on a memory-use benchmark from another group whose task design does not mirror the training data, such as PersistBench, would separate learned memory reasoning from benchmark fit.
* **Fix the weak baselines (reader suggestion).** Re-running Mem0, LightMem, and Supermemory with configurations that reproduce their published LoCoMo results would make the comparison fairer.
* **Scale the ontology (reader suggestion).** Stores of 22 records do not test what happens to traversal when the relation graph is large and densely connected; traversal with no filtering could flood the context.
