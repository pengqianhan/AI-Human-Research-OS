# Q1 Problem Definition

* **Input (X):** a broad information-seeking query that requires gathering many independently verifiable facts across multiple entities and organizing them into a schema-constrained table (a specific set of required columns), plus a shared LLM (Qwen3-4B backbone) instantiated as one lead agent and several subagents.
* **Output (Y):** WideSeek-R1, a lead-agent–subagent multi-agent system where the lead agent decomposes the task and delegates parallelizable subtasks (its only tool is `call_subagent`), and each subagent independently searches and synthesizes its assigned piece (tools: `search`, `access`) before returning findings to the lead agent for the next round of decomposition or final answer assembly.
* **Core problem:** recent LLM progress mostly scales *depth* — a single agent doing more sequential multi-turn reasoning and tool calls on one long-horizon query. As tasks grow broader rather than deeper, a single agent's context accumulates irrelevant information from earlier subtasks ("context pollution") and is forced to process independent subtasks serially, capping throughput regardless of how much depth scaling it is given.
* **Scope:** a 4B-parameter model (WideSeek-R1-4B, from Qwen3-4B) trained via multi-agent RL, evaluated up to 10 parallel subagents per lead-agent turn, with a maximum of 10 lead-agent turns and 20 subagent turns; the underlying multi-agent framework supports deeper recursion, but training deliberately restricts it to a static two-layer (lead + subagents) hierarchy.

# Q2 Problem Novelty

Width scaling itself is not new — prior multi-agent frameworks such as CAMEL and AutoGen already decompose tasks across multiple LLM instances, and sampling-based methods such as best-of-N and self-consistency already parallelize compute at test time. The paper's stated novelty is that neither of those two families is *trained end-to-end for width scaling*: CAMEL/AutoGen-style frameworks hand-craft the decomposition and coordination workflow rather than learning it, while best-of-N/self-consistency parallelize repeated attempts at the *same* task rather than decomposing a *broader* task into independent parallel subtasks. Concurrently, other multi-agent RL work (OWL, AgentFlow) trains hierarchical agents but with turn-taking, one-subtask-at-a-time execution rather than genuinely parallel subagent dispatch, and self-play multi-agent RL lines (MARSHAL, Absolute Zero) target distributed reasoning rather than search orchestration. WideSeek-R1's contribution is jointly training a lead agent and its subagents with a *shared* model via multi-agent reinforcement learning (MARL) so that scalable orchestration (what to delegate, how to phrase subagent prompts) and parallel execution (how to search and synthesize a subtask) are learned together rather than one being hand-designed and the other trained in isolation.

# Q3 Scientific Hypothesis

If a lead-agent–subagent system is trained end-to-end via multi-agent reinforcement learning — with a shared LLM instantiated across isolated-context roles, a single group-normalized outcome reward per rollout, and an advantage-reweighting scheme that credits both token- and agent-level contributions — then the resulting system should exhibit *width scaling*: performance on broad information-seeking tasks should keep improving as more parallel subagents are added, in contrast to single-agent *depth scaling* (more turns/tokens), which the paper expects to plateau once context and serial-execution limits are reached. The paper further hypothesizes that this width-scaled, jointly trained 4B system can match a much larger (671B) single-agent system on broad information seeking despite using roughly 170× fewer parameters.

# Q4 Related Work and Key People

* **Scaling dimensions in LLMs.** Positions itself against training-time scaling (parameters, data, compute) and single-agent test-time depth scaling (extended chain-of-thought, multi-turn tool use, as in reasoning models and Kimi K2/Gemini 3 Pro-style agentic models), arguing width scaling via multi-agent systems is a complementary, underexplored third axis, distinct from sampling-based aggregation (best-of-N, self-consistency).
* **Search agents.** Builds on single-agent RL search training (Search-R1, ASearcher) as both conceptual precedent and a source of standard-QA training data (ASearcher's dataset is mixed 1:1 into WideSeek-R1's training set); positions itself against the WideSearch and DeepWideSearch benchmarks for broad information seeking and against deep-research benchmarks (GAIA, BrowseComp) for single-complex-query depth.
* **Multi-agent frameworks and agentic RL.** Contrasts hand-crafted-workflow multi-agent frameworks (CAMEL, AutoGen) and turn-taking hierarchical multi-agent execution (OWL, AgentFlow, MiroFlow) with its own jointly-trained, parallel-execution design; situates itself within the broader agentic-RL literature spanning search (Search-R1), code (SWE-RL), and computer use (UI-TARS-2), noting multi-agent RL for LLMs specifically remains comparatively underexplored.

# Q5 Key Solution Idea

1. **Restricted-tool lead agent.** The lead agent's only available tool is `call_subagent`; this restriction is deliberate, to avoid the context pollution that would come from also letting the lead agent search directly. Each turn it emits a set of well-defined subtasks with clear delegation prompts, then goes idle until all dispatched subagents return before proceeding to its next turn (or final answer).
2. **Isolated-context parallel subagents.** Each subagent runs in its own isolated context with two tools — `search` (retrieve snippets/URLs for a query) and `access` (summarize a specific URL against the query) — executing multi-turn tool-integrated reasoning on its assigned subtask in parallel with its siblings. Subagents function as high-level, learned tools for the lead agent; their precision in filtering and synthesizing evidence is what the lead agent's final answer quality depends on.
3. **Multi-agent advantage assignment.** Rather than solve fine-grained inter-agent credit assignment, WideSeek-R1 uses one verifiable outcome reward per multi-agent rollout (based on final-answer correctness against ground truth), group-normalizes it across a GRPO-style rollout group, and assigns the *same* group-normalized advantage to every agent and every token in that rollout — a deliberately simple design chosen to avoid reward hacking from more complex credit-assignment schemes.
4. **Dual-level advantage reweighting.** Extends GRPO along two axes for multi-agent, multi-turn training: (a) token-level reweighting across turns (à la DAPO) so that turns with more tokens are not diluted relative to short ones; (b) agent-level reweighting that averages the objective over the agents present in a rollout, which prevents rollouts with many subagents from dominating the gradient and — critically — removes the incentive for the lead agent to spawn extra subagents that do not improve final reward, since agent-level averaging means "adding agents only helps if it improves the final reward."
5. **Automated schema-constrained data pipeline (20k tasks).** Three-stage pipeline built from HybridQA seeds: (i) *Query generation* extracts a user intent and stochastically targets 10–50 rows, then synthesizes and refines a schema-constrained query with explicit column definitions; (ii) *Answer generation* prompts Gemini for two independent responses per query plus the "unique column(s)" needed to align predicted rows to ground truth regardless of permutation; (iii) *QA pair filtering* discards pairs whose two independent answers disagree cell-wise below a 0.9 consistency threshold, and discards overly simple results (fewer than 3 rows), keeping only high-consistency, sufficiently-difficult instances.

# Q6 Experiment Design

Main evaluation is on the WideSearch benchmark (200 tasks, 100 English/100 Chinese, requiring tabular output), sampled 4× per task and reported as item F1, row F1, and success rate (Avg@4 for all three, Max@4 for the F1 scores, Pass@4 for success rate). Baselines span single-agent (SingleSeek-R1-4B — a same-data single-agent ablation trained for fair comparison, Qwen3-4B, Search-R1-7B, ASearcher-7B, DeepSeek-R1-671B) and multi-agent (WideSeek-R1-4B, multi-agent Qwen3-4B, AgentFlow-7B, OWL-8B, MiroFlow-8B — the latter two implemented on Qwen3-8B without additional training since OWL only releases 32B and MiroFlow is framework-only). A separate width-vs-depth scaling study plots performance against number of turns (depth) versus number of parallel subagents at fixed turns (width) for both the base model and WideSeek-R1-4B. Two ablations dissect the framework: (1) a 2×2 role-swap assigning WideSeek-R1-4B or Qwen3-4B to the lead agent and subagents in all four combinations; (2) a training-data ablation comparing wide-only, deep-only (ASearcher data), and hybrid training sets at matched sample counts. A final generalization check evaluates on seven standard single-/multi-hop QA benchmarks (NQ, TriviaQA, PopQA, 2WikiMultiHopQA, HotpotQA, Bamboogle, MuSiQue) via LLM-as-judge Avg@4.

# Q7 Datasets and Code

The paper constructs and plans to open-source a 20k-task broad-information-seeking dataset (schema-constrained queries with canonical tabular answers and unique-column identifiers), built from HybridQA seeds via a Gemini-assisted three-stage pipeline (Section 4). Training combines this dataset in equal proportion with ASearcher's existing multi-hop QA data; a local offline knowledge base built from Wiki2018 serves as the `search`/`access` tool backend during training for cost efficiency. The GitHub repository listed (RLinf/RLinf, 4,838 stars at retrieval time) is the authors' broader open-source RL infrastructure project rather than a WideSeek-R1-specific release; the paper does not establish that the 20k dataset or WideSeek-R1-4B checkpoint were already published at submission time.

# Q8 Evidence Quality

This note is built from the arXiv HTML full text (Introduction through Conclusion, plus Appendix A's stated limitations and the start of Appendix B's rollout formalism), retrieved via `hf papers read`. Headline numbers are consistent between the abstract and the body (WideSeek-R1-4B: 40.0% item F1 on WideSearch, comparable to DeepSeek-R1-671B's 41.3% at roughly 170× fewer parameters). The paper is candid about several boundaries this note preserves: it evaluates only a single model size (4B) because training a reasoning-based multi-agent system is computationally expensive (approximately 3,000 H100 GPU-hours even at 4B), leaving larger-scale validation untested; its MARL credit assignment is explicitly coarse — a shared outcome reward cannot distinguish whether a failure came from the lead agent's flawed orchestration or a subagent's execution error; the two-layer hierarchy is a training-stability choice, not a capability ceiling — the paper states that allowing subagents to recursively spawn their own subagents destabilized MARL training and was therefore disabled; and roughly 90% of training step time is dominated by long-tail rollout generation under the paper's synchronous, collocated training design. The Impact Statement explicitly flags a dual-use risk: "autonomous agent swarms could be misused for scalable automated data gathering or misinformation generation."

# Q9 Contributions

1. WideSeek-R1, a lead-agent–subagent framework trained end-to-end via multi-agent reinforcement learning — extending GRPO with multi-agent advantage assignment and dual-level (token- and agent-level) advantage reweighting — to jointly learn scalable orchestration and parallel execution for broad information seeking.
2. An open-sourced (planned) 20k-task broad-information-seeking dataset built from an automated, schema-constrained query-generation and dual-response-consistency-filtering pipeline, complementing existing multi-hop QA datasets that are tailored to single-entity, depth-scaling queries.
3. Empirical evidence that width scaling via MARL lets a 4B multi-agent system match single-agent DeepSeek-R1-671B on WideSearch and exhibit continuous performance gains as the number of parallel subagents increases, in contrast to single-agent depth scaling, which plateaus once context limits bind — while also surpassing larger (7–8B) multi-agent baselines on both the target benchmark and seven standard QA benchmarks.

# Q10 Next Steps

The paper's own stated limitations point toward: evaluating at larger model scales beyond the single 4B configuration tested (Appendix A, "Model Size"); developing more granular, role-specific reward modeling to resolve the coarse lead-agent-vs-subagent credit-assignment ambiguity inherent to its shared-outcome-reward design; relaxing the fixed two-layer hierarchy once a more stable training recipe for recursive subagent spawning is found, so the system could autonomously deepen its organizational structure for unexpectedly complex subtasks; and exploring asynchronous or decoupled rollout/training paradigms to reduce the roughly 90% of training time currently spent waiting on long-tail rollout generation.

This note flags one open question beyond the paper's own: agent-level advantage reweighting is designed to stop the lead agent from spawning *extra, useless* subagents (since added agents only help if the final reward improves), but the paper does not report whether the same mechanism can push the lead agent toward spawning *too few* subagents when a fixed per-turn cap (10, in this paper) and a static two-layer topology are both externally imposed rather than learned — it is not established whether an untrained, uncapped lead agent trained under a *learned* rather than fixed subagent budget would converge to an efficient count on its own, or whether that would reopen the same MARL instability the paper found when relaxing hierarchy depth.
