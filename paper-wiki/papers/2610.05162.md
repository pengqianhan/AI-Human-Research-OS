# Q1 Problem Definition

* **Input (X):** a current user request q, the visible task context and evidence c, and the set of memories M retrieved by an existing long-term memory system (A-MEM, Mem0, NaiveRAG, MemoryBank, or LightMem; top-10 on MemTrapBench, 4-16 per instance on PersistBench). The memory system itself is left unchanged.
* **Output (Y):** the final user-facing answer y, produced so that each memory influences only what the current task justifies (for example, tone or presentation, but not an objective decision).
* **Core problem:** *memory-induced sycophancy*, where an agent over-aligns with a user's remembered beliefs, preferences, or identity even when they are inaccurate, outdated, or contradicted by current evidence. The paper argues the risk is not a property of the memory's content: an accurate, relevant memory (for example, "the user is a cardiologist") can rightly shape how an explanation is pitched yet should not tilt a treatment choice. The task is therefore to calibrate, after retrieval, what each memory may support, which parts of the response it may affect, and which conclusions it cannot justify.

# Q2 Problem Novelty

Partly new. Memory-induced sycophancy and over-personalization are documented by recent benchmarks (MemSyco-Bench, PersistBench, MemTrapBench, OP-Bench, BenchPreS, STALE) and by "Recalling Too Well" and Mao et al.'s study of persistent sycophancy in stateful agents. Existing mitigations act *before* reasoning: at extraction (summarizing instead of extracting discrete memories; selective forgetting), at retrieval (Self-ReCheck's relevance filter, MemGate's learned admission gate), or at organization (domain-structured memory). The new framing is that memory risk is relational, depending on the memory, the task, and the evidence together, so it has to be handled after retrieval by regulating each memory's role rather than by deciding which memories are visible. The preliminary study supports why this matters: with only accurate, relevant memories, accuracy still fell.

# Q3 Scientific Hypothesis

1. **Accurate memories still mislead.** If a model receives only accurate, benign, task-relevant memories that cannot settle the answer, accuracy will still fall relative to no memory, and the new errors will follow the memory (Section 2.1, Figure 2a).
2. **Counterfactual boundaries expose hidden risk.** If each memory is held fixed and examined under hypothetical task settings, the resulting condition-to-influence rules will improve memory use before any task-specific reasoning (ablation variant B, Table 3).
3. **Post-retrieval calibration beats pre-reasoning filtering.** If the boundaries are resolved against the actual task and the answer is checked span by span against permitted memory uses, memory-use reliability will improve across memory systems and backbones more than prompt disclaimers, relevance filtering, domain grouping, or a learned gate (Tables 1-2).

# Q5 Key Solution Idea

MemAdapter adds three LLM stages after retrieval, with prompts given in Appendix H.1:

1. **Counterfactual Induction.** The model sees only the retrieved memories, not the query. For each memory it derives a set of task types the memory could serve, builds concrete hypothetical settings (a request plus an evidence configuration), assesses in each setting what the memory may *support*, its *scope*, and its *limitation*, and keeps only substantive differences across settings as conditional-use rules. The output is one JSON "boundary card" per memory.
2. **Context-Aware Reflection.** Given the actual query, dialogue, evidence, all memories, and their boundary cards, the model resolves each card for the current task, jointly accounting for updates, qualifications, and conflicts among memories, and writes a natural-language *use instruction* per memory: what it may support, which response component it may affect and how much, and where its influence stops.
3. **Evidence-Based Reasoning.** The model generates the answer under these instructions while internally recording an answer-support trace (role, source, applicable instruction for each major span), checks that each source is present and supports its span and that each memory use stays within its instruction, and returns only the answer.

The key difference from prior mitigations is that no memory is removed or rewritten; instead each memory's permitted inferential role is made explicit. The method needs no training and does not touch memory construction or retrieval.

# Q6 Experiment Design

* **Benchmarks.** MemSyco-Bench (all 1,550 instances; When to Use Memory = Objective Fact Judgment, Contextual Scope Control, Memory-Evidence Conflict, 300 each; How to Use Memory = Personalized Memory Use, 300, and Valid Memory Selection, 350); MemTrapBench (1,050 instances; Reasoning Fixation over Task Boundary, Cognitive Bias, and Trauma scenarios, and Belief Distortion over Safety; 0-5 judge scores); PersistBench (500 samples: Cross-Domain Leakage 200, Sycophancy 200, Beneficial Memory Use 100; FR@3 counts a sample as failed if any of three generations is judged 3 or higher; lower is better). All scoring follows each benchmark's official LLM-judge protocol; the judge model is not named in the retrieved text.
* **Memory systems.** A-MEM, Mem0, NaiveRAG, MemoryBank, and LightMem, all with BGE-M3 embeddings (1,024 dimensions) and DeepSeek-V4-Flash for any LLM-based memory processing. Retrieval runs once per instance and the frozen memory set is shared by every method.
* **Baselines.** Direct generation; Anti-Sycophancy (a prompt disclaimer, from Recalling Too Well); Self-ReCheck (relevance filtering); Dynamic Partition (domain grouping); MemGate (released checkpoint, gate threshold 0.07).
* **Backbones.** DeepSeek-V4-Flash (temperature 0.2, thinking off) for the main results; GPT-5.6-sol and Qwen3-8B (4-bit NF4, greedy) for the cross-backbone check, on MemSyco-Bench only.
* **Ablation.** B (Counterfactual Induction only), B+R (plus Context-Aware Reflection), and the full method, on MemSyco-Bench with DeepSeek-V4-Flash (Tables 3 and 8).
* **Preliminary study.** 75 instances (25 from each benchmark), sampled and manually reviewed, and reconstructed where needed, so that every memory is accurate, benign, relevant, and insufficient to determine the answer; with and without memory. The backbone for this study is not stated in the retrieved text.
* **Runtime.** Mean, P50, P95, and P99 seconds per sample on PersistBench for three memory systems (Table 9).
* **Not designed in.** No repeated runs, variance, or significance tests; no human evaluation of responses; no token-cost accounting; no variant with Evidence-Based Reasoning but without the boundary cards.

No new dataset; the three benchmarks are existing public ones. # Q8 Evidence Quality

* **Supported.**
  * The motivating claim is supported within its scope: on 75 curated instances, adding accurate, relevant memories lowered accuracy from 96.0% to 77.3% (MemSyco-Bench 96.0 to 68.0, PersistBench 100.0 to 84.0, MemTrapBench 92.0 to 80.0), and 19.4% of answers correct without memory became wrong, every one toward the memory.
  * The headline MemSyco-Bench gains are large and consistent. With DeepSeek-V4-Flash, MemAdapter has the highest When-to-Use (87.89-91.22) and How-to-Use (82.15-89.39) accuracy under all five memory systems, and the spread of average accuracy across systems narrows from 37.03-71.71 to 85.48-90.45. The gains over direct generation are largest where the backend is weak (LightMem +56.67 When-to-Use; Memory-Evidence Conflict 4.33 to 97.00).
  * PersistBench sycophancy failures fall in every system: FR@3 drops from 76.50-82.00 to 51.00-58.50 (21.0-31.0 points), and FR@1 and FR@2 fall too.
  * With Qwen3-8B, average MemSyco-Bench accuracy rises from 24.57-38.38 to 80.46-86.67.
* **Weaker or narrower than the headline.**
  * Margins over the best competing intervention are sometimes small, for example 0.44 points on A-MEM When-to-Use over Anti-Sycophancy. On PersistBench cross-domain leakage, Self-ReCheck beats MemAdapter in four of five systems, and MemAdapter is 0.50 points worse than direct generation with LightMem.
  * The beneficial-memory failure rate rises in four of five systems (NaiveRAG +1, A-MEM +2, LightMem +4, MemoryBank +6 points) and falls only for Mem0 (-3). The paper calls this a "memory-system-dependent trade-off"; read plainly, the method sometimes suppresses memory the user wanted used.
  * With GPT-5.6-sol, Personalized Memory Use drops for three of five systems (up to -9.00 with A-MEM), and gains on the other dimensions are moderate (+3.10 to +9.56 average for three systems).
  * The ablation does not separate the stages cleanly. Counterfactual Induction alone gives most of the gain (NaiveRAG 70.25 to 84.26); Reflection changes the average by -0.40 to +1.49 points (it lowers LightMem from 82.27 to 81.87); the final stage adds 2.90-6.19 points. Because no variant runs Evidence-Based Reasoning without the earlier stages, a careful evidence-grounding prompt alone might account for part of the full method's gain.
  * Each configuration appears to be one run; with judge-scored metrics and temperature 0.2, small differences (under about one point) cannot be told apart from noise.
  * One of the three benchmarks (MemSyco-Bench) comes from overlapping authors, and all three are scored by LLM judges whose model is not named.
  * The runtime table reports latency comparable to single-call baselines (mean 6.63-6.95 s against 6.04-7.10 s) for a method that makes three sequential calls; the token cost is not reported, so the cost claim is incomplete.
* **Reader observation.** Appendix D.3.1 defines PersistBench's beneficial-memory score with 1 as success and 2-3 as failure, while the judge prompt in Appendix H.3.3 rates 3 as full success and 1 as no use. One of the two descriptions is inverted; the retrieved text does not say which convention produced Table 7.

# Q9 Contributions

* A reframing of memory-induced sycophancy as a post-retrieval problem of how a memory is used, with a small controlled study showing that accurate, relevant memories alone can flip correct answers.
* MemAdapter, a training-free three-stage layer (counterfactual boundary cards, task-specific use instructions, support-checked answering) that works on top of five different memory systems without changing them.
* A comparison against four post-retrieval interventions on three benchmarks and five memory systems, plus two extra backbones, with released code and prompts.

# Q10 Next Steps

* **Isolate the stages.** Run an evidence-grounding-only variant and a variant that skips Reflection, and report variance over repeated runs, to show which stage carries the gain.
* **Cost.** Report tokens per query and test caching boundary cards per memory, since Counterfactual Induction does not depend on the query and could run once at memory-write time.
* **Beneficial use.** Track the beneficial-memory failure rate as a first-class target; a method that suppresses useful personalization trades one failure for another.
* **Human judgment.** Validate the judge-scored gains with human ratings of whether personalization was kept where wanted.
* **Agents that act.** The benchmarks are question answering; testing the same calibration in agents that take actions on remembered preferences (purchases, scheduling) would show whether the boundaries hold when the stakes are actions rather than text.
* **Project fit (reader note).** This repository keeps durable human cognition and project memory that agents read at startup; MemAdapter's "support, scope, limitation" triple is a usable checklist for when a remembered preference should shape an agent's choice and when task evidence must win.
