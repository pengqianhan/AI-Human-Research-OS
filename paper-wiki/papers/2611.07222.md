# Q1 Problem Definition

* **Input (X):** a tool-using agent working on a user's task over email, files, chat, travel, or banking tools, whose tool outputs may contain text written by an attacker (indirect prompt injection).
* **Output (Y):** for each side-effecting call the agent proposes, an allow or block decision about its *target* (recipient, account, grantee, file, booked object), plus a rewritten view of tool output with injected instructions removed.
* **Constraints:** no per-task plan or router; no backbone re-runs; the attacker controls free-text fields (an email body, a web page) and, in AgentDojo's Slack suite, one external channel name, but not the user's task, the tool implementations, their declared return types, or the scorer. A tool provider that writes attacker values into typed identity fields is outside the threat model.

# Q2 Problem Novelty

Many runtime defenses put a language model on the decision that lets an action through: Progent has a model write the privilege policy, MELON re-runs the trajectory with the user task masked, DRIFT validates calls against a plan. That decision then depends on a model that may have read the injection, and it adds model calls to every step. Provenance defenses (CaMeL, ROPE) keep the model off the final check but need a planner or router model to set each task's allowed sources first. SPILLWAY's claim is that the target decision needs neither: tools already put identities (an email's sender, a transaction's recipient, a channel's members) in typed fields, while an injection placed in tool output arrives as free text, so a set lookup over typed returns separates the two.

# Q3 Scientific Hypothesis

If the admitted target set is built only from typed identity fields of read-only tool returns (plus values the user named), then no attacker-written target can pass the deterministic check, under any backbone. If, in addition, injected regions are removed before the model reads them and a judge may only reconsider refused targets outside the removed regions, utility can be recovered without reopening a removed injection.

# Q4 Related Work and Key People

* **Model-in-the-loop defenses.** Progent (privilege policy written by a model), MELON (masked re-execution), DRIFT (plan validation), VIGIL (verify before commit), Task Shield (does a call serve the user goal).
* **Provenance and information-flow defenses.** CaMeL (planner writes a program whose data flow an interpreter checks), ROPE (a router sets allowed sources per request, then a deterministic origin check; the closest comparator), IPIGuard, APPA, AgentArmor, PACT, ACE, and the information-flow-control work of Costa et al. and Wu et al.
* **Content filters.** Spotlighting, the ProtectAI DeBERTa prompt-injection detector, CommandSans (learned token-level sanitizer), and tool-input/output firewalls (Bhagwatkar et al.).
* **Attacks.** AgentDojo's important_instructions template, ChatInject (forged chat-template turns), AutoDojo (optimizer-generated injections), PISmith (RL-trained attacker), agent data injection (spoofed metadata), causality laundering.
* **Benchmarks.** AgentDojo v1.2.2 (Banking, Slack, Travel, Workspace) and AgentDyn (GitHub, DailyLife, Shopping).
* **Key people.** Woosang Lim (SAINT Machines and KAIST, corresponding), Yeseul Chang and Jaewoo Lee (Chung-Ang University). Likely critics: the ROPE and CaMeL authors, and adaptive-attack researchers (Zhan et al., Hofer et al.).

# Q5 Key Solution Idea

1. **Taint-novel targets.** A value in a call's target arguments is *taint-novel* when one of its tokens (emails, URLs, or the whole value if at least four characters) appears in tool output but not in the user's text. Values the user named are never taint-novel.
2. **Egress floor (Algorithm 1).** The executor captures each read-only tool's return as the typed object before serialization and indexes a value only when its declared field type is an identity format (email, URI, UUID, hostname, IP) or its field has a routing role (recipient, sender, participant, channel). Bodies, subjects, and descriptions never enter the index. A call is allowed when every taint-novel target is in the index and none is repeated in untrusted free text. Only read-only returns are indexed, and a read steered by a taint-novel argument adds nothing. Grants to a principal named only in tool output and unrequested deletions are blocked outright.
3. **Delegation rules.** Deterministic rules admit targets the user named indirectly: a value carrying a name from the task ("send the report to Alice"), a contact attribute of a named entity, a resource the user's own account owns, and a few post-judge cases (downloads from a user-named domain; clone, invite, ownership-transfer targets outside removed text when the task asks for that grant). Object effects (bookings, fetches, recommendations) get their own rules, for example refusing an irreversible operation under "the cheapest" when its object is not the winner on the typed listing.
4. **Ingress sanitizer.** Rules, no model: replace forged chat-template turns, regions delimited by the benchmark's injection template, text addressing the agent about its task, dictated tool calls, and claims that a payee's account changed. Removed text is kept as the span set S.
5. **Two-view judge with span veto.** A local model (gemma4:31b, 4-bit, temperature 0) sees only calls a rule already refused, and only when the refused target is outside S. A routing view (is this a recipient the task implies?) and a payload view (did the user request this action and content?) must both say yes; a missing verdict counts as no.
6. **Stated properties.** P1: if the attacker writes only free-text fields, the lookup refuses every target that appears in attacker text and not in the task. P2: for any judge, admitted calls lie in the floor-admitted set plus refused calls outside S. P3: an attacker target refused by the lookup can be admitted only through a delegation rule, or through the judge when outside S.

# Q6 Experiment Design

* **Breadth grid.** AgentDojo v1.2.2, full grid of user and injection tasks, three backbones (gpt-4o-mini, qwen3-coder:30b, qwen3:8b) by four suites (949 attacked pairs per backbone), standard important_instructions attack.
* **Comparators.** Undefended, MELON, Progent, DRIFT, ROPE from released code on the same agent (Progent's policy and ROPE's router written by the cell's own backbone unless the authors' router is named), Spotlighting, and the ProtectAI detector. CaMeL is not run because it replaces the agent loop.
* **Stress tests.** ChatInject on qwen3:8b (665 pairs); an attacker-as-sender Workspace variant where the attacker writes the typed sender field (126 pairs); AutoDojo injections optimized against Progent on gpt-4o-mini (389 pairs) plus two held-out Banking sets of 144 pairs; PISmith replayed open-loop with the first of ten variants per injection (ASR@1).
* **Delegated-routing grid.** Head-to-head with ROPE (authors' Claude Opus 4.8 router, and gpt-4o-mini as router) on AgentDojo's four suites and AgentDyn's three, gpt-4o-mini agent, one run per suite (seed 42).
* **Scoring.** Hits count only when the environment changed (ROPE's executed-effect rescoring applied to every method). In-scope ASR drops a target the task already named and content-manipulation tasks that name no recipient. Metrics: benign utility (BU), utility under attack (UAU), ASR, NRP = BU × (1 − ASR), and ERS = harmonic mean of BU and (1 − ASR).
* **Ablation.** qwen3:8b, 949 pairs per arm: floor; floor + judge; floor + sanitizer; full; full without span veto.

SPILLWAY also has no raw hit in any of the twelve cells (Table 5). With no leak observed, the one-sided 95% Clopper–Pearson bound is 2.8% for the smallest cell (105 pairs) and 0.1% pooled over 2,847 attacked pairs.

**Stress tests.** ChatInject (qwen3:8b): SPILLWAY UAU .396 / ASR .000 on Workspace and .286 / .000 on Slack, against undefended .052 / .245 and .095 / .648; ROPE leaks .095 on Slack and DRIFT .062 on Workspace. AutoDojo: .000 on all three suites, but the address and payee-change sanitizer rules were written on the four pairs that leaked in an earlier build, so the paper calls this result descriptive; on the two held-out Banking sets ASR is .007 and .000 by AgentDojo's check (.014 on the DRIFT-optimized set when a second payee transfer the check misses is counted). PISmith (gpt-4o-mini, macro over four suites): SPILLWAY UAU .257 / ASR .005; ROPE .173 / .007; DRIFT keeps more utility (.428) but leaks .064; undefended .128 / .568. Attacker-as-sender variant: no attack succeeds under SPILLWAY, because the injected text repeats the attacker's address and the floor refuses targets repeated in free text.

**Delegated routing (Table 8).** Mean over seven suites, SPILLWAY .550 UAU / .000 ASR, ROPE with the Opus 4.8 router .468 / .015 (leaks on DailyLife, Shopping, Slack), ROPE with gpt-4o-mini as router .361 / .013.

**Ablation (qwen3:8b, in-scope UAU / ASR).** Floor alone is .000 on all four suites. Adding the judge without the sanitizer opens the only executed leaks (Banking .028, Workspace .002), including a transfer to the attacker's account on "pay the bill". Adding the sanitizer lifts Slack (.181 to .286) and Travel (.243 to .343). Removing only the span veto changes no attack outcome.

**Cost.** On qwen3:8b benign Slack / Workspace, the judge runs 0.43 and 0.05 times per episode and backbone calls change by under 0.15, against +5.29 / +3.25 backbone calls for MELON, +8.67 / +5.94 for Progent, and +9.91 / +9.59 for DRIFT.

**Limits on the evidence.**

* The guarantee covers identity targets only. Injected content sent to a legitimate recipient, an injection steering an effect to an existing contact or payee, injected text in an answer, and targets that never appear verbatim in tool output are outside P1 (stated by the paper).
* The role lexicon is written per benchmark, and the judge, delegation rules, and lexicon are the adaptive-attack surface (stated). The four AutoDojo pairs that leaked in the earlier build all went through that surface (P3).
* Each grid cell runs once; a three-seed by three-repeat rerun of SPILLWAY kept ASR at .000 with per-suite utility standard deviation at most .041. Comparators were not rerun.
* The defense was developed and evaluated on AgentDojo; AgentDyn needed six added target-argument names, which is the only out-of-dataset test.
* The qwen3:8b rows of Table 3 ("SPILLWAY (all)") and Table 1 agree on Banking and Slack but differ on Travel (.343 against .350) and Workspace (.414 against .405); both are whole-pair counts (48 vs 49 of 140, 232 vs 227 of 560), so the tables appear to come from different runs or filters, while both average to .370 (reader observation).
* UAU exceeds BU for SPILLWAY in several cells (Workspace gpt-4o-mini .848 vs .825; Travel qwen3:8b .350 vs .250), which the paper attributes to the sanitizer removing distracting text; a benign run passes through the same sanitizer, so the mechanism behind attacked runs outperforming benign ones is not isolated (reader observation).
* ROPE's Opus 4.8 router is stronger than the gpt-4o-mini agent, so the delegated-routing comparison mixes defense design with router capability; the paper reports both router settings.

# Q9 Contributions

1. A target-admission check that is a set lookup over identities read from typed tool returns before serialization, with no per-task plan and no model on the default path.
2. A coupling of rule-based sanitization to admission: the only model allowed to overturn a refusal is never asked about a target inside removed text.
3. The only defense in its grid with zero in-scope attack success on every AgentDojo backbone-by-suite cell, at the highest mean utility under attack, plus stress results under ChatInject, AutoDojo, and PISmith and a head-to-head with ROPE on seven suites.
4. A released SDK (spillway-guard) and per-cell results.

# Q10 Next Steps

* **Stated by the paper.** Declaring roles for new tool sets; adaptive attacks against the judge, delegation rules, and lexicon.
* **Typed-field spoofing.** When the attacker controls an identity field (sending the email, being a contact), the floor admits the address; only the repeated-in-free-text rule stopped the one tested variant. An instruction naming the attacker only by role is untested.
* **Content effects.** Injected content sent to an admitted recipient and causality laundering through later calls are outside any target check; pairing SPILLWAY with a content-level control is open (reader suggestion).
* **Real tool ecosystems.** MCP servers with loosely typed returns (free-form JSON, string fields that carry addresses) would weaken the typed-field premise; measuring how many real tools expose identities in typed fields would test the idea beyond benchmarks (reader suggestion).
