# Q1 Problem Definition

* **Input (X):** a natural-language task request `u_0`, inducing a formal task contract ℰ = (𝒲, W₀, q, 𝒜, 𝒯, Ω, **B**, D, V_D): a workspace-state space and initial workspace, a normalized objective `q`, an action set, a state-transition operator, an observation interface, a resource-budget vector, a delivery contract, and a task-level verifier.
* **Output (Y):** Apodex 1.1, a general-purpose model plus execution system (a shared harness and AgentOS runtime) that produces an execution trace of actions, observations, and asynchronous user interventions, ending in a terminal workspace whose delivered artifacts satisfy the delivery contract as judged by the task-level verifier — plus a 35B-parameter "Apodex 1.1 Mini" variant for local deployment.
* **Core problem:** general-purpose language models can reason and often know the right answer, yet fail at what the paper calls *working capability* — sustained, verifiable progress over a long horizon: finding and interpreting evidence, operating on heterogeneous files, executing and debugging code, maintaining and revising a coherent plan across many steps, recovering from failed actions without discarding valid progress, and delivering artifacts another person can inspect or continue. The paper frames this as a model-*and*-system problem rather than an answer-quality problem alone.
* **Scope:** general-purpose across professional work, finance, scientific research, mathematics, coding, and search. This is the developer's own technical report: several comparison numbers are the authors' internal reproductions under their own harness rather than externally reported results, which the paper discloses explicitly in its table captions.

# Q2 Problem Novelty

The report does not claim to originate reasoning-and-acting (ReAct), tool use (Toolformer), or multi-agent coordination (AutoGen, MetaGPT, ChatDev, AgentVerse) — all cited as prior work. Its stated novelty is organizing model development around two named, complementary scaling surfaces beyond parameters, data, or inference compute: **Environment Scaling** (the diversity, fidelity, and verifiability of the file, search, and code worlds the policy learns and acts in) and **Agentic Coordination Scaling** (decomposition, delegation, staged-result integration, and replanning trained as model behavior rather than only an inference-time wrapper), bound together by one execution harness (AgentOS) so the same contract serves trajectory collection during training and sustained execution at runtime. The paper explicitly argues the relevant scaling variable for multi-agent work is not the number of agents or parallel samples, but "the amount of useful work that can be coordinated as an objective evolves" — a claim that most Agent Team benefit comes from continuous staged-result integration and replanning rather than parallelism per se.

# Q3 Scientific Hypothesis

If a model is trained on (a) diverse, verifiable, causally structured executable file, search, and code environments (Environment Scaling) and (b) trajectories of decomposition, delegation, staged-result integration, and replanning across agents and time (Agentic Coordination Scaling), both collected and executed through one shared harness (AgentOS) that preserves authoritative state across tools, agents, context pressure, intervention, and partial failure, then the resulting policy should reach a leading band of *working capability* — sustained, verifiable task completion — across professional, financial, scientific, mathematical, coding, and search domains, using a substantially smaller model than many frontier systems, and this efficiency benefit should persist down to a 35B-parameter "Mini" variant.

# Q4 Related Work and Key People

* **General-purpose agentic models.** Positioned alongside Kimi K3, GPT-5.6, Claude Fable 5, GLM-5.2, and DeepSeek V4 as models treating agentic work as core general intelligence rather than an application layer; Apodex's claimed differentiator is organizing development around the two named scaling surfaces above.

# Q5 Key Solution Idea

1. **A formal task contract.** ℰ = (𝒲, W₀, q, 𝒜, 𝒯, Ω, **B**, D, V_D) separates the input request `u_0` from the normalized objective `q` and the separately verified delivery contract `D`; asynchronous user interventions are admitted as runtime updates to the workspace rather than actions the model itself selects; a message that materially changes the objective or required deliverables instantiates a new task contract even while carrying forward workspace state that remains valid.
2. **Environment Scaling across three families sharing one contract.** File worlds (authority and transformation — a profession-conditioned registry spanning 33 domains, 318 occupations, and 1,208 deliverable clusters; verification anchored to independently re-derivable, code-checked values rather than LM-judged plausibility). Search worlds (discovery and evidence alignment — the gold object includes the relevant source set and claim-to-evidence alignment, not just a final answer). Code worlds (executable transformation — real harvested pull requests plus synthesized-and-perturbed tasks, sandboxed fail-to-pass/pass-to-pass test verification, and an explicit adversarial check for whether a solver can obtain reward without completing the task before a synthesized world is trusted; construction follows a "forward cheap, inverse expensive" principle).
3. **Agent Team: Agentic Coordination Scaling at runtime.** Externalizes the lead agent's decomposition onto a persistent Task Board — a shared coordination record, not a visualization of private reasoning — so a returned result can unlock a dependent item immediately, a failed premise invalidates only its descendants, and a slow branch does not block independent work. Four capabilities extend Apodex 1.0's latent decomposition: asynchronous human intervention (a mid-execution message updates the live board; the runtime decides whether it is a task-preserving edit or a new task contract); asymmetric verification (a verifier receives one specific claim, its supporting evidence, and the applicable delivery constraint — never the whole problem again — to avoid becoming "another source of context pollution" through a second, equally unconstrained chain of errors); adaptive Max Team Effort (additional investigation is assigned only to weak, contested, or load-bearing claims, revised after each return, rather than a fixed agent count); and evidence-grounded synthesis (a dedicated post-execution stage builds a claim-evidence graph from the terminal task board, subagent reports, evidence, and verifier findings before a writer agent drafts, rather than treating the lead agent's last message as the report state).
4. **AgentOS: the shared execution substrate.** Instantiates workspace state as file state, retrieved evidence, executable state/logs, an artifact index, a dependency graph, and optional coordination control state; three filesystem namespaces (`/inputs` read-only, `/workspace` scratch, `/outputs` the collection root) make the delivery contract checkable; coordination state (Task Board and Agent Bus) lives outside the LLM's message history and is periodically re-injected so plans survive context compaction; tiered compaction triggers on the inference provider's own reported token usage (cheap tool-observation eviction first, an LLM summary only if that relief proves insufficient); soft-deadline/hard-timeout budget handling recovers a bounded partial result rather than discarding in-flight work; and controlled artifact delivery uses a single-writer publishing lease with an exact declared manifest, reconciled against a pre-lease baseline snapshot so a stale or empty file cannot silently satisfy the delivery contract.
5. **Training.** A unified SFT mixture (filtered for behavioral validity, rubric-thresholded rather than single-aggregate-judge-filtered for rubric tasks, model-souped across domain-specialized variants) establishes the cold-start policy. Agentic RL then uses **PIVOT-RL**: hindsight-guided localization of consequential "pivot" decisions in a trajectory (where the model begins an unproductive strategy, relies on insufficient evidence, misuses a tool, or fails to revise an assumption), constructing a localized continuation task from the preserved useful prefix with a short corrective hint present only in the continuation's construction — never at inference, never a prediction target — mixed with unhinted full-task rollouts; asynchronous training lets fast and slow trajectories (file, code, search, and coordination differ hugely in wall-clock cost) enter optimization without blocking on the slowest episode. The full loop — observed failures → Task Pipeline → Environment/Coordination Scaling → training → evaluation and failure attribution → the next Task Pipeline target — is described as a controlled engineering loop; the paper is explicit that its "self-evolution" language refers only to this managed loop, not unconstrained model self-modification.

# Q6 Experiment Design

Two execution modes throughout: ReAct (a minimal scaffold isolating the model's own policy) and Agent Team (trained coordination plus additional organized compute). Public-benchmark results are reported for professional work (APEX-Agents, GDPVal), finance and business simulation (FrontierFinance, YC-Bench), scientific research (FrontierScience-Research, BioMysteryBench Human-difficult), general reasoning and deep search (Humanity's Last Exam, DeepSearchQA), plus mathematics and coding sections this note has not read in full, each compared against a roster of contemporary proprietary and open models (DeepSeek V4, Gemini 3.x, Claude Opus 4.x/5, GPT-5.x, GLM-5.2, Kimi K3, Qwen3.x). Table captions explicitly flag which rows are the paper's own internal reproductions under the Apodex harness — all external GDPVal win-rate entries, the Claude Opus 5 APEX-Agents result, and the DeepSeek V4 FrontierFinance entries — versus externally reported reference results for the remaining rows. Beyond the public tables, the paper reports on an internal FrontierSearchBench and introduces FrontierResearchBench for end-to-end research delivery (§4.4, not read in detail for this note). The evaluation closes with **HDS6**, a six-capability, 24-rubric-item process-verification framework (long-horizon state coherence, evidence fidelity, hypothesis management, boundary and failure reasoning, tool use and execution-state management, self-correction under verification) graded by a role-specialized agentic judging pipeline over a stitched execution log, with a hard integrity gate that zeroes an entire trajectory if a fabricated tool result or a narrated-but-unexecuted action is found. HDS6 compares Apodex 1.0 against 1.1 across three panels (Deep Discover: 397B model, Agent Team; Deep Solve: 397B model, ReAct; Deep Research: 35B model, ReAct) that the paper explicitly says should be read as within-panel comparisons, not a matched cross-panel ablation — the panels also differ in aggregation protocol (Apodex 1.0's Deep Discover result aggregates eight runs, Apodex 1.1's is a single run). Separately, the 35B "Apodex 1.1 mini" is evaluated against comparably sized open and proprietary models on FrontierFinance, FrontierScience-Research, and APEX-Agents as a direct model-scale-efficiency test.

# Q7 Datasets and Code

No single new pretraining corpus is released; the report describes an internally constructed environment suite (the profession-conditioned File-world registry, harvested-plus-synthesized Code worlds) by construction methodology rather than publishing the underlying environments themselves. Publicly reused evaluation benchmarks include APEX-Agents, GDPVal, FrontierFinance, YC-Bench, BioMysteryBench, Humanity's Last Exam, and DeepSearchQA; FrontierSearchBench and FrontierResearchBench appear to be internal evaluations rather than public releases. Model weights are published on Hugging Face (`apodex/apodex-11`), code at github.com/ApodexAI/FrontierAgent (833 GitHub stars per HF metadata at the time of this note), alongside a public API platform (platform.apodex.ai) and official site (apodex.ai) — this is a commercial product release accompanying the technical report, not a research-only artifact.

HDS6, the paper's process-quality framework, is the paper's own invention, judged by the paper's own agentic pipeline over its own model's logs — a stated methodology, not an independently validated third-party evaluation. Reading Table 3 and Table 4 as transcribed: on FrontierFinance, Apodex 1.1 Agent Team's reported 54.3 is the highest value in the table, ahead of the next-highest listed external model (Claude-Fable-5, 49.2); on FrontierScience-Research, its reported 63.3 is likewise the highest listed value, ahead of the next-highest (DeepSeek-V4-Flash-0731, 55.0). On BioMysteryBench Human-difficult, APEX-Agents, GDPVal, Humanity's Last Exam, and DeepSearchQA, Apodex 1.1 Agent Team's reported scores (35.3, 38.5, 78.8, 56.1, 92.4 respectively) are *not* the highest in their tables — Claude Opus 5 is reported higher on all five (49.4, 42.3, 89.4, 64.7, 95.0) — which this note states explicitly because the paper's own abstract language ("reaches the leading performance band") could otherwise be read as uniform leadership across every reported benchmark, which the tables as transcribed do not show.

# Q9 Contributions

1. A formal task contract (workspace, objective, actions, transition/observation operators, resource budget, delivery contract, verifier) used consistently to define "completed work" across file, search, and code domains, separating the input request from the normalized objective and the separately verified delivery contract.
2. Two named scaling surfaces beyond parameters, data, and inference compute — Environment Scaling and Agentic Coordination Scaling — bound by one execution harness (AgentOS) so training and runtime execution share a contract.
3. Apodex Agent Team 1.1: an explicit persistent Task Board replacing latent lead-agent decomposition, plus asynchronous human intervention, asymmetric narrow-claim verification, adaptive Max Team Effort allocation, and a dedicated evidence-graph-based synthesis stage.
4. AgentOS: a persistent execution substrate with a stable three-namespace filesystem, coordination state externalized outside the LLM's message history and periodically re-injected, provider-token-triggered tiered compaction, soft/hard budget handling with graceful partial-result recovery, and single-writer leased artifact delivery with baseline reconciliation.
5. PIVOT-RL: hindsight-guided localization of consequential trajectory "pivot" decisions for targeted RL continuation training, mixed with unhinted full-task rollouts, plus asynchronous training over heterogeneous-cost agentic trajectories.
6. Reported evaluation results placing Apodex 1.1 Agent Team as the highest-scoring system in the paper's own FrontierFinance and FrontierScience-Research tables among the models compared, while scoring below Claude Opus 5 on BioMysteryBench, APEX-Agents, GDPVal, Humanity's Last Exam, and DeepSearchQA in the same tables — a mixed rather than uniform result despite the paper's "leading performance band" framing. The 35B "Apodex 1.1 mini" leads its own comparison table's models on FrontierFinance (50.2), but trails DeepSeek-V4-Flash-0731 on FrontierScience-Research (51.7 vs. 55.0) and trails both DeepSeek-V4-Flash-0731 and GLM-5.2 on APEX-Agents (27.7 vs. 34.4/35.6), while substantially improving over Apodex 1.0 mini on every overlapping evaluation reported.
7. HDS6, a six-capability, 24-item process-verification framework with an agentic judging pipeline and a hard integrity gate against fabricated tool results, used to compare Apodex 1.0 and 1.1 on execution-process quality rather than outcome scores alone.

# Q10 Next Steps

The paper's own stated longer-term direction, toward its "Heavy-Duty Solver" goal, is scaling the coverage and fidelity of executable environments further, strengthening learned coordination over longer horizons, improving training and credit assignment over hierarchical multi-agent traces, and closing the loop between real deployment failures, task construction, training, and evaluation more tightly. The paper itself names several explicit boundaries worth preserving: the coordination plane (Task Board, Agent Bus) is run-scoped rather than a durable distributed database, so process-restart recovery and historical filesystem rewind are explicitly "outside the present contract," with joint versioning of coordination state, message history, and workspace named as "the natural extension of the mechanisms described" rather than something already built; the publication guard is a tool-level policy, "not a syscall-level filesystem monitor"; and the paper states plainly that none of AgentOS's mechanisms "guarantee that a retrieved source, computation, scientific method, or final conclusion is correct" — those claims still require task-appropriate verification and human review in high-stakes settings.

This note flags one open question the report does not address directly: HDS6's judging pipeline is built and run by the same team releasing the model it evaluates, using an agentic judge over that model's own execution logs. The paper's text acknowledges only that HDS6 "does not isolate the causal contribution of an individual system component," without discussing whether a self-graded process-evaluation framework needs the kind of cross-family, independent-reviewer safeguard this wiki's [Multi-agent systems](../topics/multi-agent-systems.md) topic already surfaces for exactly this reason via [ARIS](2605.03042.md)'s cross-model-family executor/reviewer design — a different independence mechanism from Apodex Agent Team's own same-team, narrowed-scope asymmetric verification.
