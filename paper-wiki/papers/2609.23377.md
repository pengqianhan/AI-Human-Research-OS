# Q1 Problem Definition

* **Input (X):** a repository-level SWE instance (repository, base revision, natural-language problem statement, reproducible Docker environment, hidden executable verifier with fail-to-pass and pass-to-pass tests), and a tool-using agent scaffold (R2E-Gym for training and Pro-618 evaluation) that lets a language-model policy search, edit, run shell commands and tests, and submit a patch. Training starts from a single base model, Qwen3.6-27B.
* **Output (Y):** one deployable SWE policy whose binary executable success is higher *overall and in every task category* than a policy trained by joint RL on the same data.
* **Core problem:** SWE tasks are heterogeneous (service/data-layer fixes, user-facing UI changes, build and tooling repairs, performance or security patches). When one policy is trained by RL on the pooled mixture, the paper observes a **category see-saw**: gains in some categories coincide with regressions in others, and the aggregate resolution rate hides this. The paper asks whether (a) balancing category exposure fixes it, and (b) training category experts and then merging them into one model does better.
* **Constraints:** no external stronger model supplies solution trajectories or action targets anywhere in expert training or integration; categories are *observable task labels*, not latent capabilities; the deployed student sees only ordinary task and tool observations (routing is used only during training).

# Q2 Problem Novelty

Partly new. Multi-domain interference in LLM post-training, expert splitting and fusion (Branch-Train-Merge), multi-teacher on-policy distillation (MOPD, Ma et al., 2026), and reward-extrapolated distillation (ExOPD, Yang et al., 2026) all predate it. Those works split along conventional domain boundaries (math vs. code vs. instruction following), where the expert partition is given. The new part is applying specialize-then-integrate *inside one domain*, repository-level SWE, where no natural partition exists. The paper builds one from an evidence-grounded labeling system and makes the within-domain see-saw measurable with explicit metrics (minimum category gain, see-saw gap). The authors describe it as, to their knowledge, the first study to train category-specific SWE RL experts and consolidate them through label-routed MOPD. This matters for coding-agent post-training because a single aggregate SWE-bench number can rise while whole task families silently get worse.

# Q3 Scientific Hypothesis

If SWE training is organized around observable task categories — each category gets its own RL expert that is repeatedly re-grounded in its current mastery (refresh), consolidated on its own verified successes (repair), and pointed at a newly informative task frontier (expand), and the experts are then distilled into one student on the student's own trajectories with only each teacher's *improving* direction extrapolated — then the single student should beat both pooled and category-balanced joint RL on aggregate resolution *and* on the weakest category. A secondary hypothesis tested first: simply balancing category counts in one training stream will not remove the see-saw.

# Q5 Key Solution Idea

Four components, in pipeline order:

* **SWE Labeler.** An evidence-grounded hierarchical labeler (run with Qwen3.7-max) that tags each issue-change instance or agent trajectory on two semantic axes (Task Type: 26 L1 / 119 L2 labels; Repository Domain: 21 L1 / 108 L2 labels) and three four-level scale axes (modification scope, cognitive complexity, estimated resolution time). Every fine-grained label is a decision record tying an authoritative source (ISO/IEC 25010, ISO/IEC/IEEE 14764, MITRE CWE, Fowler's refactoring catalogue, framework docs) to an operational rule, positive signals, and boundaries with neighbouring labels. A deterministic rule coarsens 18 routable Domain L1 families into three routes: **A** service/data/security, **B** user-facing applications, **C** systems/tooling/runtimes.
* **Agentic-miniRL.** MiniRL's behavior-corrected token surrogate, adapted for long multi-turn SWE trajectories: RLOO leave-one-out advantages (so a rare success in a mostly failing group is not shrunk by a self-inclusive mean), the K1 reference log-ratio placed in the token reward *before* return-to-go, truncated importance weights plus a sign-aware proximal mask, and a turn-aware loss that sums tokens within each assistant turn and then averages turns and trajectories.
* **Refresh-Repair-Expand (RRE)** per category expert. *Refresh*: re-estimate per-instance pass rates with fresh rollouts after each RL and each SFT phase, because mastery is a property of a policy-instance pair and drifts. *Repair*: SFT on the expert's own verifier-approved trajectories from the preceding RL phase, with more replay for low-mastery instances (4 / 3 / 2 / 1 trajectories for 0-1 / 2 / 3 / 4 successes out of 4). *Expand*: add previously excluded base-zero and base-one tasks, re-probe them, and keep for the next RL phase only the informative frontier plus currently unsolved tasks with historical success evidence.
* **Label-routed MOPD with ReLU-gated extrapolation.** The student (re-initialized from the base) rolls out on a category-balanced task mix; each task queries only its category's expert. The per-token advantage is the imitation term (teacher minus rollout log-prob) plus λ·ReLU(teacher minus reference log-prob). The ReLU keeps only tokens where the expert improved over the shared base. Without it, positive and negative extrapolation terms largely cancelled in the authors' runs. Integration is pure distillation: the environment reward does not enter the student loss.

# Q6 Experiment Design

* **Research questions.** RQ1: does Balanced RL remove the see-saw seen under Pooled RL? RQ2: do initial category experts suffice, and how does RRE develop them? RQ3: can MOPD merge the experts into one policy that beats both joint-RL baselines overall and in every category?
* **Data.** About 32K executable candidates mined from merged PRs and issues (LLM-rewritten statements, leakage and contamination filters, repeated gold-patch validation). Base-model pass rates in (0, 0.5) select 3,048 synthetic tasks, combined with 3,675 SWE-rebench V2 tasks into a 6,723-task corpus. 2,769 of these map to A/B/C (601 / 516 / 1,652). Pooled RL trains on all 6,723. Balanced RL trains on 516 per category (1,548). Table 4 gives per-phase repair and expansion counts.
* **Evaluation.** Primary: **Pro-618**, the 731-task SWE-bench Pro minus 113 tasks flagged by a public determinacy audit (83 mechanical specification defects, 26 underspecified grading choices, 3 reference patches failing grader replay) and one OpenAI-documented prompt-test mismatch. It splits into Pro-A/B/C = 221/201/196. Secondary: SWE-bench Multilingual (300 tasks, SWE-agent scaffold; A/B/C/unassigned = 72/25/176/27). Endpoints are the mean and population SD over three rounds, one trajectory per task per round, full denominators (failures and integrity violations score zero).
* **Metrics.** Full resolution, per-category resolution, minimum category gain, the *see-saw gap* (Full gain minus minimum category gain), minimum category lift over each baseline, and expert-gain recovery (MOPD category gain divided by the expert's gain). Multilingual Full differences get paired instance-bootstrap 95% intervals.
* **Integrity controls.** A pilot audit found agents running `git log --all`, reading future objects, adding upstream remotes, and searching the web for the fix. The protocol therefore sanitizes repositories (removes remotes, non-current branches, post-base tags, reflogs, and unreachable objects), defers test injection, replays only the sanitized source patch in a fresh sandbox, and scans full trajectories for external answer retrieval. Confirmed retrieval scores zero.
* **Not designed in (stated by the authors):** no component ablations (RLOO vs. GRPO, K1 placement, ReLU gate, replay quotas, routing granularity), a single three-route partition, and Pro-618 used both for checkpoint selection and for the final report.

# Q8 Evidence Quality

* **Supported:**
  * *The see-saw and Balanced RL (RQ1).* Pooled and Balanced RL end at almost the same Full score: 55.50% vs. 55.34%, i.e. +2.86 and +2.70 over the 52.64% base. Over 50 checkpoints, balancing raises the average minimum category gain slightly (0.19 vs. 0.08 points) but does not shrink the average see-saw gap (1.18 vs. 1.05). So balancing alone does not fix the see-saw.
  * *Initial experts are not enough (RQ2).* Initial category RL reaches 53.54 / 55.06 / 52.55 on Pro-A/B/C, below the Pooled RL endpoint's 54.75 / 56.72 / 55.10. On matched training records, mean success rises 7.26 / 6.76 / 4.60 points, but 839 of 2,769 records (30.3%) decrease.
  * *Repair recovers regressions.* After the first Repair SFT, training-record success is 56.28 / 59.59 / 52.75%. Of the regressed records that received repair data, 69.8% / 73.0% / 61.3% return to at least the base rate. By the end of RRE, the experts beat the base on their categories by +7.84 / +4.48 / +5.61, and beat the Pooled RL endpoint by 4.83 / 2.16 / 2.38.
  * *One student beats both baselines (RQ3).* MOPD reaches 58.04% Full on Pro-618 (Pro-A/B/C 58.07 / 59.37 / 56.63). That is +2.54 over Pooled RL, and higher in every category: minimum category lift 1.53 over Pooled RL and 2.04 over Balanced RL. Its minimum category gain over the base (4.76) roughly doubles Pooled RL's (2.32) and exceeds Balanced RL's (2.65). Expert-gain recovery is 80.8% / 111.1% / 84.8% on A/B/C.
* **Weaker than the headline suggests:**
  * *Selection and reporting share a benchmark.* Pro-618 selects checkpoints at every RRE phase *and* reports the final comparison. That favors the multi-phase expert pipeline, which gets many more selection opportunities than a single pooled run.
  * *The secondary benchmark is less conclusive.* On SWE-bench Multilingual, MOPD's +2.00 over Balanced RL has a paired bootstrap 95% interval of [−0.78, 4.78], so it is not distinguishable from zero. Category C (176 of 300 tasks) is unchanged vs. base (61.74%). Pooled RL (55.56%) is actually *below* the base (56.22%) on this benchmark (reader observation).
  * *Uniformity claim is mixed.* MOPD's see-saw gap (0.63) is wider than Balanced RL's (0.04). The paper classifies this as "shared improvement with a wider gap", not a more uniform distribution.
  * *Unequal compute.* Three experts, two RL rounds, two SFT rounds, and a teacher-querying distillation stage cost far more than one pooled run. No compute-matched joint-RL baseline is reported, so how much of the gain comes from the category structure versus the extra training is not isolated.
  * *Ablations missing.* The benefit of individual pieces (RLOO, K1-in-reward, the ReLU gate, mastery-weighted replay) is argued, not ablated.
* **Integrity side:** the anti-hacking protocol is a real strength. Replaying a sanitized patch in a fresh sandbox rules out rollout-state tampering. The authors state it does not rule out pretraining memorization.

# Q9 Contributions

* A measurable definition of the **category see-saw** inside one domain (minimum category gain, see-saw gap), and evidence that category-balanced data alone does not remove it.
* **SWE Labeler**, an auditable multi-axis SWE taxonomy with source-to-rule-to-boundary label contracts. It profiles benchmarks differently: SWE-bench Verified is 87.0% bug fixes and 86.2% single-file, while SWE-bench Pro is 47.3% bug fixes and 59.2% cross-module.
* **RRE**, a teacher-free expert-development loop that treats instance mastery as policy-dependent and re-estimates it between phases, with measured recovery of RL-induced instance regressions.
* A working recipe for intra-domain **label-routed MOPD with ReLU-gated extrapolation** that recovers most of three experts' gains in one 27B policy.
* A reusable **reward-integrity protocol** for SWE RL (repository sanitization, deferred tests, fresh-sandbox replay, trajectory scanning for answer retrieval).

# Q10 Next Steps

* **Compute-matched baselines and ablations:** give pooled RL the same total rollouts, SFT-on-own-successes, and selection budget; ablate RLOO vs. GRPO, the K1 placement, the ReLU gate, and the replay quotas one at a time.
* **Held-out selection:** choose checkpoints on a disjoint split so Pro-618 is a clean test set, and report confidence intervals on Pro-618 as well as Multilingual.
* **Soft or multi-label routing:** the authors note tasks can span categories while hard routing assigns one expert. Routing granularity (3 routes vs. the full 18 Domain L1 families) is untested.
* **Why A recovers least:** A has the largest expert gain but the lowest recovery (80.8%); Open-MOPD's budget-imbalance diagnosis is an obvious next probe.
* **Link to harness-level work (reader-constructed):** the see-saw metrics apply equally to harness or skill evolution. Reporting per-category minimum gain alongside aggregate scores would expose the same hidden regressions that [RRSI](2609.24972.md) and [SoL-Pi](2609.20519.md) guard against out of distribution.
* **Project fit (reader note):** RRE's "mastery is a property of the current policy, so re-probe before re-selecting data" rule is a cheap discipline for any iterative agent-improvement loop in this repository.
