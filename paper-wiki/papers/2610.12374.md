# Q1 Problem Definition

* **Input (X):** a *code world*: a scene program $p$ run by a simulator or game engine, which keeps scene state $s_t$ (object poses, articulations, task variables) and camera pose $\pi_t$ and applies agents' actions $a_t$ through $(s_{t+1},\pi_{t+1}) = f_p(s_t,\pi_t,a_t)$; plus an appearance reference image $x_0$ and a text description $y$.
* **Output (Y):** (a) visual observations $x_t = R_\theta(x_{<t}, c_{\le t}, x_0, y)$ generated in real time by a shared neural renderer from structured conditions $c_t = h_p(s_t,\pi_t)$ (colorized depth or surface normals) and visual history; (b) agents that act on those frames alone and improve across rounds by writing playbooks.
* **Core problem:** environments for agent learning need to be *faithful* (consistent state, rules, dynamics) and *realistic* (observations that look like real video). Simulators give the first but need expensive 3D assets for the second; video world models give the second but keep state implicit in generated history, where it cannot be inspected, edited, or tested.

# Q2 Problem Novelty

Partly new. Keeping world state outside a video model and using the model only to render it is an active line the paper cites (state learned jointly with frames, advanced by an engine, or written as code by an agent). The paper's claimed differences are the interface (depth or normals, which any 3D simulator exports and which can be estimated from real video, so one renderer serves many engines), a causal renderer that runs in short blocks in real time so new actions enter throughout a rollout, and the use of the result as a full executable environment in which pretrained agents practice over rounds. The distillation method (Adversarial Forcing) is new as a combination of known parts: Self Forcing-style distribution matching, a two-pass history-gradient replay like Self Gradient Forcing made bitwise exact, and a DMD2/R3GAN-style real-data adversarial loss with an exact R1/R2 computation.

# Q3 Scientific Hypothesis

1. **Separation removes drift from state.** If the engine's transition takes no rendered frame as input, rendering errors cannot accumulate in the world state, and a recorded state trajectory can be re-rendered under another appearance or camera without changing events.
2. **Exact replay matters.** If the differentiable replay of a rollout reproduces the sampled trajectory bitwise rather than approximately, later losses can update how history is written into the cache without the replay diverging from what was sampled.
3. **Real-data adversarial supervision prevents long-rollout decay.** If a real-data adversarial term is added to distribution matching, long rollouts keep texture and detail that score distillation alone loses.
4. **Pretrained agents learn fast in such worlds.** If agents with web-scale priors perceive only rendered frames and carry written lessons between rounds, physical tool-use strategies appear within a handful of rounds rather than the millions of episodes self-play RL needed.

# Q4 Related Work and Key People

Likely critics: video world-model groups (Genie, Matrix-Game), who would ask for quantitative visual and controllability metrics, and RL researchers, who would question the comparison with self-play.

# Q5 Key Solution Idea

* **Split state from appearance.** The engine owns state and rules; the renderer only sees geometry conditions plus $x_0$, $y$, and visual history. Attributes geometry leaves open (color, material) come from the reference and history.
* **Coding agents build worlds.** From a single image, perception tools produce instance masks, monocular depth and intrinsics, 3D boxes, and meshes, and a coding agent fits them into a scene program and extends unseen space; from text, it writes the program with primitives and turns a first render into $x_0$ with an image-editing model. In both cases it checks rollouts from probe cameras and engine queries (contact, collision clearance, occlusion) and repairs the scene. Only coarse geometry is needed.
* **Renderer training in three stages.** (1) Geometry conditioning of Cosmos 3-Nano (36 layers, width 4096; frozen text tower and Wan autoencoder): geometry tokens are concatenated with RGB tokens along the sequence and processed by the same layers, with random depth/normal choice, dropout, texture suppression, warps, and latent noise for robustness. (2) Block-causal teacher forcing with clean and noisy copies of each block under one attention mask. (3) **Adversarial Forcing**: the student generates its own blocks in four steps and is matched to the frozen bidirectional teacher by distribution matching; an *exact replay* pass recomputes history keys and values with gradients using the same block-by-block attention calls as the rollout, so the replay is bitwise identical; and a discriminator head on the frozen teacher's features adds a relativistic real-data loss whose R1/R2 penalty is computed exactly with one vector-Jacobian and one Jacobian-vector product, avoiding double backward through FlashAttention.
* **Streaming inference.** A bounded KV cache (5 sink and 44 recent latent frames when served), rotary positions remapped past the training horizon, custom Triton kernels, CUDA graphs, a distilled tiny decoder, and WebRTC streaming.
* **Rounds of practice.** A task file gives the goal, actions, and limits but no solution; agents act through short Python programs, see only rendered frames (no coordinates, map, or score until the episode ends), then write playbooks (Markdown skill files, one lesson each) that later agents, started fresh, inherit.

# Q6 Experiment Design

* **Renderer.** Qualitative 30-second rollouts with Self Forcing against Adversarial Forcing on the same condition trajectories (Figure 7); replay error, forward time, and memory for an SGF-style full-sequence FlexAttention replay against block-by-block SDPA (one H100, 61 latent frames); steady-state throughput for one served 16-frame block.
* **Training.** 32 H100 GPUs; data from DL3DV-10K scene captures, OpenDV driving video, internet videos of gameplay, navigation, and robot interaction, and a small set of rendered synthetic scenes.
* **Hide-and-seek.** A sequential one-hider, one-seeker variant of the 2019 physics environment; the agent is GPT-6 Astra; each role keeps its own playbook; rounds of five games over sampled layouts and seeds, starting from empty playbooks. Milestones are compared with the 2019 self-play RL study.
* **Four further worlds.** Companion dog (engagement score in a 60 s session), one-lane bridge (two cars, each its own agent, swap ends; seconds), herding (two dogs pen four sheep; score out of 100), quarry loader (push rocks, deliver one to a bunker, park in 360 s; score out of 100). Four rounds each, one episode per round.

# Q8 Evidence Quality

* **Supported.**
  * *Exact replay is exact and not more expensive.* Full-sequence FlexAttention replay differs from the cached rollout by 3.99% relative L2; block-by-block SDPA replay is bitwise identical, with forward time 2.95 s to 2.79 s (-5.4%) and peak memory 50.83 to 50.92 GiB (+0.2%).
  * *Real-time rendering.* One served 16-frame block takes 438.8 ms in total (condition encoding 10.6 ms, four denoising steps and cache publication 414.4 ms, tiny decoder and transfer 8.8 ms): 36.5 frames/s at 480x832 on one H100, measured at steady state with a full cache.
  * *Round-by-round improvement is reported in every world.* Hide-and-seek: panel shelters by round 4, ramp crossings by round 10. Companion dog 13 to 19; bridge 71 s to 41 s; herding 60 to 88.3 (three of four sheep penned, then all four in rounds 2-4); quarry loader 30, 0, 30, 90.9.
* **Weaker or narrower than the headline.**
  * *The "4 rounds versus millions" contrast is not a sample-efficiency result, by the paper's own account.* The abstract compares learning "from just 4 rounds" with "millions" for RL, but Section 5.2 says the numbers reflect different paradigms, not a sample-efficiency ratio: the 2019 agents learned from random weights over privileged object state, while GPT-6 Astra arrives with pretrained knowledge of ramps and walls. The 2019 milestones also come from the original environment, whereas this study uses a sequential one-hider, one-seeker variant of it.
  * *Single runs, no variance, no control.* Each extra world has one episode per round and one run of four rounds; herding dips from 90.1 to 87.6 and the loader goes 30, 0, 30, 90.9, so round-to-round noise is visible and unquantified. No control (fresh agents without playbooks for the same number of rounds, or shuffled playbooks) separates learning from variation in layouts and seeds.
  * *Adversarial Forcing's visual benefit is shown only qualitatively.* Figure 7 shows Self Forcing rollouts developing repetitive patterns and losing detail; there is no quantitative image or video quality metric, no condition-adherence measurement, and no ablation of the adversarial term, exact replay, or R1/R2 on visual quality.
  * *The renderer's effect on the agents is not measured.* Agents never run on engine-rendered frames for comparison, and the paper notes that generated frames need not perfectly realize the supplied state. Whether the neural renderer helps, hurts, or is neutral for agent learning (relative to plain engine graphics) is open.
  * *Geometry-only conditions limit which worlds work.* The authors note that a spinning symmetric object, color, material, and identity are not determined by depth or normals and may be lost after long occlusions or beyond the cache window.

# Q9 Contributions

* A code-world framework: explicit, editable engine state and rules coupled through depth or normal conditions to one shared real-time neural renderer, so new worlds need coarse geometry rather than per-scene visual assets.
* Adversarial Forcing: few-step block-causal distillation combining distribution matching on self-rollouts, bitwise-exact history-gradient replay, and a real-data adversarial loss with an exact, double-backward-free R1/R2 for a frozen-backbone discriminator.
* A real-time serving stack (over 35 fps at 480x832 on one H100).
* A demonstration that pretrained agents seeing only rendered frames improve across rounds through written playbooks in hide-and-seek and four other worlds.

# Q10 Next Steps

* **From the authors.** More compact and complete conditions (structured text about object attributes and interaction state, or latent features) aligned with the code world's state; coding agents that write and revise worlds, with automatic checks that a world is solvable from what the agent sees, that careless strategies fail, and that something learned carries to the next round; experience management across many worlds (which lessons to keep, merge, or drop), using exact reset and replay to test a lesson before passing it on.
* **Controls for the agent study (reader suggestion).** Repeat each world's four rounds several times, add a no-playbook control with the same number of rounds, and report means and spread; replay the agents on engine-rendered frames to measure what the neural renderer changes.
* **Playbook versus raw history (reader suggestion).** [Learn2Play Bench](2610.08215.md) finds that distilled lessons can freeze a wrong rule while raw histories let agents revise it. Code worlds can be reset and replayed exactly, so the two memory formats could be compared here under identical seeds.
* **Project fit (reader note).** The playbook protocol (fresh agent, task file, inherited lesson files written so another reader can check them) mirrors how this repository's agents hand work across sessions; AgentGarten's future-work point that a lesson should be tested by replay before being passed on applies to those handoffs too.
