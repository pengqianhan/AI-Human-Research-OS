# Q1 Problem Definition

* **Input (X):** a fixed corpus of past runs collected without memory, each a task, the agent's trajectory of actions and observations, and a binary success or failure label; then a new test task. No gold solutions or expert explanations exist, so a label does not say which actions caused the outcome.
* **Output (Y):** a memory built once from that corpus, frozen and read-only, plus the agent's behavior on test tasks with the memory available.
* **Constraints:** no extra runs may be spent validating a memory item; every compared method builds from the same no-memory training runs. The goal has two parts that average accuracy mixes together: solve more tasks, and keep solving the ones the agent already solves.

# Q2 Problem Novelty

Not a new observation. The paper cites earlier findings that memory can lower performance, that agents ignore or misread condensed experience, and that continual memory suffers retrieval competition and negative transfer. Methods that control what enters memory also exist: PREPING validates synthetic practice trajectories before storage, [SkillOpt](2605.23904.md) admits skill updates through held-out evaluation, and ReMe updates or removes memories by later utility. What is new is where the check sits. The paper leaves admission alone and gives the acting agent a path back to the source run at the moment it is about to follow a lesson, and it measures harm separately from benefit against a rerun baseline.

# Q3 Scientific Hypothesis

If each lesson stays linked to an account of why its run succeeded or failed and to the raw trajectory, and the agent is told to open those links when the lesson lacks detail, conflicts with another lesson, or comes from a failed run, then the agent will solve more previously failed tasks and break fewer previously solved ones than with the same lessons alone. The stated reason is that a trajectory often still contains the observation that contradicts a wrong lesson.

# Q4 Related Work and Key People

* **Experience-driven procedural memory.** Verbal feedback and stored successes (Reflexion, [ExpeL](../concepts/expel.md)), executable skills (Voyager), guidelines, manuals, and workflows (AutoGuide, AutoManual, [Agent Workflow Memory](../concepts/agent-workflow-memory.md), Memp), and continual reasoning memories and playbooks ([ReasoningBank](../concepts/reasoningbank.md), ACE, ReMe). These build and update lessons; WikiTrace reassesses them during execution.
* **Reliable reuse of unverified memory.** Studies of ignored or misinterpreted experience, negative transfer in continual learning, and amplified unsafe behavior from reused experience; admission and revision methods (PREPING, SkillOpt, ReMe).
* **Memory structure and access.** Hierarchical memories for compression and retrieval; HORMA, which connects filesystem summaries to raw interaction history and learns a minimal sufficient context; active-access methods that decide when to retrieve; Direct Corpus Interaction, which gives corpus access through terminal tools.
* **Key people.** Yukyeong Lee and Yumin Choi (equal contribution), Jinheon Baek, and Sung Ju Hwang at KAIST, with a DeepAuto.ai affiliation listed. Yumin Choi, Jinheon Baek, and Sung Ju Hwang also wrote PREPING. Likely critics are the authors of the adapted baselines, who could object to the offline single-pass protocol (see Q8).

# Q5 Key Solution Idea

Keep the lesson and its evidence together, and let the agent decide when to read the evidence.

1. **Three linked layers.** A compiler reads one run (task, trajectory, outcome) and writes a *compilation*, a diagnosis of the run's key decisions or failure causes with separate templates for successes and failures, plus at most three *insights*. Each insight is its own document stating what to do, when it applies, which run it came from, and whether that run succeeded. The raw trajectory is kept unchanged, and each insight links to both its compilation and its raw run.
2. **No merging, updating, or filtering.** One compiler call per trajectory. Insights are never edited or deleted, so the pool can hold redundant or contradictory lessons; choosing among them is left to the agent.
3. **Test-time access.** The first message contains every insight and names the three past runs whose tasks are most similar to the current one. The memory is mounted as read-only files that the agent searches with `read` and `bash`. The prompt asks it to descend to the source run when an insight lacks the details needed to act, comes from a failed run, or disagrees with another insight, and again whenever an action fails.

The paper's motivating case is an ExpeL rule saying an ALFWorld lamp task ends once the object is beside the lit lamp. The run the rule came from shows the agent picking the object up, which contradicts it.

# Q6 Experiment Design

* **Suites.** Eight suites from five benchmarks: [ALFWorld](../concepts/alfworld.md) seen and unseen, [ScienceWorld](../concepts/scienceworld.md) (ten of 30 task types), PlanCraft seen and unseen, [AppWorld](../concepts/appworld.md) Test-Normal and Test-Challenge, and τ³-bench Retail, which the paper cites to the τ-bench and [τ²-bench](../concepts/tau2-bench.md) papers.
* **Agent.** A Pi terminal agent given each benchmark's ReAct instruction, running deepseek-v4-flash at high reasoning effort for both the agent and the memory builders.
* **Methods.** No Memory; AWM; ExpeL; ReasoningBank; Insights Only, which injects the same insights as WikiTrace but mounts no compilations or trajectories and omits the descent prompt; WikiTrace. The three existing methods use official implementations adapted to an offline protocol: memory is built once from the shared training runs, the true binary outcome replaces LLM judges or environment reward, and each trajectory is read once.
* **Protocol.** Three trials per suite and method, each benchmark's own metric.
* **Gain and Regression.** With B the majority No Memory outcome of a task over three trials, Gain is the success rate with memory on tasks where B is failure, and Regression is the failure rate with memory on tasks where B is success. Three further No Memory trials scored against the same B give a rerun floor. Intervals come from 10,000 task-level bootstrap resamples.
* **Analyses.** An LLM judge (gpt-5.6-sol) classifies the cause of failures on tasks solved in all three no-memory trials; runs are split into Descent and Stay; a judge labels each descent's trigger, target, and effect (Cohen's κ against a second judge, GLM-5.3, is 0.77 on trigger and 0.63 on target); memory built from successes, failures, or both; baselines given three or nine times their build budget; a second backbone, GLM-5.3-flash, on three suites.

# Q8 Evidence Quality

**Main result.** Mean over three trials, averaged over the eight suites:

| Method | Avg. | Note |
|---|---|---|
| No Memory | 79.5 | |
| ExpeL | 80.3 | below No Memory on three suites |
| AWM | 81.6 | |
| ReasoningBank | 81.7 | |
| Insights Only | 87.0 | same insights, no source access, no descent prompt |
| WikiTrace | 90.2 | best on all eight suites |

WikiTrace is the only method at or above No Memory on every suite. Most of its margin over the existing methods is already present in Insights Only (7.5 points above No Memory); source access and the descent prompt add 3.2. Per-suite gaps between the two are often within one standard deviation across trials, for example PlanCraft unseen at 81.3 ± 8.5 against 73.0 ± 10.7. The main table carries no significance test (reader observation).

**Gain and Regression.** Regression is 4.5% for WikiTrace, 6.5% for Insights Only, and 9.7% for the rerun floor; WikiTrace is lower than Insights Only on seven of eight suites and is the only method whose interval lies entirely below the rerun band. Its Gain exceeds the rerun floor by 35 points, against 27 for Insights Only and 7 to 14 for the existing methods. Two reader observations on these numbers:

* The floor shows that rerunning the agent with no memory already flips about one solved task in ten, so most measured Regression is run-to-run variation. The paper's own framing, existing memory methods having Regression "comparable to, or even higher than" a rerun, is the accurate one.
* The per-benchmark counts (Table 6) show how thin Gain is in places: only 10 ALFWorld tasks and 6 τ³-bench tasks are eligible. On τ³-bench WikiTrace's Gain is below Insights Only (2.3 against 2.7 tasks). Pooling the table's counts over benchmarks gives WikiTrace 26.0 regressed of 649 eligible tasks per trial (4.0%) against 39.0 (6.0%) for Insights Only, and 112.7 gained of 172 (65.5%) against 98.0 (57.0%) (reader calculation; the paper averages suites instead).

**Why memory breaks solved tasks.** In 52% of the judged failures the cause traces to a memory item the agent followed, most often a wrong item (20%); the rest show no link to memory. The labels come from an LLM judge reading the agent's stated reasoning, which the limitations section acknowledges.

**When descent helps.** In the three text-world benchmarks the agent opens source material in 22% of runs on Easy tasks and 44% on Hard ones. Descent runs lead Insights Only by 1.6 to 4.7 points more than Stay runs. Descents after a problem (36% of descents) lead by 10.4 points against 3.7 when nothing had gone wrong; routine checks are the most common kind (38%) and add 3.4. The opened run changes the plan in 43% of descending runs, by revising an insight (24%), filling in a detail (14%), or supplying a new fact (4%), and those runs lead by 8.3 points against 4.4. The paper notes that the agent chooses when to descend, so the two groups differ in more than the descent.

**What the ablation isolates.** Stay runs, which never open a source, still lead Insights Only by 0.6 to 12.4 points and report 19 to 28% fewer insights as used. So some of the 3.2-point gap comes from the prompt and the mounted files changing how selectively the agent uses memory, even when no evidence is read. Insights Only removes source access and the descent prompt together, and no arm separates them (reader observation).

**Failed runs.** On PlanCraft and ScienceWorld both methods score higher with failure-only memory than with success-only memory, and highest with both. Insights Only has its highest Regression with failures alone (9.3% and 9.4%); WikiTrace lowers these to 7.1% and 8.9%, a half-point change on ScienceWorld.

**Cost and second model.** WikiTrace costs 1.17 times as much per test task as Insights Only. Giving AWM nine build passes and ExpeL and ReasoningBank three raises them to 83.8, 83.3, and 82.8, still below Insights Only. With GLM-5.3-flash on PlanCraft and ScienceWorld, WikiTrace averages 92.7 against 90.9 for Insights Only and 71.2 for No Memory, and each existing method falls below No Memory on at least one suite.

**Limits on the comparison (reader observations).** The offline single-pass protocol removes parts of the baselines' designs: ExpeL loses its repeated attempts and exemplar retrieval, and ReasoningBank its update after every test task. The memory is small, about 50 runs with at most three insights each, so placing every insight in the first message is feasible here and untested at scale. Both models are fast-tier.

# Q9 Contributions

1. Gain and Regression measured against a no-memory rerun floor, which shows that memory methods can raise average accuracy while breaking solved tasks at about the rate chance does.
2. A cause analysis of memory-induced failures in which about half trace to a followed memory item and a fifth to a wrong one.
3. WikiTrace: insights that stay linked to a run diagnosis and the raw trajectory, with a prompted descent at test time.
4. A same-insights control showing that use-time access to evidence adds 3.2 points and lowers Regression, with the largest effect when the evidence changes the agent's plan.

# Q10 Next Steps

* **Limitations stated by the paper.** Memory is built from binary outcomes, so a compilation's diagnosis may be wrong; a link lets the agent check an insight but does not verify it; the prompt grows with memory, and retrieval for a memory too large to inject is left open; cause and descent labels describe the agent's stated reasoning.
* **Separate the prompt from the evidence.** Run Insights Only with the descent prompt but no sources, and WikiTrace with sources but no prompt (reader suggestion).
* **Write revisions back.** The memory is frozen, so an insight the agent finds wrong stays wrong for the next task. Recording the revision, with its own evidence link, would connect use-time checking to the admission methods the paper sets aside (reader suggestion).
* **Scale.** Test with thousands of runs, where the agent must first find the relevant insights, and with stronger models that may need the evidence less.
* **Project fit.** For a file-based research memory, the design argues for keeping a pointer from every distilled lesson to the session or artifact that produced it, and for treating lessons from failed work as the ones most worth re-checking.
