# Q1 Problem Definition

* **Input (X):** an off-the-shelf, frozen agentic LLM (backbone) and a task.
* **Output (Y):** a synthesized, task-adaptive agent harness `h = (M, P, A, F)` wrapped around that backbone — a memory module, a planning module, an action module, and a tool/skill-orchestration module — plus, over time, repaired and self-evolved successor harnesses drawn from an accumulating archive.
* **Core problem:** agent capability is not determined by the backbone model alone; the surrounding harness (memory management, planning strategy, action protocol, tool/skill orchestration) can dominate the model's own contribution, yet harness design today is manual, task-specific, and does not scale.
* **Scope:** a harness-generation intervention — the backbone LLM's weights are left untouched; JIT-Agent is a separate, dedicated model that produces and revises the harness around it.

# Q2 Problem Novelty

This repository's [agent harness engineering](../topics/agent-harness-engineering.md) topic already contains several papers that treat the harness as a single object refined during one deployment: LongHorizon-Harness splits one fixed role structure (manager/executor/auditor) around existing backends; StateM externalizes state into one versioned YAML runbook; AutoSaddler and Recuris each diagnose and patch one running harness from execution traces; Prime Agent exposes more addressable state (L0-L3) within one persistent harness for the model itself to revise. JIT-Agent's novelty is treating harness *construction* itself as a trainable, transferable skill: it formalizes any agent harness as a fixed, composable four-module protocol `h = (M, P, A, F)`, builds a shared implementation substrate (HarnessFactory) that reimplements 13 existing named harness designs (ReAct, Plan-and-Execute, ReSum, Flash-Searcher, General Agentic Memory, MemoBrain, AggAgent, OAgent, AgentFold, HiAgent, DeepAgent, ROMA, AOrchestra) under that one protocol, and trains a dedicated model to synthesize, repair, and self-evolve new harness instances on the fly for arbitrary off-the-shelf agentic LLMs — rather than hand-designing or incrementally patching one fixed harness per system.

# Q3 Scientific Hypothesis

If harness construction, repair, and evolution are each learned as explicit capabilities of a dedicated model — rather than performed by hand or fixed at design time — then that model can synthesize task-adaptive harnesses for arbitrary frozen backbone LLMs that outperform both the backbone's own default fixed harness and hand-designed alternative harnesses, transfer across model families, and keep improving through an accumulating archive of prior harness designs — establishing "harness intelligence" as a trainable dimension of agent capability that compounds independently of backbone model scaling.

# Q5 Key Solution Idea

* **Four-module harness protocol:** `h = (M, P, A, F)`. `M` (Memory) compresses history and maintains controller state (e.g. full history, summarized retrieval, hierarchical organization). `P` (Planning) forms a local directive from the task, state, and current view (e.g. DAG planning, todo lists, a null planner). `A` (Action) updates state and emits actions through the frozen executor (e.g. ReAct-style loops, recursive execution). `F` (Orchestration) selects capabilities — tools and skills — from a registry given the current directive.
* **HarnessFactory:** a unified codebase reimplementing the 13 named systems above under this one protocol, turning them into comparable, interchangeable points in one design space rather than fixed, incommensurable baselines.
* **Three-stage training pipeline for JIT-Agent itself:**
  1. **Customization:** a teacher model generates protocol-compliant harnesses per task; JIT-Agent is supervised-fine-tuned on the accepted generations, then preference-trained over reward/latency/cost trade-offs.
  2. **Repair:** failed harnesses and their execution diagnostics are converted into bounded (at most 2 rounds) repair trajectories; JIT-Agent learns to propose small, high-leverage revisions directly from error messages.
  3. **Evolution (Evo-GDPO, Evolutionary Group-Decoupled Policy Optimization):** JIT-Agent proposes new harness candidates that are evaluated against an archive of prior harness designs; a candidate is retained only when it advances the Pareto frontier on reward, latency, or cost — self-evolution gated by archive-relative dominance rather than a single scalar reward.
* At deployment, this supports a **streaming** mode that retains and reuses harnesses across a stream of tasks (versus a **static** mode that resynthesizes per task).

# Q6 Experiment Design

Backbones span open models (DeepSeek-V4-Flash/Pro, GLM-5.2, Qwen3.6-Flash/Plus, Mimo-V2.5-Flash/Pro) and frontier closed models (GPT-5.6, Gemini 3.1 Pro, Gemini 3.5 Flash), evaluated on 9 benchmarks (0-100 scale) across four categories: Deep Research ([BrowseComp-Plus](../concepts/browsecomp-plus.md), DeepSearchQA, xBench-DS), Daily Work (AgentIF-Oneday, PinchBench), Planning (DeepPlanning-Shopping, DeepPlanning-Travel), and Workspace (OfficeBench, OdysseyBench). Two comparison axes: (a) vanilla backbone vs. JIT-Agent-equipped backbone vs. other frontier models (Table 3); (b) a controlled comparison holding the backbone LLM fixed and varying only the harness — JIT-Agent-generated vs. the five fixed harnesses (Claude Code, Codex, OpenCode, Hermes, NanoBot) — reporting quality jointly with token count and dollar cost (Table 4). A generalization check (Figure 5) runs 24 comparisons of JIT-Agent vs. plain ReAct across 3 model families x 2 size variants x 4 benchmarks. A test-time-evolution check (Figure 6) compares streaming JIT-Agent (retaining harnesses across a task stream) against static JIT-Agent on cumulative accuracy across DeepPlanning-Shopping, DeepPlanning-Travel, and OfficeBench. Two qualitative case studies visualize harnesses JIT-Agent actually synthesized: "Palimpsest" for artifact-production tasks (a GraphPlan module turning a cross-app task into an explicit DAG with bounded execution width/depth, memory storing intermediate artifacts) and "Trapdoor" for deep-research tasks (a DynamicDecomposer with a delegated subagent research tool, plus a FactGraphMemory extracting key-value facts for multi-hop evidence integration).

Headline results as retrieved: DeepSeek-V4-Flash + JIT-Agent reaches 85.1 on DeepSearchQA (vanilla backbone 76.2; GPT-5.6 76.0) and 82.0 on xBench-DS (vanilla 70.1). GLM-5.2 + JIT-Agent reaches 93.9 on DeepSearchQA (the top score reported across the paper's tables), 88.0 on xBench-DS (vanilla 76.0, +12.0), 69.9 on AgentIF (vanilla 63.0, +6.9), 93.3 on PinchBench (best overall), and 83.0 on DeepPlanning-Travel (vanilla 62.8, +20.2). On BrowseComp-Plus specifically, JIT-Agent+GLM-5.2 scores 78.0 and JIT-Agent+DeepSeek-V4-Flash scores 74.0, against a spread of 67.5-76.9 for the nine other backbones/frontier models reported in the same table (best: GPT-5.6 at 76.9). In the controlled same-backbone comparison (DeepSeek-V4-Flash), JIT-Agent improves on the strongest fixed harness by 4.7 points on DeepSearchQA (85.1 vs. 80.4, NanoBot) and 4.0 points on xBench-DS (82.0 vs. 78.0), each at lower cost (e.g. 400K tokens / $0.066 vs. NanoBot's 924K tokens / $0.131 on DeepSearchQA; OpenCode scores 75.9 on DeepSearchQA, 65.0 on xBench-DS, 48.1 on AgentIF for context); on AgentIF it trails Claude Code by 3.1 points (63.8 vs. 66.9) while costing about 14.9% less ($0.097 vs. $0.114). On Qwen3.6-Flash, JIT-Agent strictly dominates on AgentIF (58.3, at a minimum cost of $0.078 vs. $0.170 for the prior best) and cuts cost 51.8% on xBench-DS relative to NanoBot. Across the 24-comparison generalization check against plain ReAct, the average gain is 7.6 points (per-family averages: DeepSeek V4 +10.2, Qwen 3.6 +4.0, Mimo 2.5 +8.6). Streaming JIT-Agent consistently outperforms static JIT-Agent on cumulative accuracy across the three streaming-evaluated benchmarks. Average cost reduction across six controlled settings versus the cheapest fixed baseline is 36.0%, with the single largest reduction at 54.1% (Qwen3.6 on AgentIF, $0.170 to $0.078).

# Q8 Evidence Quality

The Table 4 comparison is reasonably well controlled — it fixes the backbone LLM and varies only the harness, against five real fixed harnesses including Claude Code, Codex, and OpenCode, reporting quality jointly with token count and dollar cost rather than quality alone — and the 24-comparison generalization check (Figure 5) spans three model families rather than one favorable pairing. The paper is also transparent about a case where JIT-Agent loses to a fixed harness (AgentIF vs. Claude Code, -3.1 points) rather than reporting only wins. However, no ablation isolating the marginal contribution of each of the three training stages (Customization, Repair, Evolution) was found in the retrieved text, so it is not established from the paper itself how much of the reported gain comes from Stage I's supervised fine-tuning and preference learning alone versus the Stage II repair loop or the Stage III archive-gated Evo-GDPO stage; no explicit Limitations section was found either. **Fidelity note:** the HF CLI's `papers read` command returned only a page-chrome/logo fragment for this paper rather than body text, so the full paper was retrieved as an AI-summarized rendering of the arXiv HTML page instead; the figures above should be read as that retrieval's best-effort transcription of the source tables rather than a direct read of the PDF.

# Q9 Contributions

1. Formalizes the agent harness as a fixed, composable, machine-generatable four-module protocol `h = (M, P, A, F)` and reimplements 13 existing named harness designs under it (HarnessFactory), turning them into comparable, interchangeable points in one design space instead of ad hoc fixed baselines.
2. Trains a dedicated "harness intelligence" model through a three-stage pipeline — supervised customization from a teacher, bounded repair from execution diagnostics, and archive-gated Evo-GDPO self-evolution — that synthesizes, fixes, and improves task-adaptive harnesses for arbitrary frozen backbone LLMs at inference time.
3. Empirically demonstrates gains across nine benchmarks and multiple open and frontier backbone families, generally outperforming both the same backbone's fixed default harness and hand-designed alternative harnesses (including Claude Code, Codex, and OpenCode) at lower token cost in most matched comparisons, plus a streaming test-time-evolution mode that keeps improving across a stream of tasks.

# Q10 Next Steps

* The paper does not report an ablation isolating each of its three training stages, so it remains open how much of the reported gain is attributable to supervised customization alone versus the repair loop or the archive-gated evolution stage — a natural follow-up experiment.
* JIT-Agent explicitly trails Claude Code on one benchmark (AgentIF, -3.1 points) despite lower cost; understanding what a mature, hand-designed harness captures that a learned, per-task-synthesized harness currently does not would sharpen the harness-intelligence framing.
* **Research-OS fit:** this is a sharp complement to this repository's other [agent harness engineering](../topics/agent-harness-engineering.md) entries — rather than patching one fixed harness over the course of a deployment (StateM, AutoSaddler, Recuris) or exposing more addressable state within one persistent harness (Prime Agent), JIT-Agent trains a transferable model that manufactures a fresh harness per task for any off-the-shelf backbone, treating "harness design skill" itself as the trainable, transferable artifact — worth comparing against how this repository's own project templates and skill-selection choices are currently made by hand rather than learned.
