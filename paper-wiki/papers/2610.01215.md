# Q1 Problem Definition

* **Input (X):** structured specifications of a GUI world (operating system, screen geometry and action space; visual appearance; initial interface state such as windows, layout, and visible controls), with no running software behind them.
* **Output (Y):** screenshot-action-screenshot trajectories with grounded click targets, converted into single-step training samples (pre-action screenshot, task, recent history → action description and tool call) for a screenshot-based GUI agent.
* **Core problem:** trajectory diversity is limited by which environments can be deployed. Scientific, CAD, electronic-design, and creative software each need installation, configuration, state preparation, and sometimes licenses or accounts. Human demonstrations, automated exploration, and tutorial or video mining all stay tied to software someone already ran.
* **Formal framing:** GUI interaction is a POMDP whose latent state (the full computer configuration) the agent never sees; it sees only screenshots. Because a screenshot agent's training data depends only on the observation-level transition P(s̃_{t+1} | h_t, a_t), the authors aim for **interaction fidelity**: the generated next screenshot should match what a real system would show after the same history, without reconstructing the latent state at all.

# Q2 Problem Novelty

Partly new. GUI world models already exist as executable programs, textual or structured state predictors, learned visual predictors, and code that renders predicted interfaces, and generative pipelines build executable environments with tasks and verifiers. The new part is using a general pretrained image generator as the transition model for *training data*, with a planner fixing task logic in advance, grounding supplying click coordinates, and transition-level quality control, and then testing whether agents trained on the result improve in real environments.

# Q3 Scientific Hypothesis

If a planner specifies what each atomic action should change and a pretrained image generator edits the current screenshot to show that change, the resulting trajectories, once grounded and filtered, carry enough correct interaction structure that fine-tuning on them improves a GUI agent's execution and grounding in real desktop and scientific software, including applications never deployed for data collection.

# Q4 Related Work and Key People

* **Trajectory collection:** human demonstrations on websites and mobile devices, record-based extraction from tutorials and screen recordings, automated exploration and task synthesis, large-scale collections used for training (for example UI-TARS and OpenCUA/AgentNet), and generated executable environments.
* **GUI world models:** executable or learned transition predictors, text-based lookahead, imagined rollouts for policy improvement, visual next-screenshot predictors, and code-based renderers; Gabeur et al.'s "image generators are generalist vision learners" for the image-prior idea.
* **Benchmarks:** [OSWorld](../concepts/osworld.md), Windows Agent Arena, macOSWorld, ScienceBoard, and [ScreenSpot-Pro](../concepts/screenspot-pro.md).
* **Key people:** the Hunyuan AI Data Team (Tencent Hunyuan per the Hugging Face organization tag). Core contributors Cheng Yang and Yifan Wu; supervisors Tianwen Jiang, Jihong Zhang, and Yuyu Luo.

# Q5 Key Solution Idea

* **Structured world sampling and seed realization.** An initial scene is sampled from three factors (OS substrate, visual appearance, initial GUI state), compiled into a detailed description, and rendered by gpt-image-2 ("Image2") into the seed screenshot. The seed metadata is kept so that tasks and plans stay consistent with what is on screen.
* **Seed-conditioned tasks.** Tasks are generated after the seed, from its visible elements, so they do not refer to absent windows or applications. A task registry discourages near-duplicates. The same interface also supports benchmark-derived tasks, mapping benchmark metadata onto the seed sampler (for example pinning the required foreground application).
* **Planner, Voyager, and Image2.** A Meta Planner writes the whole atomic action sequence first, each step with its intent, target element, and expected visual change. At each step, Voyager looks at the current screenshot and the planned action, writes the agent's first-person thought and an action summary, and writes a rendering prompt for the after-action screen; Image2 edits the current screenshot accordingly. The planner decides *what* happens; the image generator decides *how it looks*.
* **Grounding and quality control.** LocateAnything maps each target description to a box whose center becomes the click label. A Gemini VLM checker judges each step on target existence, box accuracy and tightness, action validity, and whether the before/after change matches the action. Bad boxes are re-grounded (3,390 of them), steps with absent targets or invalid actions are removed, and transitions that fail the consistency check are filtered out.
* **Training samples.** Each sample is the clean pre-action screenshot, the task, and a two-level history (the last five steps with screenshots, the five before as text only), supervised on the action description and tool call.

# Q6 Experiment Design

* **Data:** 79,266 step samples: Chrome 35,209, Ubuntu 24,250, Windows 14,778, macOS 5,029; 31 Ubuntu, 45 Windows, and 16 macOS applications and 67 websites.
* **Data analysis:** visual alignment with real screenshot corpora (ScaleCUA, AgentNet, aria_ui, WebSTAR, Mind2Web, OS-Atlas) through MMD in Qwen3.5-9B visual-token space and DINOv2, classifier two-sample tests, low-level patch statistics, OmniParser UI coverage, and trajectory statistics.
* **Training:** full fine-tuning of Qwen3.5-35B-A3B (the vision encoder frozen) for three epochs on 32 GPUs, giving AGW-35B; six checkpoints of one run are evaluated.
* **Evaluation:** OSWorld (361 tasks, Google Drive tasks excluded) and Windows Agent Arena (154) as mean task score with partial credit; macOSWorld (231 English tasks) and ScienceBoard (143 tasks; the Lean domain excluded for documented task defects) as success rate; up to 100 steps per task. ScreenSpot-Pro grounding on 1,581 English examples.
* **Comparison:** the base model; and a Qwen3.5-35B-A3B run on about 350k AgentNet human-demonstration examples, evaluated under the same task sets but with thinking enabled.

# Q8 Evidence Quality

* **Supported:**
  * *Gains on all four interactive benchmarks.* OSWorld 33.0 → 40.8, Windows Agent Arena 19.4 → 27.9, macOSWorld 28.1 → 45.0, ScienceBoard 14.0 → 32.2 (20 → 46 tasks); the equal-weight mean rises from 23.6 to 36.5 and increases at every evaluated checkpoint. Across the four benchmarks, 25 of 35 domains improve, 7 are unchanged, and 3 decline. On OSWorld, multi-app tasks rise from 12.0 to 20.9 and account for the largest share of the gain.
  * *Grounding.* ScreenSpot-Pro accuracy rises from 31.7 to 57.1, with icons 16.2 → 32.9 and text 41.2 → 72.0, improving in all six application domains.
  * *Against real human demonstrations.* With about 80k synthetic samples, AGW-35B beats the best AgentNet checkpoint (about 350k examples) on all four benchmarks, most on ScienceBoard (32.2 vs. 16.8).
  * *Measured transition defects.* The VLM audit flags 1,293 of 42,526 desktop transitions as inconsistent with the action (3.04%), and 818 of 39,351 (2.08%) after removing steps with invalid actions or grounding. Error rates depend on the action: 7.58% for drag, 7.09% for scroll, 6.35% for text entry, 0.67% for clicks. The failure types (substituted terminal commands or values, skipping ahead to a finished artifact, missing effects, unintended edits to persistent content) are documented with examples.
  * *Visual alignment.* The synthetic-to-ScaleCUA distance in Qwen feature space is 0.59-1.24 times the typical distance between two real datasets, and UI coverage exceeds ScaleCUA's in all twelve domain-threshold comparisons.
* **Weaker or bounded:**
  * *The only baselines are the base model and one AgentNet run.* No other GUI agent of similar size is compared in the retrieved text, and the AgentNet run uses thinking where AGW-35B does not, which the authors flag.
  * *No ablation separates the world model from the grounding labels (reader note).* Click labels come from LocateAnything, a dedicated grounding model, so much of the ScreenSpot-Pro gain may be grounding distillation. Training only on seed screenshots with grounded targets, without generated transitions, would show what the multi-step trajectories add.
  * *Possible task overlap with the benchmarks (reader note).* The pipeline can derive tasks from benchmark metadata, but the retrieved text does not say whether any of the 79,266 samples came from OSWorld, Windows Agent Arena, macOSWorld, or ScienceBoard metadata, or report an overlap check. If they did, the transfer would be closer to in-distribution than the framing suggests.
  * *Almost no failure or recovery data.* Rendered terminal states are almost always successful (rollout failure 0-0.68%), and the precondition and blocker fields are zero throughout the release, so the data shows planned success paths rather than errors and recovery.
  * *Regressions in the largest domain.* Chrome supplies 44% of the samples, yet Chrome tasks fall on OSWorld (39.0 → 26.0) and on Windows Agent Arena (11.2 → 0.0); macOSWorld safety tasks also fall (20.7 → 17.2).
  * *Synthetic images remain detectable.* A classifier separates synthetic from real screenshots with AUC about 1.00, though real datasets are also separable from each other (0.95-1.00), and DINOv2 shows a clear visual gap on Ubuntu.
  * *One training run, one evaluation per checkpoint,* with no variance. OSWorld and Windows Agent Arena scores fluctuate between checkpoints.

# Q9 Contributions

* A planner-plus-image-generator pipeline that produces GUI trajectories without deploying the software, with seed-conditioned tasks, closed-loop screenshot editing, grounding, and VLM-based transition filtering.
* A curated set of 79,266 grounded step samples across Ubuntu, Windows, macOS, and Chrome, with an analysis of visual alignment, coverage, and a measured, action-specific transition error rate.
* Evidence that fine-tuning on such data improves a 35B MoE agent on four real-environment benchmarks and a professional-interface grounding benchmark, and beats a run on four times as many real demonstration samples.

# Q10 Next Steps

* **The authors' plan:** generation errors may accumulate over longer trajectories; train image generators on domain-specific interactions to build "vertical" GUI world models for particular software.
* **Ablate the data sources (reader note):** compare training on (a) grounded seed screenshots only, (b) full generated trajectories, and (c) trajectories with the 2-3% inconsistent transitions left in, to measure what the world model and the filtering each contribute.
* **Generate failure and recovery steps (reader note):** the planner currently scripts success paths. Asking it for erroneous actions and their visible consequences, followed by corrections, would test whether synthetic data can also teach recovery, which long-horizon and multi-app tasks need.
* **Report benchmark-overlap checks (reader note):** state which tasks, if any, were derived from evaluation-benchmark metadata, and re-evaluate with those removed.
* **Relevance to this repository (reader note):** the split between a planner that fixes intended state changes and a generator that renders them, with a literal before/after consistency check, is a general pattern for synthetic agent data; the measured action-dependent error rates (text entry and drag far worse than clicks) indicate where such checks are most needed.
