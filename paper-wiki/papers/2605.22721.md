# Summary

This paper introduces DecentMem, a decentralized memory framework for self-evolving multi-agent systems. Rather than sharing a single central memory repository across all agents, each agent maintains its own dual-pool memory: an **exploitation pool** of consolidated past trajectories, and an **exploration pool** of LLM-generated candidate responses for unseen contexts. An LLM-as-a-judge reweights the two pools online using stage-wise feedback.

The motivation is that centralized memory creates communication and coordination overhead, raises privacy concerns, and collapses agent diversity over time.

# Key Ideas

* Each agent keeps independent memory, eliminating cross-agent coordination overhead and preserving behavioral diversity.
* Dual-pool design separates exploitation (reliable past solutions) from exploration (LLM-generated candidates for new contexts), allowing dynamic adaptation.
* LLM-as-a-judge provides online reweighting of the two pools based on stage-wise performance feedback.
* Theoretical analysis proves global reachability of the solution space and O(log T) cumulative regret, matching the stochastic bandit lower bound up to constants.

# Method

DecentMem assigns a dual-pool memory to every agent independently. During inference the agent queries both pools, and the LLM-as-a-judge scores each candidate to determine the pool mixing weight. Memory consolidation happens locally, avoiding synchronization across agents.

# Experiments

* Tested on three MAS frameworks: AutoGen, DyLAN, AgentNet.
* Backbone models: Qwen3 (4B / 8B / 14B) and Gemma4 (E2B / E4B).
* Five benchmarks spanning math, code, QA, and embodied tasks.
* Improves average accuracy by up to 23.8% over the strongest centralized memory baseline.
* Improves by up to 52.5% over a no-memory baseline.
* Reduces token usage by up to 49% relative to centralized memory.

# Limitations

* Results depend on the quality of LLM-as-a-judge signals; a weak judge may misweight the two pools.
* The exploration pool relies on LLM generation for unseen contexts, which may introduce hallucinated candidates.
* Evaluation uses Qwen3 and Gemma4 families; generalization to other model families is not directly tested.

# Notes

Reading questions:

* How does the judge decide what counts as "stage-wise feedback" — is it task-level reward, step-level critique, or something else?
* How do the exploitation and exploration pools interact when a context is only partially covered by past trajectories?
* Does per-agent memory lead to inconsistent agent behaviors in tasks that require tight coordination?
* How does DecentMem compare to 2606.10662 (DeLM), which uses decentralized agents with shared verified context instead of per-agent memory?
