# Q1 Problem Definition

* **Input (X):** a personal agent (a backbone LLM inside a harness such as OpenClaw, Claude Code, or Codex) that runs alongside a user over several days, with access to the user's records (messages, documents, calendar) and tools, a simulated clock with the user's active and sleep periods, and limited shared resources (GPU time, token quotas).
* **Output (Y):** the agent's proactive behavior over time: which unrequested needs it pursues, when it computes and when it presents the result, and at what intervention depth (prepare, suggest for review, or execute without confirmation), including choosing to do nothing (NOOP).
* **Core problem:** proactive help is not automatically useful. Correct work can be irrelevant, poorly timed, compete with the user's own work for compute, or exceed what the user lets the agent do, and repeated misjudgments erode trust. The paper asks what principles should govern proactive agents, what design choices and system components realize them, and how to evaluate the consequences of proactive actions across interactions rather than on one static request.

# Q2 Problem Novelty

Partly new. Mixed-initiative interaction (Horvitz, 1999) and personal-assistant research (Myers and Yorke-Smith, 2007) already weigh the benefits of acting against interruption cost and uncertainty; trust-aware dialog work (Kraus et al.) models user trust separately from task reward; sleep-time compute (Lin et al., 2025) and idle-time preparation (ProAct) use spare compute for anticipated needs. Recent benchmarks (ProactiveBench, ContextAgentBench, ProAgentBench, PROBE, PARE-Bench, KnowU-Bench, ProPerSim, VibeLifeBench) test need prediction, timing, or task success. The new part is combining these into three jointly evaluated objectives for LLM agents, with Table 2 arguing that no prior benchmark operationalizes temporal allocation and few model trust separately, and building a dynamic testbed in which earlier actions change later tasks, resources, and the simulated user's trust.

# Q3 Scientific Hypothesis

1. **The objectives come apart.** If agents are scored separately on task capability (TC), temporal allocation (TA), and trust (TR), gains in TC will not carry over to TA or intervention-depth agreement (TR-D) (Figure 6c).
2. **Current agents cannot defer.** If a scenario contains two competing tasks where only one needs attention now, agents will pick the urgent one far more often than they explicitly defer the other (Table 9).
3. **LLM judges conflate trust with competence.** If LLM judges rate trust from interaction histories, their ratings (TR-J) will track TC more than intervention-depth alignment, unlike human judgments (Sections 5.2 and 5.3).
4. **Humans value timing and alignment, not only correctness.** If people compare agents, they will reject correct help that competes with ongoing work, accept imperfect help scheduled for sleep time, and lose trust after a single misaligned intervention even when the outcome is correct (Figure 7).

# Q5 Key Solution Idea

* **3T objectives.** Task Capability: anticipate relevant needs and do the work correctly. Temporal Allocation: allocate compute over *interaction time* and *sleep time* according to resource availability and when results are needed, deciding both when to compute and when to present. Trust: sustain the user's confidence and appropriate reliance, estimated through the behavioral proxy of *intervention depth* (how far the user lets the agent proceed). The paper writes the combined target as a weighted sum of the three scores but never sets or optimizes the weights.
* **Design space.** Five dimensions: task scope (within-task or out-of-task), anticipation horizon (immediate, within-interaction, out-of-interaction), activation trigger (user, event, or agent), processing timing (interaction or sleep time), and intervention depth (prepare, suggest, execute).
* **System realization.** Situation modeling builds a representation of the user (goals, attention, preferences, trust) and environment (task progress, deadlines, resources), separating observed facts from inferred states; the backbone and harness then choose actions, including deferring work, allocating compute, presenting or applying results, or NOOP.
* **Proactivity-Gym.** Ten hand-authored scenarios of 7-10 simulated days (research, travel, living, food, career, business, education, finance, shopping, health), 10-19 tasks each and 124 in all, with latent needs, conditional branches, NOOP cases, and one competing-task decision window per scenario. Each scenario has three personas (Reviewer, Planner, Operator) that differ in the intervention depth they want per task. The user simulator is Qwen 3.8-27B, but a deterministic state machine decides approve, decline, or defer from the requested actions, time, persona, history, and trust state, so the generated reply cannot grant extra permission.

# Q6 Experiment Design

* **Configurations.** Nine models (GPT 5.6 Luna and Sol, Claude Sonnet 5 and Opus 5, Qwen 3.5 2B/9B/27B, Gemma 4 12B/31B) across OpenClaw, Claude Code, and Codex, giving 23 combinations (open models on all three, GPT on Codex and OpenClaw, Claude on Claude Code and OpenClaw). Reasoning is off in the main runs. Each configuration runs 10 scenarios × 3 personas × 3 repetitions = 90 runs (2,070 trajectories in all).
* **Metrics.** TC (0-100): rule-based Evidence, Outputs, and Constraints checks plus LLM-judged Semantics (correctness, grounding) and Completion (completeness, artifact quality), task-weighted. TA (%): a run scores 1 only if, within the decision window, the agent both attends to the urgent task now and explicitly defers the other. TR-D (%): share of active tasks where the chosen depth matches the persona's expected depth. TR-J (1-5): judge ratings of the five trust constructs at each task's last turn. Judges are Qwen 3.8-27B and Gemini 3.8-Flash, averaged, with cited quotes checked against the trajectory.
* **Extra analyses.** Judge agreement (Tables 4-6), reasoning effort for GPT 5.6 Sol on Codex (low to xhigh), scenario and persona variation, and component breakdowns (Tables 8-10).
* **Human study.** 30 participants (8 undergraduates, 16 graduate students, 6 professionals, all frequent LLM users) review 14 scenario vignettes, mostly adapted from the gym: four week-long trust logs rated at Days 2, 4, and 7, four TR pairwise comparisons, three TA, and three TC comparisons, with 20,000-sample bootstrap intervals.
* **Not designed in.** No human judgments of the same gym trajectories the LLM judges scored; no real compute budgets (resources are scripted constraints); TA covers one decision window per scenario.

# Q8 Evidence Quality

* **Supported.**
  * The gap between task capability and the other objectives is consistent: Claude Opus 5 averages 65.1 TC but 51.7% TA and 52.4% TR-D; every other model is below 20% TA, with TR-D between 39% and 51%. Agents pick the urgent task 44.32% of the time but explicitly defer the competing one only 10.8%.
  * Under-intervention is common: when the persona expected execution, 77.21% of cases ended without a valid execution attempt (45.96% for Claude Opus 5).
  * Harness effects are real and model-dependent: moving open models from Claude Code to OpenClaw changes TC by -11.1 (Gemma 4 12B) to +0.5 (Qwen 3.5 27B), and for Claude Opus 5 the same move raises TA by 21.1 points while lowering TR-D by 3.8.
  * The two judges rank configurations almost identically (TC ρ = .999 after aggregation), so the ranking does not depend on judge choice even though absolute scores do (Gemini gives about .17 higher TC components).
  * The human-study effects are large: correct content preferred in 92.2% of comparisons; with equal content, depth-aligned agents preferred in 88.3%; acceptance rises from 26.7% for correct help that competes with ongoing work to 97.8% for imperfect sleep-time help (Appendix G.5 reports a paired increase of 67.7 points, 95% CI 52.2-82.2); trust falls 1.86 points after an aligned-to-misaligned transition but rises only 1.27 after the reverse, and in the aligned-misaligned-aligned log it recovers to 3.43 from 4.43.
* **Weaker or narrower than the headline.**
  * The claim that LLM judges "overlook" misalignment is indirect. It rests on TR-J correlating with TC (r = 0.70) more than with TR-D (r = 0.23), and on high TR-J for agents with low TR-D, compared with humans who rated *different*, hand-written vignettes. No study has humans and LLM judges rate the same trajectories.
  * TA is coarse: one binary decision per run from one window per scenario, so each configuration's TA reflects ten conflicts. It also requires *explicit* deferral, and the two judges agree on the exact NOW/LATER label with only κ = .438, so TA differences of a few points are not meaningful.
  * Resource constraints are scripted, not real; TA measures stated prioritization rather than actual compute use.
  * The simulated user's trust and approvals come from a deterministic state machine the authors designed, so TR-D measures agreement with the authors' persona rules.
  * The human study uses vignettes read by 30 frequent LLM users (paid KRW 10,000; comments translated from Korean), not people using a proactive agent over real days; preferences may differ in lived use.
  * Harness comparisons are partly confounded, since GPT and Claude models were each run on only two of the three harnesses.
  * The weighted 3T objective is stated but not used to rank agents or to set trade-offs.

# Q9 Contributions

* A definition of proactivity and three jointly required objectives (task capability, temporal allocation, trust), with intervention depth as an observable proxy for trust.
* A five-dimension design space and a situation-plus-system modeling layer for building proactive agents.
* Proactivity-Gym: multi-day, stateful, persona-conditioned scenarios with action-dependent branches, scored separately on the three objectives, with judge-agreement analysis.
* A 23-configuration evaluation showing large deficits in deferral and depth alignment, and a 30-person study showing that timing and alignment change acceptance and trust independently of correctness.

# Q10 Next Steps

* **Same-trajectory human ratings.** Have humans rate a sample of gym trajectories alongside the LLM judges to test directly whether judges discount depth misalignment.
* **Richer TA.** Add variable task durations, real or simulated compute budgets, preemption, and several decision windows per scenario, as the authors propose, so TA has more resolution than ten binary decisions.
* **Train for 3T.** Use the gym as an RL or preference-training environment with separate rewards for deferral and depth alignment, and test whether a weighted 3T objective trades off as Equation 1 suggests.
* **Learned trust state.** Replace the scripted approval state machine with simulated users whose trust evolves from the interaction itself, validated against human trajectories.
* **Project fit (reader note).** This repository already runs scheduled overnight agents (for example a nightly paper-reading run) and lets agents continue authorized local work without confirmation; the 3T framing and the intervention-depth levels give a vocabulary for deciding which unattended work should be prepared, suggested, or executed, and the human-study result that one over-reach costs more trust than one aligned action earns is a reason to keep those boundaries explicit.
