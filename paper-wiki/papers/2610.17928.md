# Q1 Problem Definition

* **Input (X):** at each step of a mobile GUI task, the task instruction, the current screenshot, and one demonstration step retrieved from a bank of successful past steps (its task, its screen, and the action taken there).
* **Output (Y):** which form the retrieved step's screen should take in the actor's prompt, a text description built from the benchmark's UI annotations or the screenshot itself, followed by the frozen actor's next action given only that form.
* **Constraints:** the actor is frozen and open-weight (the router reads its hidden states); retrieval is fixed (one text-embedding top-1 lookup per step, the same step for both forms), so only the representation changes.

# Q2 Problem Novelty

New as a question. GUI memory systems already store experience as text traces, procedures, or operation documents (EchoTrail, AppAgent, RAG-GUI), as screenshots or cropped action regions (AGMem), or as both, but each fixes the form once and keeps it for every step. Work on vision-language models has shown that text and images carry different information and that which helps depends on the reasoning context; the paper asks whether the same holds step by step inside one GUI trajectory and whether the choice can be predicted.

# Q3 Scientific Hypothesis

1. Which memory form gives the better next action changes from step to step, so any fixed form leaves performance unused.
2. The preference is reflected in the actor itself: the difference between its hidden states under the two forms predicts which form helps.
3. A router trained to reproduce that internal signal, from the actor's state and the two memory embeddings, will choose forms well enough to beat fixed text, fixed image, and both together, while passing only one form to the actor.

# Q4 Related Work and Key People

* **Mobile GUI agents.** Aguvis and UI-TARS as GUI-specialized models; the AndroidWorld paper, source of M3A and MobileMiniWoB++; LearnAct, whose LearnGUI benchmark conditions agents on demonstrations.
* **GUI memory.** Episodic retrieval of past experience as in-context examples; textual traces and procedures (EchoTrail, AppAgent, RAG-GUI); visual memory of screenshots or changed regions (AGMem).
* **Modality in VLM reasoning.** Text abstraction can help structured visual reasoning while images keep fine spatial detail; Chain-of-Embedding (Long et al., 2026), which compares hidden representations across input conditions, is adapted here into a signed, directional version.
* **Key people.** Jaewoo Kang's DMIS lab at Korea University (code under `dmis-lab`), with Myongji University and AIGEN Sciences; first author Taeyun Roh's earlier work covers agent memory organization (CLAG) and text-induced bias in multimodal QA (BUZZY). Likely critics: authors of the memory baselines (EchoTrail, AGMem), who might ask for tuned ports, and online-evaluation groups, who would ask for task success on AndroidWorld-scale suites.

# Q5 Key Solution Idea

**Measure the preference.** For each training state, the actor samples seven actions with text memory and seven with image memory; each is scored against the recorded action, and the mean-score difference Δ = u_image − u_text says which form helped. Across AITW and LearnGUI both forms win on many steps, and a step-wise oracle that takes the better of the two beats the best fixed form on every benchmark.

**Find it in the actor.** The *Directional Chain-of-Embedding* is the per-layer difference between the actor's final-input-token hidden states under image and under text memory, d = h_image − h_text. A linear probe on its PCA-reduced form, trained on states where at least five of seven samples agree, predicts the preferred form, and better in deeper layers (best at layer 31 on AITW, layer 23 on LearnGUI; the method uses the final block on both).

**Turn it into a target, then a router.** On the final-layer d (standardized, 64 PCA dimensions), a logistic probe fitted to the sign of Δ gives a continuous score t per training state: positive favours image. The router takes the actor's hidden state for the prompt without memory (instruction plus current screenshot) and an embedding of each memory candidate (Qwen3-VL-Embedding-2B), builds a pair feature [s; e; s ⊙ e; |s − e|] for each form, scores both with one shared two-layer MLP (1024 → 256 → 1), and regresses the score difference onto t. At inference, image memory is used when the difference passes a threshold chosen on training predictions; only the chosen form reaches the actor. Training therefore needs both forms' forward passes, inference one extra hidden-state pass plus the small MLP.

# Q6 Experiment Design

* **Benchmarks.** AITW (next-action prediction on human demonstrations: 20,000 training steps split by trajectory into 10,019 query steps and 9,981 memory steps; 5,000 test steps from 759 held-out trajectories, retrieving from the full training bank). LearnGUI (101 successful online demonstrations, 1,500 steps, supply both queries and memories; evaluation in its offline one-shot setting with action-level accuracy). MobileMiniWoB++ (online, closed-loop task success on 92 task templates; the LearnGUI router is reused unchanged, the memory bank is 129 steps from 50 successful runs on another seed, and the threshold is set on a third seed's initial screens, without actions or rewards, to match LearnGUI's image-selection rate).
* **Comparisons.** General VLMs without memory (GPT-5.4-mini, Qwen3.5-9B); GUI-specialized models (Aguvis-7B, three UI-TARS variants); and, with the same frozen Qwen3.5-9B actor and retrieval bank, RAG-GUI, M3A, AppAgent, EchoTrail, AGMem, and fixed Text, Image, and Both.
* **Analyses.** Routing behaviour within trajectories; image-over-text utility and the router's image rate against screen element density, action type (spatial versus function), and initial versus later states; alternative routers (Utility and Binary trained on sampled utilities directly, Basic without actor hidden states); ratio-matched random routing; latency per step on one RTX PRO 6000; transfer to a UI-TARS-7B-SFT actor; paired cluster bootstrap and randomization tests (McNemar for MobileMiniWoB++).

# Q8 Evidence Quality

* **Supported.**
  * *Best in all three settings.* SwitchMem scores 51.42 on AITW, 38.13 on LearnGUI, and 63.04% on MobileMiniWoB++, against 49.30, 37.44, and 60.87 for the best fixed form (Image, Image, and Both). The AITW and LearnGUI gains are significant (+2.12, 95% CI 1.27 to 2.95, p < .001; +0.69, CI 0.15 to 1.26, p = .016) and survive Holm correction.
  * *The choice varies within a trajectory.* 83.8%, 90.8%, and 57.8% of trajectories use both forms, with 1.6 to 1.8 switches per trajectory and runs of 2.4 to 5.0 steps.
  * *Step assignment, not the mix, carries the gain.* SwitchMem beats random routing at the same image rate at every non-trivial rate tested, on LearnGUI and on AITW.
  * *The actor-derived target matters.* Routers trained on sampled utilities directly or without the actor's hidden states gain little over fixed Image on LearnGUI; on AITW they gain but stay below SwitchMem, with the sign-only Binary router close.
  * *Interpretable pattern.* Image memory helps more on dense screens, for function-oriented actions than for tapping and scrolling, and after the first step; the router picks image more often in exactly those conditions.
  * *Giving both forms can hurt.* Both scores 26.92 on LearnGUI against 37.44 for Image alone and 47.08 on AITW against 49.30.
  * *Cheap at inference.* It adds 0.13 to 0.30 seconds per step over Image memory (1.41 to 1.86 s in total), far below RAG-GUI's 8.8 to 11.1 s.
  * *Carries to another actor.* With UI-TARS-7B-SFT as actor it again beats fixed Text and Image on all three benchmarks (33.68, 41.06, 36.96).
* **Weaker or narrower than the headline.**
  * *Small effects, mostly offline.* AITW and LearnGUI score the predicted next action against a recorded one; the only closed-loop test is MobileMiniWoB++, where the gain over Both is two tasks (58 against 56 of 92), the interval spans −3.3 to +7.6, and p = .688. The authors present that result as cross-benchmark transfer, not in-domain evidence.
  * *Close to always-image on LearnGUI.* 81.3% of LearnGUI steps are routed to image, and the gain over fixed Image is 0.69 points, so most of the step-level selection there decides a minority of steps.
  * *Memory does not always beat no memory.* On MobileMiniWoB++ the actor alone scores 58.70%, above fixed Text (53.26) and fixed Image (57.61), so the comparison against no memory in the online setting rests on Both and SwitchMem only.
  * *The prior-method baselines are weak in this setting.* With the same actor, RAG-GUI, M3A, and AppAgent score 14.8 to 18.3 on AITW against 41.9 for no memory at all, and EchoTrail and AGMem fall below the simple fixed forms. These are training-free ports under a shared retrieval bank, so they show the forms these methods use under this protocol, not each method at its best (reader observation).
  * *White-box only, and tied to the retrieval design.* The router needs the actor's hidden states, which rules out API models, and it chooses between two forms of one top-1 retrieved step; whether the result holds with several retrieved steps, a different retriever, or memory written by the agent itself is untested.
  * *Android only, emulated.* The authors list iOS, newer Android versions, and physical devices as unverified.

# Q9 Contributions

* Evidence that the useful form of a GUI agent's memory is a per-step property: a step-wise oracle over text and image beats every fixed choice, and mixing both in one prompt can be worse than either.
* The Directional Chain-of-Embedding probe, which reads a modality preference from the signed difference of an actor's hidden states under two input conditions, with the signal strongest in late layers.
* SwitchMem, a router trained on that signal that passes one memory form per step at about a tenth of a second to three tenths of a second of added latency, with controls (ratio-matched random routing, direct-utility routers) that tie its gains to step assignment.
* Descriptive findings on when screenshots help: dense screens, function-oriented actions, and states after the first.

# Q10 Next Steps

* **From the authors.** iOS and newer Android versions, physical devices, and routing for API models that do not expose hidden states.
* **Close-loop evaluation at scale (reader suggestion).** Report task success on a larger online suite (AndroidWorld or similar) with the router trained in-domain, so the effect can be distinguished from noise.
* **More than two forms (reader suggestion).** Add a cropped action region (AGMem's form), no memory, and both forms to the router's options; the MobileMiniWoB++ results suggest "no memory" and "both" are sometimes the right choice.
* **A black-box target (reader suggestion).** Train the router from sampled utilities with a cheaper proxy for the actor's state, such as the actor's output log-probabilities, to test how much the hidden-state target is needed.
* **Project fit (reader note).** For agents in this repository that keep screenshots or rendered pages as evidence, the result argues for storing both a text summary and the image and choosing per use, rather than converting everything to text up front; the gains here are small, so this is a default to keep options open, not a measured win for repository work.
