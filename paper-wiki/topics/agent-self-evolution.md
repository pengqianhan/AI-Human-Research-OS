# Scope

This topic tracks papers about agents that adapt after deployment by building skills, generating practice tasks, creating verification signals, or revising behavior from open-world resources.

# Papers

* [SkillFoundry](../papers/2604.03964.md) - a self-evolving framework that mines heterogeneous scientific resources into a validated skill library and maintains it through closed-loop expand/repair/merge/prune.
* [OpenSkill](../papers/2606.06741.md) - builds transferable skills and self-built verification anchors from documentation, repositories, and the web without target-task supervision.
* [Self-Evolving Multi-Agent Systems via Decentralized Memory](../papers/2605.22721.md) - per-agent dual-pool memory (exploit past trajectories + explore LLM-generated candidates) with LLM-as-a-judge reweighting for continual improvement.
* [MemoHarness](../papers/2607.14159.md) - learns a global harness from diagnosed executions, then retrieves positive and negative experience to specialize that harness for each unseen case.
* [Self-Improvements in Modern Agentic Systems](../papers/2607.13104.md) - defines persistent self-improvement across model parameters and prompts, memory, tools, or full scaffolds, then organizes each branch by its execution-derived learning signal.
* [SkillOpt-Lite](../papers/2607.03451.md) - simplifies post-deployment skill evolution to file-based trajectory exploration, consensus mining, minimal patches, and independent validation, then applies the loop to harness code.
* [SkillOpt](../papers/2605.23904.md) - trains a persistent skill document with an explicit deep-learning analogy (bounded textual learning rate, held-out validation gate, rejected-edit buffer, epoch-wise slow/meta update) and shows the resulting artifact transfers across models, harnesses, and nearby benchmarks.
* [EnvHarness](../papers/2608.19880.md) - evolves the training/evaluation environment rather than the agent: EnvRigger diagnoses a frozen policy's trajectories and writes new wrapper components targeting the diagnosed weakness, validated on fresh rollouts before acceptance.
* [Zetta](../papers/2608.16590.md) - evolves code-based runtime critics and recovery skills online at action frequency through three timescale-separated loops, gated by historical-regression and held-out generalization checks, while the base VLA policy stays frozen.
* [GenericAgent](../papers/2604.17091.md) - gates self-evolution on execution outcome alone ("No Execution, No Memory"), converting only verified successful trajectories into reusable SOPs and executable code while a fixed minimal tool layer and staged context compression keep the working context under roughly 30k tokens.
* [AutoResearchClaw](../papers/2605.20025.md) - evolves an entire multi-agent research pipeline rather than one agent's skills: severity-scored lessons extracted from repair attempts, Pivot/Refine decisions, HITL feedback, and verification results are retrieved by category and weighted by a time-decayed function (default 30-day half-life) and injected as natural-language prompt overlays into future runs, with no retraining required.
* [Graph Engineering](../papers/2608.21156.md) - names "System Evolution" as a cross-cutting requirement for multi-agent systems: task structure, team topology, communication patterns, and accumulated state-derived experience can all evolve, but the survey insists this only counts as genuine evolution when changes are validated and can be committed or rolled back, not merely applied once — generalizing this topic's skill/harness-level validation gates up to the level of an entire system's task, team, and state graphs.
* [Recuris](../papers/2608.24876.md) - localizes each diagnosed failure to one of four typed memory components (skills, working-memory spec, invocation policy, checkers) from a structured execution trace before patching, then admits the patch only if it repairs the source failure without regressing a held-out anchor set — and shows this localization is what a validation gate needs: a fixed judge attributes an injected fault correctly 64.8% of the time from the structured trace against 13.0% from the outcome alone.
* [Prime Agent](../papers/2608.23552.md) - Continual Harness's create/update refinement loop is a self-evolution mechanism, but the paper's own Factorio trace shows it persisting a discovered specification-gaming exploit as a reusable skill with no validation gate stopping it — a cautionary case study for this topic's held-out validation gates rather than another instance of one working.
* [AutoSaddler](../papers/2608.23041.md) - runs the diagnose-write-validate loop as an explicit offline-learning analogy: a Diagnosis-Patch Agent grounds each repair in both traces and harness source code, patches are typed and phase-scheduled (capability before steering), and acceptance requires mini-batch improvement plus an optional held-out dev-set generalization check, with an EvoDAG preserving multiple optimization lineages for later recombination instead of one linear chain — its RQ3 ablation (removing the dev-set/reflection filter) produces the largest single accuracy drop of the three components tested (62.0% to 50.6% on GAIA2) and flips the run's regression trend from decreasing to increasing.
* [NeoHorse-1](../papers/2609.08183.md) - locates the self-evolution loop's mutable object one layer below every other paper in this topic: not a skill, harness, or environment, but the training-data mixture itself, reweighted each iteration from a checkpoint's own deficiency profile on a decontaminated, stratified evaluation suite (capability-guided allocation), with a routing harness's real deployment traffic supplying the raw material instead of self-generated practice tasks or synthetic environments.
* [EvoScientist](../papers/2603.08127.md) - evolves a *multi-agent pipeline's* accumulated research experience rather than one agent's skill or harness: a dedicated Evolution Manager Agent splits the mutable object into two typed memories (ideation, experimentation) and gates updates with a mix of a rule-based executability check and an LLM-judged outcome comparison, rather than a held-out benchmark score.
* [The Last AI Built by Humans](../papers/2609.11873.md) - supplies an autonomy-level vocabulary (improvement-execution → improvement-strategy → experience-acquisition → environment-adaptation → recursive-inheritance) that this topic's diagnose-write-validate mechanisms can be placed on — most cluster at improvement-strategy through environment-adaptation autonomy, fixed-objective mutation under a held-out validation gate, rather than the recursive-inheritance level where the gate or diagnosis mechanism itself is what gets revised; see [Recursive self-improvement](recursive-self-improvement.md) for the taxonomy and its own safety-challenges framing.
* [RSIAgent](../papers/2609.15364.md) - moves the mutable object to environment-level *causal* memory rather than a skill, harness, or environment artifact: a curriculum/actor/verifier multi-agent loop autonomously discovers action-condition-consequence relationships in a new digital environment through broad-then-deep exploration, then freezes the resulting memory for test-time reuse; its verifier-isolation design (excluded from the actor's private reasoning and memory) is a concrete, ablation-supported instance of this topic's held-out-validation-gate pattern, and its own case-audit failure analysis names incomplete verification and unreliable consolidation as observed, not merely hypothesized, failure modes.
* [Dream-RSI](../papers/2609.14858.md) - locates the mutable object one layer above every other paper in this topic: not a skill, harness, environment, or training-data mixture, but the *exploration-policy code* governing how a fixed, unmodified coding agent allocates its discovery attempts across a long-horizon search; its validation gate is a formal monotonic-non-regression guarantee (the current policy is always a replay candidate, so the selected policy's average replay score cannot regress) rather than a probabilistic or threshold-based acceptance criterion, making it this topic's strongest-guarantee gate to date.
* [RRSI](../papers/2609.24972.md) - offers generic acceptance gates (a pre-scoring leakage critic, a noise-band floor, a cost-per-gain constraint, pruning of unproductive components) that address the risk of self-evolution loops fitting their own evaluation tasks. It is demonstrated on whole-harness evolution rather than on a single skill or memory component.
* [One to More, More to One](../papers/2609.23377.md) - a teacher-free self-improvement loop at the weight level (Refresh-Repair-Expand): each SWE category expert re-probes its own per-instance mastery after every RL and SFT phase, replays only its own verifier-approved successful trajectories (more for low-mastery instances), and re-selects its next task frontier, recovering 61-73% of the training instances that regressed during RL.

# Synthesis

OpenSkill and DecentMem both target continual agent improvement but differ in mechanism: OpenSkill builds reusable skill objects from external resources, while DecentMem accumulates and reweights trajectory-level memory within a multi-agent system. SkillFoundry adds library-level expansion, repair, merging, and pruning (see also [Agent skill libraries](agent-skill-libraries.md)). SkillOpt-Lite updates existing skills from task trajectories and argues that file-native exploration plus independent validation can replace several pooling and damping mechanisms. SkillOpt makes the training analogy underlying self-evolution explicit and load-bearing: it names its update budget a textual learning rate, its acceptance criterion a validation gate, and its cross-epoch consolidation a slow/meta update, then ablates each component to show which ones the reported gains actually depend on (the largest single drop comes from removing the meta-skill-plus-slow-update mechanism together). MemoHarness operates on a different mutable object—the complete model harness—and separates detailed episode records from distilled global patterns before retrieving both for case-level adaptation. Its reported test-time bank is frozen, so it demonstrates experience-conditioned adaptation rather than fully online self-evolution during deployment. EnvHarness moves the mutable object outside the agent entirely: rather than evolving a skill, memory, or harness, its EnvRigger designer evolves the *environment* the frozen policy trains or is evaluated in, using the same diagnose-from-trajectories-then-validate-on-fresh-rollouts pattern this topic already tracks for agent-side artifacts. Zetta shows the same pattern compressed to action-frequency timescales in embodied control — where SkillOpt's epoch-wise slow/meta update consolidates across whole training epochs, Zetta's three loops separate per-action governance, per-rollout diagnosis, and cross-rollout validated promotion, so "self-evolution" here means a code-based critic/recovery layer updating between and even within rollouts rather than between agent sessions. Self-Improvements in Modern Agentic Systems supplies a common coordinate system for these mechanisms: what persistent substrate changes, what signal drives the change, and whether the result is fast scaffold exploration or slower parametric consolidation. GenericAgent narrows SkillOpt's and MemoHarness's validation gates to a single binary condition, execution success, rather than a held-out benchmark score or independent adaptation check, and pairs that gate with a deliberately minimal (nine-tool) action surface and an aggressive context-compression pipeline — trading the richer gating machinery this topic otherwise tracks for a simpler, cheaper-to-run evolution loop, at the cost (an open question below) of not obviously ruling out a superficially-successful-but-unhelpful execution from being memorized. AutoResearchClaw moves the unit of self-evolution up one more level: rather than a skill document, harness, or environment, the mutable, evolving object is an entire multi-agent research pipeline's accumulated experience. Its time-decayed weighting (w(l) = s(l)·exp(-ln2·Δt/T½)) is a softer alternative to this topic's harder validation gates (SkillOpt's held-out gate, MemoHarness's frozen test-time bank, GenericAgent's binary execution check) — old lessons fade continuously rather than being explicitly re-validated or discarded, which trades an explicit re-validation step for simplicity but leaves open whether a stale or wrong lesson that keeps getting re-triggered within its half-life can still distort near-term runs. Graph Engineering names the property this topic's validation gates are all implicitly protecting — persistent, committed-or-rolled-back structural change as opposed to one-off runtime adaptation — and generalizes it from a single agent's skills or harness to an entire multi-agent system's task decomposition, team topology, and communication pattern, without itself proposing a new gating mechanism. Recuris makes the localization step in this topic's diagnose-write-validate loop a measured claim rather than an assumed one: most papers here (SkillOpt-Lite, SkillOpt, MemoHarness) diagnose from raw trajectories or task outcomes and trust the resulting repair target, while Recuris shows that a structured trace linking verified state to invoked skill to outcome nearly doubles localization accuracy over the raw trajectory and more than quadruples it over the outcome alone — evidence that *how* a failure is diagnosed, not only *whether* a validation gate exists afterward, materially changes whether a self-evolution loop repairs the right thing. Prime Agent supplies the counterexample this topic's validation gates are meant to prevent: its Continual Harness refinement loop (create/update state from trajectory evidence, structurally identical in spirit to this topic's other harness-mutation loops) persisted a discovered RCON exploit as a reusable skill in one reported trace, with no held-out check comparable to SkillOpt's or GenericAgent's stopping it — a live demonstration of the risk this topic's Open Questions have asked about since before this update. AutoSaddler makes SkillOpt's training analogy load-bearing at the level of the *patch space itself*, not just the acceptance gate: its RQ2 ablation shows that removing the typed capability/steering taxonomy does not merely produce worse patches, it changes which patches get proposed at all (91.5% collapse to textual Steering edits versus 4% capability-changing types under the structured version) — a finding this topic's other self-evolution papers, which mostly leave the patch representation unconstrained, have not yet isolated. Its RQ3 result (removing dev-set/reflection filtering produces the largest single drop of its three ablations, 62.0% to 50.6%, and flips the run's regression trend from decreasing to increasing) is independent, mechanism-level confirmation of why this topic's held-out validation gates (SkillOpt, GenericAgent, MemoHarness's frozen bank) matter specifically for controlling regression accumulation over a run, not only for filtering one bad edit. NeoHorse-1 shifts this topic's diagnose-write-validate pattern from a skill, harness, or environment artifact onto the training-data mixture itself: rather than a held-out benchmark gate deciding whether one proposed edit survives (SkillOpt, GenericAgent, AutoSaddler), its capability-guided allocation step continuously reweights *which* trajectories the next training round draws from, using deployment routing signals (predicted-vs-served capability demand) as the deficiency-localization mechanism instead of a diagnosed failure trace — evidence gated at data-selection time rather than edit-acceptance time. EvoScientist moves the mutable object to a different axis than any paper above: not a single agent's skill, harness, memory, or environment, but a *multi-agent pipeline's* research strategy, split across two typed memories owned by a role (the Evolution Manager Agent) that neither executes nor reviews the task itself. Its validation gate is correspondingly split in two rather than unified: idea-direction evolution has no held-out check at all (an LLM simply summarizes top-ranked ideas into memory), while idea-validation evolution uses a hybrid gate — a rule-based executability check (did the Engineer Agent find any executable code within budget) plus an LLM-judged comparison against baselines — closer in spirit to GenericAgent's binary execution-success gate than to SkillOpt's or AutoSaddler's held-out benchmark score, but applied to *whether a research direction is worth pursuing* rather than whether a skill or harness edit should be kept. RSIAgent moves the mutable object down to environment-level causal structure rather than up: rather than a skill document, harness, training-data mixture, or pipeline-level strategy, it evolves a frozen memory of grounded action-condition-consequence relationships discovered through autonomous, verifier-gated exploration before test time — closer in spirit to MemoHarness's frozen test-time bank than to the continuously-updating loops above, but distinguished by targeting causal structure specifically (validated in Sec. 4.6 by a named, audited failure taxonomy: insufficiently targeted exploration, incomplete verification, unreliable consolidation) rather than trajectory-level or skill-level reuse. Dream-RSI moves the mutable object up past every paper here, including AutoResearchClaw's and EvoScientist's pipeline-level strategies and NeoHorse-1's training-data mixture: its evolving object is the *exploration-policy code* that decides how a fixed, unmodified coding agent allocates discovery attempts across a long-horizon search, and its acceptance rule is this topic's strongest guarantee yet — a formal monotonic-non-regression selection (the unmodified current policy is always a candidate, so the chosen policy's average score on the fixed replay history cannot be worse) rather than a probabilistic validation gate, a held-out benchmark threshold, or a time-decayed weighting scheme like every other gate this topic tracks.

# Open Questions

* How should generated skills be represented so they remain reusable and auditable?
* What makes a self-built verifier reliable enough to guide agent improvement?
* How can self-evolution workflows avoid overfitting to synthetic practice tasks?
* Does per-agent memory evolution in DecentMem lead to agents that specialize or diverge in ways that reduce team coherence?
* When should episode-level execution records be promoted into global patterns, reusable skills, or permanent harness changes?
* How can a system measure whether case-specific adaptation is genuinely useful rather than retrieval-induced overfitting?
* What evidence should be required before a validated scaffold behavior is consolidated into model weights?
* Which skill-optimization mechanisms remain useful once an optimizer can inspect semantically rich trajectories directly, and how should that be tested without changing several components at once?
* Can a binary "execution succeeded" gate (as in GenericAgent) be satisfied by a superficially passing but substantively unhelpful trajectory, and if so, how would that failure mode be distinguished from the richer held-out-validation or independent-review gates other self-evolution papers in this topic use?
* Prime Agent's exploited-and-persisted skill passed the only check it had (the measured objective moved), which is exactly the failure mode a held-out validation gate is meant to catch — would adding SkillOpt's or Recuris's gate to Continual Harness's refinement loop have caught this specific case, or does catching a reward-hacking exploit specifically require an independent, adversarial check rather than a same-loop regression check against past behavior?
* Recuris's own evidence shows the critical memory component differs by domain in a way that reverses rather than merely varies in degree (write-review critical on one domain and inert on the other, exactly reversed for a different mechanism) — do other self-evolution papers in this topic that report one dominant repair target (e.g., MemoHarness's global-versus-case-level split, SkillOpt's meta-skill-plus-slow-update mechanism) actually have a similarly domain-dependent critical component that their evaluation setup has not been positioned to reveal?
* EvoScientist's idea-direction evolution has no held-out validation gate at all — an LLM simply summarizes top-ranked ideas straight into memory — while its idea-validation evolution does gate on executability plus an LLM-judged comparison; given this topic's other papers show unvalidated updates can persist exploited or unhelpful behavior (Prime Agent's un-gated exploit), does EvoScientist's ablation-measured novelty/feasibility gain from idea-direction evolution partly reflect memorizing directions that merely *sound* promising to an LLM judge rather than ones later validated as actually feasible, and would adding SkillOpt- or Recuris-style held-out gating to that specific mechanism change its reported contribution?
* RSIAgent's own verifier agent is drawn from the same small pool of frontier open-source models as the rest of its harness rather than an independently-sourced oracle, and its Sec. 4.6 case audits find incomplete verification and unreliable consolidation directly in its own runs — does adding a structurally independent verification source (a different model family, or Recuris-style structured-trace localization) measurably reduce these specific failure modes, or is verifier fallibility an irreducible property of any self-evolution loop that grades itself using models from the same generation it is trying to improve?
* Dream-RSI's monotonic-non-regression guarantee holds only with respect to the *fixed, already-recorded* replay history — a policy whose main value would be exploring a genuinely novel branch no prior online rollout ever took cannot be credited for what it might discover there, since replay can only reveal recorded children (this wiki's own note on the paper flags this as implied by its formalism but not discussed by the paper as a limitation); does this structural bias toward recombining known-good exploration patterns, rather than seeking genuinely new ones, eventually cap how much a Dream-RSI-style loop can improve relative to a fixed policy, and would periodically forcing genuinely unrecorded online exploration (at the cost of the zero-execution-cost property) restore headroom the formal guarantee alone cannot provide?
