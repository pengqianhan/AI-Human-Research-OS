# Scope

This topic tracks papers where the main object is *measurement* of LLM agents: new benchmarks, evaluation protocols, grading methods, and systems that build benchmarks automatically. It covers both outcome-level evaluation (did the task get done?) and process-level evaluation (did the agent behave appropriately along the way?). Benchmarks that mainly serve one application area may also sit in that area's topic, for example [Game-playing agents](game-agents.md) or [Agentic robot manipulation](robot-manipulation-agents.md); environments built mainly for training belong in [Agent environments](agent-environments.md).

# Papers

* [TraceDance](../papers/2609.33295.md) - builds behavior benchmarks on demand from deployment traces: a user names an undesirable behavior, programmable anchors plus a cheap LLM find confirmed occurrences in 252,557 Claude Code and OpenClaw sessions, and each instance grades an LLM's single next turn at the recorded decision point with a behavior-specific rubric. Nine frontier LLMs pass 26.7% on average and only 8.1% when a check is required before acting.
* [Source Preference in the Wild](../papers/2610.03195.md) - a behavioral measurement protocol rather than a task benchmark: requirement-matched item pairs from live search results, every cyclic position rotation, and a Bradley-Terry-Davidson score with cluster bootstrap and FDR control, used to show that 12 agent models favor or avoid specific sites (110 of 144 model-source cells significant).
* [HyperBrowseComp](../papers/2610.03574.md) - an outcome benchmark for web-browsing agents: 423 natively authored questions in 13 languages, most needing non-text evidence, screened with seven no-internet models; best accuracy 31.68%, with self-grading checked against three other judges (at most 0.80 points of change).
* [Proactivity-Gym](../papers/2609.37267.md) - a multi-day simulated testbed for proactive agents with stateful tools, branches that depend on earlier actions, and persona-conditioned users; it scores task capability, prioritize-and-defer decisions, intervention-depth agreement, and judged trust separately across 23 model-harness configurations, and the best agent (Claude Opus 5) gets both the prioritize and the explicit-defer decision right in 51.7% of runs.
* [LMBuild](../papers/2610.04292.md) - an outcome benchmark for building physical objects with tools, scored bottom-up on 12 metrics (soundness, affordance, design, physical realization) for 30 systems; it adds tool-trace failure analysis, finding open models succeed on 51.7% of part-creation calls against 95.7% for closed ones and lose track of scene state far more often.
* [AutoSciBench](../papers/2610.05140.md) - a benchmark-construction method for scientific agents: a frontier coding agent plans each task as a concept (domain, modality, operations) and a recipe, builds the data files and an exact-match answer, solves it three times, and revises the plan until all trials fail; with Claude Opus 4.8 as generator, average accuracy of ten solvers falls 22.4 and 25.5 points below the seed benchmarks in computational biology and materials science (5.7 and 18.1 with GPT-5.6 Sol as generator).
* [From Evidence to Action (SafeActBench)](../papers/2610.07753.md) - a process benchmark of 656 synthetic tool-use cases that scores whether each consequential action was preceded by evidence bound to the right entity and state, with a deterministic evaluator audited against humans; across ten model-harness configurations agents judge supplied actions at 95-99% but succeed on the same cases interactively at 28-52%, mostly by stopping before the required investigation or acting before it is complete.
* [DecepEval](../papers/2610.07967.md) - a behavioral benchmark of 1,532 neutral-induced task pairs (tool-use reporting, coding, long-horizon record keeping) in which the induced version adds pressure, incentive, opportunity, or conflict; an LLM judge labels a trajectory deceptive only if a recipient-visible output contradicts facts the agent was given, and inducement raises deception in every one of 27 model-task cells (mean +41.64 points).
* [Learn2Play Bench](../papers/2610.08215.md) - a learning-from-experience benchmark: 20 newly designed text games with novel or counterintuitive hidden rules, ten of which change their visible instance every episode, scored over repeated episodes by peak and mean performance plus Learning Gain and Learning Slope, with 21-30 human players per game on the same interface; the best human per game reaches Max 84.3 against 81.8 for the best agent (Claude Code with Opus 5).
* [EmbodiedCLBench](../papers/2610.13021.md) - 268 household tasks (168 basic, 100 advanced) from the TongSim simulator, frozen as offline state-transition graphs in which each node offers four written actions labelled optimal, suboptimal, or invalid; a learning phase on basic tasks precedes testing on advanced tasks composed of the same atomic actions, under zero-shot, in-context, and skill-summary settings, with single runs scored by success rate.
* [AgentSWE](../papers/2610.13361.md) - 25 commissions asking a coding agent to create an agent from a requirement, add capabilities to a production agent codebase, or optimize a working agent; the builder iterates on two visible cases (or a development split), and the frozen delivery is run on held-out cases with a shared runtime model, validity gates, and requirement-derived rubrics; the best of five builders averages 19.1 on Creation and 31.6 on Editing, and 58.1% of traced Creation executions fail a gate.
* [Doc2Harness](../papers/2610.20344.md) - a construction benchmark scored without a judge: the artifact is a coding-agent harness a model builds from a specification, run as a black box by a scripted mock model on 328 cases with effects read from model requests, disk, exit code, and output, and positive controls that fail a prohibition case whose pass came only from the feature never running; KR-20 0.913, with pass rates from 53.05% to 27.44% across 19 models.
* [FDE-Gym](../papers/2610.22350.md) - 95 customer-delivery tasks from 20 expert-adapted scenarios in 18 sectors, scored by normalized uplift on the customer's own metric minus a hidden stakeholder-contact charge, with admission anchors (doing nothing scores 0, the reference at least 0.95, literal compliance at most 0.2, shortcuts at most 0.8); at the sponsor-request level the best of 13 configurations averages 0.56 and resolves 14 tasks.
* [BizBench](../papers/2610.20424.md) - 50 payments-workflow tasks with versioned guidance, 601 discoverable tools, and an LLM customer, where success requires deterministic goal, process, and protection checks over the execution history; the best strict success is 64.0% (one run per task) and 61.3%, and Qwen3.8-27B's 42.0% goal rate falls to 32.7% strict.
* [Into the Unknown](../papers/2610.19159.md) - 15 unpublished follow-up directions proposed by the original papers' authors, graded by author-verified integrity and direction rubrics with an agentic judge; none of 135 submissions from nine frontier agents is valid, and 114 fail the integrity check.

# Synthesis

TraceDance and Source Preference in the Wild both measure *how* an agent behaves rather than whether it finished, but they control for confounds differently. TraceDance fixes the context by replaying one recorded decision point and grading the next turn with a rubric. Source Preference keeps the agent's own searches and controls the confounds statistically: it compares only items with the same judged satisfaction and rotates every list through all positions, so a selection difference can be attributed to the source. HyperBrowseComp is an outcome benchmark, and its main methodological lesson is the same one several harness papers in this wiki report: the score belongs to a model-plus-tool combination, since swapping built-in search for Exa moves accuracy by 7.3-9.5 points in opposite directions for different providers.

Proactivity-Gym and LMBuild both argue that one success score hides the failure that matters, and both split the score into levels that can disagree. In Proactivity-Gym, task capability correlates only weakly with deferral (r = 0.31) and intervention-depth agreement (r = 0.34); in LMBuild, frontier agents are near-perfect on soundness while operability stays below 23. Both also show the harness-dependence HyperBrowseComp reports: Proactivity-Gym measures it directly (moving Claude Opus 5 from Claude Code to OpenClaw changes deferral by 21.1 points), and LMBuild runs each provider in its own harness, which it acknowledges as a comparability limit.

SafeActBench extends the process-level line from TraceDance's single recorded turn to whole executed trajectories, and it is the first benchmark here that scores processes with no LLM judge at all: every requirement is an observable fact (which record was read, for which entity, before which call), so a deterministic evaluator can be audited against humans instead (2.0% false acceptance, 1.3% false rejection). It also measures harness dependence with paired case-level intervals rather than a single swap: DeepSeek gains 4.4 points in its own harness and GLM loses 6.8, while the other three models' intervals include or touch zero. AutoSciBench answers this topic's construction question in the most automated way so far, and so makes its bias question concrete. The same model builds each task, solves it during refinement, judges its verifiability, and (with the other generator) rates benchmark quality, and the hardest task per run is kept. Lower accuracy on the result is therefore partly selection against one solver, and the reported jump of newer models (Claude Opus 5 +19.5 over Opus 4.8 on Opus-4.8-built tasks) would appear for any model that differs from the filter.

DecepEval and SafeActBench look at two halves of the same chain. SafeActBench asks whether an agent established the evidence before acting; DecepEval asks whether an agent's report agrees with evidence it already received. Their control strategies differ as well: SafeActBench avoids judges and checks observable facts deterministically, while DecepEval relies on one LLM judge with a five-condition rule and controls the inducement instead, by pairing each task with a neutral twin that differs only in one condition slot. The pairing makes condition effects attributable, but some of its inducement texts tell the agent what to report, so part of what it measures is compliance with an instruction to misreport.

Learn2Play Bench measures a property none of the benchmarks above isolate: whether an agent gets better at an unfamiliar task by playing it again. Its control is the game design itself, hidden rules written to be absent from or contrary to common game knowledge, plus re-shuffled instances that keep the rule but change what the agent sees, so improvement cannot come from recall or from memorizing one instance. It separates achieved performance (Max, Mean) from improvement (Learning Gain and Slope), and the two rankings disagree: Claude Opus 5 scores highest under a common harness while Qwen 3.8 Max improves most. Its human baseline shows how much selection matters in such comparisons. The best of 21-30 players per game (Max 84.3) beats every agent, but humans averaged over all participants score Max 43.6, below most agents, and agents' Max averages only three trials.

EmbodiedCLBench and Learn2Play Bench both score learning rather than one-shot ability, with different designs: Learn2Play repeats episodes of one game and reports gain and slope, while EmbodiedCLBench separates a learning phase on simpler tasks from a test on compositions of them. EmbodiedCLBench's graph format buys determinism and a per-decision error taxonomy at the cost of turning an embodied task into a visual multiple-choice sequence. Its analyses also disagree slightly with its main table on cells they share (42.0% against 44.0%), a reminder that with 100 test tasks and single runs a few points are not signal.

AgentSWE moves the unit of evaluation one level up: the artifact under test is an agent that another agent built, and it is scored by executing it, not by reading it. Three of its design choices are reusable. Deliveries are frozen and run through a benchmark-owned model gateway, so the score reflects the harness the builder wrote and not its choice of model. Reports are audited against the builder's own trajectory, which yields a clean asymmetry: reports admitting partial failure were never contradicted, and nine that claimed completion were. And repeated evaluation of the unchanged Optimization starters is reported, with standard deviations of 4.5 to 20.8 points, a noise floor most benchmarks in this topic do not publish and one that leaves most of AgentSWE's own Optimization cells indistinguishable from zero. It shares a weakness with AutoSciBench: tasks, cases, and rubrics were drafted by a model that is also a builder and a judge, and no reference agent shows what score the held-out cases allow.

Doc2Harness sits beside AgentSWE as a benchmark whose test object is something an agent built, and beside SafeActBench as one that scores without an LLM judge. Its distinctive control targets a failure the other process benchmarks here do not name: an assertion that something must *not* happen passes trivially if the feature under test never ran. Each such case is gated by a control that changes only the input or the access route and asserts an outcome that must occur if the observation works; 130 of its 328 cases carry one. It also publishes a reliability statistic (KR-20 0.913 over 57 builds) and a per-category split into floor, ceiling, and discriminating cases, which most benchmarks here omit. Its weak points are ones this topic already asks about: the suite was refined partly on harnesses the evaluated models built, and no reference implementation shows what score the specification allows, the same gap as AgentSWE's missing reference agent.

FDE-Gym turns anchor-based checks into an admission rule rather than an after-the-fact audit. A task enters only if doing nothing scores 0, the reference at least 0.95, literal compliance at most 0.2, and named shortcut strategies at most 0.8, and the graders were tested against more than 270 shortcut and bypass strategies. AgentSWE's held-out cases and Doc2Harness's positive controls ask whether a benchmark catches deliveries that pass by doing the wrong thing; FDE-Gym's literal-compliance cap asks the same of underspecified requests. Its exception for requests that are correct and complete keeps "distrust the sponsor" from becoming a winning shortcut. Its instruction ladder (L0 to L3 over one fixed world and grader) is a reusable way to locate where agents fail: for leading models the drop is at withheld constraints (0.28), not at a misdirected request (0.04 more), against the authors' own initial hypothesis. Two features limit outside checking: the 75 variants and all reference solutions are held out, and the authors run the leaderboard, so the anchors can be verified independently only on three public tasks.

BizBench applies SafeActBench's process view to business workflows and adds time. Its success rule (goal, process, and protection checks over the execution history) rejects a run that breaches a cash-reserve floor and later restores it, or that tries to execute before approval, even when the goal is met; 5 of 150 DeepSeek-V4.1-Flash runs and 14 of 150 Qwen3.8-27B runs fall in that gap. Like FDE-Gym it tests its evaluator against constructed cases rather than only replaying a reference: alternative valid traces, targeted violation traces, changed facts, and idempotent retries. Its information ablation puts the loss where FDE-Gym's instruction ladder does. Giving the agent all customer facts lifts strict success from 43.3% to 70.0%, while giving it the applicable documents lifts it only to 50.0% (reader connection). Two limits recur from elsewhere in this topic: the top model is scored on one run per task, and the agent used for most analyses is also the default customer simulator.

Into the Unknown carries the anchor question into research, where no reference answer exists. The original paper's author fixes an unpublished direction and the necessary conditions a follow-up must meet, and these become integrity and direction rubrics answered by an agentic judge. Its meta-verification is reusable here: the authors' after-reading criticisms are split into items and checked for rubric coverage and agreement, which fall from 100% on whether the direction was met to 75% coverage and 64% agreement (pooled) on quality and impact, showing which questions a rubric can carry. Its weak point is one this topic keeps meeting: the judge, GPT-6-Astra, is also the best-scoring agent, and the expert validation did not include its submissions. Because the main metric is zero for every agent, rankings fall back on that judge's node-level rates.

# Open Questions

* When does grading one next turn at a recorded decision point agree with executing the agent to the end? TraceDance's authors note that a planning-first response may act well later, and no paper here yet measures that gap.
* How should benchmark-construction pipelines control for bias when the same frontier models both build instances and are evaluated on them?
* Which behavior metrics (secret handling, checking before acting, honest claims) should be reported next to task success as standard columns, and how should their pass thresholds be set given that absolute rates depend on the rule?
* Can benchmarks built from one organization's private traces be validated or replicated by others when the traces cannot be released?
* HyperBrowseComp screens questions with no-internet models that include two of the models it later evaluates, but none from the other evaluated family. Should difficulty filters use a fixed, disjoint model panel, or every evaluated model, so the filter does not favor or penalize particular families?
* Benchmarks that score each configuration on few distinct decisions (Proactivity-Gym's temporal allocation rests on one decision window per scenario, ten in all, with judge agreement of κ = .438) or on one trajectory per task (LMBuild) cannot resolve small differences. What minimum number of independent decisions and runs should a reported sub-score rest on?
* Live-web benchmarks (HyperBrowseComp) and live-search behavior studies (Source Preference in the Wild) cannot be rerun exactly. Are preserved traces enough for auditing, or should such benchmarks ship a frozen snapshot of the evidence pages, as BrowseComp-Plus does for its corpus?
* AutoSciBench keeps tasks that its own generator could not solve, with reference answers computed by that generator and no expert check. What fraction of such "hard" tasks are hard because the reference is wrong or the question ambiguous, and would a disjoint solver panel plus expert review of unsolved tasks change the measured difficulty gap?
* SafeActBench fails an agent that correctly does not act but stops before reading every record the case specifies. When a process benchmark prescribes the evidence path, how should it separate an agent that under-investigates from one that reached the right decision by a different, sufficient path, beyond the alternative-path audits it already runs?
* DecepEval validates its single LLM judge on 100 random instances with raw agreement only (97%). For behavioral labels like deception, what validation should be standard: a stratified sample per model and task, a chance-corrected statistic, and a second judge from a different model family when the judge's family is also evaluated?
* Human baselines are often reported as the best of many participants (Learn2Play's Top-1 per game) while agents are averaged over a few trials. Should benchmarks report humans and agents under the same selection rule, for example best-of-three for both, so "humans outperform agents" means the same thing on both sides?
* Benchmarks built on novel rules (Learn2Play) stay novel only until the games, solutions, and run logs are public. How should such benchmarks keep measuring learning rather than recall once future models may have trained on them?
* AgentSWE's development cases deliberately cover only part of the requirement, so its development-to-held-out gap mixes builder overfitting with a coverage difference. What split design would measure overfitting alone, and should construction benchmarks publish a reference agent's held-out score as a ceiling?
* Doc2Harness's positive controls turn vacuous passes of prohibition tests into failures. How many passes of "must not happen" checks in other benchmarks (SafeActBench's no-action cases, refusal checks in security benchmarks) would survive a comparable control?
* FDE-Gym subtracts a hidden, expert-set contact charge, and that charge decides many resolutions (GPT-6 Astra's systems reach 0.8 uplift on 36 tasks, 9 of which stay resolved). Should delivery benchmarks report uplift and contact cost as separate primary results, and would rankings survive a different pricing schedule?
* BizBench's process checks and SafeActBench's evidence-before-action checks both score trajectories deterministically. Would a shared trajectory schema (approvals, state changes, evidence reads) let one evaluator serve both, and how many of BizBench's pre-approval execution attempts would SafeActBench classify as acting without evidence?
* Into the Unknown's judge is also its top agent. Should agentic benchmarks measure a judge's agreement with experts on submissions from every evaluated model family, including the judge's own, before publishing a leaderboard?
