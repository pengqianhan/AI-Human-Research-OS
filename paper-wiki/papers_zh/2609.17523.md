# Q1 问题定义

* **输入（X）：** 研究者与已部署科学智能体之间持续产生的交互流：带上传数据（文档、表格、序列、图像）的请求、后续回复，以及智能体的执行记录（代码、工具调用、观测、产物）。智能体由任务模型 π_θ 和可编辑的脚手架（harness）H（指令、限定范围的技能、上下文设置）组成，运行在固定的科学基础设施之上。
* **输出（Y）：** 更新后的“模型-脚手架”对 (θ_{k+1}, H_{k+1})，在留出的科学任务上表现更好，并重新部署给同一批研究者。
* **核心问题（作者原话的意思）：** 科学智能体如何把与研究者的协作转化为工作流程和底层能力上*持续*的改进，而不只是在一次对话里改正一个答案？
* **约束：** 研究者回复和历史答案不被当作真值标签。编辑脚手架时，工具、基础设施、评分细则（rubric）和评估器保持固定；训练模型时，脚手架和评分细则保持固定。开发集、训练任务和最终留出测试集彼此分开。

# Q2 问题新颖性

部分新。脚手架与提示词进化（Reflexion、GEPA、ACE、[Meta-Harness](../concepts/meta-harness.md)）、基于评分细则的强化学习（Rubrics as Rewards）、从用户交互中学习（OpenClaw-RL），以及脚手架与权重联合更新（SIA；HELIX 把脚手架进化与训练数据构造联系起来）都早于本文，论文也把它们列为先例。新的地方在于*嵌套*：内层在固定模型下编辑脚手架，选出的脚手架再决定外层强化学习的任务分布和轨迹；整对系统重新部署给真实研究者，他们的新交互开启下一轮。另一个新点是把协作记录打包成带任务专属评分细则的可执行任务。其意义在于：科学智能体的部署界面本身成了它的训练数据来源。

# Q3 科学假设

如果把研究者协作转化为带任务专属评分细则的可执行任务，并且只通过小幅、经验证集把关的编辑来修改固定任务模型的脚手架，然后在选定的脚手架下对模型做强化学习，那么：（a）仅靠脚手架编辑就能在权重不变时提高留出准确率；（b）仅靠强化学习就能在脚手架不变时扩大可解问题的范围；（c）两者多轮交替会叠加增益，且留出问题上的退步很少。

# Q4 相关工作与关键人物

* **持久的流程适应：** Reflexion、GEPA、ACE（Agentic Context Engineering）、[Meta-Harness](../concepts/meta-harness.md)、PILOT。“每次只做一处有界编辑、提升才接受”的规则来自 [SkillOpt](../papers/2605.23904.md) 和 SkillGen，考虑退步的评估来自 SkillGen。
* **递归自我改进：** Darwin Gödel Machine 与 Hyperagents（可编辑的改进过程本身）、SEAL（自生成更新指令）。论文明确指出其反思器（reflector）保持固定，因此任务表现变好*并不*意味着改进机制本身变强。
* **从交互中学习与联合适应：** OpenClaw-RL、RLAnything、SIA、HELIX、AgentBuild（科学家编写的评分细则）。
* **训练信号：** 奖励聚合用 Rubrics as Rewards，任务自适应评分细则用 AdaRubric，固定评审用 Robust Rubric Rewards，优化器为 [GRPO](../concepts/grpo.md)（DeepSeekMath），按难度校准的任务扩增借鉴 Environment Evolution for Terminal Agents。
* **科学基础设施：** Biomni（工具目录与数据湖）、LAB-Bench、Harbor（任务打包）、ReAct。
* **关键人物：** PhAI Labs（全部一作），通讯作者为 Zhenfei Yin、Yingcheng Wu、Ling Yang；合作单位还包括复旦大学/中山医院、牛津、斯坦福、普林斯顿。可能的批评者：Meta-Harness 与 HELIX/SIA 的作者（本文组合了他们的思路），以及要求在基准数字上做受控基线对比的人。

# Q5 关键解法思路

* **工作台与可插拔脚手架。** 对话加轨迹视图的界面，接入 22 个模块共 224 个工具（基因组学、分子与肿瘤生物学、药理学、生物成像、文献、数据库；工具目录源自 Biomni），支持 Python/R/Bash 执行、本地数据湖和持久工作区。可编辑的脚手架（指令、技能、上下文流程）位于统一执行接口之后，因此流程变化是显式、可评估的。
* **协作 → 任务 + 评分细则。** 把相关轮次围绕同一目标合并；写一个*不含*历史答案的自包含指令；根据完整协作轨迹构建评分细则（范围、方法、证据、所需产物）。二者打包成 Harbor 任务（指令、素材、环境、基于评分细则的测试），可用于拒绝采样 SFT 或强化学习。
* **内层递归（改脚手架，模型固定）。** 一个独立且固定的辅助模型（GPT-6 Astra）阅读近期轨迹和评分反馈，指出未满足的标准，并提出*一处*有界编辑（增删改一个技能、一条指令或一个上下文设置），由 schema 和大小预算检查。父版本与候选版本在相同的开发任务、随机种子和预算下评测；只有候选合规且平均评分严格提升时才接受（平局保留父版本），评测中包含以前已解决的任务以发现退步。
* **外层递归（训模型，脚手架固定）。** 针对当前模型和选定脚手架扩增并校准任务环境难度；用 GRPO 在新鲜的同策略轨迹上训练，奖励为加权的评分细则得分（能用可执行检查就用，否则用固定评审）。在新权重下重新评估继承下来的脚手架，然后整对部署。后台训练期间在线服务照常运行。

# Q6 实验设计

证据由四个案例研究构成，而不是与其他系统的受控基准对比。

* **RQ1，研究者交互（定性）：** 两个真实会话（小细胞肺癌中 JAK1 的研究方案；ARL4C 研究的汇报幻灯片）。论文展示了它们如何变成任务目标和标准，但注明这些任务规格是示意性推导，“不是存档的评分细则包，也不是打过分的输出”。
* **RQ2，耦合循环：** Qwen3.5-4B，三轮（小节标题写“Two-Cycle”，正文和图写三轮，编号 k = 0, 1, 2）。每轮先做 10 步脚手架搜索（按验证准确率选择），再做 20 次强化学习更新。报告留出集单次作答准确率和分任务族结果。
* **RQ3，只改脚手架：** 固定 Qwen3.5-4B，在 288 个适应对话上做 24 批编辑，用户由*模拟器*扮演（固定的 Qwen3.8-27B 辅助模型从一组不泄露答案的有限回复中选择）。选出的脚手架与初始脚手架在独立验证集上比较。
* **RQ4，只做强化学习：** 固定初始脚手架 H0，约两小时强化学习，在同一题组上比较前后的 pass@4 覆盖率。
* **任务池：** 来自 LAB-Bench 和 Biomni-Eval1 的 895 个任务，分四个任务族（LitQA2 96、DbQA 511、ProtocolQA 108、GWAS 180；共 16 个子主题）。

# Q7 数据集与代码

没有新基准；案例研究复用 LAB-Bench 和 Biomni-Eval1 任务。论文发布了产品（http://science-buddy.io）和 GitHub 仓库（Gen-Verse/ScienceBuddy）。检索到的正文没有说明协作衍生的任务、评分细则、进化出的脚手架或训练好的检查点是否发布。

# Q8 证据质量

* **报告的结果：**
  * *耦合循环：* 每轮内脚手架验证准确率上升（38.9→44.4%、34.4→46.7%、61.1→70.0%）；每个强化学习阶段前后半程的平均训练奖励上升（33.3→38.8%、44.1→60.5%、57.8→69.8%）。留出准确率从 42.2% 升到 73.3%；33.3% 的测试题由错变对，2.2% 由对变错；四个任务族都有提升。
  * *只改脚手架：* 权重固定时验证准确率 31.1% → 51.1%（+20 个百分点）；适应过程中最好的批次准确率为 75.0%。最终脚手架包含 4 条指令和 9 个限定技能（Python 执行、schema 检查、有界记录查询、答案提交、基因集检查、染色体带查询）。
  * *只做强化学习：* pass@4 覆盖率 48.3% → 67.8%（+19.5 个百分点）。
* **这些证据的局限：**
  * *评测集小且未报告规模。* 正文没有给出测试集大小。2.2%、33.3% 这样的比例与约 45 道题的测试集相符（读者推断），即每题约值 2 个百分点，且没有置信区间。
  * *没有外部基线。* 没有与 Meta-Harness、GEPA、SIA/HELIX 或等算力的纯强化学习比较；耦合结果也没有拆分每轮中脚手架与模型各贡献多少。
  * *定量的脚手架研究用的是模拟反馈。* 测得的脚手架增益来自有界、参考答案辅助的用户模拟器，而非真实研究者；真实研究者的证据（RQ1）是定性的，没有产出打分的评分细则。
  * *指标不统一。* 脚手架增益用首次回答准确率，强化学习增益用 pass@4 覆盖率，耦合研究用单次作答准确率，三者不在同一尺度上。
  * *没有逐项归因。* 作者自己说明，单个技能和反馈来源的作用“没有被单独分离”。
  * *反思器固定。* 作者自己指出这不能证明改进机制在变强，变强的只是模型和脚手架。

# Q9 贡献

* 一个已发布、可用的科学工作台，带可检查的轨迹视图和可插拔脚手架接口。
* 把协作记录转成可执行任务加任务专属评分细则的具体做法，并明确划分了任务策略、用户模拟器、反馈解释器、脚手架反思器、验证器和学习器之间的信息边界（论文表 2）。
* “递归中的递归”调度：在固定模型下做经验证集把关的单处脚手架编辑，嵌套在固定脚手架下的评分细则奖励 GRPO 之中；每次模型更新后重新评估继承的脚手架；后台异步更新，在线服务不中断。
* 案例证据：两个循环各自单独以及耦合起来，都能在生物医学任务族上提升一个 4B 模型。

# Q10 下一步

* **受控比较：** 在更大的留出集上、等算力条件下比较只改脚手架、只做强化学习和耦合三种调度，并给出置信区间；内层与 Meta-Harness 或 GEPA 比，联合循环与 SIA/HELIX 比。
* **真实而非模拟的反馈：** 用真实研究者交互流测量脚手架增益，并检验协作衍生的评分细则是否与专家评分一致。
* **内层是否过拟合？** 脚手架在小开发集上按“严格提升”规则选择。[RRSI](../papers/2609.24972.md) 关于无正则化脚手架进化会拟合进化集的论点可以直接套用（读者建立的联系）。
* **两个循环的顺序与比例：** 每轮 10 步脚手架、20 次强化学习只是一种任意调度；每次模型更新后是否都应重新搜索脚手架，或两者共同进化，尚未测试。
* **与路由脚手架式 RSI 的关系（读者笔记）：** [NeoHorse-1](../papers/2609.08183.md) 同样把已部署脚手架产生的信号转为后训练数据。比较两者从部署中提取什么（这里是评分细则打分的任务，那里是路由与能力信号），能看出哪种信号最有用。

# 相关

* [递归自我改进](../topics/recursive-self-improvement.md) - 把方法命名为“递归中的递归自我改进”，但作者说明提出编辑的反思器保持固定，因此改进的是模型和脚手架，不是改进机制本身；在该主题的自主性尺度上，它低于自指层级。
* [智能体脚手架工程](../topics/agent-harness-engineering.md) - 内层是经验证集把关的脚手架进化，每次只做一处对指令、技能或上下文设置的有界编辑；由于脚手架的价值取决于所配的模型，每次模型更新后都会重新评估。
* [AI for science](../topics/ai-for-science.md) - 一个已部署的生物医学研究工作台，研究者协作成为其自身智能体的训练与评测任务。
* [Meta-Harness](../concepts/meta-harness.md) - 被引为先前的脚手架代码搜索；ScienceBuddy 把每次提议收窄到一处有范围的改动，并外加一个更新权重的外层循环。
* [GRPO](../concepts/grpo.md) - 外层循环的优化器，以加权的任务专属评分细则得分作为轨迹奖励，所有生成 token 共享。
* [LLM-as-a-Judge](../concepts/llm-as-a-judge.md) - 需要科学解读的评分标准由固定评审打分，与可执行检查并用；优化期间评分细则和评审都固定。
