# Q1 问题定义

* **输入（X）：** 在移动端 GUI 任务的每一步，给出任务指令、当前截图，以及从成功历史步骤库中检索到的一个示范步骤（它的任务、它当时的屏幕、在那里采取的动作）。
* **输出（Y）：** 检索到的这一步的屏幕在执行模型（actor）的提示中以哪种形式出现：由基准自带的 UI 标注生成的文字描述，还是截图本身；然后冻结的执行模型只在这一种形式下给出下一步动作。
* **约束：** 执行模型是冻结的开源权重模型（路由器要读取它的隐藏状态）；检索方式固定（每一步做一次基于文本嵌入的 top-1 检索，两种形式用的是同一个检索结果），因此只有表示形式在变。

# Q2 问题新颖性

作为一个问题是新的。已有的 GUI 记忆系统把经验存成文字轨迹、流程或操作文档（EchoTrail、AppAgent、RAG-GUI），存成截图或裁剪出的动作区域（AGMem），或两者兼有，但都是一次性定好形式、每一步都沿用。关于视觉语言模型的研究已经表明，文字和图像承载的信息不同，哪种更有帮助取决于推理情境；这篇论文追问：在同一条 GUI 轨迹内部，是否逐步都是如此，这种选择能否被预测。

# Q3 科学假设

1. 哪种记忆形式能带来更好的下一步动作，会随步骤变化，所以任何固定形式都会浪费一部分性能。
2. 这种偏好体现在执行模型自身之中：它在两种形式下隐藏状态的差异，能预测哪种形式更有帮助。
3. 一个被训练来复现这种内部信号的路由器，只依据执行模型的状态和两种记忆的嵌入，就能把形式选得足够好，胜过固定文字、固定图像以及两者同时提供，而且每次只把一种形式交给执行模型。

# Q4 相关工作与关键人物

* **移动端 GUI 智能体。** Aguvis 和 UI-TARS 等 GUI 专用模型；AndroidWorld 论文，它提出了 M3A 和 MobileMiniWoB++；LearnAct，其 LearnGUI 基准让智能体以示范为条件执行任务。
* **GUI 记忆。** 把过往经验作为上下文示例检索的情景记忆；文字轨迹与流程（EchoTrail、AppAgent、RAG-GUI）；保存截图或变化区域的视觉记忆（AGMem）。
* **VLM 推理中的模态问题。** 文字抽象有助于结构化的视觉推理，而图像保留了精细的空间细节；链式嵌入（Chain-of-Embedding，Long et al., 2026）比较不同输入条件下的隐藏表示，本文把它改造成带符号、有方向的版本。
* **关键人物。** 高丽大学 Jaewoo Kang 的 DMIS 实验室（代码在 `dmis-lab` 名下），合作单位为明知大学和 AIGEN Sciences；第一作者 Taeyun Roh 此前的工作涉及智能体记忆组织（CLAG）和多模态问答中的文本诱导偏差（BUZZY）。可能的批评者：各记忆基线（EchoTrail、AGMem）的作者，可能会要求更充分调优的移植版本；以及做在线评测的团队，会要求在 AndroidWorld 规模的套件上报告任务成功率。

# Q5 关键解决思路

**测量偏好。** 对每个训练状态，执行模型在文字记忆下采样七个动作、在图像记忆下也采样七个，每个动作都与记录的动作比对打分，平均分之差 Δ = u_image − u_text 说明哪种形式更有帮助。在 AITW 和 LearnGUI 上，两种形式都在很多步上胜出；每一步取两者中较好者的"逐步神谕"在每个基准上都胜过最好的固定形式。

**在执行模型内部找到它。** *有向链式嵌入*（Directional Chain-of-Embedding）是执行模型最后一个输入 token 在图像记忆与文字记忆两种条件下、逐层隐藏状态的差值 d = h_image − h_text。在其 PCA 降维结果上训练的线性探针，只用七次采样中至少五次一致的状态，就能预测偏好的形式，而且层越深预测越好（AITW 上第 31 层最好，LearnGUI 上第 23 层最好；方法在两个基准上都统一使用最后一个模块）。

**先变成目标，再训练路由器。** 在最后一层的 d 上（标准化，降到 64 维 PCA），用一个拟合 Δ 符号的逻辑斯蒂探针，为每个训练状态给出连续分数 t：为正则偏向图像。路由器的输入是执行模型对"不含记忆的提示"（指令加当前截图）的隐藏状态，以及每个记忆候选的嵌入（Qwen3-VL-Embedding-2B）；它为每种形式构造配对特征 [s; e; s ⊙ e; |s − e|]，用同一个两层 MLP（1024 → 256 → 1）为两者打分，并让两个分数之差回归到 t。推理时，分差超过在训练预测上选定的阈值就用图像记忆；只有被选中的形式会交给执行模型。因此训练时需要两种形式各做一次前向计算，推理时只多一次隐藏状态计算和一个小 MLP。

# Q6 实验设计

* **基准。** AITW（在人类示范上预测下一步动作：20,000 个训练步骤按轨迹划分为 10,019 个查询步骤和 9,981 个记忆步骤；测试为 759 条留出轨迹中的 5,000 个步骤，从完整训练库中检索）。LearnGUI（101 条成功的在线示范、共 1,500 步，同时提供查询和记忆；评测采用其离线 one-shot 设置，报告动作级准确率）。MobileMiniWoB++（在线闭环，在 92 个任务模板上报告任务成功率；原样复用 LearnGUI 上训练的路由器，记忆库为另一随机种子下 50 次成功运行中的 129 步，阈值在第三个种子的初始屏幕上设定，不看动作和奖励，只让图像选择率与 LearnGUI 一致）。
* **比较对象。** 不带记忆的通用 VLM（GPT-5.4-mini、Qwen3.5-9B）；GUI 专用模型（Aguvis-7B、三个 UI-TARS 版本）；以及在同一冻结 Qwen3.5-9B 执行模型和同一检索库下的 RAG-GUI、M3A、AppAgent、EchoTrail、AGMem，和固定文字、固定图像、两者同时三种设置。
* **分析。** 轨迹内的路由行为；"图像相对文字"的效用及路由器的图像选择率随屏幕元素密度、动作类型（空间型与功能型）、初始与后续状态的变化；替代路由器（直接用采样效用训练的 Utility 和 Binary，以及不用执行模型隐藏状态的 Basic）；按相同比例随机路由；在单张 RTX PRO 6000 上的每步延迟；迁移到 UI-TARS-7B-SFT 执行模型；配对聚类 bootstrap 和随机化检验（MobileMiniWoB++ 用 McNemar 检验）。

# Q7 数据集与代码

没有新数据集；三个基准都是公开的。代码位于 [dmis-lab/SwitchMem](https://github.com/dmis-lab/SwitchMem)（抓取时 1 星），另有[项目页](https://txxnrd.github.io/switchmem/)。文字记忆不需要额外的描述生成模型：它直接序列化各基准自带的 UI 标注（AITW 的 UI 文本和当前 activity、LearnGUI 的元素描述、MobileMiniWoB++ 的无障碍树）。仓库内容未核查。

# Q8 证据质量

* **有支撑的结论。**
  * *三个设置中都是最好。* SwitchMem 在 AITW 上得 51.42，LearnGUI 上 38.13，MobileMiniWoB++ 上 63.04%；最好的固定形式分别为 49.30、37.44 和 60.87（图像、图像、两者同时）。AITW 和 LearnGUI 上的提升显著（+2.12，95% 置信区间 1.27 到 2.95，p < .001；+0.69，区间 0.15 到 1.26，p = .016），经 Holm 校正后依然显著。
  * *选择在轨迹内部会变化。* 分别有 83.8%、90.8% 和 57.8% 的轨迹同时用到两种形式，每条轨迹切换 1.6 到 1.8 次，连续使用同一形式的长度为 2.4 到 5.0 步。
  * *带来提升的是逐步分配，而不是两种形式的配比。* 在 LearnGUI 和 AITW 上，SwitchMem 在每一个测试过的非平凡图像比例下都胜过相同比例的随机路由。
  * *来自执行模型的目标很重要。* 直接用采样效用训练、或不用执行模型隐藏状态的路由器，在 LearnGUI 上相对固定图像几乎没有提升；在 AITW 上它们有提升但仍低于 SwitchMem，只看符号的 Binary 路由器最接近。
  * *模式可解释。* 屏幕元素密集时、在功能型动作（相对于点击和滚动）上、以及第一步之后，图像记忆更有帮助；路由器恰好在这些条件下更常选择图像。
  * *同时给出两种形式可能有害。* "两者同时"在 LearnGUI 上得 26.92，而单用图像为 37.44；在 AITW 上得 47.08，单用图像为 49.30。
  * *推理开销小。* 相比图像记忆，每步多 0.13 到 0.30 秒（总计 1.41 到 1.86 秒），远低于 RAG-GUI 的 8.8 到 11.1 秒。
  * *能迁移到另一个执行模型。* 以 UI-TARS-7B-SFT 为执行模型时，它在三个基准上同样胜过固定文字和固定图像（33.68、41.06、36.96）。
* **比标题弱或更窄的地方。**
  * *效应小，且大多是离线的。* AITW 和 LearnGUI 是把预测的下一步动作与记录的动作比对；唯一的闭环测试是 MobileMiniWoB++，在那里相对"两者同时"的提升只有两个任务（92 个中 58 对 56），置信区间为 −3.3 到 +7.6，p = .688。作者把这一结果定位为跨基准迁移，而非领域内证据。
  * *在 LearnGUI 上接近"总是用图像"。* LearnGUI 上 81.3% 的步骤被路由到图像，相对固定图像的提升为 0.69 分，所以那里的逐步选择只决定了少数步骤。
  * *有记忆并不总比没有记忆好。* 在 MobileMiniWoB++ 上，不带记忆的执行模型得 58.70%，高于固定文字（53.26）和固定图像（57.61），所以在线设置中"有记忆优于无记忆"只靠"两者同时"和 SwitchMem 成立。
  * *已有方法的基线在这个设置下很弱。* 在同一执行模型下，RAG-GUI、M3A 和 AppAgent 在 AITW 上只有 14.8 到 18.3，而完全不带记忆为 41.9；EchoTrail 和 AGMem 也低于简单的固定形式。这些都是共享检索库下的免训练移植版本，所以它们展示的是这些方法所用的记忆形式在本协议下的表现，而不是各方法的最佳水平（读者观察）。
  * *只适用于白盒模型，且绑定于检索设计。* 路由器需要执行模型的隐藏状态，因此排除了 API 模型；它只在同一个 top-1 检索步骤的两种形式之间选择。换成多个检索步骤、别的检索器，或智能体自己写的记忆，结论是否成立都未经检验。
  * *只有安卓，且是模拟器。* 作者把 iOS、新版安卓和实体设备列为尚未验证。

# Q9 贡献

* 证据表明，GUI 智能体记忆的合适形式是逐步的属性：在文字和图像之间逐步取优的神谕胜过任何固定选择，而把两者混在一个提示里可能比单用任一种更差。
* 有向链式嵌入探针：从执行模型在两种输入条件下隐藏状态的带符号差值中读出模态偏好，该信号在靠后的层中最强。
* SwitchMem：基于这一信号训练的路由器，每步只传一种记忆形式，额外延迟约 0.1 到 0.3 秒；配套的对照（相同比例的随机路由、直接用效用训练的路由器）把它的提升归因于逐步分配。
* 关于截图何时有帮助的描述性发现：元素密集的屏幕、功能型动作，以及第一步之后的状态。

# Q10 下一步

* **作者提出的方向。** iOS 与新版安卓、实体设备，以及对不暴露隐藏状态的 API 模型做路由。
* **大规模闭环评测（读者建议）。** 在领域内训练路由器，并在更大的在线套件（AndroidWorld 或类似）上报告任务成功率，使效应能与噪声区分开。
* **不止两种形式（读者建议）。** 把裁剪的动作区域（AGMem 的形式）、不给记忆和两者同时都加入路由器的选项；MobileMiniWoB++ 的结果表明，"不给记忆"和"两者同时"有时才是正确选择。
* **黑盒目标（读者建议）。** 用更廉价的执行模型状态代理（例如执行模型输出的对数概率）从采样效用训练路由器，检验隐藏状态目标到底有多必要。
* **与本项目的契合（读者笔记）。** 对本仓库中把截图或渲染页面当作证据保存的智能体，这个结果支持"同时保存文字摘要和图像、按用途选择"，而不是一开始就全部转成文字；但这里的提升很小，所以这只是一个保留选择余地的默认做法，而不是对仓库工作已被证明的收益。

# 相关

* [GUI 与计算机操作智能体](../topics/gui-computer-use-agents.md) - 为冻结的移动端 GUI 执行模型逐步选择以文字描述还是截图呈现检索到的示范，在 AITW、LearnGUI 和 MobileMiniWoB++ 上评测。
* [智能体记忆](../topics/agent-memory.md) - 把检索到的记忆以什么形式呈现（而非其内容或检索方式）当作逐步决策，并发现同时给出两种形式可能有害。
* [ExpActivator](../papers/2609.33304.md) - 同样利用冻结骨干模型自身的表示，为移动端 GUI 智能体做逐步的记忆决策，并离线对照记录的动作评测；ExpActivator 选择展示哪一个过往动作，SwitchMem 选择以哪种形式展示它。
* [MemAdapter](../papers/2610.05162.md) - 同样在检索之后介入，方法是让模型写明每条记忆能支持什么；SwitchMem 改变的是记忆的模态。
* [UI-Mate](../papers/2608.15930.md) - 让 GUI 智能体以转换成子任务工作流的示范为条件；SwitchMem 保留单个示范步骤，只改变其形式。
* [RSIAgent](../papers/2609.15364.md) - 与 SwitchMem 的文字轨迹记忆基线之一 EchoTrail 做了比较。
