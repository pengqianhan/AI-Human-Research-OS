> 论文：**SkillOpt: Executive Strategy for Self-Evolving Agent Skills**
> 论文链接：<https://arxiv.org/abs/2605.23904>
> 机构：微软、上海交通大学、同济大学、复旦大学

# Q1 问题定义

* **输入 `X`**：一个目标领域（某个基准和执行 harness）、一份初始技能 `s`（自然语言策略文档），以及一个权重永不更新的冻结目标模型 `M`。
* **输出 `Y`**：一份经过优化并导出的 `best_skill.md`——一份约 300–2,000 token 的紧凑自然语言策略——通过留出验证从训练过程中产生的候选技能里选出。
* **核心问题**：当冻结前沿 agent 的领域适配是通过自然语言技能文档而非模型权重完成时，应该如何用训练式的证据、步长、验证、更新方向控制来优化这份技能文档本身，而不是靠一次性写好或无约束地重写？
* **范围**：每个领域只优化一份持久化的技能制品；目标模型权重、执行 harness、评估器在整个过程中保持不变。

# Q2 问题的新颖性

技能打包（Agent Skills 标准）、技能构建/演化（SkillFoundry、EvoSkill、AutoSkill、Trace2Skill、SkillX）都已是既有方向，提示词优化（TextGrad、GEPA、ABSTRAL、EvoTest）同样如此。本文的新意在于把一套显式的深度学习训练类比——用 rollout 与反思批大小类比证据量、用带调度的有界文本学习率类比步长、用留出验证门类比校验集、用被拒编辑缓冲区类比负反馈、用按 epoch 的慢速/元更新类比动量项——具体应用到*一份*持久化、harness 无关的技能文档上，而不是应用到完整提示词、系统设计或不断增长的技能库上。作者将本文定位为(据其所知)首个把技能优化系统性地当作前沿 agent 领域适配训练方法来研究的工作。

# Q3 科学假设

如果把技能编辑当作一个可控的领域适配过程——外部技能文档状态、一个独立的前沿优化器模型，以及对证据（rollout/反思批大小）、步长（有界文本学习率及调度）、验证（留出验收门）、更新记忆（被拒编辑缓冲区、按 epoch 的慢速/元更新）的训练式控制——那么产出的紧凑技能制品将优于无技能、人工撰写、单次 LLM 生成、轨迹蒸馏（Trace2Skill）、提示词优化（TextGrad、GEPA）以及技能演化（EvoSkill）等基线,并能在不改变模型权重的情况下跨模型、跨 harness、跨相关基准迁移。论文通过 52 个(模型、基准、harness)对比单元格外加成分消融和迁移实验来验证这一假设；并未检验学到的规则是否代表超出所评估基准家族的通用程序性知识,也未检验无自动打分的开放式/主观判断任务。

# Q4 相关工作与关键人物

* **提示词自动调优与 agent 配置搜索**：GEPA(轨迹反馈驱动的反思式提示词演化,在若干 agent 任务上超过强化学习)；ABSTRAL 与 EvoTest 把这一思路从单一提示词扩展到多 agent 设计文档和完整 agent 系统的测试时演化。SkillOpt 的不同之处在于优化的是一份持久化、可导出、可复用的技能文档,而非提示词或完整配置。
* **技能构建与演化**：SkillsBench 与一篇关于 agentic 技能的 SoK 把技能定义为可复用的程序性知识；AutoSkill、Trace2Skill、SkillX、SkillFoundry、Memp 从经验、轨迹或异构资源中构建这类技能；EvoSkill、SkillForge、EvoSkills、SkillClaw、SkillRL、面向技能库的强化学习、AutoRefine、ProcMEM、Evolver 进一步通过失败分析、协同演化、集体更新或强化学习来精炼技能。SkillOpt 研究的是一个更窄的问题——用深度学习式控制训练*一份*紧凑的领域技能——而非发现、库的增长、共享或策略优化。
* **作为动机引用的基础性 agent 工作**：ReAct、Toolformer、Voyager、SWE-agent(支撑 harness 无关的工具使用部署)；Reflexion、Self-Refine(支撑反向传播阶段的轨迹驱动反思)。
* **作者/机构**：Yifan Yang、Ziyang Gong、Weiquan Huang、Qihao Yang、Ziwei Zhou、Zisu Huang、Yan Li、Xuemei Gao、Qi Dai、Bei Liu、Kai Qiu、Yuqing Yang、Dongdong Chen、Xue Yang、Chong Luo——微软、上海交通大学、同济大学、复旦大学。

# Q5 核心解法

一个针对单一冻结目标模型 `M` 的逐步优化循环,由独立的优化器模型驱动：

1. **前向传播(rollout 证据)**：`M` 用当前技能对训练集的一个 rollout 批次(默认 40 个任务)执行;harness 记录完整轨迹——消息、工具调用、观测、输出、验证器反馈。
2. **反向传播(小批反思)**：优化器模型把成功和失败分开,并各自划分为反思小批(默认大小 8,配 16 个并行分析工作者),提出结构化的增/删/替换编辑(或在重写模式下给出全量重写建议)。局部提议先分层合并,优先采纳失败驱动的修正,并过滤重复、矛盾或针对单个样例的建议。
3. **有界文本更新**：合并后的编辑池按预期效用排序,并裁剪到文本学习率 `L_t`(默认 4,余弦衰减到下限 2;也支持常数、线性、自适应调度)——这是与无约束提示词重写的关键区别,后者可能抹掉有用的规则或对单次失败过拟合。
4. **验证门与被拒编辑缓冲区**：每个候选技能都用同一冻结模型和 harness 在留出的选择集上打分;只有严格优于当前选择集分数才被接受(平局也算拒绝),只有同时超过历史最佳分数才成为 `best_skill.md`。被拒的编辑及其造成的分数下降会被记录进一个 epoch 内的缓冲区,并反馈给后续的反思调用作为负反馈,且不额外消耗推理成本。
5. **按 epoch 的慢速/元更新**：每个 epoch 结束时,在上一个 epoch 的技能与当前 epoch 的技能下分别采样同一批训练样例,归类为改善/退步/持续失败/稳定成功,并把一段纵向指导写入技能文档中一个受保护的区域——该区域不可被逐步编辑覆盖;这一候选同样要经过相同的验证门。一份独立的、仅优化器可见的"元技能"(从不下发给目标模型)总结跨 epoch 哪些编辑模式有效、哪些被拒,并被前置到后续优化器提示词中。
6. **harness 无关部署**：一个轻量级 `AgentAdapter` 负责构造批次、把当前技能注入 agent 上下文、运行原生 harness(直接对话、Codex CLI 或 Claude Code CLI),并返回打分后的轨迹。同一份 `best_skill.md` 文件格式在三种模式下都可用,这正是论文跨 harness 迁移实验得以成立的基础。

# Q6 实验设计

六个基准(SearchQA、SpreadsheetBench、OfficeQA、DocVQA、LiveMathematicianBench、ALFWorld)× 七个目标模型(GPT-5.5、GPT-5.4、GPT-5.4-mini、GPT-5.4-nano、GPT-5.2、Qwen3.5-4B、Qwen3.6-35B-A3B)在直接对话模式下运行,外加 GPT-5.5 在 Codex CLI 和 Claude Code 两种 harness 下各评估五个基准(ALFWorld 因需要持续的具身环境交互而被排除)——共计 52 个(模型、基准、harness)单元格。每个单元格对比七种基线:无技能、人工撰写技能、单次 LLM 生成技能、Trace2Skill、TextGrad、GEPA、EvoSkill(harness 侧的竞争对手)。确定性的训练/选择/测试划分(种子 42,默认 2:1:7,消融扫描时用 4:1:5);选择集仅用于接受或拒绝候选编辑,所有主要结果均在留出的测试集上计算。默认超参数:4 个 epoch、rollout 批大小 40、反思小批大小 8(16 个并行工作者)、`L_t=4` 余弦衰减到下限 2、严格的留出验证门、慢速更新每 epoch 采样 20 个任务、patch 编辑模式、可选的被拒编辑缓冲区。消融实验扫描训练集比例、小批/rollout 批大小、学习率取值(1/2/4/8/16)、调度方式(常数/余弦/线性)、慢速更新采样数,并移除被拒缓冲区或元技能+慢速更新机制。迁移实验测试跨模型(在一个模型规模上训练的技能部署到另一规模)、跨 harness(Codex ↔ Claude Code)、跨基准(OlympiadBench → Omni-MATH)的泛化能力。另有一项优化器强度消融,对比强前沿优化器(GPT-5.5)与和被部署模型同规模的目标匹配优化器。

# Q8 证据质量

实验广度很强:在七种基线家族(无技能、人工、单次 LLM、轨迹蒸馏、两种提示词优化器、一个技能演化型 harness 竞争者)上做到 52/52 个单元格最优或并列最优,是一个异常干净的全面胜出,而消融实验清楚拆解了各组件的贡献——整个消融套件中最大的单项性能下降(SpreadsheetBench 上 -22.5 分)来自同时移除元技能和慢速更新。跨模型、跨 harness、跨基准的迁移结果全部为正(没有一行低于目标模型的无技能基线),进一步支撑了可复用性的主张。需要注意的地方:与 TextGrad、GEPA、Trace2Skill、EvoSkill 的对比都是本文自己的复现,而非各方法原始发布的代码和超参数,因此基线相对强弱依赖于这些复现的保真度;六个基准全部采用自动的精确匹配或硬性成功率打分,因此该方法在开放式、主观判断类任务上的表现未经检验,论文自己也明确指出了这一局限;部分基准上的优化器成本相当可观(DocVQA 上每提升一个绝对测试点最高需要 4640 万训练 token),不过这一成本只在离线训练阶段支付一次,部署时不增加任何开销。

# Q9 主要贡献

1. 把 agent 技能学习形式化为对一个外部自然语言状态的优化问题,并提出 SkillOpt:rollout 批次、反思小批、增/删/替换编辑、文本学习率与调度、留出验收门、被拒编辑缓冲区、按 epoch 的慢速/元更新。
2. 一项覆盖六个基准、七个目标模型、三种执行 harness 的大规模实证研究,表明 SkillOpt 在 52 个单元格中全部最优或并列最优,GPT-5.5 相较无技能平均提升 +23.5 分(直接对话)、+24.8 分(Codex)、+19.1 分(Claude Code)。
3. 成分消融加三项迁移研究(跨模型、跨 harness、跨基准),表明导出的 `best_skill.md`——仅由 1–4 次被接受的编辑构成、长度 300–2,000 token——是紧凑、可解释、且无需更新模型权重即可复用的。

# Q10 下一步

* 论文自述的局限(附录 B):该循环依赖有打分的轨迹和留出选择集,因此最适用于目标任务具备自动验证器、精确匹配指标、可执行检查或其他可靠反馈信号的场景;对于成功标准主观、多维或代价高昂的开放式领域,验证门可能需要更强的人工或模型评估;尽管最终部署的制品只是一份紧凑的 `best_skill.md`,训练技能仍需要额外的 rollout 计算和对优化器模型的调用——这一成本在同一技能被复用时可被摊薄,但对一次性任务吸引力较低;SkillOpt 刻意只优化一份可移植的技能,而非扩大技能库或改变模型权重,这在设计上简化了部署,但单一技能可能不足以覆盖需要许多互不相干程序的高度异构领域;优化出的技能可能编码了训练分布特有的启发式规则,因此在迁移到明显不同的模型、harness 或任务设置之前,仍需要审慎的留出评估。
* 论文自述的展望:跨领域共享基础设施的技能库;跨基准复用优化器侧的元技能;面向开放式任务的无奖励或偏好驱动验证门;把优化后的技能反蒸馏回目标模型,作为通向权重级适配的一个中间步骤。
* **与本仓库的关联**:留出验证门、被拒编辑缓冲区,以及受保护的慢速/元更新区域,构成了一种可直接对照本仓库自身技能编写与记忆更新约定(先合并再追加、`human-cognition-cache` 中的证据阈值)的模式——如果本仓库未来要从执行日志自动调优技能文件,而不是手工编辑 `SKILL.md`,这套设计值得比较参考。
