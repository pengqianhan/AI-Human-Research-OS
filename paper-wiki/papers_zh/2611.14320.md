# Q1 问题定义

* **输入 (X)：** 一批在无记忆条件下收集的历史运行，每条包含任务、智能体的动作与观察轨迹，以及一个成功或失败的二值标签；之后是新的测试任务。没有标准解答，也没有专家解释，所以标签并不说明是哪些动作导致了结果。
* **输出 (Y)：** 由这批运行一次性构建、之后冻结且只读的记忆，以及智能体带着记忆在测试任务上的表现。
* **约束：** 不允许为验证某条记忆额外运行任务；所有对比方法都从同一批无记忆训练运行构建记忆。目标有两部分，平均准确率会把它们混在一起：解决更多任务，同时不把原本能解决的任务做坏。

# Q2 问题新颖性

这不是新发现。论文引用了已有结论：记忆可能降低表现，智能体会忽略或误读压缩后的经验，持续更新的记忆存在检索竞争和负迁移。控制“什么能进入记忆”的方法也已存在：PREPING 在存储前验证合成的练习轨迹，[SkillOpt](../papers/2605.23904.md) 通过留出评估决定是否接纳技能更新，ReMe 根据后续效用更新或删除记忆。新的地方在于检查发生的位置。论文不改动准入环节，而是在智能体即将采用一条经验时，给它一条回到来源运行的路径；并且对照“重跑基线”把损害和收益分开度量。

# Q3 科学假设

如果每条经验都保持与“这次运行为何成功或失败的说明”以及原始轨迹的链接，并且在经验缺少细节、与另一条经验冲突或来自失败运行时提示智能体打开这些链接，那么与只给同样的经验相比，智能体会解决更多原先失败的任务，并更少把原先成功的任务做坏。理由是：轨迹里往往还保留着能反驳错误经验的那条观察。

# Q4 相关工作与关键人物

* **经验驱动的程序性记忆。** 语言反馈与保存的成功案例（Reflexion、[ExpeL](../concepts/expel.md)），可执行技能（Voyager），指南、手册与工作流（AutoGuide、AutoManual、[Agent Workflow Memory](../concepts/agent-workflow-memory.md)、Memp），以及持续更新的推理记忆与 playbook（[ReasoningBank](../concepts/reasoningbank.md)、ACE、ReMe）。这些工作负责生成和更新经验；WikiTrace 关注在执行过程中重新审视经验。
* **未经验证的记忆能否可靠复用。** 关于经验被忽略或误读、持续学习中的负迁移、复用经验放大不安全行为的研究；以及准入和修订方法（PREPING、SkillOpt、ReMe）。
* **记忆的结构与访问。** 用于压缩和检索的层级记忆；HORMA 把文件系统摘要连到原始交互历史并学习最小充分上下文；决定何时检索的主动访问方法；Direct Corpus Interaction 通过终端工具访问语料。
* **关键人物。** KAIST 的 Yukyeong Lee 与 Yumin Choi（共同一作）、Jinheon Baek、Sung Ju Hwang，另列有 DeepAuto.ai 单位。Yumin Choi、Jinheon Baek、Sung Ju Hwang 也是 PREPING 的作者。可能的批评者是被改造的基线方法的作者，他们可以质疑离线单遍协议（见 Q8）。

# Q5 核心解决思路

把经验和它的证据放在一起，由智能体决定何时去读证据。

1. **三层链接。** 一个编译器读入一次运行（任务、轨迹、结果），写出一份 *compilation*，即对这次运行关键决策或失败原因的诊断（成功和失败用不同模板），再加上至多三条 *insight*。每条 insight 是独立文档，写明做什么、何时适用、来自哪次运行、那次运行是否成功。原始轨迹原样保留，每条 insight 同时链接到它的 compilation 和原始运行。
2. **不合并、不更新、不过滤。** 每条轨迹只调用一次编译器。insight 写入后不再编辑或删除，所以池中可能有重复甚至互相矛盾的经验，取舍留给智能体。
3. **测试时访问。** 第一条消息包含全部 insight，并列出任务与当前任务最相似的三次历史运行。记忆以只读文件挂载，智能体用 `read` 和 `bash` 检索。提示要求它在 insight 缺少行动所需细节、来自失败运行或与另一条 insight 不一致时下探（descend）到来源运行，动作失败时再次下探。

论文的动机案例是 ExpeL 的一条规则：ALFWorld 的台灯任务只要物体在亮着的台灯旁就算完成。而产生这条规则的那次运行里，智能体其实拿起了物体，与规则相矛盾。

# Q6 实验设计

* **测试集。** 五个基准的八个套件：[ALFWorld](../concepts/alfworld.md) seen 与 unseen、[ScienceWorld](../concepts/scienceworld.md)（30 类任务中的 10 类）、PlanCraft seen 与 unseen、[AppWorld](../concepts/appworld.md) Test-Normal 与 Test-Challenge，以及 τ³-bench Retail（论文引用的是 τ-bench 和 [τ²-bench](../concepts/tau2-bench.md) 的论文）。
* **智能体。** Pi 终端智能体，配各基准的 ReAct 指令；智能体和记忆构建器都使用高推理强度的 deepseek-v4-flash。
* **方法。** No Memory；AWM；ExpeL；ReasoningBank；Insights Only（注入与 WikiTrace 相同的 insight，但不挂载 compilation 和轨迹，也没有下探提示）；WikiTrace。三种已有方法使用官方实现并改成离线协议：记忆只从共享训练运行构建一次，用真实二值结果代替 LLM 评判或环境奖励，每条轨迹只读一遍。
* **协议。** 每个套件和方法跑三次，使用各基准原有指标。
* **Gain 与 Regression。** 设 B 为某任务三次 No Memory 运行的多数结果。Gain 是在 B 为失败的任务上带记忆的成功率，Regression 是在 B 为成功的任务上带记忆的失败率。另外再跑三次 No Memory，用同一个 B 评分，得到“重跑下限”。置信区间来自对任务的 10,000 次自助重采样。
* **分析。** 一个 LLM 评判（gpt-5.6-sol）对“无记忆三次都成功、带记忆却失败”的案例归因；把运行分成 Descent 和 Stay；评判再标注每次下探的触发原因、目标和效果（与第二个评判 GLM-5.3 的 Cohen's κ 在触发上为 0.77，在目标上为 0.63）；分别用成功运行、失败运行或二者构建记忆；把基线的构建预算提高到三倍或九倍；在三个套件上换用第二个骨干模型 GLM-5.3-flash。

# Q8 证据质量

**主结果。** 三次试验的均值，再对八个套件取平均：

| 方法 | 平均 | 说明 |
|---|---|---|
| No Memory | 79.5 | |
| ExpeL | 80.3 | 在三个套件上低于 No Memory |
| AWM | 81.6 | |
| ReasoningBank | 81.7 | |
| Insights Only | 87.0 | 相同 insight，无来源访问，无下探提示 |
| WikiTrace | 90.2 | 八个套件全部最好 |

WikiTrace 是唯一在每个套件上都不低于 No Memory 的方法。它相对已有方法的大部分优势在 Insights Only 中已经出现（比 No Memory 高 7.5 分）；来源访问和下探提示再加 3.2 分。两者在单个套件上的差距常常落在跨试验的一个标准差以内，例如 PlanCraft unseen 为 81.3 ± 8.5 对 73.0 ± 10.7。主表没有显著性检验（读者观察）。

**Gain 与 Regression。** WikiTrace 的 Regression 为 4.5%，Insights Only 为 6.5%，重跑下限为 9.7%；WikiTrace 在八个套件中的七个上低于 Insights Only，并且是唯一一个置信区间完全低于重跑带的方法。它的 Gain 比重跑下限高 35 个百分点，Insights Only 高 27，已有方法高 7 到 14。对这些数字有两点读者观察：

* 重跑下限说明，不带记忆重跑智能体，本来就会让大约十分之一的已解决任务翻转，所以测到的 Regression 大部分是运行间波动。论文自己的表述，即已有记忆方法的 Regression“与重跑相当，甚至更高”，才是准确的说法。
* 按基准的计数（表 6）显示 Gain 的样本在某些地方很薄：ALFWorld 只有 10 个、τ³-bench 只有 6 个任务符合条件。在 τ³-bench 上 WikiTrace 的 Gain 低于 Insights Only（2.3 对 2.7 个任务）。把表中计数跨基准合并，WikiTrace 每次试验在 649 个符合条件的任务中做坏 26.0 个（4.0%），Insights Only 为 39.0 个（6.0%）；在 172 个任务中新解决 112.7 个（65.5%），对 98.0 个（57.0%）（读者计算；论文是按套件平均）。

**记忆为什么会做坏已解决的任务。** 在被评判的失败中，52% 可追溯到智能体采用的某条记忆，最常见的是这条记忆本身是错的（20%）；其余看不出与记忆的联系。这些标签来自阅读智能体自述推理的 LLM 评判，局限性一节承认了这一点。

**下探何时有用。** 在三个文本世界基准中，智能体在 Easy 任务的 22% 运行、Hard 任务的 44% 运行中打开了来源材料。Descent 运行相对 Insights Only 的领先幅度比 Stay 运行多 1.6 到 4.7 分。出问题之后的下探（占 36%）领先 10.4 分，而没出问题时的下探只领先 3.7 分；例行检查是最常见的一类（38%），带来 3.4 分。打开的运行在 43% 的下探运行中改变了计划：修订一条 insight（24%）、补上细节（14%）或提供新事实（4%），这些运行领先 8.3 分，对 4.4 分。论文指出，何时下探由智能体自己决定，所以两组之间的差别不只是下探本身。

**消融到底隔离了什么。** 从不打开来源的 Stay 运行仍然领先 Insights Only 0.6 到 12.4 分，并且自报使用的 insight 少 19% 到 28%。所以 3.2 分的差距里，有一部分来自提示和挂载的文件让智能体更有选择地使用记忆，即使没有读任何证据。Insights Only 同时去掉了来源访问和下探提示，没有哪一组把二者分开（读者观察）。

**失败运行。** 在 PlanCraft 和 ScienceWorld 上，两种方法用仅失败运行的记忆都比仅成功运行的记忆得分高，两者都用最高。Insights Only 在仅失败运行时 Regression 最高（9.3% 和 9.4%）；WikiTrace 把它们降到 7.1% 和 8.9%，在 ScienceWorld 上只降了半个百分点。

**成本与第二个模型。** WikiTrace 每个测试任务的成本是 Insights Only 的 1.17 倍。让 AWM 构建九遍、ExpeL 和 ReasoningBank 构建三遍，它们分别升到 83.8、83.3 和 82.8，仍低于 Insights Only。用 GLM-5.3-flash 在 PlanCraft 和 ScienceWorld 上，WikiTrace 平均 92.7，Insights Only 为 90.9，No Memory 为 71.2，每种已有方法都至少在一个套件上低于 No Memory。

**对比的局限（读者观察）。** 离线单遍协议去掉了基线设计的一部分：ExpeL 失去了重复尝试和示例检索，ReasoningBank 失去了每个测试任务之后的更新。记忆规模很小，约 50 次运行、每次至多三条 insight，所以把全部 insight 放进第一条消息在这里可行，但没有在更大规模上测试。两个模型都属于快速档。

# Q9 贡献

1. 对照无记忆重跑下限度量 Gain 和 Regression，显示记忆方法可以在提高平均准确率的同时，以接近随机波动的比例把已解决的任务做坏。
2. 对记忆致失败的归因分析：约一半可追溯到被采用的某条记忆，五分之一是错误的记忆。
3. WikiTrace：insight 始终链接到运行诊断和原始轨迹，测试时有提示驱动的下探。
4. 一个“相同 insight”的对照，显示使用时访问证据带来 3.2 分并降低 Regression，而且在证据改变了智能体计划时效果最大。

# Q10 后续方向

* **论文自述的局限。** 记忆由二值结果构建，compilation 的诊断可能是错的；链接让智能体可以核对 insight，但并不验证它；提示随记忆增长，记忆大到无法全部注入时的检索问题留待以后；归因和下探标签描述的是智能体自述的推理。
* **把提示和证据分开。** 跑“有下探提示但没有来源”的 Insights Only，以及“有来源但没有提示”的 WikiTrace（读者建议）。
* **把修订写回去。** 记忆是冻结的，智能体发现某条 insight 错了，下一个任务它仍然是错的。把修订连同它自己的证据链接记录下来，可以把使用时检查和论文搁置的准入方法连起来（读者建议）。
* **规模。** 用上千次运行测试，此时智能体必须先找到相关的 insight；也用更强的模型测试，它们可能不那么需要证据。
* **与本项目的关系。** 对基于文件的研究记忆，这个设计说明：每条提炼出的经验都应保留指向产生它的会话或产物的指针，而来自失败工作的经验最值得重新核对。
