# Q1 问题定义

* **设定：** 搜索智能体的“出题者-解题者”（proposer-solver）自演化，如 Dr. Zero（Yue et al., 2026, arXiv:2601.07055）。出题者把源文档变成问题和伪标签（pseudo-label）；被接纳的问题对用来训练解题者；解题者在新题上与伪标签的一致程度，又成为出题者的奖励。全程不使用人工标注的问答数据。
* **输入（X）：** 一个源文档语料、同时扮演两个角色的基座模型（Qwen3.5-4B 或 Qwen3.5-9B），以及一个搜索工具。
* **输出（Y）：** 训练好的搜索策略（主解题者），在开放域单跳与多跳问答上评测。
* **核心问题：** 在这个闭环里，“一致”是正确性唯一的代理信号。一个错误的伪标签会把解题者训练成在同一来源的后续题目上重复同样的错误，出题者随后又因这种一致而获得奖励。作者把这一结果称为**合谋作弊（co-cheating）**：内部奖励上升，外部正确率却没有跟上。作者强调这并不意味着任何有意的协同。
* **度量方式：** 一个事后审计器（gpt-6-astra/high）根据每篇源文档构造有证据支撑的参考答案，评判保存下来的伪标签以及用于出题者奖励的五个解题回答。它报告标签正确率 T_P、解题正确率 T_S、环内一致率 A、**错误一致质量**（false-agreement mass）F（两者在同一个错误答案上一致的比例），以及丢失的得分 L（正确回答因错误标签而未获计分）。审计器从不反馈进训练。

# Q2 问题新颖性

部分新颖。作者明确表示自己没有提出自博弈（self-play）、答案验证或交叉拟合（cross-fitting）。自生成课程（SPIN、R-Zero、Absolute Zero、SPICE）、自演化搜索（Dr. Zero、Search Self-Play）、代理奖励的过度优化（Gao et al., 2023）以及伪标签的确认偏差（Arazo et al., 2020）都是已有工作。SearchMaster（arXiv:2608.01822）被列为对搜索自博弈误导信号最接近的互补诊断，CAFE（arXiv:2608.24794）则是关于“共同演化反馈”的同期工作。本文更窄的贡献在于：用外部审计证明这一特定失效逐轮加剧，并分离出一个原因——**为出题者提供反馈的那个解题者的训练来源（ancestry）**。

# Q3 科学假设

如果给某个题目打分的解题者曾在同一源文档派生的伪标签上训练过，那么源自该文档的错误就可能以奖励的形式回到出题者。切断这条路径——让每个打分的解题者都从未在被评估的来源上训练——应当降低错误一致，得到更好的课程，进而得到更好的下游搜索策略。仅提升标签质量（训练前验证）帮助应当更小，因为它没有切断回流路径。

# Q5 关键解法思路

* **多样本验证（MSV），一种准入时检查。** 对每个提议，同一模型在提供源文档时回答三次、不提供时回答三次。某一视角中至少两个样本一致即形成多数答案。只有两个多数答案都存在且相互兼容时才接纳该题，并用多数答案替换出题者的草稿标签。代价是每个候选多出六次标注生成。按作者的说法，其局限在于：同一模型的六个样本可能共享错误，而且验证无法阻止后续的反馈解题者复用由被评估来源派生的标签。
* **CrossFit，本文主方法。** 每篇源文档只被分配一次，进入第 0 折或第 1 折，由它派生的所有问题都沿用该折。两个辅助解题者各自只在本折被接纳的问题上训练。之后，第 0 折的问题由在第 1 折上训练的解题者打分，反之亦然。出题者奖励沿用 Dr. Zero 的“前沿”规则：五个解题回答中有 k 个匹配时 f(k) = (5−k)/4（0 < k < 5，否则为零）；唯一的变化是由**哪个**解题者产生这些回答。主解题者不拆分，仍在两折全部被接纳的问题上训练。
* **为什么按来源分折：** 若按单个问题拆分，同一文档派生的相关问题会落到两侧，回流路径依然存在，消融实验证实了这一点。
* **两者结合：** MSV 决定是否接纳以及采用哪个标签；CrossFit 决定由谁给下一个提议打分。

# Q6 实验设计

* **训练：** 每种处理跑三轮，每轮 18 次出题者更新、25 次主解题者更新；每轮接纳 1,600 道题；每题五个解题回答；使用按序列归一化的策略梯度目标与组内归一化优势；温度 0.8，top-p 0.95；每条轨迹至多五次助手动作、每次至多 512 个新 token。CrossFit 为每个辅助解题者每轮增加 25 次更新（共 50 次）。所有处理都从同一个公开检查点出发。
* **处理组：** Dr. Zero（耦合反馈）、MSV、CrossFit、MSV + CrossFit。另在相同骨干上复现了 Prompting、R1-Instruct 和 Search-R1 作为外部基线。
* **下游评测：** 固定的 1,325 题集合：Natural Questions、TriviaQA、PopQA、HotpotQA、2WikiMultiHopQA、MuSiQue 各 200 题，外加 Bamboogle 全部 125 题。每题一条贪心轨迹，工具预算与答案抽取完全相同，指标为 Cover-EM（归一化后的参考答案出现在归一化预测中即算对），七个基准做宏平均。
* **审计：** 每个计划步骤都审计（每次运行 129 步，每轮 43 步），报告第 3 轮均值。各处理的审计覆盖率 J/E 约为 0.86；无法判定的样本保持未判定，不强行打标签。
* **固定题库上的机制对照：** 复用同样 3,000 道已保存的问题及其采用标签，只改变反馈解题者的训练数据（耦合、同源辅助、全数据辅助、按问题随机拆分、按来源 ID 拆分、半预算按来源拆分，以及 MSV 变体），报告五个随机种子的均值 ± 标准差。这排除了准入变化和课程变化作为解释。
* **成本：** 每次运行预留的 H200 小时数、token 数和评审请求数。

# Q8 证据质量

* **有支撑的：**
  * *耦合反馈下合谋作弊逐轮加剧。* 第 1 轮错误一致质量均值仅为 0.004（4B）和 0.003（9B），到第 3 轮达到 0.061 和 0.088，同时丢失得分下降。一致率升到解题正确率之上（第 3 轮：4B 上 A 0.710 对 T_S 0.669；9B 上 0.752 对 0.689）。
  * *CrossFit 让审计指标朝预期方向变化。* 第 3 轮标签正确率从 0.747 升至 0.819（4B）、从 0.737 升至 0.851（9B）；错误一致降至 0.030 和 0.037；一致率降到解题正确率之下或持平。单独的 MSV 只降到 0.057 和 0.072；MSV + CrossFit 降到 0.020 和 0.017。
  * *下游收益。* 平均 Cover-EM（4B/9B）：Base 0.384/0.409，Search-R1 0.401/0.434，Dr. Zero 0.400/0.428，MSV 0.407/0.436，CrossFit 0.488/0.512，MSV + CrossFit 0.491/0.515。CrossFit 在两个规模的每个基准上都有提升，四个多跳基准的增益（10.0/10.9 个百分点）大于三个单跳基准（7.3/5.2）。它相对 Dr. Zero 的优势从第 2 轮后的 4.2/4.3 扩大到第 3 轮后的 8.8/8.4。微平均与宏平均对各处理的排序一致。
  * *起作用的是“来源排除”（固定题库）。* 仅仅换一个评估者不够：同源辅助解题者和全数据辅助解题者的 F 仍为 0.064/0.087 与 0.058/0.069，按问题随机拆分为 0.050/0.062。按来源 ID 拆分降到 0.004/0.001，固定题库上的解题正确率 0.687→0.770（4B）、0.717→0.868（9B），回放准确率 88.1%→91.5% 和 87.0%→91.7%。半预算辅助解题者（0.005/0.002，91.6%/91.8%）排除了“额外更新”这一解释。
* **较弱或有边界的：**
  * *每种处理只跑了一次自适应训练。* 下游结果表和审计都来自每个处理、每个规模各一次的自演化运行；只有固定题库回放报告了随机种子。1,325 题上的结果没有置信区间或显著性检验。
  * *审计本身是 LLM 评审。* 参考答案构造和正误判定都由 gpt-6-astra/high 完成；约 14% 的审计样本未能判定。获取到的正文没有报告人工一致性检查，尽管相关工作部分把人工验证列为采用盲化证据收集的动机。
  * *算力不对等。* 实际使用的 CrossFit（每折 25 次更新）比 Dr. Zero 多预留 72%（4B）和 79%（9B）的 H200 小时（650 对 379、854 对 476）；MSV 多约 90%，评审请求近五倍；MSV + CrossFit 为 2.6-2.7 倍。半预算 CrossFit（+36%/+40%）在固定题库上与完整版效果相当，但其下游 Cover-EM 未报告。预留小时包含等待时间，因此这些只是预算比例，不代表 GPU 利用率。
  * *效应大小与机制（读者注）。* 耦合自演化只比基座高 1.6-1.9 个百分点，而 CrossFit 高 10.4（4B）和 10.3（9B）个百分点，对应的错误一致质量变化只有 3-5 个百分点。回放实验把*审计指标*的变化归因于来源排除，但没有实验分离下游收益中有多少来自合谋作弊的减少，有多少来自用训练方式不同的辅助解题者打分带来的其他效应（例如前沿奖励得到了不同的难度信号）。
  * *错误一致下降还有其他解释。* 作者指出，只靠拒收难题也能让被接纳题目上的 F 下降；共享的预训练错误、重叠的网页证据和语义相关的来源仍会让两个解题者的错误相关。CrossFit 抬高了丢失得分（4B 上 0.020→0.038，9B 上 0.025→0.041），即以更多“被错误拒绝的得分”换取更少的错误一致。
  * *基线。* 复现的 Search-R1、R1-Instruct 和 Prompting 遵循 Dr. Zero 的协议；获取到的正文没有说明 Search-R1 复现使用的训练数据。评测是各基准的固定子样本，指标是宽松的 Cover-EM。

# Q9 贡献

* 为“出题者-解题者”自演化命名了一种失效模式（合谋作弊），给出外部、有证据支撑的审计协议与指标（T_P、T_S、A、F、L），把环内一致与正确性区分开，并证明它随轮次恶化。
* 一个简单且保持原目标的干预 CrossFit：只改变出题者反馈的来源，主解题者的数据和更新规则保持不变。
* 固定题库回放对照：把来源级排除与“复制评估者”“任意拆分”“课程选择”“额外优化”区分开。
* 一张成本表：报告每种干预在预留 GPU 时间、token 和评审请求上的代价。

# Q10 下一步

* **作者列出的方向：** 把排除从单篇文档扩展到相互关联的来源（相关网页、共享证据），并测量端到端效率；对关联来源的鲁棒性和更低的端到端成本目前都尚未确立。
* **随机种子与人工审计（读者注）：** 在把 8-9 个百分点的收益视为稳定结论之前，应以多个随机种子重复自适应运行，并由人工裁定一部分审计样本以校准 LLM 评审。
* **算力对等的比较（读者注）：** 给 Dr. Zero 同样的额外预算（更多解题者更新或更多轮次），并报告半预算 CrossFit 的下游得分。
* **超出搜索问答（读者注）：** 只要一个在自生成标签上训练的学习型评估者给下一轮提议打分，就存在同样的回流路径，例如自博弈代码生成，或自己给自己的测试打分的自演化技能库。[智能体自我演化](../topics/agent-self-evolution.md)主题里的验证者独立设计（RSIAgent 的隔离验证者、HexaAnything 让验证者独立于提议模型）在驾驭层面针对同一问题；CrossFit 则是该思路在权重层面、以数据来源为抓手的版本。
* **与 Iris 准入测试的对比（读者注）：** [Iris](../papers/2609.04304.md) 只接纳“参考模型闭卷答不出、给出支撑实体图后能答出”的训练题，强调难度与可解性；MSV 接纳的则是“有源与无源两种多数答案一致”的题，强调稳定性。两种过滤会选出不同的题目，且都不涉及反馈来源问题。
