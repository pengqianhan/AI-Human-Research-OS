# Q1 问题定义

* **输入 (X)：** 一个 LLM 智能体，配有 18 个 MCP 工具（远程运营、实体执行、持久笔记本）、固定的系统提示词，以及每天一份关于现金、净资产、库存、节假日和每台机器库存、销量、临期状态的日报。环境是一个模拟器：20 台自动售货机（6 台工厂、2 台校园、4 台住宅、6 台商业、2 台办公），共用一个仓库和 1,372 种商品的目录。
* **输出 (Y)：** 180 个模拟日内关于选品、每台机器定价、采购、补货上门和报废的决策。评分是期末净资产：现金加上货架、仓库和在途的未过期库存（按成本计），起始资金 40,000 元。
* **约束：** 采购下单即付款，三天后到仓；货架库存只能通过上门作业改变，每台机器每天收 35 元上门费；批次在到仓 30 或 90 天后过期，卖出一件过期商品罚 1,000 元；仓库租金每件每天 0.03 元，机器租金每台每天 4 元；每台机器最多放 200 件。需求参数和未满足的需求对智能体不可见。

# Q2 问题新颖性

部分新。长程经营类基准已有不少：Vending-Bench 经营一台售货机，RetailBench 一家超市，MerchantBench 和 StoreBench 一家网店，E-Commerce Bench 最多四家共用库存的网店。论文的表 1 把 AutoVend 定位为其中唯一同时具备"20 个不同类型的经营单元、真实商业数据、实体作业"的基准。新的地方在于组合：一个智能体要把共享库存分配给各不相同的站点，而每一次实体动作都要花钱、花时间。

# Q3 科学假设

如果智能体必须把在 Web 式界面上做出的决策转化为多个站点的线下零售结果，那么期末利润取决于单站点基准无法区分的三种能力：跨站点协调共享资源、规划付费的实体执行、根据累积反馈改进经营策略。论文预期当前的 LLM 智能体在这些方面还不够强，经典库存规则仍是很难超过的基线，而运营指标能解释钱亏在哪里。

# Q4 相关工作与关键人物

* **买方侧电商评测。** WebShop 式购物、个性化购物、客服、多智能体市场（Magentic Marketplace），都以一次任务、对话或交易结束。
* **卖方侧与持续经营基准。** Vending-Bench、Vending-Bench 2 及其 Arena、RetailBench、MerchantBench、StoreBench、Business Arena、E-Commerce Bench。
* **长程智能体评测。** 网站和电脑工作流（这里引用了 WebArena）、模拟公司任务、进度率、能力画像，以及 AhaBench 等持续学习基准。
* **基线和模拟器背后的运筹学。** 报童模型（Arrow、Harris、Marschak）、周期性补货至目标库存、库存路径问题、易腐库存理论、带"不购买"选项的多项 logit 选择模型（Talluri 和 van Ryzin）。
* **关键人物。** Qiming Shi 和 Yikun Li（共同一作，StepFun 实习生），通讯作者 Zuo Bai（StepFun 和 FinStep），合作者来自 StepFun、浙江大学、西交利物浦大学、阿德莱德大学和中国人民大学；HTML 的作者栏把部分姓名与单位、邮箱错配，因此逐人的单位信息不可靠。可能的批评者：Andon Labs 的 Vending-Bench 作者，以及 E-Commerce Bench 和 MerchantBench 的作者。

# Q5 核心方法

**基于真实数据的需求模型。** 每台机器每天的购买尝试次数服从泊松分布，其强度由货架的总吸引力与"不购买"权重共同决定；每次尝试按吸引力比例选择商品（多项 logit 模型）。商品的吸引力等于基础值乘以货架饱满度因子、陈列少于 5 件时的惩罚、价格弹性项和天气节假日乘子。跨日相关的冲击让需求波动大于泊松。基础吸引力由 99 台真实机器六个月的订单级记录（共售出 220,128 件）校准：经验贝叶斯收缩后的商品热度、站点类型偏好、子品类系数和每台机器的规模系数。

**假设而非估计的部分。** 毛利率（饮料 30-40%，零食 50-60%）、保质期、价格弹性（按站点类型 2.4 到 3.5）、天气与节假日响应，以及所有运营成本都是基准的设定。

**接口。** 工具通过 Model Context Protocol 模拟联网售货运营商的平台：采购、定价、报废，对商品、库存、销量、财务的查询，只读 SQL，以及日历和天气查询；两个实体工具在仓库与货架之间搬货并触发上门费；记忆工具读写一个在上下文压缩（context compaction）后仍然保留的笔记本，而对话历史跨天延续。

**利润之外的诊断。** 相对启发式参考组合的选品质量、损耗率、相对价格搜索参考的定价遗憾、货架利用率、空架站点日占比、资金效率、工具调用数、每美元 API 成本带来的净资产增长；另有重分配差距（把现有选品在站点间重新分配能好多少）和每个补货周期的回报。

# Q6 实验设计

* **智能体。** Claude Sonnet 5.5、GPT-6.1 Sol、DeepSeek V4.1 Flash、Kimi K3、GLM-5.3-Flash，统一用 Pi harness，各自取最高推理强度；每个模型跑三次，都在同一个随机种子的固定世界里。
* **基线。** 确定性规则：报童临界比加周期性补货至目标库存，用滚动 30 天的需求估计，每周上门，选品跟随已观察到的销量，价格通过局部毛利试验调整。种子 1-3 上得到 208.73 ± 2.26 千元，报告的是种子 1（210.97）。
* **模拟器验证。** 用八周留出窗口之前的数据重新估计参数，在参考价格和中性天气下回放 67 台机器的真实货架，100 个种子，与朴素参考和持续性参考比较。
* **研究问题。** RQ1 持续经营（净资产轨迹），RQ2 跨站点协调（六个 30 天检查点的重分配差距），RQ3 实体执行（第 16-180 天的可得性和上门周期回报），RQ4 从反馈中改进（第 16-45 天对比第 136-165 天），以及四个人工检查的失败案例。

# Q8 证据质量

* **有支撑的结论。**
  * *多数智能体输给简单规则。* 平均期末净资产（千元）：GPT-6.1 Sol 309.35，规则基线 210.97，GLM-5.3-Flash 148.43，DeepSeek V4.1 Flash 133.92，Claude Sonnet 5.5 103.04，Kimi K3 91.52。GPT 的三次运行都超过基线，其余 12 次都没有；全部 15 次运行的期末资产都高于 40,000 元的起始资金。
  * *利润和成本效率给出不同的排名。* DeepSeek 每美元 API 成本带来 31,010 元净资产增长，GPT 是 1,117 元；论文称 GPT 的 API 花费约为 DeepSeek 的 80 倍，而增长约为 2.9 倍。
  * *没有模型在所有维度领先。* Claude 的损耗率（0.16%）和定价遗憾（每台每天 1.32 元）最低，但 25.21% 的站点日是空架，选品得分也最低（0.500）；GPT 利润最高，定价遗憾也最大（30.18）；所有模型的选品得分都低于基线的 1.034。
  * *需求模型对留出销量的拟合优于简单参考。* 总量误差在 0.7% 以内；机器-周 WAPE 0.473，朴素参考 0.606，持续性参考 0.561；子品类 TVD 0.153 对 0.206；机器内商品销量的 Spearman 相关中位数 0.577。
* **比标题结论更弱或更窄的地方。**
  * *一个世界、一个种子、三次运行。* 论文自己说明了这个限制。Kimi K3 的标准差是均值的 45.6%，DeepSeek 约 20%（读者根据表 2 计算），所以基线以下四个模型的顺序并不确定：它们的均值在 91.52 到 148.43 之间，标准差在 11 到 42 之间。
  * *智能体最依赖的部分是假设的。* 验证是在参考价格下回放真实货架；论文说价格和环境响应"按设计未做验证"。因此任何靠定价起作用的策略，都是在假设的弹性上被打分（读者观察）。机器-周 WAPE 0.473 虽然优于两个参考，绝对误差仍然很大。
  * *参考指标是启发式的。* 选品和定价遗憾是相对启发式参考组合和固定条件下的价格搜索来衡量的，不是相对最优解。GPT 定价遗憾最大而利润最高，说明指标和结果可以不一致，论文也指出了这一点。
  * *"没有从反馈中改进"无法识别因果。* 五个模型的均值和 15 次运行中的 13 次，日均资产增长从前期到后期都下降，但论文说环境条件和库存状态的变化使这一比较不能做因果解读。规则基线自身的变化只在图 6 中展示。
  * *失败模式是个案。* 四个案例（一次 Kimi 运行中 49 条分配全部被拒、重复购买同一个 21 种商品的组合、为 5.14 元毛利付 35 元上门费、第 163 天和第 168 天出现同样四条不可行分配）只用于说明行为，论文明确说不代表发生频率。
  * *只有一个 harness。* 所有模型都在 Pi 下运行，使用它的压缩机制和笔记本工具；论文没有检验弱模型的结果是来自模型本身，还是来自这个 harness 管理 180 天历史的方式（读者观察）。
  * *API 成本是估算值。* API 效率按标准参考价乘以记录的 token 用量计算，不是实际账单。

# Q9 贡献

* 一个多站点、共享库存、实体执行要付费的经营基准，有统一的任务、工具接口和评测协议。
* 一个用真实售货记录校准的需求模拟器，并对总量、品类结构和商品排名做了留出检验。
* 一组评测：五个当前智能体中有四个不及经典库存规则，并用运营诊断（重分配差距、上门周期回报、前后期增长对比）把损失定位到协调、执行成本和策略修正上。
* 一个成本效率视角（每美元 API 成本的净资产增长），它改变了模型的排名。

# Q10 后续方向

* **改变世界设定。** 作者提出要在不同运营条件下、用受控干预（如显式状态核查和持久的策略更新）检验这些发现。多个世界种子和需求情形能说明 GPT-6.1 Sol 的领先和其他模型的落后是否稳定。
* **验证价格响应（读者建议）。** 利用源数据中的价格变动，或对假设弹性做敏感性实验，能说明各智能体的结果有多少依赖这些设定。
* **混合智能体（读者建议）。** 把报童规则作为工具或初始策略交给智能体。如果之后能追平或超过规则，差距就在运筹学知识；如果不能，差距在长程执行。
* **Harness 消融（读者建议）。** 用不同的记忆设计跑同样的模型，因为四个失败案例中有两个是没能把一次纠正延续下去。
* **读者联系。** 本知识库中的 FDE-Gym（arXiv:2610.22350）把 Vending-Bench 引为用商业模拟代替人工评审的例子；AutoVend 补上了这类交付基准需要的"每单位成果的成本"视角。
