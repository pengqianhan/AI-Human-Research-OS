# Q1 问题定义

* **输入（X）：** 一个 LLM 智能体（某个基座模型放在某个 harness 中，可选地加上一种自进化方法），通过黑盒命令接口玩 20 个新设计的文字游戏之一。每一回合，游戏描述当前状态并列出可选动作；智能体选一个动作，得到文字反馈。游戏规则是隐藏的，并且刻意设计得新颖或反直觉（在某个游戏里，偷同事的午餐能让你升职，努力工作反而不行）。智能体要重复玩多局（普通游戏 5 局，五个挑战游戏 10 局），可以把经验带到下一局，但模型权重始终不变。
* **输出（Y）：** 每局一个确定性、自动计算的终局得分，按每个游戏的参考分 $C_g$ 归一化到 0-100（$z = 100x/C_g$），以及跨游戏汇总的四个指标：**Max**（各次试验峰值的平均）、**Mean**（各局平均）、**学习增益（Learning Gain）**（最后 $k$ 局均值减最初 $k$ 局均值，$k=\min(3,\lfloor T/2\rfloor)$）和**学习斜率（Learning Slope）**（对各局得分做线性拟合的斜率）。
* **核心问题：** LLM 智能体能多有效地从交互中获得*新*知识（而不是调出预训练中已有的知识），以及基座模型、自进化方法和 harness 各自如何影响这种能力。

# Q2 问题新颖性

部分新颖。已有的自进化或持续学习智能体基准会测量在任务流或重复尝试中的进步（StreamBench、MemoryBench、Evo-Memory、LifelongAgentBench、SWE-Bench-CL、MemoryArena、基于 Jericho 游戏的 J-TTL、AutoEnv）。本文的异议是：这些任务大多遵循熟悉的现实规则或公开游戏的规则，因此"进步"可能只是回忆而不是学习；ARC-AGI-3 使用陌生环境，但同时混入了视觉能力。Learn2Play 声称的新意在于组合：（a）规则不出现在现有游戏中的手工设计游戏；（b）确定性、可重放的反馈与自动评分；（c）"重洗牌（re-shuffled）"变体——每局改变可见实例但保持规则不变，用来测试迁移；（d）在同一界面上的人类实验。

# Q3 科学假设

论文以五个研究问题而不是假设的形式组织。把它们改写成被检验的主张：

1. **RQ1。** 若某方法保留更多原始证据（原始交互历史，而不是提炼出的规则、教训或工作流），智能体跨局学得更多，因为它能修正早期的错误结论。
2. **RQ2。** 若固定基座模型、只换 harness，表现与学习能力都会变化，且模型自家厂商的 harness 表现最好。
3. **RQ3。** 人类与智能体的探索方式不同：人类尝试的策略更多样，受挫后更常反弹。
4. **RQ4。** 若可见实例每局都变而规则不变，学习会变慢，且基座越弱变慢越多。
5. **RQ5。** 更高的 token 单价或更多推理本身并不能换来更好表现；更合适的 harness 可以以更低成本取得更高分。

# Q4 相关工作与关键人物

* **不更新权重的自进化智能体。** [Reflexion](../concepts/reflexion.md)（语言反思）、ExpeL（洞见加检索轨迹）、Voyager（可执行技能）、[Agent Workflow Memory](../concepts/agent-workflow-memory.md)（归纳工作流）、Dynamic Cheatsheet、ACE（结构化 playbook）、ReasoningBank 与 ERL（可复用的推理模式）、GEPA（提示词进化）、Agents of Change（修改提示词与代码）、EvoTest（进化整个智能体配置）、Meta-TTL（进化适应策略本身），以及 TT-SI（测试时微调，不在本文范围内）。
* **从经验中学习的基准。** StreamBench、MemoryBench、Evo-Memory、LifelongAgentBench、SWE-Bench-CL、MemoryArena、AutoEnv、J-TTL、ARC-AGI-3。
* **Harness 效应。** 论文引用厂商的说法（MacCallum 与 Fioca，2026；Shihipar，2026）——模型是配合自家 harness 训练的、harness 也针对模型调过——来解释为何在相同基座下 Claude Code 和 Codex 胜过 OpenCode。
* **关键人物。** 全体作者来自新加坡国立大学，Bryan Hooi 为资深作者。可能的批评者：被评测的自进化方法（EvoTest、ReasoningBank、AWM）的作者，因为这些方法都在统一协议下运行，而不是各自调好的设置；以及 ARC-AGI 类评测者，他们会追问一条手写的文字规则对模型而言究竟有多"新"。

# Q5 关键解决思路

* **新颖规则 + 受控变化。** 20 个游戏模板（论文表 4-5）：十个*固定*游戏每局重复同一实例，智能体可以不断完善地图、配方或计划（PrimordialSoup、GemForge、Catnip、Dungeon、DreamGarden、Ecosphere、Grapevine、Castaway、RedEye、Patch Reality）；十个*重洗牌*游戏改变菜单、客人、上司或布局，但规则不变（Poisoner、SynergyCorp、Haunted Inn、Roommates、Roadside Observatory、Lost and Found、Mola Tea、Plague、Butterfly、Model Auditor）。五个挑战游戏（Catnip、DreamGarden、Mola Tea、RedEye、Roadside Observatory）用 10 局窗口、权重 3，因此挑战游戏与普通游戏在汇总中各占一半权重。
* **参考分归一化。** 每个固定实例都有参考分，并标注证据等级：精确（有 oracle 或证明）、部分（已证明的最好值）或估计（搜索或分数上限）；20 个中有 14 个是精确的。
* **把"学到多少"与"表现多好"分开。** Max 与 Mean 衡量达到的表现；学习增益和学习斜率衡量跨局变化，从而区分"强但不进步"和"弱但在进步"的智能体。
* **同一协议下的三组比较。** 九个基座模型放在同一个通用 harness 中（OpenCode，一个开源编码智能体 CLI）；固定基座下比较六种经验方法（Naive，无跨局记忆；Memory，保留原始历史；Reflexion；EvoTest；ReasoningBank；AWM）；以及同基座换 harness（Claude Opus 5 上 OpenCode 对 Claude Code，GPT-5.6-SOL 上 OpenCode 对 Codex）。每个配置每个游戏做三次独立试验。

# Q6 实验设计

* **RQ1 基座模型。** Claude Opus 5、Claude Sonnet 5、Gemini 3.5 Flash、Gemini 3.7 Flash、GPT-5.6-SOL、GPT-5 Mini、DeepSeek V4 Pro、Kimi K3、Qwen 3.8 Max，全部用 OpenCode，智能体循环、提示词、重放协议和记忆格式固定。
* **RQ1 方法。** 六种方法分别在 Kimi K3、Claude Opus 5 和 GPT-5 Mini 上运行。
* **RQ2 harness。** 各次试验相互隔离（Claude Code 关闭持久自动记忆，Codex 用 `--ephemeral`，OpenCode 开新会话）；同一试验内，先前各局保留在会话中，受各 harness 的上下文处理方式约束。
* **RQ3 人类。** 大学生在同一界面上游玩，不使用 AI 工具或代码，有参与报酬，高分另有奖励；每个游戏 21-30 名参与者。每个游戏按 Max 选出 Top-1、Top-3、Top-5 的记录。行为比较在固定游戏上进行：相邻两局动作序列的相似度（Python `SequenceMatcher`），以及得分下降后下一局立刻创个人新高的比例。
* **RQ4 迁移。** 对每个重洗牌游戏设一个同实例对照（每局重复同一实例）；在 10 局上比较学习斜率，覆盖七个 OpenCode 基座以及 Claude Code 和 Codex。
* **RQ5 成本。** 根据记录的 token 用量估算，按 2026 年 8 月 30 日的价格快照分别计价新输入、缓存读、缓存写和输出；不是实际账单。
* **规则发现审计。** 附录 D 给出逐游戏的学习曲线、排行榜，以及对某次运行是否发现目标规则的存档证据标注，按游戏报告而不做汇总。

# Q7 数据集与代码

Learn2Play Bench 是新基准：20 个按种子生成实例的游戏模板，每个游戏固定的种子和参考分列于表 6。代码在 [liushiliushi/Learn2Play-Bench](https://github.com/liushiliushi/Learn2Play-Bench)（抓取时 0 星），另有[项目主页](https://liushiliushi.github.io/learn2play-bench-website/)；论文采用 CC BY 4.0 许可。智能体结果依赖托管的模型 API 和三个 CLI harness，其版本和默认设置可能变化；所读章节未说明人类交互记录是否公开。

# Q8 证据质量

* **有支撑的结论。**
  * *基座模型在表现和学习上都不同，且两种排名不一致。* 在 OpenCode 下，Claude Opus 5 的 Max（74.5）和 Mean（53.8）最高，而 Qwen 3.8 Max 的学习增益（+25.2）和斜率（+6.30）最高；GPT-5 Mini 垫底（Max 34.0）。
  * *Kimi K3 上原始历史胜过提炼的经验。* 在 Kimi K3 的六种方法中，Memory 四项指标全部领先（Max 63.3，LG +16.9），对比 EvoTest（62.4，+1.8）、Reflexion（61.6，+14.8）、ReasoningBank（59.9，+8.3）、AWM（56.1，+4.8）和 Naive（54.7，+0.3）。
  * *固定基座时 harness 很重要。* Claude Code + Opus 5 达到 Max 81.8 / Mean 62.3 / LG +27.1，OpenCode 为 74.5 / 53.8 / +21.3；Codex + GPT-5.6-SOL 达到 74.3 / 54.8 / +22.2，OpenCode 为 57.0 / 41.1 / +14.5。OpenCode 本身又在同基座下胜过所有自进化方法（Kimi K3：68.5 对 Memory 的 63.3；Opus 5：74.5 对 EvoTest 的 66.1）。
  * *更好的 harness 也可能更便宜。* 对 Kimi K3，OpenCode 每局用 0.55M 输入 token、8.1 次模型调用（0.313 美元），Memory 则是 1.26M 和 27.0 次（0.586 美元），因为 OpenCode 一次模型回复执行多个动作，并去掉重复的游戏反馈。
  * *重洗牌会拖慢学习，且程度不一。* 学习斜率下降：Claude Sonnet 5 为 2.67，Gemini 3.7 Flash 为 2.15，GPT-5.6-SOL 为 1.94；而 Opus 5 仅 0.59，Claude Code 仅 0.52；Qwen 3.8 Max（-0.41）和 Codex（-0.19）的下降为负值（重洗牌后斜率反而更高）。
  * *具体的失败机制。* 在 GemForge 中，一次 EvoTest-Opus 5 运行把一次失败的融合变成了禁止所有二级、三级融合的提示规则，随后停滞（46、81、83、83、83）；在 Haunted Inn 中，智能体能说出禁忌，却贪心地安排客人，导致后来的客人没有安全房间；在 Poisoner 中，一次 GPT-5 Mini 运行每场宴会都上同一菜单位置的菜。
* **比标题更弱或更窄的地方。**
  * *"原始历史胜过提炼"只在三个基座中的一个上成立。* 在 Claude Opus 5 上，Memory 的 Max 仅排第三（60.9），落后于 EvoTest（66.1）和 Reflexion（64.8），学习增益最高的是 ReasoningBank（+12.3）。在三个基座的平均中，Max 最高的是 Reflexion（60.0），Memory 领先的是 Mean、LG 和 LS。GemForge 案例只是一次试验，作者也说它不能证明是压缩导致了总体差异。
  * *人类比较是"众中取最佳"对"三次取平均"。* Human Top-1 是每个游戏 21-30 名玩家中的最佳者，且就是按其被评分的 Max 选出的；而每个智能体的 Max 是三次试验的平均。若对全部合格参与者取平均，人类的 Max 为 43.6、Mean 31.2、LG +10.4，低于大多数智能体配置。Claude Code + Opus 5（81.8）接近 Human Top-1（84.3），且高于 Human Top-3（79.1）。这一发现说的是最强的人类（摘要也是这么说的），不是一般人。
  * *行为统计是描述性的。* 动作序列相似度（人类 0.54，150 对；智能体 0.66，918 对）和受挫后的反弹率（人类 39 次下降中 13 次，33.3%；智能体 238 次中 52 次，21.8%）合并了不独立的局，并把 Top-3 人类与全部六种 Opus 5 方法比较；作者称其为描述性而非因果性结果。
  * *试验次数少，主表无区间。* 每个配置三次试验；各次试验的标准差只在附录 C 中给出，相邻方法间的许多差异很小（例如 Kimi K3 上 Memory 63.3 对 EvoTest 62.4 的 Max）。
  * *方法在统一协议下运行，而非各自调好的设置。* 自进化方法每个动作调用一次模型并重新插入存储的经验，而 harness 可以批量执行动作、运行代码；因此方法间差距有一部分是循环设计的差距——论文自己也用这一点解释 OpenCode 的优势。
  * *Harness 的机制是断言而非检验。* Claude Code 和 Codex 胜出是"因为模型配合它们训练"这一解释来自厂商说法；没有实验把训练协同与上下文处理等 harness 特性区分开。
  * *20 个参考分中有 6 个是部分或估计值，* 因此在这些游戏中，归一化分接近或超过 100 并不保证是最优玩法。
  * *内部引用错误。* 正文把标为表 1 的表称为"Table 2"，并有未解析的"Table 4.3/4.5"引用；就所核对之处，正文与附录中的数字本身是一致的。

# Q9 贡献

* Learn2Play Bench：20 个带有新颖或反直觉隐藏规则的文字游戏，具有确定性可重放反馈、自动的参考分归一化评分，以及把"学会规则"与"记住实例"区分开的固定/重洗牌变体。
* 一组把达到的表现（Max、Mean）与进步（学习增益、学习斜率）分开报告的指标。
* 在同一协议下对九个基座、六种经验复用方法和三个 harness 的对照比较，并附 token 成本估计，表明 harness 和记忆格式的影响可以与基座相当。
* 在同一界面上的人类实验，以及关于探索与反弹的行为比较。

# Q10 下一步

* **作者提出的方向。** 平衡探索与利用，让智能体在某个策略奏效后仍继续尝试新策略；存储学到的规则时与支撑它的交互关联起来，以便新反馈与之矛盾时能修正规则；帮助智能体区分跨情境不变的规则与实例特有的细节。
* **带出处的规则记忆（读者建议）。** GemForge 的失败是一条规则比它唯一的支撑观察活得更久。一种把每条提炼规则与其支撑的局放在一起、并在第二次观察印证之前将其标为"暂定"的记忆，正好可以检验作者的第二个方向；[Trace2Env](../papers/2610.06100.md) 的 worldbook 保留出处并让缺乏支撑的规则保持暂定，是一个可以借鉴的现成设计。
* **公平的人类基线（读者建议）。** 把人类 Max 报告为每个游戏随机三名玩家的平均（与智能体的三次试验对齐），或者给智能体做与人类人数相同次数的试验再取最佳，让两边采用相同的选择规则。
* **污染期限（读者注）。** 规则只在游戏、解法和运行日志公开之前是新颖的；未来在这些数据上训练过的模型会把"学习"重新变回"回忆"。保留一部分模板不公开，或定期刷新规则参数，能让基准继续衡量学习。
* **与本项目的契合（读者注）。** 本仓库的定时智能体通过记忆文件把教训带到下一次。Learn2Play 发现原始局记录可能胜过提炼规则（至少在一个基座上），这支持为每条记忆条目保留指回支撑它的对话或运行的链接。

# 相关

* [智能体基准与评测](../topics/agent-benchmarks.md) - 一个对跨重复局的进步（而不只是最终成功）打分的结果型基准，并在同一界面上加入人类基线。
* [智能体自进化](../topics/agent-self-evolution.md) - 在同一协议下比较六种不更新权重、跨局携带经验的方式；原始历史与提炼的规则、工作流和进化的提示词相比并不逊色。
* [智能体 harness 工程](../topics/agent-harness-engineering.md) - 固定基座时，把 OpenCode 换成 Claude Code 或 Codex 会提升全部指标，且可能降低成本。
* [Reflexion](../concepts/reflexion.md) - 被评测的六种方法之一：Max 在 Kimi K3 上排第三、在 Opus 5 上排第二，三基座平均 Max（60.0）最高，但在 Kimi K3 上学习增益和斜率低于原始 Memory。
* [Agent Workflow Memory](../concepts/agent-workflow-memory.md) - 被评测的六种方法之一；它只从成功的局中学习，在三个基座上都是非 Naive 方法里学习斜率最低的（+0.62、+0.43、-0.98）。
* [AgentGarten](../papers/2610.12374.md) - 同一周关于智能体通过书面 playbook 进步的论文；AgentGarten 把每一轮提炼成 playbook，而 Learn2Play 发现提炼的教训可能锁定错误规则。
* [RSIAgent](../papers/2609.15364.md) - 通过由验证者把关的探索，在新环境中发现"动作-条件-后果"规则；Learn2Play 则把同一种规则发现能力做成基准来衡量，而不是为它构建方法。
* [ASI-Bench](../papers/2608.17271.md) - 另一个同一基座仅因换 harness 而分数变化的基准。
