# Q1 问题定义

* **输入 (X)：** 一条用户指令，一组放在持久沙箱里的附件（PDF、Word、Excel、PowerPoint），以及四个工具：`bash`、`web_search`、`web_fetch`、`view_image`（求解模型是纯文本模型时，由一个辅助视觉模型回答）。
* **输出 (Y)：** 满足指令的交付物文件，按任务专属的评分细则（rubric）评判，有参考交付物时一并对照。
* **约束：** 工作是长程的、以文件为依据的；训练数据必须带有真实的工作意图、真实的文件和交付物级别的评分；目标模型很小（4B）。

# Q2 问题新颖性

在有经济价值的办公类工作上评测智能体已有成熟做法（[GDPval](../concepts/gdpval.md) 及其后继）。论文指出的缺口在训练数据：现有数据集各自只覆盖指令遵循、文档问答或某一种交付物类型，而合成的文件缺少真实文件的版式、缺漏和跨文件引用。人工编写的工作流又无法扩展。从真实来源合成端到端的生产力任务是新的；先 SFT、再在合成任务上做 RL 并不新。

# Q3 科学假设

如果合成的每个阶段都以真实来源为依据（职业活动种子、网页文本中的工作流证据、公开文件），并且任务带有细粒度的评分细则，那么在几千条这样的任务上训练的小模型，会在真实的生产力基准上提升，也会在没有专门训练过的文件推理上提升。两个子论断被分开检验：真实文件比生成文件训练得更好；带评分细则的奖励比不带的训练得更好。

# Q4 相关工作与关键人物

* **生产力基准。** GDPval、$1M-Bench、Agents' Last Exam、Finance Agent Benchmark、APEX-Agents、AgentSkillOS、ClawBench、EdgeBench、Workspace-Bench、EnterpriseClawBench。
* **面向智能体后训练的数据合成。** 从语料、程序或模板扩展出的工具调用轨迹和可执行环境；把网页教程重放成 GUI 轨迹；终端智能体的环境生成器。论文的意见是这些方法针对的是预定义的工具接口或结构化文本文件，而不是办公文件。
* **办公文件相关工作。** 以文档为依据的问答，以及单一类型文件的生成（演示文稿、电子表格）。
* **关键人物。** Teng Pan、Zixuan Wang、Yuchen Yan、Qifei Wu、Yao Chen、Yingqi Qu、Ruiqing Zhang、Yongliang Shen，来自浙江大学和百度（ZJU-REAL，也是 [Actor, Judge, or Teacher?](../papers/2611.17167.md) 的团队）。可能的批评者：其他以 O*NET 为种子、面向 GDPval 的训练流水线的作者，例如 [GraphForge](../papers/2609.38923.md)，它用另一种尺度报告 GDPval。

# Q5 核心解法

由 Qwen3.6-Plus 执行的三阶段流水线，之后是两个训练阶段。

1. **工作流抽取。** 网页语料片段（DLR-Web，从 FineFineWeb 过滤而来）按学科对应到 O*NET 的职业活动种子。通过“工作流过滤”和“面向文件过滤”的片段被转成蓝图：步骤、信息依赖、所需文件类型、预期输出。
2. **附件搜索。** 一个多轮循环负责写搜索查询（带文件类型过滤）、筛选标题和摘要、下载有希望的文件，并检查封面和目录。超过 50 页或 2 MB 的文件被丢弃。只有保留下来的文件合起来能覆盖所需信息的工作流才进入下一阶段。
3. **任务合成。** 模型在沙箱里查看文件，选出附件子集，并同时写出指令和评分细则。随后由 Claude-Opus-4.5 求解该任务，它的轨迹成为 SFT 数据，它的输出成为参考交付物。验证器用评分细则检查参考交付物：未满足的条目如果缺乏依据或不合理，就修改细则；如果合理，就让专家模型回去修改一次。
4. **训练。** Qwen3-4B-Thinking-2507 先在约 3k 条专家轨迹上微调，再在约 1k 个不重叠的任务上用 [GRPO](../concepts/grpo.md) 训练。奖励是评判者给出的细则得分除以满分，没有产出交付物则为零。训练时的评判者是 Qwen3.6-Plus，它读取渲染出的页面图像（电子表格还包括重新计算后的数值和公式），而不是带工具的智能体。对工具调用错误不加惩罚。

# Q6 实验设计

* **基准。** GDPval（220 个任务），按交付物类型分为办公类和非办公类；OfficeQA 的 Markdown 版本作为域外测试；附录中还有 GTA-Workflow（132 个工作流）。
* **评分。** GDPval 的交付物由以 Gemini-3.1-Pro 为模型的智能体评判者按 GDPval 的细则评分。Pass@k 是在至多 k 次尝试中“取第一次产出交付物的那次来评分”。OfficeQA 结合规则匹配和模型评估。最多 100 步。
* **基线。** GPT-4.1、Gemini-2.5-Pro、Claude-Opus-4.5、DeepSeek-v3.1、GLM-4.7，以及 Qwen3 的 30B 和 235B（纯文本与 VL），全部在同一个沙箱和工具框架里重跑。
* **分析。** 各变体的完成率、工具调用步数和错误数；在轨迹和交付物上基于规则的“走捷径”指标；真实文件对比生成文件（1k 对配对的 SFT 任务）；有无细则奖励；两个评判模型的重复评测；SFT 数据规模；针对 RL 阶段的 4k-SFT 对照；污染审计；100 个任务的人工审计。

对照选得不错：4k-SFT 对照把 RL 与“多出来的数据”分开，配对任务把文件因素单独隔离出来。但每项都只有一次训练。

# Q7 数据集与代码

从 10k 个候选中得到约 4k 个任务（工作流抽取阶段丢弃约 2.2k，附件搜索与验证阶段丢弃约 3.8k）。附件：5,010 个 PDF、3,149 个 DOCX、1,258 个 XLSX、390 个 PPTX；平均每个任务 2.51 个。评分细则平均 15.3 条。专家轨迹平均 18.0 步、41.8k token。对 100 个任务的人工审计：工作流与问题的一致性 86%，细则条目有效性 99.8%，视觉呈现 97%，跨文件一致性 95%，仅凭指令和附件可完成的比例 85%。细则里出现的具体数字中，41.9% 出现在指令里，39.0% 只出现在附件里，19.1% 两处都没有、需要计算得到。智能体循环基于 verl v0.6.x，运行在 AIO Sandbox 中，搜索通过 Serper。代码链接为 https://github.com/ZJU-REAL/Agent-R2 ；本笔记没有检查它，读到的正文也没有说明 4k 个任务及其文件是否公开。

# Q8 证据质量

**GDPval（Gemini-3.1-Pro 智能体评判）。**

| 模型 | 办公类 Pass@1 | 非办公类 Pass@1 | 全集 Pass@1 | 全集 Pass@3 |
|---|---|---|---|---|
| Claude-Opus-4.5 | 73.8 | 68.2 | 72.6 | 76.3 |
| GLM-4.7 | 60.8 | 61.9 | 61.1 | 67.4 |
| Gemini-2.5-Pro | 57.0 | 61.4 | 57.9 | 60.2 |
| Qwen3-VL-235B-A22B-Thinking | 48.4 | 54.7 | 49.7 | 52.4 |
| Qwen3-235B-A22B-Thinking-2507 | 46.9 | 52.0 | 48.0 | 54.1 |
| Qwen3-4B-Thinking-2507（基座） | 31.1 | 37.8 | 32.4 | 37.0 |
| Agent-R2-4B-SFT | 45.9 | 42.8 | 45.3 | 50.7 |
| Agent-R2-4B | 51.5 | 48.9 | 51.0 | 54.8 |

**OfficeQA（Pass@1 / Pass@3）。** 基座 2.2 / 4.5；Qwen3-235B 13.8 / 25.6；SFT 11.4 / 21.7；Agent-R2-4B 14.8 / 26.8。

**在 GDPval 上的行为。** 每个任务的工具调用步数从 6.7（基座）到 39.0（SFT）再到 33.1（RL），错误数从 2.88 到 16.3 再到 12.9，完成率从 86.8% 到 78.2% 再到 90.9%。写完后重新检查交付物的比例从 0.5% 升到 91.7% 再到 95.8%；带着未修复的错误就去写交付物的比例从 55.0% 降到 16.0% 再到 11.0%；含占位文字的比例从 12.5% 降到 9.6% 再到 5.7%。

**消融与对照（GDPval Pass@1）。** 在 1k 个任务上做 SFT：真实文件 43.3，生成文件 41.4（专家轨迹的工具调用数为 20.4 对 8.0）。RL 带细则奖励 51.0，不带 49.5。在全部 4k 条轨迹上做 SFT 得 45.5，而 3k SFT 为 45.3，3k SFT 加 1k RL 为 51.0。SFT 规模：1k、2k、4k 分别为 43.3、44.9、45.5，而在留出的合成任务上得分持续上升（0.486、0.507、0.617）。

**评判稳定性。** 各重复三次：在 Gemini-3.1-Pro 下，Agent-R2-4B 为 50.8 到 51.1，Qwen3-235B 为 47.7 到 48.2；在 DeepSeek-v4-Flash 下分别为 51.7 到 52.3 和 49.2 到 49.9；两个评判者逐任务的 Pearson 相关为 0.93。

**证据的局限（读者观察）。**

* 这里的“Pass@1”是细则得分的均值，不是通过率。稳定性附录报告同一任务在重复评测之间的得分差中位数为 3.2 个点，二值结果做不到这一点。这些数字不能与其他论文里的 GDPval 胜率或 Elo 分数相比。
* 两个组件论断分别建立在 1.9 个点（真实文件，仅 SFT，1k 任务）和 1.5 个点（细则奖励）上，各来自一次训练。重复评判把评判噪声限定在零点几个点，但说明不了训练方差。正文没有描述“不带细则”的变体里奖励是什么。
* 测到的最大效应来自 RL 阶段（比 3k SFT 高 5.7 个点，比 4k-SFT 对照高 5.5 个点）。数据的两个特色，真实文件和评分细则，贡献远小于流水线整体。
* 与 Qwen3-235B 的头条对比，Pass@1 差 3.0 个点，Pass@3 只差 0.7（54.8 对 54.1）。写出 SFT 轨迹和参考交付物的 Claude-Opus-4.5 得 72.6，所以学生追回的不到基座与教师之间差距的一半（读者相减：40.2 个点中的 18.6）。
* SFT 让完成率下降（从 86.8% 到 78.2%），同时提高了得分；只做 SFT 的模型在两个基准上都低于 Qwen3-235B，头条结果是 RL 阶段带来的。
* 随 SFT 数据增多，GDPval 上的得分趋于饱和，论文把这读作没有过拟合基准。这也意味着，把更多这类数据用于模仿，在 GDPval 上已经不再有帮助。
* 污染审计：没有相同的文件哈希或 URL；训练指令与 GDPval 提示的最近邻余弦相似度平均为 0.43，接近 GDPval 提示与其最近的另一条 GDPval 提示之间的 0.46。两者都使用 O*NET 的职业，所以训练集在构造上就贴近 GDPval 的任务分布；OfficeQA 和 GTA-Workflow 是更干净的迁移测试。
* 人工审计发现 15% 的任务仅凭指令和附件无法完成，14% 与其工作流只是部分一致。这些任务仍留在训练集里。
* 论文在模型之间把“有效步数”与 GDPval 得分联系起来，而它自己的附录报告：在同一个模型内部，越长的轨迹得分越低（Spearman 相关：SFT 为 −0.15，RL 为 −0.41）。按报告的均值相减，有效步数约为 3.8（基座）、22.7（SFT）、20.2（RL）（读者相减）。

端到端的结果，即一个 4B 模型从 32.4 提到 51.0、所有基线都在同一套框架里重跑，就一次训练而言支撑充分。把收益归因于真实文件和评分细则，证据偏弱。

# Q9 贡献

1. 一条面向文件型生产力任务的真实来源合成流水线，每个阶段都有结构化的过滤决定，并给出了数据损耗的数量。
2. 约 4k 个任务，带真实的多格式附件、约 15 条的评分细则、专家轨迹和参考交付物，并做了人工质量审计。
3. 一个两阶段训练方案，其 RL 阶段用“渲染交付物后对照细则评判”作奖励，并有对照表明 RL 的收益不是来自额外数据。
4. 一组基于规则的“走捷径”指标（重新检查、带着未修复的错误写交付物、占位文字、可追溯的数字），用来描述训练如何改变行为。

# Q10 下一步

* **训练方差。** 在多个种子上重复真实文件和细则奖励两项消融；它们只有 1.5 到 1.9 个点，是最需要重复的论断（读者建议）。
* **评判者耦合。** Qwen3.6-Plus 既写评分细则，又给 RL 奖励打分。换一个训练评判者可以检验策略是否学到了细则作者的偏好（读者建议）。
* **RL 的占比。** RL 用四分之一的数据带来了大部分收益。把 3k/1k 的划分向 RL 倾斜是个显而易见的实验，论文没有做（读者建议）。
* **不可完成的任务。** 过滤掉 15% 不可完成的任务，或用它们训练智能体说出缺了什么，都没有测过。
* **非办公类交付物。** 音频、视频等媒体不在流水线范围内；在这些任务上 RL 比 SFT 帮助更大，说明在格式不迁移的地方，通用的工作习惯仍会迁移。
* **更大的学生模型。** 全部实验都在 4B 上；对一个本来就会探索和复查的模型，这些数据是否仍有帮助还不清楚。
