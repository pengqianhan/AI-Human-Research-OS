> 论文:**NeoHorse-1: Towards Recursive Self-Improvement via Agentic Post-Training with Routing Harness**
> 论文链接:<https://arxiv.org/abs/2609.08183>
> 机构:TokenRhythm Technologies / Infinigence AI / 清华大学 / 北京大学 / 香港中文大学 / Visionplus Capital / WX Capital / 阿里巴巴集团

# Q1 问题定义

* **输入 `X`**:一个已部署的路由 harness 在服务异构模型池时自然积累下来的交互历史——执行轨迹(用户请求、模型推理、工具调用、环境观测、终止结果),以及每个用户轮次上路由器预测的能力需求、经策略调整后选定的服务档位、以及最终实际服务该请求的档位。
* **输出 `Y`**:NeoHorse-1,一个基于 Qwen3.5(4B 与 9B)的 agent-native 模型家族,通过把上述 harness 数据转化为一套路由引导的训练课程而产生;论文同时描述了一个运行中的闭环——把评测反馈转化为下一轮训练配比的"能力引导数据分配"——后训练模型经此回到 harness 中,为下一轮迭代提供素材。
* **核心问题**:递归自我提升(RSI)需要一个具体机制,让系统能观察自身能力并把这些证据转化为下一轮学习。本文的主张是:这个机制无需从零搭建——一个真正在服务真实流量、带路由器的 harness,本身在正常运行中就会产生执行轨迹(任务经验)与路由预测/结果(模型能与不能做什么的证据)。
* **范围**:两个模型规模(4B、9B),在覆盖基于 harness 的端到端 agent、工具使用、代码与指令遵循的十个基准上评测。报告明确将自己定位为"迈向 RSI 道路上的一个初步模型训练原型",而非一个已完成的 RSI 系统——只是评测-选择-更新闭环的单次通过,并未验证多轮迭代下的收益是否会持续累积。

# Q2 问题的新颖性

论文并不声称首创 agentic 后训练、LLM 路由、课程学习或在线策略蒸馏(OPD)——它引用 FireAct、AgentTuning、Agent-FLAN、AgentBank 作为轨迹式 SFT 的前作,Llama 3 作为合成工具使用 SFT 加迭代式 SFT/拒绝采样/DPO 的前作,FrugalGPT 与 RouteLLM 作为按成本路由的前作,并采用 Agarwal 等人提出的 OPD 机制。其自陈的新颖之处在于:把"面向异构模型池的路由 harness"本身——而非某个固定模型自身的生成结果,也不是外部人工设定的难度标签——当作训练经验与课程排序信号的共同来源。这一框架带来两个具体设计:(1) 用路由器*预测*的能力需求而非*实际服务*该请求的模型身份,作为课程排序的代理信号,因为实际服务的模型同时也受用户覆盖、服务可用性与部署策略的影响,并不单纯反映任务难度;(2) 闭合一个能力引导的数据分配循环——某个检查点在一个经去污染、分层的评测集上暴露出的能力缺陷,会重塑下一轮训练配比,使系统学会做什么反过来影响它接下来从什么中学习。报告明确表示自己是另一篇论文"Agentic Routing: the harness-native data flywheel"[33] 的直接方法延伸——本笔记未读过那篇论文——两篇论文的作者名单(同属 TokenRhythm Technologies)有相当程度的重叠。

# Q3 科学假设

如果把 harness 记录下来的执行轨迹转化为保留交错推理、工具调用与 harness 上下文的用户轮次训练样本;如果用 harness 路由器重新估计出的能力需求信号(而非实际服务模型的身份)来调度一个三阶段 SFT 课程,并把同一套分阶段进度延伸到在线策略蒸馏——由一个固定教师监督学生自己生成的响应前缀;并且如果一个能力引导的数据分配步骤,把每个检查点的评测缺陷反馈进下一轮训练配比——那么由此产生的 agent-native 模型,相比未经后训练的基座模型,应当在基于 harness 的 agent 执行、工具使用、代码与指令遵循基准上呈现出一致的、大范围的提升,在 4B 与 9B 两个规模上均是如此,且更大的模型应在需要迭代调试、从执行失败中恢复以及在环境约束下调整策略的任务上保持更明显的优势。论文把这视为对"这个闭环能否在操作层面真正闭合"的一次初步、单轮测试,而非声称由此产生的收益会无限期地跨迭代累积。

# Q5 核心解法

1. **三粒度数据组织。** *轨迹*是一次完整的 harness 执行交互;*用户轮次*(一个请求加上其后到下一个请求之前的助手响应/工具交互)是基本的序列化训练单元;*子场景*把共享局部目标的相邻用户轮次归为一组,作为语义刻画的单元——从原始交互到训练样本的溯源关系被完整保留。
2. **结构校验,再六维语义评测。** 一个基于规则的门控重建每条轨迹的轮次、工具调用与观测,校验因果事件顺序以及工具调用/结果的闭合;结果分为完整/部分可恢复/隔离三类。结构上可用的轨迹随后在六个独立维度上被打分——目标达成、指令遵循、工具使用、证据一致性、错误恢复、终止——标记为 PASS/WARN/FAIL/NOT_EVALUATED,高确定性的失败用确定性规则检测,需要任务级解读的情形交给一个仅限于轨迹内部证据的语义判官;缺失的证据永远不会被转化为正面判定。
3. **三轴子场景刻画(场景/目标/结果)。** 每个子场景在"用户在做什么"(场景)、"成功意味着什么"(目标,拆解为验收标准与跨轮次的目标关系)以及"可验证的结果"(结果)三个轴上被打标签——每个属性的推导方式与置信度分别保留,使语义判官无法悄悄覆盖一个结构层面已确立的事实。
4. **预测-行动-结果分离的路由信号。** harness 路由器把每个轮次分配到四个档位之一(C0 有界低风险、C1 通用默认、C2 多步推理/执行、C3 最高能力),但语料库把路由器的*原始*预测、*经策略调整*的决定以及*实际服务*的档位分别作为三个独立字段保留——因此后文课程排序使用的是原始预测需求,而不会把它与部署策略对"实际服务哪个档位"的影响混为一谈。
5. **能力引导的数据分配。** 每轮迭代都在一个与训练数据保持不相交(用同一套去重/去污染筛选)的分层评测集上评测当前检查点;结果按属性、质量维度与路由档位聚合,形成一份逐检查点的能力缺陷画像,用以重新加权(而非替换)下一轮训练配比,同时新的 harness 轨迹在同一套流水线下持续加入,从而闭合评测-选择-更新循环。
6. **带掩码的用户轮次 SFT。** 每条训练序列是当前用户轮次(保留推理、工具调用与响应)加上历史上下文(更早轮次的可见响应/工具结果,但不含更早的推理);一个二值 token 级损失掩码把预测损失限制在当前轮次的助手目标片段上(式 1),按批次内被监督 token 数归一化,遵循 Qwen3.5 的对话/工具调用模板。
7. **路由引导的三阶段课程。** 每条 SFT 样本根据请求与响应前的历史被重新打分(硬排序:分配的档位索引;软排序:分数加权的平均档位,式 2)——而不是根据 harness 实际服务了哪个模型。训练分三个大致等长的阶段进行,逐步引入更高分的样本,同时刻意在后期阶段保留一部分低分样本,阶段之间不重置优化器或学习率调度。
8. **路由引导的在线策略蒸馏(OPD)。** 同一套三阶段能力需求调度被用来选取记录下来的响应前上下文作为生成起点(式 4);在每个阶段,当前学生从这些上下文生成一批响应,一个固定教师在学生自己的 top-K 候选 token(加一个聚合的溢出桶)上给出下一 token 分布,学生最小化按响应长度归一化的反向 KL 散度(式 3)——rollout 检查点会周期性刷新,使后期阶段的上下文能获得对更新学生行为的教师监督,而只有学生参数被更新。

# Q6 实验设计

两个规模(4B、9B),均基于 Qwen3.5 基座初始化,在十个基准上评测,分三类:**agentic**——基于 harness 的端到端执行(QwenClawBench、WorkBuddy Bench、PinchBench、VitaBench)与工具使用/交互式任务完成(BFCL V4、覆盖 Airline/Retail/Telecom 三域的 τ²-Bench);**代码**(HumanEval、LiveCodeBench v6);**指令遵循**(IFEval、IFBench)。4B 组对比 Qwen3.5-4B、Spark-X2.5-4B、Gemma-4-E4B-it、Nanbeige-4.2-3B 与 Agents-A1-4B;9B 组对比 Qwen3.5-9B、Granite-4.2-8B、Ornith-1.5-9B、Gemma-4-12B-it,以及规模大得多的 Muse-Glimmer-30B(作为背景参照)。每个基准内所有被比较模型使用相同的 harness/工具接口/上下文预算,各自使用官方对话模板;表中带星号的条目取自其他模型的官方博客或报告,而非在本文流水线下实测得到。

**主要结果。** NeoHorse-1-4B 把宏平均从 Qwen3.5-4B 的 58.94 提升到 64.87,在所有双方均有结果的基准上都优于 Qwen3.5-4B,领先 4B 组内第二名 Nanbeige-4.2-3B(62.31)与 Spark-X2.5-4B(62.22)。NeoHorse-1-9B 把宏平均从 Qwen3.5-9B 的 65.60 提升到 69.04,是其自身对比表中平均分最高的模型——领先规模大得多的 Muse-Glimmer-30B(67.86)与 Gemma-4-12B-it(63.51),不过 9B 规模上指令遵循的提升较小(其中一项指标甚至略有下降)。NeoHorse-1-9B 在所有双方均有结果的基准上都优于 NeoHorse-1-4B,规模带来的最大增益集中在基于 harness 的 agent 任务、函数调用与较难的代码任务上,在指令遵循上的差距则相对较小;论文报告 NeoHorse-1-4B 在若干基准上已经追平甚至超过 Qwen3.5-9B。

**主文轨迹分析。** 三个代表性轨迹定性展示了这一模式:一个 QwenClawBench 项目排期案例中,NeoHorse-1-4B(与 Qwen3.5-4B 不同)找回了一封被忽略、含有更新依赖约束的邮件,并把修正后的产出保存到正确路径;一个 WorkBuddy 代码修复案例中,NeoHorse-1-9B(与只尝试一次就停止的 NeoHorse-1-4B 不同)完成了完整的编辑-测试-检查-修复循环;一个 PinchBench 数据分析案例中,发现 pandas 不可用后,NeoHorse-1-9B 放弃反复失败的依赖安装尝试、转而使用 Python 标准库,相比 4B 轨迹分别减少约 70.8%/76.7%/83.6% 的请求数、执行时间与 token 用量完成同一任务。

**附录案例研究(A-C)。** 三个额外的完整示例对比 NeoHorse-1-9B 与 Qwen3.5-9B:一个受时间与审计约束的日常工单报告任务,NeoHorse-1-9B 报告的 50 条合格记录/19 张工单与独立重新计算一致,而 Qwen3.5-9B 的最终报告内部总数相互矛盾(20 对 26 对 31),并把次日更新的状态错误地赋给了窗口内的一条记录;一个基于仓库需求实现的时间泄露审计器任务,NeoHorse-1-9B 读取了 README 并应用其中规定的五分钟容差、同时保持所需输出 schema,而 Qwen3.5-9B 从未读取 README、硬编码了两秒容差、拒绝了一个本该有效的样本、并破坏了输出 schema;以及一个 HTML 五子棋游戏,同样的 26 次点击回放中,NeoHorse-1-9B 正确记录了全部 26 颗棋子且游戏保持可玩,而 Qwen3.5-9B 由于点击处理器中的一个 DOM 属性索引错误导致全部 26 次点击均失败、始终没有棋子被渲染出来。

**数据消融实验(固定在 4B 模型上,基于 Qwen3.5-4B,五个基准子集:LiveCodeBench、HumanEval、IFBench、BFCL V4、τ²-Bench)。** 在匹配的初始化、课程调度、优化器、随机种子与训练预算下,来自路由 harness 的轨迹在全部五个基准上都优于一个公开的合成工具-agent 数据集(Toucan),非加权平均领先 +6.26 分(70.57 对 64.32),最大增益出现在 HumanEval(+8.54)与 τ²-Bench(+11.31)上。第二个消融在严格嵌套的子集上扩大路由 harness 监督规模(初始化、优化方式与训练轮数均固定):五基准平均分从基座模型的 69.31 提升到测试范围内最大数据规模下的 71.45(横轴为对数尺度的 token 数),在测试范围内未观察到饱和迹象。

# Q9 主要贡献

1. 重新界定了 RSI 的数据问题:主张一个部署中的、面向异构模型池的路由 harness,本身已经产出 RSI 所需的三种信号——执行轨迹、区分预测与实际服务能力需求的路由信号、以及结果反馈——无需额外搭建一套专门的 RSI 观测层。
2. 一套在三个相互关联的粒度(轨迹/用户轮次/子场景)上运作的"轨迹转训练样本"流水线,结合基于规则的结构校验、六维语义评测(确定性规则加证据受限的判官,标记为 PASS/WARN/FAIL/NOT_EVALUATED),以及三轴(场景/目标/结果)子场景刻画,使结构性事实不被语义判官覆盖。
3. 一套路由引导的三阶段 SFT 课程——用重新估计的能力需求而非实际服务模型的身份来排序——并延伸到路由引导的在线策略蒸馏,配合一个紧凑的 top-K 加一溢出桶反向 KL 目标以及周期性刷新的 rollout 检查点。
4. 能力引导的数据分配,闭合了一个评测-选择-更新循环:每个检查点在一个去污染、分层评测集上的自身缺陷画像,重新加权下一轮训练配比。
5. 报告的宏平均提升为 4B 的 58.94→64.87、9B 的 65.60→69.04(基准数量的"十 vs. 十一"差异见 Q8),NeoHorse-1-4B 在所有可直接比较的基准上都优于 Qwen3.5-4B,NeoHorse-1-9B 在其自身对比表中取得最高平均分,领先规模大得多的 Muse-Glimmer-30B。
6. 消融证据表明,来自路由 harness 的轨迹在完全相同的训练配置下,比一个匹配的公开合成 agent 数据集(Toucan)迁移效果更好(五基准非加权平均 +6.26),且扩大唯一路由 harness 监督规模在测试范围内持续带来提升(69.31→71.45),未观察到饱和。

# Q10 下一步

论文明确表示,自身证据只覆盖评测-选择-更新循环的单次通过:把后训练检查点送回 harness 后获得的收益能否在连续几代模型间持续累积,"仍有待检验",而非本报告已经证明的结论。论文提出了三个具体延伸方向:把反馈闭环跨连续模型世代持续迭代;把经验收集、能力引导分配与课程设计扩展到 harness 服务的全部任务、执行环境与模型范围(当前验证仅覆盖 agentic、代码、工具使用与指令遵循能力);以及把路由信号本身打磨为经过校准的难度/缺陷估计——包括训练路由器本身,论文将其明确列为直接的未来步骤,而非已经建成的部分。

除论文自身框架之外,有两点值得向评估本笔记证据基础的读者指出。第一,本报告被呈现为另一篇论文"Agentic Routing: the harness-native data flywheel"[33] 的直接方法延伸,作者团队与该文(同属 TokenRhythm Technologies)有相当程度重叠;本笔记未读过那篇论文,因此无法独立核实底层 C0-C3 路由器本身的预测准确率——只能确认 NeoHorse-1 把路由器的原始预测当作课程排序信号来使用。第二,论文没有报告对自身六维语义评测判官的任何人工评测——而正是这个判官决定哪些轨迹可以进入训练数据——这就留下一个开放问题:该判官的误差是否会以报告的基准增益无法体现出来的方式,偏移训练分布;这与本知识库 [Post-training feedback](../topics/post-training-feedback.md) 主题已经在追踪的、判官驱动训练信号的评判者可靠性问题在结构上相邻,不过 NeoHorse-1 的判官把关的是*数据准入*,而非直接塑造一个标量奖励。
