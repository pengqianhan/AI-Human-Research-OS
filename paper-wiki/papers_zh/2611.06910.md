# Q1 问题定义

* **输入（X）：** 一份类似课题负责人（PI）指示的高层说明（`task.md`，有时附提案），必要时提供的数据和支持文件，以及带有智能体工具的沙箱。不给定方法或解题路径。
* **输出（Y）：** 确定性产物（计算量、模拟输出、处理后的数据）和一份手稿 `paper.pdf`。基准本身的输出是每次运行（rollout）的通过与否和质量分。
* **约束：** 每次运行上限 10 小时；通过要求全部验证器测试和全部阻断项（blocker）规则。非阻断项打 0、1、2 分，权重 1 到 10；门槛通过时任务分为其加权百分比，否则为 0。

# Q2 问题新颖性

部分是新问题。作者的表 1 梳理了这一领域：推理类基准（CritPt、FrontierScience-Research）、工作流子任务（Terminal-Bench-Science）、提供论文的复现（PRBench、ReplicationBench、QMP-Bench）和隐藏答案的端到端任务（NatureBench、PRL-Bench、ResearchClawBench、PhySciBench）。他们主张只有 FrontierPhysics 同时具备贡献者自己的研究、隐藏参考、对文献和写作的评分、专家规则、确定性验证器和失败分析。这张比较表是作者自己的编码，表外的基准如 [Into the Unknown](../papers/2610.19159.md) 也评估开放式研究（读者注；本文未引用）。

# Q3 科学假设

如果任务来自研究者自己的项目，经过筛选以保持开放性并防止误判，并且同时按正确性和手稿质量评分，那么前沿智能体的得分应当远未饱和，而专家阅读失败轨迹应能揭示真正限制它们的因素。

# Q4 相关工作与关键人物

* **科学基准。** 教科书级题集（OlympicArena、PHYBench、UGPhysics）、面向专家级问题的 Humanity's Last Exam、面向研究级问题的 Agents' Last Exam，以及表 1 中的基准。
* **科学智能体。** 带工具的化学模型（Bran 等）、AI Scientist、Co-Scientist、AlphaEvolve、Agent Laboratory、Virtual Lab 和 CASCADE。
* **评分。** PaperBench、HealthBench 和 SedarEval 中的规则评分；FrontierCode 的阻断项与非阻断项划分；Ansari 等通过专家重评发现物理评估存在缺陷的研究。
* **关键人物。** Bingran You、Wenjun Ke、Ria Rosenauer 和 Bo Liu（共同第一作者），资深作者包括 Xiangyi Li（BenchFlow）以及 Gerbrand Ceder 和 Hartmut Haeffner（加州大学伯克利分校），共列出 37 个机构。可能的批评者：关注评分有效性的 Ansari 等，以及表 1 中端到端基准的作者。

# Q5 关键解决思路

**只有作者本人才能评的任务。** 贡献者必须证明项目由本人完成，且至少投入两周研究，然后撰写说明和评分规则。评分项旨在体现只有做过这项研究的人才有的洞见。完全由 AI 生成的提交会被拒绝，182 份提交中接收了 56 份。

**针对基准自身错误的筛选。** 领域审查者（主要是博士生和博士，分别占 47% 和 37%）检查说明是否过度规定、规则是否有真实物理内容，以及至少三次用最先进智能体的运行是否暴露假阳性或假阴性。由六人管理团队批准合并。

**门槛加质量分。** 阻断项是科学有效性的二元要求。非阻断项高分无法挽救未通过的门槛，而正确但写得差的论文可以低分通过。

**由智能体担任评审。** 评审智能体在独立沙箱中评分，可以访问轨迹、代码和输出，因为奖励攻击、幻觉结果和文献检索的检查不能只看 `paper.pdf`。所有运行都使用同一评审：Codex 中的 GPT-5.6 Sol（xhigh）。

**把失败阅读作为基准的一部分。** 每位贡献者对三次 GPT-6 Astra 运行撰写失败报告，管理团队复核后归纳出 14 个标签的分类体系，覆盖这 168 次运行。

# Q6 实验设计

* **运行。** 22 个模型共 26 种配置，每个任务三次试验，56 个任务共 4364 次运行，使用可用的最高推理强度（四个 GPT 模型另跑 xhigh）。
* **Harness。** GPT 用 Codex，Claude 用 Claude Code，Grok 用 Grok Build，Gemini 用 Antigravity。DeepSeek、GLM、Kimi、MiMo 和 Mistral 都在 Claude Code 中运行。
* **基础设施。** BenchFlow CLI、Daytona 沙箱，或较重任务用 Azure 虚拟机上的 Docker 并接入 Lambda GPU。
* **失败处理。** 由模型造成的结束算失败，基础设施故障则重跑。缺失结果算失败（GPT-5.6 Luna xhigh 一个槽位，DeepSeek V4.1 Flash 四个）。
* **统计。** Pass@1、Pass@3、分数、二项区间、按任务自助抽样，以及对榜首配置的配对符号翻转检验。
* **可靠性检查。** 专家假阴性审计、用 Claude Opus 5.5 担任评审重评，以及在 33 个任务上给作者自己的手稿评分。

# Q7 数据集与代码

结果基于 FrontierPhysics v0.1。任务按名称和领域列出（九个主要领域，15 个任务有次要领域），附录 A 展示一个完整示例。检索到的文本没有给出任务或保存轨迹的 Hugging Face 数据集的公开链接，`hf papers info` 也未列出代码库。运行工具 [BenchFlow](https://github.com/benchflow-ai/benchflow) 是公开的，撰写本笔记时未打开。

# Q8 证据质量

* **有证据支持。**
  * *远未饱和。* Opus 5.5 以 27.4% 的 Pass@1 领先（95% 置信区间 17.9 到 36.9），8 个任务三次全过，25 个任务至少过一次。GPT-6 Astra max（23.2）、GPT-6 Astra xhigh（19.6）和 GPT-6.1 Sol（19.6）与它在统计上不可区分，Gemini 3.8 Flash 和 Mistral Large 4 没有通过任何运行。
  * *失败模式大多不是物理知识不足。* 在 GPT-6 Astra 审计中，失败运行里严谨性占 48%，直觉占 34%，文献占 27%，遵循指令占 26%，标签可重叠。循环自我验证是最主要的例子。审计表中没有运行带奖励攻击标签，有两次带幻觉标签（读者统计表 5）。
  * *花钱不一定换来通过。* 通过率通常随成本上升，但在这些 Claude 模型中随成本上升而下降：Opus 5.5（26.95 美元，27.4%）、Fable 5.1（32.63 美元，11.3%）、Opus 5（56.77 美元，9.5%）。GPT-6.1 Sol 以 5.33 美元达到 19.6%，每次通过约 27 美元，Opus 5.5 约 98 美元（读者计算）。
  * *审计会改变数字。* 168 次 GPT-6 Astra 运行中有 9 次被错误判为失败，该配置因此从 14.9% 变为 20.2%。任务修复并重跑后其 Pass@1 为 19.6%，接近修正值。
  * *规则与人类工作吻合。* 作者自己的材料在手稿级评分项上平均得 96.2%，可从表 11 重算（读者核对）。
* **比标题所说更弱或更窄。**
  * *诊断来自单一配置。* 摘要说的是“前沿智能体”，但审计只覆盖 GPT-6 Astra（xhigh），它并不是榜首配置。作者也说其他模型可能以不同方式失败，并且子智能体轨迹太难阅读。
  * *修正不对称。* 只有 GPT-6 Astra 能准确标注假阴性。任务修复覆盖了所有配置，但其他模型单次运行层面的评分错误仍留在其通过率中，这在前四名统计上接近时很重要（读者观察）。论文没有报告假阳性率。
  * *只有一个评审家族。* 用 Opus 5.5 重评时，几乎所有 GPT-6 Astra 运行的判定相同，但该评审对自家模型更宽松（表 6，其数值不在转换后的文本中）。所有主要结果都由 GPT 评审打分，Sol 是否偏向 GPT 模型没有以同样方式检验（读者观察）。
  * *模型与 harness 混淆。* 各实验室的模型运行在自家 harness 中，另外五家的模型共用 Claude Code，因此实验室之间的差距不完全是模型差距（读者观察）。
  * *“可发表”是作者定义的门槛。* 通过意味着越过他们设计的门槛，没有手稿经过同行评审。参考材料检查只覆盖手稿级评分项，三个参考条目未通过阻断项（`cpt-frustrated-chain-spectra`、`cvqkd-calibrated-detector-noise`、`phase-controlled-optical-tweezer-holography`），还有一篇原始论文只得 50%（读者阅读表 11）。
  * *选择与激励。* 通过筛选的任务部分取决于智能体在其上如何失败，而任务作者也是论文作者。论文指出对抗性规则设计是一个缺陷来源并加以审计，但只针对一种配置（读者观察）。
  * *表 5 无法完全重新统计。* 其中 129 次没有 PASS 标签的运行的标签，除以 143 得到 47%、34%、27% 和 26%，接近文中比例；但表中有 39 个 PASS 标签，而修正前只有 25 次通过，因为 PASS 可与失败标签共存。文本没有定义该表中 PASS 的含义（读者核对）。
  * *领域样本少。* 每个领域任务不多，论文本身也认为领域差异不确定。

# Q9 贡献

* 一个由贡献者自己的研究构建的 56 任务物理基准，包含确定性验证器、阻断项、加权规则和手稿评分。
* 对 26 种配置的测量，包括成本、时间、token 和按任务聚类的不确定性。
* 基于专家阅读 168 次运行得到的 14 标签失败分类。
* 对评分误差的直接测量：假阴性修正、第二评审的分歧，以及对人类参考工作的评分。

# Q10 下一步

* **更开放的评估（论文提出）。** 有能力的智能体应当超越给定任务，这需要能处理探索性推理、部分进展和意外发现的评估。
* **审计第二种配置（读者建议）。** 对 Opus 5.5 做同样的阅读，可以检验严谨性是否同样居首，并让榜首比较变得对称。这需要阅读子智能体轨迹的工具。
* **跨家族评分（读者建议）。** 用评审家族与被评家族的矩阵给同一批样本打分，可以测量双向的宽松程度。
* **同一模型跨 harness（读者建议）。** 让一个模型在 Codex 和 Claude Code 中分别完成全部 56 个任务，可以分离出 harness 对差距的贡献。
* **把严谨性作为干预点（读者问题）。** 独立于智能体自身假设的验证器能否减少循环自我验证？[Into the Unknown](../papers/2610.19159.md) 在 64 条被审计轨迹中有 58 条发现宽松的自我验证，说明同样的弱点也出现在另一个基准上。
