> 论文:**SWE-bench Science: Can Coding Agents Resolve Engineering Tasks in Science?**
> 论文链接:<https://arxiv.org/abs/2608.19799>
> 机构:OpenMOSS(复旦大学团队)

# Q1 问题定义

* **输入 `X`**:一个固定在某个基线 commit 上的真实科学软件 GitHub 仓库(源代码、公开测试夹具、依赖、编译器/工具),加上三种范式之一的任务说明(问题驱动、专家探索式、工程集成式),交给一个编码 agent。
* **输出 `Y`**:编码 agent 认为能解决该任务的代码补丁,评测方式是在干净环境中将补丁应用到仓库、重新构建项目,并通过每个任务专属的 Docker 验证镜像运行留出测试;成功与否是每个任务的二元 pass@1。
* **核心问题**:科学软件正日益成为科学仪器本身的一部分,因此一次修复失败不仅会破坏程序行为,还可能损害支撑某个科学结论的证据——然而现有编码 agent 基准主要衡量聚合任务成功率,对于 agent 在修复科学软件时*为何*失败几乎没有提供洞察,因为科学软件依赖的领域契约(单位、坐标系、数值不变量、文件格式语义、物理假设、工作流约定)是普通代码基准从不暴露的。
* **范围**:119 个发布任务,覆盖 98 个 GitHub 仓库、20 个科学领域(默认选集中 96 个任务为无限制许可,另有 23 个受限许可任务需显式选择加入);评测对象是仓库级修复而非孤立函数合成。

# Q2 问题的新颖性

据摘要所述,现有对编码 agent 的评测主要强调聚合任务成功率,对于 agent 在修复科学软件时具体为何失败提供的洞察有限。SWE-bench Science 的新颖之处在于,把 SWE-bench 式的仓库级修复范式收窄到一个领域(科学计算),在这个领域中,正确性依赖于普通代码基准很少暴露的契约——单位、坐标系、数值不变量、物理假设——并把这一基准与一套明确的失败机制分类(四种反复出现的失败机制)以及一个隔离"科学指导对修复质量因果影响"的受控消融实验配对,而不只是报告 pass@1。

# Q3 科学假设

如果编码 agent 在源自真实科学软件仓库、要求保留领域特定科学契约的仓库级修复任务(问题驱动、专家探索式、工程集成式三种范式)上被评测,那么即使是当前最强的 agent 也会表现出显著低于通用软件工程基准的 pass@1;其失败会聚集为与科学知识缺口相关的、可辨识的机制,而非通用编码错误;提供显式的科学指导是否有帮助,取决于该指导是否与任务良好契合——也就是说,科学知识对 agent 修复而言并非一概有益。

# Q4 相关工作与关键人物

* 来自 **OpenMOSS** 的团队(Zhipeng Xu、Jiahao Lu、Yining Zheng、Yuxin Wang、Xipeng Qiu),以 OpenMOSS-Team 组织在 Hugging Face 发布。
* 直接延续了 SWE-bench 系列基于真实 GitHub issue 的仓库级编码 agent 基准脉络(本知识库 [SWE-bench Verified](../concepts/swe-bench-verified.md) 概念页所追踪的同一系列),将其扩展到科学软件领域;与 SWE-bench Verified 面向通用 Python 仓库、经人工验证的 issue 不同,SWE-bench Science 专门为科学代码所依赖的领域契约筛选任务,并加入了通用 SWE-bench 系列所不具备的配对消融方法论。
* 在本知识库中,与 [LLM agents](../topics/llm-agents.md) 中的其他编码 agent 评测与 harness 论文,以及 [AI for science](../topics/ai-for-science.md) 中的 AI-for-science agent 评测线索并列——后者迄今更侧重于*规划并执行*科学实验的 agent(AutoScientists、Arbor、EurekAgent、SkillFoundry),而非*修复既有*科学软件的 agent。

# Q5 核心解法

1. **三种任务范式。** 任务被组织为问题驱动型(解决一个已陈述的 bug/功能请求,最接近经典 SWE-bench)、专家探索型(要求 agent 在没有明确 issue 的情况下发现修复目标)、工程集成型(将科学计算功能集成或扩展进既有系统)——这一分类旨在区分不同的失败模式,而非把所有仓库修复都当作同一种任务。
2. **保留契约的仓库级评测。** 119 个任务中每一个都配有基线源码、公开测试夹具、依赖/编译器/工具、留出测试,以及两个已发布的 Docker 镜像(环境镜像 + 验证镜像);评测流程把 agent 的补丁应用到干净基线上、重新构建项目,并对照留出测试打分,因此正确性是对照构建基准时所用的同一套可复现基础设施来检验的,而非依赖 agent 自身的说法。
3. **四机制失败分类法。** 通过分析 agent 的失败,论文识别出四种反复出现的机制:科学知识或抽象能力的缺失、误导性探索或表层修复、修复覆盖不完整或系统集成缺失、以及未能将科学知识泛化到未见案例之外——为"agent 为何失败"而非仅仅"是否失败"提供了一套共同词汇。
4. **配对式科学指导消融。** 一个受控消融在保留仓库和可执行工程上下文的同时,从任务中移除显式的科学指导,以隔离该指导的因果贡献。结果是不对称的:契合良好的科学信息可以约束搜索空间,提升平均表现和 token 效率,而与任务不契合的指导可能诱发锚定效应,不但不能可靠提升、甚至可能损害精确修复的成功率。
5. **可复现的分发流水线。** 任务通过 Hugging Face(任务表、选集、运行工具)、Docker Hub(不可变的每任务环境/验证镜像)和 GitHub(文档、工具、审计记录)分发;`materialize.py` 工具生成显式的 `selection.json`,记录确切的任务 ID 和一个选集哈希,`run_batch.py` 则驱动 agent 在配置好的 harness(如 Codex)下执行,凭证保存在检出目录之外。

# Q6 实验设计

头条结果(来自摘要,并被项目主页排行榜印证)是表现最好的被评测 agent、**Claude Code(搭配 Opus-5,max 设置)**,pass@1 低于 50%——项目主页自己的排行榜(截至 2026-08-16)将其列为 47.90%,其后是 GPT-5.6-sol(max)46.22%、DeepSeek-V4-Pro(max)42.02%、Kimi-K3(max)35.29%、GLM-5.2(max)31.93%,总共评测了九组(模型、配置)组合。除排行榜外,论文的核心实验贡献是配对消融(科学指导有 vs. 无,仓库/工程上下文保持不变),用于将四机制失败分类归因到具体原因,而非只报告单一聚合数字。

引入了该基准本身:119 个发布任务(默认选集中 96 个为无限制许可,另有 23 个受限许可任务可选择加入),来自 98 个 GitHub 仓库、20 个科学领域。通过 Hugging Face(huggingface.co/datasets/OpenMOSS-Team/SWE-bench-Science)分发任务表和运行工具,通过 Docker Hub 分发不可变的每任务环境和验证镜像,通过 GitHub(github.com/OpenMOSS/SWE-bench-Science,据 `hf papers info` 有 46 个 star)分发文档、物化工具和审计记录;项目主页为 swescience.github.io。工具部分采用 MIT 许可,第三方材料保留其上游许可,审计声明记录在 NOTICE.md 中。

# Q9 主要贡献

1. **SWE-bench Science**,一个将 SWE-bench 仓库修复范式扩展到科学软件的基准,包含 119 个任务、98 个仓库、20 个领域,组织为三种任务范式(问题驱动、专家探索、工程集成),通过可复现的基于 Docker 的环境/验证镜像评测。
2. 一项实证发现:即使是当前最强的编码 agent(Claude Code 搭配 Opus-5,max)也只能解决不到一半的这类任务(据项目排行榜为 47.90% pass@1),确立了科学软件修复对当今 agent 而言比通用仓库修复要难得多。
3. 一套**四机制失败分类法**(科学知识/抽象缺失、误导性探索/表层修复、覆盖不完整/集成缺失、泛化失败),为后续工作诊断 agent 在科学软件任务上"为何"失败提供了共享词汇。
4. 一个**配对消融**,隔离了显式科学指导对修复的因果影响,表明该效应依赖于指导质量,而非一概为正——契合良好的指导能提升平均表现和 token 效率,而不契合的指导可能诱发锚定,并不能可靠提升精确修复率。

# Q10 下一步

本笔记在没有完整论文正文的情况下无法解答的开放问题:区分三种任务范式的精确操作性定义(在边界情形下,是什么使一个任务被归为"专家探索式"而非"问题驱动式");按范式或按科学领域细分的四机制失败量化拆解;以及在消融实验中,"契合良好"与"不契合"的科学指导是如何被操作化或选取的——这对判断该指导质量发现对 harness 设计者的可操作性程度很重要。**与本仓库的关联**:与任何评测编码 agent 在科学计算仓库上表现、或为此类 agent 设计科学指导 prompt/技能的项目相关——指导质量消融是对"更多领域上下文总是更好"这一假设的直接实证警示,值得在完整论文可检索后重新审视(可稍后重试 `hf papers read`,或直接抓取 PDF/TeX 源码)。
