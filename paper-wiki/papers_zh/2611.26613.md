# Q1 问题定义

* **输入（X）：** 对于前沿多模态智能体执行的机器人操作回合中的每个动作，给出全局任务指令 G、智能体自己为该动作声明的局部意图（local intent）g_t，以及一个有界的多视角画面窗口（动作前、动作后，夹爪闭合时再加一小段抬起后的画面），外加所下达的动作及其执行状态。
* **输出（Y）：** 结果标签（达成、失败、部分、无法验证）；失败动作的失败模式（Grasp 抓取、Alignment 对准、Interference 干扰、Effect 效果、Incomplete motion 动作未完成、Choice 选择，或 Unresolved 未定）；抓取失败的子类别；以及一句基于证据的简短理由。汇总后回答：前沿智能体在直接控制机器人时是如何成功、又在哪里失败的。
* **约束：** 智能体"直接"控制机器人：以结构化工具调用发出低层数值目标（末端位姿、关节配置、夹爪开度），不使用高层技能原语，零样本，不做任务特定微调也不给示范。每个动作只对照它自己的局部意图评判，与回合结果无关。

# Q2 问题新颖性

已有多份报告显示 GPT-6 Astra 等前沿模型通过数值动作控制机器人，并在零样本下胜过 VLA（RoboDojo、RoboMME、RoboLab-120、RoboColiseum、UniVTAC 与 OpenViTac、GPT-GEAR、Embodied First Exam）。它们都只在回合层面评估。机器人失败推理工作（REFLECT、AHA、RoboFAC、ViFailback、FailBench）研究的是 VLA 或扰动示范中的失败。新角度是对前沿智能体轨迹中自然出现的失败做逐动作评判，并通过让策略为每个动作声明局部意图使之可定义：操作任务是多模态的，同一个动作是成功还是失败取决于它本来想做什么。

# Q3 科学假设

如果策略为每个动作同时声明局部子目标，那么 VLM 评判器就能可靠地判断每个动作的结果并归因其失败（以人工标签衡量）；由此得到的动作级标签会揭示回合级成功率掩盖的能力和瓶颈：尤其是前沿智能体能在闭环中从自身的局部失败中恢复，而剩下的失败属于物理精度问题而非语义问题。

# Q4 相关工作与关键人物

* **前沿智能体作为机器人策略。** SayCan 式的技能规划和 code-as-policies 都调用原语；近期工作让前沿多模态智能体直接输出数值动作。本 wiki 中的 [EmbodiedSWE](../papers/2609.27308.md) 和 Self-Evolving Coding Agents（2609.35432）代表另一条写程序的路线：智能体编写控制代码，而不是逐步发出数值指令（读者对比）。
* **对前沿智能体的回合级评估。** GPT-6 Astra 在全部 42 个 RoboDojo 任务、RoboMME、RoboLab-120、真实双臂桌面任务、UniVTAC/OpenViTac 上的报告；跨模型框架（RoboColiseum、物理机械臂上的 RoboDojo 研究）；GPT-GEAR；Embodied First Exam 框架。
* **失败检测与推理。** REFLECT、AHA（扰动示范）、RoboFAC、ViFailback、FailBench。
* **关键人物。** Yiyang Du 与 Chenyan Xiong（通讯作者；卡内基梅隆大学），Yuxuan Kuang、Qitao Zhao、Zhanqiu Guo（CMU），Yixuan Wang（UIUC），以及 Yi Xu、Xin Li、Wenbin He、Liu Ren（博世北美研究院与博世人工智能中心）。可能的批评者：VLA 与世界-动作模型团队（比较只在零样本下进行）以及机器人失败推理方向的作者。

# Q5 核心方法

1. **以意图为依据的轨迹。** 每个机器人工具调用都有一个必填的 note 参数写明局部意图，缺少它的调用会被执行框架拒绝。对七个基准（LIBERO-MAX、Meta-World+、DexJoCo、RoboWits、RoboTwin 2.0、YAMLab、ContactBench 1.0）作者新采集了 GPT-6 Astra 回合；对另外五个（RoboDojo、StationeryBench、Astranomy、UniVTAC、OpenViTac）则导入已发布的、原本就记录了决策说明和画面的 GPT-6 Astra 轨迹。
2. **以意图为依据的评判器。** C(G, g_t, O_t) 返回结果、失败模式和说明。三条协议规则：按接触语义选取画面窗口（闭合动作按是否抓住并保持来判，用抬起画面）；局部有效性与回合结果脱钩（被后续纠正的失败抓取仍算失败；达成意图的刻意小幅试探算达成）；在带边界规则的编码手册下依证据归因（例如物体不再被握持算 Grasp，被握持物体仍偏离目标算 Alignment）。所有分析标签都由 GPT-6 Astra 作为评判器给出。
3. **Choice 是相对于声明的意图而言的。** Choice 失败指执行与意图中所写的对象、顺序或类别相矛盾；按编码手册，*按意图要求*按下 7 键不算 Choice，即使任务需要的是 3 键。所以 Choice 衡量的是意图与动作的一致性，而不是智能体是否为任务选对了目标（读者强调，依据附录 A）。
4. **验证与蒸馏。** 一个 400 个动作的人工标注测试集（34% 达成，66% 失败），用来比较另外十个评判器；然后用 12,844 个由 GPT-6 Astra 标注的动作（每三个失败配一个达成，按回合划分数据）对 Muse-Glimmer-30B 做 LoRA 微调（秩 32，两个 epoch）。

# Q6 实验设计

* **规模。** 12 个基准；仅 RoboDojo 就有 2,100 个回合、105,429 个动作（按 Precision、Open、Long-horizon、Generalization、Memory 五个维度报告）；新采集的六个基准共 197 个回合、9,232 个动作。回合成功率从 7%（StationeryBench）和 22%（RoboDojo）到 98%（LIBERO-MAX、Meta-World+）不等。
* **恢复分析。** 1,989 个已评分回合中 12,163 个带失败模式的失败动作；当后续动作可验证地修复或绕过其子目标时（例如重新抓取后物体随夹爪升起）计为已恢复；按回合加权和只取首个失败两种方式检验稳健性；对 24 个失败的第二次独立阅读中有 21 个结论一致。
* **零样本比较。** 在不做任务特定微调的条件下比较 GPT-6 Astra 与 pi_0.5、InternW0-Delta（图 6），附录中在匹配的 Embodied First Exam 任务上扩展了与 pi_0.5 的比较。
* **评判器评估。** 结果（400 个动作）与失败模式（264 个失败动作）的准确率和 Cohen's kappa、总体准确率（两者都对）和推理成本；对 GPT-6 Astra 做去掉意图的消融；自我偏好检查（每个评判器把多少个人工判为失败的动作判成达成）。
* **附录探查。** 一个 DexJoCo 任务在有无评判反馈下重跑；要求局部意图与不要求意图的 Embodied First Exam 运行对比；决策延迟。

设计为每条核心论断都提供了测量，但策略、多数分析标签以及微调评判器的训练目标都来自同一个模型 GPT-6 Astra，且人工标签只有 400 个动作。

# Q7 数据集与代码

论文发布 12,844 个动作的训练集、400 个动作的人工标注基准和微调后的 Muse-Glimmer-30B 评判器（GitHub cxcscmu/AgentRoboCritic 与项目页）；评判器的系统提示、用户提示和编码手册在附录 B 和 J 中给出。本笔记未核对发布内容。12 个基准中有 5 个依赖第三方已发布的轨迹。

# Q8 证据质量

* **评判器可靠性。** 在人工集上，GPT-6 Astra 的结果准确率 79.25%（kappa 0.497），失败模式准确率 80.68%（kappa 0.600），总体准确率 71.25%；Claude Fable 5.2 在结果上接近（78.25%），在失败模式上较低（72.73%）。结果上 0.5 左右的 kappa 属于中等一致。文中所说"超过 90%"的一致率，计入了标注者复查分歧后接受评判器标签的情况；这是偏向评判器的事后裁定，不应读作独立的准确率（读者评估）。
* **意图消融。** 去掉 g_t 后，GPT-6 Astra 的结果准确率降到 25.25%、失败模式准确率降到 25.00%，主要是把动作判为无法验证。这有力支持了本文的核心方法论断：动作级评判需要执行者的意图。
* **自我偏好。** GPT-6 Astra 既是策略又是评判器。它只把 264 个人工判为失败的动作中的 19 个（7.2%）判为达成，是所有评判器中最少的，这说明它并未宽待自己的失败。但这没有检验 Astra 是否以对自己有利的方式错判失败*模式*；而且微调评判器是从 Astra 的标签蒸馏而来，其 74.24% 的失败模式准确率部分反映的是与 Astra 标注风格的一致（读者评估）。
* **恢复。** 49.8% 的成功回合含有失败动作；38.9% 的失败在 10 个动作内被恢复，57.7% 在回合结束前被恢复（按回合加权 60.7%；只看首个失败为 76.2%）。按模式：动作未完成 68.2%，抓取 63.7%，干扰 59.1%，对准 35.7%，效果 29.6%。12 个基准间恢复率与回合成功率的 Pearson r = 0.81（Spearman 0.86），但这 12 个点权重不均：12,163 个失败中 9,923 个来自 RoboDojo。恢复由局部意图和画面识别；复核流程没有说明由谁识别，独立复读只覆盖 24 例。
* **语义落地。** Choice 占失败的 0.2%，在任一基准上至多 3.3%。由于 Choice 是对照智能体自己声明的意图来定义的，意图本身选错目标并不计入，因此"可靠的语义落地"意味着智能体说到做到，而不是为任务选对了对象（读者评估；编码手册中的例子说明了这一点）。
* **零样本优势。** 与 pi_0.5 和 InternW0-Delta 的比较按设计是零样本的，而这恰是 VLA 最弱的场景；正文只以图给出结果。GPT-6 Astra 每次决策的中位耗时为 31.9 秒，pi_0.5 为 0.11 秒（附录 H.4），这一实际差距正文未讨论。
* **个例式探查。** 评判反馈修好一个 DexJoCo 任务只是单个案例、一次对照运行；要求局部意图在 76 个匹配实例上没有改变成功率（两种方式都是 42/76）。
* **读者核查。** 失败模式准确率都是 264 的整数计数（80.68% = 213/264，74.24% = 196/264，32.58% = 86/264），400 个动作按 34% / 66% 划分为 136 / 264，与各表一致。

# Q9 贡献

1. 通过要求执行智能体为每个动作声明局部意图，使操作任务的逐动作评判变得可定义，并配有七类失败模式的编码手册和按接触语义选取的证据窗口。
2. 在 12 个基准上对一个前沿智能体直接控制机器人的大规模动作级刻画：闭环恢复、罕见的意图-动作不一致，以及随任务几何变化的物理瓶颈（一般任务中闭合时的抓取、仅视觉的紧公差任务中的对准、杂乱场景中的干扰）。
3. 400 个动作的人工标注评判基准、12,844 个动作的训练集，以及一个开源微调评判器：其失败模式准确率超过除 GPT-6 Astra 外的所有专有评判器，成本低 30 倍以上。

# Q10 后续方向

* **大规模独立标签。** 对更大的分层样本做人工标注（尤其是 RoboDojo 之外），并报告裁定前的一致率（读者建议）。
* **其他策略。** 用同一流程分析其他前沿智能体，以及改造后能输出意图的 VLA，使结论关乎直接控制本身而不只是 GPT-6 Astra（读者建议；论文指出改造 VLA 并不容易）。
* **任务层面的选择错误。** 增加对意图本身与任务是否相符的检查（智能体是否打算操作正确的对象？），以补充只检查动作与意图一致性的 Choice（读者建议）。
* **在线评判器。** 把廉价的微调评判器用作在线监控，发现物体丢失（9.5% 的抓取失败是夹爪已空时仍在执行的动作），并对恢复率很低的对准失败触发重试；在单个 DexJoCo 案例之外做规模化检验。
* **精度与延迟。** 既然闭合偏移和毫米级配合占主导，可测试深度或触觉输入以及更精细的三维定位，并在报告成功率时同时报告延迟（读者建议）。
* **其他场景中的意图声明。** [Intent Contracts](../papers/2611.24025.md) 同样要求执行者逐步声明意图，在那里作为授权记录；两篇都表明，意图检查抓得住"说的和做的不一致"，抓不住目标选错（读者联系）。
