> 论文:**Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory**
> 论文链接:<https://arxiv.org/abs/2504.19413>
> 机构:Mem0.ai

# Q1 问题定义

* **输入 `X`**:一段持续进行的多轮会话(用户/助手消息对构成的流),以及在查询时提出的一个新问题,该问题可能需要单跳、多跳、时间性,或开放域推理才能回答。
* **输出 `Y`**:一个持久化、增量维护的记忆库——基础版 Mem0 中是自然语言事实,Mem0^g 变体中是一个带方向标签的实体-关系图——以及针对该问题的答案,答案通过只检索相关记忆(而非重放整段对话)生成。
* **核心问题**:LLM 固定的上下文窗口使其难以在跨越数天、数周乃至数月的对话中可靠地保持连贯性。单纯扩大窗口并不能解决问题:再宽裕的长度限制最终也会被超过,而且即便信息在技术上仍处于上下文之内,注意力机制在距离较远的 token 上也会退化——因此全上下文方案要在大量与当前主题无关的历史内容中推理,才能找到少数几条真正相关的事实,浪费 token 和延迟。
* **范围**:面向单 agent 的长期对话记忆,而非多 agent 共享记忆;评测专门针对双人长期对话展开。

# Q2 问题的新颖性

面向 LLM agent 的长期对话记忆本身已是活跃方向——MemGPT 的分层记忆、ReadAgent、MemoryBank、A-Mem 的 agentic 记忆演化,以及 Zep 和 OpenAI ChatGPT 记忆功能等商业平台皆属此列。本文的新意在于一套具体的抽取/更新流水线——用一次 LLM 工具调用,针对每条候选事实,对照其 top-k 语义相似的既有记忆,决定是新增(ADD)、更新(UPDATE)、删除(DELETE),还是不做改动,而不借助单独的分类器——再加上一个用于关系型查询的可选图结构变体(Mem0^g),并在一次覆盖六类基线(既有 LOCOMO 系统、一个开源方案、多种分块大小的 RAG、全上下文、一个专有系统、一个商业记忆平台)的评测中验证,覆盖面比以往单篇论文通常报告的更广。

# Q3 科学假设

如果一个 agent 把记忆维护为一组紧凑、增量更新的抽取事实——而不是原始检索文本块或完整对话——通过一次 LLM 工具调用,针对每条候选事实、对照其 top-k 相似的既有记忆决定新增、更新、删除,还是忽略,那么它在长期对话问答准确率(LLM-as-judge 分数)上就能达到或超过全上下文和 RAG 基线,同时只消耗一小部分的 token 和延迟;而如果进一步把这份记忆构造成实体-关系图而非扁平文本,时间性和多实体关系型查询还会进一步改善,代价是额外的 token 和延迟开销。

# Q4 相关工作与关键人物

* 与五个既有的 LOCOMO 基准系统(LoCoMo、ReadAgent、MemoryBank、MemGPT、A-Mem——作者重新运行了 A-Mem 以获取 LLM-as-judge 分数)、一个开源方案(LangMem)、七种分块大小 × 两个 k 值的 RAG、全上下文处理、OpenAI 的 ChatGPT 记忆功能,以及商业记忆平台 Zep 做了对比。

# Q5 核心解法

**Mem0(基础版)**:一个两阶段的增量流水线。*抽取阶段*:给定一对新消息,加上 (a) 一份周期性异步刷新的会话摘要,以及 (b) 最近 `m=10` 条消息作为上下文,一个 LLM 抽取函数 φ 从这次新交流中提取出一组候选显著事实。*更新阶段*:对每条候选事实,通过向量检索找出 top `s=10` 条语义相似的既有记忆,再把二者一起交给 LLM,通过一个函数调用("tool call")接口,由 LLM 自己选择四种操作之一——ADD(不存在等价记忆时新建)、UPDATE(用补充信息扩充既有记忆)、DELETE(既有记忆被新信息否定)、NOOP(无需改动)——而不经过单独的分类器路由。

**Mem0^g(图结构变体)**:把记忆表示为一个带方向标签的图 G=(V,E,L)——实体作为节点(每个节点带类型、嵌入向量、创建时间戳),带标签的关系三元组作为边——通过一个 LLM 实体抽取器和一个 LLM 关系生成器构建,存储在 Neo4j 中。新关系会按嵌入相似度阈值与既有节点做匹配;一个基于 LLM 的冲突解决器会把被否定的关系标记为失效,而不是物理删除,以保留时间推理能力。检索结合了实体中心式的子图搜索(锚定查询中的实体,探索其入边/出边关系)和覆盖全图的语义三元组相似度搜索。

# Q6 实验设计

**基准**:LOCOMO——10 段较长的双人对话(每段约 600 轮对话 / 约 26000 个 token),每段对话平均配有约 200 个问题,分为单跳、多跳、时间性、开放域四类;数据集自带的"对抗性"(不可回答)问题类别因缺乏可用的标准答案而被排除在评测之外。

**评测指标**:F1 和 BLEU-1(词面重合度指标)加上 LLM-as-a-Judge(J)作为主要质量指标——鉴于 J 具有随机性,每种方法独立运行 10 次,报告均值 ± 1 个标准差——此外还有部署指标:token 消耗量(用 tiktoken 的 `cl100k_base` 编码测量)和延迟(仅检索阶段与总耗时的 p50/p95)。

**六类基线**:既有的 LOCOMO 系统(LoCoMo、ReadAgent、MemoryBank、MemGPT、A-Mem);一个开源方案(LangMem);7 种分块大小(128–8192 token)× k∈{1,2} 的 RAG;全上下文(把约 2.6 万 token 的完整对话都放进上下文);一个专有系统(OpenAI 的 ChatGPT 记忆功能,底座为 GPT-4o-mini);以及一个商业记忆平台(Zep)。Mem0/Mem0^g 的全部 LLM 操作均使用 GPT-4o-mini。

**主要结果**:总体 J 分数——Mem0 为 66.88%(±0.15%),Mem0^g 为 68.44%(±0.17%),最强的 RAG 配置约为 60.97%(分块大小 256、k=2)——也就是说 Mem0 相对提升约 10%,Mem0^g 相对提升约 12%。全上下文方法取得了单项最高的总体 J 分数(约 72.90%),但 p95 总延迟约为 17.1 秒,而 Mem0 只需 1.44 秒(降低 91%),Mem0^g 需要 2.59 秒(降低 85%)。分类别 J 分数:单跳——Mem0 最佳,67.13;多跳——Mem0 最佳,51.15(F1 为 28.64);时间性——Mem0^g 最佳,58.13(F1 为 51.55),Mem0 为 55.51;开放域——Zep 以 76.60 略胜 Mem0^g 的 75.71 和 Mem0 的 72.93。Token 开销:Mem0 约每段对话 7K token,Mem0^g 约 14K,相比之下原始对话约为 26K,而 Zep 的记忆图超过 60 万 token(论文将其归因于 Zep 在每个节点都缓存了一份完整的摘要式概括,同时又在边上存储事实,造成大量冗余)。

# Q8 证据质量

六类基线的全面对比,以及针对 J 的随机性所采用的报告协议(10 次运行,均值 ± 标准差),对于这类系统论文而言相当扎实,而且论文很坦诚地承认全上下文方法在原始 J 分数上仍然领先——本文主张的是最佳的"精度—成本"权衡,而非绝对最佳的精度,p95 延迟和 token 开销的数字也直接支撑了这一更有限的主张。检索到的文本中可见的几处注意点:(a) OpenAI ChatGPT 记忆基线的评测方式是把整段对话摄入一个聊天会话,再用它生成的任何记忆作为"完整上下文"——论文明确指出这实际上让该基线获得了对全部记忆(而非仅与问题相关的记忆)的优先访问权,这一差异并未在其报告分数中被完全剥离出来;(b) 关于 Zep 的对比记录了一个运行层面的怪现象——记忆刚被写入后,即时的检索尝试往往无法正确回答查询,而在延迟数小时后重新运行相同的检索,结果明显变好,作者用相同检索重跑来规避这一问题——这记录的是该基线在测试时的可用状态限制,未必反映其稳态能力;(c) Mem0/Mem0^g 的全部 LLM 调用都专门使用了 GPT-4o-mini,因此报告的差距大小与这一底座、以及同一模型充当抽取相关角色的选择绑定在一起,检索到的文本没有报告换用不同底座后的结果,因此无法确认排序是否与底座无关;(d) 论文附录中的提示词模板和确切的 LLM-as-judge 提示词并不在检索到的内容之中,因此评判者校准方面的细节——正是本知识库 [LLM-as-a-Judge](../concepts/llm-as-a-judge.md) 概念页所关注的那类问题——在此未能独立核实。

# Q9 主要贡献

1. Mem0:一个增量式的抽取加更新记忆流水线,用一次 LLM 工具调用(ADD/UPDATE/DELETE/NOOP)对照 top-k 相似的既有记忆做决策,而不是用单独的分类器或简单的仅追加式存储。
2. Mem0^g:一个图结构扩展,把记忆表示为一个实体-关系图,并用 LLM 驱动的冲突解决机制把被否定的关系标记为失效而非删除,从而提升时间性和关系型查询的表现。
3. 一次在 LOCOMO 上的六类基线评测,同时报告精度(F1/BLEU-1/LLM-as-judge)和部署成本(token 消耗、p50/p95 延迟),展示的是一种精度对成本的权衡,而非宣称绝对最佳精度。

# Q10 下一步

* 论文自身提出的未来工作:优化 Mem0^g 的图操作以降低其相对基础 Mem0 的延迟开销;探索融合效率与关系表达能力的分层记忆架构;开发更复杂、受人类认知过程启发的记忆巩固机制;以及把该框架从对话记忆扩展到程序性推理和多模态交互场景。
* 检索到的文本未能解答的开放问题:在比 GPT-4o-mini 更强的底座下,抽取/更新流水线和 LLM 评判者的结果会如何变化;当 LLM 工具调用误判是否存在矛盾时,NOOP/DELETE 决策应如何被审计或撤销;当实体图规模远超 LOCOMO 量级的对话时,Mem0^g 的冲突解决机制能否扩展。
* **与本仓库的关联**:密集自然语言记忆足以应对单跳/多跳检索,而显式的关系图结构则专门有助于时间性和开放域查询——这一发现,对本仓库中任何长时程 agent 记忆组件都是一个具体的设计信号。它与 [LongHorizon-Harness](../papers/2608.01964.md) 共享"把状态外置于模型不断增长的上下文之外"这一总体原则,但服务的是跨会话的对话记忆,而非由独立审计者核验的任务内执行状态。
