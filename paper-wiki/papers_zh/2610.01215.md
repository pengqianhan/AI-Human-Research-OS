# Q1 问题定义

* **输入（X）：** 对一个 GUI 世界的结构化描述（操作系统、屏幕尺寸与动作空间；视觉外观；初始界面状态，如窗口、布局和可见控件），背后没有任何真正运行的软件。
* **输出（Y）：** 带有点击目标定位的"截图-动作-截图"轨迹，转化为单步训练样本（动作前截图、任务、近期历史 → 动作描述与工具调用），用于训练基于截图的 GUI 智能体。
* **核心问题：** 轨迹的多样性受限于能部署哪些环境。科学、CAD、电子设计和创意类软件各自需要安装、配置、准备状态，有时还需要许可证或账号。人工演示、自动探索以及从教程或视频中挖掘，都仍然依赖某人已经运行过的软件。
* **形式化框架：** GUI 交互是一个 POMDP，智能体看不到其潜在状态（完整的计算机配置），只能看到截图。由于截图智能体的训练数据只取决于观察层面的转移 P(s̃_{t+1} | h_t, a_t)，作者追求**交互保真度（interaction fidelity）**：在相同历史下，生成的下一张截图应与真实系统会显示的一致，而完全不必重建潜在状态。

# Q2 问题新颖性

部分新颖。GUI 世界模型已有多种形态：可执行程序、文本或结构化状态预测器、学习得到的视觉预测器，以及渲染预测界面的代码；生成式流水线也能构建带任务和验证器的可执行环境。新的部分在于：把通用的预训练图像生成器用作产生*训练数据*的转移模型——由规划器事先确定任务逻辑、由定位模型提供点击坐标、并做转移级别的质量控制——然后检验用这些数据训练的智能体在真实环境中是否变强。

# Q3 科学假设

如果由规划器规定每个原子动作应造成的变化，再由预训练图像生成器编辑当前截图来呈现这一变化，那么得到的轨迹在经过定位和过滤后，携带足够正确的交互结构，用它们微调可以提升 GUI 智能体在真实桌面和科学软件中的执行与定位能力，包括那些从未为采集数据而部署过的应用。

# Q4 相关工作与关键人物

* **轨迹采集：** 网站和移动设备上的人工演示、从教程和录屏中提取记录、自动探索与任务合成、用于训练的大规模数据集（例如 UI-TARS 和 OpenCUA/AgentNet），以及生成的可执行环境。
* **GUI 世界模型：** 可执行或学习得到的转移预测器、基于文本的前瞻规划、用于策略改进的想象 rollout、预测下一张截图的视觉模型，以及基于代码的渲染器；"图像生成器是通用视觉学习者"（Gabeur 等）是图像先验这一思路的出处。
* **基准：** [OSWorld](../concepts/osworld.md)、Windows Agent Arena、macOSWorld、ScienceBoard 和 [ScreenSpot-Pro](../concepts/screenspot-pro.md)。
* **关键人物：** 混元 AI 数据团队（据 Hugging Face 机构标签为腾讯混元）。核心贡献者 Cheng Yang 和 Yifan Wu；指导者 Tianwen Jiang、Jihong Zhang 和 Yuyu Luo。

# Q5 关键解法思路

* **结构化世界采样与种子实现。** 初始场景从三个因素（操作系统底座、视觉外观、初始 GUI 状态）中采样，编译成详细描述，再由 gpt-image-2（文中称 "Image2"）渲染为种子截图。种子元数据被保留下来，使任务和计划与屏幕内容保持一致。
* **以种子为条件生成任务。** 任务在种子确定之后、依据其可见元素生成，因此不会提到不存在的窗口或应用。任务登记表抑制近似重复。同一接口也支持从基准派生任务，把基准元数据映射到种子采样器上（例如固定所需的前台应用）。
* **规划器、Voyager 与 Image2。** 元规划器（Meta Planner）先写出整个原子动作序列，每一步包括意图、目标元素和预期视觉变化。每一步中，Voyager 查看当前截图和计划动作，写出智能体的第一人称思考和动作摘要，再写出动作后画面的渲染提示；Image2 据此编辑当前截图。规划器决定*发生什么*，图像生成器决定*看起来如何*。
* **定位与质量控制。** LocateAnything 把每个目标描述映射为一个框，框中心作为点击标签。一个 Gemini VLM 检查器逐步判断：目标是否存在、框是否准确且贴合、动作是否有效、前后变化是否与动作相符。错误的框被重新定位（3,390 个），目标缺失或动作无效的步骤被删除，未通过一致性检查的转移被过滤掉。
* **训练样本。** 每个样本包含干净的动作前截图、任务，以及两级历史（最近五步带截图，再往前五步只有文字），监督目标是动作描述和工具调用。

# Q6 实验设计

* **数据：** 79,266 个单步样本：Chrome 35,209、Ubuntu 24,250、Windows 14,778、macOS 5,029；涵盖 31 个 Ubuntu 应用、45 个 Windows 应用、16 个 macOS 应用和 67 个网站。
* **数据分析：** 与真实截图语料（ScaleCUA、AgentNet、aria_ui、WebSTAR、Mind2Web、OS-Atlas）的视觉对齐，方法包括 Qwen3.5-9B 视觉 token 空间与 DINOv2 中的 MMD、分类器双样本检验、低层图块统计、OmniParser 界面覆盖率，以及轨迹统计。
* **训练：** 对 Qwen3.5-35B-A3B 做全参数微调（视觉编码器冻结），32 张 GPU 训练三个 epoch，得到 AGW-35B；评估同一次训练的六个检查点。
* **评估：** OSWorld（361 个任务，排除 Google Drive 任务）和 Windows Agent Arena（154 个）报告含部分得分的平均任务分；macOSWorld（231 个英文任务）和 ScienceBoard（143 个任务；因有记录的任务缺陷排除 Lean 领域）报告成功率；每个任务至多 100 步。ScreenSpot-Pro 在 1,581 个英文样本上测定位。
* **对比：** 基座模型；以及在约 350k 条 AgentNet 人工演示样本上训练的 Qwen3.5-35B-A3B，使用相同任务集评估，但开启了思考模式。

# Q8 证据质量

* **有支撑的：**
  * *四个交互式基准全部提升。* OSWorld 33.0 → 40.8，Windows Agent Arena 19.4 → 27.9，macOSWorld 28.1 → 45.0，ScienceBoard 14.0 → 32.2（成功任务 20 → 46 个）；四项等权平均从 23.6 升到 36.5，并在每个被评估的检查点上都上升。四个基准的 35 个领域中，25 个提升、7 个不变、3 个下降。在 OSWorld 上，多应用任务从 12.0 升到 20.9，是总增益的最大来源。
  * *定位。* ScreenSpot-Pro 准确率从 31.7 升到 57.1，其中图标 16.2 → 32.9、文本 41.2 → 72.0，六个应用领域全部提升。
  * *与真实人工演示对比。* 用约 80k 合成样本训练的 AGW-35B，在四个基准上都超过最好的 AgentNet 检查点（约 350k 样本），在 ScienceBoard 上差距最大（32.2 对 16.8）。
  * *量化了转移缺陷。* VLM 审查在 42,526 个桌面转移中标出 1,293 个与动作不一致（3.04%）；去掉动作无效或定位错误的步骤后为 39,351 个中的 818 个（2.08%）。错误率依动作而异：拖拽 7.58%、滚动 7.09%、文本输入 6.35%、点击 0.67%。失败类型（终端命令或数值被替换、直接跳到最终成品、动作没有效果、意外改动持久内容）都配有示例。
  * *视觉对齐。* 在 Qwen 特征空间中，合成数据到 ScaleCUA 的距离是两个真实数据集之间典型距离的 0.59-1.24 倍；界面覆盖率在全部 12 个"领域 × 阈值"组合中都超过 ScaleCUA。
* **较弱或有边界的：**
  * *基线只有基座模型和一次 AgentNet 训练。* 获取到的正文中没有与同等规模的其他 GUI 智能体比较；而且 AgentNet 那次运行开启了思考模式、AGW-35B 没有，作者也指出了这一点。
  * *没有消融把世界模型与定位标签分开（读者注）。* 点击标签来自专门的定位模型 LocateAnything，因此 ScreenSpot-Pro 的增益中可能有很大一部分是定位能力的蒸馏。只用带定位目标的种子截图、不加生成的转移来训练，就能看出多步轨迹究竟额外带来了什么。
  * *可能与基准任务重叠（读者注）。* 流水线可以从基准元数据派生任务，但获取到的正文没有说明 79,266 个样本中是否有来自 OSWorld、Windows Agent Arena、macOSWorld 或 ScienceBoard 元数据的任务，也没有报告重叠检查。如果有，迁移结果会比论文的表述更接近分布内。
  * *几乎没有失败或恢复数据。* 渲染出的终止状态几乎都是成功（rollout 失败率 0-0.68%），且前置条件和阻塞字段在整个发布版本中都为零，因此数据呈现的是计划好的成功路径，而不是错误与恢复。
  * *最大领域出现退步。* Chrome 占样本的 44%，但 Chrome 任务在 OSWorld（39.0 → 26.0）和 Windows Agent Arena（11.2 → 0.0）上都下降；macOSWorld 的安全类任务也下降（20.7 → 17.2）。
  * *合成图像仍可被识别。* 分类器区分合成与真实截图的 AUC 约为 1.00，不过真实数据集之间也能互相区分（0.95-1.00）；DINOv2 显示 Ubuntu 上仍有明显视觉差距。
  * *一次训练、每个检查点一次评估*，没有方差。OSWorld 和 Windows Agent Arena 的分数在检查点之间有波动。

# Q9 贡献

* 一条"规划器加图像生成器"的流水线，无需部署软件即可生成 GUI 轨迹，包括以种子为条件的任务、闭环截图编辑、定位和基于 VLM 的转移过滤。
* 一个覆盖 Ubuntu、Windows、macOS 和 Chrome 的 79,266 个带定位单步样本的数据集，并分析了视觉对齐、覆盖率以及按动作类型量化的转移错误率。
* 证据表明，用这类数据微调能提升一个 35B MoE 智能体在四个真实环境基准和一个专业界面定位基准上的表现，并胜过使用约四倍真实演示样本的训练。

# Q10 下一步

* **作者的计划：** 轨迹越长，生成误差可能越累积；用特定领域的交互数据训练图像生成器，为特定软件构建"垂直" GUI 世界模型。
* **对数据来源做消融（读者注）：** 比较用（a）仅带定位的种子截图、（b）完整生成轨迹、（c）保留 2-3% 不一致转移的轨迹进行训练，以衡量世界模型和过滤各自的贡献。
* **生成失败与恢复步骤（读者注）：** 目前规划器只写成功路径。让它写出错误动作及其可见后果、随后再纠正，可以检验合成数据能否也教会恢复——这正是长程和多应用任务所需要的。
* **报告与基准的重叠检查（读者注）：** 说明哪些任务（如果有）派生自评测基准的元数据，并在去除它们后重新评估。
* **与本仓库的关联（读者注）：** "规划器确定预期状态变化、生成器负责渲染、再逐步做字面意义上的前后一致性检查"这一分工，是合成智能体数据的通用模式；按动作类型测得的错误率（文本输入和拖拽远差于点击）指明了最需要这类检查的地方。
