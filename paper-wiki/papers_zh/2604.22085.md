> 论文:**Memanto: Typed Semantic Memory with Information-Theoretic Retrieval for Long-Horizon Agents**
> 论文链接:<https://arxiv.org/abs/2604.22085>
> 机构:Moorcheh.ai

# Q1 问题定义

* **输入 `X`**:一个 agent 持续写入的记忆流(事实、偏好、决策、承诺等 13 个类型化类别之一,通过 `/remember` 提交),以及评测时需要仅凭已积累记忆回答的自然语言问题。
* **输出 `Y`**:通过单次语义检索(`/recall`,或包装为 RAG 的 `/answer`)取回相关记忆,并据此让 LLM 生成答案,与基准的参考答案比对打分。
* **核心问题**:论文把 Mem0、Zep、Letta、A-MEM 等混合图+向量式 agent 记忆架构所背负的成本——写入时 LLM 介导的实体抽取、图 schema 维护、多查询检索流水线所累积的算力、延迟与运维复杂度——命名为"记忆税"(Memory Tax)。论文提出的问题是:这种复杂度对于取得有竞争力的基准准确率是否真的必要,还是一个高度优化、带类型化 schema 与冲突消解机制的纯向量后端就能在彻底消除写入延迟与多查询开销的同时,匹配甚至超过它。
* **范围**:在两个成熟的长对话记忆基准(LongMemEval-S、LoCoMo)上评测,并给出一套量化的四轴架构复杂度评分与美元成本对比;论文明确未测试非对话式的 agentic 工作流(研究 agent、代码生成、多 agent 协作),也未直接对冲突消解本身做基准测试。

# Q2 问题的新颖性

论文并不声称首创类型化记忆(它明确承认是在延伸 ENGRAM 关于类型分离优于无差别存储的发现,只是把类别从更少扩展到 13 个)、无知识图谱的 agent 记忆(Merrill 等人的《Evaluating memory structure in LLM agents》已表明简单检索可以超过更精巧的层级结构),或"高召回优于高精度"的原则(LongMemEval 论文自身也报告过在 GPT-4o 上超过 2 万 token 检索量后准确率仍在提升)。其具体新颖之处有三:(1) 把检索后端建立在一个专有的"信息论搜索"(Information Theoretic Search)引擎(Moorcheh)之上,用一种确定性、免索引的二值化表示取代 HNSW 加余弦相似度,从根本上消除让其他系统写入变为同步、多秒级操作的索引构建延迟;(2) 把"记忆税"形式化为一个具名的四轴复杂度评分(是否需要图数据库/写入时是否调用 LLM/是否多查询检索/是否递归查询),并具体针对 Mem0、Mem0-graph 与 Zep 量化到毫秒与美元层面,而不只是报告准确率差值;(3) 其六条生产级设计准则部分来自一场自陈的"与 Claude(Anthropic)的结构化对话"——论文要求该模型诊断自身记忆架构的局限,据称模型独立提出的七个缺口恰好映射到论文的 D1-D6 框架,即把一个前沿 LLM 当作需求引出的信息来源,而非只综合既有文献与部署反馈。

# Q3 科学假设

如果检索优先追求召回而非结构精度(给 LLM 一个宽泛的、按阈值门控的候选集,而非窄 top-k 或预先计算好的图遍历),并把这种高召回与一个 13 类的类型化 schema、自动冲突检测、以及非破坏性的时间版本控制相结合——全部建立在一个零 LLM 介导写入、确定性单查询的向量后端之上——那么所得系统应能在 LongMemEval 与 LoCoMo 上匹配甚至超过混合图+向量架构的基准准确率,同时消除写入延迟、多查询检索成本与图基础设施开销。论文进一步把"检索召回优先于结构精细化"当作一条设计原则而非仅是观察到的结果,预测它将主导 prompt 工程与推理模型选择,成为 agent 记忆准确率的首要杠杆。

# Q4 相关工作与关键人物

* **混合图+向量记忆系统(直接竞品)。** Mem0(用户/会话/agent 三层结构,LLM 工具调用做 ADD/UPDATE/DELETE/NOOP 决策,含一个 Neo4j 图变体——其自身消融实验显示图结构仅带来约 2% 的准确率提升,Memanto 引用这一结果支持自己的"无图"论点);Zep/Graphiti([Zep](../papers/2501.13956.md),双时态知识图谱,论文肯定其企业级审计场景但批评其同步、多秒级的抽取流水线);Letta/MemGPT(操作系统式虚拟内存分页,依赖递归摘要);A-MEM(卡片盒式互联笔记,每次写入需要一次完整推理);Hindsight(唯一在原始准确率上超过 Memanto 的系统——91.4%/89.6%——但代价是论文自定义复杂度评分的最高值 4/4,依赖并行多查询检索加反思环节;Memanto 复用其答案生成与判官 prompt 以保证评测口径一致)。
* **类型化与认知科学基础。** ENGRAM(类型化记忆编排的直接前作,论文称其为 schema 设计的直接动机);Tulving 的情景/语义/程序记忆三分法;Baddeley 工作记忆模型(与 RAG 组件做了较松散的类比);MacPherson 等人的立场论文,主张情景记忆是长期 LLM agent 缺失的一环。
* **长上下文与检索瓶颈文献。** 经典 RAG(Lewis et al. 2020);作为 Memanto 所替代的主流范式的 HNSW 近似最近邻搜索;Liu 等人的"Lost in the Middle"(被用来支持 Memanto 的高召回立场,论证失败模式取决于信息的位置而非检索量);HippoRAG、RAPTOR、REPLUG 作为层级式/图式长程检索的替代架构。
* **评测基准与第三方批评。** LongMemEval 与 LoCoMo(本文的两个评测集);MemoryAgentBench(被引用作为冲突消解尚未解决的独立证据——"所有被评测方法在多跳冲突场景下均失败"——用来为 Memanto 的冲突消解功能背书,但并未直接对其做基准测试);Merrill 等人质疑随着模型原生上下文窗口增长,现有基准是否仍能奖励真正的结构化记忆收益。
* **关键人物与机构。** 六位作者均隶属 Moorcheh.ai(机构标注为 "moorcheh"),即 Memanto 检索后端所依赖的专有信息论搜索引擎的开发公司;本文是一份厂商技术报告,而非独立的第三方学术评测。提交于 2026 年 4 月 27 日(arXiv v1)。

# Q5 核心解法

1. **以 Moorcheh 信息论搜索(ITS)引擎为唯一后端。** 三项算法创新取代 HNSW 加余弦范式:最大信息二值化(MIB)把高维浮点嵌入压缩 32 倍,且未测得检索相关信号的损失;高效距离度量(EDM)按候选片段能在多大程度上降低对查询的不确定性来打分,而非按几何邻近度;信息论评分(ITS)给出一个归一化到 [0,1] 的确定性相关度分数,支持基于阈值的确定性检索(同一查询总是返回同一结果),不同于 ANN 依赖索引状态、带抖动的检索。这使得索引构建被彻底消除,写入即可立即被检索到。
2. **六条设计准则(D1-D6)作为约束而非仅是分类。** 可查询而非被动注入(agent 按需拉取相关记忆,而不是在对话开始时收到一份静态上下文);具备时间感知与衰减;置信度与出处追踪;类型化与层级化存储;冲突感知(标记而非静默覆盖);零开销写入(写入时无索引延迟、无强制 LLM 抽取、无图构建)。D2 直接对应 LongMemEval 的知识更新与时间推理类别;D5 针对论文命名的"约束漂移"(constraint drift)失效模式——未解决的矛盾累积导致的渐进性不连贯。
3. **13 类类型化记忆 schema**(事实、偏好、决策、承诺、目标、事件、指令、关系、情境、经验教训、观察、错误、制品),每类都有自己隐含的优先级/衰减权重,支持按类型过滤检索,避免结果集被无关类别污染。
4. **内置冲突消解。** 新写入的记忆会与同命名空间内同类型的既有记忆做语义相似度比对(可配置阈值);一旦检测到冲突,系统给 agent 呈现三种处理方式——替代(supersede)、保留(retain)、或标注(annotate,两者并存并打上冲突标记),而非由系统自行静默决定。
5. **非破坏性时间版本控制。** 三种查询模式(某时刻状态查询、变更区间查询、仅当前有效查询);被替代的条目会被标记但仍然保留,支持面向合规场景的完整审计轨迹重建。
6. **三端点 FastAPI 服务**(`/remember`、`/recall`、`/answer`),按 agent 做命名空间隔离,并以六小时会话窗口做分组——该窗口只用于分组,并不限制跨会话检索,同一命名空间内的全部记忆始终可被检索。
7. **五阶段渐进式消融方法论**,依次隔离每个架构杠杆(检索上限、相似度阈值、prompt 设计、推理模型)相对上一阶段的增量,而不是只报告一个端到端总分——这是论文用因果分解而非单一消融表来支撑其"召回优先"论点的选择。

# Q6 实验设计

**基准。** LongMemEval-S(500 道人工精选问题,涵盖六个类别——用户信息、助手响应、偏好、知识更新、时间推理、多会话推理——嵌入约 115K token、约 50 个会话的对话中,全程用 Claude Sonnet 4 作 LLM 判官)。LoCoMo(四个推理类别——单跳、多跳、开放域、时间——对话平均 35 个会话、300 轮、约 9K token)。两个基准的答案生成与判官 prompt 均改编自 Hindsight 仓库,专门用来缓解两类已知的评测伪影:对模糊问题的拒答,以及判官对语义正确但字面表述不同答案的僵化拒绝。

**五阶段渐进式消融(LongMemEval / LoCoMo 准确率,累计变化):**
1. 朴素基线(k=10,阈值=0.15,Claude Sonnet 4):56.6% / 76.2%。
2. 召回扩展(k=40,阈值=0.10):77.0%(+20.4 个百分点)/ 82.8%(+6.6 个百分点)——五个阶段中单次增益最大的一步。
3. Prompt 优化(采用 Hindsight 衍生 prompt,检索参数不变):79.2%(+2.2 个百分点)/ 82.9%(+0.1 个百分点)——增益微弱。
4. 最大召回(动态扩展到最多 k=100,按 ITS 阈值门控,阈值=0.05):85.0%(+5.8 个百分点)/ 86.3%(+3.4 个百分点)。
5. 推理模型升级(Claude Sonnet 4 → Gemini 3,为与竞品所用推理模型对齐):最终 89.8% / 87.1%(LongMemEval 上 +4.8 个百分点)。

**最终分类别结果(第 5 阶段)。** LongMemEval:单会话-助手 100.0%,单会话-用户 95.7%,单会话-偏好 93.3%,知识更新 93.6%,时间推理 88.0%,多会话(最低)81.2%。LoCoMo:开放域 92.4%,时间 85.4%,单跳 78.7%,多跳(最低)70.8%。

**对比结果。** 与其他系统公开报告的数字相比(并非在 Memanto 自身框架下复现):Hindsight 在原始准确率上领先(LoCoMo 89.6% / LongMemEval 91.4%),但代价是论文自定义复杂度评分的最高值 4/4(无图,但依赖并行多查询检索加反思);Memanto 领先所有纯向量系统,在 LongMemEval 上领先 Mem0 22.9 个百分点、在 LoCoMo 上领先 20.2 个百分点,并直接超过 Zep(71.2%/75.1%)与 Letta(LoCoMo 74.0%)。

**记忆税量化。** Memanto:每次写入 0 次 LLM 调用,每次检索 1 次,写入延迟低于 10ms,空闲成本为零。Mem0:1 次写入调用,约 500ms 写入延迟。Mem0-graph:≥2 次调用,约 2 秒写入延迟,需要 Neo4j。Zep:≥2 次调用,约 3 秒写入延迟,需要独立的图存储。按每日 1 万次操作估算日成本:Memanto 0.50 美元,对比 Mem0-graph 2.32 美元、Zep 1.70 美元;相对 Mem0-graph,论文报告每个 agent 每年可节省约 662 美元,且随 agent 舰队规模复合放大。

# Q7 数据与代码

论文未贡献新基准;LongMemEval 与 LoCoMo 均为已有公开数据集,按标准切分直接使用。Memanto 本身以 pip 包形式发布(`pip install memanto`,全部评测均基于 2.1.4 版本),代码见 [github.com/moorcheh-ai/memanto](https://github.com/moorcheh-ai/memanto)(撰写本笔记时据 HF 元数据有 2,051 个 star),项目主页为 [memanto.ai](https://memanto.ai/)。底层 Moorcheh ITS 引擎是一个专有云服务(通过 SDK/API key 访问),并非可本地运行的开源组件;其自身的检索质量基准(MAIR:64-74% NDCG@10,9.6ms 延迟,2,000+ QPS,相对 Pinecone+Cohere 提速 6.6 倍)报告于另一篇作者高度重叠的自撰论文(arXiv:2601.11557)中,本笔记未独立阅读该文。

# Q8 证据质量

本笔记基于通过 `hf papers read` 抓取的 arXiv HTML 全文(全部章节与十张表格)以及 `hf papers info` 元数据撰写。这是厂商(Moorcheh.ai)针对自家商业产品的技术报告,而非独立的第三方评测——全部作者均隶属于被评测引擎与产品所在的公司。主对比表(表 IX)中所有竞品数字均取自"其各自发表的论文或官方基准报告",而非在统一框架下复现,因此各行之间 LLM 判官、prompt 集合与具体基准子集的差异并未被完全控制;论文自身在第 5 阶段明确把推理模型升级到 Gemini 3,"以便与领先竞品对齐",这本身就承认了推理模型能力的差异、而非仅仅是架构差异,在所报告的差距中占有一部分。论文对两处证据缺口保持坦诚,值得单独指出:(1) 它直接声明"LongMemEval 与 LoCoMo 均未系统性测试矛盾记忆"(第 V-C 节),意味着冲突消解——论文引言中声称的四项贡献之一——在本文中没有任何量化的基准评测,其正当性依赖的是第三方基准(MemoryAgentBench)证明该问题在别处普遍未解决,而非对 Memanto 自身冲突消解准确率的实测。(2) Moorcheh ITS 引擎的核心检索质量论断(32 倍压缩且"未测得损失"、确定性精确匹配检索、MAIR 基准数字)均继承自另一篇本笔记未独立阅读的自撰引擎论文,而非在本文中重新推导或独立验证。论文还自陈基准存在标签噪声(约 5% 的 LongMemEval 问题与 6-7% 的 LoCoMo 问题存在模糊或无法验证的参考答案),并将其视为与架构无关的准确率天花板。

# Q9 主要贡献

1. 一套面向生产环境的纯向量 agent 记忆架构——13 类类型化 schema 加内置冲突消解与时间版本控制——论文主张它在无需知识图谱、多查询检索或 LLM 介导写入的情况下,匹配甚至超过混合图+向量架构的准确率。
2. 一套五阶段渐进式消融,因果地分解了准确率增益的来源(检索上限调优、相似度阈值校准、prompt 优化、推理模型选择),而非只报告单一端到端数字,最终达到 LongMemEval 89.8% / LoCoMo 87.1%——纯向量系统中的最优结果,领先 Mem0 20-23 个百分点。
3. 一套形式化的四轴"记忆税"复杂度评分(是否需要图数据库/写入时是否调用 LLM/是否多查询检索/是否递归查询),以及针对 Mem0、Mem0-graph 与 Zep 的量化运维成本对比(写入延迟、单次操作 LLM 调用数、空闲成本、估算美元成本)。
4. 六条生产级记忆设计准则(D1-D6),部分来自认知科学文献,部分来自一场自陈的需求引出对话——要求 Claude 诊断自身记忆架构的缺口。
5. 一项经验性主张:消融中单次增益最大的一步出现在召回扩展阶段(k=10→40 带来 +20.4 个百分点,而 prompt 优化只贡献 +2.2 个百分点),据此论证检索召回——而非架构或结构上的精巧程度——是 agent 记忆准确率的首要杠杆,重新定位了图式精细检索工程(图遍历、多跳冲突消解、递归查询分解)可能是在解决错误的问题,因为现代 LLM 本身就具备强大的上下文内过滤能力。

# Q10 下一步

论文自陈的局限:基准范围局限于对话场景,非对话式 agentic 工作流(研究 agent、代码生成、多 agent 协作)未被测试;两个基准都可能正在接近饱和,因为竞品准确率不断逼近其自身 5-7% 标签噪声所隐含的天花板,这促使论文呼吁开发更有针对性的评测方案(尤其是针对冲突消解、多 agent 协作与非对话任务);最终结果部分依赖推理模型能力(Gemini 3 贡献了 +4.8 个百分点),论文预测随着基础模型能力提升,这种依赖会加深,使检索质量成为相对更重要的差异化因素;尽管底层引擎已在别处报告过 1000 万+文档、2,000+ QPS 的验证,但针对 Memanto 本身、面向大量并发 agent 的大规模评测仍是未来工作;跨命名空间的多 agent 共享记忆(目前按设计相互隔离)正在积极开发中。

除论文自身框架之外,有两点值得向评估本笔记证据基础的读者指出。第一,冲突消解——引言中声称的四项贡献之一——只有一个说明性示例和一条第三方引用作为支撑;论文没有报告 Memanto 自身的冲突检测在任何基准上的正确率、误报率或漏报率。第二,由于 Memanto 在架构上是叠加在一个封闭、专有检索引擎之上的类型化 schema 加冲突消解层,读者无法把报告的准确率分别归因于 Memanto 自身的类型/冲突/版本控制设计与 Moorcheh ITS 引擎本身的检索质量——论文的消融实验在固定这个后端的前提下调整检索参数(k、阈值),但并未在保持 schema 与冲突消解逻辑不变的情况下,把 ITS 引擎替换为另一个可替代的向量存储做对比。

* [Agent memory](../topics/agent-memory.md) - 对该主题"记忆管理的基本单元是什么"这一问题给出第五种架构答案:不是双时态图(Zep)、对自然语言事实的抽取/更新决策(Mem0)、跨基底的可调度资源(MemOS)、还是 MemCell/MemScene 组成的生命周期(EverMemOS),Memanto 的答案是一条经类型化、经冲突校验的向量记录,通过一次确定性查询取回——并主张一旦检索本身足够精准、足够高召回,其他系统所添加的整个图层都并非必要。
* [Mem0](../papers/2504.19413.md) - Memanto 最直接的量化对比对象:它复用 Mem0 自身的消融发现(图结构相对向量结构仅带来约 2% 的准确率提升)作为支持自身"无图"论点的证据,随后报告在 LongMemEval 与 LoCoMo 上均领先 Mem0 与 Mem0-graph 20 个百分点以上,同时写入时的 LLM 调用次数为零,对比 Mem0 的一次(向量版)或两次以上(图版)。
* [Zep](../papers/2501.13956.md) - Memanto"记忆税"框架最具体的对比对象:按 Memanto 的核算,Zep 的双时态 Graphiti 架构每次写入需要 ≥2 次 LLM 调用、约 3 秒,而 Memanto 做到零 LLM 调用、写入延迟低于 10ms,同时在两个基准上都报告了更高的准确率(87.1%/89.8% 对 75.1%/71.2%)。
* [LongMemEval](../concepts/longmemeval.md) - Memanto 的两个评测基准之一;论文的 D2(时间感知)设计准则被明确对应到该基准的知识更新与时间推理类别,消融第 2 阶段(召回扩展)也直接针对该基准自身的发现——多会话问题需要综合分布在互不相交会话中的事实。
* [LoCoMo](../concepts/locomo.md) - Memanto 的第二个评测基准,作为 LongMemEval(约 115K token)之外一个更短(约 9K token)、互补的对话连贯性与多跳推理深度测试。
