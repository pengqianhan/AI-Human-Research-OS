> 论文:**VoiceMem: Streaming Dual-Brain Memory for Real-Time Interaction**
> 论文链接:<https://arxiv.org/abs/2608.26005>
> 机构:南洋理工大学 / 新加坡国立大学 / 清华大学 / 香港中文大学 / Open Interaction Lab

# Q1 问题定义

* **输入 `X`**:与一个双工/流式语音语言模型(SLM)之间正在进行的语音对话——用户话语逐轮到达,系统必须从中增量提取事实、人设特征与情绪上下文;可选地还包括携带说话人身份、副语言线索与环境声音的原始音频。
* **输出 `Y`**:在每一轮对话中,给出一个稠密(top-5)的检索记忆集合——既包含事实性内容,也包含情感/人设内容——用于条件化 SLM 的回复,且必须在语音活动检测器(VAD)判定回复必须开始之前那约 400-500 毫秒的静默窗口内完成,从而不给对话带来任何可感知的延迟。
* **核心问题**:现有记忆引擎(Mem0、Zep 等)是为文本 agent 设计的:它们用 2-3 秒检索出多达 top-100 的候选项,而情绪(如果考虑的话)通常只是叠加在单一事实存储之上的一个重加权项。实时语音交互把这两个约束都反转了过来——语音模型只能消费寥寥数条检索结果,而检索预算大约只有 400 毫秒而非数秒——同时还需要一个*独立的*、持久的用户人设与情绪模型,而不仅仅是用户说了什么。
* **范围**:论文提出的不只是一个架构(VoiceMem),而是一整套配套体系——通过蒸馏训练具备记忆能力的 SLM、一个面向语音助手记忆的新基准,以及一个后端无关的部署设计——而非仅仅是一个孤立评测的检索算法。

# Q2 问题的新颖性

论文提出三个此前没有系统同时解决的障碍。**(O1)信息与情感的统一架构**:通用记忆引擎(Mem0、Zep、LangMem)与 agentic 记忆系统(A-MEM、MemoryOS)以信息为中心;情感感知检索方法(Emotional RAG、KEEM)把情感相似度作为叠加在同一次检索之上的重加权项,而非把情感维护为自身独立演化的结构。**(O2)零延迟下的高信息密度**:传统记忆流水线需要 2-3 秒,且返回多达 top-100 条结果,这既违反了约 500 毫秒的 VAD 轮转预算,又超出了语音模型有限上下文能真正消化的量——面向语音的记忆系统必须在 top-5 就达到高准确率,而非 top-100。**(O3)基础设施与可演化性**:当前 SLM 完全无法接受音频与记忆的联合输入(没有任何现有语音模型具备显式的记忆访问能力),而底层记忆引擎的技术格局又变化很快,因此语音记忆系统需要一个后端无关的设计,而不是与某一个引擎强绑定。

论文将自身置于三条前作脉络的对立面:记忆引擎(Mem0、Zep、LangMem)与 agent 记忆(A-MEM、MemoryOS、MemOS)是纯文本、且不考虑延迟的;个人记忆系统(MemoryBank、EverMemOS)增加了纵向结构但依然以文本为中心;情感感知 RAG(Emotional RAG、KEEM)把情感折叠进单一的检索打分,而非将其建模为与特定人物、事件、实体绑定、独立维护的并行结构。

# Q3 科学假设

如果把对话记忆拆分为两个并行、彼此交叉链接的结构——一个"左脑",通过位于可替换后端引擎之上的粗粒度 schema/细粒度实体索引来组织事实性内容;一个"右脑",通过独立节点(人格特质层面)与跨实体节点(情境层面)维护人设与情绪,分别由短时程(逐轮)与长时程(逐会话)归因机制更新——并且把针对这两个结构的检索重构为对齐语音轮次各阶段(倾听、语音尾段、预判、搜索)的四阶段流式流水线,那么由此产生的系统就能够:(i) 在比该领域惯常的 top-100 设置低一个数量级的 top-5 预算下,达到或超过文本 agent 记忆的准确率;(ii) 因为把情绪维护为自身独立结构而非检索重加权项,从而在人设/情感建模上达到业界领先水平;(iii) 不给实时语音对话带来任何可感知的延迟。

# Q4 相关工作与关键人物

* **记忆引擎**(本知识库已有的基线):[Mem0](2504.19413.md)(增量式 ADD/UPDATE/DELETE/NOOP 抽取)与 [Zep](2501.13956.md)(双时态知识图谱),二者既被直接用作评测基线,后续又都被用作 VoiceMem 的可替换后端。
* **Agent / 个人记忆**:A-MEM、MemoryOS、[MemOS](2507.03724.md)、MemoryBank、[EverMemOS](2601.02163.md)——均为纵向或操作系统式的记忆结构,且都是纯文本的。
* **情感感知检索**:Emotional RAG 与 KEEM 把情感相似度折叠进与语义相似度相同的排序分数,而非维护一个独立的情感结构——这正是 VoiceMem 右脑所针对的空白。
* **语音/双工语言模型**:论文把自己置于一系列流式 SLM(Mini-Omni、Mini-Omni2、Moshi、SALMONN-omni、Audio-Interaction)以及"边听边想"系统(Mind-Paced Speaking、SHANKS、Chronological Thinking、Mini-Omni-Reasoner)的脉络之中,指出记忆在所有这些系统里都被排除在实时交互回路之外。
* **关键人物**:第一作者谢志飞(Zhifei Xie,同时也是 Mini-Omni 系列与 Audio Interaction Model 的作者)与资深作者严水城(Shuicheng Yan);作者机构横跨南洋理工大学、新加坡国立大学、清华大学、香港中文大学与 Open Interaction Lab。

# Q5 核心解法

1. **左脑——位于可替换后端之上的 schema/实体索引。** 一个两级*schema → 实体 → 记忆项*索引位于原始后端存储(当前实现中为 Mem0)之上:schema 负责粗粒度路由,实体定位具体的人物/事件/概念,通过一跳强/弱边把流式匹配到的查询扩展为一个被收窄的候选池,再交给后端检索——后端只在这个预先收窄的池子内排序,而非整个记忆库。
2. **簇涌现机制。** 不使用固定或按规则拆分的 schema,而是让子簇从重复的检索共现模式中"涌现":对一个连通实体子图计算查询一致性得分 ρ(H),识别出总是被一起检索的实体群,再由一个 LLM 判官在把该子图提升为新 schema 之前校验其相关性/重要性/完整性(算法 1)——使存储的组织方式跟随实际使用模式,而非预设的分类体系。
3. **右脑——独立节点与跨实体节点。** 独立节点编码稳定的、纵向的用户特质;跨实体节点编码绑定到某个具体左脑实体的情境化情绪(这段情绪关乎谁或什么)。短时程归因在每一轮根据情感估计器的输出更新图结构;长时程归因在会话结束后,把整段(话语,情绪)序列汇总为稳定的独立节点。
4. **隐藏在 VAD 窗口内的四阶段流式检索。** 倾听/语音尾段(0-200ms)在用户说话的同时实时运行 ASR 与实体/schema 匹配;预判阶段(200-400ms,一旦静默达到 200ms 即触发)对查询做 embedding 并扩展两个脑的候选图;搜索阶段(400-500ms)运行后端检索并合并结果。实测端到端检索耗时为 134ms,在标准 500ms VAD 阈值强制回复之前,留有充分余量。
5. **多模态扩展。** 除文本外,VoiceMem 还可以把音频作为说话人声纹、声学 embedding 或原始波形保留下来并挂载到对应的实体节点上,从而支持副语言与环境(非言语)记忆的召回(例如"昨天咖啡馆里放的是什么歌")。
6. **解耦的基础设施。** 两项补充设计使系统可部署且面向未来:(a) 具备记忆能力的 SLM 训练——通过黑盒在线策略蒸馏("SLM-verified OPD"),把 Qwen2.5-Omni、Qwen3-Omni 与 Step-Audio2-Mini 这些原本"语音输入/文本输出"的模型,转变为具备显式记忆访问能力的模型,蒸馏教师为更强的闭源模型(Qwen3.5-Omni、Step-Audio2),训练通过记忆世界构建、在线纠错与事后校验的循环完成;(b) 严格解耦的上层(路由、双脑组织、流式逻辑)与下层(后端引擎,当前为 Mem0)架构,使索引与流式逻辑无需重新设计即可迁移到未来任何后端。

# Q6 实验设计

**基准与基线。** 三个系列:信息记忆(LoCoMo、LongMemEval-S、Memora)、人设记忆(ES-MemEval、PersonaMem、PersonaLens),以及论文自建的面向语音记忆的 ChatMem-Bench(316 道问题,横跨 53 小时/15,314 轮音频,4 个维度 × 14 个细粒度类别:信息、人设、情感归因、副语言与环境)。十个基线分四组:Full-Context(参照);Mem0/Zep/LangMem(记忆引擎);A-MEM/MemoryOS/MemOS(agent 记忆);MemoryBank/EverMemOS/Emotional RAG(个人记忆)。所有基线均使用 GPT-4o-mini + text-embedding-3-small、温度为 0;VoiceMem 在 K ∈ {1,3,5,10,30,100} 上扫描,默认工作点为 K=5。

**信息记忆。** VoiceMem 在 LoCoMo/LongMemEval/Memora 各子类别上平均达到 76.39,超过其自身后端 Mem0(52.27)达 +24.12,超过 Full-Context(60.49)达 +15.90;差距在时间推理上最大(+54.9),在更新追踪上最小(+7.4,该类问题只需最新一条记忆即可作答)。

**人设记忆。** 以 GPT-4o-mini 作为回复模型时 VoiceMem 达到 74.16(用论文自己微调的模型则为 76.56),超过最强基线 MemOS(72.27)达 +1.89。在 ES-MemEval 上,Full-Context 在冲突检测(12.10)与用户建模(21.70)两项上反而不如基于检索的记忆方法(VoiceMem 为 69.10/74.00)——这说明把原始文字记录直接放进上下文并不足以支撑情感归因。

**ChatMem-Bench(音频)。** VoiceMem 在 14 个类别中的 11 个上领先,平均分为 68.73。差距在副语言与环境类别上最大,因为纯文字记录在这里完全不携带证据:纯文本基线在三个声学类别上得分仅为 3.23-26.92,而 VoiceMem 达到 45.16-53.84。情感归因是个例外——文本基线在这里依然具有竞争力,因为遣词造句本身已经携带了大部分情感信号,VoiceMem 在音频上的额外收益则集中在依恋导向决策与情感感知措辞上。

**成本/延迟(图 5-6)。** 在 K=5 时,VoiceMem 用 430 个记忆 token 与 134ms 检索耗时,在 LoCoMo 上达到 91.2 的准确率;最强基线 EverMemOS 用 1,899 个 token 达到 83.13(即 VoiceMem 以 4.4 倍更少的 token 换来 +8.1 分的优势)。检索延迟在 K=3 到 K=100 之间基本保持在 134ms 不变,因为 schema 路由在排序之前就已经限定了候选池大小。在 LoCoMo 上对 K 做扫描显示,VoiceMem 的优势在预算最紧张时最大(K=1 时超过 Mem0 达 +26.5、超过 EverMemOS 达 +11.8),并在 K=5 之后趋于平坦(K=10 仅再提升 1.3 分,K=100 用 8 倍的 token 也仅再提升 2.3 分)。

**消融实验(图 7,四个数据集:LoCoMo/ES-MemEval/ChatMem-Bench/Memora)。** 去掉上层 schema/实体索引在所有数据集上损失都最大(-9.9/-5.3/-6.7/-4.4);去掉右脑次之(-6.3/-4.3/-5.4/-4.4);涌现式聚类(-5.5/-2.0/-3.4/-0.2)与双时程更新(-5.4/-2.0/-3.2/-1.4)在会话最长的 LoCoMo 上影响最大;联合(取并集)检索的损失最小(-2.6/-3.1/-2.7/-0.4),即便没有更精细的融合方式,这也是一个可行的退路。

**存储结构(图 8)。** 左脑存储共 510 项,分布在六个预设槽位之外,还有两个从语义图中*涌现*出来的槽位(从未被预设)覆盖了 254 项——占存储总量的 49.8%——且每个都横跨多个预设类别(例如一个"宠物与户外"簇,48% 来自日常生活、27% 来自健康、17% 来自人际关系),这正是为什么在会话最长的 LoCoMo 上禁用涌现机制损失最大。右脑存储共 251 项,分布在四个模块中,通过 280 条边与左脑实体交叉链接。

**后端迁移(表 4,RQ4)。** 把 VoiceMem 的上层索引应用到三个不同后端——不做任何阈值重新调优——分别提升了 Mem0(61.68→91.20,+29.52)、LangMem(56.18→71.94,+15.76)与 Zep(62.93→85.85,+22.92);平均提升 +22.73。LangMem 与 Mem0 在裸后端上相差不到 5.50 分,但加上索引之后差距拉大到 19.26 分,说明后端本身的质量依然限制着索引能恢复多少准确率。

**次级消融(附录 B)。** 把一跳邻接 schema 压缩为一句话描述,与把它展开为与 top-K 竞争的记忆项相比,在 LoCoMo 上几乎没有差别(91.2 对 91.10),但压缩在 ES-MemEval 上更优(+2.76),且候选池更小(144.1 对 165.7 项)——论文选择压缩是因为它能限定池子大小,而非因为准确率更高。在 ES-MemEval P1(拆分次数相匹配)上比较簇维护策略,涌现机制(74.40)优于拆分次数相同的随机拆分对照组(72.40,2.00 分的差距可归因于"拆对了地方"而非"拆分本身"),也优于朴素的规模阈值拆分器(71.61)——后者的表现甚至不如完全不拆分(静态基线:72.60)。

# Q7 数据与代码

# Q9 主要贡献

1. 一种把事实性与人设/情感记忆维护为两个并行、交叉链接结构的记忆架构,而非把情感折叠进单一的检索打分——按论文自身在相关工作部分的表述,这是该领域第一个把信息记忆与情感记忆同等结构化、而非把情感当作重加权项处理的系统。
2. 一个 schema/实体索引加上由查询一致性驱动的簇涌现机制,能在比文本 agent 记忆领域常见的 top-100 低一个数量级的 top-5 预算下达到业界领先准确率,检索延迟(134ms)在不同 K 值下保持平坦,且足够小,可以隐藏在标准 VAD 的轮转窗口之内。
3. 一个后端无关的两层设计,其上层索引在不重新调优阈值的情况下,把三种不同的记忆引擎(Mem0、LangMem、Zep)分别提升 15.8-29.5 分,把流式/路由方面的贡献与具体的底层存储解耦开来。
4. 一套 SLM 训练流水线(源自闭源教师模型的黑盒在线策略蒸馏),据作者所言由此产生了首批具备显式记忆访问能力的语音语言模型,同时发布了训练语料(ChatMem-400K)与评测基准(ChatMem-Bench),专门覆盖语音助手场景下的信息、人设、情感归因与副语言/环境记忆。
5. 在全部三个被评测系列上都取得领先——信息记忆(超过自身 Mem0 后端 +24.12)、人设记忆(超过 MemOS +1.89)、以及音频驱动的长时程记忆(在 ChatMem-Bench 14 个类别中的 11 个上领先,且增益最大的地方恰恰是文本基线完全无法接触到相应信号的地方)。

# Q10 下一步

论文明确表示,ChatMem-Bench 完整的构建与标注细节留待另一篇后续技术报告披露,因此仅凭本文,该基准尚不能被独立复现。所有基线(以及未经微调的 VoiceMem 版本)都通过 GPT-4o-mini 而非前沿闭源模型评测,这就留下一个开放问题:在更强的骨干模型下,报告的差距是否依然成立——这也是本知识库 [Agent memory](../topics/agent-memory.md) 主题一直在追踪的一个更普遍的开放问题。全文的评测都依赖 LLM 判官打分而非人工评分,论文并未针对人设/情感这类主观校准最重要的维度,单独用人工判断做验证。右脑人设图与黑盒 OPD 训练循环都依赖闭源教师模型(分别用于 LLM 判官校验与蒸馏教师),因此完整复现该流水线需要论文本身并未提供开源替代方案的 API 访问权限。论文自身的表述暗示了两个前进方向:把已经实现流式化的记忆*访问*流水线,进一步延伸到记忆*修订*与多模态(原生音频)输入的联合流式化上——当前 SLM 仍无法原生接受音频与记忆的联合输入(障碍 O3);以及把后端无关的索引适配到"参数化与潜在记忆机制"上,论文将其标注为一个正在浮现、但本文有意未与之绑定的方向。

本笔记在论文自身框架之外补充一条联系:VoiceMem 的消融结果显示,去掉上层索引造成的损失远大于去掉任何单一下游机制(涌现、双时程更新、联合检索)——也就是说,大部分准确率增益来自*在排序之前收窄候选范围*,而非把排序做得更好——这是本知识库 [Agent memory](../topics/agent-memory.md) 主题已经从 Zep、Mem0、MemOS 身上归纳出的同一条经验在语音场景下的一个实例:这些系统中占主导地位的设计杠杆,是检索*之前*施加的结构(双时态图边、ADD/UPDATE/DELETE 决策、schema 路由),而不是检索或排序步骤本身。
