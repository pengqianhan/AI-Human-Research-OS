# Q1 问题定义

* **输入（X）：** 一个基础策略 P₀（大语言模型）、一个种子 harness H₀（决定模型看到什么、动作如何执行、得到什么反馈、何时结束一轮的代码与提示词）、一组软件工程训练任务 D（每个任务都有给出二值"是否解决"信号的可执行验证器），以及 harness 搜索预算 K。
* **输出（Y）：** 一对改进后的 harness 与策略 (H_t, P_t)，在留出基准上解决更多问题。
* **目标：** 在 D 上、按该组合采样轨迹得到的期望解决率 J(H, P)。
* **约束：** 在自我改进设定中，不允许更强的模型来提议 harness 修改，因此正在训练的策略本身也要充当提议者；harness 搜索与强化学习共用同一批训练任务；各候选 harness 下模型的采样参数固定不变。

# Q2 问题新颖性

两半各自都已有工作。Harness 优化固定模型，在提示词、工作流或智能体代码上搜索（Meta-Harness、Self-Harness、Task-CoEvolve、Evo2）；策略优化固定 harness，用可验证奖励训练模型（Orchard 配方中的 RLVR）。论文的论点是两者互相限制：为某个检查点调好的 harness 不再针对下一个检查点的失败，而强化学习只能从固定 harness 引出的轨迹中学习。联合方法也已存在，论文在两个维度上与之区分（其表 5）：WHALE 用冻结的外部提议者配合 SFT 更新策略，Evo2 为冻结的求解器训练一个单独的提议者，HASE 让自我提议的策略把 harness 编辑放进联合的强化学习动作空间。Self-HPO 的具体主张是：刚训练完的策略就是下一轮的 harness 提议者，下一轮的搜索集取自策略在强化学习中失败的任务，而不是一个固定集合。

# Q3 科学假设

如果 harness 搜索与策略训练交替进行——由当前策略针对自身失败提议 harness 修订，并从它在强化学习中没能解决的任务中抽取下一轮搜索集——那么两部分会互相弥补对方的局限。解决率应当在每一步都上升，在各部分预算对齐的情况下超过只优化 harness 或只优化策略的做法，并且联合收益大于两部分单独收益之和。论文还预期收益能迁移到 Python 训练集之外的语言和仓库，并同时体现为可靠性（pass@1）和能力边界（pass@k）的提升。

# Q4 相关工作与关键人物

* **Harness 优化。** 提示词与程序优化器（Pryzant 等人的自动提示词优化、DSPy、Promptbreeder、Yuksekgonul 等人的语言模型反馈反向传播、GEPA），工作流优化器（Automated Design of Agentic Systems、AFlow），以及依据执行证据修订 harness 的系统：Meta-Harness、Agentic Harness Engineering、Self-Harness、[AutoSaddler](../papers/2608.23041.md) 等；同组还引用了持续适应（[Harness²](../papers/2610.14224.md)）和通过搜索控制与模块化编辑提升泛化（[RRSI](../papers/2609.24972.md)）。
* **策略学习与自我改进。** STaR 式的过滤推理、迭代偏好训练、自博弈课程、演化环境（[EnvHarness](../papers/2608.19880.md)）、可执行 SWE 训练环境（SWE-Gym、R2E-Gym、SWE-smith）、SWE-RL，以及可验证奖励强化学习（GRPO、DeepSeek-R1，以及 Orchard——P 步沿用了它的 RLVR 配方和平衡自适应采样）。
* **Harness 与策略的联合演化。** WHALE、HarnessForge、Evo2、HASE（harness-aware self-evolving）、MetaRSI（在一个循环里完成数据生成、harness 编辑和训练），以及关于 harness 迁移和多 harness 训练的同期研究。
* **基准。** SWE-bench Verified（500 题）、SWE-bench Multilingual（300 题，九种非 Python 语言）和 SWE-bench Pro 的公开集（642 题）。
* **关键人物。** Zhepei Wei（弗吉尼亚大学，在微软研究院实习），以及 Wenlin Yao、Baolin Peng、Qianhui Wu、Hao Cheng、Jianfeng Gao（微软研究院）、Danqing Wang（卡内基梅隆大学）和 Yu Meng（弗吉尼亚大学）。Peng、Yao、Wu、Cheng、Gao 也是 Orchard 的作者。可能的批评者：Meta-Harness 和 Self-Harness 的作者（他们的方法是只优化 harness 的基线），以及 WHALE、Evo2、HASE 的作者（他们的联合方法只在概念上被比较）。

# Q5 关键解决思路

**交替进行，并由策略提议。** 第 t 轮分两步。在 **H 步**中，策略 P_t 被冻结并身兼两职：求解者和提议者。当前组合先在搜索集 S_t 上运行；提议者作为一个编码智能体，可以通过 shell 访问父 harness、它在搜索集上的轨迹、搜索集任务的参考修复（reference fix）、先前候选的输出以及它自己记录的笔记，并写出修订后的 harness。依次提出 K = 6 个候选，每个都在当前最佳 harness 的基础上、利用所有已评估 harness 及其轨迹进行修订，S_t 上得分最高者成为 H_{t+1}。在 **P 步**中，H_{t+1} 被冻结，P_t 在其下用强化学习在全部 D 上训练，得到 P_{t+1}。

**搜索集跟随策略变化。** S₀ 是随机抽取的 300 个训练任务。此后，S_{t+1} 是在 P 步的所有 rollout 中从未被解决过的任务，这样下一个 H 步看的是更新后策略在这些任务上的新失败，而不是第一个 harness 所针对的任务。当困难任务集在相邻两轮之间趋于稳定时循环停止；论文共运行了两轮。

**这里的 harness 是什么。** 一个候选就是种子 mini-SWE-agent 类的一个 Python 子类加上它的提示词模板。它可以重写智能体的 step，用来检查状态、在接受提交前返回反馈、替换提交的补丁，或在任意一步介入。外部提议者设定下第二个 H 步得到的 harness 保留了"查询—执行"循环，并增加了四项控制：接近步数或时间上限时发出警告并要求尽力提交；一次性的空补丁拦截，要求模型用 `git add -N` 暂存新文件；对第一次非空提交暂扣一次，要求模型对照仓库及其测试检查 API 名称和签名；以及在提交的补丁无法应用时，改为提交沙箱中的 git diff。

**强化学习细节。** GRPO 配合 Orchard 的平衡自适应采样（Balanced Adaptive Rollout，BAR）：每个任务采 8 条 rollout，从中留 4 条组成成功比例在 0.25 到 0.75 之间的组，凑够 32 组即得到 128 条轨迹的批次并做一次优化器更新。裁剪阈值 0.2/0.28，Adam 恒定学习率 10⁻⁶，无 KL 惩罚，每个 P 步 50 次更新。

# Q6 实验设计

* **设置。** 基础策略为 Qwen3.5-35B-A3B，种子 harness 为 mini-SWE-agent，训练任务 2,484 个，来自 SWE-rebench、SWE-rebench V2 和 Scale-SWE（仅 Python）；两轮，每个 H 步 K = 6 个候选，每个 P 步 50 次强化学习更新。强化学习和 SFT 在一台 8 卡 B200 节点上运行。
* **评测。** 在 SWE-bench Verified（分布内）以及 SWE-bench Multilingual 和 SWE-bench Pro（分布外）上的解决率，取三次运行的均值并给出标准差；步数上限 250，temperature 与 top-p 均为 0.95。
* **基线。** 自我改进设定：RLVR（只优化策略，使用种子 harness，相同的强化学习配置，每个 P 步 50 次更新）和 Self-Harness（只优化 harness，以基础策略为提议者，相同的搜索预算）。以 Opus 4.8 为外部模型的设定：用 Opus 4.8 已解决轨迹做 SFT（只优化策略）、以 Opus 4.8 为提议者的 Meta-Harness（只优化 harness），以及 HPO（Opus 4.8 提议，强化学习更新策略）。
* **消融。** 在 SWE-bench Verified 上以 HPO 为参照：P 步改用 SFT 或拒绝采样微调（RFT）代替强化学习、固定搜索集、改用策略自身作为提议者（即 Self-HPO）。
* **分析。** H₀-H₂ 与 P₀-P₂ 的 3×3 交叉评测；每题 8 次尝试得到 k = 1-8 的 pass@k；按基础模型成功率划分难度后的 pass@1；最后一个 P 步中零成功组的比例与 RLVR 对比；以及与 SWE-bench Verified 排行榜上 mini-SWE-agent 下前沿模型成绩的比较。

# Q7 数据集与代码

没有新数据集；训练任务沿用 Orchard 的做法，取自公开的 SWE-rebench、SWE-rebench V2 和 Scale-SWE。代码在 [MSR-Orchard/Self-HPO](https://github.com/MSR-Orchard/Self-HPO)（`hf papers info` 显示 5 星），另有 Hugging Face 组织页和项目博客；本笔记均未打开。附录给出了提议者的系统提示词、优化后 harness 相对种子的 diff，以及一个演化后的 harness 让同一策略改变结果的 SWE-bench 案例。

# Q8 证据质量

* **得到支持的结论。**
  * *两种设定下联合优化都胜过单边优化。* Self-HPO 在 Verified / Multilingual / Pro 上为 69.5 / 59.7 / 65.2（平均 64.8），RLVR 为 67.5 / 56.3 / 61.8（61.9），Self-Harness 为 65.2 / 54.3 / 60.7（60.1），基础模型为 61.0 / 54.2 / 58.3（57.8）。以 Opus 4.8 为提议者时，HPO 达到 71.6 / 61.4 / 66.0（66.3），Meta-Harness 为 69.1 / 56.5 / 64.8（63.5）。
  * *分布外收益。* 训练只用 Python 任务；在 Multilingual 上，Self-Harness 比基础模型只高 0.1 分，Self-HPO 高 5.5 分。
  * *每一步都有帮助。* 沿 Base-H₁-P₁-H₂-P₂ 序列，平均分每一步都上升；而 Self-Harness 再做一次只改 harness 的步骤后，Multilingual 从 55.0 降到 54.3。在 Verified 上的候选级曲线为 64.3（第一个 H 步）、67.8（P 步）、68.6（第二个 H 步）、69.5（第二个 P 步），而继续只搜索 harness 只到 65.2。
  * *消融。* P 步改用 SFT 得到 67.2，改用 RFT 得到 70.5，强化学习为 71.6；固定搜索集得到 70.1；自我提议得到 69.5。
  * *可靠性与能力边界。* pass@8 从 80.0% 升到 84.8%；pass@1 在中等难度任务上提升 17.2 分、简单任务 12.9 分、困难任务 6.1 分，但在基础模型总能解决的任务上下降 2.2 分。最后一个 P 步的最后十次更新中零成功组比例降到 6.5%，而 RLVR 最后 50 次更新中维持在 11-17%。
  * *外部提议者的知识通过 harness 传递效果更好。* Meta-Harness 在 Verified 上比用 Opus 4.8 轨迹做 SFT 高 4.1 分，平均高 8.9 分；SFT 在两个分布外基准上都低于基础模型。
* **比标题结论更弱或更窄的部分。**
  * *"超可加性"混入了相互适配。* 交叉评测（H₂ 配 P₀ 为 64.5，H₀ 配 P₂ 为 64.4，H₂ 配 P₂ 为 69.5）给出联合收益 8.5 分，而 3.5 + 3.4 = 6.9。但 P₂ 是在 H₁ 下训练的，H₂ 是为 P₁ 选出来的，所以"单独"收益衡量的是每个部分与一个并非为它调过的搭档组合时的表现；多出的 1.6 分也接近报告的标准差（0.9-1.5）（笔记作者的观察）。
  * *各方法的计算量不对等。* Self-HPO 同时花了 harness 搜索预算和强化学习预算，而每个单边基线只花其中一项，因此"联合胜过单独"同时也是"更多的总优化胜过更少的优化"（笔记作者的观察）。论文没有报告 harness 搜索的开销。
  * *提议者能看到参考修复。* H 步提议者可以看到搜索集任务的标准补丁；这些是训练任务，因此不构成测试泄漏，但"分析自身失败"的说法低估了它实际使用的信息（笔记作者根据附录 D 的观察）。
  * *选择噪声。* 每个候选在每个搜索任务上只跑一次，并保留六个中最好的那个；留出基准取三次运行的均值，这保证了最终数字的稳定，但不能保证选中的 harness 本身可靠。
  * *一个基础模型，两轮。* 所有结果都基于 Qwen3.5-35B-A3B；自我提议对更小的策略是否有效、第三轮是否仍有帮助，都没有测试。
  * *与前沿模型的比较跨来源。* 其表 4 中的排行榜数字来自 SWE-bench 网站在 mini-SWE-agent 下的结果，并非重跑；而 Self-HPO 的 69.5 用的是演化后的 harness。

# Q9 贡献

* 一个 harness 与策略共同演化的循环，其中正在训练的策略同时也是 harness 提议者，因此不需要更强的外部模型。
* 一个随策略移动、由失败驱动的搜索集：策略在强化学习中始终未能解决的任务成为下一轮的 harness 搜索集。
* 在三个 SWE-bench 变体上的证据：无论在自我改进设定还是外部提议者设定下，联合优化都胜过只做强化学习或只做 harness 搜索，从仅 Python 的训练迁移到分布外，并在 pass@1 和 pass@8 上都有提升。
* 一个具体的例子，说明编码智能体学到的 harness 修改长什么样：在预算耗尽和提交时刻加入运行时检查（空补丁拦截、API 检查、补丁回退），而不只是修改提示词。

# Q10 后续方向

* **衡量提议者本身，而不只是组合（笔记作者的建议）。** 这个循环的递归主张是：更好的策略也是更好的提议者。在求解者和搜索集相同的情况下，分别用 P₀ 和 P₂ 作为提议者运行 H 步，可以看出提议质量本身是否随轮次提高；现有的消融（Opus 4.8 对比自我提议）并不检验这一点。
* **计算量对等的基线（笔记作者的建议）。** 给 RLVR 增加更新次数，或给 Self-Harness 增加候选数，使其等于 Self-HPO 的总预算，以区分"交替"本身的价值和"更多优化"的价值。
* **用新鲜数据验证 harness 的选择（笔记作者的建议）。** [RRSI](../papers/2609.24972.md) 和 [Self-evolving Agent Harness](../papers/2610.18813.md) 综述都警告：在被搜索的任务上选出的 harness 可能过拟合。用困难任务中留出的一部分而不是 S_t 本身来选择 H_{t+1}，可以检验 Self-HPO 的搜索集是否需要这种保护。
* **SWE 之外（论文与笔记作者）。** 这一设置的强化学习奖励和 harness 打分都依赖二值的可执行验证器；在奖励由评分细则或评审模型给出的场景中——例如 [Harness²](../papers/2610.14224.md) 所用的专业类基准——交替方法是否仍然有效，尚无答案。
