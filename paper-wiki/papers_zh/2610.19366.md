# 一句话概要

能记住自己看到、听到、在屏幕上或房间里做过什么的智能体，要做两个决定：每段经历以什么形式保存（原始图像、特征向量、描述文字、图节点、隐藏状态、适配器），以及维护记忆的规则本身能否随使用而改变。这篇综述沿这两个选择整理了约三百个系统，并说明二者相互关联：保存形式决定了之后能否核查、修正或删除；而少数能从部署反馈中学习记忆规则的系统，全都把部分记忆保存为可编辑的文本或结构。适合为多模态或具身智能体设计记忆的人阅读，也适合需要判断某个"自演化记忆"说法是否只是普通记忆更新的人。

# 概览

**范围。** 记忆被定义为：由经历派生、在形成它的那一步之后仍然存在、并在之后影响推理、生成、规划或行动的状态，且至少有一种非文本模态参与其形成或使用。瞬时激活、一次性推理链和偶然出现在提示里的内容不算，除非被刻意持久化并复用。综述把记忆与*上下文*（模型当前看到的内容；检索出的图像两者都是）区分开，也与长上下文处理和上下文管理区分开。覆盖图像与文档、视频与视听流、音频与语音、GUI 交互，以及具身或 3D 环境。当前版本的分类体系包含 297 个记忆架构和 82 条基准记录。

**为什么多模态改变了问题。** 文本经历可以紧凑地存成 LLM 能直接读写的形式；一帧画面、一段声音或一个 3D 场景，往往无法无损地归约为单一表示。因此每种存储选择都在保真度、效率、可编辑性、源证据可恢复性和与下游模型的适配之间有所取舍。同一个实体还可能同时以原始媒体、特征、描述和世界状态记录的形式存在，于是维护时必须让多个相互关联的表示保持一致。

**生命周期。** 两个耦合阶段：*形成与表示*决定保留什么、如何切分成记忆单元（一张图、一个区域、一段剪辑、一个事件、一条物体轨迹、一个界面状态、一次转移、一条轨迹、一整个回合）以及以何种形式保存；*管理*决定记忆如何持续、变化、被访问和被使用。形成阶段丢掉的信息，任何访问机制都找不回来。

**定位。** 以往的智能体记忆综述按来源、表示、功能、时间范围或操作分类，多模态综述则按记忆类型、VLM 分类、架构、基准和应用分类。这篇以运行生命周期为分析单位：经历如何变成记忆，表示如何限制之后的检索、修订和核查，以及适应发生在哪里。

# 框架

| 轴 | 分支 | 保存什么 | 主要取舍 |
|---|---|---|---|
| 一、形成与表示 | 源证据与模态特定表示 | 保留的源证据（图像、裁剪区域、截图、视频帧、视听片段、带位姿的 RGB-D）；或模态原生编码与几何状态（视觉词元、patch 特征、体素地图） | 源证据可恢复、可核查但代价高；编码紧凑但有损，且绑定于兼容的模型接口 |
| | 跨表示的显式记忆 | 感知转文本记录（描述、事件、事实、画像、流程）；或空间、时间、跨模态结构化记忆（场景图、时间知识图谱、模式化记录） | 可逐条检查、搜索、编辑；写入时丢掉的细节无法恢复 |
| | 内化的潜在与参数记忆 | 持久潜在状态（隐藏状态、记忆词元、刻意保留的 KV 缓存）；或由经历条件化的参数（权重更新、按任务或按视频的适配器） | 与推理紧密结合；难以检查、编辑、溯源或跨模型迁移 |
| | 混合（一种组合，不是第四种类型） | 以上多种的组合，常为*源链接*式：抽象记录保留指向其来源观测的指针 | 既有高效抽象又能回到证据，前提是记录变化时链接仍然有效 |
| 二、记忆管理 | T1 静态 | 记忆形成一次后只读 | 稳定，不会被未经验证的写入污染；但保留了形成时的错误，且会过时 |
| | T2 动态 | 在部署期间固定的策略（启发式或事先训练）下改变记忆状态 | 更新可预测；策略无法从自身错误中学习 |
| | T3 自演化 | 反馈会持久地修改负责写入、维护或检索的策略 | 能适应部署环境；需要对策略变化做归因和验证 |

分类体系依靠两条规则。轴一按*最终交给推理器或策略的表示*分类，而不是按用作索引的东西。PixelRAG 用视觉嵌入给截图分块建索引，但交给 VLM 的是截图本身，所以属于源证据记忆。轴二把 T3 写作 M_{t+1} = U_{π_t}(M_t, x_t)、π_{t+1} = E(π_t, f_t)，其中 f_t 是任务结果、验证器判断或用户纠正。只要选择与更新机制不变，修改检索键、技能描述或使用统计仍属 T2。每个架构按其支持的最高层级归类。

T2 被拆成五种操作，每种用两个维度描述：*表示处理模式*（在单一表示内、在可分离的多个表示之间协调，或跨表示投影或融合）和*计算机制*（启发式、提示 LLM、训练好的更新模块，或迭代优化）。五种操作是：**更新**（加入或整合新证据）、**巩固**（合并或抽象已积累的记录）、**修订**（修正被新证据否定的记录）、**重组**（在层级间迁移记录、重连图的边、重建索引）、**遗忘**（删除、降低细节或降低检索优先级）。T3 分为写入策略、维护策略和检索策略的演化。

跨轴分析（论文表 1）列出了每个层级对表示的要求，后一层继承前一层的要求：

* **T1：** 形成时以可定位、可复用的形式保留任务相关信息。
* **T2：** *可编辑性*，且操作范围最小而足够；*可核查性*，要有把旧状态、操作、证据与结果连起来的痕迹；*可逆性*，依靠版本、操作日志或逆操作（用随机的 LLM 重新生成摘要，并不能恢复原来那份）；以及*更新传播*，要在相关联的表示之间既完整又有选择。
* **T3：** *策略可寻址性*（有一个可以被修改的明确部件）、*策略级反馈归因*（区分写入、维护、检索、推理与行动的失败），以及*持久且经过验证的策略修订*（在之后的或留出的案例上检验是否有回退）。

# 关键技术

## 源证据与模态特定记忆

* **保留源证据。** 记忆单元保持原始模态，可以原样交还给模型。对图像和 GUI 来说，这保留了版式、字体、颜色和精细的空间细节。视频和音频的证据得先在时间上定位，综述把组织方式分为帧级（ToolMerge 在采样帧上组合全局、区域和 OCR 检索工具）、事件级（HippoMM 写入带摘要、时间边界和指向源片段指针的事件记录）和实体级（M3-Agent 把文本、图像、音频证据关联到持续存在的人、物和事件）。具身系统把保留的图像与空间结构配对（GraphEQA、DovSG）。
* **编码特征与几何状态。** 视频系统直接持久化特征：MovieChat 合并相邻帧中相似的视觉词元后转入长期记忆，MA-LMM 把 patch 特征作为交叉注意力的键和值，Flash-VStream 结合低分辨率质心与高分辨率关键帧。具身系统持久化几何（DynaMem 带时间戳和视觉-语言特征的稀疏体素地图）或面向策略的历史（MemoryVLA 的感知词元库）。这类压缩通常不可逆，且与特定模型绑定。图像智能体大多保留源图像、嵌入只用于索引；持久的音频特征记忆几乎没有被探索。

## 显式记忆

* **感知转文本。** 视频智能体把画面变成事件记录（VideoAgent 的时间性描述；Video-EM 的"何时/何地/何事/何人"情节；ReMA 带时间戳的片段描述，在新观测重叠时合并）。MIRIX 把屏幕和对话分发给六个专门的文本记忆组件。局限在于写入时的语义瓶颈：描述模型当时没认为重要的东西就此丢失；图像和具身记忆很少只用文本，因为它们依赖细节和度量关系。
* **结构化记忆。** ConceptGraphs 把开放词表检测结果融合成 3D 物体节点和关系；DovSG 在场景变化时局部修正场景图，规划器把它当作当前世界状态来读；GraphEQA 的层级场景图还告诉智能体下一步去哪里探索。PyraVid 和 WorldMM 为视频建立"事实-片段-叙事"图和多分辨率时间知识图谱。TAME 把动态的个人属性与稳定属性分开；PolarMem 用 HAS 和 NOT_HAS 边把记忆连到概念上，从而能表示"已确认不存在"，并用它压制外观相似但已被排除的记忆。结构化 GUI 记忆很少见，因为界面布局会随版本和窗口大小而变。

## 潜在与参数记忆

* **潜在状态。** ReKV 和 MuKV 保留视频 KV 缓存并恢复与问题相关的块；VisMem 和 TRAM 让视觉证据和中间推理在长生成中保持影响力；L2-VMAS 在多个视觉-语言智能体之间共享感知与思考记忆库；Mem-W 把检索到的轨迹和已过期的会话内历史压缩成记忆词元；LaMem-VLA 把短期和长期记忆库压缩成定长词元用于动作生成。
* **参数记忆。** MemEIC 为知识编辑分别保留视觉和文本 LoRA 适配器，并配有显式编辑记录；Frames2LoRA 用超网络一次前向就从视频生成专属 LoRA，之后提问不再需要视觉词元；SE-GA 用 LoRA 更新把 GUI 经验巩固进策略；VLA-Pro 按程序性状态索引存储按任务的适配器，并按相似度组合。

## 混合记忆

VimRAG 维护一个推理 DAG，每个节点带摘要和按相关性与新近程度调整大小的视觉词元库。FOLIO 存储带缓存关键帧引用的结构化流记录，需要时可恢复关键帧。MementoGUI 保存文本事件摘要和相关屏幕区域的裁剪图，压缩后仍能把区域标识解析回裁剪图。VISTA 在可修改的笔记旁保留一份无损帧档案。ObsGraph 建立"房间-视角-物体"层级，还能据此判断该去别的房间、细化视角还是探索前沿。

## 管理机制

* **T2 示例。** FluxMem 按新近程度分层巩固；ReMA 是综述用来说明"在固定规则下合并、细化记录属于 T2 而非 T3"的范例；层级迁移（MovieChat 从短期到长期，TAME 从动态到静态）、重连（DovSG 的局部子图，M3-Agent 的人脸与声音关联）和重建索引都属于重组。遗忘分四种：驱逐活跃证据（FIFO、蓄水池采样、按新近程度加权）、细节衰减（记忆图像随时间降采样）、可达性衰减（随时间降低检索优先级，被回忆时恢复），以及协调遗忘（在一种表示中丢弃细节而保留另一种紧凑表示）。
* **T3 示例。** 根据任务反馈调整的写入策略，包括用失败痕迹修复图构建和"源到记录"的映射；在一次查询失败暴露出信息被丢弃后延长保留时间的维护策略；从成功与失败的检索轨迹中提炼出的检索策略（长视频中的 RRM）、优先选择直接观测到的物体记录的验证规则，以及在临床场景中根据下游反馈更新的效用估计。

## 系统基础设施

综述区分*逻辑记忆*（由经历派生的状态）、它的*物理实现*（记录、张量、适配器、副本、索引）和*物化的执行状态*（计算实际消费的东西）。然后梳理了在 HBM、DRAM、SSD 和池化内存之间的驻留（ReKV、Mooncake、InferCept 的保留/换出/丢弃、Continuum 的保留 TTL、MORI）；传输、压缩与重算（CachedAttention、CacheGen、Cake、MPIC、TokenCake）；复用与调度（SGLang 的基数前缀缓存、Prompt Cache、CacheBlend、Preble、ThunderAgent、KVFlow）；以及一致性（所有权、写入中记录的发布、写时复制、按权限过滤的检索、模型更新后的嵌入回填）。这一节有两条对分类重要的规则：驱逐一个可重建的缓存或冗余副本不一定是遗忘了底层经历；缓存替换本身不算 T2 适应，按负载调度本身也不算 T3 策略演化。

# 案例

## 应用领域

* **回忆与基于证据的推理：** 多模态问答、情节检索、长视频与长音频、企业文档分析（MARDoc）、金融推理（FinAcumen）。强调可恢复的出处和时间有效性。
* **个性化与跨会话连续性：** M2A、TAME、Persode；强调身份范围、选择性保留，以及在不串用户的前提下修订偏好。
* **控制与任务执行：** 能跨界面变化迁移的 GUI 技能（MAGNET）、具身导航与操作、市场决策（FinAgent）、业务文档抽取（Matrix）、钓鱼攻击响应（MemoPhishAgent）。记忆必须改变智能体的行为，并保持可修订。
* **生成与世界一致性：** 幻灯片制作（MemSlides）、带可执行事件结构的智能体视频生成、金融报告（FinSight）；这是专门记忆基准最少的领域。

## 评测现状

基准用六项共享能力描述：跨模态证据（CE）、长程证据（LE）、状态变化（SC）、冲突记忆（CF）、无法回答的查询（UQ）和以记忆为依据的行动（MA）。旁边还有模态特定能力（图像：细粒度细节、实体跟踪、视觉变化；视频：时间定位、时间关系、多事件整合；音频：说话人跟踪、声学线索、修正持久性；GUI：界面状态、动作-结果关联、跨会话复用；具身：空间记忆、物体状态、任务进度）。作者把 LE、TL、ME、XR 对应到 T1，把状态变化和冲突类能力对应到 T2，把 UQ 和 MA 对应到使用环节；没有哪个标签本身能确立 T3。例子包括 [LoCoMo](../concepts/locomo.md)——其原始问答和摘要实验把对话中共享的图像换成了描述文字——以及随 [VoiceMem](../papers/2608.26005.md) 提出的 ChatMem-Bench（53 小时对话上的 316 个问题）。综述的判断是：模态覆盖广，生命周期覆盖窄。检索测得多；冲突和证据不足测得少；以记忆为依据的行动主要出现在 GUI 和具身基准中；源出处、端到端归因和策略适应评测薄弱。

# 证据边界

* **综述本身确立的**是一套术语、一个双轴分类、按层级的表示要求，以及按其自身分类得到的语料统计。统计：297 个架构中，221 个（74.4%）在运行中更新记忆状态或策略，其中 T2 204 个（68.7%）、T3 17 个（5.7%），余下 76 个为 T1（读者相减所得）。混合是最大的表示类别，139 个（46.8%）。17 个 T3 系统中 13 个是跨表示的显式记忆，4 个是含显式组件的混合系统；作者表示"据我们所知"，没有任何仅源证据或仅潜在/参数的系统属于 T3。
* **语料如何构建没有说明**（就所读正文而言）：没有检索流程、纳入时间窗或对层级与表示标签的标注一致性检查；语料被称为"当前分类版本"，因此各版本之间计数可能变化。马赛克图、发生率图和各能力的基准覆盖百分比（图 12）只读了图注。
* **各系统的性能说法是转述，不是比较。** 例如 FluxMem 的"有竞争力的表现"或 VLA-Pro 的跨任务迁移提升，都来自各自论文、各自设置；综述没有在统一基准上运行。
* **有些规律是论证出来的，不是统计出来的。** "策略演化集中在检索上"（8.2.2 节）在所读正文中没有给出 17 个 T3 系统按目标的分类计数。"T3 需要显式记忆是因为显式单元提供了可修改的目标"，是作者对一个 17 系统规律的解释。
* **处方都是提议。** 最小出处包、有效性状态（当前、历史、已被取代、不确定）、选择性核查、按表示分配预算、跨表示定义遗忘、按生命周期阶段评测——这些方向在本文中都没有实证检验。
* **本笔记中由读者构造的部分：** T1 计数、代表系统表的组织方式，以及下面的要点。

# 要点

读者整理的、可带入自己工作的几点：

1. **按模型实际读到的东西给记忆分类，而不是按索引方式。** 很多关于某系统是"视觉记忆"还是"文本记忆"的争论由此可以解决。
2. **用 T2/T3 界线检验自演化说法。** 一个在固定规则下改写记录、键或技能描述的系统是在更新记忆，而不是在学习如何管理记忆。这对[智能体自演化](../topics/agent-self-evolution.md)主题中的论文是一个有用的筛选标准。
3. **在写入时就为可逆做准备。** 保留源观测不足以撤销一次 LLM 生成的修订；要保留旧版本或操作日志。
4. **删除与核查相互掣肘。** 出处和版本历史让记忆可核查，同时也让副本继续存在；一次遗忘请求必须覆盖所有派生表示。
5. **按阶段评测。** 把形成、维护、访问和使用分开，并通过反事实地移除检索到的证据，证明答案确实依赖了记忆。
6. **与本仓库的关联。** 本仓库自己的记忆层（全局与项目记忆文件、认知缓存）是在指令所写规则下维护的显式文本记忆，按综述的说法属于 T2；它们的出处链接和大小与衰减规则，正对应综述中的可核查性与遗忘要求。

# 开放问题

* 每条形成的记忆，按模态和表示，至少要携带什么出处信息，才能在不保留全部源观测的前提下让抽象仍可恢复？（作者，8.1.1）
* 潜在或参数记忆能否暴露出可被管理识别、单独修改、事后验证的单元，同时不失去促使人们采用它的紧凑性？（作者，8.1.2）
* 新证据何时应取代旧状态，何时两者应并存，何时应保留不确定性而不是急于消解？（作者，8.2.1）
* 如何把延迟出现、跨模态的反馈归因到当初导致失败的那次写入、合并、修订或遗忘决定，从而让策略演化扩展到检索之外？（作者，8.2.2）
* 修订后的策略在依赖哪种模态上发生多大变化算健康的适应，什么时候就成了应阻止该更新的"失去依据"？（作者，8.3.3）
* 当目标信息已扩散到描述、嵌入、摘要、潜在状态和共享参数中时，如何验证遗忘已完成？（作者，8.3.4）
* 读者问题：17 个 T3 系统全都有显式记忆。这是因为策略演化必须依赖显式记忆，还是因为如今的策略演化大多靠在文本上提示 LLM 实现，而这只能作用于显式记忆？一个带有可学习、可由反馈更新的写入门控的潜在记忆系统，可以把这两种解释分开。

# 相关

* [智能体记忆](../topics/agent-memory.md) - 为多模态智能体记忆提供双轴分类和 297 个系统的语料，与该主题中以文本为中心的系统互补。
* [智能体自演化](../topics/agent-self-evolution.md) - 其 T3 层把自演化记忆定义为由反馈驱动、持久且经过验证的记忆管理策略变化，并在 297 个架构中只找到 17 个。
* [LoCoMo](../concepts/locomo.md) - 被列为图像记忆基准，并提醒其原始问答和摘要实验用描述文字替换了共享图像。
* [Reflexion](../concepts/reflexion.md) - 被引为文本智能体的基础之一：把反馈存成可复用的语言教训，是多模态记忆继承的设计之一。
* [MemOS](../papers/2507.03724.md) - 在基础设施展望中被引为异构记忆资源的通用抽象。
* [VoiceMem](../papers/2608.26005.md) - 其 ChatMem-Bench 是综述主要的音频记忆基准，覆盖信息更新、拒答、说话人关联和非词汇声学证据。
* [Mem0](../papers/2504.19413.md) - 被引为紧凑、可编辑的文本记忆，是界定多模态表示问题时所对照的文本智能体基线。
* [SwitchMem](../papers/2610.17928.md) - 综述未引用；一个 GUI 记忆系统，逐步选择把检索到的记忆以文本还是截图形式呈现，相当于把综述的轴一选择放到读取时做（读者关联）。
* [Self-Improvements in Modern Agentic Systems](../papers/2607.13104.md) - 另一篇把记忆变化与其他自我改进途径分开的综述；这篇多模态综述的 T2/T3 界线是判断记忆变化何时算策略演化的更严格标准（读者关联）。
