# Q1 问题定义

* **输入（X）：** 某个交互环境的初始技能文档 S₀（由 LLM 生成）、在上下文中使用该技能执行任务的动作智能体 π，以及互不相交的训练、验证、测试任务集。
* **输出（Y）：** 一个冻结的最终技能 S*（经过 E = 4 个轮次后最新的"已验证技能"），交给 π 后能提高测试任务成功率。不更新任何模型权重。
* **核心问题：** 现有技能演化方法把执行反馈转成编辑，却丢掉了编辑与促成它的行为之间的联系，因此无法检验编辑是否真的改变了那个行为。它们还用一个验证分数评判整次修订，修订被拒时，其中局部有效的编辑也一并被丢弃。论文要回答：如何在编辑成为持久指导之前，保留、检验并反复审视它的执行依据。

# Q2 问题新颖性

部分新颖。基于轨迹构建和修订技能是一条很拥挤的研究线：Trace2Skill 把轨迹局部的经验提炼成补丁，SkillDisCo 从成功轨迹中编译共有流程，SkillGrad 把诊断转成文本更新信号，SkillAdaptor 与 SkillRevise 依据失败进行修订，EvoSkill 通过失败分析提出技能，SkillOpt 在留出验证门控下做有界编辑并把被拒编辑作为反馈保留。EviSkill 的新意有两点：（1）每条编辑都带有一个可从记录状态重放的证据对象，而不是一段文字经验；（2）把"单条编辑的局部支持"与"整次修订的全局接受"分开，局部得到支持的编辑以临时形式带入后续轮次。两项预研究分别支撑这两点：把 Trace2Skill 的编辑放回促成它的任务上重跑，有的有帮助、有的没效果、有的变差（图 2）；从被全局拒绝的 Trace2Skill 修订中挑出部分编辑，能让训练集准确率高于之前的已验证技能（图 3）。

# Q3 科学假设

1. **重放胜过"看起来合理"。** 如果每条候选编辑都在促成它的那几段步骤上重新执行，只有重放显示出预期改变且没有引入新失败时才保留，那么进入技能的无效编辑会减少，测试准确率会提高（消融"w/o Replay"）。
2. **被拒的修订里有有用的编辑。** 如果把未通过全局验证的修订中、经重放得到支持的编辑临时保留，并把未解决的证据带到后续轮次，其中一部分会在之后进入被接受的技能，准确率会提高（消融"w/o Cross-Epoch"、Cards Only / Edits Only）。
3. **基于证据的演化可跨骨干模型泛化。** 如果方法有效，它在三个环境、六个动作模型上都会胜过无技能、固定初始技能以及四种演化基线（表 1 与表 4）。

# Q5 关键解法思想

EviSkill 维护两种技能状态：**已验证技能**（Validated Skill）S^V，只有当候选修订在验证集上胜过它时才更新；**工作技能**（Working Skill）S^W = S^V ⊕ P，其中 P 是**临时编辑账本**（Provisional Edit Ledger），存放经重放支持但尚未通过验证的编辑（最多 16 条）。每个轮次：

1. **基于证据的编辑合成。** π 用 S^W 把每个训练任务各跑一次。一个 GPT-5.5 抽取器写出**可重放证据卡**（Replayable Evidence Card）C = ⟨编号, 触发区间, 拟议修正⟩，其中触发区间（任务、轮次、起始步、结束步）精确指向支撑该修正的轨迹片段；一个落地校验器会丢弃区间不能支撑修正的卡片。**对比卡**来自对已在使用的编辑，比较同一任务相邻两个轮次的轨迹。活跃卡片经 Qwen3-Embedding-0.6B 编码并用 HDBSCAN 聚成 4-20 张卡的"证据窗口"，编辑器再把每个窗口转成候选编辑（对 Markdown 技能做追加、插入、替换或删除），并保留与卡片的链接。
2. **重放引导的编辑验证。** 对每条编辑，先重放记录下的轨迹前缀，重建触发区间开始前的状态，再让 π 在 S^W ⊕ 编辑 下重新执行该片段（每条编辑最多三个区间）。GPT-5.5 评估器比较原始片段与重放片段，给出接受、反思（存在局部可修的缺陷，并附反馈）或拒绝。被判为反思的编辑修改一次后再重放。被接受的编辑合并成一次候选修订。
3. **跨轮次证据传递。** 若候选修订在验证集上胜过 S^V，它成为新的 S^V，账本清空。若未胜出，每条合并后的编辑单独在 S^V ⊕ 编辑 下再重放一次（拒绝后重放），仍然通过的进入账本，下一轮的工作技能就会使用它们。卡片会改变状态：活跃（可进入新窗口）、受保护（支撑某条临时编辑）、归档（已被纳入）、过时（被重放拒绝两次后）。

它与 SkillOpt 验证门控的区别在于"拒绝落在哪里"：SkillOpt 把被拒编辑当作负反馈保留，EviSkill 则把被拒修订中经重放支持的部分作为有效指导留在工作技能里，直到之后的验证接受或取代它。测试时使用的技能只包含已验证的编辑。

# Q6 实验设计

* **环境与划分。** ALFWorld（6 个任务族；训练 96、验证 48、valid_unseen 测试 134），AppWorld（官方划分：训练 90、dev 57、test_normal 168），ScienceWorld（24 个任务族；训练 96、验证 48、官方测试 211）。指标为任务成功率。
* **基线。** 无技能（No Skill）；LLM 技能（固定的初始技能 S₀）；Trace2Skill、EvoSkill、SkillGrad、SkillOpt。每个设置下动作骨干、划分、环境与评测都保持一致。获取的文本没有说明 S₀ 由哪个模型写成，也没有说明基线使用哪个优化模型。
* **动作骨干。** GPT-5.5、GPT-5.4、GPT-5.4-mini（中等推理）与 Qwen3.6-35B-A3B、Qwen3.5-9B、Qwen3.5-4B（非推理模式），温度 0.7，交互窗口 8 步，ALFWorld 与 AppWorld 上限 50 步。EviSkill 的抽取器、编辑器和评估器对所有骨干都使用 GPT-5.5。
* **消融。** w/o Replay、w/o Cross-Epoch（按模型家族平均），以及在 ALFWorld 上用三个 Qwen 骨干做的 Cards Only / Edits Only。
* **机制分析。** 18 次运行（6 个骨干 × 3 个环境）共 72 个轮次：重放判定比例、反思后的挽回率、临时编辑的晋升、卡片的跨轮复用、对已跟踪编辑的对比修正、卡片支撑广度（单任务与跨任务）以及重放工作量。
* **未纳入设计的部分。** 每个设置只跑一次，没有方差或显著性检验；没有 token 或金额成本；没有"用同样的 GPT-5.5 预算但不做重放"的变体；评估器的接受/反思/拒绝判定没有人工核查。

# Q7 数据集与代码

没有新数据集；三个环境都是公开的。代码发布在 [Zhouyaner/eviskill](https://github.com/Zhouyaner/eviskill)。附录 C 给出算法、卡片与编辑的结构、重放流程、生命周期规则与全部超参数；附录 H 给出五个核心提示词（卡片抽取、卡片落地校验、编辑合成、重放评估、对比卡抽取）。

# Q8 证据质量

* **有支撑的结论。**
  * *主对比。* 在 18 个"模型-环境"设置中，EviSkill 在 14 个上准确率最高，在 16 个上进入前两名。它在全部 18 个设置上都优于无技能（平均 +17.93 个百分点），在 17 个上优于 LLM 技能，第 18 个持平（Qwen3.5-9B 在 AppWorld 上，43.45）。在 ALFWorld 上它对六个骨干都是最好。
  * *ScienceWorld 上演化最容易失败，而 EviSkill 稳住了。* 用 GPT-5.5 时，LLM 技能为 76.78，Trace2Skill、EvoSkill、SkillGrad 跌到 65.40、54.50、67.30；SkillOpt 为 80.09，EviSkill 为 83.41。用 Qwen3.5-9B 时，EviSkill 为 37.91，最好的基线为 22.27。
  * *消融。* 在 GPT 骨干平均下，去掉重放分别损失 2.49、4.56、2.85 个百分点（ALFWorld、AppWorld、ScienceWorld），去掉跨轮传递使 AppWorld 从 89.68 降到 85.52。在 Qwen 骨干上，跨轮传递在 ALFWorld 和 ScienceWorld 上更重要（3.48 和 1.58 个百分点），重放在 AppWorld 上更重要（3.17）。在 ALFWorld（Qwen 平均）上，Cards Only 与 Edits Only 各恢复一部分收益（86.32、86.82），两者合起来达到 88.06，两者都没有时为 84.58。
  * *机制。* 首次重放未通过的候选编辑比例为 20.7%（ALFWorld）、41.8%（AppWorld）、42.5%（ScienceWorld）；反思随后挽回了 AppWorld 上 16 条中的 13 条、ScienceWorld 上 54 条中的 49 条。被拒修订中的 155 条合并编辑里，128 条被重放，96 条被接受，其中 70 条（占被接受的 72.9%）之后进入了已验证技能；四轮预算结束时仍有 27.1% 停留在临时状态。被对比卡针对的 29 条已跟踪编辑中，20 条得到了经重放接受的修正。
* **比标题更弱或更窄的部分。**
  * *AppWorld 上的优势很薄甚至为负。* 用 GPT-5.4-mini 时 EviSkill 排第三（83.93，EvoSkill 为 85.12），用 Qwen3.6-35B-A3B 时排第二（63.10，Trace2Skill 为 64.88），用 Qwen3.5-9B 时排第四（43.45，SkillOpt 为 47.62）。用 GPT-5.5 时它只比固定初始技能高 0.59 个百分点，相当于 168 个测试任务中的 1 个。三个测试集上 1 个任务分别相当于 0.75、0.60、0.47 个百分点，而每个设置只在温度 0.7 下跑了一次，因此一两个任务的差异落在运行间噪声之内。
  * *优化器不对称。* 即使动作模型是 4B、9B 的 Qwen，EviSkill 的证据抽取器、编辑器和重放评估器仍是 GPT-5.5。Qwen 上的大幅收益（相对无技能平均 +22.85 个百分点，GPT 骨干为 +13.00）可能部分来自更强的模型在写技能；获取的文本没有说明基线的优化器是否也是 GPT-5.5。
  * *成本被低估。* 效率表（每 100 次训练 rollout 带来 3.77 个验证百分点，EvoSkill 为 1.55，SkillGrad 为 0.84）只统计训练 rollout。重放在 18 次运行中额外执行了约 19,200 个智能体步（窗口重放 18,007 步、拒绝后重放 1,205 步，另有复制的前缀），还要加上 GPT-5.5 在抽取、落地校验、编辑和评估上的调用；论文没有报告 token 或金额对比。
  * *重放接受是 LLM 的判断。* 接受/反思/拒绝由读取成对片段的 GPT-5.5 评估器给出，而不是在留出任务上重新测得的成功率，也没有与人工判断核对。重放用的还是产生证据的训练任务，因此它说明的是编辑改变了促成它的行为，而不是编辑能泛化；全局验证仍是唯一的样本外检验。
  * *预研究 2.2 是样本内的。* "被拒修订中的有用编辑"这一结果，是让 GPT-5.5 从每次修订中挑出看起来最有希望的 min(3, N−2) 条编辑，再在完整训练集（即这些编辑的来源任务）上测 GPT-5.4-mini 的准确率。它说明被拒修订并非一无是处，但不能说明被保留的编辑能泛化。
  * *机制统计需要分母。* 72.9% 的临时编辑之后得到晋升，但晋升指的是包含它们的某次候选修订（连同其他编辑一起）通过了验证，并不是对每条编辑的单独检验。

# Q9 贡献

* 指出经验驱动的技能演化中的两个缺口：编辑丢失了促成它的执行证据；修订级验证会丢弃局部有效的编辑。
* EviSkill：带步区间溯源的可重放证据卡、从记录状态出发的局部重放（用于验证和修复每条编辑），以及临时账本加卡片生命周期，在保持部署技能受验证门控的同时，把得到支持的编辑和未解决的证据带到后续轮次。
* 在三个环境、六个动作骨干上与四个演化基线的评测，附消融与生命周期统计，并发布了代码和提示词。

# Q10 下一步

* **预算匹配的对照。** 给基线同样的 GPT-5.5 优化器和同样多的额外智能体步（用来跑更多 rollout 而非重放），以区分重放本身的价值与更多算力的价值。
* **方差。** 每个设置用多个随机种子重复；AppWorld 与 ALFWorld 上很多差异只有一两个任务。
* **审视评审。** 人工标注一部分重放判定，或在环境允许时用重放片段上重新测得的任务结果取代 LLM 判定，并报告一致性。
* **被接受编辑的泛化。** 在*没有*产生其证据的训练任务上重放被接受的编辑，检验重放接受能否预测迁移。
* **与验证门控的相互作用。** 临时编辑在被验证之前就会影响下一轮的轨迹；需要测量一条坏的临时编辑是否会把之后的证据引向支持保留它自己。
* **与本仓库的契合（读者笔记）。** 本仓库把 hub 技能安装到智能体中并手工编辑；EviSkill 的卡片格式（把证明某次修改合理的步区间和修改一起保存）可以作为记录"某行技能为何被加入"的约定，让之后的审阅者能重跑促成它的那个案例。

# 相关

* [智能体技能库](../topics/agent-skill-libraries.md) - 与 SkillOpt、SkillOpt-Lite 一样，针对每个环境改进一份已有的技能文档，但让每条编辑携带可重放证据，并在修订级门控之前用局部重执行来验证它。
* [智能体自我演化](../topics/agent-self-evolution.md) - 一个带两道门的"诊断-编写-验证"循环：先在促成编辑的步区间上逐条重放，再做全局验证；通过前者但所在修订未通过后者的编辑留在临时账本中。
* [SkillOpt](../papers/2605.23904.md) - 四个基线之一，也是设计上最接近的方法：两者都用留出验证门控并保留被拒编辑的信息，但 SkillOpt 把它们作为负反馈，EviSkill 则把经重放支持的那部分作为有效的临时指导。
* [RASO](../papers/2609.38024.md) - 另一个受验证门控的单技能优化器；它改变的是修复的来源（检索到的外部流程），EviSkill 改变的是修复的检验方式（在自身证据上重放）。
* [RSIGame](../papers/2609.39045.md) - 同样用重放验证器为每次编辑把关，场景是游戏构建；EviSkill 只重放编辑所针对的那段轨迹，而不是整个工件。
* [ALFWorld](../concepts/alfworld.md) - 三个环境之一（134 个 valid_unseen 测试任务）；EviSkill 对六个骨干都最好，例如 GPT-5.5 下 96.27、Qwen3.5-9B 下 91.04。
* [AppWorld](../concepts/appworld.md) - 三个环境之一（168 个 test_normal 任务）；EviSkill 在此最不稳定，三个骨干下第一或并列第一，另外三个骨干下低于一个或多个基线。
* [ScienceWorld](../concepts/scienceworld.md) - 三个环境之一（211 个测试任务）；多个演化基线在此跌到固定初始技能之下，而 EviSkill 在五个骨干下排第一。
