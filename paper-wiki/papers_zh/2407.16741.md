> 论文:**OpenHands (f.k.a. OpenDevin): An Open Platform for AI Software Developers as Generalist Agents**
> 论文链接:<https://arxiv.org/abs/2407.16741>
> 机构:UIUC、CMU、耶鲁、UC Berkeley、Contextual AI、KAUST、ANU、HCMUT、阿里巴巴、All Hands AI

# Q1 问题定义

* **输入 `X`**:一个用户指定的任务——软件工程问题、网页浏览目标,或杂项协助类查询——加上选定的 agent 实现和底座 LLM。
* **输出 `Y`**:一条由动作(bash 命令、Python/IPython 代码、浏览器交互)和观测组成的事件流轨迹,最终完成任务,并针对 15 个已集成的基准(覆盖软件工程、网页浏览、杂项协助)给出评分。
* **核心问题**:要让 agent 像人类开发者那样与世界交互——写代码、跑终端、浏览网页——需要同时解决几个相互耦合的基础设施问题:让 agent 有能力在复杂软件系统中创建和修改代码,让它能随时获取任务所需信息,并且要安全地做到这一切(沙箱化,不对用户系统产生副作用)。论文自己的 Table 1 对比表明,现有 agent 框架各自只覆盖了其中一部分:有的缺乏沙箱化代码执行,有的缺浏览器,有的缺多 agent 委派,有的缺系统化的评测框架。
* **范围**:这是一个开源平台(agent 抽象 + 运行时 + 工具库 + 评测 harness),而不是单一固定的 agent;平台之上提供了一个默认通才 agent(CodeActAgent)和若干专才 agent(BrowsingAgent、一个 GPTSwarm 集成)。

# Q2 问题的新颖性

在本文之前已经存在多个开源 agent 框架(AutoGPT、LangChain、MetaGPT、AutoGen、AutoAgents、Agents、XAgent、OpenAgents、GPTSwarm),以及面向软件工程的专用系统(SWE-Agent、AutoCodeRover)。论文自己的九维框架对比(图形界面、标准化工具库、内置沙箱与代码执行、内置网页浏览器、多 agent 协作、人机协作、AgentHub、评测框架、agent 质量控制/集成测试)显示,OpenHands 是唯一一个九项能力全部具备的系统。其新意在于这种能力组合本身,再加上把软件——代码、命令行、浏览器——当作 agent 与世界交互的通用接口,呼应人类本身正是通过软件作用于世界这一事实,而不是提出某个新的单 agent 算法。

# Q3 科学假设

如果一个 agent 平台提供一套通用的事件流交互协议、一个暴露 bash/IPython/浏览器原语的 docker 沙箱化运行时、一个可扩展的 agent-computer 接口技能库,以及一套用于协作专才 agent 的委派机制,那么建立在该平台之上的单个通才 agent(CodeActAgent)——无需针对具体基准做提示词工程——就能同时在性质不同的任务族(软件工程、网页浏览、杂项协助)上保持有竞争力的表现,而以往系统通常一次只针对一个任务类别优化。

# Q4 相关工作与关键人物

* 延续了 CodeAct(Wang et al., 2024)作为动作表示——用代码执行而非 JSON 函数调用——构成默认的 CodeActAgent。
* 与通用型 agent 框架(AutoGPT、LangChain、MetaGPT、AutoGen、AutoAgents、Agents、XAgent、OpenAgents、GPTSwarm)以及面向软件工程的 agent-computer 接口工作(SWE-Agent 的 ACI 概念、AutoCodeRover)做对比;详见论文 Table 1 与附录 C。
* 集成了 15 个既有基准(SWE-Bench、HumanEvalFix、BIRD、BioCoder、ML-Bench、Gorilla APIBench、ToolQA、WebArena、MiniWoB++、GAIA、GPQA、AgentBench、MINT、Entity Deduction Arena、ProofWriter),而非提出新基准。
* **作者/机构**:项目负责人 Xingyao Wang,加上 23 位合作者,分布在 UIUC、CMU、耶鲁、UC Berkeley、Contextual AI、KAUST、ANU、HCMUT、阿里巴巴、All Hands AI;指导者为 Graham Neubig、Heng Ji、Hao Peng。

# Q5 核心解法

五个平台组件:

1. **事件流交互机制**:通过一条按时间顺序排列的动作与观测历史,把用户界面、agent、环境连接起来,并附带辅助执行状态(累计的 LLM 花费、多 agent 委派元数据)。
2. **docker 沙箱化 agent 运行时**:在一个安全隔离的容器内暴露一个 bash shell、一个 Jupyter IPython 服务,以及一个基于 Playwright 的 Chromium 浏览器(通过 BrowserGym 动作原语——导航、点击、输入、滚动);通过把 OpenHands 动作执行 API 注入用户提供的任意 docker 镜像,支持在任意操作系统环境下运行。
3. **AgentSkills 库**:一个自动导入到 IPython 环境中的可扩展 Python 函数工具箱。只有满足以下条件之一才会新增一个技能:(1) LLM 难以直接写代码实现该功能;(2) 需要调用外部模型(例如用视觉语言模型解析图像/PDF)。库中包含改编自 SWE-Agent 和 Aider 的文件编辑工具。
4. **Agent 委派**(`AgentDelegateAction`):允许一个 agent——例如浏览能力有限的通才 CodeActAgent——把子任务委派给专才 agent,例如把复杂的网页导航交给 BrowsingAgent。
5. **评测框架**:集成 15 个覆盖软件工程、网页浏览、杂项协助的基准,用于在同等条件下评测每一个已发布的 agent。

# Q6 实验设计

把 OpenHands 的 agent(主要是跨 GPT-4o-mini、GPT-4o、Claude-3.5-Sonnet 三种底座的 CodeActAgent,以及 BrowsingAgent 和一个 GPTSwarm 集成)与不针对特定基准调优的开源基线在 15 个基准上做对比,报告成功率和每任务平均美元成本。

**软件方向**:SWE-Bench Lite(300 个实例,不使用提示文本)——CodeActAgent v1.8 / Claude-3.5-Sonnet 达到 26.0% 的解决率,每实例 1.10 美元,与同期的 SWE 专才系统(Aider 的 26.3%)相当但未超越。HumanEvalFix Python 子集(164 个实例,0-shot)——CodeActAgent v1.5 / GPT-4o 达到 79.3% 的 pass@k,低于 SWE-Agent 的 87.7%(但后者是 1-shot,而 OpenHands 是 0-shot)。BIRD 文本转 SQL——最高 47.3%;ML-Bench——最高 76.5%;BioCoder——最高 27.5%;Gorilla APIBench——最高 36.4%;ToolQA(easy 子集)——最高 47.2%。

**网页方向**:WebArena(812 个任务)——BrowsingAgent / Claude-3.5-Sonnet 达到 15.5%,在零样本、领域通用提示的 agent 中具竞争力,但不及经过训练的专用模型。MiniWoB++(125 个环境)——最高 40.8%,远低于经 RL 训练的专用模型(CC-NET 的 91.1%)。

**杂项协助方向**:GAIA——CodeActAgent / GPT-4o 达到 53.1%(结果表中引用的是 v1.5 数字);GPQA——该对比列中报告的最强基线是少样本思维链 GPT-4,达到 38.8%。

# Q7 数据与代码

未发布新基准;把 15 个既有基准(见上)集成进一个统一的评测 harness。以 MIT 许可证发布;论文写作时已获得 3.2 万 GitHub star,来自 188 位以上贡献者的 2100 多次贡献,是一个持续至今(以 OpenHands / All Hands AI 之名)的社区项目。

# Q8 证据质量

本文的核心主张是覆盖面广、跨任务有竞争力,而非在任何单一基准上取得最优——结果表对此相当坦诚:OpenHands 的 agent 在几乎每个单项基准上都落后于最强的专才基线(例如 HumanEvalFix 79.3% 对 SWE-Agent 1-shot 的 87.7%;MiniWoB++ 40.8% 对 CC-NET 这一经 RL 训练专才模型的 91.1%),但它是唯一一个——在单一未经修改的系统提示词下——同时在三大任务类别上都接受评测的系统,因为第 4 节全程使用的都是同一个 CodeActAgent,而非针对各基准分别调优的版本。论文自己明确指出的一个注意点:部分基线对比并非严格匹配(例如 SWE-Agent 的 HumanEvalFix 数字是 1-shot,而 OpenHands 是 0-shot),因此跨行对比时需要留意这一差异,而非当作严格对等比较。作为一篇系统/平台论文而非单一假设的实证论文,其最有力的证据可以说是 Table 1 的能力对比表,加上社区采用规模的数字(3.2 万 star、188 位以上贡献者)——这是真实的使用/采纳证据,但并非受控实验。

# Q9 主要贡献

1. 一个开源 agent 平台(OpenHands,原 OpenDevin),整合了事件流交互协议、沙箱化的多模态运行时(bash + IPython + 浏览器)、可扩展的 agent-skills 工具库,以及协作式多 agent 委派——在论文自己的九维框架对比中,是唯一具备所有列出能力的系统。
2. AgentHub:一个包含 10 个以上社区贡献的 agent 实现的枢纽,共享同一套 agent 抽象,包括基于 CodeAct 的通才 CodeActAgent、一个 BrowsingAgent,以及一个 GPTSwarm 集成。
3. 一套集成的评测框架,覆盖软件工程、网页浏览、杂项协助三大类共 15 个既有基准,证明单个通才 agent 和系统提示词能够同时在三个类别上保持竞争力。

# Q10 下一步

* 论文自身在附录 A 中提出的局限与未来工作:更有原则性的多模态支持(通过标准 IPython/浏览器集成而非临时技能来查看图像/视频、处理表格文件);agent 在复杂任务上仍然吃力,需要通过训练和推理时技术共同提升;长文件编辑能力仍然薄弱;以及基于图(GPTSwarm/LangGraph 式)的自动化工作流生成,以减轻当前手工设计 agent 的负担。
* 其伦理声明把这个平台本身定位为一种风险缓解工具——通过系统化评测在部署前发现风险、通过人机协作而非无监督自主运行、通过向研究界广泛开放前沿 agent 工具来支持安全研究——而不是把 agent 能力的增长当作风险中性的事情。
* **与本仓库的关联**:OpenHands 的 AgentSkills 收录规则——只有当 LLM 难以直接写出等价代码,或需要调用外部模型时才新增一个技能——为本仓库自身的技能库纪律([research-skills-hub](../../research-skills-hub/index.md))提供了一个具体、可复用的设计启发。它的委派机制(`AgentDelegateAction`)也是本知识库已经在 [LongHorizon-Harness](../papers/2608.01964.md) 中追踪的多 agent 委派模式的一个较早、可直接引用的先例。
