# 概述

这篇综述首先划定了一个很重要的边界：现代基础模型智能体什么时候算是在**自我改进**，而不只是依靠更长的上下文、任务内重试或临时计划把当前任务做完？作者的答案是“持久化”。一次执行必须产生学习信号，并把结果提交为模型或运行脚手架中的持久变化；变化要跨越当前任务边界，继续影响后续行为。

论文把第 `t` 轮智能体写成 `A_t = (θ_t, Σ_t)`。其中 `θ_t` 是基础模型参数，`Σ_t = (p_t, m_t, T_t, g_t)` 是运行脚手架（operational scaffold），包括可复用 Prompt、记忆、工具以及路由、调度、安全等控制逻辑。当前对话、临时计划或工作记忆属于执行状态 `X_t`；除非其中的结果被固化进 `θ` 或 `Σ`，否则不构成本文定义下的自我改进。

由此形成两条互补路径。**基础模型改进**更新 `θ`：速度慢、成本高、难以归因和回滚，但可以把能力摊销到许多未来任务。**脚手架改进**更新 `Σ`：通常更快、更显式、更容易检查和撤销，但更依赖具体上下文，也会产生记忆漂移、工具失效、Prompt 过拟合或工作流退化。论文最值得带走的部署原则是：先在脚手架层探索和验证，只有当行为稳定且能够迁移时，才考虑把它蒸馏进模型参数。

# 框架

论文用“自诱导更新算子”（self-induced update operator）定义自我改进。当前智能体先在任务或部署环境中执行，产生轨迹、批评、验证结果、偏好、候选补丁等学习信号；更新算子再把其中一部分提交成持久变化。自指性有两种形式：

1. **间接、分布层面的自指**：智能体生成示范、判断或交互轨迹，之后由优化器用它们更新模型参数。
2. **直接、行动层面的自指**：智能体直接修改自己的 Prompt、记忆、工具接口、路由逻辑或脚手架源码。

论文的分类先看**更新对象**，再看**学习信号**：

| 更新对象 | 持久载体 | 主要信号 | 典型权衡 |
|---|---|---|---|
| 基础模型 | 参数 `θ` | 合成示范、自我评价、环境交互经验 | 能力可广泛固化，但成本高、难审计和回滚 |
| Prompt | 可复用指令 `p` | 标量得分、语言批评、种群适应度、文本梯度 | 便宜且可解释，但容易模板化和 Benchmark 过拟合 |
| 记忆 | 记忆对象与结构 `m` | 显著性、效用、检索失败、矛盾、容量压力 | 能积累经验，但有污染、陈旧和检索噪声风险 |
| 工具 | 工具集与接口 `T` | 路由结果、执行错误、验证反馈、能力缺口 | 扩展可执行能力，但增加集成、权限和可靠性风险 |
| 完整脚手架 | 控制逻辑与源码 `Σ` | 测试、任务结果、批评、成本和安全信号 | 可进行深层架构搜索，但改进器和评估边界本身成为攻击面 |

论文还把**技能（skill）**定义为一个具名、可复用、已经序列化的更新算子。技能可以存储在 Prompt、记忆条目、工具、控制逻辑或模型参数里；决定它身份的是它封装了什么可复用更新，而不是它存在哪里。对象级技能作用于任务世界；元级技能作用于智能体自身。技能库因此不只是文件集合，而是“持久更新的存储 + 检索策略”。

# 关键技术

## 基础模型改进

参数更新路径按监督来源分为三类：

* **内生生成示范**：智能体创建指令—回答对、推理轨迹、执行日志、课程或多模态样本，再用置信度、单元测试、形式验证器或多样性规则筛选后微调。它降低人工标注成本，但可能造成模型坍缩、知识泡泡、错误自我放大和灾难性遗忘。
* **内生评价反馈**：内部或辅助评估器生成得分、偏好、置信度、批评或修改后的答案，用于训练模型。Rubric、Self-consistency 和纠错反馈都很灵活，但改进器与 Critic 往往共享盲点。论文建议使用异构评估器、外部锚点、把评估器分歧视为不确定性，并定期审计 Rubric 和奖励模型。
* **外生探索经验**：智能体从真实、沙箱化、规则化环境或学习到的代理世界中收集轨迹。单元测试等程序化验证最可靠；学习型奖励模型覆盖缺乏形式判据的任务；智能体也可以自创任务，但成功与否仍由环境决定。世界模型降低真实交互成本，却可能生成看似合理、实际错误、且可被策略利用的动态。

## Prompt 改进

Prompt 优化从依赖标量反馈的无梯度搜索，发展到自然语言批评、种群进化和结构化文本梯度。需要区分两个更新对象：修改长期复用的系统策略，会改变智能体稳定的行为先验；为单个案例选择示例或组装检索上下文，则是在改变这次执行如何条件化该先验。两者都属于脚手架适应，但持久性和影响范围不同。

## 记忆改进

论文把记忆拆成**对象、结构和处理流程**。对象可以是压缩后的经验、规则与技能，也可以是经过选择的原始证据或两者的混合。结构可以是时间流、层级树、图或向量索引。处理则成为自适应 CRUD 循环：选择性写入、按任务效用而不只是语义相似度检索、修改冲突或过期内容，并在不丢失稀有关键证据的前提下删除噪声。记忆因此从“追加日志”变成需要治理的生命周期。

## 工具治理

工具改进被表述为三种治理元认知能力。**动态路由**负责在不断扩大的工具池中选择和组合工具；**迭代精炼**根据错误轨迹和验证结果，把脆弱程序或文档变成可靠技能；**自主创建**在现有能力不足时发明新工具。论文强调，生成代码只是起点：没有验证、文档、权限控制、标准化集成和工具准入策略，就不能算完成了工具能力扩展。

## 完整脚手架改进

最深层的路径把智能体自身 Harness 当作可修改程序。当前脚手架提出对自己的补丁，再由测试、回归套件、安全检查或其他验证器决定候选版本是否替换活动版本。ADAS、Self-Taught Optimizer、Darwin Gödel Machine、Huxley–Gödel Machine 和 Live-SWE-agent 都实现了某种有边界的循环。现阶段真正可操作的进步不是无限制的递归自我改进，而是在显式程序载体上进行版本化、验证器门控的搜索。

# 应用案例

论文按照各领域能够提供的反馈环境来解释不同机制：

* **软件工程**有编译器、测试、Lint 和 CI，既适合脚手架自修改，也适合用可执行奖励训练参数；风险是测试不完整、Verifier 过拟合和针对 Benchmark 的 Harness 特化。
* **网页自动化**面对稀疏延迟反馈、界面漂移和 Prompt Injection。跨会话记忆和 Grounding 能快速适应，但评估必须测试网站与布局变化，而不能只看固定快照。
* **游戏与策略推理**有可重置环境和 Self-play，但固定对手池可能掩盖策略循环、非传递性、脆弱约定、说服或欺骗行为。
* **科学发现**依靠可执行工作流、模拟器、领域工具和批评，但实验昂贵、噪声大且只有部分结果可形式验证，因此进展应绑定到可复现实物和来源链，而不是叙述质量。
* **具身 AI 与通用计算机控制**增加了 Sim-to-real、安全约束、昂贵 Rollout、脆弱界面和长时状态跟踪问题，使权限边界和失败恢复本身成为改进目标。

# 核心结论

1. **持久性区分普通适应和自我改进。** 任务内重试、更长历史或临时计划只有在改变智能体持久配置时才算自我改进。
2. **脚手架是天然实验层。** Prompt、记忆、工具和控制逻辑可观察、可回滚；参数固化应该以稳定迁移证据为前提。
3. **Critic 是需要治理的基础设施。** 同一系统若既提议又接受更新，容易形成自我确认回路。最终评估应独立于改进信号，Critic 自身的演化也要受限且可审计。
4. **评估必须看完整轨迹。** 应在固定计算、Token、时间、工具和人工监督预算下报告学习曲线、留出迁移、旧任务回归、安全违规、方差和总成本，而不是只报告最高终点分数。
5. **完整自修改应按不可信代码处理。** Prompt Injection、记忆污染或工具劫持一旦被固化，会从单次失败变成架构漏洞；候选更新需要功能、权限、回归、扰动和安全多层门控。

本文是大规模分类与设计综述，不是一个新自我改进系统的控制实验。它的证据主要来自形式化、历史梳理、定性比较和对快速变化文献中已报告结果的归纳。广度使它非常适合作为共同词汇和检查表，但不同方法使用的模型、任务、预算、人工监督和评估协议并不一致，不能据此判断哪类机制整体更成熟或更安全。记忆对象评分表也明确是定性判断，不是统一 Benchmark 的统计结果。因此，论文最强的贡献是概念整合；它提出的部署原则仍需在具体领域中独立验证。

# 开放问题

* 系统应如何先把失败正确归因到模型参数、Prompt、上下文组装、记忆、工具接口或控制逻辑，再选择更新对象？
* 什么准入规则能够把经过验证的脚手架行为安全地固化进参数，同时保留稀有恢复策略并重新确认安全边界？
* Critic 如何在不受被评估智能体任意控制的条件下继续演化？
* 哪种记忆更新策略能够同时保存来源、解决矛盾、抵御污染并支持主动遗忘？
* 当方法在任务成功率、Token、时间、工具调用、模型训练、人工复核和回归风险之间交换时，应如何定义改进效率？
* 多智能体能否通过版本控制共享测试、补丁、工具和技能，同时避免传播被污染的奖励或形成共享单点故障？
* 什么样的非平稳 Benchmark 能区分真实持续适应与反复针对静态接口和隐藏测试优化？
