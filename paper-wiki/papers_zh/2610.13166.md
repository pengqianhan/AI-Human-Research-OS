# Q1 问题定义

* **输入（X）：** 对合成引擎而言，是从文档、代码仓库、issue 报告和专业资料中找到的真实专业工作，加上已被接受的任务集合，以及此前调研和评审留下的记录。对训练出的智能体而言，是任务包的公开部分 $\mathcal{P}(T) = (I, E)$：指令 $I$ 和可执行的终端环境 $E$。
* **输出（Y）：** 引擎产出任务包 $T = (I, E, S, V, M)$，包含参考解 $S$、私有验证器 $V$ 和执行配置 $M$（即 Terminal-Bench 的任务包格式）。教师模型在这些环境中产出多轮轨迹。训练产出一个能完成长时程终端任务的模型。
* **约束：** 验证器只能检查智能体能从指令中读到、或能在环境中发现的要求（论文公式 3）；测试数据可以保密，但评分不能引入无法发现的要求。整条流水线全自动。
* **核心问题：** （i）任务可以写明要调查、实现和验证，但提供的材料可能已经把其中一部分做完了，于是采集到的轨迹直接跳过这些工作；（ii）任务更长或更难，并不会自动让后面的工作依赖前面的结果，而这正是作者所说的行为模式“跨阶段连接”。

# Q2 问题新颖性

为微调而合成终端任务已经是一条很拥挤的路线：论文表 1 列出了来自十四个系统的二十个已有模型。论文声称的空白在于时程以及时程里装了什么。作者认为，现有合成方法产出的轨迹较短，能展示命令和工具调用，却展示不了持续的问题求解；他们用一套 27 种“智能体行为模式”的分类来描述目标，分为五族（信息探索与判断；诊断与纠错；构建与工作推进；验证与结果确立；策略与执行协调）。论文点名的最接近的已有工作是对参考解做递归扩展的 RST（Li et al., 2026a），它同样会把任务拉长；TerminalHorizon 的区别是用实际执行来检查预期的工作是否仍然必须由智能体完成。

# Q3 科学假设

1. **独立执行能暴露环境预先做掉的工作。** 让一个没有参与构建的智能体只凭公开任务包去尝试任务，把它的轨迹与任务种子预期的工作对比，就能找出由构建造成的缺口（环境自带的求解器、预置的恢复路径、已经给出的决定），再重建任务，让这些工作变成必须做的。
2. **在同一目标下扩展任务，能把模式延续到多个阶段。** 如果新增要求依赖任务前面获得的证据、产物和状态，得到的轨迹就会包含更长的、由反馈串起来的动作链。
3. **这样的轨迹数据效率高。** 用几千条这样的轨迹微调模型，在终端基准上的提升会超过用多得多的短轨迹训练出的模型，而且提升能迁移到其他智能体任务，同时不损害通用推理。

# Q5 关键解决思路

**阶段一：挑战引导的长时程合成。** 每个任务有一个内循环，每一批任务有一个外循环。

* **Planner 智能体。** 阅读已接受的任务和累积的记录，为下一批写调研简报：工作范围、尚未覆盖的要求，以及要调查的真实来源。
* **Deep Research 智能体。** 按简报查阅文档、仓库、issue 报告和专业资料，产出任务种子：一份指令草稿，加上关于智能体必须发现、实现或调试什么的证据。
* **Construction 智能体。** 把指令、环境、参考解、验证器和配置放在一起构建，并遵守“验证器只检查有公开依据的要求”这条规则。
* **独立挑战者。** 一个看不到调研记录、设计蓝图、参考解和私有测试的智能体去尝试候选任务。随后的合成评审阅读任务包、轨迹和得分，记录运行缺陷、信息泄漏、评分不一致，以及预期的工作是否被保留。
* **时程缺口分析与重建。** 把种子预期的工作与挑战者实际做的对比，把被省掉的工作追溯到初始材料、对象关系或工具行为。任务被修订后再次接受挑战。评审要区分两种情况：一种是确实做了工作的高效解法，另一种是环境预先把工作做完了。被接受的任务和所有记录会进入下一批的规划。

**阶段二：渐进式时程扩展。** Evolution 智能体在同一目标下为已接受的任务提出扩展，并检查父任务的解是否已经满足新要求。内容上有四个方向：更广的角色、更深的机制、更丰富的证据、方法升级。交互上有三种设计，把新工作与此前的进展绑在一起：后面的决定依赖通过探查获得的证据；可观察的工具或系统效应把前面的操作与后面的诊断联系起来；在固定的公开规格下，对象或状态在不同运行之间变化。被接受的子任务成为下一次扩展的父任务。

**附录中的实例。** 在一个射电干涉校准任务中，第一版环境自带 `solve-bandpass` 和 `solve-gain` 工具，挑战者调用它们就通过了；重建去掉了拟合例程，保留了检查和残差反馈，于是下一个挑战者必须自己实现并修改拟合。一个 RabbitMQ 网络分区恢复任务经历了五轮重建和六次挑战，因为在中间版本里恢复分支虽然存在，运行中的环境却从未触发它。论文从这个案例得出的结论是：增加一个分支并不增加工作量，除非执行真的走到那里。

# Q6 实验设计

* **数据。** 1,535 个任务环境，覆盖 25 个专业领域。每个任务由 DeepSeek-V4-Pro-0813 在 [Terminus 2](../concepts/terminus-2.md) harness 下产出两条轨迹，再由 LLM 评审（gpt-5.6-luna，高推理强度）按三条标准过滤：轨迹有效性、基于环境的进展、多轮训练价值。评审看不到最终得分，过程可靠的失败轨迹会被保留。最后留下 2,852 条轨迹（TerminalHorizon-3K）。
* **训练。** 用 LLaMA-Factory 对 Qwen3.5-27B 做全参数 SFT：学习率 $1\times10^{-5}$，余弦调度，三个 epoch，最大序列长度 262,144，不做序列打包，144 张 H20 GPU。同样的配方也用于 Qwen3.5-35B-A3B 和 Qwen3.5-122B-A10B。
* **评测。** 十二个基准：Terminal-Bench 1.0（80 个任务）、2.0 和 2.1（各 89 个任务），通过 Harbor 与 Terminus 2 运行，每个任务三小时，取三次运行的平均 pass@1；AutomationBench v1.0.6（600 次 rollout，三次运行）；τ²-Bench 的 Airline 和 Retail（每个任务四次运行）；VitaBench 英文跨领域集（100 个任务，Avg@4）；MATH-500、GSM8K、AIME 2024、AIME 2025 和 KOR-Bench Cipher（三次运行）。
* **分析。** 与其他合成方法的轨迹统计对比（各抽 300 个任务，相同教师协议）、在 100 个抽样任务上比较两个教师模型、三种模型规模、数据规模曲线、Terminal-Bench 2.1 分类别结果，以及四个 12 小时的 RSI-Exam 案例研究。
* **去污染。** 把全部 1,535 条训练指令与 3,251 个评测实例对比，方法包括 13-gram 和 14-gram 精确重叠、5-gram Jaccard、TF-IDF 余弦，以及保留数学符号的 8-gram 检索；190 对候选由 gpt-5.6-luna 评审。

# Q8 证据质量

* **有支撑的结论。**
  * *轨迹确实更长。* 平均 52.8 个交互轮次，90 分位为 98，在相同教师协议下高于所有被比较的合成方法（论文图 4）；由反馈连接的最长动作链中位数为 25 轮；每条轨迹平均包含 8.6 种核心模式。
  * *微调在终端任务上有帮助。* Terminal-Bench 1.0 从 46.3 升到 55.0，2.0 从 41.6 升到 55.8，2.1 从 46.82 升到 60.67。在 2.1 上，微调模型在全部 16 个类别中持平或超过基座，其中 11 个有提升，提升最大的是调试（+46.7 个点）、数据科学（+25.0）和机器学习（+22.2）。
  * *提升不限于某一个基座模型。* 27B、35B-A3B 和 122B-A10B 在 Terminal-Bench 2.1 上分别提升 13.85、13.11 和 14.98 个点。
  * *能迁移到其他智能体基准。* AutomationBench 的 Pass Rate 从 5.5 到 17.2，Partial 从 26.4 到 49.7；VitaBench 从 20.5 到 31.8；τ²-Bench Airline 从 79.0 到 84.5，Retail 从 84.9 到 87.5。
  * *文本层面的去污染没有发现问题。* 没有 13-gram 或 14-gram 的精确匹配，5-gram Jaccard 最大为 0.006，190 对被评审的候选中没有一对被判为污染。
* **比标题结论更弱或更窄之处。**
  * *两个阶段从未被消融。* 没有模型是在重建之前的初版任务上训练的，也没有只用阶段一任务不做扩展的，或用同一流水线产出的、长度匹配的短轨迹训练的。说明“挑战引导的重建和扩展导致了提升”的证据只有附录 H 和 I 的案例，以及长度统计。实验表明这份数据集有效，但没有表明引擎的哪一部分让它有效（读者观察）。
  * *“不到十分之一的数据”数的是轨迹条数。* TerminalHorizon-27B 用约 3k 条轨迹在 Terminal-Bench 2.0 上得到 55.8，Terminal-Universe-27B 用 32.0k 条得到 52.8，两者基座模型和 harness 相同。但这里的轨迹按设计就长好几倍，训练序列最长可达 262,144 token；两边都没有报告 token 总量，所以这个比较不能说明按 token 计的效率（读者观察）。这 3.0 个点的差距，也是在和另一篇论文报告的数字比较。
  * *Terminal-Bench 2.0 的基座分数不是作者自己跑的。* 41.6 标注为取自官方模型卡，而微调模型的 55.8 来自本文的协议（三小时上限、三次运行、带 JSON 解析器的 Terminus 2）。1.0 和 2.1 的对比没有这个标注。
  * *结果同时也是蒸馏。* 轨迹来自 DeepSeek-V4-Pro-0813，论文没有给出它自己的基准成绩；在 100 个任务的抽样上，它通过了其中 50.0%。没有对照实验是用同一教师在其他合成方法的任务上产出的轨迹来训练的（读者观察）。教师对比表明这些任务也能让 GLM-5.2 产出长轨迹（平均 46.1 轮，对比 53.5 轮），但没有模型是用 GLM-5.2 的数据训练的。
  * *推理上的提升样本很小。* AIME 2024 和 2025 各只有 30 道题，所以 +3.4 和 +6.6 个点大约相当于一道题和两道题（三次运行平均）。“保持”有支撑；“增强”的依据很薄。
  * *RSI-Exam 研究是四次单独运行。* 四个案例中有三个，基座模型分别在 0.20、1.12 和 1.28 小时后自行停止，而微调模型用满了 12 小时，所以这些提升（归一化分数 +27.03、+20.74、+7.71）同时反映了坚持程度和研究质量；论文把“继续做下去”当作要展示的能力。第四个案例中两者都运行了约 11.4 到 12 小时，基座模型最终提交的解丢掉了它最好的中间解所用的宏压缩（公开集成本 466.35，而记录到的最好成绩是 286.05），这是交付环节的失败，而不是搜索的失败。
  * *数据规模只有一条曲线。* 正文说从 1,000 条到约 3k 条轨迹时性能持续上升、没有饱和迹象；中间的数值只在图里。
  * *质量控制靠模型判断。* 合成评审、轨迹过滤和污染评审都是 LLM 的判断（[LLM-as-a-judge](../concepts/llm-as-a-judge.md)）；没有报告对任务质量或过滤决定的人工审核。

# Q9 贡献

* 一种检查合成任务是否被环境预先做掉了工作的办法：让一个未参与构建的智能体去解，把它的轨迹与预期的工作对比，然后重建。其中最有用的观察是，第一个挑战者往往照样通过：任务成功并不能说明任务没有被掏空。
* 渐进式扩展，把新增要求与此前的证据、产物和状态绑在一起。
* TerminalHorizon-3K 以及三种规模的微调模型，在 Terminal-Bench 和终端之外的四个智能体基准上都有提升。
* 一套 27 种模式的词汇，用来描述一条长轨迹里有什么；以及一个不看结果、只判断过程并保留有信息量的失败轨迹的过滤器。

# Q10 下一步

* **对引擎做消融（读者建议）。** 在相同 token 量下，分别用初版任务、重建后但未扩展的任务，以及完整数据集训练。没有这个实验，引擎的两个想法作为“原因”就没有被检验。
* **报告 token 量（读者建议）。** 与其他合成方法按训练 token 而不是按轨迹条数比较。
* **把坚持与能力分开（读者建议）。** 在 RSI-Exam 设置下，强制基座模型用满预算，或给两个模型都加上禁止提前停止的规则，并重复运行。
* **审核评审者（读者建议）。** 抽样已接受的任务和被丢弃的轨迹做人工复核，并报告最后一轮之后挑战者仍然发现“预置工作”的频率。
* **作者提出的。** 规模曲线没有饱和，作者认为这意味着还可以继续加数据。
* **项目契合（读者笔记）。** “挑战”这一步对本仓库里任何由智能体编写的任务或评测都是一个便宜的检查：在信任一个任务之前，让一个全新的智能体只凭公开材料去解，然后读它的轨迹，找出哪些步骤被环境设置省掉了。RabbitMQ 案例是一个提醒：代码路径存在，不等于它被执行过。

# 相关

* [智能体环境](../topics/agent-environments.md) - 一个终端任务工厂，特别之处是先让独立智能体解题，再对“预期的工作”和“实际做的工作”做缺口分析，反复重建直到这些工作确实必须做。
* [智能体微调](../topics/agent-fine-tuning.md) - 在约 3k 条长教师轨迹上做普通的全参数 SFT，轨迹由一个看不到得分、只看过程的过滤器筛选；12 个基准全部提升，但合成的两个阶段没有消融。
* [Terminal-Bench](../concepts/terminal-bench.md) - 主评测：46.3 到 55.0（1.0），41.6 到 55.8（2.0，基座分数取自模型卡），46.82 到 60.67（2.1），Terminus 2 下三次运行的平均 pass@1。
* [Terminus 2](../concepts/terminus-2.md) - 教师轨迹采集和评测都使用的 harness，也是 12 小时研究 harness 的基础。
* [AutomationBench](../concepts/automationbench.md) - 迁移基准：在 v1.0.6 上三次运行，Pass Rate 5.5 到 17.2，Partial 26.4 到 49.7。
* [τ²-Bench](../concepts/tau2-bench.md) - 迁移基准：Airline 79.0 到 84.5，Retail 84.9 到 87.5，每个任务四次运行，DeepSeek-V4-Pro-0813 担任用户模拟器和断言评审。
* [VitaBench](../concepts/vitabench.md) - 迁移基准：在 100 个任务的英文跨领域集上 Avg@4 从 20.5 到 31.8，DeepSeek-V4-Pro-0813 担任用户模拟器和轨迹评审。
* [LLM-as-a-judge](../concepts/llm-as-a-judge.md) - gpt-5.6-luna 决定哪些轨迹进入训练集，并评审污染候选；合成评审同样是模型判断。
* [通过递归自重写扩展复杂任务轨迹](../papers/2610.02826.md) - 本 wiki 中最接近的一篇：同样是对 27B 的 Qwen 模型在 Terminus 2 轨迹上做 SFT、贡献在数据环节；那篇改写轨迹，TerminalHorizon 重建任务。
* [GraphForge](../papers/2609.38923.md) - 同样在教师 rollout 之后修订每个合成任务，对象是带证据锚定评分细则的工作区任务；这里的修订针对的是环境预先做掉的工作。
* [AutoSciBench](../papers/2610.05140.md) - 同样用求解者的轨迹来修订生成的任务，目标是难度（直到所有尝试都失败），而不是保留应做的工作。
* [EnvHarness](../papers/2608.19880.md) - 诊断目标策略的轨迹来增加环境组件；TerminalHorizon 诊断挑战者的轨迹来恢复被去掉的工作。
* [CompoWorld](../papers/2609.33665.md) - 同样在 VitaBench 和 AutomationBench 上评测的环境扩展工作；它组合带类型的服务，而不是重建专业任务。
* [ProgramGym](../papers/2610.13395.md) - 另一个由智能体构建的编码环境工厂；它的检查针对弱测试，TerminalHorizon 的检查针对“因为错误的原因而过于简单”的任务。
* [AREX-2](../papers/2609.38288.md) - 同样在保留失败的完整长改进轨迹上训练；TerminalHorizon 的过滤器同样会保留过程可靠的失败轨迹。
