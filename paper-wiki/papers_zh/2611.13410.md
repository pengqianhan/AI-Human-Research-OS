# Q1 问题定义

* **输入 (X)：** 一个全精度（BF16）智能体检查点，既作为冻结的教师，也作为量化学生的初始化；一个固定的量化器（4 比特或 2 比特权重，16 比特或 8 比特激活）；状态可以保存、恢复和比较的训练环境。
* **输出 (Y)：** 一个量化后的学生模型，在多轮工具调用任务上的成功率接近教师，推理时单独运行，不需要教师，也不需要额外提示。
* **约束：** 纠正必须来自学生自己走到的上下文；每条失败的学生轨迹都需要同一任务、同一初始状态下的一条成功教师轨迹；一条纠正只有在执行后复现了参考轨迹的环境状态转移时才保留。

# Q2 问题新颖性

LLM 的低比特量化是老问题，基于训练的恢复方法（量化感知训练、蒸馏、带可验证奖励的 RL）也已经存在。论文的切入点是智能体场景。它观察到，量化后的智能体失败的方式是忽略某条任务要求或某个环境条件，例如还没进入目录就去读文件，并把由此产生的、与成功的全精度轨迹之间的不一致称为“行为偏离”（behavioral divergence）。论文认为，现有训练数据恰好在这些位置缺少纠正：离线数据不会经过学生的失败上下文，学生自己重试也很少出现正确动作。在 BFCL V4 多轮诊断中，从同一个出错前状态无引导重试四次，只有 9.6% 的偏离轮次能出现一次正确动作。

# Q3 科学假设

如果教师在第一个偏离轮次解释学生忽略了什么，由学生自己生成纠正后的回复，并用环境来检验这次纠正，那么把这些纠正轮次蒸馏进学生（上下文中不带解释），比在学生无引导轨迹上做在线蒸馏或 RL 能恢复更多的智能体能力，训练成本也更低。次要假设与损失函数有关：在纠正轮次用前向 KL 对齐“被引导的学生”，在其他轮次用反向 KL 对齐教师，比全程只用一个方向更好。

# Q4 相关工作与关键人物

* **低比特量化下的能力恢复。** 权重重构、缩放与旋转（GPTQ、QuaRot 等）；用硬标签训练（EfficientQAT）；用教师的软分布（BitDistiller）；用可验证奖励（QeRL、NVIDIA 的量化感知 RL）。
* **面向智能体的教师引导。** 教师生成的回复，以及以特权上下文为条件的轨迹（EDGE、EDGE-OPD）；FutureBridge-OPD 用后续学生轨迹中的蒸馏信号来评估教师干预；OVCSD 用任务是否成功来验证从学生失败状态出发的特权续写。SteerDistill 则在偏离轮次当场验证，对照的是参考轨迹的状态转移。
* **上下文蒸馏。** [在线策略蒸馏](../concepts/on-policy-distillation.md)（Agarwal et al.）和在线上下文蒸馏（Ye et al.）：把教师上下文中一段文字带来的好处，转移到看不到这段文字的学习者的权重里。
* **关键人物。** Genming Cui 与 Xiangyu Li（共同一作，Li 为项目负责人）、Zixu Hao、Xin Ding、Yunxin Liu、Ting Cao（通讯作者），来自清华大学智能产业研究院（AIR），其中 Cui 和 Ding 同时属于中国科学技术大学。被引用的 BitDistiller 的作者中有一位 “T. Cao”，本文沿用了它的量化器实现。可能的批评者：QeRL 和 NeMo-RL 的作者，因为他们的方法在对比中被从较新 GPU 上的 NVFP4 移植到了 A100 上的整数量化。

# Q5 核心解法

一个训练周期包含两个阶段，学生更新后重复进行。

1. **教师引导的轨迹修订。** 冻结的量化学生先跑出轨迹。对每条失败且有成功教师参考的轨迹，按环境状态转移对齐两条轨迹（效果相同的不同动作视为等价），选出学生第一个偏离的轮次，并恢复该轮之前的历史和环境状态。教师写一段结构化的引导提示（差异是什么、引导在什么条件下适用、纠正规则）；学生在带着提示的上下文中生成修订后的回复并执行。“局部验证”把执行后的状态和返回信息与参考转移做比较。失败时，教师根据这次尝试的反馈改写提示，每次干预最多 R = 4 次尝试。通过验证的回复替换掉原来失败的那一轮，学生在没有引导的情况下继续往下走；如果任务仍然失败，就在下一个偏离处重复这个过程。即使任务最终没有解决，已验证的纠正也会保留。
2. **内化。** 学习者始终看不到引导提示。在纠正轮次，它最小化相对于“带提示的冻结学生快照”的前向 KL；在其他所有轮次，它在学生自己生成的回复上最小化相对于全精度教师的反向 KL。学习者前向使用伪量化，梯度通过直通估计器回传到 BF16 主权重。

与已有的教师引导蒸馏相比，区别在于：纠正是学生在引导下自己的输出，经过执行的局部检验，并且监督来源按轮次切换。在 BFCL V4 诊断中，引导把偏离轮次的轮次级 Pass@4 从 9.6% 提高到 82.3%。

# Q6 实验设计

* **基准。** [BFCL](../concepts/bfcl.md) V4（Overall）、[τ²-Bench](../concepts/tau2-bench.md)（Pass@1）、[WebShop](../concepts/webshop.md) 和 [ALFWorld](../concepts/alfworld.md)（成功率），以及 Search QA（按 [Search-R1](../concepts/search-r1.md) 的做法，在七个问答数据集上取精确匹配的平均）。
* **模型与精度。** Qwen3-8B、Qwen3.5-4B、Gemma 4 12B-it 在 W4A16 下评测；Qwen3-8B 另外评测 W4A8 和 W2A16。每个 BF16 检查点先按任务族用 [GRPO](../concepts/grpo.md) 做后训练，然后同时作为教师和所有量化方法的初始化。
* **训练数据。** BFCL V4 和 τ²-Bench 使用 [Agent World Model](../concepts/agent-world-model.md) 的可执行工具调用任务（同一个检查点在两个基准上评测）；WebShop 和 ALFWorld 使用各自的训练环境；Search QA 使用 NQ 和 HotpotQA 的训练集。
* **基线。** GPTQ（训练后量化）、EfficientQAT、BitDistiller（离线蒸馏）、On-Policy QAD（NVIDIA NeMo-RL 的流程）和 QeRL（带可验证奖励的 RL）。所有基于训练的方法使用相同的学习率（8e-6）、批大小（16 条轨迹）和两个 epoch。
* **效率。** τ²-Bench Pass@1 随训练 GPU 小时的变化（8 块 A100，包含引导和验证的时间），以及每个成功任务的输出 token 数。
* **消融（BFCL V4，Qwen3-8B，W4A16）。** 在哪里干预、谁来产生纠正、谁来写提示以及用什么格式、是否验证以及是否要求最终成功、KL 的分配方式。

每个声称的组件都有对应的消融，但只在一个基准、一个模型上做。

# Q7 数据集与代码

没有新数据集。评测用公开基准，训练用 Agent World Model 的任务和各基准自带的训练环境。量化沿用 BitDistiller 的非对称分组整数量化实现，权重分组大小为 64。τ²-Bench 的用户模拟器是温度为 0 的 GPT-5.6。代码链接为 https://github.com/air-embodied-brain/SteerDistill，项目页为 https://air-embodied-brain.github.io/SteerDistill；本笔记没有检查这两处的内容。

# Q8 证据质量

**主表（五个基准得分的平均，百分比）。**

| 模型与精度 | BF16 | 最强基线 | SteerDistill | 与 BF16 的差距 |
|---|---|---|---|---|
| Qwen3-8B，W4A16 | 53.54 | 51.00（QeRL） | 53.18 | 0.36 |
| Qwen3.5-4B，W4A16 | 61.68 | 59.24（QeRL） | 60.95 | 0.73 |
| Gemma 4 12B-it，W4A16 | 65.13 | 62.64（QeRL） | 64.31 | 0.82 |
| Qwen3-8B，W4A8 | 53.54 | 49.69（QeRL） | 51.62 | 1.92 |
| Qwen3-8B，W2A16 | 53.54 | 39.58（On-Policy QAD） | 42.97 | 10.57 |

与 BF16 的差距是读者自己做的减法。除了 W2A16 下的 Search QA（34.05，低于 BitDistiller 的 34.22）之外，SteerDistill 在每个区块的每个基准上都是最好的。“与 BF16 相差不到一分”只对三行 W4A16 成立；在 2 比特权重下，方法领先基线 3.39 分，但仍比全精度低十分以上。

**训练成本。** 在 Qwen3-8B 的 τ²-Bench 上，32 GPU 小时的检查点达到 31.68% Pass@1，而 QeRL 在 96 GPU 小时为 29.84%，On-Policy QAD 在约 40 GPU 小时为 28.77%。“少用 67% 的 GPU 小时”指的是 32 对 96。曲线是每个检查点四次评测运行的均值。

**推理成本。** τ²-Bench 上成功任务平均输出 4.0K token（BF16 为 3.9K，量化基线为 4.1K 到 5.2K），11.6 个交互步（BF16 为 11.4，基线为 12.1 到 13.8），4.24 次工具调用。每个平均值都是在该方法自己成功的任务上算的，所以任务集合并不相同，附录也说明了这一点。

**消融（BFCL V4 Overall；完整方法 46.84，On-Policy QAD 44.43）。**

| 改动 | 得分 |
|---|---|
| 在随机的可干预轮次干预 | 43.52 |
| 在第一个动作不一致处干预 | 45.01 |
| 学生无引导重试 | 44.46 |
| 教师直接接管该轮 | 45.06 |
| 教师写自由格式提示 | 44.78 |
| 学生自己写结构化提示 | 41.74 |
| GPT-5.6-Sol 写结构化提示 | 45.27 |
| 不做局部验证 | 42.18 |
| 只保留最终成功任务中的纠正 | 46.30 |
| 全程反向 KL | 45.29 |
| 全程前向 KL | 44.58 |
| KL 分配方式反过来 | 44.28 |

有三个变体低于普通的在线蒸馏：随机干预、学生自己写提示、不验证纠正。错误的纠正比没有纠正代价更大。让更强的外部模型来写提示（45.27）不如同族的全精度教师。

**证据的局限（读者观察）。**

* 表 1 没有区间，也没有说明每个格子训练了几次；只有 τ²-Bench 的效率曲线展示了波动（四次评测运行）。在单个基准上对 QeRL 的优势是一到三分。
* 去掉初始的 GRPO 后训练之后（Qwen3-8B，W4A16），对 QeRL 的领先缩小到 BFCL V4 上 0.82 分（39.67 对 38.85）、τ²-Bench 上 0.13 分（29.05 对 28.92）。论文把这张表解读为排序不变；τ²-Bench 上的差距太小，没有区间就不能算成立。
* W4A8 区块的 30 个数全部是 0.05 的倍数，其中 21 个是 0.1 的倍数；而 W4A16 和 W2A16 区块分别只有 55 个中的 4 个、30 个中的 1 个落在 0.05 的网格上（对 HTML 表格做的脚本检查）。Qwen3.5-4B 的 BF16 行也只给到一位小数。论文没有说明这些区块是否以不同的方式产生或取整。
* QeRL 和 On-Policy QAD 是从它们的参考配置（较新 GPU 上的 NVFP4）移植到 A100 上的分组整数量化的，所以它们的数字是本文的改写版本。
* 在消融表中，完整方法的 Non-Live 得分（88.29）高于 BF16（87.14），可见学生并不是在每个子集上都被教师封顶。
* 9.6% 和 82.3% 这两个诊断数字衡量的是训练期间在引导下是否出现正确动作，而不是蒸馏后的学生独立运行时的表现。

核心主张，即“经过局部验证、由学生自己生成的纠正，比无引导轨迹更适合作为蒸馏目标”，得到了一个基准上的消融和 W4A16 下十五个“基准-模型”格子里一致的优势的支持。相对于 RL 的优势有多大，没有表格看上去那么确定。

# Q9 贡献

1. 描述了量化智能体的失败方式（忽略要求和条件，表现为与成功的全精度轨迹之间的状态转移偏离），并测得学生自己重试几乎无法修复这些偏离。
2. 闭环教师引导：按环境状态定位偏离、根据执行反馈改写的结构化引导、对照参考转移的局部验证。
3. 一个按轮次分配的蒸馏目标，把被引导的行为内化到不带引导的学生中。
4. 在五个基准、三个模型、三种精度上的结果，以及训练成本和轨迹长度的比较。

# Q10 后续方向

* **论文承认的局限。** 方法需要成功的教师参考、可恢复的环境状态和可靠的局部验证；缺少其中任何一项的情形都没有测试。没有成功参考的失败轨迹得不到纠正，所以教师自己解不了的任务不会被触及。局部验证只检查一次状态转移，不检查推理过程，也不保证最终结果。
* **报告波动。** 在多个训练种子上重复 W4A16 的比较，至少在领先最小的“无 GRPO”设置下这样做（读者建议）。
* **量化之外。** 这个闭环只需要一强一弱两个策略共用一个状态可恢复的环境。可以尝试用它把大智能体蒸馏成小智能体，那时两个模型不共享检查点（读者建议；论文中 GPT-5.6-Sol 写提示的结果提示，不匹配的教师引导效果会差一些）。
* **无法恢复状态的环境。** 网页和桌面任务很少允许恢复状态；需要基于重放的、或近似的局部验证。
* **涌现出的恢复能力。** 附录展示了蒸馏后的学生在轨迹中途从执行错误中恢复，而这并不是训练目标。统计这种情况出现的频率，可以判断方法教会的是具体的修复，还是更一般的“先检查前置条件”的习惯。
