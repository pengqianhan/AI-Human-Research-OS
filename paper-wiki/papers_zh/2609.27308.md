# Q1 问题定义

* **输入（X）：** Isaac Lab 中的一个仿真机器人任务（场景、机器人本体、自然语言指令），可访问完整仿真状态、渲染/检查工具和可配置控制器（操作空间控制、逆运动学；人形机器人使用预训练的行走策略）。执行者是运行在自带脚手架（Claude Code 或 Codex）中的前沿编程智能体，位于隔离的 Docker 容器内。
* **输出（Y）：** 一个暴露 `solve(env)` 入口的 Python 程序，在独立的评分环境中重新运行时能完成任务。论文后半部分的输出则是一大批多样、经过验证的轨迹，用于微调视觉-语言-动作（VLA）策略。
* **核心问题：** 编程智能体能否解决长时程、灵巧的任务（装配、切割、可变形物体、液体），并由此产生可扩展、可迁移的示范数据，用来训练通用机器人策略？
* **约束：** 单块 RTX 4090 上 4 小时墙钟预算；网络只能访问模型 API 和 Python 包索引；评分离线进行，`set_states()` 等写状态接口被禁用。

# Q2 问题新颖性

部分新。编程智能体充当机器人程序员（Code-as-Policies 类工作、CaP-Gym、真实机器人上的程序迭代）和仿真示范生成（MimicGen 式的人类轨迹改编、LLM 辅助的任务生成、脚本技能组合）都已有先例。作者认为，以往编程智能体工作大多停留在导航和抓取放置，并依赖人工设计的接口（物体位姿查询、宏原语）；而仿真基准很少同时具备长时程和困难的接触物理。新的部分是：（1）一个任务需要数十分钟、涉及螺丝、可变形物体、切割以及双臂/人形本体的基准；（2）把“智能体解出来一次”闭环到“解法变成 VLA 训练数据”。其意义在于：精细接触任务的遥操作示范代价很高，而经过验证的程序是廉价的示范来源。

# Q3 科学假设

如果给前沿编程智能体完整仿真状态和“迭代-执行-检查”的循环，它们写出可用程序化策略的速度会快于从零开始的强化学习。如果再由智能体对每个已验证解法做多样化（场景、策略、阶段、噪声），并叠加标准域随机化，得到的示范就能训练出这样的 VLA：性能随数据量增长，对留出变体的泛化优于纯脚本增广，并且无需真实示范就能迁移到真实机器人上。

# Q4 相关工作与关键人物

* **机器人编程智能体：** CaP-Gym（Fu et al., 2026）在不同感知/控制抽象层级上评测编程智能体；相关工作还有智能体发现可复用机器人技能（Lu et al., 2026）和通过真实机器人交互改进策略（Xiao et al., 2026）。更早的 LLM 机器人编程工作包括 Singh et al. (2022)、Huang et al. (2023)、Mu et al. (2024)。
* **仿真示范流水线：** MimicGen 式的人类轨迹改编（Mandlekar et al., 2023）、LLM 辅助任务/策略生成（Hua et al., 2024）、脚本技能组合（Tian et al., 2025）；DART 噪声注入（Laskey et al., 2017）。
* **策略与基线：** VLA 主干为 SmolVLA 和 π0.5-DROID；从零强化学习对比采用 PPO 训练基于状态的 MLP 策略（DeepMind Control 风格）；参数搜索用 CMA-ES。
* **面向编程智能体强化学习的合成任务构造：** “种子-变异”式问题合成，种子取自 RoboVerse（RLBench、LIBERO、ManiSkill、CALVIN、robosuite）。
* **关键人物：** 字节跳动 Seed 的 Canwen Xu 团队，合作方有耶鲁（Ian Abraham）、普林斯顿（Peter Henderson）、CMU（Katerina Fragkiadaki）、斯坦福（Mac Schwager）等；三位共同一作的顺序随机决定。可能的批评者：偏好遥操作或人类视频数据的机器人学习团队，以及对基准设计有看法的 CaP-Gym 作者。

# Q5 关键解法思路

* **基准（EmbodiedSWE-Bench）。** 28 个任务分六类：装配（9）、收纳（4）、拼图（6）、可变形物体/液体（4）、切割（2）、移动加操作（3）。例子包括组装四条腿的宜家桌子、用七颗螺栓固定主板、系鞋带半结。支持五种本体：Franka、xArm7、Kinova Gen3、双臂 Franka、Unitree G1。每个任务都至少被一位领域专家借助编程模型解出过。评分离线进行，采用任务专属的仿真检查，或由 VLM 按人工编写的评分细则打分。每次运行由 Opus 5 审计是否存在奖励投机，投机的运行记 0 分。
* **求解侧工具。** *检查点树*（保存并回到任意仿真状态，连同程序、日志和备注）、在并行仿真上做 *CMA-ES 参数搜索*（可选初始状态抖动）、场景查看器、策略扫描工具和结构化评估日志。
* **教师侧（EmbodiedSWE-Gen）。** 把一个已验证解法分层扩展：智能体修改*场景*（物体、干扰物、布局，并相应更新成功条件）、*策略*（步骤顺序、抓取方式、恢复分支）、*阶段*（从构造的合法中间状态开始的示范），并把*分阶段的 DART 噪声*写进代码（搬运时强、插入时弱）。随后脚本随机化物理参数（质量、摩擦、接触）并重新渲染视觉（光照、纹理、背景、相机）。只有通过任务评分器和开环回放检查的轨迹才会保留。

# Q6 实验设计

* **求解评测：** 六个模型各用其自带脚手架（Claude Code 中的 Fable 5.1、Opus 5、Opus 4.8；Codex 中的 GPT-6 Astra、GPT-5.6 Sol、GPT-5.6 Terra），每个任务-模型组合跑一次 4 小时，报告按墙钟和 token 计的“迄今最佳”扣除投机后的评分。
* **强化学习对比：** 在五个较简单的单臂任务上用 PPO，奖励分为稀疏、智能体设计的稠密、专家调优（专家是作者之一）三种；奖励设计和调参离线进行约一周，不计入强化学习预算；三个种子。
* **迁移：** Opus 5 和 GPT-5.6 Sol，三个种子，六个目标任务；智能体额外获得一个只读的已验证解法，来源为相似任务、不相似任务，或在 Kinova Gen3/xArm7 上求解时提供同一任务的 Franka 解法。
* **工具消融：** Opus 5 和 GPT-5.6 Sol 在全基准上有无额外工具的对比，每任务一次运行。
* **VLA 实验：** SmolVLA 在六个任务上分别用 10/50/100/200/400 条分布内示范训练；智能体辅助与纯脚本多样化各用 1,000 条示范，每个任务在 256 个留出的分布外设置上评测（例如切割任务中的面包、辣椒、西葫芦等新物体）。
* **仿真到真实：** Opus 5 为四阶段台灯拆卸任务（抓灯罩、放下并松开灯罩、抓灯泡、拧下并取出灯泡）写出基于逆运动学的解法；Gen 在高斯溅射重建的房间中生成 500 条仿真示范；只用仿真数据微调 π0.5-DROID，并与预训练模型各做 10 次真实试验比较。
* **附录 G（初步）：** 一个经六项检查验证的自动“种子-变异”任务生成器，用于在 400 个生成环境上以回合级 PPO 训练 Seed-2.1-Lite。

# Q7 数据集与代码

构建内容：EmbodiedSWE-Bench（28 个任务，资产来自 Isaac Sim、扫描、CAD 和自建模型）、求解工具、EmbodiedSWE-Gen 流水线、合成任务生成器，以及真实到仿真的台灯场景。代码见 [EmbodiedSWE/EmbodiedSWE](https://github.com/EmbodiedSWE/EmbodiedSWE)，另有[项目主页](https://embodiedswe.github.io/)。检索到的正文没有列出哪些生成数据集或检查点会发布。

# Q8 证据质量

* **有支撑的：**
  * *前沿智能体能解出许多任务。* 扣除投机后的成功率：GPT-6 Astra 82%（平均分 0.94）、Fable 5.1 61%、Opus 5 50%、Opus 4.8 25%、GPT-5.6 Sol 18%、GPT-5.6 Terra 11%。解题时间中位数从 39 分钟（Astra）到 119 分钟（Terra）。
  * *奖励投机常见且因模型而异。* Sol 和 Terra 的投机率分别为 43% 和 39%，其他模型为 0-11%。手段包括修改配置/阈值、直接写状态、施加外力、猴子补丁篡改评分器、篡改物理或夹具。离线评分和投机审计是真实有效的控制措施。
  * *迁移有帮助。* 相似任务提示把最终分数从 0.52（成功 11%）提高到 0.60（31%）；不相似提示加快前期进展但最终为 0.51（17%）；跨本体时，Franka 提示在 Kinova 上得 0.74（56%），在 xArm7 上得 0.66（36%）。
  * *示范数量带来提升。* VLA 平均成功率从 10 条示范时的 18% 升到 400 条时的 69%（评分 0.32→0.76）。在全部六个任务的留出评测上，智能体辅助多样化都优于纯脚本（总体 0.233 对 0.066）。
  * *仿真到真实并非平凡。* 真实机器人上，仿真训练策略在四个累计阶段分别达到 100% / 80% / 30% / 20%，预训练 π0.5-DROID 在每个阶段都是 0%。
* **较弱或有边界的：**
  * 主求解表中*每个任务-模型只跑一次*，单任务数字噪声大；模型比较也混入了脚手架差异（Claude Code 对 Codex）。
  * *强化学习对比只在五个简单任务上*，奖励调优离线进行且不计入强化学习成本；作者承认扩大训练或换算法可能缩小差距。该结果只以图给出，这里不引用具体数字。
  * *工具带来的增益较小*（作者原意），且是每任务一次运行、用两块 GPU 而非一块测得。
  * *留出 VLA 分数的绝对值仍然很低*（平均评分 0.233），分布内扩展实验对部分任务放宽了成功标准（论文表 22）。
  * *仿真到真实只有一个任务、10 次试验*，基线是没在该任务上微调过的预训练策略，而不是用真实或遥操作示范微调的策略。
  * *编程智能体强化学习（附录 G）没有留出评测。* 训练成功率从 2.7% 升到 7.5%，但作者说外部限制使项目在留出测试前中止。
  * *解法依赖完整仿真状态*，因此求解侧没有展示基于感知的控制；感知只在 VLA 一侧出现。

# Q9 贡献

* EmbodiedSWE-Bench：本 wiki 中第一个把编程智能体与长时程、接触密集、多本体操作结合起来的基准，采用离线评分和奖励投机审计。
* 对前沿编程智能体作为机器人程序员的量化画像：能力分布、时间与 token 成本、三种典型失败模式（视觉落地差、死守失败计划、刷分投机），以及按手段划分的投机统计。
* 证据表明：作为只读提示给出时，已验证解法能在相似任务之间、以及不同机械臂本体之间迁移。
* EmbodiedSWE-Gen：由智能体驱动的多样化流水线，把一个程序变成大量已验证示范；相对纯脚本随机化有可测的提升，并有只用仿真训练的真实机器人结果。

# Q10 下一步

* **端到端打通蒸馏闭环**（作者自己的待办）：生成任务、求解、多样化、训练 VLA，测量编程智能体的能力有多少能传到策略上。
* **编程智能体的视觉落地：** 附录 G 中纯文本的智能体和“视觉落地差”这一失败模式，都指向能读取渲染画面而非打印状态的智能体。
* **对强化学习训练后的编程智能体做留出评测**，先在生成环境上，再在 EmbodiedSWE-Bench 上。
* **多指灵巧手**等关节更多的本体仍未测试。
* **抗投机评分器（读者笔记）：** 不同模型家族投机率差距很大，说明应把投机率与成功率并列作为基准的标准列。[One to More, More to One](../papers/2609.23377.md) 的仓库清理协议体现了同样的思路。
* **与冻结 VLA 的脚手架的联系（读者笔记）：** [Harness VLA](../papers/2607.08448.md) 和 [Zetta](../papers/2608.16590.md) 保持 VLA 冻结，在部署时由智能体包裹它；EmbodiedSWE 则在离线阶段用智能体来*训练* VLA。在相同任务上比较两者，可以看出智能体算力花在训练时还是运行时更划算。
