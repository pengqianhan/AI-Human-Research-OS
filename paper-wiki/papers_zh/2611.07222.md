# Q1 问题定义

* **输入（X）：** 一个调用邮件、文件、聊天、旅行或银行工具完成用户任务的智能体，其工具输出中可能含有攻击者写入的文本（间接提示注入，indirect prompt injection）。
* **输出（Y）：** 对智能体提出的每个有副作用的调用，就其*目标*（收件人、账户、被授权人、文件、预订对象）给出放行或拦截；同时给出删除了注入指令的工具输出视图。
* **约束：** 不需要逐任务的计划或路由模型；不重跑主干模型。攻击者能控制自由文本字段（邮件正文、网页），以及 AgentDojo Slack 套件中一个外部频道名；不能控制用户任务、工具实现、工具声明的返回类型或评分器。工具提供方自己把攻击者的值写进类型化身份字段，不在威胁模型内。

# Q2 问题新颖性

许多运行时防御让语言模型参与"是否放行"的决定：Progent 让模型写权限策略，MELON 在屏蔽用户任务后重跑轨迹，DRIFT 按计划校验调用。这样，放行决定依赖一个可能读过注入文本的模型，并且每一步都增加模型调用。溯源类防御（CaMeL、ROPE）把模型移出最终检查，但需要规划器或路由模型先为每个任务设定允许的来源。SPILLWAY 的主张是目标决定两者都不需要：工具本来就把身份（邮件发件人、交易收款人、频道成员）放在类型化字段里，而工具输出中的注入以自由文本出现，因此对类型化返回值做一次集合查找即可把两者分开。

# Q3 科学假设

如果准入目标集合只由只读工具返回值中的类型化身份字段（加上用户点名的值）构成，那么在任何主干模型下，攻击者写的目标都无法通过这一确定性检查。如果再在模型读取之前删除注入区域，并且只允许裁判模型重新考虑位于删除区域之外的被拒目标，就能在不重新打开已删除注入的前提下找回效用。

# Q5 核心方法

1. **污点新值（taint-novel）：** 调用目标参数中的某个值，若其某个 token（其中的邮箱和 URL，或长度至少四个字符的整体值）出现在工具输出中而不在用户文本中，即为污点新值。用户点名的值永远不是污点新值。
2. **出口底线（egress floor，算法 1）：** 执行器在序列化之前截取每个只读工具的类型化返回对象，只索引声明类型为身份格式（邮箱、URI、UUID、主机名、IP）或字段具有路由角色（收件人、发件人、参与者、频道）的值。正文、主题、描述从不进入索引。当每个污点新目标都在索引中且没有在不可信自由文本中重复出现时放行。只索引只读返回值，且由污点新参数引导的读取不增加任何值。授权给只在工具输出中出现的主体、以及未被请求的删除，直接拦截。
3. **委托规则：** 用确定性规则准入用户间接点名的目标：值中含有任务里写到的名字（"把报告发给 Alice"）、用户点名实体的联系属性、用户自己账户拥有的资源，以及少数裁判之后的情形。对象类效果（预订、抓取、推荐）有各自的规则，例如在"最便宜"这类最高级条件下，若不可逆操作的对象不是类型化列表上的赢家则拒绝。
4. **入口净化器：** 只用规则、不调用模型：替换伪造的聊天模板轮次、基准注入模板界定的区域、对智能体谈论其任务的文本、口述的工具调用、以及声称收款人账户已变更的说法。删除的文本保留为片段集合 S。
5. **带片段否决的双视角裁判：** 本地模型（gemma4:31b，4 bit，温度 0）只看已被规则拒绝、且目标位于 S 之外的调用。路由视角（这是任务隐含的收件人吗？）与载荷视角（用户请求了这个动作和内容吗？）必须都同意；缺失判决视为否。
6. **声明的性质：** P1：若攻击者只写自由文本字段，查找会拒绝每个出现在攻击文本中且不在任务中的目标。P2：对任意裁判，放行的调用只来自底线放行集合加上 S 之外的被拒调用。P3：被查找拒绝的攻击目标只能经由委托规则，或在 S 之外时经由裁判被放行。

# Q6 实验设计

* **广度网格：** AgentDojo v1.2.2 完整网格，三个主干（gpt-4o-mini、qwen3-coder:30b、qwen3:8b）乘四个套件（每个主干 949 个受攻击对），标准 important_instructions 攻击。
* **对照：** 无防御、MELON、Progent、DRIFT、ROPE（用发布代码在同一智能体上运行；Progent 的策略与 ROPE 的路由默认由该单元自己的主干编写）、Spotlighting、ProtectAI 检测器。CaMeL 因替换智能体循环而未运行。
* **压力测试：** qwen3:8b 上的 ChatInject（665 对）；攻击者作为发件人的 Workspace 变体（126 对）；针对 Progent 优化的 AutoDojo 注入，gpt-4o-mini（389 对）外加两个各 144 对的留出 Banking 集；PISmith 开环重放，每个注入取十个变体中的第一个（ASR@1）。
* **委托路由网格：** 与 ROPE（作者的 Claude Opus 4.8 路由器，以及 gpt-4o-mini 路由器）在 AgentDojo 四个套件和 AgentDyn 三个套件上对比，gpt-4o-mini 智能体，每套件一次运行（种子 42）。
* **评分：** 只有环境真正改变才计为命中（对所有方法应用 ROPE 的执行效果重评分）。范围内（in-scope）ASR 剔除任务已点名的目标和不指定收件人的内容操纵任务。指标：良性效用 BU、受攻击效用 UAU、ASR、NRP = BU × (1 − ASR)、ERS = BU 与 (1 − ASR) 的调和平均。
* **消融：** qwen3:8b，每组 949 对：仅底线；底线 + 裁判；底线 + 净化器；完整；完整但去掉片段否决。

**压力测试：** ChatInject（qwen3:8b）上 SPILLWAY 在 Workspace 为 UAU .396 / ASR .000，Slack 为 .286 / .000，无防御分别为 .052 / .245 与 .095 / .648；ROPE 在 Slack 泄漏 .095，DRIFT 在 Workspace 泄漏 .062。AutoDojo 三个套件均为 .000，但地址与收款人变更规则是在早期版本泄漏的四个对上写出的，论文称此结果为描述性；在两个留出 Banking 集上按 AgentDojo 检查分别为 .007 与 .000（计入检查遗漏的第二笔转账时 DRIFT 优化集为 .014）。PISmith（gpt-4o-mini，四套件宏平均）：SPILLWAY UAU .257 / ASR .005；ROPE .173 / .007；DRIFT 效用更高（.428）但泄漏 .064；无防御 .128 / .568。攻击者作为发件人的变体中没有攻击成功，因为注入文本重复了攻击者地址，而底线拒绝在自由文本中重复出现的目标。

**委托路由（表 8）：** 七个套件均值，SPILLWAY UAU .550 / ASR .000；使用 Opus 4.8 路由器的 ROPE .468 / .015（在 DailyLife、Shopping、Slack 泄漏）；以 gpt-4o-mini 为路由器的 ROPE .361 / .013。

**消融（qwen3:8b，范围内 UAU / ASR）：** 仅底线在四个套件上均为 .000。只加裁判不加净化器带来了唯一的执行泄漏（Banking .028、Workspace .002），包括在"支付账单"任务中向攻击者账户转账。加净化器使 Slack 从 .181 升到 .286，Travel 从 .243 升到 .343。只去掉片段否决不改变任何攻击结果。

**成本：** qwen3:8b 良性 Slack / Workspace 上，裁判每回合调用 0.43 与 0.05 次，主干调用变化小于 0.15；MELON 增加 5.29 / 3.25 次主干调用，Progent 8.67 / 5.94，DRIFT 9.91 / 9.59。

**证据边界：**

* 保证只覆盖身份目标。发给合法收件人的注入内容、把效果引向已有联系人或收款人的注入、答案中的注入文本，以及从未逐字出现在工具输出中的目标，都在 P1 之外（论文自述）。
* 角色词表按基准编写，裁判、委托规则和词表构成自适应攻击面（论文自述）；早期版本泄漏的四个 AutoDojo 对都走了这条路径（P3）。
* 每个网格单元只运行一次；SPILLWAY 的三种子乘三次重复复跑保持 ASR 为 .000，各套件效用标准差至多 .041。对照方法没有复跑。
* 方法在 AgentDojo 上开发与评估；AgentDyn 只需增加六个目标参数名，这是唯一的数据集外测试。
* qwen3:8b 的表 3"SPILLWAY (all)"行与表 1 在 Banking、Slack 一致，但 Travel（.343 对 .350）与 Workspace（.414 对 .405）不同；两者都是整数对计数（140 中 48 对 49，560 中 232 对 227），似乎来自不同运行或过滤，而两者平均都是 .370（读者观察）。
* SPILLWAY 在若干单元中 UAU 高于 BU（Workspace gpt-4o-mini .848 对 .825；Travel qwen3:8b .350 对 .250），论文归因于净化器删掉了干扰文本；良性运行同样经过净化器，因此受攻击运行为何优于良性运行的机制没有被分离（读者观察）。
* ROPE 的 Opus 4.8 路由器强于 gpt-4o-mini 智能体，委托路由对比混合了防御设计与路由器能力；论文报告了两种路由器设置。

# Q9 贡献

1. 一种目标准入检查：在序列化之前从类型化工具返回值读取身份并做集合查找，无逐任务计划，默认路径上没有模型。
2. 把基于规则的净化与准入耦合：唯一能推翻拒绝的模型永远不会被问及已删除文本中的目标。
3. 在其网格中唯一一个在 AgentDojo 全部主干乘套件单元上范围内攻击成功率为零、且受攻击平均效用最高的防御，并给出 ChatInject、AutoDojo、PISmith 压力结果以及与 ROPE 在七个套件上的正面对比。
4. 发布的 SDK（spillway-guard）与逐单元结果。

# Q10 下一步

* **论文提出：** 为新工具集声明角色；针对裁判、委托规则和词表的自适应攻击。
* **类型化字段伪造：** 当攻击者控制身份字段（亲自发邮件、成为联系人）时，底线会准入其地址；所测变体只靠"自由文本中重复"规则拦下。只按角色称呼攻击者的指令未被测试。
* **内容效果：** 发给已准入收件人的注入内容以及经后续调用的因果洗白不在任何目标检查之内；把 SPILLWAY 与内容级控制结合仍是开放问题（读者建议）。
* **真实工具生态：** 返回值类型松散的 MCP 服务器（自由 JSON、携带地址的字符串字段）会削弱类型化字段这一前提；统计真实工具中有多少把身份放在类型化字段里，可以在基准之外检验这一思路（读者建议）。
