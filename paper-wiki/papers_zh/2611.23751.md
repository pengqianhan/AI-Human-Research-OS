# Q1 问题定义

* **输入（X）：** 一个按过程性技能执行多步任务的智能体，工作流的每一步被标为 D（确定性，直接作为代码运行）、G（生成式，需要大模型）或 E（可枚举：读取非结构化状态，从有限选项中选一个）。一个 E 步是一个决策点模板（问题、带一句话定义的选项，外加“以上都不是”），结合运行时状态后成为一个实例。
* **输出（Y）：** 对每个 E 步，由小模型（System-1）在一次前向传播中给出选项上的概率分布，再由一个门控决定采用它的首选，还是交回大模型（System-2）。
* **约束：** 成功率不得低于所有 E 和 G 步都由 System-2 执行的情形；System-1 必须能用于它没见过的技能和基准；阈值在测试运行之前固定。节省的上限是 E 步所占的成本份额减去 System-1 的开销。

# Q2 问题新颖性

用类型化决策模型（typed decision model）作 System-1 的双系统智能体已经存在于搜索和特定工具 harness 中，论文引用了几个（SearchJev、AgentDecision、商用 Jev）。在这些工作里，工程师为一个固定工作流手工挑选决策点并在其上训练。新的一步是监督信号的来源：过程性技能本来就写明了哪里要做选择、有哪些选项，所以可以从公开技能语料中一次性挖出决策点，为所有决策点训练一个模型。把技能或 SOP 编译成程序也是已有工作；本文把它与语义分支处一个学习得到、经过校准的打分器结合起来。

# Q3 科学假设

如果从大量公开技能中挖掘决策点，并配上真实执行得到的状态，那么在其上训练的一个紧凑模型就能足够准确地完成未见工作流中的可枚举决策，且置信度足够校准，使得一个阈值就能决定何时信任它，从而在不降低任务成功率的前提下削减成本和延迟。

# Q4 相关工作与关键人物

* **智能体技能：** 按需加载的 SKILL.md 技能；关于智能体如何检索、遵循和内化技能的研究（包括 SkillRL）；从技能语料合成任务和轨迹。
* **工作流编译：** 把自然语言流程编成显式程序，把 SOP 编成伪代码，把技能编成状态机或运行时接口，把反复出现的路径编成规则。
* **类型化决策模型：** 商用 Jev（TypeSafe AI）；开源权重的指针头或决策头（Kev、SearchJev、AgentDecision）；用循环置换去偏的概率（AnyJev）。
* **选择性让渡与级联：** 选择性分类、LLM 级联与路由、早期用小生成模型的快慢智能体。
* **校准：** 温度缩放与标签平滑的研究。
* **关键人物：** Rui Li、Liyang He、Zhenya Huang、Qi Liu（中国科学技术大学），Zheng Zhang（南洋理工大学）。可能的批评者：研究委派边界的作者，他们会指出去掉门控后 ALFWorld 的崩溃，并追问该方法在无法编译的工作流上表现如何。

# Q5 核心方法

1. **挖掘决策点：** LLM 分析器把每个技能及其附带文档读三遍，返回带类型的候选决策点，每个附一段逐字引文，并用精确字符串匹配核对。等价的点被合并；保留三遍中至少两遍发现、且仅凭状态即可回答的 E 点。
2. **取得真实状态：** 对每个技能，LLM 编写自包含的多阶段任务，含输入文件、参考解、隐藏验证器和两个干扰技能；只有在断网容器中验证器拒绝初始文件并接受参考解的任务才保留。OpenHands 智能体执行每个任务；LLM 定位器把轨迹对齐到技能的决策点，并逐字抄下之前的观察。
3. **用顺序不变的共识打标签：** 每个状态由教师跑两遍，第二遍颠倒选项顺序；只保留两遍一致的状态。
4. **训练一个指针模型：** Qwen3.5-4B-Base 加一个选项交互头：决策 token 和每个选项结束 token 处的隐状态经过一层无位置编码的双向注意力，再把每个选项与决策状态匹配。损失是带标签平滑（ε = 0.1）的交叉熵。
5. **门控：** 当 System-1 的最大概率不低于 τ 时采用它的选择，τ 是在校准决策上达到 95% 一致率的最小阈值。AnyS1-cold 使用一个全局 τ = 0.918，在留出开发技能的 153 个样本上拟合。AnyS1-warm 对每个基准用 50 个无标注开发回合拟合 τ，这些回合里 System-2 回答每个 E 步，同时记录 System-1 的分数。

所有离线 LLM 步骤使用 DeepSeek-V4.1-Flash。

# Q6 实验设计

* **基准（与训练技能无重叠）：** SOPBench：268 个留出的客服任务，由机器可读的 SOP 确定性编译。ALFWorld：134 个未见任务，由 SkillRL 技能库编译成六个任务族程序。WebShop：500 条指令，由 SkillRL 技能编译成七个类别程序。
* **System-2：** DeepSeek-V4.1-Flash（主）与 GPT-6 Sol；两者之间 System-1 权重不变。
* **配置：** 直接读技能的未编译 System-2 智能体（SOPBench 参考智能体；其余为带 SkillRL 技能的 ReAct）、每个 E 和 G 步都用 System-2 的编译工作流（All-S2）、商用 Jev 作 System-1、AnyS1-warm、AnyS1-cold，以及无门控的 All-S1。
* **指标：** 通过率、成功率、WebShop 得分；相对未编译智能体的每回合成本节省（System-2 和 Jev 按 API 标价；自托管 4B 模型按 L4 GPU 吞吐折合每千次决策 0.0045 美元）；关键路径上的平均模型调用时间。所有配置与 All-S2 共享完全相同的 System-2 请求缓存，所以各次运行只在 System-1 作答处出现分歧。
* **消融：** 门控；执行得到的状态对比 LLM 编写的状态摘要；标签平滑对比硬标签交叉熵和交叉熵加 Brier；工作曲线对比同比例随机委派；校准回合数。

# Q7 数据集与代码

Any-DP 由 SkillMD-138K 语料中的 1,072 个公开技能（16 个类别）构建：17,865 个带类型的决策点（D 21.3%、E 64.5%、G 14.2%），2,846 个经容器验证的任务，25,986 个共识标注的状态，教师一致率 89.2%。贡献段落说 Any-DP 已发布，作者列表下给了项目主页（https://middle-chunjie.github.io/AnyS1/）；本笔记未打开它，也未核实实际可获取的内容。

# Q8 证据质量

**主要结果（表 2；效果 / 相对未编译智能体的成本节省 / 模型时间（秒））。**

| DeepSeek-V4.1-Flash | 未编译、读技能的智能体 | 55.2 / – / 51.4 | 82.8 / – / 163 | 54.9 / – / 146 | – |
| DeepSeek-V4.1-Flash | 编译（All-S2） | 83.2 / 86 / 25.0 | 96.3 / 81 / 21.3 | 66.9 / 76 / 29.0 | 81 |
| DeepSeek-V4.1-Flash | Jev 作 System-1 | 84.0 / 87 / 23.9 | 96.3 / 84 / 20.5 | 67.1 / 83 / 17.3 | 84 |
| DeepSeek-V4.1-Flash | AnyS1-warm | 84.3 / 91 / 15.6 | 95.5 / 88 / 12.9 | 68.1 / 86 / 17.1 | 89 |
| DeepSeek-V4.1-Flash | AnyS1-cold | 83.2 / 87 / 21.2 | 95.5 / 85 / 15.7 | 67.9 / 89 / 12.7 | 87 |
| GPT-6 Sol | 未编译、读技能的智能体 | 61.2 / – / 207.6 | 88.8 / – / 413.5 | 48.5 / – / 317.3 | – |
| GPT-6 Sol | 编译（All-S2） | 82.1 / 86 / 124 | 96.3 / 56 / 193 | 70.6 / 72 / 81.4 | 71 |
| GPT-6 Sol | AnyS1-warm | 82.5 / 91 / 75.8 | 95.5 / 75 / 101 | 70.4 / 80 / 49.4 | 82 |

**消融。**

* 去掉门控（All-S1）后，SOPBench 不变（84.3），WebShop 略降到 66.3，但 ALFWorld 从 96.3% 跌到 40.3%。
* 执行状态对比 LLM 编写的摘要（三个种子）：留出的容器开发集（185 个状态）上 83.8 对 65.0，SOPBench 的 E 决策上 93.5 对 91.7，ALFWorld 的 E 决策上 68.9 对 63.6。
* 标签平滑对比硬标签交叉熵（单个种子）：准确率 82.4 对 82.3，ECE 0.094 对 0.146，门控后一致率 97.7% 对 92.4%；不做平滑时拟合出的阈值会膨胀到接近 0.998。
* 在 warm 阈值下，ALFWorld 委派 50% 的 E 决策，与 System-2 的一致率为 92.4%（同样大小的随机子集为 68.2%）；WebShop 委派 41%，一致率 84.3%（69.8%）；SOPBench 委派 98%（总体一致率 91%）。cold 阈值在 SOPBench 上委派 40%、一致率 100%，在 WebShop 上委派 55%、一致率 80.0%。20 个开发回合的拟合与完整 50 回合拟合的委派比例相差不到 1 个点。
* System-1 给一个决策打分的中位耗时是 21.8 到 31.7 毫秒，System-2 的一次 E 调用是 1.51 到 1.78 秒。

**证据的局限。**

* 标题数字中的大部分节省来自编译，而不是 System-1。All-S2 已经节省 76% 到 86%（Flash）和 56% 到 86%（Sol）；AnyS1-warm 在 Flash 上再加 5 到 10 个点（读者根据表 2 计算），在 Sol 上最多 19 个点（ALFWorld，56 到 75）。摘要中的“75–91%”是相对未编译智能体的。论文自己的公式 1 分析说的是同一件事：编译之后，E 步在 ALFWorld 和 WebShop 上占未编译成本的 17% 到 22%，在 SOPBench 上占 4%。
* 测试时 System-1 回答的决策点来自由 SOP 和 SkillRL 技能库编译出的程序。自动编译开放式的仓库技能被列为未来工作，所以“任意智能体工作流”目前指的是任何已被人编译成 D/E/G 步的工作流。
* 标签和门控目标都是与 System-2 的一致（教师为 DeepSeek-V4.1-Flash；τ 按 95% 一致率设定），不是真实正确性；任务成功率是唯一的真值检验。WebShop 上被委派的决策与 System-2 的一致率是 84.3%，但得分没有下降，这提示许多分歧无害，或者 System-2 在那里并不总是对的（读者推断）。
* 各编译配置之间的效果差异在约一个点以内，任务数为 134 到 500，在线结果没有给出区间或重复运行；ALFWorld 的一个任务是 0.75 个点（读者计算）。“保持可靠性”有证据支持；平均 +0.5 个点的优势与噪声无法区分。
* 编译相对未编译智能体的提升（平均约 17 个点）不是本文要解释的贡献，而且未编译基线因基准而异（参考智能体或 ReAct）。
* warm 设置对每个工作流要花 50 个开发回合，其中 System-2 回答每个 E 步（论文所述）。

# Q9 贡献

1. 从过程性技能中挖掘 System-1 监督信号的想法，以及 Any-DP：一个包含带类型决策点、执行状态和共识标签的数据集。
2. 一个带标签平滑的 4B 指针模型加置信度门控，无需重新训练即可迁移到三个未见基准和第二个 System-2 模型族。
3. 分析表明：执行得到的状态优于 LLM 编写的状态；校准对门控的影响大于对原始准确率的影响；无门控的 System-1 会破坏长程搜索；E 步份额决定节省的上限。

# Q10 后续方向

* **论文提出的：** 根据被让渡的 System-2 调用在线调整阈值；自动编译开放式的仓库技能。
* **未编译场景：** 在普通的读技能智能体循环内的决策点上测试 System-1，那里每个决策的节省更大（因为没有东西被编译掉），难点在于运行时定位决策点（读者建议）。
* **真值标签：** 在有隐藏验证器的地方（2,846 个合成任务），按“哪个分支通向验证成功”给决策打标签，看教师共识出错的频率（读者建议）。
* **对本仓库：** D/E/G 分类是审视 OS 自身技能的实用视角：固定命令的步骤可以写成脚本，在列出的选项中做选择的步骤可以交给带回退的廉价模型（读者推断）。
