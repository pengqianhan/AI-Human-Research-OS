# Q1 问题定义

* **输入 `X`**:一个冻结的 LLM 策略 π_θ、一个工具集 T,以及每一步都维护交互历史 h_t 和工作状态 w_t 的长时程任务;一个 Skill Memory M_k = (E_k, W_k, ρ_k, C_k)——经验记忆(可复用技能)、工作记忆规格(状态模式与更新提议逻辑)、调用策略(何时、哪些技能能进入模型上下文)以及检查器集合(哪些观测能支持一次状态提议)。
* **输出 `Y`**:Recuris,一个递归的经验-工作记忆架构。在单个任务内部,一个经检查器验证的工作状态决定何时、从经验记忆中调用哪个技能,状态只在观测确认后才推进,而非依据模型自己声称的成功。跨任务层面,一个固定的 Meta-Agent 读取由此产生的结构化执行轨迹,将每个诊断出的失败归因到四个记忆组件之一,提出一个有针对性的补丁,并由一个固定的验证门控针对留出的开发集来决定是否接纳该补丁。
* **核心问题**:递归自我改进(RSI)在长时程任务中很难做到,因为不断增长的历史会模糊任务状态、并使技能调用错位。现有的经验记忆方法要么从初始指令中检索(会错过后来才出现的需求),要么在完整交互历史中搜索(混杂了过时信息、已完成步骤和执行噪声);而仅凭最终结果的学习信号,无法指出当一次运行失败时,究竟应该修复哪个记忆机制——是某个存储的技能、被追踪的状态、调用触发条件,还是进度校验器。
* **范围**:在本文所有实验中,基础 LLM、工具、Meta-Agent、定位与打补丁流程、验证门控,以及记忆控制层之外的 harness 机制都保持固定;递归被限制在这一外置的记忆控制层内,而非模型本身或外层改进流程。

# Q2 问题的新颖性

经验记忆与 agent 技能(Voyager、AWM、ExpeL、Buffer of Thoughts、Dynamic Cheatsheet、Anthropic 的 Agent Skills 格式、SkillOpt、SkillComposer)以及显式的工作记忆状态追踪(StateAct、ReflAct、Magentic-One 的账本、StateFlow、StructAgent)都是本文所依托、而非首创的活跃领域。论文声称的新意在于把二者耦合起来:已有经验记忆工作大多关注*存什么*,对技能应当*何时、如何*被调用关注较少——要么把技能作为固定文本块注入,要么让模型自行决定是否调用,论文引用的一个基准显示 agent 往往难以自行选对技能,而注入不准确的技能甚至会主动损害任务完成度。已有的工作记忆研究维护显式状态,但这一状态未必*可信*:它要么受制于泛化能力差的手写规则,一旦任务偏离设计好的流程就会失效;要么由模型自己上报,容易遗漏和产生幻觉。两个被引用的系统(AutoGuide、SGDR)确实把检索建立在执行上下文之上,但它们的条件信号是通过相似度匹配的原始观测——环境当前看起来是什么样子——而非一份经过验证、记录 agent 确实已完成了什么的记录。Recuris 通过一个显式的检查器层,把状态*提议*与状态*确认*分离开,再把由此产生的经过验证的耦合当作跨任务记忆演化的结构化诊断证据,从而把"该修复四个组件中的哪一个"从一个只能靠结果猜测的问题,变成一个可观测、可衡量的问题。

# Q3 科学假设

如果 (a) 一个紧凑的、经检查器验证的工作状态——而非原始对话或模型自我上报的进度——决定何时、从经验记忆中调用哪个技能,调用点由明确定义的执行事件触发;并且 (b) 由此产生的、把状态、被调用技能、动作与经检查器验证的结果串联起来的结构化轨迹,让一个固定的 Meta-Agent 能把每个诊断出的失败归因到四个记忆组件之一(技能、工作记忆规格、调用策略、检查器),并对该组件应用一个有针对性、经验证门控的补丁;那么单任务内的执行应当有所改善——尤其是在完成被追踪的必要动作方面,而不只是检索到相关知识——由此演化出的记忆应当能迁移到留出任务、以及从未参与演化该记忆的模型上,并且这一优势应当随交互时程增长而扩大而非衰减,同时底层的冻结模型与外层改进流程始终不变。

# Q4 相关工作与关键人物

* **经验记忆与 agent 技能**:Voyager 存储可执行代码技能,AWM 归纳自然语言工作流,ExpeL 从成功与失败中提取洞见,Buffer of Thoughts 和 ReasonFlux 维护提炼出的思维模板,Dynamic Cheatsheet 在测试时整理笔记;Anthropic 的 Agent Skills 格式为 E_k 提供了标准化表示。SkillOpt(本知识库已收录)把技能文件当作可训练参数从反馈中优化;SkillComposer 学习创建、改进和合并技能。
* **面向 LLM agent 的工作记忆**:StateAct 与 ReflAct 让模型自己书写和反思结构化状态;Magentic-One 维护任务与进度账本;StateFlow 用手写状态机约束执行。StructAgent 是最接近的前作——一个有校验器支撑的进度转移机制——但其经验证的状态只反馈给 agent 自己的下一步动作,并没有从中检索任何程序性记忆,这正是 Recuris 的经验-工作记忆耦合所填补的空缺。
* **LLM agent 的递归自我改进**:从哥德尔机(Schmidhuber,2003)一路追溯到脚手架自我应用(Zelikman et al.;Fernando et al.),再按*改写哪一层*对近期系统分类——运行时/代码库、工作流图、工具集,还是模型权重——将 Recuris 定位在最窄的一层,即记忆本身,与本知识库 [Agent memory](../topics/agent-memory.md) 主题已经追踪的增删改查记忆系统、Memento(冻结基础模型,只适配一个案例库)以及 EvolveMem(演化记忆架构,由聚合基准表现的提升作为门控)并列。批评该领域主流的接纳信号——模型自身对有用性的判断,或某个聚合数字的提升——无法说明*究竟是哪一部分*导致了一次失败运行,并引用一个失败归因基准在无结构日志上的准确率仅为 53.5%(负责的 agent)和 14.2%(决定性的步骤)。

# Q5 核心解法

1. **Skill Memory 架构**。M_k = (E_k, W_k, ρ_k, C_k):以 Agent Skills 格式存储可复用技能的经验记忆;定义状态模式与更新提议逻辑的工作记忆规格;决定在哪些执行事件、哪些技能能进入模型上下文的调用策略;测试某个观测是否支持一次状态提议的检查器集合。一次候选补丁只修改诊断所指明的组件,其余组件原样复制——作用范围是逐条编辑而非逐轮次控制的。
2. **单任务内、状态驱动的技能调用**。结构化的工作状态追踪每个目标的内容、状态(pending、done 或 blocked)、支持证据和可选的阻塞原因。调用发生在明确定义的执行事件上,而非仅从初始指令一次性触发或在完整历史中搜索:调用时机(call-time)调用在 agent 起草一个会改变状态的工具调用时触发(该草稿会被拦截并替换为一个"未执行"的合成结果,因此被检索到的技能能在真正的动作被发出之前进入模型上下文,匹配依据是该调用所命名的工具);边界(boundary)调用在轮次边界上依据工作状态谓词触发(例如 first_turn)。
3. **证据驱动的状态更新**。一个提议的下一状态会通过一个针对具体组件的完成谓词与实际返回的观测进行核对,一个固定的提交内核只有在检查器给出正向判定后才推进状态——某个目标从 pending 变为 done,绝不依据模型自己声称动作成功,只依据一次与之匹配的、经检查器确认的观测。
4. **基于轨迹的跨任务失败定位**。一条结构化轨迹 Γ_k 在每一步都记录工作状态、被调用的技能、动作与观测,以及提议状态、提交状态和检查器判定。一个固定的 Meta-Agent 把每个诊断出的失败归因到 {E, W, ρ, C} 之一——缺失或有缺陷的技能、被遗漏的目标或错误的更新提议、被错过/延迟/不相关的调用,或者错误的接受/拒绝——然后一个固定的打补丁阶段针对每个被指明的组件各提出一处编辑,作为一个候选方案一并应用。
5. **验证门控的接纳与有边界的递归**。一个固定的门控把候选方案与当前记忆在失败源任务加上一个留出开发集(当前记忆已经能解决的锚点任务)上进行比较,只有当候选方案修复了目标失败、且没有让锚点任务退化时才予以接纳;测试任务、轨迹与分数从不进入定位、打补丁或接纳的任何一步。由此产生两种运行模式:跨任务演化针对每个基准只构建一次记忆,来源仅是某个中等规模"部署模型"自身的失败,之后原样冻结地发给其他模型使用;测试时适应则针对单个孤立任务,从该任务自己失败的轨迹与一个隐藏校验器给出的通过/失败位出发重建记忆,并在更新后的记忆下重试,直到首次成功。论文报告称,任务结构——共享的工具、策略与任务家族,还是孤立的任务——决定了哪种模式适用:在 Terminal-Bench 2.1 上,跨任务演化在十三次运行中都没有接纳任何补丁,因此这里只评测了测试时适应。

# Q6 实验设计

四个长时程基准:τ²-Bench Retail(114 个任务)和 Airline(50 个任务),双向控制的工具调用对话,由要求满分才算成功的环境校验器打分,读操作与必需写操作的召回率分别报告;SkillFlow(166 个任务,涵盖 20 个共享执行流程的家族,二元的程序化校验器),用于测试终身技能发现;以及 Terminal-Bench 2.1(仅限测试时适应,经由 Terminus-2 agent)。十个模型——五个开源权重模型(Granite-4.1-3B、Qwen3.5-4B/9B、GPT-OSS-20B、Qwen3.6-27B/35B),通过单一代理接入的三个前沿模型(Gemini 3.7 Flash、GPT-5.6 Sol、Claude Opus 5),外加部署模型 doubao-seed-2-0-pro——均在温度 0、k=4 次独立尝试下运行,每次尝试上限 200 步、连续 10 次工具错误即中止。每个基准的 Skill Memory 只构建一次,仅基于部署模型,使用一个建立在 Claude Code 上的固定 Meta-Agent,后者只能看到基准自身未修改的参考 agent 产生的失败——这是一个刻意的单一来源设计,而非针对每个目标模型分别调优的记忆。全程比较三种配置:基础参考 agent;带 M₀(一个中性的起始记忆,用于隔离出这一层在尚未学到任何东西之前贡献了什么,附录中的消融实验报告其在四个目标模型上的效果与零无法区分)的 Recuris;以及带演化后记忆的 Recuris。统计方案:配对的、按任务分簇的 bootstrap 95% 置信区间,以及针对配对二元对比的 McNemar 精确检验。

# Q8 证据质量

本笔记基于完整 arXiv HTML 正文中的引言、方法(第 2 节及所有子节)、实验(第 3 节及所有子节 3.1-3.5)、相关工作(第 4 节)和结论撰写,因为对这篇非常新(2026年8月25日)的投稿,`hf papers read` 只返回了一个占位性的页面图标描述,故本笔记改为直接从 arxiv.org/html 抓取。本笔记未阅读附录 A-E(统计方案、Harness 消融、基准与数据划分、算力与上下文、案例研究)中正文未引用的部分,因此这些附录特有的数字细节未在此独立核实。这篇论文在统计诚实性上处理得相当细致:明确把已确立的收益(置信区间不含零,标注为†)与仅有方向性的结果区分开(τ²-Airline 上经验-工作记忆耦合消融的每一个区间都包含零,论文自己也把它读作"一个方向,而非一个已确立的效应");坦率报告了空结果(在 τ²-Retail 上移除检查器对通过率的改变恰好为零,归因于"解码噪声而非真实导致的失败";某次演化运行第四轮的候选方案被证明从未在任何留出任务上被调用过,论文明确将其与真正的收益递减区分开来);并且专门在第二个独立重新实现的 agent 技术栈(DeepSeek Harness,对比原始的 Claude Code 实现)上复现了其核心 Meta-Agent 结果,以排除实现特定的干扰因素,发现二者"在统计上可以互换",并在机制上收敛到同一处修复。头条数字(37 个模型-基准组合中的 35 个有所改善;在 τ²-Retail 上为 GPT-5.6 Sol/Claude Opus 5 分别带来 +17.8/+15.6 分;故障定位准确率为 64.8% 对 13.0%)在摘要与正文之间保持一致。

# Q9 主要贡献

1. 确立了状态驱动的记忆使用——一个经检查器验证的工作状态来门控技能调用,而非从初始指令或原始交互历史中检索——作为长时程 agent harness 中递归自我改进的一项要求。
2. Recuris,一个递归的经验-工作记忆架构,把持久化的技能经验与一个动态维护、经证据支撑的任务状态耦合起来,实现由执行事件触发的技能调用,而非固定文本块或由模型自行决定的检索。
3. 表明经验-工作记忆耦合把 harness 执行转化为结构化的诊断证据:一个固定的裁判从结构化轨迹出发定位一个被注入的组件故障,准确率达到 64.8%,而从原始轨迹出发是 37.0%,仅凭结果是 13.0%(低于 33.3% 的常数猜测下限),从而使针对具体组件而非整个记忆的修复成为可能。
4. 在四个基准、十个模型上的实证结果:37 个已完成的模型-基准组合中有 35 个任务成功率有所提升;优势随交互时程增长而扩大而非衰减(在最长的四分位区间上达到 +32.2 分);一次在中等规模模型上演化出的记忆能够迁移到从未参与其演化的前沿模型上(在 τ²-Retail 上为 GPT-5.6 Sol/Claude Opus 5 分别带来 +17.8/+15.6 分);并且经门控的更新能保留已有能力(在相同噪声下,42 个锚点任务中有 4 个退化,相比之下未改变的记忆重新运行一次的退化率为 25.9%,p=0.013)。

# Q10 下一步

论文自己报告的开放问题:哪个记忆组件是关键的取决于具体领域,无法在设计时就固定下来——在 τ²-Airline 上 write-review 是关键而 status board 无关紧要,而在 τ²-Retail 上这一模式恰好反转(一种"双重分离")——论文认为这正说明为何任何固定的、不区分场景的修复力度分配都必然在某处出错,从而支持从轨迹中读出修复目标,而非提前把它定死。演化出的记忆只增不减(在报告的演化谱系中新增 51 个技能、修订 2 个、废弃 0 个,17 对近乎重复的技能也留存进了被接纳的版本),论文指出一个剪枝算子会是更新集合中"一个自然的补充",但目前尚未实现。在 Terminal-Bench 2.1 上,论文自己的拆解表明尝试预算/重试效应(+26.4 分)主导了测试时适应本身带来的学习效应(+2.3 分,区间含零,尽管有七个任务只有在适应下才被解出、其他任何配置都做不到);论文明确指出,在所测试的样本规模下,其逐次尝试可靠性数字的每一个区间仍然包含零——即在这里只是一个方向,而非一个已确立的效应。

本笔记在论文自身的框架之外补充一条联系:上述"关键组件因领域而异"的发现,是 [Graph Engineering](2608.21156.md) 在多 agent 系统层面提出的同一个问题在单个 agent 内部的一个实例——即任何固定的、设计时就定死的结构分配(在那篇论文中是任务/团队/状态图的拓扑,在这里是该信任四个记忆组件中的哪一个)都无法适应实际发生的具体失败模式,而两篇论文都以把这一分配变成一个运行时的、由证据驱动的决策,而非静态设计选择,来回应这一点。

* [Agent harness engineering](../topics/agent-harness-engineering.md) - 把其四组件补丁空间(技能、工作记忆规格、调用策略、检查器)明确称为"agent harness 的记忆控制层",为本主题的诊断-编写-验证循环提供了一个比单一未分化 harness 对象更细粒度、按组件类型划分的修复目标。
* [Terminal-Bench](../concepts/terminal-bench.md) - 用于论文的测试时适应模式(87 个任务,Terminus-2 agent),这是论文中唯一一种跨任务记忆演化找不到可利用的共享结构的场景(十三次演化运行均未接纳任何补丁),因此只适用单任务内的重试加适应。
