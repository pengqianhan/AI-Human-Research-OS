> 论文:**Securing the AI Agent: A Unified Framework for Multi-Layer Agent Red Teaming**
> 论文链接:<https://arxiv.org/abs/2606.31227>
> 机构:腾讯朱雀实验室(Tencent Zhuque Lab)

# Q1 问题定义

* **输入 `X`**:一个 AI agent 的完整部署面——它所运行的模型服务/agent 平台基础设施、扩展它的 MCP server 与已安装的 agent 技能、它面向终端用户暴露的实时对话行为,以及底层 LLM 在对抗性提示下的对齐鲁棒性。
* **输出 `Y`**:针对四个层各自的结构化发现集合(问题类型、严重程度、支撑证据、修复建议)和一个聚合安全评分;在模型层,输出的是跨(漏洞类型 × 攻击算子)组合的攻击成功率画像,而非单一的二元判定。
* **核心问题**:AI 原生软件(模型服务、agent 平台、MCP server)的增长速度已经超过了保护它们的安全工具——这些组件对现有指纹数据库来说太新、版本号不规范,且主导威胁模型(未授权算力访问、凭证泄露、prompt 注入、工具滥用、越狱)与经典 Web 扫描器针对的类别不同。没有任何单一检测技术能同时在这四个层面上建立可靠证据。
* **范围**:四个集成模块——基于规则的基础设施扫描、LLM 驱动的 MCP server 与 agent 技能审计、黑盒多轮 agent 红队测试、大规模越狱评测——由腾讯朱雀实验室以开源平台形式发布(CLI、Web 服务,以及可安装的 agent 技能)。

# Q2 问题的新颖性

按论文自述的动机,现有工具的覆盖范围与 AI 攻击面之间存在三个缺口:*编目缺口*(指纹数据库缺乏新生 AI 组件的签名)、*版本缺口*(AI 项目使用不规范的版本方案——构建号、`.dev` 快照、滚动的 `latest` 标签——会破坏语义化版本比较)、*威胁模型缺口*(AI 时代的主导风险是未授权访问、凭证泄露、prompt 注入和工具滥用,而非经典扫描器针对的注入/XSS 类别)。论文的第二个新颖性主张是架构性的:安全风险按四个层分层,这些层不仅在实现上不同,在"什么样的证据能确立一个发现"这一点上也根本不同——因此按其自身的相关工作对比表(表 6,对比 Nuclei、Semgrep、CodeQL、Invariant MCP-Scan、MCPSafetyScanner、garak、PyRIT、promptfoo、DeepTeam),此前没有开源工具能覆盖全部四层,也没有工具审计 agent 技能供应链,这被论文视为其最直接的新颖点。

# Q3 科学假设

形式化为**分层自适应评估原则(Layer-Adaptive Assessment Principle)**:如果每个攻击面层都用能够产生该层所需证据类别的*最廉价*评估范式来评估——基础设施用确定性签名匹配,MCP server 与 agent 技能用 LLM 驱动的语义审计,已部署 agent 行为用交互式黑盒红队测试,模型对齐用大规模统计攻击枚举——那么由此得到的框架能实现单一范式工具无法达到的、跨 AI 技术栈的安全覆盖,同时在更廉价的范式已经足够的地方保留其速度、可复现性和近乎零误报的优势。论文由两条支撑原则正式推导出这一点:安全异质性(不同风险类别需要根本不同的证据)与证据充分性(一个评估程序只有在能够产生某属性所需的证据类别时才是有效的)。

* 建立在活跃的 MCP 安全文献之上,该文献已确立工具投毒、工具影子劫持、"rug pull"——攻击向量是工具的宣称元数据而非其输出或源码——是真实且有效的;论文将其 M2/M3 模块定位为在一个可部署的审计器和红队测试器中操作化检测这些类别,而非孤立测量单一攻击类别。
* 模型层模块(M4)建立在一个开源红队评测框架(DeepTeam 的扩展分支)之上,并整合了文献中已确立的越狱技术(GCG 式优化、PAIR 查询式搜索、tree-of-attacks 搜索、Crescendo 多轮升级、best-of-n 采样)和标准化基准(SafeBench、JailbreakBench);其在此声称的贡献是整合与规模化,而非新攻击或新基准。

# Q5 核心解法

1. **分层-范式匹配。** 四个攻击面层(基础设施、协议/工具、agent 行为、模型)被映射到四个证据类别(签名、语义、行为、统计)及对应的四种检测范式,在第 4 节中被形式化为 Q3 所述的分层自适应评估框架。
2. **基础设施扫描(M1)。** 一个手写解释器评估声明式 YAML 指纹与漏洞规则——覆盖 75 个 AI 组件的 107 条指纹规则和 1,443 条漏洞规则——匹配四个字段(body/header/icon/hash),并配有专为不规范 AI 版本(构建号、`.dev` 标签、滚动 `latest`)设计的版本归一化流程。发现结果被明确按置信度分级(已验证 / 基于版本 / 推断),并为拒绝声明式描述的组件(如 MLflow)提供了可编程指纹的逃生舱口。
3. **MCP server 审计(M2)。** 一个 LLM 驱动的 agentic harness,带有有界的推理-行动循环、面向大型代码仓库的上下文压缩,以及异构模型路由(为推理、代码阅读、廉价过滤分别配置不同模型)。引入了 **"Prompt-as-Rule"**:检测知识被编码为自然语言标准加显式排除条件(十种模式,对齐 OWASP MCP Top 10),以静态(源码可见)和动态(仅通过协议的黑盒)两种模式运行。由于一个读取不可信代码/工具输出的 LLM 审计器本身就是注入目标,harness 在结构上将指令与摄入的数据分离,并根据*响应*而非精心构造的*请求*来判定工具滥用类发现("分析结果,而非分析输入")。
4. **Agent 技能扫描**将同一套 LLM 驱动范式扩展到 SKILL.md 软件包:一个分阶段流水线(预处理 → 静态风险线索检索 → 受约束的 agentic 分析 → 风险分类)审计一个技能的实际行为是否与其声明的用途相符,将制品分类为正常/可疑/恶意,并发布 **SkillTrustBench**(从主流市场的 62,652 个技能中提炼出 5,520 个评测用例)来衡量检测效果。
5. **AI agent 红队测试(M3)。** 一个仅通过对话探测已部署 agent 的黑盒、多轮红队测试 agent,围绕能力感知(跳过目标不具备对应攻击面的测试)、升级阶梯(良性探测 → 规避 → 公开越狱尝试,在首次确认命中后停止)、以及把主观判断变为近乎确定性检查的客观锚点(SSRF 金丝雀 token、埋设标记)组织,覆盖四个风险家族(数据泄露、工具滥用、间接注入、授权绕过)。
6. **LLM 越狱评测(M4)。** 一个三角色(模拟器/目标/评判)、三要素(漏洞类型/攻击算子/度量)的评测 harness,整合了约七十种单轮编码/混淆算子以及多轮策略(带回溯的 crescendo、tree-of-attacks、best-of-n),覆盖十六个数据集(约 7,000 条有害 prompt,涵盖偏见、毒性、非法活动、PII 等),由通用加专项的 LLM-as-judge 家族评判,产出可比较的、按模型划分的攻击成功率画像。
7. **交付形式。** 同一后端以三种形式暴露——CLI、Web 服务(基于 WebSocket/SSE 流式传输的服务器-agent 架构)、以及可安装于 OpenClaw、Cursor、Claude Code、CodeBuddy 和 Windsurf 的、无依赖可分发的 agent 技能——在使用可选的云端威胁情报服务时遵循严格的数据最小化约定。

# Q6 实验设计

这主要是一篇系统/工程技术报告,而非单一受控实验。其最明确的定量评估是 **SkillTrustBench 排行榜**(表 3):同一个 AI-Infra-Guard 技能扫描器换用不同底座 LLM 运行,固定审计规范只改变底座模型,以 loose F1、precision、recall 和误报率(FPR)打分——最强模型的 loose F1 超过 0.98,recall 接近 1.0。除该基准外,报告没有为基础设施扫描器、MCP 审计器或 agent 红队测试器给出对照真值的检测准确率对照表;它对这些模块的证据主要是描述性的(设计理由、示例场景,如系统 prompt 提取的升级轨迹)加上表 6 中与外部命名工具的定性能力覆盖对比。

# Q7 数据与代码

发布了 **SkillTrustBench**(数据集:huggingface.co/datasets/cuhk-zhuque/SkillTrustBench;排行榜:huggingface.co/spaces/cuhk-zhuque/SkillTrustBench-Leaderboard),据称已被 ClawScan(OpenClaw 生态中的一个外部安全扫描项目)采纳为推荐评测基准之一。代码发布于 github.com/Tencent/AI-Infra-Guard(据 `hf papers info` 有 5,347 个 GitHub star);产品/项目主页为 matrix.tencent.com/clawscan/。漏洞规则库(1,443 条规则)被描述为中文("zh")语料库,并有一份并行的英文语料库镜像;十六个越狱数据集和十种 MCP 静态审计检测模式在论文附录中有文档记录,但未像 SkillTrustBench 那样作为独立排行榜发布。

# Q8 证据质量

本笔记通过 `hf papers read`(arxiv.org/html 渲染)成功检索到完整论文正文,因此能直接读取方法部分、第 4 节的形式化理论以及相关工作对比表,而不仅是摘要。作为一篇系统/工程技术报告,其大多数主张是架构性和描述性的,而非有留出测试集准确率支撑:语料规模数字(75+ 个组件、1,400+ 条规则、16 个数据集、约 70 种编码算子、约 7,000 条有害 prompt)是作者自己的统计,未经独立核实;SkillTrustBench 是唯一有真正基准表的模块,但它评测的是 AI-Infra-Guard 自身扫描器设计(跨不同底座模型),而非与竞品技能扫描器的对比。"唯一覆盖全部四层的开源框架"这一主张,依据的是作者自己针对八个命名工具的表 6 对比,而非系统性文献综述,因此该对比的完整性在本笔记中未经独立核查。除技能扫描基准外,没有报告对该框架自身误报/漏报率的对抗性或第三方评估。

# Q9 主要贡献

1. **分层-范式匹配 / 分层自适应评估**原则:一个形式化论证(安全异质性 + 证据充分性),说明为何 AI agent 安全需要四种与四类证据一一对应的不同检测范式,而非单一的通用扫描方法论。
2. 端到端实现该原则的四个集成检测模块——带有 AI 专属指纹/版本归一化逻辑的基于规则的基础设施扫描器、建立在 **Prompt-as-Rule** 范式之上的 LLM 驱动 MCP server 与 agent 技能审计器、带有成本感知升级策略的黑盒多轮 agent 红队测试器、大规模越狱评测 harness——以一个开源、可扩展的平台发布,可作为 CLI、Web 服务或可移植 agent 技能部署。
3. **SkillTrustBench**,一个同时衡量 agent 技能可信度和扫描器检测效果的新基准(从各大市场 62,652 个真实世界技能中提炼出 5,520 个用例),已被外部项目(ClawScan)引用。
4. 作者认为可推广到本系统之外的三种跨模块设计模式:Prompt-as-Rule(声明式自然语言检测标准加显式排除条件)、对本来主观的 LLM 判断进行客观锚定(金丝雀 token、埋设标记)、以及把扫描器自身当作对抗性目标——它必须防御自己分析的那些不可信制品。

# Q10 下一步

论文自述的未来方向:(a)大规模测量——将基础设施扫描器应用于公开 AI 部署全景以量化真实世界暴露程度;(b)让四个层协同工作——例如用基础设施发现来引导 agent 侦察,或用静态 MCP 发现来聚焦动态测试;(c)持续扩展指纹/CVE、Prompt-as-Rule 和越狱算子知识库,以跟上生态演进。本笔记在论文自身清单之外提出的开放问题:分层-范式匹配是否能推广到这四层模型未覆盖的攻击面(持久化 agent 记忆、多 agent 通信信道);该框架自身的误报/漏报率在唯一有基准的模块(SkillTrustBench)之外,与人类红队测试者相比如何;以及 Prompt-as-Rule 检测标准如何在 MCP 与 agent 技能生态演进速度超过任何静态规则库的情况下保持时效——这在结构上与本知识库 [Agent harness engineering](../topics/agent-harness-engineering.md) 主题下已存在的 harness 可维护性问题类似,只不过应用对象是安全规则而非能力代码。
