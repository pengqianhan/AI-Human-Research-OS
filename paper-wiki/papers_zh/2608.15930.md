> 论文：**UI-Mate: Advancing Open-Weight Foundation GUI Agents with In-Context Demonstrations**
> 论文链接：<https://arxiv.org/abs/2608.15930>
> 代码：<https://github.com/Tencent/UI-Mate>
> 机构：腾讯混元（Tencent Hunyuan）Frontier 团队

# Q1 问题定义

* **输入 `X`**：一条自然语言指令 `x` 与一个计算机使用环境 `E`（安装了应用和文件的操作系统），agent 通过截图与 GUI 动作直接操作；可选地，附带一段同任务或相关任务的多模态演示 `d`（来自人类或更强 agent 的录制）。
* **输出 `Y`**：一条观测/响应对轨迹 `τ = (x, o_1, y_1, ..., o_T, y_T)`，由检查 `E` 最终状态的可执行验证器打分 `R(τ) ∈ {0,1}`；若提供了演示，agent 还会额外产出 `subtask_complete` 控制动作，用以推进指针，沿演示被切分出的子任务结构前进。
* **核心问题**：基础 GUI agent 面临训练瓶颈（数据稀缺与偏斜——一条轨迹只有在其初始状态可实例化、动作可执行、结果可验证时才有训练价值，而廉价生成的短程单应用任务在语料中天然占主导）与交互瓶颈（日常工作流依赖用户特定的工具与默契约定，指令通常只交代期望结果而非达成结果的具体流程，导致这些默认选择在不同运行间被以不同方式"猜测"解决，同一 agent 这次成功、下次可能失败）。如何在真正多样、可验证的长程数据上大规模训练 GUI agent？如何让 agent 利用一段可选的演示来消解程序性歧义，而不退化为对演示的机械重放？
* **范围**：面向桌面/办公场景的计算机使用 agent（Linux/macOS 沙箱及原生应用控制）；演示机制被明确当作**先验**而非目标——实时截图在任何时候都对演示中的步骤拥有否决权，且策略必须在无演示（`g_t = ∅`）的常规情形下同样具备竞争力。

# Q2 问题的新颖性

基础计算机使用系统（UI-TARS、Qwen-UI-Agent）以及从屏幕录制中提炼可复用程序性知识的人类示教型 GUI agent（ShowUI-Aloha）已经存在，环境驱动的数据规模化工作（AgentNet、ScaleCUA、InfiniteWeb、CUA-Gym）也已存在。UI-Mate 的新颖之处在于：把演示当作一种切分好的、子任务级的"工作流先验"，而非完整的指令条件化信号，也非逐字重放的动作序列——它把一段录制离线转换为若干带自然语言目标、可验证完成准则、以及建议性（非像素坐标）动作描述的子任务，随后让实时观测有权覆盖任何过时、缺失或与当前状态不符的工作流步骤。论文还专门为此引入了 OSWorkerBench——一种受控的配对协议（指令/环境/预算/验证器保持一致，只改变是否提供演示），这是现有仅支持指令输入的基准（OSWorld、WindowsAgentArena）所无法测量的。

# Q3 科学假设

如果一个闭环、环境驱动的数据流水线（任务生成、环境构建、回放过滤、由能力树驱动的再平衡）为 SFT 与在线 agentic RL 供给数据，且训练出的策略额外学会以工作流视图 `g_t = (d, n_t)` 为条件——一份展示所有子任务目标并标注已完成/当前/待办的进度清单，但只展示当前活跃子任务的详细动作步骤——而非逐字重放演示，那么：(1) 仅靠该训练体系本身即可取得开放权重通用计算机使用的业界最优结果；(2) 额外提供一条相关演示能显著且稳定地同时提升严格任务成功率与长程任务的部分进展——其提升幅度不止于平均完成率，更体现在 agent 消解指令未明确说明之处的**一致性**上。论文在 OSWorld-Verified、WindowsAgentArena 及新提出的 OSWorkerBench（自演示设置：演示与目标是**同一**任务）上检验了这两点，但明确尚未确立更难的变体演示主张——即演示能否在**非完全相同**的相关任务间迁移程序性结构——对此仅在 45 个变体演示目标中的 10 个上做了初步、尚不足以写入基准结论的试点。

# Q4 相关工作与关键人物

* **基础计算机使用/GUI agent**：UI-TARS、UI-TARS-2、Qwen-UI-Agent——能感知界面、锚定动作、在屏幕上执行长流程的视觉语言模型。UI-Mate 的基础策略（在 Qwen3.6-27B 基座上）延续这一脉络，但加入了演示条件化机制与环境驱动的训练体系。
* **可规模化的 GUI 训练数据**：AgentNet、ScaleCUA（跨平台轨迹规模化）、InfiniteWeb（合成网页环境）、CUA-Gym（可验证训练环境）。UI-Mate 的数据流水线借用这些作为原始指令来源，但额外用层级能力树专门诊断并再平衡覆盖缺口（长程、跨应用、错误恢复类任务在廉价生成的语料中系统性地稀缺）。
* **人类示教/演示引导的 agent**：ShowUI-Aloha 表明屏幕录制能暴露可复用的程序性知识。UI-Mate 的 DemoCUA 的区别在于把录制转化为灵活的子任务级工作流（带显式 `subtask_complete` 控制动作与由观测驱动的指针推进），而非逐步脚本。
* **基准**：OSWorld、WindowsAgentArena（通用的仅指令计算机使用评测，UI-Mate 也在其上评测其无演示主张）；OSWorkerBench 是本文新提出的基准。
* **机构**：腾讯混元（Hunyuan）Frontier 团队；核心/联合负责贡献者包括 Longxu Dou、Zihang Jiang、Lei Ke、Weixian Lei、Yingchen Yu（在作者贡献部分被标注为项目联合负责人/负责人/督导）。

# Q5 核心解法

1. **环境驱动的数据流水线（闭环）**。任务指令来自四类互补来源：开源计算机使用数据集（AgentNet、ScaleCUA）；从失败或停滞回放中拆解出的原子子任务（专门针对 agent 明显吃力的操作）；基于真实文档/表格/演示文稿/网站生成的指令（引用具体实体，支持长程多应用工作流）；以及由能力树驱动的生成（挖掘日常工作流本会忽略的细粒度操作）。从回放诊断中提取的层级能力树用于识别覆盖不足的应用/操作/工作流，并反馈回后续的任务与环境构建——形成数据飞轮而非一次性语料。
2. **训练体系**。SFT 教授交互协议、视觉锚定、应用工作流与多步执行；随后在线 agentic RL（含轨迹到 token 的信用分配、异步组相对优化、自适应课程采样）直接针对可执行的任务-验证器组合、在大规模并行环境中训练策略。
3. **DemoCUA 的形式化**。一段演示 `d = (s_1,...,s_N)` 被离线切分为子任务 `s_n = (φ_n, v_n, u_n)`：自然语言目标 `φ_n`、可验证完成准则 `v_n`，以及一组建议性（不可执行、无像素坐标）动作描述 `u_n`。在实时执行的每一步，agent 只以工作流**视图** `g_t = (d, n_t)` 为条件——展示所有子任务目标并标注已完成/当前/待办，但只有当前活跃子任务展示详细动作步骤，而非一次性展示整段原始录制。动作空间被扩展以包含 `subtask_complete`；一旦实时观测 `o_t` 满足 `v_{n_t}` 就发出该动作，从而推进指针 `n_t`。实时截图始终拥有否决权：正确动作由当前观测决定，无演示情形（`g_t = ∅`）被明确当作策略必须同样胜任的基线情形。
4. **训练以实现"优雅地"使用演示**。训练样本刻意覆盖演示与当前界面状态一致、偏离、或完全无关这三类情形，使模型学会把工作流当作可遵循、可跳过、可推翻的指引，而非要盲目执行的固定脚本。
5. **OSWorkerBench 与统一 harness**。100 个跨 41 个规范化应用、10 个职业族的长程办公任务（67 个需要延迟复用动态信息的"长记忆"任务；49 个需要跨至少 3 个应用做信息转移的"多应用"任务），支持仅指令与演示引导两种评测模式，后者又分两种演示机制（33 个自演示目标来自同任务的成功强 agent 回放；45 个变体演示目标来自相关但不完全相同源任务的人类录制）。一个共享 harness（观测-推理-动作循环、历史管理、平台适配器）把同一个训练好的策略同时接入基准评测环境与 UI-Mate App 的实时桌面部署——用户可以录制自己的演示，随即让 agent 针对同一实时环境运行。

# Q6 实验设计

**通用计算机使用**（仅指令、无演示）：UI-Mate-27B 在 OSWorld-Verified、WindowsAgentArena、OSWorkerBench（仅指令模式）上对比闭权重模型、其他开权重模型及通用计算机使用基线。**DemoCUA/演示引导评测**：在 OSWorkerBench 的 33 任务自演示子集与一个 30 任务的 OSWorld-Verified 子集上使用配对协议——相同指令、初始化环境、交互预算、可执行验证器，分别在有无配对演示条件下评测，从而把演示的边际价值与仅指令能力区分开。第 7.2.4 节的决策轮分析进一步在单次决策轮的粒度上考察演示的存在如何改变 agent 行为。45 任务的变体演示设置仅做了一个 10 任务的初步试点，不作为主要基准结论。对比基线包括 Qwen3.6-27B（基座模型本身）、Kimi K2.6、EvoCUA-32B、GPT-5.5、Claude Sonnet 5、Qwen3.7-Plus。

# Q7 数据集与代码

* 通用能力主张使用了两个已有的外部基准（OSWorld-Verified、WindowsAgentArena），训练则使用已有开源数据来源（AgentNet、ScaleCUA）。
* 发布了一个新基准 OSWorkerBench（100 个长程办公任务，41 个应用，配套自演示与变体演示两类资源）——这是一项真正的新数据集贡献，独立于训练语料。
* 项目主页 ui-mate.github.io；代码见 github.com/Tencent/UI-Mate（据 HF 元数据约 57 星）；机构 Tencent-Hunyuan。

# Q8 证据质量

通用能力主张有两个独立的、非作者掌控的既有基准上的配对比较支持得很充分（OSWorld-Verified 77.0%、WindowsAgentArena 66.2%，两者都被报告为对比多个具名开权重与闭权重基线后的新开权重业界最优），OSWorkerBench 上仅指令模式相对同架构基座模型（Qwen3.6-27B）的提升（严格成功率 +17.7、进展 +24.5 个百分点）专门隔离出了训练流水线本身的贡献。演示引导主张是本文最有力、隔离得最干净的结果：自演示配对协议固定指令、环境、预算、验证器不变，只改变演示是否可用，且效应量在三个不同的任务池上都很大且一致（OSWorkerBench 自演示：严格成功率 17.2%→35.4%，进展 67.9%→81.1%；30 任务 OSWorld-Verified 子集：40.3%→65.8%；GameDev：76.8→81.2）。论文对这一证据的边界表述得非常坦诚：明确指出报告中所有量化 DemoCUA 结果都使用**自演示**设置（演示与目标字面上是同一任务），"不应被解读为跨任务变体的程序性迁移"——更难的变体演示主张仅作为一个不稳定的 10 任务试点被报告，而非基准结论，这是一种可信的自我设限而非过度宣称。另有一处自陈的工程局限（关于工作流上下文位置的部分）指出，工作流目前位于上下文起始处，每次子任务更新都会使 KV 缓存前缀失效——这是一个已知的效率代价，而非正确性问题。

# Q9 主要贡献

1. 一个闭环、环境驱动的数据流水线，联合构建任务与可执行环境、过滤回放，并用层级能力树诊断并再平衡训练数据的覆盖缺口，同时供给 SFT 与在线 agentic RL。
2. DemoCUA：一种上下文学习范式，把人类或 agent 的多模态演示转化为自适应的子任务级工作流（每个子任务含目标、可验证完成准则、建议性动作描述），而非僵化的动作序列重放，实时观测在任何一步都拥有否决权。
3. OSWorkerBench：一个新的 100 任务、41 应用、10 职业族的长程办公基准，带受控配对协议（自演示 vs. 变体演示），能把演示引导的边际价值与仅指令 agent 能力区分开——这是现有基准（OSWorld、WindowsAgentArena）不支持的一种测量能力。
4. UI-Mate-27B 在 OSWorld-Verified（77.0%）与 WindowsAgentArena（66.2%）上取得开权重业界最优；演示引导把 OSWorkerBench 自演示的严格成功率从 17.2% 提升到 35.4%，进展从 67.9% 提升到 81.1%。

# Q10 下一步

* 论文自陈的未解问题（第 10 节，讨论与未来工作）：变体演示设置（在非完全相同的相关任务间做程序性迁移）尚未解决——提出三个方向：训练 agent 从部分匹配的演示中提取可迁移结构、识别其未覆盖之处，而非逐步重放；离线大规模获取演示（来自书籍、文档、教学视频），而非逐任务录制；检索——针对实时状态在演示语料库中检索，使覆盖度随语料规模而非标注工作量增长。
* 另一个被单独提出的未来方向是"由验证器锚定的进展信用"：利用第 9 节所述进展信用机制（PCM）的里程碑结构，直接奖励里程碑完成/恢复、惩罚倒退，对可验证里程碑用确定性检查、对不确定状态才用学习到的判定器，同时保持环境的终局残差为权威信号。
* 明确提出的工程修复：把工作流表示移到上下文末尾（仅追加），以在整个episode中恢复 KV 缓存复用，目前因子任务更新位于上下文前缀而失效。
* **对 Research-OS 的启示**：自演示与变体演示的区分，为本仓库中任何希望以过去一次成功运行为条件的技能或 agent 工作流提供了一个有用的框架——本文的证据说明同任务演示引导今天已经很有效，但跨相关而非完全相同任务的迁移仍是一个开放的研究问题，这限定了"给 agent 看一个过去的例子"作为通用可靠性策略时应有多大信心。
