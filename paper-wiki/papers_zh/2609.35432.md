# Q1 问题定义

* **输入（X）：** 给机器人的自然语言任务（RoboCasa365 中的厨房任务、RoboDojo 中的操作任务、PhyBench 中的物理实验，或真实双臂机器人上的桌面任务），相机图像、深度、本体感知，以及一个工具注册表。工具包括感知、运动规划、抓取，以及视觉-语言-动作（VLA）策略等学习得到的动作模型。
* **输出（Y）：** 完成的任务（实验则输出定量结果），外加一条带类型的执行轨迹（世界程序、策略程序、观察、工具调用、结果、验证器判定、记忆），可作为训练数据复用，也可作为修改工具和工作流的证据。
* **核心问题：** VLA 和世界-动作模型（WAM）把观察和指令直接映射成动作块和停止信号，子目标、完成条件和恢复都是隐式的，无法检查或纠正。作者用自己的探测实验支撑这一判断：在 LIBERO 上屏蔽指令训练的 QwenGR00T 策略仍有 92.3% 的成功率，带指令时为 96.2%。
* **约束：** 世界程序必须由真实机器人拥有的信息（图像、本体感知、工具输出）构建，不能依赖仿真器的特权状态；是否成功必须由独立于模型自身完成声明的验证器判定。

# Q2 问题新颖性

部分新。Code as Policies 及其后续工作（CaP-X、CaP-Gym、CaP-Agent0）已经把程序本身当作策略；VisProg、ViperGPT、ConceptGraphs、SayPlan、Statler、VoxPoser、ReKep 等结构化状态系统也用代码表示感知或约束。围绕冻结策略的具身脚手架（Thea、Guava、[Harness VLA](../papers/2607.08448.md)、[Zetta](../papers/2608.16590.md)、SHAPER、GaP、BATON、ASPIRE）已经在演化评审器、恢复规则和技能。作者认为，这些工作每次只改进一个部件而固定其余部分，并把学到的东西存在模型之外。他们主张的不同之处在于：（1）状态与流程共用一种可执行表示，由同一个独立验证器检查；（2）这种表示跨回合持久存在，失败会变成对谓词、工具或工作流的修改；（3）经过验证的轨迹被用来*训练下一版模型*，因此脚手架同时是数据采集工具。

# Q3 科学假设

如果把任务状态保存为可执行的世界程序、把执行过程保存为带类型的策略程序，并把冻结的动作模型作为程序中的一个工具来调用，那么长时程成功率应当上升，因为智能体可以验证进度、打断和恢复，而不是相信动作模型的停止信号。如果用由此得到的已验证轨迹微调规划器，新模型在同一脚手架中应当更好，说明代码轨迹能把物理执行能力内化。如果用失败轨迹在固定评估器下修改工具代码，工具成功率应当在不改变任何权重的情况下上升。

# Q4 相关工作与关键人物

* **动作模型：** VLA 与 WAM 系列（π0.5、GR00T 式动作头、XR-1），以及表明已发布 VLA 对指令不敏感、在视角、初始状态或布局变化下很脆弱的证据。
* **代码即策略：** Code as Policies、把语言计划落地到可用技能上的早期工作（如 “Do As I Can, Not As I Say”）、CaP-X（CaP-Gym、CaP-Bench、CaP-Agent0）、Inner Monologue、ReAct、Voyager。
* **代码即世界：** VCode（把图像理解转化为 SVG 生成）、Visual Sketchpad、场景图、状态记录，以及程序合成的世界模型；作者沿用 VCode 的做法，从图像写出世界程序。
* **具身脚手架：** Thea、Guava、Harness VLA、Zetta、SHAPER、GaP、BATON、ASPIRE。
* **自我演化系统：** GenSim、RoboGen、MimicGen、Eureka、Text2Reward、AlphaEvolve、Darwin Gödel Machine、The AI Scientist、AutoML-Zero、KernelBench、Evolution Gym，以及 autoresearch（智能体在固定评估协议下修改训练脚本）。
* **关键人物：** HexaFuture（hexafuture.ai）。Hongcheng Gao 为项目负责人，Hongcheng Gao 与 Jingjing Zhou 为共同一作，Sihang Wu 与 Xiao He 为通讯作者。可能的批评者：端到端 VLA 团队（会要求与更强或经过微调的动作模型比较），以及 CaP-X 作者（会追问提升中有多少来自设计者提供的工具）。

# Q5 关键解法思路

* **物理编程（Physical Coding）。** *代码即世界*（Code as World）记录物体、关系、测量值、约束和进度谓词，每一项都绑定其来源观察。*代码即策略*（Code as Policy）把规划、工具调用、验证、停止和恢复组织为可以静态检查的显式节点。脚手架是两者之间的“编译器和运行时”。
* **HexaAnything 运行时。** 脚手架有五个接口：工具（VLA/WAM 只是其中一个动作工具）、工作流、验证器、恢复、带来源信息的记忆。它还引入显式契约：保持用户原始任务文本不可变的 GoalContract；只含少数节点类型（观察、动作、VLA 调用、评判、验证、恢复、分支、顺序、循环）的类型化策略；记录每条观察来源的 ObservationEnvelope；以及 TrialOutcome 和 ExperimentSpec 记录。
* **类型化判定。** 验证器返回 Pass、Fail、InsufficientEvidence、Blocked 或 SafetyStop。模型声称“完成”或动作模型给出停止状态都不算成功；达到步数上限记为停止原因，而不是任务失败。恢复是“失败即关闭”的：模棱两可的状态不会被提升为成功。
* **自我演化循环。** 每一轮包含七个操作（规定、执行、验证、诊断、提议、评估、选择并提交），作用于一个带版本的产物包：世界程序、策略、脚手架、数据、记忆和评估器配置。只有在固定留出集上有提升、在受保护集上不退化、并且可以回滚的改动才会被保留。证据阶梯从 E0（产物能运行）到 E4（迁移到真实机器人或有记录的分布变化）区分不同强度的证据。
* **四个演化目标：** 脚手架、数据与环境、模型、本体与算力，“表示与接口的演化”贯穿其中。论文只实际测试了脚手架与工具的演化，以及一次从数据到模型的更新。
* **Vibe as Policy（真实机器人）。** 编程智能体在回合之间编写、验证并冻结工具，冻结的执行智能体在运行时通过 URAI（人类操作员和智能体共用的工具接口）组合这些工具。

# Q6 实验设计

* **脚手架效果（RoboCasa365）：** 50 个任务（18 个 Atomic-Seen、16 个 Composite-Seen、16 个 Composite-Unseen），每个 50 个种子，最大环境步数相同。条件：原生 XR-1；以 GPT-5.6-Sol 为规划器、调用 XR-1 的 HexaAnything；以及用同一模型驱动、调用 XR-1 的 Codex。案例研究在三个 Composite-Unseen 任务上各跑 100 个种子。
* **模型演化：** HexaModel v0.1 是在 1.786 亿 token 上训练一个 epoch 的 Qwen3.8-27B。其中 38.8% 的 token 来自脚手架返回的数据：1,010 条智能体轨迹（703 条基础 Qwen3.8-27B 的成功运行、204 条 GPT-5.6-Sol 的恢复运行、103 条早期微调检查点的恢复运行）和 9.3K 条带思维链的 RoboCasa365 视觉问答样本；其余是通用具身视觉问答、场景描述，以及数学、代码和指令数据。它在同一脚手架中作为规划器进行比较。
* **工具演化（RoboDojo）：** 三个仿真任务（叠衣服、倒花瓶、按数字按键），任务和评估器固定。编程智能体读取失败轨迹并修改工具代码，共两轮修订。叠衣服的开发历史还在不使用特权信息的条件下，于 5 个开发种子和 5 个留出种子上重新评估。
* **PhyBench：** 在 Isaac Sim 中新建的实验室，包含三个实验：弹簧劲度系数（误差 15% 以内算成功）、用三个单摆测重力加速度（3% 以内）、耦合振子的两个简正频率（10% 以内）。每次运行限时 7,200 秒墙钟、18,000 帧仿真预算；每个模型每个任务 10 次试验；四个模型：GPT-6-Astra、Opus 5.5、GPT-5.6-Sol、Qwen3.8-Max。指标是有效运行的平均相对误差。
* **真实机器人：** 配有四台 RealSense 相机的 AgileX PiPER-X 双臂系统上运行七个桌面任务，每个三次，执行智能体为 GPT-6-Astra。用时与同一模型在其他硬件上的公开结果（GPT-Policy、Robocurve）比较。

# Q7 数据集与代码

构建内容：HexaAnything 脚手架及其契约、HexaModel v0.1、PhyBench、URAI 工具接口，以及一组更长的 RoboCasa365 任务（已设计，尚未评测）。Hugging Face 上列出了代码仓库 [HexaFuture/PhysicalCoding](https://github.com/HexaFuture/PhysicalCoding) 和[项目主页](https://hexafuture.ai/blog/physical-coding)；检索到的论文正文本身没有说明会公开哪些组件、数据集或检查点。

# Q8 证据质量

* **有支撑的：**
  * *脚手架能帮助固定的 VLA，在未见过的组合任务上帮助最大。* XR-1 不变时，HexaAnything + GPT-5.6-Sol 把 Composite-Unseen 成功率从 34.3% 提高到 38.3%，Composite-Seen 从 54.8% 到 61.5%，Atomic-Seen 从 78.0% 到 80.9%，总体从 56.6% 到 61.1%。用开放的 Qwen3.8-27B 作规划器时，Composite-Unseen 达到 37.3%。
  * *长任务上单任务提升很大。* 各 100 个种子：LoadKebabSandwich 17%→48%，PortionHotDogs 22%→37%，WaffleReheat 53%→70%。在 PortionHotDogs 上把原生动作预算翻倍并无帮助（21/100 对 22/100），说明提升不只是多走了几步。案例展示了机制：在“两种食材都在烤箱里”这一谓词成立之前，智能体拒绝关上烤箱门。
  * *用脚手架轨迹训练能改进规划器。* HexaModel v0.1 在所有划分上都超过其 Qwen3.8-27B 基座（Composite-Unseen 37.3%→39.5%，总体 60.5%→61.7%），并在同一脚手架中在每个划分上都以 0.1-1.2 个百分点小幅超过 GPT-5.6-Sol。
  * *智能体修改工具，无需改权重即可提升。* 在 RoboDojo 上，两轮修订后叠衣服、倒花瓶、按数字按键的成功率从 0%/40%/0% 升到 80%/100%/100%。提升并非单调：倒花瓶第一轮修订后降到 0%。
  * *同一脚手架能完成物理实验。* GPT-6-Astra 和 Opus 5.5 在各自 30 次运行中全部得到有效结果，GPT-5.6-Sol 为 30 次中的 27 次；三者在每个任务上的平均相对误差都低于 5%（例如 Opus 5.5：劲度系数 1.3%、重力加速度 1.0%；GPT-6-Astra：简正频率 0.8%）。Qwen3.8-Max 在三个任务上分别只有 5、3、3 次（共 10 次）得到有效结果。
  * *真实机器人上多数任务可以完成。* 七个任务中有五个三次全部成功；扔积木进碗和叠衣服各成功一次（进度 77.8% 和 83.3%），失败原因在感知和可达范围，而不在工具。
* **较弱或有边界的：**
  * *脚手架带来的提升有限，且受模型限制。* 只用一个动作模型（XR-1）在一个基准上测量；相对同一模型驱动的 Codex，总体只领先 1.6 个百分点，而 Codex 在 Atomic-Seen 上更高（81.7% 对 80.9%）。这些局限作者自己也列出了。
  * *模型演化的提升很小。* HexaModel 的提升为 0.2-2.2 个百分点，每个任务 50 个种子，没有报告置信区间。训练数据中 61% 不是脚手架数据，也没有把脚手架轨迹与通用数据分开的消融（读者笔记）。
  * *工具演化的数字基于很少的种子，且有一个任务在开发时用了特权输入。* 叠衣服开发时，操作员在为三个开发种子选择像素时参考了与官方检查同源的衣物关键点，而且每次调用的像素都由操作员选择。在去掉特权信息后重新评估，最终工具在开发种子上 3/5、在留出种子上 4/5 成功。按作者自己的说法，这衡量的是工具和接口，而不是自主感知。
  * *PhyBench 是作者自建的新仿真基准*，每个模型每个任务只有 10 次试验；胡克定律和单摆的案例是挑选出来的、完整通过且保留了完整轨迹的运行。
  * *真实机器人的比较不是同一台机器人。* GPT-Policy 和 Robocurve 的参考结果（快 2.7 倍、3.5 倍、2.4 倍）来自其他硬件和运行限制，每个任务只有三次试验。
  * *若干主张属于规划而非已证明。* 模型架构演化、表示演化、本体与硬件演化，以及更长的 RoboCasa365 任务（已设计未评测）都是未来工作，论文对此有明确说明。

# Q9 贡献

* 物理编程的形式化：世界与策略是相互耦合的可执行程序，观察带来源标记，由类型化的独立验证器作为一切自我演化的门控。
* HexaAnything：一个具体的脚手架，带有执行契约（GoalContract、类型化策略节点、ObservationEnvelope、失败即关闭的恢复），使提升可以归因到工作流、验证器、恢复、模型或工具的改动。
* 围绕固定 VLA 的脚手架、模型和工具改进的受控证据，包括一个用脚手架轨迹训练的开放 27B 规划器，在同一脚手架中与前沿规划器持平。
* PhyBench：一个交付物是“有记录证据支撑的物理量估计”的仿真实验室；以及首次真实机器人部署，其中工具演化只依靠相机和关节轨迹加上操作员判断。

# Q10 下一步

* **减少脚手架辅助下的权重内化**（作者的分阶段计划）：检验去掉验证和恢复脚手架、或在留出组合上时，HexaModel 能否保持提升。
* **更强的动作模型和更多基准：** 用其他 VLA/WAM 和基准重复脚手架对比，因为“单一 VLA、单一基准”是其普适性的主要威胁。
* **工具演化中的自主感知：** 用智能体选择的像素替代操作员选择的像素，重新测量叠衣服这类提升。
* **验证器与模型的共同适应：** 作者把“防止模型与验证器共同适应”列为开放问题；一旦验证器也开始演化，这一点就很关键。
* **离线与部署时的智能体投入（读者笔记）：** [EmbodiedSWE](../papers/2609.27308.md) 把编程智能体的算力花在离线生成 VLA 训练数据上，HexaAnything 则在运行时包裹冻结的 VLA，再把轨迹蒸馏进*规划器*。在相同的 RoboCasa365 任务上同时运行两者，可以回答 [智能体机器人操作](../topics/robot-manipulation-agents.md) 中的开放问题。
* **验证器看到了什么（读者笔记）：** [Zetta](../papers/2608.16590.md) 在视觉证据不足时退回到仿真器特权信号，HexaAnything 则刻意避免这样做。一次匹配的比较能看出这一限制在仿真中的代价。
