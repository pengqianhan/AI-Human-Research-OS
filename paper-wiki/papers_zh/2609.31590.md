# Q1 问题定义

* **输入（X）：** 一个回合制 MMORPG 沙盒中的任务。沙盒基于开源 Kaetram 引擎，每个任务包括：
  * 一个任何单个智能体都无法独立完成的主目标；
  * 3–20 个角色不对称的智能体，各自有不同技能、出生位置和初始物品；
  * 25–55 回合的回合预算；
  * 给每个智能体的指引文档，写明相关配方、怪物属性和资源位置。

  每一回合，每个智能体依次收到周边环境的结构化文本观测和团队聊天记录，并从 13 个高层 API 工具（移动、攻击、采集、合成、转移、聊天等）中恰好调用一个。
* **输出（Y）：** 团队轨迹。评分有三种：每个任务的 Python 验证器根据最终游戏状态判定的二值任务成功（SR）；验证器检查点完成比例（部分成功率，PSR）；以及新提出的协作指标——因果协作有效性（Causal Collaboration Effectiveness，CCE）。
* **约束——黑箱设定：** 智能体看不到队友的内部状态、观测或动作历史，只能通过环境转发的聊天消息协调。
* **核心问题：** 论文认为现有多智能体基准无法单独衡量*协作*能力。它们或者时程短（≤10–20 步），或者把协作和底层动作控制（3D 导航、方块放置）混在一起，或者只是汇总个体表现；大规模社会模拟则缺乏具体可测的任务。

# Q2 问题新颖性

部分新颖。多智能体 LLM 协作基准已有不少（MultiAgentBench、Collab-Overcooked、MINDAGENT、TeamCraft、MineLand、MindCraft），人口规模模拟也有（Generative Agents、Project Sid、AgentSociety）。论文声称的空白是表 1 中的*组合*：长时程、黑箱交互、角色不对称，以及用工具屏蔽底层控制的开放世界沙盒。对比表把 AgentWorld 的时程写成"50+"回合，而正文给出的每任务预算是 25–55 回合（平均 38）；摘要中的"50+"应理解为上限范围，而非最低值（读者观察）。

指标方面的贡献更有特色：CCE 不再让 LLM 整体打分（"给协作打 1–5 分"），而是从成功动作出发向回追溯，只做二值的因果依赖判断。

# Q3 科学假设

如果把底层控制抽象成单次工具调用，并把任务设计成*必须*依靠跨智能体的资源流转和时间配合才能成功，那么：(a) 基准分数将主要反映协作质量；(b) 当前 LLM 会暴露出很大的协作差距，而单看任务成功率会低估这一差距。

论文用基线和设计消融检验 (a)：单智能体、无通信、神谕通信（oracle communication）等变体，以及去掉角色、文档或长时程的版本。用 CCE 检验 (b)：统计团队投入中有多少真正促成了结果。

# Q4 相关工作与关键人物

* **多智能体 LLM 基准：** MultiAgentBench（协调协议）、Collab-Overcooked 与 MINDAGENT（Overcooked 厨房）、TeamCraft 与 MineLand（Minecraft）、MindCraft（心智理论对话）、TheAgentCompany（模拟职场）。单智能体游戏和智能体基准——AgentBench、AgentBoard、Voyager、BALROG、Craftax——被认为没有涉及协作。
* **社会模拟与框架：** Generative Agents 及其 1,000 人后续工作、Project Sid、AgentSociety、Werewolf Arena 与用 RL 玩狼人杀的工作（社交推理）、CAMEL、AutoGen、AgentVerse；平台对比表还列出了 Smallville。
* **多智能体 RL 平台：** PettingZoo、SMAC、Overcooked-AI、Melting Pot、Hanabi。这些环境很丰富，但面向 RL 智能体而非 LLM 智能体。
* **关键人物：** 由哥伦比亚大学、宾夕法尼亚大学、宾州州立大学、首尔大学与 OpenAgents 社区合作完成，第一作者 Raphael Shu 署名 OpenAgents。资深作者为 Zhou Yu（哥伦比亚）、Lyle Ungar 与 Sharath Chandra Guntuku（宾大）、Rui Zhang（宾州州立）。最可能提出批评的是 MultiAgentBench、Collab-Overcooked、TeamCraft 和狼人杀/社交推理工作的作者，以及 CCE 所针对的"用 LLM 评审给协作打分"做法的支持者。

# Q5 核心解决思路

AgentWorld 与此前协作基准的区别在于两个设计：

* **隔离协作的环境。** 世界足够丰富，任务才能多样且长：380+ 种物品、144 种怪物、70+ 个 NPC、1,531 个资源点、8 种技能、9 种生物群系。每个多步机制都封装进一次工具调用（例如 `attack_entity` 包办寻路、战斗和拾取战利品），决策预算因此花在*做什么、和谁配合*上，而不是*怎么操作*。确定性的轮转顺序保证可复现；模拟器本身最多支持 1,000 个并发智能体。
* **因果协作有效性（CCE）。** 从 LLM 识别出的成功动作出发，逐回合向回扫描。每一回合，LLM（GPT-4.1，温度 0）做二值判断：哪些更早的动作在因果上促成了已确认的贡献动作。由此得到贡献集合 C，CCE = |C| / |T|，分母是所有智能体的*全部*动作（包括聊天消息）；失败任务的 CCE 记为 0。每个智能体的版本（PAC）可以显示成功是否只依赖少数智能体。标注策略刻意从宽，所以论文把 CCE 解读为真正有用动作比例的*上界*。

# Q6 实验设计

* **任务：** 100 个人工标注的主任务，分 8 类（战斗、合成、采集、交易、探索、生存、建造、协调），每个任务配有验证器和每个智能体的文档。任务由 5 名标注者设计，并用两个 LLM 做试跑、反复修改，直到只剩智能体本身的错误。另有 100 个由 Claude Opus 4.5 生成的增强变体（目标更重、出生点更远、初始物品更少）。人工抽查 10%：全部保留了协作需求、目标和角色不对称，90% 的难度被判为合适。
* **模型：** Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini、DeepSeek R1-70B，使用相同的提示词和工具定义。另外单独报告了两个模型：Muse-Glimmer-30B，以及结果标注为临时的 Gemma 4 26B A4B。
* **基线（Gemini 3 Flash，主集）：** 随机合法动作；单个智能体掌握所有角色和物品；无通信；无通信但给一份人写的共享计划；神谕通信（一个智能体看到所有消息并协调团队）。
* **设计消融（35 个任务的子集）：** 去掉角色信息；把回合预算从 50 缩到 10；随机出生点；不给文档。
* **指标验证：** 人工核对 84 个动作级因果判断；换用 Claude Sonnet 4 和 Llama-4 Maverick 作评审重算 CCE。
* **稳健性：** Gemini 3 Flash 在 35 任务子集上跑三次（温度 0.7，三个随机种子）。
* **没有设计进去的：** 其他模型没有多种子运行，模型之间没有显著性检验，也没有评测任何厂商最强档的模型——四个主要模型都是小型或快速版本（读者观察）。

# Q7 数据集与代码

新基准：100 个人工标注任务加 100 个增强变体，附验证器、基于 Kaetram 的沙盒、评测脚本和网页任务标注平台，论文称全部开源（项目主页 [agentworld.io](https://agentworld.io/)；论文说代码和数据在 GitHub 上，但检索到的正文没有给出仓库地址）。底层游戏引擎是 [Kaetram-Open](https://github.com/Kaetram/Kaetram-Open)。

# Q8 证据质量

* **有支撑——任务确实需要多个智能体和通信：** 随机动作解决 5.7%，单智能体 28.6%，无通信团队 22.9%，默认黑箱团队 52.0%，神谕通信 60.0%（表 3）。
* **有支撑——基准远未饱和：** 主集 SR 分别为 52.0%（Gemini 3 Flash）、45.0%（Claude Haiku 4.5）、36.0%（GPT-5 Mini）、20.0%（DeepSeek R1-70B）；所有模型在增强集上都下降（Gemini 降到 24%）。结论部分称 27% 的任务没有任何模型解出。
* **有支撑——通信多不等于协调好：** GPT-5 Mini 发消息最多（每任务 44.1 条）却只排第三；在它失败的任务中 26% 的动作是聊天。对 Gemini 3 Flash 消息的错误分析找到 61 个通信错误，占比最大的（37.7%）是过时或冗余的消息。
* **有支撑但有保留——CCE 定义合理：** 人与评审在 84 个判断上一致率 82%（Cohen's κ = 0.64），与两个评审模型之间的一致性相当（7,298 个判断上 κ = 0.66）。三个评审下模型排名完全一致，CCE 绝对值最多变化约 0.05。但只有来自 11 个任务、1 名标注者的 84 个判断，人工核对规模偏小。
* **CCE 相对 SR 的增量有限：** 平均 CCE 的排名与 SR 相同，因为失败任务记 0。真正有信息量的是*以成功为条件*的 CCE——Claude Haiku 4.5 0.653、Gemini 0.609、GPT-5 Mini 0.571——Claude 的 SR 较低，但成功时浪费的动作更少。
* **令人意外但缺乏检验：** 人写的共享计划反而*降低*了无通信团队的成功率（22.9% → 17.6%）。论文解释为没有通信就无法修补计划，但没有进一步验证。
* **较弱之处：** 设计消融和方差检查只用了 35 任务子集和一个模型；三个种子的 SR 完全相同（54.3%），但正如论文所说，这既不能说明其他模型的稳定性，也不能说明模型差异显著。两个额外模型在另一个划分上评测，其中一个结果是临时的，与四个主要模型不可比。

# Q9 贡献

* 一个长时程、黑箱、角色不对称的协作基准：用工具抽象刻意去除底层控制这一混淆因素，配有人写的验证器和便于扩展的开放标注平台。
* CCE：一个轨迹级协作指标，只让 LLM 做二值因果判断，排名对评审模型稳健。这是一个可复用的模式，适用于任何需要衡量"无效投入"的多智能体或长时程轨迹。
* 把协作与原始能力分开的基线证据（单智能体 28.6%、团队 52.0%、神谕通信 60.0%），以及一份通信失败模式清单。

# Q10 下一步

* **更强的模型、更多种子：** 评测最强档模型，并对每个模型重复运行，这样模型之间 7–9 个点的 SR 差距才能做显著性检验。
* **扩大 CCE 的人工验证：** 更多任务和标注者，并检查从宽标注策略带来的高估，因为 CCE 被定位为上界。
* **通信与规划干预：** 共享计划的结果提示可以测试*可修改*的计划，或计划加有限通信；也值得检验神谕通信的提升（+8 个点）来自信息汇集还是集中决策。
* **用作训练环境（读者构想的方向）：** 验证器、回合制的确定性和 CCE 式的稠密信号，可以作为多智能体协调的 RL 奖励，类似 [WideSeek-R1](../papers/2602.04634.md) 端到端学习任务委派。
* **与项目的关联（读者笔记）：** CCE 的向回因果追溯是一种通用的轨迹审计方法，可用于本仓库：检查哪些动作真正促成了最终交付的产物，而不需要开放式的质量打分。

# 相关

* [多智能体系统](../topics/multi-agent-systems.md) - 该主题中各种协调模式的评测侧对应物：它衡量没有辅助的 LLM 团队仅靠聊天能协调得多好；神谕通信基线（一个智能体看到所有消息）是集中式协调与分散式聊天的受控对照。
* [游戏智能体](../topics/game-agents.md) - 以游戏世界为测试平台，但通过高层工具去掉了控制问题，这与像素加按键的游戏基准（如 [GameHorizon Suite](../papers/2609.25001.md)）的设计取向相反，因而单独考察规划与协调而非动作执行。
* [Game Arena](../papers/2609.31473.md) - 互补的竞争设定：一对一策略游戏，外加一个社交推理多人游戏（狼人杀）；AgentWorld 则是完全合作的。
* [LLM 作为评审](../concepts/llm-as-a-judge.md) - CCE 保留了 LLM 评审，但把它收窄为二值因果依赖判断，并报告人工一致性（κ = 0.64）和跨评审的排名稳定性，以论证这比整体打分更可复现。
