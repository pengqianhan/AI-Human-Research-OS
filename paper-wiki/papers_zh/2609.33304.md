# Q1 问题定义

* **输入（X）：** 用户的交互历史 $\mathcal{M}_u = \{r_i\}$，每条记录 $r_i = (g_i, p_i, c_i, \tau_i, \xi_i)$ 包含目标、应用、场景、时间戳，以及一条由“屏幕-动作”对组成的轨迹。两种设置：*个性化执行*另外给出一条有歧义的指令 $q$（“点我常喝的咖啡”）、当前屏幕 $s_t$ 和此前的动作；*主动建议*只给出场景和时间戳 $(c_x, \tau_x)$。
* **输出（Y）：** 执行设置下是下一个 GUI 动作；建议设置下是一条建议的例行事务，或者选择不建议。
* **约束：** GUI 策略模型和所有编码器都冻结，不做任何训练。历史是每个用户按时间排序的前 80% 记录。
* **核心问题：** 在每一次决策时，历史中的哪一部分应该送到策略模型面前。检索在任务层面回答这个问题（哪些记录与这条指令相关）；论文认为真正有用的答案取决于决策时刻的情境（哪个过去的动作适合眼前这块屏幕；某个例行事务在此时此地是否该做了）。

# Q2 问题新颖性

个性化和主动式的手机智能体已经是一条现有路线（Fingertip 20K、KnowU-Bench，以及提出 AndroidIntent 基准和 HIM-Agent 的 PersonalAlign），它们使用历史的方式都是把记录检索或总结后放进提示词。新的部分是诊断：把一个 episode 的第一步与其余步骤分开计分后可以看到，检索到的历史在第一次决策时就被用完了。论文把这称为“相关性”与“适用性”之间的差距，并把个性化重新表述为决策时刻的选择问题。

# Q3 科学假设

1. **任务级检索只在开头起作用。** 如果把检索到的历史附加到提示词里，episode 第一个动作（决定打开哪个应用）的步成功率会提高，而其余步骤停留在不用历史的水平。
2. **步级激活在轨迹内部起作用。** 如果把每一块新屏幕与任务相关轨迹中记录下来的屏幕做匹配，把最匹配的那一个过去的动作作为参考提供给策略，并在每次观察后重新计算，轨迹内部的步成功率会上升，而且用到的历史 token 更少。
3. **显式的门控让主动建议有选择性。** 如果只有当某个例行事务过去的发生记录在当前时段和当前场景下提供了足够支持时才建议，智能体就能区分该建议和不该建议的状态，而在提示词层面使用历史做不到这一点。

# Q4 相关工作与关键人物

* **个性化 GUI 智能体。** Fingertip 20K、KnowU-Bench，以及 PersonalAlign（Lyu et al., 2026）；后者提出了 AndroidIntent 和 HIM-Agent，一种把长期记录聚合成偏好原型和例行原型的层级意图记忆。HIM-Agent 是最接近的先例，也是最强的基线。
* **GUI 智能体中的记忆与经验复用。** Agent Workflow Memory 等工作流式或结构化记忆；MementoGUI 围绕冻结的骨干模型学习记忆的选择与压缩；ATMem 跟踪任务信息的角色和状态。ExpActivator 的不同之处是每一步只选出一个具体的过去动作，不训练记忆控制器。
* **主动协助。** 从历史、屏幕活动和设备上下文推断意图的基准，以及对介入时机的交互式评测。
* **关键人物。** 南洋理工大学与阿里巴巴（单位一栏写的是“NTU & Alibaba”；最后一位作者是 Wei Yang Bryan Lim）。可能的批评者：PersonalAlign 的作者，因为四个基线中有两个是他们基准自带的机制，还有一个（LLM-UM）是本文作者重新生成的；以及会要求做真机执行、而不是与记录动作做逐步比对的 GUI 智能体研究者。

# Q5 关键解决思路

两种机制是同一条规则的两个实例：从候选集合中选出与当前输入最相容的元素，返回它对应的动作或意图。

**步级激活（执行过程中）。**

* *先按任务收窄。* 用冻结的多语言 MiniLM 编码器嵌入指令和每个历史目标（去掉开头“打开某应用”的短语）；轨迹可读的记录中相似度最高的 $K_\xi = 8$ 条构成候选集，在整个任务中保持不变。
* *开场参考。* 在第一次观察之前，对最相似的十条记录做按排名加权的投票，选出一个应用，提供 `open_app(p*)`。
* *匹配屏幕。* 用 GUI 骨干模型自己的视觉塔，对当前截图取若干池化后的 token 块（最后一层 token 网格的四个象限，MAI-UI 另加一个全局块），每个块减去它在校准图像上的均值并归一化。相容性得分是与候选轨迹中每块已记录屏幕的逐块余弦相似度的平均。
* *只提供一个动作。* 把最匹配的那块屏幕上记录的动作序列化（点击坐标用 0-999 的归一化坐标系），作为候选附在提示词后面；策略模型看过当前屏幕后可以采纳、改写或拒绝它。
* *每一步都刷新。* 每次观察后重新匹配，所以参考可以在不同步骤之间、也可以在不同轨迹之间移动。

**任务级激活（执行之前）。**

* *形成例行事务。* 每个历史意图都是一个中心；它的邻域是所有嵌入相似度不低于 $\eta = 0.94$ 的历史意图，查询时间戳上的记录除外。邻域之间可以重叠。
* *在情境中计算支持度。* $M_j(x)$ 对“与当前场景相同”的邻居求和，每一项是按一天内环形时间距离计算的高斯权重（$\sigma = 1$ 小时）。
* *先过门，再排序。* 一个例行事务只有在总共出现至少 $n_{\min} = 12$ 次、在当前场景中出现至少 $n_{\mathrm{ctx}} = 4$ 次、且 $M_j \geq \delta = 0.25$ 时才有资格。没有任何一个有资格时，智能体不建议。否则选 $M_j / n_j$ 最高的那个，并把其中同场景成员里最居中的意图交给冻结的骨干模型，由它把建议说出来。

因此，“要不要开口”是在调用语言模型之前由一条显式规则决定的；模型只负责措辞。

# Q6 实验设计

* **数据。** AndroidIntent：82 位用户的长期手机使用记录，涉及 135 个应用和 13 类场景。历史共 15,966 条记录（每位用户 39 到 414 条，中位数 196.5）。执行设置有 775 个 episode、7,915 步，指令是有意写得含糊的；主动建议设置有 315 个状态，215 个正例、100 个负例。
* **协议。** 离线、逐步进行：策略模型拿到的是记录下来的当前屏幕和真实的前序动作，它预测的动作与记录的动作比对。步成功要求动作类型和参数都匹配（点击落在归一化距离 0.14 以内、滚动方向相同、输入文本字符相似度达到 0.7、打开的应用正确）。CSR 是基准自带的 episode 指标，对靠前的步骤按指数加权。
* **骨干模型。** Qwen3-VL-8B、[MAI-UI-8B](../papers/2512.22047.md)、Qwen3.5-9B 和 GUI-Owl-1.5-8B，全部冻结，贪心解码；QwenVL-Max 作为外部参照。
* **基线。** 不用历史；Recent（最近三条记录）；Retrieve（最相似的三条记录）；LLM-UM（离线由 LLM 写的用户画像，因为原始画像没有发布，作者用 Qwen3.5-9B 重新生成）；以及按其发布流程运行的 HIM-Agent。所有方法读取同一份历史。
* **主动建议指标。** 平衡准确率和马修斯相关系数（MCC）；之所以选它们，是因为 68% 的状态是正例，一条“永远建议”的规则就已经能拿到 81.1 的 F1。
* **统计。** 按用户做配对自助法（20,000 次抽样，同一用户的所有步骤放在一起）。
* **分析。** 开场步与轨迹内部的成功率对比、历史 token 成本、按历史规模对用户分四分位、同一条轨迹“选一步”对比“整条附加”、过期屏幕对照、参考在轨迹之间切换的频率、任务级的三项消融，以及阈值扫描。

# Q7 数据集与代码

有[项目主页](https://fyzhang1.github.io/ExpActivator/)和 GitHub 仓库 [fyzhang1/ExpActivator](https://github.com/fyzhang1/ExpActivator)（抓取时 4 星）；仓库内容本笔记没有核查。没有新数据集：所有实验都在 PersonalAlign（arXiv:2601.09636）的 AndroidIntent 上进行。论文说它的成本分析和历史规模分析可以用两个具名脚本从封存的运行文件中复现。

# Q8 证据质量

* **有支撑的结论。**
  * *诊断本身。* 在 Qwen3-VL-8B 上，开场步的成功率从不用历史时的 28.26% 升到三种检索或画像基线下的 62.06-62.32%，而其余 7,140 个动作的轨迹内成功率停在 17.63-18.36%，不用历史时是 18.43%；每个差值的置信区间都包含零。在全部十六个“基线-骨干”组合中，轨迹内的提升从未超过 2.4 个点，其中十二个与零无法区分。
  * *步级激活在检索无效的地方有效。* 相对于不用历史，四个骨干模型上的轨迹内提升分别为 +8.24、+5.67、+3.74 和 +2.38 个点，所有区间都不含零。总体 SSR 在每一组中都最高（30.9、26.6、24.3、28.9），CSR 也是（47.9、42.7、40.9、45.8）。
  * *原因是“选择”，不是“更多历史”。* 只允许使用排名第一的那条轨迹时，整条提供得到 18.47% 的 SSR，从中选一个动作得到 23.84%。改为用上一块屏幕做匹配会损失 4.03 个点，每四步才刷新一次会损失 3.50 个点，两个区间都不含零。
  * *提示词 token 更省。* 每步 144.6 个历史 token，HIM-Agent 为 417.8，另外三种为 730.6-843.7。
  * *不需要很长的历史。* 在每个用户四分位中，相对最强基线的提升都至少有 6.4 个点，包括只有 39 到 111 条记录的用户。
  * *门控带来了表中唯一有选择性的主动行为。* MCC 为 42.7、45.2、38.9 和 44.6，HIM-Agent 为 20.7、14.1、22.0 和 19.0；基于记录和画像的基线接近零，其中三个在 MAI-UI 上对每个状态都给出建议。ExpActivator 的误报率为 21-37%，而大多数基线为 70-100%。
* **比标题结论更弱或更窄之处。**
  * *评测的是与记录动作的一致，而不是任务完成。* 每一步喂给策略模型的都是记录下来的屏幕和真实的动作前缀，所以没有任何 episode 被真正执行，错误也不会累积。这些数字说明的是在用户自己的数据上预测下一步动作更准，这是基准的协议；它们对真机成功率没有直接说明。
  * *参考可能离答案很近。* 这个方法取回的是同一位用户在一块几乎相同的屏幕上做过的事，而指标衡量的是模型是否复现了该用户接下来做的事。对重复的例行事务来说，这在构造上就是很强的先验信息，这正是论文的主张，但也意味着提升幅度衡量的是这些用户在这些应用中有多重复（读者观察）。在校准中，匹配到的屏幕上的动作与记录动作一致的比例只有 35.1-36.6%（按像素匹配为 29.6%），所以参考只是提示，不是查表。
  * *各骨干模型上的提升不均匀。* 在 GUI-Owl-1.5-8B 上，轨迹内提升为 +2.38 [+0.53, +4.41]，HIM-Agent 为 +1.92；总体 SSR 只比 Retrieve 高 0.7 个点（28.9 对 28.2）。摘要中的“平均 28%”是约 11% 到 45% 的相对提升的平均（读者根据论文表 12 计算）。
  * *主动建议的大部分提升可能来自“有一道显式的门”这件事本身。* 基线把决定权交给一个读原始记录的 8-9B 模型，它们大多永远建议。论文对自己规则的消融，去掉时间加权或去掉场景条件后，平衡准确率仍有 69.33 和 64.58（在生成建议之前计分），高于所有靠提示词的基线（最高 61.2）。所以这个对比更多说明“规则胜过提示词”，而不是“这条规则胜过别的规则”（读者根据论文表 1 和表 10 推断）；论文没有包含简单的“频率加时间”规则基线。
  * *门控常数是怎么选的，没有说明。* 步级设置是在伪留出的历史上校准的，并给出了样本数。对任务级的六个常数，附录只列出取值并说它们在评测前就已固定；在 315 个测试状态上的扫描显示，所声明的设置距网格最大 AUROC 不到 0.33 个点，而且 $n_{\min}$ 正好取在可用范围的上沿。在已读部分中没有提到为它们单独划分验证集。
  * *建议质量并非处处最好。* 语义得分在 MAI-UI 上低于 HIM-Agent（49.6 对 50.5），在 Qwen3.5-9B 上低于 Retrieve（51.0 对 52.1）。召回率从接近 100% 降到 62.8-82.3%，F1 与“永远建议”大致相同。在所声明的阈值下，27.6% 的状态根本没有任何有资格的例行事务。
  * *一个数据集，82 位用户。* AndroidIntent 来自 HIM-Agent 的作者；有一个基线是重新实现的。token 统计没有计入每步额外的一次视觉编码，以及为每张历史截图存储的特征；论文描述了这些开销，但没有给出代价。

# Q9 贡献

* “开场步对比轨迹内部”这一分析方法：一个简单的办法，用来看记忆在哪里起作用，适用于任何带逐步标签的智能体基准。
* 证据表明，同一条记录，从中选出一个适用的动作时有帮助，整条附加时毫无作用。
* 一个免训练的步级机制，复用策略模型自己的视觉特征做状态匹配；以及一个基于规则的主动建议门，把“是否有资格”（绝对支持度）和“如何排序”（每次出现的平均支持度）分开。
* 论证了在类别不平衡的状态集上不应该用 F1 评主动建议，并在给出平衡准确率和 MCC 的同时报告了完整的混淆矩阵比率。

# Q10 下一步

* **做真机执行（读者建议）。** 在设备或模拟器上实际执行 episode，让“采纳参考”真的改变下一块屏幕，并测量完成率。
* **为主动建议加入规则基线（读者建议）。** 只看频率、只看时间的触发规则，经过同一套骨干模型提示词；并为门控常数划分验证集。
* **在重复之外检验（读者建议）。** 对应用或目标此前出现次数很少的 episode 单独报告提升，看历史只是松散相关时激活能做什么。
* **让策略模型判断适用性（读者建议）。** 提示词已经告诉模型可以拒绝候选；测量它拒绝的频率、以及拒绝得对不对，就能看出结果是由屏幕匹配还是由策略模型撑起来的。
* **项目契合（读者笔记）。** “与任务相关”和“适用于这一步”的区分同样适用于本仓库的记忆层。在会话开始时加载相关的 handoff 或记忆条目属于任务级检索，按这篇论文的测量，它主要帮助决定从哪里开始。要影响后面某个具体决策的指引，需要在那个决策点、按当时实际观察到的状态去取。

# 相关

* [GUI 与计算机使用智能体](../topics/gui-computer-use-agents.md) - 每一步用一个过去的动作来约束冻结的手机 GUI 策略，这个动作通过在策略模型自己的视觉特征中把当前截图与用户记录过的屏幕做匹配来选出。
* [智能体记忆](../topics/agent-memory.md) - 把相关性（每个任务检索一次）与适用性（每次决策重新选择）分开，并表明附加的历史只帮到 episode 的第一步。
* [主动式智能体](../topics/proactive-agents.md) - 在调用语言模型之前，用一条显式的“时间与场景支持度”规则决定是否建议；并主张在多数状态为正例时用平衡准确率和 MCC 取代 F1。
* [MAI-UI](../papers/2512.22047.md) - 四个冻结骨干之一（MAI-UI-8B）；它校准后的屏幕描述在四个象限之外增加了一个全局块。
* [UI-Mate](../papers/2608.15930.md) - 同样用上下文中的经验来约束 GUI 执行，那里是把多模态演示变成子任务级的工作流；ExpActivator 只提供一个动作，并在每块屏幕上重新选择。
* [Foundations of Proactive Agents](../papers/2609.37267.md) - 围绕“何时介入、介入多深”来刻画主动性；ExpActivator 给出了一条关于“何时”的具体规则，评测的是单个状态上的建议决定，而不是跨多日的信任。
* [nanoMuse](../papers/2610.08699.md) - 一个有屏幕控制和文件式记忆、但没有能力测量的个人智能体；ExpActivator 测量了这类智能体使用个人历史的一种方式。
* [Memadapter](../papers/2610.05162.md) - 同样在检索与使用之间插入一个免训练的层，追问检索到的记忆何时适用；对象是对话记忆和谄媚，而不是 GUI 动作。
* [Jev-Mem](../papers/2609.23986.md) - 把记忆控制决策交给非生成式的控制器，LLM 只负责合成；ExpActivator 的主动建议门是同样的分工。
* [Learn2Play Bench](../papers/2610.08215.md) 和 [EmbodiedCLBench](../papers/2610.13021.md) - 比较携带经验的不同形式（原始历史对比提炼的教训或技能）；ExpActivator 增加了第三种选项，即选出的单个步骤，并发现整条轨迹与不用历史没有差别。
