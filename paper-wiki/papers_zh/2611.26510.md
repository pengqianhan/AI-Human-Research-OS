# Q1 问题定义

* **输入（X）：** 一个固定的教师模型（DeepSeek-V4-Pro-Preview），每个领域一个由 1,000 个训练任务组成、带执行环境的固定任务池，一个初始学生检查点（Qwen3.5-4B 或 9B），以及未加引导的教师和初始学生生成的初始轨迹。
* **输出（Y）：** 一个由 512 条轨迹组成的训练集，以及在其上微调得到的学生；要求它在领域基准上的得分高于在 512 条随机抽取的、成功的未引导教师轨迹上训练出的学生。
* **约束：** 各方法的教师、任务池、训练集大小和 SFT 配方都相同；学生总是从初始检查点开始训练；评测时学生不带任何生成的技能，遵循各基准的官方协议；智能体最多有五轮外层循环的预算。

# Q2 问题新颖性

在成功的智能体轨迹上做 SFT（从 FireAct 开始）、按有用行为挑选轨迹（Behavior Priming）、从教师失败中恢复示范（PROOF-Gen）、不更新权重的技能与提示优化（GEPA 等），以及由智能体来执行后训练（FT-Agent、RSI-Master）都已存在。本文的切入点是：成功标签并不说明一条示范在教什么行为。成功轨迹里仍可能有无依据的论断、反复瞎猜或流于表面的检查。论文主张在生成阶段就塑造教师的行为（包括教师本来就能解决的任务），并由一个智能体来负责这种塑造。

# Q3 科学假设

如果由智能体编写技能指令，改变固定教师的推理和验证方式，并同时按行为和结果挑选示范，那么用同样数量的轨迹、同样的配方微调出的学生，会比在随机成功的未引导轨迹上训练出的学生得分更高。第二个假设：在学生的训练输入中保留技能文本（尽管评测时没有），有助于学生内化每种行为的适用条件。

# Q4 相关工作与关键人物

* **自主后训练。** 根据评测反馈修改训练代码的智能体（autoresearch 式循环）、FT-Agent（数据与训练策略迭代）、RSI-Master（持久化实验记录与审稿人指导）、Agent²RL-Bench。
* **基于技能的智能体学习。** GEPA 等提示与技能优化器；技能库或流程脚手架与训练的协同演化；Skill-to-LoRA（用技能引导的示范训练技能专用适配器）；Skill-SD（以技能为条件的教师给学生自己的 rollout 逐 token 打分）。
* **从智能体轨迹中学习。** FireAct、AlphaMath、步级偏好方法、错误恢复轨迹、Behavior Priming、PROOF-Gen。
* **关键人物。** Guoxin Chen 和 Shuang Sun（共同一作）、Fanzhe Meng、Xinyu Tang、Ruihua Song 和 Wayne Xin Zhao（中国人民大学高瓴人工智能学院；RUC-AIBOX）。本文用到的若干训练任务来源和评测框架也出自同一团队。可能的批评者：做在线策略蒸馏（on-policy distillation）和智能体 RL 的作者，会问它与在学生自己的 rollout 上训练相比如何。

# Q5 关键解决思路

1. **Skill-FT。** 对任务 x，把选中的技能 s 拼接到基础系统提示 p 之后，教师生成轨迹 τ ~ Rollout(π_T, x; p ⊕ s)。学生在选中的轨迹上做标准 SFT，输入中保留原始系统提示（包括技能文本）；损失只计算助手的推理、回复和工具调用。
2. **内层循环（智能体）。** 智能体查看任务、未引导的教师轨迹，以及后几轮中学生的评测轨迹；寻找要抑制的习惯和教师很少表现出的有用行为；编写技能并决定作用于哪些任务；先做小规模试跑（pilot rollout）检验；把有希望的方案扩大成批量生成；再按结果和行为挑出 512 条示范。它也可以直接挑选已经表现出目标行为的未引导轨迹。
3. **外层循环。** 每一轮都从同一个初始检查点训练 θ_r = SFT(θ_0, D_r)，不带技能评测，返回分数和轨迹；实验历史延续到下一轮，权重不延续。
4. **基础设施。** 智能体在 Docker 容器中，通过 MCP 工具读取任务和轨迹、提交 rollout 和 SFT 作业；SFT 完成后执行控制器自动安排 SGLang 评测；记录把每次评测关联回它的训练集和技能。最后由智能体选定最终检查点并写明理由，该检查点再做三次全新的评测。

附录 B 展示了四个生成的技能，例如：把数值验收条件写进实际执行的检查、禁止放宽容差的技能；以及在搜索停滞时把下一次查询绑定到未被支持的假设上的技能。

# Q6 实验设计

* **领域与基准。** 终端（训练任务来自 CalibForge；Terminal-Bench 2.1，89 题）、搜索（FORT-Searcher；BrowseComp-Lite，185 题）、软件工程（DeNovoSWE；Doc2Repo，50 个仓库，指标为平均测试通过率）。每个领域随机抽取 1,000 个训练任务。
* **模型。** AutoMaster 在 Codex 中运行 GPT-6 Astra（xhigh 推理强度）；教师为 DeepSeek-V4-Pro-Preview（high）；学生为 Qwen3.5-4B 和 9B。
* **基线。** Base（不微调）和 Vanilla SFT（512 条随机的成功未引导教师轨迹）。所有方法都做全参数 SFT：512 条轨迹、3 个 epoch、学习率 1e-5、全局批大小 32、最大长度 131,072 token。
* **消融。** 去掉技能引导（智能体只从未引导 rollout 中挑选）、去掉数据选择（智能体为固定的随机任务子集设计技能，不由智能体挑选轨迹）、任务匹配 SFT（在 AutoMaster 最终训练集的同一批任务 ID 和每任务样本数上使用未引导 rollout，成功和失败都保留），以及训练输入中保留与移除技能文本的对比。
* **统计。** 每个检查点三次评测的均值 ± 标准差；对主要增益在任务层面做配对 bootstrap 95% 置信区间（10,000 次重采样）。

# Q7 数据集与代码

评测使用公开基准；训练任务来自同一团队及合作者发布的公开数据集。论文给出项目主页、GitHub 仓库（RUCAIBox/AutoMaster）和模型链接。除附录 B 中的四个以外，智能体提示和其他生成的技能本笔记未核查。

# Q8 证据质量

* **主表。** AutoMaster 在全部六个设置中均值最高：Terminal-Bench 2.1 上 28.09 对 22.47（4B）、35.58 对 26.59（9B）；BrowseComp 上 46.13 对 43.24、51.53 对 46.85；Doc2Repo 上 33.72 对 32.30、40.79 对 36.05。配对 bootstrap 区间在 9B 的三个设置和 4B 的 Terminal-Bench 上不含零，但 4B BrowseComp（[-1.08, 6.85]）和 4B Doc2Repo（[-1.94, 5.33]）的区间包含零。论文自己也说明了这一点。
* **标准差覆盖了什么。** ± 是同一检查点三次评测的波动，只反映评测噪声；每种方法只训练一次，没有报告训练种子带来的方差。在 89 题的基准上，一道题就是 1.12 分。
* **检查点选择。** AutoMaster 的智能体在最多五轮中依据同一基准的评测反馈挑选最终检查点，再做三次新评测；基线各只有一个检查点。新评测消除了对评测噪声的挑选，但没有消除"在测试集反馈下从五个学生中挑一个"的选择效应；图 8 中最好的一轮比第一轮高 2.16 到 4.87 分。没有一个留出的基准把设计与评测分开（读者评估）。
* **消融有信息量。** 两个组件在六个设置中都有作用，任务匹配 SFT 说明增益不只来自任务选择（AutoMaster 领先 1.08 到 10.11 分）。但在 4B Terminal-Bench 上，两个单组件变体（17.60、20.22）都低于 Vanilla SFT（22.47）；而且任务匹配 SFT 保留了失败轨迹，所以这个对比把行为塑造和成功过滤混在了一起。
* **成功标签。** 表 A5 中，AutoMaster 在终端和搜索领域的示范有 8.79% 到 20.70% 是在匹配的未引导 rollout 失败时成功的，因此部分增益可能来自难题上更多的成功示范，而不只是双方都成功的任务上更好的行为。
* **保留与移除。** 在全部六个设置中，保留技能文本比移除高 2.15 到 4.01 分，而监督输出完全相同。作者给出的解释（规则及其适用条件在输入中保持明确）只是一种可能，由两个例子支持。
* **读者核查。** Terminal-Bench 的均值落在 89 题乘三次评测应有的 1/267 网格上（28.09 = 75/267），BrowseComp 的均值落在 1/555 网格上，与所述协议一致。

# Q9 贡献

1. Skill-FT：在 rollout 中用自然语言技能塑造固定教师的行为（包括教师已能解决的任务），以此获得更好的 SFT 示范。
2. AutoMaster：由智能体运行的后训练循环，负责设计、试跑、扩大和修订技能并挑选示范，基础设施把每次评测关联到其训练集和技能。
3. 在三个领域、两种规模上的受控证据：在数据量和配方相同的情况下胜过随机成功轨迹 SFT，并有组件消融和任务匹配消融。
4. 发现训练输入中保留技能指令优于移除，尽管评测时没有技能。

# Q10 下一步

* **训练种子方差。** 每种方法用多个种子训练，以说明增益超过训练噪声，尤其是区间包含零的 4B BrowseComp 和 Doc2Repo 设置（读者建议）。
* **留出集上的选择。** 让智能体在验证集或另一个基准上选择检查点，使报告的基准不再同时是智能体的反馈信号（读者建议）。
* **与在线策略方法比较。** 在相同算力下，把 Skill-FT 与使用同一技能条件教师的在线策略蒸馏（Skill-SD 式）比较（读者建议）。
* **技能迁移。** 检验为某个学生规模或教师设计的技能能否迁移到另一个，以判断智能体找到的是通用行为还是只针对某一组模型调优（读者建议）。
