# Q1 问题定义

* **输入（X）：** 一个视觉问题（一张或多张图像加文字），其答案可能需要模型无法仅凭输入推断的证据：拥挤场景中的精确计数或框、网络上关于长尾实体的事实，或深度、三维距离这类度量量。
* **输出（Y）：** 答案（整数、框、选项或自由文本），由一个多模态大模型编排器（orchestrator）在最多 15 轮工具调用中产生。
* **目标：** 让通用多模态大模型以一致的方式访问异构的感知、搜索和计算工具，把工具输出呈现为模型能检查的形式，并让底层产物在多步之间可复用，同时不对模型做微调。
* **约束：** 所有骨干模型和全部 22 个基准使用同一套 harness、工具、提示词和评分；模型权重始终固定，领域专门化时也不例外。

# Q2 问题新颖性

视觉工具使用并不新。论文把已有工作分为三条线：把问题编译成固定工具流水线的程序合成系统（ViperGPT、Visual Programming）；被训练进特定工具协议的多轮框架（DeepEyesV2、PixelReasoner、AdaReasoner、OpenThinkIMG，以及 MMSearch-R1、DeepMMSearch-R1、WebWatcher 等领域系统）；以及工具接口由人工设计、无需训练的 harness（Visual Sketchpad、OctoTools）。它声称的空白更窄：异构工具返回的掩码、深度图和网页是模型无法直接读懂的，而后续步骤需要的是原始产物而不是对它的描述。论文用自己的推理强度实验来说明问题的动机：把 GPT-6 Luna 从 xhigh 调到 max，模型 token 成本变为 2.7 倍，而 22 个基准的平均分只提高 0.7 分。

# Q3 科学假设

如果把工具输出渲染成模型可以检查的观察（用带数量和归一化框的标注叠加图，而不是 RLE 掩码），并让底层产物可以通过句柄寻址，使后续工具和生成的代码能够复用，那么通用多模态大模型从"获取并组合证据"中得到的收益，会大于在原始输入上推理更久的收益。论文预期这种收益在不同模型家族和规模上都成立，超过已有的免训练和需训练的视觉工具 harness，来自两种机制的共同作用（各自在原始工具访问之上都有增益），并且与更高的推理强度互补而不是相互替代。

# Q4 相关工作与关键人物

* **视觉工具使用。** ViperGPT 和 Visual Programming（固定程序）；DeepEyesV2、PixelReasoner、AdaReasoner、OpenThinkIMG（经训练的多轮工具使用）；MMSearch-R1、DeepMMSearch-R1、WebWatcher、Vision-DeepResearch（多模态搜索智能体）；Visual Sketchpad 和 OctoTools（免训练 harness，主要基线）。
* **工具型智能体的工作记忆。** MemGPT 和 gist memory 阅读智能体把紧凑的可见状态与详细的外部内容分开；ReWOO 用变量引用工具证据；CodeAct 把中间结果保存为解释器变量；HuggingGPT 和 LLMCompiler 解析对先前输出的符号引用。OpenVLHarness 把这些思路扩展为一个覆盖图像、结构化数据和网页引用的类型化注册表。
* **后端。** SAM 3（定位）、PaddleOCR-VL（OCR）、Depth Anything 3 与 VGGT（深度和相机轨迹）、Serper API（搜索）；备选后端有 Grounding DINO、DeepSeek-OCR 以及带 Google 搜索的 Gemini。
* **基准。** 四个领域共 22 个数据集：定位感知（CountQA、FSC-147、OdinW-13-All、FSCD-147、FSCD-LVIS）、视觉搜索与深度研究（FVQA、MMSearch、MMSearch-Plus、HLE-VL、BrowseComp-VL、RealX-Bench）、通用 VQA 与幻觉（RealWorldQA、SimpleVQA、HallusionBench、FREAK-VQA、FREAK-MCQ、V*）、空间推理（MMSI-Bench、ERQA、EmbSpatial-Bench、SparBench、MindCube）。
* **关键人物。** Yu Zhou、Cheng-Fu Yang、Rui Sun、Di Wu、Sibo Peng、Mingyang Zhang、Nanyun Peng 和 Kai-Wei Chang（加州大学洛杉矶分校），以及 Zhen Yang、Ruiyi Zhang 和 Zhe Gan（Apple）。可能的批评者：Visual Sketchpad 和 OctoTools 的作者（他们的 harness 在 Qwen3-VL 和 GPT-6 Luna 上被比较），以及 DeepEyesV2 和 PixelReasoner 的作者（他们训练过的模型只在较旧的 Qwen2.5-VL-7B 底座上被比较）。

# Q5 关键解决思路

**能力层（capability layer）。** 每种能力由它提供的操作、类型化输入，以及它暴露的证据和可复用数据来定义，与具体后端无关。共九种能力：五种感知（放大、视觉定位、OCR、深度估计、相机轨迹）、三种信息检索（文本搜索、图像搜索、网页访问）和一个 Python 编码智能体。每种能力都有一个输出处理器，把原始结果渲染成面向模型的观察，组合视觉附件、简短描述和紧凑结构：定位返回带对象数量和 0-1000 网格归一化框的标注掩码叠加图；搜索返回由 Qwen3-VL-8B 摘要器写出的前 10 条结果摘要，附行内引用。

**持久多模态记忆。** 每个查询维护一个注册表，把产物的内容与引用它的句柄分开。注册表包含图像产物（输入图像、工具生成图像和检索到的图像，例如 `input_image_3` 或 `tool_generated_image_6`，按内容去重）、结构化数据绑定（框、分数、掩码、深度数组、相机参数、OCR 结果，每项都有字段与形状描述符）以及网页引用（`webpage_url_1`）。每轮工具调用后，"环境更新"（Environment Update）列出当前可用的句柄而不重复内容；后续调用只需写出句柄，由 harness 解析成接收工具所需的输入。

**基于记忆的计算。** 编排器用自然语言说明计算目标（"计算每个检测区域内的平均深度"）；同一骨干模型的一个新上下文写出程序，程序运行时以真实的绑定值作为命名变量，输出再登记以便复用。这样智能体可以把定位掩码与深度数组结合，或者调和两次定位查询的掩码以纠正漏数，而不必把数组序列化进自己的上下文。

**无需训练的专门化。** 面对新领域时，用户数据上的失败决定在两种由 Codex（GPT-5.5）驱动的流程之间如何选择：harness 搜索修改系统提示词、工具描述和输出模板；工具生成用现有能力组合出新工具，只有在其样例的留出一半上恢复了失败时才接受该工具。

# Q6 实验设计

* **骨干模型。** 四个开放模型（Qwen2.5-VL-7B、Qwen3-VL-8B、Qwen3-VL-32B、Kimi K3）和四个专有模型（GPT-5，以及 medium 强度下的 GPT-6 Luna、Sol、Astra）。Qwen3-VL 的结果取三次运行的均值；专有模型因 API 成本只运行一次。
* **基线。** 同一骨干不带工具；两种 Qwen3-VL 规模上的 Visual Sketchpad 和 OctoTools；GPT-6 Luna 上的 Visual Sketchpad 和 Codex（Codex CLI，关闭网页搜索，只读沙箱）；在共同底座 Qwen2.5-VL-7B 上，AdaReasoner、PixelReasoner、DeepEyesV2 的检查点与 OpenVLHarness 对比。
* **评分。** 计数用精确匹配，定位用 COCO 框 AP，选择题用选项匹配；六个搜索基准用 GPT-4o 评审（判断报告中是否包含正确答案），其余开放式答案用 Qwen3-VL-8B 评审。
* **推理强度与 harness 的对比。** 在 GPT-6 Luna 上以五档推理强度运行 Base、Codex、Visual Sketchpad 和 OpenVLHarness，覆盖全部 22 个基准的完整划分（每档 26,229 题，共 524,580 题），按标准档价格计算模型 token 成本。
* **消融。** 在 Qwen3-VL-8B 和 32B 上做阶梯式消融（每个数据集最多抽 500 条，三次运行）：无工具；原始工具（极简 schema、原始输出、无记忆）；加能力层；加文本记忆（数据绑定、URL 句柄、环境更新，但工具图像以文字描述代替）；以及带图像句柄的完整 harness。
* **失败分析与专门化。** 用 Kimi K3 评析 9,893 条 Qwen3-VL-8B 失败轨迹（在 100 条样本上与人工标注一致率 92%）并提出补救方案；随后在按补救类型分布差异挑选的四个数据集上运行 harness 搜索和工具生成，使用与评测数据不相交的划分。

# Q7 数据集与代码

没有新数据集；22 个基准都是公开的，附录列出了划分、规模、提示词和评审。harness、工具、评测协议和两种优化流程都发布在 [uclanlp/OpenVLHarness](https://github.com/uclanlp/OpenVLHarness)（`hf papers info` 显示 18 星），并有项目页；本笔记均未打开。

# Q8 证据质量

* **得到支持的结论。**
  * *跨骨干的一致收益。* 22 个基准的平均分：Qwen3-VL-8B 从 34.2 升到 45.4，Qwen3-VL-32B 从 38.3 到 50.9，GPT-6 Luna 从 45.8 到 56.5，GPT-6 Astra 从 60.3 到 70.2，GPT-5 从 44.4 到 55.7，GPT-6 Sol 从 52.7 到 64.3，Kimi K3 从 56.4 到 66.1，正好覆盖摘要中 9.7-12.6 的范围；Astra 和 Sol 在全部 22 个基准上都有提升。第八个骨干 Qwen2.5-VL-7B 只出现在与训练型方法的比较中，在已读部分没有找到它不带工具的分数。
  * *优于已有免训练 harness。* 在 Qwen3-VL-8B 上，OctoTools（31.8）和 Visual Sketchpad（30.5）的平均分都低于裸模型（34.2）；在 GPT-6 Luna 上，Codex（43.8）也低于裸模型（45.8），而 OpenVLHarness 达到 56.5。
  * *在训练型模型自己的底座上也更好。* 在 Qwen2.5-VL-7B 上平均 33.45，高于 PixelReasoner 的 28.02、AdaReasoner 的 25.29 和 DeepEyesV2 的 25.02，在定位和搜索上差距最大；训练型模型在 RealWorldQA、V* 等少数分布内数据集上领先。
  * *更高的推理强度替代不了 harness。* 从 low 到 max，Base 从 44.3 到 48.0，Visual Sketchpad 从 44.7 到 48.8，Codex 从 36.9 到 48.6，而 OpenVLHarness 从 49.9 到 60.1；在 medium 强度下（每千题 0.92 美元），它胜过其他所有方法的任何强度，包括 max 强度的 Visual Sketchpad（48.84，5.15 美元）。
  * *每种机制都有增益。* 8B / 32B 的总体分：无工具 37.06 / 41.29，原始工具 40.84 / 45.61，能力层 44.23 / 48.80，文本记忆 44.93 / 49.12，完整 harness 47.14 / 52.51。图像句柄在视觉搜索与深度研究上增益最大（+6.2 / +3.5）。
  * *补救类型能预测哪种专门化有效。* Harness 搜索让 ERQA 和 RealWorldQA 分别提高 4.1 和 3.7 分（工具生成为 0.2 和 0.1）；工具生成让 SparBench 和 FREAK-VQA 提高 8.2 和 4.5 分（harness 搜索为 −0.5 和 −1.0）。
* **比标题结论更弱或更窄的部分。**
  * *在搜索基准上，是否有搜索能力混淆了 harness 的比较。* 裸模型和 Codex（为防止它搜到标准答案而关闭了网页搜索）都不能搜索网络，因此在六个搜索基准上，一部分差距衡量的是"有没有 Serper 搜索"，而不是 harness 如何呈现搜索结果（笔记作者的观察）。论文的"无检索捷径"检查称搜索从未逐字检索到标准答案，但没有说明如何检查。
  * *成本只计模型 token。* 37% 这一数字不含工具执行（SAM 3、OCR、深度和搜索 API）以及搜索工具内部的 Qwen3-VL-8B 摘要器，论文对此有说明，因此 harness 的完整成本优势没有被衡量。
  * *消融的底层阶梯被设置得较弱。* 原始工具这一级把每个 schema 削减为极简签名并直接输出原始内容，所以能力层的增益同时包含恢复完整工具描述和输出渲染两部分；论文也说明该比较无法区分二者。按领域看，阶梯也不单调：在 8B 的定位感知上，完整 harness（45.46）低于文本记忆（47.27）（笔记作者根据表 3 的观察）。
  * *专有模型的结果只有一次运行。* GPT-5、GPT-6 以及整个推理强度实验每格只跑一次；论文还指出 GPT 模型对身份类问题的拒答拉低了部分搜索分数。
  * *搜索评审较宽松。* GPT-4o 评审只要报告中任何位置包含正确答案就判为正确，这对长报告比对简短答案更有利（笔记作者的观察）。
  * *专门化的证据只有一个骨干上的四个数据集*，且这些数据集是按补救类型的反差挑选的，增益为 3.7-8.2 分。

# Q9 贡献

* 一种能力抽象，把"工具做什么"与"由哪个后端提供"分开，并为每个工具配备渲染器，把原始输出变成多模态大模型可以检查的证据。
* 一个按查询维护的多模态产物注册表（图像、类型化数据绑定、URL），其句柄可由后续工具和模型生成的代码解析，把文本智能体中的变量传递思路扩展到图像和数组。
* 一个覆盖 22 个基准、八个骨干的评测，表明该 harness 对开放和专有模型都有帮助，胜过以往的免训练和训练型视觉工具系统，并且在所测预算内无法靠花更多推理 token 追平。
* 一套"先诊断再专门化"的做法，用失败评析在"修改 harness 文本"和"生成新的组合工具"之间做选择；并开源了 harness、工具、协议和流程。

# Q10 后续方向

* **工具对等的基线（笔记作者的建议）。** 通过一个极简接口给裸模型和 Codex 同样的 Serper 搜索和 SAM 3 工具，以便把搜索基准上的收益拆分为工具访问的贡献与渲染、记忆的贡献。
* **完整的成本核算（笔记作者的建议）。** 在模型 token 之外报告延迟以及工具后端和搜索摘要器的成本，因为 harness 把一部分工作从编排器转移到了工具上。
* **密集感知（来自论文）。** 定位感知在超过 25 个对象的拥挤图像中仍会失败，该领域 75% 的失败是工具输出错误，因此那里更需要更强的定位后端或分块检测，而不是修改 harness。
* **长期记忆（笔记作者的建议）。** 注册表只在一个查询内存在。如果像 [Agent harness 工程](../topics/agent-harness-engineering.md) 中的自我演化 harness 保留编辑那样，跨查询保留经过验证的产物或生成的工具，就能把单次查询的记忆变成可复用的能力；论文中被接受的生成工具已经构成了一个工具库。
* **多语言多模态搜索（笔记作者的建议）。** [HyperBrowseComp](../papers/2610.03574.md) 的 BrowseComp 式问题，其证据位于视频、扫描件、地图和 13 种语言中；它可以检验图像和网页句柄能否在纯文本搜索智能体吃力的地方发挥作用。
