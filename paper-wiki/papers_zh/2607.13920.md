# Q1 问题定义

* **输入 (X)：** 一个搜索智能体（模型加上它的 harness）、一个带有数据集自带支撑证据的问题，以及一个场景设定：每篇返回文档看起来可信（T，trustworthiness）、与查询相关（R，relevance）、事实正确（F，factuality）的概率。
* **输出 (Y)：** 智能体最终答案所属的五类结果之一（正确、错误、弃答、超出工具预算、缺少答案标签），以及把证据可靠程度和运行成本都算进去的汇总分数。
* **约束：** 每次搜索只返回一篇生成的文档；每次只降低一个维度，其余两个保持 100%；每个问题最多 100 次工具调用。

# Q2 问题新颖性

检索增强模型对劣质证据的鲁棒性是已有课题，近期也有工作通过扰动工具输出或投毒搜索结果来做攻击式评测。论文的看法是：这类失败在固定语料里只能事后观察到，而且难以复现，因为不同智能体发出的查询不同。在查询时现场生成文档，并让实验者控制文档的标签，就把“劣化比例”变成了一个可以对主动搜索的智能体施加的自变量。这一点，以及按证据可靠度给弃答计分，是新的部分。该框架被定位为一个实验室，而不是替代现有基准。

# Q3 科学假设

如果沿着一个受控的维度降低证据质量，那么在干净检索下最终准确率相近的智能体，会因为失败方式不同而被区分开（自信地答错、弃答、无休止地搜索、输出格式崩坏），而且这些差别与智能体的训练方式有关。关于数据集的次要假设：一个靠参数知识就能回答的基准，即使所有证据都是假的，也会保留一部分正确率。

# Q4 相关工作与关键人物

* **搜索智能体。** ReAct 和 IRCoT（提示式）；[Search-R1](../concepts/search-r1.md)、ZeroSearch（已经用微调模型生成文档，但用于训练）和 DR-Tulu（训练式）。
* **搜索基准。** HotpotQA、BrowseComp，以及 [BrowseComp-Plus](../concepts/browsecomp-plus.md)，后者用固定语料把检索器与模型的作用分开。
* **对抗环境。** AgentNoiseBench、SafeSearch、SearchGEO，以及 WARP（对用户生成的网页投毒）。
* **准确率之外。** 失败分类法、轨迹分析（TRACE），以及 Xie 等人的 Tokens Per Correctness 指标。
* **知识冲突。** DRAGged into Conflicts 和 TRACK，针对的是静态 RAG 或上下文内推理。
* **关键人物。** Ismaël Rousseau 和 Géraldine Damnati（Orange Research，拉尼翁），以及 Frédéric Béchet（艾克斯-马赛大学、CNRS、LIS）；Rousseau 同时列在两个机构下。被评测的智能体之一 SpiqaDR 是作者自己的模型。可能的批评者：Search-R1、AutoRefine、ASearcher、DR-Tulu 的作者，他们的智能体是在原生检索环境之外被运行的。

# Q5 核心解法

1. **拦截搜索调用。** 每次调用时，模拟器按场景的概率为每个维度采样一个二值标签，再让一个 LLM（Gemma-4-31B）针对智能体的实际查询写一篇约一段维基百科长度的文档，带标题和 URL。
2. **三种控制。** 事实正确的文档以数据集的金标准证据为依据；事实错误的文档被要求写入严重的事实错误。不可信的文档会得到一个从 OpenSources 误导性网站名单中抽取的域名，以及相应的小报式文风；可信度只关乎外观，与事实正确与否无关。不相关的文档是为同一数据集中另一个问题写的、有依据的文档。
3. **五类结果。** 超出预算和缺少答案标签由程序判定；其余由 GPT-4.1 判为正确、错误或弃答。
4. **RAS。** 可靠度 ρ 是该次运行中可信、相关、事实正确的文档的实际占比之积。答对得 1 分，答错或格式错误得 0 分，弃答或耗尽预算得 1 − ρ 分。因此一个永远弃答的智能体在 ρ = 0 时得 1 分，在证据完全可靠时得 0 分。
5. **CoPRAS。** 总成本（生成 token 数 + 0.25 × 输入 token 数 + 500 × 搜索次数，取自 Xie 等人）除以 RAS 总和，是 Tokens Per Correctness 的可靠度感知版本。

# Q6 实验设计

* **数据。** 从 HotpotQA 和 BrowseComp-Plus 各随机抽 200 个问题。
* **场景。** 每个维度取 0%、50%、100%，另两个维度保持 100%，共七个场景。
* **系统（12 个）。** gpt-5-nano 和 gpt-5-mini，各在低、中、高三档推理强度下运行；SpiqaDR（3B）、Search-R1（7B）、AutoRefine（3B）、ASearcher（7B，本地 RAG 版本）、DR-Tulu（8B），以及把推理块立即关闭的 DR-Tulu。文档按各 harness 的约定格式化。
* **规模。** 12 × 2 × 200 × 7 = 33,600 条轨迹。
* **检验。** 三位标注者对 50 篇生成文档做人工标注；不带搜索的直接推理基线；在更小的工具预算下重新计算所有指标；对查询操作符的使用、以及推理步骤是否说出了对文档质量的顾虑，做探索性分析（每个系统、场景、数据集抽 100 步，由 LLM 判定）。

一次只变一个因素让结果容易解读，但也意味着多种劣化同时出现这一更现实的情况没有被测到。

# Q7 数据集与代码

HotpotQA 和 BrowseComp-Plus 提供问题，以及用来支撑“事实正确文档”的金标准证据。生成的文档平均 102.7 和 106.4 个词。环境代码承诺“同行评审后”公开，没有给出链接；SpiqaDR 的 URL 同样没有给出。生成和评判用的提示词在附录中。作者声明生成的文档不用于分发。

# Q8 证据质量

**汇总指标（两个数据集合并；每一列是该质量水平下三个单维度设置的平均）。**

| 系统 | 正确率 0% | RAS 0% | 正确率 100% | RAS 100% | 成本 0% | 成本 100% |
|---|---|---|---|---|---|---|
| gpt-5-nano（中） | 0.41 | 0.84 | 0.83 | 0.83 | 22.7k | 6.5k |
| gpt-5-mini（低） | 0.41 | 0.90 | 0.71 | 0.71 | 3.0k | 1.7k |
| gpt-5-mini（高） | 0.27 | 0.96 | 0.63 | 0.63 | 55.6k | 34.3k |
| SpiqaDR-3B | 0.24 | 0.48 | 0.61 | 0.61 | 4.5k | 1.7k |
| Search-R1 | 0.35 | 0.37 | 0.80 | 0.80 | 5.2k | 2.8k |
| AutoRefine | 0.28 | 0.28 | 0.67 | 0.67 | 1.1k | 1.1k |
| ASearcher | 0.12 | 0.12 | 0.17 | 0.17 | 3.4k | 2.6k |
| DR-Tulu | 0.21 | 0.30 | 0.59 | 0.60 | 29.0k | 10.6k |
| 平均（12 个系统） | 0.30 | 0.60 | 0.66 | 0.66 | 20.5k | 10.9k |

**各维度上的行为。**

* *可信度。* Search-R1 在每个水平上的正确率都在 78% 到 80% 之间；SpiqaDR、AutoRefine、ASearcher 也几乎不变。DR-Tulu 的正确率从 59.8% 降到 40.9%，同时无答案的比例从 10.8% 升到 34.6%。GPT 智能体更常不给答案：gpt-5-mini（低）的弃答率为 22.5%（原为 14.0%），gpt-5-mini（高）有 62.7% 的运行耗尽预算（原为 32.0%）。
* *相关性。* 所有系统的正确率都下降。Search-R1 的答错率从 19.5% 升到 79.2%；AutoRefine 缺少答案标签的比例从 18.2% 升到 61.9%。
* *事实性。* SpiqaDR 在事实性为 0% 时弃答率为 15.2%，而相关性为 0% 时为 38.0%；DR-Tulu 的答错率为 59.1%，对比 33.8%。论文的解读是：相关但错误的文档比不相关的文档更难被拒绝。

**数据集。** 事实性为 0% 时，HotpotQA 的平均正确率为 33.75%，BrowseComp-Plus 为 0.33%；gpt-5-mini（中）在 HotpotQA 上达到 60%。完全不给搜索工具时，这些系统在 HotpotQA 上得 0.19 到 0.69，在 BrowseComp-Plus 上得 0.00 到 0.02。论文建议：没有直接推理基线，就不要用 HotpotQA 评测搜索智能体。

**生成器检验。** 人工标注与预设标签的一致率：可信度 96.4%，事实性 85.5%（标注者间 κ 为 0.86 和 0.64）。

**预算。** 按正确率的排名要到约 50 次工具调用后才稳定；按 RAS 的排名在约 10 次时就已经有参考价值。

**证据的局限（读者观察）。**

* RAS 给“耗尽预算”和“明确弃答”同样的分数。gpt-5-mini（高）在 0% 水平上 RAS 最高（0.96），而它在 GPT 系统中正确率最低（0.27）、成本最高（55.6k），主要靠一直搜到上限。附录承认这是一个设计选择，并提出可以给它更低的权重；CoPRAS 通过成本对此有所惩罚。
* 可信度一项把“拒绝一篇小报文风但内容正确的文档”视为可以接受。这是论文明说的认识论立场，它也意味着在可信度为 0% 时，RAS 奖励的是对证据其实正确的问题不作回答。
* 事实性混淆矩阵显示，标为事实正确的文档的 69 次标注中有 13 次被判为不正确，所以在标注者看来，“100% 事实正确”的条件里含有一些错误。按矩阵的格子算，一致的是 100 次中的 86 次，而表中报告的是 85.5%。
* 数据集层面的表（表 11）对“完全可靠”这一设置给出了三个不同的数值（HotpotQA 正确率在可信度、相关性、事实性三行下分别为 55.45、63.25、65.48），而按设计，任何维度取 100% 都是同一个场景；并且可信度一行在 0% 时的正确率高于 100% 时，与正文按系统的描述相反。论文没有解释；可能是可信度两列写反了，或者各行来自不同的运行集合。上面按系统的结论取自正文。
* 正文说 0% 水平上平均 RAS 为 0.61、CoPRAS 为 36.8k，而表中是 0.60 和 36.9k。
* ASearcher 在证据完全可靠时只得 0.17，所以它的鲁棒性数字主要反映的是 harness 不匹配（本地 RAG 版本、经常缺少答案标签），而不是对劣化的反应。
* 把训练方式与脆弱性联系起来的说法（“狭窄的 RL 奖励往往产生脆弱的模型”）比较的是 3B 到 8B 的 RL 训练开源模型与 GPT-5 变体，训练方式、模型规模和厂商的后训练混在一起。附录中 Qwen2.5 基座模型（0.5B 到 32B，未经 RL）在 0% 水平上的 RAS 随规模上升，32B 时为 0.66 或 0.67，这用规模来解释至少同样说得通。
* 主表没有给出每格的置信区间；结果分布的区间在附录中，本笔记没有逐格核对。每个数据集 200 个问题时，一个接近 50% 的比例的 95% 半宽约为 7 个点（读者计算）。
* 每次调用只返回一篇文档，去掉了真实搜索中“同一页结果内部相互矛盾”的情况，局限性一节也说了这一点。

定性的发现，即干净条件下准确率相近的智能体在劣质证据下以不同方式失败，在结果分布中很清楚。RAS 的排名取决于作者自己也标明为“选择”的计分方式。关于 RL 训练的因果解读没有确立。

# Q9 贡献

1. 一个模拟环境，使证据的可信度、相关性和事实性可以按每次搜索调用来控制，适用于任何只有一个搜索工具的智能体。
2. 五类结果的划分，以及两个汇总指标（RAS、CoPRAS），按证据不可靠的程度给“不回答”相应的分数。
3. 对 12 个系统的比较，显示出不同的失败风格：RL 训练的开源智能体跟着上下文走，GPT-5 智能体弃答或延长搜索，DR-Tulu 和 AutoRefine 则是格式崩坏。
4. 测量表明当前模型不看证据也能回答 HotpotQA 中相当大的一部分，并用直接推理基线量化了这一点。

# Q10 下一步

* **论文自述的局限。** 每次调用一篇文档；单循环、单工具的智能体；各维度独立变化；合成文档比真实网页干净；需要金标准证据来支撑事实正确的文档。
* **组合劣化。** 低可信度配高事实性，对比高可信度配低事实性，可以检验智能体到底有没有使用可信度线索，还是只看内容是否一致（读者建议；流水线本来就是独立采样各标签的）。
* **拆开混杂因素。** 在模拟器下运行同一个基座模型的“有搜索 RL”和“无搜索 RL”两个版本。论文里 Qwen2.5-7B 和基于 Qwen2.5-7B 的 Search-R1 分别出现在不同的表中；把它们并排比较，可以直接检验“RL 导致脆弱”的说法（读者建议）。
* **训练信号。** 作者提出把 RAS 和文档标签用作可靠度感知的奖励。由于永远弃答在 ρ = 0 时得 1 分，这样的奖励需要混合多种场景，才不会教会模型一味拒答。
* **过程度量。** 对查询操作符和“说出顾虑”的分析都是探索性的；说出顾虑并没有明显改善答案，而且 GPT 智能体只暴露推理摘要。
* **更复杂的 harness。** 带重排、摘要或子智能体的系统，可能在策略看到之前就把坏文档过滤掉了。
