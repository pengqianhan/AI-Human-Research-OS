# Q1 问题定义

* **输入（X）：** 对一个未知的、确定性的、目标导向的 POMDP $\mathcal{M}=\langle\mathcal{S},\mathcal{A},\mathcal{O},T,\rho,G\rangle$ 的黑盒交互；一个冻结的 LLM；以及 $B$ 次真实动作的预算。在 ARC-AGI-3 上，一次观测是 64x64 的彩色网格，动作是含义未知的按键和点击，智能体拿不到任务描述，也看不到环境源码，只有通关信号。
* **输出（Y）：** 一个持久的世界模型假设 $h_t=(\psi_t,\theta_t)$：自然语言规则手册（rulebook）$\psi_t$（物体、动作语义、动力学、目标、尚未解决的备选解释），以及可执行程序 $\theta_t$（初始化器、状态转移预测器、观测函数、目标集合），供规划器搜索到达目标的动作序列。
* **目标与约束：** 首先最大化在 $B$ 次动作内到达目标的概率，其次最小化所用动作数。发给环境的每个动作都计数，包括探索、失败尝试和重置；构建模型、模拟推演和重放不计数。
* **核心问题：** 有限的交互历史会留下一个版本空间（version space）：其中的程序都能复现已观察到的转移，却在未见状态上给出不同预测（"箱子碰到墙停下"与"箱子在第 7 列停下"）。重放能否决不一致的程序，却无法在一致的程序中挑出正确规则。

# Q2 问题新颖性

不是新问题。从交互中学习代码世界模型（WorldCoder、GIF-MCTS），以及在规划前用重放验证可执行模型的 ARC-AGI-3 系统（Rodionov 的 baseline1、OPINE-World、Twin、Tycho）都已存在，论文自己也这样说："语言规则、可执行产物、反思和重放都是已有的组件"。它声称的不同在于这些部件如何组织。规则层面的假设写在一本与代码分离、并约束代码的规则手册里，因此理解上的变化必须先写成规则再编译，而实现上的 bug 可以在不动规则手册的情况下修复。在作者自己的系列中，Memento、Memento 2 和 Memento-Skills 学的是策略侧（情景记忆、反思式学习、可执行技能），Memento 3 被定位为模型侧。

# Q3 科学假设

1. **规则手册加快收敛。** 若把规则假设保存在语言中、并要求代码实现它们，智能体就能用比只有代码时更少的真实动作和更少的智能体轮次得到有效的可执行模型。
2. **两部分验收让规划保持可靠。** 若只有当 LLM 判断代码忠实于规则手册、*并且*精确重放复现了每一条已记录的下一步观测时，模型才用于规划，那么验收就不只依赖语言模型的自信。
3. **种群减少自我确认。** 一个错误模型如果自己的计划从不经过它出错的状态，就可能一直不被证伪。若 $N$ 个模型共享同一份交互历史、每个规划回合抽取其中一个，不同模型会引导探索，整次运行对某个早期假设的依赖也更小。
4. **这个循环是递归自我改进的一种形式。** 规则手册和可执行程序既是被修改的对象，也是引导下一轮证据收集的工具，而 LLM 的权重保持不变。

* **把工作区当作学习状态。** DreamTeam（Workspace Optimization）、Continual Harness、NOOA、Belief-Calibrated Optimization。
* **关键人物。** 伦敦大学学院（UCL）、华为诺亚方舟实验室（英国）和利物浦大学；Jun Wang 为通讯作者，Haitham Bou-Ammar 在作者之列。可能的批评者：其他 ARC-AGI-3 系统的构建者，他们会要求相同的主干模型和留出游戏；以及基于模型的强化学习研究者，他们会质疑 Pong 上的学习成本比较。

# Q5 关键解决思路

* **Code as Model。** 学习状态是 $Z_t=(H_t,\psi_t,\theta_t)$：完整的交互记录、规则手册和可执行程序。在 ARC-AGI-3 上，它们是一个 Markdown 文件 `world_model.md` 和一个 Python 模块 `world_model_engine.py`，后者预测完整的下一帧网格以及关卡是否完成。
* **每次真实动作后的五阶段循环。** *观测*：追加这次转移。*反思*：LLM 在 `retain`（保留）、`revise_rulebook`（修订规则手册）和 `repair_code`（修复代码）之间选择。*规则修订*：若被选中则编辑规则手册。*编译*：根据此前的代码、提议的规则手册和记录生成代码。*验证*：只有当（a）LLM 判断源码忠实于规则手册，且（b）从每条轨迹的首个观测开始重放、所有已记录帧的 64x64 个格子全部匹配时，才接受这一对。被拒绝的提议回到反思阶段。
* **偏好简单。** 在可接受的各对中，要求 LLM 偏好更短的规则手册和实现，论文把这解读为最小描述长度先验；每次简化都会重新检查。
* **规划与探索。** 规划器在可执行程序中找到通往预测目标的最短路径，逐个动作执行，在第一次预测不符时停止。没有可达目标的计划时，LLM 选择一个中间目标（测试某个机制、揭示某个区域、触碰一个尚未解释的物体），由辅助规划器到达。
* **Git 记忆。** 规则手册和模块放在同一个仓库里；控制器在每次迭代后提交并打标签，智能体可以对比或恢复更早的版本。
* **种群扩展。** $N$ 个"规则手册-可执行程序"对共享 $H_t$。计划为相同动作序列的成员构成一个行为等价类；每个规划回合均匀抽取一个类；每次真实转移都对所有成员检查，被证伪的成员得到修复。论文称这是对剩余版本空间的计算近似，而不是经过校准的后验。

# Q6 实验设计

* **ARC-AGI-3 主结果。** 全部 25 个公开游戏（183 关）。实验框架从 baseline1 的代码库出发，在 Claude Code 中以 Claude Opus 5、超高（extra-high）推理强度运行，$N=1$。指标：相对人类动作效率（Relative Human Action Efficiency，RHAE，上限 100），后面的关卡权重更大，单关效率 $(h_\ell/a_\ell)^2$ 封顶为 1.15。基线是社区排行榜上五个附有论文的条目（baseline1、NOOA、OPINE-World、DreamTeam、Continual Harness）；它们的数字和人类动作数来自 ARC Prize 官方记分卡。
* **规则手册消融。** 把规则手册从更新循环中移除，只留下纯代码的世界模型，框架、验证器、执行器、主干和推理强度不变；每个难度档选一个游戏（ft09、ka59、cn04，人类每关动作数分别为 35、104、132）。
* **种群。** 在人类动作基线最大的游戏 wa30 上比较 $N=2$ 与 $N=1$。
* **Atari Pong 案例研究。** Arcade Learning Environment，跳帧 4。关卡规划器换成一个查询所学模型的反馈策略；某个检查点以 21:0 获胜后停止学习；随后固定控制器，在三局开局不同的比赛中评分，期间不调用 LLM。基线：同一 LLM 仅根据最近两帧、无记忆地选择每个动作，随机策略，以及已发表的无模型（GDI、LASER、IMPALA、Rainbow）和基于模型（EfficientZero、EfficientZero V2）结果。

# Q7 数据集与代码

评测使用 ARC-AGI-3 公开集和 ALE Pong，没有新数据集。论文正文和 Hugging Face 论文页都没有给出代码仓库，规则手册和可执行程序只以图中节选的形式出现（sc25、tr87、Pong）。复现依赖托管模型（Claude Opus 5）以及框架所基于的 baseline1 代码库。论文没有报告 token、时间或费用成本，不过它以每次运行"可观的时间和金钱成本"作为消融只覆盖很少游戏的理由。

# Q8 证据质量

* **有支撑的结论。**
  * *在效率上限处全部通关。* 25 个游戏全过，183 关全过，平均 RHAE 100.0；7,518 次动作，人类基线为 17,135 次（0.44；单游戏比值从 m0r0 的 0.20 到 lf52 的 0.67，中位数 0.42），每个游戏都低于人类动作数。
  * *领先于所列基线。* baseline1 99.0（25 个游戏，8,347 次动作，人类的 0.49），NOOA 85.1（19 个游戏），OPINE-World 78.4（20 个），DreamTeam 38.1（6 个），Continual Harness 20.5（3 个）。论文还称平均 RHAE 比使用 ARC Prize 标准框架的 Claude Opus 5 高 59.3 分。
  * *Pong。* 学到的控制器在三局评分比赛中都以 21:0 获胜（分别用 3,358、4,014 和 5,039 次动作）；同一 LLM 不带世界模型得 -19，随机策略得 -20.7。
* **比标题更弱或更窄的地方。**
  * *对最接近系统的优势很小。* baseline1（本框架正是从它的代码库出发）同样通关所有游戏；差距是 1.0 个 RHAE 点，来自两个游戏（sc25 84.2 和 tn36 90.1），动作数少约 10%（读者根据表 1 和表 2 的计算）。基线数字是各系统在自己的主干和预算下的记分卡数值，不是条件对齐的重跑。
  * *按论文自己的说法，公开集已接近饱和。* 相关工作一节指出，Tycho 和 Rodionov 的组件研究报告了更强的前沿模型在公开集上饱和或接近饱和，公开集通关"无法分离出世界模型架构的贡献"，比较还应考察模型选择、推理预算、重复运行的稳定性和留出评测。本文只报告公开集，没有重复运行，也没有留出游戏。
  * *规则手册消融只有三个游戏。* 有规则手册：617 次动作、678 个智能体轮次；没有：677 和 830（分别少 9% 和 18%）。逐游戏的动作差为 75 对 79、341 对 382、201 对 216。两组都达到 RHAE 100，没有报告离散度，作者的措辞是结果"提示"收敛更快。
  * *种群结果只有一个游戏、$N=2$。* wa30 的计分动作从 899 降到 597（0.66 倍），九关中八关持平或更好，第 8 关更差（130 到 138）。维护两个模型带来的额外 LLM 开销没有报告。
  * *Pong 的成本比较只算环境帧数。* 9,504 帧，对比无模型基线的 2.0x10^8 和 EfficientZero 的 4.0x10^5（论文给出的倍数约为 2.1x10^4 和 42）。学习期间的 LLM 计算不在这一度量之内；已发表的基线各用各的协议；学习是在达到 21:0 这一随后被报告的标准时停止的；而且如论文所述，LLM 借助了关于物体和动力学的预训练知识。精确重放在这里也被放宽："全帧重放仍保留残余的渲染和球拍运动误差。"
  * *规则手册忠实度是 LLM 的判断。* 写规则手册、编译它、判断代码是否忠实的是同一个冻结的 LLM；论文没有给出这一判断出错的比率，也没有统计各种反思选择或拒绝出现的次数。

# Q9 贡献

* Code as Model：把持久的规则手册及其可执行实现作为智能体的世界模型记忆，在 LLM 冻结的情况下，通过观测、反思、规则修订、编译和验证的循环加以修订。
* 一条验收规则：把 LLM 的忠实度检查与针对整份交互记录的精确重放配对。
* 一个共享历史的世界模型种群，按行为上不同的计划采样。
* 基于模型的递归自我改进的定义，并给出贝叶斯自适应 POMDP 形式化：单模型是点信念，种群是经验信念。
* ARC-AGI-3 结果（全部 25 个公开游戏达到 RHAE 上限，动作数为人类的 44%），以及一个控制器在执行时无需调用 LLM 的 Pong 案例研究。

# Q10 下一步

* **作者提出的方向。** 论文没有局限性一节。相关工作的最后一段指出 ARC-AGI-3 上的比较应覆盖：模型选择与推理预算、动作效率、重复运行的稳定性，以及留出评测。
* **条件对齐的对照（读者建议）。** 用相同的主干和推理强度重跑 baseline1；每项消融重复多次并覆盖更多游戏；在动作数之外报告 LLM token 和墙钟时间，因为动作数不包含任何构建模型的工作。
* **测量忠实度判断（读者建议）。** 记录代码通过重放却未通过忠实度检查、以及相反情况出现的频率，并人工抽查；这是唯一没有执行作依据的验收步骤。
* **原始历史对比提炼规则（读者建议）。** [Learn2Play Bench](../papers/2610.08215.md) 发现，提炼的教训可能把错误规则固定下来，而原始历史让智能体能够修正它。Memento 3 两者都保留——完整记录，以及必须能对它重放的规则手册——这是对该失败模式的一种设计回应；在 Learn2Play 的隐藏规则游戏上运行它，可以在 ARC-AGI-3 之外检验这一回应。
* **与本项目的契合（读者注）。** "规则手册陈述相信什么、代码陈述如何应用"的划分，加上每次修订都提交、因而可以对比或恢复早先的假设，与本仓库用 Git 跟踪的记忆文件相似；论文中"理解的变化先写下来，再改实现"的规则，是智能体维护指令文件时可用的约定。

* [ARC-AGI-3](../concepts/arc-agi-3.md) - 主要评测：25 个公开游戏全部通关，平均 RHAE 100.0，用 7,518 次动作（人类的 44%）。
* [Reflexion](../concepts/reflexion.md) - 被引用为一种文本记忆，保存的是关于过去决策的建议；Memento 3 保存的则是关于环境如何运作的可修订规则。
* [Code as Worlds](../papers/2608.27549.md) - 被引用为通过"提议-执行-渲染-验证"为物理推理做可执行建模；Memento 3 把同样的"以执行来验证"用在行动中的智能体内部、在线进行。

* [RSIAgent](../papers/2609.15364.md) - 为新环境构建经验证器检查的"动作-条件-结果"记忆；Memento 3 把这类知识编译成可重放、可在其中规划的程序。
* [AgentGarten](../papers/2610.12374.md) - 智能体在轮次间携带未经验证的 playbook；Memento 3 的规则手册只有连同能复现证据的代码才被接受。
