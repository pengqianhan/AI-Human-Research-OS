# Q1 问题定义

* **输入（X）：** 一个目标物体名称（例如"办公椅"）和一张参考图像，不提供几何或部件层面的规格。智能体在一个 3D 工具环境中工作，环境提供一个零件目录（零件数至少是所需数量的三倍），基线设置下还提供创建新零件的工具。变体设置包括去掉目录、去掉零件创建、增加一到三轮修改，或在提示中加入基于维基百科的属性与功能要求。
* **输出（Y）：** 一个装配好的结构：带位姿和自然语言角色的已放置零件、每个零件的材料、带轴线、原点和限位的关节（固定、旋转、连续旋转、平移、圆柱、球铰），以及带插入方向的装配顺序。
* **核心问题：** 现有 3D 生成评测大多奖励几何或视觉质量，而一个看起来没问题的物体可能会散架、缺少起作用的部件、动不起来，或者根本无法装配。论文要回答：LLM 智能体能否生成*可建造且能工作*的结构，并构建一个端到端衡量这一点的基准。

# Q2 问题新颖性

部分新颖。编写 Blender 或 CAD 代码的 LLM 智能体（SceneCraft、BlenderAlchemy、Text2CAD、生成 CAD 代码的 VLM）、部件感知生成器（PartCrafter、PartPacker）、关节预测器（JoinABLe、Particulate）、物理感知资产生成器（PhysX-3D、PhysX-Anything）以及带稳定性检查的积木装配系统（BrickGPT、BrickNet、BrickComposer、Blox-Net）各自覆盖了一部分。已有评测（T³Bench、Eval3D、多模态评审协议）给外观、对齐度打分，积木类则给稳定性与放置打分。新的地方在于：一个基准同时覆盖多种物体类型（乐高、家具、带关节的日常物品、工程 CAD、开源硬件产品），从连通性一直评测到仿真中的可操作性，并以维基百科和 Wikidata 中的真实世界功能知识作为参照，判断一个物体需要哪些部件和运动。

# Q3 科学假设

1. **几何已不再是瓶颈。** 如果自下而上地给前沿智能体打分，它们在结构稳健性和设计上会得高分，而在功能部件、运动学和可操作性上低得多（表 2）。
2. **零件创建只帮助强模型。** 如果在检索之外加入零件创建，较强的模型会利用它，较弱的模型反而会被额外的自由度拖累（图 3）。
3. **明确规格胜过反复修改。** 如果给智能体明确的功能要求，功能完整性和可操作性的提升会大于给它带诊断反馈的额外修改轮次（图 4）。
4. **开源模型败在约定与状态。** 如果分析工具调用轨迹，开源模型的失败会集中在 CAD 程序约定与场景状态跟踪上，而不是几何推理上（第 3.5 节）。

# Q5 关键解法思想

LMBuild 由三部分组成，它的主要区别在于：分数的每一层都问的是物理问题，而不是视觉问题。

* **环境。** 一个有状态的纯 Python 工具环境，提供 19 个工具（列出、检查零件、放置、移动、贴合、测量、设置材料、添加或删除关节、设置装配顺序、创建零件、获取场景、计次的 `check` 与 `render`、提交）。新零件是声明式 CSG 程序（最多 96 个节点，基元包括立方体、圆柱、球、圆环、拉伸与旋转体），由 manifold3d 编译为水密实体。几何以 4 毫米体素化，有 9 类共 23 种材料，渲染由无界面 Blender 完成。预算：每轮 160 次工具调用，每个回合 6 次 `check`、4 次 `render`、最多放置 80 个零件，零件创建 30 次（去掉目录时为 60 次）。
* **数据。** 从约 36.8 万个源物体（BrickNet、BrickComposer、PartNeXt、Fusion 360 Gallery 装配体、Artiverse，以及 27 个开源硬件项目的产品级 CAD）中，按覆盖面优先选出 LMBuild-Full（2,549 个物体）与 LMBuild-Core（200 个物体，每个类别最多出现一次，每个物体至少四个零件）。每个物体配一份知识表：Qwen3.5-27B 提出关于部件、属性、子系统和运动学的断言，每条都必须附带来自固定版本维基百科、Wikidata 或 WordNet 的原文引用，再由 Gemma-4-31B 核查是否有据、是否典型。
* **评测。** 12 项指标，统一为 0-100 分。结构稳健性：连通性、碰撞、倾覆稳定性。功能可供性：形状 F 分数、所需功能部件（与最多 12 个同类真实物体组成的群体比较计数）、运动学（关节质量为类型、轴线、偏移、行程、运动集合、自由扫掠各项的乘积，再以召回与精确率的 F1 汇总）。设计质量：分解、美观、对齐，各由两个 VLM 评审（Qwen2.5-VL-32B、Gemma-3-27B）打分并按人工评分校准，D.1 与 D.3 还混合了程序化信号。物理实现：装配顺序可行性（插入扫掠与中间状态是否有支撑）、材料兼容性，以及可操作性：在 MuJoCo 中驱动所声明的关节，每项所需能力按其最弱的要求计分。

# Q6 实验设计

* **被测系统。** 共 30 个：六个闭源 API（GPT-6 Astra、GPT-5.6 Sol、Claude Opus 5、Claude Fable 5.1、Claude Sonnet 5、Claude Haiku 4.5）；13 个用 vLLM 部署的开源模型（Qwen3、Qwen3-VL、Qwen3.5 的 4B 至 35B-A3B 各版本，GPT-OSS-120B、Gemma-4-31B-IT、Ministral-3-8B、InternVL3.5-8B/38B、MiniCPM-V-4.5、ERNIE-4.5-VL-28B-A3B）；11 个领域专用配置（BrickGPT、LegoACE、PartCrafter-15/8、PartPacker、Cube3D+CubePart、PhysX-Anything，以及四个用 Particulate 补关节的变体）。
* **运行框架。** Claude 模型通过 Claude 命令行界面运行，GPT 模型通过 Codex 运行，二者都用 shell 命令调用环境；GPT 回合允许最多三次执行尝试。开源模型使用文本格式的工具调用协议，温度 0.6、随机种子 0。领域专用系统运行其原生流程，超出其输出范围的指标记为 N/A。
* **主评测。** 在 200 个物体的核心集上，每个模型每个任务一条轨迹（表 2）；用两个互不相交的分层 50 物体样本和 1,000 次重抽样检验稳定性（表 6-7）。
* **消融。** 在 25 个抽样物体上比较只检索、只创建与基线设置（图 3）；一到三轮修改，以及属性或功能提示（图 4，按模型的 95% 自助法区间与按回合的 Wilcoxon 检验）。
* **评审校准。** 四名志愿标注者为六个系统生成的 90 个物体打分；用 8 个物体上的 48 个条目拟合校准，再在 7 个留出物体上检验（每个维度 42 个设计，表 5）。

# Q8 证据质量

* **支撑充分的部分。**
  * 核心差距在表 2 中很清楚。闭源 API 的碰撞分为 90.3-97.4、分解分为 69.3-77.6，但运动学最高只有 42.7（Claude Opus 5），可操作性最高只有 22.1（Claude Opus 5）。所有开源模型的运动学最多 16.7、可操作性最多 10.5。
  * 对六个闭源 API 的失败分析很具体：运动学平均 37.9、可操作性平均 18.3；失败的运动目标中 57% 完全缺少要运动的部件，另有 17% 有部件却没有关节；54.5%-68.5% 的设计缺少或错放了至少一半的所需部件；48%-68% 的装配顺序不能完整执行。
  * 零件创建的差距很具体：闭源模型 95.7% 的创建调用成功，开源模型只有 51.7%（Qwen3.5-27B 为 89.4%），失败可追溯到 CAD 内核约定（例如多边形顶点按顺时针排列）和格式错误的程序图。
  * 明确的功能要求使功能部件完整性提高 10.3 个点、可操作性提高 12.0 个点（p < 0.001），而三轮修改只带来约 2%。
  * 相对排名在不同物体子集上稳定（两个互不相交的 50 物体样本之间 Pearson 0.937-0.988）。
* **比标题结论更弱或更窄的部分。**
  * 正文夸大了最好成绩。第 3.2 节说最强系统在运动学上"只是略高于 50"、可操作性最高在"30 多分"，而表 2 的最大值分别是 42.7 和 22.1。
  * 基准规模的表述前后不一致。正文、表 1 和附录 A.5 用的是 200 物体的核心集与 2,549 物体的完整集；附录 A.3 与 A.6 则描述为 50 物体的核心集，以及另外 2,349 或 2,399 个物体的完整划分。
  * 每个模型-任务组合只有一条轨迹，因此置信区间反映的是物体之间的差异，而不是不同运行之间的随机性（作者在 A.6 中承认这一点）。
  * 不同厂商的运行框架不同（Claude CLI、允许最多三次尝试的 Codex、开源模型的文本工具调用协议），因此闭源与开源之间的差距有一部分可能来自接口而非模型。
  * "检索与创建"的结论只基于 25 个物体，图中除一个例子（Qwen3-VL-32B 从 61.7 降到 34.1）外没有数值表。
  * 物理模型是简化的：稳定性只考虑倾覆，可操作性使用统一密度和固定摩擦，没有建模公差、紧固件或制造。论文把分数视为比较性的代理指标，而不是可以投入使用的证明。
  * 设计指标在系统层面与人工一致（Spearman 0.77、0.83、0.94），但逐条目只是中等（0.52-0.64）；在 7 个留出物体上，人工之间的一致性为 0.52-0.73。
  * 较小的模型搭出的装配体较小，这会让连通性、装配顺序和材料指标更容易得分（附录 A.5），因此按单项指标排行会奖励简单设计。

# Q9 贡献

* 一个工具环境：智能体在其中搭建带关节、带材料、带装配顺序的装配体，所创建的零件保证是有效实体。
* 一个来自六类来源、共 2,549 个物体（核心集 200 个）的基准，包括完整的开源硬件产品，每个物体都有基于维基百科、经核查的功能知识。
* 一个从连通性到仿真可操作性的 12 项指标层级，设计部分采用按人工校准的 VLM 评审。
* 证据表明：区分当前智能体与"可建造输出"的是功能可供性和可操作性，而不是几何；明确功能比反复修改更有效。

# Q10 下一步

* **需求获取。** 规格实验的结果提示，可以让智能体在搭建前先检索或询问物体的功能要求；LMBuild 的知识表可以作为这一步的目标。
* **重复运行与框架对等。** 报告运行层面的方差，并让所有通用模型在同一种工具调用接口下运行，以区分模型与框架的影响。
* **把功能检查放进循环。** 基于规则的 `check` 报告只覆盖碰撞、连通性和缺失的声明；把运动学与可操作性测试作为反馈加入，可能才能让修改轮次见效，因为当前的修改只是在修智能体本来就做对的几何。
* **实物验证。** 按作者的提议，打印并装配一部分物体，用真实结果校准仿真可操作性分数。
* **完整划分。** 在 LMBuild-Full 上评测，看排名和功能差距在 152 个类别上是否依然成立。
