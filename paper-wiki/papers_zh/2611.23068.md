# Q1 问题定义

* **输入（X）：** 一套权重冻结的智能体进化（agent evolution）流程：提议器（proposer）写出候选产物（提示、技能、记忆手册、harness 代码），评测在任务集上给相应智能体打分，选择器保留得分更高的候选。
* **输出（Y）：** 对这类循环在哪里失效的诊断，用两个实测方差表达：评测噪声 σ²（对同一产物重复评测）与运行间方差 τ²（独立进化运行所得产物的真实质量差异）；并定义评测流程的**分辨率（resolution）**，即它能可靠地与噪声区分开的最小真实改进。
* **约束：** 每个方法的所有角色用同一个模型；使用官方实现，各模型预算相同；进化只能看到训练集和验证集；循环内每个验证分数都是每任务一次 rollout。

# Q2 问题新颖性

“进化型智能体很脆弱”并不新：论文引用了关于运行方差和任务顺序敏感性、依赖反馈的稀疏增益、技能引发的失败、技能无控积累造成的污染，以及 PACE 对重复带噪比较下误提交的分析。新的是把一个机制在两个层面上隔离出来：用随机效应估计量把评测噪声和运行间方差分开，并用冻结的候选池分别检验提议质量和选择可靠性，规模（每个配置 8 到 16 次进化运行，每个产物评测 8 到 16 次）是单次运行的论文达不到的。

# Q3 科学假设

**分辨率假说：** 智能体进化的瓶颈是识别哪些产物带来改进，而不是提出它们。若成立，则（P1）候选池中存在真正有用的产物；（P2）常见选择机制在两个候选中挑出更好者的准确率接近随机；（P3）每轮的选择错误跨轮累积，形成让方法排名翻转的运行间方差。在方法层面，它预测进化只能积累大于分辨率的改进，因此文献中的大幅增益应来自能一次抬高大多数任务的单一行为。

# Q4 相关工作与关键人物

* **所研究的进化方法：** 文本产物类：GEPA（提示）、SkillOpt-Lite 与 Trace2Skill（技能）、ReasoningBank（记忆手册）。harness 类：HarnessLens（指令、技能、工具描述）、Meta-Harness 与 AHE（代码）。
* **对进化为何失败的分析：** 运行方差与任务顺序敏感性、匹配预算的基线、跨轮稀疏增益、SkillsBench 及后续对技能引发失败和污染的研究、SEAGym 与持续学习评测。
* **带噪选择的统计学：** 最优臂识别、模型选择准则的过拟合、考虑不确定性的 RL 评测、PACE 的随时有效接受检验。
* **不在范围内：** 用确定性打分的程序进化（GPU 内核优化、ARC-AGI-2、Atari 策略搜索），论文指出其结构上噪声更低，但本文未测。
* **关键人物：** Yuanhao Zeng 与 Kan Ren（上海科技大学，两个联系邮箱）。可能的批评者：被审计方法的作者，他们可以指出单条规则测试是看过产物后才选的，且候选层面的证据只来自 10 到 11 个 Terminal-Bench 任务。

# Q5 核心方法

1. **方差分解：** Var(Ŷ) = σ² + τ²。判断一个固定产物相对参照的增益只受 σ² 限制；比较两个方法受 τ² + σ² 限制，因为每次运行都会产生新产物。在 80% 功效、α = 0.05 下检出差距 Δ 所需的每方法运行数：N ≥ 2((z₁₋α/₂ + z₁₋β)/Δ)²(τ² + σ²)。
2. **增益审计：** 对文献中最大的增益，逐条指令检查（LLM 标记加人工核对）找出最可能负责的那一条规则，只把它追加到未进化的基线上；然后修复评测（恢复官方评分器或按语义评分）并重新打分；在四个基准上还在修复后的评测下重新进化。
3. **冻结候选池：** 提议池（基于 SkillOpt-Lite 的提议器在 10 个 Terminal-Bench v2.1 训练任务上生成 100 个技能，在 10 个不相交的测试任务上评测，每个技能-任务对 16 次 rollout）用来度量 Quality@K，即随机抽 K 个技能中最好者的期望成功率，并与“所有候选质量相同”的零假设曲线对照，以去掉对带噪分数取最大值的向上偏差。选择池（100 个技能来自 Terminal-Bench 与 DeepSWE 轨迹，11 个按难度分层的任务，每对 8 到 15 次 rollout）让选择器只看前一两次 rollout，再用其余留出的 rollout 评判它的选择。
4. **轨迹重评：** 对 8 次 SkillOpt-Lite 和 8 次 GEPA 运行中的每个中间产物，用每任务 8 次 rollout 重新评分（进化时只用 1 次）。

# Q6 实验设计

* **模型：** GPT-5.4 nano、GPT-5.6 Luna 与 Terra、DeepSeek-V4-Flash、Kimi-K3、GLM-5.2；便宜的实验用全部六个，昂贵的用子集。
* **方差网格：** 七个方法，ALFWorld、SpreadsheetBench、OfficeQA、Terminal-Bench v2.1：150 个配置（117 个方法配置加基线），每个 8 次进化运行（文本产物方法在 GPT-5.4 nano 上 16 次），每个产物评测 16 次（Terminal-Bench 和 harness 方法为 8 次）。
* **文献调查：** 九篇智能体进化论文主表中的 171 个“基准-模型”结果。
* **增益审计：** 十二个基准（网格中的三个，加上 HotpotQA、PUPA、HoVer、IFBench、AIME 2025、LiveBench-Math、LiveMathematicianBench、SearchQA、DocVQA），三个模型。
* **对比的选择器：** 随机、单次 rollout 执行分数、SkillOpt-Lite 与 GEPA 自带的父代选择（两次 rollout），以及三种 LLM 轨迹评审（逐点、成对、ACE 式），评审模型为 DeepSeek-V4-Flash。
* **论文给出的总开销：** 超过 1000 万次 LLM 调用和 40 万 CPU 核时。

# Q8 证据质量

**方法层面。**

* 评测噪声 σ 在 SpreadsheetBench、OfficeQA、ALFWorld 上为 1.0 到 3.7 个百分点（pp），在 Terminal-Bench 上达到 4.5 pp；运行间 τ 为 0 到 12.3 pp。进化一次、评测一次的方法，典型标准差为 1.7 到 4.1 pp（各基准的中位数）。
* 在同模型、同基准的配置对中，超过 60% 的全运行均值差距低于单次运行比较的一个标准差（按方法为 53% 到 79%）。
* 调查的论文中，所提方法领先最强对手的中位数是 3.4 pp（四分位距 1.2 到 6.6）；171 个结果没有一个报告方差估计，只有 6 个对多于一次进化运行取平均。
* 检出 3.4 pp 需要每个方法大约 5 次运行（SpreadsheetBench）、10 次（OfficeQA）、19 次（ALFWorld）、23 次（Terminal-Bench；按下四分位差距则为 181 次）。每方法只跑一次的结果表，在前三个基准上有 51% 到 73% 的概率选中四个文本产物方法中真正最好的那个，在 Terminal-Bench 上只有 33%，而瞎猜是 25%。

**增益审计。**

* 在增益超过 3 pp 的 27 个“模型-基准”对上，追加一条规则能恢复增益的中位数 90%。例如：SpreadsheetBench 发布版评分器读取公式单元格时不重算，所以“写入计算好的数值，不要写公式字符串”值约 30 pp；LiveMathematicianBench 中“可证明更强结论”的选项只要出现就是正确答案。
* 修复后增益中位数从 17.6 降到 0.8 pp。重新进化的文本产物方法在 OfficeQA 和 SpreadsheetBench 上最多增益 1.9 pp，只有一个例外（+5.8 pp）。HotpotQA 是论文说明的例外，GEPA 在两种评测下都改进了检索；ALFWorld、PUPA、HoVer、IFBench 未发现捷径。
* harness 方法在修复后的评测下重新进化，在 SpreadsheetBench 和 OfficeQA 上最多增益 9 pp；ALFWorld 上较大的增益（Meta-Harness 与 AHE 为 16 到 32 pp）可追溯到一个设置：初始智能体只保留历史的最后两步。

**候选层面（仅 Terminal-Bench）。**

* P1：在 2 小时预算下，Quality@K 从 K = 1 的 49.2% 升到 K = 100 的 61.8%（原始超时下为 39.7% 到 51.6%），在 K = 100 处比等质量零假设高 3.3 到 3.4 pp。最好的单个共享技能达到 57.5%，池均值为 49.2%，最差为 41.9%。
* P2（表 1，后验均值 ± 95% 区间半宽）：

| 选择方式 | 成对准确率（%） | 误接受率（%） |
|---|---|---|
| 随机 | 50.0 ± 0.0 | 30.5 ± 14.0 |
| 执行分数（1 次 rollout） | 49.7 ± 1.9 | 62.1 ± 42.9 |
| SkillOpt-Lite（2 次 rollout） | 48.6 ± 2.6 | 59.4 ± 46.2 |
| GEPA（2 次 rollout） | 48.6 ± 2.6 | 31.6 ± 14.5 |
| LLM 评审（逐点） | 45.4 ± 4.5 | 39.9 ± 17.5 |
| LLM 评审（成对） | 49.0 ± 2.2 | 57.6 ± 23.3 |
| LLM 评审（ACE） | 46.9 ± 3.5 | 39.0 ± 15.6 |

  单次执行分数与后验质量的秩相关为 0.054。K 增长到 100 时没有任何选择器变好，而神谕选择在 K < 5 时就超过了它们全部。
* P3：循环内验证增益随进化增长到 6.9 到 9.0 pp，而重评后的增益停在 +0.4 到 −3.2 pp 之间；校正后的运行间方差从 0 增长到最后一轮的 4.2 到 24.5 平方 pp。
* 一个直接干预（附录 F.3）：SkillOpt-Lite 中每个候选用 16 次验证 rollout 取平均，16 次运行的最终测试均分从 61.4% 升到 64.4%，最好产物从 64.8% 升到 72.7%。

**证据的局限。**

* 候选层面的结果只基于一个基准、10 和 11 个任务、每池 100 个技能、一类提议器，P3 只涉及两个方法和两个模型；论文自己列出了这一点。
* P2 说的是只看一两次 rollout 时的选择，也就是这些方法实际使用的预算。它没有证明选择不可能做到，16 次 rollout 的实验表明评测更多时选择能恢复（读者对论文所报结果的归纳）。
* 误接受率一栏的区间宽到 ±42.9 个点；论文说这无法判断基于执行的选择是否比随机接受更差。成对准确率一栏才是精确的。
* 单条规则测试是在检查产物之后选规则，所以它说明一句话足以得到增益，并不说明产物里没有别的东西（附录 E.1 已说明）。首轮标记由 LLM 智能体完成。
* 审计覆盖 GEPA 与 SkillOpt-Lite 发布的产物以及作者自己的运行；发布的产物被迁移到与其优化时不同的模型上，论文指出这通常会缩小增益。
* 尚未发布任何材料，所以目前无法复跑。

# Q9 贡献

1. 一个明确、可检验的假说：冻结权重的智能体进化受限于识别；以及一个能告诉你某个声称的差距需要多少次运行的方差分解。
2. （据作者称）迄今最大的智能体进化可复现性网格，表明四个基准上已发表的差距都在单次运行噪声之内。
3. 一次审计：在十二个基准中的八个上发现发布版评测存在评分器或移植捷径，并表明那里的大幅增益在评测修复后大多消失。
4. Terminal-Bench 上把提议与选择分开的受控候选池实验，两个诊断指标（针对提议器的 Quality@K、针对选择器的被选质量曲线），以及报告 σ̂ 与 τ̂ 的倡议。

# Q10 后续方向

* **论文提出的：** 方差更低的中间检查（初步分析中，未屏蔽诊断信息的检查通过率的评测噪声比通过/失败判定低 13 到 57 倍，但触发更多检查不等于解决更多任务）；对提议器和选择器分别评测；检验分辨率是否同样限制程序进化和基于 RL 的权重更新。
* **预算分配：** rollout 预算固定时，进化循环应如何在“更多候选”和“每个候选更多 rollout”之间分配？16 次 rollout 的结果和 PACE 式序贯检验提示，竞速或逐次减半式的选择器是显而易见的下一个实验（读者建议）。
* **配对评测：** 表 1 的选择器比较的是未配对的带噪分数。公共随机种子、缓存环境状态或按任务配对求差，可能在不增加 rollout 的情况下提高分辨率（读者建议，论文未测）。
* **对本仓库：** 研究 OS 中任何依靠一次验证就接受修改的技能或 harness 自改进循环，都会遇到同样的问题；在信任一次被接受的修改之前，先记录对现任版本的重复评测，可得到本地的 σ̂（读者推断）。
