# Q1 问题定义

* **输入（X）：** 一个带参考答案 y* 的深度搜索问题 x，以及一个策略 π_θ（Qwen3.5-4B），运行 ReAct 式循环，有两个工具：`search`（Serper）和 `visit`（Jina Reader）。一次 rollout 由 N_i 个*会话*（session）组成，每个会话都是有自己上下文的普通多轮片段。新会话有两种产生方式：*压缩*（compaction），即上下文接近上限时智能体把历史压缩成更短的前缀（每个会话上限 128K token）；以及*子智能体分叉*（subagent forking），即主智能体通过专门的动作把子任务交给一个不嵌套的子智能体。
* **输出（Y）：** 一个更新后的策略，用逐会话的优势（advantage）替代单一的轨迹优势来训练。每个会话是一个独立的训练片段，一次 rollout 中所有会话的 token 级损失被汇总为一个按 token 加权的轨迹目标，因此无论会话数多少，每条 rollout 在组内权重相同。
* **奖励：** 由 LLM（deepseek-v4-flash）对照参考答案判定的二值结果 R ∈ {0, 1}。
* **约束：** 基于 GRPO、无评论家（critic-free）的组内相对优化，没有学习的价值模型；会话级信号需要参考答案。

# Q2 问题新颖性

作为一个被明确提出的设定，它是新的。多数智能体强化学习方法在单会话轨迹上训练，即每条 rollout 只有一个持续累积的上下文；而推理时智能体越来越多地压缩上下文或分叉子智能体，打破了这一假设，造成训练与推理不匹配。常见的权宜做法是*广播*（broadcasting）：把轨迹级结果优势复制到每个会话的每个 token 上（论文引用 Accio-Lab 的 Dressage 和 POLAR）。它让多会话 rollout 可以训练，但分不清有用的会话和浪费的会话，也无法控制一条轨迹用多少个会话。论文把一般设定命名为*多会话智能体强化学习*（每条轨迹可以有任意数量、任意类型的会话），并为之提出方法。相近的工作有 CompactionRL（联合优化任务执行与上下文摘要）和 IGPO（在单会话搜索智能体中把信息增益用作回合级奖励）。

# Q3 科学假设

如果按一条轨迹用了多少会话来调整其轨迹优势，且调整方向取决于它是否成功；再让每个非最终会话获得一个局部奖励，大小等于它把策略对正确答案的似然提高了多少，那么多会话强化学习将比广播达到更高的准确率，同时使用更少的会话。分析部分还给出一个进一步的主张：有效的多会话优化靠的是提高每个会话的效用并更好地分配会话，而不是用更多会话。

# Q5 关键解决思路

Mosaic 在两个层级上优化，然后把两者相加。

**感知会话的轨迹优势（3.1 节）。** 三条排序约束规定了会话数应起的作用。C1：在成功的轨迹中，会话越少优势越高（执行成本更低）。C2：在失败的轨迹中，会话越多优势越高（但仍为负），因为过早放弃可能意味着探索不足。C3：结果必须占主导，失败的轨迹不能排在成功的之前。为满足这些约束，组被按结果拆开，每条轨迹的会话数在其结果子组内转换成居中秩 u_i ∈ [−1, 1]（用秩而非原始计数，以免长尾计数放大信号）。然后把 GRPO 优势乘以 (1 − ρ u_i)，ρ = 0.2。由于该因子介于 1 − ρ 与 1 + ρ 之间，它只能缩放优势而绝不会翻转符号；附录 A 证明了混合结果组满足 C1-C3，并解释了为何选乘法而不选可能逆转结果方向的加法。当组内所有 rollout 结果相同时，GRPO 优势为零，于是用一个后备规则提供少量信号：全成功组用 −β₁u_i（β₁ = 0.2），全失败组用 β₀ min(u_i, 0)（β₀ = 0.1），以保证失败的轨迹永远得不到正优势。

**由信息增益得到的会话级塑形（3.2 节）。** 每个会话是从一个上下文状态到另一个的转移，共三类：*普通*（推理与工具调用）、*压缩*（输入完整历史，输出压缩后的前缀）和*子智能体*（委派前主智能体的上下文，以及结果合并回来之后的上下文）。一个状态的*势*（potential）是更新前策略对参考答案各 token 的平均对数概率，在一段固定的续写（"Now there's enough information to answer." 加答案标签）之后用教师强制计算。会话的奖励是跨越该会话的势变化，并停止梯度。奖励在提示组内*按会话类型分别*归一化，因为压缩会话的平均增益低于普通会话，否则会被系统性地压低。最后一个会话的奖励设为零，因为其输出包含最终答案，答案的似然会淹没信号。会话优势等于轨迹优势加上 λ_r = 0.1 倍的归一化奖励。两道闸门防止局部项盖过结果：在基础优势接近零的全失败组中去掉正向塑形；任何会逆转非零基础优势符号的塑形项都被丢弃（附录 B.2）。

# Q6 实验设计

* **基准。** [BrowseComp](../concepts/browsecomp.md)，1,266 道题，选它是因为其难度需要长时间交互，从而产生多会话轨迹。
* **训练。** REDSearcher_RL_1k（1,000 个深度搜索任务），一个 epoch，rollout 批大小 16，组大小 8，采用 rollout 与训练交替的同机部署，以免异步性干扰比较。超参数 ρ = 0.2、β₀ = 0.1、β₁ = 0.2、λ_r = 0.1。
* **基线。** 基础模型；单会话训练的 GRPO，分别用单会话和多会话推理（不经多会话训练的测试时扩展）；单会话训练的 IGPO；多会话训练的广播；多会话训练的 Mosaic。所有多会话配置都在压缩和子智能体两种场景下运行，各自用自己的智能体循环做 rollout 和评测。
* **分析。** 组件消融（图 3c-d）；训练中的奖励与会话数曲线（图 4）；优势与会话数的关系，以及全局归一化与按类型归一化下信息增益的分布（图 5）；计算信息增益的开销与 IGPO 回合级版本的对比（图 3b）；会话层面的模式：会话数、信息增益为正的会话占比，以及每个会话的信息增益（表 2）。
* **未包括。** 只有一个基础模型和一个基准；没有跨随机种子的方差；没有对 ρ、β 或 λ_r 的敏感性研究；没有与 CompactionRL 的直接比较。

# Q8 证据质量

* **有支撑的结论。**
  * *在压缩场景下，多会话训练胜过广播。* Mosaic 在 BrowseComp 上达到 38.86，每条轨迹 2.35 个会话；广播为 35.31，3.17 个会话，相对提升 10.1%（3.55 分）且会话更少（表 1）。两者都胜过用压缩运行的单会话 GRPO（34.68）和未训练的基础模型（24.80）。
  * *单会话训练向压缩迁移得不好。* 单会话 GRPO 在推理时加入压缩会提升（31.99 到 34.68），但只用 1.24 个会话；IGPO 在压缩下从 28.52 升到 31.36、用 4.12 个会话，在子智能体下则降到 24.64。论文据此认为多会话能力不会单靠泛化自然出现。
  * *会话数如预期被引导。* 在混合结果组中，成功轨迹的优势随会话数下降，失败轨迹的优势随之上升，而成功轨迹始终高于失败轨迹（图 5）。两种方法训练中会话数都在增长，但 Mosaic 更明显地趋于平稳（图 4）。
  * *按类型归一化是有用的。* 在全局归一化下，原始增益较低的压缩会话整体被压低；按类型归一化让两类会话都能得到正负信号（图 5）。
* **比标题更弱或更窄的地方。**
  * *子智能体场景下的增益很小，单会话 GRPO 几乎与之持平。* 在子智能体场景中，Mosaic 得 32.46，广播 31.44，用子智能体运行的单会话 GRPO 31.91，后者用的会话还更少（2.09 对 3.77）。在 1,266 道题上一分约等于 13 道题，且没有报告方差，所以子智能体结果分不出方法高下（读者从表 1 观察到）。作者的消融也发现这里两个组件叠加只带来小幅提升，并推测当轨迹构成图而非链时，边际增益会错估一个会话的贡献。
  * *会话质量指标与训练信号同源。* 表 2 中信息增益为正的会话占比（压缩场景下 59.92% 对 47.74%）和每会话增益，都是用 Mosaic 所奖励的同一个似然势来度量的，因此其上升部分只是被优化的量本身在变动（读者提醒）。
  * *范围窄。* 一个 4B 模型、在 1,000 个任务上训练一个 epoch、一个基准、一个评判模型、固定的超参数。消融和信息增益开销对比只出现在图中。
  * *局部信号需要参考答案。* 势是参考答案字符串的似然，适合短答案问答，不能直接用于以测试或评分细则打分的任务；而且一份压缩摘要可能靠提到一个候选答案、而不是保留有用证据来提高它（读者担忧）。

# Q9 贡献

* 多会话智能体强化学习的形式化：把轨迹视为会话集合、各会话作为独立片段训练，以广播为基线，并用按 token 加权的汇总保持 rollout 等权。
* 一个保持符号、有界的会话数调制，用于 GRPO 优势，给出排序约束、证明，以及结果相同的组的后备规则。
* 基于答案似然信息增益的会话级塑形，按会话类型归一化，并加闸门使其不能逆转结果信号。
* 在两种多会话场景（压缩与子智能体分叉）下的实验，以及对会话数量、质量和分配的分析。

# Q10 下一步

* **作者提出的。** 为多会话强化学习提供公开的训练数据和执行环境；把跨会话的状态传递（压缩保留什么、分叉交出什么、合并如何回报）作为一个统一目标来学习；在异步采样和策略陈旧下保证多会话优化可靠，此时偏向先完成的 rollout 会偏向短轨迹；在 Claude Code 这类部分不透明的生产级 harness 内做强化学习，包括会打断上下文连续性的机制（丢弃推理 token 或工具响应）。
* **面向分叉的图感知信用（读者建议）。** 让子智能体会话通过它影响的每个后续会话获得信用，而不只看其即时增益，并检验这能否在子智能体场景中找回压缩场景下的优势。
* **不依赖参考字符串的信号（读者建议）。** 在编码或报告任务上，用测试结果、评分细则分数，或智能体自己最终答案的似然来替代答案似然势，看按类型归一化是否仍然有效。
* **多种子与 CompactionRL 对比（读者建议）。** 每种配置报告多个随机种子，并与同时训练摘要器和执行器的 CompactionRL 比较。
