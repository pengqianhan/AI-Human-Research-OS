> 论文:**JIT-Agent: Scaling Harness Intelligence via Just-in-Time Harness Evolution**
> 论文链接:<https://arxiv.org/abs/2608.25593>
> 机构:新加坡国立大学(National University of Singapore)

# Q1 问题定义

* **输入 `X`**:一个现成的、权重冻结的 agentic LLM(骨干模型)和一项任务。
* **输出 `Y`**:一个围绕该骨干模型即时合成的、任务自适应的 harness `h = (M, P, A, F)`——包含记忆模块、规划模块、动作模块和工具/技能编排模块——并且随时间推移能够被修复、并从不断积累的历史存档中自我演化出后续版本。
* **核心问题**:agent 的能力并非只由骨干模型决定;围绕它的 harness(记忆管理、规划策略、动作协议、工具/技能编排)可能主导模型自身的贡献,但目前 harness 设计仍是人工的、任务特定的,难以规模化。
* **范围**:这是一个 harness 生成层面的介入——骨干 LLM 的权重保持不变;JIT-Agent 是一个独立训练出来的模型,专门负责生成并修订围绕骨干模型的 harness。

# Q2 问题的新颖性

本知识库 [Agent harness engineering](../topics/agent-harness-engineering.md) 主题下已有多篇论文,把 harness 当作一次部署过程中不断打磨的单一对象:LongHorizon-Harness 围绕现有后端拆分出一套固定的角色结构(manager/executor/auditor);StateM 把状态外化进一个带版本的 YAML runbook;AutoSaddler 和 Recuris 各自从执行轨迹出发诊断并修补一个正在运行的 harness;Prime Agent 在一个持久化的 harness 内部暴露更多可寻址状态(L0-L3),供模型自己修订。JIT-Agent 的新颖之处在于把 harness *构建* 本身当作一种可训练、可迁移的能力:它把任意 agent harness 形式化为一个固定的、可组合的四模块协议 `h = (M, P, A, F)`,构建了一套共享的实现底座(HarnessFactory),在该协议下重新实现了 13 种既有的具名 harness 设计(ReAct、Plan-and-Execute、ReSum、Flash-Searcher、General Agentic Memory、MemoBrain、AggAgent、OAgent、AgentFold、HiAgent、DeepAgent、ROMA、AOrchestra),并训练一个专门模型来即时为任意现成 agentic LLM 合成、修复并自我演化新的 harness 实例——而不是手工设计或逐步修补某一个固定 harness。

# Q3 科学假设

如果 harness 的构建、修复与演化都被当作一个专门模型的显式能力来学习——而不是靠人工设计或在设计阶段就固定下来——那么该模型就能够为任意冻结的骨干 LLM 合成任务自适应的 harness,其表现优于该骨干模型自身的默认固定 harness,也优于人工设计的替代 harness;这种能力可以跨模型家族迁移,并能通过不断积累的历史 harness 存档持续改进——从而把"harness 智能"确立为一个独立于骨干模型规模扩张、可训练且可复合增长的 agent 能力维度。

# Q5 核心解法

* **四模块 harness 协议**:`h = (M, P, A, F)`。`M`(记忆)压缩历史并维护控制器状态(如完整历史、摘要检索、层级化组织)。`P`(规划)根据任务、状态与当前视图形成局部指令(如 DAG 规划、待办列表、空规划器)。`A`(动作)通过冻结的执行器更新状态并发出动作(如 ReAct 式循环、递归执行)。`F`(编排)根据当前指令从注册表中选取能力——工具与技能。
* **HarnessFactory**:在这一协议下重新实现上述 13 个具名系统的统一代码库,把它们变成同一设计空间中可比较、可互换的点,而不是各自独立、难以比较的固定基线。
* **JIT-Agent 自身的三阶段训练流程**:
  1. **定制化(Customization)**:一个教师模型为每个任务生成符合协议的 harness;JIT-Agent 先在被接受的生成结果上做监督微调,再针对 reward/延迟/成本权衡做偏好学习。
  2. **修复(Repair)**:把失败的 harness 及其执行诊断转化为有界(至多两轮)的修复轨迹;JIT-Agent 学习直接根据错误信息提出小幅度、高杠杆的修订。
  3. **演化(Evolution,Evo-GDPO,Evolutionary Group-Decoupled Policy Optimization)**:JIT-Agent 提出新的 harness 候选方案,并将其与既有 harness 设计存档进行比较;只有当某个候选方案在 reward、延迟或成本上推进了帕累托前沿时才会被保留——即以"相对存档的帕累托支配关系"作为自我演化的门控,而非单一标量 reward。
* 在部署阶段,JIT-Agent 支持一种**流式(streaming)**模式,可在一连串任务中保留并复用已生成的 harness(相对地,**静态(static)**模式则为每个任务重新合成)。

# Q6 实验设计

骨干模型覆盖开源模型(DeepSeek-V4-Flash/Pro、GLM-5.2、Qwen3.6-Flash/Plus、Mimo-V2.5-Flash/Pro)与前沿闭源模型(GPT-5.6、Gemini 3.1 Pro、Gemini 3.5 Flash),在 9 个基准(0-100 分制)上评测,分属四类:深度研究([BrowseComp-Plus](../concepts/browsecomp-plus.md)、DeepSearchQA、xBench-DS)、日常工作(AgentIF-Oneday、PinchBench)、规划(DeepPlanning-Shopping、DeepPlanning-Travel)与工作空间(OfficeBench、OdysseyBench)。比较沿两条轴展开:(a)原始骨干模型 vs. 配备 JIT-Agent 的骨干模型 vs. 其他前沿模型(Table 3);(b)固定骨干 LLM、只改变 harness 的受控比较——JIT-Agent 生成的 harness vs. 五种固定 harness(Claude Code、Codex、OpenCode、Hermes、NanoBot),同时报告质量、token 数与美元成本(Table 4)。泛化性检验(Figure 5)在 3 个模型家族 × 2 个规模档位 × 4 个基准上,对 JIT-Agent 与朴素 ReAct 做了 24 组比较。测试时演化检验(Figure 6)在 DeepPlanning-Shopping、DeepPlanning-Travel 与 OfficeBench 上,比较流式 JIT-Agent(跨任务流保留 harness)与静态 JIT-Agent 的累计准确率。两个定性案例展示了 JIT-Agent 实际合成出的 harness:面向产物生产型任务的"Palimpsest"(GraphPlan 模块把一个跨应用任务转化为显式 DAG,限定执行的宽度/深度,记忆模块存储中间产物)和面向深度研究型任务的"Trapdoor"(DynamicDecomposer 搭配一个委托型子 agent 研究工具,以及一个 FactGraphMemory 抽取键值事实以支持多跳证据整合)。

据检索到的内容,主要结果如下:DeepSeek-V4-Flash + JIT-Agent 在 DeepSearchQA 上达到 85.1(原始骨干模型 76.2;GPT-5.6 为 76.0),在 xBench-DS 上达到 82.0(原始骨干模型 70.1)。GLM-5.2 + JIT-Agent 在 DeepSearchQA 上达到 93.9(全文所有报告数字中的最高分),xBench-DS 上达到 88.0(原始骨干模型 76.0,+12.0),AgentIF 上达到 69.9(原始骨干模型 63.0,+6.9),PinchBench 上达到 93.3(整体最高),DeepPlanning-Travel 上达到 83.0(原始骨干模型 62.8,+20.2)。在 BrowseComp-Plus 上,JIT-Agent+GLM-5.2 得分 78.0,JIT-Agent+DeepSeek-V4-Flash 得分 74.0,而同一张表中报告的另外九个骨干/前沿模型分数分布在 67.5-76.9 之间(最高为 GPT-5.6 的 76.9)。在固定骨干模型(DeepSeek-V4-Flash)的受控比较中,JIT-Agent 在 DeepSearchQA 上比最强的固定 harness 高出 4.7 分(85.1 对 80.4,NanoBot),在 xBench-DS 上高出 4.0 分(82.0 对 78.0),且成本更低(例如 DeepSearchQA 上为 40 万 token/0.066 美元,对比 NanoBot 的 92.4 万 token/0.131 美元;作为参照,OpenCode 在 DeepSearchQA、xBench-DS、AgentIF 上分别为 75.9、65.0、48.1);而在 AgentIF 上,JIT-Agent 落后 Claude Code 3.1 分(63.8 对 66.9),但成本约低 14.9%(0.097 美元对 0.114 美元)。在 Qwen3.6-Flash 上,JIT-Agent 在 AgentIF 上严格占优(58.3 分,最低成本仅 0.078 美元,此前最佳方案为 0.170 美元),在 xBench-DS 上相对 NanoBot 降低成本 51.8%。在与朴素 ReAct 的 24 组泛化性比较中,平均提升 7.6 分(分模型家族平均:DeepSeek V4 +10.2,Qwen 3.6 +4.0,Mimo 2.5 +8.6)。在三个用于流式评测的基准上,流式 JIT-Agent 的累计准确率始终优于静态 JIT-Agent。在六个受控设置中,相对最便宜的固定基线,平均成本降低 36.0%,单项最大降幅为 54.1%(Qwen3.6 在 AgentIF 上,从 0.170 美元降到 0.078 美元)。

# Q9 主要贡献

1. 把 agent harness 形式化为一个固定的、可组合的、可由机器生成的四模块协议 `h = (M, P, A, F)`,并在该协议下重新实现 13 种既有的具名 harness 设计(HarnessFactory),使它们成为同一设计空间中可比较、可互换的点,而不是各自独立的固定基线。
2. 通过三阶段流程——来自教师模型的监督定制化、来自执行诊断的有界修复、以及存档门控的 Evo-GDPO 自我演化——训练出一个专门的"harness 智能"模型(JIT-Agent),能够在推理时为任意冻结的骨干 LLM 合成、修复并改进任务自适应的 harness。
3. 在九个基准和多个开源、前沿骨干模型家族上给出实证结果,总体上优于骨干模型自身的固定默认 harness,也优于人工设计的替代 harness(包括 Claude Code、Codex、OpenCode),且在大多数受控比较中成本更低;此外还提供一种流式测试时演化模式,可在一连串任务中持续改进。

# Q10 下一步

* 论文没有报告把三个训练阶段各自拆解开的消融实验,因此提升幅度中有多少来自监督定制化本身、多少来自修复循环、多少来自存档门控的演化阶段仍是开放问题——这是一个自然的后续实验方向。
* JIT-Agent 在 AgentIF 基准上明确落后 Claude Code(-3.1 分),尽管成本更低;弄清楚一个成熟的、人工设计的 harness 捕捉到了哪些当前学习式、按任务合成的 harness 尚未捕捉到的东西,将有助于进一步锐化"harness 智能"这一框架。
* **对本知识库的启示**:这是对本知识库 [Agent harness engineering](../topics/agent-harness-engineering.md) 主题中其他条目的一个尖锐补充——不同于在一次部署过程中打磨同一个固定 harness(StateM、AutoSaddler、Recuris),也不同于在一个持久化 harness 内部暴露更多可寻址状态(Prime Agent),JIT-Agent 训练一个可迁移的模型,为任意现成骨干模型现场制造一个全新 harness,把"harness 设计能力"本身当作可训练、可迁移的产物——这值得拿来与本仓库目前依靠人工选择项目模板和技能而非学习得到的做法作对比。
