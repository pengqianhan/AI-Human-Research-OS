# Q1 问题定义

* **输入（X）：** 一个*代码世界（code world）*：由模拟器或游戏引擎运行的场景程序 $p$，它维护场景状态 $s_t$（物体位姿、关节、任务变量）和相机位姿 $\pi_t$，并按 $(s_{t+1},\pi_{t+1}) = f_p(s_t,\pi_t,a_t)$ 执行智能体的动作 $a_t$；外加一张外观参考图 $x_0$ 和一段文字描述 $y$。
* **输出（Y）：** （a）由共享神经渲染器实时生成的视觉观测 $x_t = R_\theta(x_{<t}, c_{\le t}, x_0, y)$，输入是结构化条件 $c_t = h_p(s_t,\pi_t)$（着色深度图或表面法线图）和视觉历史；（b）只依据这些画面行动、并通过书写 playbook 跨轮改进的智能体。
* **核心问题：** 供智能体学习的环境需要既*忠实*（状态、规则、动力学一致）又*逼真*（观测看起来像真实视频）。模拟器满足前者，但要达到后者需要昂贵的 3D 资产；视频世界模型满足后者，但状态隐含在生成的历史中，无法检查、编辑或测试。

# Q2 问题新颖性

部分新颖。把世界状态放在视频模型之外、只让模型负责渲染，是论文引用的一条活跃路线（状态与画面联合学习、由引擎推进、或由智能体写成代码）。论文声称的不同之处在于：接口（深度或法线——任何 3D 模拟器都能导出，也能从真实视频估计，因此一个渲染器可服务多个引擎）；一个以短块实时运行的因果渲染器，使新动作可以在整个过程中随时加入；以及把结果作为完整的可执行环境，让预训练智能体在其中逐轮练习。其蒸馏方法（Adversarial Forcing）是已知组件的新组合：Self Forcing 式的分布匹配、类似 Self Gradient Forcing 但做到逐位精确的两遍历史梯度重放，以及 DMD2/R3GAN 式的真实数据对抗损失与精确的 R1/R2 计算。

# Q3 科学假设

1. **分离可以阻止漂移进入状态。** 若引擎的状态转移不以渲染画面为输入，渲染误差就无法在世界状态中累积，而且一条记录下来的状态轨迹可以换一种外观或相机重新渲染，而不改变事件本身。
2. **精确重放很重要。** 若对一次 rollout 的可微重放逐位复现采样轨迹而不只是近似复现，后续损失就能更新"历史如何写入缓存"，且重放不会偏离实际采样的结果。
3. **真实数据对抗监督能防止长 rollout 退化。** 若在分布匹配之外加入真实数据对抗项，长 rollout 能保留单靠分数蒸馏会丢失的纹理和细节。
4. **预训练智能体在这样的世界里学得快。** 若具有网络规模先验的智能体只通过渲染画面感知世界，并在轮次间携带书面教训，物理工具使用策略会在少数几轮内出现，而不需要自博弈强化学习所需的数百万局。

# Q4 相关工作与关键人物

* **可执行环境与代码世界。** Habitat 2.0、ManiSkill2、ProcTHOR、OpenAI 的捉迷藏研究（Baker 等，2019）；由 LLM 构建环境（Holodeck、SceneCraft、LLMR、Code2Worlds、SimWorld Studio）；用代码恢复动力学（WorldCoder、代码世界模型、Code as Worlds）。它们都可执行，但用传统图形管线渲染，观感受限于可用资产。
* **视频模型背后的显式状态。** 世界演化与外观分离的引擎驱动或代码驱动视频生成；以 G-buffer 或粗糙模拟为输入的神经渲染与生成式渲染。
* **交互式视频世界模型。** Genie、GameNGen、Matrix-Game 2.0 与 3.0、WorldPlay、SolarWM、Astronex-World、Genie 3、Wonder、ActWorld、LingBot-World，世界存在于生成的历史和学习到的记忆中。
* **自回归视频蒸馏。** CausVid、Self Forcing、LongLive、Causal Forcing、Causal-rCM、Mask Forcing、DMD/DMD2、Self Gradient Forcing、对抗后训练（APT）、蒸馏出的微型自编码器。
* **从书面经验中学习的智能体。** [Reflexion](../concepts/reflexion.md)、ExpeL、Voyager；论文把自己的 playbook 归入这一家族，并说不同之处在于：只通过画面感知、任务文件不给解法、playbook 在全新对话中的独立智能体之间传递。
* **关键人物。** MirroS 与清华大学、北京大学；Jialong Wu 和 Fangfu Liu 为项目负责人，Mingsheng Long 和 Yueqi Duan 在作者之列。可能的批评者：视频世界模型团队（Genie、Matrix-Game），他们会要求定量的视觉质量和可控性指标；以及强化学习研究者，他们会质疑与自博弈的比较。

# Q5 关键解决思路

* **把状态与外观分开。** 引擎掌管状态和规则；渲染器只看到几何条件以及 $x_0$、$y$ 和视觉历史。几何无法确定的属性（颜色、材质）来自参考图和历史。
* **由编码智能体构建世界。** 从单张图片出发时，感知工具产出实例掩码、单目深度与内参、3D 包围盒和网格，编码智能体把它们拟合进场景程序并扩展看不见的空间；从文字出发时，它用几何基元写程序，并用图像编辑模型把首帧渲染变成 $x_0$。两种情况下，它都会从探测相机检查 rollout、运行引擎查询（接触、碰撞间隙、遮挡）并修复场景。只需要粗糙几何。
* **渲染器分三阶段训练。** （1）对 Cosmos 3-Nano（36 层，宽度 4096；文本塔和 Wan 自编码器冻结）做几何条件化：几何 token 与 RGB token 沿序列拼接、由相同的层处理，并通过随机选择深度/法线、丢弃、纹理抑制、形变和潜变量噪声提升鲁棒性。（2）在一个注意力掩码下，用每个块的干净副本和加噪副本做块因果教师强制。（3）**Adversarial Forcing**：学生模型用四步生成自己的块，并通过分布匹配对齐冻结的双向教师；*精确重放*一遍用与 rollout 相同的逐块注意力调用、带梯度地重算历史的 key 和 value，因此重放与 rollout 逐位相同；一个建在冻结教师特征上的判别器头加入相对式真实数据损失，其 R1/R2 惩罚用一次向量-雅可比积和一次雅可比-向量积精确计算，避免对 FlashAttention 做二阶反向。
* **流式推理。** 有界 KV 缓存（服务时保留 5 个 sink 帧和 44 个最近潜变量帧）、超出训练长度时重映射旋转位置编码、自定义 Triton 内核、CUDA graph、蒸馏的微型解码器，以及 WebRTC 推流。
* **逐轮练习。** 任务文件给出目标、动作和限制，但不给解法；智能体通过短小的 Python 程序行动，只能看到渲染画面（没有坐标、地图，局结束前也没有分数），然后写 playbook（Markdown 技能文件，每个文件一条教训），由后续全新启动的智能体继承。

# Q6 实验设计

* **渲染器。** 在相同条件轨迹上比较 Self Forcing 与 Adversarial Forcing 的 30 秒定性 rollout（图 7）；比较 SGF 式全序列 FlexAttention 重放与逐块 SDPA 重放的重放误差、前向时间和显存（一张 H100，61 个潜变量帧）；测量一个 16 帧服务块的稳态吞吐。
* **训练。** 32 张 H100；数据来自 DL3DV-10K 场景采集、OpenDV 驾驶视频、网络上的游戏、导航和机器人交互视频，以及少量渲染的合成场景。
* **捉迷藏。** 2019 年物理环境的一个顺序式"一藏一找"变体；智能体是 GPT-6 Astra；每个角色各有 playbook；每轮五局，布局和种子随机抽取，从空 playbook 开始。里程碑与 2019 年自博弈强化学习研究对比。
* **另外四个世界。** 陪伴犬（60 秒内的参与度得分）、单车道桥（两辆车各由一个智能体驾驶，互换两端；用秒数衡量）、牧羊（两只狗把四只羊赶进羊圈；满分 100）、采石场装载机（推石头、把一块送进掩体、在 360 秒内停车；满分 100）。每个世界四轮，每轮一局。

# Q8 证据质量

* **有支撑的结论。**
  * *精确重放确实精确且不更贵。* 全序列 FlexAttention 重放与缓存 rollout 的相对 L2 误差为 3.99%；逐块 SDPA 重放逐位一致，前向时间从 2.95 秒降到 2.79 秒（-5.4%），峰值显存从 50.83 GiB 到 50.92 GiB（+0.2%）。
  * *实时渲染。* 一个 16 帧服务块总耗时 438.8 毫秒（条件编码 10.6 毫秒，四步去噪加缓存发布 414.4 毫秒，微型解码器加传输 8.8 毫秒）：一张 H100 上 480x832 分辨率 36.5 帧/秒，在缓存满的稳态下测得。
  * *每个世界都报告了逐轮进步。* 捉迷藏：第 4 轮出现用挡板搭的掩体，第 10 轮出现用坡道翻墙。陪伴犬 13 到 19；单车道桥 71 秒到 41 秒；牧羊 60 到 88.3（第 1 轮赶进三只羊，第 2-4 轮四只全进）；装载机 30、0、30、90.9。
* **比标题更弱或更窄的地方。**
  * *按论文自己的说法，"4 轮对数百万局"不是样本效率结论。* 摘要把"仅 4 轮"与强化学习的"数百万"对比，但第 5.2 节说这些数字反映的是不同范式，不是样本效率之比：2019 年的智能体从随机权重开始、在特权物体状态上学习，而 GPT-6 Astra 自带关于坡道和墙的预训练知识。2019 年的里程碑也来自原始环境，而本研究用的是它的顺序式一藏一找变体。
  * *单次运行，无方差，无对照。* 另外四个世界每轮只有一局、只跑了一次四轮；牧羊从 90.1 降到 87.6，装载机为 30、0、30、90.9，可见轮间噪声存在却未被量化。没有对照（例如同样轮数但不带 playbook 的新智能体，或打乱的 playbook）来把学习与布局和种子的变化区分开。
  * *Adversarial Forcing 的视觉收益只有定性展示。* 图 7 显示 Self Forcing 的 rollout 会出现重复纹理并丢失细节；但没有定量的图像或视频质量指标，没有条件遵循度测量，也没有对对抗项、精确重放或 R1/R2 做视觉质量消融。
  * *渲染器对智能体的影响没有测量。* 智能体从未在引擎直接渲染的画面上运行作对比，论文也指出生成画面不一定完美体现所给状态。神经渲染器对智能体学习是有帮助、有损害还是无影响（相对于普通引擎画面），仍是未知数。
  * *只用几何条件限制了哪些世界可行。* 作者指出，旋转的对称物体、颜色、材质和身份都无法由深度或法线确定，长时间遮挡后或超出缓存窗口后可能丢失。

# Q9 贡献

* 一个代码世界框架：显式、可编辑的引擎状态与规则，经由深度或法线条件连接到一个共享的实时神经渲染器，使新世界只需粗糙几何而不需逐场景的视觉资产。
* Adversarial Forcing：少步块因果蒸馏，结合自 rollout 上的分布匹配、逐位精确的历史梯度重放，以及带有针对冻结主干判别器的精确、无需二阶反向的 R1/R2 的真实数据对抗损失。
* 一套实时服务栈（一张 H100 上 480x832 超过 35 帧/秒）。
* 一个演示：只看渲染画面的预训练智能体，在捉迷藏和另外四个世界中通过书面 playbook 逐轮进步。

# Q10 下一步

* **作者提出的方向。** 更紧凑、更完整的条件（关于物体属性和交互状态的结构化文本，或潜变量特征），并与代码世界的状态对齐；由编码智能体编写和修改世界，并自动检查一个世界是否能从智能体所见中解出、粗心的策略是否会失败、是否有可以带到下一轮的东西可学；跨多个世界管理经验（保留、合并或丢弃哪些教训），并利用精确重置与重放在传递之前检验一条教训。
* **智能体研究的对照（读者建议）。** 每个世界的四轮重复多次，加入同样轮数的无 playbook 对照，并报告均值与离散度；让智能体在引擎渲染的画面上重跑，以测量神经渲染器带来的改变。
* **Playbook 对比原始历史（读者建议）。** [Learn2Play Bench](../papers/2610.08215.md) 发现提炼的教训可能冻结错误规则，而原始历史让智能体能够修正它。代码世界可以精确重置和重放，因此可以在相同种子下比较这两种记忆格式。
* **与本项目的契合（读者注）。** playbook 协议（全新智能体、任务文件、继承下来的、写得让另一位读者能够核查的教训文件）与本仓库智能体跨会话交接工作的方式相似；AgentGarten 在未来工作中提出的"教训在传递前应通过重放检验"同样适用于这些交接。

# 相关

* [智能体环境](../topics/agent-environments.md) - 由可编辑的引擎程序和共享神经渲染器组装的环境，由编码智能体从一张图片或一段文字构建，而不是用手工 3D 资产。
* [作为智能体环境的世界模型](../topics/world-model-environments.md) - 学习到的视频模型负责渲染观测，但只负责外观；状态和规则保留在可执行代码中，不同于把世界保存在生成历史中的视频世界模型。
* [智能体自进化](../topics/agent-self-evolution.md) - 智能体通过书写 Markdown playbook 跨轮进步，由全新智能体继承，不更新权重，也没有对所写内容的验证关口。
* [Reflexion](../concepts/reflexion.md) - 论文把自己的 playbook 归入 Reflexion、ExpeL 和 Voyager 这一把所学保存在文本中的智能体家族，不同之处在于只靠视觉感知、并在独立智能体之间交接。
* [Learn2Play Bench](../papers/2610.08215.md) - 衡量提炼的教训与原始历史哪个更有助于智能体学会隐藏规则；与 AgentGarten 选择在轮次间只携带 playbook 直接相关。
* [从轨迹到智能体世界（Trace2Env）](../papers/2610.06100.md) - 同一周构建环境副本的另一种做法：Trace2Env 用语言模型智能体在由轨迹构建的 worldbook 上做模拟，而不是用可执行代码加渲染器。
* [AutoGUIWorld](../papers/2610.01215.md) - 用图像生成器模拟 GUI 环境且没有潜在状态；AgentGarten 把显式状态保留在引擎中，只用生成器负责外观。
* [VibeWorlding](../papers/2608.15265.md) - 智能体通过编辑工具构建 3D 世界，并由几何验证器把关；AgentGarten 的编码智能体则从图片或文字构建场景程序，并用引擎查询验证。
