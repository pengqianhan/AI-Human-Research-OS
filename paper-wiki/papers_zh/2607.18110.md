# Q1 问题定义

论文关心的是**不可验证的开放式任务**（解释、推荐、创意写作、通用指令跟随）上的后训练。这类任务没有唯一正确答案，质量由事实性、相关性、完整性、组织性、风格等多个维度共同决定。

* 输入 `X`：提示 `x`，以及为该提示预先生成的评分细则（rubrics）`R_x`；策略 `π_θ` 采样出回复 `y`。
* 输出 `Y`：更新后的策略参数 `θ`。
* 约束：唯一的质量信号来自另一个语言模型 `M` 对 `(x, y, R_x)` 的评估；推理阶段不能依赖 `M`，也不能依赖任何额外上下文。

要解决的具体缺陷是**信息瓶颈**：标准 RL 只保留 `M` 给出的标量分数，把文字分析全部丢掉，于是同分的回复在优化器眼里完全无法区分。作者指出这个问题在分数上限附近最严重——大量"还不错"的回复都拿满分，而评估模型其实说得清它们之间的差别。

# Q2 问题的新颖性

任务设定本身并不新（基于 rubric 的后训练、LLM-as-a-Judge 已是既有路线）。论文声称新的是**诊断视角**：把限制因素归到**反馈通道的宽度**，而不是**评估模型的质量**。论文明确表示这两者可以分离，评估模型的校准问题是它没有处理的互补方向。

这个视角有意义，是因为"没有验证器"的后训练数据占比很大，rubric-based RL 正在成为默认配方，因此这里的结构性缺陷会被放大传播。

# Q3 科学假设

如果把反馈模型基于 rubric 的评估**蒸馏成可迁移的自然语言"经验知识"**，用它条件化一个教师模型，并让策略去匹配教师的逐 token 分布（而不是把评估压缩成标量奖励），那么策略将会：(a) 在留出的开放式评测上得分更高；(b) 更好地迁移到未见过的基准；(c) 更不容易出现训练集奖励过优化。

# Q4 相关工作与关键人物

作者来自 Microsoft Research，本文直接建立在同组的 *On-Policy Context Distillation for Language Models*（arXiv 2602.12275）与 *Online Experiential Learning for Language Models*（arXiv 2603.16856）之上。

论文给出的相关工作分类：

* **从经验中学习**——Silver 与 Sutton 的"经验时代"；Reflexion；ExpEL；TextGrad；GEPA；Feedback Descent；Critique-GRPO。作者的反驳是：这些方法要么把经验留在外部记忆或提示里，要么虽然把批评并入目标函数，但学习信号最终仍被标量奖励卡住。
* **上下文蒸馏与自蒸馏**——Askell 等；Snell 等；MiniLLM；on-policy distillation（Thinking Machines）；on-policy context distillation。论文还引用了一大批 2026 年的自蒸馏工作，包括分析自蒸馏何时**损害**推理能力的研究。
* **RL 与评判**——Sutton & Barto；GRPO / DeepSeekMath；MT-Bench 的 LLM-as-a-Judge；G-Eval；Rubrics-as-Rewards；奖励博弈（Skalse 等）。

可能欣赏它的读者是 on-policy 蒸馏社区；可能批评它的是 RLHF 研究者，他们会追问 GRPO rubric-reward 基线是否调得足够强，以及"带宽"这个说法究竟解释了多少东西。

# Q5 核心解法

把**同一个**反馈模型 `M`、在**同一套** rubric 下，从**裁判（judge）**改造成**教练（coach）**：

1. 从策略在线采样回复 `y ~ π_θ(·|x)`。
2. 教练产出 `e = Extract_Knowledge(M(x, y, R_x))`——从输出的 `<experience>` 标签中抽取的、可迁移的通用指导，而不是针对该实例的具体修改意见。
3. 把 `e` 作为前置上下文喂给教师模型 `π_teacher`，得到一个被引导过的分布。
4. 沿策略自己的采样，最小化 `π_θ(·|x, y_<t)` 与 `π_teacher(·|e, x, y_<t)` 之间的 **token 级反向 KL**。

教师要么是初始冻结的策略检查点（默认），要么是上一个 epoch 的检查点。由于知识被固化进权重，推理时既不需要教练也不需要经验上下文。

与"批评条件化的 RL"相比，真正的差别在**优化目标**，论文的讨论部分说得很直白：RL 是**追求奖励**的（概率质量向最高奖励回复集中，因此任何与奖励相关的特征都可能被利用）；EL 是**分布匹配**的（保持贴近教师分布的形状）。

支撑这一设计的是**反馈带宽直觉**：1–10 的离散分数最多承载 log₂10 ≈ 3.3 比特，bf16 奖励头最多 16 比特；而 1024 token、词表 15 万的上下文理论上限约 17,600 比特——超过 bf16 标量的 1,000 倍、离散 1–10 分的 5,000 倍。论文反复强调这是**通道容量上界，不是可用监督量**：自然语言的冗余和不完美的知识抽取会让有效信息小得多。

# Q6 实验设计

训练提示来自 WildChat-IF（7,500 条真实用户查询），每条提示的 rubric 由 GPT-4o 预先生成。策略模型为 Qwen3-8B（非思考模式）与 OLMo-3-7B-Instruct；反馈模型为初始冻结策略检查点（自反馈）或 GPT-4o。

基线是用 GRPO 实现的 Rubric-as-Reward，以裁判给出的 1–10 分作为标量奖励。两种方法共享超参：每批 256 条提示 × 8 个采样回复，学习率 1e-6，提示/回复长度上限 8192/4096，采样温度 1，训练 3 个 epoch，每 10 步存一次检查点。反向 KL 只在学生模型预测概率排名前 256 的词表 token 上计算，且不重新归一化。

评测：250 条留出的 WildChat-IF 提示（每条采样 4 个回复，GPT-4o 作 rubric 条件化裁判），外加四个训练中未见的基准——AlpacaEval v2.0 与 ArenaHard v2.0（对 GPT-4-Turbo 的胜率）、WildBench（[-100, 100] 偏好分）、CreativeWritingV3（[0, 100] 直接 rubric 打分）。IFEval 用作分布外能力检查。表中数字为表现最好的 3 个检查点的平均。

这个设计对三条假设的覆盖是合理的：两个策略族 × 两种反馈来源对应 (a)，训练子集与测试集的对比对应 (c)，未见基准对应 (b)。两组消融分离机制——教师更新策略、教师上下文格式——外加一个合成的分布匹配实验。

设计上的弱点：GPT-4o 这一个评估模型族同时负责生成 rubric、给 RL 打奖励、给评测打分，评估者的偏好会贯穿整条流水线；作者称用更强的闭源评估器交叉验证过、相对趋势一致，但没有公布那批数字。没有人工评测。主表也没有报告种子方差。

# Q7 数据与代码

* **训练**：WildChat-IF（7,500 条）+ GPT-4o 生成的 rubric；迭代教师设定下按 1:0.25 混入 Tulu3 提示，并过滤掉与 WildChat 重叠的 SFT 来源。
* **评测**：WildChat-IF 留出 250 条；AlpacaEval v2.0；WildBench；ArenaHard v2.0；CreativeWritingV3（EQ-Bench）；IFEval 作分布外检查。
* **模型**：Qwen3-8B、OLMo-3-7B-Instruct；教师上下文消融用 Qwen3-1.7B（策略）/ Qwen3-4B（教练）；GPT-4o 通过 API 调用。
* **代码**：论文声明发布在 [aka.ms/el-code](https://aka.ms/el-code)（本笔记未独立核实）。

完整复现需要为 rubric 生成和全部评测付费调用 GPT-4o，这是主要的实际门槛。

# Q8 证据质量

主结果（表 2）方向一致但幅度不大。Qwen3-8B 自反馈：WildChat 78.1（基座）→ 79.2（RL）→ 80.0（EL）；AlpacaEval 34.5 → 37.3 → 40.0；WildBench 17.6 → 18.4 → 21.8；ArenaHard 29.1 → 30.5 → 31.0；CW-v3 73.8 → 74.3 → 76.0。OLMo-3-7B 的迁移增益最大（自反馈下 AlpacaEval 45.9 → 50.8，WildBench 42.1 → 47.5）。唯一输给 RL 的是 Qwen3-8B + GPT-4o 在 AlpacaEval 上（37.4 对 38.2）——论文用"在多数基准上更优"的措辞是准确的，没有夸大。

**泛化这一条的证据最强**：在 1,000 条训练样本子集上 EL 的提升**小于** RL，但在 WildChat 测试集、AlpacaEval、WildBench 上都更高（图 3）。"训练集涨、迁移不涨"是奖励过优化的典型特征，很难用"EL 只是优化得更好"来解释。因此奖励博弈的说法作为**行为观察**是成立的，但论文没有直接诊断 RL 策略究竟学会了利用什么。

**教师上下文消融在机制上最有信息量**（Qwen3-1.7B，表 4）：基座 64.8 / IFEval 68.0；RL 67.7 / 67.6；Full Critique 67.9 / 64.6；Rubrics Only 68.1 / 65.6；Multiple-Choice 66.3 / 68.5；默认 EL 68.6 / 68.8。这里干净地分离出两个机制。带评估味道的上下文（完整批评、纯 rubric）会把教师推向**批评者**分布，策略模仿它，于是分布外指令跟随受损。Multiple-Choice 被刻意构造成约 3.3 比特（与标量奖励等宽），它保住了分布外性能但增益最小——这是论文中最接近"带宽论点受控检验"的结果。真正起作用的是**抽取可迁移知识**，而不只是"给更多文字"。

迭代教师消融暴露出真实代价：WildChat 从 80.0 升到 80.7，但 IFEval 从 83.1 塌到 74.9；混入 Tulu3 通用提示（以冻结检查点为教师）后回升到 79.9。这是对遗忘失效模式的诚实报告，而不是一个干净的胜利。

**证据薄弱之处**：带宽论点是论文的招牌直觉，却**没有被测量**——17,600 比特是通道容量上界，论文自己在脚注和正文里都说明了这一点。分布匹配实验（3.5 节）是一个 200 词表的一维玩具设定，奖励量化是人工构造的；作者明确说它既不是对训练流程的模拟，也不构成"所有标量奖励方法都有此局限"的证明。作为示意它没问题，但不应被引用为关于 RL 的一般性证据。模型规模上限只到 8B。还有一个配置（把策略回复连同完整评分输出一起放进教师上下文）在几步内就发散，论文提到但未分析。

总体判断：在所测设定下（7–8B 策略、rubric 打分的开放式指令跟随、GPT-4o 族评估）假设成立；但解释**为什么**成立的因果故事，依赖一个合理却未被测量的带宽直觉，加上一组有启发性的受控消融。

# Q9 主要贡献

1. 一个命名清晰的重构——裁判 vs 教练——把反馈通道的**宽度**与反馈模型的**质量**分离，并清楚说明了在评估者可能出错时，追求奖励与分布匹配这两种目标为何行为不同。
2. 一个具体方法（EL）：教练抽取可迁移经验知识 + on-policy 上下文蒸馏，推理阶段无需携带任何额外东西。
3. 证据表明文本化的经验监督比标量 rubric 奖励迁移得更好，跨两个策略族与两种反馈来源成立，其中"训练集 vs 迁移"的落差是承重观察。
4. 一组消融分离了三个更粗糙的实验会混淆的因素：知识**抽取** vs 原始批评、上下文**格式** vs 上下文**体量**、带宽 vs 内容。
5. 记录了两种失效模式——带评估味道的教师上下文诱发批评模仿；迭代教师导致分布外遗忘——并给出可用的稳定手段（用冻结检查点在通用提示上做 OPD）。

# Q10 下一步

论文承认的局限：带宽只是未测量的上界；玩具分析仅作示意；EL 处理的是通道宽度而非评估者偏差，校准差的教练依然会带偏训练；迭代教师若无通用提示稳定器就会遗忘。

论文没有强调的局限：规模不超过 8B；单一评估模型族同时负责 rubric 生成、RL 奖励与最终打分；没有人工评测；没有报告种子方差；也没有核算教练推理成本（论文认为方法特有的更新开销相对共享的 rollout 与反馈生成很小，但教练调用本身就属于那份共享成本，所以 EL 并不比 RL 便宜，只是量级相当）。

值得跟进的方向：

* **把通道测出来，而不是只给上界。** Multiple-Choice 消融本质是一个带宽旋钮；把它扫成曲线（4、16、64、256 个改进指令；截断不同长度的经验上下文）就能把核心直觉变成可测量的结论。
* **解耦评估者与裁判。** rubric 用一个模型族、教练用第二个、评测用第三个，才能检验增益在流水线不再共享潜在偏好时是否还在——这与 [AI Agents Do Not Fail Alone](../papers/2607.14275.md) 提出的测量效度问题是同一个。
* **教练校准。** 既然 EL 与反馈质量正交，那么配一个校准更好的教练应当可以叠加；增益是相加还是相互干扰，尚未验证。
* **迁移到 agent 场景。** 从 rubric 评估中蒸馏出的经验知识，在精神上接近 [MemoHarness](../papers/2607.14159.md) 的经验库检索与 [OpenSkill](../papers/2606.06741.md) 的技能库；真正的开放问题是经验该**在推理时检索**还是**固化进权重**，而本文只在单轮开放式任务上论证了后者。

对本仓库而言，值得带走的是裁判/教练这一区分，而不是训练配方本身：任何把丰富的模型批评压缩成一个标量再据此行动的循环，都丢掉了批评者所知道的大部分内容。
