> 论文:**ContextPilot: Teaching Agents for Proactive Context Management via Fine-grained RL**
> 论文链接:<https://arxiv.org/abs/2608.28476>
> 机构:清华大学 / 腾讯优图实验室 / 上海人工智能实验室

# Q1 问题定义

* **输入 `X`**:一个建模为 ReAct 式交互的长时程智能体任务——用户查询 `q` 构成初始上下文 `c0`;每一步智能体依据当前上下文生成一对(思考,工具调用),随后把产生的(思考,工具调用,观测)追加进上下文,使上下文随交互推进单调增长。
* **输出 `Y`**:每一步从一个动作空间中选择动作,该空间既包含普通任务动作,也包含上下文管理动作 `A_cm ⊆ A`(其中一个子集,即"上下文编辑动作" `A_ce ⊆ A_cm`,会通过一个上下文转移函数直接改写交互历史);智能体先经监督微调、再经强化学习训练,以便在长文本问答或深度搜索任务中使用这些工具,同时保持工作上下文紧凑。
* **核心问题**:近期的"主动上下文管理"方法允许模型自行通过工具编辑其工作上下文,但论文指出三点局限:(1) 工具集通常局限于检索、删除与摘要,不支持全局规划、长期记忆或自适应压缩;(2) 训练对所有上下文管理动作一视同仁地探索,但作者自己的先导研究(图 2:从每种工具处分支并测量续接轨迹最终成功率的标准差)显示不同工具对最终结果的影响差异巨大;(3) 训练把单一的稀疏轨迹级奖励直接赋给所有中间上下文编辑动作,但一项案例研究(图 3)表明,任务是否正确与上下文管理质量本身可能并不一致——一条正确的轨迹可能依赖反复、低效的检索,而一条错误的轨迹却可能表现出相当合理的上下文管理。
* **范围**:仅限两类任务——长文本问答与深度搜索,均为纯文本、工具增强的智能体场景。论文明确指出不涉及代码智能体或 GUI 智能体(列为未来工作)。

# Q2 问题的新颖性

主动上下文管理本身并非新问题——让模型自行决定何时、如何编辑自己的上下文,区别于被动的基于规则的截断或摘要,已是一个活跃方向(MemGPT、StateLM/"Pensieve"、Sculptor、MemAct、AgentFold,见第 2.2 节综述)。ContextPilot 声称的新意在于识别并同时解决这条路线此前彼此独立的三个局限——工具集广度、跨工具的探索分配、信用分配的粒度——并且每一点都由论文自己的先导研究直接给出实证支持,而非仅凭假设:图 2 显示部分工具的分支结果方差远大于其他工具(例如图中 `readChunk` 与 `deleteContext` 的结果方差最高,`buildIndex` 与 `finish` 最低);图 3 的配对案例研究则展示了一条上下文管理相对薄弱却答对的轨迹,与一条上下文管理相对扎实却答错的轨迹并列对照。

# Q3 科学假设

如果 (a) 把上下文管理工具集从检索、删除、摘要扩展为显式支持规划、结构化长期记忆(抽取实体/时间戳/事件并建立跨片段关联边)与柔性、可恢复的上下文卸载;并且 (b) 强化学习训练采用基于上下文与熵变化的部分 rollout,把额外探索预算专门分配给已显示出高下游敏感度的上下文编辑动作;并且 (c) 对每个中间轨迹快照的信用估计来自所有以其为前缀的终止轨迹的平均奖励,而不是把单一轨迹级奖励统一广播给所有快照,那么由此训练出的智能体将在保持更紧凑工作上下文的同时,取得比基于规则的被动上下文管理、以及此前经强化学习训练的主动上下文管理智能体(如 StateLM)更高的任务准确率,并且这一优势能在多个基础模型、长文本问答与深度搜索两类任务上保持一致。

# Q4 相关工作与关键人物

第 2 节把既有工作分为**被动上下文管理**(一旦上下文长度越过阈值即触发基于规则的截断或摘要,或将上下文折叠纳入强化学习训练、从压缩状态恢复推理——无论哪种情形,模型都只是被动接受外部规则管理的上下文)与**智能体式主动上下文管理**(MemGPT 把智能体记忆当作虚拟内存、通过工具调用管理;不依赖外部控制器、训练智能体自行管理记忆的编辑工具;Sculptor、StateLM("Pensieve 范式")与 MemAct 提供分片、检索、摘要、删除等上下文编辑工具并对模型做微调;AgentFold 用监督微调学习多尺度的折叠操作)。ContextPilot 直接建立在 StateLM 的基础工具集与其"轨迹快照 + token 级损失掩码"训练方案(第 3.1 节)之上,在工具设计与强化学习训练配方两方面同时加以扩展。作者:Zhuoshi Pan 与 Qizhi Pei(标注为同等贡献),以及 Junru Lu、Honglin Lin、H. Vicky Zhao、Di Yin、Xing Sun(Di Yin 与 Xing Sun 标注为通讯作者);所属机构为清华大学、腾讯优图实验室与上海人工智能实验室。在本知识库中,ContextPilot 与 [Context engineering](../topics/context-engineering.md) 主题下的 GenericAgent(以"上下文信息密度"为设计目标、配合固定的九工具接口)、MemoHarness(按用例自适应组装上下文)并列;但与二者不同,ContextPilot 的核心贡献是针对工具使用策略本身的强化学习*训练*方法,而非一种新的上下文组装架构。

# Q5 核心解法

1. **扩展的上下文管理工具集**(表 1,建立在 StateLM 基础工具之上)。新增的"感知与规划"类别在 `analyzeText`/`checkBudget` 之外加入 `plan`(提出一份简要计划)。长期记忆方面新增 `memorize`(抽取结构化的实体、时间戳与事件片段,并在相关记忆项之间建立关联边)、`updateMemory` 与 `readMemory`(检索目标记忆及其图上邻居)。柔性上下文卸载方面新增 `summarizeContext`、`compressContext`(通过轻量压缩模型 LLMLingua-2)与 `foldHistory`(把历史消息折叠进一个可检索索引,之后可通过 `searchContext` 关键词查询恢复)——相对于 StateLM 中较为生硬的 `deleteContext`(将消息替换为占位符)而言更为柔和。凡是会改写交互历史的工具(卸载、写记忆、更新记忆)都被视为上下文编辑动作,也正是轨迹被切分为独立训练快照的位置。
2. **上下文感知的部分 rollout**。对每个上下文管理动作,计算一个上下文变化量(该动作前后上下文长度的相对变化)与一个熵变化量(观测之后 `k` 个生成 token 的平均熵,与*轨迹初始*熵而非上一步熵相比较——这是有意为之的设计,目的是捕捉相对于最初查询状态的不确定性整体偏移,而非相邻步骤间的局部波动)。二者组合为敏感度分数 `S = α·ΔC + β·ΔH`。给定每个查询固定的快照预算 `N`,方法先执行常规的轨迹级 rollout,切分为 `M ≤ N` 个快照;若 `M < N`,则按 `S` 降序对所有上下文管理动作排序,把剩余的 `N − M` 预算用于从敏感度最高的动作处采样额外的续接子轨迹,把更多探索预算导向图 2 所示对下游影响更大的决策点。
3. **细粒度、快照级的信用分配**。不同于 StateLM/Sculptor 的做法——把单一终止轨迹的奖励(结果项、格式项,以及针对无效工具调用或上下文长度违规的惩罚项)统一广播给所有中间快照——ContextPilot 把某个中间快照的奖励估计为以其为前缀的*所有*终止轨迹奖励的均值,这依赖部分 rollout 为敏感快照提供的多条续接轨迹。快照级优势随后通过对同一查询下采样的所有快照做组内均值/标准差归一化得到,并用 GRPO 优化,把每个快照当作一个独立训练样本。附录 A 证明这一按快照取均值的估计量是无偏的——其目标与轨迹级信用分配相同——并且只要某个分支点被采样了不止一条续接轨迹,其方差就严格更低,这为"部分 rollout 带来的额外续接直接提升信用分配质量,而不仅仅是提升探索覆盖面"给出了形式化的理由。
4. **两阶段训练**。先做监督微调:以 Qwen3.5-397B-A17B(思考模式)作为教师模型,置于一个脚手架式训练环境中——该环境只动态展示前置条件已满足的工具(例如 `readChunk` 在 `searchContext` 被调用之前不可见),并对可恢复的工具参数错误进行重试,这些脚手架提示本身会从最终训练轨迹中剔除;监督微调数据来自 NovelQA 的 PublicDomain 子集与 NarrativeQA 的训练子集。随后在长文本问答上,于 LongBench-v2 上做 GRPO 强化学习;在深度搜索上,由于 WebSailor/WebExplorer 主干模型已具备基础检索能力,跳过监督微调、直接在 1000 条采样自 OpenSeeker 的问题上做强化学习。

# Q6 实验设计

**长文本问答**:基础模型为 Qwen3-8B、Qwen3-14B 与 Gemma4-E4B-it,分别比较无工具(128K 上下文)、有工具但未训练("w/ tools",提示词层面的 32K 基线)、ContextPilot-{规模}(仅监督微调,32K)与 ContextPilot-{规模}-RL(监督微调加强化学习,32K)——并列出 RL-MemoryAgent-7B/14B、ReadAgent-8B/14B 与 StateLM-8B/14B-RL 的已发表数字(论文标注取自 StateLM 原论文)。评测集为 NovelQA(Copyright 子集)、∞Bench(En.MC 子集)、LongMemEval-S 与 BrowseComp+(基于固定语料库,非实时联网检索),多选题采用精确匹配,其余采用 LLM 评判。表 2 的关键结果:ContextPilot-8B-RL 在四个基准上平均超过 StateLM-8B-RL 3.55 分;在 SFT-only 的 ContextPilot 基础上做强化学习平均再提升 3.62 分,其中在更长、更难的 BrowseComp+(平均输入约 55.2 万 token)上提升幅度达 5.34 分,远大于在 NovelQA(平均输入约 11.9 万 token,监督微调数据本身已有重叠)上的提升,作者据此认为强化学习的收益随任务难度增大而增大。**深度搜索**:主干模型为 WebSailor-7B 与 WebExplorer-8B,评测集为 BrowseComp(pass@3)、BrowseComp-ZH(pass@3)、GAIA 纯文本子集(103 例,pass@1)与 xBench-DeepSearch(pass@1),均采用 LLM 评判,对比对象包括 ReAct、带截断的 ReAct(28K token 阈值)、ReSum(推理时摘要)、SUPO(联合强化学习训练摘要与智能体能力)与 OpenSeeker(在相同 1000 条样本上做强化学习但不含上下文管理工具)。论文报告 ContextPilot 在两个主干模型上平均超过 SUPO 1.51 分(表 3);本笔记在 PDF 转文本提取中发现表 3 的 WebExplorer-8B 部分存在行对齐歧义(见 Q8),因此只报告论文自述的这一汇总结论,而不逐格重新核对该区块的每个数字。**进一步分析**:token 效率分析(图 4)显示,在 BrowseComp 上 WebExplorer-8B 每轮输入 token 数到第 15 轮增长至约 3 万,而 ContextPilot-8B 稳定在约 8 千至 1 万 token/轮;强化学习训练过程中的工具使用动态(图 5、6)显示,信息检索类工具占比在训练早期约占一半、随后逐渐下降,而规划/记忆/卸载类工具占比上升,同时记忆与卸载类工具的调用失败率随任务成功率上升而下降。

# Q7 数据与代码

论文未提出新基准,复用 NovelQA、NarrativeQA、LongBench-v2(长文本问答)以及 OpenSeeker、BrowseComp、BrowseComp-ZH、GAIA、xBench-DeepSearch(深度搜索),另外还使用 BrowseComp+ 与 LongMemEval-S 作为长文本问答的额外评测集。训练数据统计(附录 B,表 6):监督微调阶段,3096 条 NovelQA 问题中保留 2987 条轨迹,100 条 NarrativeQA 问题中保留 81 条轨迹,共切分出 51469 个训练快照(其中 NovelQA 贡献 50691 个,NarrativeQA 贡献 778 个);强化学习阶段使用 488 条 LongBench-v2 问题(长文本问答)与 1000 条采样自 OpenSeeker-v1 的问题(深度搜索)。训练采用 `verl` 强化学习框架,每个查询的 rollout 预算为 `N = 128` 个快照,每条轨迹最多切分为 8 个快照,推理时最大输入/生成长度分别为 3 万与 2000 token。论文开头给出了代码、项目主页与 Hugging Face 模型合集链接:`github.com/Tencent/ContextPilot`、`tencent.github.io/ContextPilot`、`huggingface.co/collections/panzs19/contextpilot`。

# Q9 主要贡献

1. 通过一项测量各工具结果方差的先导研究,以及一项揭示"任务正确性"与"上下文管理质量"可能不一致的案例研究,识别并用实证支撑了此前主动上下文管理智能体的三点局限:工具集狭窄、跨上下文管理动作的探索一视同仁、信用分配粒度粗糙。
2. 在 StateLM 基础工具之上,扩展出一套包含规划(`plan`)、结构化长期记忆(`memorize`/`updateMemory`/`readMemory`,支持实体、事件与关联边抽取)与柔性、可恢复上下文卸载(`summarizeContext`、经 LLMLingua-2 的 `compressContext`、配合 `searchContext` 的 `foldHistory`)的工具集。
3. 上下文感知的部分 rollout,结合上下文长度变化与熵变化(以轨迹初始熵为参照)识别高敏感度的上下文编辑动作,并为其分配额外的分支采样预算。
4. 细粒度、快照级的信用分配,把中间上下文编辑动作的价值估计为其所有采样续接轨迹的平均奖励,而非单一实现轨迹的奖励;附录 A 证明只要某分支点采样了不止一条续接轨迹,该估计量相对轨迹级信用分配就是无偏且方差更低的。
5. 据报告,在三个基础模型家族与两类任务(长文本问答、深度搜索)上均一致优于基于规则的方法与此前经强化学习训练的基线(StateLM、SUPO、ReadAgent、MemAgent、ReSum、OpenSeeker),且工作上下文更紧凑(稳定在约 8-10K token/轮,而基线近乎线性增长到约 3 万)。

# Q10 下一步

* **工具集覆盖面**(局限性部分):扩展后的工具集可能仍未覆盖所有形式的上下文编辑需求;作者将更丰富的组织、压缩与检索操作列为开放方向。
* **超参数搜索**(局限性部分):受限于计算资源,作者未对训练超参数(尤其是部分 rollout 与信用分配相关的超参数)做充分搜索,因此已报告的增益可能未反映每个机制的全部潜力。
* **任务范围**(局限性部分):评测仅限于长文本问答与深度搜索;把主动上下文管理扩展到代码智能体与 GUI 智能体被明确列为未来工作。
* **未被解释的熵不稳定性**:消融实验(表 5)显示,仅使用基于熵的部分 rollout 并不稳定——在 Qwen3-8B 上反而使 BrowseComp+ 准确率下降 1.32 分——只有与上下文长度变化结合后才转化为稳定的增益。论文并未解释为何单纯的熵信号对上下文编辑动作(区别于推理动作)会失效,这是本笔记提出、而非论文自身讨论的一个开放问题。
* **对本知识库的意义**:本知识库 [Context engineering](../topics/context-engineering.md) 主题已经提出,应如何在不损失可恢复性的前提下验证被检索的执行经验、决定压缩或丢弃什么。ContextPilot 的细粒度信用分配结果(附录 A 的方差证明)为专门*训练*一个上下文编辑策略提供了一个通用答案:在任何具有真实下游不确定性的决策点上,对分支出的多条续接轨迹取平均奖励——这一思路或许可以推广到该主题中其他harness 层面与记忆层面的上下文决策,只要它们在训练时同样可以被分支采样。

# Related

* [Context engineering](../topics/context-engineering.md) - 在该主题既有的上下文组装与压缩架构(GenericAgent 以密度为目标的工具面、MemoHarness 按用例自适应组装)之外,补充了一种专门针对执行上下文编辑的工具使用策略本身的强化学习训练方法,而非一种新的组装或检索架构。
* [Agent fine-tuning](../topics/agent-fine-tuning.md) - 相比该主题现有条目 Agent Lightning 与 VibeWorlding 中较粗粒度、每回合单一数值的 GRPO,贡献了一种更细粒度的信用分配方案:把每个上下文编辑快照的价值估计为其所有分支续接轨迹的平均奖励,并给出形式化的方差归约论证,说明只要某分支点被采样了不止一条续接轨迹,这就优于轨迹级信用分配。
* [GRPO](../concepts/grpo.md) - 把按上下文编辑动作切分出的独立轨迹快照当作 GRPO 的分组样本,用某快照所有分支续接轨迹的平均奖励取代 GRPO 通常"每个采样回答对应一个奖励"的做法。
