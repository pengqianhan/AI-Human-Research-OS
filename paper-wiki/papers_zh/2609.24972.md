# Q1 问题定义

* **输入（X）：**
  * 一个冻结的骨干策略 π。
  * 一个初始执行框架（harness）H₀，包括提示词、控制流、工具接口与描述、记忆/技能文件和上下文管理。
  * 一个有限的*演化集*（evolve set），附带验证器 r(x, τ) ∈ [0, 1]：编程领域用单元测试，智能体工作空间任务用 LLM 评审，工程设计用冻结的仿真器。

  提议器（proposer）LLM 修改执行框架源码，每个候选在同一演化集上、每个任务跑 k 次随机试验来打分。
* **输出（Y）：** 一个演化后的执行框架 H_T，*原封不动*地运行在留出任务上。留出任务包括：有条件时的同分布留出集，以及任务描述、工具接口或验证器都不同的分布外（OOD）基准。报告任务得分 S(H; D) 和每次试验的平均策略 token 成本 C(H; D)。
* **核心问题：** 迭代式执行框架演化在多轮之间自适应地复用同一演化集（每轮候选依赖于之前在同一批任务上的测量），因此演化集上的提升可能来自论文点名的三种相互耦合的失效模式——*基准特定拟合*（benchmark-specific fitting）、*追逐噪声*（noise chasing）和*复杂度累积*（complexity accumulation），而不是可复用的智能体机制。图 1(a) 和表 1 显示，已有方法在分布外几乎保不住演化集上的提升，有几种甚至低于 H₀。
* **范围：** 只研究冻结权重下的执行框架级 RSI（局限性一节明确排除权重更新）；每个领域只在一个套件上演化。主实验中 Claude Opus 4.8 同时担任策略、提议器、失败分析器和泄漏审查器；Gemini 3.5 Flash 仅在编程领域作为第二个搜索策略。

# Q2 问题新颖性

问题本身不新。执行框架演化已有先例，对比基线 Meta-Harness、AHE、TTHE、HarnessX 都属此类。过拟合的担忧也已由作者引用的同期评测论文提出，包括《Rethinking the evaluation of harness evolution for agents》（Wang 等，2026b）、Evo-Bench（Huang 等，2026d）以及增量归因分析（Ding 等，2026）。同期方法也在针对这一问题：HarnessCompass 把泛化作为显式搜索目标，一种门控语义质量-多样性方法用存档取代贪心选择。

RRSI 声称的新意在于*视角*：把演化循环看作自适应经验优化，把经典正则化思想同时引入提议端和选择端，*而不限制*哪些执行框架组件可以被修改。引入的思想包括 L0 基数约束、L1 稀疏化、L2 收缩、熵式探索，以及 Dwork 等（2015）关于留出集复用的谨慎原则。

这个问题重要，是因为当前智能体产品的大量进步来自执行框架工程；论文引用了 Anthropic 与 OpenAI 的工程文章以及 Lilian Weng 的博文。一个离开自身基准就失效的演化方法，根本谈不上递归自我改进。

# Q3 科学假设

如果约束执行框架搜索把有限、带噪反馈转化为持久修改的*方式*，就应得到这样的结果：演化集提升*小于*无正则化演化，但留出集与分布外提升*更大*，策略 token 成本更低。具体约束包括：
* 随运行推进，每个候选捆绑的修改越来越少；
* 被证伪的假设作为负证据被记住；
* 基准特定内容在打分前就被拒绝；
* 只接受超过实测噪声带的提升；
* 成本增长必须与提升成比例；
* 不再带来实测收益的组件被删除。

表 2 是直接检验：

| 设置 | Harvey LAB（演化集） | 分布外平均 | 每次试验 token |
|---|---|---|---|
| H₀ | 89.4 | 39.7 | 1.56M |
| 无正则化演化 | 92.8 | 40.3 | 3.80M |
| RRSI | 90.5 | 43.6 | 2.42M |

# Q4 相关工作与关键人物

* **人工构建的执行框架：** 引用 Anthropic 的《Harness design for long-running application development》（Rajasekaran，2026）和 OpenAI 的《Harness engineering》（Lopopolo，2026）作为工程证据，说明长时运行智能体的成败取决于执行框架，而不仅是权重。引用《Better harnesses, smaller models》（Yang 等，2026a）说明执行框架可部分替代规模。[Harness Handbook](../papers/2607.13285.md)（Wang 等，2026a）与《Language model harnesses are compositional generalizers》（Zhang 与 Khattab，2026）把执行框架本身作为分析对象。[EnvHarness](../papers/2608.19880.md)（Huang 等，2026b）说明每换一个骨干就要重新工程化的代价。

  * HarnessX（Chen 等，2026）：类型化模块原语加轨迹驱动适配。

  另引用 Self-Harness、Recursive Harness Self-Improvement、Continual Harness、DarwinX、AutoHarness 以及《Don't train the model, evolve the harness》。
* **单组件演化与自我改进智能体：**

  * 自修改智能体谱系：Darwin Gödel Machine、Huxley-Gödel Machine、Hyperagents、Agent0、R-Zero。

  [NeoHorse-1](../papers/2609.08183.md) 与 RSI-Exam 作为 RSI 框架被引用，[Prime Agent](../papers/2608.23552.md) 作为自我改进执行框架被引用。

# Q5 关键解法思路

保持编辑空间 Ω(H) 完全开放（提示词、控制流、配置、上下文管理、工具、技能、记忆、子智能体都可改），转而正则化*搜索轨迹*。

* **提议端：**
  * *L0 式退火更新稀疏性*：用 b_t = ⌈b_min + (b_max − b_min)·½(1 + cos(πt/T))⌉ 限制每个候选中可独立归因的修改数。早期轮次可以捆绑协同修改，后期轮次变得稀疏、可归因。
  * *证据感知的功劳分配*：对每个被评估的候选，记录其修改的组件、检验的假设、diff、得分与成本变化、是否被接受。提议器以此为条件，被拒绝的机制持续作为负证据。
  * *结构化探索*：若最近 w 轮进展都落在噪声带 δ 内，就把部分提议预算留给本轮尚未动过的组件，类似熵正则化。
* **选择端：**
  * *泄漏筛查*：审查器在评估*之前*阅读每个 diff，拒绝编码了任务名、实体名、任务特定数值、答案的修改以及无效机制，使泄漏候选永远拿不到虚高分数。
  * *稳定性感知接受*：先反复评估 H₀ 估计 δ，再要求 Ŝ(H′) ≥ S* − δ（S* 为目前最佳分），防止通过一连串单个看似噪声大小的退化一路走低。
  * *Ridge/L2 式复杂度感知接受*：对超过 δ 的提升，要求相对成本增量 ΔC ≤ β₀ + β₁ΔS（β 在演化集上选定后冻结）。
  * *Lasso/L1 式结构剪枝*：在剪枝窗口内没有严格正向实测收益的组件，交给提议器作为删除目标。

论文明确说明 L0/L1/L2 只是定性类比：并不优化任何范数惩罚目标，执行框架组件也不被视为同一参数向量（第 3.1 节、附录 C）。

# Q6 实验设计

* **三个领域，各在一个套件上演化后原样迁移：**
  * 编程：在 Terminal-Bench 2.1（89 题）上演化；分布外为 SWE-bench Verified。
  * 智能体工作空间：在 120 道 Harvey LAB 法律任务上演化，同分布留出 40 道；分布外为 JobBench、GDPval、APEX-Agents。
  * 工程设计：在 61 道无许可限制的 EngDesign 任务上演化；分布外为 Frontier-Eng 奖牌分。47 道中 38 道能在其沙箱中构建，并排除了与演化集重叠的 EngDesign 子域。
* **基线：** H₀ 与四种演化方法（Meta-Harness、AHE、TTHE、HarnessX），全部从同一 H₀ 出发，共享冻结策略、演化集与候选预算。编程领域的基础执行框架为 Terminus-2；其余领域为基于 MCP 工具网关的 ReAct 循环，配动态工具带与 ReSum 式上下文管理。
* **对混杂因素的控制：**
  * 每个数字都与同一时间窗口测得的 H₀ 配对，排除评测基础设施漂移。
  * 工程设计用确定性仿真器，排除执行框架"讨好评审"的可能。
  * APEX-Agents 在全部 480 题的分母上把基础设施故障计为失败。
  * GDPval 使用跨厂商三评审团，并交换两种呈现顺序。
* **分析：**
  * 两组消融（去掉提议端、去掉接受端、两者都去掉）并报告 token 成本（表 2）；
  * 用 Gemini 3.5 Flash 重跑编程演化检验策略鲁棒性（表 3）；
  * 把 Gemini 演化出的执行框架迁移到未见过的 Gemini 3.1 Flash Lite（表 4）；
  * 各设置每次试验的成本与步数（图 4）。
* **未纳入设计的部分：**
  * 基线对比（表 1）与消融（表 2）只在智能体工作空间领域报告；
  * 没有逐个正则化器的消融，只有两组；
  * 正文未给出噪声带 δ 的数值和最终结果的种子数（可能在本次阅读未覆盖的附录 D 中）。

没有新数据集，使用公开基准：Terminal-Bench 2.1、SWE-bench Verified、Harvey LAB、JobBench、GDPval、APEX-Agents、EngDesign（无许可限制子集）、Frontier-Eng。代码开源于 [google-research/rrsi](https://github.com/google-research/rrsi)，项目页 [regularized-rsi.com](https://regularized-rsi.com/)。复现主实验需要前沿模型 API（Claude Opus 4.8 作策略与提议器，Gemini 3.5 Flash 作评审）以及多个容器化/沙箱化的基准环境。

# Q8 证据质量

* **有支撑的：**
  * 表 1（智能体工作空间）直接支持核心论断。RRSI 的演化集得分是演化方法中*最低*的（90.5，对比 90.7–93.0），但同分布留出并列最佳（89.2），三个分布外基准全部最佳：JobBench 40.7、GDPval 52.3、APEX-Agents 37.9，对比 H₀ 的 36.0/48.8/34.2。AHE 与 TTHE 在 GDPval 和 APEX-Agents 上低于 H₀。
  * 消融（表 2）单调地呈现了预测的权衡：去掉任一组正则化器都会提高演化集得分、降低分布外得分。
  * 确定性工程设计领域的迁移（Frontier-Eng +4.3 奖牌分，论文称相对提升 24.3%）削弱了"执行框架学会讨好评审"的解释。
* **比标题弱的地方：**
  * "最高 14.1 分"来自 Gemini 3.5 Flash 的编程演化（64.6 → 78.7）。Claude Opus 4.8 那次在 Terminal-Bench 上只 +6.0，在 SWE-bench Verified 上 +1.8。
  * Harvey LAB 演化集只 +1.1。
  * 工程设计和编程领域没有基线对比，只有 H₀ 对 RRSI。
  * 分布外提升为 1.8–4.7 分，且都是单个评测窗口。正文没有置信区间，较小的差距（如 Harvey 留出集与 Meta-Harness 同为 89.2，打平）无法与噪声区分。
* **机制归因粗糙：** 只有分组消融，泄漏审查器、噪声底线、剪枝各自的贡献未被确立；审查器与提议器同属一个模型家族。
* **成本表述：** 摘要中"比无正则化演化少 30% 策略 token"在我读到的正文里没有给出计算方式。按表 2 的 2.42M 对 3.80M 约少 36%，图 4 比较的对象是基线而非无正则化演化，因此"30%"的确切参照不清楚（读者观察）。包括 RRSI 在内，所有演化后的执行框架都比 H₀（1.56M token、21.2 步）更贵，论文也承认这一点。

# Q9 贡献

* 在同预算对比的支持下，给出清晰诊断：现有执行框架演化方法用分布外性能换取演化集提升，有几种在未见基准上甚至不如起点。
* 一组可复用、保持编辑空间开放的搜索动力学正则化器。原则上与方法无关：泄漏审查器、噪声带底线、按收益计成本规则都能包裹任何"提议—评估—选择"循环。
* 证据表明所得执行框架可跨基准、跨策略家族（Claude、Gemini）迁移，并能迁移到更弱的未见骨干（Gemini 3.1 Flash Lite 在 Terminal-Bench 2.1 上 11.2 → 14.6），同时是对比中最省的演化执行框架。
* 一套评测卫生模板：同窗口 H₀ 配对、全分母计分、确定性评分领域、交换顺序的评审团。

# Q10 下一步

* **逐个正则化器归因：** 对七个机制分别消融，并报告 δ、种子数和置信区间，以便对照噪声判断较小的分布外提升。
* **独立的泄漏审查器：** 测试与提议器不同家族的审查器，并测量它对通用改进的误拒率；过严的审查器看起来像"正则化"，实际上只是阻断了进展。
* **更长运行与权重更新：** 局限性一节把更长时间的自我改进和权重更新设定列为开放问题。尚未检验退火预算与剪枝能否在更多轮次中持续控制执行框架复杂度。
* **与其他方法组合（读者构想）：** 这些正则化器与"改什么"正交，可以叠加到 [SoL-Pi](../papers/2609.20519.md) 的"留出结果永不回流"规则或 [AutoSaddler](../papers/2608.23041.md) 的诊断-补丁循环上，检验提升能否叠加。
* **与本仓库的契合（读者笔记）：** 本仓库中任何执行框架演化循环（技能、AGENTS.md、记忆策略）都面临同样的自适应复用问题。在相信自报的改进之前，噪声带底线和泄漏筛查是廉价的防护。
