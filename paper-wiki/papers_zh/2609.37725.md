# Q1 问题定义

* **输入 `X`**：一个长时程智能体任务（深度研究、终端编程、数学优化、代码仓库优化，或多智能体集群），在固定的上下文预算下运行（多数实验为 32K token，集群实验为 272K）。累积的历史很快就会超出实时上下文能容纳的长度。
* **输出 `Y`**：每一轮产生的“下一份上下文” `C_{t+1}` 本身。标准语言模型只会把输出追加到末尾（`C_{t+1} = C_t ⊕ y_t`，式 1）；上下文语言模型（Context Language Model, CLM）则生成 `C_{t+1} = f(C_t, y_t)`，其中 `f` 是模型自己选择的任意变换（式 2），与它原本要执行的任务动作并行。
* **核心问题**：上下文管理并不是语言模型的原生能力。它要么由人工设计的 harness 按计划执行（例如 Codex、Cursor、Terminus-2 在达到长度阈值时压缩），要么以少量人工定义的工具形式提供给模型（压缩、卸载、检索、折叠）。论文认为这两种方式都限制了模型可用的策略；其先导基准也表明，每种固定策略都至少会在一个简单任务上失败。
* **约束**：实现必须能在现有模型上零样本运行，并兼容标准推理服务。而在标准服务中，任何“中间位置”的编辑都会让前缀 KV 缓存失效、触发重新预填充（re-prefill），所以效率评估必须把这部分开销算进去。

# Q2 问题的新颖性

“在有限上下文中长期保持有用信息”这个问题本身早已确立。论文的新意在于**动作空间**：它把自己定位为一条演进路线的终点——从 harness 定时压缩（Codex、MEM1），到模型触发但工具预定义的方法（Self-Compact、AutoCompact、Context-as-a-Tool、ACM、Sculptor、Context Folding、AgentFold），再到对实时上下文拥有完整读写权。它也明确区别于[递归语言模型（RLM）](../papers/2512.24601.md)：RLM 把**输入**外置为只读的 REPL 变量，但检索到的内容仍被追加到不断增长的实时上下文中；CLM 则让实时上下文（包括执行历史）本身可编辑。论文把两者视为互补。整体立论直接援引“苦涩的教训”（The Bitter Lesson）：让模型自己搜索策略，而不是固化人类先验。

# Q3 科学假设

如果模型可以用通用代码直接改写自己的实时上下文（而不是在少数预定义上下文工具中选择，或服从 harness 的调度），那么：(a) 能力足够的现有模型会自行发现比人工设计更好的上下文管理策略，在准确率和推理算力（prefix-reuse FLOPs）上同时占优；(b) 由于上下文管理变成了普通的模型行为，它可以像其他技能一样被改进——通过自然语言指令、演化出的技能文档以及强化学习——而无需改动 harness。

# Q5 核心解决思路

**把上下文当作文件。** 实时上下文被镜像到一个文件中，文件路径写在系统提示里。模型用普通的 Bash 或 Python 编辑它；编辑会同步到推理服务器，成为下一轮的上下文。如果模型不编辑，生成内容照常追加，因此默认仍能复用前缀缓存。多智能体场景自然成立：一个智能体集群就是多个上下文文件，创建或删除一个文件即启动或终止一个子智能体。

围绕这一核心，论文构建了四个配套部件：

1. **Prefix-reuse FLOPs**（式 3，附录 C）：轨迹级的算力指标，在标准前缀缓存下统计解码、预填充以及任何编辑引起的重新预填充。这样 CLM 不会仅因上下文更短而“显得便宜”。
2. **上下文内学习策略**（式 4–5）：一份指令或技能文档 `s` 可以引导上下文管理；`s` 可以通过 GEPA 式的提示演化循环优化，提议者可以是更强的外部模型（辅助演化），也可以是智能体自己（自演化）。
3. **带“成功门控效率优势”的强化学习**（式 6）：由于编辑打破了只追加的轨迹结构，采用分步 GRPO，把每条轨迹的结果优势广播给它的所有片段。额外的效率优势项**只在组内成功的轨迹之间**按 prefix-reuse FLOPs 排序（成功轨迹少于两条时置零），从而奖励低成本的上下文编辑，又不会因“丢掉信息”而得到奖励。
4. **后缀缓存复用（Suffix Cache Reuse, SCR）**（4.3 节，附录 B）：一个 SGLang 补丁。当一次编辑替换了某段内容后，它把仍保留的后缀片段的 KV 缓存重定位（重新旋转 RoPE 位置）而不是重新预填充，并把每次编辑重定位的片段数上限设为 `k`。复用的状态编码的是编辑前的上下文，因此 SCR 是一种近似，论文用实验验证其效果。对于混合模型（Qwen3.6-27B 的 64 层中有 48 层为线性注意力），它对循环状态做快照，编辑只体现在全注意力层中。

定性上，零样本的 CLM 还发明了作者没有编写过的行为：一个协调者记分板通过 163 次原地编辑持续更新，同时上下文始终只有 6–8K token；新建一个 `notes` 对话角色；用循环清除无关的搜索结果；以及定义并调用 37 次的可复用函数 `compact_turns`。

# Q8 证据质量

**支撑充分**

* *计入算力后的零样本收益。* Qwen3.6-27B、32K 下，CLM 在 BrowseComp-Plus 上达到 59.4%，相对最强基线（Codex 式摘要）高 11.4%，prefix-reuse FLOPs 比摘要和 MEM1 分别少 21.5% 与 28.9%。在 TerminalBench 2.1 上它以摘要 70% 的 FLOPs 打平，在 TBLite 上以 91% 的 FLOPs 超过摘要（73.7% 对 67.0%）。由于该指标计入了重新预填充，这并不只是“上下文更短”的假象。
* *长时程优化。* EdgeBench-10 上，Qwen3.6-27B 的 CLM 以每次 179 PFLOPs 得到 44.6 分，摘要则是 437 PFLOPs 得 42.3 分；Claude 4.6 Sonnet 下 CLM 为 51.0，摘要为 42.3。四个数学问题上 CLM 均取得最佳单次运行最好成绩（如 Heilbronn 0.03653 对 OpenEvolve 0.03127；圆填充 2.618 对 2.541）。
* *可学习性。* 强化学习把 Qwen3.5-9B 的 CLM 在 BrowseComp-Plus 上从 28.8% 提升到 42.5%，与训练后的摘要 harness（42.1%）持平，而每题算力为 1.34 对 2.19 PFLOPs。辅助演化把 KV Store 的保留测试集准确率从 38.3% 提升到 74.2%（四个 ContextBench 任务在开发集上均有提升）。
* *SCR。* 在 BrowseComp-Plus 上，SCR 以标准 SGLang 65.0% 的 prefix-reuse FLOPs 达到相同准确率。

**比标题结论更弱或更窄**

* *运行次数少。* 数学问题每种方法只跑一次；EdgeBench 报告三次中的最好值；Software World 只有一组等花费对比。这些结果具有启发性，但没有统计上的确立。
* *ContextBench 为作者自建。* 任务与每个基线的使用技能都由作者编写。论文称各技能详细程度相当，但基线表现仍依赖于这份编写。
* *harness 待遇不对等*（见 Q6）：预算提醒、不计入轮数的编辑轮以及 BrowseComp-Plus 上的回滚重试都是 CLM 专有的。
* *依赖模型能力。* 收益随模型能力增长。Qwen3.5-9B 编辑上下文的频率更低（每个 TerminalBench 任务 1.4 次对 2.6 次），其峰值上下文中位数几乎占满 32K 预算。读者观察：9B 的零样本对比在不同设置下结论相反——附录 F 中 CLM 39.9% 对摘要 37.7%，而表 2 的 RL 前结果为 28.8% 对 34.7%。两者配置不同（RL 设置为 28K 预算、80 轮），因此论文结果更支持“CLM 需要能力足够或经过训练的模型”，而非“CLM 零样本总能获胜”。
* *集群结果是外部评估，但只有一例。* 65% 指的是在相同花费下、相对初始版本的下游加速幅度更大，在一个六仓库世界的 17 个保留基准上以执行指令数衡量。
* *SCR 是近似方法。* 重定位的状态编码的是编辑前的上下文。其稳健性依赖于 64 题上对 `k` 的敏感性研究；而在 SCR 额外复用的 7.8 个百分点提示 token 中，有 5.3 个来自推理 token 剥离而非 CLM 编辑——因此 SCR 的很大一部分收益适用于一般的推理模型服务。

# Q9 贡献

1. 定义了上下文语言模型（由模型控制上下文转移 `C_{t+1} = f(C_t, y_t)`），并给出一个极简、轻 harness 的实现——上下文即文件——可在现有模型上运行，并直接扩展到子智能体与集群。
2. ContextBench：一个把上下文管理与推理、知识能力分离的诊断基准，表明现有六种策略即便在简单合成任务上也都不完美。
3. Prefix-reuse FLOPs：一个轨迹级算力指标，使被编辑的上下文与只追加的上下文在标准服务下可比。
4. 在编程、深度研究、数学优化、12 小时仓库优化和 24 小时智能体集群上的零样本证据，表明无限制的上下文编辑能以更低成本达到或超过 harness 定义与工具式的上下文管理。
5. 两条学习路径：引导与演化上下文内技能；以及带成功门控效率优势的分步 GRPO 配方。
6. 后缀缓存复用：一种针对非前缀编辑的 SGLang 服务协同设计（含混合线性注意力模型），也能惠及普通的推理 token 剥离场景。

# Q10 后续方向

* **可编辑上下文的安全性**（作者提出）：可写的上下文是一条新通道，提示注入或模型自生成的指令可能借此跨轮次持续存在；论文引用了模型在自己的压缩摘要中插入未授权指令的报告。如何在保持灵活性的同时保障上下文完整性仍是开放问题。
* **扩大强化学习规模、把 harness 蒸馏进 CLM**（作者提出）：许多 harness 操作本质上是上下文变换，因此 harness 可被视为一种程序性记忆——先在外部开发，再内化进模型权重。
* **上下文长度感知**（附录 G）：模型在长上下文下难以准确估计自身 token 用量，需要环境提示；CLM 目前依赖预算提醒。直接训练这种感知能力仍待解决。
* **推理服务**（附录 B）：在混合模型上，剩余的冗余预填充主要源于 SGLang 只在请求边界保存循环状态；更细粒度的检查点（如在消息边界）对标准缓存和 SCR 都有帮助。
* **读者注意到的缺口：** 去掉 CLM 额外待遇（预算提醒、不计数的编辑轮、回滚）的公平性消融，可以单独检验无限制编辑的作用；数学与集群设置需要多个种子；还应审计 CLM 删除了**什么**——能自由改写自身历史的模型，也可能抹掉人类审查者希望保留的证据。
* **与本 Research OS 的契合（读者解读）：** 本仓库已经把持久状态当作智能体读写的文件（`HANDOFF.md`、项目记忆、技能）。CLM 把同样的“文件原生”思路下沉一层——到实时上下文本身；其技能演化结果表明，上下文管理策略也可以作为普通技能存在于这里，而不必写成 harness 代码。
