# Q1 问题定义

* **输入（X）：** 一个冻结的语言模型 M；一个执行驾驭层（harness）h（工具、文件访问、观察接口、交互预算、评分规则）；任务描述 T 与驾驭层描述 H；互不相交的训练 / 验证 / 测试任务划分；以及一个外部技能语料库 C（GitSkills），按标题切分为小节。
* **输出（Y）：** 一份自然语言技能文档 s*，放入智能体上下文后使验证集期望奖励最大化，再在留出的测试集上评分。论文把*初始*技能的构建也纳入优化问题，而不是假设有人事先提供。
* **核心问题：** 现有技能优化器（TextGrad、GEPA、SkillOpt、WikiSkill）只从智能体自身 rollout 中改进技能，于是智能体无法从自身失败推断出的程序性知识始终拿不到，而每次改进都要花 rollout。公开共享的数百万技能已经编码了这类知识，但它们写给别的任务和驾驭层：在 SpreadsheetBench 上，92.9% 的检索结果来自不同的驾驭层（图 1），直接复用可能有害。
* **约束：** M 与 h 固定，技能文本是唯一决策变量；候选技能只有在验证集上胜过现任技能时才被接受。

# Q2 问题新颖性

新在问题框架而不在部件。"从执行经验优化技能"（SkillOpt、SkillOpt-Lite、WikiSkill、Trace2Skill、SkillGrad、EvoSkill）和"从外部知识构建技能"（SkillRouter、SkillFlow、Graph-of-Skills、Anything2Skill、OpenSkill、Agent KB）都是成熟方向。论文的主张是：没有人在优化*全过程*中使用外部技能语料——检索式方法要么在测试时逐任务重复检索，要么只在初始化时用外部知识；经验式优化器则从不查语料。这点重要，因为语料落地的初始技能让第一份可用技能在任何 rollout 之前就存在，而语料还能为诊断出的失败补上缺失的程序，而非依赖优化器模型的参数化猜测。

# Q3 科学假设

如果（a）从大规模技能语料中按小节检索相关程序性知识，（b）把每个检索到的小节改写成只用目标驾驭层的对象、命令和单位表达的"课"（lesson）——去掉领域名词、无对应物的步骤、以及驾驭层描述未佐证的工具声明，（c）这一"检索并适配"步骤既在任何 rollout 之前执行，也在每次由 rollout 驱动的更新内部执行，那么得到的技能将在同等 rollout 预算下胜过仅凭优化器参数化知识写出的技能和未经适配直接检索的技能，并且两个阶段各自独立贡献增益。

# Q4 相关工作与关键人物

* **技能优化器（基线）：** TextGrad（文本梯度）、[GEPA](../concepts/gepa.md)（带 Pareto 前沿的反思式变异）、[SkillOpt](../papers/2605.23904.md)（有验证门的有界增删改编辑）、WikiSkill（技能与失败模式 wiki 共同演化）。论文报告的是自己的复现结果。

* **语料：** GitSkills（Destefanis 等，2026，arXiv:2608.10906），从 GitHub 爬取的智能体技能数据集。
* **本 wiki 邻居：** [SkillOpt-Lite](../papers/2607.03451.md) 与 [Code2Skill](../papers/2609.05571.md) 同样优化或挖掘技能；[Raven](../papers/2609.33439.md) 在推理时从爬取目录（SkillCorpus）为每个任务检索至多两份技能，正是 RASO 反对的"逐任务重复检索"路线。
* **关键人物：** Hyunwoo J. Kim（KAIST，通讯作者）及 KAIST、高丽大学的学生（一作 Jaewon Chu，也是 AgentGrad 的作者）；Yunyang Xiong（Meta AI）。

# Q5 核心解决思路

* **小节级 BM25 检索。** 技能文档按标题切分；查询生成智能体写出查询，BM25 返回前 K = 5 个小节。按小节而非整篇检索，是为了把埋在总体目标不同的技能里的相关步骤翻出来。
* **跨驾驭层适配（Cross-Harness Adaptation）。** 适配智能体接收需求 c_i（RASI 中是一个任务步骤，RASU 中是一条文本梯度）、T、H 和检索小节，输出一条简洁的课，遵循三条规则：去掉领域专有名词和目标驾驭层中无对应物的步骤；只处理 c_i；只有 H 佐证时才保留具体的工具或参数声明。图 5 的例子把卫星影像技能里"跳过空组"的规则改写成电子表格任务中的"把输出视为缺失"，修正了无检索版本会犯的索引错位。
* **RASI（初始化，零 rollout）。** 由 T、H 生成 M 个需求—查询对，为每个需求检索并适配出一条课，再由技能初始化智能体写出 s_0，每条课附在对应步骤上。无检索对照 RFSI 跑完全相同的流程但去掉检索与适配，因此两者差距只反映检索到的知识。
* **RASU（更新，有 rollout）。** 用 s_t 对 40 个训练任务的小批次做 rollout；生成器按每 8 条轨迹一块阅读失败轨迹，产出（文本梯度，检索查询）对，再由一次合并调用去重；为每对检索并适配出一条课；更新器据 s_t、梯度和课生成 s_{t+1}，只有验证奖励提升才接受。对训练集跑两个 epoch。
* **防泄漏。** 建索引前整库删除名字匹配基准名称或其源数据集的仓库。T 与 H 由编码智能体（codex）阅读驾驭层代码一次性写出，不接触测试实例，并在所有方法、模型、随机种子间复用。

# Q6 实验设计

* **基准与划分（训练 / 验证 / 测试）：** OfficeQA 50 / 24 / 172（约 89,000 页美国财政部公报上的 246 个数值问题）；SpreadsheetBench 80 / 40 / 280（在线评测风格，每题多份测试工作簿）；ALFWorld 39 / 18 个游戏，134 个分布外评测游戏；WebShop 80 / 40 / 500。划分沿用 SkillOpt。

# Q8 证据质量

* **有支撑：**
  * *零 rollout 初始化在每个格子都有帮助。* GPT-5.6-Luna：RASI 45.74 / 49.17 / 72.64 / 45.06，对比 RFSI 40.11 / 44.40 / 69.40 / 43.89 和 No skill 11.44 / 32.98 / 64.43 / 43.56（OfficeQA / SpreadsheetBench / ALFWorld / WebShop）。Qwen-3.5-9B：RASI 40.50 / 30.48 / 47.76 / 23.27，对比 RFSI 34.89 / 27.74 / 42.04 / 12.54。
  * *不适配的检索可能有害。* SkillRouter 在多数格子不高于 No skill（GPT 下 ALFWorld 55.97 对 64.43；Qwen 下 WebShop 9.42 对 16.27、SpreadsheetBench 23.45 对 28.81）。
  * *完整方法胜过按常规方式运行的基线。* GPT：RASO 49.03 / 63.33 / 74.13 / 46.61，对比最佳基线 45.54 / 57.02 / 72.64 / 45.54。Qwen：42.25 / 31.55 / 51.00 / 24.73，对比 37.40 / 29.76 / 43.53 / 13.43。
  * *两阶段可分且可叠加。* 从 RFSI+RFSU（40.70 / 51.67）出发，换入 RASU 得 47.56 / 61.07，换入 RASI 得 45.93 / 58.45，两者都换得 49.03 / 63.33。单独适配在 RASI 中贡献 +3.88 / +7.74，在 RASU 中贡献 +2.33 / +5.47。
  * *更新优势在同等初始化下仍成立。* 所有更新方法都从 RASI 出发（GPT）时，RASU 49.03 / 63.33，对比 SkillOpt 46.51 / 60.24、WikiSkill 47.09 / 55.00、GEPA 45.74 / 58.69、TextGrad 43.41 / 57.97。Qwen 在 RASI 下，无检索更新器最多提升 +0.59，四个中有三个在 OfficeQA 上低于初始技能，而 RASU 提升 +1.75 / +1.07。
  * *成本。* 两个 epoch 下 RASO 的 rollout 数与 TextGrad、WikiSkill 相同（196 / 320 / 114 / 360），少于 GEPA 和 SkillOpt；GPT-5.6-Luna 的 API 成本（$0.84 / $0.49 / $0.79 / $10.28）在三个基准上最低，第四个相差不到 $0.06。
  * *检索设置。* K = 5 在两个消融基准上最佳，K = 10 略有下降；1% 的语料已胜过无语料。
* **较弱或有边界：**
  * *表 1 的头条比较未匹配初始化。* 基线从 RFSI 出发而 RASO 从 RASI 出发，主表差距混合了两阶段；匹配后的比较（表 4）把 RASO 的领先缩小到 OfficeQA 上比 WikiSkill 高 +1.94、SpreadsheetBench 上比 SkillOpt 高 +3.09（读者注）。
  * *部分差距相对误差不大。* 若干增益在约两个标准误以内：GPT 的 WebShop（46.61 ± 0.11 对 GEPA 45.54 ± 0.35），以及 Qwen 的 SpreadsheetBench 更新增益（31.55 ± 0.31 对初始 30.48 ± 0.78）。明确的胜出是 GPT 的 OfficeQA 与 SpreadsheetBench、Qwen 的 ALFWorld 与 WebShop（读者注）。
  * *验证集很小。* 接受与否取决于 24 个 OfficeQA 和 18 个 ALFWorld 验证样本，一个样本就能让门槛移动 4-6 个点（读者注）。
  * *语料防泄漏靠关键词。* 技能提到基准名或其数据集时整库删除；不点名却编码了基准特有流程的技能会漏过（作者承认此点，并以仓库级删除来降低风险）。
  * *消融只覆盖两个基准、一个模型。* 2×2、适配、K、语料规模分析都只用 GPT-5.6-Luna 在 OfficeQA 和 SpreadsheetBench 上做。
  * *优化器与适配智能体是同一前沿模型。* 适配是否需要强改写器未测试；Qwen 运行用 Qwen 做适配器，绝对增益更小。

# Q9 贡献

* 把技能优化框架为从零开始，并证明零 rollout 构建的语料落地初始技能在全部八个模型—基准格子上胜过 LLM 自写的技能。
* 跨驾驭层适配作为共享操作：把检索到的程序受约束地改写为目标驾驭层的词汇；消融显示正是它把检索从有害（SkillRouter）变为有益。
* 更新循环内的失败驱动检索（RASU），在匹配与常规两种初始化下都胜过四种无检索更新器，且 rollout 相同、成本更低。
* 证据表明增益来自多样的外部知识而非少数源文档：1% 语料已有帮助，性能随语料规模上升。

# Q10 下一步

* **论文陈述：** 结论之外无明确未来工作；没有专门的局限讨论。
* **初始化匹配的主表（读者注）：** 默认让所有基线从 RASI 出发，因为论文自己的表 4 才是更公平的比较，而更新阶段的优势正是有争议的主张。
* **适配器强度（读者注）：** 交叉搭配适配模型与目标模型（强适配器、小目标模型），看跨驾驭层适配是否是一次性廉价成本，能让小模型受益于前沿模型写的课。
* **泄漏审计（读者注）：** 抽样实际进入被接受的课的检索小节，检查其中是否有基准特有流程，这是关键词黑名单留下的缺口。
* **与本仓库的相关性（读者注）：** 本仓库的技能中心本身就是一个技能语料。RASI 的配方——由任务与驾驭层描述生成需求—查询对、检索小节、为目标驾驭层改写——可作为在花任何一次运行之前从现有中心技能起草新项目技能的候选工作流；其适配规则（丢弃未佐证的工具声明）也与技能中心的来源政策关切一致。
