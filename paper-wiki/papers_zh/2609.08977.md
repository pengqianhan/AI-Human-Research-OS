> 论文链接:<https://arxiv.org/abs/2609.08977>
> 机构:腾讯混元语音团队 / 浙江大学 / 上海交通大学 / 香港中文大学 / 南洋理工大学

# Q1 问题定义

* **输入 `X`**:一次持续进行的人机交互中连续到达的多模态流式输入——视频、语音与文本同时、异步到达,期间包含用户随时的打断、背景噪声、多人同时说话以及"嗯""对"一类的附和(backchannel)。
* **输出 `Y`**:Gander,一个端到端模型,以固定的一秒为窗口持续决定自己是继续倾听、开口说话,还是打断自己正在进行的回应;同时判断某个请求是否超出了本地可解决的范围、需要委派给一个独立的长时程任务执行 agent——随论文一并发布模型权重、代码,以及(据摘要)训练数据。
* **核心问题**:传统人机交互是轮流式、以文本为中心的,而人与人之间的交流是持续、交叠、可随时打断的。论文提出两个必须回答的问题:真正的交互能力能否由外部模块(语音活动检测器加 ASR 加对话模型)组合出来,还是必须内生于模型本身;以及同一个模型能否同时提供实时交互所需的低延迟与复杂 agentic 任务所需的长时程推理,还是两者之间存在不可避免的响应性-智能性权衡。
* **范围**:一份产业界技术报告(腾讯混元语音团队,合作机构包括浙江大学、上海交通大学、香港中文大学与南洋理工大学),在对话能力、全模态理解、交互能力与 agentic 智能四个维度上评测,并使用现成基准与项目主页上的演示——论文明确指出目前尚无专门面向"全模态交互智能体"的基准。

# Q2 问题的新颖性

报告并不声称首创全双工语音交互(引用 BayLing-Duplex、Qwen-Audio-3.0-Realtime、Audio Interaction Model、Seeduplex、GPT-Live/Moshi 作为前作)、全模态建模(Qwen Omni、MiniCPM-o 4.5、JoyAI-VL-Interaction、SeedRealtime)或语音驱动的任务委派(Qwen Audio Agent、搭配 Codex 的 GPT-Live、Claude Voice Mode)——这些均被定位为已有工作。其自陈的新颖之处在于架构上的统一加"内生性"主张:并非把感知、交互时机与任务执行分别构建或由外部编排组合起来,Gander (1) 把交互控制(倾听/说话/打断)作为模型自身自回归 token 流的一部分、以固定时间窗口预测出来,不依赖外部 VAD 触发响应;(2) 用一个明确训练无关、即插即用的"大脑"来化解响应性-智能性的权衡——更强的推理模型可以在不重新训练实时交互模型的前提下被替换进来——并通过一套结构化的工具调用协议以及一个专门的 agent 编排运行时(一个管理任务生命周期、权限与结果交付的持久化网关)来协调,而非临时的、基于提示词的交接。

# Q3 科学假设

如果交互状态的决策以固定窗口为周期、内生地进行预测,作为把感知输入与生成输出在共享时间轴上交织在一起的单一扁平化多模态 token 流的一部分——而非由外部组合的 VAD/ASR 流水线触发——并且如果一个轻量、低延迟的"小脑"负责实时感知与对话控制,同时通过一套由持久编排运行时中介的结构化工具调用接口,把复杂、长时程的工作委派给一个独立的、训练无关的"大脑",那么由此产生的系统应当能够:(i) 在轮转与打断时机上达到或超过专门的全双工系统,同时不牺牲大脑单独可达到的委派准确率;(ii) 尽管训练重心在交互而非静态感知上,依然保持接近基座模型的语音对话与全模态理解能力;(iii) 支持长时程 agentic 任务执行,且无需随后端推理模型的进步而重新训练交互侧模型本身。

# Q4 相关工作与关键人物

* **语音语言模型与全双工交互。** BayLing-Duplex 把倾听/说话/终止的决策作为专门的状态 token 嵌入单一自回归模型;Qwen-Audio-3.0-Realtime 以增量流式分块方式处理音频;Audio Interaction Model 把实时交互从对话式语音扩展到一般性的主动式音频响应;Seeduplex 在嘈杂、多说话人条件下增加了专注倾听与干扰抑制;GPT-Live 采用类 Moshi 的全双工架构。论文认为这些工作大多仍以音频为中心,评测场景也相对受限。
* **全模态与持续多模态交互。** Qwen Omni 集成多种输入模态并支持流式语音生成;MiniCPM-o 4.5 的 Omni Flow 把多模态输入/输出置于统一时间轴上(Gander 的前端"小脑"明确基于 MiniCPM-o 4.5 的 Thinker-Talker 设计构建,并将其作为全模态理解退化对比的基座,见 Q6);JoyAI-VL-Interaction 把持续视觉感知本身视为交互过程的一部分;SeedRealtime 加入了原生音视频全双工交互,能对观察到的环境变化主动响应。
* **从全模态对话到语音智能体。** Qwen Audio Agent 提供一个实时语音运行时,把复杂任务(代码生成、文件操作)委派给后端工作流;搭配 Codex 的 GPT-Live 与 Claude Voice Mode 被引用为把语音交互与通用助手能力结合的产品化先例。论文认为这些系统仍把对话交互与任务执行当作部分独立的能力,而 Gander 的小脑-大脑设计旨在把它们整合进同一个持续过程。
* **关键人物与机构。** Orantqing、纪圣鹏(Shengpeng Ji)、童俊龙(Junlong Tong)与左嘉龙(Jialong Zuo)标注为共同一作;主要机构为腾讯混元语音团队,合作者来自浙江大学、上海交通大学、香港中文大学与南洋理工大学。合著者谢志飞(Zhifei Xie)同时也是本知识库 [VoiceMem](2608.26005.md) 的第一作者——一篇处于同一实时语音交互赛道、但目标不同瓶颈的独立论文。

# Q5 核心解法

1. **三组件架构。** 前端"小脑"(一个基于 Thinker-Talker 设计的实时全双工全模态模型)负责持续多模态感知与交互式沟通;"大脑"(一个训练无关的通用长时程任务执行 agent——默认实现使用 Codex app server,文中同时提到 Claude Code 作为替代)负责长时程推理、文件/代码操作、检索等工具中介工作;"agent 编排运行时"作为两者之间的协调层,同时负责实时多模态推理与异步后台任务编排。
2. **结构化委派协议。** 小脑发出三种绑定到传输层已确认用户轮次(而非小脑自己生成的工具参数,以确保委派始终建立在经身份确认的用户输入之上)的工具操作:`task_start`(创建并命名一个新的后台任务)、`task_send`(把后续输入路由到一个已有任务,`main` 模式引导正在进行的任务,`fork` 模式发起一次不改变主任务状态的只读侧查询)以及 `task_resolve`(确定性的生命周期控制——`cancel`、`allow_once`、`allow_session`、`deny`)。
3. **精简模式与协调器模式。** 在*精简*模式下,运行时直接执行小脑分类出的任务动作,以原始用户轮次作为大脑的指令——控制路径更短、延迟更低、确定性更强。在*协调器*模式下,一个独立的控制面模型基于可信用户请求与有界系统状态,生成声明式的执行指令(推理强度、追问策略、权限策略、交付方式),再由网关依据任务状态、后端能力、权限边界与部署配置对其做结构化校验;协调器本身从不执行任务,也不接触文件、shell 或网络。
4. **网关:统一 Worker Provider 接口背后的五个持久化实体。** Project、Task、Run、WorkerEvent、Delivery 组织后端执行、状态转移、worker 调度、工作区隔离、并发控制、权限处理与结果交付;每个后端(Provider)自行声明其能力(原生可引导性、只读侧查询、用户交互、跨进程恢复、支持的输入模态、上下文获取方式、并行执行)。默认的 Codex 后端实现为每条任务谱系保留一个持久化线程——后续输入注入到该活跃线程,只读侧查询则分叉出一个隔离线程以保留主线程状态。
5. **带三个运行时专用工具的训练无关大脑。** 除原生的文件、命令行、检索工具外,大脑还可调用 `context_fetch`(按引用、角色、事件类型、时间范围与字符预算,检索实时任务上下文/事件/产物)、`memory_search`(跨会话的持久多模态记忆检索)与 `share`(把已验证的发现、中间进展或纠正意见推回实时小脑)。
6. **两个并行、增量式编码器实现的全模态感知。** 视觉:一种任意分辨率切片方案,每个切片由 SigLIP 视觉 Transformer 独立编码,再由一个基于 query 的重采样器压缩为每切片固定小数量的 token(相对原始 patch 网格约 16 倍压缩),分辨率上限设为 448×448,以在实时延迟约束下控制单帧开销。音频:一个流式、逐块的语音编码器,以约 50 帧/秒的速率输出,再经一个轻量 MLP 投影层做 5 倍下采样,压缩到约 10 token/秒后再进入骨干模型——两条通路都持续刷新,而非只在轮次边界更新。
7. **流式分块扁平化。** 交互被切分为固定一秒的窗口;每个 chunk 把该窗口内编码得到的音视频 token、一个预测出的控制 token(倾听/说话/打断)以及最多 *N* 个模型自选的文本 token 拼接在一起,先感知最新证据再生成,每个窗口只做一次决策——把"是否要说"的决策放在"说什么"之前做出,论文将其归因为比外部触发式响应更稳定的全双工行为的原因。上下文通过一个固定的、滑动的 128-chunk(约两分钟)预算管理,使会话无论多长,单步推理成本都保持有界。
8. **解耦的语音生成。** 骨干模型不直接对高帧率声学单元做自回归,而是用骨干最后一层隐藏状态(加同步文本 token)驱动一个小型自回归语音 token 解码器,沿共享时间轴与文本交错生成离散语义语音单元,再由一个流式、逐块、因果的流匹配解码器,基于参考音频提示(从而实现零样本音色控制)增量渲染波形,而非等整句生成完再解码。
9. **四大类、270 万条样本的训练语料。** 语音交互(约 37%,含一个专门构建、标注严谨的全双工"InteractionSpeech"子集,竞争性打断与支持性附和均有明确的操作性判定标准且各自独立标注时序);音视频交互(约 41%,来自流式视频问答/旁白/主动响应,重新对齐并改写为约 8 token/秒的响应速率);agentic 交互(约 13%,种子驱动的音频-agentic 与 GUI/视频驱动的全模态-agentic 轨迹合成,约 3.6 万条,覆盖任务全生命周期——发起、追加、约束更新、澄清、进度询问、取消、交付);鲁棒性/负例数据(约 8%,无关视频、无指令、抗干扰与多方场景),用于减少虚假响应。

# Q6 实验设计

全部结果来自同一个 Gander 检查点,系统提示词与训练时逐字节一致(无针对基准的专门调优);涉及大脑的场景中,大脑由 GPT-5.6 驱动的、训练无关的 Codex worker provider 实现,只能调用各基准所暴露的工具。三个评测轴调用系统的不同部分,评分协议互不可比,因此分开报告而非合并:

**全双工交互(Full-Duplex-Bench v3,100 个带自然不流畅现象的工具增强服务场景)。** 指标:工具选择 F1(ToolSel)、参数正确率(ArgAcc)、回复质量(RespQual,GPT-4o 判官打分)、严格的二值 Pass@1(工具多重集完全正确且全部参数正确),以及三项时序指标——Take-turn(恰当时机接话的比例)、Interrupt(在用户说完前就开始的比例,越低越好)、Filler(在给出答案前先加占位性话语的比例,越低越好,仅在该套件自身的 LLM 延迟分析返回明确判定的场景上定义)。评测直接运行官方发布的评分脚本、未做修改,走完整链路——音频输入,经 Talker 与语音解码器合成音频输出,再对该输出的 ASR 转写打分——因此结果包含真实的合成与识别误差。由于该基准的系统提示要求被测系统立即执行工具而非反问澄清,但外部实例化的大脑并不会看到该提示,作者在大脑的工作目录中放入一份等效指令的合同文件,以使双方处于对等约束下。另单独报告一个**仅大脑**条件(绕开小脑与音频链路,直接由用户轮次文字转写驱动),作为执行层上限参照;由于没有音频时间轴,该条件不支持三项时序指标,论文将其留空而非记为 0。

**语音对话(SpokenQA:Llama Questions、Web Questions;VoiceBench:AlpacaEval、SD-QA——共 2,052 条语句)。** 语音直接进入 Thinker,文本输出被打分;开放式回复由 GPT-4o 判官评分。基线数字取自作者此前 Audio-Interaction 论文的对比表,按交互体制分组(轮流式 vs. 全双工流式),因为轮流式模型能拿到完整语句并有不受限的计算预算,而流式模型还必须在每一步额外判断语句是否已经说完。

**全模态理解(WorldSense,n=3,172;Daily-Omni,n=1,197——共 4,369 道选择题)。** 遵循各基准的官方评测框架与两阶段答案抽取流程;精确字母匹配打分(不用 LLM 判官),贪心解码(确定性)。该设置完全为轮流式(整个问题在解码开始前就已可见,不合成语音,大脑不参与),因此单独衡量前端小脑的感知/推理能力,而不涉及交互行为。另对每道题分别在音视频、仅视频、仅音频三种条件下运行(共 13,107 次推理),量化跨模态融合的作用。

**结果。** 在 Full-Duplex-Bench v3 上,Gander 取得表中最佳轮转行为——100.0% 的接话时机恰当(仅与级联式 Whisper→GPT-4o→TTS 基线并列),且过早打断比例最低(8.0%,对比 GPT-Realtime 的 13.5% 与最弱基线 Ultravox v0.7 的 47.9%)——而在全部四项任务准确率指标上落后,对最弱基线只是小幅落后(Pass@1 0.400 对 0.410),对最强基线 GPT-Realtime(Pass@1 0.600)差距更大。51.6% 的填充语比例是其唯一不领先的交互指标,论文将其归因为在委派任务运行期间需要"占住话轮"而非时机把握上的缺陷。仅大脑条件的 ToolSel 达到 0.934——高于表中包括 GPT-Realtime 在内的全部端到端系统——同时 Pass@1 为 0.520、RespQual 为 0.740,说明执行层本身并非准确率的瓶颈;论文把该行与完整系统之间的差距归因于两个未分别做消融的因素:整个系统需要自行判断何时委派,以及打分基于合成语音的 ASR 转写而非纯文本。

在 SpokenQA/VoiceBench 上,Gander(9B)在全双工流式一组内两个 SpokenQA 子集上均领先(75.60、59.30——分别超过 Audio-Interaction +8.29/+4.96,超过 Moshi 十三分与三十三分以上),在该组内两个 VoiceBench 子集上排第二(AlpacaEval 落后 0.32,SD-QA 落后 5.30)。放到包含轮流式系统在内的全部字段中比较,Gander 的 SpokenQA 分数依然排第二(Llama Questions 落后 Baichuan-Omni-1.5 2.90 分,Web Questions 落后 Qwen2.5-Omni-7B 3.50 分),而 AlpacaEval 与 SD-QA 在全部九个系统中分别排第六与第五。大脑在全部 2,052 个样本中从未被调用——论文将其视为有意的选择性升级而非委派不足,因为该基准是自足的问答任务而非长时程工具工作。

在全模态理解上,Gander 达到 49.62(WorldSense)与 78.53(Daily-Omni),在 Daily-Omni 上与其 MiniCPM-o 4.5 基座相差不到 1.67 分(仍领先 Qwen3-Omni 的 70.70),而在 WorldSense 上比基座低了 6.08 分;视觉塔在整个训练过程中冻结、完全未改变,因此论文把 WorldSense 的退化归因于后训练答题行为以及交互语料中大量视频内容是"无关上下文干扰项",而非视觉编码本身退化。模态消融显示了真实的融合效应而非单一模态主导:音视频联合输入在 WorldSense 上比更强的单一模态高 5.01 分,在 Daily-Omni 上高 19.13 分,增益幅度与各基准实际所需吻合(Daily-Omni 需要时间性音视频对齐,WorldSense 往往靠单一模态即可作答)。

这是模型开发者自身的技术报告;论文坦承了并非全部有利的结果——Gander 在 Full-Duplex-Bench v3 的七个准确率/参数列中有四个落后,在四个语音对话子集中有两个即便在同组内也只排第二,并且在 WorldSense 上相对自身基座出现了真实的、未被回避的 6.08 分退化。部分基线数字(表 4 的 Audio-Interaction 对比)取自作者此前的发表,而非独立复现的运行;WorldSense/Daily-Omni 基线(表 5)被描述为其他系统"官方报告"的数字。论文本身指出目前尚无专门面向全模态交互智能体的基准,因此本文每个评测轴都只覆盖完整系统的一部分(Full-Duplex-Bench v3 有交互但无全模态视觉;SpokenQA/VoiceBench 是轮流式;WorldSense/Daily-Omni 完全不涉及交互与 agentic 委派)——这一局限由论文自己在未来工作部分明确指出,而非本笔记推断得出。

# Q9 主要贡献

1. Gander:一个统一全模态多模态感知、内生全双工实时交互与委派式长时程 agentic 执行的单一端到端模型,而非把三者作为分别训练或外部编排的三个组件拼接起来。
2. 一种小脑-大脑架构,把交互控制(倾听/说话/打断)作为一个扁平化多模态 token 流内、每窗口一次的内生决策来预测,而非由外部 VAD/编排层触发——表 3 的结果显示,Gander 同时避开了对比基线中分别出现的"等太久错过话轮"与"抢话过早打断"这两种失效模式。
3. 一套结构化的小脑到大脑委派协议(`task_start`/`task_send`/`task_resolve`,配合 main/fork 路由与 cancel/allow_once/allow_session/deny 决议)加一个 agent 编排运行时——一个带精简与协调器两种控制模式的持久化五实体网关——使大脑保持训练无关且可替换,任何更强的后端推理 agent(Codex、Claude Code)都能在不重新训练交互侧模型的前提下接入。
4. 一个 270 万条样本、四大类的训练语料,含一个明确标注、独立计时的全双工交互子集(竞争性打断 vs. 支持性附和,各有严格的操作性判定标准)以及专门针对无关上下文、静默、噪声与多方场景的鲁棒性/负例数据。
5. 如实披露权衡的评测结果:在 Full-Duplex-Bench v3 上对六个商业/开源系统取得表中最佳轮转与打断时机,同时在四项任务准确率指标上落后;在全双工体制内取得领先的语音问答准确率,可与处于更宽松交互约束下的轮流式系统相竞争;并在全模态理解基准上展示出经过测量、未被掩饰的跨模态融合增益,同时在其中一个基准上相对自身基座出现真实退化。

# Q10 下一步

论文第 6 节明确列出五个开放挑战:**数据与模型规模化**(agent 调用与对话行为在复杂全模态场景下仍对训练数据分布敏感;计划通过尚未在本报告中描述的独立产业级模型 Hy-Realtime 进一步扩展);**稳定的后训练**(目前尚未针对长时程全模态交互智能体场景大规模应用在线策略蒸馏或强化学习;有效的奖励设计、信用分配与优化稳定性在联合多模态交互与 agentic 执行下仍是开放问题,小脑-大脑架构还带来了局部交互质量与全局任务目标之间如何协调的新问题);**小脑-大脑架构探索**(当前两组件间的通信依赖 ASR 派生信号;更丰富、更结构化的双向通信——两个方向都是——是未来工作);**记忆与长上下文管理**(长的多模态历史、工具调用与不断演变的任务状态对上下文与记忆管理构成挑战——前端小脑固定的 128-chunk(约两分钟)滑动窗口本身就是本笔记直接读到的一个现存限制,见 Q5);以及**评测**(现有基准分别评测全模态理解、双工交互与 agentic 执行,并未充分捕捉小脑-大脑协作本身——本笔记的抓取在这一条要点中途被截断,见 Q8,因此未能读到其完整的应对方案)。

本笔记补充一点论文自身未展开讨论的观察:表 3 中"仅大脑"一行(ToolSel 0.934,表中最高,对比完整系统的 0.759)是论文自身最清楚的证据,说明准确率差距并非执行层的局限,但论文给出的两个候选原因——小脑自身的委派时机决策,以及对合成语音做 ASR 转写引入的退化——并没有一个消融实验来分辨哪个因素占主导。另外,表 4 显示大脑在全部 2,052 个语音对话样本中从未被调用(论文将其解读为正确的选择性路由),而表 3 恰恰是专门要求委派的基准;两张表合在一起,展示的是在一个简单基准上正确地不委派,以及在一个困难基准上一个只有部分解释的准确率差距,但没有一个评测条件能独立于下游语音链路,单独检验委派决策本身是否校准得当。
