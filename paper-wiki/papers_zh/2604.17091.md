# Q1 问题定义

* **输入 `X`**:一个长程 agentic 任务(文件操作、代码执行、网页浏览),可能跨越多个 episode 或多次重复遇到相似任务;执行该任务的 LLM agent 会随着交互变长而不断积累工具描述、检索到的记忆和原始环境反馈。
* **输出 `Y`**:由 GenericAgent(GA)产出的一段动作轨迹——该系统组合了固定的极简原子工具集、层级化的按需记忆、把已验证的历史轨迹转化为可复用 SOP 与可执行代码的自进化机制,以及四阶段的上下文截断/压缩层——能够以远少于基线 agent 系统的 token 数和交互次数完成任务,且成功率相当或更高,并在多次遇到相似任务时持续改进。
* **核心问题**:论文认为,长程 LLM agent 的根本限制并非上下文长度本身,而是随着工具描述、检索记忆和原始反馈不断积累、挤占有限上下文预算,能有多少与决策相关的信息得以保留;同时,从已完成任务中获得的有用经验通常会在各个 episode 之间丢失,而非被保留和复用。
* **范围**:一篇提出 agent 架构并对其做实证评测的系统性论文,针对任务完成度、工具使用效率、记忆有效性、自进化和网页浏览等维度,与命名的基线 agent 系统(Claude Code、OpenClaw,另提及 CodeX 作为相关系统)做对比;自进化完全作用于 agent 的信息环境(SOP、脚本、记忆)而非底层 LLM 的权重,唯一的例外是一项被明确标注为初步探索的、基于反思的权重调整实验。

# Q2 问题的新颖性

以往的长程 agent 方法通常通过扩展上下文窗口、外挂记忆/检索子系统,或暴露一个庞大的工具面来追求通用性来解决问题。GenericAgent 提出的重新表述是:性能由"上下文信息密度"决定——即在一个固定的、刻意保持较小的预算内(论文的目标是将"无幻觉上下文长度"控制在 3 万 token 以下),能够保留多少与决策相关的信息——而非取决于可用上下文的多寡。论文将这一想法具体化为:明确拒绝"完整性/简洁性/自然性"这一常见三难权衡框架,主张真正的核心张力在于完整性与简洁性之间,自然性只是次要约束;这一立场促使作者设计出仅含 9 个工具的极简接口(相对于论文所述对比系统动辄数十个工具),以及一套激进的分阶段压缩流水线,并结合一种由"无执行,无记忆"规则显式门控的自进化机制,只有经过验证、成功执行的信息才会被长期保留。

# Q3 科学假设

如果一个 agent(a)仅暴露一个极简的原子工具集,(b)将记忆按层级组织,使默认可见的上下文中只保留一份精简的索引,而更深层的流程性知识与原始记录只能通过显式工具调用访问,(c)只从经过验证的成功执行中演化出针对特定任务的 SOP 与可执行脚本,并(d)通过分阶段的方式对上下文做激进的截断与压缩以维持一个小而高密度的工作上下文,那么它将能够匹配或超过那些暴露庞大工具面并依赖扩展上下文窗口的 agent 系统的任务成功率,同时消耗远更少的 token 和交互次数,并且其表现会随着多次遇到相似任务而持续提升,而非保持静态。

# Q5 核心解法

1. **极简原子工具集。** 涵盖五类能力共九个工具——文件操作(`file_read`、`file_patch`、`file_write`)、代码执行(`code_run`)、网页交互(`web_scan`、`web_execute_js`)、记忆管理(`update_working_checkpoint`、`start_long_term_update`)、人在回路(`ask_user`)——通过组合而非枚举大量专用工具来构建复杂能力。论文报告称,对比系统更庞大的工具面在实际执行中仍会高度集中于极少数工具(单一工具占全部调用的约一半),据此认为多出的工具大多只增加了提示开销与决策复杂度,而未带来相应的行为收益。
2. **层级化按需记忆。** 分为四层——L1(始终可见的精简索引/指针层)、L2(存放已验证信息的事实层)、L3(流程性知识的 SOP 层)、L4(原始会话归档层)——默认工作上下文中只包含 L1;更深层只能通过显式工具调用访问,从而在保留可达性的同时保持活跃上下文的精简。
3. **执行门控的自进化。** 固定的工具层与不断演化的知识层相互分离;针对特定任务的能力以可复用 SOP 与脚本的形式积累,并受"无执行,无记忆"规则约束——只有经由成功任务执行验证过的信息才会被写入长期记忆,从而明确防止失败尝试污染知识层——这是本知识库已追踪的 SkillOpt 系列验证门控机制的一个更严格、以执行结果为唯一门控条件的变体。
4. **四阶段上下文截断与压缩。** (1)对每个工具的输出按头尾字符保留策略做截断;(2)每五轮做一次标签级压缩,替换冗余块并截断推理过程文本;(3)一旦超出上下文预算即按 FIFO 顺序淘汰消息;(4)持续注入工作记忆锚点提示,在上述有损阶段之间保留任务关键信息——共同将工作上下文目标控制在约 3 万 token 以内,而非依赖扩展的上下文窗口。

# Q6 实验设计

在五个维度上、基于具名基准做评测:任务完成度与 token 效率(SOP-Bench、Lifelong AgentBench、RealFin-Benchmark)、工具使用效率(一个长程复杂任务场景)、记忆有效性(重复运行的效率变化、一项精简记忆消融实验,以及相较基于嵌入检索方案的长期事实保留能力)、自进化与自主探索(一个按广度/深度/实用性/创新性打分的技能树课程规划器,辅以案例研究)、以及网页浏览(在序列化之前进行 DOM 分析与元素可见性分类)。主要结果:在 Lifelong AgentBench 上,GA 使用 22.2 万输入 token 即达到 100% 准确率,而 Claude Code 需 80 万、OpenClaw 需 143 万;在 RealFin-Benchmark 上,GA 用 11.4 万总 token 达到 65% 准确率,优于 Claude Code 的 55%-60% 和 OpenClaw 的 35%;GA 在各基准上的效率指标(每百万 token 对应的准确率)在 4.15 至 5.70 之间。在一个长程复杂任务场景中,GA 报告以 188,829 个 token 达到 100% 成功率,约为 Claude Code 消耗量的 35%、OpenClaw 的 30%,而成功率相当或更优。记忆有效性消融实验报告称,一种精简、高密度的记忆配置与冗长配置在任务成功率上打平(均为 66.48%),但仅使用 165 个 token,而冗长版本使用 288 至 575 个 token。重复运行效率方面,据报告在同一任务族的多次运行中效率显著提升,单次操作耗时从第一次运行的 102 秒降至后续运行的 66 秒,token 消耗从 20 万降至 10 万。

# Q9 主要贡献

1. 把长程 agent 的性能重新表述为围绕上下文信息密度而非上下文长度展开,并通过四个相互衔接的组件——极简原子工具集、层级化按需记忆、执行门控的自进化、分阶段上下文压缩——加以落实。
2. 一种具体的执行门控自进化机制("无执行,无记忆"),只把经过验证、成功执行的轨迹转化为可复用的 SOP 与可执行代码,同时保持基础工具层固定,并与不断演化的知识层相分离。
3. 报告了在五个评测维度上的实证效率收益——在至少一个长程任务场景中,以约三分之一的 token 消耗匹配或超过两个具名基线 agent 系统的任务成功率——这些结果仍有待对照论文自身的 PDF 与表格做独立核实。
