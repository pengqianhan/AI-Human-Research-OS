> 论文:**WideSeek-R1: Exploring Width Scaling for Broad Information Seeking via Multi-Agent Reinforcement Learning**
> 论文链接:<https://arxiv.org/abs/2602.04634>
> 机构:RLinf 团队(清华大学相关)

# Q1 问题定义

* **输入 `X`**:一个广度信息检索任务,要求跨多个实体收集大量可独立验证的事实,并按 schema 约束(指定列)整理成表格,外加一个共享的 LLM(以 Qwen3-4B 为骨干)分别实例化为一个 lead agent 和若干 subagent。
* **输出 `Y`**:WideSeek-R1,一个 lead agent–subagent 多 agent 系统。lead agent 负责任务分解并把可并行的子任务分派出去(其唯一工具是 `call_subagent`);每个 subagent 独立搜索并综合自己被分配的部分(工具为 `search` 与 `access`),再把结果返回给 lead agent 供下一轮分解或最终作答。
* **核心问题**:近期 LLM 的进步大多是在扩展*深度*——单个 agent 对一个长时程查询做更多轮的顺序推理和工具调用。当任务从"深"转向"宽"时,单个 agent 的上下文会不断累积此前子任务留下的无关信息("上下文污染"),而且被迫串行处理本可并行的独立子任务,无论给多少深度扩展,吞吐量都会受限。
* **范围**:一个通过多 agent 强化学习训练的 4B 参数模型(WideSeek-R1-4B,基于 Qwen3-4B),训练时每个 lead agent 轮次最多调用 10 个并行 subagent,lead agent 最多 10 轮,subagent 最多 20 轮;底层多 agent 框架支持更深的递归,但训练时刻意将层级限制为固定的两层(lead + subagent)。

# Q2 问题的新颖性

宽度扩展本身并不新——CAMEL、AutoGen 等已有的多 agent 框架早已把任务拆分到多个 LLM 实例上,而 best-of-N、self-consistency 等采样式方法也早已在测试时并行消耗算力。本文声称的新意在于:上述两类方法都不是"为宽度扩展而端到端训练"的——CAMEL/AutoGen 式框架手工设计分解与协调工作流而非学习它;best-of-N/self-consistency 是对*同一*任务重复采样,而非把一个更*广*的任务拆分成独立并行的子任务。与此同时,其他多 agent RL 工作(OWL、AgentFlow)训练了层级化 agent,但采用轮流式、一次一个子任务的执行方式,而非真正的并行 subagent 分派;自博弈式多 agent RL(MARSHAL、Absolute Zero)则针对分布式推理而非检索编排。WideSeek-R1 的贡献是用*共享*模型通过多 agent 强化学习(MARL)联合训练 lead agent 与其 subagent,使可扩展的编排(委派什么、如何措辞子任务提示)与并行执行(如何搜索并综合一个子任务)被一起学到,而非一方手工设计、另一方单独训练。

# Q3 科学假设

如果一个 lead agent–subagent 系统通过多 agent 强化学习端到端训练——共享 LLM 实例化为相互隔离上下文的角色,每次 rollout 只用一个组归一化的结果奖励,并配合一种同时考虑 token 级与 agent 级贡献的优势重加权机制——那么该系统应当展现出*宽度扩展*性质:随着并行 subagent 数量增加,广度信息检索任务上的表现应持续提升,而单 agent 的*深度扩展*(更多轮次/token)预计一旦触及上下文和串行执行的限制就会趋于饱和。论文进一步假设,这种宽度扩展、联合训练的 4B 系统能在广度信息检索上匹敌一个大得多(671B)的单 agent 系统,尽管参数量少了约 170 倍。

# Q4 相关工作与关键人物

* **LLM 的扩展维度**。将自身定位为训练时扩展(参数、数据、算力)与单 agent 测试时深度扩展(推理模型和 Kimi K2/Gemini 3 Pro 一类 agentic 模型中的长链思维、多轮工具使用)之外的第三个互补维度,并与 best-of-N、self-consistency 等采样式聚合方法区分开来。
* **搜索 agent**。建立在单 agent RL 搜索训练(Search-R1、ASearcher)之上,既作为概念前身,也作为标准 QA 训练数据来源(ASearcher 的数据以 1:1 比例混入 WideSeek-R1 的训练集);将自身定位于 WideSearch、DeepWideSearch(广度信息检索基准)以及 GAIA、BrowseComp(单一复杂查询的深度基准)之间。
* **多 agent 框架与 agentic RL**。将手工设计工作流的多 agent 框架(CAMEL、AutoGen)与轮流式层级化多 agent 执行(OWL、AgentFlow、MiroFlow)同自身联合训练、并行执行的设计相对照;将自身置于覆盖搜索(Search-R1)、代码(SWE-RL)、电脑操作(UI-TARS-2)的更广泛 agentic RL 文献之中,并指出面向 LLM 的多 agent RL 相对而言仍未被充分探索。

# Q5 核心解法

1. **工具受限的 lead agent**。lead agent 唯一可用的工具是 `call_subagent`;这一限制是刻意为之,以避免让 lead agent 直接检索而带来的上下文污染。每一轮它都会给出一组带清晰委派提示的明确子任务,然后保持空闲,直到所有派出的 subagent 都返回后才进入下一轮(或给出最终答案)。
2. **隔离上下文的并行 subagent**。每个 subagent 运行在自己独立的上下文中,拥有两个工具——`search`(针对查询检索片段/URL)与 `access`(针对查询总结某个具体 URL)——对被分配的子任务进行多轮工具集成推理,与同伴并行执行。subagent 相当于 lead agent 的高层可学习工具;其在过滤和综合证据上的精度,直接决定了 lead agent 最终答案的质量。
3. **多 agent 优势分配**。与其解决精细的跨 agent 信度分配问题,WideSeek-R1 为每次多 agent rollout 只用一个可验证的结果奖励(主要基于最终答案与标准答案的一致性),在同组 GRPO 式 rollout 内做组归一化,并把归一化后的*同一个*优势值赋给该 rollout 中的每个 agent 和每个 token——这一刻意从简的设计是为了避免更复杂信度分配方案带来的 reward hacking。
4. **双层优势重加权**。沿两个方向扩展 GRPO 以适配多 agent、多轮训练:(a) 跨轮次的 token 级重加权(参照 DAPO),使 token 更多的轮次不会被轮次级平均稀释;(b) agent 级重加权,对 rollout 中出现的 agent 做平均,既防止 subagent 数量多的 rollout 主导梯度,更关键的是——消除了 lead agent 通过增派无益 subagent 来"刷"回报的动机,因为 agent 级平均意味着"只有在提升最终奖励时,增加 agent 才有帮助"。
5. **自动化 schema 约束数据管线(2万条任务)**。基于 HybridQA 种子的三阶段管线:(i) *查询生成*提取用户意图,随机设定 10–50 行的目标规模,再合成并精修带明确列定义的 schema 约束查询;(ii) *答案生成*让 Gemini 针对每条查询独立生成两份回答,并给出对齐预测行与标准答案(不受行顺序影响)所需的"唯一列";(iii) *问答对过滤*丢弃两份独立答案在逐单元格比较中一致性低于 0.9 阈值的样本,并丢弃过于简单的结果(行数少于 3),只保留高一致性、足够困难的实例。

# Q6 实验设计

主评测在 WideSearch 基准上进行(200 个任务,英文/中文各 100 个,要求表格化输出),每个任务采样 4 次,报告 item F1、row F1 与成功率(三者均报告 Avg@4,F1 分数还报告 Max@4,成功率还报告 Pass@4)。基线覆盖单 agent(SingleSeek-R1-4B——为公平比较专门训练的同数据单 agent 消融、Qwen3-4B、Search-R1-7B、ASearcher-7B、DeepSeek-R1-671B)与多 agent(WideSeek-R1-4B、多 agent Qwen3-4B、AgentFlow-7B、OWL-8B、MiroFlow-8B——后两者因 OWL 只发布 32B 版本、MiroFlow 仅为框架,而在 Qwen3-8B 上未经额外训练直接实现)。另有一项宽度 vs 深度扩展研究,绘制了性能相对轮次数(深度)与固定轮次下并行 subagent 数(宽度)的曲线,分别针对基础模型和 WideSeek-R1-4B。两项消融进一步拆解框架:(1) 2×2 角色互换,将 WideSeek-R1-4B 或 Qwen3-4B 分别指派给 lead agent 与 subagent 的全部四种组合;(2) 训练数据消融,在样本数相同的条件下比较仅宽数据、仅深数据(ASearcher 数据)与混合数据集。最后在七个标准单跳/多跳 QA 基准(NQ、TriviaQA、PopQA、2WikiMultiHopQA、HotpotQA、Bamboogle、MuSiQue)上通过 LLM-as-judge 的 Avg@4 做泛化检验。

# Q7 数据与代码

论文构建并计划开源一个 2 万条的广度信息检索数据集(带标准表格答案与唯一列标识的 schema 约束查询),基于 HybridQA 种子通过 Gemini 辅助的三阶段管线构建(第 4 节)。训练时将该数据集与 ASearcher 既有的多跳 QA 数据按等比例混合;训练时的 `search`/`access` 工具后端由一个基于 Wiki2018 构建的本地离线知识库承担,以降低成本。所列出的 GitHub 仓库(RLinf/RLinf,检索时 4,838 星)是作者更广泛的开源 RL 基础设施项目,而非专为 WideSeek-R1 发布的仓库;论文并未确认 2 万条数据集或 WideSeek-R1-4B 权重在投稿时已经发布。

# Q8 证据质量

本笔记基于通过 `hf papers read` 获取的 arXiv HTML 全文(引言至结论,以及附录 A 所述局限性、附录 B rollout 形式化描述的开头部分)撰写。摘要与正文的头条数字保持一致(WideSeek-R1-4B 在 WideSearch 上取得 40.0% 的 item F1,与 DeepSeek-R1-671B 的 41.3% 相当,而参数量少了约 170 倍)。论文对若干边界相当坦诚,本笔记予以保留:仅评测了单一模型规模(4B),因为训练基于推理的多 agent 系统计算代价高昂(即便 4B 也需约 3,000 H100 GPU 小时),更大规模的验证尚未开展;其 MARL 信度分配明确是粗粒度的——共享的结果奖励无法区分失败究竟来自 lead agent 编排失误还是 subagent 执行错误;两层层级是出于训练稳定性的选择,而非能力上限——论文指出允许 subagent 递归地再派生自己的 subagent 会破坏 MARL 训练的稳定性,因而被禁用;在论文采用的同步、共置训练设计下,约 90% 的训练步时被长尾 rollout 生成占用。Impact Statement 部分明确指出一项双重用途风险:"自主 agent 群体可能被滥用于大规模自动化数据采集或虚假信息生成"。

# Q9 主要贡献

1. WideSeek-R1,一个通过多 agent 强化学习端到端训练的 lead agent–subagent 框架——在 GRPO 基础上扩展出多 agent 优势分配与双层(token 级与 agent 级)优势重加权——联合学习面向广度信息检索的可扩展编排与并行执行。
2. 一个基于自动化、schema 约束查询生成与双回答一致性过滤管线构建、计划开源的 2 万条广度信息检索数据集,补充了偏向单实体、深度扩展查询的既有多跳 QA 数据集。
3. 实证证据表明,通过 MARL 实现的宽度扩展让一个 4B 多 agent 系统在 WideSearch 上匹敌单 agent DeepSeek-R1-671B,并随并行 subagent 数量增加持续提升表现,而单 agent 深度扩展一旦触及上下文限制便趋于饱和;同时在目标基准和七个标准 QA 基准上均超过更大规模(7–8B)的多 agent 基线。

# Q10 下一步

论文自身指出的局限包括:在目前只测试的单一 4B 配置之外评测更大模型规模(附录 A"Model Size");开发更细粒度、按角色区分的奖励建模,以解决共享结果奖励带来的、无法区分 lead agent 与 subagent 责任的粗粒度信度分配问题;一旦为递归 subagent 派生找到更稳定的训练方案,就放开目前固定的两层层级限制,使系统能够针对意外复杂的子任务自主加深组织结构;以及探索异步或解耦的 rollout/训练范式,以降低目前约 90% 训练时间耗费在长尾 rollout 生成上的问题。

本笔记在论文自身问题之外补充一个开放问题:agent 级优势重加权旨在阻止 lead agent 增派*多余、无益*的 subagent(因为只有提升最终奖励时增加 agent 才有帮助),但论文并未报告,当每轮 subagent 数上限(本文为 10)和静态两层拓扑都是外部强加而非学习得到时,同一机制是否也会把 lead agent 推向*派生过少* subagent 的方向——目前尚不清楚,一个在*学习得到*而非固定 subagent 预算下训练、且未设上限的 lead agent,能否自行收敛到高效的 subagent 数量,还是会重新引发论文在放宽层级深度时发现的同一种 MARL 不稳定性。
