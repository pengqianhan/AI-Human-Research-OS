> 论文：**COLLEAGUE.SKILL: Automated AI Skill Generation via Expert Knowledge Distillation**
> 论文链接：<https://arxiv.org/abs/2605.31264>
> 代码：<https://github.com/titanwings/colleague-skill>
> 机构：上海人工智能实验室（Tianyi Zhou、Dongrui Liu、Leitao Yuan、Jing Shao、Xia Hu）

# Q1 问题定义

* **输入 `X`**：目标人物/角色的轻量画像、来源范围（同事 / 名人公众人物 / 亲密关系三种预设之一），以及异构原始材料（聊天记录、工作文档、邮件、截图、字幕、访谈、用户自述）。
* **输出 `Y`**：一个版本化技能包 `S = (A, M, L)`——生成文件集 `A`（SKILL.md、work.md、persona.md、work_skill.md、persona_skill.md、manifest.json、meta.json）、机器可读元数据 `M`，以及生命周期状态 `L`（版本号、更新时间、修正次数、回滚历史）。
* **核心问题**：关于某个人或某个角色的可操作知识——审查判断、决策经验、沟通风格——通常散落在杂乱的原始材料里而非写成清晰指令，目前没有一套端到端流程能把这些材料蒸馏成可检视、可修正、agent 可用的技能。
* **范围**：这是一个"制品构造"问题，而非行为克隆。系统不宣称能忠实还原一个人，只宣称能产出一个有边界、可编辑的制品，且其来源和限制始终可见。

# Q2 问题的新颖性

技能打包（Agent Skills 标准、Claude Code 技能）、记忆/人格系统、角色扮演 agent 都已是既有方向。本文的新意在于把它们组合成一份统一的制品契约：把"蒸馏一个人的知识与风格"当作软件工程问题来做，明确要求可移植性、可检视性、可修正性、可组合性、可治理性，而不是当作提示词工程或微调问题。同事 / 名人 / 亲密关系三种预设加上公开画廊，把这套想法变成了一个真实部署、外部可观察的系统，而不只是实验室演示。

# Q3 科学假设

如果把人物相关知识拆成两条协同的轨道——能力轨道（实践方法、心智模型、决策经验）与有边界的行为轨道（沟通风格、互动规则、修正历史）——并配上显式元数据、版本管理与修正处理机制，那么产出的制品应当具备可移植、可检视、可回滚、可跨 agent 宿主安装的特性，而不需要开放式的人物模拟。论文**没有**检验生成的技能是否行为忠实于原型人物，也没有检验其对下游任务是否有实际帮助——本文只验证制品流水线与生命周期操作本身是否按设计运转。

# Q4 相关工作与关键人物

* **Agent 技能与可复用能力**：ReAct、Toolformer、Reflexion/Self-Refine、AutoGen、AgentBench，以及 Agent Skills 标准（SKILL.md + 渐进式披露）共同构成了本文所打包的"模块化能力"框架。
* **技能库与技能合成**：Voyager、SkillX、SkillGen、AutoSkill 从执行轨迹中构建或提炼技能库；本文不同之处在于蒸馏的是**人的**原始材料而非 agent 轨迹，并显式拆分能力/行为两条轨道，附带可检视的修正与回滚状态。
* **记忆、个性化、角色扮演**：RAG、LaMP、PersonaAgent、Character-LLM、RoleLLM、SOTOPIA 研究模型对用户历史或角色扮演保真度的适配。本文刻意比这些方向更窄——目标是一个可检视、可复核的制品，而不是无约束的人格模拟器。
* **作者/机构**：Tianyi Zhou、Dongrui Liu、Leitao Yuan、Jing Shao、Xia Hu——上海人工智能实验室。

# Q5 核心解法

一个共享的蒸馏—打包核心，叠加三种领域预设：

1. 采集器/解析器把异构来源（飞书、钉钉、Slack、微信 SQLite 导出、邮件存档、PDF、截图、字幕）标准化为本地知识目录。
2. 分析器分别抽取持久性能力（工作方法、决策经验、心智模型）与有边界的行为（表达风格、互动规则）两条轨道。
3. 写入器将结果渲染为版本化 schema（当前为 schema v3）：SKILL.md（合并版）、work.md/persona.md（可编辑源文档）、work_skill.md/persona_skill.md（可独立调用的子技能）、manifest.json/meta.json。
4. 修正处理器把自然语言反馈（"他不会这么说"）转化为对能力轨道的 Markdown 补丁，或对行为轨道的规范化记录 `{scene, wrong, correct}`；每次更新前都会归档当前版本，因此支持回滚。
5. 同事、名人/公众人物、亲密关系三种预设复用同一套流水线，只是来源边界、同意假设不同；名人预设额外加入六维度公开证据研究流程与质量检查。

关键设计选择是让能力与行为可以**独立调用**：用户可以只取"审查判断"而不带上"沟通风格"，反之亦然。

# Q6 实验设计

论文没有做任务表现或人类被试实验。取而代之的是系统与部署层面的证据：制品 schema 与文件契约、修正/回滚生命周期，以及 2026-05-28 观察到的公开部署计数（仓库星标数、画廊技能/贡献者数、跨技能卡片的累计星标数）。论文明确说明这些数字只是"分发规模"的证据，不是采纳质量或行为忠实度的证据——这一点论文自己讲得很清楚，并未夸大。

# Q7 数据与代码

* 没有使用或发布基准数据集；"语料"就是用户提供的任意原始材料（私有工作文档、公开访谈/字幕，或私人互动记录）。
* 代码与画廊均开源：[github.com/titanwings/colleague-skill](https://github.com/titanwings/colleague-skill)，公开网站 [titanwings.github.io/colleague-skill-site](https://titanwings.github.io/colleague-skill-site/)。
* 截至成文时（2026-05-28）：约 1.85 万 GitHub 星标，画廊列出 215 个技能、55 个元技能、165 位贡献者，报告的（有滞后、量级估计）跨技能卡片累计画廊星标超过 10 万。

# Q8 证据质量

现有证据支撑论文的窄claim（制品流水线确实存在、能运行、且有真实的公开部署），但不支撑更广的"有用"或"忠实"claim。论文没有与任何基线人格/记忆系统对比，没有衡量抽取出的能力是否真的匹配原型人物的判断，也没有研究修正质量、回滚有效性，或亲密关系预设中的滥用/过度依恋风险。论文自己明确把这些列为未解决问题：来源匹配度、任务表现、情感安全、信任校准都留给未来的人类与任务研究。

# Q9 主要贡献

1. 把"人物相关的原始材料到技能蒸馏"形式化为一个制品问题，明确五项属性：可移植、可检视、可组合、可修正、可治理。
2. COLLEAGUE.SKILL 流水线：能力/行为双轨、版本化制品 schema、修正—回滚生命周期。
3. 一种泛化机制（应用预设），通过不同的来源/同意/证据规则，让同一套流水线复用于同事、名人/公众人物、亲密关系三个领域。
4. 一个带公开画廊的开源部署，展示该制品格式可以成为受治理的分发层，而不只是私人提示词集合。

# Q10 下一步

* 开展人类/任务层面的研究：同事技能能否发现与原专家相同的审查问题；纯能力版本是否在不带人格风险的情况下保留实用性；修正是否会带来回归。
* 评估名人/公众人物技能是否真正引用证据而非虚构动机，以及亲密关系技能是否会诱发过度依恋或非自愿模拟风险。
* 在匹配的来源证据下，对比完整版、纯能力版、纯行为版三种制品变体，作为风险—收益评估协议。
* **与本仓库的关联**：能力/行为拆分与修正记录 schema（`{scene, wrong, correct}`）是一个值得对照的具体模式——如果本仓库未来的技能/记忆编写需要类似的修正生命周期，可参考 `human-cognition-cache` 的"先合并再追加"规则做比较。
