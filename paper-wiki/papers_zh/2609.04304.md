# Q1 问题定义

* **输入 `X`**:一个需要实时网络搜索才能回答的自然语言问题——通常是只能通过多条相互制约的间接线索才能锁定的长尾实体或事实,外加一个 MoE 基座 LLM(Qwen3.6-35B-A3B 或 Qwen3.5-397B-A17B,256K token 上下文)。
* **输出 `Y`**:Iris-mini(35B-A3B)与 Iris-pro(397B-A17B),两个单 agent 的 ReAct 搜索 agent(无 sub-agent,无测试时验证),通过交替进行推理与 `SEARCH`/`SCRAPE` 工具调用来对接实时搜索,并以最终答案结束。
* **核心问题**:构建一个真正有能力的搜索 agent,不仅需要强大的骨干模型,还需要有效的、"难但可解"的训练数据——自然产生的网络问题通常太简单(可从参数记忆直接答出,或通过直接搜索一个表层字符串就能解决),而人工撰写难题又难以规模化;另外,推理时的上下文管理(CM,如轨迹摘要、丢弃重启、带记忆重试)可能比参与比较的系统之间的策略差异本身更能左右基准得分,如果只报告开启 CM 的分数,就会把策略本身的能力与推理时的 harness 工程混为一谈。
* **范围**:两种模型规模(35B-A3B "mini",397B-A17B "pro"),分别在开启和关闭 CM 的情况下于四个基准上评测(BrowseComp、BrowseComp-ZH、DeepSearchQA、HLE 纯文本子集),所有比较均固定工具集、上下文长度限制与评判标准。

# Q2 问题的新颖性

搜索 agent 的 RL 训练(Search-R1、ASearcher、R1-Searcher、Search-o1)以及基于超链接/知识图谱构造难题(WebSailor、WebShaper、DeepDive,以及作者团队自己此前的 OpenSeeker/OpenSeeker-v2、REDSearcher、FORT-Searcher)都是已有的成熟方向,本文正是直接建立在这些工作之上。其声称的新意在于把此前工作只部分结合的四个要素放在一起:(a) 完全逆向构造的管线,从真实网络语料的超链接结构出发生成多跳问题,并加入显式的锚点抽象步骤,去除每一个可直接检索的表层字符串,迫使模型依靠推理而非字符串匹配来消歧;(b) 双重标准验证,只有当参考模型闭卷失败、而提供支撑实体图后又能正确作答时才录用该问题,同时约束难度与可解性/答案唯一性;(c) 训练前的两级(轨迹级与轮次级)轨迹过滤,轮次级评分标准*从评判模型自身对样本轨迹的自由式点评中归纳得出*,而非人工撰写;(d) 一种"SFT-RL 攀登"循环,交替进行 RL 探索与对该轮中最难解、最高效样本的监督蒸馏,并明确地、分开地报告开启/关闭 CM 的结果——这种方法学上的透明度是多数既有搜索 agent 论文所不具备的。

# Q3 科学假设

如果训练数据是从真实网络图的超链接/实体结构逆向构造而来——通过锚点抽象阻断字符串匹配式的走捷径,并通过双重标准验证只录用那些同时满足困难(闭卷失败)与可解(开卷、答案唯一)的问题——并且如果由此产生的教师轨迹在训练前经过轨迹级(正确性、非退化性、最小搜索深度)与轮次级(一套由数据本身归纳出的评分标准,遮蔽比例不超过 10%)两级过滤,那么交替进行监督微调与针对实时搜索的强化学习("SFT-RL 攀登",把每一轮中最难解、最高效的 RL rollout 蒸馏回下一轮监督训练)应当能训练出紧凑的 ReAct 搜索 agent,其*内在*(无上下文管理)能力在同等规模的开源模型中达到最先进水平,而开启上下文管理后进一步、且是*额外*叠加地提升表现,而非替代内在能力本身。

# Q4 相关工作与关键人物

* **搜索 agent RL 谱系**。建立在 Search-R1 与 ASearcher(针对实时/静态搜索的 RL)之上,并将自身置于 R1-Searcher、Search-o1 等工具集成推理 agent 之列。
* **基于超链接/图谱的难题构造**。在 WebSailor、WebShaper、DeepDive 利用超链接或知识图谱遍历加实体遮蔽的基础上扩展,并被定位为作者团队自身此前工作(OpenSeeker、OpenSeeker-v2、REDSearcher、FORT-Searcher)在构造抗走捷径搜索任务方面的最新延续。
* **对比的上下文管理策略**。discard-all(源自 DeepSeek-V3.2,被 Iris 采纳为自己的默认策略)与 retry(源自 MiroThinker,被视为推理成本较高的性能上限而非默认配置来探索)。
* **使用的基准**。BrowseComp 及其中文对应版本 BrowseComp-ZH、DeepSearchQA,以及 Humanity's Last Exam(HLE)的纯文本子集。
* **主结果表中比较的前沿与同类系统**。XYZ-Aquila、Nex-N2、Apodex-1.0(mini 与完整版,外加单独的重算力"H"档位)、MiroThinker-1.7/H1,以及在前沿/重算力参考区间中的 Kimi-K2.6、GLM-5.2、DeepSeek-V4-Pro(预览版)、Claude Fable 5、GPT-5.6 Sol、Kimi-K3、Qwen3.8-Max。

# Q5 核心解法

1. **网络图任务合成**。将语料建模为有向超链接图;通过锚定答案模式的采样策略选取种子页面(固定目标答案实体),再沿其出链扩展为一个局部子图。由于阅读器服务会剥离行内锚点,论文通过融合语料的结构化语义镜像(RDF 三元组)与渲染后的页面标记,来恢复真实的出链集合以最大化链接召回。
2. **实体图提炼、多跳问题生成与锚点抽象**。将原始页面提炼为一个紧凑、连通、保留跨页关系结构的实体图;生成问题的同时给出一条至少包含 N 个耦合关系的推理路径(强制真正的多跳依赖);随后把每一个非答案实体改写为不指名的描述性指代,使问题无法通过搜索一个表层字符串解决,而必须依靠推理消歧。
3. **双重标准验证**。一对(问题,答案)只有在参考模型闭卷(不使用工具)失败、且在提供实体图作为上下文后能正确作答时才被采纳——在生成任何轨迹之前就同时确保难度与可解性/答案唯一性。
4. **训练前的两级轨迹过滤**。由强教师模型在 ReAct 范式下(交替推理、`SEARCH`/`SCRAPE` 调用、把即时生成的文档摘要作为观测)求解每个被采纳的问题。粗筛只保留正确(经评判模型对照参考答案验证)、非退化(基于滑动窗口压缩率的循环检测器,加上针对重复与相同参数工具调用的辅助检测器)且足够深(达到最小工具调用轮次)的轨迹,再去重。细筛随后用一个 LLM 评判逐轮标注 KEEP/MASK,其评分标准*从评判模型对样本轨迹的自由式点评中归纳得出*,而非人工撰写,每条轨迹最多遮蔽 10% 的轮次,使被遮蔽但保留的轮次仍能提供上下文而不参与训练损失。
5. **针对实时搜索的 RL,配合内部奖励与摘要模型**。使用请求级的部分 rollout 来优化组相对策略梯度——长尾会话在请求级被中断,并在下一步从已提交的前缀处恢复(rollout 组织为一片消息状态构成的森林,通过截断重要性采样修正跨权重版本拼接产生的偏差),而非任务级地整体丢弃。一个共置的内部 Qwen3.5-397B-A17B 模型同时充当二元生成式奖励模型(只对提取出的最终答案与参考答案打分,无额外的格式项)与观测摘要器(压缩检索到的页面——这是 rollout 中唯一的上下文压缩机制),从而在训练循环中移除对外部 API 的依赖。
6. **SFT-RL 攀登**。SFT 与 RL 以"攀登"轮次交替进行。每一轮攀登针对通过率 0 < R̄(q) ≤ 1/2(可解但尚不可靠)的查询,选取满足最小工具调用轮次的最短成功 rollout,并将其蒸馏回下一轮 SFT,形成一个随策略提升而自动加难的自定进度课程。
7. **将上下文管理(CM)作为显式、单独报告的评测维度**。每个基准都分别报告开启与关闭 CM 的结果,固定工具集、上下文长度限制与评判标准;discard-all(达到上下文阈值时清空历史并重启)是默认报告配置,而 retry(MiroThinker 式的把失败尝试总结后带入下一次尝试)作为推理成本较高的性能上限单独探讨,而非作为headline 配置采用。

# Q6 实验设计

在四个基准上以 pass@1(单次 rollout)评测——BrowseComp、BrowseComp-ZH(准确率)、DeepSearchQA(F1,证据完整性打分)以及 HLE 纯文本子集(准确率)——均使用各基准自身的官方 LLM 评判提示打分。主结果表(开启 CM、discard-all)将 Iris-mini/Iris-pro 与 30–35B 及约 400B 的开源同类系统,外加一个前沿/重算力参考区间放在一起比较,论文明确说明其中部分结果直接引用官方公布分数而非自己重跑得到。另一张 CM 分析表通过比较 w/o-CM、retry、discard-all、discard-all+retry 四种配置,并对照三个明确报告了无 CM 基线的既有系统(OpenSeeker-v2、REDSearcher、FORT-Searcher),单独衡量上下文管理的效果,并明确将某个对比系统(XYZ-Aquila)使用的额外测试时验证/重新作答策略排除在纯 CM 比较之外。一个基准泄露防护机制在三个环节阻断对承载基准问答的 Hugging Face 数据集/Space 页面的访问:从搜索结果中移除、拒绝抓取,以及即便模型凭记忆给出该 URL 也会被事后 URL 守卫拦截。

# Q7 数据与代码

没有引入新的基准;评测复用了 BrowseComp、BrowseComp-ZH、DeepSearchQA 与 HLE。训练语料完全由论文自己的网络图逆向构造管线生成,并结合了未具体说明的"内部与开源问题集"。模型分别从 Qwen3.6-35B-A3B 与 Qwen3.5-397B-A17B(均为 MoE,256K token 上下文)初始化;SFT 训练两个 epoch,全局 batch size 为 64,最大序列长度 262,144 token;RL 使用开源的 Relax 训练引擎。论文写明"我们计划发布模型权重及数据构建、训练和评测的完整方案"——截至本笔记撰写时尚未发布。所链接的 GitHub 仓库(AllSpark-Research/Iris)检索时有 37 个 star。

# Q8 证据质量

本笔记基于 arXiv PDF 全文(全部 12 页,含案例研究附录)撰写,使用 `pypdf` 提取,因为这篇非常新(2026 年 9 月 3 日提交、9 月 7 日处理)的论文在检索时其 arXiv HTML 镜像只返回了一个 logo 图片的占位页面——`hf papers read` 同样未返回可用的正文内容。摘要、图 1 与表 1 之间的头条数字保持一致(Iris-mini 在 BrowseComp/BrowseComp-ZH/DeepSearchQA/HLE 上为 82.2/84.8/86.9/52.3,Iris-pro 为 88.6/85.1/92.9/56.4)。论文对若干证据边界相当坦诚,本笔记予以保留而非淡化:附录 A 报告了一个具体案例(BrowseComp-ZH 第 85 题),agent 给出的答案("Bolton")似乎有引用的原始材料直接支撑,而官方标准答案("Lannister")却没有,论文明确将其定性为"基准标注与底层素材之间可能存在的不一致",而非隐瞒的失分;论文明确说明没有采用某对比系统(XYZ-Aquila)在 BrowseComp-ZH 上使用的"reverify/reanswer"测试时验证策略,自己报告的数字始终来自单次 ReAct rollout,不叠加额外的验证机制;论文也明确说明,尽管 discard-all+retry 在多数设置下是单项最高分配置,却并未将其作为默认配置报告,理由是每次重试都有额外的推理成本,并呼应了 DeepSeek-V3.2 关于在比较 CM 策略时必须核算实际计算成本的观点。所有报告结果均为单模型、pass@1 的单次点估计,没有置信区间或多次种子的方差;表 1、表 2 中若干对比系统的数字(MiroThinker、FORT-Searcher、Nex-N2、Apodex-1.0、XYZ-Aquila、Agents-A1)是引用自其各自论文/报告而非由本文作者重跑得到,标注为 "r" 的行明确说明是由第三方(XYZ-Aquila 团队)复现,而非原作者自报,本笔记对此类数字均保留其原始出处,未做独立复核。

# Q9 主要贡献

1. 一个自动化、可验证的数据构建管线,从真实网络语料的超链接/实体结构逆向构造难度较高的多跳搜索问题,通过锚点抽象阻断字符串匹配式走捷径,并通过双重标准(闭卷失败、开卷可解)控制录用。
2. 一套结合 SFT(轨迹级与数据归纳的轮次级过滤)与实时网络 RL(共置的内部奖励模型与观测摘要器、带前缀复用的请求级部分 rollout)的训练方案,以"SFT-RL 攀登"交替进行,使每一轮 RL 中最难解、最高效的 rollout 作为自定进度课程蒸馏回下一轮监督训练。
3. Iris-mini(35B-A3B)与 Iris-pro(397B-A17B),据论文报告在各自参数规模区间内于 BrowseComp、BrowseComp-ZH、DeepSearchQA 与 HLE 上取得最强的开源搜索 agent 结果,并采用了明确的开启/关闭上下文管理评测协议,把策略本身的内在能力与推理时 harness 带来的增益区分开来——即便是 Iris-pro 关闭 CM 时的成绩,也已能与若干借助 CM 辅助的万亿参数前沿系统相竞争。

# Q10 下一步

论文自身指出的下一步方向是:其合成的搜索数据以及经过搜索专项训练的模型——作为同策略蒸馏的教师模型——都正向迁移到了未被明确针对训练的领域,包括通用工具使用(BFCL、τ-bench)和"Cowork"任务(OfficeQA、APEX);作者据此推断,搜索或许是一种可迁移的*原子能力*,而非狭窄的垂直专长,并表示打算继续探索在整个训练过程中普遍使用搜索数据与搜索衍生的教师模型,而非将其局限于单独的专项训练阶段。论文也明确将缩小与最强前沿/重算力系统(如 Apodex-1.0-H、Kimi-K3、Claude Fable 5、GPT-5.6 Sol 在 BrowseComp 上的表现)之间的差距,列为"未来工作的重要方向"。

本笔记在论文自身问题之外补充一个开放问题:论文用于*训练*数据的双重标准验证(第 2.3 节,基于参考模型的闭卷/开卷判断)与在*评测*基准(附录 A 中的 BrowseComp-ZH 第 85 题)中暴露出标准答案歧义的判断逻辑,在结构上是完全相同的——论文只报告了对其不受自己控制的下游评测基准做了这类失效模式的核查,却并未说明是否也对自己逆向构造的训练语料做过类似的核查,这就留下了一个未解的问题:类似的答案唯一性歧义是否也未被察觉地存在于训练数据本身之中。
