# Q1 问题定义

* **输入（X）：** 一个个人智能体（骨干 LLM 运行在 OpenClaw、Claude Code 或 Codex 等运行框架中），在数天内陪伴用户工作，可以访问用户的记录（消息、文档、日历）和工具，有一个带用户活跃时段与睡眠时段的模拟时钟，以及有限的共享资源（GPU 时间、token 配额）。
* **输出（Y）：** 智能体随时间展开的主动行为：追求哪些用户没有提出的需求，什么时候计算、什么时候呈现结果，以及在哪个干预深度（intervention depth）上行动（准备、提出建议供审阅、或不经确认直接执行），也包括选择什么都不做（NOOP）。
* **核心问题：** 主动帮忙不一定有用。正确的工作也可能无关、时机不对、与用户自己的工作争抢算力，或者超出用户允许智能体做的范围，而反复的误判会侵蚀信任。论文要回答：主动式智能体应遵循哪些原则、哪些设计选择和系统组件能实现这些原则，以及如何评估主动行为在多次交互中的后果，而不是只看对一个静态请求的回答。

# Q2 问题新颖性

部分新颖。混合主动（mixed-initiative）交互（Horvitz，1999）与个人助理研究（Myers 与 Yorke-Smith，2007）早已在权衡主动行动的收益与打断成本、不确定性；信任感知对话研究（Kraus 等）把用户信任与任务奖励分开建模；睡眠时间计算（Lin 等，2025）与空闲时间准备（ProAct）利用空闲算力为预期需求做准备。近期基准（ProactiveBench、ContextAgentBench、ProAgentBench、PROBE、PARE-Bench、KnowU-Bench、ProPerSim、VibeLifeBench）测试需求预测、时机或任务成功。新的部分在于：把这些整合为面向 LLM 智能体、需要联合评估的三个目标（表 2 认为此前没有基准把时间分配操作化，也很少单独建模信任），并构建一个动态测试平台，让早先的行动改变后续的任务、资源以及模拟用户的信任。

# Q3 科学假设

1. **三个目标彼此分离。** 如果分别为任务能力（TC）、时间分配（TA）与信任（TR）打分，TC 的提升不会自动带来 TA 或干预深度一致率（TR-D）的提升（图 6c）。
2. **当前智能体不会推迟。** 如果一个情境中有两个相互竞争、只有一个需要立即处理的任务，智能体选中紧急任务的频率会远高于明确推迟另一个任务的频率（表 9）。
3. **LLM 评审把信任和能力混为一谈。** 如果让 LLM 评审依据交互历史给信任打分，其评分（TR-J）会更多地跟随 TC，而不是干预深度是否一致，这与人的判断不同（第 5.2 与 5.3 节）。
4. **人看重时机与一致，而不只是正确。** 如果让人比较智能体，他们会拒绝与手头工作冲突的正确帮助，接受安排在睡眠时间、但不完美的帮助，并且在一次不一致的干预之后信任明显下降，即使结果是正确的（图 7）。

# Q4 相关工作与关键人物

* **理论基础。** 混合主动界面（Horvitz，1999a）与为预期需求进行计算（Horvitz，1999b）；Madsen 与 Gregor（2000）以及 McAllister（1995）的信任构念；信任感知对话与社会感知强化学习（Kraus 等，2021、2023）；界面主动性连续谱（Isbell 与 Pierce，2005）；睡眠时间计算（Lin 等，2025，Letta）。
* **基准。** ProactiveBench 与 ContextAgentBench（需求预测）、ProAgentBench（时机与内容分开评测）、PROBE（在记录中发现并修复问题）、PARE-Bench、ProactBench、KnowU-Bench、ProPerSim、π-Bench、VibeLifeBench 与 ProactiveMobile；Agent.xpu 调度给定的 LLM 工作负载，但不预测需求。
* **智能体框架。** 作为本地个人智能体运行环境的 OpenClaw 与 OpenJarvis；关于干预决策与授权的框架（Tang 等，2026a），以及面向写作者的主动式伙伴（Zhang 等，2026a）。
* **关键人物。** 作者来自 KAIST（Jio Oh、Seunghyun Do、Steven Euijong Whang）与明尼苏达大学（Young-Jun Lee、Dongyeop Kang）；Whang 与 Kang 在作者行中标有星号。相关方包括 Eric Horvitz 的混合主动研究脉络、Kraus 等信任感知对话的作者、Letta 睡眠时间计算的作者，以及上述主动式基准的维护者。

# Q5 关键解法思想

* **3T 目标。** 任务能力（Task Capability）：预见相关需求并把工作做对。时间分配（Temporal Allocation）：根据资源可用性和结果需要的时间，把算力分配到*交互时间*与*睡眠时间*，同时决定何时计算与何时呈现。信任（Trust）：维持用户的信心与恰当依赖，通过*干预深度*（用户允许智能体走多远）这一行为代理来估计。论文把联合目标写成三项分数的加权和，但从未设定或优化这些权重。
* **设计空间。** 五个维度：任务范围（任务内或任务外）、预见时域（立即、本次交互内、交互之外）、激活触发（用户、事件或智能体自身）、处理时机（交互时间或睡眠时间），以及干预深度（准备、建议、执行）。
* **系统实现。** 情境建模（situation modeling）构建用户（目标、注意力、偏好、信任）与环境（任务进展、截止时间、资源）的表示，并区分观测到的事实与推断的状态；然后骨干模型与运行框架选择行动，包括推迟工作、分配算力、呈现或应用结果，或 NOOP。
* **Proactivity-Gym。** 十个人工编写的情境，每个持续 7-10 个模拟日（科研、出行、生活、饮食、职业、商业、教育、金融、购物、健康），每个情境 10-19 个任务，共 124 个，包含潜在需求、条件分支、NOOP 情形，以及每个情境一个任务竞争的决策窗口。每个情境有三种用户画像（Reviewer、Planner、Operator），它们对每个任务希望的干预深度不同。用户模拟器是 Qwen 3.8-27B，但批准、拒绝或推迟由一个确定性状态机根据请求的行动、时间、画像、历史和信任状态决定，因此生成的回复不能额外授予权限。

# Q6 实验设计

* **配置。** 九个模型（GPT 5.6 Luna 与 Sol、Claude Sonnet 5 与 Opus 5、Qwen 3.5 2B/9B/27B、Gemma 4 12B/31B）与 OpenClaw、Claude Code、Codex 组合，共 23 种（开源模型三个框架都测，GPT 只测 Codex 与 OpenClaw，Claude 只测 Claude Code 与 OpenClaw）。主实验关闭推理。每种配置运行 10 个情境 × 3 个画像 × 3 次重复 = 90 次（总计 2,070 条轨迹）。
* **指标。** TC（0-100）：基于规则的证据、输出、约束检查，加上 LLM 评审的语义（正确性、有据性）与完成度（完整性、产物质量），按任务加权。TA（%）：只有在决策窗口内既立即处理紧急任务、又明确推迟另一个任务时，该次运行才得 1 分。TR-D（%）：所选深度与画像期望深度一致的活跃任务比例。TR-J（1-5）：评审在每个任务最后一轮对五个信任构念的打分。评审为 Qwen 3.8-27B 与 Gemini 3.8-Flash，取平均，并核对所引用的原文确实出现在轨迹中。
* **附加分析。** 评审一致性（表 4-6）、GPT 5.6 Sol 在 Codex 上的推理强度（low 到 xhigh）、情境与画像差异，以及各分项细分（表 8-10）。
* **人类研究。** 30 名参与者（8 名本科生、16 名研究生、6 名职场人士，都是频繁使用 LLM 的人）阅读 14 个情境短文，大多改编自测试平台：四份为期一周的信任日志（在第 2、4、7 天打分）、四组 TR 成对比较、三组 TA 与三组 TC 比较，置信区间用 20,000 次自助法重抽样。
* **未纳入设计。** 没有让人去评同一批被 LLM 评审打分的测试平台轨迹；没有真实的算力预算（资源约束是脚本设定的）；TA 每个情境只覆盖一个决策窗口。

# Q8 证据质量

* **支撑充分的部分。**
  * 任务能力与其他目标之间的差距很一致：Claude Opus 5 平均 TC 为 65.1，但 TA 只有 51.7%、TR-D 只有 52.4%；其他所有模型的 TA 都低于 20%，TR-D 在 39% 到 51% 之间。智能体有 44.32% 的情况选中了紧急任务，但只有 10.8% 的情况明确推迟了竞争任务。
  * 干预不足很常见：当画像期望执行时，77.21% 的情况以没有有效执行尝试告终（Claude Opus 5 为 45.96%）。
  * 运行框架的影响是真实的，而且随模型而异：把开源模型从 Claude Code 换到 OpenClaw，TC 变化从 -11.1（Gemma 4 12B）到 +0.5（Qwen 3.5 27B）；对 Claude Opus 5，同样的切换使 TA 提高 21.1 个点，TR-D 降低 3.8。
  * 两个评审对配置的排名几乎相同（汇总后 TC 的 ρ = .999），所以排名不取决于评审选择，尽管绝对分数会变（Gemini 给出的 TC 分项高约 .17）。
  * 人类研究的效应很大：92.2% 的比较中偏好内容正确的一方；内容相同时，88.3% 偏好干预深度一致的智能体；对与手头工作冲突的正确帮助接受率为 26.7%，对安排在睡眠时间、需要修正的帮助接受率为 97.8%（附录 G.5 报告配对提升为 67.7 个点，95% 置信区间 52.2-82.2）；从"一致"转为"不一致"后信任下降 1.86 分，反向转变只回升 1.27 分；在"一致-不一致-一致"的日志中，信任只恢复到 3.43，而初始为 4.43。
* **比标题结论更弱或更窄的部分。**
  * "LLM 评审忽视了不一致"这一结论是间接的。它的依据是 TR-J 与 TC 的相关（r = 0.70）高于与 TR-D 的相关（r = 0.23），以及 TR-D 低的智能体却得到很高的 TR-J；而作对比的人评的是*另外*手写的情境短文。没有任何实验让人和 LLM 评审给同一批轨迹打分。
  * TA 很粗：每次运行只有一个二元决策，每个情境只有一个窗口，因此每种配置的 TA 只反映十个冲突。它还要求*明确*推迟，而两个评审在精确的 NOW/LATER 标签上的一致性只有 κ = .438，所以几个百分点的 TA 差异没有意义。
  * 资源约束是脚本设定而非真实的；TA 衡量的是口头上的优先排序，而不是实际的算力使用。
  * 模拟用户的信任与批准来自作者设计的确定性状态机，因此 TR-D 衡量的是与作者画像规则的一致程度。
  * 人类研究用的是情境短文，由 30 名频繁使用 LLM 的人阅读（报酬 10,000 韩元；评论由韩语翻译），而不是真正在多天里使用主动式智能体的人；真实使用中的偏好可能不同。
  * 运行框架的比较部分存在混杂，因为 GPT 与 Claude 模型各自只在三个框架中的两个上运行。
  * 加权的 3T 目标只是写了出来，并没有用于给智能体排名或设定权衡。

# Q9 贡献

* 主动性的定义，以及三个需要同时满足的目标（任务能力、时间分配、信任），并以干预深度作为信任的可观测代理。
* 一个五维设计空间，以及构建主动式智能体所需的"情境建模 + 系统建模"层。
* Proactivity-Gym：多天、有状态、以画像为条件、带行动依赖分支的情境，三个目标分别打分，并做了评审一致性分析。
* 一项 23 种配置的评测，显示在推迟与深度一致方面存在明显缺陷；以及一项 30 人研究，显示时机与一致性在正确性之外独立地影响接受度与信任。

# Q10 下一步

* **同一轨迹的人工评分。** 让人与 LLM 评审一起给一部分测试平台轨迹打分，直接检验评审是否低估了深度不一致。
* **更丰富的 TA。** 按作者的提议加入可变的任务时长、真实或模拟的算力预算、抢占，以及每个情境多个决策窗口，使 TA 的分辨率高于十个二元决策。
* **为 3T 训练。** 把测试平台用作强化学习或偏好训练环境，为推迟与深度一致分别设置奖励，并检验加权 3T 目标是否像公式 1 所说的那样形成权衡。
* **可学习的信任状态。** 用信任随交互本身演化的模拟用户替代脚本化的批准状态机，并用人类轨迹验证。
* **与本仓库的契合（读者笔记）。** 本仓库已经在运行无人值守的定时智能体（例如每晚的论文阅读任务），并允许智能体在授权范围内继续本地工作而无需确认；3T 框架与干预深度层级提供了一套词汇，用来决定哪些无人值守的工作应该准备、建议还是执行；而人类研究中"一次越界失去的信任多于一次一致行动换回的信任"这一结果，说明应当把这些边界写清楚。
