# Q1 问题定义

* **输入（X）：** 目标领域的多步智能体轨迹池 D，每条轨迹是带回合级成功标签的动作序列（WebArena 浏览器动作、ScienceWorld 与 WebShop 文本命令）；一个待微调的基础策略；在三种设定中的两种里还有带验证器的环境。
* **输出（Y）：** 一棵可复用经验树（reusable eXperience tree，X-Tree）——叶子是规范化动作、内部节点是反复出现且与成功相伴的子技能组合（带深度 d_v）的确定性层级；以及一个通过三种训练整合方式之一把该结构吸收进权重的策略。
* **核心问题：** SFT 和 RLVR 把轨迹当作平铺的 token 流消费，对每个 token 一视同仁，于是跨任务反复出现的子程序（浏览并选择、拿起并移动）从未被当作整体记功，每条稀缺轨迹能教的少于它所包含的。确实利用了这种结构的驾驭层把它保存为上下文中由 LLM 撰写的技能——要花 LLM 调用、无法从数据复现、也永远进不了权重。

# Q2 问题新颖性

各个部件都有长久历史：分层 RL 中的 option 发现与轨迹切分（Sutton、Konidaris、CompILE）、压缩即抽象（Sequitur、DreamCoder、LILO），以及把 BPE 用于量化后的连续控制动作（PRISE、Subwords-as-Skills）。LLM 智能体方面的工作大多用另一个 LLM 抽象经验（Agent Workflow Memory、Voyager、SkillWeaver、WALT）并把它留在上下文里。新颖之处在于把这些组合用于 LLM 智能体：由规范化器给出的带类型动作字母表、以成功和长度而非原始重现次数为权重的合并准则，以及把挖出的词汇不是当作固定宏动作空间、而是作为先验分别以数据、奖励、上下文三种形式喂入训练。问题重要，因为经过验证的智能体轨迹制作昂贵，从固定轨迹池里榨取更多是数据效率的直接杠杆。

# Q3 科学假设

如果从轨迹池中确定性地挖出可复用、与成功相伴的动作组合，并用它们来（a）定义 RL 训练实例并给予随组合深度增长的完成奖励，（b）为已执行的组合添加只在验证器无法区分 rollout 组时才生效的奖励加成，或（c）充当同权重教师的特权上下文，那么得到的策略会在相同数据和预算下胜过标准配方，且增益取决于挖出的结构本身（而非切块、随机树或额外算力）。

* **多轮智能体训练：** Go-Browse（WebArena 轨迹来源）、WebRL、WebAgent-R1、GiGPO（verl-agent）、RLVMR（ScienceWorld 训练代码与泛化划分），以及在线策略自蒸馏（Self-distilled reasoner、Self-distillation enables continual learning、Self-distilled agentic RL）；参见 [On-policy distillation](../concepts/on-policy-distillation.md) 与 [GRPO](../concepts/grpo.md)。

# Q5 核心解决思路

* **规范化。** 每个原始动作（不含思考）变为 verb<role>：verb 来自函数或命令，role 来自可访问性树角色（WebArena）、DOM 元素（MiniWoB++）或九类对象词典（ScienceWorld）；被剥离的值保留在槽位中，因此映射确定、完备且无信息损失。
* **X-Score 合并。** 对相邻符号 u、v：X(u, v) = f_uv · (ℓ_u + ℓ_v)^{p_ℓ} · (succ(uv) + ε)^{p_s}，其中 f_uv 为重现次数、ℓ 为展开长度、succ 为成功占比；递归合并得分最高的一对，受压缩约束 f_uv − 1 > η(ℓ_u + ℓ_v) 和技能上限限制。节点深度比较深的子节点多一。把树应用到一条轨迹上得到由最大技能构成的平铺。
* **离线 RL（无环境）。** 黄金轨迹中某位置的每个节点是一个 GRPO 实例：策略看到黄金前缀，输出至多 ℓ_v 个动作，只在每个动作复现黄金动作时继续并追加记录的观察。奖励 r = (1 − α)·(匹配步骤比例) + α·(1 + γ d_v)·[全部步骤匹配]，α = 0.3，γ = 0.5。
* **在线 RLVR（自适应技能加成）。** r_i = R_out(τ_i) + λ_g Σ_{v ∈ matched(τ_i)} b_v，其中 λ_g = λ_0 · clip(1 − w_g / w_ref, 0, 1)，w_g 为该组经验证器判定的成功比例。无 rollout 成功时加成全额生效，组成功率达到 w_ref 时归零。节点价值 b_v 在 ScienceWorld 上为 1 + 0.5 d_v（嵌套匹配只记一次），在 WebShop 上为 s_v k_v / T（语料成功率乘以与目标相关的步数再除以回合长度）。
* **OPSD（特权上下文）。** 同一权重作为教师，前置检索到的 X-Tree 渲染（每节点一行，含成功率与出现次数）；逐 token 蒸馏项经 σ(β δ_t) 门控，只在上下文提高该 token 概率处把学生拉向教师，系数 c = 0.01。

# Q6 实验设计

* **WebArena 离线 RL：** 从 7,974 条 Go-Browse 轨迹挖出 256 个技能；Qwen2.5-7B-Instruct 在一半轨迹上 SFT，再在另一半的节点上做 GRPO（verl，805 步，每步 6 个节点，n = 2）；在 694 个确定性任务上评测，30 步上限，使用归一化成功率（官方评测器返回 1，或精确匹配任务的黄金字符串逐字出现）。基线：2 个和 4 个 epoch 的 Go-Browse SFT-Full（算力匹配）、仅结果奖励的离线 RL、随机片段、节点平铺混合、深度课程、随机树。迁移到 Qwen2.5-14B 与 GLM-4-9B。
* **在线 RLVR：** ScienceWorld（从 1,673 条 AgentTraj-L 轨迹挖出 80 个技能；G0 已见任务、G1 未见变体、G2 未见任务，19 种训练类型、10 种留出类型）与 WebShop（从 1,824 条轨迹挖出 48 个技能；512 个留出回合，成功率与分级得分）。从 200 / 500 条轨迹在 1.5B / 3B / 7B 上 SFT 热启动，再做带或不带加成的 GRPO（n = 8）；λ_0 = 0.75，w_ref = 0.4 / 0.85。分析：rollout 数 n ∈ {2, 4, 8, 16}；只从 SFT 数据挖掘的资源匹配实验；挖掘语料从 50 到 1,824 条轨迹；随机片段与随机树；移除留出任务类型后重新挖掘。
* **OPSD：** 同样的热启动与评测；只改变教师的技能库（ScienceWorld 上 gpt-oss-120b 撰写、WebShop 上 GPT-o3 撰写，或 X-Tree 渲染）；空库和打乱词序的 X-Tree 消融（WebShop，3B）。
* **另外：** 在 MiniWoB++ 上把 X-Tree 作为上下文建议，对比 AWM、SkillWeaver、WALT、WebXSkill（附录 C）；在 ScienceWorld 上以每行一个 X-Tree 节点做 SFT（附录 D）。
* **报告：** 三个随机种子的均值；附录 H 给出标准差与配对 t 统计量。

# Q7 数据集与代码

无新基准；轨迹池来自 Go-Browse（WebArena）、AgentGym 的 AgentTraj-L（ScienceWorld）和 Song 等（WebShop）。代码在 github.com/sitaocheng/X-Tree 并有项目页；可复现性声明称规范化器、挖掘器、训练配置与评测驾驭层"将随论文发布"。附录 A 列出挖掘超参数（η = 0.3-0.5，技能上限 256 / 80 / 60，最小配对频次 4-5，ScienceWorld 最小技能成功率 0.9）和完整的规范化模板。

# Q8 证据质量

* **有支撑：**
  * *离线 RL 头条结果。* WebArena 成功率：完整配方 22.9，对比 Go-Browse SFT-Full 18.4、多加两个 SFT epoch 18.8（算力匹配）、二值结果奖励 18.2、随机片段 19.5、整条轨迹 19.9、随机树 17.9（低于仅 SFT）。平铺混合（20.7）与深度课程（21.2）表明完成奖励在数据单元之外还有贡献。增益集中在流程密集的站点（admin +6.4、gitlab +5.2、shopping +4.9），在 reddit、map、wiki 上缩小。
  * *离线配方的迁移。* Qwen2.5-14B 24.1 → 25.7；GLM-4-9B 14.9 → 16.9。
  * *在线加成。* 在 rollout 数扫描的 12 个格子中 11 个领先仅结果 GRPO，n 小时差距最大（n = 4：24.2 / 23.9 / 12.1 → 28.0 / 27.5 / 16.5，G0 / G1 / G2），n = 16 时领先收窄，符合设计的淡出。WebShop 成功率最多提升 3.6，分级得分最多提升 4.6，随规模增长。
  * *不是额外挖掘数据的功劳。* 只从 SFT 数据挖掘的资源匹配 WebShop 实验仍有增益（三种热启动规模下 +1.1 / +3.2 / +1.0）；100 条轨迹的 X-Tree（11 个技能）已胜过仅结果（75.2 对 73.8）；移除留出任务类型后重挖的 ScienceWorld 树仍在 G2 上领先 +2.0。
  * *OPSD。* 渲染的 X-Tree 在每个规模上匹配或胜过 LLM 撰写的库（ScienceWorld 最多 +3.7 成功率，WebShop 最多 +1.7），零 LLM 调用；7B 下 OPSD 比仅结果 RLVR 高 +5.8 成功率（ScienceWorld）和 +4.4 分级得分（WebShop）。空特权上下文停留在仅结果水平（74.2 对 74.0），因此增益不是蒸馏机制本身带来的。
  * *附带结果。* 作为 MiniWoB++ 上的上下文建议，X-Tree 在三个骨干上领先四个 LLM 撰写的库（49.8 / 65.1 / 72.6 对无技能 44.9 / 60.4 / 68.1）；每行一个节点的 SFT 把每个监督动作的 token 减少 4.0 倍（1,766 → 446），同时增加 +4.9 / +2.4 / +9.1 成功率。
* **较弱或有边界：**
  * *差距相对离散度。* 多数在线增益为 1-5 个点，而报告的标准差约 2.5（如 1.5B 仅结果 G0 为 38.6 ± 2.5）；论文在附录 H 给出配对 t 统计量，本笔记未完整阅读（读者注）。
  * *结构消融在留出任务上结论混合。* ScienceWorld G2 上随机树（26.7）高于 X-Tree（25.6），G1 上随机片段收回了 X-Tree +3.3 中的 +2.2；作者承认三种库在留出划分上相当，并把归因建立在 G0 和 G1 上。
  * *WebArena 评测协议。* 主成功率是归一化指标，也给输出中出现黄金字符串的精确匹配任务计分；官方评测器数字在表 17，本笔记未读（读者注）。所有方法共用该指标。
  * *打乱词序的 X-Tree 保留了大部分 OPSD 增益。* WebShop 3B 上打乱渲染词序只下降 0.6（76.5 对 77.1），因此特权上下文的效果部分来自词汇而非挖出的链（读者注）。
  * *规模与模型。* 在线设定用 1.5B-7B 的 Qwen2.5，离线只有一次 14B 和 GLM-4-9B 的迁移检查；规范化器按环境手写，把 X-Tree 用到新动作空间需要新模板。
  * *三种整合从未合并，*且树只从固定池挖一次而非随改进中的策略重挖；两者都是论文陈述的局限。

# Q9 贡献

* 一个确定性、无 LLM 的挖掘器，把轨迹池变成可审计的可复用技能层级，其合并准则（X-Score）把验证器奖励的组合与高频但易失败的组合区分开。
* 三种把层级训练进权重的方式：带深度缩放完成奖励的节点即实例离线 RL、只在结果信号沉默时生效的 RLVR 自适应技能加成、以及作为在线策略自蒸馏特权上下文的 X-Tree。
* 横跨三个环境、三个规模的证据表明每种整合在匹配数据与预算下都胜过其标准配方，并有对照（随机片段、随机树、算力匹配 SFT、资源匹配挖掘）把大部分增益归于挖出的结构。
* 证明在 OPSD 和作为上下文建议时，LLM 撰写的技能库可以被零 LLM 成本的计数所得库替代。

# Q10 下一步

* **作者陈述：** 从策略自身轨迹挖掘 X-Tree，让结构与策略共同改进；在一个模型中合并三种整合；用树的稀疏区域决定哪些轨迹值得合成。
* **留出归因（读者注）：** G2 消融未能回答 X-Score 在未见任务上是否胜过随机合并；更多种子或更大的留出划分能解决。
* **不手写模板的字母表（读者注）：** 规范化器是唯一的环境特定组件；学习角色词典或从工具 schema 推导，会使挖掘器可移植到新驾驭层。
* **与本仓库的相关性（读者注）：** 同样的计数可以跑在本仓库的智能体对话记录上，找出值得打包为技能的重复命令序列，并用按成功加权的 X-Score 廉价地检查候选技能是否真的与成功运行共现。
