# Q1 问题定义

* **输入 (X)：** 一篇机器学习论文、其官方代码仓库的一个固定 commit，以及一组任务。一个任务是主表中论文自身方法的一个测量值，由数据集、指标、报告统计量和位置确定。一个全新的编程智能体会话（Reproducer）拿到论文、任务，以及原始代码或精炼产物二者之一。
* **输出 (Y)：** 带执行证据的新测量值。当数值落在由五次人工核验的参考运行构造的相容区间内，并且独立的审计者（Auditor）没有判定其背后的执行无效时，任务算成功。
* **约束：** 论文陈述的设置优先于与之冲突的代码；论文中的目标数值可见，但参考观测、另一种条件和其他智能体的运行目录都被隐藏；随仓库附带的分数文件不算测量；每篇论文限时 24 小时，GPU 实验使用八块 H100-80GB。

# Q2 问题新颖性

部分新。复现类基准已经存在：PaperBench 和 SciReplicate-Bench 用评分细则评估重新实现，CORE-Bench 评估对已发布 capsule 的执行，REPRO-Bench 和 ReplicationBench 扩展到其他学科。自动复现系统也有（PaperCoder、AutoReproduce、VERITAS，以及 Compiler for Agent-Native Research Artifacts）。新的问题在于"交接物"：复现成功有多少取决于发布的产物，有多少取决于复现者补全缺失细节的能力。检验方式是固定复现者，只改变交给它的东西。

# Q3 科学假设

如果把一次复现中找回的流程和决策以标准形式保存下来（依赖解析变成安装流程，实验定位变成启动器，每处修正变成带理由和受影响任务的记录），那么之后独立的复现者会更常成功、花费更少，而且较弱的模型获益最大，因为成功不再那么依赖于推断缺失的细节。论文的工作模型把一次测量写成 Y = μ + D + ε，其中 D 是执行选择偏离指定实验造成的系统偏移，ε 是运行间的随机波动；精炼产物的目标是缩小 |D|。

# Q4 相关工作与关键人物

* **可复现性规范。** Reproducibility Enhancement Principles、NeurIPS 可复现性计划，以及 ACM 的术语：可复现指独立执行作者的产物，而不是重新实现或逐位重放。
* **复现基准。** PaperBench、SciReplicate-Bench、REPRO-Bench、ReplicationBench 和 CORE-Bench。
* **自动复现与可复用经验。** PaperCoder、AutoReproduce、VERITAS（打过补丁的代码、修复记录和结论评估；它的交接物是外部对比对象），Reflexion 和 Voyager 作为保留反馈和积累技能的例子，以及用专家评分细则打包论文和仓库的 Compiler for Agent-Native Research Artifacts。
* **测量理论。** 计量学指南中系统误差与随机误差的区分，以及 Student-t 预测区间。
* **关键人物。** Yubo Wang（滑铁卢大学和 Google），以及 Google 的 Rui Meng、Jaehyun Nam、Tomas Pfister、Jinsung Yoon。可能的批评者：CORE-Bench、PaperBench 和 VERITAS 的作者。

# Q5 核心方法

**精炼可复现产物（RRA）由四部分组成。**

* *精炼代码库：* 修复执行缺陷，补上缺失的实验支持代码。
* *环境搭建：* 相容的依赖版本，以及获取数据和 checkpoint 的途径。
* *实验启动器：* 把每个任务与其配置、执行范围、输出和分数提取连接起来的入口，并区分计分运行与冒烟测试。
* *复现指南（含变更记录）：* 十二个部分；每条歧义记录给出来源位置、缺口、采用的解决办法及理由、敏感性和受影响的任务；变更分为执行修复、正确性修复和便利性改动。

**构建流程。** 人定义流程、交付标准和协议；全部构建工作由智能体完成。六个角色分三个阶段：Specify（Intake、Planner）在看到任何结果之前先确定要测什么；Execute（Builder、构建阶段的 Reproducer）搭环境并运行实验，每个测量值都要链接到一个输出文件；Preserve（Distiller、Packager）撰写指南并组装出能在干净 shell 中通过测试的交付物。一个处于独立上下文的 Reviewer 对计划、执行记录和最终产物提出质疑。构建过程中看不到人工参考分数。

**基准的参考规则。** 五位人工复现者在不同服务器上各自从原始 commit 运行每个任务，不共享脚本或结果，并且必须在看到分数之前固定种子和重复次数。相容区间是参考均值加减"95% Student-t 预测半宽"与"均值的 1%"中较大的一个。只保留论文公布分数落在该区间内的任务：1,463 个整理出的任务中的 1,029 个（70.3%），来自 502 个实验中的 387 个。

**完整性审计。** 会话结束后，Auditor 利用时间戳和哈希，把每个上报的数值追溯到输出文件、执行记录和生成脚本。Finder 提出定位明确的违规，Refuter 尝试推翻每一条，有争议的交给评审小组。五类违规可以使结果无效：直接抄数值、替换测量工具、篡改公式的操作数、看到数值后再选择上报结果、计算了错误的统计量。

# Q6 实验设计

# Q7 数据集与代码

ReproBridge-Bench 基于 36 篇有官方代码的 ICML 2026 Spotlight 论文；另有十篇论文（五篇 NeurIPS 2026、五篇 ICLR 2026）用于开发流程，单独报告。论文给出了项目页（`https://wyyyb.github.io/reprobridge_website/`）。本次阅读的正文没有说明精炼产物、参考分数或流程代码是否发布，`hf papers info` 也没有列出仓库。

# Q8 证据质量

* **有支撑的结论。**
  * *每个模型的成功率都提高。* 原始到 RRA（三次评测的均值）：Sonnet 4.6 从 72.3% 到 91.6%，Sonnet 5 从 76.5% 到 93.3%，Opus 5 从 89.2% 到 94.7%，Gemini 3.8 Flash 从 67.6% 到 90.8%。四个模型的均值为 76.4% 和 92.6%，最好与最差模型之间的差距从 21.6 分缩小到 3.9 分（读者用表 3 核对了摘要中的数字）。
  * *下游成本更低。* 各模型 token 减少 6.3% 到 19.8%，API 花费减少 16.8% 到 23.7%，失败的尝试也计入。
  * *换一种计分方式仍成立。* 每篇论文等权时增益为 6.7 到 20.7 分；用 80% 区间时为 10.3 到 39.1 分。每个模型有 3 到 6 篇论文（共 36 篇）出现退步。
  * *标准化交接物胜过遗留的运行目录。* 在消融子集上：原始代码 73.9%，普通输出 81.2%，完整 RRA 93.0%。
  * *审计本身用人工标注衡量过。* 以共同的人工标签为准，Codex 精确率 88.6%、召回率 79.5%，Claude 为 85.7% 和 61.5%；两者各把 779 个有效结果中的 4 个误判为无效。无论用哪个审计者，原始到 RRA 的增益方向不变。
  * *在另一个基准上的复用。* CORE-Bench Hard：原始代码 62.2%，VERITAS 68.9%，RRA 73.3%，每个成功 capsule 的花费从 8.43 美元降到 4.34 美元。
* **比标题结论更弱或更窄的地方。**
  * *任务集以"可复现"为条件。* 只评测五次人工运行与公布分数一致的任务；被去掉的 434 个任务（数值不符 183、执行受阻 186、资源或访问限制 65）恰恰是交接问题最难的地方。论文说明这些结果不是整个会议的复现率。
  * *近三分之一的"挽回"来自审计。* 813 个由失败变成功的任务中，348 个原先是数值不符，210 个原先没跑起来，255 个原先数值相符但被审计者判为无效。最后这一组依赖一个召回率 79.5% 的审计者；在人工标注子集中，39 个无效结果里有 33 个出现在原始代码条件下，这支持效应的方向，但不能确定其精确大小（读者观察）。
  * *消融差异是单次评测中的小计数。* 去掉一个部件损失 3.1 到 5.2 分，在 287 个任务上约为 9 到 15 个任务（读者计算），来自单个模型的单次评测；而主表中各次评测之间的标准差为 1.1 到 3.4 分。因此四个部件的重要性排序并未确立。
  * *CORE-Bench 上的差异是两三个 capsule。* 45 个 capsule 的 62.2%、68.9% 和 73.3% 分别是 28、31 和 33 个（读者由百分比推断），只跑了一次。
  * *干预是整个流程。* RRA 和普通输出来自不同的上游运行，所以这一对比没有隔离出"把同样的知识整理好"的效果；论文说明了这一点。这些产物也正是为随后被计分的那些任务构建的，并为它们配了启动器（读者观察）。
  * *回本需要多次复用。* 构建 36 个产物花费 5,026 美元 API 费用；Sonnet 4.6、Sonnet 5 和 Opus 5 分别需要 8、13 和 9 整轮才能回本，且不含 GPU 时间、审计、维护和人工参考运行。Gemini 3.8 Flash 没有被计算：它每轮节省 66 美元（表 3 中 392 减 326），大约需要 76 轮（读者计算）。
  * *精炼也可能帮倒忙。* 136 个原本成功的任务变成失败，其中 64 个来自两篇论文（AuxiliaryMCMC 50 个，LiME 14 个）；论文指出产物可能保留或引入错误的选择。
  * *各厂商的 harness 不同，* 所以模型之间的比较只是描述性的；主实验中所有产物都由同一个模型（Opus 5）构建。
  * *论文与代码的矛盾未经验证。* 另一项由智能体辅助的静态分析记录了 238 条矛盾，涉及 669 个任务；论文说这些不是经人工验证的错误率，也不能解释增益。

# Q9 贡献

* 一个由四部分组成的产物标准，把可执行的步骤和这样做的理由存在一起。
* 一个从论文和仓库构建这种产物的智能体流程，带有预先登记的测量规格和独立评审。
* 一个基准：用人工核验的参考分布代替单个公布数值，成功的定义是数值相容加上执行完整。
* 一套包含五类违规的执行完整性审计，并用双人人工评审验证过，评审范围包括没有任何审计者标记的结果。
* 证据表明决定复现成功的不只是模型，还有交接物：有了精炼产物，四个模型都超过 90%。

# Q10 后续方向

* **人的复用。** 作者提出要研究人类研究者节省的时间和理解程度，并完整核算构建、验证和维护的成本。
* **投稿前使用。** 设想的主要用途是作者在发布前对自己的论文运行该流程，找出缺失的细节和论文与代码的冲突；这一用途只是提出，没有评测。
* **被去掉的 30%（读者建议）。** 在第 3、4 类任务上运行该流程，可以看出它能否把无法复现的结果变成可复现的结果，或变成有记录的差异。
* **同知识对照（读者建议）。** 把同一次上游运行的输出整理成四个部件，与未整理的输出比较，以区分"格式"和"额外工作"的作用。
* **更便宜的构建者（读者建议）。** 只有 Opus 5（以及 CORE-Bench 上的 Sonnet 5）构建过产物；便宜模型构建、强模型复用是否可行尚未检验。
* **读者联系。** 审计的违规类别（抄数值、替换测量、事后挑选）正是本知识库中自主科研评测在智能体所写论文里报告的失败类型；可以要求那些智能体也提供 RRA 式的证据链。
