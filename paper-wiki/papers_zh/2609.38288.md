# Q1 问题定义

* **输入（X）：** 一个环境 e = (σ, S)：任务描述 σ，以及把候选解映射为标量的评分函数 S（留出集上的验证指标，或通过的隐藏测试比例），再加上 T 轮的预算。每一轮里，智能体阅读、修改、运行和搜索，然后提交解 y_t 并收到反馈 f_t（分数、日志、错误、耗时）。
* **输出（Y）：** 一系列解，其“迄今最佳分数” s_t = max_{k≤t} S(y_k) 应随预算增加而持续上升。
* **核心问题：** 在多数系统中，“尝试-测量-修订”的循环存在于脚手架（scaffold）里：由驾驭层决定何时重试、保留什么，模型每次只负责给出一次尝试。作者希望把这个循环搬进模型内部。现有的智能体训练数据无法教会这一点，因为它们是逐次尝试构建的：只保留通过的解，中间尝试、对应反馈和随后的修订全被丢弃。
* **形式化框架：** 设 r_t 为第 t 轮的期望增益，则 T 轮总改进为各 r_t 之和。若有 T* 轮保持有效（r_t 高于一个小阈值 ε），其平均增益为 r̄，则改进约为 r̄·T*。**反思（reflection）** 决定 r̄；**长程执行（long-horizon execution）** 决定 T*。更大的预算只在 T* 之内有用。

# Q2 问题新颖性

部分新颖。依据反馈反复改进解，是 AIDE、AlphaEvolve、The AI Scientist 和 Frontis-MA1 的基础，但它们的循环由脚手架驱动。用模型自己的成功输出训练（STaR、ReST、拒绝采样微调），以及用单次尝试的智能体轨迹训练（SWE-Gym、SWE-smith、R2E-Gym）也都已有先例。新的部分在于：把*多轮改进过程本身*（包括失败的轮次）作为监督对象；按“能否很好地监督这一过程”而不是“是否像目标领域”来选择训练领域；并检验这种能力能否迁移到深度研究。

# Q3 科学假设

长程反思——判断解哪里不足、决定改什么、在失败后继续——是一种与领域无关的元技能。如果模型模仿在反馈清晰、可分级的领域（机器学习工程与算法编程）里持续改进的完整轨迹，它应当（a）在这些领域表现良好，（b）随轮次预算增加持续进步，（c）迁移到没有新增训练数据的深度研究领域。

# Q4 相关工作与关键人物

* **脚手架驱动的迭代系统：** AIDE、AlphaEvolve、The AI Scientist、Frontis-MA1（面向机器学习工程的 AI4AI 模型，其 OpenMLE 协议被用于评测）。
* **基于单次尝试的智能体训练数据：** SWE-Gym、SWE-smith、R2E-Gym；基于成功输出的自训练：STaR、ReST、拒绝采样的缩放研究。
* **基准：** MLE-bench、FrontierCS、BrowseComp、Humanity's Last Exam、GAIA、DeepSearchQA。
* **前作：** AREX（Lu et al., 2026, arXiv:2607.21461），本文原样复用其深度研究数据和评测协议。
* **关键人物：** 北京智源人工智能研究院（BAAI）的 AREX 团队。核心贡献者为 Hongjin Qian、Chaofan Li、Kun Luo、Wenqing Wei、Jianlyu Chen；项目负责人 Zheng Liu；顾问 Zhicheng Dou 和 Defu Lian。其中多位作者也写了 [Repo-To-Skill](../papers/2609.02749.md)，该文把“操作性知识”（operational knowledge）视为研究智能体的第三个组成部分，并从机器学习仓库构建了 AREX-Skill Library。AREX-2 没有引用它，但其操作性知识的框架和由仓库派生的通用技能与之吻合（读者注）。

# Q5 关键解法思路

* **从源材料编译环境。** 教师模型把 GitHub 仓库变成机器学习任务（提升该仓库所测量的指标，在智能体无法访问的留出集上评分，沙箱中已安装好仓库），把在线评测（online judge）题目变成编程任务（题面、编译器和样例，隐藏测试评分，评测允许时采用分级分数）。只有当源材料自带的参考解能运行并得分、且一个简单基线明显低于参考解（即留有改进空间）时，环境才被接纳。
* **展示持续改进的轨迹。** 教师智能体在每个任务上拥有以小时计、数百次工具调用的预算，并被告知预算，因此可以先测量、后修订。它通过阅读代码和文档、搜索代码所依赖的论文与库、运行小实验来获取操作性知识（API、数据格式、约束允许的优化）。上下文中放入精简的技能文档：通用技能由机器学习仓库和常见实践预先准备；任务特定技能通过搜索相关资料构建，并排除关于该任务本身的材料。降低分数的轮次保留在轨迹中，后面紧跟智能体对它的回应。
* **按整条轨迹筛选。** 一条轨迹被保留的条件是：最佳提交达到相对参考解的阈值，且过程合规——格式为用户-助手-工具、每次工具调用都有观察结果、以良构状态结束、没有违规（例如从留出集重构答案或泄露凭据）。单个轮次可以失败。
* **只在推进性决策上计算损失。** 整条轨迹都作为上下文。损失只作用于推动解向前的决策（诊断失败、修复、换策略、跑下一个实验、提交改进）。重复轮询、没有新观察的调用、近乎重复的回合、系统消息、环境报告和检索到的文档都不计损失。
* **训练。** 把新轨迹与原样保留的 AREX 深度研究数据混合，对 Qwen3.8-27B 做监督模仿学习。

# Q6 实验设计

* **基准：** Frontier-CS Agent Track（188 道开放式算法题，分级评分，每题 5 小时）；OpenMLE 协议下的 MLE-bench Lite（每题 12 小时，Any Medal 取三个随机种子平均，AREX-2 在上下文中带技能运行）；以及 AREX 协议下的 BrowseComp、Humanity's Last Exam（纯文本子集）、GAIA 和 DeepSearchQA（F1）（内层至多 300 轮、总计至多 1,500 轮）。
* **对比对象：** 从 4B 到 2.8T 参数的闭源与开源模型。部分 Frontier-CS 行是作者复现的；MLE-bench Lite 各行由 OpenMLE 复现并报告；HLE 各行混用了全集和纯文本子集。
* **有反馈时的轮次扩展：** 在 5 小时预算内，AREX-2（使用作者优化过的驾驭层）、DeepSeek-V4-Pro 和 DeepSeek-V4-Flash 在 Frontier-CS 上的平均“迄今最佳分数”曲线。
* **无反馈时的轮次扩展：** 在双循环递归研究流程下（内循环收集证据并给出暂定答案；外循环依据模型自身置信度决定接受、改进或重来），BrowseComp 准确率随平均轮数的变化，并在同一流程下与 AREX（122B）比较。
* **MLE-bench Lite 分阶段消融：** M0 为不带技能的基座 Qwen3.8-27B；M1 加通用技能；M2 加通用与任务特定技能并增加轮次；M3 为 AREX-2，用 M2 的技能、基础轮次；M4 为 AREX-2，用 M2 的技能和轮次。

# Q7 数据集与代码

Hugging Face 和论文列出代码仓库 [VectorSpaceLab/AREX-2](https://github.com/VectorSpaceLab/AREX-2)（获取时 10 星）和模型合集 [huggingface.co/collections/BAAI/arex-2](https://huggingface.co/collections/BAAI/arex-2)。获取到的正文没有给出环境或轨迹的数量、教师模型、轨迹筛选阈值，也没有说明环境和轨迹是否发布。

# Q8 证据质量

* **有支撑的：**
  * *领域内结果。* MLE-bench Lite Any Medal 81.8，为表中最高：比 Naive-N0.5-Flash（73.7）高 8.1 分，比 GPT-5.6 Sol（72.7）高 9.1 分；Kimi-K3 为 72.7，Frontis-MA1-35B 为 71.2，Claude Opus 4.8 为 63.6。Frontier-CS 70.7：比最强开源行（Kimi-K2.7-Code，54.7，作者复现）高 16.0 分，比 GPT-5.6 Sol（76.4）低 5.7 分，低于 Claude Opus 4.8（74.5）和 GPT-5.5（72.1），高于 Gemini-3.1-Pro（68.9）。
  * *深度研究。* BrowseComp 84.0、HLE 纯文本 52.6、GAIA 92.2、DeepSearchQA 93.8，四项都高于此前两个 AREX 模型（AREX 4B：70.7/40.6/81.6/78.5；AREX 122B：82.5/52.4/85.4/89.9）。在不超过 40B 的模型中，它在 BrowseComp、HLE 和 DeepSearchQA 上领先（例如 Iris-mini 在 BrowseComp/HLE/DeepSearchQA 上为 82.2/52.3/86.9），在 GAIA 上排第三，落后于 XYZ-Aquila-mini（97.1）和 Agents-A1（96.0）。
  * *更长预算仍然有效。* 在 Frontier-CS 上，AREX-2 一小时后达 54.4，两小时 65.9，五小时 70.7，最后一小时仍增加 2.2 分；而 DeepSeek-V4-Pro 两小时后停在 44.7，V4-Flash 三小时后停在 39.1。在无正确性反馈的 BrowseComp 上，准确率从 47 轮时的 64.8 升到 143 轮时的 84.0；在约 140 轮时比 AREX（122B）高出 12 分以上，每轮增益约为其三倍。
  * *消融。* MLE-bench Lite 从 28.8（M0）升到加通用技能后的 41.2（M1），再到加任务特定技能和更多轮次后的 68.2（M2）。在技能和轮次相同的情况下，AREX-2 达到 81.8（M4，比 M2 高 13.6）；轮次更少时仍有 75.8（M3，比 M2 高 7.6）；更多轮次再加 6.0（M3→M4）。
* **较弱或有边界的：**
  * *迁移结论同时换了基座模型。* 论文主张，相对 AREX（4B）和 AREX（122B）的深度研究增益来自新轨迹，因为深度研究数据没有改变。但 AREX-2 是从 Qwen3.8-27B 微调的，与两个旧模型的基座都不同且更新。文中没有报告“只用旧 AREX 配方训练 Qwen3.8-27B”的结果，因此迁移效应无法与基座变化分开（读者注）。BrowseComp 的轮次扩展对比也有同样的混杂。
  * *MLE-bench Lite 的头条成绩包含基线没有的技能。* AREX-2 评测时上下文中带有通用和任务特定技能。消融显示，仅技能和更多轮次就能把基座从 28.8 提到 68.2，约占总增益的四分之三，而 68.2 已与 GPT-5.5 那一行持平。由 OpenMLE 复现的基线行并未说明带有相同技能，所以相对它们 8-9 分的领先混合了训练、技能和协议三方面的因素。训练本身的贡献是 M2→M4 的差值（13.6 分）。
  * *驾驭层与协议差异。* Frontier-CS 扩展实验中 AREX-2 使用“我们优化过的驾驭层”；获取到的正文没有描述基线所用的驾驭层。若干基线行抄自其他报告，HLE 混用了全集与纯文本子集（AREX-2 的 52.6 是纯文本子集）。
  * *缺少数据和污染方面的细节。* 环境数量、教师模型、筛选阈值和训练混合数据的规模都没有报告。训练环境来自 GitHub 机器学习仓库，而 MLE-bench 由 Kaggle 竞赛构建；正文只说明任务特定技能排除了任务本身的材料，没有报告训练仓库与基准竞赛之间的重叠检查（读者注）。
  * *方差。* 只有 MLE-bench Lite 报告了随机种子平均（三个种子）；其他结果和扩展曲线都没有报告方差或显著性检验。
  * *一个相关参照（读者注）。* 在作者部分重叠的 [Repo-To-Skill](../papers/2609.02749.md) 中，固定的 GPT-5.5 Codex 智能体配合 AREX-Skill Library，在同样 188 题、每题 5 小时的 Agent Track 上得到 77.14 分，高于 AREX-2 的 70.7。两篇论文使用的智能体和驾驭层不同，因此这只是背景参照，不是受控比较。

# Q9 贡献

* 把智能体自我改进定义为单任务内的测试时扩展，并给出简单分解（反思对应 r̄，长程执行对应 T*），使“轮次越多越好”成为可测量的性质。
* 一套数据配方：从仓库和在线评测编译环境并检查参考解可用、存在改进空间；用长预算教师轨迹获取操作性知识并使用技能；按整条轨迹筛选并保留失败；损失只作用于推进性决策。
* 一个 27B 开源模型：在 MLE-bench Lite 和 Frontier-CS 上表现强，权重已发布，并给出有反馈与无反馈两种情形下的预算扩展曲线。

# Q10 下一步

* **作者的计划：** 拓宽训练领域，拉长时间跨度，并让模型用自己的轨迹作为下一轮训练数据，从而闭合循环。
* **缺失的对照（读者注）：** 只用旧 AREX 配方微调 Qwen3.8-27B，并在四个深度研究基准上与 AREX-2 比较；衡量新轨迹迁移效果的应是这个差值，而不是与 AREX（4B/122B）的比较。
* **直接测量 r̄ 与 T*（读者注）：** 该分解有定义却未被估计。报告每轮增益的分布以及 r_t 跌破 ε 的轮次，可以说明训练提升的是 r̄、T* 还是两者，以及技能影响的是否是同一个量。
* **哪些失败有用（读者注）：** 对“保留失败轮次”做消融：用同样的轨迹训练，但把失败轮次从上下文中去掉，检验论文“从挫折中恢复是迁移的关键”这一说法。
* **与本仓库的关联（读者注）：** 这一形式化为 Research OS 中长时间运行的智能体循环（例如 autoresearch 式的实验活动）提供了“自我改进”的可测量含义：按轮记录迄今最佳分数，检查增加的轮次是否仍然有效，而不是只报告最终分数。
