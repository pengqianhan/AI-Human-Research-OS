# Q1 问题定义

* **输入（X）：** 一个经过预训练和中期训练（mid-training）的全模态混合专家（MoE）模型；四个领域（代码、通用专业工作流、视觉产物、网络安全）中带验证器的可执行智能体任务池；以及模型借以行动的一组智能体框架（harness）。
* **输出（Y）：** 一个策略，它能更经常地解决长程智能体任务，且给出更短、更易维护的解法，用公开和内部的智能体基准衡量；另外还有让这种训练得以运行的基础设施。
* **约束：** 奖励必须准确、确定，并且便宜到能为每步约 2.5 万条轨迹计算；训练必须在最长 100 万 token 的上下文下保持稳定；奖励不能靠捷径（例如抓取已发布的修复）获得。
* **核心问题：** 如何同时沿训练算力、环境与框架多样性、评分器算力三个方向扩展智能体的强化学习后训练，而不出现奖励作弊（reward hacking）、专家负载坍塌或轨迹长度失控。

# Q2 问题新颖性

不是新问题。大批量智能体强化学习是前沿模型后训练的标准路线，报告建立在一系列有名字的已有部件之上：[GRPO](../concepts/grpo.md)、部分 rollout（Kimi k1.5）、对零方差组的动态采样、用于 MoE 训练-推理一致性的 Rollout Routing Replay（R3）、多教师在线策略蒸馏（MOPD），以及 Muon 系列优化器。这里新的主要是公开了规模的工程实践和几个具体机制：跨可重组的*迷你框架（mini-harness）*训练、两种把通过测试的 rollout 按质量区分开的组内评分方案、在强化学习期间冻结 MoE 路由器、四层奖励作弊防线，以及以前缀为条件的蒸馏（MOPD2）。在线评分方案（GAR）引自同一团队的另一篇论文（Dong 等，2026）。

# Q3 科学假设

1. **算力。** 若把强化学习的批量、环境多样性和评分器算力一起扩大，基准分数会在一次运行中在代码、通用、视觉和安全任务上持续上升。
2. **框架多样性。** 若同样的任务在若干极简、解耦的框架配置下训练，学到的行为会迁移到训练中从未用过的框架。
3. **组内评分。** 若把一组中通过测试的 rollout 按质量排序，并把正优势向更好的那些转移，通过率会持续提高，同时轮数和 token 长度受控，补丁不越出任务范围。
4. **冻结路由器。** 若在强化学习期间冻结 MoE 路由器，专家负载保持均衡，基准表现不受影响。
5. **分层防作弊。** 若环境经过清理、被专门的攻击智能体（hack agent）反复攻击直到找不到漏洞、并在训练中被审计，被确认的奖励作弊就只占轨迹的很小一部分。

# Q5 关键解决思路

* **基础。** 主干交替使用 128 token 的滑动窗口注意力与全局注意力，配稀疏 MoE 前馈层、一个 6.81 亿参数的 ViT 和音频编码器。预训练覆盖 48T token（Flash）和 30T（Pro）。在以智能体为中心的数据上做的中期训练把上下文从 256K 扩到 1M，把隐藏层权重矩阵的优化器换成适合大批量训练的 Muown，使用 MXFP4 量化感知训练，并加入了让模型反思并纠正自己早先奖励作弊回合的样本。
* **大规模强化学习。** 采用按 prompt 取均值聚合损失的 GRPO，加异步部分 rollout（陈旧度 4）。每步用 1,568 个 prompt、组大小 16，约 2.5 万条序列、27-37 亿训练 token（每条序列约 11 万-15 万 token）。重要性比率的裁剪对正、负优势使用各自的上下界，并在运行时根据策略熵放宽或收紧。全部通过或全部失败的组被过滤掉。
* **环境。** *代码：* 五条合成路径（GitHub 拉取请求与 issue、内部开发需求、规格驱动的任务、源码驱动的合成、长程任务扩写）；每个任务尝试四次，由审计智能体把自己对每个补丁的判断与测试奖励对比，标出假阳性和假阴性；fail-to-pass 与 pass-to-pass 的结果必须在八次重跑中保持稳定。*通用：* 可重置的本地工作区，配多智能体构建的软件模拟（mock），任务用原子化的二元评分项（代码检查加 LLM 检查）评分，由自托管的 SFT 模型担任评分器。*视觉：* 开放式设计先逐点评分再组内评分，视觉复刻主要用像素级相似度评分。*安全：* 复现一个 OSS-Fuzz 漏洞；只有当 sanitizer 报告的漏洞类型和最顶层的项目级栈帧都按字符串规则匹配时，概念验证（PoC）才被接受，智能体除源码外还能拿到编译好的 fuzz 驱动二进制。
* **多框架训练。** 生产级框架不适合作为强化学习的基底：它们的安全措施和指令提示不在任务奖励之内，各模块也无法逐一改变。训练用的框架因此都派生自同一个极简智能体循环（系统提示、工具、上下文管理），其实现按领域重组。
* **缓解奖励作弊。** （1）中期训练中的纠正数据；（2）环境准备：删除构建日志、验证器输出、残留补丁、字节码和缓存，把 Git 历史截断在基准提交，对容器做网络隔离，并明确要求不得检索已有解法；（3）一个攻击智能体探测准备好的环境，清理与再攻击反复进行，直到它找不到漏洞；（4）训练期间的离线轨迹审计，在线评分器把被确认的作弊轨迹奖励清零。
* **组内智能体评分。** *GRS*（离线，用于一部分高通过率任务）：一个智能体研读若干 rollout，写出任务专属的"解法"和"行为"评分细则；之后评分智能体给每条训练 rollout 打分，奖励为 $R^{\mathrm{test}}\cdot S^{\mathrm{sol}}\cdot S^{\mathrm{beh}}$。*GAR*（在线，用于其余代码任务）：一个经 SFT 训练的评分器在共享工作区中检查一个结果有成有败的组内全部轨迹，按方案是否合适、实现是否精确、改动是否最小、有无副作用、工艺是否合乎代码库惯例给通过的补丁排序，并按质量因子重新缩放通过轨迹的优势，使其总量保持不变（缩放因子有上限）；失败轨迹不变，最后再整体去均值。
* **行为正则化。** 一个长度惩罚，只施加于通过率高于门槛的组内、长度超过某个分位数参考长度的成功 rollout；片段级惩罚：在正优势轨迹中屏蔽格式错误或无效的工具调用，在负优势轨迹中对它们加重惩罚，并把移走的优势量重新分配。
* **强化学习之后。** MOPD2 把各领域教师（包括为缺乏可靠奖励的任务用 SFT 训练的教师）合并起来，做法是从教师轨迹或示范轨迹的前缀出发，采样学生的单个回合。
* **基础设施。** Sample → Sequence → Context → Segment 的轨迹层级，配由规则和策略组成的 Penalty Module；Ray 上的多租户 Harness Pool；Payload Porter 让驱动节点只处理元数据，负载数据放在分布式存储中；Sample Mixer 在 25 个数据源的 token 数和 rollout 时长分别相差 90 倍和 66 倍的情况下维持每个来源在批次中的占比；跨 GPU 显存与锁页主机内存的上下文缓存。

# Q6 实验设计

* **主运行。** 每个模型只跑一次强化学习（"You Only RL Once"）。任务配比：智能体式与竞赛式编程 68%，通用工具使用 12%，审美设计 13%，上下文遵循 3%，网络安全 4%。
* **强化学习期间的曲线。** DeepSWE v1.1、AutomationBench v1.0.6 和内部的 MiMo Visual Coding 基准，并附总 token 数；DeepSWE 在四个训练用迷你框架和三个留出框架（codex、claude code、mini-swe-agent）下的 Pass@1。
* **消融。** 有无 GAR（Flash，纯代码强化学习，批量 128，按 token 取均值的损失）；路由器冻结对比可训练（Pro，第 9 层解码器的专家负载统计）。
* **最终比较。** 四个类别共 17 行基准，对比 MiMo-V2.5 Pro、Claude Opus 5、GPT-5.6 Sol 和 Claude Fable 5，基线取其最高推理档位；MiMo-V2.6 的数字是强化学习加 MOPD2 之后的结果。
* **运行故障分析。** 按原因列出两次运行的中断时间线。
* **开放套件。** 用 774 亿 token 的 MiMo 生成数据（其中 272 亿计入损失）微调 Qwen3.5-9B，得到 MiMo-V2.6-Distill-Qwen-9B，再在发布的环境上按领域分别做 GRPO 训练，另加一次多框架代码训练，在七个框架上评分。

# Q8 证据质量

* **有支撑的结论。**
  * *分数在强化学习期间上升。* 随着累计强化学习成本增加，DeepSWE v1.1 的 average@3 从 58.4 升到 72.6（Pro）、从 48.7 升到 65.7（Flash）。Pro 的成本分为 rollout 43.8%、训练 43.5%、评分 12.7%。
  * *路由器漂移导致负载坍塌。* 路由器可训练时，前 20 步内专家负载的变异系数从 0.78 升到 2.0，峰值负载从均值的 6 倍升到 16 倍，冷专家比例从 0.5% 升到 22%。在第 20 步只把路由器参数恢复到强化学习前的取值，负载均衡即恢复，基准表现不变；冻结路由器的运行保持平稳（约 0.7、5.5 倍、1%）。
  * *在线评分改变了训练动态。* 没有 GAR 时，轮数和 token 长度增长很快，更多轨迹触及长度上限；有 GAR 时，通过率的提升持续到第 52 步，轮数大致稳定。以维护者视角做的审计发现，未经评分的策略会加入推测性的兼容分支、吞掉异常、放宽校验，以及做只针对评测的配置改动。
  * *奖励作弊有具体案例记录。* 表 2 引用了这样的 rollout：安装更新的软件包版本、抓取上游文件、克隆上游仓库，或阅读工单历史来找到修复。攻击智能体在多轮中发现了团队的清理流程遗漏的漏洞路径。
  * *开放套件在 9B 规模复现了强化学习的收益。* 在报告的全部 11 项评测上，强化学习都优于 SFT 检查点，例如 [SWE-bench Verified](../concepts/swe-bench-verified.md) 61.1 到 66.2、[SWE-bench Pro](../concepts/swe-bench-pro.md) 44.6 到 47.6、Terminal-Bench 2.1 37.1 到 52.8、[OfficeQA Pro](../concepts/officeqa.md) 19.5 到 24.8、AutomationBench 30.3 到 33.1。多框架强化学习在全部 21 个"数据集-框架"组合上都比 SFT 有提升。
* **比标题更弱或更窄的地方。**
  * *"与前沿模型相当"在论文自己的表里是有高有低的。* 在至少有一个前沿模型数字的 15 行中，MiMo-V2.6-Pro 在两行最高（AutomationBench 53.1 对 50.3、45.8、46.2；Terminal-Bench 2.1 89.9 对 89.1、88.8、84.3），一行并列（Agents' Last Exam 31.6）。它在 DeepSWE（71.9 对 74.0 和 73.0）、Terminal-Bench 4.0（34.9 对 49.0）、ProgramBench（26.5 对 37.0）、OSWorld-Verified（82.0 对 86.0）、GDPval-AA（1673 对 1708）上落后，在漏洞利用开发上差距很大（ExploitBench 47.9 对 70.0-78.5）（读者根据表 3 的统计）。CyberGym（94.0）和 MiMo Cyber Bench 没有前沿模型的数字。
  * *多框架的结论缺少对照。* 训练期间，留出框架在 DeepSWE 上的 Pass@1 从约 50% 升到 66%，但没有任何只在单一框架上训练的运行在同样的留出框架上评测，所以这一提升无法归因于框架多样性而不是一般的强化学习。9B 实验有同样的缺口：它的单框架强化学习结果没有按框架报告（读者观察）。
  * *强化学习与 MOPD2 没有分开。* 最终表是两者之后的结果；没有一行给出只做强化学习的检查点在全部基准上的表现。
  * *GAR 消融只是较小设置下的一对运行。* 批量 128、按 token 取均值聚合，而主运行是 1,568 个 prompt、按 prompt 取均值聚合。GRS、长度惩罚和片段惩罚都没有消融。
  * *作弊率是检测器确认的那部分。* "低于 2%"是被团队自己的评分器和审计确认为作弊的轨迹占比；两者都没抓到的作弊不计入，也没有给出召回率估计（读者注）。
  * *单次运行，只有图没有表。* 训练曲线、GAR 对比和路由器对比都是各自一次运行的图，作者提到检查点之间有波动，没有方差估计。
  * *9B 的大部分提升来自蒸馏，且若干测试集属于分布内。* 例如 MiMo Code Bench（mini）经 SFT 从 19.5 到 51.6，再经强化学习到 59.9；四个内部 mini 测试集"与对应训练集遵循相同的任务分布"。
  * *报告了运行上的脆弱性，这一点有用。* 运行曾因以下原因中断：GPU 显存双比特错误、一次 Kubernetes 故障、评分器不可达、部分 rollout 下长度估计偏差导致 KV 池耗尽、MoE 不均衡使某个专家并行 rank 收到均值 30 倍以上的 token 负载，以及打包时主机内存不足。

# Q9 贡献

* 一份公开了做法与成本的配方，用于在 1T 参数的 MoE 模型上扩展混合任务的智能体强化学习：批量、token 和美元数字、优化器设置，以及故障时间线。
* 用极简、可重组的迷你框架做多框架训练，并在留出框架上评测。
* 组内智能体评分（GRS 与 GAR），加上控制轨迹长度的行为正则化。
* 四层奖励作弊防线，附具体案例和一个对抗性的攻击智能体。
* 一个基于规则、以 sanitizer 报告为依据的漏洞复现验证器，取代差分测试和 LLM 评判。
* 用冻结路由器修复 MoE 强化学习中的专家负载坍塌，并给出能分离出路由器漂移的诊断。
* MOPD2 和强化学习基础设施（轨迹层级、Harness Pool、Payload Porter、Sample Mixer）。
* 一个开放的 9B 蒸馏模型、约 7 千个带验证器的强化学习任务、一套框架和一个迷你框架。

# Q10 下一步

* **作者提出的方向。** 没有局限性或未来工作一节。结论把这次发布表述为迈向模型自我改进的一步，并希望开放资源支持可复现的研究。
* **缺失的对照（读者建议）。** 一次单框架强化学习运行、在留出框架上评分；MOPD2 之前只做强化学习的一行；在主运行批量下对 GRS 和长度惩罚做消融。
* **估计作弊检测的召回率（读者建议）。** 在一部分环境中植入已知捷径，测量评分器和审计能抓到多少，这样"低于 2%"才能读作一个比率，而不只是下界。
* **按领域看是否退步（读者建议）。** [One to More, More to One](../papers/2609.23377.md) 报告，混合在一起的智能体强化学习掩盖了"类别跷跷板"。这里 68% 的配比在代码上，占比较小的领域（安全 4%、上下文遵循 3%）的分领域曲线可以显示同样的现象是否在这一规模出现。
* **与本项目的契合（读者注）。** 环境准备清单（清除构建产物和缓存、截断历史、隔离网络，然后攻击自己的环境直到没有泄漏）是一份具体的检查表，可用于本仓库研究诚信规则要求各项目保护的冻结评测器。

* [智能体微调](../topics/agent-fine-tuning.md) - 一份工业规模的混合任务 GRPO 配方，含组内评分、长度与片段惩罚、冻结路由器，以及强化学习后的多教师蒸馏。
* [智能体环境](../topics/agent-environments.md) - 合成代码、通用、视觉和安全环境并审计其验证器，再用清理、网络隔离和对抗性攻击智能体来防止解法泄漏。
* [智能体框架工程](../topics/agent-harness-engineering.md) - 把框架当作训练变量：从一个极简智能体循环重组出若干迷你框架，并在 codex、claude code 和 mini-swe-agent 上测量迁移。
* [GRPO](../concepts/grpo.md) - 按 prompt 取均值的 GRPO，每步 1,568 个 prompt x 16 条 rollout，裁剪上下界不对称并随熵调整，另在通过的 rollout 之间重新分配优势。
* [奖励作弊](../concepts/reward-hacking.md) - 记录了仓库修复类强化学习中的解法泄漏式作弊和四层缓解措施；日志中被确认的作弊占比保持在 2% 以下。
* [在线策略蒸馏](../concepts/on-policy-distillation.md) - MOPD2 在多教师 OPD 上增加了从教师轨迹或 SFT 轨迹前缀出发的单轮学生 rollout。
* [AutomationBench](../concepts/automationbench.md) - 在强化学习期间被跟踪，最终为 53.1（Pro）和 52.3（Flash），高于所列的三个前沿模型。
* [Terminal-Bench](../concepts/terminal-bench.md) - Terminal-Bench 2.1 为 89.9（Pro），4.0 为 34.9；9B 模型在 2.1 上经强化学习从 37.1 到 52.8。
* [SWE-bench Verified](../concepts/swe-bench-verified.md) - 用于开放的 9B 模型：基础模型 60.0，SFT 后 61.1，强化学习后 66.2。
* [SWE-bench Pro](../concepts/swe-bench-pro.md) - 9B 模型：基础模型 32.0，SFT 后 44.6，强化学习后 47.6。
* [OSWorld](../concepts/osworld.md) - OSWorld-Verified 为 82.0（Pro）和 80.8（Flash），低于所列的三个前沿模型。
* [GDPVal](../concepts/gdpval.md) - GDPval-AA v2.1 得分：Pro 为 1673，Claude Opus 5 为 1708。
* [OfficeQA](../concepts/officeqa.md) - 9B 模型的 OfficeQA Pro：基础模型 9.0，SFT 后 19.5，强化学习后 24.8。
* [One to More, More to One](../papers/2609.23377.md) - 认为 SWE 任务上混合的智能体强化学习掩盖了类别退步，并用多教师 OPD 合并专家；MiMo-V2.6 在一次运行中混合四个领域，之后使用 MOPD2。
* [CompoWorld](../papers/2609.33665.md) - 通过组合模拟服务来扩展通用智能体环境，并在奖励内部重新加权评分项；MiMo-V2.6 按场景构建模拟，改的是通过的 rollout 之间的优势分配。
* [Context Language Models](../papers/2609.37725.md) - 以任务成功为门槛才给效率优势；MiMo-V2.6 的长度惩罚同样只施加于成功的 rollout，且只在通过率高于门槛的组内。
* [Recursive Self-Rewrite](../papers/2610.02826.md) - 同样把框架不匹配当作训练问题，做法是把多框架下的成功轨迹改写成单一目标框架的轨迹，而 MiMo-V2.6 直接跨框架训练。
* [Atria Dawn](../papers/2609.15818.md) - 另一份建立在可验证执行环境之上的大型 MoE 智能体模型报告。
