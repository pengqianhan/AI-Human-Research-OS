# Q1 问题定义

* **输入（X）：** O*NET 职业数据库（职业、任务陈述、细化工作活动 DWA）、一个筛选可数字化执行任务的过滤器、一个能访问公开文档的搜索智能体，以及一个能在编码智能体脚手架中行动的教师模型 π_T。
* **输出（Y）：** 一个语料库，每条包含（由真实文件组成的工作空间、任务陈述、交付物要求、带证据锚点与验证步骤的加权正向标准、负向惩罚标准）以及一条通过准入的教师轨迹，用于对"办公智能体"（working agent，需要阅读多样文件、协调工具、产出交付物）做 SFT 和按评分标准打分的拒绝采样微调。
* **核心问题：** 用模仿训练这类智能体，既需要大量建立在真实文件上的任务，*又*需要能检查交付物的验证器。现有两条流水线各缺一半：EnvCraft 用模型生成文件，并用无法读取文档内容的状态脚本检查任务；NexForge 用真实文件，但没有任务专属的评分标准或验证器，结果质量无从检查。
* **次要问题：** 模型自由发明的任务会塌缩到高频职业和泛泛的分析任务，因此多样性必须在检索任何文件之前就加以控制。

# Q2 问题新颖性

在可程序化验证的领域（工具使用、软件工程、终端任务；表 1 列出 AgentSynth、TaskCraft、SWE-smith、CLI-Universe），智能体任务与环境合成已很成熟。办公智能体的合成是新近的（EnvCraft、NexForge，均为 2026）。新颖之处在于连接任务与验证的中介对象：一个覆盖真实文件的证据图，任务陈述和每条评分标准的锚点都由它编译而来，因此验证读取的正是任务依赖的那些文件。这点重要，因为交付物质量（一份电子表格、一份备忘录）无法仅凭工作空间状态检查，而证据锚定的裁判还能为后续自训练提供选择信号。

# Q3 科学假设

如果任务通过一个证据图落地于真实文件，该图的节点与边同时锚定评分标准，并且每个任务在收集轨迹之前先执行一次、再对照原始文件修订，那么（1）在通过准入的轨迹上做 SFT 会在独立的办公智能体基准上提升基础模型，且在 rollout 所用之外的脚手架上同样提升；（2）用证据锚定的评分标准筛选模型自身的 rollout，会比用无锚点的裁判或随机筛选带来更大的进一步提升。

# Q4 相关工作与关键人物

* **智能体任务与环境合成：** AgentSynth（计算机使用）、TaskCraft（工具使用）、SWE-smith 与 R2E-Gym（软件工程）、CLI-Universe、TerminalWorld、FACET、OpenThoughts-Agent（终端）、Agent-World 与 Agent World Model（通用）。本 wiki 的 [CompoWorld](../papers/2609.33665.md) 把模拟服务组合成可验证的跨服务任务；GraphForge 则保留真实文件，把验证移入锚定的评分标准。
* **办公智能体流水线：** EnvCraft（模型生成文件、状态检查脚本、2 万任务、开放）与 NexForge（真实文件、无验证器、5.6 千任务、发布模型但不发布数据）。NexForge 的 Nex-N2-Mini-35B 是开放权重基线。
* **办公智能体评测：** [GDPVal](../concepts/gdpval.md)（1,320 个任务、44 个职业、专家评分标准、与人类成果配对比较的 Elo）、Workspace-Bench、APEX-Agents、Claw-Eval、[SpreadsheetBench II](../concepts/spreadsheetbench.md)。
* **脚手架：** [OpenHands](../papers/2407.16741.md)、Codex、Claude Code，各自固定配置。
* **关键人物：** 赵峰（中国科学技术大学）与桂韬（复旦大学、上海人工智能实验室）领衔；一作苏启升（中科大、上海创智学院）；多位作者与该组的终端任务合成论文 FACET 重合。

# Q5 核心解决思路

* **种子定方向，文件定内容。** 一个种子是（职业、细化工作活动、职业特定的工作需求、16 种执行模式中的主导模式、预期输入文件族、检索到的职业证据）。只保留标注为 DIGITAL 的 O*NET 任务，剩下 246 个职业、16 个行业、891 种任务类型、3,419 个职业—任务对。工作需求只在有引用的专业段落支撑时保留。种子按职业、任务类型、模式、输入文件族上的边际覆盖贪心挑选，下载文件后再按同一规则重选一次。
* **带隐藏角色的真实文件工作空间。** 搜索智能体找到一个连贯的公开案例并以原始格式下载文件。每个文件获得隐藏角色（核心、支撑、干扰、环境），用于指导组装，但永不展示给办公智能体。
* **从证据图到任务规格。** 节点记录文件、它提供的事实及其角色；边记录跨文件依赖。图被编译为任务陈述、交付物要求、正向标准 c_k =（交付物、要求、期望值、权重、锚点 A_k ⊆ 节点、验证步骤 φ_k）和针对具体禁止结果的负向标准。智能体只看到陈述和文件；裁判看到锚点与 φ_k。
* **以执行为条件的一步修订。** 教师对每个初始规格执行一次；修订智能体阅读文件、图、评分标准和这次执行，只返回需要改动的字段。仅当任务陈述改变时才重跑教师；否则原轨迹按修订后的标准重新评分。81.6% 的 rollout 得以复用。
* **准入。** 先做确定性检查（文件名、可读格式、必需的工作表与公式），再由裁判打分 Q = (Σ w_k a_k − Σ λ_j v_j) / Σ w_k，其中 a_k 为该标准的满足比例，准入阶段违规为二值；Q > 0.90 准入，并丢弃工具使用退化的轨迹。
* **评分标准引导的拒绝采样微调。** 在 2,000 个新查询上用 SFT 模型每个采样 4 条 rollout，裁判对照评分标准联合评判这四条，最高分超过 0.95 时保留，训练一个 epoch。

# Q6 实验设计

* **语料：** 3,638 个物化任务 → 2,153 个准入 → 来自 2,150 个工作空间的 2,169 条轨迹；466 种任务类型，16 个行业中的 15 个，256 个行业—模式格子中的 164 个；96.7% 的轨迹含 PDF；平均 50.0 个助手步骤、162.0k token，1.3% 触及 262,144 token 上限。
* **流水线模型：** 工作空间构建、图与规格生成、修订、教师 rollout（Codex 脚手架）和裁判全部使用 GLM-5.2。
* **训练：** 对 Qwen3.6-27B 与 Qwen3.6-35B-A3B 做 SFT，3 个 epoch，Muon，峰值学习率 2e-5，批大小 8，打包至 262,144 token；从 35B SFT 检查点出发，在 462 条匹配轨迹上做 RFT，1 个 epoch，学习率 1e-6，三个分支仅选择规则不同（锚定裁判、看评分标准文本但看不到锚点的无锚裁判、四选一随机）。
* **评测：** GDPVal-AA（220 个黄金任务）以内部池上的 Bradley-Terry Elo 报告，GLM-5.3（OpenHands）固定为 1667，并以桥接节点做跨脚手架比较；Workspace-Bench-Lite 微观分；SpreadsheetBench II 执行准确率。Pass@1，固定脚手架配置，只在同一脚手架内比较；缺失交付物计为失败。RFT 分支与 SFT 模型直接配对比较评分。
* **审计：** 对 GDPVal 的文件哈希、13-gram 文本和职业重叠；按职业覆盖拆分的 SFT 对基础模型胜率；裁判扰动（删除被引用的工作表；篡改行、数字或引用）。

# Q8 证据质量

* **有支撑：**
  * *三个基准、两个基础模型上 SFT 均有增益。* Qwen3.6-27B：GDPVal 1380.0 → 1445.7（OpenHands）、1364.0 → 1427.4（Codex）；Workspace-Bench-Lite 56.0 → 63.7（Claude Code）、61.4 → 65.2（Codex）；SpreadsheetBench II 10.3 → 24.0、15.6 → 24.6。Qwen3.6-35B-A3B：GDPVal +101.7 / +101.4 Elo；Workspace-Bench-Lite +3.8 / +6.6；SpreadsheetBench II 2.8 → 19.3、4.7 → 18.7。
  * *跨脚手架迁移。* 所有 rollout 使用 Codex，而在 OpenHands 和 Claude Code 下增益同样成立。
  * *不是记住了 GDPVal。* 零共享文件哈希（39,201 对 260），无实质共享 13-gram，44 个 GDPVal 职业中覆盖 13 个；SFT 对基础模型的胜率在 155 个未覆盖职业任务上为 0.739 [0.671, 0.803]，在 65 个覆盖任务上为 0.692 [0.585, 0.800]。
  * *评分标准选择含有信号。* 在 Workspace-Bench-Lite 与 SpreadsheetBench II 上，锚定 RFT（+4.0 / +4.0，+1.0 / +0.9）胜过无锚（+2.5 / +1.7，−1.8 / 0.0）和随机（+1.1 / +2.8，−0.3 / −3.1）；随机选择在每个基准上都是最弱分支。
  * *裁判确实读取了被引证据。* 删除某条标准引用的工作表使该标准得分平均下降 0.377，而非目标标准平均只变动 0.016。
* **较弱或有边界：**
  * *220 个任务上的 GDPVal Elo 噪声大。* 27B 基础与 SFT 的区间重叠（[1326.6, 1432.1] 对 [1376.2, 1513.8]），无锚 RFT 分支的 GDPVal 点估计反而最高（+34.1 / +25.3），与论文偏向锚定的论点相悖，且所有 RFT 差值区间都包含零；作者自己也如此说明。
  * *裁判漏掉细粒度篡改。* 对被引证据内部的行、数字、引用篡改只使得分变动不到 0.03，作者归因于 GLM-5.2 作为智能体裁判的能力上限。同一裁判既决定准入又筛选 RFT 候选，所以能骗过它的内容错误会进入训练（读者注）。
  * *单一模型家族、单一流水线模型。* 两个基础模型均为 Qwen3.6；流水线各组件均为 GLM-5.2，生成器与裁判共享同一模型及其盲点。教师轨迹来自 GLM-5.2，而其自身（以 GLM-5.3 计）在 OpenHands 下的 GDPVal Elo 为 1667，比最佳学生高约 220 分（读者注）。
  * *规模与归因。* 2,169 条轨迹，无规模研究；没有消融把证据图、隐藏角色或修订步骤从整体流水线中单独分离。RFT 消融只隔离了选择规则，任务准入保持不变。
  * *绝对水平。* SFT 模型仍远低于前沿行（Claude Opus 5 的 1774.1 Elo、70.1 Workspace-Bench-Lite、33.6 SpreadsheetBench II）；SpreadsheetBench II 的增益起点很低（2.8 和 10.3），因此那里的 +13.7 和 +16.5 相对于弱起点显得很大（读者注）。

# Q9 贡献

* 一条合成流水线，其任务陈述与验证标准源自同一个覆盖真实文件的证据图，使每条标准都带有检查它所需的文件，而不向任务陈述泄露解法。
* 以职业为依据、按覆盖率挑选的种子，使办公智能体语料横跨 466 种任务类型和 15 个行业。
* 以执行为条件的一步修订，对照原始文件修复任务与评分标准，并复用 81.6% 的 rollout。
* 证据表明 2,169 条轨迹能在三个独立基准、三个脚手架上提升两个 Qwen3.6 基础模型，附有污染审计；并表明锚定评分标准在三个基准中的两个上可作为拒绝采样微调的选择信号。
* 开放数据与检查点。

# Q10 下一步

* **作者陈述：** 研究增益如何随更多轨迹扩展；用更强的前沿模型替换流水线和裁判中的 GLM-5.2；测试其他模型家族；扩展到更多任务族和文件类型；研究证据锚定验证与更长视野脚手架的交互。
* **分离生成器与裁判（读者注）：** 裁判敏感性审计显示其对内容层面的盲视；独立的裁判模型或针对数值标准的确定性检查，可检验准入轨迹是否带有未被发现的内容错误。
* **组件消融（读者注）：** 在 NexForge 式任务（真实文件、无评分标准）上或在同样工作空间但随机锚定标准的任务上训练，以衡量证据图本身对下游增益的贡献。
* **与本仓库的相关性（读者注）：** 隐藏角色工作空间（核心、支撑、干扰、环境）与标准级证据锚点，是评测需要阅读研究文件夹的项目智能体的可复用模式：把每条验收标准连同验证它的文件一起写出，并在文件夹里埴入看似合理但不适用的干扰项。
