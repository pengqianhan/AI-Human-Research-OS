# Q1 问题定义

* **输入 (X)：** 一张 1280×720 的 3D 开放世界场景截图和一个任务目标。目标要么以文字给出（GTAVBench），要么只作为游戏内目标画在第一张截图里（GTAVBench-AGI）；之后每执行一次动作返回一张新截图。
* **输出 (Y)：** 以 JSON 对象表示的键鼠动作：每个按键有各自的按住时长（不超过一秒）、鼠标相对位移、滚轮和按键事件。每局的结果是二值的成功或失败，由环境判定。
* **约束：** 在线 3D 任务最多 300 轮交互，基于图像的瞄准任务最多 20 轮；没有部分得分；默认情况下，模型思考时模拟暂停，只有在动作执行期间才推进。

# Q2 问题新颖性

面向基础模型智能体的游戏基准有三种形态，论文想把它们合在一起：沙盒或专门搭建的游戏里可验证的任务（MineDojo、GameWorld、OmniGameArena）；在商业 3D 世界里行动、用 OCR 或人工判断结果的智能体（Cradle、SIMA、Lumine）；以及根据视频或离线问题给游戏过程打分的基准（VideoGameBench、GameVerse、[GameHorizon Suite](../papers/2609.25001.md)）。论文声称的空缺是这样一个环境：保留真实 3A 任务的目标，从引擎状态自动验证结果，通过 web 服务器并行运行，并且能生成新的训练实例。对比表中 GTAGym 是唯一五项特性都具备的条目。

# Q3 科学假设

两个主张。第一，如果把源自游戏任务的目标在带有状态检查的环境中重建出来，结果会显示当前模型缺少哪些控制能力，这是离线评测或人工判定的游戏评测看不到的。第二，如果用 RL 在程序化生成的某一类任务实例上训练一个小模型，它会在该类的留出实例上提高，并把一部分提高带到其他类别和原版游戏中。

# Q4 相关工作与关键人物

* **商业游戏中的基础模型智能体。** Cradle（在《荒野大镖客 2》中用截图和键鼠控制）、SIMA 与 SIMA 2、Lumine（端到端策略，人工评测），以及 OctoGTA（通过脚本插件和程序化动作函数接入 GTA V）。
* **游戏基准。** Procgen 和 MineDojo 用于 RL 泛化和可配置任务；lmgame-Bench、Orak、VideoGameBench 覆盖多款游戏；GameWorld（状态可验证的浏览器任务）、OmniGameArena（自制 UE5 游戏）、GameVerse（用 VLM 对 3A 游戏做里程碑打分）、GameHorizon-Bench（离线的 3A 游戏评测，可验证的在线赛道在 Minecraft 中）。
* **协议来源。** OSWorld 式的基于截图的电脑操作评测，以及第二个分支所用的 Codex harness。
* **关键人物。** Jiajun Chen、Shicheng Fang、Jiahao Lu、Yuxin Wang、Xipeng Qiu（后两位为通讯作者），来自上海创智学院（Shanghai Innovation Institute）和复旦大学；Hugging Face 页面列出的组织是 OpenMOSS。3D 环境建立在开源的 GTA_SZ 项目之上，致谢中有说明。可能的批评者：Cradle、Lumine 这类原生游戏智能体的作者，他们会指出该基准的在线赛道是重建的环境，不是商业游戏本身。

# Q5 核心解法

重建的是任务目标，而不是游戏本身。

1. **任务抽取。** 根据攻略视频，人工把 75 个 GTA V 主线任务拆成子任务，每个子任务有目标、要求的交互顺序、完成约束和实体行为。由此得到十一个类别共 150 个任务。
2. **重建。** 在线场景用 Babylon.js 搭建，任务控制器暴露状态。路线从原游戏小地图上描出来，再在现有的城市几何中找转弯次数相近的路线；NPC 行为和碰撞减速等机制是预先定义的。论文说这些场景保留了目标、交互依赖和移动约束，同时调整了空间布局。射击和狙击任务则建立在 GTA V 的画面上，并标注了命中区域。
3. **基于状态的评分。** 每个任务都有可执行的成功和失败谓词，作用在引擎状态上：带移动方式要求的目的地区域、高度和深度容差、全程不得超出的跟随距离、要求把目标速度压在 3 m/s 以下并保持 1.5 秒的拦截、要求连续六十秒不被发现的逃脱。智能体自己宣称完成不算数。
4. **两个分支。** GTAVBench 给文字指令，保留十对截图和回复的历史。GTAVBench-AGI 只在第一张截图里显示指令，并让模型运行在 Codex harness 中，后者保留更长的历史并自动压缩。
5. **RL 实例生成。** 模板固定场景、资产、交互逻辑、评估器和预算；用户设定数值范围或候选集合（路线长度、转弯次数、角色速度、追捕者数量），基于规则的生成器按种子采样出可行的实例，并带有稀疏的结果奖励和终止信号。

# Q6 实验设计

* **模型。** GPT-6-Astra 和 GPT-6.1-Sol（推理强度 high），DeepSeek-V4.1-Flash-1017、GLM-5.3-Flash、Kimi-K3（max），Qwen3.8-27B（xhigh）；温度 0.7，每个配置三个随机种子，两个分支都评测。
* **人类基线。** 三位有经验的 GTA V 玩家，每人通过任务界面把 150 个任务各尝试一次。
* **分析。** 从轨迹检查中总结的四种失败机制；人工标注首个错误（感知、规划、校准、调节）并用“十次决策内恢复”的标准判断是否恢复；harness 的利弊；动作时长上限（0.5 秒、1 秒、2 秒）以及不暂停的评测，后两项都用 GPT-6.1-Sol 加 Codex 在 103 个在线任务上做。
* **RL。** 生成 50 个步行实例，匹配基准中该类别的路线长度与转弯次数分布，并在空间上与基准路线分开。Qwen3.8-27B 在 Codex harness 内用 [GRPO](../concepts/grpo.md) 训练，LoRA 秩为 32，加在注意力的 query 和 value 投影上，每次更新四个任务、每个任务八条轨迹；终局奖励为成功，加上失败轨迹上权重 0.3 的距离进展项，超过 100 轮扣 0.1。评测覆盖留出的步行任务、其余十个类别，以及来自 49 个原始任务的 100 个原版 GTA V 任务。

评测设计与基准的主张相符。RL 设计只测试了一个任务类别，而且是基础模型最容易取得进展的那一类；原版游戏检验是唯一真正运行商业游戏的地方。

# Q7 数据集与代码

GTAVBench：103 个在线 3D 任务（公路 20、步行 16、水域 11、垂直 5、空中 8、室内 8、跟随 6、拦截 13、逃脱 16）和 47 个基于图像的任务（射击 24、狙击 23）。代码链接为 https://github.com/ljbro/GTAGym，数据集为 https://huggingface.co/datasets/OpenMOSS-Team/GTAVBench；本笔记没有检查这两处。附录给出了完整的系统提示、AGENTS.md 环境说明，以及配合 Codex CLI 0.163.0 使用的唯一工具 `game_step` 的描述。

# Q8 证据质量

**主要结果（准确率 %，三个种子的均值与总体标准差）。**

| 模型 | GTAVBench | GTAVBench-AGI（Codex） |
|---|---|---|
| GPT-6-Astra | 66.4 ± 3.1 | 70.9 ± 4.4 |
| GPT-6.1-Sol | 66.0 ± 0.9 | 66.9 ± 1.3 |
| GLM-5.3-Flash | 38.9 ± 1.3 | 41.8 ± 1.3 |
| DeepSeek-V4.1-Flash-1017 | 33.8 ± 4.1 | 38.2 ± 2.5 |
| Kimi-K3 | 28.4 ± 0.3 | 33.1 ± 2.2 |
| Qwen3.8-27B | 24.2 ± 0.8 | 34.2 ± 3.1 |
| 人类（三位玩家） | 89.8 ± 1.4 | |

各类别的分布才是主要发现。两个 GPT 模型在两个分支下的步行、水域、垂直和室内导航上都超过 90%；但空中导航在文字分支下所有模型都是 0%，用 Codex 时最高也只有 8.3%（人类 45.8%）；拦截在文字分支下两个 GPT 模型都是 5.1%（人类 82.1%）；逃脱最高 25.0%（人类 81.3%）。四个非 GPT 模型在两个分支下的拦截都是 0%，公路驾驶在 1.7% 到 23.3% 之间。

**首个错误与恢复。** 在每个模型一次文字分支运行（共 900 条轨迹）中，565 条找到了首个错误：感知 112、规划 96、校准 157、调节 200，校准和调节合计占 63.2%。十次决策内恢复的比例，Astra 为 65.7%，Sol 为 49.3%，其余四个模型为 21.6% 到 25.6%；合并统计为 565 个中的 179 个。

**评测设置（GPT-6.1-Sol 加 Codex，103 个在线任务，默认设置下 62.1%）。** 把按键时长上限设为 0.5 秒，准确率升到 66.3%，轮数（62.6 到 121.2）和输入 token（每任务 4.32M 到 11.20M）大约翻倍；上限设为 2 秒则降到 60.5%，此时 66.6% 的动作超过一秒。让模拟在推理期间继续运行，准确率跌到 39.8%，跟随、拦截和逃脱全部为零，而步行和室内导航仍是 100%。

**强化学习（Qwen3.8-27B，Codex harness，三个种子的均值）。**

| 划分 | 训练前 | 训练后 |
|---|---|---|
| 步行导航（留出，16 个任务） | 54.2 | 72.9 |
| 其余十个类别 | 31.8 | 34.8 |
| 总体（150 个任务） | 34.2 | 38.9 |
| 垂直 / 水域 | 46.7 / 57.6 | 73.3 / 69.7 |
| 公路 / 空中 / 拦截 | 3.3 / 0 / 0 | 3.3 / 0 / 0 |
| 射击 | 73.6 | 68.1 |
| 原版 GTA V（100 个任务） | 15 | 23 |

**证据的局限（读者观察）。**

* 在线赛道是用 Babylon.js 重建的环境，布局经过调整，NPC 是脚本驱动的，并不是 GTA V。“真实 3A 游戏任务”指的是目标的来源。商业游戏只出现在 100 个任务的迁移检验中，而那里的成败由人看录像判定，没有报告重复次数，也没有分类别的结果。
* 标题中的“最佳配置”（Astra 加 Codex，70.9 ± 4.4）只比另外三行 GPT 结果（66.0 到 66.9）高出大约一个种子标准差。论文说 Codex 分支对六个模型都有帮助，方向上没错，但提升幅度从 0.9 到 10.0 个百分点不等，只有较大的那些超出了种子间的波动。
* GTAVBench-AGI 同时改了两件事：指令出现的位置，以及历史的管理方式（Codex 的长历史加压缩，对比十对截图的窗口）。harness 分析是定性的，所以提升无法归到其中某一项。分析中还记录了压缩会丢掉目标：Kimi-K3 在一次压缩后把“上屋顶”的目标换成了驾驶目标。
* 所有主要得分都是在“暂停、回合制”下得到的。不暂停的消融表明，动态类别在实时延迟下全面崩溃，所以与人类 18.9 个百分点的差距低估了真实游戏方式下的差距。
* 换算成任务数（读者根据百分比计算），RL 的提升大约是 16 个步行任务中多做对 3 个，其余 134 个任务中多做对 4 个；其中垂直和水域各多约 1.3 个，射击少约 1.3 个。“迁移到分布外类别”这一说法建立在两个最接近步行的移动类别里的少数几个任务上。训练前的数字与主表中的那一行相同，所以三个种子是评测种子；训练跑了几次没有说明。
* 首个错误的标签是人工标注的，而且每个模型只取了一次运行；没有报告标注者之间的一致性统计。
* 人类基线是三位玩家、每个任务一次尝试，而人类在空中任务上也只有 45.8%，所以这个类别可能对任何人来说都难以通过这套界面控制。

基准结果在定性形态上是可靠的：步行导航满分的模型不会飞、不会拦截、不会逃脱，瓶颈更多在时机和连续调节，而不是感知或规划。RL 和原版游戏迁移的主张属于概念验证。

# Q9 贡献

1. GTAGym：一个通过 web 提供的环境，具有统一的截图与动作接口、并行执行，以及针对源自 GTA V 任务的引擎状态结果检查。
2. GTAVBench（150 个任务、十一个类别）及其 GTAVBench-AGI 分支，附六个模型的结果和人类基线。
3. 一个基于模板的 RL 实例生成器，带自动奖励和终止信号，并用步行导航上的 LoRA GRPO 做了演示。
4. 一套错误分类和恢复分析，以及动作时长上限和推理期间是否暂停如何改变结果的测量。

# Q10 后续方向

* **把实时评测作为默认。** 暂停消融提示，动态类别应同时报告暂停和不暂停的得分，或者按延迟预算计分（读者建议）。
* **把 harness 和指令形式分开。** 在 Codex 里用文字指令、在十对窗口下用图内指令各跑一次，把两项改动拆开（读者建议）。
* **在困难类别上做 RL。** 在生成的拦截、逃脱或驾驶实例上训练；基础模型在这些类别上接近零分，稀疏的结果奖励几乎不提供信号；步行任务的奖励已经为失败轨迹加了距离进展项。
* **重建环境的保真度。** 用那 100 个原版任务，报告同一模型在重建环境和原版 GTA V 中分类别结果的一致程度。
* **动作时长的控制。** 允许时模型会选很长的按键时间（2 秒上限下 66.6% 的动作超过一秒），被迫用更短的步长时表现更好，但 token 成本是两倍以上。模型能否通过训练或提示学会自己选择步长，仍是开放问题。
* **与本项目的关系。** “首个错误”加“十次决策内恢复”的做法可以复用到其他长任务上：只看最终成功与否，看不出模型能不能自我纠正（读者联想）。
