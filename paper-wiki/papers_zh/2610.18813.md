# 一句话概要

许多智能体系统如今不再重训模型，而是改写模型周围的软件（提示、记忆、工具和控制代码）来提升表现。这篇论文为这种做法给出定义、一张"改的是什么"的地图，以及一条决定是否保留改动的统计规则：只有当改动在搜索从未见过的新任务上胜过当前版本，且胜出幅度足以排除运气时，才予以接受。适合构建或评测自我改进型 harness 的人阅读，也适合需要判断这类系统能否被托付持久性改动的人。

# 概览

**范围。** *Harness* H 指在任务环境 E 中支配模型 M 运行的软件与配置。一次运行产生轨迹 τ ~ Run(M, H, E)，由最终评估 y = J(τ) 打分；候选改动可以修改 H 内部的评判器或临时检查，但不能修改 J。表 1 列出 harness 的七种运行时功能（实现中可以合并）：智能体循环与执行控制；工具与技能编排；上下文构建；记忆与状态管理；上下文压缩（compaction）；调度与协作（子智能体、后台任务）；执行基础设施（沙箱、权限、审批、日志、回放）。

**Harness 自演化。** 第 k 轮，现任 harness H_{k-1} 产生一批 b 条轨迹，更新算子（诊断、提议、评估、准入）返回 H_k；若无改动被接受，则 H_k = H_{k-1}。两条要求使它成为一个生命周期而非一次性编辑：*运行反馈与更新连续性*（系统从自身执行中以算法方式构造或选择改动，并保留继续更新的机制；人与自动评估器都可以提供反馈，准入也可以需要人工批准），以及*跨运行持久化*（被接受的改动被存储，并在之后的运行中加载）。两条都满足时，观察到一次更新就足以证明该能力。按固定规则追加日志或压缩上下文不算修改 harness；学会可复用的流程或改变记忆策略才算；修改更新机制本身则再增加一层递归。

**术语。** *自演化*（self-evolution）指更新过程，*自我改进*（self-improvement）指经比较确立的增益。"Harness RSI"是这一研究方向的名称，并不预设每次改动都有益。只改权重的适应、以及没有更新机制的脚手架都不在范围内；若系统也训练权重，则在固定任务模型的前提下考察其 harness 更新。

**为什么改 harness 而不是权重。** 论文给出三点理由：harness 直接塑造固定模型的行为，可以保存任务约束和失败教训；改动复用已部署的模型（包括拿不到权重的专有 API），省去重训和额外检查点；指令、记忆和代码可以直接检查、比对版本和追踪变更，而要归因两个检查点之间的行为差异则需要受控实验。

**读了什么。** arXiv v1 是十页正文加一个附录，附录列出一份配套技术报告（"Harness Self-Evolution: Theory, Algorithms, Evaluation, Applications, and Impact"，托管在 OpenReview）的目录；更广的文献、评测一章（任务分数背后的四个主张、当前做法、纵向评测）和社会经济一章都在那份报告里。摘要所说的"66 页讨论"指那份报告和 GitHub 材料，本笔记没有阅读。

# 框架

论文把一个方法需要说明的三件事分开：*更新目标*（之后的运行继承什么状态）、*提议*机制和*准入*机制。其分类法只对第一项分类。

| 分支 | 改的是什么 | 论文归入的例子 |
|---|---|---|
| 解释型状态更新 | 指令与提示、存储的经验、在预定义能力之上的任务级协调（在固定算子之间路由的工作流，包括只组合这些算子的代码） | GEPA、Promptbreeder、ExpeL、Agent Workflow Memory、AFlow |
| 可执行：工具与代码补丁（3.1） | 可调用的过程或指定模块，外围编排不在可编辑范围内 | Voyager 与 PolySkill 的技能库；Self-Harness、HarnessCompass、Agentic Harness Engineering 只修补选定组件；MemEvolve 修改记忆管理函数；HarnessBank 保存候选档案 |
| 可执行：仓库与运行时逻辑（3.2） | 上下文构建、编排循环、执行钩子、恢复与终止：即对组件之间交互的控制，而非改动了多少文件 | ADAS、Meta-Harness、自我改进编码智能体（SICA）、Darwin Gödel Machine、DarwinX、Huxley-Gödel Machine；RRSI 与 MOSS 增加编辑约束和面向迁移的准入；VERSE 让优化器自身的提示、钩子和工具也可演化 |
| 可执行：一切皆插件（3.3） | 组件实现，或决定由哪个实现提供某项运行时服务（记忆存储、工具分发、智能体循环）的*绑定* | DeepSeek harness 与一种时空可组合编程范式作为内核底座；HarnessX、Argus、Autogenesis、ModularRSI 修改带类型的原语或限定范围的模块；Everything Is a Plugin（EIP）把它扩展到运行中生成、验证并挂载的能力 |

两条规则划定边界。解释型与可执行的界线取决于被编辑工件的*角色*，而非其编程语言：用代码写成的工作流，只要还只是给固定算子排序，就仍属解释型；一旦改动算子实现或协调运行时，就成为可执行改动。插件组合描述的是绑定而非范围，所以一次改动可以同时属于多个可执行类别。对目标分类并不说明方法是否满足反馈、连续性和持久化要求；导出的程序只有在部署后仍保留更新机制才算数，而进入档案也不等于被采纳，除非选中的程序被提升到之后任务所用的运行时里。

# 关键技术

**用进化算法解读 harness 搜索（4.1 节，图 2）。** 一次更新有四个方面：可变状态的表示、生成编辑的变异（轨迹和评语可以引导它）、适应度评估，以及保留哪个状态的选择。图 2 把方法对应到八种结构，并说明每种类比的限度：

* *精英 (1+1)*：一个候选与现任比较（SICA；MCE 作为利用历史的 (1+1)-ES；SkillOpt；SkillOpt-Lite；SkillClaw）。
* *精英 (1+λ)*：同一父代的多个编辑（Self-Harness；其之后的合并不同于经典的单幸存者规则）。
* *基于档案的搜索*：保留程序谱系，用于选父代和代码变异（DGM、DarwinX、HGM；这一类比不意味着使用树形遗传编程算子）。
* *重组*：组合先前候选的材料（DarwinX、HarnessCompass、Self-Harness、MCE 的智能体式交叉；Trace2Skill 的整合本身不构成进化循环）。
* *质量-多样性*：按语义划分档案格并保留局部精英（HarnessBank，修改了 MAP-Elites 的父代选择并加入验证闸门）。
* *协同进化*：分别优化组件后再组合（HarnessCompass，但没有独立演化的子种群）。
* *帕累托选择*：成本-性能前沿或多条准入标准（Meta-Harness、Self-Harness、SkillMOO；并非 NSGA-II 那样完整的多目标进化算法）。
* *赌博机引导的进化*：用 Thompson 采样分配搜索预算（HGM，涵盖谱系扩展和候选评估）。

这些结构都按经验适应度做选择，被接受的改动可能过拟合或遗忘，这就引出下一部分。

**三条有条件的保证（4.2 节）。** 演化状态 X_k（harness、技能、档案、反馈记忆）用 n_k 个任务更新，这些任务独立地取自一个外生分布；模型和评估器固定，损失取值于 [0, 1]。

1. *由稳定性得到期望泛化。* 把一个任务换成新抽的任务，在耦合的随机性下重跑所有下游更新（反馈、档案、选择），令 β_{s,k} 为平均损失变化。则真实风险与经验风险之差的期望不超过 β_{s,k}。这只约束期望差距，不约束任何一次运行；而代码改动小，并不能单独推出整个更新过程是稳定的。
2. *在回退预算下的保持。* 把遗忘定义为第 s 轮任务上的风险自 H_s 以来的变化。若假设之后每一步转移使第 s 轮风险至多上升 ε_{s,u}，伸缩求和得到 E R_s(H_k) ≤ E R̂_s(H_s) + β_{s,s} + Σ_{u>s} ε_{s,u}。这些预算是假设而非稳定性的推论，其额度会累加；要检验它们，需要对部署后的组合（包括合并的编辑和共享路由器）做分组的不确定性控制。
3. *用新验证集准入。* 在 T 轮中每轮至多 K 个候选，从均匀的历史混合分布中抽取 m 个独立的新任务，且与候选的构造方式无关。成对损失差落在 [−1, 1]，用条件 Hoeffding 界加上对 KT 次比较的并集界，得到以至少 1 − δ 的概率成立：Δ_k(H′) ≤ Δ̂_k(H′) + √(2 ln(KT/δ)/m)。只接受上界为负的候选。若评估器与目标风险对每个 harness 可能相差至多 η，充分条件变为 Δ̂ + √(2 ln(KT/δ)/m) + 2η < 0，而 η 本身需要可执行检查或独立人工评估提供证据。

适用范围的说明也是结果的一部分：样本量是独立任务的数量（多跑几次只降低执行噪声，并不增加任务）；相关的会话需要分组；不可加的指标需要各自的集中不等式论证；证书只覆盖历史混合分布，而非任意未来分布。受验证集启发的编辑或合并需要再次用新数据验证。论文点名两个不满足独立性假设的搜索期检查：HarnessBank 在单独的最终测试之前复用训练任务做筛选，Self-Harness 复用一个留出的回归划分。把划分保密或按比较次数做校正都不能消除自适应依赖；需要新样本，或适用于自适应数据分析的推断方法（Dwork 等）。

**读者对准入规则要求的一个估算。** 在本 wiki 常见的验证集规模下，余量 √(2 ln(KT/δ)/m) 并不小。取 K = 5 个候选、T = 10 轮、δ = 0.05，则 ln(KT/δ) = ln 1000 ≈ 6.9，m = 100 个任务时余量约 0.37，m = 500 时约 0.17，m = 1,000 时约 0.12。在 [0, 1] 的损失上，候选要在 100 个新任务上比现任好约 37 个百分点才能获得证书。这条规则是最坏情况界；它说明的是当前小划分准入闸门离证书有多远，而不是推荐做法（读者构造的例子，论文中没有）。

# 案例

### 代表系统

* **HarnessOpt 在 SpreadsheetBench 上（3.2 节，表 2）。** 由 SkillOpt-Lite 表 3 的比例换算而来。HarnessOpt 把 SkillOpt-Lite 从编辑技能扩展到修改运行时：更好的表格预览、输出检查和工具失败后的恢复。各列为初始、SkillOpt、SkillOpt-Lite、仅 HarnessOpt、HarnessOpt 加技能的准确率（%）：

  | 模型 | 初始 | SkillOpt | SkillOpt-Lite | 仅 HO | HO + 技能 |
  |---|---|---|---|---|---|
  | GPT-5.4-nano | 29.89 | 51.60 | 66.19 | 76.51 | 77.58 |
  | GPT-5.4-mini | 28.21 | 47.50 | 73.31 | 81.14 | 82.56 |
  | GPT-5.4 | 39.86 | 61.50 | 79.36 | 83.63 | 85.05 |
  | GPT-5.5 | 37.37 | 76.20 | 79.72 | 83.63 | 85.77 |

  使用 HarnessOpt 加技能的 GPT-5.4-nano（77.58）超过使用 SkillOpt 的 GPT-5.5（76.20），HarnessOpt 加技能在四个模型上比 SkillOpt-Lite 高 5.69 到 11.39 个百分点。论文把这解读为模型与 harness 的搭配，并明确说它不能证明在相同成本下更优。这些数字与本 wiki 的 [SkillOpt-Lite](../papers/2607.03451.md) 笔记一致（0.7758 对 0.7620）。
* **通过 DSH Everything 实现的"一切皆插件"（3.3 节，表 3-4）。** 一个 Codex 插件让智能体在执行中生成工具并留给之后的任务。在模拟办公负载上（来自公司不同地区、计算方式相同的电子表格），Codex 创建了批量查找和汇总工具：第一个任务的工具调用从 13 次降到 3 次，而 token 从 41,119 增至 47,572（+15.7%），墙钟时间从 15.49 秒增至 24.00 秒（+54.9%）。另一组单独报告的累计数据显示，从第二个任务起开始节省，五个任务后累计省下 110,351 个 token 和 22.97 秒。论文自己指出了不一致：第一个任务的总数意味着 +6,453 个 token 和 +8.51 秒，而累计表第一行写的是 +4,895 和 +6.74，因此两组数据不能当作同一条成本轨迹。同一来源还报告 LiveBrowseComp 上 "XYZ + dsh-everything" 得 51.39，XYZ-Aquila-mini 得 48.7，在 40B 以下的六项中排第一、十一项中排第二（XYZ-Aquila-pro 为 53.7），单位未说明。论文表示，要把这些说成插件带来的因果增益，需要重复运行、匹配预算和匹配任务质量。

### 应用领域

第 5 节讨论持久化改动在五种场景中的作用，以及软件回滚无法挽回的后果。

* *个人工作区*（Claude Code 记忆、GitHub Copilot Memory、智能体技能）：临时变通会变成常设规则，被注入的指令会跨任务持续存在，成功的执行也可能产生泛化有害的技能；恢复必须覆盖派生的技能、记忆和缓存，而不只是被版本跟踪的代码。
* *企业自动化*：本地的变通做法会扩散到权限或数据假设不同的团队，共享的错误流程会造成相关性错误（把算法单一化问题延伸到 harness 工件上）；与版本关联的部署记录和分阶段发布有助于控制影响。
* *科学发现*：利用临时检查的演化流程，可能强化在独立测量下失败的做法，而代价（仪器时间、试剂）在发现之前就已付出；J 必须留在可编辑范围之外，并辅以独立复现。
* *机器人*：EMHO 和 RoboRSI 围绕冻结模型修改规划和技能；被接受的动作代码可能造成过大的力或不安全的恢复，回滚无法逆转。急停、力与速度上限和授权检查应留在可编辑范围之外。
* *公共服务与临床系统*：重要改动必须由合格的专业人员授权；每个决定都应记录其规则版本、证据和准入历史，并提供复核与申诉。

# 证据边界

* **论文本身确立了什么。** 一个带两条可检验要求的定义、一条更新目标的分类规则、方法到进化算法结构的映射，以及由标准结果（Shalev-Shwartz 等的替换一个样本稳定性、Hoeffding 加并集界）推出的三条界。这些界在其假设下是正确的推论；没有一条在运行中的系统上检验过。
* **假设排除了多数现有做法，论文自己也承认。** 任务独立地取自固定分布、评估器固定、新验证集与候选构造无关、回退预算是假设的。论文点名 HarnessBank 和 Self-Harness 违反独立性；上面的读者估算还表明，即便独立，常见的小验证划分也难以满足准入规则。
* **没有新实验。** 表 2-4 和图 3 都是从其他来源换算或改编的。表 2 来自 SkillOpt-Lite（Shen、Li、Zhang），其第一作者与本文通讯作者同名（Yifei Shen）。EIP 的数据来自 Runqi Pan 的一篇知乎回答，以及署名 Yifei Shen 的 DSH Everything 仓库（所有者 `yshenaw`）。两者都未经同行评审，论文自己指出了两组数据之间的数值不一致，LiveBrowseComp 里的 "XYZ" 模型也未说明是什么。图 3 的延迟曲线来自一篇 2023 年的边缘 AI 论文（Shen 等），场景是固定部署，引用它是为了说明值得研究组件放置位置，而不是 harness 演化。
* **分类法和进化算法映射是定性的。** 图 2 说明类别之间有重叠，对应关系不等于与经典算法等价。方法归类是作者的解读，若干被引系统（Self-Harness、HarnessCompass、DarwinX、HarnessBank、VERSE）尚未收入本 wiki，所以这里没有核对其归类。
* **未读材料。** 配套报告的评测一章（包括"任务分数背后的四个主张"）和文献综述没有阅读；本笔记中关于评测做法的说法都来自短文的 4.2 节和 6.4 节。

# 要点

读者笔记，供带入自己的工作：

1. **对任何"自演化"的说法都问两个生命周期问题。** 系统是否从自己的执行反馈中构造改动，并保留再次修改的能力？被接受的改动是否会在之后的运行中加载？导出一个固定 harness 的一次性优化器不满足第一条；只在当前会话中得到、从未保存的教训不满足第二条。
2. **按角色而非文件类型给改动分类。** 只在固定工具之间路由的工作流脚本是解释型状态；动了工具实现或运行它们的循环，就是可执行改动，回退风险也更大。
3. **数独立任务，而不是数运行次数。** 在同一批任务上重复运行能降低执行噪声，但并不增加改动能够泛化的证据。
4. **把评判者和刹车留在可编辑范围之外。** 最终评估、权限、花费上限和物理安全限制都不应是候选能修改的东西，而创建一项能力也不应同时授予使用它的权限。
5. **与本项目的契合。** 本仓库自己会更新的几层（认知缓存、项目记忆、已安装的技能）在论文意义上满足两条生命周期要求：它们根据会话反馈修订，并被之后的会话加载。它们目前的准入是人工审阅和 `verify.sh`，后者检查结构而不检查改动是否有益；论文的框架提示，可以为每次修订记录是什么证据让它被接受。

# 开放问题

* 新的独立验证集要多大，准入规则才能接受现实中的改进？序贯方法或适用于自适应数据分析的方法能否用更少任务证明更小的增益？（读者从 4.2 节提出的问题）
* 在相同的适应成本和执行成本下，应如何在模型选择、技能优化、运行时修改和权重更新之间分配精力？冻结的、迁移的或重新演化的 harness 能否在不同模型检查点之间保住增益？（作者，6.1）
* 一个生成的插件要在多少个相关任务之后、在相同质量下，才能收回生成和验证的成本？保留的工具何时应重新验证、重新生成或退役？（作者，6.3）
* 评估器变化后（评判偏差、漂移），如何为评估器与目标之间的差异 η 定界？校准、准入和回退检查之间应如何分配预算？（作者，6.4）
* 依赖关系变化时，如何验证组合后的行为并撤销权限，使一个局部有效的插件不能在不被察觉的情况下改变共享状态或其他组件？（作者，6.3 与 6.5）
