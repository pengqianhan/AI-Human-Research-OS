# Q1 问题定义

* **输入（X）：** 一个包裹固定模型的驾驭层（harness）H_θ（提示词、工具接口、运行时控制逻辑）；互不相交的训练集、开发集和测试集；一个把执行记录转化为驾驭层更新的固定优化器 O；以及共享的 rollout 预算（训练集加开发集规模的十倍）。
* **输出（Y）：** 一个课程策略 π，在每次迭代中挑选至多三个训练场景组成批次 X_t 去执行；以及从由此产生的优化轨迹中按开发集表现选出的最终驾驭层。
* **核心问题：** 自动驾驭层优化器决定*如何*依据反馈更新驾驭层，但产生反馈的场景是事先定好的（完整训练集，或预先打乱的小批次序列）。随着驾驭层变化，固定的安排可能过早放弃仍未解决的失败、把 rollout 花在已解决的场景上，也无法在"修复已知弱点"和"寻找新弱点"之间调整。
* **形式化框架：** 固定优化器，在每种策略相同的 rollout 预算下，求 π* = argmax_π E[J(θ̂_π)]，其中 J 是总体表现，θ̂_π 是按开发集选出的驾驭层。

# Q2 问题新颖性

作为驾驭层优化的问题框架是新的。自动课程学习（学习进展赌博机、师生式任务选择、优先级关卡重放）在训练模型权重时已很成熟，但那里目标和进展信号都是显式的。这里一个场景并不对应某个固定弱点：弱点只在执行后才显现，同一场景会随驾驭层变化暴露不同失败，同一弱点会在不同场景中重复出现，也没有损失函数告诉你它是否仍未解决。相近的驾驭层工作在评估一侧做任务选择（Task-CoEvolve 挑选能区分候选驾驭层的验证任务；HarnessLens 为每个修改挑选验证任务），CoEvolve 则为权重更新生成训练任务。ActiveSaddler 调整的是为每次驾驭层更新提供证据的*训练*场景。

# Q3 科学假设

如果课程（a）按底层驾驭层弱点而不是按基准类别或单个场景把失败分组为"臂"（arm），（b）每次迭代按估计的剩余学习进展重新给这些臂打分，（c）自适应地决定何时探索未见过的场景，那么同一个驾驭层优化器在相同 rollout 预算下会找到更好的驾驭层，并且这三个设计各自都是必需的。

# Q5 关键解法思路

* **失败模式臂。** 每个优化步骤后，失败模式提取器（Failure-Pattern Extractor）先把每次失败执行抽象为候选症状（此时不看已有的臂），再把候选症状与臂集合归一化：链接到已有模式、组合已有模式，或新建一个臂。每个臂保存描述、支撑它的训练场景，以及观察到该模式时的驾驭层与诊断证据。臂在优化过程中产生，没有预先定义。
* **臂优先级器（Arm Prioritizer）。** 一个 LLM 依据四个因素给每个臂的学习进展 φ_t(a) 打 [0, 1] 区间的分：严重性（该模式在当前驾驭层下是否仍活跃）、可修复性（驾驭层改动能否解决）、广度（修复能推广多远）和副作用风险。每次选择时重新打分，转为温度 0.15 的 softmax 后采样，因此高分臂占主导，但低分臂仍有机会被选中。
* **探索控制器（Exploration Controller）。** 一个独立的智能体会话每次迭代做二选一：抽取（Draw，从未见场景池中无放回采样）或拉动（Pull，优化一个已知臂）。当所有场景都探索过、每个臂也都访问过之后，从未生成臂的早期成功场景会重新进入候选，从而无需重跑全部场景就能重新发现回归。
* **具体实现。** 三个组件运行在 GitHub Copilot SDK 上，共享一个通过 CLI 访问的模式注册表。AutoSaddler 自身的循环（诊断与补丁、在批次和开发集上评估候选、反思、EvoDAG 更新）保持不变；其补丁前和补丁后的失败都交给提取器。

# Q6 实验设计

* **基准与划分（沿用 AutoSaddler）：** GAIA2 按 Universe（人物设定）划分：训练用 Universe 29（75 个任务），开发用 Universe 30（65），测试用 Universe 21、22、27（300）。Terminal-Bench 2.0 随机划分：训练 30、开发 19、测试 40。
* **模型与预算：** 任务智能体（中等推理强度）和优化器会话（xhigh）都用 gpt-5.5；GAIA2 预算 1,400 次 rollout，Terminal-Bench 2.0 为 490 次；所有方法每次迭代至多三个场景。
* **对比对象：** 基础驾驭层；GEPA、Meta-Harness，以及使用随机固定场景顺序的 AutoSaddler；按类别准确率或场景准确率从易到难排序的 AutoSaddler（排序依据基础驾驭层的五次运行估计，这些 rollout 计入预算）；Terminal-Bench 2.0 上的 Terminus-KIRA。
* **消融：** 用类别级或场景级臂替代失败模式臂；所有臂同分（无优先级器）；每五次迭代固定探索一次（无控制器）；非 LLM 替代方案（仿 TSCL 的 EMA 失败持续度打分、基于计数的 UCB-AIR 探索规则）。
* **稳健性与迁移：** 对 AutoSaddler、两种固定课程和 ActiveSaddler 做第二次独立的 GAIA2 优化运行；把 ActiveSaddler 套在 GEPA 上测试 GAIA2。
* **报告方式：** 每个优化后的驾驭层做三次测试时执行，报告测试 Pass@1 的均值 ± 标准差；端到端成本计入优化器一侧的 LLM 用量。

没有新基准；GAIA2 和 Terminal-Bench 2.0 都是已有基准。arXiv 备注指向一个[项目主页](https://autosaddler-projectpage.github.io/activesaddler/)"及代码"，摘要说代码"将会公开"，可复现性声明提到一个存放提取技能的匿名仓库。附录给出了三个课程会话的全部提示模板、模式注册表 CLI、数据划分和超参数，以及发现的全部失败模式列表（GAIA2 上 35 个，Terminal-Bench 2.0 上 15 个）。

# Q8 证据质量

* **有支撑的：**
  * *头条结果。* GAIA2 测试 Pass@1：ActiveSaddler 59.8 ± 1.0；对比 AutoSaddler 55.4 ± 1.2（随机固定顺序）、按类别和按场景难度排序的 55.9 和 55.7、GEPA 和 Meta-Harness 的 54.2、默认智能体 53.6。Terminal-Bench 2.0：80.0 ± 2.5；对比 AutoSaddler 72.5、两种难度排序 70.8 和 73.3、GEPA 65.8、Meta-Harness 66.7、Terminus-KIRA 69.2、Terminus 2 64.2。
  * *第二次运行结论一致。* 在独立的第二次 GAIA2 运行中，ActiveSaddler 为 61.6，AutoSaddler 为 56.6；两次运行中 ActiveSaddler 在每个留出 Universe 上都胜过所有固定顺序基线，第一次领先 3.9-4.4 分，第二次领先 5.0-5.7 分。
  * *不依赖某一个优化器。* 套在 GEPA 上后，GEPA 的 GAIA2 Pass@1 从 54.2 升到 57.2。
  * *每个组件都必需。* 在 GAIA2 上，类别臂或场景臂为 56.8 和 56.2，无优先级器 55.3，固定探索 55.3；在 Terminal-Bench 2.0 上分别为 69.2、73.3、72.5 和 71.7。EMA 打分（56.7）和 UCB-AIR 探索（55.6）也都不如 LLM 组件。
  * *机制诊断。* 失败模式臂使 52.9% 的 GAIA2 小批次包含仍未解决的失败，类别臂为 36.4%，场景臂为 17.6%；Terminal-Bench 2.0 上分别为 60.4%、30.5% 和 36.6%。在 GAIA2 上臂池从 6 个增长到 35 个；到最后一次选择时，所有支撑场景都已通过的 24 个臂只占 26.2% 的拉动概率，而均匀分配时应为 68.6%。抽取占决策的比例从前半程的 44% 降到后半程的 20%；拉动决策时未解决臂的数量是抽取决策时的 2.0 倍（GAIA2）和 6.9 倍（Terminal-Bench 2.0），固定安排下则为 0.8 倍和 1.3 倍。
  * *成本。* 每生成一个补丁的优化器成本在 GAIA2 上从 7.87 美元升到 11.44 美元，在 Terminal-Bench 2.0 上从 6.77 美元升到 11.37 美元；但 ActiveSaddler 以 298 美元达到 58.5% 的 GAIA2 开发集准确率，AutoSaddler 需要 1,360 美元；以 128 美元达到 78.9% 的 Terminal-Bench 2.0 开发集准确率，AutoSaddler 需要 220 美元。
* **较弱或有边界的：**
  * *测试集小，方差只覆盖测试执行。* Terminal-Bench 2.0 的测试集只有 40 个任务，7.5 分的增益相当于 3 个任务；其开发集只有 19 个任务（一个任务约 5.3 分），而开发集同时决定驾驭层选择和成本曲线。± 值只反映同一个优化后驾驭层的多次测试执行，而不是多次独立优化；只有 GAIA2 做了第二次运行（读者注）。
  * *每个消融都落回基线附近。* 去掉任一组件都会回到大致 AutoSaddler 的水平（例如无优先级器时 GAIA2 为 55.3 对 55.4，Terminal-Bench 2.0 为 72.5 对 72.5），而 Terminal-Bench 2.0 上的类别臂甚至低于它。增益需要三部分同时存在，任何部分版本都没有帮助（读者注）。
  * *若干臂针对的是评分器的格式（读者注，依据附录 H）。* 许多 GAIA2 臂描述的是对齐 oracle 的约定，例如"序列化为 null 而不是 oracle 的空路径字符串"、"措辞偏离简洁的 oracle 风格消息内容"，或回复缺少"规范主题"。测试 Universe 的人物设定不相交，但共享 GAIA2 的检查器，因此部分测试增益可能来自学到该检查器的格式约定，而不是更通用的助手行为。作者也说明 ActiveSaddler 没有检测奖励投机（reward hacking）或规格博弈的机制。
  * *这里的 AutoSaddler 比其原论文弱（读者注）。* 本 wiki 的 [AutoSaddler](../papers/2608.23041.md) 笔记记录，使用 Claude Opus 4.6 时 GAIA2 从 53.0 升到 62.0、Terminal-Bench 2.0 从 40.0 升到 50.0。本文使用 gpt-5.5，AutoSaddler 在 GAIA2 上只提升 1.8 分（53.6 → 55.4），在 Terminal-Bench 2.0 上提升 8.3 分。骨干和预算不同，这只是背景参照而非矛盾，但 ActiveSaddler 在 GAIA2 上的领先是相对一个本身几乎没有提升的 AutoSaddler 而言的。
  * *单一模型。* 所有结果都以 gpt-5.5 同时作为任务智能体和优化器。

# Q9 贡献

* 为驾驭层优化补上了一个缺失的维度：由哪些训练场景产生反馈。在固定优化器的前提下，把它表述为自动课程学习问题。
* 从诊断出的失败在线归纳出失败模式臂，场景与弱点之间是多对多关系；实验表明它比基准类别或单个场景更适合作为优化单元。
* 基于 LLM 的学习进展打分（严重性、可修复性、广度、副作用风险）和 LLM 探索/利用控制器，并与 EMA 和 UCB-AIR 替代方案做了比较。
* 证据表明，在相同 rollout 预算下，自适应场景选择能改进两个优化器（AutoSaddler 和 GEPA），且端到端成本更低。

# Q10 下一步

* **作者陈述的局限：** 这是只在基准上评估的研究方法，没有安全、安全防护或隐私评估；驾驭层更新可能改变提示、工具和控制流，因此上线应经过独立审查、最小权限和可回滚机制，而来自真实部署的优化轨迹需要处理个人信息和密钥。
* **防止拟合评分器（读者注）：** 在失败模式提取器或臂优先级器中加入检查，标记描述"评估器格式"而非"任务行为"的臂，并分别报告包含与去除这类臂所产生补丁时的测试增益。
* **在 Terminal-Bench 2.0 上重复优化（读者注）：** 测试集 40 个任务、开发集 19 个任务，需要每种方法多次独立运行，才能把 7.5 分的差距解读为不只是几个任务的差别。
* **跨骨干检验（读者注）：** 用 Claude Opus 4.6 重跑——AutoSaddler 在该骨干上自身增益更大——看课程层是否仍能在更强的固定顺序优化器之上带来提升。
* **与本仓库的关联（读者注）：** 失败模式注册表对本仓库的定时智能体任务（例如这个每日论文任务）是一个可复用的做法：把每次失败记录为带有支撑运行的命名模式，重新处理仍然活跃的模式，只有当其支撑案例再次通过时才标记为已解决。
