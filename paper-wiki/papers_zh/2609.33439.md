# Q1 问题定义

* **输入（X）：** 一个可能跨多个领域、时间跨度很长的用户目标（贯穿全文的例子要求：调研 AI-for-AI 研究进展、复现领先算法、再做一个汇报结果的网页），一组可执行的智能体，以及一份共享的资源预算。每个智能体都是一个“模型-驾驭层（harness）”对：四个原生专家 Raven-Research、Raven-Code、Raven-Design、Raven-Oncall，一个通用 Raven 智能体，以及通过执行适配器接入的第三方智能体（Claude Code、Codex、OpenCode、Hermes Agent、OpenClaw）。
* **输出（Y）：** 一张由智能体调用组成、带显式产物依赖的有向无环图（DAG），按图执行（每次交接都记录为一个产物），最后综合出交付物。跨任务来看，系统还会产出改进后的驾驭层、存下的记忆和修订后的技能。
* **核心问题：** 智能体的实际能力既取决于模型，也取决于驾驭层（工具、上下文管理、技能、执行策略、恢复机制）。工具和运行条件越多，驾驭层越难手工设计；为某一领域调好的驾驭层又难以迁移到其他领域。作者因此追问：如何自动构建专用驾驭层，从经验中改进它们，并跨领域组合它们。
* **约束：** 能力被定义为*共享预算下的可靠任务覆盖*：验证器接受交付记录、且总成本（规划、执行者、交接、验证、重试）不超预算的概率。智能体或评审宣称“完成”不等于客观正确。

# Q2 问题新颖性

部分新颖。AutoGen、MetaGPT 等多智能体框架早已在同一个框架和控制循环内协调按角色提示的智能体；Raven 组合的则是*异构*驾驭层，各自保留自己的工具、上下文处理和控制策略，通过适配器和带类型的产物交接连接起来。大部分组件延续作者自己的前作：驾驭层演化来自 HarnessBank（arXiv:2607.13683），技能目录与检索栈来自 SkillCorpus（arXiv:2607.15557），记忆生命周期来自 [EverMemOS](../papers/2601.02163.md)（经由 EverOS 记忆层）。新的部分是：把这些整合成一个由宿主编排的生态，给出“组合何时能胜过每一个可用个体智能体”的形式化论证，以及多智能体编排基准 MAOB。

# Q3 科学假设

假设计划是一张显式的带类型图，每个节点都分配给能满足其契约的智能体，交接彼此兼容，且规划误差和各节点误差有界；那么组合系统应能在同一总预算下，可靠地解决任何一个可用智能体单独都无法可靠解决的任务。经验层面，作者预期显式的图编排比现有智能体系统的原生编排规划得更好，而按领域专门化的驾驭层在同一骨干模型、相近成本下优于通用驾驭层。

# Q5 关键解法思路

* **异构智能体注册表。** 每个条目把名称和能力描述绑定到四种后端之一：进程内 Raven 循环、命令行进程、Agent Client Protocol（ACP）连接，或 OpenAI 兼容 API。三个标志约束规划：是否有状态、能否读本地文件、是否汇报进度。宿主智能体依据这些描述用自己的模型挑选智能体，不用训练过的路由器。
* **先准入的图，而非自由消息。** 宿主上下文里只放编排指南的简短摘要，需要多个智能体时才加载完整指南。它从交付物倒推建图，提交带类型的 DAG；运行时在任何执行者启动前用五组准入检查验证它，被拒的图会返回第一个错误和指向指南的指针。执行时，依赖就绪的节点被调度，由完成评判器裁定每个节点，异常和澄清请求回传给宿主。每次交接都通过文件化的产物完成，后续图可以按引用复用。
* **共享群体记忆。** 每轮结束后，宿主把轮次摘要和对每个智能体的评估（“verdict”：收尾时一次，下一轮用户反馈后一次）写入按所有者划分的 EverOS 库，在后续规划和派发前预取。用户的个人记忆不在其中。
* **驾驭层自我演化（来自 HarnessBank）。** 冻结模型外的驾驭层被拆成记忆、规划、能力、行动四个接口，一个不可变内核保护评估与记账。演化器（Evolver）诊断失败轨迹，提出提示、知识、运行时或配置编辑；语义“基因库”按“编辑类别 × 病症”单元格各保留一个驾驭层（MAP-Elites 风格）。候选需通过有效性、激活和配对增益筛选，选中的驾驭层在留出测试前冻结。
* **记忆与技能。** EverOS 执行情景痕迹形成、语义巩固和重构式检索，分用户和智能体两条轨道。Skill Forge 把精选的 SkillHub 目录（基于 SkillCorpus）与本地技能、由记忆派生的技能融合，由 LLM 选出有限数量，并通过意图聚类和显式更新操作修订经验派生的技能。
* **理论。** 定理 1：一个有效计划的成功概率下界为 1 减去各节点与各边误差额度之和，不需要独立性假设。命题 1 再乘上宿主产出有效计划的概率。推论 1 给出*新*覆盖的条件：系统下界须高于 1−δ，而每个个体智能体的成功概率都低于它。一个构造性例子里，两个智能体各自只能读取两个隐藏比特中的一个：组合后能精确返回奇偶性，而任何一个单独作答至多一半正确。作者也指出，一个同时拥有两个读取接口的单智能体同样能解。

# Q6 实验设计

* **规划（MAOB，新建）。** 140 个请求，来自 137 种职业，借鉴 GDPval 和 JobBench 的任务结构但不复用其文本。每个请求都有一张覆盖四个专家领域（research、coding、content、oncall）的参考 DAG，全部 11 种多领域组合都被覆盖。参考图先由 Claude Opus 5 编写，再由 GLM-5.2 从图倒推生成请求；词汇过滤器剔除列出步骤或直接点名领域的请求，最后专家逐条审核。平均每图 2.72 个节点、1.84 条边；98 个纯串行，42 个含并行分支。把调用折叠到领域层级后，指标为 Node F1、基于传递约简的 Edge F1、偏序准确率（POA）和精确匹配（Exact Match）。Raven、Claude Code、Hermes Agent 分别用 Qwen3.8-27B 和 DeepSeek-V4-Flash-0731 规划，收到相同的请求文本和委派指令，提交的图直接打分、不执行任何工作节点。
* **驾驭层演化。** 论文转述 HarnessBank 已发表的结果，而非新跑实验：七个基准（Terminal-Bench-2、EvoAgentBench 的五个领域、AppWorld），冻结的 Qwen3.6-27B，留出集 Pass@1 取三次尝试平均。
* **Raven-Research。** DeepResearch Mixed 汇集 BrowseComp、FRAMES、纯文本精确匹配版 Humanity's Last Exam 和 xBench-DeepSearch，由 LLM 评审判定答案。在三个共享骨干上与 MiroFlow、DeepSeek-Harness 比较，搜索工具相同，每题一次尝试，另以三家商业服务作参考。
* **Raven-Code。** SWE-bench Pro（731 题）、SWE-bench Verified（500 题）、WorkBuddy 代码子集（80 题）、SWE-Refactor（20 个整仓迁移），在作者内部的 AgentEval 容器中用官方评分器运行；部分对比点是公开榜单数值。另用 DataAgentBench（12 个数据集上 54 个问题，五次试验）评估数据库分析。
* **Raven-Design。** PresentBench（238 个幻灯片任务，官方评估器），加上 ArtifactsBench 的 SVG 与仪表盘任务和 GDPval 交付物（由内部评分器以 GPT-5.6 Luna 为评审打分），以及七个精选展示案例。
* **Raven-Oncall。** AI4AI 任务是 autoresearch（nanochat 的单 GPU 衍生版，模型约 50M 参数：每次训练 300 秒，整个活动 5 GPU 小时，两张 A800，以验证集 bits per byte 计分），每个系统跑一次活动；AI4S 是内部的 17 个求解器、训练与模拟任务，由人工对照不公开给智能体的参考值判定。
* **技能复用。** 论文转述 SkillCorpus 已发表的结果：SkillsBench（87 题）、GDPval（220 题）、QwenClawBench（100 题），Raven 与 OpenClaw 各配 Qwen3.5-27B 和 Qwen3.5-397B-A17B。两种驾驭层收到完全相同的预计算技能选择（至多两个技能正文），每个配置取三次运行平均。

# Q8 证据质量

* **有支撑的：**
  * *MAOB 上规划图更好。* 两个骨干下 Raven 在四项指标上都领先 Claude Code 和 Hermes Agent。Qwen3.8-27B：Node F1 0.923（最强基线 0.776），POA 0.950，Exact Match 0.711（基线 0.607，+10.4 个百分点）。DeepSeek-V4-Flash-0731：Node F1 0.963（基线 0.854），Edge F1 0.897（基线 0.813），Exact Match 0.867（基线 0.762，+10.5 个百分点）。所有系统的 Edge F1 都低于 Node F1，说明依赖预测是更难的部分。
  * *研究驾驭层。* Raven-Research 在三个共享骨干上的汇总准确率都最高：56.3%（最强基线 49.7%，Qwen3.6-35B-A3B）、59.3%（56.0%，Qwen3.5-397B-A17B）、76.5%（68.9%，DeepSeek-V4-Flash）。在 DeepSeek-V4-Flash 上每题成本 0.0242 美元，介于 MiroFlow（0.0374）和 DeepSeek-Harness（0.0211）之间。六组同骨干比较中五组精确 McNemar 检验 p < 0.02，第六组（Qwen3.5-397B-A17B 上对 DeepSeek-Harness）p = 0.21。优势主要来自 BrowseComp（69.3%）和 Humanity's Last Exam（60.0%），另两个驾驭层至多 62.4% 和 43.3%；在 xBench-DeepSearch 上 DeepSeek-Harness 领先 3.4 个百分点。
  * *代码驾驭层。* Raven-Code 在八个设置中六个第一，SWE-Refactor 上优势最大（相对榜单条目，DeepSeek-V4-Flash 上 +9.5，GPT-5.6 Luna 上 +3.0）。SWE-bench Pro 上，与同为 Qwen3.8-27B 骨干的 Claude Code 相比，731 题多解 15 题。SWE-bench Verified 上领先 0.6 和 1.2 个百分点（500 题中多解 3 题和 6 题）。配 Claude Opus 5 时 DataAgentBench Pass@1 为 0.8762，是 2026 年 8 月 24 日榜单条目中最高的。
  * *设计与运行-监控驾驭层。* PresentBench 得分 80.2（Claude Opus 5）和 72.9（GPT-5.6 Luna），Claude Code 为 78.3 和 52.4。Claude Opus 5 下，Raven-Oncall 从 1.108 起步降到 1.038 bits per byte，Claude Code 为 1.053，墙钟时间相近（4.90 对 4.99 小时），报告的 token 和成本更低；AI4S 解出 17 题中的 14 题，Claude Code 为 11 题。
  * *技能有用，且对 Raven 更有用（SkillCorpus 结果）。* 12 组“单元格-基准”比较全部提升。汇总增益：SkillsBench +7.5±2.3，GDPval +1.51±0.49，QwenClawBench +2.79±0.70。同样的技能选择下，Raven 在 SkillsBench 上增益 6.5 和 13.4，OpenClaw 为 4.2 和 5.8；QwenClawBench 上 3.9 和 4.4 对 1.5 和 1.3。单次消融中，换用现成检索器使 Raven 的最佳 SkillsBench 分数从 22.6% 降到 13.8%，换成约 82.1 万个技能文件的未整理爬取库则降到 14.9%（无技能：9.2%）。
  * *驾驭层演化（HarnessBank 结果）。* 冻结 Qwen3.6-27B，七个基准的留出 Pass@1 全部上升，例如 AppWorld 41.3→56.7、BrowseComp+ 16.9→30.8、LiveCodeBench 58.1→71.8、Terminal-Bench-2 36.1→45.4。六个通过来源论文的配对增益标准；SWE-bench Verified（26 题测试集上 +5.1）未通过。
* **较弱或有边界的：**
  * *组合系统从未做端到端测试。* 论文自己的理论（2.5-2.6 节）说，要确立新任务覆盖，需要与模型、工具、信息和总成本相当的强个体智能体做匹配比较，但文中没有这样的实验。MAOB 只在任何工作节点运行前给计划打分，专家结果衡量的是各驾驭层单独的表现。因此标题中“可组合智能体智能”的主张靠的是理论和规划基准，而不是实测的组合结果。
  * *图一致不等于任务成功。* MAOB 的参考图由一个 LLM 编写、请求由另一个 LLM 生成，出自作者自建流程，打分时调用被折叠到四个领域。Raven 的编排指南本就为这种图提交而写，而 Claude Code 和 Hermes Agent 通过各自原生接口规划。更高的 Exact Match 是否预示更好的执行结果没有被检验（读者注）。各基线的 MAOB 数值只在图中给出，正文只报了上面引用的最强基线数字。
  * *两项组件结果是复用而非新做的。* 驾驭层演化和技能复用的证据转述自作者的前作，并非来自本文所描述的整合后 Raven 系统；技能消融是单次运行。
  * *比较协议不一致。* 若干图把本地运行的系统和公开榜单数值混在一起；SWE-bench Verified 运行允许联网。AI4AI 任务中 Claude Code 拿到另写的任务说明，每个系统只跑一次活动。AI4S 中 Claude Code 的任务说明包含了机器地址和作业命令（Raven-Oncall 需自己选择），且成功与否由人工判定。视觉设计分数来自以 GPT-5.6 Luna 为评审的内部评分器（相对最强对手领先 0.3-2.8 分），PresentBench 均值只统计成功评分的幻灯片。
  * *理论只给充分条件。* 各节点误差额度和宿主的规划失败率从未被测量，因此这些界没有在任何报告的任务上实例化。奇偶例子只说明组合能胜过各缺一个接口的智能体，而不说明它胜过拥有全部接口的单智能体，作者自己也这样说明。

# Q9 贡献

* 一个开放生态：把模型-驾驭层对（包括经 ACP 和 CLI 适配器接入的第三方智能体）当作可组合单元，配以准入检查的 DAG 计划、基于产物的交接、完成裁定和宿主级群体记忆。
* 把能力形式化为共享预算下的可靠覆盖，给出组合可靠性界，以及把规划与协调成本计算在内、超越每个个体智能体的新任务覆盖条件。
* MAOB：在执行前为专家选择和依赖结构打分的规划基准，覆盖固定四专家名单的全部多领域组合。
* 四个专家驾驭层（研究、代码、设计、运行-监控），同骨干比较时同时报告质量与成本；并把作者的驾驭层演化、记忆和技能检索工作整合到一起。

# Q10 下一步

* **作者的计划：** 每台设备或每个环境一个 Raven 实例，通过智能体间（A2A）协议协同，组成“全域协作网络”，并在设备间同步记忆、任务上下文和执行进度。
* **缺失的端到端测试（读者注）：** 用组合系统和“拥有全部工具、同等预算的最强单智能体”分别执行 MAOB 式跨领域任务，测量宿主规划失败率和各节点误差，看推论 1 的条件在实践中是否成立。
* **计划一致能否预测结果？（读者注）：** 实际执行 MAOB 图，把 Exact Match 或 Edge F1 与交付物质量做相关分析，毕竟该基准承认有效的替代计划可能与参考图不同。
* **适配器层包装的对比（读者注）：** [LongHorizon-Harness](../papers/2608.01964.md) 同样包装 Claude Code、Codex、OpenClaw 和 Hermes Agent，但用于在“管理者-执行者-审计者”分工下完成一项长任务；Raven 包装它们则是为了在专家之间划分任务。两者针对同一批后端回答不同问题，可以结合。
* **与本仓库的关联（读者注）：** Research OS 的 `project-dispatch` 技能通过 `os-harness` 把工作交给各项目的 Claude Code 或 Codex 会话。Raven 对提交图的准入检查和只经产物交接的做法，是这一派发层可借鉴的具体方案。另外，Raven-Oncall 的 AI4AI 任务调优的是 nanochat 衍生的预训练配方、以 bits per byte 计分，与 [nanochat_cpu](../../projects-folder/nanochat_cpu/index.md) 项目属于同一类基础设施。

* [智能体驾驭层工程](../topics/agent-harness-engineering.md) - 以模型-驾驭层对作为能力单位，通过四个带类型的策略接口和门控筛选围绕冻结模型演化驾驭层，并给出四个领域驾驭层的同骨干比较。
* [智能体技能库](../topics/agent-skill-libraries.md) - Skill Forge 在精选目录（SkillCorpus）、本地技能和记忆派生技能之间路由；在相同技能选择下，Raven 把技能转化为比 OpenClaw 更大的收益。
* [EverMemOS](../papers/2601.02163.md) - 同一团队的记忆生命周期（情景痕迹、语义巩固、重构式检索），Raven 经 EverOS 用于用户记忆、智能体经验和群体评估。
* [SkillsBench](../concepts/skillsbench.md) - 在复用的 SkillCorpus 实验中技能复用增益最大的基准（汇总 +7.5±2.3）；Raven 配 Qwen3.5-397B-A17B 从无技能的 9.2% 提升到 22.6% Pass@1。
* [SWE-bench Pro](../concepts/swe-bench-pro.md) - 同为 Qwen3.8-27B 骨干，Raven-Code 比 Claude Code 在 731 题中多解 15 题，补丁生成时不联网。
* [SWE-bench Verified](../concepts/swe-bench-verified.md) - Raven-Code 在 DeepSeek-V4-Flash 和 Claude Opus 4.8 下分别领先 0.6 和 1.2 个百分点（500 题中多解 3 题和 6 题），允许联网；它也是 HarnessBank 七个基准之一（+5.1，在 26 题测试集上不显著）。
* [Terminal-Bench](../concepts/terminal-bench.md) - Terminal-Bench-2 是本文转述的 HarnessBank 七个基准之一：冻结 Qwen3.6-27B，留出 Pass@1 从 36.1 升至 45.4。
* [BrowseComp](../concepts/browsecomp.md) - DeepResearch Mixed 汇集的四个来源之一；DeepSeek-V4-Flash 下 Raven-Research 在其 BrowseComp 题目上达到 69.3%，MiroFlow 和 DeepSeek-Harness 至多 62.4%。
* [LLM 评审（LLM-as-a-Judge）](../concepts/llm-as-a-judge.md) - 按语义等价判定 DeepResearch Mixed 的答案；GPT-5.6 Luna 作为内部评分器的评审为视觉设计基准打分，作者说明这些分数不能与官方榜单比较。
