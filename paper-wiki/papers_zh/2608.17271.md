> 论文:**ASI-Bench: At the Dawn of Artificial Superintelligence**
> 论文链接:<https://arxiv.org/abs/2608.17271>
> 机构:40 余位专家跨机构合作,核心作者以清华大学为主,并涉及 MIT、哈佛、CMU、密歇根大学、UIUC、波士顿大学、昆士兰大学、中国科学技术大学、Flatiron Institute、Microsoft Research、AG2 AI

# Q1 问题定义

* **输入(X)**:一个项目级研究目标,加上任务专属数据和一个可执行环境,以四种逐级递减的人类方法论指导水平之一呈现,同时研究目标、数据、所需输出和评分标准保持不变——**B1** 给出完整方法、数值公式和求解流程;**B2** 去掉具体流程,只给出方法类别与适用方法建议;**B3** 连方法本身也去掉,只给出观测数据、科学目标和所需输出;**B4** 保留 B3 设置,但额外加入看似合理、实则与任务无关的干扰信息。
* **输出(Y)**:每个任务的可验证研究产出与一个标量科学得分,由一个 Agent×Model 系统完成问题理解、方法选择、实现、实验、失败诊断、迭代改进和结果验证之后产生,再由专家编写的门控和加权评分器在沙箱中端到端验证后打分。
* **核心问题**:现有基准要么测试有已知答案的知识,要么测试对一个已被人类大量指定好的流程的执行;没有一个基准能同时衡量跨领域通用性、方法自主性和端到端项目级执行,也没有基准能以受控、分级的方式测量单个研究项目的结果如何随人类方法论指导的撤回而退化。论文自己的表 1 对八个已有基准(HLE、Terminal-Bench、ScienceAgentBench、PaperBench、MLE-Bench、RE-Bench、DiscoveryBench、SciCode)按跨领域通用性、方法自主性、端到端研究和"指导梯度"四个维度打分,没有一个同时满足全部四项,也没有一个具备任何指导梯度设计。
* **范围**:60 个项目级研究任务,涵盖 11 个科学领域(数学、物理、化学、生物、天文、材料科学、地球科学、医学与生物统计、计算机科学、机器人学、电子工程)。论文主结果表(表 2)明确限定为**无外部工具访问**条件下的评测;本笔记未阅读可能报告工具访问条件的附录部分。

# Q2 问题的新颖性

已有两条文献线索,ASI-Bench 在二者之上构建而非首创其中任何一条。**AI 科学家系统**(Coscientist 的化学工具增强规划;The AI Scientist 的构思到评审全流程;AI Scientist-v2 用智能体树搜索降低对人工模板的依赖;Co-Scientist 与 Kosmos 面向协作式假设生成和长时程研究)展示了广泛的自主研究*工作流*能力,但其成功并不能证明自主性,因为目标、方法或流程可能已经被人类大量指定。**科学智能体基准**从纯知识测试(GPQA、HLE)经数据驱动发现类基准(DiscoveryBench、BLADE、DSBench、HypoBench)到执行导向类基准(ScienceAgentBench、MLE-Bench、RE-Bench),再到复现类基准(PaperBench、CORE-Bench、ReplicationBench)和近期的全周期或套件类基准(FIRE-Bench、ResearchClawBench、SciAgentArena、DiscoveryWorld、AstaBench、ScienceBoard)——但每一个都在单一固定规格下评测任务,因此其分数把"完成被分配的工作流"和"独立构建该工作流"混为一谈。第三条更薄的线索改变信息可获得程度:ScienceAgentBench 比较有无专家提供知识的表现,但设计"大体上是二元的",没有把方法选择与流程指导分开;ProjectionBench 逐步披露信息,但仅针对假设生成,而非可执行的项目级工作流;ProjectEval 改变规格细节,但针对的是软件项目而非开放式科学问题。ASI-Bench 声称的新意正是这些工作都未覆盖的交集:在同一研究项目内部、保持目标/数据/输出/评分标准不变的匹配项目实例上进行分级评测,从而把此前二元或单一条件设计混为一谈的四种能力拆分开——遵循一个完整流程(B1)、把一个指定方法转化为可执行工作流(B1→B2)、独立构建该工作流(B2→B3),以及在此过程中抵御与任务无关的干扰(B3→B4)。

# Q3 科学假设

如果按 B1→B2→B3→B4 的梯度逐步撤回方法论指导,同时保持研究目标、数据和评分标准不变,那么当前前沿的 Agent×Model 系统将表现出可测量且*不对称*的性能崩溃:最大的单次下降应出现在 B1→B2(保留方法名称但失去逐步流程),B2→B3 的下降应小得多(失去方法名称本身),B3→B4 几乎不再进一步下降(加入无关干扰信息)——这揭示出把一个已知方法操作化为可执行的研究工作流,而非选择方法本身或抵御干扰,才是自主科学研究的主要瓶颈,并且这一模式应在不同领域、模型family和 agent harness 之间保持一致。

# Q4 相关工作与关键人物

* **AI 科学家系统**:Coscientist(化学领域,工具增强的规划与实验)、The AI Scientist(从构思到实验、写作、评审的全流程)、AI Scientist-v2(用智能体树搜索降低对人工模板的依赖)、Co-Scientist 与 Kosmos(协作式假设生成与长时程研究)——论文附录 A 认为这些系统展示了广泛的工作流能力,但并不能证明真正的自主性,因为其目标、方法或流程可能已被大量人为指定。
* **科学智能体基准**:GPQA 与 HLE(纯知识,无执行);SciCode(科学编程);DiscoveryBench、BLADE、DSBench、HypoBench(数据驱动的发现与假设生成);ScienceAgentBench、MLE-Bench、RE-Bench(执行导向的开放式机器学习/科学工程);PaperBench、CORE-Bench、ReplicationBench(通过分层或基于执行的评测进行研究复现);FIRE-Bench、ResearchClawBench(全周期再发现与端到端研究);SciAgentArena、DiscoveryWorld、AstaBench、ScienceBoard(交互式、模拟式或套件式科学工作流)。
* **科学自主性与指导依赖**:ScienceAgentBench(有/无专家知识的二元比较)、ProjectionBench(仅针对假设生成的渐进信息披露)、ProjectEval(针对软件项目的规格细节变化)——论文指出的空白是:这些工作都没有评测*同一*科学项目内部,从遵循指定方法到独立构建并验证一个工作流的转变,也没有评测这一转变如何与合理的干扰信息相互作用。
* **作者与构建规模**:ASI-Bench 是一次大规模的分布式协作——21 位研究者贡献了最终保留的 60 个任务,来自一个更广泛的 40 余名贡献者和评审者的群体,涉及清华大学、麻省理工学院、哈佛大学、卡内基梅隆大学、密歇根大学、UIUC、波士顿大学、昆士兰大学、中国科学技术大学、Flatiron Institute、Microsoft Research 和 AG2 AI;通讯作者为 Yongchao Chen。构建过程历经五轮评审、超过 1,100 次任务评审分配,投入超过 31,000 人时。

# Q5 核心解法

1. **在匹配项目实例上的 B1–B4 指导梯度**。60 个项目级任务每一个都以四个层级呈现,在保持底层研究目标、任务专属数据、所需输出和评分标准不变的前提下,只改变人类方法论指导的多少——从完整求解流程(B1)一路降到仅有目标和数据(B3),再到 B3 加上事实正确但与任务无关的干扰上下文(B4)。由于四个层级共享同一个任务身份,它们之间的差异隔离出撤回指导本身的代价,而不与任务难度本身混淆。
2. **多阶段构建与验证流水线**。从可追溯的科学来源收集了 1,300 多个候选研究想法,由领域专家筛选并加工为可执行任务,随后经过 AI 辅助审计和五轮人工交叉评审(超过 1,100 次评审分配、超过 2,000 次任务修订),涵盖科学逻辑、任务规格、参考产出、评分代码、信息泄漏和 agent 轨迹。每个保留的任务还要在独立沙箱中经过端到端执行验证(超过 1,500 次沙箱运行),检查运行时稳定性、参考结果可复现性、产出物生成和评分一致性;存在未解决的科学错误、执行不稳定、评测错位或非预期解法捷径的任务会被修订或剔除,最终保留 60 个任务。
3. **任务规模与丰富度**。60 个任务合计完成底层研究过程涉及超过 2,600 轮交互和 2,400 个执行步骤,agent 总执行时长超过 35 小时——论文将每个任务定位为一次真正的长时程、多阶段研究,包含多个相互依赖、开放式的决策点,而非一道孤立问题或固定流程练习。
4. **诊断式拆解而非单一聚合分数**。按模型报告 B2−B1、B3−B1、B4−B3 三个差值(在每次运行内先计算再聚合),把基准变成一个诊断工具:仅凭 B1 分数无法区分"擅长遵循指令"与"擅长自主研究",但跨层级的差值模式可以。
5. **开放、可由社区扩展的任务流水线**。一个公开提交门户(asibench.apexin.ai/submit)和 CLI 启动器引导贡献者完成 15 步引导流程:构思一个非平凡、确定性的科学问题;为同一目标构建全部四个 B1–B4 提示层级(B3/B4 不得泄漏预期方法);提供参考生成脚本(`generate_gt.py`)、评测门控与加权评分器、运行时依赖以及四种条件下的本地测试证据;然后提交给与初始 60 个任务相同的科学与技术评审流程。被采纳的贡献者会在对应的基准发布中获得署名,明确把社区提交者当作共建者而非外部数据提供方。

# Q6 实验设计

18 个 Agent×Model 组合,跨六种 agent harness(一个默认/专有 harness,以及 Claude Code、Kimi Code、MiMo Code、OpenHands)与包括 GPT-5.5(xhigh)、GPT-5.6 Sol(xhigh 与 ultra)、Claude Opus 5 与 Claude Opus 4.8、Kimi K3 与 Kimi K2.7、GLM-5.3 与 GLM-5.2、DeepSeek V4 Flash 与 Pro、MiMo V2.5 Pro 在内的基座模型配对——在全部 60 个任务上按 B1–B4 评测,三次独立运行取宏平均(Claude Opus 5 仅报告单次运行,无法估计标准差,结果表中对此明确标注)。论文报告主分数的均值 ± 一个样本标准差,以及在每次运行内先计算再聚合的 B2−B1、B3−B1、B4−B3 诊断差值。一项单独的成本分析(§3.2)针对每个 Agent×Model 组合、在每个指导层级下剖析平均单任务 token 消耗、执行时间与货币成本,并把每次运行成本与 B3 分数作图以刻画成本-性能权衡。

# Q7 数据与代码

ASI-Bench 引入了一个全新的基准,而非复用已有基准:60 个项目级任务涵盖 11 个科学领域,每个任务都配有科学目标、任务专属数据、可执行沙箱环境、参考生成脚本以及门控加权评分标准。代码、排行榜和 Hugging Face 页面发布于 github.com/apexin-ai/ASI-Bench(撰写本笔记时据 HF 元数据有 245 个 star);一个公开提交门户(asibench.apexin.ai/submit)接受社区贡献的任务,纳入未来版本,遵循与最初 60 个任务相同的评审流程。

# Q8 证据质量

本笔记基于 arXiv HTML 正文——摘要、引言、第 2 节基准设计(2.1–2.3)、第 3 节实验(3.1 主结果、3.2 计算成本)、第 4 节结论、附录 A(相关工作)、附录 B(作者)以及附录 C(为 ASI-Bench 做贡献)的部分内容——撰写,因为对这篇论文,`hf papers read` 只返回了一个占位性的图注页面,故本笔记改为直接从 arxiv.org/html 抓取。抓取在附录 C 中途因 50,000 字符上限被截断,因此附录 D(论文自己在一个二维动力系统任务上给出的 B1–B4 具体示例)以及之后的任何附录均未阅读,本笔记不从中引用任何论断——尤其是,表 2 的表注明确将主结果限定为"无外部工具访问",而这些附录是否以及如何报告工具访问条件下的结果,本笔记并不知情。头条数字(B1–B3 平均分数为 50.91 → 29.10 → 26.62;B1→B2 下降 21.82 分,而 B2→B3 仅下降 2.48 分)在摘要与正文"对详细方法论指导的依赖"一段之间保持一致。论文明确指出 Claude Opus 5 一行是单次运行、没有标准差,不同于表中其他所有配置——本笔记保留这一提醒,而非把所有行当作同等确定。表 1 对 ASI-Bench 与 HLE、Terminal-Bench、ScienceAgentBench、PaperBench、MLE-Bench、RE-Bench、DiscoveryBench、SciCode 的比较是论文自身对已有工作覆盖缺口的自我评估;本笔记未就这些勾选项对照被引用的基准本身做独立核实。

# Q9 主要贡献

1. ASI-Bench,第一个把跨领域科学通用性、自主方法选择和端到端项目级研究执行统一在一个设计中共同评测的基准。
2. 一套在匹配项目实例(跨层级共享目标、数据和评分标准)上应用的 B1–B4 渐进指导撤回协议,把自主性拆解为四个可分离的失败点——流程执行、方法操作化、自主工作流构建和抗干扰能力——而非单一的人类指导二元开关。
3. 一套大规模、经专家验证的构建与评审流水线(40 余位贡献者、超过 31,000 人时、五轮评审、超过 1,500 次沙箱验证运行),把约 1,300 个候选想法筛选为 60 个经过科学可靠性、信息泄漏和可复现评分检验的任务。
4. 在 18 个 Agent×Model 组合上的实证证据:平均科学得分从 B1 的 50.91 崩溃到 B2 的 29.10 再到 B3 的 26.62,确认方法操作化——而非方法选择,也非抗干扰能力——才是自主科学研究的主要瓶颈,即便是最强配置(Codex 配 GPT-5.6 Sol,ultra 推理强度)在 B3 下也只达到 51.60。
5. 直接证据表明固定基座模型的科学能力依赖于 harness(例如 MiMo V2.5 Pro 从 MiMo Code 的 16.17 提升到 Claude Code 的 23.25;Kimi K2.7 在同样两个 harness 下从 19.72 提升到 27.34),因此仅比较模型本身可能会把实际来自周边 agent 系统的能力错误归因于模型。
6. 一项成本-性能分析显示,完整指导(B1)计算成本最低,部分指导(B2,仅有方法名称)反而是成本*最高*的条件(比 B1 多消耗 59% 的 token、多花 32% 的时间),而更高的花费并不能可靠地换来更高的 B3 表现。
7. 一套开放、可由社区扩展的提交流水线(公开门户、CLI 启动器、15 步引导流程、贡献者署名),旨在随 agent 能力进步持续为基准补充任务、避免饱和。

# Q10 下一步

论文明确把已发布的 60 个任务定位为"一个起点,而非终点",并指出没有任何固定基准或单一研究团队能够代表未来 AI 系统必须面对的、有科学意义且可验证的问题的全部广度——论文邀请"在各自领域前沿工作"的研究者贡献新领域、拓宽现有领域内的方法多样性,并覆盖当前 60 个任务尚未充分代表的研究能力。论文将当前的绝对表现定位为足够低(最佳 B3 分数 51.60,平均 B3 分数 26.62),使基准"远未饱和",把 ASI-Bench 定位为一个纵向追踪工具,而非一次性排行榜。本笔记在论文自身框架之外补充两点联系,均标注为开放而非已被读取文本确认的问题:第一,ASI-Bench 自己的"Harness 塑造模型能力"发现,是对本知识库 [Agent harness engineering](../topics/agent-harness-engineering.md) 主题已从单一系统论文(StateM、LongHorizon-Harness)追踪到的论断——固定基座模型的实测能力并非模型本身单独决定——的一次独立、基准规模的复现;第二,由于主结果表明确限定为"无外部工具访问",从已读取的部分文本尚无法确定,给定工具访问权限后,陡峭的 B1→B2 操作化差距会缩小多少,也无法确定 harness 依赖效应在不同指导层级下是否会与工具访问产生不同的交互——这个问题未读取的附录 D 及之后部分或许有所涉及。
