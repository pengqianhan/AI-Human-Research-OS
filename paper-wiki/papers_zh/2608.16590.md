> 论文:**Zetta ζ: An Efficient Closed-Loop Embodied Harness for Self-Evolving Physical Intelligence**
> 论文链接:<https://arxiv.org/abs/2608.16590>
> 机构:清华大学智能产业研究院(AIR)、Z-Trans AI(据项目主页)

# Q1 问题定义

* **输入 `X`**:一个部署在机器人操作任务上的冻结视觉-语言-动作(VLA)策略,以及该策略在仿真环境(LIBERO-Pro、RoboCasa)中执行产生的一连串 rollout。
* **输出 `Y`**:同一个冻结策略被一层不断演化的、基于代码的控制层包裹——以动作频率监控物理状态的运行时评判器(critic),以及在执行偏离标称分布时触发的恢复技能——加上一个只有在候选评判器/恢复方案通过留出验证后才被接纳的、带版本管理的技能库。
* **核心问题**:现有的具身 agent harness 是开环的——在一次 rollout 过程中遵循固定技能,只在 episode 结束后才进行反思。事后反思无法在执行展开的过程中实时管控执行,因为物理交互要求以超出当今大型 agentic 模型自身能力的频率跟踪快速变化的机器人-环境状态。
* **范围**:围绕一个策略演化 harness(运行时评判器、恢复技能,以及运行和验证它们所需的基础设施),而非微调策略权重本身;在 LIBERO-Pro 和 RoboCasa 仿真基准上评测。

# Q2 问题的新颖性

具身 agent 正被越来越多地用于弥补端到端策略模型留下的差距,但根据摘要,现有 harness 仍是开环的:在 rollout 过程中执行固定技能,只在 episode 结束后才反思,这无法以物理交互实际要求的频率管控执行。Zetta 声称的新意在于直接闭合这个环——在执行*过程中*、在三个明确区分的时间尺度上在线演化基于代码的运行时评判器和恢复技能,而不是微调基础策略,也不仅仅依赖 episode 结束后的反思。

# Q3 科学假设

如果让基础 VLA 策略保持冻结,同时让周边的 harness 演化出可解释的、基于代码的运行时评判器(以动作频率运作)和恢复技能(分别在 rollout 级和跨 rollout 级被提出和验证),并以历史回归检查和留出泛化测试作为门控,通过后才被纳入带版本管理的技能库,那么由此得到的系统将在长时程操作任务的成功率上大幅超越单独的冻结策略,推理速度快于可比的神经网络评判器方案,能把学到的恢复技能零样本迁移到相关任务,并在特定物理瓶颈被识别和修复时,在单任务表现上呈现不连续的("顿悟时刻")跃升。

# Q4 相关工作与关键人物

* 将自身定位为对既有具身 agent harness 的改进——摘要将后者描述为开环的,在 rollout 中遵循固定技能、只在 episode 结束后才反思——Zetta 的核心主张是在执行过程中实现真正的闭环管控,而非事后的适配。
* 与本知识库 [Agent self-evolution](../topics/agent-self-evolution.md) 和 [Agent harness engineering](../topics/agent-harness-engineering.md) 主题下的 SkillOpt、MemoHarness 等论文共享一个方向:它们同样从执行产生的信号中演化一个持久的控制产物(技能文档、harness),并在接受前设置验证门控——Zetta 的特点是把同样的"诊断失败-生成候选-验证"模式应用到*动作频率的具身*控制上,而非文本/CLI agent 控制,并明确区分了三个时间尺度(动作级、rollout 级、跨 rollout 级),而非单一的适配循环。
* 作者:15 人团队,由 Xin Ding 和 Ting Cao 领衔;据项目主页,隶属清华大学智能产业研究院(AIR)和 Z-Trans AI。

# Q5 核心解法

1. **三个按时间尺度分离的循环。** *动作频率管控*(循环一):基于代码、经过学习的运行时评判器以与机器人动作相同的频率运行,监控物理状态(物体相对几何关系、接触、抓握保持、任务进度谓词),在执行偏离标称分布的瞬间触发恢复技能——在该频率下不调用神经网络模型。*rollout 级评判器-恢复方案生成*(循环二):失败的 rollout 按最早可观测的偏离点聚类,进行因果诊断,并转化为以代码形式表达的候选评判器/恢复更新。*验证门控的技能更新*(循环三):候选方案只有在通过历史回归检查(不能破坏此前已修复的案例)和严格的留出泛化测试后,才被纳入带版本管理的技能库。
2. **基于代码而非权重的评判器与技能。** 与其微调策略权重,Zetta 演化的是表达物理不变量(接触状态、抓握保持、进度)的可解释代码——论文给出的理由是:这类不变量比一个黑盒的学习型评判器更容易在相关任务间迁移,而且代码层面的审查/验证比权重更新更具可审计性。
3. **Z-Infra:将 agent 逻辑与执行资源解耦的基础设施。** 一个三层运行时(控制平面、环境 worker、rollout worker),把不断演化的评判器/恢复逻辑与异构执行资源分离开来,据项目主页称可达到约 20.6 倍的有效 rollout 吞吐量,在 8×A100 GPU 上扩展到约每分钟 35.1 个 episode——正是这套基础设施使循环三中频繁的"验证-晋升"周期在大规模场景下具备实际可负担性。
4. **"顿悟时刻"(Aha Moments)。** 项目主页把单任务的学习曲线描述为不连续而非平滑的——例如,一个"把酒瓶放入碗中"的任务成功率从约 15% 跃升到 95%,一个"放置奶油奶酪"的任务从约 5% 跃升到 90%——这被归因于 harness 识别并修复了某个具体的物理瓶颈,而非策略的渐进式改进。

# Q6 实验设计

在两个仿真操作基准上评测。据摘要,Zetta 在"当前的 rollout 预算下"在 LIBERO-Pro 上达到 90.8% 成功率,在 RoboCasa 上达到 93.6%,推理速度提升 11.1 倍,并报告成功率会随着自我探索经验持续提升,学到的技能能零样本迁移。项目主页给出了更细粒度的拆分,方向上与摘要头条数字一致,但聚合方式并不完全相同:LIBERO-Pro 上 Goal(T) 31.0%→92.5%、Goal(S) 38.0%→89.0%(在至少一个拆分上相较冻结 VLA 基线声称提升 56.3 分);RoboCasa 的 18 个 Atomic-Seen 任务 73.56%→93.56%(相较冻结 VLA 基线提升 20 分);以及把 pick-and-place 技能(宏平均 64%→84%)和接触密集型交互技能(宏平均 64%→80%)零样本迁移到相关的、非训练任务上。GitHub README 单独给出 LIBERO-Pro 90.8%、RoboCasa 93.6% 的整体数字,以及同样的 11.1 倍推理加速数字,与摘要一致。

# Q9 主要贡献

1. Zetta,一个闭环具身 harness,在基础 VLA 策略保持冻结的同时,通过三个明确按时间尺度分离的循环(动作频率管控、rollout 级方案生成、验证门控的晋升)在线演化基于代码的运行时评判器和恢复技能。
2. Z-Infra,一套将不断演化的 agent 逻辑与异构执行资源解耦的 rollout 基础设施,据称大幅提升了有效 rollout 吞吐量,使该方法所依赖的高频"验证-晋升"周期得以实现。
3. 报告了相较冻结 VLA 基线在 LIBERO-Pro 和 RoboCasa 上的大幅成功率提升、11.1 倍推理加速、学到的恢复技能向相关任务的零样本迁移,以及一种记录在案的"顿悟时刻"式单任务不连续提升模式——以上均有待对照完整论文独立核实。
