# Q1 问题定义

* **输入（X）：** 对每个任务，给出某个真实实验室在截止点时手上的交接材料（实验记录本、原始仪器数据、实验方案、阶段性结论），一份可用流程以及设备和试剂选项清单，以及以实验日、孔位等单位计的实验预算。被测的执行智能体（actor agent）有一个带 shell 和 Python 的沙箱、屏蔽了原始来源的网页搜索，以及获取新读数的唯一渠道：向该任务的 TwinLab 智能体发出实验请求。
* **输出（Y）：** 一份包含结论和推荐流程的报告，由评审智能体（judge agent）对照隐藏真相（记录在截止点之后显示的内容）打 0 到 100 分；结论本身和本次运行中支撑结论的证据都计分。
* **约束：** 每个请求消耗预算；稀缺材料用掉就无法恢复；TwinLab 智能体只返回实验应当返回的内容，不给提示，关于历史的问题只回答到截止点为止；记录和文献都无法约束的量会被标为模拟限制。

# Q2 问题新颖性

论文把 AI 科学家的能力分成逐级开放的三种：执行给定的计算流程、在给定设计空间中选择下一次测量、自己设计实验。现有基准覆盖了前两种（数据分析和终端基准；在人为设计的世界中的 SciGym、DiscoveryWorld、BoxingGym；以及回放已发表测量的 ASB，智能体只能在已记录的条件中挑选）。第三种需要一个环境，能为事先没人列出的实验返回真实读数。新意在环境本身：每个实验室一个孪生（twin），用该实验室自己的记录来回答自由组合的实验，而不是用写死的规则或语言模型的通用知识。

# Q3 科学假设

如果由一个编码智能体来回答实验请求：查找实验室记录的数值，运行只由该实验室数据构建的计算器，并把外推限制在有书面依据的邻近设置上，那么它的读数会比让语言模型扮演实验室时更贴近真实记录；在此之上构建的基准就能评测实验设计（而非记忆），因为答案只能通过智能体自己的实验得到。

# Q4 相关工作与关键人物

* **不涉及新物理实验的基准。** 知识问答集（GPQA、LAB-Bench 等）、数据分析基准、Terminal-Bench 及其科学版、机器学习研究基准（MLE-bench、RE-Bench、[PaperBench](../concepts/paperbench.md)）、端到端研究系统与基准、Kosmos。
* **来自模拟、回放或语言模型的读数。** 文本世界和方程模型（ScienceWorld、DiscoveryWorld、SciGym、BoxingGym）、EmbodiedLab（在物理模拟器中操作仪器）、已发表测量的回放、作为世界模型的语言模型，以及在智能体评测中扮演病人和用户的语言模型（已有研究报告其反馈偏离真实环境和用户）。AgentBeats 把一个基准打包成一个智能体；TwinLab-Bench 把这一角色拆成环境智能体和评审智能体。
* **量规打分。** 带完全和部分得分条件的条目，沿用 PaperBench 和 HealthBench；以视觉语言模型作为评审。
* **关键人物。** Yang Wan 和 Linchao Zhu（Hugging Face 论文页标注为浙江大学；代码位于 ZJUSCL GitHub 组织下）。可能的批评者：建设真实自动化实验室的人，会问孪生在多大程度上能替代物理执行；回放式基准一脉，会问分数有多少依赖计算器外推。

# Q5 关键解决思路

1. **任务构建。** 从约 375 个候选来源中筛出 52 个任务（49 个改编自单个实验室的记录，3 个为有依据的合成任务），物理科学 20 个、生命科学 20 个、工程 12 个。每份记录在截止点切开：之前的交给执行智能体，之后的成为隐藏真相。任务形式：结论审查（最多）、故障排查、研究攻关；有些任务不提供实验，只需分析交接材料。
2. **TwinLab 智能体。** 一个只有读文件、搜索文本和运行计算器工具的编码智能体。对每个请求，它在任务材料中寻找依据，取可比材料上的记录值或运行计算器，再按仪器自己的格式写出结果，有匹配的真实图像时一并返回。环境代码在请求之间保持状态（例如样品已用完），按实测重复性加噪声，并断言观测不泄露标识符或隐藏真相。
3. **计算器。** 针对每个任务、由实验室数据编写的确定性程序（对测量值重采样、拟合物理模型、填写真实仪器的导出模板）。在 371 个列出的参数值中有 100 个是外推的，每个都有书面依据；外推值同时充当干扰项。
4. **难度控制。** 多数任务的预算是专家路线用量的一到三倍（中位数 1.6）；稀缺材料；有看似无害解释的伪影；被混杂的测量；以及一些正确答案是"在预算内无法判定"的任务。对来自真实记录的任务，这些情形都取自记录本身。
5. **打分。** 量规条目分结论类和本次运行中的验证类；核心条目不满分则整次运行记零；每个满分的核心条目再由两次独立调用复核；最终运行前冻结量规。如果读数泄露隐藏真相、与先前观测或物理规律矛盾，或拒绝了真实实验室能做的相关实验，则该次运行无效；一个脚本会重放每次计算器调用。

# Q6 实验设计

* **主评测。** 13 个模型作为执行智能体，按推理强度计共 17 种配置；GPT 系列在 Codex 中运行，其余在 Claude Code 中。每个执行智能体的 TwinLab 和评审智能体都用 DeepSeek-flash。大多数执行智能体每题只跑一次；DeepSeek-flash 和 MiMo-V2.6-Pro 各跑三次。分数与成本一起报告。
* **孪生保真度。** 在 12 个任务上，把专家路线的请求分别回放给三种环境（只给任务描述的语言模型、给原始材料的语言模型、TwinLab 智能体）；追溯 831 次运行中 7,808 个请求的读数来源；外推依赖审计；六个外推替换变体；三个留出条件任务；在四个任务上的红队执行智能体（利用漏洞组和找缺陷组）。
* **分数效度。** 评审稳定性（同一运行评三次）、把 TwinLab 和评审模型换成 Sonnet 5.5 和 Opus 5.5，以及量规分数能否区分被独立标为正确或错误的报告。
* **记忆控制。** 在交接材料逐字不变的情况下改变实验室的真实状态（11 个状态）、闭卷记忆探测，以及在 33 个关键数据不在交接材料中的任务上做零预算基线。
* **失败分析。** 针对高推理强度的 Opus 5.5：比较计划与运行中的关键决策、零分运行的失败类型，以及预算翻倍。

# Q7 数据集与代码

作者发布了任务、环境代码（噪声、检查点、计费、稀缺材料库存）、评测代码和全部提示（执行、TwinLab、评审及各项探测），地址为 github.com/ZJUSCL/TwinLab-Bench，项目主页为 twinlab-bench.github.io。每个任务都按来源记录的许可使用；许可不允许复用时，作者联系了数据提供者。执行智能体的网页搜索屏蔽了基准名和任务名。

# Q8 证据质量

* **核心分数。** Claude Fable 5.2 为 45.0，Claude Opus 5.5 为 40.2，其余配置在 5.4 到 31.7 之间。大多数执行智能体每题只跑一次，因此单个配置的分数带有重复运行中看到的那种噪声（DeepSeek-flash 19.7 ± 3.3，MiMo-V2.6-Pro 14.0 ± 3.6）。成对结论更可靠：任务级配对比较区分了均值相差至少 10 分的 75 对中的 66 对，Fable 5.2 显著高于其余 16 种配置中的 14 种。
* **孪生是最强的贡献，并经过多方面检验。** 与记录不符的比例从 41%（只给任务描述）降到 14%（给原始材料）再降到 2%（TwinLab），重复请求的不一致从 31% 降到 8% 再到 4%，基于 12 个任务中 63 个有记录的请求。评测运行中 76% 的读数来自记录（53%）或用同一实验室数据校准的计算器（23%）。留出条件的预测中位误差为内插 0.74%、外推 2.47%（15 个读数，三个任务）；替换外推方式在 12 对中只有 2 对改变了通过判定。全部 9 次漏洞利用尝试都被拦下。这些研究规模都不大，而且保真度试验与评测使用同一个环境模型。
* **记忆控制异常周到。** 预算为零时，Opus 5.5 和 DeepSeek-flash 在 33 个任务上都没有通过；改变真实状态后，10 个可判定状态中有 8 个的结论跟随新状态；模型能说出来源的任务并没有一致地得分更高。对 Fable 5.2 的控制较弱：它能说出 16 个任务的来源，这些任务得 49.0，而它说不出来源的任务得 58.7。
* **评审可靠性。** 评审是 DeepSeek-flash，与一个执行智能体同模型；作者换用 Opus 5.5 检验自我偏好（19/20 次运行的通过判定一致，κ = 0.83）。重复评审的运行内平均分数标准差为 2.4 到 2.8。在既有正确报告又有错误报告的 21 个任务中，有 19 个任务的每份正确报告都高于每份错误报告。
* **失败分析只针对一个模型。** "知行差距"（计划中完整陈述的决策在运行中拿到最高分的 87%，未提及的拿到 62%）和失败分类（16 次零分运行中 12 次败在实验决策上，最常见的是未做区分性检验就接受某个机制）都只针对高推理强度的 Opus 5.5。正文把计划表称作表 6，但计划百分比实际在表 5。预算翻倍让 8 次耗尽预算的失败中的 2 次变为通过。
* **读者备注。** 论文说明任务是用 Claude Code 加 Claude Opus 5.5 构建的，正文也由其起草和修改；得分最高的执行智能体是 Claude Fable 5.2。论文没有分析任务构建是否偏向构建它所用的模型家族（读者观察，不是论文结论）。

# Q9 贡献

1. 一个基于真实实验室记录、评测自主设计实验的 52 任务基准，支持 100 多种实验动作类型（两位标注者分别数出 105 和 107 种），量规奖励本次运行中获得的证据，而不只是最终答案。
2. 智能体孪生：一个环境智能体，用单个实验室的记录和计算器回答自由组合的实验，噪声、状态、预算、稀缺材料和防泄露都由代码强制执行。
3. 一套针对由 LLM 运行的环境的效度研究：回放保真度、留出预测、外推替换、红队测试、评审替换，以及三项记忆控制。
4. 证据表明前沿智能体得分仍低于 50 分（满分 100），主要弱点在实验判断（接受未经检验的机制、依据早期薄弱证据做选择），而不在预算。

# Q10 下一步

* **论文自述。** 发布任务和代码并屏蔽网页搜索；长期目标是能执行任何设计实验的真实实验室。
* **对头部模型重复运行。** 让 Fable 5.2 和 Opus 5.5 每题跑三次，为 45.0 对 40.2 的差距给出不确定性（读者建议）。
* **跨家族的环境。** 用与执行智能体和构建任务的智能体都无关的模型家族来运行 TwinLab 和评审智能体，以界定可能的家族效应（读者建议）。
* **把孪生用作训练环境。** 同样的孪生可以为实验设计能力提供在线训练信号，并用留出的实验室做评测；论文没有尝试（读者建议）。
* **与自动化实验室衔接。** 用能真正执行部分设计实验的自动化实验室来校准孪生，可以检验记录条件之外的保真度（读者建议）。
