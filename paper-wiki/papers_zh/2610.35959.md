# Q1 问题定义

* **输入 (X)：** 一个长程智能体任务（DeepSWE v1.1 或 Terminal-Bench 2.1 中的任务）、一个能力强但昂贵的模型和一个便宜的高效模型（两者都在同一个 mini-SWE-agent 脚手架中运行），以及当前执行模型不断增长的轨迹。
* **输出 (Y)：** 每一轮之后决定是否把任务交给另一个模型，并转移工作区和历史；接手的模型随后独自完成任务。评估的结果是任务准确率和每任务平均 API 成本。
* **约束：** 每个任务只交接（handoff）一次，不再切回；接手模型继承所有文件修改，历史要么放进它的上下文，要么作为一个可查看的 JSONL 日志文件；成本只计云端 API 调用，可在本地部署的模型按零成本计。

# Q2 问题新颖性

部分新。请求级路由与级联（FrugalGPT、RouteLLM、RouterDC、RouterBench）为每个请求选一个模型；多轮路由（Router-R1、ToolOrchestra、SkillOrchestra、MTRouter、Agent-as-a-Router）为每一步选模型或工具。最接近的是 SWE-Router（用探索性轨迹决定是否升级）、TACIT-Switch（基于风险信号的从小到大永久交接）和 The Handoff Tax（arXiv:2608.24358），后者已在预设切换点上研究过交接方向、时机和轨迹传递接口。AgentBaton 的贡献是：发现有利的方向是"强到弱"，并提出一个能对任意模型对在线决定切换时机的学习型检测器。

# Q3 科学假设

如果由强模型开始一个长程任务，并在它已经产出实质性的产物、获得了关于该产物的任务相关反馈、剩余工作已收窄为局部修复或验证时交接，那么一个便宜得多的模型就能以很小的准确率损失完成任务；反方向——先让便宜模型做、之后再升级——省不了多少钱，因为强模型必须先弥补便宜模型的错误。一个小型学习检测器应当比"提示强模型自己交接"或"固定轮次切换"更能识别交接时机。

# Q5 关键解决思路

**先做分析。** 让每个模型单独运行，在新容器中把某条记录轨迹回放到某个检查点（源模型完整轨迹的 15% 到 90%），再让另一个模型接着做。比较两个方向和两种上下文传递方式。使用三个强模型（GPT-5.6 Sol、Kimi K3、GLM-5.3，推理强度 max）和一个高效模型（Qwen3.8-27B，推理强度 xhigh，本地运行）。

**什么是好的交接点。** 从"在某检查点交接 Qwen 失败、下一个检查点交接成功"的轨迹中，作者总结了三个就绪信号：(1) 已有实质性的实现、可运行的原型或任务要求的产物；(2) 对它的执行、测试或检查已给出任务相关反馈，即使是失败，只要能缩小问题范围也算；(3) 剩余工作是局部的诊断、修复、验证或最终输出。图 4 的例子包括交接前已修好的带引号路径 bug，以及交接前已验证的坐标变换。

**AgentBaton。** 一个 Qwen3.5-2B 模型在每一轮后读取任务以及强模型的动作和观察，输出 `HANDOFF_READY` 或 `HANDOFF_NOT_READY`；第一次判定就绪即转交控制权。训练数据是 2,000 个 SWE-rebench V2 任务上的 4,000 条 mini-SWE-agent 轨迹，来自五个强模型（GPT-6 Astra、GPT-5.6 Sol、Claude Opus 5、Kimi K3、GLM-5.3），由 Codex 标注最早满足全部三个就绪信号的轮次（或"无明确交接点"），标注时只看工具调用和输出，从不看最终奖励。标注点之后的每一轮也作为正例，使检测器错过第一次机会后仍能触发。训练两个 epoch、32K 上下文、16 张 H100；9B 版本没有明显提升。单张 H100 上检测延迟中位数 338 毫秒（p95 为 1.11 秒）。

# Q6 实验设计

* **基准。** [DeepSWE](../concepts/deepswe.md) v1.1（113 个带逐任务验证器的长程软件工程任务）和 [Terminal-Bench](../concepts/terminal-bench.md) 2.1，均在 [mini-SWE-agent](../concepts/mini-swe-agent.md) v2.4.0 下运行，每任务限时两小时，每轮最多生成 16K 新 token。
* **方向与传递方式（表 1）。** 三个强模型与 Qwen3.8-27B 配对，在 30% 和 75% 检查点上比较两个方向，以及上下文内传递与日志文件传递。
* **时机曲线（图 3、图 6）。** 两个方向上 15% 到 90% 的六个检查点。
* **主要结果（表 3）。** 五个强模型（新增 Claude Opus 5 和 Gemini 3.8 Flash）交接给 Qwen3.8-27B 或 GPT-5.6 Luna，再加上 Luna 交接给 Qwen：11 个模型对 × 2 个基准 = 22 个设置。两种传递方式的完整结果见表 5。
* **基线（表 2、表 4）。** 提示强模型自行交接；请求级路由器（训练 Qwen3.5-2B 预测 Qwen3.8-27B 能否解出任务）；复现的 MTRouter；以及设为 AgentBaton 自身平均交接点的固定进度和固定轮次交接。
* **推理强度扫描（图 1、表 6）。** 在 DeepSWE 上让源模型使用多种推理强度，每种都用 AgentBaton 交接给 Qwen，其中四个源模型还交接给 Luna。

# Q8 证据质量

* **有支持的结论。**
  * *方向很重要。* 弱到强的交接大多会损失准确率或省钱很少；最好的情况是在 30% 处由 Qwen 交给 GPT-5.6 Sol，DeepSWE 上达到 70.80%（Sol 单独为 68.10%），但成本只降低 6.1%。强到弱的交接能以很小成本保住准确率：Kimi K3 在 45% 处交给 Qwen 得到 72.57%（单独 73.45%），成本降低 61.5%。
  * *各模型对普遍大幅省钱。* 表 3 中 22 个相对成本降幅平均为 65.9%（读者核对了摘要中的数字），22 个设置中有 12 个准确率提升或相对损失低于 5%。
  * *更强的接手模型有帮助。* 以 GPT-5.6 Luna 为接手模型时，五个强模型中有四个在 DeepSWE 上超过了各自单独运行的准确率，成本降低 66.6% 到 73.9%，例如 Opus 5 交给 Luna 为 76.1%，Opus 5 单独为 67.3%。
  * *提示无法替代检测器。* 被要求在就绪时交接，Kimi K3 从不交接（113 个任务中 0 个），GLM-5.3 只在 6 个任务上交接；GPT-5.6 Sol 每次都交接，但每任务仍花 3.75 美元（单独为 5.32 美元）。
  * *在线检测胜过简单规则。* 与 MTRouter 相比，AgentBaton 在测试的四个设置中成本低 46.7% 到 86.6%，准确率相同或更高；它在准确率上胜过固定轮次交接，并与使用了源模型未来轨迹长度的固定进度交接持平，成本相同或更低。
* **比标题弱或范围更窄的地方。**
  * *最便宜的模型按约定是免费的。* Qwen3.8-27B 因可在本地硬件运行而记为 0 美元，检测器的 GPU 时间也不计费。所以以 Qwen 为接手模型时的节省是 API 支出的节省，而不是总算力或硬件成本的节省（读者观察）；以 Luna 为接手模型、两边都付 API 费用的结果才是更干净的成本检验。
  * *单次运行、任务集小。* 没有报告重复运行或置信区间。DeepSWE 上一个任务是 0.88 分；Terminal-Bench 2.1 上所有数值都符合 89 个任务的集合，一个任务约 1.1 分（读者根据数值推断）。很多"保住准确率"的说法只差一到三个任务。
  * *同一配置出现不同数字。* 表 3 给出 GPT-5.6 Sol（max）在 DeepSWE 上为 68.1% 和 5.32 美元、GLM-5.3 为 61.1% 和 3.16 美元，而表 6 被描述为同一个 DeepSWE 扫描，却给出 71.7% 和 4.84 美元、69.0% 和 3.06 美元；AgentBaton 中 GLM-5.3 交给 Qwen 在表 3 是 58.4%，在表 6 是 66.4%。Kimi K3 和 Opus 5 的行一致。正文没有解释这一差异，这暗示同一配置的运行间波动可达约 8 分（9 个任务）（读者观察）。
  * *"准确率提升"的标题用了较弱的基线。* "最多提升 8.8 分"是 Opus 5 交给 Luna（76.1%）对比 Opus 5 在 max 强度下（67.3%）；而表 6 中 Opus 5 在 xhigh 强度下单独就有 75.2%，所以相对 Opus 最佳配置的提升约为 1 分，只是成本低得多（读者观察）。
  * *两个基准、一个脚手架、只有编程任务。* 两个基准都是代码或终端任务，都在 mini-SWE-agent 下运行；检测器训练用的 SWE-rebench V2 也属同类工作；五个训练模型中有四个也是测试时的强模型。只有 Gemini 3.8 Flash 和 GPT-5.6 Luna 是未见过的源模型。
  * *标签来自单一模型。* 交接点由 Codex 标注，没有与人工标注的一致性检查。
  * *两种传递方式按源模型选择。* 每个源模型的传递方式是在第 3 节对同一批基准的比较之后确定的；表 5 显示另一种方式可能差好几分（DeepSWE 上 Kimi K3 交给 Qwen：上下文内 72.6%，日志文件 65.5%）。

# Q9 贡献

* 对长程智能体任务中一次性交接的受控分析：跨模型对和两个基准，考察方向、上下文传递和时机。
* 从强模型交接给便宜模型的三个可观察就绪信号，并写成标注协议。
* AgentBaton：一个小型的逐轮学习检测器，并与提示交接、请求级路由、逐轮路由器和固定阈值做了比较。
* 推理强度扫描的证据：交接与推理强度是互补的"购买准确率"方式，在 DeepSWE 上有超出单模型准确率-成本前沿的配置。

# Q10 下一步

* **重复运行与总成本核算（读者建议）。** 每个配置跑三次，并用一个对本地推理和检测也计费的成本模型，可以看出哪些节省能经受住噪声和硬件成本。
* **超出编程任务（读者建议）。** 工具-智能体-用户任务、网页搜索或 GUI 任务可能有不同的就绪信号；在 SWE 轨迹上训练的检测器能否迁移过去尚未检验。
* **反向再升级。** 论文认为逐轮切换会累积错误，但当便宜模型卡住时偶尔再升级一次，或许能挽回部分损失；单向设计留下了这个问题。
* **经人工核对的标签。** Codex 标注的交接点与人工判断的一致性可以界定标签噪声。
* **与 harness 选择结合（读者关联）。** HEELO 发现强模型在诊断环节回报最大，这提示可以按角色而不只是按轮次在强弱模型之间分工。
