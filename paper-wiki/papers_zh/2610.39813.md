# Q1 问题定义

* **输入（X）：** 一串演化任务，可以来自单个基准，也可以是多个基准打乱后的混合；一个全局智能体池；执行轨迹和原生评测结果。
* **输出（Y）：** 一组冻结的持久知识：团队库（每个团队包含其支持的协作需求描述和一份候选名册）、每个团队一套交互规则，以及每个智能体的指导（提示补丁和可复用技能）。这些在互不重叠的留出任务上评分。
* **核心问题：** 多智能体系统如何在需要不同分工的任务之间持续改进协作，同时不让早先的协调经验损害后来的任务？
* **约束：** LLM 权重固定；所有方法共享工具、单任务预算和数据划分。

# Q2 问题新颖性

部分是新问题。经验驱动的单智能体改进已有长期积累（Reflexion、ExpeL、Voyager、ReCreate），近期工作开始演化协作本身：Meta-Team、[基于去中心化记忆的自演化多智能体系统](../papers/2605.22721.md)、SkillMAS、Skill-MAS 和 EMAS。这篇论文的新焦点是跨异构任务的持续演化。它的预研究发现，Meta-Team 在继承另一基准的演化结果后，甚至继承同一基准另一任务类别（团队模板兼容）的结果后，在目标任务上的成绩都低于只在目标上演化。作者归结为两个原因：重组被限制在一个共享团队内，以及交互规则被用到不相容的情境中。

# Q3 科学假设

如果把可复用的团队结构彼此分开，把交互规则限定在习得它们的团队内，而让个人技能跨团队共享，那么在混合任务上演化的系统相比只在单一基准上演化，就不应丧失性能。习得的规则应当在团队选择之外带来额外价值，没有规则时团队选择也应带来价值，而且演化产物在换用评测模型后仍应有用。

# Q5 关键解决思路

**把能力与组织解耦。** 全局智能体池保存所有智能体。团队 T = ⟨d_T, C_T⟩ 由它支持的协作描述和从智能体池选出的候选名册组成。LLM 团队选择器检查是否有团队符合查询的协作需求和功能角色，仅主题相似并不够。没有合适团队时，由组合器构建临时团队。团队按协作需求而不是按基准组织，所以在一个案例中，来自 LoCoBench、LOCA-Bench 和 BeyondSWE 的留出任务复用了同一个分析-实现-验证团队。

**按任务招募和规划。** 主席（Chairman）从名册招募执行团队，把查询分解为子任务并分配，进度受阻时可在团队内重新分配。因此同一团队在不同任务上可以启用不同成员。

**限定规则范围。** 只把所选团队的规则集注入智能体上下文，作为软性指导。每次交接时，发送方根据发送-接收对、规则触发条件和当前需求判断规则是否适用；不适用就直接沟通。规则规定的是交接必须携带哪些信息和证据，而不是完整流程。

**三个层次的反思。** 系统记录个人轨迹和交接轨迹。团队反思器修订名册和描述，并决定临时团队能否入库（名册必须支持所需分工且可复用）。规则反思器根据交接事件和传递内容增加、修改或删除规则。智能体反思器根据个人轨迹更新其技能。规则留在团队内，技能留在智能体身上并跨团队使用。全部内容在留出评测前冻结。

**论文强调的对比。** 在一个 LOCA-Bench 案例中，Meta-Team 的反思把累积的 45、43 和 31 条档案笔记各替换成一条，并按队友名称共享，没有任何基准条件。EvoTeam 的更新只增加一条限定任务族的规则，其余保留。作者也说明，这次覆盖发生在评测之后，因此不能解释该任务的分数差异，而 EvoTeam 的招募档案同样是共享的。

# Q6 实验设计

* **基准与划分（演化/留出）。** GAIA 验证子集（20/100），LoCoBench Python 的功能实现和跨文件重构（各 20/80），[LOCA-Bench](../concepts/loca-bench.md)（96K 上两个种子共 16 个/其他长度和种子上共 240 个），BeyondSWE 的 CrossRepo（20/180）和 DepMigrate（20/158）。子集和划分沿用 Meta-Team。
* **两种演化设置。** 单基准：每个基准或赛道单独演化。混合：116 个任务按一个固定的打乱顺序（种子 20260828）交错，演化同一系统，并在全部 838 个留出样例上评测。
* **基线。** ReAct 单智能体、与 EvoTeam 协作结构相同但不演化的 MAS、OWL、AgentSquare、ReCreate、Meta-Team 和 Skill-MAS，尽量使用官方实现，并统一模型、工具和预算。
* **模型与指标。** GPT-5.6-Luna（温度 0.2），跨模型实验在 GAIA 和 LoCoBench 上加入 DeepSeek-V4.1-Flash。指标为 GAIA 答案准确率、LOCA-Bench 最终状态成功率、BeyondSWE 解决率（全部 F2P 和 P2P 测试）以及 LoCoBench 的加权 LCBS。论文说明每个测试样例取三次 rollout 的平均（avg@3）。
* **消融与成本。** 在全部六个指标上移除规则、移除团队和规则；单任务成本与分数的比较见图。

# Q8 证据质量

* **有支持的结论。**
  * *混合任务流上领先。* 六个指标全部第一：GAIA 77.00 对 Meta-Team 的 67.00，LOCA-Bench 67.08 对 58.33，LoCoBench 65.55 和 65.65 对 64.90 和 64.52，DepMigrate 40.51 对 37.97，CrossRepo 41.67 对 40.56。
  * *对混合稳健。* 平均分从单基准的 58.85 变为混合的 59.58，而 Meta-Team 从 58.30 降到 55.55。
  * *规则和团队在若干任务上各有贡献。* 规则在 GAIA 上贡献 10.00，在 LOCA-Bench 上贡献 8.75；无规则时团队贡献 6.00 和 2.50。
  * *产物可在模型间迁移。* 六组比较中，跨模型结果都与同模型结果相差不超过 4.00，并高于不演化的 MAS，例如在 DeepSeek-V4.1-Flash 上 GAIA 为 76.00 对 58.00。
* **比标题说法更弱或更窄之处。**
  * *单基准演化几乎打平。* 平均分只领先 0.55，Meta-Team 明显赢下 LOCA-Bench（69.58 对 63.75），小胜 CrossRepo（41.67 对 41.11）。GAIA 的 5 分差距就是 100 题中的 5 题。
  * *混合领先高度集中（读者计算）。* 六个指标的差距合计 24.18 分，其中 18.75 分来自 GAIA 和 LOCA-Bench。移除规则后，这两项分数恰好等于 Meta-Team（67.00、58.33），可见这两项的领先完全来自规则。
  * *演化的知识可能有害。* 附录显示，移除规则反而提高 LoCoBench 重构成绩（66.40 对 65.65）；在 DepMigrate 上，两者都移除优于只移除规则（37.97 对 36.71）；正文的图只展示了不含这两项的四个任务。按论文给出的差值，只保留技能演化的变体在 GAIA 上得 61.00，低于不演化 MAS 的 72.00（读者计算），说明在混合任务流上累积技能可能先失分，再靠规则和团队挽回。
  * *没有技能消融。* 技能跨团队共享，这一层面的干扰仍可能发生，也没有变体移除或限定技能（读者观察）。
  * *只有一种任务顺序。* 正文描述的是 116 个任务的一个固定打乱顺序，每个来源约 20 个，也没有重复演化，因此顺序和随机反思器的影响都没有被测量（读者观察）。
  * *rollout 次数存疑（读者推断）。* 论文说明用 avg@3，但表 1 中 LOCA-Bench 和 BeyondSWE 的每个分数都恰好是留出样例的整数个（如 240 个中的 161 个、158 个中的 64 个），对三次二元 rollout 取平均很少会这样。这些分数可能来自每个样例一次运行。
  * *未报告团队库规模。* 正文没有说最终有多少团队和规则，所以无法从数字判断复用范围有多严格（读者观察）。
  * *成本和预研究是图表证据。* 本笔记只通过图注和相关正文阅读这些图。

# Q9 贡献

* 一个以协作为中心的架构，把持久知识分为三种范围不同的类型：可复用团队、团队专属规则、跨团队的智能体技能。
* 证据表明（在一种任务顺序下），共享系统在混合任务流上演化，平均性能不低于单基准演化。
* 从角色和规则层面解释跨任务经验复用为何会失败，并用消融显示规则在哪里有用、在哪里无用。
* 对演化后团队产物进行双向的跨模型检验。

# Q10 后续方向

* **多模态场景（来自论文）。** 评测未覆盖视觉交互环境，那里智能体必须共享视觉证据，并随场景变化协调行动。
* **与模型适应结合（来自论文）。** 经验在权重固定的情况下显式存储，其价值依赖模型的理解；训练可以把常用的协调做法内化到模型中。
* **团队库维护（读者问题）。** 算法 1 只修订或增加团队，没有合并或淘汰步骤。在长任务流上，团队库会增长到多大，选择准确率能否保持？
* **用证据把关更新（读者建议）。** 更新由反思直接接受，没有配对检验。与论文介绍的 EMAS 那种对照当前系统的验证相比较，也许能解决规则降低分数的情形。
* **重复并改变任务流（读者建议）。** 多种任务顺序和重复演化，并报告团队库规模和规则数量，才能说明混合领先是否稳定。
* **把技能也限定范围（读者建议）。** 比较限定任务族的技能与全局技能，可以回应只有技能演化时在 GAIA 上的下降。
