# Q1 问题定义

* **输入（X）：** 一个案例，包含公开的任务指令和工具接口：读取记录的信息工具，以及改变应用状态的后果性工具（退款、发送、更新）。对智能体隐藏的是：每个后果性动作 a 的证据要求 R(a)（目标实体、当前状态、金额、授权、版本），预期的动作与参数，以及动作之间的依赖。
* **输出（Y）：** 智能体可观察的轨迹（信息调用、后果性调用、返回的回执、最终决定），由确定性评估器打出二元的"案例完全成功"（exact case success，ECS）：执行 a 之前，R(a) 中每项要求都已由先前的观察确立；调用使用了正确的工具、目标与精确参数；后续动作使用前驱动作*实际*返回的结果；当证据不支持行动时，不发生任何动作。
* **核心问题：** 正确的终态并不说明动作有依据。智能体可能向正确的扣款发出正确的退款并拿到成功回执，却从未先确认这笔扣款确实重复、确实可退。论文要回答：随着任务从"决定是否行动"走向"单个动作"，再到"相互依赖的多动作工作流"，这条"证据→行动"链条在哪里断裂。

# Q2 问题新颖性

部分新颖。交互式工具使用基准（AgentBench、WorkArena、OSWorld、WorkBench、AppWorld、τ-bench 及其后继）评的是结果与终态；ToolSandbox 增加了里程碑 DAG 与顺序约束；Agent-SafetyBench 研究危险动作；同期的 Near-Miss 检查变更型调用之前是否有满足策略要求的只读观察；EnvTrustBench 研究对过时或被篡改观察的信任；AgentAbstain 研究暂缓不可逆动作。SafeActBench 的对比表（附录 A）称它是唯一同时把以下各项作为评分要求的基准：行动前的证据、证据与正确实体和状态的绑定、返回结果的传递，以及*经调查的不行动*（investigated non-action，即只在完成足以支持"不行动"的调查后才停止）——而且全部从轨迹上判定，不用 LLM 评审。

# Q3 科学假设

1. **会判断不等于会做。** 如果让能在完整证据下正确判断给定动作的智能体，改为自己收集证据、自己构造动作，成功率会大幅下降（Legacy 对比 V1-V3；附录 C.2 的同案例对照）。
2. **失败发生在上游。** 若把链条拆开，大多数失败会来自调查不完整或过早行动，而证据完整之后的执行是可靠的（BSR、PAR、CAS）。
3. **工作流带来新的失败类型。** 多动作工作流会在后续检查点出现未满足的前提，以及只执行了一部分的工作流（Gap、Part.）。
4. **框架改变的是失败类型，而不只是比率。** 同一模型在其家族自带框架（harness）和共享 ReAct 框架中，成功率和主导失败模式都会不同（配对比较，附录 C.3）。
5. **智能体对缺失证据不够敏感。** 若扣下一条关键记录，许多智能体仍会行动；而缺失支持的呈现方式比泛泛的警告更能改变行为（干预与探针实验）。

# Q5 关键解法思想

* **五个难度递增的协议：** **Legacy**（86 例；对给定候选动作做 Allow/Block/Defer 判断，不对轨迹打分）、**V0** 经调查的不行动（175 例；完成要求的调查后不行动）、**V1** 单动作（131 例；确立证据后恰好执行一个正确动作）、**V2** 线性多动作（132 例；后续动作使用先前动作的实际结果）、**V3** 依赖约束多动作（132 例；可按 DAG 的任意拓扑序执行，含分叉与汇合）。六个领域：客户与策略运营（112）、工程与基础设施运营（109）、法律与金融运营（144）、科研助理（97）、智能家居（96）、医疗运营（98）。一条正确轨迹平均需要约 5.6-7.1 次指定读取，最多 17 次。
* **证据账本（Evidence Ledger）。** 每个已确立的事实都绑定到其来源调用以及它所描述的实体和状态，因此在扣款 C1 上读到 $49.99，即使数值相同，也不能确立扣款 C2 的金额。动作返回的结果可以直接支撑依赖它的动作；当工具语义要求时，必须先观察到新状态。
* **确定性评估器。** 按私有规格重放轨迹，检查调查是否完整、工具、目标、参数、回执、依赖与终止条件。它不读取隐藏推理，也不使用 LLM 评审。
* **诊断指标。** BSR（V0 中未完成调查就停止的回合）、PAR（V1 中在调查完成前发起的动作）、CAS（V1 中首次动作发生在调查完成之后时的成功率）、Gap（V2/V3 中某个动作检查点存在缺失要求的回合）、Part.（V2/V3 中执行了动作但工作流失败的回合）。Gap 与 Part. 可以重叠。

# Q6 实验设计

* **智能体。** 五个模型（Claude Opus 5、GPT-5.6 Sol、DeepSeek-V4-Flash、Qwen3.8-Flash、GLM-5.2），每个分别运行在其家族框架（Claude Code、Codex、DeepSeek Harness、Qwen Code、ZCode）和基于 Inspect AI 的共享 ReAct 框架中，共十种配置。所有配置使用相同的公开任务与工具；开源模型温度 0.6、top-p 0.95，GPT 与 Claude 用服务商默认采样并开启高推理强度，同一模型在两个框架下设置一致；每例 600 秒，并有按案例设定的信息调用上限。
* **主评测。** 每个"案例-配置"组合跑三次；比率在每次重复内计算后取平均；覆盖率 100%。
* **框架比较。** 在 570 个 V0-V3 案例上按案例配对，95% 案例自助法区间（5,000 次重采样）；每次重复的结果见附录 C.9。
* **同案例的静态与交互对比。** 三种配置在 100 个 V1 案例上比较（静态：给完整证据和一个有效候选；交互：原始任务），另有 24 个无效参数负例；以及一个类别平衡的对照：99 个情景（33 个基础任务 × Allow、Block、Defer），覆盖全部十种配置。
* **干预。** 在 43 个冻结的 V1 案例上，用 DeepSeek-DSH、GLM-ZCode 与 Qwen-Qwen Code：Withheld（扣下一条关键记录）以及其中 22 例的 Contradicted（修改某字段使前提被违反）。从 Withheld 状态出发的探针：呈现相关返回内容的证据包、请求者声称缺失记录已核查无误、泛泛的紧迫提示、明确警告"缺失证据不代表安全"，以及无关的干扰记录。配对案例自助法，10,000 次重采样。
* **基准验证。** 全部 656 个参考解都通过；两名盲审标注者在 120 个分层抽样案例上重建要求；在目标动作检查点审计 300 条模型轨迹；替代证据路径的重放，以及错误实体与过时证据的负对照。
* **补充研究。** SCGR：一个无需训练的运行时，保留由模型选择的证据账本，并在提交前运行公开的结构检查，有两个变体（SCGR-Select、SCGR-EG）。

# Q7 数据集与代码

SafeActBench 是新基准：656 个规范案例，建立在虚构实体、记录与策略构成的合成环境上（没有真实用户数据）。资源链接见 [safeact.github.io](https://safeact.github.io)，Hugging Face 列出的 GitHub 仓库为 [caoshidong66/safeact](https://github.com/caoshidong66/safeact)。附录 B 记录了构成、复杂度、验证、运行设置、失败处理以及每个指标的精确定义；附录 D 给出六条带注释的轨迹。

# Q8 证据质量

* **有支撑的结论。**
  * *判断给定动作比亲自执行容易。* 总体 ECS 从 37.7%（GLM-ZCode）到 67.2%（Claude-Claude Code）。GLM-ZCode 在 Legacy 上得 97.7%，在 V1-V3 上只有 32.1%、12.1%、34.1%；DeepSeek-DSH 在 Legacy 上 96.5%，V1-V3 为 61.1%、65.2%、59.1%。在同样的 100 个 V1 案例上，静态准确率为 95-99%，交互 ECS 为 28-52%，差距 43-69 个百分点，区间均不含零。
  * *失败始于执行之前。* V0 上 BSR 为 21.7-62.9%，V1 发起动作的回合中 PAR 为 37.0-66.9%，而十种配置中有九种的 CAS 为 93.2-100%（DeepSeek-Inspect 为 83.3%）。
  * *框架效应依模型而异，且在重跑中稳定。* 在 570 个配对案例上，DeepSeek 在自家框架中提升 4.4 个百分点 [1.1, 7.9]，GLM 在 ZCode 中下降 6.8 [−11.2, −2.5]；Claude、GPT、Qwen 的区间包含或触及零。各次重复间的标准差为 0.2-0.7 个百分点，三次重复的方向一致。两个 Qwen 框架在 570 个案例中有 134 个结论不同（75 个只在 Qwen Code 下成功，59 个只在 Inspect 下成功）。
  * *缺失证据常常拦不住行动。* 扣下一条关键记录使行动概率下降 37.2-45.2 个百分点，但 Withheld 回合中仍有 46.5-53.5% 采取了行动；矛盾证据在其子集上使行动概率下降 54.5-70.0 个百分点。从 Withheld（DeepSeek、GLM、Qwen 分别为 23/43、20/43、23/43 次行动）出发，证据包把行动降到 18/43、14/43、13/43，而请求者声称"记录已核查"则降到 6/43、10/43、6/43，三者的区间都不含零。紧迫提示和明确警告没有可靠效果。
  * *评估器经过审计。* 标注者在动作支持上一致率 95.83%（κ 0.87），在要求必要性上 93.36%（κ 0.81），在要求是否确立上 86.72%（κ 0.74）。在 300 条审计轨迹上，评估器误接受 3/150（2.0%），误拒绝 2/150（1.3%）；20 个错误实体对照和 30 个过时证据对照全部被拒，修复一个日期处理缺陷后，所有被测的有效替代路径都被接受。
* **比标题更弱或更窄的部分。**
  * *巨大的静态-交互差距主要来自"构造动作"。* 在两种条件都提供候选的类别平衡对照中，大多数配置的静态优势缩小到 5.1-13.1 个百分点，GLM-Inspect 甚至反转（−10.1）。作者指出两种条件下的无效输出数量不同（Claude-Inspect 的 22.2 个百分点差距背后是静态 5 个、交互 24 个无效输出），因此其中混入了输出格式的可靠性。
  * *V0 失败不等于不安全行动。* 如果智能体正确地没有行动，但在读完案例要求的全部记录之前就停下，V0 也判失败；作者说明 V0 低分不应被理解为不安全行动率。因此 BSR 与 PAR 部分衡量的是对作者证据规格的遵从，而部分案例的规格包含指定来源和查询次数（附录 B.3）。
  * *干预样本小。* 干预只用了 43 个 V1 案例、三种配置、每个条件一次重复，并且只用 Original 的第 1 次重复；若干探针的区间包含零，跨框架干预检查中原生框架和 Inspect 的运行采集于不同时间。
  * *把证据结构化并不稳定地有帮助。* SCGR-Select 使 Qwen-Qwen Code 的 ECS 提高 11.6 个百分点，却使 Claude-Claude Code 下降 9.1、GPT-Codex 下降 2.6、GLM-ZCode 下降 2.8；SCGR-EG 使十种配置都提升 0.3-16.2 个百分点（GLM-ZCode 从 37.7 到 53.9），但它加入了自动工具扫描，因此收益混合了结构化与更多检索。
  * *合成的、由作者规定的案例。* 六个领域都是虚构的，作者声明结果不是对真实部署的安全认证。总体 ECS 还把 86 个 Legacy 案例与 570 个交互案例混在一起；只看 V0-V3，家族框架下的排名为 Claude 62.6、Qwen 62.1、GPT 60.7、DeepSeek 57.9、GLM 28.6（附录 C.9）。

# Q9 贡献

* 把后果性工具使用表述为一条可观察的"证据→行动"链：每个动作之前有绑定到实体与状态的证据、经调查的不行动，以及实际动作结果沿依赖的传递。
* SafeActBench：656 个案例、五个协议、六个领域，一个绑定来源的证据账本，以及一个经人工标注与轨迹审计验证、不用 LLM 的确定性评估器。
* 一项覆盖十种"模型-框架"配置的分析：定位失败（上游的调查与时机，工作流中的前提与不完整执行），用配对区间量化框架效应，并通过干预表明智能体会在缺少证据时行动，且对请求者的说法比对证据缺失本身更顺从。

# Q10 下一步

* **对工作流做干预。** 作者提出在每个 V2/V3 检查点改变证据，那里的依赖动作能揭示智能体是否把后续步骤绑定到先前结果上。
* **请求者声称作为攻击面（读者推断）。** 当请求者声称缺失的检查已通过时，智能体更少行动，这里降低了行动率；同样的顺从也可能在请求者声称某个失败的检查已通过时提高行动率。测试相反方向的声称，可以把这个基准与提示注入和社会工程风险联系起来。
* **在框架中设门。** 既然证据完整后的执行是可靠的，那么在框架层面加一个行动前检查、在所需读取齐备之前阻止后果性调用，可以直接针对 PAR；SCGR 的混合结果说明这种检查必须被强制执行，而不是仅仅提供给模型。
* **校准 V0。** 报告有多少 V0 失败的回合读取了智能体自己认为关键的全部记录，以区分调查不足与"不同意作者规格"。
* **与本仓库的契合（读者笔记）。** 本仓库中的智能体会在读取状态后采取后果性动作（提交、推送、定时运行）；"经调查的不行动"和"行动前把证据绑定到确切目标"可以直接作为审查这些运行的标准。
