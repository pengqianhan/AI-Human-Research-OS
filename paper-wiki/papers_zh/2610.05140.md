# Q1 问题定义

* **输入（X）：** 一个科学领域、该领域的种子基准（100 道种子题及其数据文件）、生成智能体可检索的科学文献，以及一个负责规划、实现、求解和评审的前沿编码智能体（Claude Code 配 Claude Opus 4.8，或 Codex 配 GPT-5.6 Sol）。
* **输出（Y）：** 一个由任务组成的基准，每个任务包含问题、一组科学数据文件和一个可用精确匹配核对的标准答案；回答它需要分析文件，而不是读题或回忆事实，并且当前的求解器做不出来。
* **核心问题：** 科学智能体基准构建缓慢、昂贵，且很快饱和。论文要回答：能否自动生成这类基准，并根据智能体实际的解题方式自动修订，使任务无法靠"只读一个工具输出"之类的捷径解答，而必须重新检查原始数据、核对中间结果并整合证据。

# Q2 问题新颖性

部分新颖。面向 LLM 问答的自动基准生成已有工作：AutoBencher 与 BenchMaker 依据声明式目标或质量标准生成实例，BenchAgents 与 Benchmark Self-Evolving 分阶段构建或通过变换扩展基准，S-Eval 依据风险分类生成安全提示。论文认为这些方法生成的不是智能体任务，因为智能体任务需要数据和环境，答案必须从中获取。它的新增部分是：两层规划（先概念、后配方），决定哪些信息直接给出、哪些必须通过分析恢复；由求解轨迹驱动的修订；以及把过去的修订经验用于生成新概念。

# Q3 科学假设

1. **生成的任务更难，但质量不差。** 如果任务按"概念 + 配方"规划，并修订到可验证且无人解出为止，求解器在其上的准确率会低于人工构建的种子基准，而评审给出的质量不会下降（表 1 与表 2）。
2. **修订提高难度。** 如果依据观察到的求解行为修订任务，困难任务的比例会随轮次增加，修订会把任务推向重新检查原始数据和整合证据（图 4）。
3. **经验可以迁移。** 如果把早期修订历史的摘要交给概念生成，新概念产生的任务会比独立生成的概念更难（表 3）。
4. **应当修订的是计划。** 修订概念与配方比直接修订已实例化的任务更能提高难度（图 5）。

# Q5 关键解法思想

1. **概念（concept）** c = （领域，数据模态，所需操作），依据从种子题推断出的概念，以及从近期文献中抽取的工作流和反复出现的分析模式来提出；会给出先前的概念以避免重复。
2. **配方（recipe）**，一个七字段的计划：数据策略（复用基准数据、从网上获取或模拟）、数据计划、答案如何构造与隐藏、标准答案如何计算与验证、答案格式、工具与资源，以及题目如何避免泄露解法。
3. **实现。** 智能体获取或构建数据，用代码计算并验证答案，写出一道答案唯一、可精确匹配的题目。
4. **求解与评审。** 生成模型自己做三次独立求解；评审读取题目、数据、参考答案、作答与轨迹，评定可验证性与难度（有效试次全对、部分对、全错分别为容易、中等、困难），并给出理由。
5. **修订。** 若任务不同时满足"可验证"和"困难"，就修订配方；连续四次修订配方仍不满足时，修订概念本身。最多 10 轮。
6. **经验。** 每段完成的修订历史（无论成败）都被总结为一张卡片，包含经验教训、有效设计、反模式和建议；最多 12 张卡片和 120 个先前概念用于指导下一批概念的生成。

与问答生成方法的预期区别在于：推动修订的是求解行为，而不是固定的质量量表——轨迹中出现的捷径会变成数据设计上的修改。论文的例子在 UMI 条形码中加入测序错误，使"数不同序列的个数"不再能得到答案，此后三次求解全部失败。

# Q6 实验设计

* **领域与种子。** 计算生物学（CompBioBench 全部 100 题）、材料科学（抽样 100 个 MatTools 代码生成任务）、临床影像（MedCTA 训练集中 100 题）。
* **生成。** Claude Code CLI 配 Claude Opus 4.8，以及 Codex CLI 配 GPT-5.6 Sol，每种条件下所有阶段使用同一模型，该模型同时担任修订阶段的求解器；高推理强度，温度用 CLI 默认值，每阶段 3,600 秒。每个领域、每个生成器：五次经验引导的迭代，每次 10 个概念，每个概念一次修订运行，每次运行保留一道题，优先保留难度更高的（共 50 题）。
* **求解评测。** 十个模型（Claude Opus 5、Opus 4.8、Opus 4.7、Sonnet 5、Haiku 4.5、GPT-6 Astra、GPT-5.6 Sol、Terra、Luna、GPT-5.5）求解生成的任务和种子基准；CompBioBench 的分数取自其官方排行榜，其中若干是在不同或未报告的推理强度下得到的；人工构建的临床影像结果被省略，因为 MedCTA 由 LLM 评分。
* **质量。** 两个 LLM 评审（Claude Opus 4.8 与 GPT-5.6 Sol）按 1-5 分为可验证性、有用性与"适合智能体评测程度"（fitness）打分，并报告评审间的排序一致性。
* **消融**（仅材料科学、仅 Claude Opus 4.8）：有无经验引导的概念生成（共享 10 个初始概念，各 50 题）；完整框架对比去掉配方、去掉概念与配方。
* **成本。** 每道生成题的美元成本，以及实现和求解阶段所占比例。
* **未纳入设计的部分。** 没有领域专家审查生成的题目或参考答案；没有人工质量评分；生成流程没有重复运行；没有来自两个生成器之外模型家族的评审。

# Q8 证据质量

* **有支撑的结论。**
  * *生成的任务更难，尤其是 Opus 4.8 生成的。* 十个求解器的平均准确率：CompBioBench 为 79.8%，Opus-4.8 生成集为 57.4%，GPT-5.6-Sol 生成集为 74.1%；MatTools 为 95.7%，两个生成集分别为 70.2% 与 77.6%。摘要中的"22.4 与 25.5 个百分点"是 Opus-4.8 生成集的降幅；GPT-5.6-Sol 生成集的降幅为 5.7 与 18.1 个百分点。
  * *在材料科学中更能拉开模型差距。* 十个求解器在 MatTools 上都在 92.7-97.7%，而在 Opus-4.8 生成集上从 21.3%（Haiku 4.5）到 90.0%（Claude Opus 5）不等。
  * *唯一一次消融中，经验有帮助。* 没有经验卡片时求解成功率为 66.7%，困难任务占 15.0%；有经验卡片时为 35.0% 与 50.0%。
  * *两个评审都更偏好生成的任务。* 两位评审平均后，计算生物学两个生成集质量为 3.93 与 4.28，CompBioBench 为 3.18；材料科学为 3.87 与 4.06，MatTools 为 2.54；临床影像为 3.07 与 4.02，MedCTA 为 2.23。每位评审单独打分时排序相同，合并后的评审间排序相关为 0.74-0.87（Spearman）。
* **比标题更弱或更窄的部分。**
  * *难度部分是筛选出来的。* 生成器同时是修订阶段的求解器，修订持续到它的三次求解全部失败（或满 10 轮），每次运行保留最难的那道题。因此生成模型自己准确率低，在一定程度上是构造使然。其他求解器的分数也更低，说明难度可以迁移，但与人工基准的对比是"经过筛选的集合"对"未经筛选的集合"。
  * *"随智能体更新基准"的结果被同一筛选所混淆（读者推断）。* 在 Opus-4.8 生成集上 Claude Opus 5 比 Opus 4.8 高 19.5 个百分点，在 GPT-5.6-Sol 生成集上 GPT-6 Astra 比 GPT-5.6 Sol 高 15.1 个百分点。任何与筛选所针对的模型不同的模型都会在这样的集合上获益，因此这个差距会高估新模型进步的速度。
  * *参考答案没有经专家核查。* 答案由生成器自己的代码计算，常常基于模拟数据（微卫星不稳定性的例子使用合成参考序列与模拟的 BAM 文件），可验证性也由同一模型家族评判。一道题没有任何试次解出，可能是因为参考答案错了或题目有歧义；生成集的可验证性得分只有 2.99-4.08，说明评审自己也认为部分题目有歧义。
  * *质量评审就是生成器。* Claude Opus 4.8 与 GPT-5.6 Sol 在评价它们自己生成的基准。GPT-5.6 Sol 给自己的计算生物学集打分比 Opus 4.8 的集高 0.58 分，而 Opus 4.8 给两者的分差只有 0.12。"适合度"标准（是否需要观察、规划、工具执行）描述的也正是生成器被要求构建的东西，因此 MatTools 有用性与适合度的低分（1.49 与 1.39）部分反映的是：一个代码生成基准被拿去对照一份面向智能体分析的量表来评判（读者推断）。
  * *基线不一致。* 人工 CompBioBench 的分数来自排行榜，其中若干在不同或未报告的推理强度下得到，临床影像也没有人工基准的对比。
  * *消融范围窄。* 经验与规划的消融各只用一个领域、一个生成器、50 道题、一次运行；图 5 的曲线在正文中没有给出数值。
  * *成本。* 用 Opus 4.8 每道题 22.36-58.47 美元，用 GPT-5.6 Sol 为 110.45-114.11 美元，其中 79-92% 花在实现和求解上；若这些数字是按保留下来的题目计算，一个 50 题的基准每个领域、每个生成器约需 1,100-5,700 美元（读者估算）。

# Q9 贡献

* 一个把科学智能体基准构建变成循环的框架：概念与配方规划、带数据文件与已验证答案的实现、求解与评审、依据反馈修订计划，以及经验引导的新概念生成。
* 在计算生物学、材料科学和临床影像中生成的基准：相对种子基准降低了求解器准确率，并在种子基准饱和之处拉开了模型差距；附十二个完整示例和全部提示词。
* 消融表明：修订历史能改进之后的概念生成，修订结构化计划比直接修订任务更能提高难度。

# Q10 下一步

* **专家验证。** 请领域专家核查一部分生成的题目和参考答案，尤其是无人解出的题，以估计"难"中有多少其实是"错"。
* **独立的筛选与评审。** 用一组与被评测模型不重叠的固定求解器来筛选难度，并用未参与生成的模型家族或人工来评判质量。
* **重复生成。** 在每个领域多次运行流程，看任务难度和基准排名有多稳定。
* **随时间的饱和。** 用更新的模型（Opus 5、GPT-6 Astra）重新生成，检查差距是否重新拉开——这正是论文所主张、但尚未端到端检验的"自适应评测"。
* **发布。** 不发布生成的任务和代码，其他团队就无法审计或复用这些基准。
* **与本仓库的契合（读者笔记）。** "概念-配方-修订"循环可以作为为本仓库研究智能体构建评测任务的模式，前提是参考答案由不同于构建它的模型来独立核查。

# 相关

* [智能体基准与评测](../topics/agent-benchmarks.md) - 一种基准构建方法而非固定基准：任务被生成、求解、评审并修订，直到当前智能体做不出来；构建、求解与评审都由同一批前沿模型完成。
* [AI for science](../topics/ai-for-science.md) - 在计算生物学、材料科学与临床影像的数据分析任务上评测科学智能体，这些任务中的中间结果是需要解读的证据，而不是通过/失败式的反馈。
* [LLM-as-a-Judge](../concepts/llm-as-a-judge.md) - LLM 评审在修订中评定可验证性与难度，并为最终质量打分（可验证性、有用性、适合度）；质量评审就是两个生成模型，没有人工评分。
* [HyperBrowseComp](../papers/2610.03574.md) - 同样用之后会被评测的模型来筛选题目；AutoSciBench 更进一步：生成器就是修订阶段的求解器，并且每次运行保留最难的题。
* [False Frontiers](../papers/2609.39102.md) - 表明评估者不独立于提议者的"提议者-求解者"循环可能收敛到错误答案；AutoSciBench 不涉及训练，但修订阶段的生成器、求解器与评审是同一模型，因此错误的参考答案与评审对它的判断可能有同样的盲点。
* [ASI-Bench](../papers/2608.17271.md) - 一个覆盖 11 个领域、60 个任务的固定自主科研基准；AutoSciBench 则自动构建范围更窄、可精确匹配的数据分析任务。
