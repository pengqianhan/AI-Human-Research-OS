# Q1 问题定义

* **输入（X）：** 一个候选公开 Python 仓库（有包元数据、非空本地测试集、至少五个实现文件、少于 40,000 行；不依赖外部服务、网络、图形界面或专用硬件），并排除已被现有编码基准使用的仓库。
* **输出（Y）：** 训练环境 e = (I, W, V, O)：语言规格说明 I、隔离的工作区与运行时 W、由仓库自身测试构成的验证器 V，以及作为隐藏 oracle 的原始代码 O。智能体拿到 (I, W) 后需重建整个项目，V 给出 [0, 1] 的分数。
* **约束：** oracle 必须得满分、空工作区必须得零分；修订的好坏不靠运行解题智能体或训练模型来判断；循环预算固定，最多 12 轮。

# Q2 问题新颖性

DeNovoSWE、MindForge 等仓库级环境流水线是线性的：在固定参考实现周围修文档或修构建，仍不合格的仓库就丢弃。ProgramGym 用执行诊断与覆盖率来修构建、加强测试，提高的是可靠性，而不是任务要求的工作量。BenchEvolver、SETA、DataMaster 以学习者的 rollout 或下游训练为反馈，对长程任务而言又慢又贵。RepoFactory 同时修订 oracle 实现、规格说明与测试，并用训练价值的廉价代理（调用图耦合度、代码规模加依赖广度）而非模型反馈来引导；论文称这是首个以此方式演化全仓库生成环境的工作。

# Q3 科学假设

oracle 代码的静态属性（函数之间的相互依赖程度、涉及多少代码和依赖）可以作为环境训练价值的代理。在有效性检查之下优化它们，既能挽回线性流水线会丢弃的仓库，也能产出更能训练长程编码智能体的轨迹。

* **仓库级软件任务：** SWE-Gym、SWE-smith、R2E、OpenSWE、ScaleSWE、SWE-rebench；DeNovoSWE、MindForge、RefactorForge、TrajLong、ProgramGym。

# Q5 核心方法

1. **目标 Q = A · C · S：** 有效性 A 仅当 oracle 满分且未改动的工作区零分时为 1。结构耦合 C = R / N²，即 oracle 静态内部调用图中可达的有序函数对（含自身对）所占比例。实现规模 S = log10(LOC) + log10(1 + D) − 2，D 为直接运行时依赖数。
2. **构建流水线：** 搜索并筛选仓库；构建 Docker 镜像，仅当所有测试在新容器中离线通过才保留；用 AST 扫描器提取公开类、函数、签名及测试导入的符号；合成智能体撰写规格说明与 API 清单，并与测试导入的符号核对。
3. **环境演化循环：** 先根据验证报告修复有效性。之后若 S < 0.5 或 C < 0.01，优先提升该项；否则由智能体自选。每次对 oracle、规格与测试的修订都重新验证，只有目标分数严格上升才保留；最多 12 轮。所有构建智能体都用 Qwen3.8-Max。
4. **训练数据：** Qwen3.8-Max 在每个环境上跑五次；保留奖励高于 0.5 且通过确定性检查与大模型评审质检的轨迹：来自 5,577 个环境的 10,947 条样本，用于监督微调（三个 epoch，峰值学习率 1e-6）。

# Q6 实验设计

* **模型：** 在这些轨迹上微调的 Qwen3.5-35B-A3B（RepoHorizen-35B-A3B），以及一个不做环境演化的变体。
* **基准：** NL2Repo-Bench（按自然语言描述构建仓库）、SWE-bench Verified、SWE-bench Pro、SWE-bench Multilingual、Terminal-Bench 2.1；使用 Claude Code 2.1.140 harness，上下文 262,144 token，用量达 80% 时压缩，温度 1.0。
* **数据源对比：** 六个开放 SWE 数据集（OpenSWE、R2E、ScaleSWE、SWE-smith、SWE-rebench、SWE-rebench-v2）按同样方式采集与清洗轨迹，各 11,000 条，微调同一基座；另列出已发表结果。
* **扩展性：** NL2Repo 准确率随训练环境数的变化，以及在 9B、27B、35B-A3B 基座上的表现。
* **目标消融：** 挽回：抽样 500 个仓库，比较最多三次修复与不修复。训练价值：从同样 1,000 个环境出发做两次演化，一次只优化 S、一次只优化 C；第 3、6、9、12 轮后的环境分别为 1 到 4 级，每级提供 2,000 条轨迹用于微调。

# Q8 证据质量

**主要结果（表 1，Claude Code harness）。**

| 模型 | NL2Repo | Verified | Pro | Multilingual | TB2.1 | 平均 |
|---|---|---|---|---|---|---|
| Qwen3.5-35B-A3B（基座） | 23.8 | 65.8 | 42.4 | 59.7 | 33.7 | 45.1 |
| RepoHorizen-35B-A3B | 46.4 | 72.2 | 47.6 | 61.0 | 40.5 | 53.5 |
| 不做环境演化 | 41.3 | 70.9 | 45.1 | 60.8 | 39.3 | 51.5 |
| Qwen3.5-122B-A10B | 27.7 | 73.4 | 49.5 | 67.2 | 44.9 | 52.5 |
| Ornith-1.0-35B | 34.6 | 75.6 | 50.4 | 69.3 | 62.8 | 58.5 |
| Qwen3.8-Max（教师） | 55.9 | 85.6 | 67.7 | - | 86.6 | 74.0 |

在 NL2Repo 上 RepoHorizen 超过 GPT-5.5（45.1）、Gemini-3.1 Pro（33.4）、DeepSeek-V4-Pro（38.5）和 MiniMax-M3（42.1）。相对不做演化的变体，演化在 NL2Repo 上多 5.1 分，平均多 2.1 分。

**数据源（表 2）：** RepoFactory 在五个基准上全部领先六个受控基线；NL2Repo 上 46.4 对最好的 OpenSWE 25.2。此前已发表（harness 各异）的最好 NL2Repo 成绩为 28.9。

**扩展性：** NL2Repo 从没有 RepoFactory 数据时的 23.8 升到 3,000 个环境时的 36.5、5,577 个时的 46.4，未见饱和。在 9B、27B、35B-A3B 基座上提升 12.2 到 22.6 分，35B-A3B 提升最多。

**目标消融：** 修复使 500 个仓库中通过验证的环境从 169 个增至 347 个（33.8% 到 69.4%），主要来自第一次修复。优化 S 使 NL2Repo 从 30.2（1 级）升到 32.9（4 级），轨迹变长；优化 C 达到 32.5，交互变短、监督 token 略减。教师成功率从规模最小的五分之一环境的 23.0% 降到最大的五分之一的 13.4%。

**数据统计：** oracle 中位数 4.2k 行、26 个源文件；静态识别出 209 万个测试定义；轨迹中位数 64 个助手轮次；最大领域占环境的 12.5%。

**证据的局限：**

* 每个配置只训练一次，未报告方差；S 与 C 的分级消融在固定 2,000 条轨迹上只差 2 到 3 分（读者观察）。
* 收益来自对强得多的教师的监督蒸馏（Qwen3.8-Max 在 NL2Repo 上 55.9）；论文指出表 2 中各数据源的教师相同，但六个基线都是修 issue 的数据，因此 NL2Repo 上的领先可能部分反映了与基准任务形式的匹配，而非一般意义上的训练价值（读者推断）。另外四个基准上的提升为 1.3 到 6.8 分。
* 获取的正文未说明不做演化的变体用了多少环境或轨迹，因此无法核实 5.1 分的演化效应是否在数据量上对齐。
* 有缺失单元格时，平均列是在不同基准集合上求的（Kimi-K2.6 的 70.7 是不含 NL2Repo 的四项平均；Qwen3.8-Max、GPT-5.6-sol、MiniMax-M3 缺 Multilingual），所以前沿模型的平均分彼此之间、与 RepoHorizen 之间都不可比（读者计算）。标题中的 +8.5 是各基准提升的平均；平均列之差为 8.4。
* 仅限 Python（原文说明）；代理指标描述结构，不刻画任务考查哪些能力（原文说明）。

# Q9 贡献

1. RepoFactory：从真实仓库生成 10,159 个可验证全仓库生成环境的流水线，覆盖 17 个领域。
2. 环境演化循环：以有效性为门槛、针对调用图耦合与实现规模的目标，无需求解器 rollout 即可引导对 oracle、规格与测试的联合修订。
3. RepoHorizen-35B-A3B，以及与六个 SWE 数据源的受控对比、扩展曲线和逐项消融。

# Q10 后续方向

* **原文提出：** 扩展到其他编程语言；设计能刻画任务所需能力的代理指标。
* **在环境上做 RL：** 这些环境自带验证器，但只报告了基于教师轨迹的 SFT；用验证器做强化学习可检验环境本身是否在教师之外还有价值（读者建议）。
* **代理指标验证：** 把 C、S 与每个环境的学习增益（而不只是教师成功率）做相关，检验耦合度是训练价值信号而非难度信号。
* **数据量对齐的演化消融：** 让不做演化的变体使用同样数量的环境与轨迹。
