# Q1 问题定义

* **输入 (X)：** 一个任务由三部分组成：persona（用户是谁、怎么说话）、隐藏的 belief（用户想要的策略）和测试条件，即数据截止日期（cutoff）、智能体可以获取数据的渠道、轮数上限和每轮时间上限。智能体只看到一句含糊的开场请求，不会拿到任何数据。
* **输出 (Y)：** 交付物，即整个会话中智能体交出的所有消息和文件：数据表、代码、回测结果和报告。只有交付物被评分；执行日志和工作区只能让某项检查不通过，不能让它通过。
* **约束：** 交付数据中每一行带日期的记录都不得晚于截止日期，每笔成交都必须晚于它的信号，报告的指标必须能从交付的交易日志重新算出。实验中每个会话至多六轮，每轮 300 秒。

# Q2 问题新颖性

是已知难点的新组合。论文认为，现有每个基准都在某一处把世界“关上”，于是消除了一类失败而不是度量它。把任务完整说清，就消除了“用户没要过的策略”；直接给整理好的数据，就消除了“未经核实的数字”；在基准自己的流水线里重放历史，就消除了“偷看未来的回测”。τ-bench 一系的模拟用户基准确实隐藏了意图，但面对的是封闭数据库和目标状态。论文的对比表列出 FinBen、FinDeepResearch、AlphaForgeBench、CLQT、InvestorBench、AMA、Herculean 和 τ-banking，只有 FinCosmos 同时具备隐藏意图、自行获取数据、由智能体自己保证时点正确（point-in-time）、可生成任务、可执行的交付物和无参考答案评分。

# Q3 科学假设

如果意图、数据和时间线都保持开放，并且由程序直接验证交付物，那么在用户或 LLM 评判看来成功的会话，仍然会在可检查的不变量上失败。论文称之为静默失败（silent failure）：没有任何东西崩溃，报告读起来和正确的一样可信。第二个主张是这些任务可解，通过让一个带持久记忆的智能体根据评估器反馈反复练习来检验。

# Q4 相关工作与关键人物

* **金融智能体与基准。** 带记忆、工具和多智能体角色的交易智能体（如 FinMem；本 wiki 的 [TradingAgents](../papers/2412.20138.md) 在同一组被引用）、研究智能体、针对财报的问答（FinBen、MultiFinBen）、问题完全给定的研究基准（FinDeepResearch）、给出规格和整理数据的策略基准（AlphaForgeBench），以及在历史或实盘市场中的交易基准（InvestorBench、AMA）。
* **开放世界的智能体评测。** 在封闭世界里隐藏意图的模拟用户（τ-bench、[τ²-Bench](../concepts/tau2-bench.md)、τ-Voice、τ-Knowledge）；开放环境但任务说全的 Web 基准（WebArena、Mind2Web、GAIA、BrowseComp）；由 LLM 评判打分的深度研究基准（DeepResearch Bench、PaperBench）；会刷新或重新生成的任务集（LiveBench、GDPevo）。论文引用了模拟用户保真度有限的证据，因此把模拟器当作按固定披露规则行事的考官。
* **前视偏差（look-ahead bias）。** 模型记住训练截止前的金融数值、交易智能体从泄漏的结果中获利，以及对回测惯例的审计。这些工作审计的是模型或固定流水线；FinCosmos 检查的是每个智能体自己搭的回测。
* **关键人物。** The Fin AI 社区（Yupeng Cao、Xueqing Peng、Lingfei Qian、Haohang Li、Yangyang Yu、Jimin Huang、Sophia Ananiadou），其中数人是 InvestorBench、AMA 和 FinBen 的作者，另有 Xue Liu 和 Jian-Yun Nie。可能的批评者：被评测智能体的作者会指出 300 秒的单轮时限，模拟用户方向的研究者会问换一个模拟器模型结果怎么变。

# Q5 核心解决思路

把规格藏起来，不给数据，凡是能重算的数字都用程序评分。

1. **策略生成器。** 一个隐藏策略为六个组件各定一个选项：选股、择时、组合构建、风险控制、执行和交易成本。一致性规则排除说不通的组合。在抽取参数值之前，空间约有 380 万种策略；每个选项有 0 到 3 的难度；抽样带种子。发布版冻结了最先抽到的十个任务（种子 0 到 9）。
2. **用户模拟器。** 一个语言模型扮演三种 persona 之一（散户、通才分析师、生物科技专家）。belief 以带具体数字的日常语言写进它的提示。披露策略是：开场只说一个含糊的想法，之后只说智能体问到或提出的内容；提议与 belief 冲突时提出异议；交付物偏离时指出哪一部分不对，但不复述策略。每个模拟器决策在消息发出前都由程序校验，只有当每个核心目标都有被引用的证据支持时，模拟器才可以结束会话。
3. **评估器。** 七个类别共 45 个维度；其中五个类别（数据、策略、回测、评估、用户体验）的 37 个维度按 0 到 4 打分，成本和过程透明度只报告不计分。程序评 17 个维度，LLM 评判评 19 个，两者共同评 6 个。当 LLM 分数有对应的程序分数时，取较低者。十五个维度是否决项（veto）。否决前质量 Q 是各类别等权平均，范围 0 到 100；只有所有否决项都通过、用户以满意结束且评分完整时，会话才被接受。
4. **关键检查。** 数据溯源（每个序列都能追到 URL 或 API 调用）；时点正确性（只要有一行晚于截止日期，否决项就不通过）；独立重算（从交付的交易日志重建收益，并在固定容差内与报告指标比较；缺交易日志或价格序列即不通过）；策略保真度（隐藏策略的每一项都对照交付物检查，用户说过的要求缺失则分数上限为 1，从未说过的缺失则上限为 2）。
5. **不泄漏的反馈。** 智能体会收到每个维度的分数和证据，但数据和策略维度只给分数不给理由，因为它们的证据会暴露隐藏策略。

# Q6 实验设计

* **系统。** Claude Code（Claude Opus 5.5）、Codex（GPT-6.1 Sol）、Gemini CLI（Gemini 3.8 Flash）、Kimi Code（Kimi K3），以及不带工具的 Claude Opus 5.5 作为裸模型基线。记忆功能关闭。
* **环境。** 每个会话一个沙箱；各厂商自带的搜索和抓取工具；代码执行；通过 [Model Context Protocol](../concepts/model-context-protocol.md) 接入的 Financial Modeling Prep 服务器，含 247 个金融 API。十个任务都是美股。
* **模拟器与评判。** 模拟器运行在低推理强度的 Claude Opus 4.8 上；LLM 评判运行在 Claude Opus 5.5 上。
* **协议。** 十个任务，每个任务和系统做三次独立会话，共 150 次。主指标是接受率。此外还有 pass^k（一个任务的 k 次会话全部被接受，沿用 τ-bench）、带任务级自助区间的否决前质量、各类别分数、各否决项失败占比、结束原因、静默失败率、澄清覆盖率（开场没说的条目中，智能体让用户说出来的比例）和假设率（始终没说的条目中，交付物做错的比例）。差异用任务上的配对置换检验加 Holm 校正。
* **人工研究。** 两位没有参与框架构建的金融专家，对 60 个会话中的每条用户消息标注模拟器错误，在 30 个会话的校准集上给四个由 LLM 评判的否决项打分，并把每个失败会话归因于智能体、模拟器或评估器。
* **从反馈中学习。** 带持久记忆的 Claude Code 对每个任务反复练习直到第一次被接受；每次评分后有一个复盘步骤编辑记忆。

# Q8 证据质量

**主表（每个系统 30 个会话）。**

| 系统 | 用户认可 | 被接受 | 质量 [95% CI] | 失败否决项数 | 300 秒截断的轮次 | 每会话美元 |
|---|---|---|---|---|---|---|
| Claude Code | 30% | 0 | 37.1 [27.8, 45.0] | 7.4 | 65% | 2.24 |
| Codex | 33% | 0 | 37.2 [30.6, 43.3] | 7.2 | 69% | 0.80 |
| Gemini CLI | 33% | 0 | 22.2 [16.9, 27.4] | 9.3 | 75% | 0.80 |
| Kimi Code | 20% | 0 | 22.3 [14.3, 31.6] | 10.1 | 74% | 0.83 |
| 裸模型 | 0% | 0 | 20.2 [18.8, 21.5] | 9.1 | 0% | 0.24 |

Codex 和 Claude Code 无法区分（p = 0.99）。Gemini CLI 和 Kimi Code 与裸模型没有差异，而裸模型没有工具，靠描述一个计划得分（策略 49.8，用户体验 44.6，数据 0）。质量随任务难度下降（Spearman ρ = -0.24）。

**静默失败。** 模拟用户在 150 个会话中认可了 35 个（23%），这 35 个全部至少有一个否决项不通过。29 个没有交付交易日志或价格，15 个用了截止日期之后的数据或在信号之前成交，15 个交付的不是用户的策略，35 个中有 33 个至少在这三项之一上失败。被认可的会话看起来比其余的好（否决前质量 50.8 对 21.0）。如果只用四个由 LLM 评判的否决项，35 个中会有 17 个被接受，接受率是 11% 而不是 0。评分方式还会改变智能体排名：按用户认可，Gemini CLI 以 30 个中的 10 个并列第一，但在 LLM 评判的否决项下一个都留不住，而 Codex 留住 8 个。

**智能体在哪里出问题。** 120 个智能体会话中，25 个交付了用户的策略；按顺序看，其中 15 个把数据保持在截止日期之内，14 个同时避免了前视，没有一个交付的交易能重现它报告的收益。一个任务的 belief 平均有 6.7 个条目，开场请求说出 2.6 到 3.7 个，到会话结束用户说出了 4.5 到 5.4 个，所以智能体问出了没被告知内容的 54% 到 64%，而从未说出的条目中有 66% 到 83% 做错。策略歧义否决项在 68% 的会话中不通过。

**零接受率建立在什么之上（读者观察）。**

* 两个严格的完整性否决项，过程完整性和验证器审计，在 120 个智能体会话中分别有 120 和 119 个不通过，并且不能区分智能体。论文报告说去掉它们后 150 个会话中会有 2 个被接受。所以标题里的“零”几乎由两项定义不在论文中的检查决定；真正有信息量的是工作流表和静默失败的分解。
* 时间是硬约束。70% 的智能体轮次撞到 300 秒上限，120 个智能体会话中只有 58 个进行到第四轮，77 个以用户不满意离开结束。用户离开会让会话以 blocked 结束，而这会使对话体验否决项不通过。论文把轮次时限列为局限；这些结果度量的是智能体在每会话至多 30 分钟工作预算下的表现。
* 有两组计数加起来不到 35。论文说 29 个被认可的会话缺交易日志或价格，程序能重建收益的有 5 个；又说报告指标与智能体自己的净值曲线相符的有 10 个、矛盾的 11 个、没有曲线的 12 个（合计 33）。剩下的会话没有说明。
* 十个任务、每个三次会话，区间很宽，论文自己也这么说。

**基准是否可信。** 专家在 60 个抽样会话中的 3 个里标出了影响任务结果的模拟器错误，并把 60 个失败会话中的 53 个（88%）归因于智能体，3 个归因于模拟器，4 个归因于评估器。LLM 评判在校准集上与专家的一致性为 κ = 0.87，两位专家之间为 0.93。专家是领薪的团队成员。模拟器、评判和一个被评测的智能体来自同一模型家族，局限性一节说明了这一点。

**从反馈中学习。** 带记忆的智能体在全部十个任务上都达到了接受，每个任务的中位数是 34.5 个会话（范围 12 到 132，共 506 个）；中位任务在最初五个会话里平均每次有 6.3 个否决项不通过，在被接受前的最后五个会话里是 2.6 个。有三个任务最后五个会话的失败否决项数不少于最初五个。策略歧义在 10 个任务中的 6 个上是最后通过的否决项。读者推断：每个任务的隐藏策略在每次尝试中都相同，也没有测试留出任务，所以这说明任务可以被通过、反馈可用，而不说明智能体学到了能迁移到新策略的能力。论文自己的局限，即反馈分数可能跨尝试泄漏隐藏策略，指向同一个结论。

# Q9 贡献

1. 一种评测设计：隐藏意图、不给数据、让智能体自己负责时点正确性，任务由语法生成而不是来自固定题库。
2. 无参考答案的评分：能重算的由程序重算，并用程序分数限制 LLM 评判的分数，再加上漂亮报告无法抵消的否决项。
3. 测量结果显示，按用户认可或按 LLM 评判的否决项，会分别接受 23% 和 11% 被程序检查拒绝的会话，并且会给出不同的智能体排名。
4. 工作流诊断：智能体最常在问清策略和交付可复现结果这两端失败。
5. 一个带不泄漏反馈的练习回路，带记忆的智能体最终通过了全部十个任务。

# Q10 后续方向

* **论文自述的局限。** 十个冻结任务、每个智能体三次会话；只覆盖做多的美股策略和固定成本模型；模拟器、评判和一个智能体来自同一模型家族；多数轮次撞到时限；程序检查不能证明每个数字都是真的；反馈可能跨尝试泄漏隐藏策略，所以排行榜结果应来自冻结的智能体。
* **改变预算。** 用更长的轮次重跑，把“智能体做不到”与“300 秒内做不完”分开（读者建议）。
* **在完整规则旁边，同时报告去掉两个已饱和否决项后的接受率**，这样随着智能体进步，指标仍能区分它们（读者建议）。
* **学习的留出迁移。** 在种子 0 到 9 上练习之后，用同一语法的新种子测试记忆（读者建议）。
* **模拟器敏感性。** 更换模拟器模型，报告用户认可率和澄清覆盖率如何变化。
* **与本项目的关系。** “工作区日志只能让检查不通过、不能让它通过”和“报告的数字只有能从交付文件重建才算数”这两条规则，可以直接用于评估研究产物。
