> 论文:**Very Large-Scale Multi-Agent Simulation in AgentScope**
> 论文链接:<https://arxiv.org/abs/2407.17789>
> 机构:阿里巴巴、中国人民大学

# Q1 问题定义

* **输入 `X`**:一次大规模 agent 仿真的配置——参与的 LLM agent 数量(可达百万级)、其背后使用的 LLM、系统提示词,以及(可选的)用于生成异质化背景设定的人口分布配置。
* **输出 `Y`**:在 AgentScope 平台上完成的一次仿真运行,通过基于 actor 模型的机制分布在少量物理设备上,产出每个 agent 的行为轨迹(如报告的数字、推理文本)及聚合观察结果,并可通过基于网页的 Agent-Manager 界面远程创建、监控和终止所有 agent。
* **核心问题**:现有的多智能体 LLM 平台(MetaGPT、AutoGen、CAMEL、LangSmith)在 agent 数量极大时存在三重叠加限制:(i)可扩展性与效率——基于 Python asyncio 的并发受全局解释器锁(GIL)制约,而 Ray 这类通用 actor 框架为每个 actor 分配一个完整的 worker 进程,在大规模场景下浪费资源;(ii)人口分布与 agent 多样性不足——手工为大量 agent 撰写年龄、教育、职业等维度上多样且真实的背景设定十分繁琐,导致 agent 行为趋于同质化;(iii)管理困难——手动初始化、监控、终止分布在多台设备上的大量 agent 变得难以处理。
* **范围**:在既有 AgentScope 平台之上贡献工程增强(基于 actor 的分布式机制、agent-环境交互、异质化配置、Agent-Manager 界面)以及使用这些增强的实证仿真研究;不提出新的推理算法、新的 LLM 或新的基准任务——"猜 2/3 平均数"游戏仅作为在大规模下展示该基础设施的载体。

# Q2 问题的新颖性

多智能体 LLM 平台与基于 LLM 的社会/经济仿真框架(Vidur、SOTOPIA,以及面向教育、交通、医疗等领域的专用仿真器)已经存在,但论文认为这些要么是缺乏灵活性和可扩展性的单一用途仿真框架,要么是通用 agent 平台(AutoGen、MetaGPT、CAMEL),其并发模型(受 GIL 制约的 Python 异步 I/O,或 Ray 式的"每 actor 一个 worker 进程")无法扩展到少量设备上运行数百万 agent。论文声称的新意并非新的仿真范式,而是一项具体的系统贡献:基于 actor 模型、以 agent 级(而非线程级或异步任务级)为并行粒度的分布式机制;仅需一次 `to_dist` 调用即可实现的自动化中心化到分布式工作流转换;以及一套专为群体级异质性与可观测性打造的配置/生成流水线与管理界面。

# Q3 科学假设

这主要是一篇系统/基础设施论文,而非单一假设的实证研究:其隐含主张是,基于 actor 模型、具备 agent 级并行执行与自动工作流转换的分布式机制,能够在少量设备上支撑至少百万级 LLM agent 的仿真,并随设备增加获得接近线性的可扩展性;同时,一套可配置的人口分布工具与自动背景生成流水线,能够在无需手工逐个撰写的情况下产生异质、真实的 agent 行为——并且配备此类基础设施的 LLM agent 将表现出可从博弈论文献中识别出的推理与策略调整行为。

# Q5 核心解法

1. **基于 actor 模型的分布式机制。** 建立在并发计算的 actor 模型之上,不依赖彼此输出的 agent 可并行执行;提供两种多进程模式——一对一模式(每个 agent 独占一个进程,适合计算密集型任务,避免 GIL 争用)与多对一模式(多个 agent 共享一个进程,适合 I/O 等待或等待远程 API 响应的场景,通过时间片复用 CPU)。跨进程/跨设备通信使用远程过程调用(提供 Python 与 C++ 实现)。据称这比现有平台受 GIL 制约的异步 I/O 具有更高的资源利用率,也避免了 Ray 式每 actor 一个 worker 进程带来的开销。
2. **自动工作流转换(`to_dist`)。** 将中心化的仿真脚本转换为分布式版本,只需在初始化阶段为每个 agent 添加一次 `to_dist` 函数调用,无需其他代码改动。内部分两个阶段完成:每个中心侧的 agent 被替换为一个远程 agent 加一个本地代理(proxy),后者转发消息并保留中心化编排代码的结构;占位符(placeholder)让中心程序在结果尚未被实际需要时可以继续执行而不阻塞,待分布式 agent 的输出被真正需要时才惰性解析。
3. **agent-环境交互。** 环境被建模为一种持有共享状态的特殊 agent 类型,可通过 RPC 访问以支持高并发;用户自定义函数可扩展环境中存在哪些状态及其查询/修改方式;绑定在这些函数上的"监听器"(listener)使环境具备主动向 agent 推送通知的能力(双向交互);环境可嵌套,从而在同一次仿真中支持多个按分组划分的环境加一个全局环境。
4. **异质化配置与自动背景生成。** 用户指定总体人口规模及各维度的分布(内置年龄、性别、职业、国籍、教育等模板,且可由用户扩展至新维度);仿真启动时,从这些分布中采样具体取值,转换为 JSON 格式,填入元提示(meta prompt)供 LLM 生成每个 agent 详细、多样的背景描述文本——并通过调整随机种子与温度来提升多样性。
5. **Agent-Manager 网页界面。** 在每台远程设备上启动的服务器为分布式 agent 提供常驻的创建/监控/停止服务,并将状态(服务器身份、IP、运行状态、资源利用率)同步到一个集中的网页可视化界面;由于服务器可在多次仿真间复用,用户无需在仿真之间重启基础设施,从而把管理的基本单元从单个 agent 转移到了服务器。

# Q6 实验设计

所有实验均使用经典的"猜 2/3 平均数"游戏(每个 agent 报告一个 0-100 之间的数字,报告数字最接近所有报告数字平均值 2/3 的 agent 获胜),运行于每台设备配备 8 张 A100-80G GPU、64 核 CPU、1TB 内存的集群上,使用 vLLM 作为推理引擎,采用六种开源指令微调 LLM(Llama3-8B/70B、Qwen2-7B/72B、MistralAI-8x7B/8x22B),生成温度设为 1.0。可扩展性结果:使用 Llama3-8B 的百万 agent 仿真在 4 台设备上 12 分钟内完成(若使用产生响应 token 数增加 150 倍的更长、思维链式提示则需 85 分钟;在最重的配置——Llama3-70B 配合更长提示——下需约 10.6 小时);若采用去除推理耗时干扰的虚拟(非 LLM)请求,基于 actor 的机制下同样的百万 agent 仿真仅需 40 秒,而串行执行约需 12 天,Python asyncio 异步模式约需 8.6 小时。固定 1 万 agent、将设备数从 1 台增加到 4 台时,Llama3-70B 下的运行时间从 22 分钟降至 5.6 分钟;而当设备数与每设备 agent 数同步扩大时运行时间几乎不变,证明了水平扩展性。行为发现:在无明确指示的情况下,多数 LLM 报告接近 50 的数字,MistralAI-8x7B/8x22B 除外(平均分别为 36.63 和 31.69);加入思维链式提示后报告数字显著降低(例如 Qwen2-72B 第一轮均值从 33.70 降至 12.76);在 5 轮重复博弈中,报告数字逐渐收敛至纳什均衡(0),提示越详细收敛越快(Qwen2-72B 第 5 轮均值在提示详细程度递增的情况下依次为 25.16、2.02、0.14-0.15);被赋予更高教育水平的 agent 报告数字更低(更理性),但不同 LLM 对该操纵的敏感度不同(Qwen2-72B 差距最大为 8.24,MistralAI-8x22B 仅为 3.49);将比例从 2/3 改为几乎同构的 51/100(与 1/2 结构上近似)会产生明显不同的行为,除非系统提示明确指出该游戏与经典版本的家族相似性,揭示了 LLM 先验知识造成的混淆;当纳什均衡被改为 10 而非 0 时,部分 agent(Qwen2-72B、MistralAI-8x22B)仍能收敛到正确的新均衡;个体层面的案例研究显示偶发的算术错误(如平均值计算错误),但不影响群体层面的整体结论;将采样温度从 0.05 提高到 1.00 会使报告数字的标准差从 6.50 升至 8.20,而均值变化不大。在混合 LLM 仿真(Llama3-70B、MistralAI-8x22B、Qwen2-72B 各 500 个 agent)中,随着轮次推进,个体 agent 逐渐向上一轮获胜数字靠拢(约 59.7% 报告数字低于上一轮获胜数字);分组级仿真显示,组内 agent 在第二轮即趋于收敛,且各组会根据其他组此前的报告策略性调整自己组的报告数字。

# Q9 主要贡献

1. 一种面向多智能体 LLM 仿真的基于 actor 的分布式机制,提供 agent 级并行执行以及仅需一行代码(`to_dist`)即可实现的中心化到分布式工作流自动转换,据报告在虚拟请求下可将百万 agent 仿真的运行时间从串行约 12 天缩短到 40 秒。
2. agent-环境交互支持(环境即 agent、基于 RPC 的共享状态、监听器触发的双向通知、可嵌套的多环境结构),使仿真在大规模下同时支持 agent 间交互与 agent-环境交互动态。
3. 一套可配置的人口分布工具加自动化的 LLM 驱动背景生成流水线,可在无需手工逐个撰写的情况下产生异质、多样的 agent 特征,并配有基于网页的 Agent-Manager,用于创建、监控和终止大量分布式 agent。
4. 在百万 agent 规模的经典博弈上进行的实证展示,表明 LLM agent 表现出可识别的策略推理(向纳什均衡收敛)、对提示细节/背景特征/模型选择的敏感性,以及不影响群体行为趋势的偶发算术错误。

# Q10 下一步

* 论文自身表明的展望是继续将大规模多智能体仿真作为一个研究与应用方向深入探索,在第 4.7 节提供进一步观察与建议,而非列出具体待解决的技术问题清单;其自身的案例研究中隐含了若干开放问题,例如:为何被赋予极端角色设定(七岁儿童)的 agent 仍表现出成人级别的多步推理,而非与角色设定一致的有限推理能力。
* 本笔记无法从检索到的文本中解答的问题:基于 actor 机制的线性扩展性主张在超出 4 台设备或超出所测 LLM 规模时是否依然成立;报告的行为发现(教育/职业敏感度、先验知识混淆)在重复试验或超出这一款游戏的其他任务框架下是否可复现;以及在论文自身声明拒绝任何基于年龄、教育水平、职业等特征的歧视性偏见的伦理声明背景下,人口分布/背景生成流水线所产生的 LLM 生成内容如何被检查是否存在刻板印象或不真实的偏差。
* **与本仓库的关联**:`to_dist` 式的一行代码中心化到分布式转换,以及环境即 agent 的抽象,为本仓库自身的多智能体协调模式([Multi-agent systems](../topics/multi-agent-systems.md))如果未来需要从团队规模扩展到群体规模的 agent 协调、而又不想推倒重来架构时,提供了一个具体、可参照的先例。
