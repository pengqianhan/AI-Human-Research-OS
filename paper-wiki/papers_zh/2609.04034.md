> 论文:**Editable Visual Design**
> 论文链接:<https://arxiv.org/abs/2609.04034>

# Q1 问题定义

* **输入 `X`**:一份设计需求(需要出现的内容、交付物类型与尺寸、视觉基调),例如活动海报、信息图、营销物料或长文本排版。
* **输出 `Y`**:一个以原生 DOM(HTML/CSS/SVG)交付、文本/素材/背景层完全解耦、且文字为真实可编辑文本(而非栅格化)的可编辑设计作品,由一个 Coding Agent 生成——一个 VLM"创意大脑"(本文所报告系统中为运行在 GPT-5.6 Sol 上的 Codex)按需调用一个图像生成模型(GPT Image 2)作为"视觉世界模拟器"——外加一份记录完整创作与技术轨迹的"Agent Design Replay"。
* **核心问题**:现有两条自动化视觉设计路径各有偏废。纯扩散式图像生成(如 GPT-Image-2、Nano-Banana)视觉效果丰富,但生成的是压平的位图,文字容易出错,图层深度纠缠,无法做任何逐层的后期编辑。纯代码生成路径(Coding Agent 直接写 HTML/SVG/CSS)能提供精确的布局控制和天然解耦、可编辑的图层,但当前的代码 LLM 缺乏二维空间感和审美直觉,也很不擅长手绘复杂视觉素材(电影感背景、3D 主视觉、插画),往往只能退回到简单的色块、渐变或表情符号作占位。
* **范围**:单页设计作品——海报、信息图、营销物料、长文本排版——通过案例研究而非量化基准来验证;多页幻灯片和完整网站的一致性明确不在本次验证范围内。

# Q2 问题的新颖性

视觉代码生成(Design2Code、WebSight、Web2Code、LaTCoder、UICopilot、DesignBench 等布局保真度基准/方法)与基于图像的设计生成(COLE、OpenCOLE、Graphist、PosterCraft、TextDiffuser)是本文明确建立并加以区分的两条既有独立路线。以推理驱动的智能体式设计生成(Visual ChatGPT、GenArtist、Idea2Img、RPG、GoT、T2I-R1、Mind-Brush)同样是已有方向,包括本文明确的直接前身 GenClaw——它以代码作为可控的中间画布,方向是"代码→图像"。本文声称的新意是把这一方向反转为"图像→代码":把图像生成模型用作前置的视觉模拟器和逐层的中间素材生成器,而把结构化代码——而非一张栅格图像——作为最终的工程交付物,其分工方式(VLM 作为创意大脑、图像模型作为视觉模拟器)明确受到 World Action Model(WAM)的启发。

# Q3 科学假设

如果一个由 VLM 主导的 Coding Agent (a) 在写任何代码之前先调用图像生成模型生成一张"想象视觉",建立全局的审美与构图先验;(b) 把逐层的独立视觉素材与该想象视觉分开生成(从不复用其像素);(c) 在明确的按元素图层标记方案下,编写原生的、不依赖视口的 HTML/CSS,把这些素材与真实文字结合起来;并且 (d) 针对确定性布局检查与基于 VLM 的渲染截图视觉评审两方面做迭代式自我修复;那么交付的作品应当同时做到精细、非模板化的美感(弥补纯代码生成的短板)与完全的、生产级的图层/文字可编辑性(弥补纯扩散式图像生成的短板),并配合一份 Agent Design Replay 轨迹,使整个创作到技术实现的过程可检视、可复现,而非一个不透明的最终产出。

# Q4 相关工作与关键人物

* **视觉代码生成与 LLM**。前沿代码模型(GPT-5.6 Sol、Claude Fable 5、Kimi K3)作为代码生成的基础;涵盖 Design2Code、WebSight、Web2Code、Interaction2Code、DesignBench(网页/UI 代码生成基准),LaTCoder、UICopilot、LayoutCoder、UI2Code(布局保真度方法),以及 StarVector、OmniSVG、InternSVG、AutoPresent、PPTAgent、ChartMimic、ChartCoder(矢量/幻灯片/图表代码生成)。

# Q5 核心解法

1. **两角色分工(受 World Action Model 启发)**。VLM 担任"创意大脑",负责需求理解、规划、代码构建与结果判断;图像生成模型担任按需调用的"视觉世界模拟器",负责生成想象视觉与独立素材——它本身从不是最终交付物。
2. **"先想象,后行动"**。在写任何代码之前,agent 先调用图像模型生成一张*想象视觉*——不是结构草图,而是成品可能呈现的样子——用以建立构图、光照与色彩先验。这一步被视为设计规划本身的一部分(方案要等有东西可看之后才算定下来),也是用户介入成本最低的节点:在任何代码产生之前就可以说"方向不对,重来"。
3. **视觉模拟即先验提取**。VLM 对想象视觉进行视觉解析,提取色调、构图分布与整体风格特征作为后续代码构建的全局参照,不要求逐一复刻其像素;论文将这一步类比为渲染反馈——一个是看代码当下写成的样子,另一个是看尚未写出的设计可能的样子,二者都是把像素交给 agent 判断。
4. **结构化编码与按需素材生成**。agent 根据视觉先验确定画布的视觉拓扑以及图文的空间分布,再按需单独调用生成模型产出干净、独立的局部视觉素材(无文字的背景、独立的主体),而非从想象视觉中裁剪,从而避免图层纠缠与像素污染。素材生成有两条路线:模型支持时直接带 alpha 通道请求,否则将主体置于纯绿背景上再由抠图脚本提取。在代码侧,agent 编写原生 HTML/CSS,将页面声明为固定像素尺寸的画布(布局不允许依赖视口,这样用户拖拽产生的坐标才有意义),并把每一个用户可能想单独移动的元素标记为独立图层。
5. **验证与视觉自我修复**。系统先在无头浏览器环境中加载代码,执行确定性的布局规则检查(元素是否越界、外部资源是否加载失败、DOM 结构是否畸形),再把实际渲染截图交给 VLM 评审,对照原始设计意图评估视觉平衡、对齐精度与文字可读性。发现缺陷时,agent 生成针对性的局部补丁而非整页重来,通常一到两轮反思修复即可收敛。
6. **可编辑交付与 Agent Design Replay**。最终作品是原生 DOM,文本、素材、背景层完全解耦(可双击编辑文字、拖拽缩放素材、按图层独立导出)。与此同时,系统把从需求分解、视觉想象、素材提示词到代码演进与最终反思修复的完整决策过程序列化为 Agent Design Replay,旨在使生成过程摆脱以往不可解释的黑箱状态,为用户追溯设计意图和手动干预提供依据。

# Q6 实验设计

验证以案例研究为主,而非量化基准,从三个角度展开:(1) 在同一需求下与纯扩散式生成(GPT-image-2)和纯代码生成(运行在 GPT-5.6 Sol 上的 Codex)做受控比较,标注每个基线各自的失败模式(扩散模型文字错乱、纯代码大面积留白且布局混乱),并对照 Editable Visual Design 兼具排版整洁与图层可分离性的结果;(2) 覆盖活动海报、信息图、营销物料、长文本排版等多样场景的展示,检验信息密集场景下字号层级/网格对齐是否保持,视觉驱动场景下多层空间是否组织得当;(3) 通过两个真实案例——一个信息密集的小熊猫科普信息图(120 个可编辑图层,分为 13 组,评审环节捕捉并修复了真实的布局缺陷)与一个视觉驱动的旅行海报(6 个图层,1 组,评审无需修改即通过)——按理解规划、生成构建、评审修复三个阶段完整走一遍 Agent Design Replay 轨迹,每一步均带时间戳记录。

# Q8 证据质量

本笔记基于 arXiv HTML 全文(摘要至相关工作部分;参考文献列表未被用于支撑本笔记中的任何论断)撰写。论文对自身案例研究证据的局限表述得相当直白:第 5 节明确指出"审美质量很难像生成质量那样被评估",没有关于海报"应当"是什么样的标准答案,因此论文"报告案例而非分数",其视觉质量检查是"一个用来代替设计师之眼的 VLM 判断,而非任何可测量的东西"——本笔记因此将论文中所有关于美感或质量的论断均视为定性的案例证据,而非任何经过基准测试的结果,因为论文自身也并未建立这样的基准。可编辑性方面同样是断言而非度量的结果(图层数、DOM 结构可以报告,但论文明确指出"真正重要的是打开文件的设计师能否让它做到自己想要的效果,而这不会归约为一个数字")。论文也坦率说明了自身的约束条件:交付质量受限于两个底层模型中较弱的一个(编码 agent 的布局代码,或者——按论文所述更常见的情况——图像模型的设计感,后者可能返回"技术上干净但构图平庸"的参考);素材生成路线还要求主体能与背景干净分离;并且只测试了单页作品,论文明确指出多页幻灯片或完整网站"必须在多页之间保持一致",而这一点本文并未评测。

# Q9 主要贡献

1. Editable Visual Design,一种由 Coding Agent 驱动的可编辑视觉设计范式,把直接前身 GenClaw 的"代码→图像"方向反转为"图像→代码"。
2. 一套五步工作流——理解与规划、视觉模拟、按需逐层生成独立素材的结构化编码、双重(确定性加 VLM)验证与自我修复、可编辑交付——产出文本/素材/背景层解耦、文字为真实可编辑文本的作品。
3. Agent Design Replay,一份记录完整创作到技术实现轨迹(需求分解、视觉想象、素材提示词、代码演进、反思修复)的序列化记录,在海报、信息图、营销物料与长文本排版等案例研究上得到展示,旨在使生成过程可审计、可为人类理解,而非一个不透明的最终产出。

# Q10 下一步

论文的讨论部分给出了若干前进方向,而非具体的既定实验:把"以生成促理解"(Generation for Understanding)从此前偏重符号逻辑和线性推理的任务(几何辅助线、空间迷宫,作者认为这些尝试目前收效相对有限)拓展到把生成用作视觉想象与审美先验来源、进而辅助构图决策,并以"人在梦中很难解出严谨的数学题,但梦境却常常是视觉灵感、意象与创意的来源"作类比;推广经由 GenClaw 与 Mind-Brush 一脉相承的分工模式,把生成模型作为任意通用推理 VLM 可随时调用的外部模拟器与局部素材渲染器;进一步从"位图输出"推向更普遍意义上的"结构化交付";以及探索更自然的人机设计交互形式——例如让 agent 通过 GUI 直接操作鼠标在画布上布局绘制,以此延续 Agent Design Replay 的过程可见性目标。论文明确点出的、留待未来工作的局限包括:跨多页幻灯片或完整网站保持一致性(字号、配色、视觉线索的贯穿)尚未在单页之外得到测试;整体上限受制于编码 agent 或图像模型中较弱的一方,论文报告中更常见的情况是图像模型给出构图平庸的参考;以及目前完全没有量化的美感或可编辑性指标,只能依靠案例研究和一个代替设计师之眼的 VLM 判断来评估。

本笔记在论文自身问题之外补充一个开放问题:验证环节中的 VLM 评审是拿渲染结果与"原始设计意图"做比较,但这份"意图"本身正是由同一个 VLM 在更早的想象视觉与规划步骤中自行确立的——论文并未报告这一自我指涉式的评审循环(由同一模型评判自己更早做出的设计决策,而非对照一份外部的、人工撰写的设计说明书)是否曾对照过外部人工制定的设计规范加以核验,这将影响我们判断自我修复步骤究竟在多大程度上是在纠正对需求的偏离,还是仅仅在强化 VLM 自身最初的审美选择。
