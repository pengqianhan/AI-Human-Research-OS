# Q1 问题定义

* **输入 (X)：** 一个自然语言问题、一组可选的初始图片（204 个任务中有 187 个带图）和规定的答案格式，交给一个多模态模型或智能体；智能体可以使用网页搜索、网页阅读、以文搜图、以图搜图（反向图片搜索）和图片裁剪。
* **输出 (Y)：** 一个最终答案（实体、集合、有序列表或类似表格的答案），按是否完全正确评分，并对其中写出的中间结果和子问题答案给部分分。
* **约束：** 答案必须能从写题前就固定下来的公开可搜索来源推出；关键视觉证据按设计不能被题干、网页标题、图注、OCR 或模型自身知识替代。

# Q2 问题新颖性

部分新。多模态搜索基准已经不少：MMSearch、BrowseComp-VL、MMSearch-Plus、MM-BrowseComp、VisBrowse-Bench、BrowseComp-V3、InterLV-Search 和 VDR-Bench。本文的论点是：其中很多任务里，图片主要用来识别起始实体，之后靠文本搜索就够了；而图片搜索次数多，本身并不意味着视觉上下文更难。本文关注的是*视觉上下文管理*（visual context management）：保存关于多个对象的视觉观察，把它们与身份和外部事实联系起来，并用它们决定后续搜什么。作者自己的对比表（作者做的定性分类）声称它是唯一同时具备集合型答案、多图、多跳、证据链接任务和部分给分的基准。

# Q3 科学假设

如果任务要求智能体在许多图片、对象和相互依赖的搜索步骤之间传递视觉证据，那么即使是带搜索工具的前沿模型也很少能完全解出。部分给分会显示"中间结果大多正确"与"整个答案正确"之间的巨大差距，在需要逐一检查集合每个成员的任务上尤其如此。让智能体直接看检索到的图片，应当优于只给它这些图片的文字描述。

# Q4 相关工作与关键人物

* **智能体信息搜寻。** [GAIA](../concepts/gaia.md)、[BrowseComp](../concepts/browsecomp.md)、[WideSearch](../concepts/widesearch.md)（广度与逐项完整性）、DeepWideSearch、[DeepSearchQA](../concepts/deepsearchqa.md)、[GISA](../concepts/gisa.md)（集合、列表和表格答案，附人工搜索轨迹）和 DeepResearch Bench II；以及 [SearchOS-V1](../papers/2607.15257.md) 这类搜索系统，它维护任务、证据、覆盖情况和失败尝试的共享记录。

# Q5 关键解决思路

**五类任务。** *集合型视觉搜索*（Set-wise，68 个任务）：对一个明确集合的每个成员检查某个视觉属性，再筛选、比较或计数。*顺序型视觉搜索*（Sequential，34）：一步中的视觉发现决定下一步搜什么。*广深混合搜索*（Hybrid Wide-Deep，34）：前面的发现确定候选集合，筛选后得到下一个目标。*竞争性视觉辨别*（Competitive Visual Disambiguation，34）：依靠局部细节区分几乎一样的候选。*视觉结构引导搜索*（Visual-Structure-Guided，34）：图中对象的顺序、位置或连接决定搜什么、按什么顺序搜。参考解法平均 17.6 步（中位数 17，共 3,593 步），从辨别类的 3.9 步到集合类的 23.9 步不等（混合类最长 61 步）。

**构建流程。** 标注者先固定公开来源，要求实体集合有边界、实体与图片的对应可靠、事实可独立核验；再把实体、图片、事实和候选集合组织成证据结构，套用某一类任务的结构约束，写出隐藏中间节点和答案的问题。程序检查覆盖记录结构、评分提示占位符、图片完整性和导出一致性；人工审核覆盖来源、视觉整合、捷径和答案一致性，每个保留的任务都经过审核。绕过视觉证据或存在更短意外路径的任务会被丢弃。

**评分。** 准确率（Accuracy）只有在答案包含且仅包含全部要求内容时才为 1，接受别名，除非题目要求，否则集合不计顺序。过程分（Process Score）是最终答案中答对的标注关键状态所占比例，再对任务取平均，因此恢复出相同状态的不同搜索路径得分相同。两个指标都由语义评审依据每个任务的评分提示分别调用得出，只使用 `final_answer` 字段。

# Q6 实验设计

* **系统。** 16 个直接作答的模型（13 个开放权重模型，从 Qwen3-VL-4B 到 Qwen3.5-397B-A17B、Kimi-K3、DeepSeek-V4.1-Flash、GLM-5.3-Flash 和 MiniMax-M3；以及 GPT-5.5、Gemini 3.5 Flash 和 Claude Opus 4.8）。其中七个底座以 [ReAct](../concepts/react.md) 智能体运行，三个以 DeerFlow 智能体运行。
* **工具预算。** 最多 30 轮搜索、60 次证据工具调用且每轮最多四次，每次搜索返回五条结果，网页文本截断到 12,000 字符，每个任务最多 20 张图（最长边 1,536 像素），裁剪最多放大四倍。正向搜索用 Serper，反向图片搜索用 SerpApi。
* **协议。** 每个任务从全新上下文运行一次（Pass@1），温度为 0，GPT-5.5 和 Claude Opus 4.8 除外（使用默认温度）。
* **视觉访问消融。** 对三个 ReAct 底座比较：*Text*（只有网页搜索和阅读）、*Caption*（有图片搜索和反向搜索，但检索到的图片由同一模型另行调用生成描述）和 *Full*（直接查看并裁剪），并统计逐任务的得失（表 5 和表 6）。图 5 汇总了工具使用和耗时，另有 17 条轨迹作为案例。

# Q7 数据集与代码

基准已发布（[项目页](https://dingwu1021.github.io/VisSearch-Bench/)、[antins-labs/VisSearch-Bench-v1](https://github.com/antins-labs/VisSearch-Bench-v1) 仓库，`hf papers info` 显示 4 颗星，以及一个 Hugging Face 数据集），本笔记都没有打开。发布格式为内嵌图片的 Parquet，每个任务九个字段，包括参考答案、带来源链接的标准轨迹和两个评分提示；有英文和中文两个版本。论文给出了全部智能体与评审提示以及推理超参数。正文没有说明智能体框架代码是否发布。

# Q8 证据质量

* **有支持的结论。**
  * *任务对现有系统很难。* 直接作答最高只有 6.37% 准确率（GPT-5.5 和 Gemini 3.5 Flash），最好的搜索智能体解出 204 个任务中的 54 个（Kimi-K3 加 ReAct，26.47%）。
  * *搜索对所有测试的底座都有帮助。* Qwen3.5-397B-A17B 从 1.96% 升到 ReAct 下的 15.69% 和 DeerFlow 下的 10.29%，过程分从 12.72 升到 ReAct 下的 32.43；表 3 中每个配对的 ReAct 或 DeerFlow 结果都高于对应的直接作答行。
  * *部分结果拼不成完整答案。* 在集合型任务上，GPT-5.5 加 ReAct 的过程分为 44.10，准确率却只有 8.82%（68 个中 6 个），没有系统超过 11.76%。在竞争性辨别任务上，所有模型直接作答都是 0%，而搜索智能体最高达到 44.12%。
  * *直接看图优于看描述。* 三个底座上，Full 在准确率和过程分上都优于 Caption 和 Text；完全去掉图片工具（Text）使准确率下降 1.47 到 10.29 分。
* **比标题弱或范围更窄的地方。**
  * *只跑一次，差距很小。* 前两名智能体只差两个任务（54 对 52），Full 比 Caption 多 2、2、7 个任务。表 6 显示设置之间变动很大：Full 与 Caption 之间有 14、18、33 个任务结果翻转，净变化只有 2、2、7。每个任务只采样一次，两个闭源模型还用默认温度，这种量级的运行间波动是可能的，但没有被测量（读者推断）。
  * *领域列建立在很少的任务上。* 由领域占比可推出：文化 48、生命科学 36、物理科学 36、社会、地理和技术各 24、商业 12 个任务，所以一个商业任务就值 8.33 分（读者算术）。
  * *评分器是 LLM，而且描述前后不一。* 第 3.3 节描述的是带别名归一化的规则比较，附录 B 却说两个指标都由按任务提示评分的语义评审给出。正文没有写明评审模型，也没有检查评审与人工的一致性（见 [LLM-as-a-Judge](../concepts/llm-as-a-judge.md)）。
  * *过程分奖励的是"写出来的"而不是"找到的"中间结果。* 它根据最终答案文本计算，不看轨迹，因此不搜索也能得分：GPT-5.5 直接作答总过程分 22.61，在结构引导类任务上 43.47（读者观察）。
  * *"视觉不可替代"是人工检查的，没有逐任务测量。* Text 设置下每个底座仍能解出 12 到 25 个任务，直接作答最多解出 13 个。论文没有报告哪些任务不用图片工具也能解，因此真正需要视觉证据的任务有多少并未确定（读者观察）。
  * *框架比较很单薄。* DeerFlow 只跑了三个底座，除工具协议外没有描述其配置；消融只用了三个开放模型。
  * *承诺的比较没有出现。* 附录 A 把四个外部基准描述为"用于跨基准评测"，但在本笔记阅读的正文和表注中没有出现跨基准的结果。
  * *今后的数据污染风险。* 对公开网页任务发布带来源链接的标准轨迹，会让日后训练数据泄露变得容易；论文没有描述留出或私有的划分（读者观察）。

# Q9 贡献

* 一个多模态搜索的任务分类，关注视觉证据如何在对象和步骤之间传递，而不只是是否用到了图片。
* 204 个人工构建的任务，来源固定且公开，附参考答案、标准轨迹和逐任务评分规则，以中英文发布。
* 对 16 个模型和两种智能体框架做的 Pass@1 评测，配合一个把中间正确性与完整答案分开的部分给分指标。
* 一个带逐任务得失统计的视觉访问消融。

# Q10 下一步

* **更好的集合聚合（来自论文的发现）。** 最弱的是集合型搜索：智能体能答对很多项，却很少全部答对；像 [SearchOS-V1](../papers/2607.15257.md) 的覆盖记录那样显式逐项跟踪，是很自然的检验。
* **重复运行（读者建议）。** 每个系统跑三到五次，可以看出排名前列和 Full 对 Caption 的优势能否经得住采样噪声。
* **逐任务的无视觉对照（读者建议）。** 标出 Text 或直接作答已能解出的任务，并在其余任务上报告结果，可以把"视觉不可替代"的说法变成测量。
* **评审验证（读者建议）。** 写明评审模型，并在样本上报告与人工评分的一致性，特别是集合和表格答案，可以给评分误差划定范围。
* **基于轨迹的过程评分（读者建议）。** 根据轨迹（实际查看了哪些页面和图片）给关键状态打分，会奖励真正找到的证据，而不是猜出来的中间答案。
