> 论文:**Repo-To-Skill: Distilling GitHub Repositories Into AI4AI Skills**
> 论文链接:<https://arxiv.org/abs/2609.02749>
> 机构:北京智源人工智能研究院(BAAI)、中国科学技术大学、中国人民大学、香港理工大学

# Q1 问题定义

* **输入 `X`**:一个研究任务 `tau = (q, D, E, g)`(问题陈述、数据/材料、包含工具与预算的环境、目标),以及一个既有的智能体系统 `A = (M_theta, H)`——一个冻结的 LLM 骨干模型加上一个提供编排、记忆、验证与迭代精化的 harness。
* **输出 `Y`**:一个"操作性知识(operational knowledge)"集合 `K = {S_1, ..., S_m}`,由经过验证的技能组成,作为显式的操作上下文加入,使得 `A_res = (M_theta, H, K)`,智能体策略变为 `a_t ~ pi_theta(a | tau, h_t, H, K)`。
* **核心问题**:骨干模型(先验广博但固定)与 harness(控制流程但不提供领域内容)都没有提供那种把"知道一个方法"和"能让它真正跑起来"区分开的领域专属知识——该用哪个方法/工具、什么时候用、以及如何正确使用它,包括 API 的具体细节与实现陷阱。这些知识并非不存在,它们散布在代码仓库与论文中,但形式是写给人类读者的,且体积太大,无法在一次任务预算内加载。目前智能体只能在每个任务上通过代价高昂的试错重新发现这些知识,而无法复用它。
* **范围**:骨干模型与 harness 保持不变;DisCo 只负责构建并提供这层缺失的知识 `K` 作为操作上下文,该知识蒸馏自代码仓库、论文以及任务特定的网络检索。

# Q2 问题的新颖性

本知识库 [Agent skill libraries](../topics/agent-skill-libraries.md) 主题下已有多个技能包系统:[SkillFoundry](2604.03964.md) 通过 expand/repair/merge/prune 循环把异构的科学资源蒸馏进一个不断增长的库;[OpenSkill](2606.06741.md) 在没有目标任务监督的情况下,从开放世界资源中构建技能与自建验证锚点;[ResearchStudio-Idea](2607.04439.md) 把文献检索与想法生成打包成可互操作的技能;[SkillOpt-Lite](2607.03451.md) 与 [SkillOpt](2605.23904.md) 通过一种文本空间训练类比,从执行轨迹中*优化一个既有的*技能文档;[COLLEAGUE.SKILL](2605.31264.md) 蒸馏的是人类留下的痕迹(而非智能体轨迹)。Repo-To-Skill 在这一脉络中的新颖之处有三点:(1)它明确把"操作性知识"`K` 形式化为模型和 harness 之外的第三个组件,而不是把技能当作一种隐式的提示工程产物;(2)它把蒸馏锚定在*陈述性源材料*——有版本的软件仓库与论文——上,通过一个由两种形式共享的四阶段流程(scope->ground->construct->verify):任务无关型(提前从一个源构建)与任务导向型(按需从一个任务构建),每次运行都以一份保留证据、检查项与未解决缺口的构建记录 `R` 收尾;(3)它的规模在同类工作中独树一帜:AREX-Skill 库包含从 1000 个 ML 代码仓库中蒸馏出的 5000 多个技能,并按一个生成式的 20 个领域 / 178 个能力族的分类体系组织,评测时在四个独立的、已有的第三方基准(MLE-bench、PaperBench、FrontierCS、PassNet)上做匹配的有/无技能消融,而不是使用自建的内部基准。

# Q3 科学假设

如果从陈述性源材料(代码仓库、论文、任务特定检索)中蒸馏出领域专属的操作性知识,将其打包为可复用的、渐进式披露的技能,并作为操作上下文提供给一个本身不做改动的模型加 harness 智能体,那么该智能体在解决机器学习研究与工程任务时,将比没有这层知识的同一智能体表现得更好——这种提升在固定骨干模型、harness 与执行预算的条件下,跨不同类型的基准都能成立,并且随任务难度增加而增大,同时无需对智能体自身的控制回路做任何改动。

# Q4 相关工作与关键人物

* **与本知识库其他条目同属技能库谱系**:[SkillFoundry](2604.03964.md)、[OpenSkill](2606.06741.md)、[ResearchStudio-Idea](2607.04439.md)、[SkillOpt-Lite](2607.03451.md)、[SkillOpt](2605.23904.md)、[COLLEAGUE.SKILL](2605.31264.md)——Repo-To-Skill 的区别在于以 1000 个代码仓库为规模,锚定在既有的软件/论文产物上,而不是锚定在智能体执行轨迹或人类痕迹上。
* **论文自身在 Related Work 中直接对比的、从经验中获取技能的既有方法**:Voyager(跨环境学习并组合可执行技能)、Agent Workflow Memory(从过往轨迹中提取可复用流程)、ExpeL(从任务经验中蒸馏自然语言洞见)——论文认为这些方法主要从交互轨迹中派生出自由格式的代码/流程/洞见,导致技能质量难以核验、失败难以归因,而 DisCo 则从静态产物中蒸馏出可溯源、经过验证的技能,并附带显式的构建记录。
* **所用基准(均为既有的、外部的)**:MLE-bench(Chan 等,2025)、PaperBench(Starace 等,2025)、FrontierCS(Mang 等,2025)、PassNet(Liu 等,2026)。
* **MLE-bench 排行榜对比基线(Table 1)**:Famou-Agent 2.0 / FM Agent、AIBuildAI、CAIR MARS+、MLEvolve、PiEvolve、Thesis、R&D-Agent。
* **作者/机构**:Jianlyu Chen、Yuyang Hu、Hongjin Qian、Jiawei Liu、Wenqing Wei、Xiaolong Chen、Defu Lian、Zhicheng Dou、Chaozhuo Li、Qiwei Ye、Zheng Liu——北京智源人工智能研究院(BAAI)、中国科学技术大学、中国人民大学、香港理工大学。

# Q5 核心解法

* **把操作性知识实例化为技能**:`K` 被实例化为遵循 Agent Skills 规范的技能 `S = (SKILL.md[知识接口], references/[知识底层材料], scripts/[执行接口])`,按源材料组织成技能图 `G = (S, L)`,其中的连边编码路由、依赖或组合关系;一个入口技能负责路由到组件技能,渐进式披露意味着智能体在任意时刻的上下文里只装载已展开的那一分支。
* **统一的四阶段蒸馏流程**:`z -> scope -> Q -> ground -> X -> construct -> G~ -> verify -> (G, R)`,其中 `z` 是锚点,`Q` 是该次运行决定覆盖的能力集合,`X` 是收集到的证据,`G~` 是组装出的候选图,`(G, R)` 是通过验证的图加上其构建记录(使用过的证据、执行过的检查、尚未解决的缺口)。
* **共享该流程的两种蒸馏形式**:*任务无关型*(锚点为一个源 `c`,如一个代码仓库或一篇论文;提前构建,供未来任何任务复用)与*任务导向型*(锚点为一个任务 `tau`;主动检索源材料以填补能力缺口,按需产出但可复用于同类任务)。
* **DisCo 在同一骨干模型与 harness 之上的两种模式**:*创建者模式*运行蒸馏流程,把通过验证的图存入 AREX-Skill 库;*研究者模式*在解决任务时只加载库中相关的一支作为 `K`。两种模式的成本是非对称的:创建者模式对每个源只需付出一次,并分摊到未来所有任务上;研究者模式只为任务实际打开的部分付出成本。
* **AREX-Skill 库的构建**:在 1000 个仓库图中共计 5353 个技能(使用 GPT-5.5 与 GPT-5.6-sol,xhigh 推理强度,平均每个仓库约 40 美元构建成本),依据一个 LLM 归纳出的两级分类体系分类(20 个领域、178 个能力族,通过对 100 批仓库进行迭代式的 locator 加 judge 收敛协议构建,模型输入只使用仓库标识符与摘要——星标数、URL、既有分类字段均被排除),产生 2209 条精确的领域到能力族分配(700 个仓库属于多个能力族),并通过一个生成式路由器对外暴露。分类与技能生成是分离的:原始仓库(而非生成出的图)才是分类体系归属的主要证据来源。
* **入库前的验证**:断言支撑的可用性用例,加上安全的仓库原生检查(示例、测试、CLI、微型 fixture、烟雾测试);失败会触发局部修复并重跑;静态门控还会检查元数据、链接完整性、自包含性、来源信息以及本地路径泄漏。
* **超出公开仓库集合之外**:为 PaperBench 的 20 个目标任务,从 153 篇源论文中蒸馏出 636 个论文衍生技能(排除每个目标论文自身及其发布的代码/产物),此外还为 MLE-bench(每个竞赛一张图,仅描述性、不可直接执行)、FrontierCS(所有 188 个任务共享一张 9 节点、42 条边的修复导向路由图)、PassNet(一张基准级别的图)专门构建了任务导向型技能——在每种情况下,技能构建都在下游基准评测开始之前完成并冻结,使用单独的一次性构建预算。

# Q6 实验设计

全程固定 GPT-5.5 骨干模型与 Codex harness;唯一被控制的变量是是否可以访问 DisCo 蒸馏出的技能。四个独立的、既有的基准:

* **MLE-bench(完整版,75 个 Kaggle 竞赛,分 Low/Medium/High 三档)**:Any-Medal 分数从无技能时的 31.11% 提升到 72.89%(+41.78 个百分点,相对提升 134.3%),各档均一致提升(Low +43.94,Medium +37.72,High +48.89 个百分点;High 档相对提升最大,从 13.33% 到 62.22%,相对提升 366.8%)。Codex + AREX-Skill 还以整体 +8.45 个百分点的优势超过 MLE-bench 公开排行榜上最强的条目(Gemini-3-Pro-Preview 上的 Famou-Agent 2.0 / FM Agent,64.44%),且未使用定制 harness 或改动控制回路。
* **PaperBench(完整版,20 篇论文,使用官方复现评分器)**:平均复现分数从 29.45% 提升到 39.59%(+10.14 个百分点,相对提升 34.4%);在 20 篇论文中的 18 篇上提升,2 篇上下降(sample-specific-masks:57.11→52.04;stay-on-topic:32.31→27.79);相对提升最大的出现在无技能基线较低的任务上(rice:7.94→48.51;ftrl:1.50→17.17,提升 11.4 倍)。
* **FrontierCS(Agent Track,188 个任务,每任务 5 小时/2 CPU/4GiB 预算)**:Score 从 70.63 提升到 77.14(+6.51,相对提升 9.22%;配对 bootstrap 95% 置信区间为 [3.41, 9.83]);在 74 个任务上提升,66 个任务基本不变;单任务提升幅度与额外消耗的 token/步数/工具调用次数几乎不相关(Spearman ρ 分别为 0.006/0.014/0.015);Codex+AREX-Skill 在分数、token 数、步数与工具调用次数上同时帕累托支配 Claude Code 的两种配置(Opus 4.8 与 Qwen3.7 Max),且 token 用量少 3.1-3.3 倍。
* **PassNet(200 个样本,图编译器 pass 生成任务,NVIDIA A100)**:AS Score 从 1.343 提升到 1.5313(相对提升 14.0%),超过 TorchInductor 的 1.419;失败样本数从 14 降到 5(下降 64.3%);正确率从 81.35% 提升到 90.76%。

在每个评测设置中,技能构建预算始终与匹配的执行预算分离,并且先于执行预算完成(例如 MLE-bench 的探索/技能构建阶段与实际计分阶段各自限定不超过 24 GPU 小时)。

# Q8 证据质量

核心消融设计相对严谨:骨干模型、harness 与运行预算保持固定,只改变是否可访问技能,并且是在四个独立、既有的第三方基准上完成,而非仅有一个自建基准——这比本知识库 [Agent skill libraries](../topics/agent-skill-libraries.md) 主题下多数条目的评测设计更强。论文报告了任务级的细分,而不只是聚合数字(在 FrontierCS 的 188 个任务中有 74 个受益,在 PaperBench 的 20 篇论文中有 18 篇受益,并且明确报告并推测了 PaperBench 上 2 例回退的原因——一种可能的检索精度权衡,即检索到的技能把智能体拉离了一个它本可以自行找到的、特异性的解法路径)。FrontierCS 的分层分析(单任务提升幅度与额外 token/步数/工具调用消耗之间几乎为零的 Spearman 相关性)是一次真正有价值的检验,说明聚合提升并非只是资源规模扩张的另一种表现。局限之处:PaperBench 的源论文筛选("从相关工作中选取最多 10 篇代表性论文")与 MLE-bench 基于网络检索的逐任务技能构建都涉及模型的主观判断,其一致性在检索到的文本中并未被独立审计;技能构建成本(每个仓库约 40 美元、xhigh 推理强度,乘以 1000 个仓库,加上另外三个基准各自的构建预算)相当可观,论文没有报告需要多少下游任务才能摊销这一成本,因此构建这样一个库相对于不构建它的净计算/成本权衡并未被直接确立;此外 MLE-bench/FrontierCS 的基线对比行取自公开排行榜,而非作者在相同硬件下重新运行,因此这部分跨系统比较(而非核心的有/无技能消融本身)带有通常的排行榜可比性局限。**保真度说明**:与本知识库同期加入的另外两篇论文不同,HF CLI 的 `papers read` 命令成功返回了这篇论文的完整正文;上述数字均直接来自该次检索,并与正文中复现的表格做了交叉核对。

# Q9 主要贡献

1. 把"操作性知识"`K` 形式化为自主研究智能体(`A_res = (M_theta, H, K)`)中区别于模型骨干与 harness 的第三个显式组件,并论证这是二者目前都未提供的一层。
2. 提出 DisCo,一个双模式(创建者/研究者)的、由技能驱动的研究智能体,围绕一个统一的四阶段蒸馏流程(scope/ground/construct/verify)构建,该流程横跨任务无关型(源锚定)与任务导向型(任务锚定)两种技能生产方式,每一份候选技能图入库前都要经过验证,缺口被记录而非被隐藏。
3. 以区别于本知识库已有技能库工作的规模构建 AREX-Skill 库:从 1000 个 ML 代码仓库中蒸馏出 5000 多个经过验证的技能,依据一个 LLM 归纳的 20 个领域 / 178 个能力族分类体系与生成式路由器组织,另外还从 153 篇论文中蒸馏出 636 个论文衍生技能。
4. 通过固定骨干模型、harness 与预算的有/无技能匹配消融,证明仅靠添加蒸馏出的操作上下文就能在四个独立基准上带来一致的提升(MLE-bench +134.3%、PaperBench +34.4%、FrontierCS +9.2%、PassNet +14.0%),且相对提升最大的集中在更难或无技能基线更低的任务上。

# Q10 下一步

* 论文没有评测把蒸馏出的技能与不同于 Codex 或更强的 harness 结合使用,因此这一提升如何与并行的 harness 工程进展相组合,仍是未知数。
* 观察到的两例 PaperBench 回退被归因于一种假设中的检索精度权衡,但并未被直接诊断;论文把更好的路由机制或在检索技能匹配度差时显式回退到无引导推理列为未来工作,但既未实现也未评测。
* 论文没有报告需要多少下游任务才能摊销这笔一次性的、相当可观的技能构建成本(规模化后每仓库约 40 美元,再加上另外三个基准各自的构建预算),因此像 AREX-Skill 这样构建一个库相较于不构建的净成本效益,仍是一个开放的实证问题。
* **对本知识库的启示**:这是本知识库 [Agent skill libraries](../topics/agent-skill-libraries.md) 主题下规模最大的条目,也是第一个通过在四个独立、既有的第三方基准上做受控的有/无技能消融,而非依靠自建内部基准,来分离技能贡献的工作。它与 [SkillOpt](2605.23904.md) 在 52 个 (model, benchmark, harness) 单元格上全部持平或更优的主张,大概率是互补而非竞争关系:SkillOpt 通过一个文本空间训练循环,从执行轨迹中优化每个领域一份紧凑的技能文档,而 DisCo 提前从陈述性材料中为每个源蒸馏出多个技能——一个自然的后续实验是,从一个由 AREX-Skill 构建出的初始技能出发,再叠加一个 SkillOpt 式的轨迹优化循环,而不是把二者当作互斥的替代方案。
