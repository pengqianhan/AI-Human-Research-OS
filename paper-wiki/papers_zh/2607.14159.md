# Q1 问题定义

论文研究如何优化固定语言模型外部的完整 **Agent Harness**，并针对每个新任务动态生成不同的 Harness。搜索阶段的输入是带标签的任务、可见任务特征和参考答案；输出是一个全局 Harness 和一套执行经验库。评估阶段只能看到新任务的指令和可见特征，不能读取标签、接收反馈、更新权重或重新搜索，但仍要生成适合该任务的专用 Harness。

这里的优化对象不只是 Prompt，而是上下文组装、工具与检索、生成参数、多轮编排、记忆管理和输出处理六个控制面。候选 Harness 首先按正确性排序，只有正确性相同时才用 Token 成本作为次级条件。

# Q2 问题新颖性

已有方法会优化 Prompt、指令、LM Pipeline、Agent Workflow，或使用反思记忆改进后续尝试。Meta-Harness 更进一步，直接搜索 Harness 代码，是本文最接近的前置工作。MemoHarness 的新意在于把三件事组合起来：以六个明确维度结构化编辑 Harness；同时保存逐任务执行记录和跨任务归纳模式；在测试时用冻结经验库一次性适配当前任务。

这个问题的重要性来自“一个全局 Harness”本身的局限。不同任务在歧义、推理深度、工具需求、外部证据和输出格式上不同，平均最优的 Prompt、工具和工作流不一定适合每一个具体任务。

# Q3 科学假设

核心假设是：如果 Harness 搜索不仅保存总分，还保存由验证器证据支持的失败诊断，再把重复失败蒸馏成可复用规律，并为新任务检索相似的成功与失败经验，那么固定基础模型无需测试时标签或额外搜索，也能优于静态全局 Harness。

论文还隐含两个假设：六维分解比整体 Prompt 搜索更容易定位和修复失败；部分 Harness 决策描述的是通用执行策略，因此能够跨数据集和基础模型迁移，而不只是对某个模型措辞的过拟合。

# Q4 相关工作与关键研究者

论文把相关工作分为四层：OPRO、ProTeGi 和 Promptbreeder 等 Prompt 优化；Self-Refine、Reflexion 等反馈与反思记忆；DSPy/MIPRO、TextGrad 等复合 LM 系统优化；AutoFlow、AFlow 和 Meta-Harness 等 Workflow 或 Harness 搜索。ReAct、Toolformer、SWE-agent、OpenHands、Terminal-Bench，以及 Context/Harness Engineering 实践则说明模型外部控制层会显著影响最终行为。

作者来自圣母大学（University of Notre Dame）、慕尼黑大学（LMU Munich）和南加州大学（University of Southern California）。Agent 优化、测试时适配、案例推理、Benchmark 方法和软件智能体基础设施研究者最可能追问：提升究竟来自全局搜索还是经验库与逐任务适配；检索是否跨数据划分泄漏任务结构；学到的策略能否迁移到更开放、不可执行验证的任务。

# Q5 核心方案

MemoHarness 把 Harness 划分为六个可编辑控制面：

| 维度 | 控制面 | 示例修改 |
|---|---|---|
| D1 | 上下文组装 | 重构指令、加入示例、压缩上下文 |
| D2 | 工具交互 | 启用检索、设置 top-k、重排证据 |
| D3 | 生成控制 | 修改 Token 上限、温度和候选数量 |
| D4 | 编排 | 从单次调用切换到规划—执行—改进 |
| D5 | 记忆管理 | 保留状态、总结轨迹、移除过时信息 |
| D6 | 输出处理 | 提取答案、验证 Schema、选择回退方案 |

训练从一个极简 Harness 开始，进行十轮外层搜索。每轮中，控制器从经验库检索一个有界切片，修改 Harness，在搜索任务上执行，记录正确性、Token 成本和失败诊断。逐任务记录包含任务特征、Harness 差异、执行轨迹、得分、成本、成功状态、主要与次要失败维度和自然语言分析。系统周期性地把重复失败聚合成带证据和修复建议的全局模式。

最终全局 Harness 按字典序选择：先最大化平均任务得分，再在同分方案中最小化 Token。测试时经验库冻结；系统检索最相似的成功案例、失败案例、特征匹配记录和全局规律，然后只调用一次控制器，把全局 Harness 改造成当前任务的专用 Harness。本轮测试结果不会立刻触发学习或再搜索。

# Q6 实验设计

三个源任务分别是长程 Shell Agent 的 Terminal-Bench、单次代码生成的 LiveCodeBench 和多步金融推理的 FinanceAgent。搜索模型是 GPT-5.3-Codex，使用固定 80/20 划分、随机种子 42 和确定性生成。最终 Harness 由验证集选择，而不是直接采用测试集上的峰值轮次。

| Benchmark | 基础 Harness | 最终 MemoHarness | 绝对提升 |
|---|---:|---:|---:|
| Terminal-Bench | 0.722 | 0.806 | +0.084 |
| LiveCodeBench | 0.900 | 0.967 | +0.067 |
| FinanceAgent | 0.600 | 0.767 | +0.167 |

Terminal-Bench 的主要结果来自 18 个留出任务。FinanceAgent 在后期搜索中仍持续获益，而 LiveCodeBench 很快接近模型能力上限。

跨数据集实验覆盖 MMMLU、HumanEvalFix、StrongReject、Reasoning-Gym-Easy、LawBench 和 SWE-Bench Pro。迁移是选择性的：Terminal-Bench 学到的 Harness 在 MMMLU、StrongReject 和 SWE-Bench Pro 上分别提高 0.030、0.030 和 0.059，但饱和数据集没有变化，LawBench 结果也依赖训练来源。

跨模型 Terminal-Bench 实验中，同一个 GPT-5.3-Codex 学到的 Harness 在另外六个模型上都提高分数，平均提升 0.098，范围从 GPT-4.1 的 0.038 到 GLM-5 的 0.233。成本实验中，MemoHarness 使用 14.18M 输入 Token，其中 13.32M 被缓存，按论文的价格假设总成本为 6.89 美元，而 Codex 为 10.28 美元。

# Q7 数据集与代码

论文使用 Terminal-Bench、LiveCodeBench、FinanceAgent 和六个迁移评测集，没有提出新的独立数据集，也没有发布单独的经验库数据集。Terminal-Bench 的主要实验把 89 个任务按 80/20 划分，产生 18 个留出任务。

公开 Python 仓库包含配置、评估脚本、双层经验库、控制器、Harbor/Daytona Runtime、模型与 Embedding 工具和结构化运行包。文档要求 Python 3.10+、Harbor、Daytona 和至少一个模型提供商密钥，并提供训练与纯评估入口。但现有来源没有证明仓库包含每张表的原始重复运行结果、完整历史轨迹、已归档数据或可一键复现全部结果的正式 Release。

# Q8 证据质量

正面证据包括：三个差异明显的任务家族方向一致；最终模型由验证集而非留出峰值选择；跨数据集迁移被诚实报告为选择性而非普遍提升；六个额外基础模型都得到正迁移；成本不能抵消错误答案。

但统计和因果证据仍有限：

* Terminal-Bench 主要留出集只有 18 个任务，论文只报告点估计，没有置信区间或显著性检验。
* 结果虽然是重复运行平均值，但正文没有清楚给出重复次数。
* 不同商业 Agent Baseline 的底层模型和 Runtime 并不完全相同，因此部分比较是系统级比较，不是严格控制的 Harness 消融。
* 论文没有系统地分别消融全局 Harness、逐任务记录、全局模式和测试时适配，无法确定双层经验库或逐任务专门化各自贡献多少。
* 诊断器把异常、超时、命令失败和验证结果启发式映射到六个维度，但没有独立验证这些因果归因是否准确。
* 跨数据集提升较小且有选择性，两个任务已经饱和。
* 成本优势依赖很高的缓存命中率；如果 13.32M Token 不能复用，成本结论可能反转。
* 新增 Shell 命令与得分提升之间的关联分析是观察性的，不能证明这些命令导致提升。

因此，论文支持 MemoHarness 是一个有前景的自适应 Harness 原型，但还不足以证明它是统计稳健、组件贡献清楚的通用方案。

# Q9 主要贡献

1. 把 Harness 建模为六个明确的可编辑控制面，而不是单一 Prompt 或不透明代码对象。
2. 提出同时保存详细执行记录和全局归纳模式的双层经验库。
3. 区分训练时全局搜索和无反馈的逐任务测试时适配。
4. 使用正确性优先的字典序选择，避免用低成本补偿错误结果。
5. 在 Shell、代码和金融推理任务上报告域内提升，并展示选择性的跨数据集迁移。
6. 展示同一终端 Harness 对六个额外基础模型的正迁移。
7. 提供公开实现和可检查的诊断记录结构。

# Q10 后续研究

最关键的实验是析因消融：分别比较静态 Harness、仅全局搜索、只有逐任务记录、只有全局模式、只检索成功案例、只检索失败案例和完整测试时适配。实验需要更大的留出集、预注册指标、多随机种子、置信区间、逐任务配对检验，以及排除 Benchmark 泄漏的检索审计。

系统还需要测试错误或过时经验、分布外任务、对抗性相似案例、冲突全局模式，以及经验库长期增长后的检索退化。成本应在多种缓存命中率下报告，延迟、安全性和鲁棒性也应成为显式目标。

对本 Research OS 最可复用的思想，是把**单次执行证据**与**跨任务蒸馏规律**分开。每次任务尝试、Evaluator 输出、命令、失败和 Artifact Hash 可以保留为 Case 记录；只有被多次证据支持的经验才能升级为项目记忆、全局记忆或 Skill。运行时适配应同时检索正反案例，生成有边界的任务专用流程，保留全局默认方案作为回退，并在共享 Harness 被修改前经过留出评估或人工审查。
