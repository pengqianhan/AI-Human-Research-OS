# Q1 问题定义

* **输入（X）：** 一个权重冻结的大模型，在极简沙箱 harness（Claude Code 或 Pi，禁用默认系统提示、记忆、网络与子智能体）中担任教师；给它一个目标提示（通过文本文件提升玩家在未见过的单人游戏上的表现，且产物要能泛化）、一个默认玩家提示、从 {Read/Write、Bash、Gameplay} 中选出的工具集，以及 20 次上下文更新和 150 次观察对局的预算。
* **输出（Y）：** 玩家上下文 c_final（提示加上教师写的任意文本文件），由同一模型的新玩家实例在留出游戏基准上评估。
* **约束：** 没有人类编写的游戏，也没有验证分数；教师自己写游戏（PuzzleScript，消融中为 Python），无法编译或被 BFS 求解器证明不可赢的游戏会被 Gameplay 工具拒绝；玩家盲玩，奖励为二元，回合数与输出 token 有上限；推理强度为低。

# Q2 问题新颖性

非对称自博弈、GEPA、ACE、MCE、Meta-Harness、Darwin Gödel Machine 与 Hyperagents 都让模型生成数据、改写上下文或修改自身代码，但任务分布、目标与外层循环由外部指定。Open-Ended Optimization 与同期的 ASPIRE 把流程交给模型，但仍可访问外部数据或同一设置中的隐藏评测项。本文中模型既没有任务也没有分数，必须自己发明练习和进度检查，并以迁移到不同环境的效果来评判。

# Q3 科学假设

足够强的模型不再需要预先规定的自我改进算法：只要有生成经验和编辑文本的基本工具，它们就能组合出一套提升留出表现的学习流程，而且这种元能力随模型代际增强。

# Q4 相关工作与关键人物

* **非对称自博弈与无监督环境设计：** 师生式任务生成、可学习性奖励，以及防止坍塌的机制（评审、真实数据锚点）。
* **上下文与 harness 优化：** GEPA、ACE、MCE、Meta-Harness；自修改智能体（Darwin Gödel Machine、Hyperagents）。
* **自建学习流程：** Open-Ended Optimization；ASPIRE（同期工作）。
* **认知框架：** Zimmerman 的自我调节学习循环模型；最近发展区。
* **基准：** PuzzleScript 社区游戏、ARC-AGI-3、MazeBench。
* **关键人物：** Shobhita Sundaram 与 Phillip Isola（MIT CSAIL）、Cansu Sancaktar（图宾根大学）。可能的批评者：自博弈与 UED 研究者，他们会追问效果有多少来自论文自己也提到的强游戏先验。

# Q5 核心方法

1. **有师生、无规定循环：** 算法 1 只是在预算用完前不断采样教师动作；每次更新是对玩家目录的一次编辑工具调用。Gameplay 工具用教师选定的产物启动新玩家，返回得分、结束原因、剩余预算和对局记录路径。
2. **以迁移衡量：** 自我改进定义为留出基准上的 J(c_final) − J(c_0)：PuzzleScript-t20（20 个人类编写关卡，解长 ≤ 12，20 回合）、PuzzleScript-t30（20 个关卡，解长 13 到 22，30 回合）、ARC-AGI-3 第 1 关（17 个游戏）、MazeBench（3D ASCII 世界中的 16 个房间，100 回合，SPL）。基准剔除了 Claude Opus-5 在 8 次中 8 次都能解的关卡，之后重新跑基线。
3. **行为分析：** 算法计数（A/B 测试、平凡游戏、更新大小、提升某个观察胜率的更新）；把 13 个自我调节学习子过程改编成 0 到 3 分的量表，由 GPT 6-Astra 评分；重玩率与观察胜率的关系。
4. **信息消融：** 告诉教师什么（对九个推箱子式游戏的描述，0 到 6,551 token），以及工具施加什么限制（自选与 t20 一致的回合和 token 预算）。

# Q6 实验设计

* **模型：** Claude Opus-4.6 与 Opus-5、GPT 5.6-Sol 与 6-Astra、GLM-4.7 与 5.3；教师与玩家为同一模型；每个模型三个教师种子。
* **评估：** PuzzleScript 与 ARC 每关 4 次 rollout，MazeBench 每个房间 2 次。
* **对比：** 以 Opus-5 为玩家和反思模型的 GEPA，在 10 个训练和 10 个验证真实 PuzzleScript 关卡上运行，到 150 次对局预算时停止。工具集消融（仅 Read-Write、加 Bash、加 20 或 30 回合 Gameplay、Python Gameplay）。Opus-5 与 GPT 6-Astra 之间互换 c_final。预算扩展、饱和关卡检查，以及教师观察收益与实测收益（8 次 rollout）的核对。

# Q8 证据质量

**谁能自我改进（图 4，PuzzleScript-t20）：** 每个家族中较新的模型都超过其默认上下文基线：Opus-5 +20%，GPT 6-Astra +10%，GLM 5.3 +6%；Opus-4.6、GPT 5.6-Sol、GLM-4.7 几乎没有提升。在相同 rollout 预算下，Opus-5 在自编游戏上的自组织学习与在 20 个真实游戏上运行的 GEPA 大致相当（图 3）。

**迁移（图 9，Opus-5）：** 用 20 回合 PuzzleScript 对局学到的上下文使 PuzzleScript-t20 提升 20%、t30 提升 9%、ARC-AGI-L1 提升 21%、MazeBench SPL 提升 0.15。30 回合 Gameplay 在所有基准上最好，包括 t20。仅 Read-Write 也胜过基线，但除 MazeBench 外收回不到 Gameplay 收益的一半；加 Bash 更好，且在一次只有 Bash 的会话中教师自己写并运行了游戏模拟器。Python 对局在四种情况中有三种几乎收回了 PuzzleScript 对局的全部收益。

**跨模型（表 1，PuzzleScript-t20 胜率）。**

| 玩家 | 产物来源 | 胜率（%） |
|---|---|---|
| Opus 5 | 无 | 25.4 ± 3.6 |
| Opus 5 | GPT-6 Astra | 47.5 ± 4.5 |
| GPT-6 Astra | 无 | 67.1 ± 3.8 |
| GPT-6 Astra | Opus 5 | 72.1 ± 4.0 |

**行为：** 能自我改进的模型更多做 A/B 测试，更少生成平凡游戏（解长 < 5 且观察胜率 100%），在多数自我调节学习子过程上得分更高，并且最常重玩低到中等胜率的游戏；Opus-5 与 GLM 5.3 的大部分重玩落在观察胜率 20% 到 60% 的游戏上，论文将其类比为可学习性目标的倒 U 形；部分 Opus-5 与 GPT 6-Astra 会话编写了带 BFS 难度过滤的程序化关卡生成器。对推箱子式游戏的描述越详细，起初对该游戏集和 ARC-AGI-3 都有帮助，之后只对该游戏集有帮助；施加 t20 预算会提高 t20、降低 t30。在十个已饱和关卡上，学到的产物保持 98.8%（基线 100%）。

**证据的局限：**

* 提升数值来自图中以"%"标注、三个教师种子 ±1 标准差的结果；表 1 的数字表明单位是胜率的百分点（读者推断）。PuzzleScript-t20 每次评估 80 次 rollout，一次 rollout 等于 1.25 分（读者计算）。
* 所有留出集都剔除了 Opus-5 在 8 次中全部解出的关卡。重新跑基线去掉了直接的选择效应，但因 Opus-5 偶然失败而被保留的关卡对任何上下文都可能向上回归，这会特别有利于 Opus-5 的实测提升（读者推断）。GPT 6-Astra 在这个按 Opus 过滤的集合上本已有 67% 胜率。
* 自我调节学习的评审是 GPT 6-Astra，它本身是被评的六个模型之一（读者观察）；论文也说明这种对应是相关而非因果。
* 迁移、GEPA 与信息研究只用了 Opus-5，因此"新模型能泛化"在 PuzzleScript-t20 之外只靠一个模型支撑。
* 游戏领域在预训练数据中有丰富的课程设计文献，评测时程短、只有 20 次更新；更大预算下表现趋于平台（原文说明）。

# Q9 贡献

1. 一个受控、无数据的设置：冻结的大模型必须自己设计上下文优化流程，以迁移到留出游戏基准的效果衡量成败。
2. 证据表明三个家族的较新一代能在其中自我改进而旧一代不能，并用自我调节学习与可学习性的概念描述其策略。
3. 迁移与消融结果：自写文本可跨回合长度、引擎、3D 表示和模型泛化，而关于评测设置的信息会在泛化与专门化之间取舍。

# Q10 后续方向

* **原文提出：** 刻画较难被人理解的行为；在模型先验较弱的领域测试；探索如何在 20 次更新之后继续提升，迈向 100 或 1,000 次；研究自发自我改进的安全含义。
* **跨家族评审与筛选：** 用被评家族以外的评审重新标注自我调节学习行为，并用不在研究范围内的模型来过滤留出集（读者建议）。
* **权重空间版本：** 以微调作为更新原语、采用同样开放的流程，可检验这一发现是否只限于文本优化。
