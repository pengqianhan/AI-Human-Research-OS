# Q1 问题定义

* **输入（X）：** 任务目标 G、初始观察 o₀、一个智能体逐步与之交互的环境（文本动作、MCP 工具调用、诊断工具调用，或向模拟病人提问），以及动作预算 T。
* **输出（Y）：** 一串动作，以完成任务或给出最终提交（根因实体与故障类型，或诊断结论）结束；动作依据显式信念 B_t 而不是原始历史来选择。
* **核心问题：** 在长任务中，动作会改变世界，新观察会推翻之前的推断。原始轨迹按时间保留一切；记忆方法对其做选择、压缩或重组。两者都没有给智能体一个关于*当前*世界、可以显式检查的估计。作者为 LLM 写出的信念提出两条要求：它必须保持内部一致并有证据支撑；智能体还必须能察觉自己在持续行动却没有进展，作者称之为**信念陷阱（Belief Trapping）**（重复无效动作、在已访问状态间循环，或收集对完成任务无用的信息）。
* **形式化框架：** 一个 POMDP，其中信念 b_t(s) = P(s_t = s | h_t) 本应是决策的充分统计量。PoS 用一个结构化、以任务为条件的信念 B_t = (W_t, G, Δᴱ_t, Δᴬ_t) 来近似它：世界状态、目标、认知缺口（epistemic gaps，仍未知的信息）和达成缺口（achievement gaps，仍需完成的事）。

# Q2 问题新颖性

部分新颖。显式表示智能体状态已有先例：QuBE 通过问答构建信念，StateAct 维护一串状态，ReflAct 对照目标反思当前状态，Tru-POMDP 维护关于假设的粒子信念，Graph of States（同一第一作者）把信念与因果图和状态机结合用于溯因任务，[LongHorizon-Harness](../papers/2608.01964.md) 维护经审计的任务状态。关于进展停滞，T3 在 RL 训练中检测信念偏移并截断轨迹，CGDP 用"耗尽门"终止无效的上下文收集。本文的主张在于组合：每步都被校验、*同时*被监测是否陷入陷阱的信念，并在回合内部恢复，而不是截断或终止。

# Q3 科学假设

如果智能体依据一个把当前世界状态与"仍需了解的"和"仍需完成的"分开的显式信念做决策，并且该信念（a）在提交前经过内部一致性和证据一致性检查，（b）被持续监测，一旦停滞就触发针对"如何卡住、卡在哪里"的恢复，那么在执行类和诊断类任务上的长程成功率都应提升，并且在上下文增长时保持稳定，超过单纯保留、压缩或重组历史所能达到的水平。

# Q4 相关工作与关键人物

* **以记忆为上下文：** ReAct（原始轨迹）；压缩类（ReadAgent、ACON、SUPO）；结构化保留（HiAgent 的子目标记忆、COMPASS 的进度简报、PACE 按相关性分级保留历史）；由智能体控制上下文（MemGPT、CaT、AgentFold、Sculptor）。
* **以信念为上下文：** 探测 LLM 世界状态表示的研究；QuBE、StateAct、ReflAct、Tru-POMDP、自然语言信念摘要、Graph of States，以及 [LongHorizon-Harness](../papers/2608.01964.md)——本文认为后者依赖可独立验证的中间结果，因此不太适合诊断类任务。
* **进展停滞：** T3（RL 中截断）和 CGDP（智能体搜索的 POMDP 框架中的耗尽门）。
* **基准：** ALFWorld、LOCA-Bench、RCA-100、ClinDiag。
* **关键人物：** 南开大学（Yu Luo、Jiamin Jiang、Yimin Zuo、Rongchen Gao、Yongqian Sun、Shenglin Zhang；Yongqian Sun 名字旁标有星号）、阿里巴巴集团（Xidao Wen、Guiyang Liu、Cheng Zhang、Fang Situ、Qi Zhou），以及清华大学的 Dan Pei。工作完成于阿里巴巴实习期间。多位作者也是四个基准之一 RCA-100（Cai et al., 2026）以及 Graph of States 的作者。

# Q5 关键解法思路

* **信念建模。** 世界状态 W_t 是"实体–状态–关系"（Entity–State–Relation）结构：实体是任务中的对象或主体，状态是对实体当前状况的自然语言描述，有向关系连接实体与状态。每条状态和关系都带有来源、置信度，以及可用时的支撑证据。只保留会影响动作可行性、结果判断或目标达成的记录。
* **活跃缺口。** PoS 从所有未解决的缺口中选出一个活跃缺口 Δ_t 作为当前焦点，并保持到其解决。动作按 a_t ~ π(· | B_t, Δ_t, C_t) 选取，其中 C_t 是恢复约束，正常运行时为空。
* **信念哨兵（Belief Sentinel）。** 每次观察后，任务智能体写出候选信念；哨兵审查新增或修改的实体、状态、关系和缺口，查找内部矛盾（例如微波炉同时被记为开和关）和外部矛盾（与最新观察冲突），任务智能体修订后才提交。局部审查每步进行；全局审查每 8 步一次（LOCA-Bench 上每 32 步）。
* **信念健康度。** 每个经校验的转移都得到一个进展标签：诊断任务看总置信度变化是否超过 ε = 0.30；执行任务由哨兵判断活跃缺口是否推进。在 K = 8 个转移的窗口内，PoS 计算缺口持续度 P_X（X 类缺口在整个窗口内都未解决的比例）、进展停滞度 S_t 和信念复现度 R_t（与缺口相关的世界状态按 Jaccard 距离重复出现的频率，滞后最多 4 步）。健康度为 H_t = 1 − max_X [P_X · max(S_t, R_t)]，H_t ≤ 0.25 时判定陷入陷阱。仅有缺口持续并不会触发：缺口未解决但持续有进展时健康度仍为 1（附录 B.3 将其与几何平均和取最大值两种聚合方式做了对比）。
* **因子化诊断与恢复。** 依次把动态分为静止（Static，世界状态不变）、循环（Cycle，周期性复现）或漂移（Drift，世界在变，但与活跃缺口相关的部分不变），被阻塞的缺口类型取认知与达成中持续度更高的一方。恢复约束由模式约束（抑制无效转移、打破循环，或重新锚定到活跃缺口）和缺口约束（寻找有区分度的证据，或做出与任务相关的状态改变）组合而成，健康度回升到阈值以上后解除。

# Q6 实验设计

* **基准：** ALFWorld valid_unseen（134 个任务，50 步动作）；LOCA-Bench（15 个种子任务 × 8K 到 256K 的 7 种上下文长度 × 5 个环境种子 = 525 例，100 次 MCP 调用）；RCA-100（全部 103 个微服务故障案例，分别评故障分类、根因定位及两者联合；50 轮，至多 150 次工具调用）；ClinDiag（302 个常见病例加 302 个罕见病例，30 次提问；需授权访问的急诊子集被排除）。
* **骨干模型：** 通过 DashScope API 调用的 Qwen3.7-Plus、Kimi-K3 和 GLM-5.3，温度为 0。PoS 和各基线的所有 LLM 组件都使用被评测的骨干；ClinDiag 的模拟病人和评判固定为 Qwen3.7-Plus。
* **基线：** 在同一 ReAct 驾驭层中的原始轨迹（Raw Trajectory）、ACON、PACE 和 HiAgent，以及保留原生"管理-执行-审计"循环的 LongHorizon-Harness。ACON 保留运行时压缩，但去掉了指南优化和蒸馏（没有训练集）；PACE 因代码仓库无法访问而按论文重新实现，并换了嵌入模型；HiAgent 从 AgentBoard 移植。
* **分析：** 去掉一致性校验或陷阱诊断的消融；陷阱发生率与模式分布；因子化恢复与通用恢复提示的对比；RCA-100 上的 token 成本；LOCA-Bench 上成功率随上下文长度的变化；一个 RCA-100 案例分析。

# Q8 证据质量

* **有支撑的：**
  * *主表中一致领先。* 在全部 12 个"基准 × 骨干"组合中，PoS 的总体得分都是最高。相对每个骨干下最强的基线，最大相对增益为：ALFWorld 22.68%（Qwen3.7-Plus：88.81 对 LongHorizon-Harness 72.39）、LOCA-Bench 7.53%（GLM-5.3：70.86 对 ACON 65.90）、RCA-100 联合准确率 37.89%（Qwen3.7-Plus：38.83 对 28.16）、ClinDiag 11.31%（GLM-5.3：52.15 对原始轨迹 46.85）。使用 Kimi-K3 时，RCA-100 联合准确率达到 51.46，最强基线为 41.75。
  * *基线并不总是优于原始历史。* PACE 在 LOCA-Bench 上比原始轨迹低 24.57-28.19 分；在 GLM-5.3 的 ClinDiag 上，没有任何记忆类基线超过原始轨迹。LongHorizon-Harness 在 ALFWorld 以及 Qwen3.7-Plus 的 LOCA-Bench 上是最强基线，但在 RCA-100 上落后，这与论文"其审计需要可验证的中间产物"的观点一致。
  * *两种机制都重要。* 去掉一致性校验在 ALFWorld 上最多损失 14.93 分、在 LOCA-Bench 上损失 11.81 分，但在 ClinDiag 上只损失 0.33-0.66 分；去掉陷阱诊断在 RCA-100 上损失 4.85-6.79 分、在 ClinDiag 上损失 2.65-3.97 分。在 RCA-100 上，去掉校验主要损害故障分类（Qwen3.7-Plus 下 −6.80），去掉恢复主要损害根因定位（−3.88 到 −4.85）。
  * *上下文增长。* 在 LOCA-Bench 上，PoS 从 96K 到 256K 基本稳定，在 256K 时领先最强基线 10.67-16.00 分。
* **较弱或有边界的：**
  * *成本没有对齐。* 在 Qwen3.7-Plus 的 RCA-100 上，PoS 每回合用 1,800K token，原始轨迹为 356K（5.06 倍）；其中哨兵（822K）和信念维护（697K）各自都比任务智能体（281K）更贵。预算只在环境动作数上对齐；没有给任何基线同等的额外推理（例如采样或自我验证），因此无法判断增益来自信念结构还是更多计算（读者注）。token 成本只报告了 RCA-100。
  * *去掉校验器后，PoS 常常不如最强基线（读者注，依据表 1）。* 无校验变体在三个骨干的 LOCA-Bench 上都低于最强基线（例如 Qwen3.7-Plus 下 44.57 对 52.57），在 GLM-5.3 的 ALFWorld 上也是如此。因此在执行类基准上，相对最强基线的优势依赖于校验，单靠显式信念做不到；在 RCA-100 上，无校验变体仍优于所有基线。
  * *单次确定性运行，部分组合差距很小。* 每个组合只有一次温度为 0 的运行，没有方差。ALFWorld 一个任务约 0.75 分，RCA-100 一个案例约 0.97 分，所以 Kimi-K3 和 GLM-5.3 在 ALFWorld 上对 LongHorizon-Harness 的领先（2.24 和 1.49 分）只相当于 2-3 个任务。Qwen3.7-Plus 和 RCA-100 上的大差距远超这一粒度。
  * *基线改造。* ACON 没有使用学到的指南，PACE 是换了编码器的重新实现，这可能削弱它们；PACE 在 LOCA-Bench 上的崩溃可能部分源于此（读者注）。
  * *RCA-100 的领先在故障类型而非定位（读者注，依据表 9）。* 使用 Qwen3.7-Plus 时，PoS 定位根因实体的准确率（67.96）低于原始轨迹（68.93）、HiAgent（76.70）和 LongHorizon-Harness（75.73）；其联合准确率的领先来自故障分类（39.81，基线至多 33.01）。
  * *因子化恢复与通用恢复的对比* 只以 Qwen3.7-Plus 的图给出，正文没有报告数字。
  * *作者自建的基准。* RCA-100 来自部分重叠的作者；论文没有说明 PoS 是否在其上开发。

# Q9 贡献

* 命名并操作化了**信念陷阱**，用三个信念层面的信号（缺口持续、停滞、复现）组合判定，使单纯的缺口未解决不被算作停滞。
* 一个结构化、以任务为条件的信念（世界状态加认知缺口与达成缺口），配合活跃缺口和逐步一致性审查。
* 因子化恢复：把针对动态模式的脱困约束（静止、循环、漂移）与针对缺口类型的进展约束组合起来。
* 在统一接口下对多种上下文管理基线做跨领域比较，表明在当前长上下文模型上，记忆压缩和结构化并不能稳定胜过原始历史。

# Q10 下一步

* **作者的计划：** 降低自然语言信念的 token 成本，例如用紧凑的潜在世界状态表示；在信念更新中加入领域知识检索，因为 ClinDiag 的许多错误发生在智能体已拿到正确信息、却缺乏解读所需医学知识的时候。
* **算力对齐的对照（读者注）：** 给 ReAct 基线与 PoS 相同的 token 预算（自洽采样、复查一遍或再试一次），以区分信念结构本身的价值与额外推理的价值。
* **校验器成本（读者注）：** 哨兵是最大的单项开销。检验更便宜的模型或更低频的审查能否保住执行类任务上的增益，因为正是校验让 PoS 在那里超过最强基线。
* **与审计者结合（读者注）：** PoS 依据已有证据校验信念，而 [LongHorizon-Harness](../papers/2608.01964.md) 对照环境做验证。在产物可检查之处用环境审计、在进展属于推断之处用信念校验，这种混合方案可以检验论文对"两者各自何时占优"的解释。
* **与本仓库的关联（读者注）：** 认知/达成缺口的划分，以及"缺口持续且伴随停滞或复现"的停滞规则，都很容易用于本仓库的长时间智能体运行，例如在会话交接中加一项检查：列出仍未知的事和仍未完成的事，若这些未决项在若干步内都没有变化，就标记该运行。
