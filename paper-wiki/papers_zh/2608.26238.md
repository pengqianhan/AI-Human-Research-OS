> 论文:**Procedura: Agentic 3D Modeling with Procedural Control**
> 论文链接:<https://arxiv.org/abs/2608.26238>
> 机构:南京大学 / Envision

# Q1 问题定义

* **输入 `X`**:一段文本提示词(可选配一张参考图),描述一个包含许多零件、具有硬表面特征的物体;以及一个具备视觉输入与代码执行能力(可调用类 OpenSCAD 的 CSG 编译器)、冻结的、未经过任何三维专项训练的 LLM。
* **输出 `Y`**:Procedura——一个把物体逐个零件生长为过程化装配体 A=(P,C) 的 agentic 框架,其中 P 是一组带名字的参数化 CSG 零件,C 是连接这些零件、类型化且可机器校验的"配合(mate)"关系;编译该程序即得到一个具有锐利机加工边缘、原生零件分解、且参数可由用户编辑的网格,而非一个软化、未分解、不可编辑的网格。
* **核心问题**:原生三维生成器(基于分数蒸馏、前馈回归、原生三维扩散、自回归网格等方法)能恢复令人印象深刻的几何形态,但输出的是密集网格,论文写道"在机加工物体本应锋利的地方,网格却是软的";网格里"没有任何信息能说明哪些三角面属于哪个零件";也不暴露任何可编辑参数——分割与可编辑性都需要额外的后处理模型。基于程序的替代方案(CSG 树归纳、结构化装配程序、草图-拉伸式 CAD、LLM 脚本生成)原则上能产出可编辑、零件化的形状,但论文指出这条路线"仍停留在单次生成,一次性写出代码而没有视觉反馈,导致零件数量多的物体会出现零件数量错误、位置错位"。
* **范围**:LLM 策略保持冻结,不接受任何三维专项训练;所有结构都来自 agentic 脚手架(规划、配合驱动的构建、验证门控、解耦评审器,以及独立的材质/关节化环节),而非模型权重本身。

# Q2 问题的新颖性

原生三维生成(DreamFusion、Magic3D、Point-E、Shap-E、LRM、LGM、Direct3D、TRELLIS、UltraShape、Hunyuan3D、PolyGen、MeshAnything、MeshGPT)与基于程序的三维生成(CSGNet、UCSG-Net、ShapeAssembly、JoinABLe、AutoMate、DeepCAD、Fusion 360 Gallery、SkexGen、Text2CAD)都是本文所依托、而非首创的活跃方向;近期具备草稿-执行-修订循环的 agentic 三维代码系统(CADDesigner、CadSmith)和领域微调的代码生成器(CAD-Coder、cadrille),以及 LLM 场景布局系统(ProcTHOR、LayoutGPT、SceneCraft)同样如此。Procedura 声称的新意在于把这些工作都不曾同时具备的三个特性耦合起来:(1) 零件之间的每一段关系都是一个*类型化、可机器校验的配合*,会针对已编译网格进行验证,而非模型凭空给出、只能寄望其正确的原始变换;(2) 位置是从被配合的坐标系中*解出*的,而非由模型猜测——论文称这一点消除了"此前三维代码系统中最大的单一漂移来源";(3) 负责诊断缺陷的评审器与负责修复它的 agent 是*解耦*的,论文给出的理由是"一个评判自己输出的模型,身上带着正是造成该错误的那些假设,因此独立的评审者更可能发现它"——这与此前那些由同一模型既做评判又做修改的 agentic 三维代码循环形成对比。

# Q3 科学假设

如果一个 LLM agent (a) 在写任何代码之前,先把一个多零件物体规划成一张带有类型化配合声明的有序装配图;(b) 每次调用只生长一个零件,而非每一轮都重新生成整个物体,并从每个新零件所声明的配合中解析式地求解其位置,而不让模型给出一个原始变换;(c) 一个零件只有在通过编译门、逐配合的注册面积/穿透深度门,以及考虑变化量的连通性门之后才会被接纳;并且 (d) 这一构建阶段与一个解耦的单轮视觉评审器交替进行,该评审器的诊断以"一次诊断解锁一次编辑"的方式门控恰好一次后续编辑——那么由此产生的物体在边缘锐度、零件连通正确性,以及被评判的几何/美学/语义质量上,都会优于原生三维生成器以及此前单次生成或自我评判式的三维代码 agent,同时依然可按零件名完全编辑,并且可无需改变底层冻结 LLM 就扩展到逐零件材质与经模拟器验证的关节化。

# Q4 相关工作与关键人物

* **原生三维生成**:基于分数蒸馏的优化方法(DreamFusion、Magic3D)、前馈回归(Point-E、Shap-E、LRM、LGM)、原生三维扩散(Direct3D、TRELLIS、UltraShape、Hunyuan3D)以及自回归网格模型(PolyGen、MeshAnything、MeshGPT)都只针对输入视角做优化,输出密集、软化、未分解的网格;要恢复零件或编辑句柄,需要事后再挂一个独立的分割模型(PartField、SAMPart3D)。
* **基于程序的三维生成**:CSG 树归纳(CSGNet、UCSG-Net)、结构化装配程序(ShapeAssembly、JoinABLe、AutoMate),以及 CAD 原生的草图-拉伸生成(DeepCAD、Fusion 360 Gallery、SkexGen、Text2CAD)都直接以可编辑、零件化的输出为目标,论文把基于 LLM 的参数化脚本生成(Three.js/Blender 脚本)也归入这一类,认为它本质上仍是单次生成。
* **Agentic 三维代码生成——最相近的前作**:草稿-执行-修订循环(CADDesigner、CadSmith)和领域微调的代码生成器(CAD-Coder、cadrille)已经具备迭代能力,但没有 Procedura 的类型化配合验证或解耦评审器;论文自己的基准结果(见 Q6)显示 CAD-Coder 与 cadrille 在 MechBench-36 相当一部分案例上根本没能产出网格。基于 GPT-5.6-sol 构建的 ArtiCraft 被作为最强的前作 agentic 三维代码基线来评测。另外,已有的关节化工作(视觉-语言关节化方法、LLM 场景布局系统 ProcTHOR/LayoutGPT/SceneCraft)为 Procedura 的关节化阶段提供了参考,其中关节图直接复用了同一套配合网络,而非另建一套表示。

# Q5 核心解法

1. **带类型化配合的过程化装配体**。物体表示为 A=(P,C):一组带名字的参数化 CSG 零件 P,每个零件都编译为精确的平面/圆柱面(而非采样几何),彼此由配合 C=(i,j,type,Fᵢ,Fⱼ,d,φ) 连接——一段类型化关系,连接新零件上的一个配合坐标系与已放置零件上的一个配合坐标系,二者共享一个标称尺寸 d 加一个带符号的配合偏移 φ。论文定义了九种静态配合类型(螺栓阵列、销孔、座面、法兰、榫槽、压装、唇口企口、卡扣、键)和三种运动学类型(旋转副、移动副、球面副),每一种都固定了特定的自由度签名。
2. **两阶段装配图规划**。一次视觉调用把目标物体分解为一个有序、带名字的零件列表,并声明各自的接口(配合伙伴、类型、共享标称尺寸),约束是每个零件都必须连接到某个已放置的零件上;第二次视觉调用对照参考图审阅该计划,但在代码层面被限制为只能补充缺失零件或细化描述/配合——绝不能合并、删除、重命名或重排,这条规则由代码强制执行,而非寄望于提示词。
3. **配合驱动、逐零件调用的构建**。agent 不是每轮重新生成整个物体,而是每次调用恰好新增一个零件,依据三类信息:装配参考(图像、提示词与当前的计划片段)、已构建至今的完整程序文本,以及 agent 自己从固定目录中挑选、最多 12 个渲染视角(6 个正交面、6 个等轴测角)。对于一个静态配合,位置是*解出*的,而非生成的——Tⱼ = Fᵢ·Δ(φ)·Fⱼ⁻¹——论文认为这一点消除了此前系统中最大的漂移来源。每个候选零件在被接纳前必须通过三道门:编译门(失败时把编译器报错回传给模型)、逐配合的注册面积/穿透深度门(a(c) ≥ τₐ·d² 且 δ(c) ≤ δₘₐₓ(φ)),以及一个考虑变化量的连通性门,该门只有在游离零件数量相对当前基线*增加*时才拒绝(从而允许合法的后续连接)。每个零件最多有三次质量尝试机会,用尽后仍会带警告接纳。
4. **带诊断门控编辑不变量的解耦评审精修**。每一轮构建之后,一个在架构上与构建 agent 分离的单轮视觉评审器——接收渲染视角、零件配色图例、程序文本,以及此前若干轮的标记记录——返回一句话摘要,以及一份按严重程度标注(HIGH/MED/LOW)、指名负责模块的问题清单。随后由一条硬性不变量门控编辑:一次成功的诊断会设置一个一次性的锁存位,恰好由紧随其后的一次编辑消耗掉,编辑工具在锁存位未设置时拒绝执行(若渲染视角相对当前程序已经过期,诊断本身也会拒绝)。一项针对该门控的消融显示,一旦去除门控,诊断-编辑比会从约 1:1 恶化为 2 次诊断对应 15 次编辑。一个基于跨度(span)的连通性度量(组件跨度比与阈值 τ=0.01 比较,选用跨度而非体积,是因为体积检查会漏判薄而平的、视觉上明显脱离却体积接近零的面板)会门控终止动作 finish,直到游离零件数为零。
5. **复用同一配合图的独立材质与关节化环节**。材质:一个非 agentic 的四阶段流水线,从参考图中提取一个紧凑的 PBR 材质库,把库中材质逐一分配给命名零件,运行一个独立的单轮材质评审器,再把带多种材质的零件改写为相邻的分色代码块。关节化:静态配合把零件分组为刚性连杆,运动学配合从确定性几何证据(旋转对称轴、接触区域)中给出关节类型/轴/锚点候选,一次视觉调用在由此得到的父子树上分配轴/限位/驱动,结果导出为 OpenUSD/URDF,并在 Isaac Sim 中经过一套固定检验(动态沉降、逐关节驱动扫描、静止接触扫描、轮式移动测试、URDF 重新导入)验证,任何被标记的故障都会把渲染出的模拟帧回传给规划器进行一次修精。

# Q6 实验设计

两个基准:MechBench-36,一个新的硬表面基准,包含 36 个刻意设计为多零件的物体(漫游车、机甲、起重机、挖掘机、发动机、起落架),用于比在单一子装配体形状之上更严苛地考验零件数量、放置与连通性;以及已有的 P3D-Bench,203 个由其自带装配评判器打分的文本加图像案例。所有被比较方法的提示词与参考视角都锁定一致。评判采用盲测:每个方法的输出都从同一固定视角集重新渲染,套上灰陶土渲染规则,分配一个不透明哈希后盲评,由一个视觉 LLM 评判器(高推理模式下的 Gemini 3.7 Flash)沿语义保真度、几何质量与美学三个维度打分,并辅以 CLIP 图文对齐度、超过 60° 二面角阈值的锐边长度(Shrp₆₀),以及第 95 百分位二面角(Dih₉₅)。Procedura 主要以 Gemini 3.7 Flash 为主干模型运行(冻结、未经三维训练),GPT-5.6-sol 作为第二主干;编译器为 OpenSCAD,渲染用 Blender,物理验证在无头 Isaac Sim 中进行。

在 MechBench-36 上,Procedura(Gemini 3.7 Flash)综合得分达到 0.828,领先最强的原生生成器 TRELLIS.2(0.810)、最强的前作 agentic 三维代码基线 ArtiCraft(基于 GPT-5.6-sol,0.702),以及 GPT-5.6 单次生成(0.792);CAD-Coder 与 cadrille 分别只有 0.135 与 0.092,且各自在 36 个案例中的 11 个与 5 个上根本没能产出网格。Procedura 的锐边长度(158.08)是次优代码方法的 2.6-3.1 倍,远高于原生生成器(集中在 6.4-35.2 Shrp₆₀);其第 95 百分位二面角(97.97°)同样领先。与其自身的非 agentic 基础模型配对比较,Procedura 在美学上提升 +0.105(20 胜 7 负,p=0.019),CLIP 提升 +1.80(p=0.011)。在 P3D-Bench(203 个案例)上,Procedura 在两个主干模型下都领先每一个被打分的列(Gemini 3.7 Flash:综合 0.590±0.009;GPT-5.6-sol:0.575±0.010),领先各自对应的单次生成主干(0.566、0.563),并进一步领先 GPT-5.5(0.524)、Gemini 3.1 Pro(0.513)与 Opus 4.6(0.448);其几何维度的差距(0.490 对单次生成的 0.392)是单一维度上最大的差距,本笔记认为这直接对应了"配合驱动的精度"这一核心主张。

一项在 MechBench-36(n=36)上的消融实验,每次从完整流水线(综合得分 0.828)中移除一个机制:去掉精修循环降至 0.800,去掉规划环节降幅最大、至 0.791(单一机制中代价最大,主要集中在美学维度),去掉三维反馈(渲染视角上下文)降至 0.819,且各维度都有损失。一项针对"突击越野车"模型的定性精修案例研究显示,高严重度问题数量随精修轮次从 4 降到 3 再降到 2,其中一轮实现了亚毫米级的接触修正,改变了连通性却未改变外形轮廓。此外,材质在同一辆越野车模型上做了演示(提取 25 个材质库条目、分配给 41 个零件,经材质评审器修正,再拆分为子零件分色代码块);关节化在 18 个物体上评测:18 个中有 14 个通过了物理验证的每一个阶段,其中 9 个还通过了附加的资产建议规则,4 个彻底失败(其中 1 个无负载响应,3 个的执行器从未到达指令范围),而通过测试的位置驱动关节能到达至少 97% 的指令范围。

# Q9 主要贡献

1. 把三维形状即代码(3D-shape-as-code)的生成范式确立为目标,并用一个冻结、未经三维训练的 LLM agent 而非专门的三维模型来实现这一扩展——Procedura 仅凭一个通用视觉-语言模型加一个编译器,就能从文本提示词生成细节丰富的多零件形状。
2. 一种带类型化、可机器校验配合的过程化装配表示:零件位置从声明的配合坐标系中解析式求解,而非作为原始变换生成;每一次零件提交都由编译门、配合注册面积/穿透深度门与连通性门把关,使构建过程始终保持连通、精确、且可按名字编辑。
3. 一个带诊断门控编辑不变量(一次诊断解锁恰好一次编辑)的解耦视觉评审器,据报告在门控开启时能把诊断-编辑比维持在约 1:1,而去除门控后会恶化为 2 次诊断对应 15 次编辑。
4. 在与原生三维生成器和所有已测试的前作三维代码 agent 的对比中取得最先进结果(P3D-Bench 与新提出的 MechBench-36),在边缘锐度与几何质量上的领先幅度最大;向逐零件 PBR 材质与经模拟器验证的关节化(18 个物体中 14 个通过完整物理检验)的扩展,证明了同一套配合图能支撑静态几何之外的下游任务。

# Q10 下一步

论文自陈的局限性:agent 只通过渲染图像来感知构建结果,渲染视角能很好地传达轮廓与位置信息,但被遮挡的内部结构与细微的接触几何可能在每个相机角度下都无法被看到——作者建议深度图、剖面图或直接的网格查询会是更强的反馈信号;CSG 几何适合表达机械、硬表面物体,但对有机、自由形态曲面的表达不如神经场自然;配合词汇表只覆盖刚性关节,计划中从未声明为配合的关系,门控系统也就无法对其进行验证,这为计划本身遗漏的连通性错误留下了一条未受验证的通道。论文的结语把其原则推广到三维建模之外:把生成看作编码、用可验证关系连接零件、把评审者与修复者分开、在编译器或模拟器中验证每一个主张,而非信任模型自己的汇报——论文陈述这些原则可以延伸到"更广义的基于程序的生成"。

本笔记在论文自身框架之外补充一条联系:Procedura 的诊断门控单次编辑不变量(一次诊断解锁恰好一次编辑,由一次"视角过期即拒绝"检查来保证)是本知识库 [Agent self-evolution](../topics/agent-self-evolution.md) 与 [Agent harness engineering](../topics/agent-harness-engineering.md) 两个主题在跨任务层面所追踪的诊断-打补丁纪律(例如 SkillOpt 的留出验证门控、AutoSaddler 的类型化补丁)在单个任务内的一个实例——这里的门控是为了防止单次构建自身的评审-修复循环失控震荡,而不是为了把一次变更接纳进一个跨未来任务持久存在的记忆,但底层的承诺("在让一次提议的变更生效之前先验证它")是同一种纪律,只是作用在细得多的粒度上。
