# Q1 问题定义

* **输入（X）：** 学术级算力预算与开放数据来源。训练流程包括：
  * 通用预训练：Stage 1 约 0.99T token，Stage 2 约 3.20T token；
  * 中期训练（mid-training）：上下文按 16K → 64K → 256K 课程扩展，数据含推理、指令和智能体轨迹；
  * SFT：4,921,933 条样本，通用 96.46%、智能体 3.54%；
  * 混合 GRPO 强化学习：数学、代码、通用任务。
* **输出（Y）：** ZGCM-1-7B，一个 7.39B 参数、256K 上下文的稠密解码器。同时发布各阶段权重、中间检查点、训练代码、分阶段数据与配方、W&B 日志和评测框架。推理时是一个启用思考的策略，可以直接回答，也可以运行 ReAct 工具循环（网页搜索/阅读、Ghidra 二进制分析、bash）。
* **核心问题：** 作者指出两道壁垒：
  * *规模壁垒*：普遍认为前沿推理和深度智能体搜索需要数千亿参数的模型；
  * *不透明壁垒*：有竞争力的模型只开放权重而非完全开源，过滤配方、中期训练课程、长上下文调度和智能体轨迹都无法研究。
* **范围：** 单个 7B 稠密模型；报告的评测使用发布的 256K *SFT* 检查点、思考模式（第 5.1 节）。混合强化学习阶段有描述，但不是标题表格背后的检查点。智能体主张集中在网页深度研究和二进制分析；软件工程与终端能力只作为附录诊断报告。

# Q2 问题新颖性

目标本身不新：完全开放的小模型（如 Olmo-3-7B-Think、OpenThinker3-7B、MiMo-7B-RL、MiniCPM4.1-8B）和小型搜索智能体都已存在。论文声称的贡献是一个*组合*：从零训练、完全开放的 7B 模型，用同一套权重同时瞄准竞赛数学和多步智能体搜索，采用效率优先的配方，并发布中间产物。"紧凑模型 + 深度思考 + 主动使用工具"的论点对本 wiki 有意义，因为它追问：搜索智能体能力能否放进一个小到学术实验室可以端到端训练和研究的模型中，而不只是在前沿模型上靠提示获得。

# Q3 科学假设

如果紧凑模型无法记住整个开放网络，那么训练它把长链式思考与外部工具使用结合起来，应当能让 7B 模型在证据可被*获取*的任务（网页深度研究、二进制分析）上接近大得多的模型，同时在闭卷、依赖记忆的知识任务上仍然落后。训练手段有两点：一是在中期训练中把交互轨迹转为稠密的、以状态为条件的下一动作监督；二是 SFT 的工具 schema 与推理环境严格一致。

评测结果符合这一模式：
* **证据可获取的任务：** 在重搜索的基准上具有竞争力甚至更好。按报告数值，WebWalkerQA 63.09 对 Kimi-K2 的 63.00，BrowseComp 19.43 对 Claude 4 Sonnet 的 12.20。
* **闭卷知识：** 在 MMLU（73.88，同级最高 85.40）和 GPQA-Diamond（47.87，同级最高 60.10）上落后于 7–8B 同级模型。

# Q4 相关工作与关键人物

* **架构与优化器：** 门控滑动窗口注意力（Qiu 等，2025），采用 Gemma 3 的 5:1 局部/全局比例；GQA、RMSNorm、SwiGLU、部分 RoPE、QK-norm；Muon（Jordan 等，2024；Liu 等，2025）配合混合 FP8 和 TWEO 离群值正则化（Liang 等，2025）。架构研究还对比了 MLA 与 GDN 线性注意力混合方案。
* **智能体中期训练：** 沿用*智能体持续预训练*（Su 等，2025）的做法，把轨迹重构为 MDP 式、以状态为条件的下一动作预测。[Agent Lightning](../papers/2508.03680.md) 在强化学习侧使用了同样的 MDP 框架。
* **后训练：** GRPO，配 DAPO 式动态采样与超长处理（Yu 等，2025）；SFT 的工具 schema 采用 GLM-5.1 结构化工具格式。
* **基线：**
  * 7–8B 推理模型：DeepSeek-R1-0528-Qwen3-8B、MiniCPM4.1-8B、Qwen3-8B、Olmo-3-7B-Think、MiMo-7B-RL、OpenThinker3-7B；
  * 网页研究：WebDancer-32B、Qwen3-235B-A22B、Kimi-K2、DeepSeek-R1、QwQ-32B、GPT-4o、GPT-5、Claude 4 Sonnet；
  * 二进制搜索：DeepSeek-V4 Flash、Qwen3.5-397B-A17B、GLM-5.1、Kimi-K2、DeepSeek-R1、GPT-4o、Qwen3-8B。
* **关键人物：** 中关村学院与中关村人工智能研究院（HF 组织 ZGCAGI）。Jiyan He 为项目负责人；Tie-Yan Liu、Shuxin Zheng、Bin Shao 在贡献者之列。可能的批评者有两类：被比较的 7–8B 开放模型团队（Olmo、MiMo、MiniCPM、Qwen）；以及搜索智能体团队，因为大多数网页基线数字是从其他报告中照搬的。

# Q5 关键解法思路

一个效率优先、完全开放的全栈配方，围绕"思考 + 搜寻"组织：

* **混合注意力：** 27 层门控 SWA（128 token 窗口）加 5 层全局层（第 6、12、18、24、30 层）。每 token 的 KV 缓存从 128 KiB 降到 20 KiB；在 256K 时为 32.0 GiB → 5.0 GiB（6.4 倍）。吞吐提升从 4K 时的 1.13 倍增长到 256K 时的 3.94 倍。在 10B token、4K 序列的对比中，SWA 5:1 与全注意力尾部损失持平（1.93），吞吐最高（9,566 token/s/GPU）。
* **系统协同设计：** FP8 + Muon + TWEO，在 16K 下相对 AdamW/BF16 获得约 4.2 倍预训练 time-to-loss 加速。
* **课程式中期训练：** 上下文按 16K → 64K → 256K 扩展，引言将这一课程概括为 600B token。中期训练保持全序列因果语言建模，同时加入推理、指令和智能体数据。智能体轨迹被转为 MDP 式下一动作样本，软件工程轨迹经过执行过滤。在最终损失上，分阶段路线（10B@64K + 20B@256K）优于直接 30B@256K。
* **schema 对齐的智能体 SFT：**
  * 数据包括 20,217 条深度研究轨迹（搜索/访问工具）、30,014 条有执行依据的和 30,000 条无执行的软件工程轨迹，以及终端轨迹。
  * 工具调用校验参数结构、调用/观测配对和唯一 ID。
  * 通用与智能体数据交错的联合训练优于先后顺序训练。
  * 只对 assistant 部分计损失；每条轨迹都有对齐的思考与不思考两种形式。
  * 分层过滤剪掉约 50% 的原始通用 SFT 候选，总体上优于未筛选语料。
* **AI 原生研发：**
  * 由研究者指挥的智能体负责数据清洗、集群运维（通过共同开发的技能包）、针对 I/O 性能的自动研究，以及评测；
  * ACE 诊断套件含 2,503 个探针、183 项能力，约 2–3 分钟跑完；
  * 会议智能体 ZGent 把讨论转成派发出去的任务。

# Q6 实验设计

* **非智能体评测：** 20 个基准（数学与抽象推理、代码、知识、指令遵循），温度 1.0、262,144 token 预算下 32 次运行的平均 pass@1；部分基线单元格为 4 次平均或单次运行（第 5.1 节）。
* **网页深度研究：** 启用思考的 ReAct，最多 64 步搜索与阅读，使用 Serper/Jina 搜索和 Jina Reader。网页由 ZGCM-1 自身以不思考模式做摘要，答案由 Qwen3-30B-A3B-Instruct-2507 评判（附录 11.1）。*除 WebDancer 外，基线取自公开报告，并未在本框架中重跑。*
* **二进制函数搜索（新基准）：** 给定行为描述，通过 Ghidra 工具接口在剥离符号的 ELF 二进制中找到目标函数的精确入口地址。共 50 题，取自 10 个留出项目各 5 题（tmux、tree、GNU Wget2、XZ Utils、YAJL、zlib、libuv、libgit2、nm、Lua），用从未剥离二进制构造的隐藏预言机核对。所有基线都在同一框架中重跑。
* **附录诊断：** SWE-bench Verified Mini50（mini-SWE-agent v2，250 步）和 Terminal-Bench 2.0（89 题，64 步）。
* **配方消融：** 注意力调度、上下文路线、SFT 过滤强度、联合与顺序智能体 SFT、思考/不思考迁移（第 10.4 节，本次未细读）。
* **AI4AI 自主度：** 九位核心贡献者在 L1–L5 量表上为 11 类研发任务打分，共 99 个评分。

# Q8 证据质量

* **支撑充分的：**
  * 同一协议下的 7–8B 数学对比，均为 32 次平均：AIME 2026 75.00（表中最佳），HMMT 2025 70.42 与 HMMT 2026 59.48（均为最佳），MATH-500 97.13。
  * 二进制函数搜索：同一框架、精确地址预言机、留出项目。ZGCM-1-7B 得分 31/50 = 62%；Qwen3-8B 为 12%，GLM-5.1 为 66%，DeepSeek-V4 Flash 与 Qwen3.5-397B 为 76%。
  * 注意力与 KV 缓存的效率数字是直接测量值。
* **比论文表述弱的：**
  * *网页对比并非同条件。* 除 WebDancer 外，基线数字来自其他报告，框架、搜索提供商、日期和评审都不同；ZGCM-1 则在自己的框架里由 Qwen3-30B-A3B 评判。附录 11.1 自己也写道，结果"取决于搜索日期与可用性、提供商行为、网页抽取、摘要、评审设置和重试策略"。因此 BrowseComp 上 19.43 对 Claude 4 Sonnet 12.20、对 Qwen3-235B 2.30 的差距，混合了模型效应和框架效应。
  * *"与 GLM-5.1 相当"仅基于二进制函数搜索*，GLM-5.1 不在网页表格中。
  * *检查点不一致。* 论文描述了强化学习阶段，但报告数字来自 256K SFT 检查点，因此未显示强化学习对标题结果的贡献。
  * *广度参差。* 在 MMLU、GPQA-Diamond、LiveCodeBench v6、IFEval（75.42，最佳为 88.20）和 MBPP+ 上落后于同级模型。附录诊断中 SWE-bench Verified Mini50 仅解决 2/50（4.0%），Terminal-Bench 2.0 仅解决 2/89（2.25%），局限性一节承认这些结果"有限"。
  * *AI4AI 自主度*是团队贡献者在序数量表上的自评，论文自己称之为"贡献者判断，而非标准化测量"。
* **本次未核实：** 摘要宣称的"八条可操作的经验发现"在检索到的 HTML 文本中没有以带标签的列表出现，本笔记未逐条列出。

# Q9 贡献

* 一个真正开放、带分阶段产物的 7B 推理加智能体模型，使得研究智能体能力如何在预训练、中期训练和 SFT 中出现成为可能，这是只开放权重的发布做不到的。
* 证据表明：用 schema 对齐的智能体数据训练的 7B 模型，可以在结构化工具任务上具有竞争力（报告的网页研究，以及受控框架下的二进制函数定位），但在开放式代码仓库和终端工作上仍然很弱。这为"小模型智能体当前在哪里可行"画出了有用的地图。
* 可复用的工程结论：5:1 门控 SWA 的 KV/吞吐权衡、分阶段长上下文路线、联合而非顺序的智能体 SFT、以及对 schema 不匹配的敏感性。
* 一个更难被污染的新智能体任务（二进制函数搜索），以及一份早期、坦诚的 AI 辅助模型开发逐任务自主度画像：运维类任务评为 L4，架构与算法设计评为 L2。

* **报告强化学习检查点，并直接消融智能体 MDP 中期训练**（有/无），分别看网页与二进制任务。正文中这两项对智能体结果的贡献都没有被单独检验。
* **交互式智能体强化学习：** 作者自己列出的未来方向是从 SFT 和结果奖励强化学习，转向在终端、网页、编译器沙箱中的多轮强化学习。这是改善 2–4% SWE-bench/Terminal-Bench 成绩最直接的抓手。
