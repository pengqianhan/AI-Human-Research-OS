# Q1 问题定义

* **输入（X）：** 一个已在源设置（策略模型 M_S、基准 X_S）中经递归自我改进（RSI）演化出的 harness H_S，以及随之带入的优化记录；目标设置要么换基准（跨数据集，策略不变），要么换策略模型（跨模型，基准与划分不变），但 harness 接口仍可执行。
* **输出（Y）：** 在目标设置中再经 N 轮"提议者-选择者"优化后的 harness，在目标的留出集上计分。
* **约束：** 只有演化集反馈能到达提议者、选择者或记忆；策略权重冻结；各条件的轮数（N = 10）与每轮候选数（k = 5）一致。

# Q2 问题新颖性

Harness RSI 方法（Meta-Harness、Agentic Harness Engineering、RRSI）都在固定模型与基准内优化，迁移研究则问一个做好的 harness 换个地方是否还有用。本文关注两者之间的情形：变化发生后*继续*优化，继承来的修改可能要保留、修订或删除。已有系统保存候选档案、编辑历史、改进库（Harness²）或按问题分组的 harness 库（HarnessBank）；SIM 的特别之处在于组合：按问题记录每次尝试的理由、事先登记的"预计修好哪些任务"、实际结果（包括退化）和出处，并由提议者和选择者完整读取。

# Q3 科学假设

只看演化后的 harness，无法知道每处修改为何而做、表现如何。把这些证据带进目标优化，优化器就能判断哪些继承机制仍然适用；因此从同一 harness 出发，带完整记录的继续优化会比无记录或只带诊断的结果更好。

# Q4 相关工作与关键人物

* **Harness RSI：** Meta-Harness（本文沿用其问题形式化）、Agentic Harness Engineering（其最小编码种子）、RRSI（正则化搜索；本文采用其工作空间与工程环境、种子和评分接口）、自修改智能体、SIA（harness 加权重更新）。
* **迁移与继续优化：** Harness²（跨基准复用改进库）、HarnessBank、Meta-Skill、Meta2、Continual Harness、Adaptive Auto-Harness、EvoHarnessBench；自演化智能体的保持与干扰问题。
* **基准：** Terminal-Bench 2.1 与 4、Meta-Harness 的在线文本分类环境、Harvey LAB、JobBench、GDPval、APEX-Agents、EngDesign、Frontier-Eng。
* **关键人物：** Xin Yu（宾州州立大学，Google 实习）、Fei Xia、Ting Yu 等，来自 Google Cloud AI 与 Google DeepMind；Lingzhou Xue（宾州州立大学）。可能的批评者：RRSI 与 Harness² 的作者，他们也保存优化历史，可能认为收益来自更多上下文而非其结构。

# Q5 核心方法

1. **按 harness 问题组织条目：** 对一个根因假设 c_i（如"过早结束"），条目保存按顺序排列的尝试，每次包含修改及理由、预测与实际的任务结果、出处（领域、基准、策略、轮次）。预测在评估前写下，评估后核对。
2. **提议者与选择者都读：** 完整记忆放进提议者的系统提示，并由选择者读取，不做检索也不截断。每个提议要么引用已有根因，要么命名新根因。
3. **只追加的更新：** 选择后只记录被选中的候选，即使它造成退化或没修好预测的任务也照实记录；根因文本相同的条目合并而不丢历史。
4. **四个条件：** Cold Start（种子 harness，无记忆）、Harness Transfer（H_S，无记忆）、Problem-Only Memory（H_S，仅根因）、Full SIM（H_S，完整记录）。三个迁移条件共享 H_S，因此 Harness Transfer 是检验记忆作用的直接对照。

# Q6 实验设计

* **领域（源到目标）：** 编码：Terminal-Bench 2.1 到 Terminal-Bench 4（种子为最小 AHE 和 Terminus-2）。文本分类：Meta-Harness 环境中从 3 个源数据集到 8 个留出数据集（种子 NoMemory、FewShotAll）。智能体工作空间：Harvey LAB 到 JobBench、GDPval、APEX-Agents 的等权平均（Gemini 3.8 Flash 作评审）。工程设计：EngDesign 到 Frontier-Eng。后两者的种子是通过 MCP 网关的 ReAct。
* **划分：** 均匀随机分成演化与留出两半；例如 TB4 有 33 个留出任务（165 次 rollout），Frontier-Eng 有 23 个（115 次）。每个任务 5 次 rollout。
* **模型：** 跨数据集：两阶段策略都是 Gemini 3.8 Flash，它也担任提议者与选择者。跨模型：源 RSI 以 Claude Opus 5.5 为策略，之后在同一基准与划分上换成 Gemini 3.8 Flash。
* **附加研究：** TB2.1 上的代际链（Gemini 2.5 Flash、3.5 Flash、3.8 Flash、4 Argon）；文本分类上让一个 harness 同时服务 Grok 4.20 Reasoning、Claude Opus 5.5 与 Gemini 3.8 Flash；十次独立的 Terminus-2 源运行，每次在 TB4 上分别带与不带 SIM 继续优化。
* **报告方式：** 除成对编码研究外，每个条件只是一次完整 RSI 运行；五次 rollout 估计的是执行噪声，而非优化方差（原文说明）。

# Q8 证据质量

**跨数据集（表 5，目标留出集，目标 RSI 前→后）。**

| 编码 / AHE | 16.36 → 19.39 | 18.18 → 20.61 | 18.18 → 18.79 | 18.18 → 24.85 |
| 编码 / Terminus-2 | 18.18 → 19.39 | 19.39 → 19.39 | 19.39 → 20.61 | 19.39 → 21.82 |
| 文本分类 / NoMemory | 68.60 → 72.00 | 71.40 → 71.00 | 71.40 → 73.40 | 71.40 → 73.60 |
| 文本分类 / FewShotAll | 75.72 → 75.92 | 72.92 → 74.12 | 72.92 → 75.52 | 72.92 → 77.92 |
| 工作空间 / ReAct | 73.89 → 82.98 | 74.93 → 85.07 | 74.93 → 85.54 | 74.93 → 87.89 |
| 工程 / ReAct | 39.13 → 40.87 | 39.13 → 42.61 | 39.13 → 42.61 | 39.13 → 46.96 |

Full SIM 在全部六个设置中最终最高，比 Harness Transfer 高 2.43 到 4.35 分，比 Problem-Only Memory 高 0.20 到 6.06 分；Problem-Only 相对 Harness Transfer 在低 1.82 到高 2.40 之间。FewShotAll 演化出的 harness 起点低于种子（72.92 对 75.72），只带 harness 的继续优化最终仍低于 Cold Start。

**跨模型，Opus 5.5 到 Gemini 3.8 Flash（表 6）：** Opus 演化的 harness 在四个领域起点都低于 Gemini 的种子（差 0.60 到 5.48 分）。Full SIM 处处最高，比 Harness Transfer 高 3.60 到 11.33 分：编码 21.82 对 18.18，文本分类 83.80 对 80.20，工作空间 84.75 对 73.42（都从 68.41 出发），工程 50.43 对 42.61。Harness Transfer 在三个领域仍低于 Cold Start。

**成对编码研究（表 3）：** 十次 Terminus-2 源运行，各自在 TB4 上带与不带 SIM 继续优化十轮：SIM 在 10 对中 9 对更高，从共同起点 18.36 出发，平均 21.70 对 19.33，平均差 2.36（95% 置信区间 1.05 到 3.68；配对 t(9) = 4.06，p = 0.003；符号秩检验 p = 0.006；d_z = 1.28）。

**其他研究：** 代际链（表 1）：CRSI 在 Gemini 3.5 Flash（76.8 对 73.3）和 3.8 Flash（90.5 对 88.9）上胜过从头 RSI，在 4 Argon 上没有（94.8 对 95.6）。共享 harness（表 2）：统一合成在留出集上 75.24，分模型 harness 75.20，共享种子 73.28；顺序 CRSI 74.20。源任务保持（AHE）：Full SIM 在 TB2.1 的 225 次成功 rollout 中丢掉 3 次，Problem-Only 4 次，Harness Transfer 6 次。案例研究追踪一个继承的完成门控：SIM 保留它并加入目标检查（可行与最优之分），无记忆的运行则把它收紧，并两次修复死锁。

**证据的局限：**

* 编码以外，每个单元格都只有一次 RSI 运行（原文说明）；"六加四个设置 Full SIM 全胜"的模式一致，但各设置的差距没有优化方差估计。
* 编码差距以 rollout 计很小：TB4 留出集 165 次 rollout，一次 rollout 等于 0.61 分，成对平均 2.36 约为四次 rollout；表 3 每个分数都是 165 次中成功次数的整数比。Frontier-Eng 上 4.35 分的跨数据集差距是 115 次中的 5 次（读者计算）。
* Full SIM 给优化器的上下文也比 Harness Transfer 多；Problem-Only Memory 部分控制了这一点，但条件中没有等长的非结构化日志（如 Harness² 或自由文本笔记）（读者观察）。
* 主比较中 Gemini 3.8 Flash 同时是策略、提议者、选择者和工作空间评审，工作空间分数与被评智能体共用同一模型（读者观察；伦理部分提到评审偏差）。
* 代际链只报告一位小数且无方差；4 Argon 的反转说明收益并非随代际单调。

# Q9 贡献

1. 提出 CRSI 设置，含跨数据集与跨模型两种变体，现有 harness-RSI 方法可直接使用，无需改动其提议、评估与选择流程。
2. 自我改进记忆：按问题组织的编辑、理由、事先登记的预测、实际结果与出处记录，同时影响提议与选择。
3. 四个领域的同起点证据、带显著性检验的十对编码研究，以及继承修改如何被复用或修订的案例。

# Q10 后续方向

* **原文提出：** 在编码以外做更多重复运行；更长的转换链；调整规划、token 分配与工具接口；没有兼容 harness 接口的设置。
* **等长对照：** 用同样大小的非结构化日志与 SIM 比较，分离"结构"与"更多历史"的作用（读者建议）。
* **记忆增长：** 所有条目不经检索全部读入；经过多次转换后记录会超出提示长度，如何压缩而不丢掉"预测对实际"的证据仍待解决。
* **跨家族评审：** 用 Gemini 家族以外的评审重新给工作空间结果打分。
