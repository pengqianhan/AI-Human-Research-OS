# Q1 问题定义

* **输入（X）：** 一张室内场景的 RGB 照片，可以是合成图，也可以是杂乱的真实照片。
* **输出（Y）：** 一个组合式 3D 场景：房间几何（墙、地板、天花板、开口）加一组单独建网格、带纹理的物体，每个物体有位置、统一缩放、朝向（yaw）和 PBR 材质参数；同时恢复发光光源和一个标定好的相机，使渲染结果与输入视角吻合。
* **核心问题：** 单视角场景重建是病态问题：遮挡严重，照片不提供显式的度量尺度和物体间关系。论文把现有方法分为两派：几何驱动的流水线（分割、重建、再把物体对齐到估计的深度或点云）会弄错位姿，也处理不好小物体和被遮挡物体；VLM 驱动的流水线能把握“靠墙”“放在上面”这类关系，但无法做精确的数值推理，渲染结果与输入偏差明显。
* **约束：** 不训练或微调任何组件，只组合现成的基础模型；不需要逐场景人工干预。

# Q2 问题新颖性

不是新问题。单图组合式场景重建已有 Gen3DSR、CAST、3D-RE-GEN、ZeroScene、MIDI、SceneGen 等工作，以及 VLM 智能体方法（Holodeck、SAGE、VIGA，以及文本条件的 SceneSmith）。本文的贡献是一种新的*组合*：由 VLM 按显式的分层顺序规划并放置物体，每次放置后再用稠密几何证据（轮廓和点云）校正，并在每个阶段后由 VLM 检查。作者认为这很重要，因为单靠任何一派都无法同时做到语义正确（朝向、配对、支撑）和像素级、度量级的对齐。

# Q3 科学假设

如果先由 VLM 确定一个度量尺度的房间坐标系和相机，再按“新放的物体不会被已放物体遮挡”的顺序放置物体（先墙面物体，再从最深的墙角向外放家具，最后把装饰放到其承载物上），并用轮廓和深度证据校正每次放置、每个阶段后渲染并与输入比对，那么重建场景应在语义相似度（N-CLIP）、像素误差和 3D 几何上同时优于纯几何和纯 VLM 流水线；去掉其中任何一步都应变差。

# Q4 相关工作与关键人物

* **图像到 3D 物体生成：** 3DShape2VecSet、CLAY、TRELLIS/TRELLIS.2、Hunyuan3D 2（本文使用）、TripoSG、Direct3D-S2、SAM 3D。
* **几何驱动的场景重建：** Gen3DSR（分而治之加 SDS）、ZeroScene（联合 2D/3D 位姿损失）、CAST（GPT 场景解析加 SDF 物理校正）、3D-RE-GEN（4 自由度可微地平面对齐），以及前馈式场景模型（Coherent 3D Scene Diffusion、MIDI、SceneGen）；点云来自 VGGT。
* **智能体式 3D 场景生成：** SceneSmith（文本条件的分层放置顺序，HARMONY 借用了其“墙 → 家具 → 装饰”层级）、Holodeck/Holodeck 2.0（VLM 约束加布局求解器）、SAGE、VIGA（渲染并比对的 Blender 智能体）、Spatially-Contextualized VLMs（VLM 加 Fast3R 点云）。
* **关键人物：** 宾夕法尼亚大学 Lingjie Liu 团队（Shufan Sun 与 Chen Wang 为共同一作），以及 Jiatao Gu；致谢中感谢 Apple 的支持。可能的批评者：VIGA 与 CAST 的作者，以及会要求位姿级指标而非渲染相似度的 3D 视觉研究者。

# Q5 关键解法思路

* **先定度量房间和相机。** VLM 估计房间尺寸（例如卧室 3×4×3 米），选最深的可见墙角作为锚点，并标注可见的墙面。VGGT 点云给出曼哈顿坐标系（对法向做 SVD 聚类）和对应墙角。一个闭式相似变换（旋转来自曼哈顿轴，尺度为 VLM 房高除以 VGGT 墙角棱长，平移把地面角点钉到规范位置）把 VGGT 相机放入规范房间坐标系。
* **逐物体资产。** 每一层由 VLM 列出物体及数量；开放词汇检测器与分割器给出掩码；图像编辑模型根据 VLM 描述对被遮挡物体做无模态补全，VLM 检查补全结果；Hunyuan3D-2 生成网格，经 PCA 规范化后，由 VLM 从多视角渲染中标注物体正面朝向。
* **分层、深度优先的放置。** 放置顺序为墙面物体 → 家具/吊顶物体 → 装饰。家具从锚点墙角向外放置，因此从相机看，每个已放物体都位于下一个物体之后，新物体总能无遮挡地被看到。VLM 写出关系提示（“沙发靠背贴左墙”“椅子朝向茶几”），根据规范正面设定朝向，并做小幅视觉旋转修正。当两个相似的承载物容易混淆时，用包围盒重叠检查纠正装饰物的归属。
* **几何校正。** 轮廓的水平偏移给出横向平移；轮廓宽度给出缩放与深度之比 s/Z；对 VGGT 点云与渲染点云的物体前表面做稳健（中位数/MAD）比较得到 Z，从而确定度量尺度。碰撞按两种分离移动中较小的一种处理，若持续存在则交给 VLM 重新排序。
* **反思循环与光照。** 每个阶段后渲染场景，由 VLM 与照片比对：尺度、朝向、错放或缺失的物体，以及成组物体（如成对椅子）尺寸一致；最后清点并补齐缺失实例。VLM 还分配 PBR 材质、估计光源，并通过比较 Blender Cycles 渲染与输入来细化。

# Q6 实验设计

* **数据：** Front100（100 张带真值网格的 3D-FRONT 渲染图）和 HARMONY30（30 张无版权的真实照片）；完整流水线也在 HARMONY300 上运行。
* **指标：** 从输入视角渲染后计算 N-CLIP（1 − CLIP-ViT-B/32 余弦相似度）、光度 MSE（PL）和 LPIPS；Front100 上另算 Chamfer 距离和阈值 0.1/0.01/0.001 的 F 分数。用户研究：16 名志愿者在 20 个场景上对六种方法排序（平均名次、Top-1、Top-2）。
* **基线：** Gen3DSR（默认配置）、3D-RE-GEN（改用 gpt-image-2 补全）、CAST（非官方实现）、SAM3D*（使用 HARMONY 自己的掩码）、VIGA（使用 SAM3D 和 GPT-5.5），以及作为定性和定量参照的 GPT-6 Astra。CAST 与 SAM3D 在感知指标上使用 HARMONY 的背景。
* **消融：** 八个变体，分别去掉 VGGT 校正、深度优先遍历、VLM 放置推理、放置校正、反馈循环、放置顺序和相机标定。
* **失败分析：** VLM 与检测器词表不一致的少见物体类型；离相机很近、大部分被裁切的物体。

# Q7 数据集与代码

发布 HARMONY300（100 个简单的 3D-FRONT 场景、100 个中等难度真实照片、100 个复杂真实照片）。每个场景含参考照片、重建场景、光照渲染、标定相机、分割色图，以及逐物体 JSON（阶段、类型、尺寸、位置、贴墙关系，以及朝向/在前方/在上方/成组等关系）。许可为 CC-BY-NC-4.0；来源为 Pexels、Unsplash、3D-FRONT 和 3D-FUTURE。代码见 [ShufanSun/harmony-release](https://github.com/ShufanSun/harmony-release)。论文表 4 列出的基础模型包括作为 VLM 的 gpt-5.5、用于编辑的 Gemini 图像模型、VGGT 和 Hunyuan3D-2。在 L40 GPU 上每个场景耗时 20-90 分钟，平均每放置一个物体调用 3.4 次 VLM。

# Q8 证据质量

* **有支撑的：**
  * *Front100（表 1）：* HARMONY 在所有指标上最好：N-CLIP 0.092、PL 0.041、CD 0.049、F@0.1/0.01/0.001 为 89.82 / 19.47 / 0.130。各指标上最强的基线为 CAST（CD 0.052，F@0.1 85.70）和 SAM3D*（F@0.01 14.44）。GPT-6 Astra 的 N-CLIP 接近（0.095），但几何更差（CD 0.061，F@0.1 77.44）。
  * *真实照片（表 2）：* HARMONY 的 N-CLIP 0.112、PL 0.045，对比 Astra 的 0.127 / 0.047 和 3D-ReGen 的 N-CLIP 0.154。用户研究中平均名次 1.54 ± 0.93，Top-1 占 67.0%，Top-2 占 86.0%；次好的 SAM3D* 平均名次为 3.26。
  * *消融（表 3）：* 去掉相机标定伤害最大（N-CLIP 0.1034 → 0.1381，PL 0.0462 → 0.0596），其次是反馈循环（N-CLIP 0.1184）；每种去除在两个指标上都比完整系统差。
* **比表面看起来弱的：**
  * *消融效应小。* 除标定和反馈循环外，去掉其他组件只让 N-CLIP 变化 0.001-0.005（例如去掉深度优先遍历为 0.1045，完整系统 0.1034），且未报告方差或种子。消融中完整系统的 N-CLIP（0.1034）既不等于表 1（0.092）也不等于表 2（0.112），正文未说明消融用的是哪些场景。
  * *部分基线的设置对 HARMONY 有利。* SAM3D* 用的是 HARMONY 自己的掩码，CAST 和 SAM3D 在感知指标上用的是 HARMONY 的背景，CAST 是非官方重实现，VIGA 与 3D-RE-GEN 换了模型运行。
  * *渲染相似度指标*（输入视角下的 N-CLIP、PL）奖励的是与唯一可见视角的匹配，而该方法的渲染-比对循环恰恰在优化这个视角；只有 Front100 检查了 3D 几何。
  * *用户研究规模：* 16 名无报酬志愿者、20 个场景，且只选了每种方法都成功渲染的场景。
  * *“智能体”部分是固定流水线。* VLM 在人工设计的阶段顺序中做决策和评判，没有开放式的工具选择或学习到的策略。这是设计选择而非缺陷，但限制了结果对一般智能体的说明力。

# Q9 贡献

* 一种闭式的、以 VLM 为锚的相机与房间标定，从单张照片确定度量尺度。
* 带深度优先家具遍历的分层放置顺序，让 VLM 每次看到的新物体都不被遮挡；外加逐阶段的渲染-比对反思检查。
* VLM 与几何之间明确的分工：VLM 负责关系、朝向、支撑和数量；几何负责由轮廓定横向位置、由点云定深度，并由两者共同定尺度。
* HARMONY300：300 个重建场景的数据集，附逐物体关系标注。

# Q10 下一步

* **多视角输入与可动（铰接）物体**是作者自述的未来工作。
* **位姿级评测：** 在 3D-FRONT 上报告逐物体的位置、朝向误差和关系准确率，而不只是渲染相似度与 Chamfer 距离。
* **更扎实的消融：** 在与主表相同的评测划分上，给出跨种子或跨场景的方差。
* **成本：** 每个物体 3.4 次 VLM 调用、每个场景最多 90 分钟。哪些阶段能用更小或微调过的 VLM 完成？
* **物理有效性（读者笔记）：** 与 [SceneMosaic](../papers/2609.05594.md) 和 [Code as Worlds](../papers/2608.27549.md) 不同，HARMONY 唯一的物理检查是碰撞消解，没有仿真。加一步“放进仿真器看是否稳定”，可以检验与渲染吻合的场景是否在物理上也成立。
* **训练信号（读者笔记）：** HARMONY300 的逐物体关系 JSON 可以作为已训练场景智能体的监督或验证目标，例如目前用 MLLM 评分细则给世界打分的 [VibeWorlding](../papers/2608.15265.md)。
