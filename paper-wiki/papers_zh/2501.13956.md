> 论文:**Zep: A Temporal Knowledge Graph Architecture for Agent Memory**
> 论文链接:<https://arxiv.org/abs/2501.13956>
> 机构:Zep AI,2025 年 1 月 20 日提交

# Q1 问题定义

* **输入 `X`**:通过 Zep API 摄取的原始数据"episode"流——就本文实验而言,具体是带有参考时间戳 t_ref 和说话者/行为者的聊天消息——以及查询时的自然语言文本查询 α。
* **输出 `Y`**:摄取阶段,产出一个动态维护的双时序知识图谱 𝒢=(𝒩,ℰ,φ),包含三层级联子图(episode 子图、语义实体子图、社区子图);检索阶段,产出一个格式化的文本上下文字符串 β = f(α) = χ(ρ(φ(α))),其中包含 LLM agent 回答 α 所需的事实以及实体/社区摘要。
* **核心问题**:LLM agent 需要来自对话和业务数据的持续演变的记忆,而不是传统 RAG 所假设的、基本静态的语料库;完整的对话历史和业务数据集无法装进 LLM 的上下文窗口,因此 agent 记忆需要自己的架构,而不能被当作文档检索的一个特例来处理。
* **范围**:论文特别聚焦于消息类型的 episode(对话记忆),尽管 Zep 的 episode 抽象同时支持文本和 JSON 类型输入;文本/JSON episode 的处理以及 episode 边的引用/溯源机制被描述为未来工作,本文并未评测。社区子图的检索方法和系统对业务数据的综合能力同样未在本文的两个实验中直接评测。

# Q2 问题的新颖性

给 LLM agent 加记忆并非新想法,此前已有 MemGPT(受操作系统启发,在受限上下文窗口和外部存储之间分页)和知识图谱增强的 RAG 一般性工作(GraphRAG、AriGraph)探索过。本文自陈的新颖点是 Graphiti 的双时序模型——同时追踪一条事件时间线 T(某个事实在现实世界中何时为真)和一条事务时间线 T′(Zep 的数据摄取何时记录或使某个事实失效)——作者将其描述为"基于 LLM 的知识图谱构建中的一项新进展",使图谱能够以非有损的方式持续更新,表示一个不断演化的世界,而非一个静态的文档索引。三层子图结构(episode/语义实体/社区)本身明确取材于已有工作(episodic/semantic 区分借鉴 AriGraph,社区摘要借鉴 GraphRAG),并非独立的新颖点;新颖性主张主要落在其上叠加的时序抽取与边失效机制上。

# Q3 科学假设

如果把对话与业务数据摄取进一个动态的双时序知识图谱,该图谱(a)非有损地保留原始 episode 数据,(b)通过 LLM 驱动的去重来抽取和解析语义实体与事实,(c)同时用一条现实世界时间线和一条事务时间线追踪每个事实何时生效、何时失效,(d)通过一个"检索→重排→构建"三阶段流水线查询,该流水线结合了词法、语义和图遍历检索——那么,以此图谱作为记忆的 LLM agent,在需要跨会话综合、时序推理和长期上下文维护的问题上,将比使用完整对话上下文、会话摘要或 MemGPT 分页方案的 agent 回答得更准确、延迟更低,尤其是当对话长度超出上下文窗口舒适容纳范围时。

# Q4 相关工作与关键人物

* 直接与 MemGPT(DMR 基准的原始提出者,论文称其为该基准此前的最先进系统)以及作者自行实现的两个基线(完整对话上下文、会话摘要)对比。
* 其episode/语义双子图设计取材于 AriGraph 的 episodic-memory 知识图谱世界模型,社区检测与 map-reduce 式社区摘要取材于 GraphRAG(Edge et al.)——同时明确指出 Zep 的检索方法论(三种搜索函数加多种重排器)与 GraphRAG 的 map-reduce 检索方法有实质性不同。
* 将其广度优先图搜索置于 RAG 中此前对图遍历关注有限的背景下(AriGraph、Distill-SynthKG),并指出其社区名称关键词搜索与 LightRAG 的高层级关键词搜索是独立收敛得到的相似方案。
* 本知识库在本笔记出现之前已经有两篇后续记忆论文把 Zep 作为对比基线:[MemOS](2507.03724.md) 在共享的 GPT-4o-mini 骨干模型上直接复现了 Zep("时间感知的知识图谱记忆"),并报告在 LoCoMo/LongMemEval/PreFEval/PersonaMem 上全面胜出;[EverMemOS](2601.02163.md) 报告在 LoCoMo 上胜过 Zep(相对提升 7.0-9.2%)。[Mem0](2504.19413.md) 也将"Zep,一个商业记忆平台"列为其六类基线之一。本笔记是本知识库首次为 Zep 本身建立正式条目,在此之前 [Agent memory](../topics/agent-memory.md) 主题下只有与之对比的论文。
* 作者:来自 Zep AI 的 5 人团队(Preston Rasmussen、Pavlo Paliychuk、Travis Beauvais、Jack Ryan、Daniel Chalef),2025 年 1 月 20 日提交——在本知识库已收录的三篇记忆论文中,这是时间最早、且被另外两篇拿来当基线的一篇。

# Q5 核心解法

1. **具有三层级联子图的双时序知识图谱。** Episode 子图非有损地存储原始输入(消息/文本/JSON),并通过双向索引连接到派生实体以支持未来的引用/溯源;语义实体子图保存已解析的实体,以及在实体之间抽取出的事实(边);社区子图通过标签传播算法(而非 Leiden 算法,原因是标签传播支持增量式的单步动态扩展)将强连接的实体聚类为更高层级的摘要节点——新节点加入其邻居中占多数的社区——从而减少完整、昂贵的社区刷新频率。
2. **带反思与解析的实体与事实抽取。** 实体抽取使用当前消息加上最近 n=4 条消息作为上下文,自动将说话者抽取为实体,并采用受 Reflexion 启发的反思步骤降低幻觉;候选重复实体通过 1024 维余弦相似度嵌入检索和对名称/摘要的全文检索找到,再由一个 LLM 解析提示词将重复项合并为更新后的名称/摘要。同一套实体/事实流水线支持类似超边的多实体事实(同一事实可在多对实体之间被多次抽取)。
3. **时序抽取与边失效。** 每条事实的边存储四个时间戳:事务时间线 T′ 上的 t′created 和 t′expired(Zep 系统何时记录/使该事实失效),以及现实世界时间线 T 上的 t_valid 和 t_invalid(该事实实际何时为真)。新边会与语义相关的既有边由 LLM 进行比对;当发现时间上重叠的矛盾时,较旧的边会被失效(将其 t_invalid 设为新边的 t_valid),事务时间线始终优先采信新摄取的信息——从而使图谱能够表示一个演变中的世界,而不丢弃历史关系状态。
4. **三阶段、多方法检索流水线。** 搜索(φ)组合运行余弦语义相似度搜索、Okapi BM25 全文搜索和广度优先图遍历(可以最近的 episode 为种子,从而拉入最近提及的实体/关系),三者分别针对不同的相似性概念(词面、语义、图上下文/距离)。重排(ρ)支持 Reciprocal Rank Fusion、Maximal Marginal Relevance、一个基于图的 episode 提及频率重排器、一个基于图距离中心节点的重排器,以及一个交叉编码器 LLM 重排器(精度最高但成本也最高)。构建器(χ)将重排后的事实、实体摘要和社区摘要格式化为供 agent 使用的文本上下文字符串。

# Q6 实验设计

两个基准。**Deep Memory Retrieval(DMR)**,来自 MemGPT 论文:500 段多会话对话(每段 5 个会话,每会话最多 12 条消息),每段对话配一对问答用于记忆评测,由 LLM 评审对照标准答案打分。作者还自行实现了完整对话和会话摘要两个基线(MemGPT 自己报告的数字被直接引用,而非通过重新运行 MemGPT 独立验证)。**LongMemEval(LME)**,具体使用 LongMemEval_s 子集:更长、更贴近真实场景的对话,平均约 115,000 个 token,六种问题类型(单会话-用户、单会话-助手、单会话-偏好、多会话、知识更新、时序推理),用 GPT-4o 配合基准自带的针对每种问题类型的提示词进行评测。所用模型:BGE-m3 用于嵌入/重排;gpt-4o-mini-2024-07-18 用于图谱构建,并与 gpt-4o-2024-11-20 一起用于响应生成;另外在 DMR 上专门使用 gpt-4-turbo-2024-04-09,以便与 MemGPT 原始评测设置对齐。实验在 2024 年 12 月至 2025 年 1 月期间进行,作者从波士顿的一处住宅网络连接到部署在 AWS us-west-2 的 Zep 服务,作者指出这为评测引入了本地基线运行中不存在的额外网络延迟。

**DMR 结果:** 使用 gpt-4-turbo 时 Zep 达到 94.8%(对比 MemGPT 报告的 93.4%、完整对话基线 94.4%、会话摘要基线 78.6%、递归摘要基线 35.3%);使用 gpt-4o-mini 时 Zep 达到 98.2%(对比完整对话基线 98.0%、会话摘要基线 88.0%;由于 MemGPT 已发表的方法细节不足,作者未能在 gpt-4o-mini 下复现其数字)。论文自己明确指出这一优势并非 Zep 价值的有力证据:每段 DMR 对话仅 60 条消息,轻松装入现代上下文窗口,因此完整对话基线得分与 Zep 几乎持平并不令人意外;作者也独立批评了 DMR 的设计缺陷(仅有单轮事实检索型问题、部分问题表述含糊、对真实企业场景代表性不足)。**LongMemEval 结果:** 相较基线(检索到的正文中未完全说明具体是哪个基线配置),Zep 在 gpt-4o-mini 下准确率提升 15.2%,在 gpt-4o 下提升 18.5%,增益集中在单会话-偏好、多会话和时序推理三类问题,配合 gpt-4o 时在知识更新类问题上也有提升;由于提示词长度缩短,延迟相较基线降低约 90%。有一处报告的性能下降:单会话-助手类问题出现回退(gpt-4o 下 -17.7%,gpt-4o-mini 下 -9.06%),作者将其标记为需要进一步研究而未给出解释。论文曾尝试在 LongMemEval 上直接对比 MemGPT 与 Zep 但未成功:MemGPT 不支持直接摄取既有消息历史,作者采用的将对话消息加入归档历史的变通方案未能产生成功的回答。

# Q7 数据与代码

使用了两个既有基准(DMR 来自 MemGPT 论文所用 Multi-Session Chat 派生子集;LongMemEval_s 来自 Wu et al.),而非引入新基准。Graphiti(底层时序知识图谱引擎)开源于 github.com/getzep/graphiti;Zep 本身在论文中被描述为一个商业化/生产环境的记忆层服务(getzep.com),而非完全开源的系统——本笔记无法从检索到的正文确认 Zep 在 Graphiti 之外的检索/重排栈开源到什么程度。论文表示实验用的 notebook 会通过作者的 GitHub 仓库公开;本笔记未独立核实其是否存在。

# Q8 证据质量

本笔记基于通过 `hf papers read` 检索到的 arXiv HTML 完整论文正文撰写(从引言到附录的图谱构建提示词及参考文献列表全部检索到),因此忠实度核对可以直接对照方法描述、两个实验的设置以及报告的数字,而非仅依赖摘要。论文对 DMR 作为记忆系统评测基准的薄弱证据价值,以及 LongMemEval 上未解释的单会话-助手回退问题都相当坦诚,这支持了把论文自身的头条数字视为善意呈现的判断。但需要注意:这是一篇由厂商撰写、关于该厂商自有商业产品的论文(全部五位作者均为 Zep AI 员工),DMR 对比部分沿用了 MemGPT 自述的数字而非独立重新运行的结果,而 LongMemEval 上作为对比基础的"基线"配置在检索到的正文中并未完全说明(本笔记无法从检索到的段落确认 15.2%/18.5% 这两个提升数字对照的确切基线设置)。本知识库中已收录的后续论文([MemOS](2507.03724.md)、[EverMemOS](2601.02163.md))独立复现并超越了 Zep,这是有用的交叉印证证据,但在本文发表时(2025 年 1 月,早于 MemOS/EverMemOS 2026 年才提交)作者尚无法获知。

# Q9 主要贡献

1. Graphiti,一个双时序(事件时间与事务时间)动态知识图谱引擎,能够非有损地整合非结构化对话数据与结构化业务数据,并支持事实失效而不删除历史——这是论文相较此前基于 LLM 的知识图谱构建工作所主张的核心新颖点。
2. Zep,一个建立在 Graphiti 之上的生产级记忆层服务,具有三层子图结构(episode/语义实体/社区),以及一个可配置的"检索→重排→构建"三阶段检索流水线,结合词法、语义和图遍历检索以及五种重排策略。
3. 报告在 DMR 上相较 MemGPT 达到当时最先进水平(gpt-4-turbo 下 94.8% 对 93.4%),并在更贴近现实场景的 LongMemEval_s 基准上相较未完全说明的基线取得显著准确率提升(最高 18.5%)和约 90% 的延迟降低——同时作者自己批评 DMR 本身是区分记忆系统能力的弱基准,并以此部分论证该领域需要更好的记忆评测基准。
