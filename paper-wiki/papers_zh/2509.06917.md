# Q1 问题定义

* **输入（X）：** 一篇研究论文的正文,加上其对应的公开代码仓库(源代码、教程/notebook、示例数据集、补充材料)。
* **输出（Y）：** 针对该论文构建、经过测试的模型上下文协议(Model Context Protocol,MCP)服务器——把论文的方法学贡献封装为可调用的**工具(Tools)**、静态**资源(Resources)**(论文正文、代码库、数据、图表)以及多步骤**提示词(Prompts)**(封装好的工作流)——任何兼容 MCP 的聊天智能体都能通过自然语言调用它,成为该论文专属的"论文智能体"。
* **核心问题：** 研究论文是被动的产物。要复用一篇论文的方法,读者通常需要找到代码仓库、安装依赖、配置环境,并理解 API 与参数语义——论文以 AlphaGenome 为例具体说明:在代码中使用该方法需要安装环境、导入多个模块、用 API 密钥创建客户端对象,并构造染色体/变异体输入对象。Paper2Agent 把"论文转智能体"这一过程自动化,以消除这一门槛,把论文变成一个可持续查询、且(论文认为)比人工复现更可靠的方法接口。
* **范围：** 论文在三篇方法学论文上做了演示——AlphaGenome(基因组变异效应预测)、TISSUE(不确定性感知的空间转录组学)、Scanpy(仅限其预处理/聚类工作流部分)——外加一个跨论文的"方法+数据"案例研究,把一个 AlphaGenome MCP 与一个 ADHD GWAS 发现型论文的 MCP 连接起来。论文没有报告在随机或大规模论文样本上的通用基准测试,所有证据均为案例研究性质。构建流水线专门基于 Claude Code 实现,且在每一项报告的评测中,下游聊天智能体也都是 Claude Code(`claude-sonnet-4-20250514`),尽管作者声明论文 MCP "可以灵活地与不同的聊天智能体集成"。

# Q2 问题新颖性

论文并不声称首创"从论文自动生成代码"(它把 Paper2Code [Seo et al.] 和 "From articles to code" [Movassaghi, Momenzadeh, Meyer] 列为最接近的已有工作),也不声称首创通用型科学 AI 智能体(Virtual Lab、Google 的 AI co-scientist、Sakana AI Scientist、FutureHouse 的 Robin、CellVoyager、Biomni)。其自陈的新颖之处更为具体:Paper2Agent 并非从论文文本生成代码,也不是构建一个开放式的发现型智能体,而是把某一篇具体论文转换为一个标准协议化(MCP)、经过验证、可复用的标准工具——并配有明确的可靠性机制(针对参考代码库自身报告的输出,先验证再"锁定"每一个工具),用以应对普通 LLM 代码生成所带有的"代码幻觉(code hallucination)"风险。

论文还把自己定位为"可执行论文(executable paper)"这一脉络的下一步——包括 Elsevier 的 Executable Paper Grand Challenge、以 Jupyter notebook 为载体的出版物,以及 Papers with Code 项目——论文认为这些努力提升了可复现性与可发现性,但仍然要求读者自己投入技术精力才能真正运行代码。Paper2Agent 自陈的新颖之处,是把这条脉络的产出从"可运行的产物"转变为"可自然语言交互、能自主执行"的实体。论文借此提出一个更进一步的论点:未来论文或许会像今天的"数据可用性(data availability)"与"代码可用性(code availability)"一样,新增一个标准化的"智能体可用性(agent availability)"章节。

# Q3 科学假设

如果一篇论文的方法学贡献 (a) 是从其代码库自身的教程中挖掘出来,而非从论文文字自由生成; (b) 被封装为单一用途、参数化的工具,并在"锁定"之前针对教程自身报告的数值与可视化输出进行了测试与验证; (c) 通过一个标准化协议(MCP)暴露给一个 LLM 聊天智能体,那么由此产生的论文智能体应当能高保真地复现论文自身的结果,能正确泛化到教程示例之外的新查询,并且比"直接给一个通用编程智能体原始仓库访问权限"或"使用一个通用生物医学智能体"更可靠、更高效。

论文最核心的量化证据来自 AlphaGenome 基准测试:AlphaGenome 智能体在教程衍生查询和留出的新查询上都达到 100%(15/15)的准确率,而"Claude + Repo"(直接把原始 AlphaGenome 仓库交给 Claude Code)分别为 60%/80%,Biomni 为 40%/60%,同时中位运行时间降低 1.8 至 4.6 倍。TISSUE 与 Scanpy 智能体则被报告为能在各自代码库示例之外的数据集上复现人类专家的流水线输出(Scanpy 对应三个外部 10x Genomics PBMC 数据集;TISSUE 对应一个 Zenodo 小鼠皮层空间数据集,并与一位人类研究者手动运行同一流水线的结果做了核对)。这些证据支持该假设在这三篇被演示论文上的成立,但并未在更大规模、随机抽样的论文集合上,或在基因组学/单细胞生物学之外的领域中得到检验。

# Q4 相关工作与关键人物

# Q5 关键解法思路

1. **两层架构。** *Paper2MCP* 从一篇论文及其代码库中提取信息,构建一个远程 MCP 服务器;一个*智能体层*把该 MCP 服务器包装为上下文提供者,使下游聊天智能体(例如 Claude Code)变成该论文专属的对话式智能体。由于 MCP 服务器是模块化的,多个论文 MCP 可以同时挂载到同一个聊天智能体上——这一点在 AlphaGenome + ADHD-GWAS 跨论文案例研究中被直接实践。
2. **每个 MCP 服务器的三类组件。** *工具(Tools)* 是封装某项方法学贡献的可执行函数(例如 AlphaGenome 的 `score_variant_effect()`、`visualize_variant_effects()`);*资源(Resources)* 是静态资产——论文正文、代码库、数据集、表格、图表——以标准化、可供智能体查询的格式存储;*提示词(Prompts)* 封装了直接从论文/代码库中推断出的多步骤工作流指令(例如 Scanpy 的质量控制→归一化→特征选择→降维→构图→聚类→细胞类型注释这一正确顺序的流水线),从而免去用户自己摸清或指定顺序的负担。
3. **构建过程本身就是一个多智能体流水线,基于 Claude Code 实现。** 一个编排(orchestrator)智能体协调四个专业化子智能体,贯穿六个步骤(Extended Methods 部分):
   - *environment-manager(环境管理器)* —— 配置一个干净、隔离、可复现的工作空间,安装并锁定依赖版本,使代码库能稳定运行。
   - *tutorial-scanner(教程扫描器)* —— 系统性地扫描代码库,区分真正的教程与其他文件,报告哪些值得转化为工具。
   - *tutorial-tool-extractor-implementor(教程工具提取与实现器)* —— 把选定的教程转化为干净的单一用途函数:参数化硬编码的取值、强制采用基于文件的输入、保存产物/图表,并返回一份标准化的结果摘要,目标是在忠实复现教程自身示例结果的同时,能泛化到教程示例数据之外。
   - *test-verifier-improver(测试-验证-改进器)* —— 仅用教程自身的示例生成测试(以确保覆盖完整、并忠实复现数值与可视化两方面的结果),运行测试、诊断失败原因,并在一个循环中反复修复;如果某个函数持续失败,会被剥离其 MCP 装饰器,不再纳入最终服务器,而不是带着未经验证的状态直接上线。
   六个流水线步骤依次为:(1) 定位并下载论文的官方代码库;(2) 环境搭建;(3) 教程发现;(4) 教程执行与审计(用教程自身的示例数据端到端运行,记录输入、输出、图表、运行时约束以及隐含假设);(5) 工具提取与实现;(6) MCP 服务器组装(工具+资源+提示词,配有清单、版本管理与基本安全默认值)。
4. **可靠性机制。** 每个工具都要先针对参考代码库自身在示例数据上报告的结果与图表进行验证,然后被"锁定"——这是一个明确针对 LLM "代码幻觉"问题的设计选择,也用来降低代码生成中的随机性。每个工具还嵌入了指向原始 GitHub 源码的可追溯链接,使"溯源到论文自身代码"这条链路端到端保留。
5. **远程部署。** 构建完成的 MCP 服务器被远程托管(例如托管在 Hugging Face Spaces 上),消除了终端用户本地依赖/环境配置的摩擦;任何兼容 MCP 的智能体都可以直接连接,无需本地安装。
6. **通过"数据智能体"扩展到数据/发现型论文。** 在 ADHD-GWAS 案例研究中,同一框架面向数据的路径解析了一篇数据论文的补充 Excel 表格,清洗数据,并将其转换为带有统一元数据的标准化 MCP 资源——从而让一个方法论文智能体(AlphaGenome)与一个数据论文智能体(ADHD GWAS)能够在同一个下游"AI 协作科学家"之下组合使用,而不要求一篇论文同时包含方法和自己的数据。

# Q6 实验设计

**AlphaGenome 基准测试(论文最量化的评测)。** 22 个 MCP 工具在一台个人笔记本电脑上、无需人工干预,约 3 小时内生成完毕。智能体在两组查询上接受评测:15 条直接从 AlphaGenome 教程中人工整理的查询(例如"用 ATAC-seq 预测为运动神经元细胞对变异 chr3:58394738:A>T 打分…"),以及 15 条刻意构造在论文与代码库之外的新查询(新的变异位点、替换类型、组织/细胞类型组合),用于检验泛化能力而非教程记忆。同样的查询集上还运行了两个基线:"Claude + Repo"(把原始 AlphaGenome 仓库的本地访问权限交给 Claude Code,并明确要求其编写并执行 Python 代码,而非依据文档作答)以及 Biomni(其基于 API 的通用生物医学智能体)。三者在适用之处均使用 `claude-sonnet-4-20250514` 作为底层 LLM,在一台 MacBook Air(M2)上以非交互方式运行(`claude --model ... --print --output-format json`)。评测流程为:(1) 通过人工整理并执行代码生成标准答案;(2) 记录每个智能体的回答及运行时间/成本;(3) 人工审阅并对照标准答案打分;(4) 汇总整个查询集上的准确率与运行时间。标准答案与打分均由构建被评测 AlphaGenome 智能体的同一团队完成(见 Q8)。

**GWAS 解读案例研究(AlphaGenome 智能体,单次示范性运行)。** 智能体被要求解读变异 chr1:109274968:G>T 为何与低密度脂蛋白胆固醇相关联——这正是 AlphaGenome 自身论文中讨论过的同一个位点。智能体构建并执行了一个多步骤计划(跨模态给变异打分、筛选与性状相关的组织、生成模态特异的可视化、汇总报告),使用了 `score_variant()`、`visualize_tf_binding()` 等工具,并通过迭代的观察与反馈不断完善其计划。

**TISSUE 智能体。** 生成了 6 个工具,覆盖空间基因表达预测、预测区间构建,以及不确定性感知的下游分析(假设检验、预测、降维)。可复现性的评估方式是定性比较:让智能体针对小鼠躯体感觉皮层空间转录组学数据(Zenodo 记录 8259942)中的 *Acta2* 基因构建预测区间,并与一位人类研究者手动运行同一 TISSUE 流水线(依据其 GitHub 教程)的输出做对照;论文在抓取到的正文中只是说二者"一致",并未给出量化的相似度指标。

**Scanpy 智能体。** 约 45 分钟内生成了 7 个工具,有意只覆盖 Scanpy 功能中"预处理与聚类"这一子集,而非整个软件包。编码正确流水线顺序的 MCP 提示词是通过向 Paper2Agent 本身发出如下提示引导生成的:"基于你已有的工具,构建一个 MCP 提示词,按正确顺序复现该教程。始终先检查数据,只有在遵循默认设置会产生错误结果时才偏离默认设置。"随后该智能体在三个不属于 Scanpy 代码库的公开 10x Genomics PBMC 数据集上运行,其输出(基因过滤、归一化、主成分分析、邻域图构建、聚类)被报告为与人类研究者运行结果一致,同样未给出量化的匹配阈值。

**跨论文 AI 协作科学家案例研究。** 在把 AlphaGenome 与 ADHD-GWAS(van der Laan et al., 2025,发表于 *Nature Genetics*)两个 MCP 都连接到 Claude Code 后,系统被要求提出 10 个结合两个 MCP 的、经打分的结构化研究问题(评分维度:新颖性、可行性、影响力、验证清晰度、资源契合度,各 0-5 分),并明确约束禁止捏造引用或输出。随后用户引导系统去追问其中一个假设(AlphaGenome 能在 ADHD 精细定位可信区间中优先识别因果变异),智能体执行的方式是先从 209 个精细定位候选变异中优先锁定单一变异,随后在两小时内自主把同一工作流扩展到全部 39 个 GWAS 位点,为每个位点生成一份 markdown 报告(补充表 1)。这是单次示范性运行,而非重复试验或基准化评测。

# Q7 数据集与代码

论文未发布新的持久化基准数据集;15+15 条 AlphaGenome 基准查询被描述为人工整理而成,并说明可在 Paper2Agent 的 GitHub 仓库中获取,但抓取到的正文并未将其呈现为一个单独版本化或授权发布的基准资产。使用到的外部数据集包括:三个 10x Genomics PBMC 单细胞 RNA-seq 数据集(`pbmc_1k_v2`、`pbmc_1k_v3`、`pbmc_1k_protein_v3`)、一个小鼠躯体感觉皮层空间转录组学数据集(Zenodo 记录 8259942,"Dataset15")、GTEx 门户数据(用于人工 eQTL 交叉核对,而非智能体驱动),以及来自 van der Laan 等人(2025)的 ADHD GWAS 汇总统计数据与补充表格。

代码以 MIT 许可发布于 `github.com/jmiao24/Paper2Agent`(本笔记元数据抓取时经 `hf papers info` 显示为 3,178 星;直接抓取 README 时显示约 3.2k 星)。当前的 README(2026-09-21 抓取)描述的安装与架构方式已明显超出论文自身的描述——一种基于"技能(skill)"的安装流程("把 paper2agent 技能安装"到 Claude Code 或 Codex 中),以及一个负责启动"并行专业智能体(parallel specialist agents)"与"新鲜验证智能体(fresh verifier agents)"的协调者,而非论文原本描述的固定四子智能体编排结构(见 Q5)。本笔记按照论文自身的描述记录其架构;此处提及现有代码仓库只是为了说明它自论文发表以来仍在持续演进,如果读者直接查阅仓库,不应假定其与 Q5 的描述完全一致。一个 Hugging Face Space 托管着部署完成的 AlphaGenome 智能体 MCP 服务器(`huggingface.co/spaces/Paper2Agent/alphagenome_agent`),与论文所述的远程托管方式一致。论文自身的"Code availability"与"Agent availability"章节标题出现在抓取到的 arXiv HTML 中,但在本笔记的文本抓取中,这两个标题下均未返回正文内容;其具体内容(如果在已通过元数据获取的 GitHub/HF 链接之外还有其他内容)本笔记未做进一步核实。

# Q9 主要贡献

1. Paper2Agent:一套可运行的"编排者+四个子智能体"流水线(environment-manager、tutorial-scanner、tutorial-tool-extractor-implementor、test-verifier-improver),能以极少的人工介入,把一篇论文及其代码库转换为一个经过测试的 MCP 服务器(工具/资源/提示词),基于 Claude Code 实现。
2. 一套面向 LLM 智能体科学工具使用的具体可靠性机制——针对参考代码库自身报告的输出验证每一个生成的工具,再将其锁定,同时嵌入指向原始源码的可追溯链接——明确定位为缓解"代码幻觉",而非仅仅追求能力最大化。
3. 三个已演示的论文智能体(AlphaGenome:22 个工具,约 3 小时;TISSUE:6 个工具;Scanpy:7 个工具,约 45 分钟,限定于预处理/聚类)及相应证据:AlphaGenome 智能体在教程衍生查询与新查询上,均优于"直接给通用编程智能体原始仓库访问权限"(Claude + Repo)与通用生物医学智能体(Biomni)(100% 对 60-80% 对 40-60%),同时运行速度快 1.8 至 4.6 倍。
4. 一种已演示的跨论文组合模式——把一个方法论文 MCP(AlphaGenome)与一个数据论文 MCP(ADHD GWAS)连接到同一个下游聊天智能体、构成一个"AI 协作科学家"——它自主生成并部分执行了一个具体的、有明确分子机制细节的基因组学假设(rs1626703/谷氨酸能神经元中的 MPHOSPH9 剪接),随后在两小时内把同一分析工作流扩展到 39 个 GWAS 位点。
5. 一个作为讨论观点(而非已验证结论)提出的重新框定论点:论文转化为智能体的难易程度,或许可以作为代码库可复现性与严谨性的实用代理指标,并据此呼吁论文最终能像"数据/代码可用性"一样,增加一个"智能体可用性"章节。

# Q10 下一步

论文自陈的局限性与未来方向(讨论部分):(a) 目前的重点局限于具有清晰代码/教程结构的方法学论文——数据资源型和发现型论文被列为未来工作,届时智能体的角色可能从"计算"转向"解读、整理或解释";(b) 并非所有论文都能变成一个稳健的智能体——不完整、文档不足或存在未解决 bug 的代码库会阻碍可靠转换,作者将其重新解读为一种严谨性信号,而不仅仅是 Paper2Agent 自身的局限;(c) 基准测试方法依赖专家知识与人工实现/打分,作者提出未来可借助 LLM-as-judge 评测来扩展这一过程;(d) 当一个想法跨越一系列相关出版物时,论文可能不是"智能体化"的正确单元,这促使作者计划让一个 MCP 未来能够封装多篇相关论文,而非严格对应一篇。

除论文自身列出的方向外,以下三点值得提醒依赖本笔记的读者。第一,AlphaGenome 基准测试的标准答案、打分与被评测的智能体本身都出自同一团队,且样本规模较小(15+15 条查询)——一次采用盲打分的独立复现会显著增强其可靠性结论的说服力。第二,TISSUE 与 Scanpy "与人类研究者结果一致"这一结论在抓取到的正文中是定性表述;需要量化可复现性界限(例如相关系数或误差阈值)的读者,无法仅从这篇论文中获得。第三,由于三篇案例研究工具中有两篇是 Zou 实验室自己的论文,第三篇(Scanpy)又是一个使用极广、文档异常成熟的通用软件包,论文隐含的"Paper2Agent 能泛化到广义'研究论文'"这一主张,是被主张出来的,而非在一组更异质、或刻意挑选的对抗性论文集合上(例如计算生物学之外领域的论文,或代码库不那么成熟、教程不那么丰富的论文)被实际评估过的——论文自己确实预见到了这类失败情形("不完整、文档不足或存在未解决的错误"),但没有量化这种情形在其自选案例之外会有多普遍。

# 相关

* [LLM agents](../topics/llm-agents.md)(LLM 智能体)- 与该主题下其他智能体构建/平台类论文(OpenHands、AutoDev、Apodex 1.1)相比,这是一个确实不同的角度:那些论文构建的是供用户或下游任务直接操作的智能体执行基础设施,而 Paper2Agent 的"编排者+四子智能体"流水线(environment-manager、tutorial-scanner、tutorial-tool-extractor-implementor、test-verifier-improver)构建的是接口本身——自动把一篇静态研究论文及其代码库转换为一个经过测试、有版本管理的 MCP 服务器,因此这里被构建出来的"智能体",是针对某一篇具体论文方法的常驻交互代理,而不是一个通用的编程或任务执行平台。
* [Model Context Protocol (MCP)](../concepts/model-context-protocol.md) - 在这篇论文中,MCP 并非众多特性之一,而是论文的核心技术:Paper2Agent 的全部贡献,就是系统性地从一篇论文及其代码库构建一个 MCP 服务器(工具/资源/提示词),在锁定每个工具之前先对照参考实现自身报告的结果进行验证,再部署该服务器供任何兼容 MCP 的聊天智能体使用——相比该概念页面目前收录的条目(AgentScope 的 MCP 客户端支持、MAI-UI 的 `mcp_call` 动作、VibeWorlding 的资产操作工具,它们都只是把 MCP 当作更大智能体中的一个集成接口),这是一种更直接、更承重的协议使用方式——论文真正要构建的东西,就是这个协议本身的产物。
