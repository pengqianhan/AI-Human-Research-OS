# Q1 问题定义

* **输入 (X)：** 一个冻结的决策模型（decision model），即针对上下文回答问题、输出带类型的结果（在给定选项中做选择并给出每个选项的概率，或一个 [0,1] 的分数）而不是生成文本的模型；一个目标；以及当前状态和可选动作（行动时），或一条由观测和动作组成的已记录轨迹（评判时）。
* **输出 (Y)：** 作为行动者（Actor），输出下一步动作；作为评判者（Judge），给一个已执行动作打分；作为教师（Teacher），对正在训练的策略的轨迹打同样的分，用作 RL 的步级监督。
* **约束：** 评判者只看到观测和动作，成功标签和奖励被屏蔽；教师在训练中保持不变，测试时不调用；环境是文本环境，每回合最多 30 步。

# Q2 问题新颖性

决策模型本身很新（论文把最早公开的 JEV 定在 2026 年 9 月），此前的研究都把它当行动者来评测，而它在有先后顺序的子目标上表现很差。本文问的是另一个问题：一个行动得不好的模型，能否仍然提供有用的步级信用。这很重要，因为结果奖励给一条轨迹里的每个动作同样的信用，而替代方案要么需要每个环境的步级标注，要么要在每一步调用 LLM 评判。步级信用分配是老问题；新的地方是用一个便宜的类型化输出模型来做，并把“模型看到什么”和“模型被问什么”分开研究。

# Q3 科学假设

如果让决策模型看到整条轨迹（Hindsight，事后视角），并问它每个动作是否有助于达成目标（Progress），那么它的分数比只看前缀、或问“任务会不会成功”（Value）时更能区分有用和无用的动作；把这些分数加到 RL 的优势函数上，能训练出更好的策略，包括在该模型自己作为行动者会失败的任务上。论文给出的理由是：在回合结束后评判，能看到行动时必须预判的后果。

# Q4 相关工作与关键人物

* **决策模型。** JEV（TypeSafe AI）、GPT Decisions（OpenAI）、Decider v1.2（Perplexity AI，由 Qwen3.8-27B 全量微调）。已有研究用它们来行动：Yang 等人研究 JEV 的表面捷径，JevAgentHarness 让决策模型与 LLM 共享在线控制，另有两篇诊断论文（arXiv 2610.18579、2610.13092）分析其在智能体循环中的决策失败。
* **LLM 评判与过程监督。** [LLM-as-a-judge](../concepts/llm-as-a-judge.md) 多用于比较最终回答；过程奖励模型（Lightman 等）给中间步骤打分，但每个领域都需要步级标注。
* **LLM 智能体的信用分配。** [GRPO](../concepts/grpo.md) 让每一步都拿到整条轨迹的优势；[GiGPO](../concepts/gigpo.md) 比较从同一状态出发的不同动作；事后信用分配（Harutyunyan 等；Tan 等把它用于 LLM 智能体）用动作之后发生的事来判断其贡献；里程碑引导的策略学习（Wang 等）提供了本文采用的“里程碑”定义。论文还提到弱到强泛化（Burns 等）。
* **关键人物。** Haochen Liu、Qianhao Zhu、Zixuan Wang（共同一作），以及 Dingming Li、Tongbo Chen、Peng Qiu、Yingqi Qu、Weiming Lu、Jun Xiao、Yongliang Shen，来自浙江大学和百度。该团队（ZJU-REAL）也是被引用的 Agent-G2、里程碑引导论文以及 [Agent-R2](../papers/2611.08219.md) 的作者。可能的批评者：GiGPO 的作者（其论文报告的 GRPO 数字被用作基线），以及 LLM 价值函数信用分配（Zhu 等）的作者（被引用但没有比较）。

# Q5 核心解法

这是一项对照研究，外加一处很小的训练改动。

1. **一个模型，三种角色。** 行动者：在合法动作上做多选题。评判者：对已记录轨迹中的某个已执行动作回答是/否问题。教师：把评判者用在训练策略自己的轨迹上。
2. **评判的两个因素。** 上下文是 Prefix（到该动作为止的轨迹，不含该动作产生的观测）或 Hindsight（整条轨迹，屏蔽结果标签）。问题是 Value（如果先执行这个动作，任务在剩余步数内完成的概率）或 Progress（“目标动作是否对完成目标做出了有用的贡献？”，并说明后来的失败不抹掉之前的有用进展，后来的成功也不会让一段不必要的绕路变得有用）。
3. **把教师分数加入 GRPO。** 对每个任务，把一组轨迹中所有被打分的动作做均值中心化，再加到结果优势上：A = A_out + λ(s − s̄)，λ = 0.5。分数不除以标准差，所以教师打分接近一致的组几乎不被调整。每个已执行动作发一次教师请求。

比较了六个模型：三个专用决策模型，加上用提示输出 JSON 概率的 Qwen3.8-27B、读取首 token 概率的 Qwen3.8-27B，以及用提示的 GPT-6 Luna，后三者都关闭推理。

# Q6 实验设计

* **环境。** [ALFWorld](../concepts/alfworld.md)，分为无依赖任务（Pick、Look、Pick2）和有依赖任务（Clean、Heat、Cool，必须先改变物体状态再放置），以及 [WebShop](../concepts/webshop.md)。划分沿用 GiGPO。
* **行动者。** 按任务类型统计成功率，每个任务跑一次；目标遮蔽测试，在 66 个任务的 116 个状态上进行，这些状态下一步动作就能完成容易的子目标，而前置子目标尚未完成（完整目标对比去掉放置子目标的目标）；在同样的状态上做提示测试（原始提示、依赖提醒、提醒加一个示例）。
* **评判者。** 在成功续写的轨迹（167 条）中，对从这些状态出发的第一个动作比较 Prefix 与 Hindsight；在 462 条同时含里程碑动作和无效动作的轨迹上比较 Value 与 Progress，报告平均分、里程碑的 Recall@R 和轨迹内分差；在 2,849 个动作上做上下文扩展测试，依次露出即时反馈以及剩余轨迹的 25/50/75/100%；六个评判者的漏检率与 API 成本对比。
* **教师。** JEV 在全部四种“上下文 × 问题”组合下给 Qwen2.5-1.5B-Instruct 的轨迹打分，并在 Hindsight + Progress 下给 Qwen2.5-7B-Instruct 打分；150 次迭代，每次 16 个任务、每任务 8 条轨迹；每个策略用三个推理种子评测。GRPO 基线没有重跑，用的是 GiGPO 论文报告的数字。

每项分析只改变一个因素，其余保持不变，这是设计的长处。只用了一个教师（JEV）做训练，也只有两个环境。

# Q7 数据集与代码

没有新数据集。ALFWorld 和 WebShop 使用 GiGPO 的训练与评测划分，另用 RLVMR 的 L1 划分做更宽的行动者检验。六个模型都通过 OpenRouter 调用（JEV 1.13、Decider v1.2、GPT-6 Luna Decisions、Qwen3.8-27B、GPT-6 Luna）。训练使用 veRL 的 PPO 式更新，设置沿用 GiGPO。代码链接为 https://github.com/ZJU-REAL/decision-agents ，项目页为 https://zjureal.com/decision-agents/ ；本笔记没有检查这两处。提示词和训练算法在附录中。

# Q8 证据质量

**行动者（ALFWorld 成功率，%）。**

| 行动者 | Pick2 | Clean | Heat | Cool | 全部 |
|---|---|---|---|---|---|
| JEV | 70.8 | 11.1 | 18.8 | 16.0 | 42.9 |
| Decider v1.2 | 83.3 | 55.6 | 18.8 | 40.0 | 63.6 |
| GPT Decisions | 62.5 | 29.6 | 25.0 | 24.0 | 52.9 |
| Qwen prompted | 79.2 | 22.2 | 31.2 | 20.0 | 49.3 |
| Qwen constrained | 75.0 | 33.3 | 6.2 | 8.0 | 45.0 |
| GPT Luna | 37.5 | 18.5 | 0.0 | 4.0 | 34.3 |

在 116 个诊断状态上，JEV 把 63.8% 的概率放在容易的放置动作上，只有 14.6% 放在前置步骤上；去掉放置子目标后变为 2.5% 和 77.6%，六个模型都朝同一方向变化。只加提醒，成功率变化在 −2.8% 到 +5.2% 之间；再加示例对一些模型有帮助（Qwen constrained 从 41.7% 到 58.3%），对另一些没有（Decider v1.2 从 89.7% 降到 85.3%）。

**评判者。** 在 Hindsight 下，JEV 对朝向前置子目标的第一个动作的平均分从 0.41 升到 0.59。同在 Hindsight 下，Value 给里程碑、其他、无效动作的分数是 0.632、0.604、0.577；Progress 是 0.659、0.440、0.298。在同一条轨迹内，Progress 给里程碑的分数比无效动作高 0.36，Value 只高 0.05；按 Recall@R，Progress 多找到 8.0% 到 16.0% 的里程碑。加入即时反馈后，动作排名相对 Prefix 平均移动 1.95 位，看到整条轨迹后移动 3.30 位。Decider v1.2 的里程碑漏检率低于它用提示的基座（36.5% 对 49.6%），每次打分成本约低 43%；GPT Decisions 对 GPT Luna 是 50.2% 对 54.1%，成本约低 28%。

**教师（成功率，%，三个评测种子的均值 ± 标准差）。**

| 策略、方法 | ALFWorld 全部 | ALFWorld 有依赖 | WebShop 成功率 |
|---|---|---|---|
| 1.5B，GRPO（取自 GiGPO 论文） | 72.8 ± 3.6 | 未给出 | 56.8 ± 3.8 |
| 1.5B，Prefix + Value | 79.0 ± 3.6 | 未给出 | 67.7 ± 0.5 |
| 1.5B，Prefix + Progress | 78.3 ± 0.4 | 未给出 | 66.6 ± 0.2 |
| 1.5B，Hindsight + Value | 69.3 ± 0.7 | 未给出 | 68.3 ± 1.5 |
| 1.5B，Hindsight + Progress | 82.9 ± 2.9 | 86.8 | 71.4 ± 0.7 |
| 7B，GRPO（取自 GiGPO 论文） | 77.6 ± 5.2 | 未给出 | 66.1 ± 3.7 |
| 7B，Hindsight + Progress | 83.8 ± 1.6 | 未给出 | 73.6 ± 0.3 |

论文只对 Hindsight + Progress 给出了有依赖任务的汇总数（86.8%，比另外三种教师设置高 6.9% 到 16.2%）。每次训练的教师 API 成本为 22.21 到 30.07 美元，输入价格为每百万 token 0.042 美元。

**证据的局限（读者观察）。**

* GRPO 两行来自另一篇论文的运行。训练设置沿用 GiGPO，但没有在同一代码库里重跑 GRPO，所以差距的一部分可能来自实现差异。表里也没有 GiGPO 本身，而它的摘要（见本 wiki 的 GiGPO 页面）报告相对 GRPO 在 ALFWorld 上提升超过 12%、在 WebShop 上超过 9%，与这里的提升幅度相当。因此论文证明的是教师胜过已发表的纯结果奖励 GRPO，而不是胜过现有的步级信用方法。
* 在 WebShop 上，所有教师变体都比引用的 GRPO 高至少 9.8 个点，包括 Hindsight + Value。评判分析说这一设置在轨迹内几乎没有区分信号，它在 ALFWorld 上也低于 GRPO（69.3）。所以 WebShop 上的提升不像 ALFWorld 那样与“评判质量”的解释对得上。
* 在 ALFWorld 总体上，Hindsight + Progress（82.9 ± 2.9）与 Prefix + Value（79.0 ± 3.6）在一个标准差内重叠。± 是同一个训练好的策略在三个推理种子上的波动，没有报告训练种子的波动。
* 行动者的分数对应整数任务数：各类型为 35、13、24、27、16、25 个任务（共 140 个；JEV 的 42.9% 是 140 中的 60 个，它在有依赖任务上的 14.7% 是 68 中的 10 个），每个只跑一次。一个 Heat 任务就是 6.25 个点，所以行动者之间按类型的差距只是几个任务。有依赖任务的 86.8% 等于 Clean、Heat、Cool 三格按任务数加权的均值。
* 行动者的排序在不同划分上不稳定：在更宽的 L1 划分上，Qwen constrained 从 45.0% 变为 58.2%，GPT Luna 从 34.3% 变为 55.2%，而 JEV 在专用模型中仍然最低（38.8%）。依赖任务上的差距在两个划分上对六个模型都成立。
* 在完整事后视角下，JEV 仍给示例中过早的放置动作打 0.60，高于“走向微波炉”的 0.50，尽管问题里说明了后来的成功不会让绕路变得有用。
* 只用 JEV 做了教师。评判分析显示 Decider v1.2 在里程碑上评判得更好，但没有用它训练策略，所以“评判质量预示教学质量”只在同一个模型的不同问题和上下文之间得到检验，没有在不同模型之间检验。

行动者和评判者的发现在六个模型上一致，是支撑最充分的部分。教学的结论在两个环境上方向成立；相对于重跑的基线和 GiGPO，它的幅度没有确定。

# Q9 贡献

1. 一套三角色实验方案：固定模型，改变角色、上下文和问题；其中目标遮蔽测试表明行动者知道前置步骤，但会被更容易的子目标吸引走。
2. 证据表明问题决定了评判信号的粒度：问结果，轨迹内的分数几乎一样；问贡献，分数能拉开。六个模型都如此。
3. 一种把冻结的决策模型用作 GRPO 步级监督的简单做法（均值中心化的分数加到优势上），每次训练的成本为几十美元。
4. 一条实用建议：在花钱跑 RL 之前，先在已记录的轨迹上筛选候选评判者和问题，按评判质量而不是行动能力来选。

# Q10 下一步

* **论文自述的局限。** 两个文本环境，最多 30 步；评判发生在回合结束后，没有覆盖只有前缀可用的在线过滤或重排；JEV 和 GPT Decisions 是闭源的，不知道什么样的训练能造就好的评判者。
* **重跑基线。** 在同一代码库里带训练种子重跑 GRPO 和 GiGPO，这样才能把教师的收益与不需要 API 的步级信用方法作比较（读者建议）。
* **第二个教师。** 用 Decider v1.2 训练，它权重开放，在这里对里程碑的评判也比 JEV 好；如果评判质量决定教学效果，它教出的策略应该更好（读者建议）。
* **与状态分组结合。** GiGPO 的同状态比较与事后评判用的是不同的信息，两者相加的效果没有测过（读者建议）。
* **讨好评判者。** 策略是针对一个固定评判者的分数优化的。它会不会学到在 JEV 看来有用、实际无用的动作，论文没有检查；优势中的结果项对此有约束，但 λ 没有做消融（读者观察）。
* **更长的任务。** 事后评判的请求随轨迹变长而变大，因为给每个动作打分都要带上整条轨迹。在几百步的轨迹上，成本和评判准确率如何还不清楚。
