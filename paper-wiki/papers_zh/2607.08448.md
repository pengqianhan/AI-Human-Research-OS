# Q1 问题定义

* **输入（X）：** 每个执行回合中的多模态观测 `o_t = (I_t^rgb, I_t^d, q_t)`——一张以智能体视角拍摄的 RGB 图像、与之对齐的度量深度图、以及机器人本体状态（末端执行器位姿加夹爪状态）——连同固定的自然语言任务描述 `ℓ`；在少样本（few-shot）部署阶段，还包括从"任务专属记忆"（Task Specific Memory，同一任务此前一次探索式引导中留下的、参数化的 JSONL 原语调用轨迹及其语义"策略/规避"摘要）中检索到的记录，以及跨任务、跨基准共享的"全局记忆"（Global Memory，即成功规则与命名失败模型）。二值化的完成谓词 `G` 仅在回合结束时作为稀疏信号出现，从不作为中间奖励暴露给规划器。
* **输出（Y）：** 逐回合发出的结构化 JSON 原语调用序列 `c_t`，从一个固定的原语库 `P` 中选取——六个解析式（analytic）原语（`move_to`、`move_pose`、`rotate_wrist`、`rotate_pitch`、`set_gripper`、`release`）、一个由 VLA 支撑的原语（`vla_act`），以及仅在 RoboCasa365 中使用的两个移动底盘原语（`navigate_to`、`move_base`）——在物理仿真器（基于 Robosuite 的 MuJoCo）中执行，直至 `G` 被满足或步数预算耗尽。规划器本身从不直接输出底层力矩、关节目标或动作块。
* **核心问题：** 端到端的冻结 VLA 提供了强大的局部接触式（contact-rich）控制能力，但由于其训练数据仅覆盖分布内轨迹，一旦部署时的扰动（语义目标重定向、目标谓词重新绑定、空间布局变化，或不稳定的局部接触）使指令与场景之间隐含的绑定失效，它便会悄无声息地重复训练时的行为；而 LLM 编码智能体提供了互补的语义与组合推理能力，但其确定性的解析式原语本身无法完成不规则抓取、受限放置或铰接物体交互。本文要解决的问题是：如何在不微调 VLA 权重、也不在部署时扩充原语词表的前提下，将二者组合起来，使 VLA 只在其可靠的范围内被调用。
* **范围：** 仅限仿真环境下的操作任务——LIBERO/LIBERO-Pro 桌面操作、RoboCasa365 家庭厨房操作（含移动底盘调度）、以及 RoboTwin 双臂"由整洁到随机化"迁移；均建立在已有的公开基准和（预训练或内部后训练但均冻结的）VLA 检查点之上（LIBERO/LIBERO-Pro 使用 RLinf 的 `π0.5`-SFT 检查点，RoboCasa365 使用 RLDX-1，RoboTwin C2R 使用作者内部后训练的 LingBot-VLA）。任务级的引导式探索每个任务仅使用一个参考种子。论文测试了两种可互换的 LLM 规划器后端（OpenAI Codex、Claude Code），但并未将其作为一个被系统研究的设计维度。检索到的正文中未报告真实机器人部署结果。

# Q2 问题新颖性

论文并未声称首创"VLA + 编码智能体"的混合架构、基于 LLM 的机器人 API 任务规划，或持久化智能体记忆——其相关工作部分明确追溯了每一条脉络（VLA 方面：RT-1/RT-2/OpenVLA/`π0`/`π0.5`/GR00T/Gemini Robotics；编码智能体控制方面：Code-as-Policies、ProgPrompt、Instruct2Act、RoboCodeX、ViperGPT、VoxPoser、RoboClaw、Maestro；通用智能体框架/自我修正传统方面：SWE-agent、OpenHands、Reflexion/Self-Refine、Statler；LLM 任务规划器方面：SayCan、Inner Monologue、SayPlan、RoCo）。其声称的新颖性更为具体、更窄：其一，将原语词表保持**固定且小巧**，而不是让智能体扩充技能库——论文明确将自己与 ASPIRE 对比，后者利用执行轨迹诊断失败、并将验证过的新技能纳入不断扩张的技能库，而 Harness VLA"刻意保持原语词表固定，研究记忆引导的组合如何在不进行部署时原语扩充的情况下扩展一个冻结的 VLA"；其二，将冻结的 VLA 本身作为该固定词表内的一个可重试原语（`vla_act`）暴露出来，而不是作为一个单体式端到端控制器，也不是一个智能体可以编辑的组件。论文还指出了一个具体的空白：Voyager 表明持久化记忆能在数字沙盒中帮助具身智能体，但"这种以记忆为中心的设计此前从未与一个面向物理操作的、由 VLA 支撑的接触式原语相结合"——任务专属记忆（可复用的任务级轨迹）与全局记忆（跨任务的成功规则/失败模型）正是本文对这一结合方式给出的答案。

# Q3 科学假设

如果将一个冻结的 VLA 仅仅暴露为一个可重试的、由规划器调度的接触式原语——同时将所有非接触结构（目标定位、自由空间的搬运、姿态调整、移动底盘调度、失败后的重新布置、释放）交由固定的解析式原语在 LLM 规划器控制下完成——那么这一组合系统应当能在不做任何权重更新的情况下，将该 VLA 的有效操作范围大幅扩展到其训练分布之外；具体表现为：在部署扰动（指令重定向、位置互换、由整洁到随机化的迁移）下相对于原始冻结 VLA 及此前的 LLM 编码智能体基线取得大幅提升,同时在该 VLA 原本的分布内设定上大体保持其原有表现。论文本身将"操作范围"当作一个可实证测量的属性（对应第 3.3 节的调用次数上限曲线与原语使用统计），而非仅仅是一种假设性的表述。

# Q4 相关工作与关键人物

* **端到端 VLA 模型。** 从 RT-1、Octo、RT-2、Open X-Embodiment 开启的通才策略脉络，经 OpenVLA、基于流匹配的 `π0`/`π0.5`，到近期规模化的系统（GR00T、Gemini Robotics），论文认为这类模型在接触式视觉运动阶段最强，但在指令跟随、长程组合以及分布外场景上表现急剧下降——这正是本文所依赖的"能力错位"（asymmetry）的来源。
* **LLM 驱动的多模态智能体。** 前沿视觉语言模型（GPT-5.2、Gemini 3、Qwen3-VL、Claude 4 系列、Llama 4）被认为在大约一年内已在密集感知与空间推理上大幅缩小差距，这促使论文将语义定位与确定性操作阶段交由智能体栈顶部的前沿模型完成，而不是用 VLM 端到端地直接驱动机器人。
* **面向机器人操作的编码智能体。** Code-as-Policies、ProgPrompt、Instruct2Act、ChatGPT-for-Robotics、RoboCodeX、ViperGPT、VisProg、VoxPoser、RoboClaw、Maestro 将控制问题重新表述为对感知/运动 API 的程序合成。ASPIRE 是论文最直接的对比对象（其技能库通过诊断-合成-准入不断扩张，论文称其为"互补"而非被取代）。SWE-agent、OpenHands 以及"可执行代码动作"一脉提供了本文附录 A 所实现的 harness/REPL 模式；Reflexion、Self-Refine、Self-Debug 提供了规划器调度式 VLA 重试背后的自我修正框架；Statler 提供了跨步骤持久化符号状态的思路；Voyager 提供了 Q2 中提到的持久化记忆先例。
* **关键人物与机构。** 通讯作者为清华大学的 Chao Yu（zoeyuchao@gmail.com）；合作者分布于清华大学、Striding AI、普渡大学、中国科学院自动化研究所、Infinigence AI、中关村学院以及香港科技大学——是一个学界与业界结合的联合团队。`vla_act` 的三个后端分别来自不同来源（RLinf，一个强化学习框架/检查点来源；RLDX-1；以及作者自己在 RoboTwin 上后训练得到的 LingBot-VLA 检查点），说明论文自身的生态已经横跨多个 VLA 提供方。来自 ASPIRE 脉络（技能库扩充派）的读者很可能会追问：一个永久固定的原语词表能否覆盖真正新颖的任务族；而来自大规模端到端 VLA 脉络（`π0.5`、GR00T）的读者则可能质疑手工设计的 JSON 原语接口及仅限仿真的评测能否推广到非结构化的真实世界部署——以上两点均为本笔记的推断，并非论文本身对其潜在批评者的表述。

# Q5 关键解法思路

1. **固定原语库作为唯一动作接口。** 规划器从不直接输出原始动作；它每一回合只选择一个原语，并从语言、RGB-D、本体感知与记忆中绑定其参数。解析式原语分为"复合式"（composite，由一个内嵌求解器协调多自由度、朝向世界坐标系目标运动，例如 `move_to`）与"原子式"（atomic，将某一固有通道驱动到某一设定点，例如 `set_gripper`）。`vla_act` 在结构上是特殊的：规划器提供一个以任务为条件的提示词以及一个提前返回谓词 `τ`，冻结的 VLA 随即持续输出动作块，直到 `τ` 被满足或动作块预算耗尽。
2. **同步的、文件中介的 REPL 式 harness（附录 A）。** 一个长期运行的环境工作进程持有实时仿真器状态；规划器将一条 JSON 命令写入 `command.json`，工作进程执行后写出下一份带索引的观测及诊断记录，规划器在采取下一步行动前等待这些文件。规划器从不直接访问特权级的仿真器状态或物体位姿——只能获得渲染出的 RGB-D 与本体感知信息。
3. **两阶段生命周期。** 在"引导式探索阶段"（每个任务仅用一个参考种子 `s0`，可使用 `reset` 原语，且拥有充裕的墙钟预算）中，规划器试验不同的调度顺序、接触前姿态、`vla_act` 的调用时机以及提前返回阈值，并在失败时纠正路径。在"部署评估阶段"（禁用 `reset`，步数预算被大幅压缩，仅使用留出种子）中，规划器检索已存储的轨迹，并根据实时观测动态地重新定位（re-ground），而不是重放存储的坐标。
4. **任务专属记忆。** 一条参数化的 JSONL 轨迹（其中的空间参数被视为"参考场景绑定"，在部署时重新定位）加上一份语义化的 JSON 摘要，记录该策略*为何*奏效以及应规避什么（例如"不要重用参考 xyz 数值；用基准的成功信号来验证放置结果"）。它是一个任务级的"解法骨架"，而非一条开环轨迹，并且会被持续精炼而非单纯累积：如果后续一次引导式尝试得到了更短或更可靠的方案，它可以替换已存储的轨迹。
5. **全局记忆。** 在同一基准内跨任务共享的、与具体任务无关的操作知识：成功规则（例如，向 `vla_act` 提示时应使用完整的任务指令；一旦已建立稳定抓取，长距离搬运应优先使用解析式运动）以及命名的失败模型（"空抓"——夹爪已闭合但物体并未随末端执行器一同移动；以及"虚假成功"——不要仅凭视觉上的接近就判定终止，应检查基准信号以及最近一次的执行记录）。
6. **规划器调度式 VLA 重试（关键发现二）。** 每一次 `vla_act` 调用都是规划器主动选择的一次局部尝试，而非一次性的黑箱调用：规划器先将机器人摆放到一个可行的接触前构型，再调用 VLA，检查接触后置条件是否满足，若失败则在重试前重新调整接近姿态或视角——从而将一次瞬时的接触失败局限在当前子任务内，而不会让它拖垮整个回合。

# Q6 实验设计

**少样本评测（配合任务专属记忆，第 3.2 节）。**
* *标准 LIBERO*（400 条回合：4 个任务套件 × 10 个任务 × 10 个留出种子，`s0` 专供引导式探索使用）：Harness VLA（Claude Code）达到 96.0%（384/400，Object 套件 100.0%，LIBERO-10 套件 93.0%），而冻结的 RLinf `π0.5`-SFT 检查点本身为 95.3%——在该 VLA 的分布内设定上二者基本持平。
* *LIBERO-Pro*（800 条回合：4 个任务族 × T/指令重定向 与 S/位置互换 两种扰动 × 10 个任务 × 10 个种子）：RATS 被报告为此前最强的基线，在其自身报告的单元格上整体为 43.8%。Harness VLA 使用 Codex 达到 72.1%，使用 Claude Code 达到 82.4%——82.4 − 43.8 = **38.6 个百分点**的提升，与摘要中的头条数字一致。在论文自身协议下直接评测的 RLinf 基线整体为 50.0%——高于 RATS，但远低于 Harness VLA，论文以此作为"提升并非单纯来自冻结 VLA 骨干本身"的佐证。
* *RoboCasa365*（target50 划分，共 340 条回合：Atomic-Seen 18×10，Composite-Seen 16×5，Composite-Unseen 16×5）：直接使用 RLDX-1 的基线——即该基准中 `vla_act` 内部所用的同一检查点，在论文协议下评测——加权后整体达到 30.0%（Atomic-Seen 60.0%，Composite-Seen 21.3%，Composite-Unseen 5.0%）。Harness VLA 使用 Codex 达到 55.4%（55.4 − 30.0 = **25.4 个百分点**，与摘要一致），使用 Claude Code 达到 48.6%。表 4 中还存在其他先前论文报告的基线行，但其具体数值无法从抓取到的文本中还原（见 Q8）。

**零样本评测（不使用目标设定下的任务专属记忆，第 3.2 节）。**
* *LIBERO-Pro Goal*，隐去记忆：Harness VLA（Claude Code）在指令重定向上达到 79.0%，在位置互换上达到 31.0%，而 Cap-X 分别为 16.8% 与 25.6%——说明即便没有针对该任务检索到的轨迹，规划器基于固定原语接口的推理依然能够迁移；但位置互换上的数字明显低于少样本设定下的整体表现，暗示任务专属记忆对空间性（相对于语义性）扰动的贡献更为不成比例地大。
* *RoboTwin C2R*（250 条回合：50 个任务 × 5 个随机化种子；轨迹仅来自一个经专家验证的 `demo_clean` 种子，随机化设定下不做额外的引导式探索或微调）：直接使用 LingBot-VLA 达到 50.4%；Harness VLA 将同一冻结后端分别提升到 58.0%（Codex）与 58.4%（Claude Code）——即摘要中的 RoboTwin 头条数字，相对于未经组合的 VLA 提升了 8.0 个百分点。

**机制分析（第 3.3 节）。** 图 4 在三个受扰动基准上限制每回合允许的 `vla_act` 调用次数上限：成功率在最初几次调用后迅速上升，并向完整 harness 的结果饱和，被解读为"调用是稀疏的，但反复调度与重试很重要"的证据。图 6 统计了最终成功谓词究竟由哪一类原语触发：LIBERO Pro 系列任务通常在建立接触后由解析式原语完成收尾，而 RoboCasa365 与 RoboTwin C2R 中最终谓词往往直接依赖一次接触式操作，因此这两个基准中更多成功回合是在 `vla_act` 内部完成的。附录 F 的原语使用统计表（对 Harness VLA (Claude Code) 各次运行按规范原语名称汇总）显示，`vla_act` 在全部原语调用中所占比例随接触密度而上升：LIBERO 中为 15.8%（`move_to` 单项即占 61.8%），RoboCasa365 中为 35.3%（移动底盘原语额外贡献 19.4%），RoboTwin C2R 中为 47.4%——即便如此，解析式原语在该基准中仍占据略微多数。

# Q7 数据集与代码

论文未发布任何新的预训练或评测数据集；四个基准家族（LIBERO、LIBERO-Pro、RoboCasa365、RoboTwin）均为已有的公开基准。各检查点的来历与"冻结"历史并不相同：RLinf 官方的 `π0.5`-SFT 检查点（基于 LIBERO-130 训练，直接使用）、官方的 RLDX-1 检查点（直接使用），以及作者**内部后训练**得到的 LingBot-VLA 检查点——先在跨具身的遥操作数据上预训练，再由作者在 RoboTwin 轨迹上做监督微调（SFT）适配，随后才被冻结、同时用于直接基线与 Harness VLA 两组评测。论文所称"在不微调的情况下扩展预训练 VLA"这一表述，指的是 harness 本身在部署时不再做任何额外权重更新，而并非指每一个后端 VLA 都完全未经任何针对特定任务的训练——LingBot-VLA 正是这一表述的例外，引用论文"冻结 VLA"这一框架时应留意这一区别。HF 元数据中列出了项目主页（harnessvla.github.io）与 GitHub 仓库（github.com/RLinf/RPent，抓取时 691 星）；抓取到的 arXiv 正文本身并未描述该仓库的具体内容，本笔记也未独立浏览这两个链接（关于该仓库所属组织的说明见 Q8）。

# Q8 证据质量

本笔记基于通过 `hf papers read 2607.08448` 成功抓取到的 arXiv HTML 全文（摘要至附录 F，以及参考文献列表的开头部分）撰写——未使用网页抓取作为后备方案，对上述各节的文本层面忠实度有较高信心。仍存在两处结构性的检索缺口，二者均源于该工具渲染论文的方式，而非本文特有的问题：其一，表格的**正文内容**在标题与前后叙述之外并未被渲染为文本——例如 RATS 在抓取到的文本中从未获得完整名称、方法描述或引用编号，仅在表 3 的标题中被称为"此前报告的最强基线"，因此本笔记无法独立说明 RATS 除此之外还是什么；表 4 标题中提到的其他 RoboCasa365 基线行同样无法还原。其二，论文约 30 张嵌入图片（回合帧对比、图 4 的调用次数上限曲线、图 6 的完成归因柱状图）仅通过图注及前后文字阅读，未做视觉核查，因此任何仅出现在图中、正文未给出的数字均未在本笔记中复述。

所有报告的数字均为作者在自身协议下的自测结果，检索到的文本中没有独立复现。有几点有助于更准确地理解头条百分比：RoboCasa365 的"最强基线"（RLDX-1，30.0%）恰好就是 Harness VLA 在该基准上 `vla_act` 内部所使用的同一检查点，因此报告的 25.4 个百分点提升衡量的是该 harness 相对于其自身未经组合的接触原语的提升，而非相对于某个竞争性完整系统的提升——这与论文自身的目标表述一致，但与"击败了已发表的最佳 RoboCasa365 方法"是不同的论断（而后者是否成立，取决于未能还原的其余基线行）。任务级的引导式探索每个任务仅使用一个参考种子；论文未报告该单一种子阶段通常需要多少次探索尝试或多少墙钟时间预算，也未对参考种子的选择做任何敏感性分析。这是一篇 2026 年 7 月提交的论文（截至本笔记撰写时已有约 2.5 个月），在 HF 上零点赞、零评论——这是真实测得的低关注度，而非抓取延迟造成的假象；不过其关联的 GitHub 仓库挂靠在已有的"RLinf"组织之下（该组织正是论文自身 VLA 检查点的来源之一），而非一个专门新建的仓库，因此其 691 星很可能更多反映了 RLinf 这一框架本身的采用度，而非专门针对 Harness VLA 这一贡献的关注，不应被当作本文独立的关注度信号。

# Q9 贡献

1. Harness VLA：一个记忆增强的智能体框架，将一个冻结的 VLA 暴露为单一的可重试接触式原语（`vla_act`），并将其与一个在部署时保持固定的、面向目标定位、调度、搬运、导航与释放的小型解析式原语库组合起来——在不微调 VLA 权重、也不扩充原语词表的前提下，将一个预训练 VLA 的能力扩展到其原始轨迹分布之外。
2. 实证证据表明,这种组合确实在部署扰动下大幅扩展了冻结 VLA 的有效操作范围：相对于 LIBERO-Pro 上此前报告的最强基线（RATS，43.8% → 82.4%）提升 38.6 个百分点，相对于 RoboCasa365 的冻结 VLA 后端（RLDX-1，30.0% → 55.4%）提升 25.4 个百分点，在 RoboTwin C2R 的零样本"由整洁到随机化"迁移上提升 8.0 个百分点（50.4% → 58.4%），同时在标准的分布内 LIBERO 设定上大体保持原有表现（95.3% → 96.0%）。
3. 一种两层记忆设计——由单次引导式探索回合构建的、带语义"策略/规避"摘要的任务级参数化 JSONL 轨迹（任务专属记忆），加上跨任务的成功规则与命名失败模型（全局记忆，例如空抓与虚假成功检测）——并在一个禁用环境重置、压缩步数预算的严格部署机制下得到验证，从而迫使系统进行真正的重新定位而非单纯重放轨迹。
4. 一套机制层面的解释（关键发现一至三，辅以调用次数上限消融实验与原语使用统计），将提升归因于规划器层面的语义重新定位、对 `vla_act` 的规划器调度式重试/重新调度，以及一种分工模式——解析式原语处理非接触结构，而 `vla_act` 的调用占比随各领域的接触密度而变化（从 LIBERO 的 15.8%，到 RoboCasa365 的 35.3%，再到 RoboTwin C2R 的 47.4%）。

# Q10 后续方向

论文自身给出的局限性（第 5 节）：高层规划器与底层 VLA 之间存在一个开环的反馈回路（尚无闭环的联合自适应机制）；尚未通过环境奖励或人类偏好进行联合微调，作者明确将样本高效的强化学习（例如 GRPO）列为未来工作；此外，缺乏细粒度的图像描述能力，作者认为这限制了在高度杂乱、长程任务中的结构化推理能力。作者还提出，可将其固定词表的组合策略与诸如 ASPIRE 这样的自动技能发现系统相结合，使得当某个缺失的抽象被反复观察到时，智能体能够提出、验证并将其纳入为一个新的可复用技能，同时保留本文所研究的可审计原语接口与由 VLA 支撑的接触专精能力。

在论文自身的表述之外：单一参考种子的引导式探索设计（每个任务的全部记忆均来自一次探索回合）为"学习操作范围"这一论断提供的实证基础相当有限，也没有任何消融实验能够说明报告的提升在多大程度上依赖于该种子的代表性。RoboCasa365 的头条对比（见 Q8）衡量的是 Harness VLA 相对于其自身冻结 VLA 后端的提升，而非相对于已发表的最强 RoboCasa365 方法的提升，读者不应将其与 LIBERO-Pro 上相对于 RATS（一个外部竞争方法）的对比混为一谈。Harness VLA 这种固定词表、两阶段记忆的设计能否在真实机器人上站得住脚——毕竟真实场景中引导式探索无法依赖一个可无限次 `reset` 的仿真器，观测与诊断文件的获取也并非零成本——抓取到的正文并未涉及，这将是一个自然的后续探究方向。
