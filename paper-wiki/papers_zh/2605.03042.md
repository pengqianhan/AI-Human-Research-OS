> 论文:**ARIS: Autonomous Research via Adversarial Multi-Agent Collaboration**
> 论文链接:<https://arxiv.org/abs/2605.03042>
> 机构:上海交通大学、上海创新研究院

# Q1 问题定义

* **输入 `X`**:研究开始时给出的一个直觉或想法,交给系统去完成一个跨多个会话的长周期机器学习研究流程(文献调研、假设生成、实验、论文撰写、投稿反驳)。
* **输出 `Y`**:由 executor 模型产出、并由一个来自不同模型家族的 reviewer 模型反复检查的研究产物(实验日志、论文手稿、claim 台账),以及把每条声称的结论(claim)追溯回原始证据的逐条审计判定(支持 / 部分支持 / 不成立)。
* **核心问题**:单个 agent 执行长周期研究时不会明显地失败,而是产出"看似可信却缺乏支撑的成功"(plausible unsupported success)——结果可能被误报、不完整,或悄悄继承了 executor 自身的叙述框架,而从证据到结论的链条没有任何独立核验。
* **范围**:贡献了一套系统(harness 架构、保障机制)以及早期部署证据;明确不包含一个受控的、算力对齐的基准测试来分离出跨模型评审的因果效应(留作未来工作,附录 E)。

# Q2 问题的新颖性

自主研究 agent(The AI Scientist、AI Scientist-v2、Agent Laboratory、AI co-scientist、data-to-paper)是一个活跃方向,但本文指出并直接针对三个反复出现的缺口:(1)许多系统的 execution 和 review 使用相同或紧密相关的模型家族,这是一种同模型自我精炼模式(如 Self-Refine、Reflexion),容易让共有的盲点无法被发现;(2)工作流端到端紧耦合,难以替换单个阶段或从检查点恢复;(3)少有系统在单次评审之外提供显式的、系统级的实验完整性与手稿质量检查。ARIS 的新意在于把一条严格的工作假设——"任何由单个 agent 执行的长周期任务都是不可靠的"——当作组织原则,并把持久状态、模块化技能、独立的跨模型保障作为对这一假设的三个直接系统级回应,而不是可选的附加项。

# Q3 科学假设

如果一个研究工作流(i)被分解为通过版本化纯文本产物交换状态的模块化、可替换技能;(ii)由一个跨会话持久存在的项目级研究 wiki 支撑;并且(iii)在每个阶段都由一个来自不同模型家族的 reviewer,依据正式的"证据到结论"审计级联进行检查,那么由此得到的系统会比单 agent 或同家族自我精炼循环捕获更多"看似可信却缺乏支撑"的结论,产出更多有证据支撑的研究产物——本文将双角色 executor/reviewer 模式论证为打破自我博弈盲点所需的最小配置(以对抗性 vs. 随机性 bandit、双人博弈收敛为类比,并明确声明这是一种设计类比,而非形式化结论)。

# Q4 相关工作与关键人物

* 与 The AI Scientist / AI Scientist-v2(端到端的想法到论文自动化)、Agent Laboratory 及其 AgentRxiv 扩展(人机协同检查点、共享研究仓库)、AI co-scientist(聚焦假设生成)、data-to-paper(带人工可验证可追溯性的标注数据到论文流程)直接形成对比——本文声称的差异化之处,在于这些系统中很少有一个能联合记录文献笔记、想法、实验、负面结果和结论状态、可跨会话复用的项目级结构化记忆。
* 建立在自我精炼与多 agent 辩论文献(Self-Refine、Reflexion、多 agent 辩论、发散式思维辩论)之上,作为采用跨模型而非同模型评审的动机。
* 引用 Luo 等人对自主研究系统缺陷的批判性分析(基准选择不当、数据泄露、指标误用、事后选择偏差),作为第 3 节保障机制的直接动机。
* 与通用型或软件工程类 agent 框架(AutoGen、CAMEL、OpenHands、SWE-agent、MetaGPT、ChatDev)区分开来——ARIS 专注于研究场景、领域感知的技能定义,以及强制的 reviewer/executor 模型家族分离;相对于 Lee 等人的 Meta-Harness(harness 的外层优化循环),本文将自身定位为一个手工设计的 harness,只包含该外层循环的一个原型版本。
* **作者/机构**:Ruofeng Yang、Yongcan Li、Shuai Li 三人团队,来自上海交通大学与上海创新研究院;提交于 2026-05-03。

# Q5 核心解法

**跨模型对抗协作。** executor 产出一件产物(代码、论文段落、实验设计);一个建议来自不同模型家族的 reviewer(例如 Claude 系 executor 配 GPT 系 reviewer,通过 Codex/Oracle MCP,反之亦然)直接阅读该产物本身(而非 executor 对它的转述,以避免继承其叙述框架),并按预定义评分标准返回结构化打分和行动项。该循环持续到分数越过阈值(默认 6/10)且关键问题均已解决,或达到轮数上限(默认 4 轮)。Reviewer 沿两个正交轴配置:访问范围(仅文档 / 文档+辅助产物 / 仓库级别)以及上下文策略(每轮开新线程以避免确认偏误 vs. 跨轮保留状态以核实先前问题是否已解决)。

**三层架构。** *执行层*是一个包含 65 个以上单文件 SKILL.md 规范(YAML frontmatter + 自然语言工作流说明)的技能库,通过版本化纯文本产物交换状态(例如 IDEA_REPORT.md → EXPERIMENT_LOG.md → NARRATIVE_REPORT.md),外加一个项目级研究 wiki,存储四类实体(论文、想法、实验、结论),由八种类型化关系连接(extends、contradicts、addresses_gap、inspired_by、tested_by、supports、invalidates、supersedes)——关键设计是保留*被否决*的想法,这样后续会话就不会重新提出已经走不通的方向。*编排层*把技能串联成五条工作流(想法发现、实验衔接、自动评审、论文撰写、投稿反驳),分布在四个研究阶段中,并提供四档强度预设(lite ≈0.4×、balanced 1×、max ≈2.5×、beast ≈5–8×),用于调节搜索/评审的广度,而不改变 reviewer 自身的推理算力预算。*保障层*运行一个三阶段"证据到结论"审计级联:第一阶段(实验完整性审计)检查模型自造的参照标签、自归一化分数、幽灵结果、死代码/未使用指标注水、范围夸大;第二阶段(结果到结论映射)为每条结论分配支持/部分支持/不成立的判定,写入结论台账,并传递第一阶段的完整性问题;第三阶段(论文结论审计)由一个全新的、无上下文的 reviewer 线程,把论文中每一条量化结论与台账及原始文件逐条核对。手稿保障方面则另有一套五遍科学编辑流水线、面向理论型章节的 20 类问题分类法、同时审阅源码与 PDF 的双输入视觉评审,以及三轴引用审计(是否存在、元数据是否正确、上下文是否恰当)。一个原型化的元优化外层循环被动记录使用事件,分析模式(哪些参数被最频繁地手动覆盖、哪些工具反复失败、评审分数在何处停滞不前)并通过 /meta-optimize 提出对相应 SKILL.md 文件的补丁;每条提议补丁须经 GPT-5.4-xhigh 评分至少 7/10,才会被呈现给人类,由人类做最终决定——系统从不自动应用 harness 层面的改动。

# Q6 实验设计

本文报告的是部署/采用证据,而非受控基准测试,并明确将此列为局限。技能库从首次发布时的 21 个核心技能增长到 65 个以上,涵盖机器人、硬件设计、通信、数学证明、基金申请撰写和演示文稿生成;除了原生测试过的三个 executor 平台(Claude Code、Codex CLI、Cursor)外,另有三个平台通过社区维护的适配指南被记录在案。文中报告了一次完整记录的通宵运行(约 8 小时):完成四轮评审-修订,内部评审分数从 5.0 升至 7.5/10,启动了 20 多个 GPU 实验,并移除了缺乏证据支撑的结论。论文明确指出这只是单篇论文上的一次轨迹,不构成跨模型评审优于同模型评审、或两个 reviewer 是最优委员会规模的因果证据;分离这一效应留给附录 E 中描述的、作为未来工作的受控算力对齐基准协议。

# Q7 数据与代码

本文未引入基准数据集;所谓"评测"是观察性的部署证据(采用情况、一次记录在案的通宵运行),而非留出测试集。项目主页/代码:[github.com/wanshuiyin/Auto-claude-code-research-in-sleep](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep)。该系统还以独立的 Rust CLI(ARIS-Code,构建于"claw-code" harness 之上)形式发布,把所有技能打包为斜杠命令,并内置一个原生的跨模型评审工具。

# Q8 证据质量

论文对自身证据边界的表述相当坦诚:"主要局限在于缺乏受控评测,依赖的是观察性的部署证据"(第 7 节)。那次通宵运行(评审分数 5.0→7.5/10、20 多个 GPU 实验、结论被剪除)证明了保障/修订循环至少在一次真实轨迹上能端到端运转,但样本量为一,无法确立跨家族评审优于同家族评审,也无法界定审计级联的假阴性率(有多少缺乏支撑的结论未被捕获)。支撑双角色最小配置的 bandit/博弈论类比被明确标注为设计类比,而非形式化的遗憾界或均衡结果——论文并未从中得出数学保证。采用度指标(65 个以上技能、原生测试三个平台加社区适配三个平台)证明了工程成熟度和使用度,但不证明研究产出质量。论文还披露了一个自我指涉的局限:ARIS 自身参与了本报告的撰写与评审,作者保留最终编辑责任——这是一个透明度声明,而非独立验证。

# Q9 主要贡献

1. 一套跨模型保障栈——一个三阶段"证据到结论"审计级联(实验完整性审计、结果到结论映射、针对结论台账的论文结论审计),外加手稿层面的检查(五遍编辑、证明核验、视觉 PDF 评审、三轴引用审计)——把"看似可信却缺乏支撑的成功"这一风险,转化为具体、可检查的失败模式。
2. 一套模块化三层系统(执行层/编排层/保障层),包含 65 个以上可复用的 Markdown 技能、一个带类型化论文/想法/实验/结论关系的跨会话持久研究 wiki、可调的强度预设、可配置的 reviewer 路由,以及一个针对 harness 自身技能文件的原型化、reviewer 把关的元优化循环。
3. 跨多个 executor 平台(原生测试三个、社区适配三个)的早期部署证据,附一次记录在案的端到端通宵运行,坦诚地将其定性为观察性而非因果性证据。

# Q10 下一步

* 论文自身提出的方向:一个算力对齐的受控基准,用以分离跨模型异质性的因果贡献(协议已在附录 E 中勾勒);面向机密性敏感仓库的纯本地 reviewer 路由(尚未实现);以及针对研究者生产力的用户研究。
* 作者明确标注为尚未验证的一个更具推测性的方向:把跨模型问责原语(reviewer 独立性、证据到结论审计、可溯源的结论台账)推广到手稿之外,插入到任何模型输出与下游训练数据留存或奖励信号之间——这被表述为一个关于缓解 LLM 评判者偏差和递归训练模型坍塌风险的假设,而非本报告给出的结论。
* 检索到的材料未能解答的问题:三阶段审计级联的假阴性率与人工同行评审相比如何;评审者偏差放大(循环过拟合到某个 reviewer 模型的偏好)是否可测量、可纠正;以及在没有确定性评测器的领域(本知识库已在 [Research verifiability](../topics/research-verifiability.md) 主题下关注的问题),该系统需要如何调整。
* **与本仓库的关联**:ARIS 的"文件系统即状态"设计(所有会话状态存于可版本化文本、基于检查点恢复)以及它那保留被否决想法的研究 wiki,与本仓库自身的记忆层约定(`PROJECT_MEMORY.md`、`paper_skeleton.md`)在结构上颇为相似——值得对照它的类型化论文/想法/实验/结论关系,看本仓库当前如何把结论与证据关联起来。
