# Q1 问题定义

* **输入（X）：** 来自真实 MCP 服务运行和开放智能体语料的真实执行轨迹 M = {(f_t, x_t, o_t)}，以及目标链长 L 和环境数 K。
* **输出（Y）：** 带类型的工具组合图；按需合成数据库的环境簇；由（任务 q、验证集 V、工具链 ω、初始状态 s₀）组成的数据集；在其上训练的模型；以及现有基准的更难版本。
* **约束：** 每条链必须是图上的一次游走，满足依赖可达性、状态前置条件和参数来源（每个参数都可追溯到 q、s₀ 或更早的观察），并且从 s₀ 重新执行时必须通过全部断言。目标是在重放验证下最大化长程、跨环境的覆盖，而不是任何单个数据库的保真度。

# Q2 问题新颖性

部分是新问题。智能体环境扩展方向已经很拥挤：Simia、GenEnv 这类模拟器把 LLM 当作文本世界模型；EnvScaler、Agent World Model、Agent-World 和 AgentScaler 式合成（Fang 等）则构建可执行的数据库、工具和任务。WorkRover 和 WEFT 演化整个交互系统，[Agent-Reflex](../papers/2610.17953.md) 加入失败。作者把这些归为*以数据为中心*（主题、数据库、工具、任务依次生成），并指出三个局限：工具接口偏离真实接口、工具组合没有执行依据、任务局限于单一环境。新意在于顺序：先有真实轨迹，再有被见证的工具图，只有状态需要时才建数据库。这遵循与 [Trace2Env](../papers/2610.06100.md) 和 Terminal-Universe 相同的 Trace-to-ENV 原则。第三个局限其实比论文说的要窄：本文未引用的 [CompoWorld](../papers/2609.33665.md) 已经沿随机游走依赖图把可独立执行的服务组合成跨服务任务，只是它的图是在服务层面采样的，不是从轨迹中挖掘的（读者比较）。

# Q3 科学假设

如果工具组合来自真实执行中见证的关系，而任务是从真正运行过的游走反编译出来的，那么在这些任务上做 SFT 应当教会可迁移的跨环境编排，而不只是函数调用的形式。性能应当随数据量和环境广度增长，执行见证的边应当优于 LLM 判断的边，同一机制还应能产生前沿基准的更难版本。

# Q5 关键解决思路

**按执行真实性整理轨迹语料。** 工具定义与线上服务完全一致的 MCP 生态任务，由多个智能体在这些服务上执行。网络来源的轨迹按真实性分级：真实服务记录（Toucan-1.5M，以及移除不可用接口后的 ToolBench）为高；SWE-agent 和 [OpenHands](../papers/2407.16741.md) 在真实工作区的运行、只保留显式工具调用的为中；合成环境轨迹为低，只有工具名和 schema 与真实工具一致时才保留。

**带类型和权重的工具图。** 节点是工具加上规范化后的参数配置。在相邻调用之间，确定性规则（不用 LLM）添加三类边：下一步输入使用了上一步输出的值且字段类型匹配时加*数据*边；一次调用修改某对象、下一次读取或继续修改它时加*状态*边；调用失败后换用另一工具并成功时加*重试*边。边权是观察到的转移频率 w = N_ij / N_i。低频边被丢弃，数据边必须可追溯，这样可以排除 `limit=10` 这类常量造成的假连接。数据、状态、重试边分别占 69%、25% 和 6%。

**选择性落地。** 按连接密度聚类得到 804 个环境。*操作型*环境（181 个，含可改变状态的工具）由研究智能体按主题构建数据库，做法沿用 Agent-World。*状态查询型*环境从记录的局部快照初始化状态。*无状态*环境（如网页搜索）对匹配的调用复用语料中缓存的返回结果。

**带回滚的状态感知游走。** 从绑定数据库和快照的节点出发，只保留输入能由更早返回值或当前状态填充的邻居，按边权采样并执行。如果工具失败，或结果状态与所走的边矛盾，就把环境恢复到上一个快照并另选邻居；多次回滚仍无法继续的链被丢弃。

**反编译与重放。** LLM 写出不含工具名和调用顺序的自然语言任务，验证集结合最终状态、关键中间快照和必需输出三类断言。只有从 s₀ 重放全部通过才保留样本。之后为保留的任务生成教师轨迹，并用同样的检查过滤。难度通过 L、K 和跨环境边的比例控制。

**基准升级。** 对现有基准，收集其真实工具调用，用同样的规则把它们与共享数据或状态的外部工具相连，把单一环境扩展成环境簇。然后走更长的链，反向生成任务。三位博士级专家用两天审核候选任务，至少两人批准才保留（Fleiss' κ = 0.82，一致率 93.1%），得到 AutomationBench Pro（300 个任务）和 τ³-Bench Banking Pro（98 个任务）。

# Q6 实验设计

* **数据与训练。** 超过 20 万条原始轨迹；Kimi K3 同时作为教师和任务撰写者；34,376 个 SFT 样本和 653 个强化学习样本，后者经 35B 模型 Pass@16 筛选，只保留有一到两次正确 rollout 的候选。对 Qwen3-8B、Qwen3.6-35B-A3B（16 张 GPU）和 GLM-5.2-744B-A40B（256 张 GPU）做一个 epoch 的 SFT。强化学习是 48 步异步 GRPO，二元的基于执行的奖励，学习率 2e-6，批大小 256，组大小 16。
* **基准（七个）。** AutomationBench、SkillsBench、JobBench、τ³-Bench Banking、BFCL V4、Harvey LAB 和 OfficeQA Pro。
* **基线。** 闭源模型（Claude Opus 5、GPT 5.6 Sol）、大型开放模型、同规模 8B 环境扩展模型和 27-35B 开放模型。结果优先取官方榜单，其次是提供方报告，最后才是本地复现；ToolSpace 结果和本地复现都是三次运行的均值。
* **分析。** 七个前沿模型上 Pro 与 Standard 的对比；从 1/16 到全量的数据比例和环境比例；按 BGE 相关性选取的前 50% 环境与随机 50% 环境的对比；四个语料各 2K 问题的任务聚类（t-SNE、DBSCAN）；500 个 Agent-World 环境上的合成文件数；35B 上五个基准的组件消融。

# Q7 数据集与代码

代码位于 [dongguanting/ToolSpace](https://github.com/dongguanting/ToolSpace)（`hf papers info` 显示 28 颗星），另有带游走演示的[项目主页](https://toolspace-agent.github.io/)和 Hugging Face 模型集合；本笔记都未打开。图的统计很详细：平均出度 2.3，最大 56；平均每个环境 10.86 个工具；在 21,385 条至少含五次工具调用的合成轨迹中，平均 18.86 次调用和 2.29 个环境，最多 209 次调用和 22 个环境。论文称数据来源和 MCP 服务都有开源许可，并排除了与测试集重叠的任务、工具调用序列或初始状态。

# Q8 证据质量

* **有支持的结论。**
  * *各规模都有提升。* 七个基准的平均分：7.2 到 19.6（8B，加强化学习 20.7），23.0 到 41.0（35B，加强化学习 43.2），44.6 到 56.6（744B），高于 GLM 5.3（53.8）、Qwen 3.8 Max（54.5）和 GPT 5.6 Sol（48.9），与 Claude Opus 5（56.6）持平。不过持平的只是平均值，各项分布并不相同：744B 在 AutomationBench（54.7 对 45.6）和 Harvey LAB 上领先 Opus 5，在 JobBench（57.5 对 68.0）和 τ³-Bench Banking 上落后。
  * *组合最重要的地方提升最大。* AutomationBench 在 35B 上从 8.2 升到 45.8，而 8B 环境扩展基线在此都低于 1。
  * *Pro 划分确实更难。* 七个前沿模型全部下降：AutomationBench 下降 11.3 到 38.2 分（Opus 5.5 从 59.2 到 26.3），τ³-Bench Banking 下降 14.4 到 25.6 分，两者的工具调用数都上升。
  * *见证的边优于 LLM 判断的边。* LLM 判断的边使全部五个消融基准下降 5.4 到 8.0 分（平均 6.8，读者根据表 3 计算），接近移除状态边（7.1）或数据边（7.4）。均匀游走损失 4.7，去掉回滚损失 3.3，去掉重试边损失 1.4（读者计算）。
  * *更多数据和环境有帮助。* 全量在全部五个规模分析基准上最好，从一半到全量的数据在 AutomationBench 上仍增加 4.6。
* **比标题说法更弱或更窄之处。**
  * *合成成本只是代理指标。* 55.3% 的节省（2,724 到 1,218 个文件）是文件数，论文也说没有测量 token、时间和算力成本。收集超过 20 万条轨迹（包括在线上服务上运行）的成本没有计入（读者观察）。
  * *未过拟合的论证并不完整。* 前 50% 与随机 50% 的环境在四个具名基准上相差不超过 1.7 分，但正文没有给出 τ³-Bench Banking 的差距，而它的提升来得很晚（只有全量时才从 19.6 升到 34.0）。去污染排除的是重叠的任务、工具序列和初始状态，不包括重叠的工具，而图中最显眼的环境（Gmail、Slack、Salesforce、Airtable）正是 AutomationBench 所模拟的那类 SaaS 应用（读者观察）。
  * *"超过教师"有别的解释。* 论文把 744B 的 56.6 高于 Kimi K3 的 49.7 视为不是简单蒸馏的证据。但轨迹被过滤为通过验证的那些，学生学到的是教师的成功而不是其平均行为，而且 GLM-5.2 的起点就有 44.6（读者观察）。
  * *强化学习的证据单薄。* 35B 上强化学习的 +2.2 主要来自 τ³-Bench Banking（34.0 到 42.3）。AutomationBench 和 JobBench 精确到一位小数完全不变（45.8、40.0），这对三次运行的均值来说不太寻常，论文未作说明（读者观察）。
  * *Pro 难度可能混有测量差异。* Standard 分数来自公开榜单，Pro 分数来自作者。轨迹断言来自一次游走的中间快照，有效的不同路径可能无法通过；专家审核任务和脚本并不直接衡量这一点（读者观察）。
  * *仍有薄弱点。* Harvey LAB 在 35B 上只有 1.7 到 2.5，在 8B 上为 0.0，所以"七个基准都超过基础模型"掩盖了这里极小的增益。消融只覆盖 35B 上七个基准中的五个，也没有给出波动。
  * *基线来源混杂。* Agent-Reflex-8B 在 BFCL V4 上此处为 51.3，[原论文](../papers/2610.17953.md)为 52.9（读者比较）；Opus 5 在 AutomationBench 上此处为 45.6，[MiMo-V2.6](../papers/2610.11959.md) 中为 50.3。

# Q9 贡献

* 以工具优先的环境合成表述：用确定性规则构建一张带类型和权重、由执行见证的工具关系图，作为任务和基准背后的单一基元。
* 选择性落地：只在工具改变状态的地方建数据库，其他地方复用记录的返回值。
* 带回滚的状态感知游走和以重放为门槛的反编译，产生 34,376 个经验证样本，其中至少五次调用的样本平均 18.86 次工具调用。
* 消融证据表明，边的获取方式与边的类型几乎同样重要。
* 经专家审核的更难划分：AutomationBench Pro 和 τ³-Bench Banking Pro。

# Q10 后续方向

* **与 CompoWorld 的同基础模型比较（读者建议）。** 两篇论文都微调 Qwen3.6-35B-A3B，并都报告 AutomationBench、τ³-Bench Banking 和 SkillsBench，但数据量和教师不同。用等量的两种流程数据训练，就能区分挖掘式与采样式组合。
* **非相邻依赖（读者建议）。** 边只来自相邻调用，所以很早读取、很多步之后才使用的值，除非经过中间步骤传递，否则不会被捕获。挖掘更长距离的来源可以补上这类连接。
* **脱离脚本的重放（读者问题）。** 无状态工具对匹配的调用返回缓存结果。正文没有说明学生在强化学习中用不同措辞查询时会得到什么，而这影响智能体能探索多远。
* **与路径无关的检查（读者建议）。** 在 Pro 划分上比较只用状态断言和当前混合断言，可以看出分数下降有多少来自轨迹断言。
* **更多数据（来自论文）。** 从一半到全量的数据没有出现平台期，说明规模还未到极限。
