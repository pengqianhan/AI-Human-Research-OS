Mockup only · Notes on this mockup

How to read it

  • The striped strip is not part of the app. Path walks §2's tester path in order; on each app screen the obvious button also takes you to the next one. Other places opens S3 (the File menu), S4 (the Settings rows), and S6 (Home with no projects; also reached by unticking the example on S2).
  • The strip's second row shows the alternatives for the screen you are on, labelled A and B, with the recommended one marked. States switches one failure state at a time; a line under the strip then names it and the screens it changes. On a conversation, the first row also picks which S5 line values the project run shows (every value §6 gives) and whether the run is done or still running.
  • Choices are kept in the address after #, so a link reopens the same view.
  • Conversations are samples, not from a real session. Hashes are made up: e81c4f7 stands for the example's one commit, 5a2d9e3 for a commit an agent makes. The tiles' versions and paths, the model id, the login text, the session ids, and the turn durations are illustrative too. Nothing reads or writes Git, and no message is sent.

What each screen is drawn from

  • S1 Welcome: §6 S1, in the place and shape of today's welcome card (StateMissing.tsx:40-92): one centred card, no left menu.
  • S2 New workspace: §6 S2. In A it replaces the Welcome card; in B it is part of it. From the File menu it is a dialog over the open workspace, in both.
  • S3 File menu: §6 S3 over today's File menu (menu.ts:54-59), drawn as the macOS menu bar.
  • S4 Settings rows: §6 S4 inside today's Settings page (SystemPage.tsx) and prerequisite tiles (DesktopStatus.tsx:62-114; labels and details from doctor.ts).
  • S5 turn lines: §6 S5 inside today's turn rows (AgentChat.tsx:714-725): under "model · login" and after "done · … s". The short hash is a button that copies the full one, in both alternatives: §6 leaves that to the mockup, and the mockup keeps it.
  • S6 Home with no projects: §6 S6 in place of today's empty Projects text (HomePage.tsx:54-58).
  • Home's card: today's project card (ProjectCard.tsx) filled from nanochat_cpu's PROJECT_MEMORY.md as it would ship (§8 Q2 default). The run command, its 2 min 57 s, and the 0.2 GB of data plus 0.2 GB of wheels are from Code/README.md.
  • The root agent's turns: §2 rows 8 and 9, with the harness command in its uv form (§2 row 9).

Recommended

  • S1 with S2: A, a separate step. File → New Workspace… needs S2 on its own anyway, so one S2 serves both ways in.
  • S5: A, a text line. It is §6's proposal, and the commit reads as one more fact of the turn, in the type of the lines around it.
  • S3: B, "Open Workspace…". The menu and the Welcome page then name the same thing the same way.

Where the mockup departs from §6

  1. S2 has a heading, "New workspace", a field label, "Folder", and a label over the list, "Will be written". §6 gives S2 none of these.
  2. With the example unticked, the list and the Git line drop their example part ("…, and the project template"; "The workspace is a Git repository. Nothing is committed under your name"), and the progress skips "Making the example's repository…". §6 gives only the ticked words.
  3. Create is disabled while creating, as well as Cancel; §6 names only Cancel.
  4. "Cannot write there" is drawn as a failure of Create: the progress stops, and the message and Show log appear. §6 does not say whether it is found when the folder is chosen.
  5. After "done", a turn with no commit, no repository, or no Git repeats its start words ("no commit yet", "not a Git repository", "Git not found"). §6 gives an end line only for a repository with a commit.
  6. The run's end line says "3 changed" (Code/results/summary.json, Code/results/training_metrics.csv, PROJECT_MEMORY.md), not §6's example "7 changed". Which files a real run changes was not established; the two figures in Figs/ may change too. §6's own "3 changed, 1 new" and "7 changed" are under the S5 line choices.
  7. The S5 start line uses the muted colour, not the faint colour of "model · login", so it can be read; its size and font are that line's.
  8. The two changed prerequisite tiles open by default and carry a striped "changed in step 3" tag, which is mockup chrome; in the app they open on a click like the others.
  9. The Git row's "download link" keeps today's link text, "How to install".
  10. The tiles' "ready" also needs Git, because §6 makes Git required. Today's rule (doctor.ts) needs only the folder, Python, and one agent.
  11. Home's draft "Run the nanochat_cpu example and report" (§2 row 8's example), and then "Yes, dispatch it.", are typed in for you; the app starts with an empty box.
  12. S2 opened from the File menu is drawn as a dialog over the open workspace, and Cancel returns there. §6 says neither.
  13. In B, the form inside the Welcome card has no Cancel, because there is nothing to go back to.
  14. The identity row's button is labelled "Copy the two lines"; §6 says only that the lines can be copied.
  15. Opening nanochat_cpu before the root agent has dispatched shows its empty conversation, as the app would; the strip then offers to dispatch for you.

Suggested word changes (the mockup keeps §6's words)

  • S2's identity line ends "(see Settings)", but on a first start there is no Settings page, only the welcome card, and the row is on the same page. Perhaps "(see Git name and email below)".
  • §6's sentences have no final full stop ("…on your own plan", "…Choose an empty or new folder", "…Install it, then Check again"); the app's other sentences have one.
  • With no uv or Python, today's link goes to python.org (doctor.ts HELP.python), while the tester sheet asks for uv; uv's installation page would match.
  • The two copy lines keep §6's "…" placeholders; "Your Name" and "you@example.com" would show what to type.
  • "Check again" renames today's "re-check" on the tiles' header (§6 S1 and S4; DesktopStatus.tsx:78).

What §6 leaves open, or gets wrong

  • S4 says its rows appear inside S1 and S2, but S2's "Shows" does not list them. The mockup puts the tiles in S2 as well.
  • On a first start no folder is open, so today's tiles show the folder as "missing", Claude Code and Codex as "error" ("Needs a Research OS folder and Python to check.", doctor.ts:108-111), and the header as "not ready". §6 does not say whether S1 hides or rewords these rows.
  • "Cannot write there": §6 does not say whether it comes before or after Create, or whether Show log comes with it.
  • The end line has no "new" count, though the start line does, and no words for no commit, no repository, or no Git.
  • No keyboard shortcut is given for New Workspace…; today Open has ⌘O (Ctrl+O on Windows and Linux).
  • §6 does not say where Cancel returns when S2 was opened from the File menu.
  • With no uv or Python the generator cannot run, so a workspace cannot be created or read, and the app shows its "Preparing the snapshot" card rather than Home (StateMissing.tsx:49). S5's "the conversation's existing error" is then reachable only in a workspace that already has a snapshot.
  • Home's card shows this instance's lines to a tester: "awaiting Human Owner review" and "accepting the 2026-09-26 dispatch run also completes GOAL.md H2", and a new workspace has no GOAL.md. That is §8 Q2.
  • Root-agent turns read "no commit yet" on every turn until the user commits in the workspace's own repository (§8 Q5 default: git init, no commit). Under Q5's alternative they would read "not a Git repository".
