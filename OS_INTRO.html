AI-Human Research OS

A lightweight, folder-based research operating system where code agents (Codex, Claude Code) are the execution core and humans steer in natural language.

What it is, and why

Research is iterative: ideas, references, experiments, figures, and writing update each other constantly. This repository organizes those materials by type, not by a fixed pipeline, and adds just enough convention — stable paths, entry documents, layered memory, and reusable skills — that an agent entering the repository cold can orient itself in two short reads and work productively across many sessions at low token cost. There is deliberately no database, no backend service, no CLI, no framework: plain folders, Markdown, BibTeX, and LaTeX.

The five orientation questions

1. Where are the current goal, background, progress, and key memory?
Global state in Memory/MEMORY.md (goals, Active Projects, decisions); per-project state in projects-folder/<Project>/PROJECT_MEMORY.md (snapshot, decisions, progress log, TODOs).
2. Where do new ideas, references, code, figures, and writing go?
Ideas → Ideas/ OKF concept or nested idea bundle; project references → projects-folder/<Project>/paper/references.bib; code → projects-folder/<Project>/Code/; figures → projects-folder/<Project>/Figs/; baselines → projects-folder/<Project>/Baselines/; writing → projects-folder/<Project>/paper/main.tex.
3. Which files should an agent read first?
INSTRUCTION.md, then FILETREE.md, then the relevant memory file(s) — see the chain above.
4. How does a feasible idea become a project or paper draft?
cp -R projects-folder/templates/ai_research_template projects-folder/<ProjectName>; fill both Snapshot sections and the project index.md; mark the idea promoted with a link; add an Active Projects row; refresh FILETREE.md. (Workflow 2 in INSTRUCTION.md.)
5. When does experience become memory vs. a skill?
Lesson → PROJECT_MEMORY.md first. Procedural and project-specific → project-local skill (projects-folder/<Project>/.claude/skills/ + .agents/skills/, created on demand). Useful across projects and domain-light → Research-skills-hub/ + install into both root skill dirs.

Skills model

  • Store: Research-skills-hub/ holds canonical sources — science-skills/ (from google-deepmind/science-skills: literature search for arXiv / OpenAlex / bioRxiv / Europe PMC, uv bootstrap, workflow→skill distiller) and open-paper-skills/ (repo-local: uv-env, filetree-simple).
  • Install: copy a skill into both .agents/skills/ and .claude/skills/; the two must stay byte-identical.
  • Promote: project memory → project-local skill → hub, with scope/inputs/outputs/limitations documented in SKILL.md; update skills_map.md after changes.

Quick start — human

  1. Open the repository with Claude Code or Codex.
  2. Say what you want in natural language: “记录一个新想法…”, “start a project from idea X”, “add this paper to the references”, “run the experiment and update the draft”.
  3. Skim README.md once; everything else the agent handles by convention.

Quick start — agent

  1. Read INSTRUCTION.md (always), FILETREE.md (unless trivial), then the memory file relevant to the task.
  2. Use the six Core Workflows in INSTRUCTION.md for any material-moving operation.
  3. End sessions by updating the appropriate memory layer; never invent citations, data, or results; never delete user research material without confirmation.

Design principles

  • Occam's razor — no entities without necessity; plain files over tooling.
  • Low token cost — short always-read docs (INSTRUCTION.md ≈ 130 lines), deeper docs on demand.
  • Traceability — every claim, number, and citation maps to a file, command, or fetched metadata.
  • Preservation — original user research materials are never silently rewritten or deleted.
  • Evolvability — the OS grows through use: memory accumulates, lessons become skills, the hub grows.
