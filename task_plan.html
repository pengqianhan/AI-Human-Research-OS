§3 Target design (what "normalized" means here)

3.1 Entry-document chain (context-loading rule)

Codex session            Claude Code session
   │ reads AGENTS.md        │ reads CLAUDE.md          (1 line each: "Read INSTRUCTION.md…")
   └────────────┬───────────┘
                ▼
        INSTRUCTION.md      — ALWAYS read. Core rules + workflows + memory/skill policy.
                │             Budget: ≤ ~180 lines so the per-session cost stays low.
                ▼
        FILETREE.md         — read unless task is trivial (directory responsibilities).
                ▼
        Memory/MEMORY.md    — read for broad / cross-project work.
                ▼
        <Project>/PROJECT_MEMORY.md — read when working inside that project.

Rationale: one canonical always-read doc maximizes rule delivery and keeps token cost bounded; deeper docs load on demand. Alternative (separate WORKFLOWS.md) rejected for now — only revisit if INSTRUCTION.md exceeds the 180-line budget after Phase 4.1.

Instantiated projects are placed at the repository root, sibling to Paper_Initial_template/ (e.g. Example_Project/).
